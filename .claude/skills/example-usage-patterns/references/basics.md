# 例示の基本原則

## 4原則

### 1. 明確性（Clarity）

| 原則         | 説明                             |
| ------------ | -------------------------------- |
| 単一責務     | 各例は1つの概念に焦点を当てる    |
| 直感的な名前 | 変数名・関数名は目的を明確に示す |
| 段階的開示   | 複雑さを段階的に導入する         |

**良い例:**

```javascript
const userId = 123;
const user = await getUser(userId);
console.log(user.name);
```

**悪い例:**

```javascript
const x = 123;
const d = await f(x);
console.log(d.n);
```

### 2. 完全性（Completeness）

必須要素チェックリスト:

- [ ] すべてのインポート/依存関係が明記
- [ ] 環境設定（バージョン、環境変数）が明記
- [ ] インストール手順が提供
- [ ] コードがコピー&ペーストで動作
- [ ] 期待される出力が示されている

### 3. 実用性（Practicality）

- 現実的なシナリオに基づく
- ベストプラクティスを適用
- 非推奨パターンを避ける

### 4. 保守性（Maintainability）

- 依存関係のバージョンを明記
- テスト可能な構造を維持

## Diataxis分類

| 種類           | 目的       | 例                         |
| -------------- | ---------- | -------------------------- |
| チュートリアル | 学習       | ステップバイステップガイド |
| ハウツー       | タスク達成 | 問題解決型の例             |
| リファレンス   | 情報参照   | API全メソッドの例          |
| 説明           | 概念理解   | アーキテクチャ図付き例     |

## 段階的複雑化

```
段階1: 最小限（動作する最小コード）
  ↓
段階2: 実践的（エラーハンドリング追加）
  ↓
段階3: 高度（オプション機能・最適化）
```
