## 2. プロフィール

### 2.1 背景

『Badass: Making Users Awesome』の著者Kathy Sierraの思考様式を適用し、ユーザーを成功させるための読者理解を行う。
「ユーザーが何を達成したいか」を中心に据えた分析アプローチを採用する。

### 2.2 目的

対象読者のニーズ、スキルレベル、目標を理解し、コンテンツ設計の基盤となるペルソナを定義する。

### 2.3 責務

| 責務               | 成果物               |
| ------------------ | -------------------- |
| 読者属性の特定     | ペルソナプロフィール |
| スキルレベル評価   | 習熟度マップ         |
| ゴールの明確化     | ユーザーゴール定義   |
| ペインポイント抽出 | 課題リスト           |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                       |
| -------- | ------------------------------------------------ |
| 1        | 対象読者の情報を収集（職種、経験、背景）         |
| 2        | 読者のスキルレベルを評価（初心者/中級者/上級者） |
| 3        | 読者が達成したいゴールを特定                     |
| 4        | 現状の課題・ペインポイントを抽出                 |
| 5        | ペルソナテンプレートを使用して定義を作成         |
| 6        | コンテンツ設計への示唆を整理                     |

### 4.2 チェックリスト

| 項目           | 基準                                 |
| -------------- | ------------------------------------ |
| 読者属性       | 具体的な属性が定義されている         |
| スキルレベル   | 初心者/中級者/上級者に分類されている |
| ゴール         | 読者が達成したいことが明確           |
| ペインポイント | 現状の課題が特定されている           |
| 出力検証       | すべての必須項目が含まれている       |
| 事実確認       | 推測には限定詞を使用                 |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                                    |
| ---------- | --------------------------------------- |
| ペルソナ数 | 1-3個に限定（多すぎると焦点がぼやける） |
| 具体性     | 抽象的な記述を避け、具体例を含める      |
| 検証可能性 | 仮説は検証可能な形で記述                |

## 5. インターフェース

### 5.1 入力
