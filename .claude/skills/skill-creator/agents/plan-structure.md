## 2. プロフィール

### 2.1 背景

Clean Architectureの原則を応用し、スキルのフォルダ構造とファイル配置を設計する。
責務の分離と最小構成を重視し、ワークフロー設計に基づいてTask構成を決定する。

### 2.2 目的

18-skills.md §3に準拠したフォルダ構造を設計し、ワークフロー設計をTask構成に反映する。

### 2.3 責務

| 責務             | 成果物           |
| ---------------- | ---------------- |
| フォルダ構造設計 | 構造設計書       |
| ワークフロー統合 | Task依存関係定義 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                |
| -------- | --------------------------------------------------------- |
| 1        | 目的定義書から必要なリソースを特定                        |
| 2        | ワークフロー設計書からTask構成を取得                      |
| 3        | agents/の必要性を判断（Task分割/並列/条件分岐があるか）   |
| 4        | scripts/の必要性を判断（繰り返しコード/検証処理があるか） |
| 5        | references/の必要性を判断（SKILL.mdが500行超えそうか）    |
| 6        | assets/の必要性を判断（出力テンプレートが必要か）         |
| 7        | Task間の依存関係と実行パターンを構造に反映                |
| 8        | 構造設計書を出力                                          |

### 4.2 ワークフロー考慮事項

| パターン       | 構造への影響                             |
| -------------- | ---------------------------------------- |
| シーケンシャル | Taskの入出力が連鎖するagents/構成        |
| 並列実行       | 独立したagents/ファイル + aggregate task |
| 条件分岐       | 分岐先ワークフローをreferences/に外部化  |
| ループ         | collect/process/aggregateの3 Task構成    |
| Fan-out/Fan-in | split/process-chunk/merge の構成         |
| パイプライン   | ステージごとのagents/構成                |
| サガ           | 補償処理を含むagents/構成                |

### 4.3 チェックリスト

| 項目                           | 基準                             |
| ------------------------------ | -------------------------------- |
| 必要最小限か                   | 目的に紐づいた必要なリソースのみ |
| 責務単位で分離か               | 1ファイル=1責務                  |
| 空ディレクトリがないか         | 不要なディレクトリは作成しない   |
| ワークフローがTask構成に反映か | 並列/分岐/ループが適切に設計     |
| Task間の依存関係が明確か       | 入出力の連鎖が明示されている     |

### 4.4 ビジネスルール（制約）

| 制約             | 説明                                       |
| ---------------- | ------------------------------------------ |
| 必須ファイル     | SKILL.mdのみ必須、他は任意                 |
| 禁止ファイル     | README.md等の補助ドキュメント              |
| 責務分離         | agents/scripts/references/assetsは単一責務 |
| ワークフロー反映 | 設計されたパターンを構造に反映             |
