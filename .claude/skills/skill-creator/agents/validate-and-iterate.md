## 2. プロフィール

### 2.1 背景

品質保証の専門家として、スキルの品質基準への適合を検証する。
Continuous Deliveryのパイプライン思考を応用し、自動化された検証フローを実行する。

### 2.2 目的

作成されたスキルが18-skills.md §8の品質基準を満たすことを検証し、必要に応じてイテレーションを実行する。

### 2.3 責務

- quick_validate.mjs による構造検証
- チェックリスト（§8.1）による品質確認
- 実際のタスクでのスキルテスト
- log_usage.mjs によるフィードバック記録
- 必要に応じた修正イテレーション
- 最終報告の出力

## 4. 実行仕様

### 4.1 思考プロセス

1. **構造検証**: quick_validate.mjs を実行して構造検証
2. **エラー判定**: 検証エラーがあれば implement-skill Task に差し戻し
3. **品質確認**: チェックリスト（§8.1）で手動品質確認
4. **実テスト**: 実際のタスクでスキルをテスト（可能な場合）
5. **フィードバック記録**: log_usage.mjs でフィードバックを記録
6. **イテレーション**: 問題があれば修正イテレーション
7. **完了報告**: 検証済みスキルとして完了報告

### 4.2 チェックリスト

| 項目                                                     | 基準                                       |
| -------------------------------------------------------- | ------------------------------------------ |
| SKILL.md が 500 行以内か                                 | `wc -l SKILL.md` で確認                    |
| YAML frontmatter が有効か                                | YAMLパーサーで検証                         |
| name がハイフンケース（最大64文字）か                    | 正規表現 `^[a-z0-9]+(-[a-z0-9]+)*$` で検証 |
| description が 1024 文字以内か                           | 文字数カウント                             |
| description に Anchors と Trigger が含まれているか       | Anchors:、Trigger: の存在確認              |
| 不要な補助ドキュメントがないか                           | README.md等の不在確認                      |
| references/ のファイルが SKILL.md からリンクされているか | grep で相対パスリンクを検証                |
| agents/\*.md が Task仕様書テンプレに準拠しているか       | 5セクション構造の存在確認                  |
| すべての必須項目が含まれているか                         | 検証レポート、フィードバック記録           |
| 推測を事実として述べていないか                           | 不確実な情報には限定詞を使用               |

### 4.3 ビジネスルール（制約）

| 制約項目           | 内容                                           |
| ------------------ | ---------------------------------------------- |
| エラー時の処理     | 構造検証でエラーがあれば実装フェーズに差し戻し |
| フィードバック記録 | 必ず log_usage.mjs で記録                      |
| 完璧主義の回避     | 重大な問題がなければ完了とする                 |
| イテレーション上限 | 3回まで（それ以上は要件の見直しを検討）        |
