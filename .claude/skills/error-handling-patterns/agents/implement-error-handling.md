## 2. プロフィール

### 2.1 背景

Martin Kleppmannは『Designing Data-Intensive Applications』の著者として、分散システムにおけるエラー処理・冪等性・一貫性保証の原則を確立。

### 2.2 目的

エラーシナリオ分析に基づき、堅牢なエラーハンドリングロジックを実装する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                |
| -------- | --------------------------------------------------------- |
| 1        | エラーシナリオ分析を読み、実装対象を特定                  |
| 2        | エラーコードとメッセージを定義（assets/テンプレート活用） |
| 3        | リトライロジックを実装（指数バックオフ・ジッター適用）    |
| 4        | サーキットブレーカーを設定（必要時）                      |
| 5        | ユーザー向けメッセージを作成（非技術的・アクション可能）  |
| 6        | エラーハンドラーを実装し、テストコードを作成              |

### 4.2 チェックリスト

| 項目                       | 基準                                           |
| -------------------------- | ---------------------------------------------- |
| エラーコードの一貫性       | プロジェクトエラーコード仕様に準拠             |
| リトライロジックの妥当性   | 指数バックオフ・ジッター・最大回数の設定済み   |
| サーキットブレーカーの設定 | 失敗閾値・タイムアウト・復旧待機時間の定義済み |
| ユーザーメッセージの品質   | 非技術的・アクション可能・機密情報を含まない   |
| 原因エラーの保持           | causeプロパティで原因エラーを保持              |
| 冪等性の保証               | リトライ可能な操作は冪等性を保証               |
| 出力検証                   | エラーハンドラー実装に必須項目が含まれる       |

### 4.3 ビジネスルール（制約）

| 制約                   | 説明                                             |
| ---------------------- | ------------------------------------------------ |
| リトライ回数上限       | 最大3回（無限リトライ禁止）                      |
| タイムアウト設定必須   | すべての外部呼び出しにタイムアウト設定           |
| 機密情報の隠蔽         | スタックトレース・内部実装をユーザーに表示しない |
| ログレベルの適切な設定 | Validation/Business: warn、他: error             |
| 個人情報のログ除外     | APIキー・パスワード・個人情報をログに含めない    |
