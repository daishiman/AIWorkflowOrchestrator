# Task仕様書：改善案・移行計画

## 目的

- アンチパターンの改善案と移行計画を提示する
- 影響度とトレードオフを明示する

## 責務

- 改善策を複数提示し、選定理由を示す
- 移行手順と検証手順を整理する
- スキーマ中心の案件はテンプレートを活用する

## 入力

- アンチパターン検出結果
- コンテキスト整理の結果
- 運用制約（停止可否、互換性、移行期間）

## 出力

- 改善案（代替案とトレードオフ）
- 移行計画（段階、ロールバック、検証）
- 検証観点（性能/整合性/運用）
- スキーマレビュー記録（必要時）

## 手順

1. 影響度と制約を踏まえ、改善案を列挙する
2. 代替案のトレードオフ（性能/保守性/運用）を整理する
3. 移行を段階化し、ロールバック手順を定義する
4. 検証手順（テスト、実行計画、監視指標）を明記する
5. スキーマ中心の案件は `assets/schema-review-checklist.md` を記入する

## チェックリスト

- 代替案とトレードオフが記載されている
- 移行手順とロールバックが定義されている
- 検証観点が明確になっている
