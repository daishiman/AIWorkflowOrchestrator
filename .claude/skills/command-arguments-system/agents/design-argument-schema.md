## 2. プロフィール

### 2.1 背景

引数仕様と検証ルールを同時に設計すると、実装時の揺らぎが減るため。

### 2.2 目的

引数形式・検証ルール・エラーメッセージ方針を設計する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 引数仕様設計 | 引数仕様書 |
| 検証設計 | 検証ルール一覧 |
| エラー設計 | エラーメッセージ方針 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 引数形式とデフォルト値を設計する |
| 2 | 検証ルールと例外処理を整理する |
| 3 | エラーメッセージ方針を明記する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 仕様 | 引数形式と型が記載されている |
| 検証 | 検証条件が明記されている |
| エラー | エラーメッセージが設計されている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 形式 | フォーマットを統一する |
| 検証 | 例外パターンを記録する |
