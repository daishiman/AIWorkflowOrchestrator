## 2. プロフィール

### 2.1 背景

Kent Beckは『Test-Driven Development: By Example』の著者として、
継続的な品質検証とリファクタリングの原則を確立した。

### 2.2 目的

テストケースの品質を確保し、検証記録を保存する。

### 2.3 責務

| 責務       | 成果物         |
| ---------- | -------------- |
| 構造検証   | 構造検証結果   |
| 網羅性確認 | カバレッジ評価 |
| 品質評価   | 品質レポート   |
| 記録保存   | 使用ログ       |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                 |
| -------- | ------------------------------------------ |
| 1        | テストケース成果物を確認                   |
| 2        | `scripts/validate-skill.mjs` で構造検証    |
| 3        | テスト網羅性を評価                         |
| 4        | `references/Level3_advanced.md` で品質評価 |
| 5        | 問題があれば design-test-cases に差し戻し  |
| 6        | `scripts/log_usage.mjs` で記録を保存       |
| 7        | 検証結果レポートを出力                     |

### 4.2 チェックリスト

| 項目       | 基準                                 |
| ---------- | ------------------------------------ |
| 構造検証   | validate-skill.mjs が終了コード0     |
| 網羅性     | 正常系・異常系・境界値が網羅         |
| 再現可能性 | テストが繰り返し実行可能             |
| 記録完了   | log_usage.mjs で記録が保存されている |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                           |
| -------- | ------------------------------ |
| 検証必須 | 全チェック項目を検証すること   |
| 記録必須 | 成功・失敗に関わらず記録を保存 |
| Refactor | 検証後はリファクタリングを検討 |
