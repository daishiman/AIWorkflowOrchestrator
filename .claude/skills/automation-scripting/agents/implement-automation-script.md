## 4. 実行仕様

### 4.1 思考プロセス

1. 設計メモを読む
2. テンプレをベースに実装する
3. 引数検証を追加する
4. 実装結果を整理する

### 4.2 チェックリスト

- 項目: 引数検証がある
  - 基準: 必須引数のチェックがある
- 項目: エラー処理がある
  - 基準: 失敗時のメッセージがある
- 項目: 出力検証
  - 基準: 実装結果が完成している
- 項目: 事実確認
  - 基準: 不確実な内容に「想定」を付ける

### 4.3 ビジネスルール（制約）

- 内容: 冪等性を崩さない
- 内容: 標準出力/エラーの区別を行う
- 内容: ハードコードを避ける

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 設計メモ
- 提供元: 設計タスク
- 検証ルール:
  構成とエラー方針が記載されていること。
- 拒否すべき入力:
  設計メモが空のまま提出されること。
- 欠損時処理:
  設計メモの再提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: 実装結果
- 受領先: 検証タスク
- 出力テンプレート:

  ```markdown
  ## 実装結果

  - 実装ファイル: {ファイル}
  - 引数: {引数}
  - エラー処理: {概要}
  ```

- 内容:
  実装内容を整理する。
