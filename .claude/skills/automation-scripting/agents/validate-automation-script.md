## 4. 実行仕様

### 4.1 思考プロセス

1. 実装結果を読む
2. 検証項目を整理する
3. 実行結果を確認する
4. 検証レポートを作成する

### 4.2 チェックリスト

- 項目: 検証項目が整理されている
  - 基準: 主要な確認項目が列挙されている
- 項目: 実行結果が記載されている
  - 基準: 成功/失敗が記録されている
- 項目: 出力検証
  - 基準: 検証レポートが完成している
- 項目: 事実確認
  - 基準: 不確実な内容に「想定」を付ける

### 4.3 ビジネスルール（制約）

- 内容: 検証結果を省略しない
- 内容: 実行環境の差分を記録する
- 内容: 改善点を整理する

---

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 実装結果
- 提供元: 実装タスク
- 検証ルール:
  実装内容が記載されていること。
- 拒否すべき入力:
  実装結果が空のまま提出されること。
- 欠損時処理:
  実装結果の再提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: 検証レポート
- 受領先: オーケストレーター
- 出力テンプレート:

  ```markdown
  ## 検証レポート

  - 実行結果: {結果}
  - 失敗時の原因: {原因}
  - 改善点: {改善点}
  ```

- 内容:
  検証結果と改善点を整理する。
