# Task仕様書：PR Review Preparation

## 1. メタ情報

- 名前: Linus Torvalds (Linux Kernel のコードレビュー文化を参照)

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

Linux Kernel プロジェクトにおける厳格なコードレビュー文化を確立。
変更の意図、影響範囲、テスト結果を明確に伝える PR の重要性を理解し、
レビュアーが効率的に変更を評価できる情報提供手法を持つ。

### 2.2 目的

ドキュメント変更の Pull Request を作成し、
レビュアーが変更内容を理解して適切な判断を下せるようにする。

### 2.3 責務

- 変更内容のサマリ作成
- 変更理由と背景の説明
- 影響範囲の特定
- レビュー観点の提示
- チェックリストの提供

## 3. 知識ベース

### 3.1 参考文献

#### 書籍1

- 書籍: The Art of Readable Code (Boswell & Foucher)
- 適用方法:
  第14章「テストと読みやすさ」の原則を PR 説明に適用。
  変更の意図を明確にし、レビュアーの認知負荷を下げる。

#### 書籍2

- 書籍: Pro Git (Scott Chacon) 第6章
- 適用方法:
  GitHub/GitLab の Pull Request ワークフローのベストプラクティスを適用。
  レビュアーが確認すべき観点を PR テンプレートで構造化。

> ルール: 詳細は references/review-workflow.md を参照すること。

## 4. 実行仕様

### 4.1 思考プロセス

1. 変更内容の整理
   - git diff の確認
   - 変更されたファイルのリスト化
   - 主要な変更ポイントの抽出

2. 変更理由の明確化
   - 解決する問題の説明
   - 変更前の状態と問題点
   - 変更後の期待される状態

3. 影響範囲の分析
   - 影響を受けるドキュメントセクション
   - 関連する他のドキュメント
   - 外部リンクへの影響

4. レビュー観点の特定
   - 技術的正確性
   - 文法・スタイルの一貫性
   - リンク切れの有無
   - スクリーンショットの更新要否

5. PR テンプレートの適用
   - assets/pr-template.md の使用
   - チェックリストの埋め込み
   - 関連Issue/PRの参照追加

### 4.2 チェックリスト

- 項目: タイトルの簡潔性
  - 基準: 変更内容が一目で理解できる（60文字以内推奨）
- 項目: 変更理由の明確性
  - 基準: Why を説明し、What だけでない
- 項目: 影響範囲の網羅性
  - 基準: 変更の波及効果をすべて列挙
- 項目: チェックリストの完全性
  - 基準: すべての項目にチェック済み
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: タイトル、変更内容、変更理由、影響範囲、チェックリスト
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な影響には「可能性がある」等の限定詞を使用

### 4.3 ビジネスルール（制約）

- 内容: PR は1つの論理的な変更に限定（複数の独立した変更は分割）
- 内容: Draft PR の活用（WIP の場合は明示）
- 内容: セルフレビューを実施してから提出

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: ブランチ情報
- 提供元: Branch Strategy Planning Task
- 検証ルール:
  ブランチ名とベースブランチの組み合わせ
- 拒否すべき入力:
  存在しないブランチ名
- 欠損時処理:
  現在のブランチを使用（git branch --show-current）

#### 入力2

- データ名: コミット履歴
- 提供元: Commit Message Crafting Task
- 検証ルール:
  1つ以上のコミットが存在する
- 拒否すべき入力:
  空のコミット履歴
- 欠損時処理:
  PR 作成不可としてエラー報告

#### 入力3

- データ名: Changelog（任意）
- 提供元: Changelog Generation Task
- 検証ルール:
  Markdown 形式の変更履歴
- 拒否すべき入力:
  不正な Markdown 形式
- 欠損時処理:
  コミットメッセージから変更内容を抽出

### 5.2 出力

#### 成果物1

- 成果物名: Pull Request 説明文
- 受領先: 外部（GitHub/GitLab PR 作成画面）
- 出力テンプレート:

  ```markdown
  ## 変更内容

  {{summary}}

  ## 変更理由

  {{rationale}}

  ## 影響範囲

  - {{affected-area-1}}
  - {{affected-area-2}}

  ## レビュー観点

  - [ ] {{review-point-1}}
  - [ ] {{review-point-2}}

  ## チェックリスト

  - [ ] 技術的正確性を確認した
  - [ ] 文法・スタイルの一貫性を確認した
  - [ ] リンク切れがないことを確認した
  - [ ] 必要なスクリーンショットを更新した

  ## 関連

  Closes #{{issue-number}}
  ```

- 内容:
  assets/pr-template.md に基づいた PR 説明文

#### 成果物2

- 成果物名: レビュアー推奨リスト（任意）
- 受領先: 外部（PR 作成者）
- 出力テンプレート:
  ```
  推奨レビュアー:
  - @{{reviewer-1}} ({{reason-1}})
  - @{{reviewer-2}} ({{reason-2}})
  ```
- 内容:
  変更内容に応じた適切なレビュアーの推奨リスト
