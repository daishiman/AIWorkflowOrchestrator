## SMART要件基準

要件は以下のSMART基準を満たす必要がある：

| 基準       | 説明                         | チェックポイント                   |
| ---------- | ---------------------------- | ---------------------------------- |
| Specific   | 具体的で曖昧さがない         | 「何を」「誰が」「どこで」が明確   |
| Measurable | 測定可能で検証できる         | 数値目標、成功条件が定義されている |
| Achievable | 技術的・リソース的に実現可能 | 制約内で達成可能                   |
| Relevant   | ビジネスゴールと関連している | 上位目標へのトレーサビリティがある |
| Traceable  | 設計・実装・テストに追跡可能 | 一意のIDが付与されている           |

## 品質属性チェックリスト

### 1. 完全性（Completeness）

| チェック項目                   | 基準                                   |
| ------------------------------ | -------------------------------------- |
| 全ステークホルダーの要件が反映 | ステークホルダー表の全員から入力がある |
| 全機能要件に受入基準がある     | FR-XXXすべてにGiven-When-Thenが定義    |
| 全非機能要件に測定指標がある   | NFR-XXXすべてに数値目標が設定          |
| 全要件に優先度がある           | MoSCoW優先度が100%付与されている       |
| 必須セクションが揃っている     | IEEE 830の必須セクションがすべて存在   |

### 2. 一貫性（Consistency）

| チェック項目         | 基準                             |
| -------------------- | -------------------------------- |
| 用語の統一           | 同一概念に同一用語を使用         |
| ID体系の一貫性       | 命名規則に従ったID付与           |
| 形式の統一           | 全要件が同一フォーマットで記述   |
| 相互参照の整合性     | 参照先が実在し、内容が矛盾しない |
| バージョン番号の一致 | ヘッダーと履歴の整合             |

### 3. 検証可能性（Verifiability）

| チェック項目     | 基準                               |
| ---------------- | ---------------------------------- |
| 曖昧な表現の排除 | 「適切に」「速く」等の曖昧語がない |
| テスト可能な記述 | 自動/手動テストで検証可能          |
| 測定可能な数値   | 具体的な閾値が設定されている       |
| 再現可能な条件   | 前提条件が明確で再現可能           |

### 4. 追跡可能性（Traceability）

| チェック項目       | 基準                           |
| ------------------ | ------------------------------ |
| 前方追跡           | 要件→設計→実装の紐付けが可能   |
| 後方追跡           | テスト→実装→要件の紐付けが可能 |
| 上位目標への紐付け | ビジネスゴールとの関連が明確   |
| 変更影響の追跡     | 変更時の影響範囲が特定可能     |

## 品質スコアリング

### スコア計算方法

```
総合スコア = (完全性 × 0.3) + (一貫性 × 0.25) + (検証可能性 × 0.25) + (追跡可能性 × 0.2)
```

### 評価基準

| スコア | 評価 | 判定                     |
| ------ | ---- | ------------------------ |
| 90-100 | A    | 優秀：軽微な修正のみ     |
| 80-89  | B    | 良好：レビュー後承認可   |
| 70-79  | C    | 要改善：修正後再レビュー |
| 60-69  | D    | 不十分：大幅な修正必要   |
| 0-59   | F    | 不合格：書き直し必要     |

### 合格基準

- **最低ライン**: 総合スコア 80以上
- **各属性最低**: 個別スコア 70以上

## レビューチェックリスト

### 構造レビュー

- [ ] 必須セクションがすべて存在する
- [ ] 目次と本文の対応が正しい
- [ ] ページ番号・節番号が正確
- [ ] 参照リンクがすべて有効

### 内容レビュー

- [ ] 全要件にIDが付与されている
- [ ] 全機能要件に受入基準がある
- [ ] 全非機能要件に測定指標がある
- [ ] 用語が統一されている
- [ ] 矛盾する要件がない

### 品質レビュー

- [ ] SMART基準を満たしている
- [ ] 曖昧な表現がない
- [ ] テスト可能な形式で記述されている
- [ ] トレーサビリティが確保されている

## 一般的な品質問題と対処法

| 問題               | 原因                         | 対処法                           |
| ------------------ | ---------------------------- | -------------------------------- |
| 曖昧な要件         | 「適切に」等の主観的表現     | 具体的な数値・条件に置き換え     |
| 矛盾する要件       | 異なるステークホルダーの競合 | 優先度を決め、トレードオフを記録 |
| テスト不可能な要件 | 検証基準の欠如               | Given-When-Then形式で書き直し    |
| 過剰な詳細         | 実装詳細の混入               | What（何を）に集中、Howは削除    |
| 不足する要件       | ステークホルダー漏れ         | ステークホルダー分析を再実施     |

## 禁止表現リスト

以下の表現は曖昧であり、使用を禁止する：

| 禁止表現     | 理由         | 代替表現の例                    |
| ------------ | ------------ | ------------------------------- |
| 適切に       | 主観的       | 「200ms以内に」                 |
| 速く         | 測定不能     | 「95パーセンタイルで100ms未満」 |
| 使いやすい   | 主観的       | 「3クリック以内で完了」         |
| 十分な       | 曖昧         | 「10GB以上」                    |
| 必要に応じて | 条件不明     | 「〜の場合に」                  |
| など         | 範囲不明確   | 具体的に列挙                    |
| 適宜         | 判断基準不明 | 明確な条件を記述                |
