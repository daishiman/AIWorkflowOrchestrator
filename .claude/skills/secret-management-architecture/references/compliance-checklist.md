# コンプライアンスチェックリスト

> **責務**: セキュリティ・コンプライアンス要件の検証
> **対象Task**: validate-architecture

---

## 1. 一般セキュリティ要件

### 1.1 暗号化

| 項目             | 要件                | 検証方法               |
| ---------------- | ------------------- | ---------------------- |
| 保存時暗号化     | AES-256以上         | 設定確認               |
| 転送時暗号化     | TLS 1.2以上         | SSL Labs テスト        |
| 鍵管理           | HSM/KMS使用         | アーキテクチャレビュー |
| 鍵ローテーション | 定期的（年1回以上） | ローテーション計画確認 |

### 1.2 アクセス制御

| 項目           | 要件                     | 検証方法           |
| -------------- | ------------------------ | ------------------ |
| 最小権限の原則 | 必要最小限の権限のみ付与 | RBAC設定レビュー   |
| 職務分離       | 管理者権限の分離         | ロール定義レビュー |
| 多要素認証     | 管理者アクセスにMFA必須  | 認証設定確認       |
| セッション管理 | タイムアウト設定         | 設定確認           |

### 1.3 監査

| 項目           | 要件                   | 検証方法             |
| -------------- | ---------------------- | -------------------- |
| アクセスログ   | すべてのアクセスを記録 | ログ設定確認         |
| 変更履歴       | すべての変更を記録     | 監査ログレビュー     |
| ログ保持       | 1年以上保持            | ログ保持ポリシー確認 |
| ログ改ざん防止 | 不変ストレージ使用     | ストレージ設定確認   |

## 3. 検証チェックリスト

### 3.1 設計フェーズ

- [ ] シークレット分類が完了しているか
- [ ] 各分類に適切な保護レベルが定義されているか
- [ ] アクセス制御マトリクスが作成されているか
- [ ] ローテーション計画が策定されているか
- [ ] 災害復旧計画が策定されているか
- [ ] 監査要件が定義されているか

### 3.2 実装フェーズ

- [ ] シークレットがハードコードされていないか
- [ ] 暗号化が適切に実装されているか
- [ ] アクセス制御が実装されているか
- [ ] 監査ログが設定されているか
- [ ] アラートが設定されているか

### 3.3 運用フェーズ

- [ ] ローテーションが計画通り実行されているか
- [ ] 監査ログが定期的にレビューされているか
- [ ] アクセス権限が定期的に見直されているか
- [ ] バックアップが正常に取得されているか
- [ ] インシデント対応手順が整備されているか

## 4. 脅威モデル（STRIDE）

### 4.1 脅威カテゴリ

| 脅威                   | 説明         | 緩和策                 |
| ---------------------- | ------------ | ---------------------- |
| Spoofing               | なりすまし   | 強力な認証、MFA        |
| Tampering              | 改ざん       | 暗号化、完全性チェック |
| Repudiation            | 否認         | 監査ログ、署名         |
| Information Disclosure | 情報漏洩     | 暗号化、アクセス制御   |
| Denial of Service      | サービス拒否 | レート制限、冗長性     |
| Elevation of Privilege | 権限昇格     | 最小権限、RBAC         |

### 4.2 シークレット管理固有の脅威

| 脅威               | リスク   | 緩和策                     |
| ------------------ | -------- | -------------------------- |
| シークレット漏洩   | Critical | 暗号化、アクセス制御、監視 |
| 不正アクセス       | High     | 認証強化、監査、アラート   |
| ローテーション失敗 | Medium   | 自動化、監視、ロールバック |
| バックエンド障害   | High     | 冗長性、フェイルオーバー   |
| 監査ログ改ざん     | High     | 不変ストレージ、分離       |
