## 2. 統合パターン

### 2.1 Sidecarパターン（推奨）

```
┌────────────────────────────────────┐
│              Pod                    │
│  ┌──────────┐    ┌──────────────┐  │
│  │   App    │←───│   Sidecar    │  │
│  │Container │    │ (Vault Agent)│  │
│  └──────────┘    └──────────────┘  │
│        ↑               ↓            │
│    Shared Volume   Vault API        │
└────────────────────────────────────┘
```

| 観点       | 内容                                   |
| ---------- | -------------------------------------- |
| メリット   | アプリ変更不要、自動更新、トークン管理 |
| デメリット | リソースオーバーヘッド                 |
| 推奨ケース | Kubernetes環境、Vault使用時            |

### 2.2 Init Containerパターン

```
┌────────────────────────────────────┐
│              Pod                    │
│  ┌──────────┐    ┌──────────────┐  │
│  │   Init   │───→│     App      │  │
│  │Container │    │  Container   │  │
│  └──────────┘    └──────────────┘  │
│        ↓               ↑            │
│    Vault API      Shared Volume     │
└────────────────────────────────────┘
```

| 観点       | 内容                         |
| ---------- | ---------------------------- |
| メリット   | シンプル、リソース効率       |
| デメリット | 起動時のみ取得、動的更新不可 |
| 推奨ケース | 短命コンテナ、バッチ処理     |

### 2.3 SDK直接統合パターン

```
┌──────────────────────────────────┐
│           Application            │
│  ┌────────────────────────────┐  │
│  │    Secret Provider SDK     │  │
│  │  ┌──────────────────────┐  │  │
│  │  │   Vault/KMS Client   │  │  │
│  │  └──────────────────────┘  │  │
│  └────────────────────────────┘  │
│              ↓                    │
│        Vault/KMS API              │
└──────────────────────────────────┘
```

| 観点       | 内容                               |
| ---------- | ---------------------------------- |
| メリット   | 細かい制御、オンデマンド取得       |
| デメリット | コード変更必要、依存関係増加       |
| 推奨ケース | 非Kubernetes環境、高度な制御が必要 |

## 3. キャッシュ戦略

### 3.1 キャッシュレイヤー設計

```
┌─────────────────────────────────────┐
│           Application               │
│      ↓                              │
│  ┌─────────────────────────────┐    │
│  │      In-Memory Cache        │    │
│  │  TTL: 5min, Max: 1000 items │    │
│  └─────────────────────────────┘    │
│      ↓ (cache miss)                 │
│  ┌─────────────────────────────┐    │
│  │     Secret Backend          │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

### 3.2 キャッシュ設定ガイドライン

| 分類     | TTL     | メモリ保持 | 更新戦略           |
| -------- | ------- | ---------- | ------------------ |
| Critical | 1-5分   | 暗号化必須 | プッシュ更新       |
| High     | 5-15分  | 暗号化推奨 | TTL + イベント通知 |
| Medium   | 15-30分 | 平文可     | TTLベース          |
| Low      | 30-60分 | 平文可     | TTLベース          |

## 4. 高可用性設計

### 4.1 マルチリージョン構成

```
┌─────────────────┐    ┌─────────────────┐
│   Region A      │    │   Region B      │
│  ┌───────────┐  │    │  ┌───────────┐  │
│  │   Vault   │←─┼────┼──│   Vault   │  │
│  │  Primary  │  │    │  │  Standby  │  │
│  └───────────┘  │    │  └───────────┘  │
└─────────────────┘    └─────────────────┘
        ↑                      ↑
    Active                 Passive
```

### 4.2 フェイルオーバー戦略

| 戦略           | 説明                         | RTO    |
| -------------- | ---------------------------- | ------ |
| Active-Standby | 手動フェイルオーバー         | 5-15分 |
| Active-Active  | 自動フェイルオーバー         | 1-5分  |
| Multi-Primary  | 各リージョン独立、同期レプリ | 0分    |

## 5. 監視設計

### 5.1 監視メトリクス

| メトリクス           | 説明                         | アラート閾値 |
| -------------------- | ---------------------------- | ------------ |
| secret_access_count  | シークレットアクセス回数     | 異常増加時   |
| secret_access_errors | アクセスエラー数             | > 0          |
| secret_rotation_age  | 最終ローテーションからの日数 | > 閾値       |
| cache_hit_ratio      | キャッシュヒット率           | < 80%        |
| backend_latency_ms   | バックエンド応答時間         | > 100ms      |

### 5.2 監査ログ要件

| イベント          | ログ内容                       |
| ----------------- | ------------------------------ |
| Secret Read       | who, what, when, from_where    |
| Secret Write      | who, what, when, change_detail |
| Secret Delete     | who, what, when, reason        |
| Access Denied     | who, what, when, reason        |
| Rotation Started  | secret_id, initiated_by        |
| Rotation Complete | secret_id, success/failure     |
