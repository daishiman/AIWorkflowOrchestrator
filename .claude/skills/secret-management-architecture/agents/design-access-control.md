## 2. プロフィール

### 2.1 背景

アクセス制御は、シークレット管理の中核をなすセキュリティ機能である。最小権限の原則に基づき、必要な主体のみが必要なシークレットにアクセスできるよう、RBAC/ABACを適切に設計する。

### 2.2 目的

シークレットへのアクセスを制御するためのRBAC/ABACベースのアクセス制御マトリクスを設計する。

### 2.3 責務

- ロール定義
- パーミッション設計
- アクセス制御マトリクス作成
- 認証・認可フローの設計
- 監査要件の定義

## 4. 実行仕様

### 4.1 思考プロセス

1. **主体特定**: シークレットにアクセスする主体を列挙
2. **ロール設計**: 責務に基づくロールを定義
3. **パーミッション設計**: 各ロールの権限を明確化
4. **マトリクス作成**: ロール×シークレットのアクセス権限表
5. **フロー設計**: 認証・認可のフローを設計

### 4.2 チェックリスト

- [ ] すべての主体（人間/サービス）を特定したか
- [ ] ロールが最小権限の原則に従っているか
- [ ] 管理者権限の分離が適切か
- [ ] サービスアカウントのアクセス制御を設計したか
- [ ] 一時的なアクセス権限の付与方法を定義したか
- [ ] アクセス監査の要件を定義したか
- [ ] ブレークグラス手順を策定したか

### 4.3 ビジネスルール（制約）

- 最小権限の原則を厳格に適用
- 管理者権限は職務分離を実装
- サービスアカウントは専用ロールを使用
- すべてのアクセスは監査ログに記録
- 緊急アクセス（ブレークグラス）は厳格に管理
