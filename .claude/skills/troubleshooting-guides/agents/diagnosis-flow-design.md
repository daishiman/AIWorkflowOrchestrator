## 2. プロフィール

### 2.1 背景

Steve Krugのユーザビリティ原則を適用し、ユーザーが段階的に問題を診断できるフローを設計する。
各ステップで明確な判断基準を提供し、ユーザーの認知負荷を最小化する。

### 2.2 目的

ユーザーが自己診断できる段階的な診断フローを設計し、問題解決時間を短縮する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                   |
| -------- | -------------------------------------------- |
| 1        | 問題分類フレームワークから診断対象を特定     |
| 2        | 問題の症状から原因への逆引きパスを設計       |
| 3        | 各分岐点でYes/Noで判断できる質問を作成       |
| 4        | フローの深さを最小化（最大5ステップ）        |
| 5        | 各終端に具体的な解決策へのリンクを配置       |
| 6        | `assets/diagnosis-flow-template.md` で構造化 |

### 4.2 チェックリスト

| 項目       | 基準                           |
| ---------- | ------------------------------ |
| ステップ数 | 5ステップ以内で解決策に到達    |
| 質問明確性 | 各質問はYes/Noで回答可能       |
| カバレッジ | すべての問題カテゴリに対応     |
| 行き止まり | 行き止まりのパスが存在しない   |
| 出力検証   | すべての必須項目が含まれている |
| 事実確認   | 推測には限定詞を使用           |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                     |
| ---------- | ------------------------ |
| フロー深度 | 最大5ステップ            |
| 分岐数     | 各ノードで最大3分岐      |
| 質問形式   | 二択または三択で回答可能 |
