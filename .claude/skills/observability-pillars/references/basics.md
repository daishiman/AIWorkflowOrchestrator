## 三本柱とは

オブザーバビリティの三本柱（Three Pillars of Observability）は、システムの内部状態を外部から理解するための3つの主要なデータ型。

| 柱      | 英語       | 定義                           | 特徴                       |
| ------- | ---------- | ------------------------------ | -------------------------- |
| Logs    | ログ       | 離散的なイベントのテキスト記録 | 高カーディナリティ、詳細   |
| Metrics | メトリクス | 時系列の数値データ             | 集約、低コスト、長期保持   |
| Traces  | トレース   | リクエストの分散システム経路   | 因果関係、ボトルネック特定 |

---

## 各柱の役割

### Logs（ログ）

**目的**: イベントの詳細記録

**強み**:

- 任意のコンテキスト情報を含められる（高カーディナリティ）
- デバッグに必要な詳細情報を提供
- 構造化（JSON）により検索・集計が容易

**弱み**:

- ストレージコストが高い
- 大量データの検索が遅い
- 集約が難しい

**ユースケース**:

- エラーの詳細調査
- ユーザー行動のトレース
- 監査ログ

### Metrics（メトリクス）

**目的**: システム状態の数値監視

**強み**:

- ストレージ効率が高い
- リアルタイム集計が容易
- 長期保持に適している
- アラート設定が容易

**弱み**:

- 詳細コンテキストを含められない
- 高カーディナリティはコスト増大
- 事後の原因調査には不向き

**ユースケース**:

- SLI/SLO監視
- リソース使用率監視
- アラート

### Traces（トレース）

**目的**: リクエストフローの可視化

**強み**:

- 分散システム全体のフローを把握
- ボトルネックの特定
- サービス間依存関係の可視化

**弱み**:

- サンプリングが必要（全リクエストは非現実的）
- 実装コストが高い
- ストレージコストが高い

**ユースケース**:

- パフォーマンス問題の調査
- マイクロサービス間の依存関係分析
- エラー伝播の追跡

## 相関ID（Correlation ID）

三本柱を連携させるための統一識別子。

### 種類

| ID Type    | スコープ           | 生成タイミング     |
| ---------- | ------------------ | ------------------ |
| Request ID | 単一HTTPリクエスト | リクエスト受信時   |
| Trace ID   | 分散システム全体   | エントリーポイント |
| Span ID    | 単一操作           | 各スパン開始時     |

### 統合の利点

```
[メトリクス] Error Rate 急上昇を検知
     ↓ 時間範囲でフィルタ
[ログ] ERRORレベルのログを検索、trace_idを取得
     ↓ trace_idでリンク
[トレース] リクエストフロー全体を可視化、ボトルネック特定
```

---

## コンテキスト伝播

### 同期処理

HTTPヘッダーで伝播：

```
X-Request-ID: <uuid>
traceparent: 00-<trace_id>-<span_id>-<flags>
```

### 非同期処理

- Node.js: `AsyncLocalStorage`
- メッセージキュー: メッセージヘッダー
