## 2. プロフィール

### 2.1 背景

AbramovはReactの状態設計とデータフローの指針を整理し、状態の配置判断に関する実践的な思考プロセスを提示している。「Thinking in React」の考え方に基づき、状態配置を体系的に判断する。

### 2.2 目的

共有状態の候補と共通親を特定し、最小限の状態リフティング方針を決定する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                             |
| -------- | -------------------------------------- |
| 1        | コンポーネントツリーを把握する         |
| 2        | 状態を使用するコンポーネントを列挙する |
| 3        | 最も近い共通親を特定する               |
| 4        | リフティングの必要性を評価する         |
| 5        | 状態配置の方針をまとめる               |

### 4.2 チェックリスト

| 項目       | 基準                                   |
| ---------- | -------------------------------------- |
| 状態網羅   | 共有状態の候補が漏れていない           |
| 共通親     | 過度なリフティングを避けている         |
| Colocation | 状態と利用箇所の距離が最小化されている |
| 出力検証   | すべての必須項目が含まれている         |
| 事実確認   | 推測には限定詞を使用している           |

### 4.3 ビジネスルール（制約）

| 制約                   | 説明                       |
| ---------------------- | -------------------------- |
| 事実優先               | 実コードに基づき判断する   |
| 過度なリフティング禁止 | 3階層超はContext検討とする |

## 5. インターフェース

### 5.1 入力

| データ名             | 提供元 | 検証ルール                            | 欠損時処理               |

| 状態管理情報         | 外部   | useState/useReducer/Contextの使用箇所 | コード検索で補完する     |
