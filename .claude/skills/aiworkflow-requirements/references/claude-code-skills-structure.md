# Skill 構造・フォーマット

> 本ドキュメントは統合システム設計仕様書の一部です。
> 管理: .claude/skills/aiworkflow-requirements/
>
> **重要**: 本仕様は Anthropic公式 skill-creator を最重要資料として策定し、プロジェクト固有の拡張を追加する。

---

## Skill構造仕様

### 標準フォルダ構造（改訂：agents/ を追加）

```
skill-name/
├── SKILL.md              # 必須: 中枢（500行以内推奨）
├── agents/               # 推奨: Task仕様書（実行直前にロードされる前提で軽量に）
│   ├── task-1.md
│   └── task-n.md
├── scripts/              # 任意: 実行可能コード（Python/Bash/Node等）
│   └── log_usage.mjs     # 推奨: フィードバックループ用標準スクリプト
├── references/           # 任意: 必要時に読む参照資料（知識の外部化）
└── assets/               # 任意: 出力で使用する素材（テンプレ/雛形等）
```

**重要**: 以下のファイルは作成しない（SkillはAI実行のための情報のみ）

- README.md
- INSTALLATION_GUIDE.md
- QUICK_REFERENCE.md
- その他の補助ドキュメント

### agents/ の位置づけ（誤解防止）

- `skills/.../agents/*.md` は **「サブエージェント（永続人格）の定義」ではない**
- ここに書くのは **Taskの仕様書**（役割・入力・出力・制約・参照先）
- **実行直前に、そのTask分だけまとめて読まれる前提**
  → だから _軽量に_、知識は `references/` に逃がす

## SKILL.md 仕様

### YAML Frontmatter

**公式フィールド（Anthropic準拠）**:

| フィールド      | 型       | 必須 | 説明                                       |
| --------------- | -------- | ---- | ------------------------------------------ |
| `name`          | string   | 必須 | スキル識別子（ハイフンケース、最大64文字） |
| `description`   | string   | 必須 | スキル説明と発動条件（最大1024文字）       |
| `license`       | string   | 任意 | ライセンス情報                             |
| `allowed-tools` | string[] | 任意 | 許可ツール                                 |
| `metadata`      | object   | 任意 | 追加メタ                                   |

**プロジェクト拡張フィールド（改訂）**:

| フィールド     | 型       | 必須 | 説明                                                |
| -------------- | -------- | ---- | --------------------------------------------------- |
| `tags`         | string[] | 任意 | 検索用タグ                                          |
| `dependencies` | string[] | 任意 | 依存スキルのパス（※参照のみ。自動実行を意味しない） |

> **削除**: `references:` フィールド（書籍等の構造化リスト）は本プロジェクトでは採用しない。
> 理由：description 内にアンカーとして統合し、トリガー性能（発見性）を優先するため。

### name フィールドの規則

| 規則                     | 説明                         |
| ------------------------ | ---------------------------- |
| ハイフンケース           | 小文字、数字、ハイフンのみ   |
| 最大64文字               | 長すぎる名前は不可           |
| 先頭・末尾にハイフン不可 | `my-skill` ○、`-my-skill-` × |
| 連続ハイフン不可         | `my-skill` ○、`my--skill` ×  |
| ディレクトリ名と一致     | フォルダ名と完全一致         |

### description フィールド（最重要：トリガー設計）

**descriptionはスキルの主要なトリガーメカニズム。**
Skillは段階的ロードされるため、発見フェーズでは本文より description が効く。

| 規則                          | 説明                                                                 |
| ----------------------------- | -------------------------------------------------------------------- |
| 最大1024文字                  | 簡潔かつ包括的に                                                     |
| 角括弧禁止                    | `<` `>` は使用不可                                                   |
| 「何を」と「いつ」を含める    | 機能＋発動条件を必ず書く                                             |
| 本文に When to Use 不要       | 発動条件は description に集約                                        |
| アンカーは description に統合 | ドキュメント/リファレンス/スイーズ情報は **Markdown禁止で** 埋め込む |

**description 記述形式（Markdown禁止版）**
※ `-` や `*` による箇条書きは使わない。行区切りで表現する。

```yaml
description: |
  {{スキルの概要（2〜3行）}}

  Anchors:
  • {{アンカー名}} / 適用: {{適用範囲}} / 目的: {{目的}}
  • {{アンカー名}} / 適用: {{適用範囲}} / 目的: {{目的}}

  Trigger:
  Use when {{英語での発動条件（短く、具体例語彙を含める）}}.
```

> Anchors には「書籍」「社内ルール」「スキーマ」「Runbook」「API仕様」「設計方針」などを混在させてよい。
> ただし **“適用範囲” と “目的” を必ず添える**。

### 本文（Markdown Body）

Frontmatter の後に続く指示とガイダンス。スキル発動後にのみ読まれる。

**推奨セクション構造**:

| セクション              | 必須 | 説明                                         |
| ----------------------- | ---- | -------------------------------------------- |
| 概要                    | 必須 | 1-2文で目的                                  |
| ワークフロー            | 推奨 | Phase ベースの流れ（Task分割の案内を含める） |
| Task仕様（ナビ）        | 必須 | agents/ の各Taskをいつ呼ぶか、入出力は何か   |
| ベストプラクティス      | 必須 | すべきこと/避けるべきこと                    |
| リソース/スクリプト参照 | 推奨 | references/ scripts/ assets/ への導線        |

**行数制約**: 500行以内。超過時は references/ に分離。

## agents/ ディレクトリ仕様（Task仕様書）

### 目的

- Taskを「一時的ワーカー」として起動するときの **仕様書**
- Task内の試行錯誤ログをメインへ持ち込まない前提で、**入出力と制約**に集中させる

### agents/\*.md 標準フォーマット（必須テンプレ）

`skills/<skill-name>/agents/*.md` は **Task仕様書**であり、各Taskを「一時的ワーカー」として起動する際の **役割・判断基準・入出力契約**を定義する。

- **実在する専門家名**は「思考様式・判断軸の参照ラベル」として扱う
  - 本人を名乗る／本人の発言を捏造する／個人情報を扱う、はしない
  - 参照するのは **フレームワーク・方法論・思考の型**のみ

- agents/\*.md は **実行直前に一括ロード**される前提のため、過度に長文化しない
  - 長い知識本文・サンプル・詳細手順は `references/` に外部化し、ここは「参照先」と「適用方法（短文）」に留める

---

## scripts/ ディレクトリ仕様（維持）

（※あなたの原文を基本維持。冪等性・終了コード・ヘルプ等は量産に必須なので残しています）

### 使用場面

| 場面                         | 説明                   |
| ---------------------------- | ---------------------- |
| 同じコードを繰り返し書き直す | スクリプト化して再利用 |
| 決定論的な信頼性が必要       | AIの不確実性を排除     |
| 複雑な処理の確実な実行       | 冪等性を保証           |

### スクリプト実装要件

| 要件       | 説明                   |
| ---------- | ---------------------- |
| 冪等性     | 何度実行しても同じ結果 |
| エラー出力 | stderr に詳細を出す    |
| 引数検証   | 必須引数を確認         |
| ヘルプ     | `-h`/`--help`          |
| 終了コード | 成功0、一般1、引数2…   |

### 終了コード規則

| 終了コード | 意味           |
| ---------- | -------------- |
| 0          | 成功           |
| 1          | 一般的エラー   |
| 2          | 引数エラー     |
| 3          | ファイル不在   |
| 4          | 検証失敗       |
| 5          | 依存関係エラー |

### 標準スクリプト: log_usage.mjs

フィードバックループの核。詳細は 7章参照。

## references/ ディレクトリ仕様（維持＋補強）

### 役割（定義の明確化）

- references/ は **知識の外部ストレージ**
- SKILL.md や agents/\*.md を軽量に保つための逃がし先
- 「毎回読む前提」ではなく **必要時にだけ読む** ことを前提に設計

### 使用場面（原文維持）

| 場面                 | パス形式                                 |
| -------------------- | ---------------------------------------- |
| データベーススキーマ | `references/{{schema-name}}.md`          |
| APIドキュメント      | `references/{{api-name}}.md`             |
| ドメイン知識         | `references/{{domain-name}}.md`          |
| ポリシー・ルール     | `references/{{policy-name}}.md`          |
| ワークフローガイド   | `references/{{workflow-name}}.md`        |
| 出力パターン         | `references/{{output-type}}-patterns.md` |

### ベストプラクティス（原文維持）

| プラクティス             | 説明                                      |
| ------------------------ | ----------------------------------------- |
| SKILL.md を軽量に保つ    | 詳細は references/                        |
| 重複を避ける             | 情報は SKILL.md か references/ のどちらか |
| 大きなファイル（>10k語） | SKILL.md に検索パターンを含める           |
| 100行超のファイル        | 先頭に目次                                |

#### Progressive Disclosure パターン

**パターン1: 高レベルガイドと参照**

```markdown
# {{スキル名}}

## Quick start

{{基本的な使用方法}}

## Advanced features

- **{{機能1}}**: See [references/{{feature-1}}.md](references/{{feature-1}}.md)
- **{{機能2}}**: See [references/{{feature-2}}.md](references/{{feature-2}}.md)
- **{{機能N}}**: See [references/{{feature-n}}.md](references/{{feature-n}}.md)
```

**パターン2: ドメイン別構成**

```
{{skill-name}}/
├── SKILL.md (概要とナビゲーション)
└── references/
    ├── {{domain-1}}.md ({{ドメイン1の説明}})
    ├── {{domain-2}}.md ({{ドメイン2の説明}})
    └── {{domain-n}}.md ({{ドメインNの説明}})
```

**パターン3: バリアント別構成**

```
{{skill-name}}/
├── SKILL.md (ワークフロー + バリアント選択)
└── references/
    ├── {{variant-1}}.md ({{バリアント1パターン}})
    ├── {{variant-2}}.md ({{バリアント2パターン}})
    └── {{variant-n}}.md ({{バリアントNパターン}})
```

**重要なガイドライン**:

- 深くネストした参照を避ける（SKILL.md から1レベルに保つ）
- すべての参照ファイルは SKILL.md から直接リンク（相対パス使用）

### assets/ ディレクトリ仕様

コンテキストに読み込むためではなく、Claude が生成する出力で使用するファイル。

#### 使用場面

| 場面             | パス形式                           |
| ---------------- | ---------------------------------- |
| テンプレート     | `assets/{{template-name}}.{{ext}}` |
| 画像・アイコン   | `assets/{{image-name}}.{{ext}}`    |
| ボイラープレート | `assets/{{boilerplate-name}}/`     |
| フォント         | `assets/{{font-name}}.{{ext}}`     |
| サンプルデータ   | `assets/{{data-name}}.{{ext}}`     |

#### 利点

- 出力リソースをドキュメントから分離
- コンテキストに読み込まずにファイルを使用可能

## ワークフローパターン

### シーケンシャルワークフロー

複雑なタスクでは、操作を明確な順序のステップに分解。SKILL.md の冒頭でプロセスの概要を示す：

```markdown
{{タスク名}}は以下のステップで行う：

1. {{ステップ1の説明}}（run scripts/{{script-1}}.mjs）
2. {{ステップ2の説明}}（edit {{config-file}}.json）
3. {{ステップ3の説明}}（run scripts/{{script-2}}.mjs）
4. {{ステップNの説明}}（run scripts/{{script-n}}.mjs）
```

### 条件分岐ワークフロー

分岐ロジックを持つタスクでは、Claude を判断ポイントに導く：

```markdown
1. {{判断ポイント}}を判断する：
   **{{条件A}}？** → 「{{ワークフローA}}」に従う
   **{{条件B}}？** → 「{{ワークフローB}}」に従う

2. {{ワークフローA}}: See [references/{{workflow-a}}.md](references/{{workflow-a}}.md)
3. {{ワークフローB}}: See [references/{{workflow-b}}.md](references/{{workflow-b}}.md)
```

## 出力パターン

### テンプレートパターン

出力形式のテンプレートを提供。厳格さのレベルを要件に合わせる。

**厳格な要件の場合（APIレスポンスやデータ形式）**:

```markdown
## {{出力タイプ}}構造

必ず以下の正確なテンプレート構造を使用する：

# {{タイトル変数}}

## {{セクション1名}}

{{セクション1の内容説明}}

## {{セクション2名}}

- {{項目1}}（{{補足情報}}）
- {{項目N}}（{{補足情報}}）

## {{セクション3名}}

1. {{アクション項目1}}
2. {{アクション項目N}}
```

**柔軟なガイダンスの場合（適応が有用な場合）**:

```markdown
## {{出力タイプ}}構造

以下は妥当なデフォルト形式。最善の判断で使用する：

# {{タイトル変数}}

## {{セクション1名}}

## {{セクション2名}}

{{コンテキストに応じた適応指示}}

## {{セクション3名}}

{{調整の指針}}

{{全体的な適応ガイドライン}}
```

### 例示パターン

出力品質が例を見ることに依存する場合、入力/出力のペアを提供：

```markdown
## {{出力形式名}}

以下のパターンに従って{{出力物}}を生成する：

**パターン:**
入力: {{入力の説明}}
出力:
{{出力フォーマット}}

**形式ルール:**

- {{ルール1}}
- {{ルール2}}
- {{ルールN}}
```

**注意**: 具体的な例示は AI の出力を例に引っ張る傾向があるため、パターンと形式ルールで表現する。
