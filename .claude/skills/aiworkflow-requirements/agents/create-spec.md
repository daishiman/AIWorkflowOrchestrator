# 新規仕様作成ワークフロー

> 仕様: 新規仕様ファイルの作成手順

## 概要

references/に新しい仕様ファイルを追加するための標準ワークフロー。

## 前提条件

- 追加する仕様の目的とスコープが明確
- 既存仕様との重複がないこと

## 手順

### Step 1: 重複チェック

```bash
# 関連キーワードで既存仕様を検索
node scripts/search-spec.mjs "追加したい機能のキーワード"

# トピック一覧で類似仕様を確認
node scripts/list-specs.mjs --topics
```

### Step 2: ファイル命名

**命名規則**: `{prefix}-{topic}.md`

| ルール     | 説明                               | 例                                   |
| ---------- | ---------------------------------- | ------------------------------------ |
| kebab-case | 小文字・ハイフン区切り             | `api-endpoints.md`                   |
| prefix付き | カテゴリを示すprefix               | `architecture-`, `api-`, `security-` |
| 番号なし   | ファイル追加時にリネンバリング不要 | ✅ `api-auth.md` ❌ `08-api-auth.md` |

**prefix一覧**:

| prefix          | 用途                     |
| --------------- | ------------------------ |
| `architecture-` | アーキテクチャ・設計     |
| `interfaces-`   | 型定義・インターフェース |
| `api-`          | API設計・エンドポイント  |
| `database-`     | データベース・スキーマ   |
| `ui-ux-`        | UI/UXデザイン            |
| `security-`     | セキュリティ             |
| `technology-`   | 技術スタック             |
| `claude-code-`  | Claude Code関連          |
| (なし)          | 単独トピック             |

### Step 3: ファイル作成

```bash
# テンプレートをコピー
cp assets/spec-template.md references/{prefix}-{topic}.md
```

### Step 4: 内容記入

テンプレートの各セクションを埋める:

1. **概要** - 目的とスコープ
2. **要件** - 機能要件と非機能要件
3. **設計** - アーキテクチャとデータ構造
4. **実装ガイドライン** - 規約とテスト要件
5. **関連ドキュメント** - 参照先

**記述ガイドライン**:

| するべきこと             | 避けるべきこと              |
| ------------------------ | --------------------------- |
| 文章による説明           | ソースコードの直接記述      |
| 表・箇条書きによる構造化 | 実装詳細のコード例          |
| 誰でも理解できる粒度     | 特定実装に依存した説明      |
| 設計意図・目的の明記     | 実装コードのコピー          |
| データ構造は表形式で説明 | TypeScript/JSON等のリテラル |

### Step 5: SKILL.md更新

SKILL.mdの該当トピックテーブルに新規ファイルを追加:

```markdown
## トピック別リファレンス

### {該当カテゴリ}

| ファイル           | 内容         |
| ------------------ | ------------ | ------ |
| `{新規ファイル名}` | {内容の説明} | ← 追加 |
```

**更新対象セクション**:

| prefix          | SKILL.mdセクション |
| --------------- | ------------------ |
| `architecture-` | アーキテクチャ     |
| `interfaces-`   | インターフェース   |
| `api-`          | API設計            |
| `database-`     | データベース       |
| `ui-ux-`        | UI/UX              |
| `security-`     | セキュリティ       |
| `technology-`   | 技術スタック       |
| `claude-code-`  | Claude Code        |
| (なし)          | その他             |

### Step 6: インデックス更新

```bash
# インデックスを再生成
node scripts/generate-index.mjs
```

### Step 7: 構造検証

```bash
# スキル構造の整合性を確認
node scripts/validate-structure.mjs
```

## 出力

- `references/{prefix}-{topic}.md` - 新規仕様ファイル
- `SKILL.md` - 更新されたトピックテーブル
- `indexes/topic-map.md` - 更新されたトピックマップ
- `indexes/keywords.json` - 更新されたキーワード索引

## 注意事項

- 仕様は日本語で記述
- 見出しは ## または ### を使用（インデックス生成に必要）
- 変更履歴セクションを必ず含める
- 500行を超える場合は分割を検討
- ソースコードではなく文章で記述
