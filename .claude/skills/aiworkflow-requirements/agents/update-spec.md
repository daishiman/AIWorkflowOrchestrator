# 仕様更新ワークフロー

> 仕様: 既存仕様ファイルの更新手順

## 概要

references/内の既存仕様を更新するための標準ワークフロー。

## 前提条件

- 更新対象の仕様ファイルが特定済み
- 更新内容が明確

## 手順

### Step 1: 対象ファイル特定

```bash
# キーワードで対象ファイルを検索
node scripts/search-spec.mjs "更新対象のキーワード"

# コンテキスト付きで詳細確認
node scripts/search-spec.mjs "キーワード" -C 10
```

### Step 2: 現状確認

```bash
# ファイル内容を確認
Read references/{prefix}-{topic}.md
```

### Step 3: 編集

```bash
# ファイルを直接編集
Edit references/{prefix}-{topic}.md
```

**編集時の注意**:

| するべきこと             | 避けるべきこと     |
| ------------------------ | ------------------ |
| 既存構造を維持           | 見出し形式の変更   |
| 変更履歴に更新内容を記録 | 履歴の省略         |
| 文章・表・箇条書きで記述 | ソースコードの追加 |
| 設計意図を明確に         | 実装詳細への偏り   |

**記述スタイル**:

- 文章で説明: 誰でも理解できる粒度
- 表形式: データ構造、設定項目、API仕様
- 箇条書き: 手順、チェックリスト、要件
- 避ける: TypeScript/JSON等のソースコード

### Step 4: 変更履歴更新

ファイル末尾の変更履歴テーブルに追記:

| 日付       | バージョン | 変更内容       |
| ---------- | ---------- | -------------- |
| YYYY-MM-DD | X.X.X      | 変更内容の概要 |

### Step 5: インデックス更新

```bash
# インデックスを再生成（見出し変更時のみ）
node scripts/generate-index.mjs
```

### Step 6: 検証

```bash
# 構造検証
node scripts/validate-structure.mjs

# 更新内容が検索可能か確認
node scripts/search-spec.mjs "更新したキーワード"
```

## 出力

- `references/{prefix}-{topic}.md` - 更新された仕様ファイル
- `indexes/topic-map.md` - 必要に応じて更新
- `indexes/keywords.json` - 必要に応じて更新

## 注意事項

- 破壊的変更は慎重に
- 他の仕様への影響を確認
- セマンティックバージョニングに従う
- 500行を超える場合は分割を検討
