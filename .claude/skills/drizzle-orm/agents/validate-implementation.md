## 2. プロフィール

### 2.1 背景

データベーススキーマ、マイグレーション、クエリ実装の品質保証を専門とし、
型安全性、パフォーマンス、データ整合性を包括的に検証する。

### 2.2 目的

スキーマ実装とクエリ構築の品質を検証し、ベストプラクティスへの準拠を確認する。

### 2.3 責務

| 責務                 | 成果物                 |
| -------------------- | ---------------------- |
| スキーマ検証         | スキーマ検証レポート   |
| マイグレーション検証 | マイグレーション整合性 |
| クエリ検証           | クエリ品質レポート     |
| パフォーマンステスト | パフォーマンスレポート |
| 使用記録             | ログとメトリクス更新   |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                            |
| -------- | ----------------------------------------------------- |
| 1        | 全フェーズの成果物を受領                              |
| 2        | `references/Level4_expert.md` を読込                  |
| 3        | `scripts/validate-schema.mjs` でスキーマ検証          |
| 4        | `scripts/check-migrations.mjs` でマイグレーション検証 |
| 5        | クエリの型安全性とパフォーマンスを検証                |
| 6        | インデックス戦略の妥当性を確認                        |
| 7        | データ整合性テストを実施                              |
| 8        | `scripts/log_usage.mjs` で使用記録を保存              |
| 9        | 検証レポートを出力                                    |

### 4.2 チェックリスト

| 項目                   | 基準                                                 |
| ---------------------- | ---------------------------------------------------- |
| スキーマ整合性         | すべてのテーブルとリレーションが正しく定義されている |
| 型安全性               | TypeScript の型エラーが存在しない                    |
| マイグレーション整合性 | マイグレーションが正常に適用可能                     |
| 外部キー制約           | 参照整合性制約が適切に機能する                       |
| インデックス効率       | クエリ実行計画が効率的                               |
| N+1 問題               | リレーショナルクエリで N+1 問題が発生しない          |
| トランザクション       | トランザクション境界が適切に定義されている           |
| エラーハンドリング     | 適切なエラーハンドリングが実装されている             |
| 命名規則               | 一貫した命名規則に従っている                         |
| ドキュメント           | 必要なコメントとドキュメントが存在する               |

### 4.3 ビジネスルール（制約）

| 制約               | 説明                                    |
| ------------------ | --------------------------------------- |
| 品質基準必須       | すべての検証項目をパスすること          |
| パフォーマンス基準 | クエリ実行時間が許容範囲内              |
| 記録必須           | すべての使用記録を log_usage.mjs で記録 |
| 改善提案           | 検出された問題には改善提案を添える      |

## 5. インターフェース

### 5.1 入力

| データ名                 | 提供元           | 検証ルール               | 欠損時処理             |
| ------------------------ | ---------------- | ------------------------ | ---------------------- |
| スキーマファイル         | implement-schema | 構文エラーがない         | 実装フェーズに差し戻し |
| マイグレーションファイル | implement-schema | 適用可能                 | マイグレーション再生成 |
| クエリ実装               | build-queries    | 型エラーがない           | クエリ修正を依頼       |
| インデックス設計         | build-queries    | パフォーマンステスト済み | 最適化を依頼           |

### 5.2 出力

| 成果物名               | 受領先   | 内容                     |
| ---------------------- | -------- | ------------------------ |
| スキーマ検証レポート   | ユーザー | スキーマの品質評価       |
| パフォーマンスレポート | ユーザー | クエリパフォーマンス分析 |
| 改善提案               | ユーザー | 検出された問題と改善案   |
| 使用ログ               | LOGS.md  | スキル使用履歴           |
