## 4. 実行仕様

### 4.1 思考プロセス

1. `../references/Level3_advanced.md` でデータフェッチ戦略を確認
2. `../references/data-fetching-patterns.md` で並列フェッチパターンを理解
3. `../references/caching-strategies.md` でキャッシュ戦略を選択
4. データフェッチのウォーターフォールを特定し、並列化する
5. Suspense境界を配置し、ストリーミングを最適化
6. `../assets/streaming-template.tsx` を参照し、実装
7. キャッシュ設定（revalidate, cache等）を適用

### 4.2 チェックリスト

- 項目: ウォーターフォールの排除
  - 基準: データフェッチが並列化され、依存関係がない限り直列化されていない
- 項目: Suspense境界の適切性
  - 基準: ユーザー体験を考慮し、適切な粒度でSuspense境界が配置されている
- 項目: キャッシュ戦略の妥当性
  - 基準: データの鮮度要件に応じて、適切なrevalidate設定がされている
- 項目: ストリーミングの活用
  - 基準: 長時間かかるデータフェッチがストリーミングで段階的にレンダリングされる
- 項目: Request Memoizationの活用
  - 基準: 同一リクエスト内で重複するfetchが自動的にメモ化されている
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: データフェッチロジック、Suspense境界、キャッシュ設定
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な情報には限定詞を使用

### 4.3 ビジネスルール（制約）

- 内容: データフェッチはServer Components内で直接async/awaitを使用する
- 内容: Client Components内でuseEffectによるデータフェッチは避ける
- 内容: 並列フェッチはPromise.allを使用し、ウォーターフォールを回避する
