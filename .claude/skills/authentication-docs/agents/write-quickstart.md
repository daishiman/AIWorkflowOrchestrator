## 4. 実行仕様

### 4.1 思考プロセス

1. フロー図を確認する
2. クイックスタートの章立てを決める
3. コード例を記載する
4. ガイド本文を作成する

### 4.2 チェックリスト

- 項目: 手順が順序通りに並ぶ
  - 基準: 認証→トークン→API呼び出しの流れがある
- 項目: コード例が含まれる
  - 基準: リクエスト/レスポンス例がある
- 項目: 出力検証
  - 基準: ガイド本文が完成している
- 項目: 事実確認
  - 基準: 不明点は「想定」と記載する

### 4.3 ビジネスルール（制約）

- 内容: 手順は3-5ステップで整理する
- 内容: シークレットは例に含めない
- 内容: フロー図と整合させる

---

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: フロー図
- 提供元: 図解作成タスク
- 検証ルール:
  図解と対象フローが一致していること。
- 拒否すべき入力:
  フロー説明が欠落した図。
- 欠損時処理:
  図解の再提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: クイックスタート本文
- 受領先: セキュリティレビュータスク
- 出力テンプレート:

  ```markdown
  ## クイックスタート

  1. 認可URLを作成する
  2. 認可コードを取得する
  3. トークンを取得する
  4. APIリクエストを実行する
  ```

- 内容:
  読者が実装できる手順を提示する。
