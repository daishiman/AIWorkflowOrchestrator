# Skill Structure Guide

> このガイドは docs/00-requirements/18-skills.md §3.1-3.5 の内容を抽出したものです。

## 標準フォルダ構造（§3.1）

```
skill-name/
├── SKILL.md              # 必須: メインファイル（500行以内推奨）
├── scripts/              # 任意: 実行可能コード（Python/Bash/Node.js等）
│   └── log_usage.mjs     # 推奨: フィードバックループ用標準スクリプト
├── references/           # 任意: コンテキストに読み込む参照資料
└── assets/               # 任意: 出力で使用するファイル（テンプレート等）
```

### 必須ファイル

- **SKILL.md**: スキルのメインファイル（YAML frontmatter + 本文）

### 推奨ファイル

- **scripts/log_usage.mjs**: フィードバックループ用（§7.3）

### ❌ 作成してはいけないファイル

- README.md
- INSTALLATION_GUIDE.md
- QUICK_REFERENCE.md
- その他の補助ドキュメント

**理由**: スキルはAIエージェントが作業を実行するための情報のみを含む。作成過程、セットアップ手順、ユーザー向けドキュメントは含めない。

## scripts/ ディレクトリ（§3.3）

### 用途

実行可能コード（Python/Bash/Node.js等）を格納。決定論的な信頼性が必要なタスクや繰り返し書き直されるコードに使用。

### 使用場面（§3.3.1）

| 場面                         | 説明                   |
| ---------------------------- | ---------------------- |
| 同じコードを繰り返し書き直す | スクリプト化して再利用 |
| 決定論的な信頼性が必要       | AIの不確実性を排除     |
| 複雑な処理の確実な実行       | 冪等性を保証           |

### スクリプト実装要件（§3.3.2）

| 要件       | 説明                                  |
| ---------- | ------------------------------------- |
| 冪等性     | 何度実行しても同じ結果になること      |
| エラー出力 | stderr に詳細なエラーメッセージを出力 |
| 引数検証   | 必須引数の存在を確認                  |
| ヘルプ     | `-h` または `--help` でヘルプを表示   |
| 終了コード | 成功: 0、一般エラー: 1、引数エラー: 2 |

### 終了コード規則（§3.3.3）

| 終了コード | 意味           |
| ---------- | -------------- |
| 0          | 成功           |
| 1          | 一般的なエラー |
| 2          | 引数エラー     |
| 3          | ファイル不在   |
| 4          | 検証失敗       |
| 5          | 依存関係エラー |

### 標準スクリプト: log_usage.mjs（§3.3.4）

フィードバックループの核となる標準スクリプト。詳細は18-skills.md §7を参照。

**責務**:

- 実行記録の追記（LOGS.md）
- メトリクス更新（EVALS.json）
- レベル評価（レベルアップ条件チェック）

**引数**:

- `--result` (必須): success または failure
- `--phase` (任意): 実行したフェーズ名
- `--agent` (任意): 実行したエージェント名
- `--notes` (任意): 追加のフィードバックメモ

## references/ ディレクトリ（§3.4）

### 用途

Claude の処理と思考に情報を提供するための参照資料。必要に応じてコンテキストに読み込む。

### 使用場面（§3.4.1）

| 場面                 | パス形式                                 |
| -------------------- | ---------------------------------------- |
| データベーススキーマ | `references/{{schema-name}}.md`          |
| APIドキュメント      | `references/{{api-name}}.md`             |
| ドメイン知識         | `references/{{domain-name}}.md`          |
| ポリシー・ルール     | `references/{{policy-name}}.md`          |
| ワークフローガイド   | `references/{{workflow-name}}.md`        |
| 出力パターン         | `references/{{output-type}}-patterns.md` |

### ベストプラクティス（§3.4.2）

| プラクティス             | 説明                                          |
| ------------------------ | --------------------------------------------- |
| SKILL.md を軽量に保つ    | 詳細は references/ に移動                     |
| 重複を避ける             | 情報は SKILL.md か references/ のどちらか一方 |
| 大きなファイル（>10k語） | SKILL.md に grep 検索パターンを含める         |
| 100行超のファイル        | 先頭に目次を含める                            |

### Progressive Disclosure パターン（§3.4.3）

**パターン1: 高レベルガイドと参照**

```markdown
# {{スキル名}}

## Quick start

{{基本的な使用方法}}

## Advanced features

- **{{機能1}}**: See [references/{{feature-1}}.md](references/{{feature-1}}.md)
- **{{機能2}}**: See [references/{{feature-2}}.md](references/{{feature-2}}.md)
```

**パターン2: ドメイン別構成**

```
{{skill-name}}/
├── SKILL.md (概要とナビゲーション)
└── references/
    ├── {{domain-1}}.md ({{ドメイン1の説明}})
    ├── {{domain-2}}.md ({{ドメイン2の説明}})
    └── {{domain-n}}.md ({{ドメインNの説明}})
```

**パターン3: バリアント別構成**

```
{{skill-name}}/
├── SKILL.md (ワークフロー + バリアント選択)
└── references/
    ├── {{variant-1}}.md ({{バリアント1パターン}})
    ├── {{variant-2}}.md ({{バリアント2パターン}})
    └── {{variant-n}}.md ({{バリアントNパターン}})
```

**重要なガイドライン**:

- 深くネストした参照を避ける（SKILL.md から1レベルに保つ）
- すべての参照ファイルは SKILL.md から直接リンク（相対パス使用）

## assets/ ディレクトリ（§3.5）

### 用途

コンテキストに読み込むためではなく、Claude が生成する出力で使用するファイル。

### 使用場面（§3.5.1）

| 場面             | パス形式                           |
| ---------------- | ---------------------------------- |
| テンプレート     | `assets/{{template-name}}.{{ext}}` |
| 画像・アイコン   | `assets/{{image-name}}.{{ext}}`    |
| ボイラープレート | `assets/{{boilerplate-name}}/`     |
| フォント         | `assets/{{font-name}}.{{ext}}`     |
| サンプルデータ   | `assets/{{data-name}}.{{ext}}`     |

### 利点（§3.5.2）

- 出力リソースをドキュメントから分離
- コンテキストに読み込まずにファイルを使用可能

## 命名規則（§9）

### スキル名（§9.1）

| 規則                       | パターン                                  |
| -------------------------- | ----------------------------------------- |
| ハイフンケース             | `{{domain}}-{{topic}}`                    |
| 具体的で明確               | 曖昧な単語（optimization, utils）を避ける |
| 動詞+名詞 または 名詞+名詞 | `{{verb}}-{{noun}}` / `{{noun}}-{{noun}}` |
| 最大64文字                 | 簡潔に                                    |

### ファイル名（§9.2）

| ファイル種別 | 命名規則                                                  |
| ------------ | --------------------------------------------------------- |
| スクリプト   | `{{verb}}_{{target}}.py` または `{{verb}}_{{target}}.mjs` |
| 参照資料     | `{{topic}}.md` または `{{domain}}.md`                     |
| アセット     | `{{purpose}}.{{ext}}` または `{{asset-name}}/`            |

## ファイル参照形式（§10）

### 相対パスの記述規則（§10.1）

**SKILL.md からの相対パス形式を使用**:

| 参照対象   | パス形式                 |
| ---------- | ------------------------ |
| スクリプト | `scripts/{{file}}.py`    |
| 参照資料   | `references/{{file}}.md` |
| アセット   | `assets/{{file}}`        |

**SKILL.md での参照記述形式**:

```markdown
## Resources

- **{{リソース1名}}**: See [references/{{resource-1}}.md](references/{{resource-1}}.md)
- **{{リソース2名}}**: See [references/{{resource-2}}.md](references/{{resource-2}}.md)

## Scripts

- `scripts/{{script-1}}.py`: {{スクリプト1の説明}}
- `scripts/{{script-n}}.mjs`: {{スクリプトNの説明}}
```

### 禁止される参照形式（§10.2）

| 形式                 | 問題点                                 |
| -------------------- | -------------------------------------- |
| スキル名のみ         | パスが不明確で読み込みできない         |
| 絶対パス             | 環境依存（ユーザーごとにパスが異なる） |
| `../` を含む相対パス | 曖昧さが生じ、正確なパス解決ができない |

## 構造パターン

### パターン1: シンプル構成（scriptsのみ）

```
{{skill-name}}/
├── SKILL.md
└── scripts/
    └── log_usage.mjs
```

**適用場面**: スクリプト化が不要で、SKILL.mdのみで完結するスキル

### パターン2: 標準構成（全ディレクトリ使用）

```
{{skill-name}}/
├── SKILL.md
├── scripts/
│   ├── log_usage.mjs
│   └── {{script-name}}.{{ext}}
├── references/
│   ├── {{reference-1}}.md
│   ├── {{reference-2}}.md
│   └── {{reference-n}}.md
└── assets/
    ├── {{template-name}}.{{ext}}
    └── {{asset-name}}.{{ext}}
```

**適用場面**: 繰り返し処理、詳細資料、出力テンプレートが必要なスキル

### パターン3: Progressive Disclosure構成

```
{{skill-name}}/
├── SKILL.md (概要 + references/へのリンク)
├── scripts/
│   └── log_usage.mjs
├── references/
│   ├── {{topic-1}}.md
│   ├── {{topic-2}}.md
│   └── {{topic-n}}.md
└── assets/
    └── {{template-name}}.{{ext}}
```

**適用場面**: SKILL.mdが500行を超える場合、詳細をreferences/に分離

## スキル量産時のチェックリスト

新規スキルを作成する際は、以下を確認：

- [ ] SKILL.md が存在する（500行以内）
- [ ] scripts/ は必要か？（繰り返し書くコードがあるか）
- [ ] references/ は必要か？（SKILL.mdが500行を超えそうか）
- [ ] assets/ は必要か？（出力用テンプレートが必要か）
- [ ] log_usage.mjs を配置する（推奨）
- [ ] README.md等の補助ドキュメントを作成しない
- [ ] すべてのreferences/ファイルをSKILL.mdから相対パスでリンク
- [ ] スクリプトに冪等性・エラー出力・引数検証を実装
