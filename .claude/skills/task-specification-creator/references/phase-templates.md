# Phase別テンプレートリファレンス

各Phaseで生成されるドキュメントのテンプレート構造を定義する。

## 成果物配置ルール（重要）

**成果物には2種類あり、配置先が異なる:**

| 成果物タイプ       | 配置先                         | Phase         |
| ------------------ | ------------------------------ | ------------- |
| ドキュメント成果物 | `outputs/phase-N/`             | 全Phase       |
| コード成果物       | プロジェクトの該当ディレクトリ | Phase 4, 5, 6 |

**コード成果物（テストコード、実装コード）は `outputs/` 配下に配置しない。**
必ず `packages/*/src/` や `apps/*/src/` に配置すること。

---

すべてのPhaseドキュメントは以下の共通構造を持つ:

```markdown
## サブタスク管理

Phase実行開始時に、TodoWriteツールで以下のサブタスクを作成すること:

1. 参照資料の確認
2. 使用スキルの実行（各スキルごとに1タスク）
3. 成果物の作成・配置
4. 完了条件の検証

**重要**: 各サブタスクは実行完了後すぐにcompletedに更新すること。

## 次のPhase
```

## Phase -1: 環境準備（Git Worktree作成）

````markdown
# Phase -1: 環境準備（Git Worktree作成）

## メタ情報

| 項目   | 値         |
| ------ | ---------- |
| Phase  | -1         |
| 機能名 | {{機能名}} |
| 作成日 | {{日付}}   |

## 目的

タスク実装用の独立したGit Worktree環境を作成し、本体ブランチに影響を与えずに開発を進められる環境を準備する。

## 背景

複数タスクの並行開発や実験的な変更のため、各タスクごとに独立したWorktreeで作業を行う必要がある。これにより、本体ブランチを保護し、タスク間の干渉を防ぐ。

## 使用スキル

- なし（Bashコマンドで直接実行）

## 参照資料

| 資料名                   | パス                                  | 説明             |
| ------------------------ | ------------------------------------- | ---------------- |
| Git Worktreeドキュメント | https://git-scm.com/docs/git-worktree | 公式ドキュメント |

## 実行手順

### 1. タスク識別子生成

```bash
TIMESTAMP=$(date +%Y%m%d-%H%M%S)
WORKTREE_NAME="task-${TIMESTAMP}"
```
````

### 2. Worktree作成

```bash
git worktree add .worktrees/${WORKTREE_NAME} -b ${WORKTREE_NAME}
```

### 3. 作業ディレクトリ移動

```bash
cd .worktrees/${WORKTREE_NAME}
```

### 4. 依存関係インストール

```bash
pnpm install
```

### 5. ビルド確認

```bash
pnpm build
```

## 成果物

| 成果物           | パス                           | 説明             |
| ---------------- | ------------------------------ | ---------------- |
| Git Worktree環境 | `.worktrees/task-${TIMESTAMP}` | 独立した開発環境 |
| 作業ブランチ     | `task-${TIMESTAMP}`            | 新規ブランチ     |

## 完了条件

- [ ] Git Worktreeが正常に作成されている
- [ ] 新規ブランチが作成されている
- [ ] Worktreeディレクトリへ移動済み
- [ ] 依存関係がインストールされている
- [ ] ビルドが成功する

## 次のPhase

Phase 1: 要件定義（スキル上のPhase番号）


## Phase 4: テスト作成（TDD: Red）

```markdown
# Phase 4: テスト作成（TDD: Red）

## メタ情報

| ------ | ---------- |

| 作成日 | {{日付}}   |

## 目的

期待される動作を検証するテストを実装より先に作成する（Red状態）。

## 使用スキル

- `tdd-principles`: TDD原則適用
- `frontend-testing`: フロントエンドテスト
- `integration-testing`: 統合テスト
- `boundary-value-analysis`: 境界値分析

## 参照資料

| 資料名       | パス                                         | 説明          |

integration-testingスキルを参照し、コンポーネント間の連携テストを作成する。

### 4. 境界値テスト

boundary-value-analysisスキルを参照し、エッジケースのテストを追加する。
```

```
## 使用方法

1. タスク仕様書生成時に、対象Phaseのテンプレートを参照
2. `{{変数}}` を実際の値で置換
3. 使用スキルセクションに該当するスキルを列挙（動的に選定）
4. 参照資料に前Phaseの成果物を追加
5. ファイルを `docs/30-workflows/{{機能名}}/` に出力
6. Phase完了後、`complete-phase.mjs` で成果物を登録
```
