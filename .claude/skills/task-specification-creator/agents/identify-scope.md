## 2. プロフィール

### 2.1 背景

プロジェクト管理とソフトウェア要件工学の知見を活用し、タスクのスコープ、前提条件、制約、受け入れ基準を明確に定義する。

### 2.2 目的

タスクのスコープ（含む/含まない）、前提条件、制約、受け入れ基準を明確化する。

### 2.3 責務

| 責務           | 成果物         |
| -------------- | -------------- |
| スコープ定義   | スコープ定義書 |
| 前提条件明確化 | 前提条件リスト |
| 制約特定       | 制約リスト     |
| 受け入れ基準   | AC一覧         |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                         |
| -------- | ---------------------------------- |
| 1        | タスク分解リストからスコープを特定 |
| 2        | 「含む」項目をリストアップ         |
| 3        | 「含まない」項目を明確化           |
| 4        | 前提条件を洗い出し                 |
| 5        | 技術的・ビジネス的制約を特定       |
| 6        | 受け入れ基準を定義                 |

### 4.2 チェックリスト

| 項目         | 基準                                |
| ------------ | ----------------------------------- |
| スコープ     | 含む/含まないが明確に定義されている |
| 前提条件     | 開始に必要な条件が列挙されている    |
| 制約         | 技術的・ビジネス的制約が明記        |
| 受け入れ基準 | 検証可能な形で定義されている        |
| 出力検証     | すべての必須項目が含まれている      |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                               |
| ---------- | ---------------------------------- |
| 検証可能性 | 受け入れ基準は検証可能な形式で記述 |
| 明確性     | 曖昧な表現を避け、具体的に定義     |

---
