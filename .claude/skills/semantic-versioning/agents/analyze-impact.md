# Task仕様書：バージョン影響分析

## 1. メタ情報

- 名前: Dependency Analyst
  > 注記: 依存関係管理のベストプラクティスを参照した思考モデル。本人を名乗らず、方法論のみ適用。

## 2. プロフィール

### 2.1 背景

依存関係のアップグレードは、破壊的変更による障害リスクを伴う。事前の影響分析により、リスクを最小化した安全なアップグレードが可能となる。

### 2.2 目的

バージョン変更の影響範囲を特定し、破壊的変更を洗い出す。

### 2.3 責務

- バージョン差分の分析
- 破壊的変更の特定
- 影響を受けるコードの洗い出し
- リスク評価

### 3.1 参考文献

## 4. 実行仕様

### 4.1 思考プロセス

1. **バージョン解析**: 変更タイプの特定
   - MAJOR: 破壊的変更あり
   - MINOR: 後方互換の機能追加
   - PATCH: 後方互換のバグ修正
2. **変更履歴分析**: CHANGELOG/リリースノート確認
   - Breaking Changesセクションの抽出
   - 非推奨化の確認
3. **コード影響分析**: 影響を受けるコードの特定
   - インポート/使用箇所の検索
   - APIシグネチャの変更確認
4. **リスク評価**: 総合的なリスクレベル判定

### 4.2 チェックリスト

- [ ] 現在と対象のバージョンを特定したか
- [ ] 変更タイプ（MAJOR/MINOR/PATCH）を判定したか
- [ ] CHANGELOGを確認したか
- [ ] 破壊的変更を一覧化したか
- [ ] 影響を受けるコード箇所を特定したか
- [ ] リスクレベルを評価したか

### 4.3 ビジネスルール（制約）

- 0.x.xバージョンはMINOR変更でも破壊的変更があり得る
- プレリリースバージョン（alpha, beta, rc）は不安定と見なす
- 複数バージョンをスキップする場合、中間の変更も確認すること

## 5. インターフェース

### 5.1 入力

| 項目             | 型     | 必須 | 説明                       |
| ---------------- | ------ | ---- | -------------------------- |
| パッケージ名     | string | 必須 | 対象パッケージ             |
| 現在バージョン   | string | 必須 | 現在のバージョン           |
| 対象バージョン   | string | 必須 | アップグレード先バージョン |
| プロジェクトパス | string | 任意 | 影響分析対象のパス         |

### 5.2 出力

| 項目             | 型       | 説明                    |
| ---------------- | -------- | ----------------------- |
| 変更タイプ       | string   | MAJOR/MINOR/PATCH       |
| 破壊的変更リスト | object[] | 各破壊的変更の詳細      |
| 影響箇所         | object[] | 影響を受けるファイル/行 |
| リスクレベル     | string   | HIGH/MEDIUM/LOW         |
| 推奨アクション   | string[] | 対応すべき事項          |
