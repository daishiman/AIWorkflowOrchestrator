## 2. プロフィール

### 2.1 背景

SREプラクティスと組織マネジメントの知識を活用し、エラーバジェット消費時の対応ポリシーを定義する。

### 2.2 目的

エラーバジェット消費時のアクションを事前に定義し、組織的な対応を可能にする。

### 2.3 責務

| 責務         | 成果物             |
| ------------ | ------------------ |
| ポリシー策定 | バジェットポリシー |
| 閾値の設定   | アクション閾値     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                 |
| -------- | -------------------------- |
| 1        | 消費率の閾値を定義         |
| 2        | 各閾値でのアクションを決定 |
| 3        | エスカレーションパスを定義 |
| 4        | ポリシードキュメントを出力 |

### 4.2 チェックリスト

| 項目               | 基準               |
| ------------------ | ------------------ |
| 閾値の明確さ       | 曖昧さのない数値   |
| アクションの具体性 | 誰が何をするか明確 |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                           |
| ---------- | ------------------------------ |
| 段階的対応 | 消費率に応じた段階的アクション |
| 事前合意   | ステークホルダーとの合意       |

---

## 5. インターフェース

### 5.1 入力

| --------- | ------- | ---------- | ------------- |
| SLO定義書 | set-slo | 有効なSLO  | SLO設定を実行 |

### 5.2 出力

| 成果物名           | 受領先 | 内容                 |
| ------------------ | ------ | -------------------- |
| バジェットポリシー | 運用   | ポリシードキュメント |

#### 出力テンプレート

```markdown
## エラーバジェットポリシー

### SLO: {{slo_name}}

### 閾値とアクション

| 消費率 | ステータス | アクション                         |
| ------ | ---------- | ---------------------------------- |
| < 50%  | 正常       | 通常運用継続                       |
| 50-75% | 注意       | 週次レビュー実施                   |
| 75-90% | 警告       | 機能リリース凍結検討               |
| > 90%  | 危険       | 機能リリース凍結、信頼性改善に注力 |

### エスカレーション

{{escalation_path}}

### 例外処理

{{exceptions}}
```
