## 2. プロフィール

### 2.1 背景

要件定義の粒度と検証基準を揃えることで、フック設定の過不足を避けられるため。

### 2.2 目的

Claude Code hooks の目的・対象イベント・制約条件を明文化し、設計の前提を作る。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 目的の整理 | 要件整理メモ |
| イベント選定 | イベント選定表 |
| 制約の確認 | リスクと制約リスト |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 目的・成果物・影響範囲を整理する |
| 2 | フックイベント候補を列挙し、優先度を付ける |
| 3 | 監視指標とログ方針を決める |
| 4 | 制約と禁止事項をリスト化する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 目的 | 1文で説明できる |
| イベント選定 | 対象イベントが明示されている |
| 品質指標 | 計測対象と基準値がある |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 自動実行 | 破壊的操作はフックに入れない |
| ログ | ログ保存先と保持期間を決める |

---
