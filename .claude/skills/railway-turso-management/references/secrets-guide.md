## 1. Railway Secretsの特性

### 1.1 セキュリティ機能

| 機能           | 説明                               |
| -------------- | ---------------------------------- |
| 暗号化         | 保存時に自動暗号化                 |
| ログマスキング | ビルドログ・ランタイムログで非表示 |
| アクセス制御   | 環境ごとに分離                     |
| 監査ログ       | 変更履歴の記録                     |

### 1.2 Variables との違い

| 観点     | Variables  | Secrets      |
| -------- | ---------- | ------------ |
| ログ表示 | 表示される | マスクされる |
| 暗号化   | なし       | あり         |
| 用途     | 設定値     | 認証情報     |
| コピー   | 可能       | 制限あり     |

## 2. 設計パターン

### 2.1 命名規則

| パターン            | 例                   | 用途         |
| ------------------- | -------------------- | ------------ |
| `<SERVICE>_<TYPE>`  | `TURSO_AUTH_TOKEN`   | サービス認証 |
| `<ENV>_<SERVICE>_*` | `PROD_STRIPE_SECRET` | 環境別設定   |
| `<FEATURE>_API_KEY` | `OPENAI_API_KEY`     | 機能別API    |

### 2.2 継承設計

```yaml
# 推奨構成
Base:
  - NODE_ENV: "production"
  - LOG_LEVEL: "info"

Development:
  - NODE_ENV: "development" # オーバーライド
  - DEBUG: "true"

Production:
  - TURSO_AUTH_TOKEN: "***" # 本番専用
```

## 3. ローテーション戦略

### 3.1 推奨サイクル

| シークレット種別 | ローテーション周期 | 理由             |
| ---------------- | ------------------ | ---------------- |
| API Key          | 90日               | 業界標準         |
| Auth Token       | 30-90日            | リスクレベル依存 |
| DB Password      | 180日              | 運用影響考慮     |

### 3.2 ローテーション手順

1. 新しいトークンを生成
2. Railway Secretsを更新
3. デプロイで新トークン反映
4. 旧トークンを無効化

## 4. セキュリティチェックリスト

| チェック項目            | 確認方法             |
| ----------------------- | -------------------- |
| Secretsに機密情報を格納 | Railway UI確認       |
| ログにトークン非表示    | Railway Logs確認     |
| 環境間分離              | 環境グループ設定確認 |
| console.log未使用       | コードレビュー       |
| 一時ファイル未作成      | ファイルシステム確認 |
