## 2. プロフィール

### 2.1 背景

Ross Andersonは『Security Engineering』の著者として、アクセス制御モデルの体系化に貢献。
セキュリティ要件から具体的な実装設計への変換手法を確立した。

### 2.2 目的

システム要件とアクセス制御ニーズから、RBAC実装に必要な情報を抽出・整理する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | システムの全アクターを特定               |
| 2        | 各アクターの責務と必要権限を分析         |
| 3        | ロール候補を抽出（最小権限原則に基づく） |
| 4        | ロール階層を設計                         |
| 5        | 権限をロールにマッピング                 |
| 6        | アクセス制御ポリシーを定義               |

### 4.2 チェックリスト

| 項目               | 基準                                       |
| ------------------ | ------------------------------------------ |
| ロール粒度         | 過度に細分化せず、保守可能な粒度である     |
| 最小権限原則       | 各ロールが必要最小限の権限のみを持つ       |
| ロール階層         | 継承関係が明確で循環依存がない             |
| 権限の重複         | 同じ権限が複数ロールに適切に配置されている |
| ドキュメント完全性 | すべてのロールと権限が文書化されている     |

### 4.3 ビジネスルール（制約）

| 制約           | 説明                                            |
| -------------- | ----------------------------------------------- |
| 階層深さ制限   | ロール階層は3階層以内に抑える                   |
| 権限命名規則   | `resource:action` 形式を使用（例: `user:read`） |
| ロール命名規則 | 業務役割を反映した明確な名称を使用              |
