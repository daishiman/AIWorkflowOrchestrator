# 用語集作成ガイド

## 概要

ドメイン用語集の作成における詳細な手法とベストプラクティス。

## 用語定義のフォーマット

### 基本形式

```markdown
#### {{用語}}

- **定義**: {{「〇〇とは、△△である」形式の明確な定義}}
- **コンテキスト**: {{この用語が有効なコンテキスト}}
- **同義語**: {{非推奨の同義語（あれば）}}
- **反意語**: {{反意語（あれば）}}
- **用法例**: {{具体的な使用例}}
- **関連用語**: {{関連する他の用語}}
```

### 良い定義の例

```markdown
#### 注文 (Order)

- **定義**: 注文とは、顧客が1つ以上の商品を購入する意思を表明し、支払いを約束した取引記録である
- **コンテキスト**: EC（電子商取引）
- **同義語**: オーダー（非推奨）
- **反意語**: キャンセル
- **用法例**: 「顧客が注文を確定した」「注文をキャンセルする」
- **関連用語**: 注文明細、顧客、商品
```

### 悪い定義の例（避けるべき）

```markdown
#### 注文

- **定義**: 注文すること（❌ 循環定義）
- **定義**: 顧客が何かを買うこと（❌ 曖昧）
- **定義**: ECサイトにおいてカートに入れた商品をデータベースに永続化し... （❌ 技術的すぎる）
```

## コンテキスト別の用語管理

### 同じ用語が異なる意味を持つ場合

```markdown
### 販売コンテキスト

#### 顧客 (Customer)

- **定義**: 顧客とは、商品を購入する個人または法人である
- **主な属性**: 氏名、連絡先、購入履歴

### 配送コンテキスト

#### 顧客 (Customer)

- **定義**: 顧客とは、配送先として指定された受取人である
- **主な属性**: 配送先住所、連絡先、配送希望時間
```

## 同義語の統一

### プロセス

1. 同じ概念を指す複数の用語を収集
2. ドメインエキスパートと協議して優先語を決定
3. 非推奨語を明示的にマーク
4. コードベースから非推奨語を段階的に削除

### 記録形式

| 優先語 | 非推奨語           | 統一理由                     |
| ------ | ------------------ | ---------------------------- |
| 注文   | オーダー、発注     | 日本語を優先、社内用語に統一 |
| 顧客   | カスタマー、お客様 | ビジネス文書での標準表現     |

## 品質チェックリスト

- [ ] すべての用語に定義がある
- [ ] 定義は1-3文で簡潔である
- [ ] 循環定義がない
- [ ] 技術用語を使わずに定義されている
- [ ] コンテキストが明示されている
- [ ] 同義語が整理されている
- [ ] 用法例が含まれている
