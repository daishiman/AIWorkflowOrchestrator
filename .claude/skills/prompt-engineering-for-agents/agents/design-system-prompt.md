# System Prompt設計タスク

## タスク概要

新規エージェントのSystem Promptをゼロから設計するタスクです。
Role Prompting、Structured Workflow、制約定義などの技術を活用し、
高品質なSystem Promptを作成します。

## 前提条件

- エージェントの目的が明確である
- 対象タスクと期待される成果物が定義されている
- `references/basics.md` と `references/patterns.md` を理解している

## 実行手順

### Phase 1: 要件収集

**目的**: エージェントの要件を明確にする

**手順**:

1. エージェントの役割を1-2文で定義
2. 対象タスクを3-5個リストアップ
3. 制約条件と禁止事項を洗い出し
4. 期待される成果物を明確化
5. 成功基準を定量的に定義

**質問リスト**:

- このエージェントは何の専門家か？
- 主なタスクは何か（3-5個）？
- 絶対にしてはいけないことは何か？
- 期待される成果物は何か？
- 成功をどう測定するか（定量的指標）？

**成果物**:

```markdown
## エージェント要件定義

### 役割

{{1-2文の役割定義}}

### タスク

1. {{タスク1}}
2. {{タスク2}}
3. {{タスク3}}

### 制約

- {{制約1}}
- {{制約2}}

### 成果物

- {{成果物1}}
- {{成果物2}}

### 成功基準

- {{基準1}}: {{測定方法}}（目標値: {{値}}）
- {{基準2}}: {{測定方法}}（目標値: {{値}}）
```

### Phase 2: パターン選択

**目的**: 適切なプロンプトパターンを選択

**手順**:

1. `references/patterns.md` で7つのパターンを確認
2. タスクに適したパターンを3-5個選択
3. 各パターンの適用方法を計画

**パターン選択ガイド**:

| タスクの特徴               | 推奨パターン                        |
| -------------------------- | ----------------------------------- |
| 明確な専門分野がある       | Pattern 1: Role Prompting           |
| 複数ステップのワークフロー | Pattern 3: Structured Workflow      |
| 制約が重要                 | Pattern 2: Constrained Behavior     |
| 外部スキルに依存           | Pattern 4: Knowledge Reference      |
| 具体例が有効               | Pattern 5: Few-Shot Examples        |
| プロジェクト固有知識が必要 | Pattern 6: Context Enhancement      |
| エラー処理が重要           | Pattern 7: Error Handling Directive |

**成果物**:

```markdown
## 選択パターン

1. **Role Prompting**: {{役割定義に使用}}
2. **Structured Workflow**: {{3フェーズのワークフローを定義}}
3. **Constrained Behavior**: {{制約を明示}}
4. **Few-Shot Examples**: {{2-3個の例示を追加}}
```

### Phase 3: 骨格作成

**目的**: System Promptの骨格を作成

**手順**:

1. `assets/prompt-template.md` をコピー
2. 推奨7セクション構造に従って骨格を作成:
   - 役割定義
   - 専門分野
   - ワークフロー
   - スキル管理
   - ベストプラクティス
   - 詳細リファレンス
   - 変更履歴
3. プレースホルダーを配置

**成果物**:

```markdown
# {{エージェント名}}

## 役割

あなたは **{{役割名}}** です。

{{役割の詳細説明}}

## 専門分野

- {{専門分野1}}
- {{専門分野2}}
- {{専門分野3}}

## ワークフロー

### Phase 1: {{Phase名}}

**目的**: {{Phase目的}}

**手順**:

1. {{ステップ1}}
2. {{ステップ2}}

**成果物**:

- {{成果物1}}

## スキル管理

依存スキル:

- {{スキル1}}

## ベストプラクティス

✅ **すべきこと**:

- {{制約1}}

❌ **避けるべきこと**:

- {{禁止事項1}}

## 詳細リファレンス

- {{リファレンス1}}

## 変更履歴

| Version | Date       | Changes  |
| ------- | ---------- | -------- |
| 1.0.0   | YYYY-MM-DD | 初版作成 |
```

### Phase 4: 詳細化

**目的**: 骨格に具体的な内容を記述

**手順**:

1. **役割定義を記述**:
   - 1-2文で簡潔に
   - 参考文献・標準を明示
   - 専門分野を3-5個リスト

2. **ワークフローを記述**:
   - Phaseごとに目的、手順、成果物を明記
   - ツール使用を明示
   - 判断ポイントを追加

3. **制約を記述**:
   - すべきこと3-5個
   - 避けるべきこと3-5個
   - 具体的な基準値を設定

4. **Few-Shot Examples追加**:
   - 典型例1-2個
   - 境界例1個
   - 失敗例1個（オプション）

**チェックポイント**:

- [ ] 役割定義は1-2文で明確か？
- [ ] ワークフローは具体的な手順か？
- [ ] 制約には具体的な基準値があるか？
- [ ] Few-Shot Examplesは実際の値を使用しているか？

### Phase 5: 曖昧表現の排除

**目的**: 曖昧な表現を具体的な基準に置換

**手順**:

1. 以下の曖昧表現を検索:
   - 「適宜」→ 具体的な条件に置換
   - 「必要に応じて」→ 条件を明示
   - 「など」→ すべて列挙
   - 「いくつかの」→ 具体的な数値
   - 「できるだけ」→ 具体的な基準値

2. 測定可能な基準に置換:
   - 「高品質」→ 「テストカバレッジ80%以上」
   - 「効率的に」→ 「10分以内」
   - 「適切に」→ 「循環的複雑度10以下」

3. `references/anti-patterns.md` でアンチパターンを確認

**チェックポイント**:

- [ ] 曖昧な表現（「適宜」「など」）がないか？
- [ ] すべての基準が測定可能か？
- [ ] アンチパターンが含まれていないか？

### Phase 6: 品質検証

**目的**: 作成したSystem Promptの品質を検証

**手順**:

1. `scripts/analyze-prompt.mjs` で構造を分析
2. 以下の指標で自己評価（各1-5点）:
   - **明確性**: 指示の明瞭さ
   - **具体性**: 実行可能性
   - **構造化**: セクション構成
   - **完全性**: 必須要素の充足
3. 各指標が4点以上か確認
4. 改善点を特定

**評価基準**:

| 指標   | 5点                    | 4点                | 3点以下          |
| ------ | ---------------------- | ------------------ | ---------------- |
| 明確性 | 曖昧表現なし           | 1-2箇所曖昧        | 3箇所以上曖昧    |
| 具体性 | すべて測定可能         | 一部測定不可能     | 多くが測定不可能 |
| 構造化 | 7セクション完全準拠    | 一部セクション欠如 | 構造が不明確     |
| 完全性 | すべての必須要素を含む | 一部要素欠如       | 多くの要素欠如   |

**成果物**:

```markdown
## 品質評価結果

- 明確性: {{点数}}/5
- 具体性: {{点数}}/5
- 構造化: {{点数}}/5
- 完全性: {{点数}}/5

## 改善点

1. {{改善点1}}
2. {{改善点2}}
```

### Phase 7: 最終調整

**目的**: フィードバックを反映して最終化

**手順**:

1. Phase 6で特定した改善点を反映
2. Token数を確認（SKILL.mdは500行以内推奨）
3. 過度な詳細は `references/` に外部化
4. 変更履歴を更新
5. `scripts/validate-skill.mjs` で構造を検証

**成果物**:

- 完成したSystem Prompt
- 品質評価レポート

## 品質チェックリスト

### 必須要素

- [ ] 役割定義が1-2文で明確
- [ ] 専門分野が3-5個リスト
- [ ] ワークフローが構造化されている
- [ ] ツール使用が明示されている
- [ ] 成果物が定義されている
- [ ] 判断ポイントが明確
- [ ] すべきこと・避けるべきことが明示

### 推奨要素

- [ ] Few-Shot Examplesが2-5個
- [ ] 依存スキルが明示
- [ ] 詳細リファレンスへの参照
- [ ] エラーハンドリングが定義

### 品質基準

- [ ] 曖昧な表現（「適宜」「など」）がない
- [ ] すべての基準が測定可能
- [ ] Token数が適切（500行以内）
- [ ] アンチパターンが含まれていない
- [ ] 7セクション構造に準拠

## 注意事項

### すべきこと

- ✅ 要件を明確に定義してから設計を開始
- ✅ 適切なパターンを選択
- ✅ 曖昧表現を排除
- ✅ 測定可能な基準を設定
- ✅ 品質評価を実施

### 避けるべきこと

- ❌ 要件不明確のまま設計開始
- ❌ すべてのパターンを無理に適用
- ❌ 曖昧な表現を放置
- ❌ 測定不可能な基準
- ❌ 品質検証をスキップ
