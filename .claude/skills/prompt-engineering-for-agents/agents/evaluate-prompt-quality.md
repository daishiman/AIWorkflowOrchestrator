# プロンプト品質評価タスク

## タスク概要

System Promptの品質を評価し、改善提案を行うタスクです。
明確性、具体性、構造化、完全性の4つの指標で定量的に評価します。

## 前提条件

- 評価対象のSystem Promptが存在する
- `references/basics.md` と `references/anti-patterns.md` を理解している

## 実行手順

### Phase 1: 構造検証

**目的**: System Promptの構造的な問題を検出

**手順**:

1. `scripts/validate-skill.mjs` でスキル構造を検証
2. 推奨7セクション構造への準拠を確認:
   - [ ] 役割定義
   - [ ] 専門分野
   - [ ] ワークフロー
   - [ ] スキル管理
   - [ ] ベストプラクティス
   - [ ] 詳細リファレンス
   - [ ] 変更履歴
3. 欠けているセクションをリストアップ
4. セクション順序の論理性を確認

**評価基準**:

| スコア | 基準                  |
| ------ | --------------------- |
| 5      | 7セクションすべて完備 |
| 4      | 1-2セクション欠如     |
| 3      | 3-4セクション欠如     |
| 2      | 5セクション以上欠如   |
| 1      | セクション構造なし    |

**成果物**:

```markdown
## 構造検証結果

### 準拠状況

- [x] 役割定義
- [x] 専門分野
- [ ] ワークフロー（欠如）
- [x] スキル管理
- [ ] ベストプラクティス（欠如）
- [x] 詳細リファレンス
- [x] 変更履歴

### スコア: {{N}}/5

### 改善必要箇所

1. ワークフローセクションを追加
2. ベストプラクティスセクションを追加
```

### Phase 2: 明確性評価

**目的**: 曖昧な表現の有無を確認

**手順**:

1. 以下の曖昧表現を検索:

   ```bash
   grep -i "適宜\|必要に応じて\|など\|いくつかの\|できるだけ\|可能な限り\|適切に\|よしなに" <prompt-file>
   ```

2. 各表現の出現回数をカウント
3. 影響度を評価（高/中/低）
4. 具体的な置換案を提示

**評価基準**:

| スコア | 基準                       |
| ------ | -------------------------- |
| 5      | 曖昧表現なし               |
| 4      | 1-2箇所（影響度低）        |
| 3      | 3-5箇所（影響度中）        |
| 2      | 6-10箇所（影響度高）       |
| 1      | 11箇所以上（全体的に曖昧） |

**成果物**:

```markdown
## 明確性評価結果

### 曖昧表現リスト

| 表現       | 出現回数 | 箇所                   | 影響度 | 置換案                   |
| ---------- | -------- | ---------------------- | ------ | ------------------------ |
| 適宜       | 3        | ワークフロー Phase 1-3 | 高     | 「条件Xの場合はYを実施」 |
| など       | 2        | ベストプラクティス     | 中     | 具体的な項目をすべて列挙 |
| できるだけ | 1        | 制約                   | 低     | 「80%以上」              |

### スコア: {{N}}/5

### 総合評価

- 曖昧表現総数: {{N}}箇所
- 高影響度: {{N}}箇所
- 中影響度: {{N}}箇所
- 低影響度: {{N}}箇所
```

### Phase 3: 具体性評価

**目的**: 測定可能性と実行可能性を評価

**手順**:

1. すべての指示文を抽出
2. 各指示について評価:
   - 測定可能な基準があるか？
   - 具体的な手順が記述されているか？
   - 成果物が明確か？
3. 測定不可能な指示をリストアップ
4. 具体的な基準値を提案

**評価基準**:

| スコア | 基準                   |
| ------ | ---------------------- |
| 5      | すべての指示が測定可能 |
| 4      | 80%以上が測定可能      |
| 3      | 60-80%が測定可能       |
| 2      | 40-60%が測定可能       |
| 1      | 40%未満が測定可能      |

**成果物**:

```markdown
## 具体性評価結果

### 測定不可能な指示

| 箇所                 | 現在の指示               | 問題点       | 改善案                      |
| -------------------- | ------------------------ | ------------ | --------------------------- |
| ワークフロー Phase 1 | 「高品質なコードを書く」 | 基準が不明確 | 「テストカバレッジ80%以上」 |
| 制約                 | 「効率的に実施」         | 測定不可能   | 「10分以内」                |
| 成果物               | 「レポート」             | 形式が不明確 | 「Markdown形式のレポート」  |

### スコア: {{N}}/5

### 測定可能性

- 総指示数: {{N}}
- 測定可能: {{N}} ({{N}}%)
- 測定不可能: {{N}} ({{N}}%)
```

### Phase 4: 構造化評価

**目的**: セクション構成と論理性を評価

**手順**:

1. 各セクションの内容を確認:
   - 役割定義は1-2文で簡潔か？
   - ワークフローはPhase分けされているか？
   - ベストプラクティスは✅❌で整理されているか？
2. 論理的な流れを確認
3. 冗長性や重複をチェック
4. 箇条書き・テーブルの活用度を評価

**評価基準**:

| スコア | 基準                                         |
| ------ | -------------------------------------------- |
| 5      | 完全に構造化され、論理的な流れ               |
| 4      | 概ね構造化されているが、一部改善余地あり     |
| 3      | 部分的に構造化されているが、多くの改善が必要 |
| 2      | 構造化が不十分、長文が多い                   |
| 1      | ほぼ非構造化、読みづらい                     |

**成果物**:

```markdown
## 構造化評価結果

### セクション別評価

| セクション         | 評価 | 問題点            | 改善案          |
| ------------------ | ---- | ----------------- | --------------- |
| 役割定義           | ✅   | 良好（1文で簡潔） | -               |
| ワークフロー       | ⚠️   | Phase分けなし     | 3フェーズに分割 |
| ベストプラクティス | ❌   | 箇条書きなし      | ✅❌形式で整理  |

### スコア: {{N}}/5

### 改善提案

1. ワークフローを3フェーズに分割
2. ベストプラクティスを✅❌形式で整理
3. 長文を箇条書きに変換
```

### Phase 5: 完全性評価

**目的**: 必須要素の充足度を評価

**手順**:

1. 必須要素の有無を確認:
   - [ ] 役割定義（1-2文）
   - [ ] 専門分野（3-5個）
   - [ ] ワークフロー（Phase分け）
   - [ ] 制約（すべきこと・避けるべきこと）
   - [ ] 成果物定義
   - [ ] 判断ポイント
2. 推奨要素の有無を確認:
   - [ ] Few-Shot Examples（2-5個）
   - [ ] 依存スキル
   - [ ] 詳細リファレンス
   - [ ] エラーハンドリング
3. 充足率を計算

**評価基準**:

| スコア | 基準                               |
| ------ | ---------------------------------- |
| 5      | すべての必須要素 + 推奨要素80%以上 |
| 4      | すべての必須要素 + 推奨要素50%以上 |
| 3      | 必須要素80%以上                    |
| 2      | 必須要素50%以上                    |
| 1      | 必須要素50%未満                    |

**成果物**:

```markdown
## 完全性評価結果

### 必須要素（{{N}}/{{N}}）

- [x] 役割定義
- [x] 専門分野
- [ ] ワークフロー（欠如）
- [x] 制約
- [ ] 成果物定義（欠如）
- [x] 判断ポイント

### 推奨要素（{{N}}/{{N}}）

- [x] Few-Shot Examples
- [ ] 依存スキル（欠如）
- [x] 詳細リファレンス
- [ ] エラーハンドリング（欠如）

### スコア: {{N}}/5

### 充足率

- 必須要素: {{N}}% ({{N}}/{{N}})
- 推奨要素: {{N}}% ({{N}}/{{N}})
```

### Phase 6: アンチパターン検出

**目的**: よくある失敗パターンを検出

**手順**:

1. `references/anti-patterns.md` の10パターンを確認
2. 各アンチパターンの有無をチェック:
   - [ ] 曖昧指示病
   - [ ] 例示過多症候群
   - [ ] 非構造化長文病
   - [ ] 役割定義欠如
   - [ ] 制約なし放任主義
   - [ ] 知識重複の泥沼
   - [ ] 抽象例示の罠
   - [ ] 測定不能基準病
   - [ ] エラーハンドリング無視
   - [ ] ワークフロー欠如
3. 検出されたアンチパターンを優先順位付け

**成果物**:

```markdown
## アンチパターン検出結果

### 検出されたパターン

1. **曖昧指示病** - 🔴 高優先度
   - 箇所: ワークフロー全体
   - 影響: エージェントの動作が不安定
   - 対処: 具体的な条件を明示

2. **非構造化長文病** - 🟡 中優先度
   - 箇所: ベストプラクティス
   - 影響: 理解しづらい
   - 対処: 箇条書きで整理

3. **測定不能基準病** - 🟡 中優先度
   - 箇所: 成功基準
   - 影響: 判断が一貫しない
   - 対処: 定量的な基準を設定

### 未検出パターン

- ✅ 例示過多症候群
- ✅ 役割定義欠如
- ✅ 制約なし放任主義
```

### Phase 7: 総合評価とレポート作成

**目的**: すべての評価結果をまとめる

**手順**:

1. Phase 1-6の評価スコアを集計
2. 総合スコアを算出（平均）
3. 改善優先順位を決定:
   - 高優先度: スコア1-2の項目
   - 中優先度: スコア3の項目
   - 低優先度: スコア4の項目
4. 改善ロードマップを作成
5. 最終レポートを生成

**成果物**:

## 注意事項

### すべきこと

- ✅ 客観的な基準で評価
- ✅ 定量的なスコアを算出
- ✅ 具体的な改善案を提示
- ✅ 優先順位をつける
- ✅ 改善ロードマップを作成

### 避けるべきこと

- ❌ 主観的な評価
- ❌ 定性的な感想のみ
- ❌ 曖昧な改善提案
- ❌ 優先順位なしの羅列
- ❌ 実行不可能な提案
