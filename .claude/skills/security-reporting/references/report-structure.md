## レポート全体構造

```
セキュリティ診断レポート
├── 表紙/メタ情報
├── エグゼクティブサマリー（経営層向け）
├── スコープと方法論（監査概要）
├── 主要発見事項（技術詳細）
├── 依存関係脆弱性
├── セキュリティ設定の問題
├── アクションプラン
├── 継続的セキュリティ提案
└── 付録
```

## 必須セクション

### 1. メタ情報

| 項目           | 説明               | 必須 |
| -------------- | ------------------ | ---- |
| 監査日         | 診断実施日         | ✓    |
| プロジェクト名 | 対象システム名     | ✓    |
| 監査者         | 実施者名/チーム    | ✓    |
| バージョン     | レポートバージョン | ✓    |
| 分類           | 機密レベル         | 推奨 |

### 2. エグゼクティブサマリー

**目的**: 経営層が即座に重要度を把握できるようにする。

**必須要素**:

- 総合セキュリティ評価（A〜F）
- 脆弱性サマリー表（Critical/High/Medium/Low件数）
- Top 5発見事項
- 即座のアクション（3項目程度）

**評価基準**:

| グレード       | 条件                                |
| -------------- | ----------------------------------- |
| A (優秀)       | Critical/High: 0件、Medium: 5件以下 |
| B (良好)       | Critical: 0件、High: 3件以下        |
| C (改善必要)   | Critical: 0件、High: 5件以下        |
| D (重大な問題) | Critical: 3件以下                   |
| F (不合格)     | Critical: 4件以上                   |

### 3. スコープと方法論

**必須要素**:

- 監査対象（ソースコード、依存関係、設定ファイル）
- ファイル数/コード行数
- 使用ツール
- 評価基準（OWASP Top 10、CWE等）

### 4. 主要発見事項

**各脆弱性の必須項目**:

| 項目                 | 説明                     | 必須 |
| -------------------- | ------------------------ | ---- |
| 重要度               | Critical/High/Medium/Low | ✓    |
| CVSSスコア           | 0.0〜10.0                | ✓    |
| OWASPカテゴリ        | A01〜A10                 | ✓    |
| CWE ID               | CWE-XXX                  | ✓    |
| 影響を受けるファイル | パスと行番号             | ✓    |
| 脆弱性の説明         | 技術的説明               | ✓    |
| 悪用シナリオ         | 攻撃手順                 | ✓    |
| 影響範囲             | 被害の範囲               | ✓    |
| 修正推奨事項         | Before/Afterコード       | ✓    |
| 検証方法             | 修正確認方法             | 推奨 |

### 5. アクションプラン

**フェーズ構成**:

| フェーズ            | 期間        | 対象          |
| ------------------- | ----------- | ------------- |
| Phase 1: 緊急対応   | 即座〜1週間 | Critical/P0   |
| Phase 2: 早期対応   | 1〜4週間    | High/P1       |
| Phase 3: 計画的対応 | 1〜3ヶ月    | Medium/P2以下 |

**各タスクの必須項目**:

- タスク名
- 担当（チーム/個人）
- 期限
- ステータス

## レポート品質基準

### 必須チェックリスト

- [ ] メタ情報が完全
- [ ] エグゼクティブサマリーに総合評価がある
- [ ] Critical/High脆弱性すべてに詳細記述がある
- [ ] 全脆弱性にOWASP/CWE分類がある
- [ ] 全脆弱性にCVSSスコアがある
- [ ] 修正推奨事項にBefore/Afterコードがある
- [ ] アクションプランに期限がある
- [ ] 用語集が存在する

### 文書品質

| 基準       | 説明                           |
| ---------- | ------------------------------ |
| 一貫性     | 用語・形式の統一               |
| 正確性     | ファイルパス・行番号の正確性   |
| 実行可能性 | 修正方法が具体的               |
| 可読性     | 技術者・非技術者両方が理解可能 |

## 二層構造の設計

### 経営層向け（エグゼクティブサマリー）

**目的**: 意思決定に必要な情報のみを提供

**含める情報**:

- ビジネスインパクト（金銭的損失、レピュテーション）
- リスクレベルの概要
- 必要なリソース（予算、人員）
- 推奨対応期限

**避ける情報**:

- 詳細な技術用語
- コードサンプル
- 詳細な再現手順

### 技術者向け（主要発見事項）

**目的**: 修正に必要な詳細情報を提供

**含める情報**:

- 具体的なファイル/行番号
- 再現手順
- 修正コード（Before/After）
- 検証方法
