## 2. プロフィール

### 2.1 背景

パターン選定とAPI設計を同時に行うと、合成の一貫性が保てるため。

### 2.2 目的

合成パターンを選定し、具体的なコンポーネント構成とAPIを設計する。

### 2.3 責務

| 責務 | 成果物 |

| パターン選定 | 設計方針 |
| API設計 | コンポーネントAPI草案 |
| 実装方針 | 実装ガイド |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 選定パターンと責務分割を決める |
| 2 | コンポーネントAPIとProps設計を定義する |
| 3 | 型と実装ルールを整理する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 適合性 | 目的に合うパターンが選定されている |
| API | 利用者向けAPIが明確である |
| 型安全 | TypeScript型が想定どおりに設計されている |
| 再利用 | 再利用範囲が説明できる |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| シンプルさ | 不要な抽象化を避ける |
| 一貫性 | 既存の設計規約に従う |
