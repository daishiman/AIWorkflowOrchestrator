# Task: コードスメル分析

## 目的

対象コードからコードスメルを検出し、リファクタリングが必要な箇所を特定する。
優先度付きのスメル検出レポートを出力する。

## 入力

- 対象ソースコード（ファイルパスまたはコード本文）
- 分析スコープ（ファイル単位/ディレクトリ単位）

## 出力

スメル検出レポート:

```markdown
## スメル検出レポート

### 高優先度

- [ファイル:行] スメル種別 - 説明

### 中優先度

- [ファイル:行] スメル種別 - 説明

### 低優先度

- [ファイル:行] スメル種別 - 説明

### 推奨対応順序

1. ...
2. ...
```

## 手順

### Step 1: メトリクス収集

以下の基準でコードを分析:

| スメル種別          | 検出基準                            |
| ------------------- | ----------------------------------- |
| Long Method         | 30行を超えるメソッド                |
| Long Parameter      | パラメータ4個以上                   |
| Complex Conditional | ネスト3段階以上 or &&/\|\|が3つ以上 |
| Duplicated Code     | 3行以上の重複が2箇所以上            |
| Large Class         | 500行を超えるクラス                 |
| Magic Number        | 0,1,-1以外の数値リテラル            |

### Step 2: 優先度判定

**高優先度（即時対処）**:

- 重複コード → バグ修正時の漏れリスク
- 長大なメソッド → 可読性の大幅低下
- 複雑な条件式 → バグの温床

**中優先度（計画的対処）**:

- パラメータ過多
- データの群れ
- Feature Envy

**低優先度（余裕時に対処）**:

- マジックナンバー
- 基本データ型への固執

### Step 3: レポート生成

1. 検出されたスメルを優先度別に分類
2. 各スメルに対応するリファクタリングパターンを提示
3. 推奨対応順序を決定

## 制約

- 外部動作に影響しない範囲で分析
- テストカバレッジも併せて確認
- 誤検出の可能性がある場合は注記
