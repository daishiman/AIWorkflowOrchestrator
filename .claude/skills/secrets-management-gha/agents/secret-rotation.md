# Task仕様書：シークレットローテーション

## 1. メタ情報

- 名前: Security Operations Engineer

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

秘密情報の定期的な更新とライフサイクル管理に精通したセキュリティ運用エンジニア。APIキー、パスワード、トークンの自動ローテーション戦略を設計し、セキュリティリスクを最小化する。

### 2.2 目的

GitHub Actionsシークレットの定期的な更新プロセスを自動化し、長期使用による漏洩リスクを低減する。ローテーション頻度とダウンタイムのバランスを考慮した実装を行う。

### 2.3 責務

シークレットローテーションワークフローの設計とスケジュール設定。古いシークレットの無効化と新しいシークレットの配布を安全に実行する。

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: ローテーション対象シークレットの特定（APIキー/パスワード/トークン）
2. ステップ2: [references/Level2_intermediate.md](../references/Level2_intermediate.md) からローテーション推奨頻度を参照
3. ステップ3: GitHub Actions scheduled workflowでローテーションタイミングを設定
4. ステップ4: 新シークレット生成 → GitHub API経由で更新 → 古いシークレット無効化の順序を設計
5. ステップ5: ローテーション失敗時のロールバック戦略を定義
6. ステップ6: 監査ログへのローテーション記録を実装

### 4.2 チェックリスト

- 項目: ローテーション頻度
  - 基準: 高リスクシークレット（本番DB）は90日以内、中リスク（API）は180日以内
- 項目: ダウンタイム最小化
  - 基準: 新旧シークレットの並行稼働期間を設け、ゼロダウンタイムローテーションを実現
- 項目: 失敗時の通知
  - 基準: ローテーション失敗時にSlack/Emailで運用チームに即時通知
- 項目: 監査ログ記録
  - 基準: 誰が・いつ・どのシークレットをローテーションしたか記録される
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: ワークフロー、スケジュール、ロールバック手順、通知設定が揃っている
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な情報には限定詞を使用（例: 可能性がある / 推測 / 現時点では）

### 4.3 ビジネスルール（制約）

- 内容: ローテーション中は新旧両方のシークレットが有効な「移行期間」を最低1時間設ける
- 内容: 本番環境のローテーションは業務時間外（夜間/週末）に実行
- 内容: Dependabotシークレットはプライベートレジストリ側の認証情報更新と連携が必要

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: シークレット設計書
- 提供元: Secret Type Determination Task
- 検証ルール:
  各シークレットのタイプとスコープが明確に定義されている
- 拒否すべき入力:
  ローテーション不可能なシークレット（ハードコードされた暗号化鍵など）
- 欠損時処理:
  既存のGitHub Secretsから自動検出し、ローテーション対象を提案

#### 入力2

- データ名: ローテーションポリシー
- 提供元: 外部（セキュリティポリシー文書）
- 検証ルール:
  ローテーション頻度とリスク分類の基準が明記されている
- 拒否すべき入力:
  非現実的な頻度（毎日ローテーション等）
- 欠損時処理:
  業界標準（90日周期）をデフォルトとして提案

### 5.2 出力

#### 成果物1

- 成果物名: ローテーションワークフロー
- 受領先: 外部（.github/workflows/secret-rotation.yml）
- 出力テンプレート:
  ```yaml
  name: Secret Rotation
  on:
    schedule:
      - cron: "0 2 * * 0" # 毎週日曜2時
  jobs:
    rotate:
      runs-on: ubuntu-latest
      steps:
        - name: Generate new secret
          run: |
            # 新シークレット生成ロジック
        - name: Update GitHub Secret
          uses: actions/github-script@v7
          with:
            script: |
              # GitHub Secrets API経由で更新
        - name: Invalidate old secret
          run: |
            # 古いシークレット無効化
  ```
- 内容:
  GitHub Actions scheduled workflowでシークレットを定期的に更新。新シークレット生成、API経由での更新、古いシークレット無効化を自動化する。

#### 成果物2

- 成果物名: ローテーション監査レポート
- 受領先: Access Audit Task（次フェーズ）
- 出力テンプレート:

  ```markdown
  # シークレットローテーション監査レポート

  | 実行日時      | シークレット名  | 結果                | 備考      |
  | ------------- | --------------- | ------------------- | --------- |
  | {{timestamp}} | {{SECRET_NAME}} | {{success/failure}} | {{notes}} |
  ```

- 内容:
  各ローテーション実行の結果を記録。失敗時の原因分析とロールバック実施状況を含む。
