# Task仕様書：自動更新設定

## 1. メタ情報

- 名前: 自動更新設定タスク

> 注記: この名前はタスクの役割を示すラベル。思考様式の参照として使用する。

---

## 2. プロフィール

### 2.1 背景

Electronアプリケーションに自動更新機構を組み込み、エンドユーザーが常に最新版を使用できる仕組みを構築する専門タスク。electron-updaterの設定とアップデートサーバーの連携に精通している。

### 2.2 目的

インストーラー生成後、自動更新に必要なメタデータファイルを生成し、アップデートサーバーへの配布準備を完了する。

### 2.3 責務

- electron-updater設定の検証
- アップデートメタデータ（latest.yml等）の生成
- 段階的ロールアウト設定の構築
- アップデートサーバー連携の確認
- 自動更新設定レポートの作成

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: インストーラー生成結果を確認（ファイルパス、チェックサム）
2. ステップ2: package.jsonのpublish設定を検証
3. ステップ3: アップデートメタデータファイル（latest.yml, latest-mac.yml等）を生成
4. ステップ4: 段階的ロールアウト設定を適用（パーセンテージベース）
5. ステップ5: アップデートサーバーのエンドポイントを確認
6. ステップ6: 署名検証設定を追加（公開鍵の配布）
7. ステップ7: 自動更新設定結果をレポート

### 4.2 チェックリスト

- 項目: インストーラー確認
  - 基準: 全プラットフォームのインストーラーが生成されていること
- 項目: publish設定
  - 基準: package.jsonのbuild.publishセクションが適切に設定されていること
- 項目: メタデータ生成
  - 基準: latest.ymlファイルが正しいフォーマットで生成されること
- 項目: 署名検証
  - 基準: アップデートファイルの署名検証が有効化されていること
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: 設定結果にupdate_server, channels, rollout_percentage, signature_verificationが含まれる
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 更新動作の予測には「想定」「期待」などの限定詞を使用

### 4.3 ビジネスルール（制約）

- 内容: 自動更新は必ず署名検証を有効化
- 内容: 段階的ロールアウトは初期10%、1週間後50%、2週間後100%のスケジュールを推奨
- 内容: ロールバック用に直前バージョンを保持

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: インストーラー生成レポート
- 提供元: generate-installers タスク
- 検証ルール:
  statusが"success"で、全プラットフォームのインストーラー情報が含まれること
- 拒否すべき入力:
  statusが"failure"、またはチェックサムが欠損しているレポート
- 欠損時処理:
  エラーを返し、インストーラー生成タスクの再実行を促す

#### 入力2

- データ名: アップデートサーバー設定
- 提供元: 外部（設定ファイルまたは環境変数）
- 検証ルール:
  有効なURL（https://）であること
- 拒否すべき入力:
  http://（非暗号化）、存在しないドメイン
- 欠損時処理:
  エラーを返し、アップデートサーバーの設定を促す

### 5.2 出力

#### 成果物1

- 成果物名: electron-updater設定ファイル
- 受領先: アプリケーション本体（package.json）
- 出力テンプレート:
  ```json
  {
    "publish": [
      {
        "provider": "generic",
        "url": "https://updates.example.com/releases"
      }
    ],
    "updater": {
      "allowDowngrade": false,
      "allowPrerelease": false
    }
  }
  ```
- 内容:
  electron-updaterが参照する更新設定

#### 成果物2

- 成果物名: アップデートメタデータファイル
- 受領先: アップデートサーバー
- 出力テンプレート:
  ```yaml
  version: 1.0.0
  files:
    - url: AppName-1.0.0.dmg
      sha512: abcd1234...
      size: 52428800
  path: AppName-1.0.0.dmg
  sha512: abcd1234...
  releaseDate: "2025-01-01T00:00:00.000Z"
  ```
- 内容:
  各プラットフォーム用のアップデートメタデータ（latest.yml, latest-mac.yml等）

#### 成果物3

- 成果物名: 自動更新設定レポート
- 受領先: ログ記録（scripts/log_usage.mjs）
- 出力テンプレート:
  ```json
  {
    "status": "success|failure",
    "update_server": "https://updates.example.com/releases",
    "channels": ["stable", "beta"],
    "rollout_percentage": 10,
    "signature_verification": true,
    "metadata_files": ["latest.yml", "latest-mac.yml", "latest-linux.yml"],
    "errors": []
  }
  ```
- 内容:
  自動更新設定の完了状態と詳細情報
