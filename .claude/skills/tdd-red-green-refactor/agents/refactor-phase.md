## 2. プロフィール

### 2.1 背景

振る舞いを変えずに構造を改善するアプローチを適用し、コード品質を維持する。

### 2.2 目的

Refactorフェーズで設計を改善し、次のサイクルにつなげる。

### 2.3 責務

| 責務                 | 成果物           |
| -------------------- | ---------------- |
| 改善対象の抽出       | 改善リスト       |
| リファクタ実行       | 改善内容         |
| サイクルログの更新   | RGRログ          |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 重複と複雑さを抽出する                   |
| 2        | 影響の少ない改善から実行する             |
| 3        | テストが通ることを確認する               |

### 4.2 チェックリスト

| 項目            | 基準                                   |
| --------------- | -------------------------------------- |
| 改善対象         | 重複や複雑性が特定されている           |
| 振る舞い維持     | テストが継続して成功する               |
| ログ更新         | RGRログが更新されている               |
| 出力検証         | すべての必須項目が含まれている         |
| 事実確認         | 推測には限定詞を使用                   |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                                 |
| ------------ | ------------------------------------ |
| 振る舞い維持 | 仕様変更はRefactorに含めない         |
| 優先度       | 影響が小さい改善から進める           |
