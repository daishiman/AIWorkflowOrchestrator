# 見積もり手法ガイド

> 相対パス: `references/estimation-methods.md`
> 原典: Agile Estimating and Planning (Mike Cohn)

---

## 見積もり手法の選択基準

| 手法                | チーム規模 | 適用場面                         | 精度 |
| ------------------- | ---------- | -------------------------------- | ---- |
| Planning Poker      | 3-9人      | スプリント計画、リファインメント | 高   |
| T-Shirt Sizing      | 任意       | ロードマップ、初期見積もり       | 中   |
| Affinity Estimation | 大規模     | 大量バックログの一括見積もり     | 中   |
| Dot Voting          | 任意       | 優先順位付け                     | 低   |

---

## フィボナッチ数列

| ポイント | 複雑度 | 目安                     |
| -------- | ------ | ------------------------ |
| 1        | 最小   | 1時間〜半日で完了        |
| 2        | 小     | 半日〜1日で完了          |
| 3        | 中小   | 1〜2日で完了             |
| 5        | 中     | 2〜3日で完了             |
| 8        | 中大   | 3〜5日で完了（分割検討） |
| 13       | 大     | 1週間以上（要分割）      |
| 21       | 特大   | 要分割（見積もり困難）   |

**注意**: 時間は目安であり、相対的な複雑度を示す

---

## 基準ストーリーの選定

| 条件           | 説明                            |
| -------------- | ------------------------------- |
| 中程度の複雑度 | 3-5ポイント（スケールの中央値） |
| チーム共通理解 | 全員が要件と実装を理解          |
| 過去の実績     | 実際に完了した経験あり          |
| 参照可能       | いつでも確認できる状態          |

---

## 見積もりのアンチパターン

| パターン         | 問題                     | 対策               |
| ---------------- | ------------------------ | ------------------ |
| 時間見積もり     | 個人差、プレッシャー     | 相対ポイントを使用 |
| アンカリング     | 最初の発言に引きずられる | 同時開示を徹底     |
| 過去への固執     | 状況変化を無視           | 定期的な再評価     |
| 精度の個人責任化 | チーム学習を阻害         | チーム全体の責任   |
