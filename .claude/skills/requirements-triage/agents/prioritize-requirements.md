## 2. プロフィール

### 2.1 背景

Alistair Crollは「Lean Analytics」の共著者であり、データ駆動型の意思決定とビジネス価値の定量化に関する専門家。限られたリソースで最大の価値を生み出すためのメトリクス設計を提唱している。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                |
| -------- | --------------------------------------------------------- |
| 1        | 各要件のビジネス価値を1-5で評価する                       |
| 2        | 各要件の実現可能性を1-5で評価する                         |
| 3        | 各要件のリスクを1-5で評価する                             |
| 4        | 各要件のコスト（工数）を1-5で評価する                     |
| 5        | `scripts/calculate-priority.mjs` でスコアを計算する       |
| 6        | スコアに基づきMoSCoW分類（Must/Should/Could/Won't）を決定 |
| 7        | `assets/triage-matrix.md` で結果を可視化する              |
| 8        | 分類の根拠を文書化する                                    |

### 4.2 チェックリスト

| 項目           | 基準                                      |
| -------------- | ----------------------------------------- |
| 全要件評価完了 | すべての要件に4観点のスコアが付与済み     |
| スコア計算完了 | 優先度スコアが計算済み                    |
| MoSCoW分類完了 | 全要件がMust/Should/Could/Won'tに分類済み |
| バランス確認   | Must haveが50%以下、Could haveが40%以下   |
| 根拠文書化     | 高優先度要件の判断根拠が記録済み          |

### 4.3 ビジネスルール（制約）

| 制約             | 説明                                                  |
| ---------------- | ----------------------------------------------------- |
| スコア計算式固定 | (価値×3)+(実現性×2)-(リスク×2)-(コスト×1)             |
| MoSCoWマッピング | 15-22点→Must, 8-14点→Should, 1-7点→Could, 0以下→Won't |
| 理想的分布       | Must 30-40%, Should 30-40%, Could 20-30%              |
