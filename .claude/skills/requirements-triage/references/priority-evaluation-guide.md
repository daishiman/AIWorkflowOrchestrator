# 優先度評価ガイド

## 概要

要件の優先度を定量的に評価するためのスコアリング手法を解説する。
4観点（ビジネス価値・実現可能性・リスク・コスト）に基づく評価により、客観的な優先順位付けを実現する。

## 評価観点

### 1. ビジネス価値 (Business Value)

要件がビジネス目標にどれだけ貢献するかを評価する。

| スコア | 説明               | 例                         |
| ------ | ------------------ | -------------------------- |
| 5      | プロジェクトの中核 | 主要機能、差別化要素       |
| 4      | 大きな価値         | ユーザー体験向上、収益増加 |
| 3      | 中程度の価値       | 効率化、改善               |
| 2      | 限定的な価値       | 一部ユーザーのみ利用       |
| 1      | ほとんど価値なし   | nice-to-have、装飾的機能   |

### 2. 実現可能性 (Feasibility)

技術的・リソース的に実装がどれだけ容易かを評価する。

| スコア | 説明                 | 例                           |
| ------ | -------------------- | ---------------------------- |
| 5      | 容易に実装可能       | 既存技術で対応、経験豊富     |
| 4      | 一部調査必要         | 軽微な技術調査が必要         |
| 3      | 技術的チャレンジあり | 新技術の導入、学習コスト発生 |
| 2      | 高度な技術必要       | 専門家の支援が必要           |
| 1      | 実現困難             | 技術的に未成熟、リソース不足 |

### 3. リスク (Risk)

要件に関連するリスクの大きさを評価する。

| スコア | 説明           | 例                         |
| ------ | -------------- | -------------------------- |
| 5      | 重大リスク     | セキュリティ、法的問題     |
| 4      | 高リスク       | 大規模な依存関係、外部要因 |
| 3      | 中程度のリスク | 技術的不確実性             |
| 2      | 低リスク       | 軽微な課題                 |
| 1      | リスクなし     | 完全に予測可能             |

### 4. コスト (Cost/Effort)

実装に必要な工数・リソースを評価する。

| スコア | 説明      | 例                 |
| ------ | --------- | ------------------ |
| 5      | 6ヶ月以上 | 大規模プロジェクト |
| 4      | 3-6ヶ月   | 中規模機能         |
| 3      | 1-3ヶ月   | 標準的な機能開発   |
| 2      | 1-4週間   | 小規模機能         |
| 1      | 1週間未満 | 軽微な修正         |

## スコア計算式

```
優先度スコア = (ビジネス価値 × 3) + (実現可能性 × 2) - (リスク × 2) - (コスト × 1)
```

### 重み付けの根拠

| 観点         | 重み | 符号 | 理由                               |
| ------------ | ---- | ---- | ---------------------------------- |
| ビジネス価値 | 3    | +    | 価値創出が最優先                   |
| 実現可能性   | 2    | +    | 実装確実性は重要                   |
| リスク       | 2    | -    | リスクは価値を減衰させる           |
| コスト       | 1    | -    | コストは考慮するが過度に重視しない |

### スコア範囲

- **最高スコア**: (5×3) + (5×2) - (1×2) - (1×1) = 22点
- **最低スコア**: (1×3) + (1×2) - (5×2) - (5×1) = -10点

## MoSCoW分類マッピング

| スコア範囲 | MoSCoW分類  | 説明                           |
| ---------- | ----------- | ------------------------------ |
| 15-22点    | Must have   | 必須、プロジェクト成功に不可欠 |
| 8-14点     | Should have | 重要だが必須ではない           |
| 1-7点      | Could have  | あれば便利                     |
| 0点以下    | Won't have  | 今回は対象外                   |

## 代替手法

### RICE スコアリング

| 観点           | 計算式                                 |
| -------------- | -------------------------------------- |
| Reach          | 影響を受けるユーザー数                 |
| Impact         | 1人あたりの影響度(0.25-3)              |
| Confidence     | 確信度(0-100%)                         |
| Effort         | 必要な工数（人月）                     |
| **RICEスコア** | (Reach × Impact × Confidence) / Effort |

### Kano モデル

| カテゴリ   | 説明                             |
| ---------- | -------------------------------- |
| 基本品質   | あって当然、なければ不満         |
| 一元的品質 | 充足度に比例して満足度向上       |
| 魅力的品質 | なくても不満なし、あれば大満足   |
| 無関心品質 | あってもなくても満足度に影響なし |
| 逆品質     | あると不満、ないと満足           |

## 実践のポイント

### 評価時の注意点

- 複数人で評価し、偏りを防ぐ
- 評価基準を事前に共有する
- 定期的に評価を見直す

### よくある間違い

| 間違い           | 対策                         |
| ---------------- | ---------------------------- |
| すべて高評価     | 相対評価を意識する           |
| リスクを過小評価 | 最悪ケースを想定する         |
| コストを楽観視   | バッファを含める             |
| 主観的な評価のみ | データに基づく判断を追加する |
