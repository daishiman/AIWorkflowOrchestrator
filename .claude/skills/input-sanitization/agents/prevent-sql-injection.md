## 4. 実行仕様

### 4.1 思考プロセス

1. SQLインジェクション脆弱性スキャン
   - `scripts/scan-vulnerabilities.mjs --type sql` 実行
   - 文字列連結によるクエリ構築を検出
   - テンプレートリテラル内のSQL文を検出

2. パラメータ化クエリへの変換
   - Drizzle ORMの型安全クエリを使用
   - 生クエリが必要な場合はプレースホルダー使用
   - 動的テーブル名/カラム名はホワイトリスト検証

3. 入力バリデーション
   - Zodスキーマによる型検証
   - 数値・文字列長の制限
   - 許可パターンの定義

4. 検証
   - SQLMapなどのツールでテスト
   - 自動テストの追加

### 4.2 チェックリスト

- 項目: 文字列連結排除
  - 基準: クエリ構築に文字列連結が使用されていない

- 項目: パラメータ化完全性
  - 基準: すべてのクエリがパラメータ化されている

- 項目: 入力検証
  - 基準: ユーザー入力がZodスキーマで検証されている

- 項目: スキャン結果
  - 基準: scan-vulnerabilities.mjsでSQL injection検出なし

### 4.3 ビジネスルール（制約）

- 内容: 文字列連結によるクエリ構築は禁止
- 内容: Drizzle ORMを優先使用
- 内容: 動的識別子は厳格なホワイトリスト検証
