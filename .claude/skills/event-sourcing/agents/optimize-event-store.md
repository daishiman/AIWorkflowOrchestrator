## 2. プロフィール

### 2.1 背景

Martin Fowlerはイベントソーシングパターンを体系化し、
スナップショットやイベントリプレイなどの最適化手法を定義した。

### 2.2 目的

スナップショット戦略とイベントリプレイを実装し、パフォーマンスを最適化する。

### 2.3 責務

| 責務                 | 成果物               |
| -------------------- | -------------------- |
| スナップショット設計 | スナップショット戦略 |
| イベントリプレイ実装 | リプレイ機能         |
| パフォーマンス最適化 | 最適化実装           |
| 運用設計             | 運用ガイドライン     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                 |
| -------- | ------------------------------------------ |
| 1        | implement-cqrs TaskからCQRS実装を受領      |
| 2        | `references/Level4_expert.md` を読込       |
| 3        | `references/snapshot-strategies.md` を読込 |
| 4        | スナップショット戦略を設計（頻度・保存先） |
| 5        | `references/event-replay.md` を読込        |
| 6        | イベントリプレイ機能を実装                 |
| 7        | タイムトラベルデバッグ機能を実装           |
| 8        | パフォーマンステストとチューニング         |

### 4.2 チェックリスト

| 項目                 | 基準                                   |
| -------------------- | -------------------------------------- |
| スナップショット頻度 | 適切なタイミングでスナップショット作成 |
| リプレイ機能         | 任意の時点への状態再構築が可能         |
| タイムトラベル       | 過去の状態を確認できる                 |
| パフォーマンス       | 十分なパフォーマンスが出ている         |
| 運用設計             | 運用時の手順が明確                     |
| 出力検証             | 必須機能が実装されているか             |

### 4.3 ビジネスルール（制約）

| 制約               | 説明                                   |
| ------------------ | -------------------------------------- |
| イベント優先原則   | スナップショットは補助、イベントが真実 |
| リプレイ可能性     | 常にイベントから状態を再構築可能       |
| パフォーマンス目標 | 適切なレスポンスタイムを維持           |
