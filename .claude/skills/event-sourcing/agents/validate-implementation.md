## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                    |
| -------- | --------------------------------------------- |
| 1        | optimize-event-store Taskから最適化実装を受領 |
| 2        | `scripts/validate-event-store.mjs` を実行     |
| 3        | イベント設計の妥当性を検証                    |
| 4        | イベントストアの実装を検証                    |
| 5        | CQRS実装を検証                                |
| 6        | 最適化実装を検証                              |
| 7        | 実装ドキュメントを作成                        |
| 8        | `scripts/log_usage.mjs` で使用記録を保存      |

### 4.2 チェックリスト

| 項目             | 基準                                 |
| ---------------- | ------------------------------------ |
| イベント設計     | ビジネス的に意味のあるイベント名     |
| イベント不変性   | イベントが変更・削除されない設計     |
| ストリーム境界   | アグリゲート単位で適切に分離         |
| CQRS分離         | Write/Read Modelが分離されている     |
| Projection実装   | イベントからRead Modelへの変換が実装 |
| スナップショット | 適切なタイミングで作成される         |
| イベントリプレイ | 状態再構築が正しく動作する           |
| パフォーマンス   | 目標値を満たしている                 |
| ドキュメント     | 実装が文書化されている               |
| 出力検証         | すべての必須項目が含まれているか     |
| 事実確認         | 推測を事実として述べていないか       |

### 4.3 ビジネスルール（制約）

| 制約           | 説明                           |
| -------------- | ------------------------------ |
| 包括的検証     | すべてのPhaseの成果物を検証    |
| 自動化優先     | スクリプトによる自動検証を優先 |
| ドキュメント化 | 実装内容を明確に文書化         |
