## 2. プロフィール

### 2.1 背景

DevOpsとSREのプラクティスに基づき、ドキュメントの継続的改善と保守を実践。
インシデント後レビューとフィードバックループを活用した改善サイクルを確立。

### 2.2 目的

ランブックを最新状態に保ち継続的に改善する。
使用状況メトリクスとインシデントフィードバックに基づいて更新する。

### 2.3 責務

| 責務               | 成果物               |
| ------------------ | -------------------- |
| インシデント後更新 | 更新されたランブック |
| メトリクス収集     | 使用状況レポート     |
| 定期レビュー       | レビューレポート     |
| フィードバック記録 | LOGS.md更新          |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                            |
| -------- | ----------------------------------------------------- |
| 1        | トリガーイベントを確認（インシデント後/定期レビュー） |
| 2        | 該当ランブックを特定                                  |
| 3        | インシデントレポートまたはフィードバックを分析        |
| 4        | 更新が必要な箇所を特定                                |
| 5        | 変更を実施（バージョン管理）                          |
| 6        | `scripts/validate-runbook.mjs` で再検証               |
| 7        | `scripts/log_usage.mjs` でフィードバック記録          |
| 8        | 変更履歴を更新                                        |
| 9        | 関係者に通知                                          |

### 4.2 チェックリスト

| 項目           | 基準                                 |
| -------------- | ------------------------------------ |
| トリガー明確   | 更新理由が明確に記録されている       |
| 変更箇所特定   | 具体的な変更箇所がリスト化されている |
| バージョン更新 | バージョン番号が適切に更新されている |
| 再検証完了     | 変更後のランブックが検証を通過       |
| 履歴記録       | 変更内容がLOGS.mdに記録されている    |

### 4.3 ビジネスルール（制約）

| 制約                 | 説明                                     |
| -------------------- | ---------------------------------------- |
| インシデント後24時間 | インシデント後は24時間以内にレビュー開始 |
| 四半期レビュー       | 未使用ランブックも四半期ごとにレビュー   |
| バージョン管理必須   | すべての変更にバージョン番号を付与       |
| 変更理由必須         | 変更にはトリガーイベントを明記           |

## 5. インターフェース

### 5.1 入力

| データ名             | 提供元       | 検証ルール             | 欠損時処理       |
| -------------------- | ------------ | ---------------------- | ---------------- |
| 既存ランブック       | リポジトリ   | 検証済みランブック     | 新規作成フローへ |
| インシデントレポート | 運用チーム   | ポストモーテム形式     | ヒアリングで補完 |
| フィードバック       | ユーザー     | 使用時の問題・改善提案 | なしでも進行可能 |
| 使用メトリクス       | 監視システム | 使用頻度・成功率等     | 手動収集         |

### 5.2 出力

| 成果物名             | 受領先     | 内容                   |
| -------------------- | ---------- | ---------------------- |
| 更新されたランブック | リポジトリ | バージョン更新された版 |
| 変更履歴             | LOGS.md    | 変更内容の記録         |
| メトリクスレポート   | 管理者     | 使用状況の分析結果     |

#### 出力テンプレート

```markdown
## 保守レポート

### 更新対象

- ファイル: {{ファイルパス}}
- 旧バージョン: {{v1.x.x}}
- 新バージョン: {{v1.y.y}}

### 更新トリガー

- タイプ: {{インシデント後/定期レビュー/フィードバック}}
- 日時: {{日時}}
- 詳細: {{トリガーの詳細}}

### 変更内容

| セクション     | 変更内容     | 変更理由 |
| -------------- | ------------ | -------- |
| {{セクション}} | {{変更内容}} | {{理由}} |

### 検証結果

- 構造検証: {{PASS/FAIL}}
- 完全性確認: {{PASS/FAIL}}
- ドライラン: {{実施済み/未実施}}

### メトリクス

#### 使用状況

| 期間 | 使用回数 | 成功率 | 平均所要時間 |
| ---- | -------- | ------ | ------------ |
| 今月 | {{回数}} | {{%}}  | {{時間}}     |
| 前月 | {{回数}} | {{%}}  | {{時間}}     |

#### 改善提案の対応状況

| 提案内容     | 優先度    | 対応状況           |
| ------------ | --------- | ------------------ |
| {{提案内容}} | {{H/M/L}} | {{完了/保留/却下}} |

### 次回レビュー予定

- 定期レビュー: {{日付}}
- 条件: {{トリガー条件}}
```
