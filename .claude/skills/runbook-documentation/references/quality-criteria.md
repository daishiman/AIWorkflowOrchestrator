# ランブック品質基準

> **読込条件**: 検証・レビュー時

---

## 1. 必須要素チェックリスト

### 1.1 構造要素

| 要素                   | 必須/推奨 | 確認内容                         |
| ---------------------- | --------- | -------------------------------- |
| タイトル               | 必須      | 何のランブックか一目で分かる     |
| 目的                   | 必須      | このランブックを使う理由が明確   |
| 適用条件               | 必須      | いつ使うべきかの判断基準         |
| 前提条件               | 必須      | 必要なアクセス権限、ツール、知識 |
| 手順                   | 必須      | 番号付き、各ステップが明確       |
| 期待される結果         | 必須      | 各ステップの成功判定基準         |
| エスカレーション       | 必須      | いつ誰にエスカレートするか       |
| ロールバック手順       | 推奨      | 失敗時の復旧方法                 |
| トラブルシューティング | 推奨      | よくある問題と対処法             |
| メタデータ             | 推奨      | 最終更新日、担当者、レビュー日   |

### 1.2 内容品質

| 項目   | 基準                         |
| ------ | ---------------------------- |
| 明確性 | 曖昧な表現がない             |
| 完全性 | 必要な情報が全て含まれている |
| 正確性 | 情報が正確で最新             |
| 一貫性 | 用語、形式が統一されている   |

## 2. 禁止事項

### 2.1 曖昧な表現

| 禁止表現         | 問題点             | 改善例                   |
| ---------------- | ------------------ | ------------------------ |
| 「適切に」       | 何が適切か不明     | 具体的な基準を記載       |
| 「必要に応じて」 | 判断基準が不明     | 条件を明記               |
| 「しばらく待つ」 | 時間が不明         | 「5分待つ」等具体的に    |
| 「確認する」     | 何をどう確認か不明 | 確認項目と方法を明記     |
| 「適宜」         | 判断が曖昧         | 具体的なタイミングを記載 |

### 2.2 構造的問題

| 禁止事項             | 問題点                   |
| -------------------- | ------------------------ |
| 複数目的の混在       | 使い分けが困難           |
| 暗黙の前提知識       | 初見で実行できない       |
| 手順の欠落           | 実行が途中で止まる       |
| エラーケースの未記載 | 予期しない状況で停止     |
| 属人化表現           | 「○○さんに聞いて」は禁止 |

## 3. 品質レベル定義

### 3.1 スコアリング基準

| レベル | スコア | 基準                            |
| ------ | ------ | ------------------------------- |
| A      | 90-100 | 全必須項目満たし、推奨も80%以上 |
| B      | 70-89  | 全必須項目満たす                |
| C      | 50-69  | 必須項目に軽微な不足あり        |
| D      | 0-49   | 複数の必須項目が欠落            |

### 3.2 評価項目と配点

| カテゴリ | 項目                     | 配点 |
| -------- | ------------------------ | ---- |
| 構造     | タイトル・目的・適用条件 | 15   |
| 構造     | 前提条件                 | 10   |
| 手順     | ステップの明確さ         | 20   |
| 手順     | 期待結果の記載           | 15   |
| 安全性   | ロールバック手順         | 15   |
| 安全性   | エスカレーション         | 15   |
| 保守性   | メタデータ・履歴         | 10   |
| **合計** |                          | 100  |

## 4. レビュー観点

### 4.1 技術レビュー

| 観点             | 確認事項                       |
| ---------------- | ------------------------------ |
| コマンドの正確性 | 記載されたコマンドは動作するか |
| 設定値の正確性   | 設定値やパラメータは正しいか   |
| 環境の考慮       | 環境依存部分が明示されているか |
| セキュリティ     | 機密情報の扱いは適切か         |

### 4.2 運用レビュー

| 観点             | 確認事項                     |
| ---------------- | ---------------------------- |
| 実行可能性       | 実際の運用で使えるか         |
| 時間見積もり     | 想定所要時間は妥当か         |
| エスカレーション | エスカレーション基準は適切か |
| ロールバック     | ロールバック手順は現実的か   |

### 4.3 可読性レビュー

| 観点           | 確認事項                       |
| -------------- | ------------------------------ |
| 構造の論理性   | 流れが自然で理解しやすいか     |
| 用語の一貫性   | 用語が統一されているか         |
| フォーマット   | Markdownフォーマットが正しいか |
| リンクの有効性 | 参照リンクが有効か             |

## 5. 検証チェックリスト

### 5.1 自動検証項目

| 項目                 | ツール                 | 合格基準         |
| -------------------- | ---------------------- | ---------------- |
| 必須セクション存在   | validate-runbook.mjs   | エラーなし       |
| Markdownフォーマット | validate-runbook.mjs   | パースエラーなし |
| リンク有効性         | validate-runbook.mjs   | デッドリンクなし |
| 完全性               | check-completeness.mjs | 必須項目100%     |

### 5.2 手動検証項目

| 項目         | 検証方法     | 合格基準         |
| ------------ | ------------ | ---------------- |
| 実行可能性   | ドライラン   | 手順通り実行可能 |
| 理解容易性   | ピアレビュー | 初見で理解可能   |
| 時間見積もり | ドライラン   | 見積もり±20%以内 |

## 6. 改善優先度マトリクス

| 影響度＼緊急度 | 高               | 中                 | 低                 |
| -------------- | ---------------- | ------------------ | ------------------ |
| 高             | 即座に修正       | 24時間以内に修正   | 1週間以内に修正    |
| 中             | 24時間以内に修正 | 1週間以内に修正    | 次回レビューで検討 |
| 低             | 1週間以内に修正  | 次回レビューで検討 | バックログに追加   |

### 6.1 影響度の判断基準

| 影響度 | 基準                                     |
| ------ | ---------------------------------------- |
| 高     | 手順が実行できない、または誤操作のリスク |
| 中     | 効率が悪い、または理解に時間がかかる     |
| 低     | 体裁、フォーマットの問題                 |

### 6.2 緊急度の判断基準

| 緊急度 | 基準                                       |
| ------ | ------------------------------------------ |
| 高     | 頻繁に使用される、またはクリティカルな手順 |
| 中     | 定期的に使用される手順                     |
| 低     | 稀に使用される手順                         |
