# ランブック検証手法（Level 3）

> **読込条件**: Task 4（検証）開始時

---

## 1. 検証の目的と原則

### 1.1 検証の目的

| 目的       | 説明                                     |
| ---------- | ---------------------------------------- |
| 実行可能性 | 記載された手順で実際に実行できるか       |
| 完全性     | 必要な情報が全て含まれているか           |
| 明確性     | 曖昧な表現がなく、判断に迷わないか       |
| 安全性     | 危険な操作に適切な警告があるか           |
| 再現性     | 誰が実行しても同じ結果になるか           |
| 最新性     | 情報が最新か、古い情報が混在していないか |

### 1.2 検証の原則

| 原則             | 説明                           |
| ---------------- | ------------------------------ |
| 作成者以外が検証 | 作成者の暗黙の前提を排除       |
| 実環境に近い検証 | 本番に近い環境でテスト         |
| 複数観点の検証   | 技術的・運用的・ビジネス的観点 |
| 文書化           | 検証結果を記録し、改善に活用   |

---

## 2. 自動検証

### 2.1 構造検証（validate-runbook.mjs）

| 検証項目             | 内容                         |
| -------------------- | ---------------------------- |
| 必須セクション存在   | タイトル、目的、手順等の存在 |
| Markdownフォーマット | 正しいMarkdown構文           |
| リンクの有効性       | 内部/外部リンクが有効か      |
| コードブロックの構文 | 言語指定、閉じタグの確認     |

### 2.2 完全性確認（check-completeness.mjs）

| 検証項目         | 基準                       |
| ---------------- | -------------------------- |
| メタデータ完備   | 更新日、担当者、バージョン |
| 前提条件明示     | アクセス権限、必要ツール   |
| 手順の番号付け   | 全ステップが番号付き       |
| 期待結果の記載   | 各ステップに成功基準       |
| エスカレーション | 連絡先と基準が明記         |

---

## 3. ドライラン（机上演習）

### 3.1 ドライランの進め方

| ステップ | 内容                                   |
| -------- | -------------------------------------- |
| 1        | 参加者を選定（作成者以外を含む）       |
| 2        | シナリオを設定（想定するインシデント） |
| 3        | ランブックに従って手順を読み上げ       |
| 4        | 各ステップで疑問点・不明点を記録       |
| 5        | エスカレーション判断を確認             |
| 6        | フィードバックをまとめ、改善点を特定   |

### 3.2 ドライラン評価基準

| 評価項目     | 質問                           |
| ------------ | ------------------------------ |
| 理解容易性   | 初見で理解できたか？           |
| 実行可能性   | 記載通りに実行できそうか？     |
| 判断明確性   | 分岐点で迷わず判断できたか？   |
| 情報充足性   | 不足している情報はなかったか？ |
| 時間見積もり | 想定所要時間は妥当か？         |

---

## 4. ピアレビュー

### 4.1 レビュー観点

| 観点         | 確認事項                   |
| ------------ | -------------------------- |
| 技術的正確性 | コマンドや設定が正しいか   |
| 運用的妥当性 | 実際の運用で使えるか       |
| セキュリティ | 機密情報の扱いは適切か     |
| 可読性       | 読みやすく、理解しやすいか |
| 保守性       | 更新しやすい構造か         |

### 4.2 レビューチェックリスト

| カテゴリ         | チェック項目                       |
| ---------------- | ---------------------------------- |
| 形式             | [ ] Markdownフォーマットが正しい   |
| 内容             | [ ] 目的が明確に記述されている     |
| 内容             | [ ] 適用条件が具体的               |
| 内容             | [ ] 前提条件が網羅されている       |
| 手順             | [ ] 各ステップが明確で実行可能     |
| 手順             | [ ] 期待される結果が記載されている |
| 手順             | [ ] エラーケースが考慮されている   |
| 安全性           | [ ] ロールバック手順が存在         |
| 安全性           | [ ] 危険な操作に警告がある         |
| エスカレーション | [ ] 基準と連絡先が明確             |

---

## 5. 品質基準照合

### 5.1 品質チェックリスト

| 基準                 | 内容                         | 重要度 |
| -------------------- | ---------------------------- | ------ |
| 目的明確             | 1文で説明可能                | 必須   |
| 適用条件明示         | 数値または状態で判断可能     | 必須   |
| 前提条件完備         | 権限、ツール、知識がリスト化 | 必須   |
| 手順完全             | 番号付き、期待結果付き       | 必須   |
| ロールバック完備     | 失敗時の復旧パスが存在       | 必須   |
| エスカレーション明示 | いつ誰にが明確               | 必須   |
| 曖昧表現排除         | 「適切に」等の表現がない     | 推奨   |
| コマンド検証済み     | 実行確認済みのコマンド       | 推奨   |
| 想定所要時間         | 目安時間が記載               | 推奨   |

### 5.2 品質スコアリング

| スコア | 判定                 | 基準                                  |
| ------ | -------------------- | ------------------------------------- |
| A      | 即座に使用可能       | 全ての必須項目を満たし、推奨も80%以上 |
| B      | 軽微な修正で使用可能 | 全ての必須項目を満たす                |
| C      | 修正が必要           | 必須項目に不足あり                    |
| D      | 大幅な改善が必要     | 複数の必須項目が欠落                  |

---

## 6. 検証レポート作成

### 6.1 レポート構成

```markdown
## 検証レポート

### 対象ランブック

### 自動検証結果

### ドライラン結果

### ピアレビュー結果

### 品質基準照合

### 総合判定

### 改善提案
```

### 6.2 判定基準

| 判定           | 条件                                |
| -------------- | ----------------------------------- |
| APPROVED       | 品質スコアA or B、重大な問題なし    |
| NEEDS_REVISION | 品質スコアC、または重大な問題あり   |
| REJECTED       | 品質スコアD、または構造的な問題あり |
