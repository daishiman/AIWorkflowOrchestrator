## 概要

STRIDEフレームワークを用いたGitHub Actionsワークフローの脅威分析手法。体系的なセキュリティ設計を支援する。

## STRIDEフレームワーク

### 概要

| カテゴリ               | 説明         | CI/CDでの例              |
| ---------------------- | ------------ | ------------------------ |
| Spoofing               | なりすまし   | 偽装PRからの攻撃         |
| Tampering              | 改ざん       | 依存関係・成果物の改ざん |
| Repudiation            | 否認         | 操作の否認               |
| Information Disclosure | 情報漏洩     | シークレットのログ露出   |
| Denial of Service      | サービス拒否 | リソース枯渇攻撃         |
| Elevation of Privilege | 権限昇格     | 過剰な権限による不正操作 |

## CI/CDパイプラインの脅威シナリオ

### Spoofing（なりすまし）

**シナリオ**: 攻撃者がフォークPRを通じて悪意のあるコードを実行

**対策**:

- フォークPR制限の実装
- `pull_request_target` の慎重な使用
- コードレビューの必須化

**リスクスコア**: 発生確率: Medium(3) × 影響度: High(4) = 12

### Tampering（改ざん）

**シナリオ**: サプライチェーン攻撃による依存関係の改ざん

**対策**:

- 依存関係のバージョン固定（SHA）
- SCAツールによる脆弱性スキャン
- ロックファイルの使用

**リスクスコア**: 発生確率: Medium(3) × 影響度: Critical(5) = 15

### Repudiation（否認）

**シナリオ**: 不正なデプロイ操作の否認

**対策**:

- 監査ログの有効化
- デプロイ承認フローの導入
- ワークフロー実行履歴の保持

**リスクスコア**: 発生確率: Low(2) × 影響度: Medium(3) = 6

### Information Disclosure（情報漏洩）

**シナリオ**: シークレットのログ出力による漏洩

**対策**:

- ログマスキングの徹底
- シークレットの環境変数経由渡し
- デバッグログの本番無効化

**リスクスコア**: 発生確率: High(4) × 影響度: Critical(5) = 20

### Denial of Service（サービス拒否）

**シナリオ**: 無限ループワークフローによるリソース枯渇

**対策**:

- ワークフロータイムアウトの設定
- 同時実行数の制限
- コスト監視アラート

**リスクスコア**: 発生確率: Low(2) × 影響度: Medium(3) = 6

### Elevation of Privilege（権限昇格）

**シナリオ**: 過剰なGITHUB_TOKEN権限による不正操作

**対策**:

- 最小権限の原則
- ジョブレベルの権限分離
- 環境ごとのアクセス制御

**リスクスコア**: 発生確率: Medium(3) × 影響度: High(4) = 12

## リスクスコアリング

### 発生確率

| レベル    | スコア | 説明           |
| --------- | ------ | -------------- |
| Very Low  | 1      | ほぼ発生しない |
| Low       | 2      | まれに発生     |
| Medium    | 3      | 時々発生       |
| High      | 4      | 頻繁に発生     |
| Very High | 5      | ほぼ確実に発生 |

### 影響度

| レベル   | スコア | 説明         |
| -------- | ------ | ------------ |
| Minimal  | 1      | 影響なし     |
| Low      | 2      | 軽微な影響   |
| Medium   | 3      | 中程度の影響 |
| High     | 4      | 重大な影響   |
| Critical | 5      | 壊滅的な影響 |

### 優先度マトリクス

| スコア | 優先度   | 対応            |
| ------ | -------- | --------------- |
| 20-25  | Critical | 即時対応必須    |
| 15-19  | High     | 2週間以内に対応 |
| 10-14  | Medium   | 1ヶ月以内に対応 |
| 5-9    | Low      | 計画的に対応    |
| 1-4    | Minimal  | リスク受容可能  |

## 脅威モデリングプロセス

### 1. 資産の特定

- ソースコード
- シークレット（API キー、認証情報）
- ビルド成果物
- デプロイ環境

### 2. データフロー図の作成

```
[開発者] → [PR] → [GitHub Actions] → [ビルド] → [テスト] → [デプロイ] → [本番環境]
                         ↓
                    [シークレット]
```

### 3. 脅威の列挙

STRIDEの各カテゴリでデータフローの各ポイントを分析

### 4. リスク評価

発生確率 × 影響度 でスコアリング

### 5. 対策の決定

- 受容: リスクを許容
- 軽減: 対策を実装
- 移転: 保険・外部委託
- 回避: 機能を削除

### 6. 検証と監視

- 対策の有効性を検証
- 継続的な監視を設定
