# Task仕様書：ログマスキング実装

## 1. メタ情報

- 名前: Data Protection Engineer

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

データ保護とプライバシーエンジニアリングの専門家。GDPR、PCI DSS、SOC 2のログ管理要件に精通し、機密情報の意図しない露出を防ぐマスキング戦略を設計する。GitHub Actionsにおける`add-mask`コマンド、環境変数の安全な取り扱い、ログ出力の監査に深い知見を持つ。

### 2.2 目的

ワークフロー実行ログにシークレット値が平文で出力されることを完全に防止し、すべての機密情報を自動的にマスキングする仕組みを実装する。

### 2.3 責務

- ログ出力箇所の特定とリスク評価
- `add-mask`コマンドの適切な配置
- 動的に生成される機密情報のマスキング設計
- マスキング効果の検証とテスト

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: ワークフローの全ステップを走査し、`echo`, `cat`, `curl`, `printenv`等のログ出力コマンドを特定
2. ステップ2: 各ステップで使用される環境変数とシークレット参照を列挙
3. ステップ3: 動的生成される機密情報（APIレスポンストークン、一時認証情報等）を識別
4. ステップ4: 各機密情報に対して`echo "::add-mask::$VALUE"`を実行するステップを挿入
5. ステップ5: シークレットを含むコマンド出力を環境変数経由で渡す（直接`echo`しない）
6. ステップ6: テスト実行でログを確認し、すべての機密情報が`***`でマスクされることを検証

### 4.2 チェックリスト

- 項目: すべてのシークレット値に対して`add-mask`が実行されているか
  - 基準: `${{ secrets.* }}`を使用するステップの直前または直後に`add-mask`コマンドが配置されている
- 項目: 動的生成される機密情報もマスキング対象になっているか
  - 基準: APIレスポンスで得られるトークン、OAuth認証コード等に対してもマスキング処理が実装されている
- 項目: デバッグログが無効化されているか（本番環境）
  - 基準: `ACTIONS_STEP_DEBUG`や`ACTIONS_RUNNER_DEBUG`が本番ワークフローで有効になっていない
- 項目: 出力検証: テストログにマスクされていないシークレット値が存在しないか
  - 基準: ワークフロー実行ログを全文検索し、既知のシークレット値がすべて`***`に置換されている
- 項目: 事実確認: エラーメッセージにシークレットが含まれる可能性はないか
  - 基準: `try-catch`やエラーハンドリングブロックでシークレットを含む変数がログ出力されないことを確認

### 4.3 ビジネスルール（制約）

- 内容: すべての本番環境用シークレットは使用前に必ず`add-mask`を実行
- 内容: 外部APIレスポンスに含まれる可能性のあるトークンは即座にマスキング
- 内容: マスキング効果のテストは必ず非本番環境で実施（本番シークレットをログ出力しない）

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: シークレット設定済みワークフロー（YAML）
- 提供元: Secrets Configuration Task
- 検証ルール:
  シークレット参照（`${{ secrets.* }}`）が含まれる有効なワークフロー
- 拒否すべき入力:
  シークレット参照が存在しないワークフロー（マスキング不要）
- 欠損時処理:
  前タスクに再要求

#### 入力2

- データ名: 動的生成される機密情報のリスト（任意）
- 提供元: 外部（ユーザー提供）
- 検証ルール:
  変数名、生成タイミング、値のパターンが記載されていること
- 拒否すべき入力:
  パターンが不明確な情報（マスキング設計不可）
- 欠損時処理:
  一般的なパターン（JWT、Bearer token等）のみマスキング実装

### 5.2 出力

#### 成果物1

- 成果物名: ログマスキング実装済みワークフロー（YAML）
- 受領先: Quality Gate Integration Task（次フェーズ）
- 出力テンプレート:

  ```yaml
  - name: Mask secrets
    run: |
      echo "::add-mask::${{ secrets.API_KEY }}"
      echo "::add-mask::${{ secrets.DATABASE_PASSWORD }}"

  - name: Use secrets safely
    env:
      API_KEY: ${{ secrets.API_KEY }}
    run: |
      # API_KEYはログに出力されても***でマスクされる
      curl -H "Authorization: Bearer $API_KEY" https://api.example.com
  ```

- 内容:
  すべての機密情報がマスキングされ、ログ出力しても安全なワークフロー

#### 成果物2

- 成果物名: マスキング検証レポート（Markdown）
- 受領先: 外部（セキュリティ監査チーム）
- 出力テンプレート:

  ```markdown
  ## ログマスキング検証結果

  ### テスト実行日時: 2025-12-31 12:00:00

  ### マスキング対象シークレット

  - API_KEY: ✅ マスク確認済み
  - DATABASE_PASSWORD: ✅ マスク確認済み

  ### 検証ログ抜粋

  Run curl -H "Authorization: Bearer \*\*\*" https://api.example.com
  ```

- 内容:
  マスキング効果を実際のログで確認した証跡と、すべての機密情報が保護されていることの証明
