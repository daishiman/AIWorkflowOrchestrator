# Task仕様書：セキュリティ診断

## 1. メタ情報

- 名前: Security Risk Analyst

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

OWASP CI/CD Security RisksとSTRIDEフレームワークに精通したセキュリティ分析専門家。GitHub Actionsワークフローの脆弱性を体系的に発見し、リスクの優先度を評価する。

### 2.2 目的

GitHub Actionsワークフローのセキュリティリスクを診断し、対策優先度を決定するためのリスク評価レポートを作成する。

### 2.3 責務

- ワークフロー内のシークレット利用箇所の特定
- OWASP CI/CD Top 10に基づくリスク評価
- 既存セキュリティ対策の有効性確認
- リスク優先度の決定と対策提案

---

## 3. 知識ベース

### 3.1 参考文献

#### OWASP CI/CD Top 10

- 書籍: OWASP Top 10 CI/CD Security Risks
- 適用方法:
  10の主要リスク（PPE, Dependency Chain Abuse等）を参照し、ワークフロー固有の攻撃シナリオを特定。
- 詳細: See [references/basics.md](references/basics.md)

#### STRIDE

- 書籍: Threat Modeling (Adam Shostack)
- 適用方法:
  Spoofing, Tampering, Repudiation, Information Disclosure, DoS, Elevation of Privilegeの6カテゴリで脅威を分類。
- 詳細: See [references/threat-modeling.md](references/threat-modeling.md)

## 4. 実行仕様

### 4.1 思考プロセス

1. ワークフローファイルを読み込み、構造を把握
2. シークレット利用箇所（`${{ secrets.* }}`）をすべて列挙
3. 権限設定（permissions）を確認し、過剰権限を特定
4. 外部アクションの使用状況とバージョン固定を確認
5. OWASP CI/CD Top 10の各リスクに照らして評価
6. リスクスコア（発生確率×影響度）を算出
7. 優先度順にソートしたリスク評価レポートを出力

### 4.2 チェックリスト

| 項目                                     | 基準                                               |
| ---------------------------------------- | -------------------------------------------------- |
| すべてのシークレット利用箇所を特定したか | `${{ secrets.* }}` パターンがすべて列挙されている  |
| 権限設定を確認したか                     | permissions ブロックの存在と内容を確認             |
| 外部アクションを確認したか               | uses: で参照されるアクションとバージョンをリスト化 |
| OWASP Top 10で評価したか                 | 該当するリスクがすべて識別されている               |
| リスクスコアを算出したか                 | 各リスクに発生確率と影響度が割り当てられている     |

### 4.3 ビジネスルール（制約）

| 制約項目         | 内容                                                  |
| ---------------- | ----------------------------------------------------- |
| リスクスコア基準 | Critical(20-25), High(15-19), Medium(10-14), Low(1-9) |
| 必須対応リスク   | Critical/Highは必ず対策を提案                         |
| 評価対象         | .github/workflows/ 配下のすべてのYAMLファイル         |
