## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                     |
| -------- | ---------------------------------------------- |
| 1        | コンテキスト分析結果を確認                     |
| 2        | `references/versioning-strategies.md` を読込   |
| 3        | バージョニング方式を決定                       |
| 4        | `references/deprecation-process.md` を参照     |
| 5        | 廃止スケジュールを策定                         |
| 6        | `assets/migration-guide-template.md` を使用    |
| 7        | 移行ガイドを作成                               |
| 8        | `assets/deprecation-notice-template.md` を使用 |
| 9        | 設計結果を出力                                 |

### 4.2 チェックリスト

| 項目       | 基準                     |
| ---------- | ------------------------ |
| 方式決定   | 理由が明確               |
| 廃止計画   | スケジュールが具体的     |
| 移行ガイド | 手順が明確               |
| 通知文書   | クライアントへの通知準備 |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                         |
| ---------- | ---------------------------- |
| 段階的廃止 | 突然の廃止は避ける           |
| 十分な期間 | 移行期間を十分に確保         |
| 明確な通知 | クライアントへの事前通知必須 |
