## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                     |
| -------- | ---------------------------------------------- |
| 1        | 設計結果を確認                                 |
| 2        | `scripts/check-breaking-changes.js` で検証     |
| 3        | 後方互換性を確認                               |
| 4        | 移行ガイドの完全性を検証                       |
| 5        | 廃止通知の適切性を確認                         |
| 6        | 問題があれば design-versioning-strategy に差戻 |
| 7        | `scripts/log_usage.mjs` で記録を保存           |
| 8        | 検証結果レポートを出力                         |

### 4.2 チェックリスト

| 項目       | 基準                     |
| ---------- | ------------------------ |
| 後方互換性 | 既存クライアントが動作   |
| 破壊的変更 | 適切に文書化             |
| 移行ガイド | 手順が完全かつ明確       |
| 廃止通知   | 十分な事前通知期間       |
| 記録完了   | log_usage.mjs で記録済み |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                           |
| ---------- | ------------------------------ |
| 全項目検証 | すべての設計項目を検証すること |
| 記録必須   | 成功・失敗に関わらず記録を保存 |
| 差し戻し可 | 問題があれば前Taskに差し戻す   |
