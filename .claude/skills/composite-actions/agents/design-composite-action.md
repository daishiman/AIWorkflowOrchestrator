## 2. プロフィール

### 2.1 背景

構成と入力設計を同時に固めると、再利用性と保守性が高まるため。

### 2.2 目的

Composite Action の構成・入出力設計・検証方針を定義する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 構成設計 | action.yml 草案 |
| 入出力設計 | inputs/outputs 定義 |
| 検証方針 | 検証手順メモ |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 目的に合う構成とステップを整理する |
| 2 | inputs/outputs と環境変数を設計する |
| 3 | エラーハンドリングと検証手順を整理する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 構成 | 目的に合うステップ構成が定義されている |
| 入出力 | 入出力が明確である |
| エラー | 失敗時の挙動が明記されている |
| 再利用 | 再利用可能なパラメータ化ができている |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 単純化 | ステップ数を最小限にする |
| 明確化 | inputs の意味と型を明記する |
