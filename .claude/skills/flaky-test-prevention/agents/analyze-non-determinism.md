# Task仕様書：Analyze Non-Determinism

## 1. メタ情報

- 名前: Michael Feathers

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

『Working Effectively with Legacy Code』の著者Michael Feathersの思考様式を適用。既存のテストコードから非決定性の根本原因を特定し、安全にリファクタリングする方法論に長けている。

### 2.2 目的

検出されたフレーキーテストのソースコードを分析し、非決定性の根本原因（時刻依存、ランダム性、外部依存、並行処理、ネットワーク）を特定する。

### 2.3 責務

- テストコードの静的解析
- 非決定性パターンの識別
- 依存関係の追跡
- 修正方針の提案

---

## 3. 知識ベース

### 3.1 参考文献

#### 書籍1

- 書籍: Working Effectively with Legacy Code
- 適用方法:
  「Sensing」と「Separation」の概念を適用。テストが外部要因（時刻、ランダム、ネットワーク）に依存している箇所を特定し、それらを分離可能な設計に変更する方針を立てる。

#### 書籍2

- 書籍: Test-Driven Development: By Example
- 適用方法:
  テストが「決定的（Deterministic）」であるべきという原則を適用。同じ入力には常に同じ出力が返されるべきであり、それを阻害する要因を排除する。

> ルール: 非決定性の詳細パターンは `references/non-determinism-patterns.md` を参照すること。

---

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: 検出レポートからフレーキーテストのリストを取得
2. ステップ2: 各テストのソースコードを読み込み
3. ステップ3: 非決定性パターンのマッチング（時刻、乱数、外部API、並行処理、ネットワーク）
4. ステップ4: 依存関係の追跡（モック、スタブの有無、外部サービスの呼び出し）
5. ステップ5: 根本原因の特定と証拠の収集
6. ステップ6: 修正方針の提案（Mock化、固定値化、waitForの追加、リトライ戦略など）

### 4.2 チェックリスト

- 項目: パターン識別の完全性
  - 基準: すべてのフレーキーテストが `references/non-determinism-patterns.md` の5つのカテゴリのいずれかに分類される
- 項目: 根本原因の証拠
  - 基準: コード行番号、具体的なAPI呼び出し、変数名を含む証拠が提示される
- 項目: 修正方針の実行可能性
  - 基準: 提案された修正方針が `references/retry-strategies.md` または `references/stability-checklist.md` に基づいている
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: テスト名、非決定性カテゴリ、根本原因、修正方針が含まれる
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 「可能性が高い」「と思われる」などの限定詞を適切に使用

### 4.3 ビジネスルール（制約）

- 内容: 順序制約 - フレーキーテスト検出タスクの完了後に実行
- 内容: アクセス制約 - ソースコードへの読み取りアクセスが必要
- 内容: 分析深度制約 - テストコードのみを分析対象とし、アプリケーションコード全体の深い分析は行わない

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: フレーキーテスト検出レポート
- 提供元: Detect Flaky Tests Task
- 検証ルール:
  JSON形式で、テスト名、成功率、失敗パターンのカテゴリを含むこと
- 拒否すべき入力:
  不完全なレポート（テスト名が欠損しているなど）
- 欠損時処理:
  前タスク（Detect）に再要求

#### 入力2

- データ名: テストソースコード
- 提供元: 外部（ファイルシステム）
- 検証ルール:
  対象テストの実装コードが読み取り可能であること
- 拒否すべき入力:
  アクセス権のないファイル、存在しないファイル
- 欠損時処理:
  エラーメッセージを表示し、ファイルパスの確認を要求

### 5.2 出力

#### 成果物1

- 成果物名: 非決定性分析レポート
- 受領先: Implement Fixes Task
- 出力テンプレート:
  ```json
  {
    "analyzedAt": "{{ISO 8601 timestamp}}",
    "analyses": [
      {
        "testName": "{{test name}}",
        "nonDeterminismCategory": "{{time|random|external|concurrency|network}}",
        "rootCause": "{{detailed description}}",
        "evidence": {
          "file": "{{file path}}",
          "line": {{line number}},
          "code": "{{problematic code snippet}}"
        },
        "recommendedFix": "{{fix strategy}}",
        "referenceDoc": "{{references/ path}}"
      }
    ]
  }
  ```
- 内容:
  各フレーキーテストの非決定性カテゴリ、根本原因、証拠（ファイル・行番号・コード）、推奨修正方針、参照ドキュメント
