## フレーキーテストとは

### 定義

**フレーキーテスト**: 同じコードに対して、実行するたびに成功したり失敗したりする不安定なテスト

### 問題点

- CI/CDパイプラインの信頼性低下
- 開発者の生産性低下（原因調査に時間がかかる）
- 本物のバグを見逃すリスク
- チームの士気低下

## 基本的な3つのアプローチ

### 1. 非決定性の排除

テストが外部要因（時刻、ランダム、ネットワーク等）に依存しないようにする。

**例**:

```typescript
// ❌ 悪い例: 現在時刻に依存
const now = new Date();

// ✅ 良い例: 固定値を使用
const now = new Date("2024-01-15T00:00:00Z");
```

### 2. リトライロジック

一時的な障害に対して適切にリトライする。

**例**:

```typescript
// Playwrightの自動リトライ設定
test.describe.configure({ retries: 2 });
```

### 3. 適切な待機

要素の出現やAPIレスポンスを確実に待つ。

**例**:

```typescript
// ❌ 悪い例: 固定時間待機
await page.waitForTimeout(3000);

// ✅ 良い例: 条件ベース待機
await page.waitForSelector(".content", { state: "visible" });
```

## よくあるフレーキーテストのパターン

### パターン1: 時刻依存

テストが実行時刻によって結果が変わる。

**対処法**: テストデータで期限を明示的に設定

### パターン2: レースコンディション

非同期処理の完了を待たずに検証を行う。

**対処法**: `waitFor`系メソッドで確実に待機

### パターン3: 並列実行の競合

複数のテストが同じリソースを共有する。

**対処法**: テストごとに独立したデータを用意
