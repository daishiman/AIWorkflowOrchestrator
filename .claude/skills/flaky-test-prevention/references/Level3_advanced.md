# Level 3: Advanced

## 概要

複雑なシナリオにおけるフレーキーテスト防止の高度なテクニック。
Progressive Disclosure設計とTask分離による効率的な問題解決を整理します。

## 前提条件

- Level 2の運用を完了している
- 5つの非決定性パターンと対処法を習得している
- リソース/スクリプト/テンプレートの活用方法を理解している

## Task分離による効率的なワークフロー

### Task 1: Detect Flaky Tests

**目的**: フレーキーテストを統計的に検出し、パターン分類する

**実行仕様**: `agents/detect-flaky-tests.md` を参照

**使用タイミング**:

- CI/CDログから定期的にフレーキーテストを検出したい
- テスト実行履歴が10回以上蓄積されている
- 統計的なアプローチでフレーキーテストを特定したい

**入力**: テスト実行履歴（JSON/XML/テキスト形式）

**出力**: フレーキーテスト検出レポート（成功率、パターン分類、優先度）

### Task 2: Analyze Non-Determinism

**目的**: 検出されたフレーキーテストの根本原因を特定する

**実行仕様**: `agents/analyze-non-determinism.md` を参照

**使用タイミング**:

- フレーキーテストが検出され、その原因を特定したい
- ソースコードへのアクセスが可能
- 修正方針を立案する前に根本原因を理解したい

**入力**: フレーキーテスト検出レポート + テストソースコード

**出力**: 非決定性分析レポート（カテゴリ、根本原因、証拠、推奨修正方針）

### Task 3: Implement Fixes

**目的**: 分析結果に基づき、安定したテストに修正する

**実行仕様**: `agents/implement-fixes.md` を参照

**使用タイミング**:

- 非決定性の分析が完了し、修正方針が明確になっている
- テストコードへの書き込み権限がある
- 安全なリファクタリング手法で修正を実装したい

**入力**: 非決定性分析レポート + テストソースコード（書き込み権限）

**出力**: 修正結果レポート（修正内容、検証結果、ステータス）

## Progressive Disclosure戦略

### レベル1: 概要把握（最小コンテキスト）

まず `SKILL.md` でワークフローの全体像を把握する。

### レベル2: Task仕様確認（必要時のみ）

実行するTaskの仕様書（`agents/*.md`）のみを読み込む。
他のTaskは実行直前まで読み込まない。

### レベル3: 詳細リソース参照（問題発生時のみ）

- `references/non-determinism-patterns.md`: 具体的なパターンと対処法
- `references/retry-strategies.md`: リトライ戦略の詳細
- `references/stability-checklist.md`: 安定性チェックリスト

### レベル4: テンプレート活用（実装時のみ）

`assets/stable-test-template.ts` で実装パターンを参照する。

## 複雑なシナリオへの対処

### シナリオ1: 複数の非決定性が絡み合っている

**問題**: 時刻依存とネットワーク遅延が同時に発生

**対処法**:

1. Analyze Taskで両方の原因を特定
2. 優先度の高い方から順に修正（通常は時刻依存から）
3. 各修正後に検証を実施
4. すべての修正が完了してから統合テスト

### シナリオ2: 並列実行時のみフレーキーになる

**問題**: 単独実行では成功するが、並列実行で失敗する

**対処法**:

- テストごとに独立したデータベース/ファイルを用意
- グローバル状態の使用を避ける
- Fixtureでテストの分離を保証

**参照**: `references/non-determinism-patterns.md` の「並行処理の非決定性」

### シナリオ3: CI環境でのみフレーキーになる

**問題**: ローカルでは安定、CI環境でフレーキー

**対処法**:

- CI環境のリソース制約を考慮（CPU、メモリ）
- タイムアウト値を環境に応じて調整
- `process.env.CI` で環境を判定し、リトライ回数を増やす

```typescript
test.describe.configure({
  retries: process.env.CI ? 3 : 0,
  timeout: process.env.CI ? 60000 : 30000,
});
```

## トークン最適化戦略

### 戦略1: 必要なTaskのみ実行

すべてのTaskを実行するのではなく、必要なTaskのみを選択的に実行する。

### 戦略2: リソースの段階的読み込み

詳細リソースは問題が発生したときのみ読み込む。

### 戦略3: 要約の再利用

頻繁に参照するリソースは要点メモを作成し、再利用する。

## 実践手順

1. フレーキーテストの状況を把握（Detect Task）
2. 必要に応じて根本原因を分析（Analyze Task）
3. 修正を実装（Implement Task）
4. 各Taskは独立して実行し、メインコンテキストを汚さない
5. Progressive Disclosureで必要な情報のみを読み込む
