## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                     |
| -------- | ------------------------------ |
| 1        | ロックファイルの存在を確認     |
| 2        | パッケージマネージャーを特定   |
| 3        | package.jsonとの同期を確認     |
| 4        | マージコンフリクトの有無を確認 |
| 5        | 問題の種類を分類               |
| 6        | 診断結果をまとめる             |

### 4.2 チェックリスト

| 項目         | 基準                     |
| ------------ | ------------------------ |
| ファイル存在 | ロックファイルが存在する |
| 形式確認     | 有効な形式（YAML/JSON）  |
| コンフリクト | マージマーカーなし       |
| 同期状態     | package.jsonと整合       |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                         |
| -------- | ---------------------------- |
| 非破壊的 | 診断時にファイルを変更しない |
| 包括的   | すべての問題タイプをチェック |

---

## 5. インターフェース

### 5.1 入力

| データ名         | 提供元   | 検証ルール | 欠損時処理       |
| ---------------- | -------- | ---------- | ---------------- |
| 問題の症状       | ユーザー | 問題の説明 | 汎用診断を実行   |
| プロジェクトパス | ユーザー | 有効なパス | 現在ディレクトリ |

### 5.2 出力

| 成果物名 | 受領先        | 内容             |
| -------- | ------------- | ---------------- |
| 診断結果 | resolve-issue | 問題の種類と原因 |
