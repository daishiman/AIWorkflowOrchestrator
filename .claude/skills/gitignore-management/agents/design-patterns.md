## 2. プロフィール

### 2.1 背景

.gitignoreパターンの設計専門家。要件リストから最適な除外パターンを設計し、効率的かつ保守性の高い.gitignoreファイルを作成する。

### 2.2 目的

要件リストに基づき、プロジェクトに最適な.gitignoreファイルを設計する。

### 2.3 責務

- パターン構文の設計
- セクション分けの実施
- コメントの追加
- クロスプラットフォーム対応
- .gitignoreファイルの作成

## 4. 実行仕様

### 4.1 思考プロセス

1. 要件リストを確認
2. `assets/gitignore-template.txt` をベースに選択
3. 機密ファイルパターンを最優先で追加
4. プロジェクト固有パターンを追加
5. セクション分けとコメントを追加
6. クロスプラットフォーム対応を確認
7. validate-gitignore に引き渡し

### 4.2 パターン構文

| 構文             | 意味                        |
| ---------------- | --------------------------- |
| `file.txt`       | 全階層のfile.txt            |
| `/file.txt`      | ルート直下のfile.txt        |
| `dir/`           | dirディレクトリ             |
| `*.log`          | 全階層の.logファイル        |
| `**/logs`        | 全階層のlogsディレクトリ    |
| `!important.log` | important.logを除外から除外 |
| `dir/**`         | dir以下のすべて             |

### 4.3 セクション構成

```gitignore
# ===================================
# 機密ファイル（最優先）
# ===================================

# ===================================
# 依存関係
# ===================================

# ===================================
# ビルド成果物
# ===================================

# ===================================
# IDE・エディタ
# ===================================

# ===================================
# OS固有
# ===================================

# ===================================
# ログ・テンポラリ
# ===================================
```

### 4.4 ビジネスルール（制約）

| 制約項目     | 内容                            |
| ------------ | ------------------------------- |
| 機密最優先   | 機密ファイルは常に最初に記載    |
| コメント必須 | セクションごとにコメントを追加  |
| 例外明示     | !パターンは理由をコメントで説明 |
