# マルチエージェントシステム - 基礎概念

## 概要

マルチエージェントシステムは、複数の自律エージェントが協調して複雑なタスクを遂行するアーキテクチャ。
各エージェントは特定の専門性を持ち、ハンドオフプロトコルにより連携する。

## 核心概念

### エージェント（Agent）

```yaml
---
name: code-reviewer
description: |
  コードレビューを担当するエージェント。

  🔴 専門領域:
  - スタイルチェック
  - セキュリティ分析
  - パフォーマンス評価
tools:
  - Read
  - Grep
---
```

- 特定の責務を持つ自律的な処理単位
- 明確なインターフェース（入力/出力）を定義
- 他のエージェントと疎結合で連携

### ハンドオフプロトコル

```json
{
  "from_agent": "analyzer",
  "to_agent": "implementer",
  "status": "completed",
  "artifacts": ["analysis-result.json"],
  "context": {
    "issues_found": 3,
    "next_steps": ["修正実装"]
  }
}
```

- エージェント間の情報受け渡し規約
- 成果物（artifacts）と実行コンテキストを転送
- 標準フォーマットで一貫性を確保

### 協調パターン

| パターン           | 構造            | 用途                   |
| ------------------ | --------------- | ---------------------- |
| 委譲（Delegation） | 上位→複数の下位 | タスク分割、並行処理   |
| 連鎖（Chaining）   | A→B→C           | パイプライン、段階処理 |
| 並行（Parallel）   | [A,B,C]→統合    | 独立タスクの同時実行   |
| フィードバック     | A⇄B             | 反復改善、相互レビュー |

## 依存関係管理

### 依存グラフ

```
orchestrator
    ├→ analyzer
    ├→ implementer (depends on: analyzer)
    └→ reviewer (depends on: implementer)
```

- 明示的な依存関係の定義
- 循環依存の回避
- 実行順序の自動決定

### 依存関係ルール

```
✅ 上位エージェント → 下位エージェント
✅ 明示的な依存宣言
❌ 循環依存 (A→B→A)
❌ 暗黙の依存
```

## エラーハンドリング

### 失敗時のハンドオフ

```json
{
  "from_agent": "analyzer",
  "to_agent": "error-handler",
  "status": "failed",
  "error": {
    "type": "ValidationError",
    "message": "入力データが不正",
    "recovery_hint": "データ形式を確認"
  }
}
```

### リカバリ戦略

| 戦略           | 説明                     | 適用場面           |
| -------------- | ------------------------ | ------------------ |
| リトライ       | 同じエージェントで再試行 | 一時的な障害       |
| フォールバック | 代替エージェントに委譲   | 特定機能の障害     |
| スキップ       | 該当処理をスキップ       | オプション処理     |
| 停止           | ワークフロー全体を停止   | クリティカルな障害 |

## 通信パターン

### 同期通信

```
エージェントA ──request──► エージェントB
             ◄──response──
```

- シンプルで理解しやすい
- ブロッキング（待機が発生）
- 小規模システム向け

### 非同期通信

```
エージェントA ──message──► メッセージキュー ──► エージェントB
                                             ──► エージェントC
```

- スケーラブル
- 疎結合
- 大規模システム向け

## 判断基準

### スキル適用タイミング

- 複数エージェントの協調設計時
- ハンドオフプロトコル定義時
- エージェント間依存関係の整理時
- 既存システムへのエージェント導入時

### パターン選択基準

| 条件                       | 推奨パターン   |
| -------------------------- | -------------- |
| タスクが独立               | 並行/委譲      |
| タスクが依存               | 連鎖           |
| 高速化優先                 | 並行           |
| 品質優先                   | フィードバック |
| 複雑なオーケストレーション | 委譲           |
