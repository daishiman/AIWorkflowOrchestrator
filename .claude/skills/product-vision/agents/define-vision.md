# Task: ビジョン定義

## メタデータ

- **Task ID**: define-vision
- **Phase**: Phase 1
- **所要時間**: 2-4時間（ワークショップ含む）
- **前提条件**: プロダクトの現状理解、市場調査完了

## 目的

製品の長期的な方向性と価値提案を明確化し、ビジョンボードを作成する。

## 入力

### 必須

- プロダクトの現状（既存製品の場合）
- ターゲット市場の情報
- 競合分析
- ビジネス目標

### 推奨

- ユーザーインタビューの洞察
- 既存メトリクス（既存製品の場合）
- エグゼクティブの戦略的方向性

## 出力

### 成果物

1. **ビジョンステートメント**（1-2文）
2. **ビジョンボード**（`assets/vision-board-template.md` を使用）
   - ターゲット顧客
   - 顧客ニーズと課題
   - 製品属性
   - ビジネスゴール

### 形式

Markdown形式、図や画像を含む

## 実行手順

### Step 1: 準備（30分）

**必要な情報を収集**:

```bash
# 参照すべきリソース
cat .claude/skills/product-vision/references/basics.md
cat .claude/skills/product-vision/references/vision-board.md
```

**テンプレートの準備**:

```bash
cp .claude/skills/product-vision/assets/vision-board-template.md \
   docs/product-vision/[product-name]-vision-board.md
```

**参加者の招集**:

- プロダクトマネージャー
- デザインリード
- エンジニアリングリード
- ビジネスステークホルダー（CEO、VP等）

### Step 2: ワークショップ実施（2-3時間）

**1. ビジョンステートメントの作成（30分）**

アプローチ:

1. 各参加者が個別にドラフトを作成（10分）
2. 全員で共有・ディスカッション（15分）
3. 投票で上位3つを選択（5分）

評価基準:

- 簡潔性（1-2文）
- 記憶性（覚えやすいか）
- 鼓舞性（やる気が出るか）
- 実現可能性（野心的だが現実的）

**2. ターゲット顧客の定義（30分）**

アプローチ:

1. ペルソナを2-3個作成
2. 最も重要な1つを選択
3. 詳細を肉付け

フォーマット:

```
セグメント: [誰のためのプロダクトか]
ペルソナ: [名前、年齢、職業]
特徴:
  - [属性1]
  - [属性2]
  - [属性3]
```

**3. 顧客ニーズの特定（40分）**

アプローチ:

1. ポストイットでニーズをブレインストーミング（15分）
2. グルーピングとテーマ化（15分）
3. 優先順位付けと上位3-5個を選択（10分）

Jobs-to-be-Doneフレームワークを使用:

```
状況: [どんな時に]
課題: [何が問題か]
期待する成果: [何を実現したいか]
```

**4. 製品属性の整理（40分）**

3つのカテゴリに分類:

- **必須**: なければ製品として成立しない
- **差別化**: 競合との差別化要素
- **魅力的**: あると嬉しいが必須ではない

各カテゴリで最重要項目を特定。

**5. ビジネスゴールの設定（20分）**

測定可能な目標を設定:

```
収益目標: [具体的な数値と期間]
市場シェア: [目標シェア]
戦略的意義: [会社戦略への貢献]
```

### Step 3: 文書化（30分）

**ビジョンボードの作成**:

`assets/vision-board-template.md` を使用して、ワークショップの結果を整理。

**ビジュアル化**:

- 図やイラストを追加
- ペルソナの写真（ストック画像）
- カラーコーディング

### Step 4: レビューと調整（1週間）

**フィードバック収集**:

1. エグゼクティブレビュー
2. チーム全体レビュー
3. 顧客への検証（可能であれば）

**調整**:

- フィードバックを反映
- 矛盾や曖昧さを解消
- 最終版の確定

## 成功基準

- [ ] ビジョンステートメントが1-2文で簡潔
- [ ] チームメンバー全員がビジョンを覚えている
- [ ] ターゲット顧客が具体的なペルソナで定義されている
- [ ] 顧客ニーズが3-5個に絞られている
- [ ] 製品属性が必須/差別化/魅力的に分類されている
- [ ] ビジネスゴールが測定可能
- [ ] ステークホルダーの承認を獲得

## よくある落とし穴

### 抽象的すぎるビジョン

❌ "世界中の人々に価値を提供する"
✅ "非エンジニアがノーコードでAPIを統合できるようにする"

### ターゲットが広すぎる

❌ "すべてのビジネスパーソン"
✅ "10-50人規模のスタートアップの営業チーム"

### 機能リストになる

❌ "チャット、ファイル共有、タスク管理を持つツール"
✅ "チームのコンテキストを自動で共有し、非同期コラボレーションを実現"

## 次のステップ

1. ビジョンボードが完成したら、`agents/set-okrs.md` に進む
2. ビジョンから具体的なOKRを導出
3. ステークホルダーに共有（`agents/align-stakeholders.md` 参照）
