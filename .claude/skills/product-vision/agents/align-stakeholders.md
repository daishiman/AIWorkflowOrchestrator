# Task: ステークホルダー調整

## メタデータ

- **Task ID**: align-stakeholders
- **Phase**: Phase 4
- **所要時間**: 2-3週間（レビュープロセス含む）
- **前提条件**: ビジョン/OKR/ロードマップのドラフト完成

## 目的

チーム、経営陣、その他のステークホルダーとの方向性を統一し、戦略への合意と承認を獲得する。

## 入力

### 必須

- ビジョンボード（ドラフト）
- OKRドキュメント（ドラフト）
- ロードマップ（ドラフト）
- ステークホルダーリスト

### 推奨

- 過去のフィードバック履歴
- ステークホルダーの優先事項
- 想定される懸念事項

## 出力

### 成果物

1. **ステークホルダーマップ**
   - 影響力と関心レベルの評価
   - コミュニケーション計画
2. **レビューセッションの記録**
   - フィードバック
   - 決定事項
   - アクションアイテム
3. **承認済み戦略ドキュメント**
   - ビジョンボード（最終版）
   - OKR（最終版）
   - ロードマップ（最終版）

### 形式

Markdown形式、会議ノート、承認サイン

## 実行手順

### Step 1: ステークホルダーマッピング（1-2時間）

**ステークホルダーの特定**:

```bash
# 参照すべきリソース
cat .claude/skills/product-vision/references/stakeholder-alignment.md
```

**主要なステークホルダー**:

内部:

- エグゼクティブ（CEO、CTO、CFO等）
- プロダクトチーム
- エンジニアリングチーム
- デザインチーム
- 営業チーム
- マーケティングチーム
- カスタマーサクセス

外部:

- 主要顧客
- パートナー
- 投資家（該当する場合）

**Power-Interest Grid（影響力-関心マトリックス）**:

| ステークホルダー | 役割   | 影響力 | 関心 | 象限     | コミュニケーション頻度 |
| ---------------- | ------ | ------ | ---- | -------- | ---------------------- |
| CEO              | 承認者 | 高     | 高   | 積極管理 | 週次                   |
| CTO              | 承認者 | 高     | 高   | 積極管理 | 週次                   |
| エンジニアリング | 実行者 | 中     | 高   | 情報提供 | デイリー               |
| 営業VP           | 影響者 | 高     | 中   | 協働     | 月次                   |

**象限ごとのアプローチ**:

1. **積極管理（高影響力 × 高関心）**: 定期的な1on1、意思決定への参加
2. **情報提供（低影響力 × 高関心）**: 定期的な情報共有、透明性確保
3. **協働（高影響力 × 低関心）**: 重要な決定時のみ相談
4. **監視（低影響力 × 低関心）**: 必要最小限の情報提供

### Step 2: 理解とエンゲージメント（1週間）

**1on1インタビュー**:

各主要ステークホルダーと個別に面談:

**質問例**:

- プロダクトに対する期待は？
- 最も重要な成功指標は？
- 懸念事項は？
- 意思決定にどう関与したいか？

**懸念事項の特定**:

典型的な懸念:

- **CEO**: 収益への影響、競合優位性
- **CTO**: 技術的実現可能性、スケーラビリティ
- **営業**: 顧客への訴求力、クロージング支援
- **エンジニアリング**: 実装の複雑さ、技術的負債

**チャンピオンの特定**:

各チーム/部門に協力者を見つけ、彼らを通じて情報を拡散。

### Step 3: レビューセッションの準備（1-2日）

**資料の準備**:

1. **エグゼクティブサマリー**（1-2ページ）
   - ビジョン
   - 主要OKR
   - ロードマップハイライト
2. **詳細ドキュメント**
   - ビジョンボード
   - OKRドキュメント
   - ロードマップ
3. **バックアップデータ**
   - 市場調査
   - ユーザーインタビュー
   - メトリクス

**アジェンダの作成**:

```markdown
# プロダクトビジョン レビューセッション

**日時**: YYYY-MM-DD HH:MM
**参加者**: [リスト]
**目的**: Q1 OKRとロードマップの承認

## アジェンダ（60分）

1. 背景とコンテキスト（5分）
2. ビジョンの再確認（5分）
3. Q1 OKRの提示（15分）
4. ロードマップ概要（10分）
5. 質疑応答（20分）
6. 次のステップ（5分）
```

### Step 4: レビューセッション実施（複数回、各1時間）

**セッション進行**:

1. **導入**
   - 目的の説明
   - アジェンダの確認
2. **プレゼンテーション**
   - ストーリーテリングで伝える
   - ビジュアルを活用
3. **質疑応答**
   - オープンに議論
   - 懸念事項を深掘り
4. **フィードバック収集**
   - 何が良いか
   - 何が懸念か
   - どう改善できるか
5. **次のステップ**
   - アクションアイテム
   - 次回レビュー日程

**異なる視点への対応**:

```
懸念: "このロードマップは野心的すぎる"
対応: データで実現可能性を示す + 段階的アプローチを提案

懸念: "顧客要望と異なる"
対応: 顧客インタビューの洞察を共有 + 長期的価値を説明

懸念: "リソースが足りない"
対応: 優先順位を再評価 + MVPアプローチを提案
```

### Step 5: フィードバックの反映（3-5日）

**フィードバックの分類**:

1. **Critical（必須）**: 戦略の根幹に関わる変更
2. **Important（重要）**: 改善すべき点
3. **Nice-to-have（あれば良い）**: 考慮するが必須ではない

**調整**:

Critical と Important フィードバックを反映:

- ビジョンの表現調整
- OKRの目標値変更
- ロードマップの優先順位見直し

**再レビュー**:

主要なステークホルダーに調整版を確認してもらう。

### Step 6: 合意形成と承認（1週間）

**最終レビュー**:

全ステークホルダーが承認できる状態まで調整。

**合意の文書化**:

```markdown
## 承認

- **プロダクトマネージャー**: [名前] [日付]
- **CTO**: [名前] [日付]
- **CEO**: [名前] [日付]
```

**公開と周知**:

1. 全社ミーティングで発表
2. 社内Wiki/Notionに掲載
3. チーム別セッションで詳細説明

### Step 7: 継続的コミュニケーション（進行中）

**定期的な更新**:

- **週次**: 積極管理対象のステークホルダー
- **月次**: 情報提供対象のステークホルダー
- **四半期**: 全ステークホルダー（四半期レビュー）

**進捗レポート**:

```markdown
# OKR進捗レポート - Q1 Week 8

## ハイライト

- MAU 14,000達成（目標25,000の56%）
- リファラルプログラムベータ版リリース

## 課題

- マーケティングキャンペーンの遅延

## 次週の優先事項

- キャンペーン立ち上げ
- パフォーマンス最適化
```

## よくある落とし穴

### ステークホルダー不在

一方的な発表ではなく、対話を通じて作成する。

### ネガティブなフィードバックへの感情的反応

理由を深掘りし、データや段階的アプローチで対処する。

### 情報の透明性不足

定期的に全社で共有し、社内Wikiに最新版を掲載する。

## トラブルシューティング

### 問題: ステークホルダー間の対立

**対処**:

1. 両者の懸念を明確化
2. データで優先順位を決定（RICE等）
3. 妥協案を提示（段階的実装等）
4. 上位マネージャーに判断を仰ぐ（必要な場合）

### 問題: 頻繁な変更要求

**対処**:

1. 変更の影響を可視化（他の施策への影響）
2. 変更基準を事前に合意（どの条件で変更を受け入れるか）
3. 定期的なレビューサイクルを確立（その間は変更しない）

## 次のステップ

1. 承認された戦略を実行開始
2. 週次チェックインでOKR進捗を追跡
3. 月次レビューでロードマップを更新
4. 四半期レビューで振り返りと次四半期OKR設定
