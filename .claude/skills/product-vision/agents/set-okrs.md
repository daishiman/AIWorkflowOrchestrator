# Task: OKR設定

## メタデータ

- **Task ID**: set-okrs
- **Phase**: Phase 2
- **所要時間**: 3-4時間（ワークショップ含む）
- **前提条件**: ビジョンボード完成、前四半期OKRレビュー完了

## 目的

ビジョンから具体的な四半期目標（OKR）を導出し、測定可能な成果指標を設定する。

## 入力

### 必須

- プロダクトビジョンボード
- 前四半期のOKR結果（既存製品の場合）
- 現在のメトリクス
- 上位レベルのOKR（会社レベル）

### 推奨

- 市場動向
- ユーザーフィードバック
- 競合動向
- リソース計画（人員、予算）

## 出力

### 成果物

1. **四半期OKR**（通常3-5個のObjective、各Objectiveに2-4個のKey Results）
2. **OKRドキュメント**（`assets/okr-template.md` を使用）
   - Company OKRs（参照）
   - Product OKRs（詳細）
   - Team OKRs（必要に応じて）

### 形式

Markdown形式、テーブルやリストを使用

## 実行手順

### Step 1: 準備（30分）

**必要な情報を収集**:

```bash
# 参照すべきリソース
cat .claude/skills/product-vision/references/basics.md
cat .claude/skills/product-vision/references/okr-framework.md

# テンプレートの準備
cp .claude/skills/product-vision/assets/okr-template.md \
   docs/okrs/Q[1-4]-YYYY-okrs.md
```

**前四半期の振り返り**:

- 達成率と学び
- 何がうまくいったか/いかなかったか
- 継続すべきOKR、新規OKR

**参加者の招集**:

- プロダクトチーム全員
- 関連するステークホルダー
- エグゼクティブスポンサー

### Step 2: ワークショップ実施（2-3時間）

**1. Objectivesのブレインストーミング（30分）**

各自が付箋に目標候補を書き出す:

- "この四半期で最も重要な成果は？"
- "ビジョン実現のために何を達成すべきか？"
- "上位レベルのOKRにどう貢献するか？"

グルーピングとテーマ化:

1. 類似する目標をグルーピング（10分）
2. テーマごとにObjectiveを言語化（10分）
3. 投票で3-5個に絞る（10分）

**良いObjectiveの特徴**:

- 動詞で始まる（達成、向上、実現など）
- 具体的で明確
- 鼓舞的で記憶に残る
- 1文で表現できる

**2. Key Resultsの定義（1時間）**

各Objectiveに対して:

**質問**:

- "この目標が達成されたと測定できる指標は？"
- "現在値と目標値は？"
- "野心的だが達成可能か（70%達成を目指す）？"

**フォーマット**:

```
[指標名]を[現在値]から[目標値]に[向上/削減/増加]
```

**評価基準**:

- 定量的で測定可能
- 影響力が大きい
- オーナーが明確
- 野心的だが達成可能

各Objectiveに2-4個のKey Resultsを設定。

**3. 整合性の確認（30分）**

**上位レベルとの整合性**:

- 会社OKRにどう貢献するか？
- Product OKRsが会社の目標を支援しているか？

**チーム間の調整**:

- 他チームとの依存関係は？
- 重複や矛盾はないか？

**リソースの現実性**:

- 現在のチーム規模で達成可能か？
- 追加リソースが必要な場合、確保できるか？

### Step 3: 文書化（30分）

**OKRドキュメントの作成**:

`assets/okr-template.md` を使用:

1. 基本情報（期間、プロダクト名、作成日）
2. Company OKRs（参照のみ）
3. Product OKRs（詳細）
   - Objective
   - Key Results（現在値、目標値、進捗、信頼度、主要施策）
   - オーナー
   - 整合性（上位OKRとの関連）
4. Team OKRs（必要に応じて）

**検証**:

```bash
node .claude/skills/product-vision/scripts/validate-okr.mjs \
  docs/okrs/Q[1-4]-YYYY-okrs.md
```

### Step 4: レビューと調整（1週間）

**レビュープロセス**:

1. チーム内レビュー
2. 上位マネージャーレビュー
3. 関連チームとの調整
4. エグゼクティブ承認

**調整のポイント**:

- 目標が野心的すぎないか（または簡単すぎないか）
- Key Resultsが測定可能か
- 他チームとの重複や矛盾はないか

**コミットメントと公開**:

- 最終版を全社に公開
- キックオフミーティングで説明
- チームメンバー全員が理解・納得

## 成功基準

### Objectives

- [ ] 3-5個のObjectiveに絞られている
- [ ] 動詞で始まり、達成したい状態を表現している
- [ ] 1文で簡潔に表現されている
- [ ] 鼓舞的で記憶に残る
- [ ] 上位OKRと整合性がある

### Key Results

- [ ] 各Objectiveに2-4個のKey Results
- [ ] 定量的で測定可能
- [ ] 現在値と目標値が明記されている
- [ ] 野心的だが達成可能（70%達成を目指す）
- [ ] オーナーが明確
- [ ] 測定方法が定義されている

### 全体

- [ ] ステークホルダーの承認を獲得
- [ ] チーム全員が理解・納得
- [ ] 週次チェックインのプロセスが確立

## よくある落とし穴

### タスクリストになる

❌ **悪い例**:

```
Objective: プロダクトを改善する
KR1: 機能Aを実装する
KR2: バグを50個修正する
KR3: UIを再デザインする
```

✅ **良い例**:

```
Objective: ユーザー体験を劇的に向上させる
KR1: ユーザー満足度（CSAT）を70%から90%に向上
KR2: サポートチケット数を月300件から100件に削減
KR3: タスク完了時間を平均10分から3分に短縮
```

### 簡単すぎる目標

❌ "アクティブユーザーを10,000から10,500に増加"（5%増）
✅ "アクティブユーザーを10,000から25,000に増加"（150%増）

### 測定できないKey Results

❌ "より良いプロダクトにする"
✅ "プロダクトレビューの平均星数を3.5から4.5に向上"
