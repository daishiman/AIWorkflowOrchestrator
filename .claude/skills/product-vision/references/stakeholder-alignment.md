# ステークホルダー調整ガイド

## 概要

プロダクトビジョン、OKR、ロードマップの策定において、ステークホルダーとの調整と合意形成は成功の鍵です。このガイドでは、効果的なステークホルダーマネジメントの実践方法を提供します。

## ステークホルダーとは

### 定義

プロダクトの成功に影響を与える、または影響を受けるすべての個人やグループ。

### 主要なステークホルダー

```
内部:
  - エグゼクティブ（CEO、CTO、CFO等）
  - プロダクトチーム
  - エンジニアリングチーム
  - デザインチーム
  - 営業チーム
  - マーケティングチーム
  - カスタマーサクセス

外部:
  - 顧客
  - パートナー
  - 投資家
  - 規制当局（業界による）
```

## ステークホルダーマッピング

### Power-Interest Grid（影響力-関心マトリックス）

ステークホルダーを4象限に分類:

```
        高関心
          ↑
  ────────┼────────
  協働     │ 積極管理
  (Engage)│(Manage Closely)
  ────────┼────────
  監視     │ 情報提供
  (Monitor)│(Keep Informed)
          ↓
        低関心

← 低影響力  高影響力 →
```

**象限ごとの対応**:

1. **積極管理（高影響力 × 高関心）**
   - 例: CEO、プロダクト責任者
   - アプローチ: 定期的な1on1、意思決定への参加

2. **情報提供（低影響力 × 高関心）**
   - 例: エンジニアリングチーム、デザインチーム
   - アプローチ: 定期的な情報共有、透明性確保

3. **協働（高影響力 × 低関心）**
   - 例: CFO、法務
   - アプローチ: 重要な決定時のみ相談

4. **監視（低影響力 × 低関心）**
   - 例: 他部門のマネージャー
   - アプローチ: 必要最小限の情報提供

### ステークホルダーマップの作成

**テンプレート**:

| ステークホルダー | 役割   | 影響力 | 関心 | 象限     | コミュニケーション頻度 |
| ---------------- | ------ | ------ | ---- | -------- | ---------------------- |
| CEO              | 承認者 | 高     | 高   | 積極管理 | 週次                   |
| CTO              | 承認者 | 高     | 高   | 積極管理 | 週次                   |
| エンジニアリング | 実行者 | 中     | 高   | 情報提供 | デイリー               |
| 営業VP           | 影響者 | 高     | 中   | 協働     | 月次                   |
| マーケティング   | 協力者 | 中     | 中   | 情報提供 | 月次                   |

## ステークホルダーエンゲージメント戦略

### 1. 理解フェーズ

**目的**: 各ステークホルダーのニーズ、懸念、期待を理解する

**アクション**:

1. **1on1インタビュー**

   ```
   質問例:
   - プロダクトに対する期待は？
   - 最も重要な成功指標は？
   - 懸念事項は？
   - 意思決定にどう関与したいか？
   ```

2. **懸念事項の特定**
   ```
   CEO: 収益への影響、競合優位性
   CTO: 技術的実現可能性、スケーラビリティ
   営業: 顧客への訴求力、クロージング支援
   エンジニアリング: 実装の複雑さ、技術的負債
   ```

### 2. 巻き込みフェーズ

**目的**: 早期から巻き込み、オーナーシップを醸成する

**アクション**:

1. **ワークショップへの招待**
   - ビジョンボード作成ワークショップ
   - OKR設定セッション
   - ロードマップ優先順位付け

2. **フィードバックループの確立**

   ```
   ドラフト作成 → レビュー依頼 → フィードバック収集 → 調整 → 再レビュー
   ```

3. **チャンピオンの特定**
   - 各チーム/部門に協力者を見つける
   - 彼らを通じて情報を拡散

### 3. 合意形成フェーズ

**目的**: 戦略に対する合意を獲得する

**アクション**:

1. **レビューセッション**

   ```
   アジェンダ:
   1. 背景とコンテキスト（5分）
   2. ビジョン/OKR/ロードマップの提示（15分）
   3. 質疑応答（20分）
   4. フィードバック収集（15分）
   5. 次のステップ（5分）
   ```

2. **異なる視点への対応**

   ```
   懸念: "このロードマップは野心的すぎる"
   対応: データで実現可能性を示す + 段階的アプローチを提案

   懸念: "顧客要望と異なる"
   対応: 顧客インタビューの洞察を共有 + 長期的価値を説明
   ```

3. **合意の文書化**
   - 決定事項を明記
   - 署名/承認プロセス
   - 次の見直し時期を設定

### 4. 継続的コミュニケーションフェーズ

**目的**: 進捗を共有し、信頼を維持する

**アクション**:

1. **定期的な更新**

   ```
   週次: 積極管理対象のステークホルダー
   月次: 情報提供対象のステークホルダー
   四半期: 全ステークホルダー（四半期レビュー）
   ```

2. **進捗レポート**

   ```markdown
   # OKR進捗レポート - Q1 Week 8

   ## ハイライト

   - MAU 14,000達成（目標25,000の56%）
   - リファラルプログラムベータ版リリース

   ## 課題

   - マーケティングキャンペーンの遅延

   ## 次週の優先事項

   - キャンペーン立ち上げ
   - パフォーマンス最適化
   ```

3. **変更の透明性**
   - ロードマップ変更時は理由を説明
   - 影響を受けるステークホルダーに事前通知

## コミュニケーション手法

### 1. ストーリーテリング

**データだけでなく、ストーリーで伝える**:

❌ **悪い例**:
"MAUを25,000に増やします"

✅ **良い例**:
"現在、多くのユーザーが登録後すぐに離脱しています。彼らは製品の価値を実感する前に諦めてしまうのです。私たちは、初回体験を劇的に改善し、ユーザーが最初の1週間で価値を実感できるようにします。これにより、MAUを2.5倍に増やせると確信しています。"

### 2. ビジュアル化

**複雑な概念を視覚的に表現**:

- ビジョンボード: 図や画像を活用
- OKR: 進捗バーや信頼度インジケーター
- ロードマップ: タイムライン、テーマ別カラーコーディング

### 3. 聞き手に合わせた調整

**ステークホルダーごとに内容を最適化**:

| ステークホルダー | 焦点                 | 詳細レベル |
| ---------------- | -------------------- | ---------- |
| CEO              | ビジネス影響、収益   | 高レベル   |
| CTO              | 技術的実現可能性     | 中レベル   |
| エンジニアリング | 実装の詳細、依存関係 | 詳細       |
| 営業             | 顧客価値、訴求力     | 中レベル   |

## よくある課題と対処法

### 課題1: ステークホルダー間の対立

**シナリオ**: 営業は機能A、エンジニアリングは技術的負債の解消を優先したい

**対処法**:

1. 両者の懸念を明確化
2. データで優先順位を決定（RICE等）
3. 妥協案を提示（段階的実装等）
4. 上位マネージャーに判断を仰ぐ（必要な場合）

### 課題2: 頻繁な変更要求

**シナリオ**: エグゼクティブが頻繁にロードマップの変更を要求

**対処法**:

1. 変更の影響を可視化（他の施策への影響）
2. 変更基準を事前に合意（どの条件で変更を受け入れるか）
3. 定期的なレビューサイクルを確立（その間は変更しない）

### 課題3: 情報の透明性不足

**シナリオ**: チームが戦略を理解していない、方向性が見えない

**対処法**:

1. 全社ミーティングで定期的に共有
2. 社内Wikiに常に最新版を掲載
3. Q&Aセッションを開催
4. チーム内でチャンピオンを育成

### 課題4: ネガティブなフィードバック

**シナリオ**: ステークホルダーがビジョンに否定的

**対処法**:

1. 感情的にならず、理由を深掘り
2. データや事例で説得
3. 段階的アプローチを提案（小さく始める）
4. 実験で仮説を検証

```markdown
# プロダクトビジョン レビューセッション

**参加者**: [リスト]

## アジェンダ（60分）

1. 背景とコンテキスト（5分）
   - 前四半期の振り返り
   - 市場動向

   - プロダクトビジョン
   - 年間目標

   - Objective 1とKey Results
   - Objective 2とKey Results
   - 測定方法と現在値

   - 懸念事項の議論
   - 代替案の検討

6. 次のステップ（5分）
   - アクションアイテム
   - 承認/調整の決定
   - 次回レビュー日程
```
