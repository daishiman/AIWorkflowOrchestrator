# OKRフレームワーク詳細ガイド

## 概要

OKR（Objectives and Key Results）は、組織全体で目標を整列させ、測定可能な成果を追跡するためのフレームワーク。Googleをはじめとする多くのテック企業で採用されています。

## OKRの基本原則

### 1. 構造

```
Objective（目標）
  ├─ Key Result 1（成果指標）
  ├─ Key Result 2（成果指標）
  └─ Key Result 3（成果指標）
```

**Objective（目標）**:

- 定性的で鼓舞的
- 達成したい状態を表現
- チームのモチベーションを高める

**Key Results（成果指標）**:

- 定量的で測定可能
- Objectiveの達成度を示す指標
- 通常は2-5個（推奨は3個）

### 2. 野心的な目標設定

OKRは**70%達成で成功**とみなす「ストレッチゴール」です。

- **100%達成**: 目標が低すぎる → 次回はより野心的に
- **70%達成**: 適切な難易度 → 成功
- **30%以下**: 目標が高すぎるか実行に問題 → 振り返りが必要

### 3. 透明性と整合性

**全社公開**:

- すべてのOKRは全社員が閲覧可能
- 他チームの目標を理解し、協力機会を発見

**カスケード**:

```
Company OKRs（会社レベル）
  ↓
Product OKRs（プロダクトレベル）
  ↓
Team OKRs（チームレベル）
```

各レベルのOKRは上位レベルに貢献する必要があります。

### 4. 時間枠

- **四半期単位**: 最も一般的（Q1, Q2, Q3, Q4）
- **年次**: 会社レベルの大きな目標
- **月次**: 実験的な短期目標（稀）

## OKR設定プロセス

### Step 1: 準備（1週間前）

**情報収集**:

- 前四半期のOKR結果を確認
- 市場動向とユーザーフィードバックを分析
- 利用可能なリソースを把握
- ビジョンとロードマップを再確認

**参加者の決定**:

- プロダクトチーム全員
- 関連するステークホルダー
- エグゼクティブスポンサー

### Step 2: ドラフト作成（2-3時間のワークショップ）

**1. Objectivesのブレインストーミング（30分）**

各自が付箋に目標候補を書き出す:

- "この四半期で最も重要な成果は？"
- "ビジョン実現のために何を達成すべきか？"

グルーピングして3-5個のObjectiveに絞る。

**2. Key Resultsの定義（1時間）**

各Objectiveに対して:

- "この目標が達成されたと測定できる指標は？"
- "現在値と目標値は？"
- "野心的だが達成可能か？"

各Objectiveに2-4個のKey Resultsを設定。

**3. 整合性の確認（30分）**

- 上位レベルのOKRとの整合性
- チーム間の依存関係
- リソースの現実性

### Step 3: レビューと調整（1週間）

**レビュープロセス**:

1. チーム内レビュー
2. 上位マネージャーレビュー
3. 関連チームとの調整
4. エグゼクティブ承認

**調整のポイント**:

- 目標が野心的すぎないか
- Key Resultsが測定可能か
- 他チームとの重複や矛盾はないか

### Step 4: コミットメントと公開

- 最終版を全社に公開
- キックオフミーティングで説明
- チームメンバー全員が理解・納得

## 優れたOKRの書き方

### Objectives（目標）の書き方

**良いObjectiveの特徴**:

- 動詞で始まる（達成、向上、実現など）
- 具体的で明確
- 鼓舞的で記憶に残る
- 1文で表現できる

**例**:

✅ **良い例**:

- "ユーザーエンゲージメントを劇的に向上させる"
- "グローバル市場で確固たる地位を確立する"
- "プロダクト品質を業界トップレベルに引き上げる"

❌ **悪い例**:

- "頑張る"（測定不可能）
- "機能Xをリリースする"（タスクであり、成果ではない）
- "ユーザー満足度を改善する"（曖昧すぎる）

### Key Results（成果指標）の書き方

**良いKey Resultの特徴**:

- 定量的（数値で測定可能）
- ベースライン（現在値）と目標値を明記
- 影響力がある（達成すればObjectiveに大きく貢献）
- オーナーシップが明確

**フォーマット**:

```
[指標名]を[現在値]から[目標値]に[向上/削減/増加]
```

**例**:

✅ **良い例**:

- "月間アクティブユーザーを10,000から25,000に増加"
- "顧客チャーン率を8%から3%に削減"
- "NPSを30から50に向上"

❌ **悪い例**:

- "ユーザーを増やす"（目標値がない）
- "機能Xを実装する"（成果ではなくタスク）
- "より良いプロダクトにする"（測定不可能）

## OKRの階層構造

### Company OKRs（会社レベル）

**例**:

```
Objective: グローバル市場のリーダーになる

KR1: アジア太平洋地域のARRを$5Mから$15Mに成長
KR2: 北米市場シェアを10%から20%に拡大
KR3: 顧客満足度（NPS）を40から60に向上
```

### Product OKRs（プロダクトレベル）

会社のKR2（北米市場シェア拡大）に貢献するため:

```
Objective: 北米市場での製品競争力を強化する

KR1: エンタープライズ向け機能の採用率を30%から70%に向上
KR2: 主要競合と比較した機能充足率を60%から90%に改善
KR3: 大企業顧客（従業員1000人以上）を5社から20社に増加
```

### Team OKRs（チームレベル）

プロダクトのKR1（エンタープライズ機能採用率）に貢献するため:

```
Objective: エンタープライズ顧客のオンボーディングを最適化

KR1: オンボーディング完了率を40%から80%に向上
KR2: 初回価値実現時間を7日から2日に短縮
KR3: エンタープライズ専用ドキュメントの完成度100%達成
```

## OKRの追跡とレビュー

### 週次チェックイン

**所要時間**: 15-30分

**アジェンダ**:

1. 各Key Resultの進捗確認（%で表示）
2. 信頼度の評価（Low/Medium/High）
3. ブロッカーの特定と対処
4. 次週のアクションアイテム

**例**:

```
KR1: MAUを10,000から25,000に増加
  現在値: 14,000（進捗: 27%）
  信頼度: Medium
  ブロッカー: マーケティングキャンペーンの遅延
  アクション: キャンペーン立ち上げを来週に優先
```

### 月次レビュー

**所要時間**: 1-2時間

**アジェンダ**:

1. 全体進捗サマリー
2. On Track / At Risk / Off Track の分類
3. 主要な学びと調整事項
4. 次月の重点施策

### 四半期レビュー

**所要時間**: 半日

**最終スコアリング**:

```
Objective: ユーザーエンゲージメントを劇的に向上

KR1: MAU 10K→25K（達成: 18K = 0.53スコア）
KR2: セッション時間 5分→15分（達成: 12分 = 0.7スコア）
KR3: 週次リテンション 30%→60%（達成: 48% = 0.6スコア）

平均スコア: 0.61（Good）
```

**振り返り**:

- What went well?
- What didn't go well?
- What did we learn?
- What will we do differently?

## よくある落とし穴

### 1. タスクリストになる

❌ **悪い例**:

```
Objective: プロダクトを改善する
KR1: 機能Aを実装する
KR2: バグを50個修正する
KR3: UIを再デザインする
```

これらは**タスク**であり、**成果**ではありません。

✅ **良い例**:

```
Objective: ユーザー体験を劇的に向上させる
KR1: ユーザー満足度（CSAT）を70%から90%に向上
KR2: サポートチケット数を月300件から100件に削減
KR3: タスク完了時間を平均10分から3分に短縮
```

### 2. 簡単すぎる目標

100%達成できる目標は野心的ではありません。

❌ "アクティブユーザーを10,000から10,500に増加"（5%増）
✅ "アクティブユーザーを10,000から25,000に増加"（150%増）

### 3. 測定できないKey Results

❌ "より良いプロダクトにする"
✅ "プロダクトレビューの平均星数を3.5から4.5に向上"

### 4. オーナーシップが不明確

各Key Resultには責任者を明記:

```
KR1: MAUを10Kから25Kに増加（オーナー: 山田PM）
```

## OKRとKPIの違い

| OKR                     | KPI              |
| ----------------------- | ---------------- |
| 変化を促進              | 現状を維持       |
| 野心的（70%達成で成功） | 100%達成を目指す |
| 四半期で更新            | 継続的に追跡     |
| プロジェクト指向        | プロセス指向     |

**例**:

- **KPI**: 月間アクティブユーザー数（継続的な健全性指標）
- **OKR Key Result**: MAUを10,000から25,000に増加（成長目標）

## チェックリスト

### Objectives

- [ ] 動詞で始まり、達成したい状態を表現している
- [ ] 1文で簡潔に表現されている
- [ ] 鼓舞的で記憶に残る
- [ ] 測定可能ではないが、達成の判断ができる

### Key Results

- [ ] 定量的で測定可能
- [ ] 現在値と目標値が明記されている
- [ ] 野心的だが達成可能（70%達成を目指す）
- [ ] オーナーが明確
- [ ] 2-5個の範囲（推奨は3個）

### 全体

- [ ] 上位レベルのOKRと整合性がある
- [ ] 他チームとの重複や矛盾がない
- [ ] 利用可能なリソースで実現可能
- [ ] チーム全員が理解・納得している
