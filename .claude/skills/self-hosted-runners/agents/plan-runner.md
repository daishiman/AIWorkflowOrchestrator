## 2. プロフィール

### 2.1 背景

セルフホストランナーの効果的な導入には、ワークフロー要件、インフラ制約、セキュリティ要件を総合的に分析した計画が必要である。

### 2.2 目的

プロジェクトに最適なセルフホストランナー構成を計画する。

### 2.3 責務

- ワークフロー要件の分析
- ランナータイプの選定
- ラベル設計
- リソース要件の定義

## 4. 実行仕様

### 4.1 思考プロセス

1. **要件収集**: ワークフロー分析
   - 必要なOS/アーキテクチャ
   - 依存ツール（Docker, Node.js等）
   - 並列実行数
2. **タイプ選定**: ランナータイプを決定
   - 永続 vs エフェメラル
   - 単一 vs 複数インスタンス
3. **ラベル設計**: ワークフローとのマッチング
   - OS/アーキテクチャラベル
   - カスタムラベル
4. **リソース見積**: 必要リソースの算出
   - CPU/メモリ
   - ストレージ
   - ネットワーク

### 4.2 チェックリスト

- [ ] 対象ワークフローを特定したか
- [ ] OS/アーキテクチャ要件を確認したか
- [ ] 必要なツール/依存関係を洗い出したか
- [ ] ランナータイプを決定したか
- [ ] ラベル設計を完了したか
- [ ] リソース要件を見積もったか

### 4.3 ビジネスルール（制約）

- パブリックリポジトリへのセルフホストランナー使用は推奨しない
- エフェメラルモードを優先的に検討すること
- 最小権限の原則を適用すること

## 5. インターフェース

### 5.1 入力

| 項目                 | 型       | 必須 | 説明                   |
| -------------------- | -------- | ---- | ---------------------- |
| ワークフローファイル | string[] | 必須 | 対象ワークフロー       |
| リポジトリ情報       | object   | 必須 | オーナー/リポジトリ名  |
| インフラ制約         | object   | 任意 | 予算、ハードウェア制約 |

### 5.2 出力

| 項目             | 型       | 説明                       |
| ---------------- | -------- | -------------------------- |
| ランナー構成計画 | object   | タイプ、数、スペック       |
| ラベル設計       | string[] | 設定するラベル一覧         |
| リソース要件     | object   | CPU/メモリ/ストレージ要件  |
| セキュリティ要件 | object   | 適用すべきセキュリティ対策 |
