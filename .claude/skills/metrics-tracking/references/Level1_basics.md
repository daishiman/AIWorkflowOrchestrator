# Level 1: Basics

## 概要

メトリクス追跡の基本概念、メトリクス選択の原則、基本的なベロシティとバーンダウンの計測方法を扱います。

SKILL.md の内容だけで完結する基本運用を理解し、アジャイル開発における基本的なメトリクスの役割を学びます。

## 前提条件

- SKILL.md の概要とワークフローを読了している
- アジャイル開発の基本用語（スプリント、バックログ、ストーリーポイント）を理解している

## メトリクス追跡とは

### 目的

開発チームのパフォーマンスを可視化し、データに基づく意思決定と継続的改善を実現する。

### 主要な価値

- **予測可能性の向上**: 過去のデータから将来の見積もり精度を高める
- **ボトルネックの発見**: プロセスの問題点を数値で特定する
- **透明性の確保**: チーム内外への進捗状況の可視化
- **改善の測定**: 施策の効果を定量的に評価する

## 基本メトリクス

### 1. ベロシティ（Velocity）

**定義**: スプリント期間中にチームが完了したストーリーポイントの合計

**計測方法**:

```
ベロシティ = 完了したストーリーの合計ポイント
```

**使用タイミング**:

- スプリント終了時に計測
- 3-5スプリントの平均値を使用して次回スプリント計画を立てる

**注意点**:

- チーム構成が変わった場合、ベロシティは変動する
- ベロシティの絶対値でチームを比較しない（各チームの見積もり基準が異なる）
- 個人のベロシティは計測しない（心理的安全性を損なう）

### 2. バーンダウンチャート（Burndown Chart）

**定義**: スプリント期間中の残作業量の推移を示すグラフ

**要素**:

- X軸: スプリントの日数
- Y軸: 残りストーリーポイント
- 理想線: 一定ペースで作業が完了した場合の線
- 実績線: 実際の完了状況を示す線

**使用タイミング**:

- 毎日更新し、デイリースタンドアップで確認
- スプリント後半で理想線から大きく乖離している場合、スコープ調整を検討

**良い兆候**:

- 実績線が理想線に沿っている
- 早めに完了して余裕がある

**悪い兆候**:

- スプリント終了間際まで残作業が多い
- 実績線が横ばい（作業が進んでいない）

### 3. リードタイム（Lead Time）

**定義**: 課題がバックログに追加されてから完了するまでの時間

**計測方法**:

```
リードタイム = 完了日時 - 作成日時
```

**使用タイミング**:

- 各課題の完了時に記録
- 週次・月次で平均値と中央値を分析

**分析観点**:

- リードタイムが長い課題の特徴を分析（大きすぎる、依存関係が多い等）
- ボトルネック（レビュー待ち、テスト待ち等）を特定

## メトリクス選択の原則

### 1. ビジネスゴールとの紐付け

メトリクスは「計測しやすいから」ではなく、「ビジネス成果に貢献するから」選ぶ。

**良い例**:

- 目標: 市場投入速度の向上 → リードタイムを計測
- 目標: 品質向上 → バグ修正時間を計測

**悪い例**:

- 目標: 不明確 → コード行数を計測（意味のない指標）

### 2. 計測可能性の確認

データソースが存在し、低コストで取得できることを確認する。

**良い例**:

- Jira に課題データがある → リードタイムを自動計算可能
- GitHub に PR データがある → レビュー時間を計測可能

**悪い例**:

- データが手動入力のみ → 入力負荷が高く、継続困難

### 3. チーム文化への配慮

メトリクスが個人評価に使われると、心理的安全性が損なわれる。

**原則**:

- チーム全体のメトリクスのみを公開
- 個人のベロシティやコミット数は計測しない
- メトリクスは「改善のツール」であり「評価のツール」ではないことを明示

## 実践手順

### ステップ1: 最初のメトリクスを選ぶ

**推奨**: まずベロシティとバーンダウンから始める

理由:

- アジャイル開発の標準メトリクス
- Jira, GitHub Projects 等で簡単に可視化できる
- チームの計画精度向上に直結

### ステップ2: データを収集する

**手順**:

1. Jira または GitHub Projects でスプリントボードを作成
2. 各ストーリーにポイントを付与
3. スプリント期間中、完了したストーリーを「Done」に移動
4. スプリント終了時、完了ポイントを集計

### ステップ3: チームで結果を振り返る

**振り返りの観点**:

- 計画したポイントと実際の完了ポイントの差
- バーンダウンチャートで見えたボトルネック
- 次スプリントで改善できること
