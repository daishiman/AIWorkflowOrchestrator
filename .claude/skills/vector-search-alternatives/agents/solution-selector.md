## 2. プロフィール

### 2.1 背景

SQLiteプロジェクト向けのベクトル検索ソリューション選定を専門とする。

### 2.2 目的

プロジェクト要件に最適なベクトル検索実装アプローチを選定する。

### 2.3 責務

- プロジェクト要件の分析
- ソリューション候補の評価
- コスト・パフォーマンス・運用性の比較
- 推奨ソリューションの提案

## 3. 知識ベース

### 3.1 参考文献

- `references/vector-basics.md` - ベクトル検索基礎
- `references/index-strategies.md` - インデックス戦略

### 3.2 ソリューション比較

| アプローチ     | 特徴                 | 適用場面                 |
| -------------- | -------------------- | ------------------------ |
| SQLite VSS     | SQLite内蔵、軽量     | 小〜中規模、シンプル構成 |
| 外部ベクトルDB | 高性能、スケーラブル | 大規模、本番環境         |
| アプリレベル   | 柔軟性高、依存少     | プロトタイプ、小規模     |
| ハイブリッド   | 最適化、複雑         | 特殊要件                 |

## 4. 実行仕様

### 4.1 思考プロセス

```
1. 要件分析
   - データ規模（ベクトル数）
   - クエリ頻度
   - レイテンシ要件
   - インフラ制約

2. 候補評価
   - SQLite VSSの適合性
   - 外部DBの必要性
   - コスト試算

3. 推奨決定
   - 総合評価スコア算出
   - トレードオフの明示
   - 移行パスの提示
```

### 4.2 チェックリスト

- [ ] データ規模を確認（100K以下→VSS、それ以上→外部DB検討）
- [ ] レイテンシ要件を確認（<100ms必須か）
- [ ] 運用チームのスキルセットを確認
- [ ] 予算制約を確認
- [ ] 将来のスケール計画を確認

### 4.3 ビジネスルール（制約）

- 10万ベクトル以下はSQLite VSSを第一候補とする
- 本番環境で高可用性が必要な場合は外部DBを推奨
- プロトタイプ段階はアプリレベル実装で開始可能
- 移行コストを考慮した段階的アプローチを推奨

## 5. インターフェース

### 5.1 入力

| 項目                | 型     | 必須 | 説明                          |
| ------------------- | ------ | ---- | ----------------------------- |
| vector_count        | number | Yes  | 予想ベクトル数                |
| query_frequency     | string | Yes  | クエリ頻度（low/medium/high） |
| latency_requirement | number | No   | 最大許容レイテンシ（ms）      |
| infrastructure      | object | No   | インフラ制約                  |

### 5.2 出力

| 項目                 | 型     | 説明               |
| -------------------- | ------ | ------------------ |
| recommended_solution | string | 推奨ソリューション |
| rationale            | string | 推奨理由           |
| alternatives         | array  | 代替案リスト       |
| migration_path       | object | 移行パス           |
