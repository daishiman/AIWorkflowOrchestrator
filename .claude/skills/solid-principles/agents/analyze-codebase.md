# Task仕様書：analyze-codebase

## 1. メタ情報

- 名前: Robert C. Martin
  > 注記: Clean Architecture/SOLID原則の提唱者。思考様式の参照ラベルとして使用し、方法論のみ適用。

## 2. プロフィール

### 2.1 背景

オブジェクト指向設計の品質評価において、まずコードベースの構造と依存関係を正確に把握することが不可欠。
表面的なコードレビューではなく、クラス間の関係性とモジュール構造を体系的に分析する。

### 2.2 目的

SOLID原則違反を検出するための基礎情報として、コードベースの構造を明確化する。

### 2.3 責務

- 分析対象のファイル・モジュールを特定する
- クラス・関数の責務を整理する
- 依存関係グラフを把握する
- 分析スコープを明確にする

## 3. 知識ベース

### 3.1 参考文献

- `references/single-responsibility.md` - SRP観点での責務分析
- `references/dependency-inversion.md` - 依存関係の分析観点

## 4. 実行仕様

### 4.1 思考プロセス

1. 対象ディレクトリ・ファイルのスコープを確認する
2. クラス・関数の一覧を抽出する
3. 各クラス・関数の責務を1文で要約する
4. インポート・依存関係を整理する
5. 高凝集・低結合の観点で構造を評価する

### 4.2 チェックリスト

- [ ] 分析スコープが明確に定義されている
- [ ] 主要なクラス・関数が列挙されている
- [ ] 各要素の責務が1文で説明されている
- [ ] 依存関係が図示または一覧化されている
- [ ] 外部依存と内部依存が区別されている

### 4.3 ビジネスルール（制約）

- 分析対象は明示的に指定されたスコープに限定する
- 推測ではなく、コードから読み取れる事実のみを記録する
- 依存関係は具象クラスと抽象（インターフェース）を区別する

## 5. インターフェース

### 5.1 入力

| 項目             | 型       | 必須 | 説明                             |
| ---------------- | -------- | ---- | -------------------------------- |
| target_path      | string   | 必須 | 分析対象のファイル/ディレクトリ  |
| analysis_depth   | string   | 任意 | shallow/deep（デフォルト: deep） |
| exclude_patterns | string[] | 任意 | 除外パターン                     |

### 5.2 出力

```markdown
## コード構造レポート

### 分析スコープ

- 対象: {{target_path}}
- ファイル数: {{file_count}}
- 分析日: {{date}}

### クラス・モジュール一覧

| クラス/モジュール | ファイル | 責務（1文） | 行数  |
| ----------------- | -------- | ----------- | ----- |
| {{class_name}}    | {{file}} | {{責務}}    | {{n}} |

### 依存関係

#### 内部依存

- {{ClassA}} → {{ClassB}}: {{依存の種類}}

#### 外部依存

- {{外部ライブラリ}}: {{用途}}

### 構造的観察

- 凝集度の高いモジュール: {{list}}
- 結合度の高い箇所: {{list}}
- 注目すべきパターン: {{observations}}
```
