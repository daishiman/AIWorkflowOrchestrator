## 4. 実行仕様

### 4.1 思考プロセス

1. **データソース特定**: 入力元を特定（ファイル、HTTP、WebSocket、メモリ等）
2. **データシンク特定**: 出力先を特定（ファイル、HTTP、コンソール等）
3. **フロー方向決定**: 単方向か双方向かを判断
4. **変換要件抽出**: データ変換の必要性と内容を特定
5. **バックプレッシャー評価**: 生産速度と消費速度の差を評価
6. **ストリームタイプ選定**: 要件に基づきタイプを決定

### 4.2 ストリームタイプ選定ガイド

| ユースケース                 | 推奨タイプ | 理由                  |
| ---------------------------- | ---------- | --------------------- |
| ファイル読み込み             | Readable   | 読み取り専用          |
| ファイル書き込み             | Writable   | 書き込み専用          |
| データ変換（圧縮、暗号化等） | Transform  | 入力を変換して出力    |
| ネットワーク通信（TCP等）    | Duplex     | 双方向通信            |
| カスタムデータソース         | Readable   | push/pullモードで生成 |

### 4.3 チェックリスト

| 項目                           | 基準                                     |
| ------------------------------ | ---------------------------------------- |
| データソースが明確か           | ファイル/ネットワーク/メモリ等が特定済み |
| データシンクが明確か           | 出力先が特定済み                         |
| フロー方向が決定しているか     | 単方向/双方向が決定済み                  |
| 変換処理が明確か               | 変換の有無と内容が特定済み               |
| バックプレッシャー戦略があるか | highWaterMarkの設定方針が決定済み        |
| ストリームタイプが選定済みか   | Readable/Writable/Transform/Duplexを選定 |

### 4.4 ビジネスルール（制約）

| 制約項目               | 内容                                     |
| ---------------------- | ---------------------------------------- |
| メモリ使用量上限       | 必ず設定（デフォルト16KB超は要検討）     |
| エラーハンドリング     | 必須（未処理エラーはプロセスクラッシュ） |
| リソースクリーンアップ | destroy()の呼び出しを保証                |
