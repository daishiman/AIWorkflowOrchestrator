# 18.3.6 本文の必須セクション

**出典**: `docs/00-requirements/18-commands.md` の 18.3.6

## コマンド全体の記述形式

```markdown
# {{コマンド名}}

## 目的

{{このコマンドで何を達成するか（1-2文）}}

## 背景

{{なぜこのコマンドが必要か、どのような課題を解決するか}}

## ゴール

{{コマンド実行後の達成状態、完了時の状態}}

## エージェント起動フロー

（以下、Phase別に記述）
```

## 必須セクション

| セクション             | 必須 | 説明                        |
| ---------------------- | ---- | --------------------------- |
| 目的                   | 必須 | コマンド全体の目的（1-2文） |
| 背景                   | 必須 | なぜこのコマンドが必要か    |
| ゴール                 | 必須 | コマンド実行後の達成状態    |
| エージェント起動フロー | 必須 | Phase別の処理フロー         |

## 目的の記述ガイドライン

| ガイドライン       | 説明                                 |
| ------------------ | ------------------------------------ |
| 1-2文で簡潔に      | 「〜を作成する」「〜を分析する」形式 |
| 動詞で開始         | 「作成する」「分析する」「生成する」 |
| 具体的な対象を明記 | 何を対象にするかを明確に             |

### 例

- ✅ 良い例: 「Claude Code エージェントを作成し、18.4.8/18.4.9テンプレートに準拠したファイルを生成する」
- ✅ 良い例: 「プロジェクトの要件を分析し、実装計画書を生成する」
- ❌ 悪い例: 「色々なことをする」（抽象的すぎる）
- ❌ 悪い例: 「準備」（何を準備するのか不明確）

## 背景の記述ガイドライン

| ガイドライン         | 説明                                         |
| -------------------- | -------------------------------------------- |
| 理由を説明           | なぜこのコマンドが必要かを明確に             |
| 課題を明記           | どのような課題を解決するかを記述             |
| ユーザーの痛みに共感 | ユーザーが抱える問題を理解していることを示す |

### 例

- ✅ 良い例: 「エージェント作成には、ペルソナ設計、ワークフロー設計、スキル依存関係の設定など多岐にわたる知識が必要です。本コマンドは、これらのプロセスを自動化し、18.4.8/18.4.9テンプレートに準拠したエージェントを効率的に生成します。」
- ✅ 良い例: 「手動でスキルを作成すると、Progressive Disclosure設計やフィードバックループの実装を忘れがちです。本コマンドは、SECIモデルに基づいた体系的なスキル作成をサポートします。」
- ❌ 悪い例: 「必要だから」（理由が不明確）

## ゴールの記述ガイドライン

| ガイドライン   | 説明                       |
| -------------- | -------------------------- |
| 完了状態を明記 | 「〜が生成された状態」形式 |
| 検証可能       | 完了を確認できる状態を記述 |
| 具体的な成果物 | 何が生成されるかを明記     |

### 例

- ✅ 良い例: 「18.4.8/18.4.9テンプレートに準拠したエージェントファイル（.claude/agents/{{name}}.md）が生成され、検証が完了した状態」
- ✅ 良い例: 「18.5仕様に準拠したスキルフォルダ（SKILL.md, EVALS.json, CHANGELOG.md, LOGS.md, scripts/log_usage.mjs）が生成された状態」
- ❌ 悪い例: 「だいたい完了」（曖昧）
- ❌ 悪い例: 「良い感じ」（検証不可能）

## エージェント起動フローの記述

エージェント起動フローは、18.3.7のテンプレートに従って記述します。
詳細は `specification-18.3.7-agent-launch-flow.md` を参照してください。

## 完全な例: エージェント作成コマンド

```markdown
# エージェント作成コマンド

## 目的

Claude Code エージェントを作成し、18.4.8/18.4.9テンプレートに準拠したファイルを生成する。

## 背景

エージェント作成には、ペルソナ設計（モデル人物、参考文献）、ワークフロー設計（Phase別）、スキル依存関係の設定など多岐にわたる知識が必要です。本コマンドは、meta-agent-designer エージェントを起動し、これらのプロセスを自動化します。18.4.8/18.4.9テンプレートに準拠したエージェントを効率的に生成することで、品質の高いエージェント開発を支援します。

## ゴール

18.4.8/18.4.9テンプレートに準拠したエージェントファイル（.claude/agents/{{name}}.md）が生成され、YAML構文検証と行数チェック（450-550行）が完了した状態。

## エージェント起動フロー

### Phase 1: 要件理解と分析

#### 目的

ユーザー要件を分析し、エージェント設計方針を決定する

#### 背景

曖昧な要件のままエージェント作成を開始すると、単一責任原則が守られず手戻りが発生します。

#### ゴール

エージェントの目的・専門分野・モデル人物が明確化された状態

#### 起動エージェント

- `.claude/agents/meta-agent-designer.md`

#### Taskツール起動

Task ツールで `.claude/agents/meta-agent-designer.md` を起動

#### コンテキスト

- ユーザーが指定したエージェント名
- エージェントの目的と専門分野（ユーザーから収集）
- 既存エージェントとの重複チェック結果

#### 完了条件

- [ ] エージェントの目的が明確
- [ ] 設計方針が決定
- [ ] モデル人物の候補が特定されている
- [ ] 既存エージェントとの重複がない

### Phase 2: エージェントファイル生成

（以下、Phase 2-6を同様の形式で記述）
```

## 検証チェックリスト

- [ ] 目的セクションが存在し、1-2文で簡潔に記述されている
- [ ] 背景セクションが存在し、課題と解決方法が記述されている
- [ ] ゴールセクションが存在し、検証可能な完了状態が記述されている
- [ ] エージェント起動フローセクションが存在する
- [ ] エージェント起動フローが18.3.7のテンプレートに従っている
- [ ] 各Phaseに目的・背景・ゴール・起動エージェント・完了条件がある
