# 18.3.4 description フィールドの記述形式

**出典**: `docs/00-requirements/18-commands.md` の 18.3.4

## 記述形式

```yaml
description: |
  {{コマンドの目的（1-2行）}}

  🤖 起動エージェント:
  - `.claude/agents/{{agent-name}}.md`: {{エージェントの役割}}

  ⚙️ このコマンドの設定:
  - argument-hint: {{引数の説明}}
  - allowed-tools: {{ツールリストの説明}}
  - model: {{モデル選択理由}}

  トリガーキーワード: {{keyword1}}, {{keywordN}}
```

## 記述規則

| 規則                 | 説明                                                     |
| -------------------- | -------------------------------------------------------- |
| エージェントのみ記述 | スキルはエージェントが参照するため、コマンドでは記述不要 |
| 相対パス必須         | `.claude/agents/{{agent-name}}.md` 形式で記述            |
| スキル参照は委譲     | スキル情報はエージェントの description で管理            |

## 構成要素

### 1. コマンドの目的（1-2行）

| ガイドライン   | 説明                             |
| -------------- | -------------------------------- |
| 1-2行で簡潔に  | 長すぎる説明は避ける             |
| 何をするか明確 | コマンドの主要機能を簡潔に記述   |
| ユーザー視点   | ユーザーが理解しやすい表現を使う |

#### 例

```yaml
description: |
  Claude Code エージェントを作成するコマンド。
  要件を分析し、18.4.8/18.4.9テンプレートに準拠したエージェントファイルを生成します。
```

### 2. 起動エージェント

| ガイドライン           | 説明                                |
| ---------------------- | ----------------------------------- |
| 🤖 絵文字で明示        | `🤖 起動エージェント:` で開始       |
| 相対パス必須           | `.claude/agents/{{name}}.md` 形式   |
| 役割を簡潔に           | エージェントの役割を20-40文字で説明 |
| 1コマンド1エージェント | 基本的に1つのエージェントのみ起動   |

#### 例

```yaml
  🤖 起動エージェント:
  - `.claude/agents/meta-agent-designer.md`: エージェント設計・作成の専門家
```

```yaml
  🤖 起動エージェント:
  - `.claude/agents/skill-librarian.md`: スキル設計・最適化の専門家
```

### 3. このコマンドの設定

| ガイドライン    | 説明                                |
| --------------- | ----------------------------------- |
| ⚙️ 絵文字で明示 | `⚙️ このコマンドの設定:` で開始     |
| 3項目を記述     | argument-hint, allowed-tools, model |
| 理由を明記      | なぜその設定なのかを説明            |

#### 例

```yaml
  ⚙️ このコマンドの設定:
  - argument-hint: [エージェント名] - 作成するエージェントの名前（ケバブケース）
  - allowed-tools: Read, Write, Grep（エージェント・スキル読み取り、ファイル生成）
  - model: opus - 複雑な設計判断が必要なため
```

### 4. トリガーキーワード

| ガイドライン     | 説明                           |
| ---------------- | ------------------------------ |
| 日本語・英語併記 | 両方の言語でキーワードを列挙   |
| 5-10個が目安     | 少なすぎず多すぎない適切な数   |
| ユーザー視点     | ユーザーが使いそうな言葉を選ぶ |

#### 例

```yaml
トリガーキーワード: エージェント作成, サブエージェント作成, agent作成, create agent, new agent
```

## 完全な例1: エージェント作成コマンド

```yaml
---
description: |
  Claude Code エージェントを作成するコマンド。
  要件を分析し、18.4.8/18.4.9テンプレートに準拠したエージェントファイルを生成します。

  🤖 起動エージェント:
  - `.claude/agents/meta-agent-designer.md`: エージェント設計・作成の専門家

  ⚙️ このコマンドの設定:
  - argument-hint: [エージェント名] - 作成するエージェントの名前（ケバブケース）
  - allowed-tools: Read, Write, Grep, Task（エージェント・スキル読み取り、ファイル生成、サブエージェント起動）
  - model: opus - 複雑な設計判断が必要なため

  トリガーキーワード: エージェント作成, サブエージェント作成, agent作成, create agent, new agent
allowed-tools:
  - Read
  - Write
  - Grep
  - Task
model: opus
---
```

## 完全な例2: スキル作成コマンド

```yaml
---
description: |
  Claude Code スキルを作成するコマンド。
  SECIモデルに基づき、Progressive Disclosure設計を適用したスキルファイルを生成します。

  🤖 起動エージェント:
  - `.claude/agents/skill-librarian.md`: スキル設計・最適化の専門家

  ⚙️ このコマンドの設定:
  - argument-hint: [スキル名] - 作成するスキルの名前（ケバブケース）
  - allowed-tools: Read, Write, Bash（スキル・ドキュメント読み取り、ファイル生成、スクリプト実行）
  - model: sonnet - 標準的なスキル設計タスク

  トリガーキーワード: スキル作成, skill作成, create skill, new skill, スキル追加
allowed-tools:
  - Read
  - Write
  - Bash
model: sonnet
---
```

## 禁止事項

| 禁止事項                     | 理由                                             |
| ---------------------------- | ------------------------------------------------ |
| スキルを直接記述             | Command → Agent → Skill の依存方向に違反         |
| エージェントの内部詳細を記述 | description が肥大化する                         |
| 複数のエージェントを起動     | 1コマンド1エージェントの原則に違反               |
| 絶対パスでエージェントを参照 | 環境依存になる                                   |
| トリガーキーワードなし       | 自動発動ができなくなる（推奨事項だが、強く推奨） |

## 検証チェックリスト

- [ ] コマンドの目的が1-2行で簡潔に記述されている
- [ ] 起動エージェントが `🤖 起動エージェント:` で明示されている
- [ ] エージェントパスが相対パス形式（`.claude/agents/{{name}}.md`）
- [ ] エージェントの役割が20-40文字で簡潔に記述されている
- [ ] コマンドの設定が `⚙️ このコマンドの設定:` で明示されている
- [ ] argument-hint, allowed-tools, model の理由が記述されている
- [ ] トリガーキーワードが5-10個程度列挙されている
- [ ] スキルを直接参照していない（エージェントに委譲）
- [ ] 全体が簡潔で読みやすい（500文字程度）
