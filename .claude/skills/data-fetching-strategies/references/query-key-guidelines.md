# クエリキー設計ガイド

## 目的

クエリキーの一貫性を保ち、キャッシュの誤衝突を防ぐ。

## 基本ルール

- 配列形式で階層を表現する
- 取得対象と条件を明確に含める
- 文字列結合で曖昧なキーを作らない

## 例

```tsx
// 推奨
["users", "list", { status: "active" }]
["user", userId]

// 非推奨
"users-active"
"user" + userId
```

## 運用指針

1. キー命名規則をドキュメント化する
2. ミューテーション後は該当キーを無効化する
3. 依存関係があるキーは階層で整理する
