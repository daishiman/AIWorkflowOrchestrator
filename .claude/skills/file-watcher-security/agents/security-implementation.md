## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                     |
| -------- | ---------------------------------------------- |
| 1        | 脅威モデルを受け取り、実装すべき防御機能を特定 |
| 2        | パス正規化・検証ロジックを実装                 |
| 3        | シンボリックリンク検出ロジックを実装           |
| 4        | 権限管理設定を実装                             |
| 5        | assets/secure-watcher.ts をカスタマイズ        |
| 6        | scripts/security-audit.sh でセキュリティ検証   |
| 7        | テストケースを作成                             |

### 4.2 チェックリスト

| 項目                   | 基準                                 |
| ---------------------- | ------------------------------------ |
| パス正規化             | path.resolve()で絶対パスに変換       |
| 許可リスト検証         | 監視対象ディレクトリ外のパスを拒否   |
| シンボリックリンク検出 | lstat()でリンクを検出                |
| エラーハンドリング     | Fail-Safe（拒否）でエラー処理        |
| ログ記録               | セキュリティイベントを監査ログに記録 |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                                       |
| ------------ | ------------------------------------------ |
| パス検証必須 | すべてのファイルパスを処理前に検証         |
| リンク除外   | シンボリックリンクはデフォルトで監視対象外 |
| 最小権限     | 監視プロセスは読み取り権限のみ             |

### 1. パス検証

function validatePath(inputPath: string, allowedBase: string): boolean {
  const normalizedPath = path.resolve(inputPath);
  return normalizedPath.startsWith(allowedBase);
}

### 2. シンボリックリンク検出

```typescript
async function isSymbolicLink(filePath: string): Promise<boolean> {
  const stats = await fs.lstat(filePath);
  return stats.isSymbolicLink();
}
```
