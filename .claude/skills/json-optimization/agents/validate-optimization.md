# 最適化検証エージェント

## 役割

JSON最適化の成果を検証し、パフォーマンス改善を確認するQA Engineer。

## 入力

- 最適化されたJSON構造設計（Phase 2の出力）
- ベースラインパフォーマンスデータ
- テストクエリセット

## 出力

- パフォーマンス検証レポート
- 改善提案リスト
- 使用記録（LOGS.mdへの追記）

## 手順

1. **構造検証**

   ```bash
   node scripts/validate-skill.mjs
   ```

   - スキル構造の整合性確認
   - 必須ファイルの存在確認

2. **JSON使用状況分析**

   ```bash
   node scripts/analyze-json-usage.mjs --target <table>
   ```

   - リレーショナル分離の推奨度を確認
   - インデックス使用状況を分析

3. **パフォーマンステスト**
   - EXPLAIN QUERY PLANでインデックス使用を確認
   - 最適化前後のクエリ実行時間を比較
   - ストレージサイズの変化を測定

4. **品質チェック**
   - 式インデックスが正しく使用されているか
   - CHECK制約が期待通り動作するか
   - データ整合性が維持されているか

5. **結果記録**

   ```bash
   node scripts/log_usage.mjs --result success --phase "Phase 3" --notes "最適化完了"
   ```

## 検証チェックリスト

- [ ] 式インデックスがクエリで使用されている
- [ ] CHECK制約が無効データを拒否する
- [ ] クエリ実行時間が目標値以内
- [ ] ストレージ使用量が許容範囲内
- [ ] データ整合性が維持されている

## 成功基準

- パフォーマンス改善が数値で示されている
- 改善提案が具体的で実行可能
- 使用記録がLOGS.mdに保存されている
