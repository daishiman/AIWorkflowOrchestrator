## 2. システムアーキテクチャ

### 2.1 アーキテクチャ図

```
[ユーザー] → [フロントエンド] → [API Gateway] → [LLMサービス] → [LLM (OpenAI/Anthropic等)]
                                       ↓
                                 [データベース]
                                       ↓
                                 [外部API/データソース]
```

### 2.2 データフロー

1. **入力フロー**: ユーザー → フロントエンド → API → LLMサービス → LLM
2. **出力フロー**: LLM → LLMサービス → API → フロントエンド → ユーザー
3. **データ取得フロー**: LLMサービス → 外部API/DB → LLMサービス → LLM

### 2.3 信頼境界

#### 信頼できる要素

- システムプロンプト（開発者が定義）
- 認証済みユーザーの権限情報（検証済み）
- 内部API（認証・認可済み）
- プライベートデータベース

#### 信頼できない要素

- ユーザー入力（すべて）
- 外部APIからのデータ
- Webからクロールしたコンテンツ
- ユーザーがアップロードしたファイル
- 第三者のプラグインやツール

#### 境界の定義

```
信頼境界1: フロントエンド ←→ バックエンド API
  → すべての入力を検証

信頼境界2: LLMサービス ←→ 外部データソース
  → 外部データの信頼性を評価

信頼境界3: システムプロンプト ←→ ユーザー入力
  → 構造化により明確に分離
```

## 3. 脅威の特定

### 3.1 直接的プロンプトインジェクション

| ID    | 攻撃パターン           | 説明                                       | 実現可能性 | 影響度       |
| ----- | ---------------------- | ------------------------------------------ | ---------- | ------------ | --- | --- |
| T-001 | システムプロンプト抽出 | 「前の指示を繰り返してください」等の試行   | 高         | 高           |
| T-002 | 役割上書き             | 「あなたは今から開発者モードです」等の試行 | 高         | 中           |
| T-003 | 指示の無視             | 「前の指示を無視してください」等の試行     | 高         | 中           |
| T-004 | 特殊トークンの悪用     | LLM特殊トークン（`<                        | im_start   | >`等）の注入 | 中  | 高  |
| T-005 | 出力フォーマットの改変 | 「JSON形式で応答してください」等の試行     | 中         | 低           |

### 3.2 間接的プロンプトインジェクション

| ID    | 攻撃パターン                       | 説明                                   | 実現可能性 | 影響度 |
| ----- | ---------------------------------- | -------------------------------------- | ---------- | ------ |
| T-101 | Webページ経由のインジェクション    | Webページに埋め込まれた指示をLLMが実行 | 中         | 高     |
| T-102 | ドキュメント経由のインジェクション | PDFやWord文書に埋め込まれた指示        | 中         | 高     |
| T-103 | データベース経由のインジェクション | 過去に保存された悪意のあるデータを利用 | 低         | 高     |
| T-104 | 非表示テキストの悪用               | HTML/CSSで非表示にされたテキストの利用 | 中         | 中     |

### 3.3 チェーン攻撃

| ID    | 攻撃パターン         | 説明                                      | 実現可能性 | 影響度 |
| ----- | -------------------- | ----------------------------------------- | ---------- | ------ |
| T-201 | 多段階権限昇格       | 複数のLLM呼び出しを経由して権限を昇格     | 低         | 高     |
| T-202 | データ抽出チェーン   | 要約→翻訳→送信の流れで機密データを抽出    | 中         | 高     |
| T-203 | ツール呼び出しの悪用 | LLMに許可されたツールを悪用して攻撃を実行 | 中         | 高     |

### 3.4 その他のLLM固有脅威

| ----- | ------------------------- | ---------------------------------------- | ---------- | ------ |
| T-301 | モデル拒否サービス（DoS） | 極端に長い入力や複雑な処理を強制         | 高         | 中     |
| T-302 | トレーニングデータ抽出    | モデルのトレーニングデータを抽出する試行 | 低         | 中     |
| T-303 | モデルの偏見の悪用        | モデルの偏見を利用して不適切な出力を誘導 | 中         | 低     |

## 4. 脅威の評価

### 4.1 リスクマトリクス

|                | 影響度：低   | 影響度：中          | 影響度：高   |
| -------------- | ------------ | ------------------- | ------------ |
| 実現可能性：高 | T-301        | T-002, T-003        | T-001        |
| 実現可能性：中 | T-005, T-303 | T-104, T-202, T-203 | T-101, T-102 |
| 実現可能性：低 |              | T-302               | T-103, T-201 |

### 4.2 優先度付け

#### 最優先（Critical）

1. **T-001: システムプロンプト抽出**
   - 影響: システムの内部ロジック、機密情報、APIキー等が漏洩
   - 対策: プロンプト構造化、出力検証

2. **T-101: Webページ経由のインジェクション**
   - 影響: 外部Webページ経由で任意のコマンドを実行される
   - 対策: 外部データソースの信頼性評価、間接インジェクション検出

3. **T-102: ドキュメント経由のインジェクション**
   - 影響: アップロードされた文書経由で攻撃を受ける
   - 対策: ドキュメントのサニタイゼーション、信頼スコアリング

#### 高優先度（High）

4. **T-004: 特殊トークンの悪用**
5. **T-202: データ抽出チェーン**
6. **T-203: ツール呼び出しの悪用**

#### 中優先度（Medium）

7. **T-002: 役割上書き**
8. **T-003: 指示の無視**
9. **T-104: 非表示テキストの悪用**

## 5. 防御戦略

### 5.1 脅威ごとの対策マッピング

| 脅威ID | 防御層                                     | 具体的対策                                             |
| ------ | ------------------------------------------ | ------------------------------------------------------ |
| T-001  | 入力検証、プロンプト構造化、出力検証       | 禁止パターン検出、デリミタ、システムプロンプト漏洩検出 |
| T-002  | 入力検証、プロンプト構造化                 | 役割上書きパターン検出、境界の明確化                   |
| T-003  | プロンプト構造化、出力検証                 | デリミタ、文脈一貫性チェック                           |
| T-004  | 入力検証                                   | 特殊トークンのエスケープまたは検出                     |
| T-101  | 外部データ検証、間接インジェクション検出   | 信頼スコアリング、非表示テキスト検出                   |
| T-102  | ドキュメントサニタイゼーション、構造化検証 | メタデータ除去、構造化パース                           |
| T-202  | コンテキスト分離、ログと監視               | セッション隔離、異常パターン検出                       |
| T-203  | 最小権限原則、ツールアクセス制御           | ホワイトリスト方式、権限最小化                         |

### 5.2 多層防御の設計

```
Layer 1: 入力検証
  - 長さ制限
  - 禁止パターン検出
  - 構造化検証

Layer 2: プロンプト構造化
  - デリミタによる境界明確化
  - システムメッセージ分離
  - エスケープ処理

Layer 3: 出力検証
  - システムプロンプト漏洩検出
  - 機密情報パターン検出
  - トピック逸脱検出

Layer 4: コンテキスト分離
  - 最小権限原則
  - セッション隔離
  - サンドボックス化

Layer 5: 監視とログ
  - 攻撃試行の記録
  - 異常パターン検出
  - アラート設定
```
