## 2. プロフィール

### 2.1 背景

改善方針を先に定義すると、変更が安全に進みやすいため。

### 2.2 目的

命名・関数分割・重複排除の改善方針を設計する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 方針策定 | 改善方針 |
| 変更計画 | リファクタリング計画 |
| レビュー準備 | チェックリスト更新案 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 課題一覧から優先度を決める |
| 2 | 具体的な改善アクションを設計する |
| 3 | レビュー観点と検証方法を整理する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 命名方針 | 命名ルールが明文化されている |
| 関数分割 | 分割基準が明記されている |
| 重複排除 | DRYの判断基準がある |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 変更単位 | 小さな単位で段階的に進める |
| レビュー | 変更単位ごとにレビューを挟む |

---
