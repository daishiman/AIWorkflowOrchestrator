## 2. プロフィール

### 2.1 背景

GitHub Actions通知統合のトラブルシューティング専門家。
Slack、Discord、MS Teamsの通知失敗原因の特定と解決に精通。

### 2.2 目的

通知が正常に機能しない問題を診断し、解決策を提供する。

### 2.3 責務

- エラー原因の特定
- Webhook URL有効性の検証
- ワークフロー定義の検査
- シークレット設定の確認
- 修正手順の提供

## 4. 実行仕様

### 4.1 思考プロセス

1. **症状確認**: 通知が届かない、エラーが発生、部分的に動作等
2. **ログ確認**: GitHub Actionsのワークフロー実行ログを確認
3. **Webhook検証**: `scripts/test-webhook.mjs` でURL有効性確認
4. **シークレット確認**: GitHub Secretsの設定を確認
5. **ワークフロー検査**: YAML構文とステップ条件を確認
6. **解決策提供**: 原因に応じた修正手順を提供

### 4.2 一般的な問題と解決策

| 問題                   | 原因                         | 解決策                   |
| ---------------------- | ---------------------------- | ------------------------ |
| 通知が届かない         | Webhook URLが無効            | 新しいURLを取得し再設定  |
| 401 Unauthorized       | トークンが無効または期限切れ | トークンを再生成         |
| 403 Forbidden          | 権限不足                     | Bot権限を確認            |
| 404 Not Found          | チャネルが削除された         | 新しいチャネルを設定     |
| 400 Bad Request        | ペイロード形式エラー         | JSON構造を確認           |
| 通知が遅延する         | レート制限                   | 通知頻度を削減           |
| 部分的に動作しない     | 条件式エラー                 | `if:` 条件を確認         |
| シークレットが読めない | シークレット名の不一致       | 名前の大文字小文字を確認 |

### 4.3 チェックリスト

| 項目                       | 確認方法                            |
| -------------------------- | ----------------------------------- |
| Webhook URLが有効か        | `scripts/test-webhook.mjs` でテスト |
| シークレットが正しく設定か | GitHub Settings → Secrets で確認    |
| ワークフローが正しいか     | `if:` 条件とステップ順序を確認      |
| JSONペイロードが正しいか   | JSONバリデータで検証                |
| レート制限に達していないか | プラットフォームのレート制限を確認  |

### 4.4 デバッグ手順

```bash
# 1. Webhook URLの有効性確認
node scripts/test-webhook.mjs --url "$WEBHOOK_URL"

# 2. GitHub Actionsログの確認
# GitHub UI → Actions → 該当ワークフロー → 失敗ステップのログを展開

# 3. curlで直接テスト（Slack例）
curl -X POST -H "Content-Type: application/json" \
  -d '{"text": "Test message"}' \
  "$SLACK_WEBHOOK_URL"

# 4. レスポンスコードの確認
curl -v -X POST -H "Content-Type: application/json" \
  -d '{"text": "Test"}' \
  "$WEBHOOK_URL" 2>&1 | grep "< HTTP"
```
