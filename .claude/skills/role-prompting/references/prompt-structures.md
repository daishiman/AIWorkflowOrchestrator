# プロンプト構造

> 責務: ロールプロンプトの構造設計と記述ガイドラインを提供

## 1. 5セクション構造

18-skills.md Task仕様書テンプレートに準拠した構造：

```
1. メタ情報
   └─ 名前・専門領域

2. プロフィール
   ├─ 背景
   ├─ 目的
   └─ 責務

3. 知識ベース
   └─ 参考文献・適用方法

4. 実行仕様
   ├─ 思考プロセス
   ├─ チェックリスト
   └─ ビジネスルール

5. インターフェース
   ├─ 入力
   └─ 出力
```

## 2. 各セクションの詳細

### 2.1 メタ情報

| 項目     | 制約                                 |
| -------- | ------------------------------------ |
| 名前     | 実在する専門家名（参照ラベルとして） |
| 専門領域 | 具体的な専門分野を記述               |

**注意事項**:

- AIは専門家本人を名乗らない
- 方法論のみを適用する旨を注記に明記

### 2.2 プロフィール

| 項目 | 内容                                   |
| ---- | -------------------------------------- |
| 背景 | なぜこの専門家の思考様式が適しているか |
| 目的 | このロールで達成すべきゴール           |
| 責務 | 責務と成果物のマッピング（表形式）     |

### 2.3 知識ベース

| 項目     | 内容                          |
| -------- | ----------------------------- |
| 参考文献 | 書籍/ドキュメント名と適用方法 |
| 外部参照 | references/への相対パスリンク |

**ルール**:

- 適用方法は短く記述
- 詳細はreferences/に外部化

### 2.4 実行仕様

| 項目           | 内容                               |
| -------------- | ---------------------------------- |
| 思考プロセス   | 具体的なアクションをステップで記述 |
| チェックリスト | 合格基準を項目と基準で定義         |
| ビジネスルール | 制約条件を制約と説明で定義         |

### 2.5 インターフェース

**入力テーブル**:

| データ名 | 提供元 | 検証ルール | 欠損時処理 |
| -------- | ------ | ---------- | ---------- |

**出力テーブル**:

| 成果物名 | 受領先 | 内容 |
| -------- | ------ | ---- |

**出力テンプレート**:

- `{{変数}}`形式で構造化
- 必須項目を明示

## 3. 思考プロセスの記述

### 3.1 具体的なアクション

| NG（曖昧）           | OK（具体的）                           |
| -------------------- | -------------------------------------- |
| 必要に応じて確認する | 入力データの形式を検証ルールでチェック |
| 適切に処理する       | 責務マトリクスを作成する               |
| うまく対応する       | エラー時はフォールバック処理を実行     |

### 3.2 ステップの粒度

| 粒度     | 説明                           | 例                   |
| -------- | ------------------------------ | -------------------- |
| 粗すぎる | 複数のアクションが混在         | 「分析して設計する」 |
| 適切     | 1ステップで1アクション         | 「責務を特定する」   |
| 細すぎる | 手続き的すぎて全体像が見えない | 「変数に代入する」   |

## 4. チェックリストの設計

### 4.1 基準の明確化

| NG（曖昧）     | OK（客観的）                         |
| -------------- | ------------------------------------ |
| 適切であること | 500行以内であること                  |
| 十分な内容     | 5セクション全てが存在すること        |
| 問題ないこと   | 責務と成果物が1対1で対応していること |

### 4.2 必須チェック項目

| 項目     | 推奨基準                       |
| -------- | ------------------------------ |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用           |
| 形式検証 | 出力テンプレートに準拠している |

## 5. 出力テンプレートの設計

### 5.1 変数形式

```
{{variable-name}}
```

- ハイフンケースで命名
- 意味が明確な名前を使用

### 5.2 テンプレート構造の例

```markdown
## タイトル: {{title}}

### セクション1

| 項目      | 内容        |
| --------- | ----------- |
| {{key-1}} | {{value-1}} |

### セクション2

- {{item-1}}
- {{item-2}}

### サマリー

{{summary}}
```

## 6. 品質チェックリスト

プロンプト生成完了時に確認：

| 項目             | 確認内容                                     |
| ---------------- | -------------------------------------------- |
| 5セクション存在  | メタ/プロフィール/知識/実行/インターフェース |
| 参照ラベル       | 実在専門家名を使用                           |
| 責務-成果物対応  | テーブル形式で明示                           |
| 思考プロセス     | 具体的アクションで記述                       |
| チェックリスト   | 客観的基準で定義                             |
| 入出力仕様       | 検証ルール・欠損時処理を明記                 |
| 出力テンプレート | {{変数}}形式で構造化                         |
| 曖昧表現なし     | 「必要に応じて」等を使用していない           |

## 7. アンチパターン

| アンチパターン   | 問題点             | 解決策                 |
| ---------------- | ------------------ | ---------------------- |
| セクション欠落   | 情報が不完全       | 5セクション必須        |
| 知識の埋め込み   | Task仕様書が肥大化 | references/に外部化    |
| 曖昧な条件       | 再現性の低下       | 客観的基準に置き換え   |
| テンプレートなし | 出力形式が不安定   | {{変数}}形式で定義     |
| 専門家なりすまし | 倫理的問題         | 注記で方法論適用を明記 |
