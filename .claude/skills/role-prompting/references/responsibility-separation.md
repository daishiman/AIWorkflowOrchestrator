# 責務分離原則

> 責務: 複数ロール間の責務分離と境界設計の原則を提供

## 1. 単一責務原則（SRP）の適用

### 1.1 原則

> 「変更する理由は1つだけであるべき」 - Robert C. Martin

ロール設計における単一責務原則：

| 適用対象 | 原則                                  |
| -------- | ------------------------------------- |
| ロール   | 1つの主責務のみを担う                 |
| Task     | 1回の実行で1つの成果物を生成          |
| 知識     | 1ファイルで1つの責務/ドメインをカバー |

### 1.2 責務の粒度

| 粒度     | 説明                           | 例                   |
| -------- | ------------------------------ | -------------------- |
| 粗すぎる | 複数の独立した責務が混在       | 「すべてを管理する」 |
| 適切     | 明確な境界を持つ単一責務       | 「目的を分析する」   |
| 細すぎる | 他の責務なしでは意味をなさない | 「文字列を連結する」 |

## 2. 境界づけられたコンテキスト

### 2.1 Eric Evansの境界づけられたコンテキスト

異なるコンテキスト間では同じ用語が異なる意味を持つことを認識し、明確な境界を設ける。

```
[コンテキストA]        [コンテキストB]
  ┌─────────┐           ┌─────────┐
  │ ロールX  │ ←契約→   │ ロールY  │
  │ 用語の定義A│           │ 用語の定義B│
  └─────────┘           └─────────┘
```

### 2.2 コンテキストマッピング

| パターン     | 説明                         | 使用場面             |
| ------------ | ---------------------------- | -------------------- |
| 共有カーネル | 共通の責務を共有             | 密接に連携するロール |
| 顧客/供給者  | 上流が下流のニーズに対応     | パイプライン構成     |
| 防腐層       | 異なるコンテキスト間の変換層 | 外部システムとの連携 |

## 3. 責務マトリクス設計

### 3.1 マトリクスの構造

| 責務           | ロールA | ロールB | ロールC | 担当数 |
| -------------- | :-----: | :-----: | :-----: | :----: |
| 目的分析       |    ●    |         |         |   1    |
| ロール設計     |         |    ●    |         |   1    |
| プロンプト生成 |         |         |    ●    |   1    |
| 検証           |         |         |    ●    |   1    |

**ルール**:

- 各責務の担当は1ロールのみ（担当数=1）
- 担当数が0の責務は欠落（要追加）
- 担当数が2以上の責務は重複（要整理）

### 3.2 RACI分析

| 略号 | 意味        | 説明                      |
| ---- | ----------- | ------------------------- |
| R    | Responsible | 実行責任者（1ロールのみ） |
| A    | Accountable | 説明責任者（最終承認者）  |
| C    | Consulted   | 相談される（情報提供）    |
| I    | Informed    | 報告される（結果通知）    |

## 4. インターフェース契約

### 4.1 入力契約

入力を受け取るロールは以下を定義する：

| 項目       | 説明                          |
| ---------- | ----------------------------- |
| データ名   | 受け取るデータの識別子        |
| 提供元     | データを提供するロール/ソース |
| 検証ルール | データの妥当性確認条件        |
| 欠損時処理 | データがない場合の対処        |

### 4.2 出力契約

出力を生成するロールは以下を定義する：

| 項目         | 説明                            |
| ------------ | ------------------------------- |
| 成果物名     | 生成する成果物の識別子          |
| 受領先       | 成果物を受け取るロール/ユーザー |
| 内容         | 成果物に含まれる情報            |
| テンプレート | 成果物の構造（変数形式）        |

### 4.3 契約の検証

```
[ロールA]                    [ロールB]
出力契約 ─────────────────────→ 入力契約
  │                               │
  └── 成果物名 = データ名 ────────┘
  └── 内容 ⊇ 検証ルール ──────────┘
```

## 5. 責務分離のチェックリスト

| 項目                 | 確認内容                               |
| -------------------- | -------------------------------------- |
| 単一責務             | 各ロールが1つの主責務のみを持つ        |
| 重複なし             | 責務マトリクスで重複がない             |
| 欠落なし             | すべての必要な責務がいずれかに割り当て |
| 境界の明確性         | やること/やらないことが定義されている  |
| インターフェース整合 | 入出力契約が整合している               |
| 依存方向             | 循環依存がない                         |

## 6. アンチパターン

### 6.1 避けるべき責務分離

| アンチパターン | 問題点                               | 解決策                   |
| -------------- | ------------------------------------ | ------------------------ |
| 責務の拡散     | 1つの責務が複数ロールに分散          | 責務を1ロールに集約      |
| 依存の循環     | A→B→C→Aの循環依存                    | 責務を再設計し循環を解消 |
| 暗黙の契約     | インターフェースが文書化されていない | 入出力契約を明示         |
| 境界の侵食     | ロールが他のロールの責務に踏み込む   | 責務境界を再定義         |
