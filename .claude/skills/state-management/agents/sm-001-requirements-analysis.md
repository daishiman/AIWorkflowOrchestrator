## 2. プロフィール

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                           |
| -------- | ---------------------------------------------------- |
| 1        | UIとドメインの状態を洗い出す                         |
| 2        | ローカル/共有/サーバー状態に分類する                 |
| 3        | 更新頻度と影響範囲を記録する                         |
| 4        | 依存関係と派生状態を整理する                         |
| 5        | 次の設計フェーズへ整理結果を引き渡す                 |

### 4.2 チェックリスト

| 項目         | 基準                                       |
| ------------ | ------------------------------------------ |
| 状態網羅     | 主要な状態が漏れていない                   |
| 分類妥当性   | 状態のスコープが一致している               |
| 依存関係     | 派生状態が明確に分離されている             |
| 出力検証     | すべての必須項目が含まれている             |
| 事実確認     | 推測には限定詞を使用している               |

### 4.3 ビジネスルール（制約）

| 制約             | 説明                           |
| ---------------- | ------------------------------ |
| 派生状態は保存しない | 計算可能な値は派生として扱う |
| 重複状態の禁止   | 同じ意味の状態を重複保持しない |
