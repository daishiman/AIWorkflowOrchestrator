## 目的

自動テストでは検証できないユーザー体験・UI/UX・実環境動作を手動で確認し、統合に問題がないことを検証する。

## 背景

履歴UIコンポーネントの統合が完了し、preload/IPC/DB統合もすべて完了している状態。単体テストでは検証できない実環境特有の問題やユーザー体験（UX）の問題を発見するため、手動テストを実施する。

### タスク1: 環境準備

**目的**: テスト環境をセットアップする。

**実行手順**:

1. アプリケーションを起動
   ```bash
   pnpm --filter @repo/desktop dev
   ```
2. DevToolsを開く（Cmd+Option+I）
3. コンソールタブを表示
4. テスト用データを準備
   - 履歴データが存在するファイルを用意

**期待される成果物**:

### タスク4: アクセシビリティテスト実施

**目的**: WCAG 2.1 AA準拠を確認する。

**実行手順**:
以下のテストケースを実行し、結果を記録する。

| TC-ID  | 要件                     | 操作                | 期待結果                     | 実行結果 |
| ------ | ------------------------ | ------------------- | ---------------------------- | -------- |
| TC-201 | キーボードナビゲーション | Tab/Enter/Escで操作 | すべての機能にアクセス可能   | [ ]      |
| TC-202 | スクリーンリーダー       | VoiceOverで読み上げ | 適切なラベルが読み上げられる | [ ]      |
| TC-203 | フォーカス管理           | ダイアログを開閉    | フォーカスが適切に移動       | [ ]      |
| TC-204 | ARIA属性                 | DevToolsで確認      | role/aria属性が正しい        | [ ]      |

**キーボード操作詳細**:

- `Tab`: 次のインタラクティブ要素にフォーカス移動
- `Shift+Tab`: 前のインタラクティブ要素にフォーカス移動
- `Enter` / `Space`: ボタンのクリック、リンクの実行
- `Escape`: ダイアログを閉じる

**確認すべきARIA属性**:

- `role="list"`: VersionHistory, ConversionLogs
- `role="listitem"`: VersionHistoryItem, LogEntry
- `role="dialog"`: RestoreDialog
- `aria-modal="true"`: RestoreDialog
- `role="status"`: LoadingSkeleton
- `role="alert"`: ErrorDisplay

**期待される成果物**:

- アクセシビリティテスト結果（4ケース）

**完了チェック**:

- [ ] キーボードのみで全操作が可能
- [ ] スクリーンリーダーで適切に読み上げられる
- [ ] WCAG 2.1 AA準拠
