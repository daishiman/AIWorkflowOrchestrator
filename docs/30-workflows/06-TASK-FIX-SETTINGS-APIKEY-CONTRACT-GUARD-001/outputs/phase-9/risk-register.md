## 残存リスク評価

### R-01: totalCount の意味変更（低リスク）

| 項目   | 内容                                                                                                                                 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| リスク | `apiKey:list` ハンドラの `totalCount` が `AI_PROVIDERS.length`（固定4）から `providers.length`（バリデーション後の有効要素数）に変更 |
| 影響   | Renderer側が `totalCount` を固定4として扱っている場合、表示が変わる可能性                                                            |
| 確率   | 低（Renderer側は `ALL_PROVIDERS` 定数で4プロバイダーを表示しており、`totalCount` を直接参照していない）                              |
| 緩和策 | 既存テストで正常系の `totalCount` が期待通りであることを確認済み                                                                     |
| 判定   | 許容可能                                                                                                                             |

### R-02: console.warn によるログ出力（無視可能リスク）

| 項目   | 内容                                                     |
| ------ | -------------------------------------------------------- |
| リスク | 防御的フォールバック発動時に console.warn が出力される   |
| 影響   | 本番環境でコンソールにログが出る                         |
| 確率   | 低（Preload/sandbox が正常に動作している限り発動しない） |
| 緩和策 | 出力される情報は `typeof` の結果のみで機密情報を含まない |
| 判定   | 許容可能                                                 |

### R-03: profileHandlers の identities バリデーション範囲（無視可能リスク）

| 項目   | 内容                                                                             |
| ------ | -------------------------------------------------------------------------------- |
| リスク | `Array.isArray` ガードは配列型チェックのみで、配列要素の shape は未検証          |
| 影響   | 配列要素が不正な場合、`toLinkedProvider` 内でエラーが発生する可能性              |
| 確率   | 極低（Supabase SDK が返す `UserIdentity[]` の shape が崩れる可能性は極めて低い） |
| 緩和策 | 今回のスコープ外。要素レベルのバリデーションは未タスク化を検討                   |
| 判定   | 許容可能（現時点では対応不要）                                                   |
