## 判定基準

| 判定     | 条件             | 対応                                |
| -------- | ---------------- | ----------------------------------- |
| PASS     | 全観点で問題なし | Phase 4へ進行                       |
| MINOR    | 軽微な指摘あり   | 指摘対応後Phase 4へ進行             |
| MAJOR    | 重大な問題あり   | 影響範囲に応じて戻り先を決定        |
| CRITICAL | 致命的な問題あり | Phase 1へ戻りユーザーと要件を再確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |

## レビュー観点

### 1. 要件との整合性

- [ ] 全ての受け入れ基準が設計でカバーされている
- [ ] スコープ外の機能が含まれていない
- [ ] 機能要件/非機能要件が満たされる設計になっている

### 2. アーキテクチャ整合性

- [ ] 既存のView/Sliceパターンに従っている
- [ ] Zustand Storeの構造が適切
- [ ] IPC通信パターンが既存と整合している

### 3. UI/UXガイドライン準拠

- [ ] Apple HIG準拠の設計になっている
- [ ] 8pxグリッドシステムに従っている
- [ ] アクセシビリティ対応が考慮されている

### 4. 型安全性

- [ ] 型定義が完全に定義されている
- [ ] any型の使用が最小限
- [ ] Zodスキーマによるバリデーションが考慮されている
