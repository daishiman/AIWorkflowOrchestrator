# 統合戦略

> タスクID: TASK-SC-01-IPC-WIRING-FIX
> 作成日: 2026-03-23
> Phase: 2 - 設計

## 検討した選択肢

### 案A: 完全統合（単一ファイル）

creatorHandlers.ts の3チャネルを skillCreatorHandlers.ts に移動し、creatorHandlers.ts を削除する。

- 利点: ファイル数削減、一元管理
- 欠点: skillCreatorHandlers.ts が肥大化、Runtime と既存の責務混在

### 案B: 責務明確化 + ガードレール追加（採用）

2ファイル構成を維持し、namespace を `skill-creator:` に統一。P65 再発防止テストを追加。

- 利点: 責務分離の維持、変更範囲が最小限、Runtime 拡張時の影響局所化
- 欠点: 2ファイルの管理コスト（ただしテストで防御）

### 案C: 動的登録パターン

チャネル定義を配列化し、ループで登録する。

- 利点: 宣言的、追加が容易
- 欠点: 型安全性の低下、デバッグ困難、過度な抽象化

## 選択理由

案B を採用。理由:

1. P65 の根本原因は「namespace の分裂」であり、namespace 統一で解消済み
2. 2ファイル構成は責務分離（SRP）に適合
3. ガードレールテスト（IPC-P65-001/002, IPC-AL-001/002）により再発を自動検出
4. 変更範囲が最小限で、既存テストへの影響なし
