## 目的

実際のElectronアプリで全5シナリオを手動実行し、TerminalHandoff の `suggestedCommand` が CLI で実行可能であることを確認する。P53（CLI環境制約）を考慮した代替検証方法を使用する。

## 実行タスク

1. **シナリオA 手動確認（正常フロー）**
   - スキル生成ウィザードを開く
   - LLMモデルを選択する（AC-1）
   - スキル名・説明を入力して生成を開始する
   - 進捗がリアルタイムで更新されることを確認する（AC-3）
   - 生成完了後、スキルが一覧に表示されることを確認する（AC-5）

2. **シナリオB 手動確認（TerminalHandoff）**
   - TerminalHandoff が返却される条件でスキルを生成する
   - `suggestedCommand` が UI に表示されること（AC-7）
   - 表示されたコマンドをターミナルにコピーして実行できること
   - コマンドが実際に CLI で実行可能な形式であること

3. **シナリオC 手動確認（LLMエラー）**
   - 不正なAPIキーを設定した状態でスキル生成を実行する
   - エラーメッセージが適切に表示されること（AC-6）
   - アプリがクラッシュしないことを確認する（NFR-4）
   - リトライが可能であることを確認する

4. **シナリオD 手動確認（improve）**
   - 既存のスキルを選択して「改善」モードを起動する
   - 改善後のスキルが上書き保存されることを確認する

5. **シナリオE 手動確認（後方互換）**
   - 旧UIからスキルを作成して `skill:create` チャンネルが動作することを確認する（NFR-3）

6. **P53対策: CLI環境での代替検証**
   - Playwright の `page.screenshot()` を使用する
   - または、自動テストの PASS 結果を証跡として記録する
