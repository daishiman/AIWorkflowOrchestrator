## 目的

自動テストでは検出困難なUI/UXの問題を、実際のElectronアプリ上で手動検証する。

## 実行タスク

### Task 1: IPC エンドツーエンドテスト

#### シナリオ 1-1: 改善提案の正常適用

1. Electron アプリを起動する
2. Runtime Skill Creator で `improve` を実行し、改善提案を取得する
3. 改善提案一覧が section/before/after/reason 形式で表示されることを確認する
4. 2件の提案を選択する
5. 「選択した提案を適用（2件）」ボタンを押下する
6. 適用結果画面に applied=2 が表示されることを確認する
7. SKILL.md の該当箇所が変更されていることを確認する

**期待結果**: 選択した提案のみが SKILL.md に反映され、未選択の提案は変更されない

#### シナリオ 1-2: 一部スキップ

1. 改善提案の before テキストが現在の SKILL.md と一致しない状態を作る（手動で SKILL.md を編集）
2. 改善提案を全選択して適用する
3. 適用結果画面に skipped 件数とスキップ理由が表示されることを確認する

**期待結果**: before テキスト不一致の提案がスキップされ、理由が表示される

### Task 2: UI/UX 検証

#### シナリオ 2-1: diff 表示の視認性

- [ ] before ブロックが赤系背景で表示される
- [ ] after ブロックが緑系背景で表示される
- [ ] before/after の対比が一目で区別可能
- [ ] 長文テキスト（5行以上）がスクロール可能なブロックで表示される

#### シナリオ 2-2: チェックボックス操作

- [ ] 個別チェックボックスの ON/OFF が即座に反映される
- [ ] 「全て選択」ボタンで全提案がチェック状態になる
- [ ] 「全て解除」ボタンで全提案が未チェック状態になる
- [ ] 選択件数がボタンテキストに反映される

#### シナリオ 2-3: ローディング状態

- [ ] 「適用」ボタン押下後、ローディングインジケーターが表示される
- [ ] 適用中は全操作が disabled になる
- [ ] 適用完了後に結果画面に遷移する

#### シナリオ 2-4: ダークモード

- [ ] ライトモードで diff 表示が正しく表示される
- [ ] ダークモードに切り替え後も diff 表示が正しく表示される
- [ ] コントラスト比が WCAG 2.1 AA 基準を満たしている

#### シナリオ 2-5: 0件選択

- [ ] 0件選択時に「適用」ボタンが disabled になる
- [ ] disabled 状態のボタンが視覚的に区別可能

### Task 3: エラーハンドリング検証

#### シナリオ 3-1: IPC 通信失敗

1. Runtime Skill Creator Service を無効化した状態で適用を試みる
2. エラーメッセージが表示されることを確認する

**期待結果**: 「Runtime Skill Creator は現在利用できません」メッセージが表示される

#### シナリオ 3-2: 書き込みエラー

1. SKILL.md を読み取り専用にした状態で適用を試みる（可能な場合）
2. エラーメッセージが表示されることを確認する

**期待結果**: 書き込みエラーの詳細が errors 配列経由で表示される

### Task 4: アクセシビリティ検証

- [ ] Tab キーで全操作可能（チェックボックス → ボタン → 次の提案）
- [ ] Enter/Space キーでチェックボックス操作可能
- [ ] スクリーンリーダーで提案内容が読み上げ可能（aria-label 確認）
