## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現在のClaude Agent SDK認証基盤（TASK-FIX-16-1-SDK-AUTH-INFRASTRUCTURE）は、Anthropic APIキーのみをサポートしている。しかし、Claude Codeはサブスクリプションベースの認証（Claude Codeログイン）もサポートしており、ユーザーによっては：

1. **サブスクリプション利用者**: Claude Code CLIでログイン済みで、追加のAPIキー設定なしで利用したい
2. **APIキー利用者**: 独自のAPIキーを使用して、コストを自分のアカウントに紐付けたい

という2つの異なるニーズが存在する。

### 1.2 問題点・課題

| 課題                   | 詳細                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| 認証方式の選択肢がない | 現在はAPIキー方式のみで、サブスクリプション認証を選択できない        |
| ユーザー体験の制限     | Claude Codeサブスクリプション利用者が別途APIキーを設定する必要がある |
| 柔軟性の欠如           | 利用シーンに応じた認証方式の切り替えができない                       |

### 1.3 放置した場合の影響

- **利用ハードルの上昇**: サブスクリプション利用者がAPIキーを取得・設定する手間が発生
- **ユーザー離脱リスク**: 「Claude Codeログインで使えると思った」というユーザーの期待に応えられない
- **コスト認識の混乱**: サブスクリプション vs 従量課金の違いをユーザーが理解しにくい

---

## 2. 何を達成するか（What）

### 2.1 目的

ユーザーが認証方式を選択できるUIを提供し、サブスクリプション認証とAPIキー認証の両方をシームレスに利用可能にする。

### 2.2 最終ゴール

1. **選択UI**: ユーザーが認証方式を選択できる設定画面
2. **サブスクリプション認証**: Claude Code CLIのログイン状態を活用した認証
3. **APIキー認証**: 既存のAPIキー管理基盤との統合
4. **状態表示**: 現在の認証方式・状態を明示するUI

### 2.3 スコープ

#### 含むもの

- 認証方式選択UI（設定画面内）
- サブスクリプション認証の統合（Claude Code CLI連携）
- 認証状態の表示・管理
- 認証方式切り替えロジック
- Main Process側の認証プロバイダー抽象化

#### 含まないもの

- Claude Code CLIのインストール支援
- サブスクリプションの購入・管理機能
- 課金関連のUI（残高表示など）
- 複数APIキーの管理（将来タスク）

### 2.4 成果物

| 成果物             | 説明                                             |
| ------------------ | ------------------------------------------------ |
| 認証方式選択UI     | 設定画面内の認証モード選択コンポーネント         |
| AuthProvider抽象化 | サブスク/APIキーを切り替え可能な認証プロバイダー |
| IPC拡張            | 認証方式設定・取得のためのIPCチャンネル          |
| SkillExecutor統合  | 選択された認証方式でのAPI呼び出し                |
| 単体テスト         | 80%以上のカバレッジ                              |
| E2Eテスト          | 認証方式切り替えシナリオ                         |

### 3.5 実装課題と解決策

#### 課題1: Claude Code CLIの認証トークン取得

| 調査項目             | 確認方法                        |
| -------------------- | ------------------------------- |
| トークンの保存場所   | `~/.claude/` ディレクトリの調査 |
| トークン形式         | JWT/OAuth token形式の確認       |
| トークンリフレッシュ | 自動更新メカニズムの有無        |

**参考**: Claude Code CLIの設定ファイル調査が必要

#### 課題2: 認証方式の永続化

| 選択肢         | メリット             | デメリット       |
| -------------- | -------------------- | ---------------- |
| electron-store | 既存インフラ活用     | 暗号化が必要     |
| SQLite         | トランザクション対応 | オーバースペック |

**推奨**: electron-store（既存AuthKeyServiceと統一）
