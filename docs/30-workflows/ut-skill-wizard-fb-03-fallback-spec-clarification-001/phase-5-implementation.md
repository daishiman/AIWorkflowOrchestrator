## 実装手順

### Step 1: AC-4定義への追記

task-specification-creator SKILL.md のAC-4定義箇所を特定し、以下を追記する：

```markdown
#### フィールド間独立推論性（AC-4補足）

SmartDefaultの各フィールドは**独立して**推論される。
`purpose` は tool / timing、`category` は format の責務を持ち、あるフィールドの値が空・null・推論不可であっても、他フィールドの推論には影響しない。

| フィールド | 空白時の動作                       | 他フィールドへの影響 |
| ---------- | ---------------------------------- | -------------------- |
| purpose    | null（tool / timing のみ推論不可） | なし（独立）         |
| category   | null（format のみ推論不可）        | なし（独立）         |
| format     | category から独立推論継続          | なし（独立）         |

**誤用例**: purpose空 → 全フィールドnullとみなす ← 誤り
**正用例**: purpose空 → purpose由来の tool / timing のみ null、category 由来の format は独立推論継続
```

### Step 2: フォールバック仕様書テンプレートへの追記

フォールバック仕様書テンプレートに「フィールド間独立性」専用セクションを追加する：

```markdown
## フィールド間独立推論性

各フィールドは独立して推論される。以下の原則に従う：

1. 各フィールドは独自の推論ロジックを持つ
2. あるフィールドがnullになっても、他フィールドの推論には影響しない
3. フィールド間に明示的な依存関係がない限り、独立して評価する

### よくある誤解

| 誤解パターン                   | 正しい動作                                                       |
| ------------------------------ | ---------------------------------------------------------------- |
| purpose空 → 全フィールドがnull | purpose空 → purpose由来の tool / timing のみ null                |
| category空 → format推論不可    | category空 → format は null、purpose 由来の tool / timing は継続 |
```
