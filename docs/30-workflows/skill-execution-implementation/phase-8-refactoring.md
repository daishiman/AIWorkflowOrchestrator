## 目的

テストを維持しながらコードの品質を向上させる（TDD Refactor）。

## 背景

TDD（Test-Driven Development）のRefactorフェーズとして、Green状態を維持しながら
コードの可読性、保守性、再利用性を向上させる。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード品質評価

**目的**: 現在のコード品質を評価する

**実行手順**:

1. 以下の観点で評価

| #   | 観点             | 確認事項                         | 状態 |
| --- | ---------------- | -------------------------------- | ---- |
| 1   | 重複コードの有無 | 同様のロジックが複数箇所にないか | [ ]  |
| 2   | 関数の単一責任性 | 各関数が単一の責務を持っているか | [ ]  |
| 3   | 変数命名の適切さ | 変数名が意図を明確に表しているか | [ ]  |
| 4   | コメントの必要性 | 複雑なロジックに説明があるか     | [ ]  |
| 5   | エラーメッセージ | エラーが分かりやすいか           | [ ]  |

2. `outputs/phase-8/code-quality-assessment.md` に結果を出力

**期待される成果物**:

- コード品質評価結果

---

### タスク2: リファクタリング候補特定

**目的**: リファクタリングが必要な箇所を特定する

**実行手順**:

1. 以下のリファクタリング候補を評価

| #   | 対象                      | リファクタリング内容         | 優先度 |
| --- | ------------------------- | ---------------------------- | ------ |
| 1   | SkillService.executeSkill | エラーハンドリングの共通化   | 中     |
| 2   | skillHandlers             | 検証ロジックの抽出           | 低     |
| 3   | AgentView.handleExecute   | ローディング状態管理のhook化 | 低     |

2. `outputs/phase-8/refactoring-candidates.md` に結果を出力

**期待される成果物**:

- リファクタリング候補リスト

---

### タスク3: リファクタリング実施

**目的**: 特定した候補に対してリファクタリングを実施する

**実行手順**:

1. 優先度の高い順にリファクタリングを実施
2. 各リファクタリング後にテストを実行

```bash
pnpm --filter @repo/desktop test -- --run
```

3. 全てのテストがパスすることを確認
4. `outputs/phase-8/refactoring-result.md` に結果を出力

**期待される成果物**:

- リファクタリング結果

---

### タスク4: リファクタリング検証

**目的**: リファクタリング後の品質を検証する

**実行手順**:

1. 以下のチェックリストを確認

- [ ] 全てのテストがパスする
- [ ] 型エラーがない
- [ ] ESLintエラーがない
- [ ] コードの可読性が向上している

2. `outputs/phase-8/verification-result.md` に結果を出力

**期待される成果物**:

- 検証結果
