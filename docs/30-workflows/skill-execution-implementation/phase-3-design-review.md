## 目的

Phase 2で作成した設計の妥当性を検証し、実装に進んでよいか判断する。

## 背景

設計レビューゲートは、実装前に設計の品質を検証する重要なチェックポイント。
既存のIPC通信パターン、セキュリティ要件との整合性を確認することで、
実装後の手戻りを防止する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 設計整合性レビュー

**目的**: 既存パターンとの整合性を検証する

**実行手順**:

1. 以下のチェック項目を確認

| #   | チェック項目                               | 確認結果 |
| --- | ------------------------------------------ | -------- |
| 1   | 既存のIPC通信パターンに準拠しているか      | [ ]      |
| 2   | skillAPIの既存メソッドと整合性があるか     | [ ]      |
| 3   | SkillServiceの既存メソッドと整合性があるか | [ ]      |
| 4   | セキュリティ要件（sender検証）を満たすか   | [ ]      |
| 5   | エラーハンドリングパターンが一貫しているか | [ ]      |

2. `outputs/phase-3/design-consistency-review.md` に結果を出力

**期待される成果物**:

- 設計整合性レビュー結果

---

### タスク2: 技術レビュー

**目的**: 技術的観点から設計を検証する

**実行手順**:

1. 以下の技術観点を確認

| #   | 観点            | 確認事項                            | 結果 |
| --- | --------------- | ----------------------------------- | ---- |
| 1   | 型安全性        | TypeScript型定義が適切か            | [ ]  |
| 2   | 非同期処理      | async/awaitの使用が正しいか         | [ ]  |
| 3   | 例外処理        | try-catchが適切に配置されているか   | [ ]  |
| 4   | IPCセキュリティ | validateIpcSenderが呼ばれているか   | [ ]  |
| 5   | レスポンス形式  | OperationResult形式に準拠しているか | [ ]  |

2. `outputs/phase-3/technical-review.md` に結果を出力

**期待される成果物**:

- 技術レビュー結果

---

### タスク3: リスク評価

**目的**: 実装上のリスクを評価する

**実行手順**:

1. 以下のリスクを評価

| リスク                   | 影響度 | 発生確率 | 対策                   |
| ------------------------ | ------ | -------- | ---------------------- |
| スキル実行のタイムアウト | 中     | 中       | タイムアウト設定を追加 |
| 並列実行時の競合         | 低     | 低       | 単一スキル実行に制限   |
| 不正なスキルIDによる実行 | 中     | 低       | skillId検証を実装      |

2. `outputs/phase-3/risk-assessment.md` に結果を出力

**期待される成果物**:

- リスク評価ドキュメント

---

### タスク4: 統合テスト観点レビュー

**目的**: 統合テストの観点から設計を検証する

**実行手順**:

1. 以下の統合テスト観点を確認

| #   | 観点              | 確認事項                            | 結果 |
| --- | ----------------- | ----------------------------------- | ---- |
| 1   | Renderer→Main接続 | IPC呼び出しが正しく設計されているか | [ ]  |
| 2   | Main→Service接続  | SkillService呼び出しが正しいか      | [ ]  |
| 3   | エラー伝播        | エラーが適切に伝播するか            | [ ]  |
| 4   | 型整合性          | 全レイヤーで型が一致しているか      | [ ]  |

2. `outputs/phase-3/integration-test-review.md` に結果を出力

**期待される成果物**:

- 統合テスト観点レビュー結果

---

### タスク5: レビュー判定

**実行手順**:

3. `outputs/phase-3/review-decision.md` に結果を出力

**期待される成果物**:

- レビュー判定結果

## レビューゲート判定

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
