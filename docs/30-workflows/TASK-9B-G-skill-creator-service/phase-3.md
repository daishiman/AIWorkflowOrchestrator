## 目的

## 判定基準

| 判定  | 条件             | 対応                                  |
| ----- | ---------------- | ------------------------------------- |
| PASS  | 全観点で問題なし | Phase 4へ進行                         |
| MINOR | 軽微な指摘あり   | 指摘対応後Phase 4へ進行（未タスク化） |
| MAJOR | 重大な問題あり   | Phase 1または2へ戻り修正              |

## レビュー観点

### 要件妥当性

| チェック項目 | 確認内容                           | 結果 |
| ------------ | ---------------------------------- | ---- |
| FR網羅性     | 全機能要件が設計に反映されているか |      |
| NFR実現性    | 非機能要件が設計で達成可能か       |      |
| AC検証可能性 | 受け入れ基準がテスト可能か         |      |

### 設計妥当性

| チェック項目           | 確認内容                                       | 結果 |
| ---------------------- | ---------------------------------------------- | ---- |
| Script First           | 決定論的処理がScriptExecutorに委譲されているか |      |
| Progressive Disclosure | リソース遅延読み込みが設計されているか         |      |
| 責務分離               | 各クラスの責務が明確に分離されているか         |      |
| 依存方向               | 依存関係が上位→下位の一方向か                  |      |

### 型設計妥当性

| チェック項目 | 確認内容                         | 結果 |
| ------------ | -------------------------------- | ---- |
| 型完全性     | 全API引数/戻り値に型定義があるか |      |
| null安全性   | null/undefinedの扱いが明確か     |      |
| 拡張性       | Union型/ジェネリクスで拡張可能か |      |

### セキュリティ観点

| チェック項目 | 確認内容                                  | 結果 |
| ------------ | ----------------------------------------- | ---- |
| パス検証     | スクリプト/リソースパスの検証設計があるか |      |
| 入力検証     | ユーザー入力のバリデーション設計があるか  |      |
| エラー情報   | エラーメッセージに機密情報が含まれないか  |      |

## 統合テスト連携【必須】

| レビュー観点       | 確認項目                                       |
| ------------------ | ---------------------------------------------- |
| スクリプト連携     | ScriptExecutor → scripts/\*.js の契約が明確か  |
| リソース読み込み   | ResourceLoader のキャッシュ戦略が適切か        |
| エラーハンドリング | スクリプト失敗時の復旧設計があるか             |
| 依存関係解決       | タスク間依存の検出・解決アルゴリズムが正しいか |
