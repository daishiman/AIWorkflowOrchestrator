# Phase 3: 設計レビュー

## メタ情報

| 項目       | 値                                    |
| ---------- | ------------------------------------- |
| Phase番号  | 3                                     |
| 機能名     | LLMモデル選択インラインガイダンス追加 |
| タスクID   | TASK-FIX-LLM-SELECTOR-INLINE-GUIDANCE |
| 作成日     | 2026-03-20                            |
| ステータス | 作成済み                              |
| 依存       | [Phase 2 設計](./phase-2-design.md)   |

## 目的

Phase 2 の設計内容をレビューし、UI/UX品質・状態管理の依存方向・既存コンポーネントとの整合性を検証する。設計の妥当性を確認し、Phase 4（テスト作成）への進行可否を判定する。

## 実行タスク

### Task 1: UI/UXレビュー（Apple HIG準拠確認）

以下の観点でレビューを実施する:

#### 1-1: カラーパレット準拠確認

| チェック項目                            | 基準                                            | 確認方法                 |
| --------------------------------------- | ----------------------------------------------- | ------------------------ |
| アクセントカラーが systemBlue を使用    | ライトモード: #007AFF、ダーク: #0A84FF          | 設計書のカラー指定を確認 |
| バナー背景色がシステムカラーを使用      | systemOrange系 または secondarySystemBackground | 設計書のカラー指定を確認 |
| テキストカラーが label / secondaryLabel | ライトモード #000000 / rgba(60,60,67,0.6)       | 設計書のカラー指定を確認 |

#### 1-2: レイアウト・スペーシング

| チェック項目                                 | 基準                                   |
| -------------------------------------------- | -------------------------------------- |
| 8px グリッドに沿ったスペーシング             | padding/margin が 8px の倍数           |
| 角丸が 8px〜12px の範囲内                    | border-radius 設計値を確認             |
| バナーが ChatView 本体レイアウトを圧迫しない | バナー高さが最小限（推奨: 44px〜56px） |

#### 1-3: インタラクション

| チェック項目                             | 基準                                                       |
| ---------------------------------------- | ---------------------------------------------------------- |
| アニメーション時間 200-300ms             | 設計値が 200ms で設定されているか                          |
| ボタンにホバー・アクティブ状態が存在     | CSS クラスにホバー/アクティブスタイルが含まれる設計か      |
| バナー消滅後にレイアウトシフトが起きない | 条件付きレンダリングで即座に消えるが、チラつきを防ぐ設計か |

#### 1-4: アクセシビリティ（WCAG 2.1 AA）

| チェック項目                            | 基準                                                      |
| --------------------------------------- | --------------------------------------------------------- |
| バナーに aria-label / role が設定される | `role="alert"` または `aria-live="polite"` を設計に含むか |
| ボタンのコントラスト比 4.5:1 以上       | systemBlue on white の比率確認                            |
| キーボードフォーカスがボタンに当たる    | tab フォーカス可能な実装設計か                            |

### Task 2: 状態管理の依存方向確認

#### 2-1: レイヤー依存方向の検証

```
Renderer → Preload (contextBridge) → Main → External Services
```

確認項目:

- [ ] LLMGuidanceBanner は Renderer 層内のみで完結している
- [ ] IPC 通信を新規追加していない
- [ ] Main Process の直接呼び出しがない
- [ ] `apps/` パッケージ間の直接 import がない（P8 対策）

#### 2-2: Zustand 設計原則の検証（P31 対策）

| チェック項目                                                                 | 合否基準                                                 |
| ---------------------------------------------------------------------------- | -------------------------------------------------------- |
| 合成 Hook（`useLLMStore()` 等）の戻り値を `useEffect` 依存配列に含めていない | 設計書に合成Hook使用箇所がないこと                       |
| 個別セレクタ（`useSelectedModelId()` 等）を使用                              | 設計書に個別セレクタの記載があること                     |
| 派生セレクタ（filter/map）に `useShallow` が適用されている                   | 該当箇所がある場合のみ（本タスクでは不要な可能性が高い） |

#### 2-3: セレクタ不足時の対応設計確認

- [ ] `useSelectedModelId` が llmSlice に存在しない場合の追加設計が明確になっている
- [ ] `useSetCurrentView` の取得元が設計書に記載されている

### Task 3: 既存LLMSelectorPanelとの重複回避確認

| チェック項目                                       | 基準                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------- |
| LLMGuidanceBanner は LLMSelectorPanel と競合しない | 両者の表示トリガーが異なること、または排他的であること              |
| ガイダンスバナーはモデル選択機能を持たない         | バナーは「案内」のみで、選択UI自体は Settings 画面に委譲            |
| 既存の GuidanceBlock 実装を破壊しない              | WorkspaceChatPanel の変更が既存 GuidanceBlock の props を削除しない |

### Task 4: 実装リスク評価

| リスク                                                        | 影響度 | 対策                                                                   |
| ------------------------------------------------------------- | ------ | ---------------------------------------------------------------------- |
| llmSlice に個別セレクタが存在しない場合の追加                 | 低     | Phase 5 で追加。P31 のパターンに従い安全に実装可能                     |
| GuidanceBlock が action props を受け取れない場合              | 中     | Phase 5 で GuidanceBlock の Props 拡張が必要。既存テストへの影響を確認 |
| `setCurrentView` の型が ViewType に "settings" を含まない場合 | 中     | Phase 5 で型定義を確認し、必要に応じて型を拡張                         |
| バナーによるレイアウトシフトでユーザー体験が低下              | 低     | 条件付きレンダリング + CSS transition で対応。Phase 4 でテスト化       |

### Task 5: レビュー判定

レビュー結果を以下の基準で判定する:

| 判定              | 条件                           | 対応                      |
| ----------------- | ------------------------------ | ------------------------- |
| PASS              | 全チェック項目が合格           | Phase 4 へ進む            |
| MINOR             | 指摘箇所があるが機能に影響なし | 指摘対応後 Phase 4 へ進む |
| MAJOR（要件問題） | 要件定義の見直しが必要         | Phase 1 へ戻る            |
| MAJOR（設計問題） | 設計の根本的な変更が必要       | Phase 2 へ戻る            |

**MINOR 判定時の注意**: MINOR 指摘は「機能影響なし」でも全て未タスク仕様書に変換すること（P05-task-execution.md 準拠）。
