## 目的

Phase 5 で実装したテンプレート変更に対して、Phase 4 のテストケース（TC-01〜TC-06）では
カバーできていないエッジケースと回帰テストを追加し、品質を強化する。

## 背景

docs-only タスクのため、テスト拡充の対象は「テンプレートの構造的整合性」と
「チェックリスト項目の完全性」に限定する。

具体的には以下の 2 種類のテストを追加する：

1. **エッジケース確認** (TC-07〜TC-11): 通常フローでは検出しにくい境界条件
2. **回帰テスト** (TC-12): 既存チェックリスト項目が変更されていないことの確認

## 実行タスク

> **Task / Step 分離ルール**: このセクションには plan のみを書く。実行結果は `outputs/phase-6/` へ記録する。

### タスク1: エッジケーステストの定義・実行（TC-07〜TC-11）

**目的**: 通常フローではカバーされないエッジケースを検証する

**実行手順**:

1. 以下の各テストケースを実行し、結果を記録する
2. 全テストの PASS / FAIL を `outputs/phase-6/expanded-test-cases.md` に記録する

**テストケース一覧**:

#### TC-07: lane/index.md が存在しないワークフローでのフォールバック動作確認

| 項目           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| テスト種別     | エッジケース                                                                                             |
| 前提条件       | `lane/index.md` が存在しないワークフロー（または lane ディレクトリ自体がない）を想定する                 |
| テスト手順     | Phase 12 チェックリストの `lane/index.md` 同期項目に注記（「該当する場合」）が明記されているかを確認する |
| 期待される結果 | チェックリスト項目に「lane/index.md が存在しない場合はスキップ可」または同等の注記が存在すること         |
| 合否判定基準   | 注記が存在する → PASS / 注記がない → FAIL                                                                |

#### TC-08: completed.md と backlog.md が同一エントリを持つ場合の処理

| 項目           | 内容                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| テスト種別     | エッジケース                                                                                          |
| 前提条件       | `task-workflow.md`（backlog）と `task-workflow-completed.md` に同一タスクエントリが存在する状態を想定 |
| テスト手順     | チェックリストの「backlog から削除」と「completed に追加」が排他的操作として明記されているか確認する  |
| 期待される結果 | 両ファイルへの操作が「削除」と「追加」として明確に区別されていること                                  |
| 合否判定基準   | 区別されている → PASS / 曖昧な記述 → FAIL                                                             |

#### TC-09: artifacts.json の workflow root と skill root が両方更新される場合

| 項目           | 内容                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| テスト種別     | エッジケース                                                                                                                                             |
| 前提条件       | `outputs/artifacts.json`（workflow 側）と `.claude/skills/task-specification-creator/outputs/artifacts.json`（skill 側）の両方を同一ターンで更新する状況 |
| テスト手順     | チェックリストに「workflow artifacts」と「skill artifacts」が別項目として明示されているか確認する                                                        |
| 期待される結果 | 2 つの artifacts.json が別々のチェックリスト項目として独立して記載されていること                                                                         |
| 合否判定基準   | 独立して記載されている → PASS / まとめて記載 → FAIL                                                                                                      |

#### TC-10: チェックリストが既存の Phase 12 完了条件と重複しないことの確認

| 項目           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| テスト種別     | エッジケース                                                                                             |
| 前提条件       | 実装済みの `phase12-task-spec-compliance-template.md` と追加前の既存チェックリスト                       |
| テスト手順     | 追加した三者同期チェックリストの各項目が、既存チェックリスト項目と意味的に重複していないかを目視確認する |
| 期待される結果 | 全 5 同期項目が既存チェックリストに存在しない新規項目であること                                          |
| 合否判定基準   | 重複なし → PASS / 意味的重複あり → FAIL                                                                  |

#### TC-11: mirror (.agents/skills/) との同期確認

| 項目           | 内容                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| テスト種別     | エッジケース                                                                                                |
| 前提条件       | `.claude/skills/task-specification-creator/` と `.agents/skills/task-specification-creator/` が存在すること |
| テスト手順     | 変更した 3 ファイルについて、`.claude/skills/` と `.agents/skills/` の diff が 0 であることを確認する       |
| 期待される結果 | 両ディレクトリのファイル内容が完全に一致していること                                                        |
| 合否判定基準   | diff = 0 → PASS / diff あり → FAIL                                                                          |

### タスク2: 回帰テストの定義・実行（TC-12）

**目的**: 今回の変更が既存チェックリスト項目を意図せず変更・削除していないことを確認する

**実行手順**:

1. Phase 4 で記録した `outputs/phase-4/baseline-snapshot.md`（または同等の現行状態記録）を参照する
2. 以下のテストケースを実行する
3. 結果を `outputs/phase-6/regression-test-results.md` に記録する

#### TC-12: 回帰テスト - 既存チェックリスト項目が変更されていないこと

| 項目           | 内容                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| テスト種別     | 回帰テスト                                                                                                                              |
| 前提条件       | Phase 5 実装前の `phase12-task-spec-compliance-template.md` のスナップショット（`outputs/phase-4/baseline-snapshot.md`）                |
| テスト手順     | 1. Phase 5 実装後のファイルと Phase 4 時点のスナップショットを比較する<br>2. 追加行以外に変更行（更新・削除）が存在しないことを確認する |
| 期待される結果 | 今回の変更は「追加のみ」であり、既存行の変更・削除がゼロであること                                                                      |
| 合否判定基準   | 追加のみ → PASS / 既存行の変更・削除あり → FAIL                                                                                         |
