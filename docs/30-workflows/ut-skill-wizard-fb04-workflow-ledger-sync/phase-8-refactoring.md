## 目的

Phase 5〜7 で追記したチェックリスト文言・ガイド手順の冗長性を除去し、
既存テンプレートとの表現を統一する。

docs-only タスクのため、リファクタリングの対象は「文書品質の改善」に限定する。
コードの変更は行わない。

## 背景

> **[FB-RT-03 対策]** リファクタリング内容を「対象/Before/After/理由」テーブル形式で記録し、
> 変更の追跡可能性を確保する。

追記フェーズ（Phase 5〜7）では、正確性を優先してチェックリスト項目を記述した。
リファクタリングフェーズでは以下の観点で文書品質を向上させる：

1. チェックリスト文言の冗長性除去（同一概念の重複表現を統合）
2. 既存テンプレートとの表現統一（動詞・形式・敬体の一致）
3. 日本語表現の明確化（曖昧な主語・目的語を補足）

---

## 実行タスク

> **Task / Step 分離ルール**: このセクションには plan のみを書く。実行結果は `outputs/phase-8/` へ記録する。

### タスク1: チェックリスト文言の冗長性チェック

**目的**: Phase 5 で追記した三者同期チェックリストの文言を精査し、冗長・重複を特定する

**実行手順**:

1. `phase12-task-spec-compliance-template.md` の追記セクションを通読する
2. 既存チェックリスト項目と意味的に重複している箇所を特定する
3. 動詞表現のゆれ（「確認する」「確認した」「確認済み」等）を統一候補として記録する
4. 特定結果を `outputs/phase-8/refactoring-log.md` に記録する

**期待される成果物**:

- `outputs/phase-8/refactoring-log.md`（対象/Before/After/理由テーブル形式）

---

### タスク2: 既存テンプレートとの表現統一

**目的**: 追記内容の文体・表現を既存テンプレートの規則に揃える

**実行手順**:

1. `phase12-task-spec-compliance-template.md` の既存チェックリスト形式を確認する
   （`- [ ] <動詞> + <目的語>` 形式の一貫性）
2. `SKILL.md` の「よくある漏れ」テーブルの既存エントリ文体を確認する
3. 追記内容で形式が逸脱している箇所を修正案としてドラフトする
4. 修正案を `outputs/phase-8/refactoring-log.md` の Before/After 列に記録する

**期待される成果物**:

- `outputs/phase-8/refactoring-log.md`（タスク1 と同ファイルに追記）

---

### タスク3: 日本語表現の明確化

**目的**: 曖昧な日本語表現を補正し、実行者が迷わずに判断できる文言にする

**実行手順**:

1. 主語が省略されて意味が曖昧になっている箇所を特定する
2. 「同期する」「更新する」等の目的語が不明確な箇所を補足する
3. 修正案を `outputs/phase-8/refactoring-log.md` に追記する

**期待される成果物**:

- `outputs/phase-8/refactoring-log.md`（全修正案を集約）

---

### タスク4: 変更内容の適用と確認

**目的**: ドラフトした修正案を実際のファイルに適用し、変更後の整合性を確認する

**実行手順**:

1. `outputs/phase-8/refactoring-log.md` の修正案を確認する
2. 変更量が軽微（文言調整のみ）であることを確認してから適用する
3. 変更後のファイル 3 件（SKILL.md / compliance-template / guide）を通読し、
   Phase 1 の AC-1〜AC-6 を引き続き充足することを確認する
4. 確認完了を `outputs/phase-8/refactoring-log.md` に記録する

**期待される成果物**:

- 変更適用済みの対象ファイル 3 件
- `outputs/phase-8/refactoring-log.md`（適用完了の記録）
