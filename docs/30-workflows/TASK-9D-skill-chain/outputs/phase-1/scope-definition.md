## 概要

本ドキュメントは、TASK-9D スキルチェーン機能のスコープ内（実装対象）とスコープ外（実装対象外）を明確に定義する。スコープ判断は、アーキテクチャ層・実行モデル・トリガー方式・データ永続化の 4 軸で分類する。

## 1. スコープ内（実装対象）

### 1.1 チェーン定義の CRUD 操作（SkillChainStore）

| 項目        | 内容                                                          |
| ----------- | ------------------------------------------------------------- |
| 新規作成    | UUID v4 による ID 自動付与、createdAt/updatedAt 自動設定      |
| ID 指定取得 | chainId による単一チェーン定義取得                            |
| 一覧取得    | 保存済み全チェーン定義の配列取得                              |
| 更新        | name/steps/variables/errorHandling の変更、updatedAt 自動更新 |
| 削除        | chainId 指定による削除                                        |
| 永続化方式  | JSON ファイル（`{storePath}/{chainId}.json`）                 |
| パス検証    | path.normalize() + startsWith() によるパストラバーサル防止    |

**対応要件**: FR-1-1 〜 FR-1-6, NFR-2-3, NFR-3-3

### 1.2 チェーン順次実行エンジン（SkillChainExecutor）

| 項目               | 内容                                                              |
| ------------------ | ----------------------------------------------------------------- |
| 順次実行           | ステップを定義順に 1 つずつ実行                                   |
| 入出力マッピング   | 4 種の InputMapping + OutputMapping による入出力データ変換        |
| 条件評価           | 4 種の SkillChainCondition による実行/スキップ判定                |
| テンプレート展開   | Mustache 構文（`{{variable}}`）によるテンプレート文字列展開       |
| エラーハンドリング | 3 戦略（stop/skip/retry）による失敗時制御                         |
| タイムアウト制御   | ステップ単位のタイムアウト（デフォルト 30000ms）                  |
| 実行時間計測       | ステップ単位（duration）とチェーン全体（totalDuration）の時間記録 |
| スキル実行委譲     | SkillService.executeSkill() への委譲（既存スキル実行基盤を利用）  |

**対応要件**: FR-2-1 〜 FR-2-5, NFR-1-2, NFR-1-3, NFR-3-1, NFR-3-2

### 1.3 入力マッピング 4 種

| 種別           | 説明                                       | 対応要件 |
| -------------- | ------------------------------------------ | -------- |
| literal        | リテラル値をそのまま入力として渡す         | FR-5-3   |
| variable       | 変数マップから指定変数名の値を取得して渡す | FR-5-2   |
| template       | Mustache テンプレートを展開して渡す        | FR-5-1   |
| previousOutput | 直前ステップの出力をそのまま渡す           | FR-2-2   |

### 1.4 出力マッピング

| 項目          | 説明                                          | 対応要件 |
| ------------- | --------------------------------------------- | -------- |
| JSONPath 抽出 | extractPath による出力の部分抽出              | FR-6-1   |
| 全体格納      | extractPath 未指定時は出力全体を変数に格納    | FR-6-2   |
| 変数格納      | variableName で指定した変数名に抽出結果を格納 | FR-5-4   |

### 1.5 条件分岐 4 種

| 種別              | 説明                                       | 対応要件       |
| ----------------- | ------------------------------------------ | -------------- |
| always            | 常に実行（condition 未指定時のデフォルト） | FR-3-1, FR-3-2 |
| ifVariable        | 指定変数が期待値と一致する場合に実行       | FR-3-3         |
| ifPreviousSuccess | 直前ステップが成功した場合のみ実行         | FR-3-4         |
| expression        | 式評価結果が truthy の場合に実行           | FR-3-5         |

### 1.6 エラーハンドリング 3 戦略

| 戦略  | 説明                                                  | 対応要件       |
| ----- | ----------------------------------------------------- | -------------- |
| stop  | ステップ失敗でチェーン全体を停止                      | FR-4-1         |
| skip  | ステップ失敗でそのステップをスキップし後続を続行      | FR-4-2         |
| retry | retryCount 回リトライ後、それでも失敗なら stop と同じ | FR-4-3, FR-4-4 |

### 1.7 IPC 5 チャネル + P42 準拠バリデーション

| チャネル              | 操作 | バリデーション                                          | 対応要件 |
| --------------------- | ---- | ------------------------------------------------------- | -------- |
| `skill:chain:list`    | 一覧 | sender 検証のみ                                         | FR-7-1   |
| `skill:chain:get`     | 取得 | sender 検証 + chainId 3 段バリデーション                | FR-7-2   |
| `skill:chain:save`    | 保存 | sender 検証 + オブジェクトバリデーション                | FR-7-3   |
| `skill:chain:delete`  | 削除 | sender 検証 + chainId 3 段バリデーション                | FR-7-4   |
| `skill:chain:execute` | 実行 | sender 検証 + chainId 3 段バリデーション + variables 型 | FR-7-5   |

全チャネル共通: FR-7-6（P42 準拠 3 段バリデーション）、FR-7-7（sender 検証）

## 2. スコープ外（実装対象外）

### 2.1 UI コンポーネント

| 項目                 | 理由                  | 管理先    |
| -------------------- | --------------------- | --------- |
| SkillChainBuilder    | UI タスクとして別管理 | task-031b |
| SkillChainStepEditor | UI タスクとして別管理 | task-031b |
| SkillChainViewer     | UI タスクとして別管理 | task-031b |

**判断根拠**: TASK-9D はバックエンド（Main Process + IPC + Preload + Zustand 状態管理）のスコープ。UI コンポーネントの設計・実装は UI 専用タスク task-031b で管理し、関心の分離を維持する。

### 2.2 並列ステップ実行

| 項目                     | 理由                                   | 管理先               |
| ------------------------ | -------------------------------------- | -------------------- |
| 複数ステップの並列実行   | 現時点では順次実行のみをスコープとする | 将来タスクとして検討 |
| ステップグループの並列化 | アーキテクチャの複雑性が増すため後回し | 将来タスクとして検討 |

**判断根拠**: 並列実行は実行エンジンの複雑性を大幅に増加させる（競合制御、変数のスレッドセーフティ、エラー伝播の設計）。まず順次実行を確実に動作させ、需要に応じて並列実行を追加する段階的アプローチを採用する。

### 2.3 スケジューリング

| 項目                      | 理由                              | 管理先  |
| ------------------------- | --------------------------------- | ------- |
| cron 的な定期実行         | TASK-9G（スケジュール機能）で管理 | TASK-9G |
| チェーンの定期実行設定 UI | TASK-9G で管理                    | TASK-9G |

**判断根拠**: スケジュール機能は TASK-9G として独立したタスクで管理されている。TASK-9D で提供するチェーン実行 API（`skill:chain:execute`）を TASK-9G から呼び出す形で連携する。

### 2.4 イベントトリガー実行

| 項目                 | 理由                   | 管理先               |
| -------------------- | ---------------------- | -------------------- |
| ファイル変更トリガー | イベント基盤が未整備   | 将来タスクとして検討 |
| Webhook トリガー     | 外部連携基盤が未整備   | 将来タスクとして検討 |
| IPC イベントトリガー | イベントバス設計が必要 | 将来タスクとして検討 |

**判断根拠**: イベント駆動のチェーン実行には、イベントバスやファイル監視基盤の設計が必要。これらの基盤が未整備のため、手動実行（IPC 経由）のみをスコープとする。

### 2.5 実行履歴の永続化

| 項目                       | 理由                        | 管理先               |
| -------------------------- | --------------------------- | -------------------- |
| 実行結果のデータベース保存 | 永続化基盤の設計が必要      | 将来タスクとして検討 |
| 実行履歴の一覧・検索       | UI + バックエンド設計が必要 | 将来タスクとして検討 |
| 実行結果の統計分析         | 分析基盤の設計が必要        | 将来タスクとして検討 |

**判断根拠**: 実行結果は SkillChainResult として返却されるが、永続化はしない。Renderer 側の Zustand Store に一時保持するのみ。実行履歴の永続化には SQLite 等のデータベース設計が必要で、TASK-9D のスコープを超える。

### 2.6 その他スコープ外

| 項目                              | 理由                                   |
| --------------------------------- | -------------------------------------- |
| チェーンのバージョニング          | CRUD の基本操作のみをスコープとする    |
| チェーンのインポート/エクスポート | 将来の移行機能として検討               |
| チェーン実行のキャンセル          | 長時間実行の制御は将来タスクとして検討 |
| チェーン間の依存関係管理          | 単一チェーンの実行のみをスコープとする |

## 3. スコープ境界の判断基準

| 基準             | スコープ内                       | スコープ外                        |
| ---------------- | -------------------------------- | --------------------------------- |
| アーキテクチャ層 | Main/IPC/Preload/Renderer/Shared | UI コンポーネント（task-031b）    |
| 実行モデル       | 順次実行（ステップを 1 つずつ）  | 並列実行                          |
| トリガー         | 手動実行（IPC 経由）             | 自動実行（スケジュール/イベント） |
| データ永続化     | チェーン定義（JSON ファイル）    | 実行履歴                          |
| 時間制御         | ステップ単位のタイムアウト       | チェーン実行のキャンセル          |

## 5. スコープ変更管理

スコープの変更が必要な場合、以下のプロセスに従う。

1. 変更理由を明文化する
2. 影響範囲を特定する（対応要件、アーキテクチャ層、テスト）
3. Phase 3（設計レビュー）で MAJOR 判定の場合は Phase 1 に戻る
4. MINOR 判定の場合は未タスク仕様書に変換して管理する

### スコープ拡大の候補（将来検討）

| 候補                   | 優先度 | 前提条件                          |
| ---------------------- | ------ | --------------------------------- |
| 並列ステップ実行       | 中     | 順次実行の安定稼働確認後          |
| チェーン実行キャンセル | 中     | 長時間チェーンの利用実績蓄積後    |
| 実行履歴永続化         | 低     | SQLite 等のデータベース基盤整備後 |
| イベントトリガー       | 低     | イベントバス基盤整備後            |
| バージョニング         | 低     | チェーン利用の成熟後              |
