## 目的

Phase 1（要件定義）と Phase 2（設計）の妥当性を多角的に検証し、実装に進む前に問題を検出する。

## 実行タスク

### タスク1: 要件-設計トレーサビリティ検証

**目的**: 全ての受け入れ基準が設計でカバーされていることを検証する

**検証マトリクス**:

| AC   | 要件                          | 設計での対応                           | カバー状況 |
| ---- | ----------------------------- | -------------------------------------- | ---------- |
| AC-1 | タイムアウトで reject         | `Promise.race` + `setTimeout`          | OK         |
| AC-2 | エラーメッセージに channel 名 | テンプレート文字列に `${channel}`      | OK         |
| AC-3 | 正常応答はタイムアウトなし    | `Promise.race` で先に resolve          | OK         |
| AC-4 | チャンネル拒否は従来どおり    | `ALLOWED_INVOKE_CHANNELS` チェック維持 | OK         |
| AC-5 | タイムアウト値が定数          | `IPC_TIMEOUT_MS = 5000`                | OK         |
| AC-6 | 既存テスト PASS               | インターフェース変更なし               | OK         |

### タスク2: セキュリティレビュー

**目的**: Preload 層のセキュリティ境界への影響を検証する

**チェック項目**:

- [ ] `contextIsolation: true` への影響なし
- [ ] `sandbox: true` への影響なし
- [ ] `contextBridge` のホワイトリスト制御は維持
- [ ] タイムアウトエラーメッセージに内部パス・スタックトレースが含まれない
- [ ] channel 名はホワイトリスト内のもののみ（拒否されたチャンネルはタイムアウト前に reject）
- [ ] DoS 攻撃ベクタ: タイムアウト Timer の大量生成による影響 → 通常使用では問題なし（IPC 呼び出し頻度は低い）

### タスク3: エッジケース検証

**目的**: 設計が想定外のケースに対応しているか検証する

| エッジケース                   | 設計での対応                                                                 | 判定             |
| ------------------------------ | ---------------------------------------------------------------------------- | ---------------- |
| IPC_TIMEOUT_MS ちょうどで応答  | `Promise.race` の仕様で先に settle した方が勝つ → 実装依存だが実用上問題なし | OK               |
| Main Process がエラーで reject | `Promise.race` で IPC エラーが先に reject → 正常動作                         | OK               |
| 複数の safeInvoke 同時呼び出し | 各呼び出しが独立した Timer を持つ → 干渉なし                                 | OK               |
| IPC_TIMEOUT_MS = 0             | 即座にタイムアウト → 設定ミスだが動作は定義済み                              | OK（定数で防止） |
| Preload 未読み込み時           | `ipcRenderer` 未定義 → 既存のエラーハンドリングで捕捉                        | OK               |

### タスク4: 既知の落とし穴チェック

**目的**: 関連する既知の落とし穴との整合性を確認する

| Pitfall | 関連性                     | 対応状況                                           |
| ------- | -------------------------- | -------------------------------------------------- |
| P13     | タイマーテストの無限ループ | テスト設計で `advanceTimersByTime` を指定済み      |
| P42     | `.trim()` バリデーション   | safeInvoke の引数は channel 名（定数）のため非該当 |
| P44     | IPC インターフェース不整合 | インターフェース変更なし                           |
| P48     | non-null assertion         | 新規コードに `!` を使用しない                      |

### タスク5: 設計判定

**目的**: レビュー結果に基づく判定を行う

**判定基準**:

| 判定          | 条件                              |
| ------------- | --------------------------------- |
| PASS          | 全チェック項目に問題なし          |
| MINOR         | 軽微な指摘あり、対応後 Phase 4 へ |
| MAJOR（要件） | 要件に重大な問題 → Phase 1 へ     |
| MAJOR（設計） | 設計に重大な問題 → Phase 2 へ     |

**期待される判定**: PASS（設計はシンプルで影響範囲が限定的）
