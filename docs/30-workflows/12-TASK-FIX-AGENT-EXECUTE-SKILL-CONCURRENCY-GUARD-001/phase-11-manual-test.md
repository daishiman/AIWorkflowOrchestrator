## 目的

UIテスト・E2Eシナリオを手動で実行し、ボタン連打時の並行実行ガードとdisabled制御が実際のユーザー操作で正しく動作することを検証する。

## 実行タスク

- アプリ起動テスト: Electronアプリを開発モードで起動し、スキル実行画面に遷移
- ボタン連打テスト: スキル実行ボタンを高速連打して並行実行が防止されることを確認
- 視覚的フィードバック確認: 実行中のボタンがdisabledスタイルに変更されることを目視確認
- 正常フロー確認: 実行完了後にボタンが再度クリック可能になることを確認

## 実行手順

### ステップ1: アプリ起動

```bash
cd apps/desktop && pnpm dev
```

### ステップ2: テストシナリオ実行

#### シナリオA: ボタン連打テスト

| 手順 | 操作                                   | 期待結果                               |
| ---- | -------------------------------------- | -------------------------------------- |
| 1    | スキル一覧からスキルを選択             | スキルが選択状態になる                 |
| 2    | プロンプトを入力                       | テキストエリアにプロンプトが表示される |
| 3    | 実行ボタンを200ms以内に3回連続クリック | 1回目の実行のみ開始される              |
| 4    | ストリーミングメッセージを確認         | 単一の応答のみ表示される（混在なし）   |

#### シナリオB: disabled状態の視覚確認

| 手順 | 操作                               | 期待結果                                                 |
| ---- | ---------------------------------- | -------------------------------------------------------- |
| 1    | スキルを選択しプロンプトを入力     | 実行ボタンがクリック可能状態                             |
| 2    | 実行ボタンをクリック               | ボタンがdisabled状態に変更（opacity低下 + テキスト変更） |
| 3    | 実行中にボタンにカーソルを合わせる | カーソルが `not-allowed` スタイルになる                  |
| 4    | 実行完了を待つ                     | ボタンが再びクリック可能状態に戻る                       |

#### シナリオC: エラー後の回復テスト

| 手順 | 操作                                                | 期待結果                             |
| ---- | --------------------------------------------------- | ------------------------------------ |
| 1    | APIキーを無効な値に変更（またはネットワークを切断） | -                                    |
| 2    | スキルを実行                                        | エラーメッセージが表示される         |
| 3    | エラー後にボタンの状態を確認                        | ボタンがクリック可能状態に戻っている |
| 4    | APIキーを正しい値に戻して再実行                     | 正常に実行される                     |

### ステップ3: DevToolsでの確認

1. Chrome DevToolsを開く（`Cmd+Option+I`）
2. Consoleタブで以下を確認:
   - ストリーミングメッセージが1回の実行分のみ表示される
   - エラーログに並行実行関連の警告がない
3. React DevToolsでZustand Storeの `isExecuting` 状態を監視:
   - 実行開始時に `true` に変更される
   - 実行完了時に `false` に変更される
   - ボタン連打時に `true` → `false` の遷移が1回のみ発生する
