## レビュー観点

### 1. i18n設計の妥当性

| 確認項目       | 確認内容                | 判定基準                  |
| -------------- | ----------------------- | ------------------------- |
| ライブラリ選定 | react-i18nextが適切か   | React ecosystemとの親和性 |
| 設定構造       | config.tsの設定が妥当か | フォールバック、検出順序  |
| ファイル構造   | 名前空間分離が適切か    | 将来の拡張性              |

### 2. 翻訳キー設計の妥当性

| 確認項目 | 確認内容                                      | 判定基準                    |
| -------- | --------------------------------------------- | --------------------------- |
| 命名規則 | `component.element.state`形式が一貫しているか | 全キーが規則に準拠          |
| 網羅性   | 全ハードコードテキストがカバーされているか    | Phase 1テキスト一覧との照合 |
| 補間変数 | {{count}}等の変数が適切に定義されているか     | 型安全性の確保              |

### 3. formatRelativeTime設計の妥当性

| 確認項目     | 確認内容                       | 判定基準                 |
| ------------ | ------------------------------ | ------------------------ |
| 後方互換性   | 既存呼び出しが動作するか       | locale引数のデフォルト値 |
| Intl API     | RelativeTimeFormat使用の妥当性 | ブラウザサポート状況     |
| テスト容易性 | locale引数でテストしやすいか   | モック不要な設計         |

### 4. 既存システムとの整合性

| 確認項目       | 確認内容                     | 判定基準                    |
| -------------- | ---------------------------- | --------------------------- |
| アプリ初期化   | I18nextProviderの配置場所    | App.tsxでの適切なラップ     |
| 既存テスト     | テストでのi18nモック方針     | 既存テストへの影響最小化    |
| バンドルサイズ | 翻訳ファイルのサイズ見積もり | NFR-01（10KB以下/言語）準拠 |
