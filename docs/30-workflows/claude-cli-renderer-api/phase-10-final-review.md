## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件達成レビュー

**目的**: Phase 1で定義した要件が達成されているか確認する

**実行手順**:

1. `outputs/phase-1/requirements.md`を読み、各要件を確認する
2. 以下の機能要件が満たされているか確認する:
   - [ ] `window.claudeCliAPI.checkInstallation()` が呼び出し可能
   - [ ] `window.claudeCliAPI.listSkills()` が呼び出し可能
   - [ ] `window.claudeCliAPI.getSkillDetail()` が呼び出し可能
   - [ ] `window.claudeCliAPI.executeScript()` が呼び出し可能
   - [ ] `window.claudeCliAPI.terminateSession()` が呼び出し可能
   - [ ] `window.claudeCliAPI.listSessions()` が呼び出し可能
   - [ ] `window.claudeCliAPI.getSession()` が呼び出し可能
   - [ ] `window.claudeCliAPI.onSessionOutput()` でストリーミング購読可能
   - [ ] `window.claudeCliAPI.onSessionStatus()` で状態変更購読可能
3. 非機能要件（型安全性、セキュリティ）が満たされているか確認する

**期待される成果物**:

- 要件達成レビュー結果

---

### タスク2: 設計整合性レビュー

**目的**: Phase 2の設計と実装が整合しているか確認する

**実行手順**:

1. `outputs/phase-2/`の設計書を読み、実装との整合性を確認する
2. 以下の観点で確認する:
   - API設計と実装の一致
   - IPC設計と実装の一致
   - セキュリティ設計と実装の一致
   - 型定義と実装の一致

**期待される成果物**:

- 設計整合性レビュー結果

---

### タスク3: 品質基準レビュー

**目的**: Phase 9の品質保証結果を確認する

**実行手順**:

1. `outputs/phase-9/quality-report.md`を読み、品質基準を満たしているか確認する
2. 以下の基準を確認する:
   - Lintエラー: 0件
   - 型エラー: 0件
   - セキュリティ問題: なし
   - テストカバレッジ: 目標達成

**期待される成果物**:

- 品質基準レビュー結果

---

### タスク4: 統合テスト結果レビュー

**目的**: Preload API関連の統合テスト結果を確認する

**実行手順**:

1. 全テストを実行する: `pnpm --filter @repo/desktop test`
2. テスト結果を確認する:
   - 全テストがパスしているか
   - カバレッジ目標を達成しているか
3. IPC連携のテスト結果を確認する

**期待される成果物**:

- 統合テスト結果レビュー結果

---

### タスク5: 最終レビュー判定

**目的**: 最終レビューの判定を行う

**実行手順**:

1. タスク1-4の結果を総合し、以下の判定基準で評価する:
   - **PASS**: 全レビュー観点で問題なし → Phase 11へ進行
   - **MINOR**: 軽微な指摘あり → 指摘対応後、Phase 11へ進行
   - **MAJOR**: 重大な問題あり → 問題に応じて戻り先を決定
   - **CRITICAL**: 致命的な問題あり → Phase 1へ戻りユーザー確認
2. 判定結果を`outputs/phase-10/final-review-result.md`に出力する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`（最終レビュー結果報告書）

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
