### ステップ1: テストシナリオ一覧

以下の6シナリオを手動で実行し、各 PASS/FAIL 基準を満たすことを確認する。

---

#### TC-001: 最小入力でのスキル生成呼び出し

**検証対象**: AC-001, AC-002

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- 呼び出し前に `problem-definition.json` が存在しないこと

**操作手順**:

1. Claude Code セッションを起動する
2. `/skill-creator` とのみ入力して送信する（追加情報なし）

**期待結果**:

- スキル名・目的・想定ユーザーを確認する `AskUserQuestion` が最初のレスポンスとして返される
- インタビュー深度（quick / standard / detailed）の選択肢が含まれている
- スキルのコード生成・ファイル作成などが先行して実行されていない

**判定基準**:

| 判定 | 条件                                                                    |
| ---- | ----------------------------------------------------------------------- |
| PASS | 最初のレスポンスが `AskUserQuestion` であり、深度選択肢が提示されている |
| FAIL | 質問なしにスキル生成が開始される、または最初の応答が質問でない          |

---

#### TC-002: 詳細な要件を書いてのスキル生成呼び出し

**検証対象**: AC-003

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること

**操作手順**:

1. Claude Code セッションを起動する
2. `/skill-creator スキル名: my-tool, 目的: ファイルを自動整理するスキル, 想定ユーザー: 開発者, 入力: ファイルパス一覧, 出力: 整理済みディレクトリ構造` と詳細な情報を付けて送信する

**期待結果**:

- 詳細な要件が指定されていても、少なくとも1回の確認質問（AskUserQuestion）が返される
- インタビュー深度の確認、または要件の追加確認質問が行われる
- 質問なしに直接スキル生成が開始されていない

**判定基準**:

| 判定 | 条件                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| PASS | 詳細な要件を書いた場合でも、少なくとも1回の確認質問（AskUserQuestion）がある |
| FAIL | 詳細な要件があることを理由に質問をスキップしてスキル生成を開始する           |

---

#### TC-003: discover-problem.md 読み込み後の最初のアクション確認

**検証対象**: AC-004

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- Phase 5 で `discover-problem.md` に実行ゲートが追記されていること

**操作手順**:

1. `/skill-creator` を呼び出す
2. インタビュー深度の質問に回答する（例: `standard`）
3. `discover-problem.md` が読み込まれた直後の Claude の次アクションを観察する

**期待結果**:

- `discover-problem.md` 読み込み直後の最初のアクションが `AskUserQuestion`（Phase 0-0-1: 「何が困っているか」）である
- `discover-problem.md` の内容を分析するだけで進まず、必ずユーザーへの質問が発生する

**判定基準**:

| 判定 | 条件                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| PASS | `discover-problem.md` 読み込み後、問題発見フェーズの質問（Phase 0-0-1）が最初のアクション |
| FAIL | `discover-problem.md` を読み込んだ後、ユーザーへの質問なしに後続フェーズへ進む            |

---

#### TC-004: problem-definition.json が存在しない状態での呼び出し

**検証対象**: AC-005

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- `problem-definition.json` が存在しないこと（初回呼び出しを想定）

**操作手順**:

1. `problem-definition.json` が存在しないことを確認する
2. `/skill-creator` を呼び出す
3. インタビュー深度の質問・問題発見フェーズを経て、`interview-user.md` が参照される場面を観察する

**期待結果**:

- `problem-definition.json` が存在しないことでエラーが発生せず、フローが停止しない
- `AskUserQuestion` によって問題定義情報の収集が開始される
- 「Phase 0-0 未完了エラー」などのエラーメッセージが出力されない

**判定基準**:

| 判定 | 条件                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| PASS | `problem-definition.json` 不在でもエラー停止せず、AskUserQuestion で収集が開始される |
| FAIL | `problem-definition.json` が存在しないことでエラーが発生し、フローが停止する         |

---

#### TC-005: collaborative フロー Phase 0-0〜0-8 の動作確認

**検証対象**: AC-006

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること

**操作手順**:

1. `/skill-creator` を呼び出す
2. インタビュー深度の質問に回答する（例: `detailed`）
3. Phase 0-0 から Phase 0-8 まで、各フェーズの質問に順番に回答し、全フェーズを通過する
4. 各 Phase 番号（0-0, 0-1, 0-2, ... 0-8）が順番に進むことを確認する

**期待結果**:

- collaborative フロー（Phase 0-0〜0-8）の各ステップが、変更前と同一の順序・内容で実行される
- 追加した「必須ブロック」「実行ゲート」が既存フローの中間に割り込まない
- Phase 0-8 完了後、通常どおりスキルの生成フローへ移行する

**判定基準**:

| 判定 | 条件                                                                                |
| ---- | ----------------------------------------------------------------------------------- |
| PASS | Phase 0-0〜0-8 のすべてのステップが変更前と同一の動作仕様で正常に実行される         |
| FAIL | いずれかの Phase がスキップ・重複・順番違いで実行されるなど、既存フローが破壊される |

---

#### TC-006: create/update/improve-prompt モードでの深度確認質問

**検証対象**: 後方互換性（AC-001, AC-002 の派生）

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること

**操作手順**:

1. `/skill-creator update` と入力して送信する
2. 最初のレスポンスを観察する
3. 手順 1〜2 を `/skill-creator improve-prompt` でも繰り返す

**期待結果**:

- `create` / `update` / `improve-prompt` モードを明示した場合でも、インタビュー深度の確認質問（AskUserQuestion）が最初のレスポンスとして返される
- 深度確認なしに直接対象スキルの更新・改善に着手しない

**判定基準**:

| 判定 | 条件                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| PASS | `update` / `improve-prompt` モードでも、最初に深度確認の AskUserQuestion が返される  |
| FAIL | モードが明示されていることを理由に深度確認をスキップし、直接更新・改善作業を開始する |
