# Phase 9: 品質保証（QA）

## メタ情報

| 項目   | 値                           |
| ------ | ---------------------------- |
| Phase  | 9                            |
| 機能名 | task-sc-dialog-mandatory-001 |
| 作成日 | 2026-04-01                   |

## 目的

実装の品質を多角的に確認し、Phase 10（最終レビュー）への進行可否を判定する。
5つのチェック観点（後方互換性・LLM 指示設計・冗長性・受入基準・依存関係）を検証する。

## 実行タスク

- 後方互換性チェック（5 モードへの影響確認）
- LLM 指示設計チェック（命令形・ゲート形式の確認）
- 冗長性チェック（行数制約・読み飛ばしリスクの確認）
- 受入基準チェック（AC-001〜AC-006 全項目の確認）
- 依存関係チェック（他ファイルへの影響ゼロ確認）

## 実行手順

### ステップ1: 後方互換性チェック

既存の 5 モードが壊れていないかを確認する。

| モード         | チェック内容                              | 判定 |
| -------------- | ----------------------------------------- | ---- |
| collaborative  | Phase 0-0〜0-8 のフローが変わっていないか | ─    |
| orchestrate    | 実行エンジン選択フローが変わっていないか  | ─    |
| create         | スキル新規作成フローが変わっていないか    | ─    |
| update         | スキル更新フローが変わっていないか        | ─    |
| improve-prompt | プロンプト改善フローが変わっていないか    | ─    |

**判定基準**: 全 5 モードに問題なし → PASS

### ステップ2: LLM 指示設計チェック

追加ブロックが命令形・ゲート形式で記述されているかを確認する。

| チェック項目                                                         | 基準         | 判定 |
| -------------------------------------------------------------------- | ------------ | ---- |
| SKILL.md の必須ブロックが「〜してはならない」等の命令形か            | 命令形必須   | ─    |
| discover-problem.md の実行ゲートが「このファイルを読んだら〜」形式か | ゲート形式   | ─    |
| 「推奨」「できれば」等の曖昧な表現がないか                           | 曖昧表現ゼロ | ─    |
| LLM が読み飛ばしにくい位置（ファイル冒頭付近）に配置されているか     | 冒頭付近配置 | ─    |

**判定基準**: 全項目問題なし → PASS

### ステップ3: 冗長性チェック

7 行以内制約と読み飛ばしリスクを確認する。

| チェック項目                                   | 基準     | 判定 |
| ---------------------------------------------- | -------- | ---- |
| SKILL.md 追加ブロックが 7 行以内か             | ≦ 7 行   | ─    |
| ブロック内に不要な説明・補足がないか           | 最小構成 | ─    |
| 同じ内容が複数箇所に重複して記述されていないか | 重複ゼロ | ─    |

**判定基準**: 全項目問題なし → PASS

### ステップ4: 受入基準チェック（AC-001〜AC-006）

Phase 1 で定義した受入基準がすべて満たされているかを確認する。

| AC     | 基準                                                                                                             | 判定 |
| ------ | ---------------------------------------------------------------------------------------------------------------- | ---- |
| AC-001 | `/skill-creator` を呼び出したとき、ユーザーへの質問なしにスキル生成が開始されない                                | ─    |
| AC-002 | `/skill-creator` 呼び出し後、最初のレスポンスに AskUserQuestion（インタビュー深度選択）が含まれる                | ─    |
| AC-003 | ユーザーが詳細な要件を書いた場合でも、少なくとも 1 回の確認質問がある                                            | ─    |
| AC-004 | `discover-problem.md` を読み込んだ Claude が、問題発見フェーズの質問を最初のアクションとして実行する             | ─    |
| AC-005 | `problem-definition.json` が存在しない初回呼び出しで、Claude がエラー停止せずに AskUserQuestion で収集を開始する | ─    |
| AC-006 | 変更後も既存の `collaborative` フロー（Phase 0-0〜0-8）の動作仕様に変更がない                                    | ─    |

**判定基準**: 全 AC が PASS → Phase 10 へ進む

### ステップ5: 依存関係チェック

変更によって他の agents/ ファイルへの影響がゼロであることを確認する。

| チェック項目                                                                      | 基準           | 判定 |
| --------------------------------------------------------------------------------- | -------------- | ---- |
| 変更対象が SKILL.md / discover-problem.md / interview-user.md の 3 ファイルのみか | 3 ファイル限定 | ─    |
| 他の agents/ ファイルへの変更がゼロか                                             | 変更ゼロ       | ─    |
| packages/ や apps/ へのコード変更が一切ないか                                     | コード変更ゼロ | ─    |

**判定基準**: 全項目問題なし → PASS

### ステップ6: QA 総合判定

| チェック             | 判定 |
| -------------------- | ---- |
| 後方互換性チェック   | ─    |
| LLM 指示設計チェック | ─    |
| 冗長性チェック       | ─    |
| 受入基準チェック     | ─    |
| 依存関係チェック     | ─    |

**総合判定**: 全項目 PASS → Phase 10 へ進む / 1 項目でも FAIL → 該当 Phase に差し戻し

## 統合テスト連携

コード変更なし。QA はドキュメントレビューのみ。手動テストは Phase 11 で実施。
