| 項目   | 値                           |
| ------ | ---------------------------- |

## 目的

Phase 5 で実施した変更の品質を確認し、必要に応じてリファクタリングを行う。
文体・スタイルの統一、行数制約の遵守、Markdown フォーマットの整合性を確認する。

## 実行タスク

- 文体・スタイルの統一確認（既存ファイルの命令形強度との一致）
- 追加ブロックの行数確認（7行以内に収まっているか）
- Markdown フォーマットの確認（引用ブロック、コードブロックの書式）

## 実行手順

### ステップ1: SKILL.md の行数確認

Phase 5 で追加した `## 必須：最初の実行ステップ` ブロックの行数を確認する。

| チェック項目                               | 基準     | 判定 |
| ------------------------------------------ | -------- | ---- |
| 追加ブロックが 7 行以内に収まっているか    | ≦ 7 行   | ─    |
| 箇条書きが 3 項目以内か                    | ≦ 3 項目 | ─    |
| 命令形（「必ず〜する」）で記述されているか | 命令形   | ─    |

現在の行数: 7 行 → **OK**

### ステップ2: discover-problem.md のスタイル確認

実行ゲートブロックが既存の `> **読み込み条件**` と同じスタイルで記述されているかを確認する。

| チェック項目                                             | 基準                         | 判定 |
| -------------------------------------------------------- | ---------------------------- | ---- |
| 引用ブロック（`>`）形式が既存ブロックと一致するか        | 同一の `> **〜**` 形式       | ─    |
| 「このファイルを読んだら」から始まる命令形になっているか | 命令形・冒頭一致             | ─    |
| Phase 0-0-1 の質問ステップを明示しているか               | AskUserQuestion への言及あり | ─    |

### ステップ3: interview-user.md のフォーマット確認

セクション 5.1 のテーブル行が既存行と同じフォーマットで記述されているかを確認する。

| チェック項目                                                                     | 基準         | 判定 |
| -------------------------------------------------------------------------------- | ------------ | ---- |
| テーブル行の列数が既存行と一致するか                                             | 列数一致     | ─    |
| `problem-definition.json` のフォールバック記述が自然な日本語か                   | 自然な日本語 | ─    |
| 「Phase 0-0 未完了エラー」が「AskUserQuestion で収集を開始する」に変わっているか | 記述変更確認 | ─    |

### ステップ4: リファクタリング要否の判定

本タスクは小規模な docs-only 変更であるため、大規模リファクタリングは不要。
文体・フォーマット確認のみを実施し、軽微な修正がある場合のみ対応する。

| リファクタリング種別 | 要否判定 | 備考                           |
| -------------------- | -------- | ------------------------------ |
| 文体統一             | 確認のみ | 命令形強度を既存行と揃える     |
| 行数削減             | 確認のみ | 7 行超過時のみ対応             |
| Markdown 書式修正    | 確認のみ | 引用ブロック・テーブル書式確認 |
| 大規模再設計         | 不要     | 小規模変更につき対象外         |

## 統合テスト連携

コード変更なし。リファクタリング対象はドキュメントのみ。

| 観点         | 判断     | 確認内容                                                             |
