## 目的

設計の妥当性を検証し、実装開始前に問題を発見・解決する。

## 背景

設計レビューゲートにより、手戻りを防ぎ、品質の高い実装を確保する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: アーキテクチャレビュー

**目的**: アーキテクチャ設計の妥当性を検証する

**実行手順**:

1. ISearchStrategy準拠の確認
2. 単一責任原則の確認
3. 依存性注入パターンの確認
4. 既存戦略（Vector/Graph）との一貫性確認

**チェックリスト**:

- [ ] ISearchStrategy インターフェースを正しく実装している
- [ ] KeywordSearchStrategyは検索責務のみを持つ
- [ ] Database依存はコンストラクタ注入されている
- [ ] VectorSearchStrategy/GraphSearchStrategyと同じResult型を使用

**期待される成果物**:

- `outputs/phase-3/architecture-review.md`

---

### タスク2: インターフェースレビュー

**目的**: インターフェース設計の妥当性を検証する

**実行手順**:

1. メソッドシグネチャの確認
2. 型安全性の確認
3. エラー型の網羅性確認
4. 既存型との互換性確認

**チェックリスト**:

- [ ] search()メソッドがSearchQueryを受け取りResult<SearchResultItem[], Error>を返す
- [ ] getMetrics()がStrategyMetricを返す
- [ ] KeywordSearchErrorが全エラーケースをカバーしている
- [ ] SearchResultItemが既存のインターフェースと互換

**期待される成果物**:

- `outputs/phase-3/interface-review.md`

---

### タスク3: データフローレビュー

**目的**: データフロー設計の妥当性を検証する

**実行手順**:

1. 入力検証の完全性確認
2. エラーパスの網羅性確認
3. 変換処理の正確性確認
4. パフォーマンスボトルネックの確認

**チェックリスト**:

- [ ] 全ての入力が適切に検証されている
- [ ] 全てのエラーケースが適切にハンドリングされている
- [ ] BM25スコア→正規化スコアの変換が正確
- [ ] 大量データ時のパフォーマンス考慮がある

**期待される成果物**:

- `outputs/phase-3/data-flow-review.md`

---

### タスク4: レビュー結果の統合

**目的**: レビュー結果を統合し、判定を行う

**実行手順**:

1. 全レビュー結果の集約
2. 指摘事項の分類（CRITICAL/MAJOR/MINOR）
3. 対応方針の決定
4. 最終判定

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`

## レビューゲート

### 判定基準

| 判定     | 条件                     | 次のアクション          |
| -------- | ------------------------ | ----------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ   |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り設計修正   |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻り要件再確認 |

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点       | 確認項目                                 |
| ------------------ | ---------------------------------------- |
| API設計            | IKeywordSearchStrategy準拠性             |
| DB設計             | chunks_ftsテーブル構造の妥当性           |
| データフロー       | クエリ → FTS5 → BM25 → 正規化 → 結果変換 |
| エラーハンドリング | KeywordSearchError3種の設計              |
