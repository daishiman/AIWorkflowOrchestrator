## 目的

静的解析・セキュリティ・性能の観点から品質を保証する。

## 背景

実装・リファクタリング完了後、コードの品質を多角的に検証し、リリース基準を満たすことを確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 静的解析

**目的**: コード品質を静的解析で検証する

**実行手順**:

1. ESLintでLintエラーがないことを確認

```bash
pnpm --filter @repo/shared lint
```

2. TypeScriptで型エラーがないことを確認

```bash
pnpm --filter @repo/shared typecheck
```

3. Prettierでフォーマットが適用されていることを確認

```bash
pnpm --filter @repo/shared format:check
```

4. 未使用コード・インポートがないことを確認

**期待される成果物**:

- `outputs/phase-9/static-analysis-report.md`

---

### タスク2: セキュリティチェック

**目的**: セキュリティ上の問題がないことを確認する

**実行手順**:

1. 入力バリデーションの確認
   - クエリ長制限（MAX_QUERY_LENGTH）
   - 特殊文字のエスケープ
   - SQLインジェクション対策

2. FTS5クエリ安全性の確認
   - ユーザー入力の適切なエスケープ
   - クエリ構文インジェクション対策

3. エラーメッセージの確認
   - 内部情報の漏洩がないこと
   - スタックトレースの非公開

4. 機密情報のハードコーディングがないことを確認

**期待される成果物**:

- `outputs/phase-9/security-check-report.md`

---

### タスク3: パフォーマンス検証

**目的**: 性能要件を満たすことを確認する

**実行手順**:

1. 単一クエリ処理時間の計測
   - 目標: 100ms以下
   - 1000チャンク環境での計測

2. 複数クエリスループットの計測
   - 並列10クエリの処理時間
   - 秒間クエリ数（QPS）

3. メモリ使用量の確認
   - 検索時のメモリ増加量
   - 大量結果時のメモリ使用量

4. 非機能要件との照合
   - Phase 1で定義した要件との比較

**期待される成果物**:

- `outputs/phase-9/performance-report.md`

---

### タスク4: 品質サマリーの作成

**目的**: 品質検証結果をまとめる

**実行手順**:

1. 静的解析結果のサマリー
2. セキュリティチェック結果のサマリー
3. パフォーマンス検証結果のサマリー
4. 品質ゲート判定

**期待される成果物**:

- `outputs/phase-9/quality-summary.md`
