## 1. プロジェクト概要

### 1.1 目的

ファイル変換処理のログを構造化して記録するサービス（ConversionLogger）を実装し、システムの可観測性・デバッグ容易性・監査対応を向上させる。

### 1.2 背景

- 変換処理の追跡が困難
- エラー発生時の原因特定に時間がかかる
- 処理履歴の監査要件への対応が必要

## 3. スコープ外（Out of Scope）

### 3.1 実装しない機能

| 除外項目                   | 理由                             | 対応タスク |
| -------------------------- | -------------------------------- | ---------- |
| LogRepositoryの実装        | 別タスクで対応済みまたは対応予定 | -          |
| ログの検索・分析機能       | 履歴取得サービスの責務           | CONV-05-02 |
| ログのローテーション       | 運用要件として別途検討           | 将来対応   |
| ログのアーカイブ           | 運用要件として別途検討           | 将来対応   |
| 外部ログサービス連携       | CloudWatch, Datadog等は別途検討  | 将来対応   |
| リアルタイムストリーミング | MVP外                            | 将来対応   |
| 分散トレーシング対応       | MVP外                            | 将来対応   |
| ログの暗号化               | 現時点では不要                   | 将来対応   |

### 3.2 対応しない環境

| 環境           | 理由                 |
| -------------- | -------------------- |
| ブラウザ環境   | Node.js専用          |
| Worker Threads | シングルスレッド前提 |

### 3.3 対応しない非機能要件

| 要件               | 理由                 |
| ------------------ | -------------------- |
| 高可用性（冗長化） | ローカルSQLite前提   |
| 水平スケーリング   | 単一インスタンス前提 |
