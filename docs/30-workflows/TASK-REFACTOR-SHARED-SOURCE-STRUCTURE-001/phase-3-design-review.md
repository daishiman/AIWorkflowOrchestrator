## 目的

Phase 1（要件定義）と Phase 2（設計）の成果物を多角的にレビューし、Phase 4（テスト作成）への進行可否を判定する。移行計画の完全性、4ファイル同期チェックリストの妥当性、名前衝突解決、後方互換性、ビルド影響、Pitfall 対策、TypeScript paths 定義順序の7観点から検証を行う。

## 実行タスク

- Task 1: 移行計画の完全性レビュー — 全ファイルが移行計画に含まれていることを検証する
- Task 2: 4ファイル同期チェックリストレビュー — 各設定ファイルの変更差分が正確であることを検証する
- Task 3: 名前衝突解決レビュー — index.ts 統合における名前衝突の分析と解決方法を検証する
- Task 4: 後方互換性レビュー — 公開パスが不変であることを検証する
- Task 5: ビルド影響分析レビュー — tsup ビルド出力とパス解決を検証する
- Task 6: Pitfall 対策レビュー — P8, P11, P23, P32 の対策が設計に反映されていることを検証する
- Task 7: TypeScript paths 定義順序レビュー — 最長一致優先の順序が正しいことを検証する
- Task 8: ゲート判定 — 全レビュー観点の結果を総合して Phase 4 進行可否を決定する

### Task 8: ゲート判定

#### 判定基準

| 判定              | 条件                                                | 対応                  |
| ----------------- | --------------------------------------------------- | --------------------- |
| PASS              | 全チェック項目（MIG/SYN/NMC/BWC/BLD/PIT/TSP）が合格 | Phase 4 へ            |
| MINOR             | 軽微な修正で対応可能な指摘がある（機能影響なし）    | 指摘対応後 Phase 4 へ |
| MAJOR（要件問題） | 要件の欠落・矛盾がある                              | Phase 1 へ戻る        |
| MAJOR（設計問題） | 移行計画・設定変更に重大な誤りがある                | Phase 2 へ戻る        |

#### MAJOR 判定の具体例

- 移行対象ファイルに漏れがある（MIG 不合格）
- 4ファイル同期チェックリストのパスが実体と一致しない（SYN 不合格）
- 名前衝突が未解決（NMC 不合格）
- 公開パスが変更されてしまう（BWC 不合格）
