## Executive Summary

現在の仕様は**機能的に網羅的**だが、**認知負荷が高く、初見ユーザーには複雑**。
Appleの「シンプルさを追求しながらパワーを提供」の原則に基づき、以下を重点改善。

| 問題カテゴリ       | 重要度   | 改善項目数 |
| ------------------ | -------- | ---------- |
| 情報過多・認知負荷 | Critical | 8          |
| 導線・発見性       | High     | 6          |
| フィードバック不足 | Medium   | 5          |
| 一貫性欠如         | Medium   | 4          |
| アクセシビリティ   | High     | 3          |

## 1. Critical Issues（致命的問題）

### 1.1 スキルセレクターの情報過多

**現状の問題:**

```
┌─────────────────────────────────────────────────────────────┐
│ 📦 スキル ▴                                                 │
├─────────────────────────────────────────────────────────────┤
│ ○ なし（スキルを使用しない）                               │
│ ── インポート済み (2) ──────────────────────────────────── │
│ ● presentation-slide-generator                              │
│   HTMLプレゼンテーションスライドを生成                     │
│   サブエージェント: 4個 | 参照資料: 3個   ← 専門用語      │
```

**問題点:**

- 「サブエージェント」「参照資料」は専門用語で一般ユーザーには意味不明
- セクション分け（インポート済み/利用可能）の意味が不明確
- 一度に全情報を表示しすぎ

**改善案:**

```
┌─────────────────────────────────────────────────────────────┐
│ 📦 スキル ▴                                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ ✓ presentation-slide-generator              ← 選択中は✓  │
│   HTMLスライドを作成                                       │
│                                                             │
│ ○ task-specification-creator                                │
│   タスク仕様書を作成                                       │
│                                                             │
│ ─────────────────────────────────────────────────────────  │
│ ＋ 新しいスキルを追加...                   ← シンプルに   │
└─────────────────────────────────────────────────────────────┘
```

**改善ポイント:**

1. 専門用語を削除（詳細は「ℹ️」ボタンで表示）
2. 「インポート済み/利用可能」の区別を廃止（使えるものだけ表示）
3. 未インポートスキルは別画面（スキルストア）で管理

---

### 1.2 対話的スキル作成の6フェーズは多すぎる

**現状:**

```
Phase 1: ニーズヒアリング
Phase 2: 連携方式の確認
Phase 3: 実行方式の確認
Phase 4: セキュリティ・権限の確認
Phase 5: スキル構造のプレビュー・確認
Phase 6: 生成・即時使用
```

**問題点:**

- 6ステップは認知負荷が高い
- ユーザーは「何を作りたいか」だけ伝えたい
- 技術的詳細（連携方式、セキュリティ）は後から聞くべき

**改善案: 3ステップに簡略化**

```
┌──────────────────────────────────────────────────────────────┐
│ 新しいスキルを作成                                    [×]   │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ステップ 1/3: 何を作りますか？                             │
│  ━━━━━━━━━━━━○━━━━━━━━━━━━                                   │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ GitHubのIssueを自動で作成・管理したい               │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  AIが以下を自動判断します:                                  │
│  ✓ GitHub APIとの連携                                      │
│  ✓ 必要な認証方式（環境変数）                              │
│  ✓ 推奨されるスキル構成                                    │
│                                                              │
│  調整が必要な場合は後から変更できます                       │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                            [戻る] [続ける →] │
└──────────────────────────────────────────────────────────────┘
```

**新しい3ステップ:**

1. **何を作るか**: 自然言語で説明（AIが詳細を推測）
2. **確認**: AIの推測結果を確認・微調整
3. **完成**: 生成＆テスト

---

### 1.3 権限確認ダイアログが技術的すぎる

**現状:**

```
│  ツール: Bash                                                   │
│  コマンド:                                                      │
│  mkdir -p output && cd output && npx serve -p 3000              │
```

**問題点:**

- 一般ユーザーはコマンドを見ても意味がわからない
- 「何をしようとしているか」が伝わらない
- 選択肢が3つ（拒否/1回許可/許可）は多い

**改善案:**

```
┌──────────────────────────────────────────────────────────────┐
│ ⚠️ 操作の確認                                           [×]  │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  スキルが以下の操作を行おうとしています:                    │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 📁 フォルダ「output」を作成                            │  │
│  │ 🌐 ローカルサーバーを起動（ポート3000）               │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  [詳細を表示 ▾]                                             │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ ☐ 今後このスキルからの同様の操作は自動で許可する    │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                    [キャンセル]    [許可]    │
└──────────────────────────────────────────────────────────────┘
```

**改善ポイント:**

1. 技術的な詳細は「詳細を表示」に折りたたみ
2. **人間が読める言葉**で操作内容を説明
3. 選択肢を2つに減らす（キャンセル/許可）
4. 「1回許可」は不要（毎回確認するか、自動許可するかの2択で十分）

### 2.2 スキル実行中の進捗が不明確

**現状の問題:**


**問題点:**

- バイト数は一般ユーザーには意味がない
- 「何をしているか」が伝わらない
- 残り時間の目安がない

```
┌────────────────────────────────────────────────────────────┐
│ 📝 プレゼンテーションを作成中                              │
│                                                            │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ ✓ 構成を分析しました                                  │ │
│ │ ✓ スライドのレイアウトを決定しました                  │ │
│ │ ● HTMLファイルを生成しています...                     │ │
│ │ ○ 最終チェックを行います                              │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│ [━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━] │
│                                                            │
│                                         [⏹ 中止する]      │
└────────────────────────────────────────────────────────────┘
```

**改善ポイント:**

1. **ステップ形式**で進捗を表示（チェックリスト風）
2. 技術的詳細を隠し、「何をしているか」を人間の言葉で
3. 完了したステップには✓、進行中は●、未着手は○

## 4. Accessibility Issues（アクセシビリティ問題）

### 4.1 色だけに依存した状態表示

**現状:**

- ⏳（黄）、✅（緑）、❌（赤）で状態を区別
- 色覚異常のユーザーには区別困難

**改善案:**

- アイコンの形状も変える
- テキストラベルを追加

```
●──── 実行中    (円)
✓──── 完了      (チェックマーク)
✕──── 失敗      (×印)
⏸──── 一時停止  (停止記号)
```

---

### 4.2 キーボードナビゲーションの不備

**改善案:**

- `Tab`: 次のフォーカス可能要素へ
- `Shift+Tab`: 前のフォーカス可能要素へ
- `Enter/Space`: 選択/実行
- `Escape`: ダイアログを閉じる/キャンセル
- `Arrow Up/Down`: リスト内移動
- `Cmd+Enter`: 主要アクション実行

---

### 4.3 スクリーンリーダー対応

**追加すべきARIA属性:**

```typescript
// ツール実行状態
<div
  role="status"
  aria-live="polite"
  aria-label="ファイルを生成中です。進捗25%"
>
  ...
</div>

// 権限確認ダイアログ
<dialog
  role="alertdialog"
  aria-labelledby="permission-title"
  aria-describedby="permission-desc"
>
  <h2 id="permission-title">操作の確認</h2>
  <p id="permission-desc">スキルがフォルダを作成しようとしています</p>
  ...
</dialog>
```

## 5. 改善後のユーザーフロー

### 5.1 初回ユーザーの体験

```
1. アプリ起動
   ↓
2. ウェルカム画面（スキルの説明）
   ↓
3. 「試してみる」をクリック
   ↓
4. サンプルスキルが自動選択される
   ↓
5. 「プレゼンを作って」と入力
   ↓
6. スキルが実行され、結果を確認
   ↓
7. 「他のスキルも試してみますか？」と提案
```

### 5.2 新規スキル作成フロー（改善後）

```
1. 「新しいスキルを作成」をクリック
   ↓
2. 「何を自動化したいですか？」に回答
   例: 「毎朝の天気を確認してSlackに通知」
   ↓
3. AIが自動で構成を提案
```

## 7. まとめ

**Appleの設計原則に照らした主な問題:**

1. **Simplicity（シンプルさ）**: 情報量が多すぎる → 段階的開示に
2. **Clarity（明確さ）**: 専門用語が多い → 人間の言葉に
3. **Consistency（一貫性）**: 操作方法がバラバラ → 統一パターンに
4. **Feedback（フィードバック）**: 状態が不明確 → 明確な視覚フィードバック
5. **User Control（ユーザー制御）**: 選択肢が多すぎる → 適切に絞り込み

**成功指標:**

- 初回ユーザーが3分以内にスキルを実行できる
- ヘルプを見ずに新規スキルを作成できる
- エラー発生時に次のアクションが明確
