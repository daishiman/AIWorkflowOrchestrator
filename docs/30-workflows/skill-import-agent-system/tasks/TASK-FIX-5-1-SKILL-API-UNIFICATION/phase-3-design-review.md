## レビュー観点

### 観点 1: API設計の整合性

| チェック項目                                | 期待結果                         | 結果 |
| ------------------------------------------- | -------------------------------- | ---- |
| 全メソッドが仕様書§4の定義と一致するか      | 完全一致                         |      |
| 戻り値型が統一されているか                  | `OperationResult<T>` 廃止        |      |
| execute()のシグネチャが一意か               | `SkillExecutionRequest` 単一引数 |      |
| import()の引数が仕様書と一致するか          | `skillIds: string[]`             |      |
| 全イベントリスナーがunsubscribe関数を返すか | `() => void` 返却                |      |

### 観点 2: 型安全性

| チェック項目                                      | 期待結果                       | 結果 |
| ------------------------------------------------- | ------------------------------ | ---- |
| `SkillAPI` インターフェースがエクスポートされるか | `packages/shared` or `preload` |      |
| `window.electronAPI.skill` の型が正確か           | `SkillAPI` 型と一致            |      |
| TypeScript strictモードでコンパイル可能か         | エラーなし                     |      |

### 観点 3: 移行の実現可能性

| チェック項目                             | 期待結果                       | 結果 |
| ---------------------------------------- | ------------------------------ | ---- |
| 全呼び出し元の移行手順が明確か           | 7ステップ全て手順記載あり      |      |
| 破壊的変更の影響範囲が特定されているか   | skillSlice.ts が最大影響       |      |
| 段階的移行が可能か（一時的な互換性維持） | `window.skillAPI` 並行公開可能 |      |
| テスト修正の影響範囲が把握されているか   | モック対象の変更箇所リスト     |      |

### 観点 4: セキュリティ（Electron Preload）

| チェック項目                                         | 期待結果                   | 結果 |
| ---------------------------------------------------- | -------------------------- | ---- |
| contextBridge経由の公開のみか                        | 直接expose禁止             |      |
| 公開API面の最小化（不要メソッド除外）                | 使用されるメソッドのみ公開 |      |
| IPC送信者バリデーション（validateIpcSender）が維持か | 既存バリデーション保持     |      |
