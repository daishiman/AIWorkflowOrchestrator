## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

スキル機能のIPCチャンネルが段階的な開発（TASK-3, 4, 7, 9C）で増殖し、同じ機能に対して複数のチャンネルが存在している。仕様書では`skill:list`, `skill:import`, `skill:execute`の3つを基本とするが、現在は10以上のチャンネルが混在。

### 1.2 問題点・課題

| 問題                                            | 影響                                                                                 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| 同じ機能に2つのチャンネル                       | `skill:list` vs `skill:list-available`、`skill:getImported` vs `skill:list-imported` |
| 一部チャンネルがMain Processで未実装            | 呼び出すとエラーまたは無応答                                                         |
| ハードコードされた文字列（`as string`キャスト） | 型安全性とセキュリティチェックバイパス                                               |
| IPC_CHANNELSが2箇所で定義                       | shared vs preloadで重複                                                              |

**ハードコードの問題例**:

```typescript
// skill-api.ts:251
return safeOn<{ executionId: string }>(
  "skill:complete" as string, // ❌ IPC_CHANNELSを使用すべき
  callback,
);
```

### 1.3 放置した場合の影響

- 新規開発者がどのチャンネルを使うべきか混乱
- セキュリティホワイトリストの肥大化
- デバッグ困難（どのチャンネルが実際に動作するか不明）

---

## 2. 何を達成するか（What）

### 2.1 目的

仕様書に準拠したIPCチャンネル体系を確立する。

### 2.2 最終ゴール

1. チャンネル名を仕様書（`skill:list`, `skill:import`, `skill:execute`等）に統一
2. 重複チャンネルを削除
3. ハードコード文字列を`IPC_CHANNELS`定数に置換
4. IPC_CHANNELS定義を単一箇所に集約

### 2.3 スコープ

#### 含むもの

- スキル関連IPCチャンネルの統一
- 重複チャンネルの削除
- ALLOWED_INVOKE_CHANNELSの整理
- ハードコード文字列の置換

#### 含まないもの

- 新しいチャンネルの追加（それはTASK-4-1で実施）
- ハンドラーロジックの変更

### 2.4 成果物

| 成果物                     | 説明                 |
| -------------------------- | -------------------- |
| 統一されたIPC_CHANNELS     | 単一の定義ファイル   |
| 修正されたskillHandlers.ts | 統一チャンネル対応   |
| 修正されたskill-api.ts     | ハードコード排除     |
| 削除されたチャンネル一覧   | 重複チャンネルリスト |

## 4. 実行手順

### Phase構成

Phase 1-13の標準フローに従う。

### Step 1: チャンネル棚卸し

#### 目的

現在のIPCチャンネル全容を把握

#### 手順

1. `preload/channels.ts`の定義を確認
2. `shared/src/ipc/channels.ts`の定義を確認
3. `grep -rn "skill:" apps/desktop/src/`で使用箇所を特定
4. Main Processで実装されているハンドラーを確認

#### 成果物

- IPCチャンネル棚卸しリスト

### Step 2: マッピングテーブル作成

#### 目的

旧チャンネル→新チャンネルの対応表を作成

#### 手順

1. 仕様書のチャンネル定義を確認
2. 現在のチャンネルとの対応を決定
3. 削除対象を特定

**マッピング例**:
| 旧チャンネル | 新チャンネル | 対応 |
|-------------|-------------|------|
| skill:list-available | skill:list | 統一 |
| skill:list-imported | skill:import:list | 新名称 |
| skill:getImported | 削除 | 重複 |

#### 成果物

- チャンネルマッピングテーブル

### Step 3: IPC_CHANNELS定義の集約

#### 目的

単一の定義ファイルに集約

#### 手順

1. `@repo/shared/src/ipc/channels.ts`を正とする
2. `preload/channels.ts`から重複を削除
3. ハードコード文字列を定数に置換

#### 成果物

- 統一された`channels.ts`

### Step 4: ハンドラーとAPI修正

#### 目的

新チャンネル名に対応

#### 手順

1. `skillHandlers.ts`のチャンネル名を修正
2. `skill-api.ts`のハードコードを置換
3. 呼び出し元の修正

#### 成果物

- 修正されたハンドラー/API

## 9. 備考

### 発見経緯

無限ループ問題の調査中に、`"skill:complete" as string`のようなハードコードを発見。これが型安全性を損ない、セキュリティチェックをバイパスしていた。

### 補足事項

このタスクはTASK-4-1（IPCチャネル定義）の前提となる修正タスク。TASK-4-1では新しいチャンネルを追加するが、本タスクでは既存の重複を解消する。
