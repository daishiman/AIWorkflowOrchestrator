## 目的

Phase 2 の設計を 4 条件（価値性・実現性・整合性・運用性）でレビューし、Phase 4 実装着手の可否を判定する。
MINOR 指摘は追跡テーブルに記録し、Phase 5/9/10 で解決確認する。

## 実行タスク

### タスク1: 4 条件評価

| 条件   | チェック観点                                                                           | 評価（PASS/MINOR/MAJOR） |
| ------ | -------------------------------------------------------------------------------------- | ------------------------ |
| 価値性 | AC-1〜AC-9 を満たす機能が設計に含まれているか                                          | TBD                      |
| 実現性 | TASK-SDK-08 の Facade API に依存する部分が設計に含まれ、未実装リスクが考慮されているか | TBD                      |
| 整合性 | 薄いIPCラッパー原則（ビジネスロジック禁止・localStorage 禁止）に違反する設計がないか   | TBD                      |
| 運用性 | 期限切れセッションの TTL クリーンアップが設計されているか                              | TBD                      |

### タスク2: IPC 変更時の consumer 契約確認

新規 IPC チャンネルを追加するため、以下を確認する:

- [ ] `ipcMain.handle` の戻り値型が設計されており、Preload 層での型整合が取れているか
- [ ] `SessionResumePrompt` コンポーネントが現行の戻り値型を正しく consume する設計になっているか
- [ ] `IpcResult<T>` ラッパーを使用するか否かの判断が記録されているか（既存パターンとの整合）

### タスク3: 同名インターフェース型ドリフト検出

| チェック観点                            | 確認コマンド例                                                          |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `SkillCreatorSessionSummary` の多重定義 | `grep -rn "SkillCreatorSessionSummary\|SessionSummary" packages/ apps/` |
| `SessionResumeResult` 系の多重定義      | `grep -rn "SessionResumeResult\|ResumeResult" packages/ apps/`          |

- 同名インターフェースが複数箇所に存在する場合は `packages/shared/` への統合を検討し、未タスクとして記録する

### タスク4: 責務境界 P0-06 / P0-08 の設計検証

設計が P0-06（一時状態）と P0-08（永続状態）の境界を守っているかを確認する:

- [ ] `useInterviewState` への永続状態書き込みが設計に含まれていないか
- [ ] renderer 側での `localStorage` / `sessionStorage` 使用が設計に含まれていないか
- [ ] Facade の互換性判定ロジックを IPC 層で再実装する設計になっていないか

### タスク5: ゲート判定

**Phase 4 開始条件**:

- 4 条件評価が全て PASS または MINOR（MAJOR なし）
- IPC 4層の設計が対応表で確認されている
- 型定義の配置場所が `packages/shared/` で確定している

**MAJOR 判定の場合**: Phase 2 へ戻る（設計修正後に再レビュー）
