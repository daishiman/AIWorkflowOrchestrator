# Phase 3: 設計レビュー -- External API Support（外部APIサポート）

## メタ情報

| 項目      | 値                   |
| --------- | -------------------- |
| Phase番号 | 3                    |

## 目的

Phase 2 の設計内容を4つの観点（矛盾なし・漏れなし・整合性・依存関係整合）で検証する。
特にセキュリティ観点（APIキー漏洩リスク）を重点的に確認する。

## Task 3-1: 矛盾なし検証

### タイムアウト値の一致確認

| 項目                      | 設計値                    | 要件FR-003 | 判定 |
| ------------------------- | ------------------------- | ---------- | ---- |
| `TIMEOUT_MS`              | `30_000`（30秒）          | 30秒       | OK   |
| `AbortController` 使用    | `setTimeout(30_000, ...)` | fetch中断  | OK   |
| `ExternalApiTimeoutError` | タイムアウト時にスロー    | エラー通知 | OK   |

**結論**: タイムアウト30秒と要件FR-003は一致している。矛盾なし。

### 認証タイプの命名一致確認

| 要件定義  | 設計型定義  | IPCペイロード | 判定 |
| --------- | ----------- | ------------- | ---- |
| `none`    | `"none"`    | `"none"`      | OK   |
| `api-key` | `"api-key"` | `"api-key"`   | OK   |
| `bearer`  | `"bearer"`  | `"bearer"`    | OK   |
| `basic`   | `"basic"`   | `"basic"`     | OK   |

**結論**: 認証タイプ名称がFR-001・型定義・UIフォームで一致している。矛盾なし。

### エラークラス命名の矛盾チェック

| エラークラス名            | スロー条件       | 既存クラスとの重複 |
| ------------------------- | ---------------- | ------------------ |
| `ExternalApiTimeoutError` | 30秒タイムアウト | なし               |
| `ExternalApiHttpError`    | HTTP 4xx / 5xx   | なし               |

**結論**: 命名に矛盾なし。既存エラークラスとの衝突なし。

## Task 3-2: 漏れなし検証

### 認証4種類の実装確認

| 認証タイプ | `setAuth` 受付 | `buildAuthHeader` 実装              | フォーム表示   | テスト計画 |
| ---------- | -------------- | ----------------------------------- | -------------- | ---------- |
| none       | 対象外         | 空オブジェクト `{}`                 | 認証情報非表示 | T-01系     |
| api-key    | OK             | `X-API-Key: {cred}`                 | OK             | T-03       |
| bearer     | OK             | `Authorization: Bearer {cred}`      | OK             | T-04       |
| basic      | OK             | `Authorization: Basic {btoa(cred)}` | OK             | T-05       |

**結論**: 認証4種類すべて実装・フォーム表示・テスト計画あり。漏れなし。

### セキュリティ要件FR-005の実装確認

| 要件内容                             | 実装箇所                         | 漏れ |
| ------------------------------------ | -------------------------------- | ---- |
| APIキーを `console.log` に出力しない | `setAuth` でログなし             | なし |
| HTTPSでないURLに警告ログ             | `warnIfNotHttps()` メソッド      | なし |
| ログで認証ヘッダーをマスキング       | `buildAuthHeader` にログ出力なし | なし |

**結論**: セキュリティ要件FR-005の全項目が設計に含まれている。漏れなし。

### フォームフィールドの要件充足確認

| FR-001の設定項目     | フォームフィールド         | 漏れ |
| -------------------- | -------------------------- | ---- |
| URL                  | テキスト入力（必須）       | なし |
| メソッド（GET/POST） | セレクト                   | なし |
| 認証種別             | セレクト（4種類）          | なし |
| 認証情報             | パスワード入力（条件表示） | なし |
| カスタムヘッダー     | テキストエリア（任意）     | なし |

**結論**: FR-001の全フィールドがフォームに含まれている。漏れなし。

## Task 3-3: 整合性検証

### 型定義の整合性

| 型名                      | 使用箇所                                  | 整合 |
| ------------------------- | ----------------------------------------- | ---- |

**結論**: 型定義の整合性あり。

### IPCチャネル名の整合性

| 定数名                                              | 値                              | 使用箇所                    | 整合 |
| --------------------------------------------------- | ------------------------------- | --------------------------- | ---- |
| `SKILL_CREATOR_EXTERNAL_API_CHANNELS.CONFIGURE_API` | `'skill-creator:configure-api'` | フォーム送信・IPCハンドラー | OK   |

**結論**: チャネル定数が shared で一意定義され、両側で同一定数を参照する。整合性あり。

## Task 3-4: 依存関係整合検証

### 依存タスクとの整合

| 依存先         | 本タスクが使用する成果物                    | 整合 |
| -------------- | ------------------------------------------- | ---- |
| TASK-SDK-SC-01 | SDK Session Bridge・IPCチャネル基盤         | OK   |

**結論**: Task-01のみに依存。並列実行可能。

### 並列タスクとの非干渉確認

| 並列タスク                         | 本タスクとの重複ファイル                      | 競合リスク |
| ---------------------------------- | --------------------------------------------- | ---------- |
| TASK-SDK-SC-02（sdk-session-ui等） | なし（新規ファイル3件 + channels.ts追記のみ） | なし       |

**結論**: 並列タスクと変更ファイルが競合しない。依存関係整合あり。

## Task 3-5: セキュリティ特別レビュー（APIキー漏洩リスク）

本タスクはAPIキーを扱うため、以下を重点確認する。

| リスク項目                          | 対策                                                             | 設計反映 |
| ----------------------------------- | ---------------------------------------------------------------- | -------- |
| APIキーがログに出力される           | `setAuth` でログ出力禁止                                         | OK       |
| APIキーがIPCペイロードに平文で入る  | `ExternalApiConfig.credential` はオプション項目                  | 要注意   |
| APIキーがエラーメッセージに含まれる | `ExternalApiTimeoutError` / `ExternalApiHttpError` はURLのみ含む | OK       |
| HTTPSでないURLへの誤送信            | `warnIfNotHttps()` で警告（リクエストはブロックしない）          | OK       |

**注意点**: IPC経由で認証情報を送信する場合は、将来的にKeytarへの移行を検討する（現バージョンでは利便性優先でCredentialをIPC経由で送信する設計とするが、SEC-03として記録する）。
