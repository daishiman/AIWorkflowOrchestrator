## 目的

## NON_VISUAL 宣言

**本 Phase は NON_VISUAL task である。**

理由: 本タスクは `SkillLifecyclePanel.tsx` のロジック変更（コールバック内の条件分岐追加）であり、UI コンポーネントの構造・レイアウト・スタイルの変更を含まない。「エラーメッセージが表示されたままになること」はスクリーンショットでも確認できるが、DevTools コンソールでの `setWorkflowError` 呼び出し観察が主な確認手段となる。

### ステップ 2: シナリオ 1 — スキル生成失敗時にエラーが表示されたまま残ること

**事前条件**: Electron アプリが起動し、DevTools が開いている状態

**確認手順**:

1. DevTools の Console タブを開く
2. スキル生成画面（`SkillLifecyclePanel` が表示される画面）に移動する
3. スキル生成を開始し、意図的に失敗させる（無効な設定・ネットワーク切断等）
4. `WORKFLOW_STATE_CHANGED` イベントで `phase: 'failed'` が届くことを Console で確認する
5. エラーメッセージが UI 上に表示されたままであることを確認する
6. DevTools Console に `setWorkflowError(null)` が `phase: 'failed'` 受信後に呼ばれていないことを確認する

**期待結果**:

| 確認項目                                                   | 期待値                     | 実際の結果 |
| ---------------------------------------------------------- | -------------------------- | ---------- |
| `phase: 'failed'` の `WORKFLOW_STATE_CHANGED` イベント受信 | 受信される                 | TBD        |
| エラーメッセージの UI 表示                                 | 表示されたまま（消えない） | TBD        |
| 修正前の動作（バグ）                                       | エラーが即座に消えてしまう | 参考       |
| 修正後の動作（正しい動作）                                 | エラーが表示されたまま残る | TBD        |

### ステップ 3: シナリオ 2 — スキル生成成功時にエラーがクリアされること（既存動作維持）

**確認手順**:

1. スキル生成を正常に実行する
2. `WORKFLOW_STATE_CHANGED` イベントで `phase: 'running'` / `phase: 'completed'` が届くことを確認する
3. UI 上のエラーメッセージ（前の失敗から残っている場合）がクリアされることを確認する

**期待結果**:

| 確認項目                                | 期待値                 | 実際の結果 |
| --------------------------------------- | ---------------------- | ---------- |
| `phase: 'running'` 受信時のエラー表示   | エラーがクリアされる   | TBD        |
| `phase: 'completed'` 受信時のエラー表示 | エラーがクリアされる   | TBD        |
| `handoffBundle` の処理                  | 変わらず正常に動作する | TBD        |
