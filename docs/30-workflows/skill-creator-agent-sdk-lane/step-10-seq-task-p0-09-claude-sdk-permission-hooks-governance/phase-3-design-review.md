# Phase 3: 設計レビュー

## メタ情報

| 項目   | 値                                     |
| ------ | -------------------------------------- |
| Phase  | 3                                      |
| 機能名 | claude-sdk-permission-hooks-governance |
| 作成日 | 2026-03-29                             |

## 目的

governance 設計が dynamic skill-creator 主線を壊さず、過剰制約や過少制約になっていないかを確認する。

## 実行タスク

- plan / execute の tool 境界が妥当か確認する
- hooks が監査のみで主処理を固定化しないか確認する
- permission denial の UI 反映が十分か確認する

## 実行手順

### ステップ1: skill 準拠を照合する

- Phase 1 / 2 の成果物が `task-specification-creator` の骨格に沿っているか確認する
- `aiworkflow-requirements` の canonical path と provenance の要件を照合する

### ステップ2: 30思考法監査を実施する

- 30 種すべてを 7 カテゴリで適用する
- 「論理が正しいか」だけでなく「前提が妥当か」「再構成した方がエレガントか」を評価する

### ステップ3: 破棄判断を行う

- パッチ修正で収まるか
- 既存実装を破棄して再構成した方が、責務境界と複雑性の両面で優れるか

### ステップ4: canonical path と dependency を確認する

- 参照リンクが current canonical path を向いていることを確認する
- 旧 lane path / completed-tasks path / standalone path の drift が 0 件であることを確認する

## gate 判定

| 判定     | 条件                                         | 次の動き                         |
| -------- | -------------------------------------------- | -------------------------------- |
| PASS     | skill 準拠、30思考法、4条件が揃う            | Phase 4 へ進む                   |
| MINOR    | 1〜2 件の軽微な修正で閉じる                  | Phase 3 内で修正し、再レビュー   |
| MAJOR    | 設計の責務境界や canonical path が壊れている | Phase 2 へ戻る                   |
| CRITICAL | 前提や安全境界が破綻している                 | Phase 1 へ戻り、要件を再固定する |
