## 目的

セキュリティエッジケースとエラーハンドリングの境界条件を補強し、IPC 統合の堅牢性を確保する。

## 実行タスク

### Task 1: セキュリティエッジケーステスト

- パストラバーサル攻撃パターンの網羅テスト:
  - `../` を含むパス
  - `..\\` を含むパス（Windows パターン）
  - URL エンコードされたトラバーサル（`%2e%2e%2f`）
  - null バイトインジェクション
- Session IPC と Runtime IPC の両経路で上記が防止されることを検証する
- コマンドインジェクション防止の境界テスト:
  - シェルメタ文字（`;`, `|`, `&&`, `` ` ``）を含む入力
  - テンプレートリテラル内の式展開

### Task 2: エラーハンドリング統一テスト

- Session IPC のエラーレスポンス形式が統一されていることを検証する
- Runtime IPC のエラーレスポンス形式が統一されていることを検証する
- 両経路のエラーレスポンスが同一のフォーマットであることを検証する
- タイムアウト時のエラーハンドリングが両経路で一貫していることを検証する
- ハンドラー内の例外が renderer に安全に伝播することを検証する

### Task 3: チャネル境界テスト

- 存在しないチャネルへの invoke が適切にエラーを返すことを検証する
- ホワイトリストにないチャネルへのアクセスが拒否されることを検証する
- チャネル名の大文字小文字が正しく処理されることを検証する
- 空文字のチャネル名が拒否されることを検証する

### Task 4: 並行アクセステスト

- Session IPC と Runtime IPC の同時呼び出しが競合しないことを検証する
- 同一チャネルへの並行 invoke が正しく処理されることを検証する
- リスナー登録の多重化が問題を起こさないことを検証する

### Task 5: 型安全性テスト

- 不正な型の引数が適切にバリデーションされることを検証する
- optional フィールドが欠落した場合の挙動を検証する
- 型定義と実際の IPC メッセージの整合性を検証する
