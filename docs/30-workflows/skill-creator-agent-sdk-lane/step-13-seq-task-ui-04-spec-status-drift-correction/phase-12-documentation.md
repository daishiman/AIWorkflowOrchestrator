## 目的

task-specification-creator の Phase 12 必須成果物を canonical filename で揃え、ステータス乖離修正の実装ガイドを中学生レベル概念説明 + 技術詳細の 2 部構成で作成する。

## 実行タスク

### Task 12-1: 実装ガイド

`implementation-guide.md` に Part 1 / Part 2 を作成する。

**Part 1: 中学生レベルの概念説明**

- 「仕様書のステータス」とは何かを日常的な比喩で説明する
- たとえば、学校の宿題の提出状況表で「未提出」と書いてあるのに実は提出済みだったら混乱する。この修正作業は、提出状況表を実際の提出状態と合わせる作業と同じ。プロジェクトでも「このタスクは未着手です」と書いてあるのに実はコードが完成していたら、次に作業する人が何をすべきか分からなくなる
- `たとえば` を最低 1 回含めること（validator 安定化ルール準拠）

**Part 2: 技術詳細**

- 修正対象タスク一覧と修正内容のサマリ
- artifacts.json の status フィールドの有効値と意味
- completed-tasks 移動の手順とリンク更新の注意点
- 再乖離防止のための運用ルール提案

### Task 12-2: 変更サマリ

修正した全タスクの before/after を一覧表にまとめる。

### Task 12-3: 運用ガイド更新提案

今後の乖離防止のための運用ルールを提案する:

- Phase 完了時の artifacts.json 自動更新スクリプトの活用
- PR マージ後のステータス更新チェックリスト
- 定期的な乖離監査の推奨頻度
