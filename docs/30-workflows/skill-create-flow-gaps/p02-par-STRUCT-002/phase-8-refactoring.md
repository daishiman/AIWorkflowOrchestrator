## 実行手順

### 1. コード品質チェック

以下の観点で `plan` 生成分岐コードを確認する:

| 観点             | チェック内容                                                   |
| ---------------- | -------------------------------------------------------------- |
| 可読性           | 三項演算子の分岐が読みやすいか（if/else への変換を検討）       |
| コメント         | `create` モードと フォールバックの区別がコードコメントで明確か |
| 命名             | `plan` の命名が文脈に合っているか                              |
| 型アノテーション | `plan` 変数に型アノテーションを付けるべきか（型推論で十分か）  |

### 2. リファクタリング方針

**変更が必要な場合のみ**実施する。

主なリファクタリング候補:

```typescript
// パターン1: 現設計（三項演算子）
const plan =
  structurePlan !== null
    ? {
        /* create モード */
      }
    : {
        /* フォールバック */
      };

// パターン2: コメント付き三項演算子（可読性向上）
// create モードは structurePlan の内容を使用、その他のモードはフォールバック
const plan =
  structurePlan !== null
    ? {
        skillName: structurePlan.skillName,
        // ...
      }
    : {
        skillName: options.name,
        // ...
      };
```

**判断基準**: コメントを追加することでコードの意図が明確になるなら追加する。
構造を変える必要がない場合は変更しない。
