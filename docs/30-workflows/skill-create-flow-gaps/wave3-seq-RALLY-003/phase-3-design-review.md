## チェック観点

- [ ] IPC 4層（定数・ホワイトリスト・ハンドラ・Preload API）がすべて設計されていることを確認する
- [ ] `rollbackLastInput` の実装がワークフローエンジンの内部仕様と整合するかを確認する（rally-phase-3-review.md リスク2）
- [ ] `handleUndo` が async になったことで既存の呼び出し側に影響がないか確認する
- [ ] RALLY-005 の「invoke を正規ソース」方針と rollback 後の snapshot 返却が整合しているか確認する
- [ ] `validateSender` が IPC ハンドラに正しく組み込まれていることを確認する
- [ ] ConversationalInterview.tsx の後続変更（RALLY-010〜013）との衝突がないことを確認する

## リスク評価

| リスク                                                             | レベル | 対処                                                                                             |
| ------------------------------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------ |
| rollbackLastInput の内部実装がワークフローエンジンの仕様と競合する | 中     | 実装前に RuntimeSkillCreatorFacade の stepHistory 管理仕様を確認し、最小実装にスコープを縮小する |
| handleUndo が async になることで UI の応答性が低下する             | 低     | rollback 中は `isSubmitting` フラグを立て、完了後に解除する                                      |
| RALLY-005 未完了状態で本タスクを実装した場合の競合                 | 中     | RALLY-005 完了を必須前提とし、実装開始前に確認する                                               |
| 7ファイル変更での途中失敗                                          | 中     | 変更順序（依存関係）を厳守し、各ステップで typecheck を実行する                                  |

## ゲート判定基準
