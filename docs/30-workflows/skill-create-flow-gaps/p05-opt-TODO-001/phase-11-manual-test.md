## 実行手順

### 0. 手動テスト方針の明記【必須】

本タスクは**NON_VISUAL**タスク（コメント変更のみ）であるため、UIの変化はない。手動テストの目的は以下のとおり：

- コメント変更がUIに意図しない影響を与えていないことの確認
- 主ツールバッジが従来通り動作していることの目視確認

### 1. アプリケーション起動

```bash
# デスクトップアプリを開発モードで起動
pnpm --filter @repo/desktop dev
```

### 2. 手動テストシナリオ

**シナリオ MT-01: 複数ツール選択時の主ツールバッジ表示**

| 手順 | 操作                                                                  | 期待結果                           |
| ---- | --------------------------------------------------------------------- | ---------------------------------- |
| 1    | スキルウィザードを起動する                                            | ウィザード画面が表示される         |
| 2    | Q5（外部ツール連携）の画面へ進む                                      | Q5 の選択肢が表示される            |
| 3    | 複数のツール（例: Slack と GitHub）を選択する                         | 2つのツールが選択状態になる        |
| 4    | 先頭に選択したツール（例: Slack）に「主ツール」バッジが表示されること | Slack に主ツールバッジが表示される |
| 5    | 2番目以降のツールにバッジが表示されないこと                           | GitHub にバッジが表示されない      |

**シナリオ MT-02: 単一ツール選択時のバッジ非表示**

| 手順 | 操作                                                 | 期待結果                    |
| ---- | ---------------------------------------------------- | --------------------------- |
| 1    | Q5 でツールを1つのみ選択する                         | 1つのツールが選択状態になる |
| 2    | 選択したツールに「主ツール」バッジが表示されないこと | バッジが表示されない        |

**シナリオ MT-03: ツール選択解除時のバッジ動作**

| 手順 | 操作                                             | 期待結果                                               |
| ---- | ------------------------------------------------ | ------------------------------------------------------ |
| 1    | 複数ツールを選択してバッジが表示された状態にする | 先頭ツールにバッジが表示される                         |
| 2    | 先頭ツールの選択を解除する                       | 新しい先頭ツールにバッジが移動する、または非表示になる |
