| チェック項目                                                           | 判定基準             | 結果 |

| パターンBの場合: 更新コメントが削除条件を明記しているか                | トレーサビリティ確保 | -    |

| 検証マトリクスに型チェック・lint・grep が含まれているか                | 検証可能性の確保     | -    |

### 4. 影響範囲チェック

| チェック項目                                                    | 判定基準               | 結果 |

### 5. レビュー判定基準

| 判定  | 条件                                                             | 次のアクション         |
| ----- | ---------------------------------------------------------------- | ---------------------- |
| PASS  | 全チェック項目でリスクなし、AC-1〜AC-3 の設計対応が充足          | Phase 4 へ進む         |
| MINOR | 小さな指摘事項あり（実装時に並行解消可能）                       | Phase 4 へ進む（追跡） |
| MAJOR | 設計の根本的な問題（AC未充足・スコープ逸脱・影響範囲が管理不能） | Phase 2 へ戻る         |

**MAJOR 判定となる条件の例**:

- `shouldShowMainToolBadge` の動作変更が必要と判明し、本タスクのスコープを超える
- パターンAを採用すべき状況でパターンBの設計になっている（逆も同様）
- AC-1〜AC-3 のいずれかを設計が満たせない構造的欠陥がある
