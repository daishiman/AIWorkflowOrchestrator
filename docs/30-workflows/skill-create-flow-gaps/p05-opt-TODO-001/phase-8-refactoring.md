## 目的

TODOコメント整理後のコードを確認し、追加のリファクタリングが必要かを判断する。本タスクはコメント変更のみのため、リファクタリングのスコープは限定的であり、不要な変更は行わない。

## 実行タスク

- コード品質の確認: 変更後のコードに可読性の問題がないかを確認
- パターンA の追加整理: `shouldShowMainToolBadge` 関数の簡潔化が可能かを検討
- 不要なリファクタリングの回避: 本タスクのスコープを逸脱しない
- リファクタリング記録の作成

## 実行手順

### 1. 変更後コードの品質確認

```bash
# 変更後のコードを確認
grep -n -A 10 "shouldShowMainToolBadge\|isMainTool" \
  apps/desktop/src/renderer/components/skill/wizard/ConversationRoundStep.tsx | head -30
```

### 2. リファクタリング候補の検討

**パターンA（TODOコメント削除）の場合のみ**:

`MAIN_TOOL_BADGE_ENABLED` フラグを削除した場合、`shouldShowMainToolBadge` 関数が以下のように簡潔化できる可能性がある：

**現状（フラグ削除後）**:

```typescript
function shouldShowMainToolBadge({
  questionKey,
  optionValue,
  selectedOptions,
}) {
  return (
    questionKey === "q5" &&
    selectedOptions.length >= 2 &&
    selectedOptions[0] === optionValue
  );
}
```

**判断**: この簡潔化はすでに Phase 5 で実施済みの場合は不要。未実施であれば実施を検討する。ただし本タスクのスコープ（コメント整理）を逸脱する変更は行わない。

**パターンB（コメント更新）の場合**:

コードロジックの変更はなく、リファクタリングの対象なし。

### 3. リファクタリング実施判断

| 判断基準                                                                 | 判定 |
| ------------------------------------------------------------------------ | ---- |
| コメント整理後のコードが可読性の問題を抱えているか                       | 確認 |
| `shouldShowMainToolBadge` 関数に本タスクのスコープ内での改善余地があるか | 確認 |
| 変更によりカバレッジや既存テストに影響があるか                           | 確認 |

**リファクタリングを実施しない条件**:

- 本タスクのスコープ（コメント整理）を逸脱する変更を必要とする場合
- 既存テストの修正を要する変更の場合
- カバレッジの低下を招く変更の場合

### 4. 実施後の確認

リファクタリングを実施した場合（または未実施の場合も）：

