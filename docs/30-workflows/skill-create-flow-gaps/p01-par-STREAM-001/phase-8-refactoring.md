## 実行手順

### 1. リファクタリング候補の特定

以下の観点でコードを確認する:

| 観点               | チェック内容                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------- |
| 定数化             | 進捗メッセージ文字列（「構造を計画しています」等）を定数化すべきか                        |
| 型の明確性         | `SkillCreatorProgressData` の型定義が明確・適切な場所に配置されているか                   |
| ヘルパー関数化     | `onProgress?.({ ... })` 呼び出しを `reportProgress(onProgress, ...)` ヘルパーに抽出するか |
| コメント整備       | 5段階の呼び出しポイントにコメントが適切に付いているか                                     |
| Phase 3 MINOR 解消 | Phase 3 設計レビューで指摘された MINOR 項目が解消されているか                             |

### 2. リファクタリング実施方針

**リファクタリングを行う場合の原則**:

- テストが PASS し続けることを最優先
- 動作を変えない純粋な改善のみ実施
- 各変更後にテストを再実行して回帰がないことを確認

**リファクタリング不要と判断する場合**:

- 現状のコードが十分に可読性・保守性を持っている場合は「変更なし」として記録

### 3. リファクタリング後のテスト再実行

```bash
# リファクタリング後のテスト実行
pnpm --filter @repo/desktop exec vitest run src/main/services/skill/__tests__/SkillCreatorService.progress.test.ts
# 期待: 全 PASS（リファクタリング前と同じ）

# 既存テストの回帰確認
pnpm --filter @repo/desktop exec vitest run src/main/ipc/__tests__/

# 型チェック
pnpm --filter @repo/desktop typecheck
```

### 4. リファクタリング記録

`outputs/phase-8/refactoring-log.md` に以下を記録:

- 候補として検討した項目一覧
- 実施したリファクタリングの内容（または「変更なし」）
- テスト再実行結果
- Phase 3 MINOR 指摘の解消状況
