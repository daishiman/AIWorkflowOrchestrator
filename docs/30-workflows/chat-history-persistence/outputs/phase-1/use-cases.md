# チャット履歴永続化機能 - ユースケース一覧

## UC-001: セッション作成

**アクター**: ユーザー

**前提条件**: ユーザーがアプリケーションにログインしている

**基本フロー**:

1. ユーザーが新規チャットを開始
2. システムがセッションIDを生成（UUID v4）
3. システムがデフォルトタイトルを生成
4. システムがセッションをDBに保存
5. ユーザーにセッション情報を返却

**代替フロー**:

- 1a. カスタムタイトル指定時: 指定されたタイトルを使用

## UC-002: メッセージ送信

**アクター**: ユーザー

**前提条件**: セッションが存在する

**基本フロー**:

1. ユーザーがメッセージを入力
2. システムがメッセージを保存
3. システムがセッションのmessageCountを更新
4. システムがlastMessagePreviewを更新
5. AIがレスポンスを生成
6. システムがAIレスポンスをLLMメタデータ付きで保存

## UC-003: 履歴一覧表示

**アクター**: ユーザー

**前提条件**: ユーザーがログインしている

**基本フロー**:

1. ユーザーが履歴一覧を要求
2. システムがユーザーのセッション一覧を取得
3. ピン留めセッションを先頭に表示
4. 残りは作成日時の降順で表示

## UC-004: 履歴検索

**アクター**: ユーザー

**前提条件**: 履歴が存在する

**基本フロー**:

1. ユーザーがキーワードを入力
2. システムがFTS5で全文検索
3. 検索結果を表示

## UC-005: セッション削除

**アクター**: ユーザー

**前提条件**: セッションが存在する

**基本フロー**:

1. ユーザーが削除を選択
2. システムが確認ダイアログを表示
3. ユーザーが確認
4. システムがメッセージを削除
5. システムがセッションを論理削除

## UC-006: エクスポート

**アクター**: ユーザー

**前提条件**: セッションにメッセージが存在する

**基本フロー**:

1. ユーザーがエクスポートを選択
2. ユーザーが形式（Markdown/JSON）を選択
3. システムがデータを変換
4. ファイルをダウンロード

## UC-007: お気に入り登録

**アクター**: ユーザー

**前提条件**: セッションが存在する

**基本フロー**:

1. ユーザーがお気に入りボタンをクリック
2. システムがisFavoriteフラグを更新
3. UIが更新される

## UC-008: ピン留め

**アクター**: ユーザー

**前提条件**: セッションが存在する、ピン留め数が10件未満

**基本フロー**:

1. ユーザーがピン留めを選択
2. システムがisPinnedフラグを更新
3. システムがpinOrderを設定
4. 一覧の先頭に表示

**例外フロー**:

- ピン留め数が10件の場合: エラー表示
