## 目的

4件の修正設計がAC-1〜AC-5を満たし、回帰リスクがなく、
最小変更量で問題を解消できるかをgate判定する。

## 実行タスク

### Task 1: 設計整合性チェック

- 問題12〜19の4件の修正が互いに干渉しないことを確認する
- `ConversationRoundStep`・`GenerateStep`・`SkillCreateWizard`の3ファイルの変更が独立していることを確認する
- useEffect依存配列の追加が無限ループや不要な再レンダリングを引き起こさないことを確認する

### Task 2: 4条件レビュー

- 矛盾なし: 各修正のトリガー条件と副作用が競合しない
- 漏れなし: AC-1〜AC-5のすべてに対応する設計が揃っている
- 整合性あり: ファイル名・状態名・成果物名が統一されている
- 依存関係整合: Phase 4以降へ引き継げる設計が完成している

### Task 3: gate判定

- PASS: 実装は局所修正（3ファイルの最小変更）で足りる
- MAJOR: コンポーネント間のprops/コールバック設計の見直しが必要
- CRITICAL: ウィザードのstate管理全体を再設計する必要がある

## リスクと対策（設計レビュー時の確認観点）

設計レビューでは以下の5件リスクを観点として照合する。

| リスク                                                          | 影響度 | 発生確率 | 対策                                                                                      |
| --------------------------------------------------------------- | ------ | -------- | ----------------------------------------------------------------------------------------- |
| `useEffect` 依存配列への `answers` 追加が無限ループを引き起こす | 高     | 中       | `answers` の参照同一性・`JSON.stringify` 比較を用いた変化検知で回避。本 Phase で検証      |
| `generationLockRef` の finally 節修正で正常フローが破壊される   | 高     | 低       | 正常完了・エラー・キャンセルの全3経路でのテストケースを用意し、Phase 4 で fail-first 確認 |
| q5 再計算ロジックが他の回答変更でも発火して性能劣化する         | 中     | 中       | q5 のみを依存配列に含める設計を徹底。Phase 7 でカバレッジと不要発火のテストを確認         |
| Wave C の並列実行で `SkillCreateWizard.tsx` の変更が競合する    | 中     | 中       | Wave C 内の Phase 5 は `TASK-SW-FIX-UI-001` と順次適用。コンフリクト解消をレビューで確認  |
| templateモードキャンセルボタンが通常モードにも表示される        | 低     | 低       | `isTemplateMode && hasError` 条件の分岐を Phase 4 テストで検証                            |
