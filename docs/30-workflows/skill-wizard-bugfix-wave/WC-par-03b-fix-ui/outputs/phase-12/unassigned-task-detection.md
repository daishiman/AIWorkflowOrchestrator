## 検出した未タスク候補

### UT-FIX-UI-FOLLOWUP-001: カテゴリ選択の最大件数制限

**問題・背景**
現状のカテゴリ選択コンポーネントは選択件数に上限が設けられていない。
ユーザーが多数のカテゴリを選択した場合、UI の表示崩れやパフォーマンス低下が懸念される。

**提案する解決策**

- 選択上限を 3〜5 件に設定するガードを追加する
- 上限到達時に視覚的フィードバック（ツールチップまたはトースト）を表示する
- 上限値は設定ファイルまたは定数で管理し、将来の変更を容易にする

**優先度**: 低
**理由**: 現行バグ修正のスコープ外であり、UX 向上の改善提案に留まる。
即時影響はないが、ユーザー数が増えた段階で対応が望ましい。

**unassigned-task への配置要否**: 要（将来スプリントで検討）

### UT-FIX-UI-FOLLOWUP-002: カテゴリ解除時のアニメーション

**問題・背景**
カテゴリトグルの選択時アニメーションは実装済みだが、解除時（オフ方向）のフェードアニメーションが未実装のため、
選択・解除の動作に視覚的非対称性が生じている。

**提案する解決策**

- Tailwind CSS の `transition-opacity` または `transition-all` を利用して解除時のフェードアウトを追加する
- `duration-150` 程度の短めのトランジションで自然な操作感を実現する
- 既存の選択アニメーションと整合性を取ること

**優先度**: 低
**理由**: 機能上の問題はなく、視覚的一貫性の改善。UX ポリッシュ作業として次回のスタイル調整スプリントで対応が適切。

**unassigned-task への配置要否**: 要（UX ポリッシュバックログとして管理）

### UT-FIX-UI-FOLLOWUP-003: ProgressBar のアニメーション

**問題・背景**
ProgressBar コンポーネントは CSS 上に `transition` プロパティが定義済みであるが、
ウィザードのステップ遷移時に動的な幅変化アニメーションが有効化されていない場合がある。

**提案する解決策**

- `transition-all duration-300 ease-in-out` を ProgressBar の width スタイルに明示的に適用する
- ステップ増減どちらの方向でもスムーズに変化することを確認する
- 既存 CSS 定義と競合しないよう調整する

**優先度**: 低
**理由**: CSS 定義は既に存在しており、適用漏れの可能性が高い。実装コストは低いが、
本タスク（TASK-SW-FIX-UI-001）のバグ修正優先度とは分離して扱うべき改善。

**unassigned-task への配置要否**: 要（実装コスト低・効果中として優先管理推奨）

### UT-FIX-UI-FOLLOWUP-004: SkillCreateWizard の他ボタン `bg-blue-600` 残存確認

**問題・背景**
TASK-SW-FIX-UI-001 では LLMモードボタンの `bg-blue-600` 残存を修正した。
ただし SkillCreateWizard 内の他ボタン（カテゴリ選択ボタン・ナビゲーションボタン等）に
同様の残存がないか網羅的な確認が未実施の可能性がある。

**提案する解決策**

- `SkillCreateWizard` 配下の全ボタン要素を対象に `bg-blue-600` の静的コード検索を実施する
- 選択状態・非選択状態で `bg-blue-600` が意図せず適用されているクラスを洗い出す
- 問題箇所があれば TASK-SW-FIX-UI-001 の後続修正として対応する

**優先度**: 中
**理由**: 同一バグパターンの残存リスクがあり、ユーザー体験への直接影響が懸念される。
コード検索のみで確認可能であるため、確認コストは低い。

**unassigned-task への配置要否**: 要（優先度中・早期確認を推奨）
