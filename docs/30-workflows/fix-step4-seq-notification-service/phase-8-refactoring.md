## 目的

Phase 5 で実装したコードの可読性・保守性を改善する。
機能を変えずに構造を整理し、将来の拡張（Windows/Linux 通知対応など）を容易にする。
全リファクタリングはテストが Green のまま行われなければならない。

---

## 実行タスク

### タスク 8-1: `ElectronNotificationService.ts` のリファクタリング確認

以下の観点でコードを確認し、必要であれば修正する:

| 確認項目                                              | 判断基準                    | アクション             |
| ----------------------------------------------------- | --------------------------- | ---------------------- |
| `Notification.isSupported()` のガードが先頭にあること | 実装確認                    | 修正不要なら変更なし   |
| `console.warn` のメッセージが一貫した形式であること   | `[ClassName] message` 形式  | 形式が異なれば統一     |
| クラスに不要なプロパティが追加されていないこと        | フィールドが 0 個であること | 余分なフィールドは削除 |

### タスク 8-2: `RuntimeSkillCreatorFacade.ts` の追加箇所のリファクタリング確認

| 確認項目                                                                                 | 判断基準          | アクション             |
| ---------------------------------------------------------------------------------------- | ----------------- | ---------------------- |
| `try/catch` のコメントが「通知の失敗はスキル生成の結果に影響しない」と明記されていること | コメント確認      | コメントがなければ追加 |
| `hasRunningExecution()` が純粋な状態確認メソッドであること（副作用なし）                 | 実装確認          | 副作用があれば除去     |
| `runningExecutions` の型が明示されていること（`Map<string, ...>` または `Set<string>`）  | TypeScript 型確認 | 型が暗黙なら明示       |

### タスク 8-3: `index.ts` の追加箇所のリファクタリング確認

| 確認項目                                                                   | 判断基準                              | アクション                               |
| -------------------------------------------------------------------------- | ------------------------------------- | ---------------------------------------- |
| `before-quit` ハンドラの位置が他のライフサイクルイベントと整合していること | 既存コードのスタイル確認              | 位置が不整合なら移動                     |
| `dialog.showMessageBox` の Promise チェーンが適切に処理されていること      | `catch` の有無確認                    | 未処理の Promise があれば `catch` を追加 |
| `ElectronNotificationService` のインスタンス化が適切な場所にあること       | `facade` インスタンス化の前にあること | 順序が逆なら修正                         |

### タスク 8-4: リファクタリングログの作成

`outputs/phase-8/refactoring-log.md` に以下を記録する:

- 実施したリファクタリングの一覧（ファイル・変更内容）
- 変更しなかった箇所（理由付き）
- リファクタリング後のテスト実行結果（全 Green であること）
