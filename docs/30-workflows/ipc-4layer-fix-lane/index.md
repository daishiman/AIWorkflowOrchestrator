# IPC 4層整合性修正 Lane

この Lane は、`verify-ipc-4layer.cjs` が検証する IPC 4層整合性の不一致を、`TASK-1` と `TASK-2` に分割して最短経路で解消するための上位仕様です。

## 目的

- `TASK-1`: preload のホワイトリスト不足を解消する
- `TASK-2`: main 側のハンドラ未実装を解消する
- 両タスク完了後に `node scripts/verify-ipc-4layer.cjs` を PASS させる

## 全体構成

| Phase   | 役割         | 位置づけ                                             |
| ------- | ------------ | ---------------------------------------------------- |
| Phase 1 | 要件定義     | 変更差分の事実整理と missing 対象の確定              |
| Phase 2 | 設計         | `TASK-1` / `TASK-2` の分割、並列可否、実装方針の確定 |
| Phase 3 | 設計レビュー | 受け入れ条件、依存、リスク、検証ゲートの最終確認     |

## タスク分割

| タスク                                | 対象                                   | 役割          | 並列性            |
| ------------------------------------- | -------------------------------------- | ------------- | ----------------- |
| `UT-FIX-IPC-PRELOAD-CHANNEL-SYNC-001` | `apps/desktop/src/preload/channels.ts` | Rule-1 の修正 | `TASK-2` と並列可 |
| `UT-FIX-IPC-MAIN-HANDLER-IMPL-001`    | `apps/desktop/src/main/ipc/` 配下      | Rule-2 の修正 | `TASK-1` と並列可 |

## 実行ゲート

1. Phase 1 で missing 対象と既登録チャネルを確定する
2. Phase 2 で `TASK-1` と `TASK-2` を並列設計する
3. Phase 3 で 4 条件をレビューし、全件 PASS したら Phase 4 へ進む
4. `TASK-1` と `TASK-2` の片方だけで最終判定しない
