## 2. 詳細シナリオ

### TS-01: カバレッジチェック成功

#### 基本情報

| 項目       | 内容                              |
| ---------- | --------------------------------- |
| シナリオID | TS-01                             |
| 対応AC     | AC-01, AC-02, AC-04               |
| 前提条件   | カバレッジが80%以上のコードベース |
| 期待結果   | coverageジョブがPASSする          |

#### テスト手順

1. feature/cicd-coverage-integration ブランチをチェックアウト
2. カバレッジが80%以上であることをローカルで確認
   ```bash
   pnpm test:coverage
   ```
3. 変更をコミット・プッシュ
4. main ブランチへのPRを作成
5. GitHub ActionsのCIが実行されるまで待機
6. coverageジョブのステータスを確認

#### 期待結果

| 確認項目                 | 期待値             |
| ------------------------ | ------------------ |
| coverageジョブステータス | ✅ PASS (グリーン) |
| Codecovアップロード      | 成功               |
| PRステータス             | マージ可能         |

#### 判定基準

- coverageジョブが緑色（PASS）で完了 → **PASS**
- coverageジョブが赤色（FAIL）で完了 → **FAIL**

---

### TS-02: カバレッジチェック失敗

#### 基本情報

| 項目       | 内容                      |
| ---------- | ------------------------- |
| シナリオID | TS-02                     |
| 対応AC     | AC-02, AC-03              |
| 前提条件   | カバレッジが80%未満の状態 |
| 期待結果   | coverageジョブがFAILする  |

#### テスト手順

1. テスト用ブランチ test/coverage-fail を作成
2. テストを一時的にスキップしてカバレッジを下げる
   ```typescript
   // vitest.config.ts に一時的に追加
   test: {
     exclude: ["**/some-important-tests/**"];
   }
   ```
3. 変更をコミット・プッシュ
4. main ブランチへのPRを作成
5. GitHub ActionsのCIが実行されるまで待機
6. coverageジョブのステータスを確認

#### 期待結果

| 確認項目                 | 期待値                   |
| ------------------------ | ------------------------ |
| coverageジョブステータス | ❌ FAIL (赤)             |
| PRステータス             | マージブロック           |
| エラーメッセージ         | カバレッジ閾値未達の表示 |

#### 判定基準

- coverageジョブが赤色（FAIL）で完了 → **PASS**
- coverageジョブが緑色（PASS）で完了 → **FAIL**

#### 後処理

```bash
# テスト完了後、テストブランチを削除
git branch -D test/coverage-fail
```

### TS-04: Codecovダッシュボード更新

#### 基本情報

| 項目       | 内容                              |
| ---------- | --------------------------------- |
| シナリオID | TS-04                             |

## 4. テスト実行順序

```
TS-01 (成功) → TS-03 (コメント) → TS-04 (ダッシュボード) → TS-05 (影響確認)
                                                          ↓
                                                    TS-02 (失敗)※別ブランチ
```

**推奨順序**:

1. TS-01: 基本動作確認
2. TS-03: コメント確認（TS-01のPRで確認）
3. TS-04: ダッシュボード確認（TS-01完了後）
4. TS-05: 影響確認（TS-01のCI結果で確認）
5. TS-02: 失敗ケース確認（別ブランチで実施）
