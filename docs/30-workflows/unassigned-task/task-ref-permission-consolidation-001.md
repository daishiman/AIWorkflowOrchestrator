## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-7CでPermissionDialogを実装する際、既存の`components/Permission/PermissionDialog.tsx`との関係が検討された。設計判断として、スキル実行用に新規の`components/skill/PermissionDialog.tsx`を作成したが、将来的には統合または整理が必要になる可能性がある。

現在の状況:

- `components/Permission/PermissionDialog.tsx`: 既存のProps-based実装（2ボタン）
- `components/skill/PermissionDialog.tsx`: 新規のStore-direct実装（3ボタン）

### 1.2 問題点・課題

| 課題       | 詳細                                         |
| ---------- | -------------------------------------------- |
| コード重複 | 類似機能のダイアログが2つ存在                |
| 命名の混乱 | 同名コンポーネントが別ディレクトリに存在     |
| 保守コスト | 共通の改善を2箇所に適用する必要がある        |
| 設計一貫性 | APIパターン（Props vs Store-direct）が異なる |

### 1.3 放置した場合の影響

| 影響カテゴリ | 影響内容                       | 重要度 |
| ------------ | ------------------------------ | ------ |
| 保守性       | 改善・バグ修正の二重適用が必要 | 低     |
| 認知負荷     | 開発者がどちらを使うべきか迷う | 低     |
| コードベース | 類似コードの肥大化             | 低     |

## 4. 実行手順

### Phase 1: 調査・分析

**目的**: 既存コンポーネントの使用状況と機能差分を把握

**手順**:

1. `components/Permission/PermissionDialog.tsx`のコード分析
2. 使用箇所の検索（grepで参照を確認）
3. 機能比較表の作成
4. 調査レポートの作成

**調査項目**:

```bash
# 使用箇所の検索
grep -r "Permission/PermissionDialog" apps/desktop/src/
grep -r "from.*Permission" apps/desktop/src/
```

**成果物**: 調査レポート

**完了条件**:

- [ ] 使用箇所が全て把握されている
- [ ] 機能差分が明確化されている

### Phase 2: 方針決定

**目的**: 統合方針を決定

**選択肢**:

| 方針    | 説明                       | メリット               | デメリット         |
| ------- | -------------------------- | ---------------------- | ------------------ |
| A: 統合 | 1つのコンポーネントに統合  | 保守性向上、コード削減 | 破壊的変更の可能性 |
| B: 共存 | 用途別に両方維持           | 破壊的変更なし         | コード重複継続     |
| C: 移行 | 新規を標準とし旧を非推奨化 | 段階的移行可能         | 一時的に両方維持   |

**成果物**: 方針決定ドキュメント

**完了条件**:

- [ ] 方針が決定されている
- [ ] 決定根拠が文書化されている

### Phase 3: 実装

**目的**: 決定した方針に基づき実装

**方針A（統合）の場合**:

1. 共通ロジックを抽出
2. 単一コンポーネントに統合
3. 既存使用箇所を更新
4. 旧コンポーネントを削除

**方針B（共存）の場合**:

1. 命名を明確化（SkillPermissionDialog等）
2. ドキュメントで用途を明記
3. 共通ロジックがあれば抽出

**方針C（移行）の場合**:

1. 旧コンポーネントに非推奨警告を追加
2. 移行ガイドを作成
3. 段階的に使用箇所を更新

**成果物**: 方針に基づく実装

**完了条件**:

- [ ] 実装が完了している
- [ ] 全テストPASS

### Phase 4: ドキュメント更新

**目的**: 変更内容をドキュメントに反映

**手順**:

1. 実装ガイド更新
2. システム仕様書更新
3. コンポーネントJSDoc更新

**成果物**: 更新ドキュメント

**完了条件**:
