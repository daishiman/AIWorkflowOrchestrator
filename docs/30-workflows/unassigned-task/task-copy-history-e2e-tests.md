## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-3-2-Dでは46件の単体テストと23件の手動テストを実施した。E2E（End-to-End）テストによる自動化されたUIテストは含まれていない。

### 1.2 問題点・課題

- UIの回帰テストが手動で実施される必要がある
- 複数コンポーネント間の統合動作が自動検証されない
- CI/CDパイプラインでのUI自動テストがない

### 1.3 放置した場合の影響

- 将来の変更時に手動テストコストが発生
- 回帰バグの検出が遅れる可能性
- ただし、単体テストカバレッジが高いため影響は限定的

---

## 2. 何を達成するか（What）

### 2.1 目的

Playwrightを使用したE2Eテストを追加し、コピー履歴機能のUIテストを自動化する。

### 2.2 最終ゴール

- コピー履歴パネルの開閉テスト
- コピー・再コピー操作のテスト
- 複数選択・一括コピーのテスト
- キーボード操作のテスト

### 2.3 スコープ

#### 含むもの

- Playwrightテストファイル作成
- CI/CDパイプラインへの統合

#### 含まないもの

- ビジュアルリグレッションテスト
- パフォーマンステスト

### 2.4 成果物

- E2Eテストファイル（`*.e2e.test.ts`）
- テスト実行スクリプト更新
- CI/CD設定更新

---

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-3-2-D（コピー履歴機能）が完了していること
- Playwrightがプロジェクトに設定されていること

### 3.2 依存タスク

- TASK-3-2-D（完了済み）

### 3.3 必要な知識

- Playwright API
- Electron E2Eテスト

### 3.4 推奨アプローチ

1. 既存のE2Eテストパターンを参考に構造設計
2. CopyHistoryPanel専用のテストファイル作成
3. 手動テストケースをE2Eテストに変換
