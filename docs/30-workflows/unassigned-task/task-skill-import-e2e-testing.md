## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

skill-import-store-persistenceタスク（SKILL-STORE-001）でスキルインポート永続化のデバッグログ追加・統合テスト整備を行った。ユニットテスト28件+統合テスト23件でロジックの正常性は検証済みだが、実際のElectron GUI環境でのE2Eテストは未実施。

### 1.2 問題点・課題

- ユニットテストはモック環境で実行されるため、実際のelectron-storeとの連携動作は検証されていない
- アプリ再起動を含む実環境でのシナリオテストが存在しない
- 既存のE2Eテストスイート（`apps/desktop/e2e/`）にスキル管理関連のテストがない

### 1.3 放置した場合の影響

- 本番環境での予期しない動作が発見されない可能性
- 将来の変更時にリグレッションを検出できない
- スキル管理機能の品質保証が不十分

---

## 2. 何を達成するか（What）

### 2.1 目的

スキルインポート永続化機能のE2Eテストを作成し、実Electron環境での動作を自動検証可能にする。

### 2.2 最終ゴール

- Playwrightを使用したE2Eテストが3件以上作成されている
- アプリ再起動後のデータ永続化が検証されている
- CI/CDパイプラインでE2Eテストが実行されている

### 2.3 スコープ

#### 含むもの

- skill:import IPC経由のスキルインポートテスト
- skill:list-imported IPC経由のインポート済みスキル一覧取得テスト
- skill:remove IPC経由のスキル削除テスト
- アプリ再起動後のデータ永続化テスト

#### 含まないもの

- スキル実行機能（skill:execute）のE2Eテスト
- スキル詳細取得（skill:get-detail）のE2Eテスト
- パフォーマンステスト

### 2.4 成果物

| 成果物             | パス                                                |
| ------------------ | --------------------------------------------------- |
| E2Eテストファイル  | `apps/desktop/e2e/skill-import-persistence.spec.ts` |
| テスト結果レポート | `outputs/phase-11/e2e-test-result.md`               |

## 3. どのように実行するか（How）

### 3.1 前提条件

- skill-import-persistence-bugfixが完了していること
- Playwright E2Eテスト環境が構築済みであること（既存の`apps/desktop/e2e/`参照）
- Electronアプリがビルド可能であること

### 3.2 依存タスク

| タスク                          | ステータス |
| ------------------------------- | ---------- |
| skill-import-persistence-bugfix | 完了       |
| Playwright E2E環境構築          | 完了       |

### 3.3 必要な知識

- Playwright E2Eテスト作成
- Electron IPC通信
- electron-store永続化機構

### 3.4 推奨アプローチ

1. 既存のE2Eテスト（`agent-sdk-integration.spec.ts`等）を参考にテスト構造を設計
2. IPC経由でskill:\*チャンネルを呼び出すヘルパー関数を作成
3. アプリ再起動シナリオはElectronAppの再起動を利用
