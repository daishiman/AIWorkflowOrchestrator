## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

ARCH-001 Clean Architectureリファクタリングでは、packages/shared内のドメイン・アプリケーション・インフラストラクチャ層の単体テストのみが実施された。Presentation層（React UI）との統合後は、実際のユーザー操作に基づく手動テストが必要となる。

ARCH-001のPhase 11手動テストはCI環境での検証のみであり、実際のElectronアプリでのGUI操作テストはスコープ外であった。

### 1.2 問題点・課題

- React Context DIを通じたUse Cases呼び出しの動作未検証
- Electron IPC経由でのDB操作の実環境検証が必要
- エラーハンドリングのUI表示が未確認
- レスポンシブ・アクセシビリティの実機検証が必要

### 1.3 放置した場合の影響

- UI統合後のリグレッションが検出されない
- ユーザー体験上の問題が本番環境で発覚する
- アクセシビリティ違反が残る可能性

---

## 4. 実行手順

### Phase構成

| Phase | 名称                   | 概要                   |
| ----- | ---------------------- | ---------------------- |
| 1     | 環境準備               | テスト環境・データ準備 |
| 2     | 機能テスト（正常系）   | CRUD操作の検証         |
| 3     | エラーテスト（異常系） | エラー表示・復旧検証   |

---

### Phase 1: 環境準備

#### 目的

テスト実行に必要な環境とデータを準備する。

#### 手順

1. 開発ビルドを起動:

   ```bash
   pnpm --filter @repo/desktop dev
   ```

2. テストユーザーでログイン

3. 既存データをバックアップ（必要に応じて）

4. テスト用セッションデータを準備

#### 成果物

- テスト環境が起動している状態

#### 完了条件

- Electronアプリが正常に起動
- チャット履歴パネルが表示される

---
