## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-WCE-MONACO-001（Monaco Editor選択範囲取得機能）では、単一選択範囲のみを対象として実装した。Monaco Editorはマルチカーソル機能（Alt+クリックで複数箇所を同時選択）をサポートしているが、現在の`getSelection()`実装ではプライマリ選択のみを返す。

### 1.2 問題点・課題

1. **マルチカーソル操作時の情報欠落**: ユーザーが複数箇所を選択してもプライマリ選択のみがLLMに送信される
2. **ユースケース制限**: 「複数箇所を同時にリファクタリング」等のワークフローが実現できない
3. **ユーザー期待との乖離**: VS Code等で馴染みのあるマルチカーソル操作が正しく動作しない

### 1.3 放置した場合の影響

- マルチカーソルを使用するパワーユーザーの体験が制限される
- 競合ツール（Cursor等）との機能差が拡大
- ただし、単一選択で基本機能は動作するため、影響は限定的（優先度: 低）

---

## 2. 何を達成するか（What）

### 2.1 目的

Monaco Editorの複数選択範囲を配列として取得し、chat-edit機能で複数コンテキストを同時に扱えるようにする。

### 2.2 最終ゴール

- `chat-edit:get-selection` が複数選択範囲を `TextSelection[]` として返却可能
- 後方互換性を維持しつつ、APIを拡張
- 複数選択範囲をLLMコンテキストとして送信可能

### 2.3 スコープ

#### 含むもの

- `editor.getSelections()` APIを使用した複数選択範囲取得
- `TextSelection[]` 型の戻り値対応
- 選択範囲が存在しない場合の空配列返却
- ユニットテスト・統合テスト追加

#### 含まないもの

- UI上でのマルチカーソル表示改善
- LLM側での複数コンテキスト処理最適化
- マルチカーソル操作自体の改善

### 2.4 成果物

| 成果物                        | 説明                                  |
| ----------------------------- | ------------------------------------- |
| editorSelection.ts修正        | getSelections()を使用した複数選択対応 |
| chatEditHandlers.ts修正       | 配列型の戻り値対応                    |
| TextSelection型拡張または新型 | 複数選択用の型定義                    |
| ユニットテスト                | マルチカーソルテストケース追加        |

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-WCE-MONACO-001（Monaco Editor選択範囲取得）が完了していること
- Monaco Editor APIの`getSelections()`の仕様を理解していること

### 3.2 依存タスク

| タスク              | ステータス | 関係     |
| ------------------- | ---------- | -------- |
| TASK-WCE-MONACO-001 | ✅ 完了    | 基盤実装 |

### 3.3 推奨アプローチ

1. `editor.getSelections()` を使用して全選択範囲を取得
2. 各Selection を TextSelection に変換
3. 戻り値型を `TextSelection | null` から `TextSelection[]` に変更
4. 後方互換のため、単一選択の場合は配列の最初の要素として返却

### 3.4 システム仕様書参照（実装課題回避ナレッジ）

> **重要**: 本タスクはTASK-WCE-MONACO-001と同じMain→Renderer通信パターンを使用する。以下の課題IDを参照し、同様の問題を回避すること。
