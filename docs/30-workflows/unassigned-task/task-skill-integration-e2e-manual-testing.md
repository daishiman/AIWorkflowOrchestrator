## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-6-1でSkillSlice（Zustand状態管理）を実装完了し、以下のコンポーネントが個別にテスト済み：

- skillSlice.ts（14状態、10アクション、4内部ハンドラー）
- setupSkillListeners.ts（IPCイベントリスナー）

しかし、以下の依存タスクが未完了のため、統合テストが実施できていない：

- TASK-7A: SkillSelector（スキル選択コンポーネント）
- TASK-7B: SkillImportDialog（インポートダイアログ）
- TASK-7C: PermissionDialog（権限確認ダイアログ）
- TASK-7D: ChatPanel統合

### 1.2 問題点・課題

ユニットテストでは以下の観点を検証できない：

1. Renderer→Main→Renderer間の実際のIPCメッセージフロー
2. UIコンポーネントとstore状態の連携
3. ストリーミングメッセージのリアルタイム表示
4. 権限ダイアログのユーザーインタラクション
5. エラーハンドリングのUI反映

### 1.3 放置した場合の影響

- 個別コンポーネントが正常でも統合時に問題が発生するリスク
- ユーザー体験に影響するバグの見逃し
- リリース後の重大な不具合発見

---

## 2. 何を達成するか（What）

### 2.1 目的

SkillSlice、Main Process IPC、スキルUIの統合動作を手動テストで検証し、エンドツーエンドの機能が正常に動作することを確認する。

### 2.2 最終ゴール

以下のシナリオが手動テストで成功すること：

1. スキル一覧の取得と表示
2. スキルのインポート/削除
3. スキルの選択と実行
4. ストリーミング出力の表示
5. 権限ダイアログの表示と応答
6. 実行中止（Abort）処理
7. エラーハンドリングとリカバリー

### 2.3 スコープ

#### 含むもの

- Renderer Process（SkillSlice、UI）の統合テスト
- Main Process（IPC Handler）の統合テスト
- Preload API（skillAPI）の統合テスト
- IPCイベントリスナーの統合テスト

#### 含まないもの

- 個別コンポーネントのユニットテスト（既存テストで対応済み）
- E2E自動テスト（Playwright）の実装
- 負荷テスト・パフォーマンステスト

### 2.4 成果物

| 成果物             | 説明                             |
| ------------------ | -------------------------------- |
| テストシナリオ一覧 | 手動テストのシナリオドキュメント |
| テスト結果レポート | 各シナリオの実行結果             |
| 発見バグリスト     | テスト中に発見したバグ一覧       |
| スクリーンショット | 主要操作のエビデンス             |

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-7A〜7D（スキルUIコンポーネント）が完了していること
- Electronアプリがビルド可能な状態であること
- `.claude/skills/`に有効なスキルが存在すること

### 3.2 依存タスク

| タスクID | タスク名          | 必須/推奨 |
| -------- | ----------------- | --------- |
| TASK-6-1 | SkillSlice実装    | 必須      |
| TASK-7A  | SkillSelector     | 必須      |
| TASK-7B  | SkillImportDialog | 必須      |
| TASK-7C  | PermissionDialog  | 必須      |
| TASK-7D  | ChatPanel統合     | 必須      |

### 3.3 必要な知識

- Electronアプリの起動・デバッグ方法
- DevToolsでのRenderer/Main Processログ確認
- IPC通信のデバッグ手法
- Zustand DevToolsの使用方法

### 3.4 推奨アプローチ

1. 開発ビルドでアプリを起動
2. DevToolsを開いてコンソールログを監視
3. 各テストシナリオを順番に実行
4. 結果をドキュメントに記録
5. 発見したバグはGitHub Issueとして起票

## 4. 実行手順

### Phase構成

| Phase | 名称         | 目的                     |
| ----- | ------------ | ------------------------ |
| 1     | 環境準備     | テスト環境のセットアップ |
| 2     | シナリオ実行 | 手動テストの実行         |
| 3     | レポート作成 | 結果のドキュメント化     |

### Phase 1: 環境準備

#### 目的

手動テストを実行するための環境を準備する。

#### 手順

1. 依存パッケージのインストール

   ```
   pnpm install
   ```

2. 開発ビルドでアプリを起動

   ```
   pnpm --filter @repo/desktop dev
   ```

3. DevToolsを開く（Cmd+Opt+I）

4. コンソールタブで以下を確認
   - skill関連のログが出力されること
   - エラーがないこと

5. テスト用スキルの確認
   - `.claude/skills/`に少なくとも1つのスキルが存在すること

#### 成果物

- 起動確認のスクリーンショット

#### 完了条件

- [ ] アプリが正常に起動する
- [ ] DevToolsでログが確認できる
- [ ] テスト用スキルが存在する
