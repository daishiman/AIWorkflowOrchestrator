# UT-SC-03-007: improve() P42 準拠バリデーション追加

## メタ情報

| 項目       | 値                                                        |
| ---------- | --------------------------------------------------------- |
| 未タスクID | UT-SC-03-007                                              |
| 検出元     | TASK-SC-03-PLAN-LLM-PROMPT エレガント検証（類推思考 #16） |
| 優先度     | 低                                                        |
| 影響範囲   | RuntimeSkillCreatorFacade.ts                              |

## 概要

`RuntimeSkillCreatorFacade.improve()` メソッド（L194-219）が `skillName` と `feedback` のバリデーションを行っていない。同Facade内の `plan()` は P42 準拠の3段バリデーション（`typeof skillSpec !== "string" || skillSpec.trim() === ""`）を実施しているが、`improve()` には同等のバリデーションがなく、Facade内でバリデーション方針が不統一。

## 対応方針

1. `improve()` メソッドの `integrated_api` 分岐（L210以降）に以下を追加:
   ```typescript
   if (typeof skillName !== "string" || skillName.trim() === "") {
     throw new Error("skillName must be a non-empty string");
   }
   if (typeof feedback !== "string" || feedback.trim() === "") {
     throw new Error("feedback must be a non-empty string");
   }
   ```
2. `terminal_handoff` 経路ではバリデーションスキップ（plan() と同方針）
3. 対応テストケース（空文字列・スペースのみ・terminal_handoff経路での動作）を追加

## 苦戦箇所の記録

- **バリデーションの配置位置**: `terminal_handoff` 経路の前か後かで振る舞いが変わる。plan() は `terminal_handoff` 後にバリデーションしている（handoff側が処理するため）。improve() も同方針にすべき
- **影響範囲の小ささ**: 現在の improve() はスタブ実装（固定文字列を返すだけ）なので、LLM統合前のこの時点で修正するのが理想的
- **推奨**: UT-SC-03-005（Result<T,E>移行）と同時に対応すれば、バリデーションエラーもResultで返せる
