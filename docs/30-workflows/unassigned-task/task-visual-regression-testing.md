## 目的

UIコンポーネントの視覚的な変更を自動検出し、意図しないデザイン変更を防止する。

## 背景

Phase 7の品質レポートで中期的な改善として提案された。現在のテスト戦略は機能テストのみで、視覚的な回帰を検出する仕組みがない。

---

## 実装対象

### 1. ツール選定

| ツール         | 特徴                        | 採用検討 |
| -------------- | --------------------------- | -------- |
| Chromatic      | Storybook統合、クラウド比較 | 推奨     |
| Percy          | CI/CD統合が容易             | 代替     |
| Playwright VRT | 既存E2E環境を活用           | 代替     |

### 2. 対象コンポーネント

| 優先度 | コンポーネント     | 理由                 |
| ------ | ------------------ | -------------------- |
| 高     | ボタン・フォーム   | ユーザー操作の主要UI |
| 高     | チャットメッセージ | コアUI               |
| 中     | サイドバー         | ナビゲーション       |
| 低     | 設定画面           | 利用頻度が低い       |

---

## 受け入れ基準

- [ ] VRTツールが導入されている
- [ ] 主要コンポーネントのスナップショットが登録されている
- [ ] CI/CDでVRTが実行される
- [ ] 視覚的差分がPRでレビュー可能
