## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

i18nリソースファイル（翻訳JSON）がアプリケーションバンドルに静的に含まれると、対応言語が増えるにつれてバンドルサイズが肥大化する。特にデスクトップアプリでは初回起動速度に影響する。

### 1.2 問題点・課題

| 問題点                       | 影響               |
| ---------------------------- | ------------------ |
| 翻訳ファイルの静的バンドル   | バンドルサイズ増大 |
| 未使用言語リソースの読み込み | メモリ使用量増加   |
| 言語追加時のバンドル再構築   | デプロイ効率の低下 |

### 1.3 放置した場合の影響

| 影響                 | 深刻度 |
| -------------------- | ------ |
| 起動速度低下         | 中     |
| バンドルサイズ肥大化 | 中     |
| スケーラビリティ低下 | 高     |

---

## 2. 何を達成するか（What）

### 2.1 目的

翻訳リソースファイルを必要な言語のみ動的に読み込むことで、バンドルサイズを最適化し、起動速度を維持する。

### 2.2 最終ゴール

| ゴール                     | 検証方法           |
| -------------------------- | ------------------ |
| 翻訳ファイルの遅延読み込み | バンドル分析       |
| 未使用言語のロード回避     | ネットワーク監視   |
| 起動速度維持               | パフォーマンス計測 |

### 2.3 スコープ

#### 含むもの

- i18next-http-backendまたは動的import導入
- 言語切替時の遅延読み込み
- ローディング状態の表示

#### 含まないもの

- 翻訳キャッシュの高度化
- CDN配置
- サーバーサイド翻訳

### 2.4 成果物

| 成果物                     | ファイルパス                               |
| -------------------------- | ------------------------------------------ |
| i18n設定更新               | `apps/desktop/src/renderer/i18n/config.ts` |
| 遅延読み込みLoader         | `apps/desktop/src/renderer/i18n/loader.ts` |
| ローディングコンポーネント | `apps/desktop/src/renderer/components/`    |

| 利点               | 欠点                 |

1. 現在のバンドルサイズ計測
2. 翻訳ファイルサイズ確認
3. 遅延読み込み方式選定
4. ローディングUI設計

| ---------------- | -------------------- |
