## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現在のAgentSDKPageでは、主にマウス操作でUI操作を行う。
キーボードショートカットを追加することで、
パワーユーザーやアクセシビリティを必要とするユーザーの
操作効率を向上させることができる。

### 1.2 問題点・課題

- キーボードのみでの操作が困難な部分がある
- 頻繁な操作にマウス移動が必要
- アクセシビリティ基準を完全には満たしていない

### 1.3 放置した場合の影響

- パワーユーザーの生産性向上の機会損失
- アクセシビリティ評価への影響
- 直接的な機能障害はなし

---

## 2. 何を達成するか（What）

### 2.1 目的

主要操作にキーボードショートカットを追加し、
キーボードのみでの効率的な操作を可能にする。

### 2.2 最終ゴール

- 主要操作にショートカットが割り当てられている
- ショートカット一覧を表示できる
- ショートカットのカスタマイズは将来対応

### 2.3 スコープ

#### 含むもの

- 送信: Cmd/Ctrl + Enter
- 中断: Escape
- 新規セッション: Cmd/Ctrl + N
- フォーカス移動: Tab / Shift+Tab
- ショートカットヘルプ: Cmd/Ctrl + /

#### 含まないもの

- ショートカットのカスタマイズ機能
- Vim風キーバインド
- マクロ機能

### 2.4 成果物

- キーボードイベントハンドラー
- 更新されたAgentSDKPageコンポーネント
- ショートカットヘルプモーダル
- ユニットテスト

## 3. どのように実行するか（How）

### 3.1 前提条件

- AgentSDKPage実装が完了していること
- 既存のキーボードナビゲーションが動作していること

### 3.2 依存タスク

- postrelease-sdk-testing ワークフロー完了

### 3.3 必要な知識

- React キーボードイベント
- アクセシビリティ (WCAG 2.1)
- クロスプラットフォームショートカット

### 3.4 推奨アプローチ

1. カスタムフック `useKeyboardShortcuts` の実装
2. ショートカット定義の一元管理
3. OS判定によるCmd/Ctrl切り替え
4. ヘルプモーダルの実装

## 6. 検証方法

### テストケース

1. Cmd/Ctrl + Enter でプロンプト送信確認
2. Escape で実行中断確認
3. Cmd/Ctrl + N でセッション作成確認
4. Cmd/Ctrl + / でヘルプモーダル表示確認
5. Mac/Windowsでキー表示切り替え確認

### 検証手順

1. pnpm vitest run でユニットテスト実行
2. 手動テストでショートカット動作確認
3. Windowsエミュレーション環境でクロスプラットフォーム確認
