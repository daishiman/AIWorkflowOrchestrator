## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現在のAgent SDK統合（PR #199）では、`@anthropic-ai/claude-agent-sdk` をNode.jsライブラリとして直接importし、TypeScript APIでエージェントを操作している。しかし、本プロジェクトには `.claude/skills/` 配下に豊富なスキルライブラリが存在し、これらはClaude Code CLI環境で動作するように設計されている。

ユーザーは、Electronアプリから「ローカルにインストールされたClaude Code CLI」を呼び出し、本システムの `.claude/skills/` 配下の特定のスキルを指定して実行し、その結果を受け取りたいという要望を持っている。

### 1.2 問題点・課題

**現在のAgent SDK統合の制約:**

- Agent SDKライブラリは汎用的なAgent APIを提供するが、Claude Code CLI固有の機能（`.claude/skills/` の実行、hooks、commands）には対応していない
- 既存の `.claude/skills/` 資産を活用できない
- Claude Code CLIの豊富な機能（スキル管理、コマンド、フック）を利用できない

**スキル選択の課題（重要）:**

- 現在 `.claude/skills/` 配下に **200個以上のスキル** が存在する
- すべてのスキルを読み込むとコンテキスト枯渇・パフォーマンス低下が発生
- ユーザーは特定のタスクに必要な **特定のスキルのみ** を選択して実行したい
- 不要なスキルを除外するフィルタリング機構が必要

**実装上の課題:**

- Claude Code CLIプロセスの起動・管理方法が未定義
- スキル指定方法（スキル名、引数、設定ファイルパス）のインターフェース設計が必要
- **スキル選択UI/API** の設計が必要（全スキルリスト表示、検索、選択、ホワイトリスト管理）
- CLIの標準出力/標準エラー出力のキャプチャとパース方法が未確立
- セッション管理とプロセスライフサイクル管理の設計が必要

### 1.3 放置した場合の影響

- `.claude/skills/` 配下の800+スキル資産が活用できない
- 既存のtask-specification-creator、presentation-slide-generator等の高度なスキルが使えない
- Claude Code CLIの進化（新機能、バグ修正）の恩恵を受けられない
- 二重実装（SDK版とCLI版）が発生し、保守コストが増大する可能性

## 2. 何を達成するか（What）

### 2.1 目的

Electronデスクトップアプリから、ローカルのClaude Code CLIを呼び出し、`.claude/skills/` 配下の特定のスキルを実行し、その結果を取得できる統合基盤を構築する。

### 2.2 最終ゴール

1. **CLIプロセス管理**: Claude Code CLIプロセスを起動・停止・監視できる
2. **スキル実行**: `.claude/skills/` 配下の任意のスキルを指定して実行できる
3. **スキル選択・フィルタリング**: 200個以上のスキルから特定のスキルのみを選択して実行できる
   - スキル一覧の取得・表示
   - スキルの検索・フィルタリング
   - ホワイトリスト/プリセット設定による選択
4. **出力キャプチャ**: CLIの標準出力/エラー出力をリアルタイムで受信できる
5. **IPC統合**: Rendererプロセスから透過的にCLIスキルを呼び出せる
6. **セッション管理**: 複数のCLIセッションを並列管理できる

### 2.3 スコープ

#### 含むもの

- Claude Code CLIのインストール確認・検証機能
- CLIプロセスのスポーン・管理（child_process）
- スキル実行API設計（スキル名、引数、設定パラメータ）
- **スキル選択・フィルタリング機能**
  - `.claude/skills/` 配下のスキル一覧取得API
  - スキル名・カテゴリによる検索・フィルタリング
  - 使用スキルのホワイトリスト管理（プリセット機能）
  - 不要スキルの除外設定
- 標準出力/エラー出力のストリーミング受信
- IPC通信パターンの実装（invoke/stream）
- エラーハンドリング（CLI未インストール、スキル実行失敗、タイムアウト）
- 基本的なセッション管理（作成、終了、クリーンアップ）

#### 含まないもの

- Claude Code CLIの自動インストール機能（手動インストールを前提）
- `.claude/commands/` の実行（スキル実行に焦点）
- Claude Code Hooksの統合（将来拡張）
- UI実装（API層のみ）
- Agent SDK統合との統合・切り替え機能（別タスクで検討）

### 2.4 成果物

| 成果物                              | 説明                                                 |
| ----------------------------------- | ---------------------------------------------------- |
| `packages/shared/src/claude-cli/`   | Claude CLI統合モジュール（型定義、インターフェース） |
| `apps/desktop/src/main/claude-cli/` | Electronメインプロセス用CLI管理                      |
| `apps/desktop/src/preload/`         | IPC通信用プリロードスクリプト（CLI API）             |
| ユニットテスト                      | CLI統合のテストコード                                |
| 統合テスト                          | スキル実行のE2Eテスト                                |
| ドキュメント                        | APIリファレンス、使用例                              |

## 3. どのように実行するか（How）

### 3.1 前提条件

- pnpm monorepo環境がセットアップ済み
- Electronアプリの基本構造が存在する
- Claude Code CLIがローカルにインストールされている（`claude --version`で確認可能）
- `.claude/skills/` 配下にスキルが存在する

### 3.2 依存タスク

| タスクID                            | 説明                    | ステータス |
| ----------------------------------- | ----------------------- | ---------- |
| task-feat-agent-sdk-integration-001 | Agent SDK統合基盤の構築 | 完了       |

### 3.3 必要な知識・スキル

- Claude Code CLI の仕様と使用方法
- Node.js `child_process` モジュール
- Electron IPC通信（contextBridge, ipcMain, ipcRenderer）
- TypeScript/async generator（ストリーミング出力）
- プロセスライフサイクル管理
- `.claude/skills/` のディレクトリ構造とスキル実行方法

### 3.4 推奨アプローチ

1. **調査フェーズ**: Claude Code CLIのコマンド仕様を調査
   - スキル実行コマンド形式
   - 引数・オプションの仕様
   - 出力フォーマット（JSON/plain text）
   - エラーコード体系

2. **設計フェーズ**: アーキテクチャ設計
   - CLIプロセス管理クラス設計
   - IPC通信プロトコル設計
   - エラーハンドリング戦略

3. **実装フェーズ**: 段階的実装
   - Phase 1: CLI実行基盤（プロセススポーン、出力キャプチャ）
   - Phase 2: IPC統合
   - Phase 3: セッション管理
   - Phase 4: エラーハンドリング

4. **テストフェーズ**: 品質保証
   - ユニットテスト
   - 統合テスト
   - E2Eテスト（実際のスキル実行）

## 6. 検証方法

### テストケース

1. **正常系テスト**
   - Claude Code CLIが正常にインストールされている環境で、`.claude/skills/task-specification-creator/SKILL.md` を実行し、正しい出力が得られる

2. **異常系テスト**
   - Claude Code CLIが未インストールの場合、適切なエラーメッセージが表示される
   - 存在しないスキルを指定した場合、エラーが正しくハンドリングされる
   - プロセスがタイムアウトした場合、適切にクリーンアップされる

3. **並列実行テスト**
   - 複数のスキルを同時に実行し、出力が混在しない
   - セッション管理が正しく機能する

### 検証手順

1. `vitest` でユニットテストを実行し、全テストがパスする
2. Playwrightで統合テストを実行し、IPC通信が正常に動作する
3. 実際のElectronアプリで `.claude/skills/` 配下のスキルを実行し、期待通りの動作を確認

## 9. 備考

### 発見経緯

Agent SDK統合（PR #199）完了後、ユーザーから以下のリクエストがあった:

> この Cloud Agent SDK はローカルの Cloud Code を使って、この本システム上の Cloud Code を使って接続するようにしたいです。そしてその本システムの .Cloud スキル配下の指定のスキルを使用して Cloud Code が実行するというようなシステムを構築したいのですが、それって今回の内容で可能ですか？可能でなければそれを未タスクにしてタスクに保存するようにしておいてほしいです。

### 補足事項

- 現在のAgent SDK統合は `@anthropic-ai/claude-agent-sdk` をライブラリとして直接使用
- 本タスクは、ローカルのClaude Code CLIプロセスを介したスキル実行を実現
- 両者は異なるアプローチであり、将来的に統合または使い分けの検討が必要

### 実装優先度の考慮

本タスクは「中優先度」とした理由:

- Agent SDK統合で基本的なAgent機能は実現済み
- `.claude/skills/` 活用は付加価値であり、必須ではない
- 大規模タスクのため、段階的に着手することを推奨
