## 1. なぜこのタスクが必要か（Why）

boolean prefix を含む命名規約違反が残ると、可読性と一貫性が落ち、後続実装の判断コストが上がる。低コストで是正できるうちに閉じるべきである。

## 2. 何を達成するか（What）

命名規約違反を洗い出し、boolean 変数・関数の命名を統一する。

## 3. どのように実行するか（How）

- 規約違反箇所を列挙する
- ルールに沿った名前へ置換する
- 型 / テスト / 仕様の表記も同期する

## 4. 実行手順

1. 対象識別子を列挙する。
2. 置換後の命名案を決める。
3. 実装・テスト・仕様を同時に更新する。
4. 回帰確認を行う。

## 5. 完了条件チェックリスト

- 規約違反の識別子が解消されている
- 命名変更が仕様と一致している
- 可読性が上がっている

## 6. 検証方法

- 識別子検索で旧名が残っていないか確認する
- 関連テストと型参照を確認する

## 7. リスクと対策

- リネーム漏れが出る: 型 / テスト / 仕様を同時に見る
- 低優先度のため放置される: 小さく完了できる単位で進める
