## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

`packages/shared/src/types/rag/graph/__tests__/utils.test.ts` の性能テストに `UT-PERF-001` の TODO が残っている。

### 1.2 問題点・課題

- 現行の閾値（10,000関係を500ms以内）が環境依存で、CI/ローカル差による誤検知リスクが高い
- 対象テストが `it.skip` のままで、性能退行を自動検知できない

### 1.3 放置した場合の影響

- 実装退行が発生しても検知できない
- 性能要件の妥当性が曖昧なまま維持される

---

## 2. 何を達成するか（What）

### 2.1 目的

環境差を考慮した再現性のある性能検証基準を定義し、性能テストを有効化する。

### 2.2 最終ゴール

1. 性能基準を絶対値のみから見直し、環境差を吸収できる基準に更新
2. `it.skip` を解除してCIで実行可能な状態にする
3. 検証手順をテスト仕様に追記する

### 2.3 スコープ

#### 含むもの

- `packages/shared/src/types/rag/graph/__tests__/utils.test.ts` の性能テスト見直し
- CI実行で安定する判定基準の導入（例: 相対比較、ウォームアップ、複数回測定）

#### 含まないもの

- `calculateEntityImportance` 実装アルゴリズム自体の改修
- RAG全体のベンチマーク基盤構築

### 2.4 成果物

| 成果物         | 説明                   |
| -------------- | ---------------------- |
| 性能テスト更新 | skip解除と基準見直し   |
| 検証メモ       | 閾値設計根拠と再現手順 |

---

## 3. どのように実行するか（How）

### 3.1 前提条件

- `@repo/shared` のテストがローカル実行できること

### 3.2 依存タスク

- なし

### 3.3 必要な知識

- Vitest の性能計測時の揺らぎ対策
- CI環境の実行ばらつき

### 3.4 推奨アプローチ

1. 現行テストの計測方式を分析
2. 絶対閾値のみの判定から、相対比較または統計的判定へ変更
3. ローカル/CIの両方で安定することを確認して有効化

---

## 4. 実行手順

### Phase構成

- Phase 1: 基準設計
- Phase 2: テスト修正
- Phase 3: 検証と文書化

### Phase 1: 基準設計

1. 現行TODOとskip理由を整理
2. 計測基準（回数・ウォームアップ・閾値）を決定

### Phase 2: テスト修正

1. `it.skip` を解除
2. 設計した基準に合わせてアサーションを修正

### Phase 3: 検証と文書化

1. ローカル実行で安定性確認
2. CI相当条件で再実行
3. 変更理由をドキュメント反映
