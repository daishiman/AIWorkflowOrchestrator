## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

`apps/desktop/src/main/ipc/index.ts` L996 に以下の TODO コメントが存在する:

```typescript
// TODO: スペースを含むパス/引数のエスケープは将来タスクで対応
```

現在の IPC 経由でのコマンド実行・パス渡し処理では、スペースを含むファイルパスや引数を
そのまま使用しており、シェルコマンドや `child_process` 呼び出し時に不正な分割が発生する
可能性がある。

例として、`/Users/my user/projects/skill.md` のようなパスがシェルに渡されると、
`/Users/my`, `user/projects/skill.md` の 2 引数として誤解釈される。

### 1.2 問題点・課題

1. **パス分割バグ**: スペースを含むディレクトリ名（例: `my documents`, `Application Support`）
   を持つユーザー環境で、ファイル操作系 IPC コマンドが失敗する。
2. **引数インジェクション**: 適切なエスケープなしでシェルに渡す場合、
   意図しないコマンド分割が発生し、セキュリティリスクとなりうる。
3. **macOS 環境での頻度**: macOS ではスペース入りパスが一般的（`/Users/my name/` など）
   であるため、Electron デスクトップアプリとして無視できない。

### 1.3 放置した場合の影響

- スペースを含むユーザー名・プロジェクト名を持つ環境で、スキル実行・ファイル操作が
  サイレントに失敗する。
- エラーメッセージが不明瞭なため、ユーザーが原因を特定できない。
- セキュリティ審査でパス・引数のインジェクション対策不足として指摘されるリスク。

## 3. どのように実行するか（How）

### 3.1 前提条件

- `apps/desktop/src/main/ipc/index.ts` の L996 周辺のコードを読み、
  どのような引数がどの関数に渡されているかを把握していること。
- Node.js の `child_process.execFile` / `spawn` の引数配列方式を知っていること
  （シェル展開を回避するため、`exec` より `execFile`/`spawn` + 引数配列が推奨）。

### 3.2 依存タスク

なし（単独で着手可能）。

### 3.3 必要な知識

- Node.js `child_process.execFile` / `spawn` の配列引数による安全なコマンド実行
- シェルエスケープの基本（クォーティング、バックスラッシュエスケープ）
- Electron メインプロセスでの IPC ハンドラ実装パターン

### 3.4 推奨アプローチ

**ステップ A: 影響箇所の特定**

```bash
grep -n "exec\|spawn\|child_process\|TODO.*エスケープ" \
  apps/desktop/src/main/ipc/index.ts
```

`exec(command + path)` パターンを `execFile(command, [path])` パターンへ置換することで
シェル展開を完全に回避できる。

**ステップ B: エスケープユーティリティの実装方針**

`child_process.execFile` / `spawn` に配列引数を渡す方式が最も安全。
シェル文字列として組み立てざるを得ない場合は以下のユーティリティを使用する:

```typescript
// 案: シェル引数エスケープユーティリティ
export function shellEscapePath(p: string): string {
  // シングルクォートで囲み、内部のシングルクォートをエスケープ
  return `'${p.replace(/'/g, "'\\''")}'`;
}
```

**ステップ C: 既存 exec 呼び出しの置換**

```typescript
// Before（危険）
exec(`some-command ${filePath}`);

// After（安全）
execFile("some-command", [filePath]);
// または
exec(`some-command ${shellEscapePath(filePath)}`);
```

## 9. 備考

### 苦戦箇所（将来の実装者への参考情報）

**発見の経緯**

TASK-UI-03 の実装中、IPC ハンドラのコマンド実行部分を読んだ際に
`// TODO: スペースを含むパス/引数のエスケープは将来タスクで対応` のコメントを発見。
優先度が低いため即時対応せず、本タスクとして切り出した。

**注意点**

- `exec(string)` はシェルを経由するため引数分割が発生するが、
  `execFile(command, args[])` はシェルを経由しないため安全。
- macOS の `Application Support` などシステムパスにもスペースが含まれるため、
  Electron アプリでは特に注意が必要。
- 既存コードで `exec` を使っている場合、コマンドとして `sh -c "..."` 形式に依存している
  可能性があるため、`execFile` への変更時は動作確認を十分に行うこと。
