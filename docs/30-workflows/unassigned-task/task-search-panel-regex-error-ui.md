## 1. Why（なぜこのタスクが必要か）

### 1.1 背景

TASK-SEARCH-INTEGRATE-001 で実装された検索パネルは、正規表現モードをサポートしている。
現在の実装では、無効な正規表現パターン（例: `[` や `(`）が入力された場合、
内部でエラーをキャッチしてハンドリングしているが、ユーザーへのフィードバックは
「結果なし（0件）」と表示されるのみである。

### 1.2 問題

- ユーザーは入力した正規表現が無効であることを認識できない
- 「結果なし」と「パターンエラー」の区別がつかない
- デバッグや修正のための情報が提供されない

### 1.3 期待される効果

- ユーザーが正規表現エラーを即座に認識できる
- エラーメッセージによりパターンの修正が容易になる
- UXの向上

## 2. What（何を達成するか）

### 2.1 機能要件

| ID     | 要件                                     | 優先度 |
| ------ | ---------------------------------------- | ------ |
| REQ-01 | 正規表現エラー時にエラーメッセージを表示 | 必須   |
| REQ-02 | エラー位置（可能であれば）を示す         | 推奨   |
| REQ-03 | エラー時は検索結果を0件ではなく非表示に  | 推奨   |

### 2.2 非機能要件

| ID     | 要件                                          |
| ------ | --------------------------------------------- |
| NFR-01 | エラーメッセージはアクセシブルであること      |
| NFR-02 | エラー表示はリアルタイム（入力から100ms以内） |
| NFR-03 | 既存のテストカバレッジを維持（97%以上）       |

### 2.3 成功基準

- [ ] 無効な正規表現入力時にエラーメッセージが表示される
- [ ] エラーメッセージは明確で理解しやすい
- [ ] アクセシビリティ要件を満たす（aria-live等）
- [ ] 既存テストが全てPASS
- [ ] 新規機能のテストカバレッジ90%以上
