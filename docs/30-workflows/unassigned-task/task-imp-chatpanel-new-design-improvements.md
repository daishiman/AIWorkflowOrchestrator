## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-7D（ChatPanel 統合）では、スキル関連コンポーネント（SkillSelector、SkillStreamingView、SkillImportDialog、PermissionDialog）を ChatPanel に統合することが主目的であった。ChatPanel 自体の新規デザイン（UI/UX の刷新）はタスク定義書にて明示的にスコープ外とされた。

現在の ChatPanel は、統合されたコンポーネントに対して placeholder slot（`model-selector-slot`、`message-list-slot`、`chat-input-slot`）を使用しており、基本的な機能は維持されているが、統一されたデザインシステムに基づくビジュアルデザインは適用されていない。

### 1.2 問題点・課題

1. ChatPanel の UI が placeholder slot ベースであり、最終的なデザインが未適用
2. 各 slot のスタイリングが暫定的で、Tailwind CSS のデザイントークンが統一されていない
3. レスポンシブデザインが考慮されていない（固定レイアウト）
4. ダークモード対応が未実装
5. アニメーション・トランジションが未適用

### 1.3 放置した場合の影響

- ユーザー体験が暫定的な状態のまま留まり、製品品質の印象が低下する
- 他のコンポーネントとのビジュアル一貫性が損なわれる
- ただし、機能的には問題なく動作するため、即座のブロッカーにはならない

---

## 2. 何を達成するか（What）

### 2.1 目的

ChatPanel コンポーネントに統一されたデザインシステムを適用し、ユーザーにとって視覚的に優れた、一貫性のあるチャット画面を提供する。

### 2.2 最終ゴール

- ChatPanel が Tailwind CSS のデザイントークンに基づく統一されたスタイルを持つ
- レスポンシブデザインが適用され、様々な画面サイズに対応する
- ダークモード対応が実装されている
- 適切なアニメーション・トランジションが適用されている
- WCAG 2.1 AA 準拠のアクセシビリティが維持されている

### 2.3 スコープ

#### 含むもの

- ChatPanel のビジュアルデザイン刷新（ヘッダー、メッセージエリア、入力エリア）
- Tailwind CSS デザイントークンの統一適用
- レスポンシブデザイン対応
- ダークモード対応
- アニメーション・トランジション追加
- 既存コンポーネント（SkillSelector、SkillStreamingView 等）とのビジュアル統合

#### 含まないもの

- 機能的な変更（データフロー、Store 接続パターンの変更）
- 新規コンポーネントの追加
- ChatPanel 以外のコンポーネントのデザイン変更
- バックエンド側の変更

### 2.4 成果物

| 成果物                     | 説明                                               |
| -------------------------- | -------------------------------------------------- |
| ChatPanel.tsx（更新）      | デザイン適用済みコンポーネント                     |
| ChatPanel.module.css       | コンポーネント固有スタイル（必要に応じて）         |
| デザインモック             | Figma またはスクリーンショットベースのデザイン仕様 |
| ChatPanel.test.tsx（更新） | ビジュアルリグレッションテスト追加                 |

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-7D（ChatPanel 統合）が完了していること
- プロジェクトのデザインシステム（カラーパレット、タイポグラフィ、スペーシング）が定義されていること
- Tailwind CSS の設定がプロジェクトレベルで完了していること

### 3.2 依存タスク

| タスクID | タスク名       | ステータス |
| -------- | -------------- | ---------- |
| TASK-7D  | ChatPanel 統合 | 完了       |

### 3.3 必要な知識

- Tailwind CSS（デザイントークン、レスポンシブ、ダークモード）
- CSS アニメーション / トランジション
- WCAG 2.1 AA アクセシビリティガイドライン
- Atomic Design 原則（organisms レベルのコンポーネント設計）

### 3.4 推奨アプローチ

1. デザインモック作成（Figma または手書きスケッチ）
2. Tailwind CSS のデザイントークン定義
3. ヘッダーエリアのスタイリング（ModelSelector + SkillSelector 配置）
4. メッセージエリアのスタイリング（SkillStreamingView 統合表示）
5. 入力エリアのスタイリング（ChatInput slot）
6. レスポンシブブレークポイント対応
7. ダークモード対応（`dark:` プレフィックス）
8. アニメーション・トランジション追加

## 4. 実行手順

### Phase構成

本タスクは中規模であり、デザイン定義 → 実装 → テスト の3段階で実施する。task-specification-creator で詳細な Phase 分解を行うことを推奨する。

### Phase 1-3: 要件分析・設計・設計レビュー

#### 目的

デザイン要件を定義し、具体的なスタイルガイドを作成する。

#### 手順

1. 既存の ChatPanel レイアウトを分析
2. デザインモック（ライトモード / ダークモード）を作成
3. Tailwind CSS デザイントークンを定義
4. レスポンシブブレークポイントを定義
5. 設計レビューを実施

#### 成果物

- デザインモック
- スタイルガイドドキュメント

#### 完了条件

- デザインモックが作成されている
- レスポンシブブレークポイントが定義されている

### Phase 4-5: テスト作成・実装

#### 目的

デザインを実装し、ビジュアルリグレッションテストを作成する。

#### 手順

1. ChatPanel.tsx にスタイルクラスを適用
2. レスポンシブ対応を実装
3. ダークモード対応を実装
4. アニメーション・トランジションを追加
5. ビジュアルリグレッションテストを追加

#### 成果物

- ChatPanel.tsx（更新）
- テストケース追加

#### 完了条件

- 全テスト PASS
- ライトモード / ダークモードの表示確認
- レスポンシブ表示確認

## 7. リスクと対策

| リスク                                   | 影響度 | 発生確率 | 対策                                       |
| ---------------------------------------- | ------ | -------- | ------------------------------------------ |
| デザインシステムが未定義                 | 高     | 中       | 先にデザインシステムを定義するタスクを実施 |
| 既存コンポーネントとのスタイル競合       | 中     | 中       | CSS Modules またはスコープドスタイルで分離 |
| レスポンシブ対応で既存レイアウトが崩れる | 中     | 低       | ブレークポイントごとのテストを実施         |
| ダークモード対応でコントラスト不足       | 低     | 中       | WCAG コントラストチェッカーで検証          |
