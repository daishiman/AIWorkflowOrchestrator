## 概要

post-tool-use フック（ESLint自動修正）がテストファイルのimportパスと入力値を自動変更したが、期待値が更新されず矛盾が発生した。具体的には、テストケース#27の期待値がテストケース#17と矛盾する状態になり、テスト件数が0件として計上される危機が生じた。この問題を防ぐため、フックが変更したテストファイルのdiffを人間がレビューする手順をワークフローに組み込む必要がある。

## 現状

ワークフロー上の問題として、フックによるテストファイルへの変更が人間のレビューを経ずに通過してしまう構造がある。

```
現状のフロー:
1. コードを実装・編集
2. post-tool-use フックが自動実行（ESLint/Prettier）
3. フックがテストファイルを変更（import パス変換・入力値変更）
4. ← この変更は人間がレビューしない ← 問題
5. テストを実行 → 矛盾した期待値でfalse greenの可能性
```

## 期待される修正

フックによるテストファイル変更を明示的にレビューするステップをワークフローへ追加する。

```
改善後のフロー:
1. コードを実装・編集
2. post-tool-use フックが自動実行
3. フックによるテストファイル変更を git diff でレビュー ← 追加
4. テストケースの期待値が整合しているか確認 ← 追加
5. テストを実行
```

具体的な改善案：

- Phase 11 マニュアルテストの手順書に「フック変更のdiff確認」を必須ステップとして追加
- テストファイルに git pre-commit hook で diff サイズの異常を検出する仕組みを追加

## 苦戦箇所記録

ESLintフックがimportパスを変換し、さらに別のフックがテストの入力値を変更したが期待値は変更されなかった。どのフックが何を変えたかを追跡するのが困難で、最終的にgit diffを手動確認して原因を特定した。フックの影響範囲を明示するログ機能があれば早期発見できた可能性がある。
