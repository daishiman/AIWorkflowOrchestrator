## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-WCE-MONACO-001（Monaco Editor選択範囲取得機能）では、エディタからの選択範囲「読み取り」を実装した。chat-edit機能の完全なワークフローを実現するには、LLMが生成したコードをエディタに「書き戻す」機能が必要。

### 1.2 問題点・課題

1. **ワークフロー未完成**: 「選択→LLM処理→書き戻し」の最後のステップが欠落
2. **ユーザー手動操作必要**: LLM生成コードを手動でコピー&ペーストする必要
3. **競合ツールとの機能差**: Cursor、Copilot等は書き戻しが自動化されている

### 1.3 放置した場合の影響

- chat-edit機能の価値が大幅に低下
- ユーザーがLLM結果を手動でペーストする手間が発生
- 競合ツールと比較して体験が劣る

---

## 2. 何を達成するか（What）

### 2.1 目的

LLMが生成したコードをMonaco Editorの指定範囲に自動で書き戻し、シームレスなコード編集体験を実現する。

### 2.2 最終ゴール

- `chat-edit:apply-changes` IPCコマンドでエディタに変更を適用可能
- 選択範囲を新しいコードで置換
- Undo/Redo対応（Monaco Editorの履歴に統合）

### 2.3 スコープ

#### 含むもの

- Main→Renderer方向での書き戻しコマンド実装
- `editor.executeEdits()` APIを使用した変更適用
- Undo/Redo履歴への統合
- ユニットテスト・統合テスト追加

#### 含まないもの

- Diff表示（変更前後の比較UI）
- 書き戻し前の確認ダイアログ
- 複数ファイルへの同時書き戻し

### 2.4 成果物

| 成果物                    | 説明                   |
| ------------------------- | ---------------------- |
| chatEditHandlers.ts修正   | handleApplyChanges実装 |
| editorSelection.ts修正    | applyChanges関数追加   |
| preload/chat-edit API修正 | applyChanges IPC追加   |
| ユニットテスト            | 書き戻しテストケース   |
| 統合テスト                | E2Eでの書き戻し検証    |

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-WCE-MONACO-001（Monaco Editor選択範囲取得）が完了していること
- Monaco Editor `executeEdits` APIの仕様を理解していること

### 3.2 依存タスク

| タスク              | ステータス | 関係     |
| ------------------- | ---------- | -------- |
| TASK-WCE-MONACO-001 | ✅ 完了    | 基盤実装 |

### 3.3 推奨アプローチ

1. `editor.executeEdits()` を使用してテキストを置換
2. 置換範囲は `TextSelection` の座標を使用
3. `source` パラメータで履歴グループを指定しUndo対応
