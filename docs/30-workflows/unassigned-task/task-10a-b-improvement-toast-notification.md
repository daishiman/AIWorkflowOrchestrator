## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

改善適用後に再分析されるが、ユーザーに適用結果サマリーが通知されない。

### 1.2 問題点・課題

適用件数・失敗件数・スキップ件数が即時に把握できない。

### 1.3 放置した場合の影響

改善アクションの成否が不透明になり、UX信頼性が低下する。

## 2. 何を達成するか（What）

### 2.1 目的

改善実行完了時にトーストで結果サマリーを提示する。

### 2.2 最終ゴール

`applyImprovements` / `autoImprove` 完了後に成功・部分失敗が通知される。

### 2.3 スコープ

#### 含むもの

Rendererの通知表示、実行結果の文言整形、テスト。

#### 含まないもの

通知履歴の永続化。

### 2.4 成果物

- トースト表示コンポーネントまたは既存通知統合
- SkillAnalysisViewの通知呼び出し
- テストケース追加

## 3. どのように実行するか（How）

### 3.1 前提条件

`ImprovementResult` から `applied/skipped/errors` が取得できること。

### 3.2 依存タスク

なし。

### 3.3 必要な知識

React通知UI、非同期処理の状態遷移。

### 3.4 推奨アプローチ

通知文言の生成を関数化し、成功/部分失敗を2パターンで扱う。

## 4. 実行手順

### Phase構成

通知UI実装 → 結果連携 → テスト。

### Phase 1: 実装

#### 目的

結果通知の可視化を追加する。

#### 手順

1. 通知表示コンポーネントを配置する。
2. `handleApplySelected` / `handleAutoImprove` 成功時に通知を出す。
3. 失敗件数がある場合は警告トーンで表示する。

#### 成果物

通知UIと連携コード。

#### 完了条件

改善後に必ずサマリー通知が表示される。
