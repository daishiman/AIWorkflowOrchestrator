## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

`fix-creator-handler-duplicate-skill-name-validation` タスクで、
`SkillService.ts` の `toWizardSkillName()` に日本語・大文字・アンダースコアを
kebab-case の小文字英数字へ自動変換する処理が実装された。

例: `"My テスト Skill"` → `"my--skill"` → `"my-skill"`（連続ハイフン圧縮後）

この自動変換はバックエンドで無音で発生するため、ユーザーが「なぜ自分が入力した名前と
異なる名前でスキルが作成されたのか」を事前に把握できない状況になっている。

### 1.2 問題点・課題

- **無音の変換**: 日本語を入力してスキルを作成すると、気づかないうちに名前が変わる
- **ユーザー混乱**: スキル一覧で予想外の名前（例: `new-skill-3`）が現れても原因が不明
- **再入力コスト**: 変換後の名前が気に入らない場合、スキル名変更操作が別途必要
- **透明性の欠如**: 変換ルール（小文字英数字とハイフンのみ）がユーザーに伝わっていない

### 1.3 放置した場合の影響

- ユーザーが意図しない名前のスキルを作成してしまい、使いにくいスキル命名が蓄積する
- サポート問い合わせの増加（「なぜ名前が変わるのか」という質問）
- UX 品質の低下

---

## 2. 何を達成するか（What）

### 2.1 目的

スキル作成ウィザードのスキル名入力フィールドで、ユーザーが入力した名前が
どのように変換されるかをリアルタイムでプレビュー表示し、透明性を高める。

### 2.2 最終ゴール

- ユーザーがスキル名に日本語や大文字を入力すると、入力フィールド下部に
  「実際に使用される名前: `my-skill`」のようなプレビューが表示される
- 変換が不要な場合（既に有効な kebab-case の場合）はプレビューを非表示にする
- ユーザーがプレビューを見てスキル名を調整できる

### 2.3 スコープ

#### 含むもの

- スキル作成ウィザードの名前入力フィールドへのプレビュー表示追加
- フロントエンドでの `toWizardSkillName()` 相当のプレビュー計算
- 変換ありの場合のみプレビューを表示する条件分岐

#### 含まないもの

- `toWizardSkillName()` のロジック変更
- スキル名変換ルールの変更
- スキル名入力フィールド以外の UI 変更
- バックエンド変換ロジックの変更

### 2.4 成果物

- 更新済みスキル作成ウィザードコンポーネント（フロントエンド）
- プレビュー表示のテスト

## 3. どのように実行するか（How）

### 3.1 前提条件

- `fix-creator-handler-duplicate-skill-name-validation` の Bug Fix が main にマージ済み
- スキル作成ウィザードの UI コンポーネントの場所が特定されている

### 3.2 依存タスク

- なし（独立タスク、ただし UT-SKILL-NAME-PATTERN-001 完了後に実施することで
  フロントエンドも shared 定数を参照できる）

### 3.3 必要な知識

- スキル作成ウィザードの React/Next.js コンポーネント構造
- `toWizardSkillName()` の変換ロジック（または shared 定数化後の参照方法）
- フロントエンドでのリアルタイム入力検知（`onChange` ハンドラ）

### 3.4 推奨アプローチ

1. スキル作成ウィザードの名前入力フィールドを特定
2. `onChange` で入力値を変換ロジックに通してプレビュー値を計算
3. 入力値とプレビュー値が異なる場合のみプレビューテキストを表示
4. プレビューテキストの書式例: `"スキル名として使用される名前: my-skill"`

```tsx
// 概念コード
const [inputName, setInputName] = useState("");
const previewName = toWizardSkillName(inputName);
const showPreview = inputName !== previewName && inputName !== "";

return (
  <div>
    <input value={inputName} onChange={(e) => setInputName(e.target.value)} />
    {showPreview && (
      <p className="text-sm text-muted">
        スキル名として使用される名前: <code>{previewName}</code>
      </p>
    )}
  </div>
);
```

## 4. 実行手順

### Phase構成

Phase 1（UI特定）→ Phase 2（プレビュー実装）→ Phase 3（テスト・動作確認）

### Phase 1: UI コンポーネントの特定

#### 目的

スキル名入力フィールドが存在するコンポーネントを特定する。

#### 手順

1. `grep -r "skillName\|skill-name\|スキル名" apps/` でフロントエンドの入力箇所を特定
2. スキル作成ウィザードのコンポーネントファイルを特定
3. 名前入力の `onChange` ハンドラの現状を確認

#### 成果物

対象コンポーネントファイルのパス

#### 完了条件

名前入力フィールドのコンポーネントが特定されている

---

### Phase 2: プレビュー表示実装

#### 目的

入力名とプレビュー名が異なる場合にプレビューを表示する。

#### 手順

1. フロントエンド用の変換関数を `apps/web/src/lib/skillName.ts`（または同等箇所）に追加
   - `UT-SKILL-NAME-PATTERN-001` が完了している場合は `@repo/shared` からインポート
   - 未完了の場合はフロントエンド側に同等ロジックを実装（後で統合）
2. 名前入力フィールドの `onChange` でプレビューを計算
3. プレビューテキストを条件付きで表示
4. Tailwind CSS で視覚的に目立たせる（`text-muted-foreground text-sm`）

#### 成果物

プレビュー表示付き名前入力フィールド

#### 完了条件

日本語入力時にプレビューが表示され、英数字ハイフンのみの入力時はプレビューが消える

---

### Phase 3: テストと動作確認

#### 目的

プレビュー表示の動作をテストで保証する。

#### 手順

1. コンポーネントテストを作成
2. 日本語入力時: プレビューが表示される
3. 有効な kebab-case 入力時: プレビューが表示されない
4. 空文字入力時: プレビューが表示されない
5. 実際のスキル作成フローで手動確認

#### 成果物

コンポーネントテスト

#### 完了条件

全テストがグリーン

## 9. 備考

### 苦戦箇所（発見元タスクより）

`toWizardSkillName()` の変換順序（小文字化→非許容文字変換→連続ハイフン圧縮→端除去）は
フロントエンドでも同一ロジックを再現する必要がある。
`UT-SKILL-NAME-PATTERN-001`（shared 定数化）完了後であれば、
`@repo/shared` から変換関数をインポートできる可能性があるため、
本タスクはその後に実施することを推奨する。

### 補足事項

プレビュー表示は「警告」ではなく「情報提供」として提示すること。
エラーカラー（赤）ではなく、補足情報カラー（グレー/ミュート）を使用する。
