## 目的

sanitizeForRenderer() を IPC ハンドラー内に直接記述するか、共通ユーティリティとして独立ファイルに配置するかを確定する。

---

## 背景

- Phase 5 の sanitize-type-addendum.md で sanitizeForRenderer() の型安全な実装が定義された
- Phase 11 の discovered-issues.md D-1 で、配置先の設計判断が未確定であることが検出された
- 現状は IPC ハンドラー内に直接記述されているが、複数ハンドラーで同様のサニタイズが必要になる場合、共通ユーティリティ化が望ましい

---

## 判断基準

| 選択肢                           | メリット                               | デメリット             |
| -------------------------------- | -------------------------------------- | ---------------------- |
| IPC ハンドラー内に直接記述       | 依存関係が少ない、変更影響範囲が限定的 | 重複コードが発生しうる |
| 共通ユーティリティとして独立配置 | DRY 原則に準拠、テスタビリティ向上     | 抽象化レイヤーが増える |

---

## 実行手順

1. `grep -rn "sanitizeForRenderer\|sanitize.*Renderer" apps/desktop/src/` で現在の使用箇所を確認
2. 使用箇所が2箇所以上の場合: 共通ユーティリティとして `apps/desktop/src/main/utils/sanitize.ts` に配置
3. 使用箇所が1箇所のみの場合: IPC ハンドラー内に直接記述を維持し、2箇所目が発生した時点でリファクタリング
4. 判断結果を contract-matrix.md に記録
