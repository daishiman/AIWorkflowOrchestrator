## 1. なぜこのタスクが必要か（Why）

### 背景

システムプロンプトのDB永続化機能では、ユニットテスト・結合テストを213件実装しました。しかし、実際のUI操作を検証するE2Eテストは未実装です。

### 問題点・課題

| 問題                 | 影響                                       |
| -------------------- | ------------------------------------------ |
| E2Eテスト未実装      | 実際のユーザー操作フローが検証されていない |
| UI統合バグの発見遅延 | ユニットテストでは検出できないバグがある   |
| リグレッションリスク | UI変更時の影響範囲が不明                   |

### 放置した場合の影響

- UI操作で発生するバグが本番環境で発見される
- ユーザー体験の品質低下
- 手動テストの負担増加

---

## 2. 何を達成するか（What）

### 目的

Playwrightによる統合テストを追加し、実際のUI操作フローを自動検証する。

### 最終ゴール

| ゴール                   | 詳細                                |
| ------------------------ | ----------------------------------- |
| CRUD操作のE2Eテスト      | 作成→一覧→編集→削除フローのテスト   |
| プリセット選択テスト     | プリセット選択→チャット適用のテスト |
| オフライン動作テスト     | オフライン時のCRUD操作テスト        |
| エラーハンドリングテスト | バリデーションエラー等のUIテスト    |

### スコープ

**含むもの**:

- テンプレートCRUD操作のE2Eテスト
- プリセット選択フローのE2Eテスト
- オフライン動作確認のE2Eテスト
- エラー状態のUIテスト

**含まないもの**:

- パフォーマンステスト
- 負荷テスト
- セキュリティテスト

### 成果物一覧

| 種別         | 成果物             | 配置先                              |
| ------------ | ------------------ | ----------------------------------- |
| テスト       | E2Eテストスイート  | `e2e/tests/system-prompt/`          |
| 設定         | Playwright設定更新 | `playwright.config.ts`              |
| ドキュメント | テスト実行ガイド   | `docs/testing/e2e-system-prompt.md` |

test.describe("システムプロンプトテンプレートCRUD", () => {
  test("テンプレートを作成できる", async ({ page }) => {
    await page.goto("/settings/system-prompt");

    // 作成ボタンクリック
    await page.click('[data-testid="create-template-button"]');

    // フォーム入力
    await page.fill(
      '[data-testid="template-name-input"]',
      "テストテンプレート",
    );
    await page.fill('[data-testid="template-content-input"]', "テスト内容");

    // 保存
    await page.click('[data-testid="save-template-button"]');

    // 一覧に表示されることを確認
