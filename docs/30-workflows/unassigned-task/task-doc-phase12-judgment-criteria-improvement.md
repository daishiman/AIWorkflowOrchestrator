## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-FIX-6-1-STATE-CENTRALIZATION の Phase 12 実行時に、複数の判断ミスと漏れが発生した。これらの問題は `spec-update-workflow.md` の判断基準が曖昧だったことに起因する。

### 1.2 問題点・課題

| ID  | 問題                               | 根本原因                                                         |
| --- | ---------------------------------- | ---------------------------------------------------------------- |
| P25 | LOGS.md 2ファイル更新漏れ          | 「2ファイル更新」が明示的に強調されていなかった                  |
| P26 | システム仕様書更新遅延             | 「PRマージ後に更新」と誤判断する余地があった                     |
| P27 | topic-map.md再生成トリガー判断ミス | 「セクション追加」のみが対象と誤解（削除・更新も対象）           |
| P28 | スキルフィードバックレポート未作成 | 「改善点なし」の場合のレポート作成義務が不明確だった             |
| -   | Slice統合パターン未記載            | 複合リファクタリングケースが「よくある誤判断パターン」になかった |

### 1.3 放置した場合の影響

- Phase 12 実行時に同様の漏れが繰り返し発生
- ドキュメントと実装の乖離が累積
- 後続タスクで古い仕様書を参照し、設計ミスが発生するリスク

---

## 2. 何を達成するか（What）

### 2.1 目的

Phase 12 の判断基準を明確化し、実行者が迷わずに正確な判断ができるようにする。

### 2.2 最終ゴール

- `spec-update-workflow.md` に全ての判断パターンが網羅されている
- 「よくある誤判断パターン」テーブルが実際のインシデントを反映している
- Phase 12 実行時の漏れがゼロになる

### 2.3 スコープ

#### 含むもの

- `spec-update-workflow.md` の判断基準拡張
- `phase-11-12-guide.md` のチェックリスト強化
- `06-known-pitfalls.md` へのインシデント追加

#### 含まないもの

- スクリプトの新規作成
- 自動検証機能の実装

### 2.4 成果物

| 成果物                                    | 形式     | 配置先                                                  |
| ----------------------------------------- | -------- | ------------------------------------------------------- |
| spec-update-workflow.md 更新              | Markdown | `.claude/skills/task-specification-creator/references/` |
| phase-11-12-guide.md 更新                 | Markdown | `.claude/skills/task-specification-creator/references/` |
