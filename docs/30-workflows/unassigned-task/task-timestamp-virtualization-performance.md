## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-3-2-Cのタイムスタンプ自動更新機能は、100件程度のメッセージでテストされている。
しかし、長時間のスキル実行や大量のストリームメッセージが発生する場合、
1000件以上のメッセージでのパフォーマンス検証が必要。

仮想スクロール（virtualization）との組み合わせは未検証であり、
大量メッセージ時のパフォーマンス特性を把握する必要がある。

### 1.2 問題点・課題

| 問題                     | 詳細                                                     |
| ------------------------ | -------------------------------------------------------- |
| 大量メッセージでの未検証 | 1000件以上のメッセージでの動作が未確認                   |
| 仮想化との相互作用       | 仮想スクロールとContext更新の相互作用が未検証            |
| メモリ使用量             | 長時間稼働時のメモリプロファイルが未計測                 |
| 再レンダリングコスト     | 表示範囲外のMessageTimestampが再レンダリングされる可能性 |

### 1.3 放置した場合の影響

| 影響                 | 程度 | 説明                                     |
| -------------------- | ---- | ---------------------------------------- |
| パフォーマンス劣化   | 中   | 大量メッセージ時にUIがカクつく可能性     |
| メモリリーク         | 低   | 長時間稼働でメモリ使用量が増加する可能性 |
| ユーザー体験への影響 | 中   | スクロールのスムーズさが低下する可能性   |

**結論**: 大量メッセージのユースケースでは影響あり。事前検証が望ましい。

## 2. 何を達成するか（What）

### 2.1 目的

1000件以上のメッセージでのタイムスタンプ自動更新のパフォーマンスを検証し、
仮想スクロールとの統合時に問題がないことを確認する。

### 2.2 最終ゴール

| ゴール                       | 検証方法                                        |
| ---------------------------- | ----------------------------------------------- |
| 1000件メッセージでの動作確認 | パフォーマンステストで60fps維持を確認           |
| メモリ使用量の計測           | Chrome DevToolsのMemoryタブで計測               |
| 仮想化との統合確認           | react-window/react-virtuosoとの組み合わせテスト |
| ベンチマーク結果の文書化     | パフォーマンスレポートの作成                    |

### 2.3 スコープ

#### 含むもの

- パフォーマンステストの実装
- ベンチマーク計測スクリプトの作成
- 仮想スクロールライブラリとの統合テスト
- パフォーマンスレポートの作成
- 問題発見時の改善提案

#### 含まないもの

- 仮想スクロールライブラリの本格導入（別タスク）
- 本番コードの変更（検証のみ）
- E2Eテストの追加

### 2.4 成果物

| 成果物                 | 配置先                                             |
| ---------------------- | -------------------------------------------------- |
| パフォーマンステスト   | `apps/desktop/src/renderer/__tests__/performance/` |
| ベンチマークスクリプト | `scripts/benchmark-timestamp-update.js`            |
| パフォーマンスレポート | `outputs/phase-12/performance-report.md`           |
| 改善提案（問題発見時） | `outputs/phase-12/improvement-proposals.md`        |

## 6. 検証方法

### テストケース

| #   | ケース                    | 計測指標                |
| --- | ------------------------- | ----------------------- |
| 1   | 100件メッセージ、1秒更新  | FPS, CPU使用率, メモリ  |
| 2   | 500件メッセージ、1秒更新  | FPS, CPU使用率, メモリ  |
| 3   | 1000件メッセージ、1秒更新 | FPS, CPU使用率, メモリ  |
| 4   | 5000件メッセージ、1秒更新 | FPS, CPU使用率, メモリ  |
| 5   | 1000件＋仮想スクロール    | FPS, スクロール応答時間 |
| 6   | 5000件＋仮想スクロール    | FPS, スクロール応答時間 |

### 検証手順

1. `pnpm --filter @repo/desktop test:performance` でテスト実行
2. Chrome DevToolsのPerformanceタブで記録
3. Memoryタブでヒープスナップショット取得
4. 結果をパフォーマンスレポートに記録

### 合格基準

| 指標           | 合格基準                     |
| -------------- | ---------------------------- |
| フレームレート | 50fps以上維持                |
| CPU使用率      | 50%未満（アイドル時30%未満） |
| メモリ増加     | 10分で100MB未満の増加        |
| スクロール応答 | 16ms未満（60fps相当）        |
