## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

GraphSearchStrategy実装（CONV-07-04）のPhase 9品質保証レビューにおいて、パフォーマンス改善の推奨事項が検出された。同一クエリの繰り返し実行時、埋め込み生成APIへのリクエストが重複して発生している。

### 1.2 問題点・課題

1. **埋め込みキャッシュの不在**
   - 同一クエリでも毎回EmbeddingProvider APIを呼び出し
   - API呼び出しコスト（時間・費用）が不必要に増加
   - レスポンス時間のばらつき

2. **Phase 1スコープ外事項**
   - 埋め込み生成遅延対策がスコープ外として定義
   - 本番運用時には対策が必要

### 1.3 放置した場合の影響

- 同一クエリの繰り返しで不要なAPI呼び出しが発生
- 検索レスポンス時間の悪化
- API利用コストの増加
- ユーザー体験の低下

---

## 2. 何を達成するか（What）

### 2.1 目的

クエリ埋め込みのキャッシュを実装し、同一クエリに対するAPI呼び出しを削減する。

### 2.2 最終ゴール

1. 同一クエリの2回目以降はキャッシュからの取得
2. キャッシュヒット率のメトリクス取得
3. 設定可能なキャッシュサイズ・TTL

### 2.3 スコープ

#### 含むもの

- インメモリLRUキャッシュの実装
- クエリ埋め込みのキャッシュ
- キャッシュ設定オプション（maxSize, ttlMs）
- キャッシュメトリクス

#### 含まないもの

- Redisなど外部キャッシュストアの統合
- 永続化キャッシュ
- 他の検索戦略への適用（別タスク）

### 2.4 成果物

| 成果物                       | 説明              |
| ---------------------------- | ----------------- |
| embedding-cache.ts           | LRUキャッシュ実装 |
| graph-search-strategy.ts更新 | キャッシュ統合    |
| ユニットテスト追加           | キャッシュテスト  |
| パフォーマンステスト         | 改善効果測定      |

## 3. どのように実行するか（How）

### 3.1 前提条件

- GraphSearchStrategy基本実装が完了していること（CONV-07-04）

### 3.2 依存タスク

| タスクID   | タスク名       | 状態 |
| ---------- | -------------- | ---- |
| CONV-07-04 | グラフ検索戦略 | 完了 |

### 3.3 必要な知識

- LRUキャッシュアルゴリズム
- Map/WeakMap
- TTL管理
- パフォーマンス測定

### 3.4 推奨アプローチ

1. LRU（Least Recently Used）キャッシュアルゴリズム採用
2. クエリ文字列をキーとして埋め込みベクトルをキャッシュ
3. TTL（Time To Live）で古いエントリを自動削除
4. maxSizeで最大エントリ数を制限

#### 目的

1. LRUCache<K, V>ジェネリッククラス作成
2. get/set/delete/clearメソッド実装
3. TTL管理機能実装
4. キャッシュ統計メソッド追加

#### 成果物

#### 完了条件

- [ ] LRUキャッシュクラス実装

### Phase 6: GraphSearchStrategy統合

#### 目的

GraphSearchStrategyにキャッシュを統合する

#### 手順

1. GraphSearchOptionsにcacheオプション追加
2. search()メソッドでキャッシュチェック
3. キャッシュヒット時は埋め込み生成スキップ
4. キャッシュミス時は結果をキャッシュに保存
5. メトリクスにcacheHitRateを追加

#### 成果物

- graph-search-strategy.ts更新版

- [ ] キャッシュ統合完了
