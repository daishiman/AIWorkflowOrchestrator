## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

CONV-07-02（キーワード検索戦略 FTS5/BM25）の実装完了時、統合テストファイル（`keyword-search-strategy.integration.test.ts`）に14件のテストケースが作成されたが、実DBが存在しないため全てスキップ状態となっている。

### 1.2 問題点・課題

- 実際のSQLite FTS5環境での動作検証ができていない
- BM25スコアリングの実測値が未確認
- DB層（chunks-search.ts）との実際の連携が未検証
- 大量データでのパフォーマンス特性が未確認

### 1.3 放置した場合の影響

- 本番環境で予期しない動作が発生する可能性
- FTS5のクエリ構文エラーが検出されない
- パフォーマンス問題が本番稼働まで発見されない

---

## 2. 何を達成するか（What）

### 2.1 目的

KeywordSearchStrategyの統合テストを実DB環境で実行可能にし、FTS5/BM25の動作を検証する。

### 2.2 最終ゴール

- 14件の統合テストが全て成功する状態
- CI/CDパイプラインで自動実行される
- テストデータが再現可能な形で管理される

### 2.3 スコープ

#### 含むもの

- テスト用SQLiteデータベースの作成
- FTS5テーブル・インデックスの作成スクリプト
- テストデータ投入スクリプト
- 統合テストのスキップ解除
- CI/CDへの統合

#### 含まないもの

- 本番データベースの変更
- 他の検索戦略（Semantic/Graph）のテスト環境
- パフォーマンスベンチマーク基盤の構築

### 2.4 成果物

| 成果物                     | パス                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------- |
| テストDB作成スクリプト     | `packages/shared/scripts/setup-test-db.ts`                                                  |
| テストデータ投入スクリプト | `packages/shared/scripts/seed-test-data.ts`                                                 |
| 統合テスト（有効化済み）   | `packages/shared/src/services/search/__tests__/keyword-search-strategy.integration.test.ts` |
| CI設定更新                 | `.github/workflows/ci.yml`                                                                  |

## 3. どのように実行するか（How）

### 3.1 前提条件

- CONV-07-02（キーワード検索戦略）が完了していること
- SQLite FTS5が利用可能な環境であること
- pnpmでの開発環境が構築済みであること

### 3.2 依存タスク

- CONV-07-02: キーワード検索戦略 FTS5/BM25（完了済み）

### 3.3 必要な知識

- SQLite FTS5の基本構文
- Vitestのセットアップ・ティアダウン
- Drizzle ORMの使用方法
- CI/CD（GitHub Actions）の設定

### 3.4 推奨アプローチ

1. `vitest.config.ts`のセットアップフックでテストDBを作成
2. FTS5テーブルをマイグレーションとして管理
3. テストデータはフィクスチャとして管理
4. テスト終了時にDBをクリーンアップ

## 4. 実行手順

### Phase構成

Phase 1〜5の簡易ワークフローで実施。

### Phase 1: 設計

#### 目的

テストDB環境の設計とスクリプト構成を決定する。

#### 手順

1. テストDBのスキーマを確認（既存マイグレーション参照）
2. FTS5テーブル作成クエリを確認
3. テストデータ構造を設計
4. セットアップ・ティアダウンの方針を決定

#### 成果物

- 設計メモ（`outputs/phase-1/design-memo.md`）

#### 完了条件

- [ ] スキーマが確認されている
- [ ] テストデータ構造が決定している

### Phase 2: スクリプト作成

#### 目的

テストDB作成・データ投入スクリプトを作成する。

#### 手順

1. `setup-test-db.ts`を作成
2. FTS5テーブル・インデックス作成クエリを実装
3. `seed-test-data.ts`を作成
4. テストデータ投入ロジックを実装

#### 成果物

- `packages/shared/scripts/setup-test-db.ts`
- `packages/shared/scripts/seed-test-data.ts`

#### 完了条件

- [ ] スクリプトがエラーなく実行できる
- [ ] テストDBが作成される
- [ ] テストデータが投入される

### Phase 3: 統合テスト有効化

#### 目的

スキップされている統合テストを有効化し、実行可能にする。

#### 手順

1. `keyword-search-strategy.integration.test.ts`の`.skip`を削除
2. セットアップフックでテストDB作成を呼び出し
3. ティアダウンフックでクリーンアップ
4. ローカルで全テストを実行

#### 成果物

- 統合テストファイル（更新）

#### 完了条件

- [ ] 14件の統合テストが全て成功
- [ ] テスト間の独立性が保たれている

### Phase 4: CI/CD統合

#### 目的

GitHub ActionsでSQLite FTS5環境を構築し、統合テストを実行する。

#### 手順

1. `.github/workflows/ci.yml`を更新
2. SQLite FTS5のセットアップステップを追加
3. 統合テスト実行ステップを追加
4. PRでCIを実行して確認

#### 成果物

- CI設定ファイル（更新）

#### 完了条件

- [ ] CIで統合テストが成功
- [ ] PR時に自動実行される

### Phase 5: ドキュメント

#### 目的

テスト環境のセットアップ手順をドキュメント化する。

#### 手順

1. READMEにテスト環境セットアップ手順を追記
2. 開発者向けガイドを作成

#### 成果物

- ドキュメント更新

#### 完了条件

- [ ] セットアップ手順が明確
- [ ] 他の開発者が再現可能

## 6. 検証方法

### テストケース

1. ローカル環境で統合テストを実行
2. CI環境で統合テストを実行
3. 新規クローン後のセットアップ確認

### 検証手順

```bash
# 1. テストDB作成
pnpm --filter @repo/shared run setup-test-db

# 2. テストデータ投入
pnpm --filter @repo/shared run seed-test-data

# 3. 統合テスト実行
pnpm --filter @repo/shared test:run keyword-search-strategy.integration

# 4. 全テスト確認
pnpm --filter @repo/shared test:run keyword-search-strategy
```
