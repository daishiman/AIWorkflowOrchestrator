## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-WCE-MONACO-001（Monaco Editor選択範囲取得機能）では、選択範囲を取得しLLMに送信する機能を実装した。しかし、LLMが処理中の選択範囲をユーザーに視覚的にフィードバックする機能は未実装。

### 1.2 問題点・課題

1. **視覚的フィードバック欠如**: どの範囲がLLMに送信されたか確認できない
2. **ユーザー不安**: 選択範囲が正しく認識されたか確認できない
3. **デバッグ困難**: 開発者がテスト時に選択範囲を視覚的に確認できない

### 1.3 放置した場合の影響

- ユーザーが意図した範囲がLLMに送信されたか確認できない
- 誤った範囲を選択した場合に気づきにくい
- ただし、機能自体は正常に動作するため、影響は限定的（優先度: 低）

---

## 2. 何を達成するか（What）

### 2.1 目的

LLMに送信する選択範囲をエディタ上でハイライト表示し、ユーザーに視覚的フィードバックを提供する。

### 2.2 最終ゴール

- LLMリクエスト時に選択範囲が一時的にハイライトされる
- ハイライト色・スタイルがカスタマイズ可能
- LLMレスポンス完了後にハイライトが自動解除

### 2.3 スコープ

#### 含むもの

- Monaco Editor `deltaDecorations` APIを使用したハイライト実装
- ハイライト色の設定（CSS変数またはテーマ連動）
- ハイライトの自動解除ロジック
- ユニットテスト追加

#### 含まないもの

- ハイライト設定UI
- マルチカーソル時の複数ハイライト対応（別タスク）
- アニメーション効果

### 2.4 成果物

| 成果物                     | 説明                         |
| -------------------------- | ---------------------------- |
| editorHighlight.ts新規作成 | ハイライト制御ユーティリティ |
| スタイル定義               | ハイライト用CSS              |
| ユニットテスト             | ハイライト表示・解除テスト   |

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-WCE-MONACO-001（Monaco Editor選択範囲取得）が完了していること
- Monaco Editor `deltaDecorations` APIの仕様を理解していること

### 3.2 依存タスク

| タスク              | ステータス | 関係     |
| ------------------- | ---------- | -------- |
| TASK-WCE-MONACO-001 | ✅ 完了    | 基盤実装 |

### 3.3 推奨アプローチ

1. `editor.deltaDecorations()` を使用してハイライトを追加
2. デコレーションIDを保持し、解除時に使用
3. LLMリクエスト開始時にハイライト追加、完了時に解除
