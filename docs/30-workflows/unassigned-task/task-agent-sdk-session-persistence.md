## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現在のAgentSDKPageでは、セッション履歴がメモリ上にのみ保持されている。
ページリロードやアプリ再起動時にセッション情報が失われるため、
ユーザーは過去の会話履歴を参照できない。

### 1.2 問題点・課題

- ページリロード時にセッション一覧が消失する
- 過去の会話コンテキストを参照できない
- 長期間のAIアシスタント利用において利便性が低い

### 1.3 放置した場合の影響

- ユーザー体験の低下（毎回新規セッションから開始）
- 過去のやり取りを参照したい場合に対応できない
- 競合製品と比較して機能的に劣る

---

## 2. 何を達成するか（What）

### 2.1 目的

セッション履歴をLocalStorageまたはElectronのストレージに永続化し、
アプリ再起動後も過去のセッションを参照・再開できるようにする。

### 2.2 最終ゴール

- アプリ再起動後もセッション一覧が復元される
- 過去のセッションを選択して会話を継続できる
- セッション履歴の明示的な削除が可能

### 2.3 スコープ

#### 含むもの

- セッションメタデータの永続化（ID、作成日時、最終アクセス日時）
- セッション一覧の復元機能
- セッション削除機能
- 永続化容量制限の設定

#### 含まないもの

- 会話メッセージ全体の永続化（サーバーサイド管理の想定）
- クラウド同期機能
- エクスポート/インポート機能

### 2.4 成果物

- セッション永続化ユーティリティ
- 更新されたAgentSDKPageコンポーネント
- ユニットテスト
- 統合テスト

## 3. どのように実行するか（How）

### 3.1 前提条件

- AgentSDKPage実装が完了していること
- Electronのメインプロセスとの通信基盤が整備されていること

### 3.2 依存タスク

- postrelease-sdk-testing ワークフロー完了

### 3.3 必要な知識

- Electron localStorage / electron-store
- React状態管理
- TypeScript

### 3.4 推奨アプローチ

1. electron-storeを使用した永続化層の実装
2. セッション情報のシリアライズ/デシリアライズ
3. アプリ起動時の自動復元
4. 容量制限とLRU削除ポリシー

## 6. 検証方法

### テストケース

1. 新規セッション作成 → アプリ再起動 → セッション復元確認
2. 複数セッション作成 → 全て復元確認
3. セッション削除 → 永続化から除外確認
4. 容量制限到達 → 古いセッション削除確認

### 検証手順

1. pnpm vitest run でユニットテスト実行
2. アプリを起動しセッション作成
3. アプリを再起動しセッション復元確認
