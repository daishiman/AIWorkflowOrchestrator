## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

履歴UIコンポーネントの統合（task-req-history-integration-001, task-req-history-preload-001, task-req-history-ipc-001）が完了した後、実際のアプリケーション環境での動作確認が必要。単体テストで検証できない実環境特有の問題を発見する。

### 1.2 問題点・課題

- 統合後の動作が未検証
- 実環境特有のバグが潜在している可能性
- ユーザー体験（UX）の問題が発見されていない

### 1.3 放置した場合の影響

- 本番環境でのクリティカルバグ発生
- ユーザー体験の低下
- 信頼性の低下

---

## 2. 何を達成するか（What）

### 2.1 目的

実環境での動作を確認し、統合に問題がないことを検証する。

### 2.2 最終ゴール

- すべての機能が正常に動作することを確認
- エラーハンドリングが適切に機能することを確認
- アクセシビリティ要件を満たしていることを確認

### 2.3 スコープ

#### 含むもの

- 機能テスト（履歴表示、詳細表示、ログ表示、復元）
- エラーハンドリングテスト
- アクセシビリティテスト
- レスポンシブテスト

#### 含まないもの

- 自動テストの追加
- パフォーマンステスト

### 2.4 成果物

| 成果物             | 説明                 | 配置先                                           |
| ------------------ | -------------------- | ------------------------------------------------ |
| テスト結果レポート | 手動テスト結果       | docs/30-workflows/history-ui-components/outputs/ |
| 発見課題リスト     | 発見された問題の一覧 | 同上                                             |

## 3. どのように実行するか（How）

### 3.1 前提条件

- task-req-history-integration-001が完了していること
- task-req-history-preload-001が完了していること
- task-req-history-ipc-001が完了していること
- アプリケーションが起動できること

### 3.2 依存タスク

| タスク                           | 説明          | ステータス |
| -------------------------------- | ------------- | ---------- |
| task-req-history-integration-001 | UI統合        | 前提       |
| task-req-history-preload-001     | preload設定   | 前提       |
| task-req-history-ipc-001         | IPCハンドラー | 前提       |

### 3.3 必要な知識・スキル

- アプリケーション操作
- DevToolsの使用
- アクセシビリティ検証ツール

### 3.4 推奨アプローチ

1. 機能テストを優先実施
2. エラーケースを網羅的にテスト
3. アクセシビリティをスクリーンリーダーで確認
4. 結果をドキュメント化

---

## 4. 実行手順

### Phase 1: 環境準備

#### 目的

テスト環境をセットアップする。

#### 手順

1. アプリケーションを起動: `pnpm --filter @repo/desktop dev`
2. DevToolsを開く（Cmd+Option+I）
3. コンソールタブを表示
4. テスト用データを準備

#### 完了条件

- [ ] アプリケーションが起動している
- [ ] DevToolsが開いている
- [ ] 履歴データが存在する（テスト用ファイルを変換済み）

### Phase 2: 機能テスト

#### テストケース一覧

| TC-ID  | 機能             | 操作                       | 期待結果                   |
| ------ | ---------------- | -------------------------- | -------------------------- |
| TC-001 | 履歴一覧表示     | 履歴ページに遷移           | 履歴一覧が表示される       |
| TC-002 | ローディング表示 | 履歴ページに遷移（初回）   | スケルトンが表示される     |
| TC-003 | 空状態表示       | 履歴のないファイルを選択   | 「履歴がありません」が表示 |
| TC-004 | バージョン選択   | 履歴アイテムをクリック     | 詳細パネルが表示される     |
| TC-005 | 詳細表示         | バージョンを選択           | バージョン情報が表示される |
| TC-006 | ログ表示         | 詳細パネルでログを確認     | 変換ログが表示される       |
| TC-007 | ログフィルタ     | ログレベルを変更           | フィルタ結果が表示される   |
| TC-008 | 追加読み込み     | 「もっと見る」をクリック   | 追加データが読み込まれる   |
| TC-009 | 復元ダイアログ   | 復元ボタンをクリック       | 確認ダイアログが表示される |
| TC-010 | 復元実行         | ダイアログで確認をクリック | バージョンが復元される     |
| TC-011 | 復元キャンセル   | ダイアログでキャンセル     | ダイアログが閉じる         |

#### 完了条件

- [ ] すべてのテストケースがPASS
- [ ] コンソールにエラーがない

### Phase 3: エラーハンドリングテスト

#### テストケース一覧

| TC-ID  | 状況               | 操作                 | 期待結果                 |
| ------ | ------------------ | -------------------- | ------------------------ |
| TC-101 | API利用不可        | historyAPIを無効化   | エラーメッセージが表示   |
| TC-102 | ネットワークエラー | メインプロセスを停止 | 再試行ボタンが表示       |
| TC-103 | データなし         | 存在しないIDを指定   | NotFoundエラーが表示     |
| TC-104 | 復元失敗           | 復元中にエラー発生   | ダイアログにエラーが表示 |

#### 完了条件

- [ ] エラー時に適切なメッセージが表示される
- [ ] 再試行ボタンが機能する
- [ ] エラー後も他の機能が動作する

### Phase 4: アクセシビリティテスト

#### テストケース一覧

| TC-ID  | 要件                     | 操作                | 期待結果                     |
| ------ | ------------------------ | ------------------- | ---------------------------- |
| TC-201 | キーボードナビゲーション | Tab/Enter/Escで操作 | すべての機能にアクセス可能   |
| TC-202 | スクリーンリーダー       | VoiceOverで読み上げ | 適切なラベルが読み上げられる |
| TC-203 | フォーカス管理           | ダイアログを開閉    | フォーカスが適切に移動       |
| TC-204 | ARIA属性                 | DevToolsで確認      | role/aria属性が正しい        |

#### 完了条件

- [ ] キーボードのみで全操作が可能
- [ ] スクリーンリーダーで適切に読み上げられる
- [ ] WCAG 2.1 AA準拠
