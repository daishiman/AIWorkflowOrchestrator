## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

UT-VERIFY-DOC-CONSOLIDATION-001 にて `> 区分:` 形式を新たに導入し、`task-workflow-active.md` / `task-workflow-completed.md` / `interfaces-skill-verify-contract.md` の冒頭に付与した。しかし現在 `task-workflow-active.md` の「出力テンプレート」セクションには `> 区分:` フィールドが含まれていないため、今後追加される child companion ドキュメントで `> 区分:` が付与されないリスクがある。

### 1.2 問題点

1. **テンプレート未反映**: 新規ドキュメント作成者が出力テンプレートをそのまま使用すると `> 区分:` が漏れる
2. **一貫性担保の欠如**: `> 区分:` は UT-VERIFY-DOC-CONSOLIDATION-001 でアドホックに付与したが、テンプレートへの統合なしでは後続作業での適用が個人の知識に依存する
3. **インデックス自動検証の障壁**: 将来的に CI で `task-workflow.md` の「区分」列を自動検証する場合（改善提案#3）、各ファイルに `> 区分:` が付与されていることが前提条件となる

### 1.3 放置時の影響

- 新規 child companion を追加する作業者が `> 区分:` を付与しないケースが続発し、UT-VERIFY-DOC-CONSOLIDATION-001 の改善効果が徐々に薄れる
- テンプレートと実ファイルの乖離が定着し、修正コストが増加する

---

## 2. 何を達成するか（What）

### 2.1 目的

`task-workflow-active.md` の「出力テンプレート」セクションに `> 区分:` フィールドを追加し、今後作成される child companion ドキュメントで `> 区分:` の付与を標準化する。

### 2.2 最終ゴール

新規 child companion 作成者がテンプレートを参照するだけで `> 区分:` の付与方法を把握でき、インデックスなしで各ファイルを開いた際の区分判別が自然に維持される状態にする。

### 2.3 スコープ

**対象:**

- `.claude/skills/aiworkflow-requirements/references/task-workflow-active.md`（「出力テンプレート」セクション）

**対象外:**

- 既存ファイルへの `> 区分:` 付与（UT-CHILD-COMPANION-LABELING-001 が担当）
- テンプレートエンジンや自動生成スクリプトの変更

### 2.4 成果物

| #   | 成果物                                                                            | 形式     |
| --- | --------------------------------------------------------------------------------- | -------- |
| 1   | `> 区分:` フィールドが追加された `task-workflow-active.md` テンプレートセクション | Markdown |

## 3. どのように実行するか（How）

### 3.1 前提条件

- `task-workflow-active.md` に「出力テンプレート」セクションが存在すること
- `> 区分:` の形式定義が `task-workflow-active.md` または `task-workflow.md` で確認できること

### 3.2 依存タスク

| タスクID                        | 関係                               | 状態 |
| ------------------------------- | ---------------------------------- | ---- |
| UT-VERIFY-DOC-CONSOLIDATION-001 | `> 区分:` 形式の定義元・導入タスク | 完了 |

### 3.3 推奨アプローチ

1. `task-workflow-active.md` の「出力テンプレート」セクションを Read して現在の構造を把握する
2. H1 タイトルの直後に `> 区分: [正本|履歴記録|契約仕様]（説明）` の形式でフィールドを追加する
3. 区分値の選択ガイドをコメント形式で付記する（`<!-- 正本 / 履歴記録 / 契約仕様 から選択 -->`）

## 4. 実行手順

### Phase 1: 現状確認（目安: 10分）

**目的:** `task-workflow-active.md` の出力テンプレートセクションの現状構造を把握する

**手順:**

1. `task-workflow-active.md` を Read し、「出力テンプレート」セクションの内容を確認する
2. 現在の H1 テンプレート構造と `> 役割:` の記述有無を確認する
3. `> 区分:` 追加箇所と記述形式を確定する

**完了条件:**

- [ ] 「出力テンプレート」セクションの構造を把握済み
- [ ] 追記位置と形式が確定済み

### Phase 2: テンプレート更新（目安: 15分）

**目的:** 出力テンプレートに `> 区分:` フィールドを追加する

**手順:**

1. H1 タイトルの直後（または `> 役割:` の直後）に以下を追記する:
   ```
   > 区分: [正本|履歴記録|契約仕様]（description）
   ```
2. 区分値の選択ガイドをコメントまたは注釈として付記する
3. 既存の `> 役割:` との整合性を確認する

**完了条件:**

- [ ] テンプレートに `> 区分:` フィールドが追加されている
- [ ] 既存の `task-workflow-active.md` / `task-workflow-completed.md` の実ファイルとテンプレートが整合している

### Phase 3: 整合性確認（目安: 5分）

**目的:** テンプレート変更が既存ドキュメントと整合していることを確認する

**手順:**

1. 既に `> 区分:` が付与されたファイル（`task-workflow-active.md`, `task-workflow-completed.md`, `interfaces-skill-verify-contract.md`）と、追加したテンプレートの形式を比較する
2. テンプレート内の `> 区分:` の位置が実ファイルと一致していることを確認する

**完了条件:**

- [ ] テンプレートと実ファイルの `> 区分:` 形式が統一されている

### Phase 12: ドキュメント更新（目安: 5分）

**手順:**

1. このタスク仕様書のステータスを「完了」に更新する
2. 完了日を記録する
3. skill-feedback-report を作成する
