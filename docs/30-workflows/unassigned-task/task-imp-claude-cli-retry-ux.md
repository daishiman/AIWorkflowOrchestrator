## 1. なぜこのタスクが必要か（Why）

### 背景

スキル実行がエラーで終了した場合や、ユーザーがキャンセルした場合の後続操作（再試行、別スキル実行）のUXが未定義である。

### 問題点・課題

- エラー後に何をすべきかユーザーに不明
- 同じスキルを再試行する導線がない
- キャンセル後の状態遷移が不明確

### 放置した場合の影響

- エラー発生時のユーザー離脱
- 再試行のために手動でスキル選択し直す手間
- UX品質の低下

---

## 2. 何を達成するか（What）

### 目的

エラー発生時・キャンセル時に「再試行」「閉じる」などの明確なアクションを提供し、スムーズな後続操作を可能にする。

### 最終ゴール

- エラー時に「再試行」ボタン表示
- キャンセル時に確認メッセージ表示
- 状態に応じた適切なアクション提供

### スコープ

**含むもの**:

- エラー状態表示コンポーネント
- 再試行ボタン
- キャンセル確認メッセージ
- 状態遷移ロジック

**含まないもの**:

- API層の修正（実装済み）
- 自動リトライ機能（将来課題）

### 成果物

| 成果物               | 形式            |
| -------------------- | --------------- |
| ExecutionError.tsx   | React Component |
| RetryButton.tsx      | React Component |
| useRetryExecution.ts | React Hook      |
| ユニットテスト       | TypeScript      |

### 前提条件

- UNASSIGNED-CLI-001（Renderer API実装）完了

### 依存タスク

| タスクID           | 内容             | ステータス |

### 必要な知識・スキル

- React 状態管理
- エラーハンドリングパターン
- UXデザイン原則

### 推奨アプローチ

1. セッション状態（completed/failed/cancelled）に応じた表示切り替え
2. 再試行時は同じパラメータでexecuteScript再呼び出し
3. エラー内容の適切な表示（技術詳細は折りたたみ）

## 4. 実行手順

### Phase 1: エラー状態表示

1. `ExecutionError.tsx`を作成
2. エラーメッセージの表示
3. 技術詳細の折りたたみ表示

### Phase 2: 再試行機能

1. `useRetryExecution.ts`フックを作成
2. 前回のパラメータを保持
3. 再試行ボタンの実装

### Phase 3: キャンセル後UX

1. キャンセル確認メッセージ
2. 「新しいスキルを実行」ボタン
3. 状態のクリア処理
