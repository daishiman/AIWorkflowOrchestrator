## 目的

品質レポートで特定された未カバーのE2Eテストシナリオを追加し、クリティカルパスのテストカバレッジを向上させる。

## 背景

Phase 7の品質レポートで以下のE2Eテストが推奨された:

1. 設定画面のテスト
2. テキストコンバーターのテスト
3. エラーハンドリングのテスト

---

## 実装対象

### 1. 設定画面テスト

| シナリオ       | 検証内容                      |
| -------------- | ----------------------------- |
| APIキー設定    | 入力・保存・暗号化確認        |
| テーマ切り替え | ダークモード/ライトモード切替 |
| 言語設定       | 日本語/英語切替               |
| 設定永続化     | アプリ再起動後の設定維持      |

### 2. テキストコンバーターテスト

| シナリオ             | 検証内容              |
| -------------------- | --------------------- |
| Markdownファイル変換 | .md → チャンク生成    |
| 大容量ファイル       | 1MB以上のファイル処理 |
| バッチ変換           | 複数ファイル同時処理  |

### 3. エラーハンドリングテスト

| シナリオ           | 検証内容              |
| ------------------ | --------------------- |
| ネットワークエラー | オフライン時の動作    |
| API認証エラー      | 無効なAPIキーでの動作 |
| タイムアウト       | 長時間応答がない場合  |

---

## 受け入れ基準

- [ ] 設定画面テストが3本以上作成されている
- [ ] テキストコンバーターテストが2本以上作成されている
- [ ] エラーハンドリングテストが3本以上作成されている
- [ ] 全テストがCI/CDで実行可能
- [ ] Flaky rate 0%
