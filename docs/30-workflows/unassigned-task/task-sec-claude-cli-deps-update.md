## 1. なぜこのタスクが必要か（Why）

### 背景

Phase 9の品質保証で`pnpm audit`を実行した結果、devDependenciesに軽微な脆弱性が検出された。本番影響はないが、定期的な更新が推奨される。

### 問題点・課題

- devDependenciesに既知の脆弱性
- セキュリティスキャンでの警告
- 依存関係の陳腐化

### 放置した場合の影響

- セキュリティ監査での指摘
- 将来の本番影響リスク（devが昇格した場合）
- 技術的負債の蓄積

---

## 2. 何を達成するか（What）

### 目的

devDependenciesの脆弱性を解消し、`pnpm audit`で警告ゼロを達成する。

### 最終ゴール

- `pnpm audit`で脆弱性ゼロ
- 依存関係の最新化
- 互換性の維持

### スコープ

**含むもの**:

- devDependenciesの更新
- 互換性テスト
- package.json/pnpm-lock.yaml更新

**含まないもの**:

- dependencies（本番依存）の大規模更新
- メジャーバージョンアップグレード

### 成果物

| 成果物                 | 形式 |
| ---------------------- | ---- |
| 更新されたpackage.json | JSON |
| 更新されたlockファイル | YAML |

### 前提条件

## 4. 実行手順

### Phase 1: 現状確認

1. `pnpm audit`で脆弱性リストアップ
2. 影響範囲の確認（devのみか確認）
3. 更新可能バージョンの特定

### Phase 2: 更新実行

1. `pnpm update --latest`で更新
2. または個別に`pnpm add -D <package>@latest`

### Phase 3: 検証

1. `pnpm audit`で脆弱性ゼロ確認
2. `pnpm test`で全テスト通過確認
3. `pnpm build`でビルド成功確認
4. `pnpm typecheck`で型チェック通過確認
