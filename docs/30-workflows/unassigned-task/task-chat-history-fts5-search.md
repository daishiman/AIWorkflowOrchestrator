## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現在のチャット履歴検索はSQLiteのLIKE検索を使用している。LIKE検索は小〜中規模データでは問題ないが、大規模データセットでは以下の課題がある：

- インデックスが効かない（前方一致でない場合）
- 部分一致検索が遅い
- 日本語のトークナイズが考慮されていない

SQLite FTS5（Full-Text Search 5）を使用することで、高速かつ高機能な全文検索を実現できる。

### 1.2 問題点・課題

| 問題点           | 詳細                                       |
| ---------------- | ------------------------------------------ |
| 検索速度         | LIKE `%keyword%` はフルスキャンになる      |
| スケーラビリティ | データ増加に伴い検索時間が線形に増加       |
| 検索精度         | 形態素解析なしで日本語検索の精度が低い     |
| 機能制限         | BM25スコアリング、ハイライトなどが使えない |

### 1.3 放置した場合の影響

- 現状のデータ量では問題なし
- 数万件以上のセッション/メッセージを扱う場合に検索遅延が発生
- ユーザー体験の低下（検索レスポンス悪化）

---

## 2. 何を達成するか（What）

### 2.1 目的

SQLite FTS5を使用した高速全文検索をチャット履歴機能に実装し、大規模データでも快適な検索体験を提供する。

### 2.2 最終ゴール

- FTS5仮想テーブルによる高速検索
- BM25スコアリングによる関連度順ソート
- 日本語対応（MeCab or 簡易トークナイザ）
- 既存LIKE検索との互換性維持

### 2.3 スコープ

#### 含むもの

- FTS5仮想テーブルの設計・作成
- Drizzle ORMでのFTS5クエリ実装
- searchメソッドのFTS5対応
- マイグレーションスクリプト
- パフォーマンステスト

#### 含まないもの

- 他の機能（RAG等）へのFTS5適用
- 外部検索エンジン（Elasticsearch等）連携
- リアルタイムインデックス更新の最適化

### 2.4 成果物

| 成果物           | パス                                                |
| ---------------- | --------------------------------------------------- |
| FTS5スキーマ     | `packages/shared/src/db/schema/chat-history-fts.ts` |
| マイグレーション | `packages/shared/src/db/migrations/`                |
| Repository修正   | `DrizzleChatSessionRepository.ts`                   |
| 設計ドキュメント | `outputs/phase-2/fts5-design.md`                    |

## 3. どのように実行するか（How）

### 3.1 前提条件

- Drizzle Repository実装が完了していること（完了済み）
- SQLiteデータベースが使用されていること
- better-sqlite3がFTS5をサポートしていること

### 3.2 依存タスク

- なし（独立して実行可能）

### 3.3 必要な知識

- SQLite FTS5の仕組み（仮想テーブル、トークナイザ）
- Drizzle ORMでのraw SQLクエリ
- BM25スコアリング
- （オプション）日本語形態素解析

### 3.4 推奨アプローチ

1. FTS5仮想テーブル設計
2. Drizzleスキーマ定義（raw SQL使用）
3. マイグレーションスクリプト作成
4. Repository実装（FTS5 MATCH構文）
5. パフォーマンス比較テスト
