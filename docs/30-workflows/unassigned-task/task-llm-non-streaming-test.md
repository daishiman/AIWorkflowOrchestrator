## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

LLMストリーミングレスポンス機能（UT-LLM-STREAM-001）の実装・テスト時に、非ストリーミングの`chat()`メソッドおよび`llm:send-chat` IPCチャンネルのテストカバレッジが不足していることが判明した。

ストリーミング機能（`streamChat()`、`llm:stream-chat`）は129件のテストで十分にカバーされているが、従来の一括レスポンス方式（非ストリーミング）のテストは未整備である。

### 1.2 問題点・課題

| 問題点          | 詳細                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| カバレッジ不足  | `chat()`メソッドのLine/Branch/Functionカバレッジが低い                     |
| 回帰リスク      | ストリーミング実装時の変更が非ストリーミングに影響する可能性               |
| API互換性未検証 | 4プロバイダー（OpenAI, Anthropic, Google, xAI）の非ストリーミングAPI未検証 |

### 1.3 放置した場合の影響

| 影響                                 | 深刻度 |
| ------------------------------------ | ------ |
| 非ストリーミング機能の不具合見落とし | 中     |
| プロバイダー切り替え時のエラー未検出 | 中     |
| カバレッジ基準（Line 80%）未達       | 低     |

---

## 2. 何を達成するか（What）

### 2.1 目的

LLMアダプターの非ストリーミング`chat()`メソッドおよび関連IPCハンドラーのテストを追加し、機能の信頼性を向上させる。

### 2.2 最終ゴール

| ゴール                                    | 基準                      |
| ----------------------------------------- | ------------------------- |
| `chat()`メソッドのテストカバレッジ        | Branch 60%以上            |
| 4プロバイダーの非ストリーミングAPI検証    | 各プロバイダー5テスト以上 |
| `llm:send-chat` IPCハンドラーのテスト追加 | 正常系・異常系各3テスト   |
| 全テストPASS                              | 新規テスト全件成功        |

### 2.3 スコープ

#### 含むもの

- `BaseLLMAdapter.chat()` メソッドのユニットテスト
- `OpenAIAdapter.chat()` のプロバイダー固有テスト
- `AnthropicAdapter.chat()` のプロバイダー固有テスト
- `GoogleAdapter.chat()` のプロバイダー固有テスト
- `xAIAdapter.chat()` のプロバイダー固有テスト
- `llm:send-chat` IPCハンドラーのテスト
- エラーハンドリングテスト（API_KEY_INVALID、RATE_LIMIT等）

#### 含まないもの

- ストリーミング関連テスト（既存）
- UIコンポーネントテスト（既存）
- RAG機能テスト（別機能）
- 新規プロバイダー追加

### 2.4 成果物

| 成果物               | 配置先                                                      |
| -------------------- | ----------------------------------------------------------- |
| chat()メソッドテスト | `apps/desktop/src/main/adapters/llm/__tests__/chat.test.ts` |
| IPCハンドラーテスト  | `apps/desktop/src/main/handlers/__tests__/llm-chat.test.ts` |
| テスト結果レポート   | `outputs/phase-11/manual-test-result.md`（更新）            |
| カバレッジレポート   | `coverage/lcov-report/`                                     |

## 4. 実行手順

### Phase構成

| Phase | 名称       | 目的                         |
| ----- | ---------- | ---------------------------- |
| 1     | テスト設計 | テストケース設計・モック設計 |
| 2     | テスト実装 | テストコード作成             |
| 3     | 検証・調整 | カバレッジ確認・テスト調整   |

### Phase 1: テスト設計

#### 目的

非ストリーミングchat()メソッドのテストケースを設計する。

#### 手順

1. 既存の`streaming.test.ts`を分析し、テストパターンを把握
2. `chat()`メソッドの入出力仕様を`interfaces-llm.md`から確認
3. テストケース一覧を作成（正常系・異常系・境界値）
4. モック戦略を決定（APIレスポンスのモック方法）

#### 成果物

- テストケース設計書（Markdown）

#### 完了条件

- [ ] 正常系テストケースが5件以上定義されている
- [ ] 異常系テストケースが5件以上定義されている
- [ ] 4プロバイダー各々のテストケースが定義されている

### Phase 2: テスト実装

#### 目的

設計に基づきテストコードを実装する。

#### 手順

1. `chat.test.ts` ファイルを作成
2. BaseLLMAdapter.chat() のテストを実装
3. 各プロバイダーアダプターのテストを実装
4. IPCハンドラー `llm:send-chat` のテストを実装
5. 全テストがPASSすることを確認

#### 成果物

- `apps/desktop/src/main/adapters/llm/__tests__/chat.test.ts`
- `apps/desktop/src/main/handlers/__tests__/llm-chat.test.ts`

#### 完了条件

- [ ] 新規テストファイルが作成されている
- [ ] 全テストがPASSしている
- [ ] ESLint/TypeCheckエラーがない

### Phase 3: 検証・調整

#### 目的

カバレッジ目標達成とテスト品質の確認。

#### 手順

1. カバレッジレポートを生成
2. Branch/Line/Functionカバレッジを確認
3. 不足箇所のテストを追加
4. 最終的な全テスト実行

#### 成果物

- カバレッジレポート
- 更新された手動テスト結果

#### 完了条件

- [ ] `chat()`メソッドのBranchカバレッジが60%以上
- [ ] 全テストがPASS
