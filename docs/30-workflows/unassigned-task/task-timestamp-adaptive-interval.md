## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-3-2-Cで実装されたタイムスタンプ自動更新機能では、固定の更新間隔（1秒）を使用している。
現在は`calculateMinUpdateInterval`関数で最小更新間隔を計算できるが、実際にはTimestampProviderに渡す
`updateInterval`プロパティを動的に変更する仕組みが実装されていない。

### 1.2 問題点・課題

| 問題                             | 詳細                                                       |
| -------------------------------- | ---------------------------------------------------------- |
| 固定間隔による非効率             | 全メッセージが1時間以上前でも1秒ごとに更新                 |
| CPU使用率の無駄                  | 「X時間前」表示のメッセージに対して1秒更新は過剰           |
| calculateMinUpdateInterval未活用 | 関数は実装済みだが、Providerへの動的フィードバックが未実装 |

### 1.3 放置した場合の影響

| 影響                 | 程度 | 説明                                   |
| -------------------- | ---- | -------------------------------------- |
| パフォーマンス       | 低   | 不要な再レンダリングによるCPU使用      |
| バッテリー消費       | 低   | モバイル/ラップトップでの電力消費増    |
| ユーザー体験への影響 | なし | 表示は正確であり、ユーザーには影響なし |

**結論**: 優先度は低いが、長時間稼働するアプリケーションでは改善価値あり。

---

## 2. 何を達成するか（What）

### 2.1 目的

全メッセージのタイムスタンプを分析し、表示に必要な最小更新間隔を動的に計算して、
TimestampProviderの更新間隔を自動調整する。

### 2.2 最終ゴール

| ゴール                           | 検証方法                                           |
| -------------------------------- | -------------------------------------------------- |
| 動的更新間隔の自動調整           | 全メッセージが1時間以上前なら1時間間隔で更新       |
| calculateMinUpdateIntervalの活用 | 既存関数を使用して最小間隔を計算                   |
| パフォーマンス改善               | 不要な再レンダリング回数の削減（DevToolsで検証可） |

### 2.3 スコープ

#### 含むもの

- TimestampProviderへの動的updateInterval適用
- メッセージタイムスタンプの監視ロジック
- 新しいメッセージ追加時の間隔再計算
- 単体テスト

#### 含まないもの

- UIの変更
- 新規コンポーネントの追加
- IPC通信の変更

### 2.4 成果物

| 成果物                | 配置先                                          |
| --------------------- | ----------------------------------------------- |
| TimestampProvider更新 | `apps/desktop/src/renderer/contexts/`           |
| 単体テスト更新        | `apps/desktop/src/renderer/contexts/__tests__/` |
| 実装ガイド            | `outputs/phase-12/implementation-guide.md`      |

## 6. 検証方法

### テストケース

| #   | ケース                        | 期待結果                      |
| --- | ----------------------------- | ----------------------------- |
| 1   | 全メッセージが1分未満         | updateInterval = 1000ms       |
| 2   | 全メッセージが1分〜1時間      | updateInterval = 60000ms      |
| 3   | 全メッセージが1時間以上       | updateInterval = 3600000ms    |
| 4   | 新しいメッセージ（1秒前）追加 | updateInterval = 1000msに変更 |

### 検証手順

1. Vitestで単体テスト実行
2. React DevToolsでProvider再レンダリング回数を確認
3. 手動テストで1時間経過後の更新間隔変化を確認
