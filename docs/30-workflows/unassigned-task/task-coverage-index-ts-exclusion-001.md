## 1. なぜこのタスクが必要か（Why）

### 背景

TASK-FIX-CONVERSATION-IPC-HANDLER-REGISTRATION の Phase 7（カバレッジ確認）で、`apps/desktop/vitest.config.ts` L111 の `coveragePathIgnorePatterns` に `**/index.ts` が含まれていることが判明した。この除外パターンはバレルエクスポート専用の `index.ts`（`export * from "./foo"` のみ）を想定しているが、`apps/desktop/src/main/ipc/index.ts` は `registerAllIpcHandlers()` / `unregisterAllIpcHandlers()` 等の実装ロジックを含むため、カバレッジ計測対象から除外されてしまう。

### 問題点・課題

- `**/index.ts` がバレルエクスポート以外の index.ts も除外し、実装ロジックを含む `ipc/index.ts` のカバレッジが計測されない
- Section 13 追加分のカバレッジを直接確認できず、間接的な確認（個別テストの PASS 数）に頼る必要がある
- 除外パターンの粒度が粗く、将来的に実装ロジックを含む index.ts が増えた場合にも同様の問題が発生する

### 放置した場合の影響

| 影響領域       | 影響                                                   |
| -------------- | ------------------------------------------------------ |
| カバレッジ精度 | 実装ロジックを含む index.ts のテスト漏れを検出できない |
| 品質保証       | カバレッジレポートが実態と乖離し、信頼性が低下         |
| CI/CD          | カバレッジゲートが不正確な数値で判定される             |

## 2. 何を達成するか（What）

### 目的

`coveragePathIgnorePatterns` の除外パターンを精緻化し、バレルエクスポート専用の `index.ts` のみを除外、実装ロジックを含む `index.ts` はカバレッジ計測対象に含める。

### 最終ゴール

- `apps/desktop/src/main/ipc/index.ts` が v8 カバレッジ計測対象に含まれる
- 既存のバレルエクスポート `index.ts` は引き続き除外される
- 全テストが PASS する

### スコープ

**含むもの**:

- `coveragePathIgnorePatterns` の除外パターン精緻化
- カバレッジレポートでの計測対象確認

**含まないもの**:

- `ipc/index.ts` のファイルリネーム・分割（別タスクで検討）
- カバレッジ閾値の変更

### 成果物

| 種別 | 成果物                              | 配置先                          |
| ---- | ----------------------------------- | ------------------------------- |
| 設定 | `coveragePathIgnorePatterns` 精緻化 | `apps/desktop/vitest.config.ts` |

## 3. どのように実行するか（How）

### 前提条件

なし（独立して実行可能）

### 推奨アプローチ

#### 改善案

| 案  | 方法                                                      | メリット                 | デメリット                       |
| --- | --------------------------------------------------------- | ------------------------ | -------------------------------- |
| A   | `**/index.ts` を除外から削除、バレルファイルを個別列挙    | 最も正確                 | 個別列挙の保守コスト             |
| B   | 否定パターン `!apps/desktop/src/main/ipc/index.ts` で復帰 | 変更が小さい             | 否定パターンのサポート確認が必要 |
| C   | `ipc/index.ts` を `ipc/register.ts` にリネーム            | 除外パターンに該当しない | import パスの変更が広範          |

**推奨: 案 A** — `**/index.ts` を除外パターンから削除し、バレルエクスポート専用の index.ts を個別列挙する方式が最も正確で安全。

## 4. 実行手順

### 概要ステップ

1. `apps/desktop/vitest.config.ts` の `coveragePathIgnorePatterns` を確認
2. `**/index.ts` パターンで除外されているファイルの一覧を取得
3. バレルエクスポート専用の index.ts と実装ロジックを含む index.ts を分類
4. 除外パターンを精緻化（案 A: バレルファイルを個別列挙）
5. カバレッジレポートで `ipc/index.ts` が計測対象に含まれることを確認

### Phase 構成

| Phase | 名称                           | 内容                                        |
| ----- | ------------------------------ | ------------------------------------------- |
| 1-3   | 要件定義・設計・レビュー       | 除外対象の分類、パターン設計                |
| 4     | テスト作成                     | カバレッジ計測対象の確認テスト              |
| 5     | 実装                           | `coveragePathIgnorePatterns` の精緻化       |
| 6-7   | テスト拡充・カバレッジ         | ipc/index.ts が計測対象に含まれることの確認 |
| 8-10  | リファクタリング〜最終レビュー | 品質検証                                    |
| 11-13 | 手動テスト〜完了               | 文書更新・PR                                |
