## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

CONV-08-02（Leidenコミュニティ検出）とCONV-08-03（コミュニティ要約生成）により、Knowledge Graph上でコミュニティの検出・要約が可能になった。しかし、これらのコミュニティ構造をユーザーが視覚的に確認・探索する手段がない。

### 1.2 問題点・課題

1. **不可視性**: コミュニティ構造がデータベースにのみ存在し、ユーザーが確認できない
2. **理解困難**: 階層的なコミュニティ関係（親子関係）が把握しづらい
3. **活用制限**: コミュニティ要約を直接閲覧・検索できない

### 1.3 放置した場合の影響

- ユーザーがKnowledge Graphの構造を理解できない
- コミュニティ検出・要約機能の価値が伝わらない
- デバッグ・品質確認が困難

---

## 2. 何を達成するか（What）

### 2.1 目的

コミュニティの階層構造をグラフUIで可視化し、ユーザーが直感的に構造を理解・探索できるようにする。

### 2.2 最終ゴール

1. コミュニティ構造がグラフまたはツリー形式で表示される
2. コミュニティをクリックすると要約・メンバーエンティティが表示される
3. 階層レベルごとにフィルタリング・ズームができる
4. コミュニティの検索が可能

### 2.3 スコープ

#### 含むもの

- コミュニティ可視化コンポーネント（React）
- 階層構造のツリー/グラフ表示
- コミュニティ詳細パネル（要約・メンバー表示）
- レベルフィルタリング
- コミュニティ検索（キーワード）

#### 含まないもの

- コミュニティ検出の再実行UI
- コミュニティ要約の手動編集
- リアルタイム更新表示
- エンティティ単体のグラフ表示（既存機能）

### 2.4 成果物

| 成果物                        | 説明                                   |
| ----------------------------- | -------------------------------------- |
| CommunityGraph コンポーネント | 可視化UIの主要コンポーネント           |
| CommunityDetail パネル        | 要約・メンバー表示                     |
| CommunityFilter コントロール  | レベルフィルタリング                   |
| ユニットテスト                | コンポーネントテスト（カバレッジ80%+） |
| 統合テスト                    | E2Eフロー検証                          |

## 3. どのように実行するか（How）

### 3.1 前提条件

- CONV-08-02（Leidenコミュニティ検出）が完了していること
- CONV-08-03（コミュニティ要約生成）が完了していること
- コミュニティデータがデータベースに存在すること

### 3.2 依存タスク

| タスクID   | タスク名               | 状態 |
| ---------- | ---------------------- | ---- |
| CONV-08-02 | Leidenコミュニティ検出 | 完了 |
| CONV-08-03 | コミュニティ要約生成   | 完了 |

### 3.3 必要な知識

- React / TypeScript
- グラフ可視化ライブラリ（D3.js / vis.js / react-flow 等）
- Tailwind CSS
- Electron IPC（desktop版の場合）

### 3.4 推奨アプローチ

1. **ライブラリ選定**: react-flow または vis.js を推奨（既存プロジェクトとの整合性を確認）
2. **段階的実装**: ツリー表示 → 詳細パネル → フィルタリング → 検索の順
3. **TDD**: コンポーネントテストを先に書いてから実装
4. **アクセシビリティ**: キーボードナビゲーション対応
