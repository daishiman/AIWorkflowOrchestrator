## 目的

SDK統合テストの結果と知見をドキュメントとして整理し、将来の参照用として残す。

## 背景

Post-release SDK統合テストを通じて得られた知見、テスト結果、発見したバグ、パフォーマンス特性などを文書化する。これにより、将来のSDKアップデート時のテストや、類似プロジェクトでの参照資料として活用できる。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: テスト結果サマリー作成

**目的**: 全テスト結果を要約したサマリードキュメントを作成する。

**実行手順**:

1. 全Phaseの成果物を収集
2. テスト結果を集約
3. 成功・失敗の統計を計算
4. サマリードキュメントを作成

**含めるべき内容**:

| セクション     | 内容                        |
| -------------- | --------------------------- |
| 概要           | テストの目的と範囲          |
| テスト環境     | 使用したSDKバージョン、環境 |
| テスト結果統計 | 成功率、カバレッジ          |
| パフォーマンス | 測定結果と目標との比較      |
| 発見した問題   | バグ、改善点の一覧          |
| 結論           | テスト結果の総合評価        |

**期待される成果物**:

- テスト結果サマリー

---

### タスク2: SDK統合ガイド更新

**目的**: 実SDK統合の知見を反映してガイドを更新する。

**実行手順**:

1. 既存のSDK統合ガイドを確認
2. 新たに得られた知見を整理
3. ベストプラクティスを追記
4. トラブルシューティング情報を追加
5. サンプルコードを更新

**更新対象**:

| ドキュメント       | 更新内容                     |
| ------------------ | ---------------------------- |
| 実装ガイド         | 実SDK呼び出しパターン        |
| 認証ガイド         | 認証フローの詳細             |
| エラーハンドリング | 実際に発生したエラーと対処法 |
| パフォーマンス     | 最適化のベストプラクティス   |

**期待される成果物**:

- 更新されたSDK統合ガイド

---

### タスク3: テストケースドキュメント更新

**目的**: 作成したテストケースの文書を整理・更新する。

**実行手順**:

1. 作成したテストファイルを確認
2. テストケース一覧を更新
3. 各テストケースの説明を追記
4. 実行方法を文書化
5. メンテナンスガイドを作成

**含めるべき内容**:

| セクション         | 内容                       |
| ------------------ | -------------------------- |
| テストファイル一覧 | 各ファイルの目的と場所     |
| テストケース詳細   | 各テストの説明と期待結果   |
| 実行方法           | テストの実行コマンド       |
| 環境要件           | テスト実行に必要な前提条件 |
| メンテナンス       | テスト更新時の注意点       |

**期待される成果物**:

- テストケースドキュメント

---

### タスク4: パフォーマンスベースライン文書化

**目的**: 測定したパフォーマンス値をベースラインとして文書化する。

**実行手順**:

1. 全パフォーマンス測定結果を収集
2. ベースライン値を決定
3. 測定環境を記録
4. 将来の比較用に整理

**ベースライン項目**:

| 指標               | ベースライン値 | 測定環境       |
| ------------------ | -------------- | -------------- |
| 初回応答時間       | XX ms          | SDK v1.0.0     |
| メッセージ間遅延   | XX ms          | MacBook Pro M1 |
| セッション作成時間 | XX ms          | Node.js v20    |
| メモリ増加量/時間  | XX MB/hour     | Electron v28   |

**期待される成果物**:

- パフォーマンスベースライン文書

---

### タスク5: トラブルシューティングガイド作成

**目的**: テスト中に発生した問題とその解決方法を文書化する。

**実行手順**:

1. テスト中に発生した問題を収集
2. 問題の症状を整理
3. 原因と解決方法を記録
4. 予防策を記載

**含めるべき内容**:

| セクション   | 内容                               |
| ------------ | ---------------------------------- |
| よくある問題 | 発生頻度の高い問題                 |
| 症状         | 問題の見分け方                     |
| 原因         | 問題が発生する理由                 |
| 解決方法     | 具体的な対処手順                   |
| 予防策       | 問題を防ぐためのベストプラクティス |

**期待される成果物**:

- トラブルシューティングガイド

---

### タスク6: 未タスク検出【必須】

**目的**: 技術的負債を可視化し、継続的改善のための未タスクを検出する。

**実行手順**:

1. Phase成果物からMINOR判定の指摘事項を抽出
   ```bash
   grep -r "MINOR\|将来対応\|TODO\|FIXME" outputs/
   ```
2. コードベースのTODO/FIXMEを検出
   ```bash
   grep -rn "TODO\|FIXME\|HACK\|XXX" apps/desktop/src/ packages/
   ```
3. 検出結果を分類・整理
4. 未タスク指示書を作成（該当する場合）

**検出ソース**:

| ソース                 | 確認項目                      | Grepパターン例                             |
| ---------------------- | ----------------------------- | ------------------------------------------ |
| Phase 3レビュー結果    | MINOR判定の指摘事項           | `outputs/phase-3/`                         |
| Phase 9レビュー結果    | MINOR判定の指摘事項           | `outputs/phase-9/`                         |
| Phase 11手動テスト結果 | スコープ外の発見事項          | `outputs/phase-11/`                        |
| 各Phase成果物          | 「将来対応」「TODO」「FIXME」 | `grep -r "TODO\|FIXME\|将来対応" outputs/` |
| コードベース           | TODO/FIXME/HACK/XXXコメント   | `grep -rn "TODO\|FIXME\|HACK\|XXX" apps/`  |

**期待される成果物**:

- 未タスク検出レポート
- 未タスク指示書（該当する場合は `docs/30-workflows/unassigned-task/` に配置）

| `claude-code-agents-spec.md` | エージェント動作の仕様変更があった場合 |

## サブタスク管理

2. テスト結果サマリー作成
3. SDK統合ガイド更新
4. テストケースドキュメント更新
5. パフォーマンスベースライン文書化
6. トラブルシューティングガイド作成
7. 未タスク検出
8. システム仕様更新（aiworkflow-requirements）
9. 成果物の配置
10. 完了条件の検証

**重要**: 各サブタスクは実行完了後すぐにcompletedに更新すること。
