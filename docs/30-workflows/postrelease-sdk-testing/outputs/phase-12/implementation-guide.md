# Part 1: 概念的な説明（中学生でもわかる版）

## 1. Agent SDKって何？

### 1.1 身近な例で考えてみよう

**LINEのチャット画面を想像してみてください。**

```
┌─────────────────────────────────┐
│ 友達との会話                     │
│                                 │
│ あなた: 「今日の宿題教えて」      │
│                                 │
│ 友達: 「数学のP.42だよ」          │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ メッセージを入力...    [送信]│ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

Agent SDK（エージェント・エスディーケー）は、この「友達」の代わりに**AI（人工知能）と会話できる仕組み**です。

| 普通のチャット | Agent SDK                  |
| -------------- | -------------------------- |
| 人間が返事する | AIが自動で返事する         |
| 既読がつく     | 「考え中...」と表示        |
| 通知が来る     | リアルタイムで文字が流れる |

### 1.2 なぜこのテストが必要なの？

**学校の試験勉強に例えてみましょう。**

```
テスト（試験） = 正しく動くか確認すること

❌ テストしないと...
  「本番で初めて問題に気づく」
  →（アプリを使うお客さんが困る）

⭕ テストすると...
  「事前に問題を見つけて直せる」
  →（お客さんが安心して使える）
```

| やりたいこと                 | 身近な例                               |
| ---------------------------- | -------------------------------------- |
| 品質保証（ひんしつほしょう） | テスト前に教科書を見直す               |
| バグ発見（バグはっけん）     | 模擬試験で苦手を見つける               |
| リグレッション防止           | 新しい公式を覚えても古い公式を忘れない |

## 2. どうやって動くの？

### 2.1 郵便局に例えてみよう

```
あなた（画面） ──手紙を出す──→ 郵便局（中継点） ──配達──→ AI（返事を書く人）
     ↑                                                        │
     └────────────────返事が届く────────────────────────────────┘

【専門用語で言うと】
あなた = Renderer Process（レンダラー・プロセス）
郵便局 = IPC通信（アイピーシー通信）
AI = Main Process + Claude API
```

### 2.2 全体の流れ

```
ステップ1: メッセージを入力
    ↓
ステップ2: 送信ボタンを押す
    ↓
ステップ3: AIが考え始める（「考え中...」表示）
    ↓
ステップ4: 返事が1文字ずつ流れてくる（ストリーミング）
    ↓
ステップ5: 完了！
```

## 2. 型定義詳細（設計理由付き）

### 2.1 AgentSDKAPI Interface

**重要**: 各メソッドに「なぜこの設計にしたか」をコメントで説明する。

```typescript
interface AgentSDKAPI {
  // ===== ステータス取得 =====
  getStatus: () => Promise<AgentSDKStatus>;
  // なぜPromise: 非同期でMain Processと通信するため
  // なぜこのメソッド: SDK初期化状態を画面に表示するため

  // ===== セッション管理 =====
  createSession: () => Promise<AgentSDKCreateSessionResponse>;
  // なぜセッション: 会話の文脈を保持するため
  // なぜ戻り値にsessionId: 後続のクエリで会話を継続するため

  resumeSession: (request: AgentSDKResumeSessionRequest) => Promise<void>;
  // なぜresume: ページ再読み込み後も会話を継続するため

  destroySession: (request: AgentSDKDestroySessionRequest) => Promise<void>;
  // なぜdestroy: メモリリークを防ぐため、不要なセッションを明示的に破棄

  // ===== クエリ実行 =====
  query: (request: AgentSDKQueryRequest) => Promise<void>;
  // なぜvoid戻り値: 応答はonMessageコールバックで受け取るため（ストリーミング対応）

  abort: () => void;
  // なぜPromiseでない: 即座に中断を要求するため、待機不要

  // ===== イベント購読 =====
  onMessage: (callback: (message: AgentSDKMessage) => void) => () => void;
  // なぜコールバック: ストリーミングで逐次データを受け取るため
  // なぜ戻り値が関数: 購読解除（cleanup）を可能にするため

  // ===== オプション設定 =====
  setOption: (options: { timeout?: number }) => void;
  getOption: (key: string) => number | undefined;
  setSessionId: (sessionId: string) => void;
}
```

### 2.2 設計判断の根拠

| 設計判断           | 選択肢                      | 採用理由                                             |
| ------------------ | --------------------------- | ---------------------------------------------------- |
| セッション管理     | クライアント側 / サーバー側 | クライアント側を採用。オフライン対応とレイテンシ削減 |
| ストリーミング方式 | WebSocket / IPC             | IPCを採用。Electron環境では安定性が高い              |
| 中断機能           | AbortController / カスタム  | カスタムを採用。IPC経由で直接制御可能                |
| 権限確認           | 自動許可 / 都度確認         | 都度確認を採用。セキュリティ重視                     |

## 3. IPC チャンネル定義

### 3.1 チャンネル一覧

| チャンネル名           | 方向            | 説明               | なぜ必要か                     |
| ---------------------- | --------------- | ------------------ | ------------------------------ |
| `agent:createSession`  | Renderer → Main | セッション作成     | 会話開始時に一意のIDを発行     |
| `agent:resumeSession`  | Renderer → Main | セッション再開     | 既存の会話を継続するため       |
| `agent:destroySession` | Renderer → Main | セッション破棄     | リソース解放とメモリリーク防止 |
| `agent:query`          | Renderer → Main | クエリ実行         | AIへのメッセージ送信           |
| `agent:abort`          | Renderer → Main | クエリ中断         | ユーザーの意思で即座に停止     |
| `agent:message`        | Main → Renderer | ストリーミング応答 | リアルタイムで返事を表示       |

### 3.2 メッセージタイプ

```typescript
type AgentSDKMessageType =
  | "text" // 通常のテキスト応答
  | "tool_use" // ツール使用の通知
  | "tool_result" // ツール実行結果
  | "error" // エラー発生
  | "end"; // ストリーミング完了
```

## 6. 使用上の注意

### 6.1 セッション管理の注意点

```typescript
// ❌ 使用禁止: セッションを破棄せずに放置
const session = await agentSDKAPI.createSession();
// ... 使用後、destroySessionを呼ばない

// ⭕ 正しい使い方: 必ずクリーンアップする
const session = await agentSDKAPI.createSession();
try {
  await agentSDKAPI.query({ prompt: "Hello" });
} finally {
  await agentSDKAPI.destroySession({ sessionId: session.sessionId });
}
```

### 6.2 ストリーミングの注意点

```typescript
// ❌ 使用禁止: 購読解除を忘れる
agentSDKAPI.onMessage((msg) => {
  console.log(msg);
});

// ⭕ 正しい使い方: useEffectでクリーンアップ
useEffect(() => {
  const unsubscribe = agentSDKAPI.onMessage((msg) => {
    setMessages((prev) => [...prev, msg]);
  });
  return () => unsubscribe(); // クリーンアップ
}, []);
```

## 8. 用語集

このセクションでは、本実装で使用した技術用語を説明する。

### 基本用語

| 用語      | 読み方                       | 説明                                                                                                     |
| --------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| Agent SDK | エージェント・エスディーケー | AIエージェント（Claude）と通信するためのソフトウェア開発キット。開発者がAI機能を簡単に組み込めるツール集 |
| API       | エーピーアイ                 | Application Programming Interfaceの略。異なるプログラム同士が会話するための「約束事」                    |
| SDK       | エスディーケー               | Software Development Kitの略。開発に必要なツールがまとまったセット                                       |

### 画面・UI関連

| 用語             | 読み方                 | 説明                                                                                      |
| ---------------- | ---------------------- | ----------------------------------------------------------------------------------------- |
| Renderer Process | レンダラー・プロセス   | ユーザーに見える画面を描画（レンダリング）するプログラム。ウェブページを表示する部分      |
| Main Process     | メイン・プロセス       | Electronアプリのバックグラウンドで動く親玉プログラム。システムと直接やり取りする          |
| IPC              | アイピーシー           | Inter-Process Communicationの略。画面（Renderer）と裏方（Main）が手紙をやり取りする仕組み |
| contextBridge    | コンテキスト・ブリッジ | 画面と裏方をつなぐ「橋渡し役」。安全に情報を受け渡す門番                                  |
| Preload          | プリロード             | 画面が表示される前に準備しておくプログラム。「開店準備」のようなもの                      |
| data-testid      | データ・テストアイディ | テスト用に要素を識別するための目印。名札のようなもの                                      |

### セッション関連

| 用語       | 読み方                 | 説明                                                                    |
| ---------- | ---------------------- | ----------------------------------------------------------------------- |
| Session    | セッション             | ユーザーとAIの「会話のまとまり」。電話をかけてから切るまでが1セッション |
| Session ID | セッション・アイディー | セッションを区別するための固有番号。電話番号のようなもの                |
| UUID       | ユーユーアイディー     | Universally Unique Identifierの略。世界で絶対に重複しない番号           |

### ストリーミング関連

| 用語      | 読み方         | 説明                                                                                       |
| --------- | -------------- | ------------------------------------------------------------------------------------------ |
| Streaming | ストリーミング | 動画を全部ダウンロードせずに再生するように、AIの返事を少しずつリアルタイムで表示する仕組み |
| Chunk     | チャンク       | データの「かたまり」。大きなデータを小分けにしたもの。おにぎりを一口ずつ食べるイメージ     |
| Callback  | コールバック   | 「終わったら教えて」という約束。宅配便の再配達連絡のようなもの                             |

### テスト関連

| 用語        | 読み方               | 説明                                                                             |
| ----------- | -------------------- | -------------------------------------------------------------------------------- |
| E2E Test    | イーツーイー・テスト | End-to-End Testの略。最初から最後まで通しで動作確認するテスト                    |
| Unit Test   | ユニット・テスト     | 部品を1つずつ確認するテスト。レゴブロック1個ずつ検品するようなもの               |
| Integration | インテグレーション   | 複数の部品を組み合わせて確認するテスト。レゴで作った車が走るか確認するようなもの |
| Mock        | モック               | 本物のふりをする偽物。テスト用のダミー。映画の撮影で使う小道具のようなもの       |
| Coverage    | カバレッジ           | テストがコードの何%をチェックしたかの割合。100%なら全部チェック済み              |

### Electron関連

| 用語        | 読み方                 | 説明                                                                                         |
| ----------- | ---------------------- | -------------------------------------------------------------------------------------------- |
| Electron    | エレクトロン           | ウェブ技術でデスクトップアプリを作るためのフレームワーク。VS CodeやSlackもこれで作られている |
| ipcRenderer | アイピーシーレンダラー | Renderer側からMain側にメッセージを送る仕組み                                                 |
| ipcMain     | アイピーシーメイン     | Main側でRenderer側からのメッセージを受け取る仕組み                                           |
