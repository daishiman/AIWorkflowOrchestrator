## 目的

テストを維持しながら、実装の品質を向上させる（Refactor）。

## 背景

Phase 5-7でテストがグリーンになり、カバレッジも達成された。本Phaseでは、TDDサイクルの最終ステップとして、テストを壊さずにコード品質を向上させるリファクタリングを行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード品質分析

**目的**: 現在の実装の品質課題を特定する。

**実行手順**:

1. 静的解析ツールでコード品質を確認
   ```bash
   pnpm --filter @repo/desktop lint
   pnpm --filter @repo/desktop typecheck
   ```
2. 複雑度の高い関数を特定
3. 重複コードを検出
4. 命名規則の一貫性を確認
5. 改善対象をリスト化

**分析対象**:

| ファイル                 | 分析観点                   |
| ------------------------ | -------------------------- |
| AgentExecutor.ts         | 複雑度、エラーハンドリング |
| ExecutionManager.ts      | 責務分離、状態管理         |
| agentHandlers.ts         | IPC通信パターン            |
| agent-execution.ts（型） | 型定義の完全性             |

**期待される成果物**:

- コード品質分析レポート

---

### タスク2: リファクタリング実行

**目的**: 特定した課題を解決するリファクタリングを実行する。

**実行手順**:

1. リファクタリング対象を優先度順にソート
2. 各変更前にテストがグリーンであることを確認
3. 小さな変更単位でリファクタリング
4. 各変更後にテストを実行
5. テストが通るまで調整

**リファクタリング観点**:

| 観点       | 改善内容                   |
| ---------- | -------------------------- |
| 命名       | 意図を明確に表す命名に変更 |
| 関数分割   | 大きな関数を小さく分割     |
| 型安全性   | any型の除去、型ガード追加  |
| エラー処理 | エラーハンドリングの統一   |
| 重複排除   | 共通処理の抽出             |

**重要**: 各リファクタリングステップ後に必ずテストを実行

```bash
pnpm --filter @repo/desktop test:e2e -- --grep "agent-sdk"
```

**期待される成果物**:

- リファクタリング済みコード

---

### タスク3: テスト再実行・回帰確認

**目的**: リファクタリング後もすべてのテストが通ることを確認する。

**実行手順**:

1. 全E2Eテストを実行
2. パフォーマンステストを実行
3. 回帰がないことを確認
4. パフォーマンス劣化がないことを確認

**確認項目**:

| テスト種別           | 期待結果     |
| -------------------- | ------------ |
| E2Eテスト            | 全テストパス |
| パフォーマンステスト | 目標値維持   |
| 型チェック           | エラーなし   |
| Lint                 | エラーなし   |

**期待される成果物**:

- 回帰テスト結果

---

### タスク4: コードレビュー準備

**目的**: リファクタリング結果をレビュー可能な形で整理する。

**実行手順**:

1. 変更内容の差分を確認
2. 変更理由の文書化
3. 影響範囲の整理
4. レビューポイントの明記

**期待される成果物**:

- リファクタリングサマリー
