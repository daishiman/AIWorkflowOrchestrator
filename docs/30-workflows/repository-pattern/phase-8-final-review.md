## レビューゲート判定基準

### レビュー観点

| #   | 観点         | チェック項目                                 |
| --- | ------------ | -------------------------------------------- |
| 1   | 要件充足     | すべての機能要件が実装されているか           |
| 2   | 受け入れ基準 | すべての受け入れ基準を満たしているか         |
| 3   | 設計準拠     | 設計通りに実装されているか                   |
| 4   | 型安全       | Result型・Branded IDが正しく使用されているか |
| 5   | テスト品質   | 十分なテストカバレッジがあるか               |
| 6   | コード品質   | リファクタリングが適切に行われているか       |
| 7   | ドキュメント | JSDocコメントが適切か                        |

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 9へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 9へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類           | 戻り先                      |
| -------------------- | --------------------------- |
| 要件の漏れ・誤り     | Phase 1（要件定義）         |
| 設計の不整合         | Phase 2（設計）             |
| テスト不足           | Phase 4（テスト作成）       |
| 実装の問題           | Phase 5（実装）             |
| リファクタリング不足 | Phase 6（リファクタリング） |
