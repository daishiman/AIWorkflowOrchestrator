## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、
実装に進む前に設計の妥当性を検証する。

ここで問題を発見すれば、実装後の手戻りを防ぐことができる。

## レビューゲート判定基準

### レビュー観点

| #   | 観点               | チェック項目                                      |
| --- | ------------------ | ------------------------------------------------- |
| 1   | 要件整合性         | すべての機能要件に対応する設計が存在するか        |
| 2   | 依存関係           | Repository → DBスキーマの一方向依存になっているか |
| 3   | 型安全性           | ジェネリクス・Branded IDが適切に設計されているか  |
| 4   | エラーハンドリング | Result型で統一されているか                        |
| 5   | テスタビリティ     | モック注入可能な設計になっているか                |

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先              |
| ---------------- | ------------------- |
| 要件の漏れ・誤り | Phase 1（要件定義） |
| 設計の不整合     | Phase 2（設計）     |
