## 実行タスク

### タスク1: コードレビュー・改善点特定

**目的**: 改善すべきコード箇所を特定

**実行手順**:

1. SkillExecutor.ts のコードを確認
2. コードスメルを検出（重複、長いメソッド、複雑なロジック）
3. 改善優先順位を決定

**チェック観点**:

- [ ] 重複コードの有無
- [ ] メソッドの長さ（20行以上は分割検討）
- [ ] 循環複雑度（10以上は分割検討）
- [ ] 命名の適切さ
- [ ] 単一責任原則の遵守

### タスク2: リファクタリング実施

**目的**: 特定した改善点を修正

**リファクタリング候補**:

- メッセージ変換ロジックの分離
- エラーハンドリングの共通化
- 定数の抽出
- 型ガードの追加

**実行手順**:

1. 各リファクタリングを小さな単位で実施
2. 各変更後にテストを実行
3. テストが継続成功することを確認

### タスク3: テスト継続成功確認

**目的**: リファクタリング後もテストが通ることを確認

**コマンド**:

```bash
pnpm --filter @repo/desktop test
```

## リファクタリングチェックリスト

### SOLID原則

- [ ] **S**: 単一責任 - 各クラス/メソッドが単一の責任を持つ
- [ ] **O**: 開放閉鎖 - 拡張に開き、修正に閉じている
- [ ] **L**: リスコフ置換 - 派生クラスが基底クラスを置換可能
- [ ] **I**: インターフェース分離 - 不要な依存がない
- [ ] **D**: 依存性逆転 - 抽象に依存している

### クリーンコード

- [ ] 意図が明確な命名
- [ ] 短いメソッド（20行以下推奨）
- [ ] 低い循環複雑度（10以下推奨）
- [ ] 適切なコメント（Why を説明）
- [ ] マジックナンバーの排除
