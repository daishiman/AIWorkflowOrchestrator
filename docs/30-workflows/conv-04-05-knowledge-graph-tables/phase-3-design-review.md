## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、実装に進む前に品質を検証する。

## 背景

設計段階での問題を早期に発見し、手戻りを最小化するためのゲートフェーズ。

---

## レビュー観点

### 1. 要件との整合性

- [ ] 全ての機能要件がカバーされている
- [ ] 非機能要件（パフォーマンス、スケーラビリティ）が考慮されている
- [ ] 受け入れ基準が実現可能な設計になっている

### 2. 設計品質

- [ ] 正規化レベルが適切である
- [ ] インデックス設計がクエリパターンに合っている
- [ ] 外部キー制約が正しく設定されている
- [ ] CASCADE動作が適切に定義されている

### 3. 既存システムとの整合性

- [ ] 既存スキーマ（common.ts, chunks.ts）との整合性
- [ ] 命名規則の一貫性
- [ ] 型定義の一貫性

### 4. 技術的妥当性

- [ ] Drizzle ORMの機能を正しく活用している
- [ ] SQLite固有の制約を考慮している
- [ ] パフォーマンス上の懸念がない

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |

---

## 完了条件

- [ ] 全レビュー観点でチェックが完了している
- [ ] レビュー結果判定が決定している
- [ ] 判定がPASSまたはMINORの場合のみ次フェーズへ進む
- [ ] 指摘事項がある場合は対応が完了している
