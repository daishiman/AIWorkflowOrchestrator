# UT-FIX-5-4 要件定義書

## タスク概要

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| タスクID | UT-FIX-5-4                            |
| タスク名 | AgentSDKAPI abort()メソッド型定義修正 |
| 作成日   | 2026-02-10                            |
| 優先度   | 高（型定義の整合性確保）              |

## 背景

AgentSDKAPIの`abort()`メソッドの型定義が2箇所で`void`として定義されているが、実装（preload/index.ts）は`Promise<void>`を返している可能性がある。型定義と実装の不整合を解消し、TypeScript型安全性を確保する必要がある。

## 機能要件（FR）

### FR-1: 型定義の修正

| 要件ID | 内容                                                                                                    | 優先度 |
| ------ | ------------------------------------------------------------------------------------------------------- | ------ |
| FR-1.1 | `apps/desktop/src/preload/types.ts`のAgentSDKAPI.abort()の戻り値型を`void`から`Promise<void>`に修正する | 必須   |
| FR-1.2 | `packages/shared/src/agent/types.ts`のAgentAPI.abort()の戻り値型を`void`から`Promise<void>`に修正する   | 必須   |

### FR-2: 型整合性の維持

| 要件ID | 内容                                                             | 優先度 |
| ------ | ---------------------------------------------------------------- | ------ |
| FR-2.1 | 2箇所の型定義を同時に更新し、一貫性を保つ                        | 必須   |
| FR-2.2 | 関連する呼び出し箇所でTypeScriptエラーが発生しないことを確認する | 必須   |

## 非機能要件（NFR）

### NFR-1: 後方互換性

| 要件ID  | 内容                                         | 基準                                     |
| ------- | -------------------------------------------- | ---------------------------------------- |
| NFR-1.1 | 既存の呼び出しコードを変更せずに動作すること | `void` → `Promise<void>`は後方互換性あり |

### NFR-2: 型安全性

| 要件ID  | 内容                                                    | 基準                       |
| ------- | ------------------------------------------------------- | -------------------------- |
| NFR-2.1 | TypeScript strictモードでエラーなくコンパイルできること | `pnpm typecheck`成功       |
| NFR-2.2 | 型定義ファイル間で不整合がないこと                      | 両ファイルで同一の戻り値型 |

### NFR-3: コード品質

| 要件ID  | 内容                                     | 基準           |
| ------- | ---------------------------------------- | -------------- |
| NFR-3.1 | P23パターン（API二重定義の型管理）に従う | 2箇所同時更新  |
| NFR-3.2 | 型キャスト（as）を使用しない             | 実行時検証不要 |
