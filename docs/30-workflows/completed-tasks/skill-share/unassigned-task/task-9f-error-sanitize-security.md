## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

`importFromLocal()` / `exportToLocal()` の一部エラーメッセージに入力パスがそのまま含まれる。

### 1.2 問題点・課題

Renderer 返却メッセージに過剰なパス情報が残り、情報露出リスクがある。

### 1.3 放置した場合の影響

セキュリティ監査で継続的に指摘され、運用ポリシー違反になる。

---

## 2. 何を達成するか（What）

### 2.1 目的

ユーザー向けエラーメッセージからパス詳細を除去し、内部ログにのみ詳細を残す。

### 2.2 最終ゴール

- 外部返却: 汎用メッセージ
- 内部ログ: 追跡可能な詳細情報

### 2.3 スコープ

#### 含むもの

- エラー文言のサニタイズ
- テスト期待値の更新

#### 含まないもの

- 新規エラーコード体系の再設計

### 2.4 成果物

- `SkillShareManager.ts` サニタイズ更新
- テスト修正

---

## 3. どのように実行するか（How）

### 3.1 前提条件

- 既存エラーコードとの互換を維持する

### 3.2 依存タスク

- 依存なし

### 3.3 必要な知識

- エラーサニタイズ
- ログ/レスポンスの責務分離

### 3.4 推奨アプローチ

「ログは詳細」「レスポンスは最小情報」を原則として一貫適用する。

---

## 4. 実行手順

### Phase構成

- Phase A: サニタイズ実装
- Phase B: テスト調整

### Phase A: サニタイズ実装

#### 目的

外部返却文言からパス情報を除去する。

#### 手順

1. 影響箇所のエラーメッセージを特定する。
2. 汎用メッセージへ置換する。
3. 内部ログに詳細パスを残す。

#### 成果物

エラー文言更新。

#### 完了条件

外部応答にパス文字列が含まれない。

### Phase B: テスト調整

#### 目的

サニタイズの回帰を防ぐ。

#### 手順

1. 期待メッセージを更新。
2. パス非露出の検証ケースを追加。

#### 成果物

更新済みテスト。

#### 完了条件

全テスト PASS。
