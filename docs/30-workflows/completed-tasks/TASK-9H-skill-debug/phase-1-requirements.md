## 実行手順

### Task 1: 機能要件（FR）の定義

#### FR-1: デバッグセッション管理

| ID     | 要件                                                                                   | 優先度 |
| ------ | -------------------------------------------------------------------------------------- | ------ |
| FR-1-1 | スキル名、プロンプト、初期ブレークポイント配列を指定してデバッグセッションを開始できる | 必須   |
| FR-1-2 | デバッグセッションは一意のセッションIDを持ち、セッション状態を追跡できる               | 必須   |
| FR-1-3 | セッション状態は `idle` → `running` → `paused` → `running` → `completed` の遷移を持つ  | 必須   |
| FR-1-4 | セッション状態が `error` に遷移した場合、エラー情報を保持してセッションを終了する      | 必須   |
| FR-1-5 | `stop` コマンドにより任意の状態から即座にセッションを終了できる                        | 必須   |
| FR-1-6 | 同時に実行可能なデバッグセッションは1つのみとする（排他制御）                          | 必須   |

#### FR-2: ブレークポイント管理

| ID     | 要件                                                                                                                     | 優先度 |
| ------ | ------------------------------------------------------------------------------------------------------------------------ | ------ |
| FR-2-1 | ブレークポイントのタイプは `tool`（ツール呼び出し時）、`hook`（フック実行時）、`step`（全ステップ）の3種類をサポートする | 必須   |
| FR-2-2 | `tool` タイプのブレークポイントは `toolName` フィールドで特定ツールを指定できる                                          | 必須   |
| FR-2-3 | `hook` タイプのブレークポイントは `hookType`（`PreToolUse` または `PostToolUse`）を指定できる                            | 必須   |
| FR-2-4 | ブレークポイントに `condition` フィールド（文字列式）を設定して条件付き停止ができる                                      | 任意   |
| FR-2-5 | ブレークポイントの `enabled` フラグで一時的に無効化できる（削除せずに）                                                  | 必須   |
| FR-2-6 | デバッグセッション実行中にブレークポイントを動的に追加・削除できる                                                       | 必須   |
| FR-2-7 | 各ブレークポイントは一意の ID を自動生成して管理する                                                                     | 必須   |

#### FR-3: ステップ実行

| ID     | 要件                                                                                                       | 優先度 |
| ------ | ---------------------------------------------------------------------------------------------------------- | ------ |
| FR-3-1 | `continue` コマンド: 次のブレークポイントまで実行を継続する                                                | 必須   |
| FR-3-2 | `stepOver` コマンド: 現在のステップを実行し、次のステップで停止する                                        | 必須   |
| FR-3-3 | `stepInto` コマンド: ネストされたツール呼び出しの内部に入る                                                | 必須   |
| FR-3-4 | `stepOut` コマンド: 現在のスコープを抜けて呼び出し元に戻る                                                 | 必須   |
| FR-3-5 | `pause` コマンド: 実行中のセッションを一時停止する                                                         | 必須   |
| FR-3-6 | `stop` コマンド: デバッグセッションを即座に終了する                                                        | 必須   |
| FR-3-7 | 各ステップは `stepNumber`、`type`（`tool_call`/`hook_execution`/`agent_response`）、`timestamp` を記録する | 必須   |
| FR-3-8 | ステップの `input` と `output` を記録し、後からインスペクションできる                                      | 必須   |

#### FR-4: 変数インスペクション

| ID     | 要件                                                                                                      | 優先度 |
| ------ | --------------------------------------------------------------------------------------------------------- | ------ |
| FR-4-1 | デバッグセッション中の変数を `path` 文字列（ドット区切り）で指定してインスペクションできる                | 必須   |
| FR-4-2 | `variables` は `Record<string, unknown>` 型で管理し、ツール呼び出しの入出力・エージェントの内部状態を含む | 必須   |
| FR-4-3 | 変数変更時に `variable-changed` イベントを発火し、変更パスと新しい値を通知する                            | 必須   |

#### FR-5: 式評価

| ID     | 要件                                                                                                  | 優先度 |
| ------ | ----------------------------------------------------------------------------------------------------- | ------ |
| FR-5-1 | 一時停止中にJavaScript式を評価し、結果を返却できる                                                    | 必須   |
| FR-5-2 | 式評価のスコープはデバッグセッションの `variables` に限定する（グローバルスコープへのアクセスは禁止） | 必須   |
| FR-5-3 | 式評価のタイムアウトは5秒とし、超過時はエラーを返却する                                               | 必須   |
| FR-5-4 | 式評価でのファイルシステム・ネットワーク・プロセス操作は禁止する                                      | 必須   |

#### FR-6: コールスタック表示

| ID     | 要件                                                                                                 | 優先度 |
| ------ | ---------------------------------------------------------------------------------------------------- | ------ |
| FR-6-1 | コールスタックはエントリの `depth`、`name`、`type`（`skill`/`agent`/`tool`）、`startTime` を記録する | 必須   |
| FR-6-2 | ツール呼び出し開始時にコールスタックにエントリをプッシュし、完了時にポップする                       | 必須   |
| FR-6-3 | 一時停止中にコールスタック全体をインスペクションできる                                               | 必須   |

#### FR-7: デバッグイベント通知

| ID     | 要件                                                                                                      | 優先度 |
| ------ | --------------------------------------------------------------------------------------------------------- | ------ |
| FR-7-1 | `step` イベント: 各ステップ実行時に発火し、セッションIDとステップ情報を通知する                           | 必須   |
| FR-7-2 | `breakpoint-hit` イベント: ブレークポイントに到達時に発火し、該当ブレークポイントとステップ情報を通知する | 必須   |
| FR-7-3 | `variable-changed` イベント: 変数変更時に発火し、変更パスと新しい値を通知する                             | 必須   |
| FR-7-4 | `session-ended` イベント: セッション終了時に発火し、エラー情報（該当する場合）と完了時刻を通知する        | 必須   |
| FR-7-5 | イベント通知は IPC の `skill:debug:event` チャネルを通じて Renderer に送信する                            | 必須   |

### Task 2: 非機能要件（NFR）の定義

#### NFR-1: セキュリティ

| ID      | 要件                                                                                                                   | 基準                           |
| ------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| NFR-1-1 | 式評価はサンドボックス環境で実行し、Node.js グローバルオブジェクト（`process`、`require`、`fs`）へのアクセスを遮断する | アクセス不可を単体テストで検証 |
| NFR-1-2 | 全 IPC ハンドラで `validateIpcSender` による送信元ウィンドウ検証を実施する                                             | 検証失敗時にエラー返却         |
| NFR-1-3 | 全文字列引数に P42 準拠3段バリデーション（型チェック → 空文字列 → トリム空文字列）を適用する                           | バリデーション通過率 100%      |
| NFR-1-4 | 式評価で無限ループを検出し、タイムアウト（5秒）で強制終了する                                                          | タイムアウト動作を検証         |
| NFR-1-5 | デバッグイベントにパスワード・APIキー・PII を含めない                                                                  | ログ監査で確認                 |
| NFR-1-6 | `condition` フィールドの式もサンドボックスで評価し、副作用を持つ式を拒否する                                           | 単体テストで検証               |

#### NFR-2: パフォーマンス

| ID      | 要件                                                                                | 基準                     |
| ------- | ----------------------------------------------------------------------------------- | ------------------------ |
| NFR-2-1 | デバッグモード有効時のスキル実行オーバーヘッドは通常実行の200%以内（3倍以内）とする | ベンチマークテストで計測 |
| NFR-2-2 | ブレークポイント判定処理は1回あたり10ms以内で完了する                               | 単体テストで計測         |
| NFR-2-3 | 変数インスペクションのレスポンスタイムは100ms以内とする                             | 統合テストで計測         |
| NFR-2-4 | デバッグイベントのシリアライズと IPC 送信は50ms以内で完了する                       | 統合テストで計測         |
| NFR-2-5 | 1セッションあたりの最大ステップ数は10,000とし、超過時はセッションを自動終了する     | 上限到達テストで検証     |

#### NFR-3: 可用性・信頼性

| ID      | 要件                                                                                    | 基準                       |
| ------- | --------------------------------------------------------------------------------------- | -------------------------- |
| NFR-3-1 | セッション異常終了時（プロセスクラッシュ、タイムアウト）にリソースをクリーンアップする  | 異常終了テストで検証       |
| NFR-3-2 | セッション開始後30分経過で自動タイムアウト終了する                                      | タイマーテストで検証       |
| NFR-3-3 | IPC 通信エラー時にセッション状態を `error` に遷移し、エラー内容をサニタイズして返却する | エラーシナリオテストで検証 |
| NFR-3-4 | SkillDebugger インスタンスは SkillService ライフサイクルと連動して初期化・破棄される    | ライフサイクルテストで検証 |

### Task 4: 受け入れ基準

#### AC-1: デバッグセッションライフサイクル

- [ ] スキル名・プロンプト・ブレークポイント配列を指定してデバッグセッションを開始できる
- [ ] セッションが `idle` → `running` → `paused` → `running` → `completed` の状態遷移を正しく行う
- [ ] `error` 状態に遷移した場合、エラー情報を保持してセッションが終了する
- [ ] `stop` コマンドで任意の状態から即座にセッションを終了できる
- [ ] 同時に2つ目のセッションを開始しようとするとエラーが返る
- [ ] セッション開始後30分でタイムアウト終了する
- [ ] 異常終了時にリソース（タイマー、リスナー）がクリーンアップされる

#### AC-2: ブレークポイント

- [ ] `tool` タイプのブレークポイントで特定ツール呼び出し時に停止する
- [ ] `hook` タイプのブレークポイントで `PreToolUse`/`PostToolUse` 実行時に停止する
- [ ] `step` タイプのブレークポイントで全ステップで停止する
- [ ] `enabled: false` のブレークポイントでは停止しない
- [ ] `condition` フィールドの条件式が `true` に評価された場合のみ停止する
- [ ] 実行中にブレークポイントを動的に追加・削除できる

#### AC-3: ステップ実行

- [ ] `continue` で次のブレークポイントまで実行が継続する
- [ ] `stepOver` で次のステップに進んで停止する
- [ ] `stepInto` でネストされた呼び出しの内部に入る
- [ ] `stepOut` で現在のスコープを抜ける
- [ ] `pause` で実行中のセッションが一時停止する
- [ ] 各ステップで `stepNumber`、`type`、`timestamp` が記録される

#### AC-4: 変数インスペクション

- [ ] ドット区切りパスで変数を指定してインスペクションできる
- [ ] ツール呼び出しの入出力が `variables` に記録される
- [ ] 変数変更時に `variable-changed` イベントが発火する

#### AC-5: 式評価

- [ ] 一時停止中に JavaScript 式を評価して結果を取得できる
- [ ] `process`、`require`、`fs` 等のグローバルオブジェクトへのアクセスがブロックされる
- [ ] 5秒のタイムアウトで無限ループが強制終了される
- [ ] セッションの `variables` スコープ内でのみ評価が実行される

#### AC-6: イベント通知

- [ ] `step` イベントが各ステップ実行時に Renderer に通知される
- [ ] `breakpoint-hit` イベントがブレークポイント到達時に通知される
- [ ] `variable-changed` イベントが変数変更時に通知される
- [ ] `session-ended` イベントがセッション終了時に通知される

#### AC-7: セキュリティ

- [ ] 全 IPC ハンドラで `validateIpcSender` が呼び出される
- [ ] 全文字列引数に3段バリデーションが適用される
- [ ] エラーレスポンスに内部スタックトレースが含まれない

#### AC-8: パフォーマンス

- [ ] デバッグモードのオーバーヘッドが通常実行の200%以内
- [ ] ブレークポイント判定が10ms以内
- [ ] 変数インスペクションのレスポンスが100ms以内
