## 1. 機能概要

スキルを定期的に、または特定のタイミングで自動実行するスケジューリング機能を実装する。
以下の4種類のスケジュール方式に対応し、electron-storeによる永続化とIPC経由のCRUD操作を提供する。

| スケジュール方式 | 説明                                  | 例                          |
| ---------------- | ------------------------------------- | --------------------------- |
| cron             | cron式（node-cron互換）による定期実行 | `*/5 * * * *`（5分毎）      |
| interval         | ミリ秒指定による一定間隔実行          | `60000`（60秒毎）           |
| once             | ISO 8601日時指定による1回限りの実行   | `2026-03-01T09:00:00+09:00` |
| event            | アプリ内イベント発生時のトリガー実行  | `app_start`, `file_change`  |

## 2. 機能要件（FR）

### FR-01: Cronスケジュール実行

| 項目   | 内容                                                                                                                                                                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件   | cron式（`node-cron`互換）でスケジュールを登録し、指定パターンでスキルを自動実行する                                                                                                                                                                                      |
| 優先度 | 高                                                                                                                                                                                                                                                                       |
| 詳細   | `node-cron`の`cron.schedule()`を使用してタスクを登録する。cron式の妥当性は`cron.validate()`で事前検証し、不正なcron式は`VALIDATION_ERROR`（ERR_1005）として拒否する。タスク参照は`Map<string, ScheduledTask>`で管理し、スケジュール削除時に`task.stop()`で確実に解放する |
| 制約   | cron式は5フィールド形式（分 時 日 月 曜日）のみサポート。秒フィールド（6フィールド）は非サポート                                                                                                                                                                         |

### FR-02: インターバルスケジュール実行

| 項目   | 内容                                                                                                                                                    |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | インターバル（ミリ秒指定）でスケジュールを登録し、一定間隔でスキルを自動実行する                                                                        |
| 優先度 | 高                                                                                                                                                      |
| 詳細   | `setInterval()`を使用してタイマーを登録する。タイマー参照は`Map<string, NodeJS.Timeout>`で管理し、スケジュール削除時に`clearInterval()`で確実に解放する |
| 制約   | 最小インターバルは1000ms（1秒）。1000ms未満の指定は`VALIDATION_ERROR`（ERR_1004）として拒否する。最大インターバルは86400000ms（24時間）                 |

### FR-03: ワンショットスケジュール実行

| 項目   | 内容                                                                                                                                                                      |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | ワンショット（ISO 8601日時指定）でスケジュールを登録し、指定時刻に1回だけスキルを自動実行する                                                                             |
| 優先度 | 高                                                                                                                                                                        |
| 詳細   | `setTimeout()`を使用して指定時刻までの差分ミリ秒をタイマーに設定する。実行完了後は`enabled`を`false`に自動設定する。タイマー参照は`Map<string, NodeJS.Timeout>`で管理する |
| 制約   | 過去の日時（現在時刻より前）を指定した場合は`VALIDATION_ERROR`（ERR_1004）として拒否する。Date型はIPC境界でISO 8601文字列に変換して送受信する                             |

### FR-04: イベントトリガースケジュール実行

| 項目   | 内容                                                                                                                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | イベントトリガー（`app_start` / `file_change` / `git_commit`）でスケジュールを登録し、イベント発生時にスキルを自動実行する                                                                         |
| 優先度 | 中                                                                                                                                                                                                 |
| 詳細   | `app_start`はSkillScheduler.initialize()呼び出し時に即座実行する。`file_change`と`git_commit`は本タスクではインターフェース（型定義と`eventConfig`フィールド）のみ定義し、詳細実装は別タスクとする |
| 制約   | `file_change`の監視対象パスは`eventConfig.watchPaths: string[]`で指定する。`git_commit`のリポジトリパスは`eventConfig.repositoryPath: string`で指定する                                            |

### FR-05: スケジュール有効/無効トグル

| 項目   | 内容                                                                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | スケジュールの有効/無効を切り替えられる（`enabled`フラグのトグル）                                                                                                                      |
| 優先度 | 高                                                                                                                                                                                      |
| 詳細   | `enabled: true`→`false`に変更時、稼働中のタイマー（cron/interval/timeout）を停止する。`enabled: false`→`true`に変更時、タイマーを再起動する。トグル結果はelectron-storeに即時永続化する |
| 制約   | 存在しないスケジュールIDでのトグル要求は`RESOURCE_NOT_FOUND`（ERR_2001）として拒否する                                                                                                  |

### FR-06: スケジュールCRUD操作

| 項目   | 内容                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| 要件   | スケジュールのCRUD操作（追加・取得・更新・削除）をIPC経由で実行できる                       |
| 優先度 | 高                                                                                          |
| 詳細   | 5つのIPCチャンネル（後述）で操作を提供する。全操作の結果はelectron-storeに即時永続化する    |
| 制約   | 全IPCハンドラでP42準拠3段バリデーション（型チェック → 空文字列 → トリム空文字列）を実施する |

### FR-07: スケジュール永続化と復元

| 項目   | 内容                                                                                                                                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | アプリ再起動後に保存済みスケジュールをelectron-storeから復元し、有効なスケジュールのタイマーを再開する                                                                                                               |
| 優先度 | 高                                                                                                                                                                                                                   |
| 詳細   | `ScheduleStore`がelectron-storeの`scheduledSkills`キーでJSON形式のスケジュール配列を管理する。`SkillScheduler.initialize()`呼び出し時に全スケジュールを読み出し、`enabled: true`のスケジュールのタイマーを再登録する |
| 制約   | 復元時にワンショットスケジュールの指定時刻が既に過去であった場合、`enabled`を`false`に設定し実行しない                                                                                                               |

### FR-08: 実行履歴の記録

| 項目   | 内容                                                                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | スキル実行結果を`ScheduledRunResult`として`runHistory`に記録し、最新100件を保持する                                                                                 |
| 優先度 | 中                                                                                                                                                                  |
| 詳細   | 各スケジュール実行完了時（成功・失敗問わず）に`ScheduledRunResult`オブジェクトを`runHistory`配列の先頭に追加する。配列長が100を超えた場合は最古のエントリを削除する |
| 制約   | `runHistory`の件数上限（100件）は`MAX_RUN_HISTORY`定数としてハードコードする。件数上限はNFR-08で定義                                                                |

### FR-09: 通知設定に基づく通知送信

| 項目   | 内容                                                                                                                                                                                                             |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | スキル実行完了時に`NotificationSettings`に基づいて通知を送信する（成功時・失敗時を個別制御）                                                                                                                     |
| 優先度 | 中                                                                                                                                                                                                               |
| 詳細   | `notification.onSuccess: true`の場合は成功時にシステム通知を送信する。`notification.onFailure: true`の場合は失敗時にシステム通知を送信する。通知はElectronの`Notification` APIを使用してMain Processから送信する |
| 制約   | `notificationType`は`"system"`（システム通知）のみ初期サポート。将来的に`"in-app"`（アプリ内通知）等の拡張を想定した型設計とする                                                                                 |

### FR-10: 次回実行予定時刻の計算

| 項目   | 内容                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件   | `nextRun`を計算し、次回実行予定時刻をスケジュール情報として返却する                                                                                                                        |
| 優先度 | 中                                                                                                                                                                                         |
| 詳細   | cron式の場合は次回のcron一致時刻を計算する。intervalの場合は前回実行時刻 + インターバルで計算する。onceの場合は指定日時をそのまま返す。eventの場合は`null`を返す（次回実行時刻は予測不能） |
| 制約   | IPC境界では`nextRun`をISO 8601文字列（またはnull）で返却する                                                                                                                               |

## 3. 非機能要件（NFR）

### NFR-01: IPCバリデーション（P42準拠）

| 項目   | 内容                                                                                                             |
| ------ | ---------------------------------------------------------------------------------------------------------------- |
| 要件   | 全IPCハンドラでP42準拠3段バリデーション（型チェック → 空文字列 → トリム空文字列）を実施する                      |
| 優先度 | 高                                                                                                               |
| 参照   | `06-known-pitfalls.md#P42`                                                                                       |
| 検証   | 文字列引数（ID、スキル名等）に対して `typeof !== "string"` → `=== ""` → `.trim() === ""` の3段チェックを実施する |

### NFR-02: IPC送信元検証

| 項目   | 内容                                                                     |
| ------ | ------------------------------------------------------------------------ |
| 要件   | 全IPCハンドラで`validateIpcSender()`による送信元ウィンドウ検証を実施する |
| 優先度 | 高                                                                       |
| 参照   | `04-electron-security.md`                                                |
| 検証   | 全5チャンネルのハンドラで送信元がmainWindowであることを検証する          |

### NFR-03: IPC引数命名規約（P45対策）

| 項目   | 内容                                                                                      |
| ------ | ----------------------------------------------------------------------------------------- |
| 要件   | IPCハンドラの引数名はPreload側で渡す値のセマンティクスと一致させる                        |
| 優先度 | 高                                                                                        |
| 参照   | `06-known-pitfalls.md#P45`                                                                |
| 検証   | ハンドラの引数名とPreload APIのメソッド引数名が一致していることをコードレビューで確認する |

### NFR-04: データ永続化

| 項目   | 内容                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| 要件   | スケジュールデータはelectron-storeで永続化し、アプリ再起動後も保持する                      |
| 優先度 | 高                                                                                          |
| 検証   | electron-storeのキー`scheduledSkills`にスケジュール配列がJSON形式で保存されることを確認する |

### NFR-05: タイマーリソース管理（メモリリーク防止）

| 項目   | 内容                                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------- |
| 要件   | `setInterval`/`setTimeout`/`node-cron`のタイマー参照を`Map<string, ...>`で管理し、スケジュール削除時に確実に解放する |
| 優先度 | 高                                                                                                                   |
| 検証   | スケジュール削除後に`Map.size`が減少し、対応するタイマーが停止していることをテストで確認する                         |

### NFR-06: タイマー二重登録防止（P5対策）

| 項目   | 内容                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 要件   | 同一スケジュールIDのタイマーが二重登録されないようガードする                               |
| 優先度 | 高                                                                                         |
| 参照   | `06-known-pitfalls.md#P5`                                                                  |
| 検証   | タイマー登録前に同一IDのタイマーが既に存在する場合、既存タイマーを停止してから新規登録する |

### NFR-07: IPC境界のDate型変換

| 項目   | 内容                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 要件   | IPC境界ではDate型を`.toISOString()`でISO 8601文字列に変換して返却する                            |
| 優先度 | 高                                                                                               |
| 検証   | `createdAt`、`updatedAt`、`lastRun`、`nextRun`がISO 8601文字列で返却されることをテストで確認する |

### NFR-08: 実行履歴件数制限

| 項目   | 内容                                                                                      |
| ------ | ----------------------------------------------------------------------------------------- |
| 要件   | `runHistory`は最新100件に制限し、無制限な蓄積によるストレージ肥大化を防止する             |
| 優先度 | 中                                                                                        |
| 検証   | 101件目の実行結果追加時に最古の1件が削除され、配列長が100を超えないことをテストで確認する |

### NFR-09: エラー記録と継続動作

| 項目   | 内容                                                                                                                                                 |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件   | スケジュール実行エラーは握りつぶさず`ScheduledRunResult.error`に記録し、通知で通知する。エラー発生後もスケジュール自体は停止せず、次回実行を継続する |
| 優先度 | 中                                                                                                                                                   |
| 参照   | `02-code-quality.md#エラーハンドリング`                                                                                                              |
| 検証   | スキル実行が失敗した場合でもスケジュールが`enabled: true`のまま維持され、次回実行が正常に行われることをテストで確認する                              |

## 4. IPCチャンネル定義

### 4.1 チャンネル一覧

| チャンネル名            | メソッド | 説明               |

## 5. 型定義

### 5.1 ScheduledSkill

```typescript
/** スケジュール済みスキル */
export interface ScheduledSkill {
  /** スケジュールの一意識別子 */
  id: string;
  /** 実行対象のスキル名 */
  skillName: string;
  /** スキル実行時のプロンプト */
  prompt: string;
  /** スケジュール設定 */
  schedule: SkillSchedule;
  /** スケジュールが有効かどうか */
  enabled: boolean;
  /** 実行履歴（最新が先頭、最大100件） */
  runHistory: ScheduledRunResult[];
  /** 通知設定 */
  notification: NotificationSettings;
  /** 最後に実行した日時（ISO 8601） */
  lastRun?: string | null;
  /** 次回実行予定日時（ISO 8601） */
  nextRun?: string | null;
  /** 作成日時（ISO 8601） */
  createdAt: string;
  /** 更新日時（ISO 8601） */
  updatedAt: string;
}
```

### 5.2 SkillSchedule

```typescript
/** スケジュール設定（フラットインターフェース） */
export interface SkillSchedule {
  /** スケジュール方式 */
  type: "cron" | "interval" | "once" | "event";
  /** cron 式（type: "cron" の場合に必須） */
  cronExpression?: string;
  /** 実行間隔（ミリ秒、type: "interval" の場合に必須） */
  interval?: number;
  /** 実行日時（ISO 8601、type: "once" の場合に使用） */
  runAt?: string | null;
  /** トリガーイベント（type: "event" の場合に必須） */
  event?: "app_start" | "file_change" | "git_commit";
  /** イベント固有設定（type: "event" の場合に使用） */
  eventConfig?: Record<string, unknown>;
}
```

> **設計判断**: ユニオン型ではなくフラットインターフェースを採用。IPC境界でのシリアライズが単純になり、`type`フィールドによる条件分岐で各方式固有のフィールドにアクセスする。

### 5.3 NotificationSettings

```typescript
/** 通知設定 */
export interface NotificationSettings {
  /** 成功時に通知するかどうか */
  onSuccess: boolean;
  /** 失敗時に通知するかどうか */
  onFailure: boolean;
  /** 通知方式 */
  notificationType: "system" | "inApp" | "both";
}
```

### 5.4 ScheduledRunResult

```typescript
/** スケジュール実行結果 */
export interface ScheduledRunResult {
  /** 実行の一意識別子 */
  runId: string;
  /** 実行開始日時（ISO 8601） */
  startedAt: string;
  /** 実行が成功したかどうか */
  success: boolean;
  /** 実行完了日時（ISO 8601） */
  completedAt?: string | null;
  /** 実行結果の出力 */
  output?: string;
  /** エラーメッセージ */
  error?: string;
}
```

## 6. アーキテクチャ層別要件

| 層             | 要件                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Shared Package | `ScheduledSkill`、`SkillSchedule`、`NotificationSettings`、`ScheduledRunResult`、`EventConfig`型定義。`index.ts`からre-export |
| Main Process   | `SkillScheduler`サービス（スケジュール管理・タイマー管理・実行制御）、`ScheduleStore`（electron-store永続化）                 |
| IPC通信        | 5チャンネル追加。全ハンドラでsender検証・P42バリデーション実施                                                                |
| Preload        | `skill-api.ts`にscheduleメソッド5件追加。`channels.ts`に定数5件追加                                                           |
| Renderer       | 変更なし（UIは別タスクのスコープ）                                                                                            |

## 7. データフロー

```
Renderer
  │ Preload (skill-api.ts#schedule.list/add/update/delete/toggle)
  ↓
IPC (skill:schedule:*)
  │ validateIpcSender() + P42バリデーション
  ↓
Main Process
  │
  ├── SkillScheduler
  │     ├── addSchedule()     → ScheduleStore.save() + タイマー登録
  │     ├── updateSchedule()  → ScheduleStore.save() + タイマー再登録
  │     ├── deleteSchedule()  → ScheduleStore.save() + タイマー解放
  │     ├── toggleSchedule()  → ScheduleStore.save() + タイマー制御
  │     ├── initialize()      → ScheduleStore.load() + タイマー復元
  │     └── executeSkill()    → SkillExecutor.execute()
  │
  ├── ScheduleStore (electron-store)
  │     ├── load(): ScheduledSkill[]
  │     ├── save(schedules: ScheduledSkill[]): void
  │     └── キー: "scheduledSkills"
  │
  └── SkillExecutor (既存・TASK-9B)
        └── execute(skillName, prompt): ExecutionResult
```

| IPC通信          | `skill:schedule:list/add/update/delete/toggle` 5チャンネル。全てハンドラ形式（invoke/handle）          |
| スキル実行連携   | `SkillScheduler` → `SkillExecutor.execute()` でスキルを実行。既存の`skill:execute`と同じ実行パスを使用 |
| 永続化           | `electron-store`でJSON形式保存。キー: `scheduledSkills`。値: `ScheduledSkill[]`                        |
| 通知             | `Notification` API（システム通知）。Main Processから送信                                               |
| データフロー     | Main Process（ScheduleStore <-> SkillScheduler <-> SkillExecutor） → IPC → Preload → Renderer          |
