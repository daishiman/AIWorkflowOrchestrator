## 目的

Phase 2 で設計した実行計画が Phase 4 以降の実行に進めるレベルかを判定する。環境クリーンアップ手順・テスト実行計画・ドキュメント更新計画の3点を審査する。

## 実行タスク

- Phase 1 と Phase 2 の成果物を照合し、実行計画の前提が崩れていないかを審査する
- 環境クリーンアップ、test rerun、doc update の3レーンを review gate に掛ける
- 30思考法のうち review で効く観点を要約し、改善優先順位を固定する
- Phase 4 へ進める条件と差し戻し条件を PASS/FAIL で明記する

### タスク1: 設計ゲート審査

**目的**: Phase 2 の設計が Phase 4 進行の要件を満たすか判定する

**審査項目**:

| 観点             | 審査内容                                                      | PASS条件                         |
| ---------------- | ------------------------------------------------------------- | -------------------------------- |
| 環境クリーン     | node_modules 完全削除 → pnpm install の手順が定義されているか | コマンドが具体的に定義されている |
| フォールバック   | `pnpm store prune` フォールバックが定義されているか           | 定義されている                   |
| テスト計画       | Engine・Renderer の両テストが AC と紐付いているか             | AC-1・AC-2 との紐付けあり        |
| ドキュメント計画 | 更新対象ファイルのパスが正確か                                | パスが実在ファイルと一致する     |
| スコープ遵守     | 新規実装が含まれていないか                                    | 含まれていない                   |

### タスク2: リスク評価

**目的**: Phase 4 以降で発生しうるリスクを事前に評価する

**既知リスクと対策**:

| リスク                                        | 対策                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------ |
| node_modules 削除後も esbuild mismatch が残る | `pnpm store prune` を追加で実施する（フォールバック手順として定義済み）              |
| AC-4 の既存 kind テストが存在しない           | Phase 6 の grep 確認で検出し、必要な場合は新規テスト追加をスコープ拡大として記録する |
| TASK-RT-05 の phase-9/phase-10 パスが不明     | Phase 1 でパス確認済みとする（existence-check でゲート）                             |
