## 品質チェックリスト

以下のチェックを上から順に実行し、全て PASS したことを確認してから Phase 10 へ進む。

### 1. TypeScript 型チェック

```bash
pnpm typecheck
```

- [ ] エラー 0 件で終了すること
- [ ] 新規追加コードに `any` 型が使用されていないこと
- [ ] Props 型・状態型が明示的に定義されていること

### 2. ESLint チェック

```bash
pnpm lint
```

- [ ] エラー 0 件で終了すること
- [ ] Warning についても内容を確認し、意図的でないものは修正すること
- [ ] `// eslint-disable` コメントが不必要に追加されていないこと

### 3. テスト全件 PASS

```bash
pnpm --filter @repo/desktop test
```

- [ ] テストが全件 PASS すること
- [ ] 新規追加したテストケース（Q5 複数選択・単一選択・0 件選択・aria-label）が全て PASS すること
- [ ] 既存テストが新規コードの影響でリグレッションしていないこと

### 4. ビルド確認

```bash
pnpm --filter @repo/desktop build
```

- [ ] ビルドエラーが 0 件で完了すること
- [ ] ビルド Warning に新規追加コードに起因するものがないこと

### 5. aria 属性の妥当性確認

以下の観点でコードを目視確認する。

- [ ] 「主ツール」バッジに適切な `aria-label` が付与されていること
- [ ] `aria-labelledby` により button 名が選択肢テキストのまま維持されること
- [ ] バッジが表示されない場合（単一選択・0 件選択）に `aria-label` が残存していないこと
- [ ] `role` 属性が必要な場合は適切に付与されていること（装飾的な要素の場合は `aria-hidden="true"` も検討）

### 6. Tailwind クラスの一貫性確認

以下の観点でコードを目視確認する。

- [ ] バッジに使用した Tailwind クラスが既存コンポーネントのスタイルと一貫していること
- [ ] プロジェクト内の他のバッジ・ラベル UI と色・サイズ・角丸等のスタイルが揃っていること
- [ ] レスポンシブ対応が必要な場合は適切なブレークポイントクラスが付与されていること
- [ ] ダークモード対応が既存コンポーネントで行われている場合は同様の対応が入っていること

## PASS / FAIL 判定基準

### PASS 条件（全て満たすこと）

| #   | 判定項目              | 基準                                                           |
| --- | --------------------- | -------------------------------------------------------------- |
| 1   | TypeScript 型チェック | `pnpm typecheck` がエラー 0 件で終了すること                   |
| 2   | ESLint チェック       | `pnpm lint` がエラー 0 件で終了すること                        |
| 3   | テスト全件            | `pnpm --filter @repo/desktop test` が全件 PASS すること        |
| 4   | ビルド                | `pnpm --filter @repo/desktop build` がエラーなしで完了すること |
| 5   | aria 属性             | チェックリスト全項目が目視確認で OK であること                 |
| 6   | Tailwind クラス       | チェックリスト全項目が目視確認で OK であること                 |

### FAIL 条件（いずれか1つでも該当する場合）

- `pnpm typecheck` でエラーが 1 件以上発生している
- `pnpm lint` でエラーが 1 件以上発生している
- テストが 1 件以上 FAIL している
- ビルドがエラーで失敗している
- aria 属性チェックリストで未チェック項目がある
- Tailwind クラスチェックリストで未チェック項目がある

### FAIL 時の対処

FAIL が発生した場合は、該当するチェック項目の問題を修正し、**全てのチェックを再実行**してから判定を行う。部分的な再実行は認めない（修正が他の項目に影響する可能性があるため）。
