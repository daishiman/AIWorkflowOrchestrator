## 目的

concern と dependency edge の coverage を可視化する。

本フェーズでは、Phase 6 で実装した「主ツール」バッジ表示ロジックおよびその周辺コードに対して、テストカバレッジを計測し、未到達ブランチや未テストパスを特定する。カバレッジの可視化により、品質リスクを定量的に把握し、Phase 8 のリファクタリングおよび Phase 9 の品質保証に向けた判断材料を得る。

## 確認観点

### 1. ConversationRoundStep.tsx の主ツールバッジ表示ロジックのブランチカバレッジ

`renderQuestion` 関数内の Q5 キー分岐において、以下のブランチが全てテストされていることを確認する。

- Q5 キーが一致する分岐（バッジ表示ロジックが実行されるパス）
- Q5 キーが一致しない分岐（既存の設問レンダリングにフォールバックするパス）

### 2. Q5 複数選択時・単一選択時・0 件選択時の分岐カバレッジ

選択件数による表示の違いをカバーするため、以下の3パターンが全てテストされていることを確認する。

| パターン | 選択件数 | 期待動作                             |
| -------- | -------- | ------------------------------------ |
| 複数選択 | 2件以上  | 先頭選択肢に「主ツール」バッジを表示 |
| 単一選択 | 1件      | バッジを表示しない（または非表示）   |
| 0件選択  | 0件      | バッジを表示しない                   |

### 3. aria-label 生成パスのカバレッジ

アクセシビリティ属性 `aria-label` の生成パスについて、以下のケースがテストされていることを確認する。

- バッジが表示される場合の `aria-label` 付与
- バッジが表示されない場合（`aria-label` が付与されないパス）

## 期待カバレッジ目標

| 指標                                  | 目標値   |
| ------------------------------------- | -------- |
| ブランチカバレッジ (Branches)         | 90% 以上 |
| ステートメントカバレッジ (Statements) | 90% 以上 |
| 関数カバレッジ (Functions)            | 100%     |
| 行カバレッジ (Lines)                  | 90% 以上 |

> 注意: 上記目標値は `ConversationRoundStep.tsx` ファイル単体の値を指す。プロジェクト全体のカバレッジ目標とは別途管理する。

## 未到達箇所への対処方針

カバレッジ目標を下回る箇所が発見された場合は、以下の優先順位で対処する。

### 優先度: 高（必ず対処）

- Q5 分岐のブランチカバレッジが 90% 未満の場合: テストケースを追加する
- `aria-label` 生成パスが未テストの場合: アクセシビリティテストケースを追加する

### 優先度: 中（状況に応じて対処）

- 既存設問レンダリングのフォールバックパスが未到達の場合: 既存テストの網羅性を確認し、必要であればテストケースを補完する

### 優先度: 低（記録のみ）

- Q5 以外の設問に関するカバレッジ不足: 本タスクのスコープ外のため、別タスクとして Issue を起票して記録する

### 対処後の再計測

テストケース追加後は、再度 `pnpm --filter @repo/desktop test --coverage` を実行し、目標値を達成していることを確認してから Phase 8 へ進む。
