## 目的

Phase 1〜2 の成果物（要件定義・設計）の妥当性を検証し、

重大な問題がある場合は該当 Phase へ戻って修正する。

## 実行タスク

### タスク 1: 要件-設計整合性チェック

**目的**: Phase 1 の要件が Phase 2 の設計で満たされるか検証

**実行手順**:

1. 機能要件（FR-1〜FR-5）と設計の対応を確認
2. 非機能要件（NFR-1〜NFR-4）と設計の対応を確認
3. 不整合があれば記録

**期待される成果物**:

- 整合性チェックリスト

### タスク 2: 型定義整合性チェック

**目的**: TASK-1-1 の型定義との整合性を検証

**実行手順**:

1. `PermissionResponse` 型の使用箇所を確認
2. `requestId` フィールドの存在を確認
3. 型の互換性を検証

**期待される成果物**:

- 型整合性チェック結果

### タスク 3: 設計品質チェック

**目的**: 設計の品質・保守性を検証

**実行手順**:

1. 単一責任の原則を満たしているか確認
2. テスタビリティが確保されているか確認
3. エッジケースが考慮されているか確認

**期待される成果物**:

- 設計品質レビュー結果

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
