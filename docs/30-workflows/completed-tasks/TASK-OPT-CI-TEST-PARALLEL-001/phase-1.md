# Phase 1: 要件定義

## メタ情報

| 項目   | 値                      |
| ------ | ----------------------- |
| Phase  | 1                       |
| 機能名 | CI テスト並列実行最適化 |
| 作成日 | 2026-02-02              |

## 目的

GitHub Actions CI パイプラインのテスト実行時間短縮に関する要件を明確化する。

## 実行タスク

### Task 1: 現状分析データの整理

現在のCI実行時間データを整理し、ボトルネックを特定する。

**分析対象**:

1. 直近20回のCI実行時間データ
2. 各ジョブの実行時間内訳
3. キャッシュヒット率
4. テストファイル数・ケース数

**出力**: 現状分析レポート

### Task 2: 最適化要件の抽出

最適化目標を定量的に定義する。

**定義項目**:

1. 目標実行時間（各シャード、全体）
2. カバレッジ閾値の維持条件
3. 信頼性要件（Flaky test許容度）
4. コスト制約（ランナー時間上限）

### Task 3: 受け入れ基準の作成

各要件に対して検証可能な受け入れ基準を定義する。

## 実行手順

### ステップ1: CI実行ログ分析

```bash
# 直近のCI実行時間を取得
gh run list --workflow=ci.yml --limit 20 --json databaseId,conclusion,createdAt,updatedAt
```

各ジョブの実行時間を集計し、以下の表を作成:

| ジョブ名           | 平均時間 | 最大時間 | 最小時間 | 標準偏差 |
| ------------------ | -------- | -------- | -------- | -------- |
| Test (desktop) (1) | Xm       | Xm       | Xm       | X        |
| ...                | ...      | ...      | ...      | ...      |

### ステップ2: テスト数の確認

```bash
# テストファイル数
find apps/desktop/src -name "*.test.ts" -o -name "*.test.tsx" | wc -l

# テストケース概数
grep -r "describe\|test\|it(" apps/desktop/src --include="*.test.ts" | wc -l
```

### ステップ3: 最適化目標の設定

| 項目               | 現状    | 目標     | 根拠                         |
| ------------------ | ------- | -------- | ---------------------------- |
| 各シャード実行時間 | 19-20分 | 10分以下 | 開発者待機時間の半減         |
| 全体CI時間         | 22分    | 12分以下 | ランチ前にフィードバック取得 |
| カバレッジ         | 80%+    | 80%+     | 品質基準維持                 |

### ステップ4: 受け入れ基準の定義

AC-1〜AC-6、NFR-1〜NFR-3 をindex.mdに記載済み。
