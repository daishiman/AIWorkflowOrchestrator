# 受け入れ基準

## 作成日

2026-02-02

## 機能要件の受け入れ基準

### AC-1: シャード実行時間

- **基準**: 各test-desktopシャードの実行時間が10分以下
- **検証方法**: CI実行ログで確認
- **判定**: 全16シャードが10分以下で完了

### AC-2: 全体CI時間

- **基準**: 全体CI時間が12分以下
- **検証方法**: GitHub Actions Summary確認
- **判定**: ワークフロー開始から終了まで12分以内

### AC-3: テスト成功

- **基準**: 既存テストが全てPASS
- **検証方法**: CI実行結果
- **判定**: 全テストジョブがsuccess

### AC-4: mainブランチカバレッジ計測

- **基準**: mainブランチマージ時にカバレッジが計測される
- **検証方法**: Codecovレポート確認
- **判定**: カバレッジデータがCodecovにアップロードされている

### AC-5: PRカバレッジスキップ

- **基準**: PR時はカバレッジ計測がスキップされる
- **検証方法**: CI実行ログ確認
- **判定**: `--coverage`フラグなしでテスト実行されている

### AC-6: shared packageキャッシュ

- **基準**: shared packageビルドがキャッシュされる
- **検証方法**: "Cache hit"ログ確認
- **判定**: 2回目以降のCI実行で"Cache hit"表示

### AC-7: カバレッジ達成

- **基準**: カバレッジが80%以上
- **検証方法**: ローカル・CIで確認
- **判定**: Line Coverage >= 80%

### AC-8: ローカル環境動作

- **基準**: better-sqlite3がローカルで正常動作
- **検証方法**: テスト実行で確認
- **判定**: アーキテクチャ不一致エラーなし

## 非機能要件の受け入れ基準

### NFR-1: カバレッジ閾値維持

- **基準**: 既存のカバレッジ閾値（Line 80%+）が維持される
- **検証方法**: Codecovレポート
- **判定**: 80%以上を維持

### NFR-2: CI信頼性維持

- **基準**: Flaky testの増加なし
- **検証方法**: 複数回実行で確認
- **判定**: 3回連続で同一結果

### NFR-3: キャッシュヒット率

- **基準**: キャッシュヒット率が80%以上（依存関係未変更時）
- **検証方法**: CI実行ログ分析
- **判定**: キャッシュヒット率 >= 80%
