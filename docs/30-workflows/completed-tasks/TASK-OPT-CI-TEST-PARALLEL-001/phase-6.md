## 目的

Phase 5の実装に対して追加の検証シナリオを実行し、変更の安定性を確認する。

## 実行タスク

### Task 1: PRトリガーでのCI実行テスト

**検証手順**:

1. 変更をプッシュしてPRを作成
2. CIが正常に開始されることを確認
3. 16シャードが並列実行されることを確認
4. カバレッジ計測がスキップされることを確認

**確認項目**:

| 項目           | 期待結果 | 実際結果 |
| -------------- | -------- | -------- |
| シャード数     | 16       | [ ]      |
| カバレッジ計測 | スキップ | [ ]      |
| 全テストPASS   | 成功     | [ ]      |

### Task 2: キャッシュ動作テスト

**検証手順**:

1. 初回CI実行でキャッシュが保存されることを確認
2. 2回目CI実行でキャッシュがヒットすることを確認
3. shared packageに変更を加えてキャッシュが無効化されることを確認

**確認項目**:

| 項目                     | 期待結果                 | 実際結果 |
| ------------------------ | ------------------------ | -------- |
| 初回: キャッシュ保存     | "Cache saved"ログ        | [ ]      |
| 2回目: キャッシュヒット  | "Cache hit"ログ          | [ ]      |
| 変更後: キャッシュ無効化 | キャッシュミス、再ビルド | [ ]      |

### Task 3: パフォーマンス測定

**測定手順**:

1. 3回以上のCI実行でデータを収集
2. 各シャードの実行時間を記録
3. 全体CI時間を記録

**測定項目**:

| 項目               | 目標値   | 測定値（1回目） | 測定値（2回目） | 測定値（3回目） |
| ------------------ | -------- | --------------- | --------------- | --------------- |
| 最長シャード時間   | 10分以下 | [ ]             | [ ]             | [ ]             |
| 全体CI時間         | 12分以下 | [ ]             | [ ]             | [ ]             |
| キャッシュヒット率 | 80%以上  | [ ]             | [ ]             | [ ]             |

### Task 4: Flaky testの検出

**検証手順**:

1. 同じコミットで3回以上CIを実行
2. 結果が一貫していることを確認
3. 不安定なテストがないことを確認
