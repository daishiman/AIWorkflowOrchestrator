## 3. MINOR 指摘一覧

### MINOR-01: RAG state の Main authority 昇格の具体的 IPC 未定義

| 項目   | 内容                                                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 箇所   | design-summary.md Section 1.1 / contract-matrix.md                                                                                            |
| 指摘   | RAG state を Main authority に昇格すると設計判定されているが、具体的な IPC チャンネル名とリクエスト/レスポンス形式が contract-matrix に未定義 |
| 影響   | Phase 5 実装時に IPC 契約の追加設計が必要になる                                                                                               |
| 対応   | Phase 5 実装計画で RAG state の IPC 設計を補完する                                                                                            |
| 深刻度 | MINOR（設計方針は正しいが、契約の具体化が不足）                                                                                               |

### MINOR-02: apiKey.validate() のデバウンス方針が未決定

| 項目   | 内容                                                                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 箇所   | requirements-definition.md GAP-07 / contract-matrix.md                                                                                                      |
| 指摘   | apiKey.validate() の入力ごと IPC 呼び出し問題が GAP-07 として特定されているが、デバウンス方針（クライアント側 vs サーバー側、インターバル値）が設計に未反映 |
| 影響   | 連続入力時の IPC 通信過多が放置される                                                                                                                       |
| 対応   | Phase 5 実装計画で Renderer 側デバウンス（300ms）を標準化する                                                                                               |
| 深刻度 | MINOR（機能的問題ではなく性能最適化の範囲）                                                                                                                 |

### MINOR-03: AccountSection の header 統合が既存レイアウトと競合する可能性

| 項目   | 内容                                                                                                                                                                      |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 箇所   | ui-ux-realization.md Section 1.2                                                                                                                                          |
| 指摘   | AccountSection を削除して header に統合する設計だが、現行の header にログイン/プロフィール情報を収容するスペースが確保されていない。App Shell Header との責務分離も未定義 |
| 影響   | Phase 5 実装時に header レイアウトの再設計が必要になる可能性                                                                                                              |
| 対応   | Phase 5 実装計画で header 統合を段階的に行う（初回は AccountSection を末尾移動のみ、header 統合は後続タスク化）                                                           |
| 深刻度 | MINOR（レイアウト変更の実装詳細の範囲）                                                                                                                                   |
