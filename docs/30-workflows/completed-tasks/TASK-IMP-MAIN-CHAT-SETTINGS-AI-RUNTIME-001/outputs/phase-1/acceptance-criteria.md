## 1. 機能受入基準

### AC-1: State Authority 整理

| 基準                                                                                             | 検証方法                                         |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| provider / model / prompt / auth key 保存状態 / health / RAG state の authority が列挙されている | requirements-definition.md Section 2 で確認      |
| 全 authority が Main (Source of Truth) に配置されていること                                      | Authority マトリクスで Main 列が fully populated |
| Renderer が独自の runtime 判定ロジックを持たないこと                                             | local 判定禁止原則の遵守確認                     |

### AC-2: Gap/Drift の設計割り当て

| 基準                                                               | 検証方法                                         |
| ------------------------------------------------------------------ | ------------------------------------------------ |
| Main Chat / Settings 間の drift 箇所が後続設計へ割り当てられている | requirements-definition.md Section 3 で確認      |
| GAP-01〜07 の全件が Phase 2 設計または後続タスクへ割り当て済み     | Gap テーブルの全行に対応先が記載されていること   |
| DRIFT-1〜4 の全件が Phase 2 設計または後続タスクへ割り当て済み     | Drift テーブルの全行に対応先が記載されていること |

## 2. UI/UX 受入基準

### AC-3: 設定画面改善（2026-03-13 レビュー反映）

| 基準                                                                                    | 検証方法                                            |
| --------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 認証方式カード変更時に状態語彙 `ready` / `blocked` / `unavailable` が遅延なく更新される | authMode.set 後の UI 状態遷移テスト                 |
| APIキー保存/削除後に上位 Access Card が矛盾なく更新される                               | auth-key:set / auth-key:delete の end-to-end テスト |
| Provider APIキー一覧の登録状態と上位 Access Card の状態が同期している                   | api-key:list 後の UI 整合性テスト                   |

### AC-4: silent fallback 禁止

| 基準                                                                  | 検証方法                                 |
| --------------------------------------------------------------------- | ---------------------------------------- |
| API key 不足時に AI_CHAT が見かけ上の成功を返さないこと               | fail-fast テスト（API key なし送信）     |
| health check 失敗時に Main Chat が無言でフォールバックしないこと      | disconnected 状態での Guidance 表示確認  |
| Renderer が独自 mode 判定を行っていないこと（access matrix 消費のみ） | コードレビュー（local 判定パターン検出） |
