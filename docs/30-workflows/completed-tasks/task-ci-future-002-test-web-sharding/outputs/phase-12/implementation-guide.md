# 実装ガイド: test-web シャード化

タスクID: TASK-CI-FUTURE-002
作成日: 2026-04-15

---

## Part 1: 中学生レベルの説明

### なぜ必要だったのか

プログラムが正しく動くか確かめる「テスト」という作業があります。
テストが増えると、1 台のコンピューターで全部やると時間がかかります。

これは、運動会のリレーに例えると分かりやすいです。
**1 人で 400 メートル走るより、4 人で 100 メートルずつ走る方が速い**のと同じです。

### シャード（shard）って何？

「シャード」とは「かけら」「分割した一部分」という意味です。
テストを複数のかけら（シャード）に分けて、それぞれを別々のコンピューターで同時に実行します。

### 今回やったこと

- **今まで**: `test-web`（ウェブアプリのテスト）は CI に存在しなかった
- **今後**: `test-web` を 2 台のコンピューターで並列実行するようにした
- **ただし**: GitHub の無料プランでは同時に使えるコンピューターが **20 台まで** という制限がある

そこで、デスクトップアプリのテスト（`test-desktop`）を **17 台 → 15 台** に減らして、
空いた 2 枠を `test-web` に割り当てました。合計は変わらず **20 台** のままです。

## Part 2: 技術者向け詳細

### Vitest シャーディングの仕組み

Vitest は `--shard=N/M` オプションを標準サポートしている。

```bash
# M 分割の N 番目シャードを実行
vitest run --shard=1/2   # 全テストファイルの前半を実行
vitest run --shard=2/2   # 全テストファイルの後半を実行
```

Vitest はテストファイルのリストをハッシュで決定論的に分割する。
`vitest.config.ts` への設定追加は不要（標準機能）。

### GitHub Actions matrix 戦略

```yaml
strategy:
  fail-fast: false
  matrix:
    shard: [1, 2]
```

`matrix.shard` に `[1, 2]` を指定すると、GitHub Actions が 2 つの並列ジョブを生成する。
各ジョブ内で `${{ matrix.shard }}` を参照して vitest のシャード引数を動的に生成する。

### シャード数の計算式

```
追加可能 test-web シャード数 = GitHub Free Tier 上限 - 既存ジョブ並列数
                             = 20 - (test-desktop + typecheck + test-shared + e2e-desktop)
                             = 20 - (15 + 1 + 1 + 1)
                             = 2
```

### 変更対象ファイルと変更内容

| ファイル                        | 変更種別 | 変更内容                                                                                                                                      |
| ------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `.github/workflows/ci.yml`      | 修正     | ① test-desktop: 17→15 シャード ② test-desktop コマンド: `/17`→`/15` ③ test-web ジョブ追加（2 シャード） ④ build ジョブ needs に test-web 追加 |
| `apps/backend/vitest.config.ts` | 変更なし | --shard は設定不要（Vitest 標準機能）                                                                                                         |

### 並列数内訳と計算根拠

| ジョブ       | 変更前 | 変更後 | 差分  |
| ------------ | ------ | ------ | ----- |
| test-desktop | 17     | 15     | -2    |
| test-web     | 0      | 2      | +2    |
| typecheck    | 1      | 1      | 0     |
| test-shared  | 1      | 1      | 0     |
| e2e-desktop  | 1      | 1      | 0     |
| **合計**     | **20** | **20** | **0** |

### 実行時間ベースライン比較

| メトリクス                    | 変更前        | 変更後（推定）        |
| ----------------------------- | ------------- | --------------------- |
| test-web 実行時間             | CI ジョブ不在 | < 2 分（テスト 1 件） |
| test-desktop 最長シャード時間 | ベースライン  | +10〜15%（許容範囲）  |

### 将来のシャード数変更手順

test-web のテストが増えてシャード数を増やしたい場合：

```yaml
# ci.yml の test-desktop と test-web を同時に変更する
# 合計が 20 以内になるよう調整すること

# 例: test-web を 3 シャードにする場合
test-desktop: shard: [1..14]  # 17→14 (−3)
test-web:     shard: [1, 2, 3]  # 0→3 (+3)
# 合計: 14+3+1+1+1 = 20 ✅
```
