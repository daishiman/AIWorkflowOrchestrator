# Phase 2 証跡取得計画

## 1. 証跡フォーマット（SubAgent-DESIGN-EVIDENCE）

| 項目         | 必須 | 記録例                                         |
| ------------ | ---- | ---------------------------------------------- |
| 反映元証跡   | 必須 | `task-050-ui-00-ui-design-foundation.md:842`   |
| 反映先証跡   | 必須 | `task-058a-ui-03-agent-view-enhancement.md:19` |
| 監査時刻     | 必須 | `2026-03-05T11:20:00+09:00`                    |
| 担当SubAgent | 必須 | `SubAgent-IMP-SCREENS`                         |
| コマンド     | 必須 | `rg -n "UX言語" <file>`                        |
| 補足         | 任意 | `同義語: ダッシュボード→ホーム`                |

## 2. 証跡収集手順（番号固定）

1. 反映元IDを選択（`SRC-T*`）。
2. 対象仕様書グループをSubAgentに割当。
3. `rg -n` で該当語句を抽出（章名/要件語）。
4. `path:line` をマトリクスへ記録。
5. 判定を `反映済み/要追記/対象外` で入力。
6. `要追記` は修正提案と優先度を必須入力。
7. 統合SubAgentが語彙統一・重複除去を実施。

## 3. 並列実行の設計

| ワークストリーム             | 担当SubAgent                                  | 並列可否 |
| ---------------------------- | --------------------------------------------- | -------- |
| 分割仕様監査（00-1〜00-4）   | SubAgent-IMP-TOKENS/ATOMS/MOLECULES/ORGANISMS | 並列     |
| 画面仕様監査（057〜061/030） | SubAgent-IMP-SCREENS                          | 並列     |
| 判定統合                     | SubAgent-IMP-INTEGRATOR                       | 直列     |

## 4. 例外・エラー処理

| ケース     | 処理                                       |
| ---------- | ------------------------------------------ |
| リンク切れ | `要追記(high)` として `finding-log` に起票 |
| 章名不一致 | 同義語マッピングを追加して再検索           |
| 証跡不足   | 再検索コマンドを追記して再監査             |

## 5. 証跡品質ゲート

- 1レコードにつき `source_evidence` と `target_evidence` の両方が必須。
- `path:line` 形式でない証跡は受理しない。
- `audited_at` 未記入レコードは無効。
