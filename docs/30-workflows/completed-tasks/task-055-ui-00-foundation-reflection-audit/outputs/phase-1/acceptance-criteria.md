# Phase 1 受け入れ基準: 判定ルール・証跡要件

## 1. 判定状態（3状態固定）

| 判定     | 定義                                             | 必須証跡                                           |
| -------- | ------------------------------------------------ | -------------------------------------------------- |
| 反映済み | 反映元要件が反映先仕様へ明示記載され、矛盾がない | 反映元 `path:line` + 反映先 `path:line` + 判定理由 |
| 要追記   | 反映元要件の一部または参照導線が不足             | 不足箇所 `path:line` + 追記案 + 影響範囲           |
| 対象外   | 反映元要件の適用対象外で、理由が合理的           | 対象外理由 + 適用外根拠 `path:line`                |

## 2. 証跡必須項目（監査レコード単位）

1. `audit_id`: 反映元監査ID（例: `SRC-T5D`）
2. `target_spec`: 反映先仕様書パス
3. `source_evidence`: 反映元証跡（`path:line`）
4. `target_evidence`: 反映先証跡（`path:line`）
5. `judgement`: 判定（反映済み/要追記/対象外）
6. `subagent`: 担当SubAgent
7. `audited_at`: JST時刻（ISO8601）
8. `command_log`: 使用コマンド（`rg -n ...` など）

## 3. 失敗条件（Red条件）

| Red-ID | 失敗条件                 | 検出方法                            |
| ------ | ------------------------ | ----------------------------------- |
| RED-01 | 反映元IDに対し判定未記入 | マトリクス列 `judgement` 空欄検出   |
| RED-02 | 証跡の `path:line` 不足  | `:` を含まない証跡列を検出          |
| RED-03 | 参照先ファイル不存在     | `test -f <path>` 失敗               |
| RED-04 | 判定語彙ゆれ             | `反映済み/要追記/対象外` 以外を検出 |
| RED-05 | SubAgent未記録           | `subagent` 列空欄検出               |

## 4. 合格条件（Phase 1 完了判定）

- 反映元監査ID `SRC-T1/T2/T3/T4/T5/T5B/T5C/T5D/T6` が全件定義済み。
- 反映先仕様（分割4本 + 画面10本）が固定されている。
- 判定3状態の定義が固定され、Red条件が明文化されている。
- 並列/直列作業が分離され、SubAgent割当が重複なし。

## 5. Gate入力（Phase 3 レビュー向け）

- 判定ロジックの妥当性レビュー観点: `RED-01`〜`RED-05`
- 参照導線レビュー観点: `00-1-design-tokens.md` の正本参照整合
- 品質レビュー観点: a11y/レスポンシブ/UX文言の証跡密度
