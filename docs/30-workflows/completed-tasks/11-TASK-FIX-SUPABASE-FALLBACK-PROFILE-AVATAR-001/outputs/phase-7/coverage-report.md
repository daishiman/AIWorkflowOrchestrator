## v8 カバレッジプロバイダの制約事項

`index.ts` のv8カバレッジが0%と報告される原因:

1. **モック化された依存が極めて多い（40+モジュール）**: テストの性質上、`index.ts` が依存する全ハンドラモジュールをモック化する必要がある。v8プロバイダはモックされたモジュール内のコード実行をインストルメントできない場合がある
2. **P41関連**: v8カバレッジプロバイダのインライン関数カウントにより、`async () => notConfiguredResponse` のようなインライン arrow function が個別にカウントされる

### 機能カバレッジの実証

v8レポート値は0%だが、テストは以下を実証済み:

- `registerAllIpcHandlers()` を実行し、`ipcMain.handle` が呼ばれている（L746-787のコードが実行されている）
- Supabase未設定時: Profile 11チャンネル + Avatar 3チャンネルのフォールバックが登録される
- Supabase設定済み時: フォールバックが登録されない（T-I2）
- 全フォールバックハンドラの戻り値構造（success, error.code, error.message, dataなし）を検証
- channels.ts の定数との同期を回帰テストで保証
