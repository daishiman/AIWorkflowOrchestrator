## 目的

Phase 2 設計書の妥当性を、要件整合性・後方互換性・型安全性・テスタビリティの 4 軸でレビューし、Phase 4（テスト作成）への移行可否を判定する。

## レビュー観点

### R-1: 要件整合性

| チェック項目                                                         | 検証方法                                             | 判定基準                        |
| -------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------- |
| UiState 8 値が ui-ux-realization.md の画面状態マトリクスと一致するか | マトリクスの 9 行（running 含む）と突合              | 全値が 1:1 対応                 |
| Contract Matrix 32 セルが Phase 1 定義と一致するか                   | Phase 1 表と Phase 2 CTA マッピングを突合            | 全セルの primary/secondary 一致 |
| 到達不能セルが Phase 1 の `-` マークと一致するか                     | Phase 1 表の `-` セルと Phase 2 到達不能テーブル突合 | 全 `-` セルが網羅               |
| AC-1〜AC-7 が設計で充足可能か                                        | 各 AC に対応する設計セクション特定                   | 全 AC にマッピング存在          |

**注意**: ui-ux-realization.md は `running` を含む 9 値を定義しているが、本タスクでは `running` を除外し `streaming` に統合する。これは `running` が `streaming` のサブセットであり、UI 表示上は同じ CTA（stop/abort）を持つためである。この判断が Phase 1 要件と矛盾しないことを確認する。

### R-2: 後方互換性

| チェック項目                                              | 検証方法                                                  | 判定基準                |
| --------------------------------------------------------- | --------------------------------------------------------- | ----------------------- |
| 既存 3 値テスト（CC-1〜CC-5）が設計変更後も PASS するか   | overload 1 の戻り値型が UiStateResult であることを確認    | 既存テスト影響なし      |
| overload 2 が 3 値のみ返す形で維持されるか                | D-6 セクションの設計確認                                  | 3 値のみ返却            |
| CapabilityContext の新フィールドが optional であるか      | D-2 セクションの型定義確認                                | 全新フィールド optional |
| 既存の switch 文 default ケースで新値が安全に処理されるか | `grep -rn "switch.*uiState" apps/ packages/` で全箇所確認 | default fallback 安全   |

### R-3: 型安全性

| チェック項目                                                               | 検証方法                                              | 判定基準                    |
| -------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------- |
| `UI_STATE_VALUES` と `UiState` 型が一致するか                              | `as const satisfies` パターン確認                     | コンパイル時保証            |
| `Record<UiState, ...>` で網羅チェックが効くか                              | 8 値全てに Record エントリが必要                      | TypeScript コンパイルエラー |
| `HandoffGuidance` import が正しいか                                        | `packages/shared/src/types/handoff.ts` の export 確認 | import 解決可能             |
| 到達不能セルの実行時ガードが `console.warn` + safe fallback で実装されるか | Phase 2 D-5 ガード処理方針と一致確認                  | runtime guard 設計が明確    |

### R-4: テスタビリティ

| チェック項目                                               | 検証方法                           | 判定基準       |
| ---------------------------------------------------------- | ---------------------------------- | -------------- |
| resolveUiState() が pure function であるか                 | 外部依存（IO, Date, Random）の確認 | 副作用なし     |
| resolveCtaContract() が pure function であるか             | 同上                               | 副作用なし     |
| 評価優先順位の各分岐がテスト可能か                         | 各分岐に到達するための入力条件特定 | 全分岐到達可能 |
| 到達不能セルのガードが console.warn のみか（テスト容易性） | ガード処理の設計確認               | mock 可能      |

### R-5: Phase 4 への引き継ぎ確認（前向きチェック）

| チェック項目                                                             | 検証方法                                                               | 判定基準                         |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- | -------------------------------- |
| Phase 2 の型定義が Phase 4 テストに正確に引き継がれるか                  | D-1 の UiState 8値リストを Phase 4 テスト設計表と突合                  | 値セットが 1:1 一致              |
| Phase 2 の CapabilityContext フィールドが Phase 4 テストで使用されるか   | D-2 のフィールド名と Phase 4 テストの変数名を突合                      | フィールド名が一致               |
| Phase 2 の評価優先順位が Phase 4 テストケース順序に反映されるか          | D-3 の P1-P8 と Phase 4 テストケースの入力パターンを突合               | 全優先順位がテストされる         |
| Phase 2 D-5 到達不能セル数と Phase 4 `unreachableCells` 配列が一致するか | D-5 テーブル行数と Phase 4 Task 4 配列要素数を突合                     | セル数が完全一致                 |
| Phase 1 Contract Matrix `-` セルと Phase 2 D-5 テーブルが整合するか      | Phase 1 表の `-` マークを集計し D-5 テーブルと突合（P44 ドリフト防止） | `-` セルと到達不能テーブルが一致 |
