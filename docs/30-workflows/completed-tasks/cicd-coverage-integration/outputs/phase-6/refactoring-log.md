## 3. 見送ったリファクタリング

### 3.1 共通ステップの切り出し（Composite Action）

**検討内容**: checkout/setup-pnpm/setup-nodeを再利用可能なComposite Actionに切り出し

**見送り理由**:

1. 現在は単一ワークフローファイルで完結している
2. 共通ステップは既にGitHub公式Actionを使用している
3. 過度な抽象化は保守性を低下させる可能性がある
4. 現状で十分に可読性が高い

**将来の検討**: 複数のワークフローでsetup処理を共有する必要が生じた場合に再検討

### 3.2 環境変数の集約

**検討内容**: NODE_VERSIONなどをワークフローレベルのenv に定義

**見送り理由**:

1. Node.jsバージョンは全ジョブで同じ値（"22"）を使用
2. しかし、各ジョブで明示的に指定されている方が可読性が高い
3. 将来的にジョブごとに異なるバージョンを使用する可能性もある

## 5. 推奨事項

### 5.1 現状維持

現在の実装は以下の理由から**リファクタリング不要**と判断:

1. **可読性**: コメント・ステップ名が明確
2. **保守性**: 構造が分かりやすく、変更が容易
3. **効率性**: キャッシュ・並列実行が適切
4. **セキュリティ**: Secrets管理が適切

### 5.2 将来の改善検討項目

以下は現時点では不要だが、将来的に検討する価値がある:

1. **複数ワークフローの共通化**: 他のワークフローが追加された際に、共通ステップをComposite Actionに切り出し
2. **Matrix Strategy**: 複数のNode.jsバージョンでテストする必要が生じた場合
3. **カスタムAction**: Codecovアップロード処理を再利用可能なActionに切り出し
