## 実行タスク

### タスク1: 設計レビュー

**目的**: 設計方針が品質基準・整合性を満たしているか確認する

**実行手順**:

1. `outputs/phase-2/label-design.md` を読み、以下の観点でレビューする:
   - 追記形式が既存の `> 役割:` 記述スタイルと統一されているか
   - 4ファイル全てへの追記が設計されているか
   - `task-workflow.md` インデックスの「区分」列の値が全エントリを網羅しているか

2. `outputs/phase-2/responsibility-design.md` を読み、以下の観点でレビューする:
   - 3関数の実装ファイルが正確か（`verifySkill`/`verifyAndImproveLoop` は Facade、`verify` は Engine）
   - 返却値の型名が `@repo/shared` の定義と一致しているか
   - 責務の記述が実装と乖離していないか

3. `outputs/phase-2/change-plan.md` を読み、以下の観点でレビューする:
   - 変更対象の網羅性（4ファイル + 責務分離追記先）
   - 既存リンクへの影響が評価されているか
   - Check ID 体系（19件）への影響が評価されているか

**期待される成果物**:

- 設計レビュー結果（`outputs/phase-3/design-review-result.md`）

## レビュー結果判定

| 判定     | 条件                               | 次のアクション             |
| -------- | ---------------------------------- | -------------------------- |
| PASS     | 全レビュー観点で問題なし           | Phase 4 へ進行             |
| MINOR    | 軽微な表現の不統一などの指摘あり   | 指摘対応後、Phase 4 へ進行 |
| MAJOR    | ラベル形式不整合・責務誤記などあり | Phase 2 へ戻り設計修正     |
| CRITICAL | 要件との矛盾・NFR 違反など         | Phase 1 へ戻りユーザー確認 |
