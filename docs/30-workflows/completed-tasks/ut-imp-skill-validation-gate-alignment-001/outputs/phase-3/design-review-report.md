#### テストケース 2: `aiworkflow-requirements` の description Anchors 未記載

- Warning 内容: `Description does not contain 'Anchors' section`
- Q1: 既知の Warning か? → YES（Phase 1 で記録済み）

**補足**: 本 Warning は Phase 1 で「要監視」に分類されていた。Phase 2 の判定フローでは、初回実行時は「前回記録なし → 全て NO → Q3 へ」のルートとなり、Q3「構造影響か」で NO（description の Anchors/Trigger 未記載は判定基準リストに含まれない）となるため「要監視」に分類される。これは Phase 1 の分類と一致する。ただし、2回目以降の実行で前回記録がある場合は Q1 → YES → Q2 のルートとなり、件数横ばいなら「許容」に昇格する。この運用フローは意図的であり、初回は「要監視」、2回目以降で件数横ばいなら「許容」への自然な移行パスを提供する設計である。

**判定修正**: 初回実行の場合を再検証すると:

- Q1: 既知の Warning か? → NO（前回記録なし。初回実行時は全て NO として扱う）
- Q3: 構造影響か? → NO（description の Anchors 未記載は判定基準リストに「NO」として明記）
