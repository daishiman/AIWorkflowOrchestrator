## 軸1: 検証項目の差異

### .js にあって .py にない項目

| #   | 検証項目                                                 | 判定レベル | 影響                                   |
| --- | -------------------------------------------------------- | ---------- | -------------------------------------- |
| 1   | SKILL.md の行数制限（500行以内）                         | Error      | 大規模スキルの検出                     |
| 2   | references/ 内ファイルが SKILL.md からリンクされているか | Warning    | 参照リンク切れの検出（大量警告の原因） |
| 3   | agents/\*.md が Task仕様書テンプレに準拠しているか       | Warning    | エージェント品質の担保                 |
| 4   | description に Anchors / Trigger が含まれているか        | Warning    | SKILL.md 品質                          |
| 5   | 不要な補助ドキュメント（README.md等）の存在チェック      | Error      | ファイル構造の整合性                   |
| 6   | name がディレクトリ名と一致するか                        | Warning    | 命名整合性                             |

### .py にあって .js にない項目

| #   | 検証項目                                                          | 判定レベル | 影響                     |
| --- | ----------------------------------------------------------------- | ---------- | ------------------------ |
| 1   | frontmatter の予期しないキーの検出（allowed_properties チェック） | Error      | 不正フィールドの混入防止 |
| 2   | name の先頭/末尾ハイフン、連続ハイフンの検証                      | Error      | 命名規則の厳密チェック   |

### 共通項目

| #   | 検証項目                            | .js 判定 | .py 判定 | 差異 |
| --- | ----------------------------------- | -------- | -------- | ---- |
| 1   | SKILL.md の存在                     | Error    | Fail     | なし |
| 2   | YAML frontmatter の有効性           | Error    | Fail     | なし |
| 3   | name フィールドの存在               | Error    | Fail     | なし |
| 4   | name がハイフンケース（max 64文字） | Error    | Fail     | なし |
| 5   | description フィールドの存在        | Error    | Fail     | なし |
| 6   | description が 1024 文字以内        | Error    | Fail     | なし |
| 7   | description に角括弧(<>)がないか    | Error    | Fail     | なし |

## 軸2: 判定粒度の差異

| 観点           | quick_validate.js                  | quick_validate.py  |
| -------------- | ---------------------------------- | ------------------ |
| 判定レベル     | 3段階: Pass / Warning / Error      | 2段階: Pass / Fail |
| Warning 概念   | あり（非致命的な問題を通知）       | なし（Fail のみ）  |
| 合格判定基準   | Error 0件で合格                    | Fail なしで合格    |
| Warning の扱い | 出力に表示するが合格には影響しない | 概念なし（未実装） |

**重要**: この判定粒度の差異が、Phase 12 での判断コスト増大の根本原因。`.py` では Warning がないため、`.js` で 151 件の Warning が出力されても「合格」だが、オペレーターは Error と Warning を目視で区別する必要がある。

## 軸3: 出力フォーマットの差異

| 観点       | quick_validate.js                                                   | quick_validate.py                               |
| ---------- | ------------------------------------------------------------------- | ----------------------------------------------- |
| 通常出力   | サマリ行（N項目パス, Nエラー, N警告）                               | 単一行（"Skill is valid!" or エラーメッセージ） |
| --verbose  | パスした項目一覧 + 警告一覧 + エラー一覧                            | 未対応（引数エラーになる）                      |
| 出力形式   | テキスト（構造化されたセクション区切り）                            | テキスト（1行のみ）                             |
| 終了コード | 0(成功), 1(一般エラー), 2(引数エラー), 3(ファイル不在), 4(検証失敗) | 0(成功), 1(失敗/使用法エラー)                   |
| JSON出力   | 未対応                                                              | 未対応                                          |

## 軸4: 実行環境の差異

| 観点               | quick_validate.js                  | quick_validate.py                       |
| ------------------ | ---------------------------------- | --------------------------------------- |
| ランタイム         | Node.js（ES Modules対応必須）      | Python 3（PyYAML必須）                  |
| パス指定           | 相対パス可                         | 相対パス可                              |
| CLIオプション      | `--verbose`, `-h`, `--help`        | 位置引数のみ（オプション未対応）        |
| 引数バリデーション | 未指定時にヘルプ表示 + exit code 2 | 未指定時に Usage表示 + exit code 1      |
| バージョン管理     | git管理（repo内）                  | git管理外（.codex配下、システムレベル） |
| 更新手順           | PR経由で更新可能                   | Codex側の更新が必要（運用手順不明）     |

**問題点**:

1. 同一ワークフロー内で `.py` と `.js` が混在している
2. `.js` のパスが `ObsidianMemo` プロジェクトを指しており、本repo内のスクリプトを参照していない
3. `.py` は `--verbose` オプション未対応だが、spec-update-workflow.md では `--verbose` 付きで記載されている

## 結論

| 軸               | 統一方針への示唆                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 検証項目         | `.js` のほうが項目数が多く包括的。`.py` の unexpected-keys チェックは `.js` への移植が望ましい |
| 判定粒度         | `.js` の 3段階判定を正本とし、Warning 運用ルールを整備すべき                                   |
| 出力フォーマット | `.js` の構造化出力を正本とし、Phase 12 でのパース容易性を優先                                  |
| 実行環境         | `.js` はrepo内でバージョン管理可能であり、保守性で優位                                         |
