## 2. カバレッジ計測結果

### 2.1 コードカバレッジ（v8プロバイダ）

v8 カバレッジプロバイダによる計測を実施したが、テスト対象ファイルのカバレッジは **0%** と報告された。

```
File               | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
-------------------|---------|----------|---------|---------|-------------------
quick_validate.js  |       0 |        0 |       0 |       0 | 1-289
utils.js           |       0 |        0 |       0 |       0 | 1-341
```

#### 0% の原因分析

テストは `execSync` を使用してサブプロセスとして `quick_validate.js` を実行している。v8 カバレッジプロバイダはテストプロセス（Vitest Worker）内の `import` / `require` で読み込まれたモジュールのみを計測対象とするため、子プロセスで実行されるスクリプトのカバレッジは計測されない。

これはテストアーキテクチャに起因する制約であり、以下の理由から現在の設計が正当である:

1. **CLIスクリプトの統合テスト**: `quick_validate.js` はCLIツールであり、`node quick_validate.js <path>` 形式で実行することが本来の使用方法。`execSync` による統合テストは実際の使用パターンに合致する
2. **終了コード検証**: プロセスの終了コード（0/1/2/3/4）は `execSync` 経由でのみ検証可能
3. **stdout/stderr 出力検証**: 出力フォーマットの検証は子プロセスの標準出力を通じて行う必要がある

#### P41 影響分析

P41（v8カバレッジプロバイダのインライン関数カウント）の影響は、本テストスイートでは該当しない。テスト対象がReactコンポーネントやIPCハンドラではなく、CLIスクリプトの外部実行テストであるため、インライン関数のカウント問題は発生しない。ただし、仮にモジュールを直接 `import` する単体テスト方式に移行した場合、`QuickValidationResult` クラスの `addError`/`addWarning`/`addPassed` メソッドや `parseFrontmatter` 内の `for` ループコールバックでP41パターンが発生する可能性がある。
