# Phase 9: リスク登録簿

> タスクID: TASK-IMP-TRANSCRIPT-TO-CHAT-PROVENANCE-LINKAGE-001
> 確定日: 2026-03-22

## 目的

設計完了時点での残余リスクを登録し、各リスクの緩和策と `implementation_ready` 判定条件を定義する。

---

## リスク評価基準

| 影響度 | 定義                                           |
| ------ | ---------------------------------------------- |
| HIGH   | ユーザーデータ損失・セキュリティ侵害・機能不全 |
| MEDIUM | UX劣化・パフォーマンス問題・開発効率の低下     |
| LOW    | コード品質・保守性の問題                       |

| 発生確率 | 定義                         |
| -------- | ---------------------------- |
| HIGH     | 実装フェーズで確実に直面する |
| MEDIUM   | 直面する可能性が50%以上      |
| LOW      | 直面する可能性が低い         |

---

## 登録リスク一覧

### R-01: IPC Contract Drift（優先度: HIGH）

| 項目     | 内容                                                                                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | Main ProcessのIPCハンドラとPreload側の呼び出し形式が乖離する（P44/P45パターン）                                                                                               |
| 影響度   | HIGH                                                                                                                                                                          |
| 発生確率 | MEDIUM                                                                                                                                                                        |
| 緩和策   | Phase 2設計書のIPC contract定義を実装の唯一の真実とする。実装後に `grep -rn "transcript" apps/desktop/src/preload/` でPreload側の呼び出しを検索し、ハンドラ定義と一致確認する |
| 受入条件 | V-C1~V-C8の全ContractテストがPASS                                                                                                                                             |

---

### R-02: WorkspaceChatMessage型の破壊的変更（優先度: HIGH）

| 項目     | 内容                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | `WorkspaceChatMessage` に `transcriptProvenance` を追加する際に、既存の永続化データ（SQLite）との非互換が発生する                       |
| 影響度   | HIGH                                                                                                                                    |
| 発生確率 | MEDIUM                                                                                                                                  |
| 緩和策   | フィールドをオプショナル（`?`）にすることでマイグレーション不要とする。既存レコードのNULL/undefined処理をRendererとMain両方でガードする |
| 受入条件 | 既存チャットデータを読み込んだ際に `transcriptProvenance` が `undefined` になること（エラーにならないこと）                             |

---

### R-03: 大容量コンテンツによるIPC負荷（優先度: MEDIUM）

| 項目     | 内容                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| リスク   | OP-3（セッションを貼り付ける）でセッション全体（数万文字）を `originalContent` に格納した場合、IPC経由の転送でパフォーマンスが劣化する           |
| 影響度   | MEDIUM                                                                                                                                           |
| 発生確率 | HIGH                                                                                                                                             |
| 緩和策   | `originalContent` に文字数上限（推奨: 10,000文字）を設け、超過分は切り捨ててUI上で「...[省略]」を表示する。M-3指摘の上限定量化対応として実装する |
| 受入条件 | 10,000文字超のセッションを貼り付けた際に、cutoff表示が正しく機能しパフォーマンスが許容範囲内（操作レスポンス300ms以内）であること                |

---

### R-04: 既存コンポーネントとの名前衝突（優先度: LOW）

| 項目     | 内容                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | `TranscriptPanel`・`TranscriptProvenanceChip` という名前が既存コンポーネントと衝突する可能性がある                                                            |
| 影響度   | LOW                                                                                                                                                           |
| 発生確率 | LOW                                                                                                                                                           |
| 緩和策   | 実装開始前に `grep -rn "TranscriptPanel\|TranscriptProvenanceChip" apps/desktop/src/renderer/` で既存コンポーネントを確認する（Phase 8 簡素化候補 2.1と同様） |
| 受入条件 | 名前衝突がないこと。または衝突する場合はリネームして本設計書を更新                                                                                            |

---

### R-05: M-1（SelectedFile source）未対応による拡張時の互換性問題（優先度: MEDIUM）

| 項目     | 内容                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | `sourceType: 'file'` の対応が後回しになった状態でUIが先行リリースされた場合、`TranscriptProvenanceChip` がfileソースの表示に対応せず「不明なソース」表示になる                         |
| 影響度   | MEDIUM                                                                                                                                                                                 |
| 発生確率 | MEDIUM                                                                                                                                                                                 |
| 緩和策   | `TranscriptProvenanceChip` に `sourceType` が未知の値の場合のフォールバック表示（「ソース: 不明」等）を実装する。M-1対応タスク（未タスク）の完了まで `'file'` をpublic APIから除外する |
| 受入条件 | 未知の `sourceType` を渡した場合にコンポーネントがクラッシュせず、フォールバック表示が機能すること                                                                                     |

---

### R-06: P31派生のZustandセレクタ無限ループ（優先度: MEDIUM）

| 項目     | 内容                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | `useTranscriptShare` が Zustand Store のアクションを参照する場合、P31パターン（合成Hook無限ループ）が発生する可能性がある              |
| 影響度   | MEDIUM                                                                                                                                 |
| 発生確率 | LOW                                                                                                                                    |
| 緩和策   | Zustand Storeのアクションは個別セレクタ（`useXxx()`形式）で取得する。派生セレクタで配列を返す場合は `useShallow` を適用する（P48対策） |
| 受入条件 | `useTranscriptShare` をレンダリングするコンポーネントのユニットテストで無限ループが発生しないこと                                      |

---

### R-07: TranscriptSession型の不在による将来の技術的負債（優先度: LOW）

| 項目     | 内容                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リスク   | `TranscriptSession` 型を設けなかったことで、OP-3に関するメタデータ（行数・期間等）を格納する場所がなく、将来的に `originalContent` に混入するリスクがある |
| 影響度   | LOW                                                                                                                                                       |
| 発生確率 | LOW                                                                                                                                                       |
| 緩和策   | M-2未タスクを早期に実装フェーズ後に着手する。`originalContent` に構造化データを格納することは禁止（プレーンテキストのみ）                                 |
| 受入条件 | `originalContent` がプレーンテキスト文字列であること（JSONや構造化データでないこと）                                                                      |

---
