## 3. リスク評価

### 3.1 技術的リスク

| リスク               | 影響度 | 対策                                   |
| -------------------- | ------ | -------------------------------------- |
| バックアップ作成失敗 | 高     | 書き込み前に必ずバックアップ完了を確認 |
| ディスク容量不足     | 中     | 将来的にバックアップクリーンアップ検討 |
| 権限エラー           | 中     | 適切なエラーメッセージで通知           |

### 3.2 セキュリティリスク

| リスク                 | 影響度 | 対策                                    |
| ---------------------- | ------ | --------------------------------------- |
| パストラバーサル攻撃   | 高     | validatePath で必ず検証                 |
| 読み取り専用スキル改変 | 高     | readonly フラグで書き込み操作を全て拒否 |
| シンボリックリンク攻撃 | 中     | fs.realpath で実パスを検証              |

## 4. 設計決定事項

### 4.1 確定事項

| ID   | 決定事項                                           |
| ---- | -------------------------------------------------- |
| D-01 | バックアップはファイル単位で同一ディレクトリに作成 |
| D-02 | タイムスタンプはミリ秒精度（Date.now()）           |
| D-03 | readonlyチェックは各書き込み操作の先頭で実施       |
| D-04 | エラーはカスタムエラークラスで型安全に処理         |

### 4.2 保留事項（スコープ外）

| ID   | 保留事項               | 理由                       |
| ---- | ---------------------- | -------------------------- |
| P-01 | バックアップの自動削除 | 将来タスクで検討           |
| P-02 | バックアップの圧縮     | 現時点では不要             |
| P-03 | 同時書き込みの排他制御 | 単一ユーザー想定のため不要 |
