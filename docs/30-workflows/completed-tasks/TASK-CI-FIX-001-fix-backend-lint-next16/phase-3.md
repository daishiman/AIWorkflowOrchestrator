## 実行手順

### ステップ1: 設計レビュー

以下の観点で Phase 2 の設計をレビューする。

**レビューチェックリスト**:

| #   | レビュー観点              | 確認内容                                                                | 判定 |
| --- | ------------------------- | ----------------------------------------------------------------------- | ---- |
| 1   | スクリプト変更の妥当性    | `eslint .` コマンドが backend ソースに対して正しく lint を実行するか    | -    |
| 2   | FlatCompat 使用の妥当性   | `@eslint/eslintrc` の FlatCompat がレガシー設定変換として適切か         | -    |
| 3   | eslint-config-next 互換性 | `next/core-web-vitals` が ESLint 9.x flat config で動作するか           | -    |
| 4   | ignores 設定の網羅性      | テストファイル・ビルド出力・auto-generated ファイルが適切に除外されるか | -    |
| 5   | キャッシュ設定の妥当性    | `.next/cache/eslint/` がキャッシュロケーションとして適切か              | -    |
| 6   | ルート設定との非干渉      | ルートの `eslint .` と backend の `eslint .` が独立して動作するか       | -    |
| 7   | 依存パッケージの充足      | 追加インストールが不要であることが確認されているか                      | -    |

### ステップ2: リスク評価

| リスク                                      | 影響度 | 発生確率 | 対策の妥当性                      | 判定 |
| ------------------------------------------- | ------ | -------- | --------------------------------- | ---- |
| FlatCompat 変換で一部ルール欠落             | 中     | 低       | 変換後の設定ダンプで確認可能      | -    |
| eslint-config-next@16 の flat config 非対応 | 高     | 低       | FlatCompat で変換するため対応可能 | -    |
| ルート設定とルールの重複                    | 低     | 中       | 各設定のスコープが分離されている  | -    |

### ステップ3: ゲート判定

**判定基準**:

| 判定  | 条件                     | 対応                         |
| ----- | ------------------------ | ---------------------------- |
| PASS  | 全レビュー観点で問題なし | Phase 4（テスト作成）へ進行  |
| MINOR | 軽微な指摘あり           | 指摘対応後Phase 4へ進行      |
| MAJOR | 重大な問題あり           | 影響範囲に応じて戻り先を決定 |

**戻り先決定基準**:

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
| 両方の問題 | Phase 1（要件定義） |

**判定**: Phase 2 成果物のレビュー結果に基づいて判定する。
