## なぜこのタスクが必要か（Why）

### 背景

`apps/desktop/src/main/handlers/__tests__/llm.test.ts:290` に「TODO: Implement timeout mechanism in handler」というコメントが存在する。現在のLLMハンドラーにはタイムアウト機構が実装されておらず、LLM APIへのリクエストが無期限に待機し続ける可能性がある。

### 問題点

LLM APIコール（OpenAI, Anthropic, Google, xAI）はネットワーク状況やサーバー負荷により応答が大幅に遅延する場合がある。タイムアウト機構がない場合、以下の問題が発生する:

- ユーザーが応答を永遠に待ち続ける
- Electronアプリのメインプロセスがブロックされる可能性
- リソース（メモリ、接続）が解放されない

### 放置した場合の影響

- ユーザー体験の著しい低下（応答なしの状態が続く）
- アプリケーションがフリーズしたように見える
- システムリソースのリーク

---

## 何を達成するか（What）

### 目的

LLMハンドラーに設定可能なタイムアウト機構を実装し、API呼び出しが指定時間内に完了しない場合に適切にエラーハンドリングする。

### 最終ゴール

LLM APIコールに対してタイムアウトが設定され、タイムアウト発生時にユーザーに適切なエラーメッセージが表示される状態にする。

### スコープ

**含む:**

- LLMハンドラーへのタイムアウト機構追加
- タイムアウト時間の設定インターフェース
- タイムアウト発生時のエラーハンドリング
- 既存テストの更新と新規テストケース追加

**含まない:**

- リトライ機構の実装（別タスクで対応）
- LLM APIプロバイダー固有のタイムアウト設定
- UIでのタイムアウト設定画面
- ストリーミング応答のタイムアウト（初回応答のタイムアウトのみ）

### 成果物

| 成果物名             | 説明                                      |
| -------------------- | ----------------------------------------- |
| タイムアウト機構実装 | LLMハンドラーにタイムアウトロジックを追加 |
| テストケース         | タイムアウト動作の検証テスト              |
| エラーハンドリング   | タイムアウト時の適切なエラー応答          |

## どのように実行するか（How）

### 前提条件

- Vercel AI SDK v4.1.x のタイムアウト設定オプションを理解していること
- LLMハンドラーの現在のアーキテクチャを把握していること
- AbortController API の知識

### 依存タスク

- なし（独立して実行可能）

### 必要な知識

- Vercel AI SDK のストリーミングAPI
- AbortController / AbortSignal パターン
- Electron IPC ハンドラーの構造
- Vitest のタイマーモック

### 推奨アプローチ

AbortController を使用してタイムアウトを実装する。Vercel AI SDK は AbortSignal をサポートしているため、`AbortController.abort()` でクリーンにキャンセルできる。デフォルトタイムアウトは30秒とし、環境変数または設定で変更可能にする。

推奨コマンド:

- `pnpm --filter @repo/desktop vitest run llm` - LLMテスト実行
- `pnpm --filter @repo/desktop typecheck` - 型チェック

**成果物:** タイムアウト機構の設計仕様

**目的**: LLMハンドラーにタイムアウト機構を追加する

**手順:**

- AbortController ベースのタイムアウトユーティリティを作成

- タイムアウト発生時のエラーメッセージとレスポンスを定義
- テストケースを追加（正常タイムアウト、キャンセル、設定値変更）

**成果物:** タイムアウト機構実装コード、テストケース

## リスクと対策

| リスク                                             | 影響度 | 確率 | 対策                                                                                   |
| -------------------------------------------------- | ------ | ---- | -------------------------------------------------------------------------------------- |
| ストリーミング応答がタイムアウトで中断される       | 高     | 中   | 初回応答のタイムアウトとストリーミング中のタイムアウトを分離して設計                   |
| タイムアウト値が短すぎて正常応答がキャンセルされる | 中     | 低   | デフォルト値を30秒に設定し、設定で変更可能にする                                       |
| AbortController 非対応のAPIプロバイダー            | 中     | 低   | Vercel AI SDK が抽象化しているため影響は限定的。フォールバックとしてPromise.raceを使用 |
