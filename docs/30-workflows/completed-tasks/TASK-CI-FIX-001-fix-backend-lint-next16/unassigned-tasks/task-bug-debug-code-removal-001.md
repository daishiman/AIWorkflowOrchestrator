## なぜこのタスクが必要か（Why）

### 背景

TASK-CI-FIX-001実行中のコードベーススキャンで、プロダクションビルドに含まれるべきではないデバッグコードが2箇所発見された。

- `apps/desktop/src/renderer/App.tsx:24` - 初回起動時にストレージを全クリアするデバッグコード
- `apps/desktop/src/renderer/utils/devMockAuth.ts:29` - 認証機能復活時に削除が必要なモック認証コード

### 問題点

App.tsx のデバッグコードは初回起動時にユーザーのlocalStorageデータを全クリアする処理を含んでおり、プロダクションビルドで実行された場合、ユーザーの設定やセッションデータが失われる。devMockAuth.ts はモック認証をバイパスとして使用しており、本番認証フロー導入時に残存するとセキュリティリスクとなる。

### 放置した場合の影響

- プロダクションビルドでユーザーデータが意図せず削除される可能性
- モック認証コードが残存した場合の認証バイパスリスク
- コードレビュー時にデバッグコードと本番コードの区別が困難になる

---

## 何を達成するか（What）

### 目的

プロダクションビルドに含まれるべきではないデバッグコードを特定し、安全に除去または条件分岐化する。

### 最終ゴール

App.tsx のストレージクリアコードが除去され、devMockAuth.ts の使用箇所が明確に環境変数で制御されている状態にする。

### スコープ

**含む:**

- App.tsx のデバッグ用ストレージクリアコード除去
- devMockAuth.ts の環境変数による制御確認・改善
- 関連する import 文のクリーンアップ

**含まない:**

- 認証機能の本番実装（別タスク）
- localStorage の永続化設計変更
- 他のデバッグコード（console.log等）の除去

### 成果物

| 成果物名               | 説明                   |
| ---------------------- | ---------------------- |
| 修正済みApp.tsx        | デバッグコード除去済み |
| 修正済みdevMockAuth.ts | 環境変数制御の明確化   |

## どのように実行するか（How）

### 前提条件

- App.tsx のストレージクリア処理の影響範囲を把握していること
- devMockAuth.ts の使用箇所を全て特定していること
- 開発環境と本番環境の環境変数設定を理解していること

### 依存タスク

- なし（独立して実行可能）

### 必要な知識

- React コンポーネントのライフサイクル
- Electron アプリケーションの環境変数管理
- localStorage API

### 推奨アプローチ

App.tsx のデバッグコードは単純に除去する。devMockAuth.ts は `process.env.NODE_ENV === 'development'` による条件分岐が適切に設定されているか確認し、不足があれば追加する。
