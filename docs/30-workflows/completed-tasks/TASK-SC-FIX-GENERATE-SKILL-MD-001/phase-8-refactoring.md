## 目的

修正後の実装における重複・説明不足・命名の揺れを整理し、
必要最小限の複雑性でmaintainabilityを向上させる。

## 実行タスク

### Task 1: tmpファイル生成ロジックの関数分離（必要な場合のみ）

- tmpファイルパス生成（UUID組み込み）の処理量を確認し、独立した関数として分離が妥当かどうかを判断する
- 分離する場合はprivateメソッド`buildTmpPlanPath`等の名称が責務を明確に表しているかを確認する
- 分離しない場合はインライン実装で十分な理由を記録する

### Task 2: 定数化できる文字列の確認

- `"generate_skill_md.js"`のスクリプト名が複数箇所に散在していないことを確認する
- `"--plan"`・`"--output"`の引数名が定数として管理されているかを確認する
- 定数化が必要な場合はファイル上部またはconstオブジェクトに集約する
- 定数化不要の場合はその根拠（出現1箇所・変更頻度低）を記録する

### Task 3: `finally`節の可読性確認

- `finally`節がtry本体と明確に分離されていることを確認する
- `fs.unlink`のエラーを握りつぶす処理に対してコメントが付いていることを確認する（例: `// cleanup failure is non-fatal`）
- `finally`節の行数が5行以内に収まっており、追加ロジックが混入していないことを確認する
