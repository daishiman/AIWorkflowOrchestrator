## 実行タスク

### Task 1: 設計整合性チェック

以下の観点で設計を検証する：

- `import os from "os"` の追加が既存 import 群と競合しないこと
- `path.join(os.tmpdir(), ...)` が全 OS（macOS / Linux / Windows）で動作すること
- `try/finally` ブロックが既存の `ensureSkillMdExists`（行 152）の呼び出しと二重実行にならないこと
- `fs.unlink(tmpPlanPath).catch(() => {})` が tmp ファイル未生成時（`fs.writeFile` 失敗時）にエラーを吸収できること

### Task 2: 4条件レビュー

| 観点         | 確認内容                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 矛盾なし     | `ensureSkillMdExists` は行 152（init 直後）と行 184-185（生成失敗または存在確認失敗時フォールバック）の 2 箇所に存在し、それぞれの役割が独立している |
| 漏れなし     | AC-1〜AC-5 のすべてに対応する設計が揃っている（Task 1-4 参照）                                                                                       |
| 整合性あり   | `tmpPlanPath`・`plan`・`generateResult` の変数名が設計書と実装計画で統一されている                                                                   |
| 依存関係整合 | Phase 4 のテストが `scriptExecutor.execute` の引数とfinallyクリーンアップを観測できる設計になっている                                                |

### Task 3: リスク評価

| リスク                                                                         | 影響度 | 発生確率 | 対策                                                                                                          |
| ------------------------------------------------------------------------------ | ------ | -------- | ------------------------------------------------------------------------------------------------------------- |
| tmp ファイル名の高並列衝突リスク                                               | 低     | 低       | `randomUUID()` ベースの `skill-plan-${randomUUID()}.json` に変更済みのため、衝突リスクは実質解消済み          |
| `fs.writeFile` が失敗した場合に `scriptExecutor.execute` が不正パスで呼ばれる  | 中     | 低       | `fs.writeFile` が例外を投げるため `execute` は呼ばれない。finally で unlink の `.catch(() => {})` が吸収する  |
| `--output` に渡す `path.join(skillDir, "SKILL.md")` が既存ファイルを上書きする | 低     | 高       | スクリプトが SKILL.md を再生成することが本修正の目的のため意図した動作。生成後の `fs.access` で存在確認も行う |
| Windows の `os.tmpdir()` パスにスペースが含まれる場合の引数解析エラー          | 低     | 低       | `scriptExecutor.execute` は引数を配列で受け取るため shell-quoting 不要。リスクなし                            |
| 既存の `isMissingScriptError` 判定が新しい引数エラーを拾わない                 | 中     | 低       | `--plan` / `--output` は正当な引数のため、スクリプト不在エラーとは別経路。既存フォールバックは機能する        |

### Task 4: ゲート判定

- **PASS**: 実装は `SkillCreatorService.ts` の行 152-188 の局所修正（`os` import 追加 + try/finally ブロック）で完結する
- **MAJOR 条件**: `scriptExecutor.execute` の内部実装が引数を shell 経由で渡しており、パスのクォーティングが必要な場合
- **CRITICAL 条件**: `generate_skill_md.js` の `--plan` / `--output` 仕様が実際には異なる場合（事前確認で排除済み）

設計レビュー時点での判定: **PASS**（実装に進める）
