## 改善提案

### 提案 1: スクリプト仕様のサービス実装者向け明文化

**論点**: `generate_skill_md.js` の `--plan`/`--output` 仕様が `SkillCreatorService.ts` のコメントに記載されておらず、
同様の引数ミスマッチが再発するリスクがある。

**採用思考法**: 「防衛的ドキュメント」— バグ再発防止のためにコード近傍に仕様を明記する

**結論**: `SkillCreatorService.ts` の SKILL.md 生成ブロック直前に以下のような JSDoc コメントを追加することを推奨する。

```typescript
// generate_skill_md.js 仕様:
//   必須引数: --plan <tmp_json_path>  プランJSONファイルへのパス
//             --output <md_path>      生成先 SKILL.md へのパス
// 注意: --path 引数は本スクリプトには存在しない
```

### 提案 2: スクリプト呼び出しインターフェース層の整備

**論点**: `scriptExecutor.execute("generate_skill_md.js", [...args])` のような直接呼び出しが複数スクリプトで散在すると、
各スクリプトの引数仕様をサービス実装者が覚える必要が生じる。

**採用思考法**: 「ファサードパターンの延伸」— `ScriptExecutor` にスクリプト固有のラッパーメソッドを追加

**結論**: 現時点では過剰設計（スクリプト数が多い）のため採用しないが、将来的に `ScriptExecutor.generateSkillMd(plan, outputPath)` のような型安全なラッパーを検討する価値がある。

## 論点→採用思考法→結論 の対応表
