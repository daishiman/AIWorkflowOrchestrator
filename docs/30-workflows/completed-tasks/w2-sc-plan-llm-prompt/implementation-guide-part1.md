# 実装ガイド Part 1: LLM プロンプト統合の概念説明

## TASK-SC-03-PLAN-LLM-PROMPT

## LLM プロンプトって何？ - 料理で例えると

LLM プロンプトは「料理レシピ」のようなものです。

### 登場人物

- **シェフ（LLM = Claude）**: 料理を作る人。指示に従って料理を完成させる
- **レシピ（System Prompt）**: シェフに渡す基本の作り方。「和食の基本」「フランス料理の技法」のような知識
- **注文（User Prompt）**: お客さんが「カレーを作って」と注文する部分

### このタスクでやったこと

今回の実装では、「スキルを設計する AI シェフ」にレシピを渡しました。

```
【レシピ（System Prompt）】
├── 問題発見のコツ（discover-problem.md）  ← 「食材の見分け方」
├── ワークフロー設計のコツ（design-workflow.md） ← 「調理手順の組み方」
├── 構造設計のコツ（plan-structure.md）    ← 「盛り付けのルール」
└── 出力フォーマット指定（JSON スキーマ）  ← 「出来上がりの形」

【注文（User Prompt）】
「GitHub の Issue を自動分類するスキルを作りたい」

【完成品（JSON レスポンス）】
{
  "skillName": "github-issue-classifier",
  "agents": [{ "name": "classify-issues", "role": "..." }],
  ...
}
```

### なぜ3つのレシピを渡すの？

1つだけだと「カレーの作り方」しか知らないシェフになります。3つのレシピを渡すと「問題を見つけ → ワークフローを組み → フォルダ構造を決める」という一連の流れを理解したシェフになります。

### terminal_handoff って何？

API キーがないお客さんには、「うちのシェフ（LLM）は使えないけど、代わりにこの別のお店（ターミナル）に行ってね」とご案内します。これが terminal_handoff です。今回の変更ではこの「ご案内」の部分は一切触れていません。
