## タスク 8-2: バリデーションパターンの整理

### name フィールドの 3 段バリデーション（L140-142）

```javascript
if (typeof frontmatter.name !== "string" || frontmatter.name.trim() === "") {
  result.addError("name フィールドが存在しないか無効です");
}
```

### description フィールドの 3 段バリデーション（L161-163）

```javascript
if (
  typeof frontmatter.description !== "string" ||
  frontmatter.description.trim() === ""
) {
  result.addError("description フィールドが存在しないか無効です");
}
```

### 共通部分と差異の比較

| 要素             | name                                           | description                           | 共通   |
| ---------------- | ---------------------------------------------- | ------------------------------------- | ------ |
| 型チェック       | `typeof ... !== "string"`                      | `typeof ... !== "string"`             | 共通   |
| 空文字列         | `.trim() === ""`                               | `.trim() === ""`                      | 共通   |
| フィールド参照   | `frontmatter.name`                             | `frontmatter.description`             | 異なる |
| エラーメッセージ | `"name フィールドが..."`                       | `"description フィールドが..."`       | 異なる |
| 後続処理         | 64文字制限、ハイフンケース、ディレクトリ名一致 | 1024文字制限、角括弧、Anchors/Trigger | 異なる |

### 判断

| 条件                                                                        | 該当 | 対応                             |
| --------------------------------------------------------------------------- | ---- | -------------------------------- |
| 3 段バリデーションが完全に同一パターン                                      | 否   | -                                |
| 3 段バリデーション後の処理が異なる（name は正規表現、description は文字数） | 該当 | 3 段チェック部分のみ共通化を検討 |
| 重複が 3 行未満                                                             | 該当 | **インライン維持（変更しない）** |

共通化対象は条件式の1パターン（`typeof X !== "string" || X.trim() === ""`）のみであり、3 行未満の重複に該当する。仮に `isNonEmptyString()` ヘルパーを抽出しても:

1. 呼び出し側が `if (!isNonEmptyString(frontmatter.name))` となり、条件式の可読性向上は限定的
2. ヘルパー関数の JSDoc コメント追加で行数が増加
3. 抽象化層が1つ増え、新規開発者のコード追跡コストが発生
4. 本タスクは小規模バグ修正であり、YAGNI 原則に従い過度な抽象化は避けるべき

**結論**: `isNonEmptyString()` ヘルパー関数の抽出は行わない。インライン維持が最適。

| ------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 言語               | 日本語で統一                                              | 適合                                                                                  |

**結論**: エラーメッセージは一貫したフォーマットに統一されている。修正の必要はない。
