## 目的

Lint・型チェック・全テスト一括実行・パフォーマンス基準確認の4点で品質を最終検証する。Phase 10 最終レビューに進める状態であることを確認する。

## 背景

Phase 10 最終レビューに進める状態であることを確認するための品質ゲートフェーズ。Phase 8 のリファクタリングが完了し、テストコードの品質が向上した状態で、プロジェクト全体の品質基準を満たしているかを検証する。

品質ゲートを通過できない場合、Phase 8 に戻りリファクタリングの追加対応を行う。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ESLint 実行

**目的**: コード品質の静的検証

**実行手順**:

1. コマンドを実行する: `pnpm --filter @repo/desktop lint`
2. エラーが 0 件であることを確認する
3. 警告が 0 件であることを確認する
4. 未使用 import の残存がないことを確認する

**期待される成果物**:

- ESLint 実行結果（エラー・警告 0 件の証跡）

### タスク2: TypeScript 型チェック

**目的**: 型安全性の最終確認

**実行手順**:

1. コマンドを実行する: `pnpm --filter @repo/desktop typecheck`
2. エラーが 0 件であることを確認する
3. `any` 型の残存がないことを `grep` で確認する: `grep -rn ": any" apps/desktop/src/test/e2e/`
4. 不適切な型アサーション（`as any`）がないことを確認する

**期待される成果物**:

- TypeScript 型チェック結果（エラー 0 件の証跡）

### タスク3: 全テスト一括実行

**目的**: 全テストの PASS 確認とリグレッション検出

**実行手順**:

1. コマンドを実行する: `cd apps/desktop && pnpm vitest run`（P40 対策: パッケージディレクトリから実行）
2. E2Eテスト（シナリオA〜E）が全て PASS であることを確認する
3. 拡充テスト（同時実行・大量入力・タイムアウト・セキュリティ）が全て PASS であることを確認する
4. 既存テストへのリグレッションがないことを確認する

**期待される成果物**:

- 全テスト実行結果（全 PASS の証跡）

### タスク4: パフォーマンス基準確認

**目的**: NFR-2 パフォーマンス基準の充足確認

**実行手順**:

1. plan 実行時間が 30,000ms 以内であることを確認する（モック使用時）
2. execute 実行時間が 120,000ms 以内であることを確認する（モック使用時）
3. タイムアウトテストが期待通りに動作することを確認する

**期待される成果物**:

- パフォーマンス基準確認結果

### タスク5: セキュリティ品質確認（NFR-1）

**目的**: IPC経由での情報漏洩がないことを確認する

**実行手順**:

1. エラーメッセージにシステム内部情報（スタックトレース・ファイルパス・API Key）が含まれていないことを確認する
2. `suggestedCommand` の文字列形式が安全であることを確認する（シェルインジェクション不可）
3. セキュリティテスト（Phase 6 で追加済み）が全て PASS であることを確認する

**期待される成果物**:

- セキュリティ品質確認結果
