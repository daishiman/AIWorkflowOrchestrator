## 目的

実際の Electron アプリで全 5 シナリオを手動実行し、TerminalHandoff の suggestedCommand が CLI で実行可能であることを確認する。自動テストでは検証できない UI/UX 面および実際の CLI 実行可能性を最終確認する。

## 背景

自動テスト（Unit / Integration / E2E）では検証しきれない以下の領域を手動で確認する最終確認フェーズである。

- 実際の Electron アプリ上での UI/UX 挙動（レンダリング、レイアウト崩れ、操作感）
- suggestedCommand の実際の CLI 実行可能性
- ユーザー視点でのフロー全体の整合性

P53（CLI 環境制約）を考慮し、GUI 操作が困難な環境では Playwright の `page.screenshot()` や自動テスト PASS 結果を証跡として代替記録する。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: シナリオ A 手動確認（正常フロー）

**目的**: 正常フロー（plan → execute-plan）が UI 上で正しく動作することを手動確認する

**実行手順**:

1. スキル生成ウィザードを開く
2. LLM モデルを選択する（AC-1: モデル選択 UI が機能すること）
3. スキル名・説明等を入力する
4. 生成を実行し、進捗がリアルタイムで更新されることを確認する（AC-3: 進捗リアルタイム更新）
5. 完了後、スキル一覧に新規スキルが表示されることを確認する（AC-2: スキル一覧表示）

**確認観点**: AC-1, AC-2, AC-3

### タスク2: シナリオ B 手動確認（TerminalHandoff）

**目的**: API Key 未設定時の TerminalHandoff 経路が正しく動作することを手動確認する

**実行手順**:

1. API Key を未設定の状態でスキル生成を実行する
2. TerminalHandoff が発動し、suggestedCommand が表示されることを確認する（AC-4）
3. 表示されたコマンドをコピーする
4. ターミナルで実行し、正しく動作することを確認する

**確認観点**: AC-4（suggestedCommand 返却と CLI 実行可能性）

### タスク3: シナリオ C 手動確認（LLM エラー）

**目的**: LLM エラー発生時の UI 表示とリカバリーが正しく動作することを手動確認する

**実行手順**:

1. 不正な API Key を設定してスキル生成を実行する
2. エラーメッセージが適切に表示されることを確認する（AC-7）
3. アプリがクラッシュしないことを確認する（NFR-4: 安定性）
4. リトライが可能であることを確認する

**確認観点**: AC-7, NFR-4

### タスク4: シナリオ D 手動確認（improve モード）

**目的**: 既存スキルの改善フローが正しく動作することを手動確認する

**実行手順**:

1. 既存スキルを選択する
2. 改善モード（improve）で実行する
3. 改善結果が上書き保存されることを確認する（AC-5）

**確認観点**: AC-5

### タスク5: シナリオ E 手動確認（後方互換）

**目的**: 旧 UI 互換チャンネルが引き続き動作することを手動確認する

**実行手順**:

1. 旧 UI から `skill:create` チャンネル経由でスキル生成を実行する
2. 既存の動作が維持されることを確認する（AC-8）

**確認観点**: AC-8

### タスク6: P53 対策 -- CLI 環境での代替検証

**目的**: GUI 操作が困難な環境での代替手段を用いた証跡記録を行う

**実行手順**:

1. Playwright `page.screenshot()` による画面キャプチャを証跡として保存する
2. 自動テスト PASS 結果のログ出力を証跡として記録する
3. 証跡ファイルを `outputs/phase-11/evidence/` に配置する
