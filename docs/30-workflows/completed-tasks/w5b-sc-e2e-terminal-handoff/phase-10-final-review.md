## 目的

AC-1〜AC-8 の全充足確認と NFR-1〜NFR-4 の充足確認を行い、Skill Creator LLM統合全体のリリース判定を行う。PASS / MINOR / MAJOR / CRITICAL の判定を記録する。

## 背景

Skill Creator LLM統合全体（タスク01〜08）の最終ゲート。ここでの判定がリリース可否を決める。

本タスク（w5b / TASK-SC-08-E2E-VALIDATION）は Wave 5 の最終タスクであり、Wave 1〜5 の全8タスクの統合動作を検証する立場にある。Phase 9 の品質ゲートを通過した状態で、AC・NFR の充足を多角的に確認し、総合判定を行う。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: AC全充足確認

**目的**: 正本（`index.md`）の AC-1〜AC-8 が全て充足されていることを確認する

**実行手順**:

1. 以下のテーブルを確認し、各ACの充足状況を記録する:

| AC   | 確認内容                                                    | 対応シナリオ      | 充足 |
| ---- | ----------------------------------------------------------- | ----------------- | ---- |
| AC-1 | 自然言語入力 → LLM がカテゴリベースでスキル一式を生成する   | シナリオA         |      |
| AC-2 | 生成スキルが永続化され即座に実行可能                        | シナリオA         |      |
| AC-3 | 生成進捗が UI にストリーミング表示される                    | w5a で検証済み    |      |
| AC-4 | API Key 未設定時は TerminalHandoffBundle + CLI コマンド表示 | シナリオB         |      |
| AC-5 | improve: フィードバック → 差分提案 → 承認で適用             | シナリオD         |      |
| AC-6 | verify: 要求充足トータル検証                                | シナリオA(verify) |      |
| AC-7 | エラー時に適切なメッセージ表示                              | シナリオC         |      |
| AC-8 | 既存 skill:create が破壊されない                            | シナリオE         |      |

2. 全ACにチェックが入っていることを確認する
3. AC-3 については w5a（TASK-SC-07-STREAMING-PROGRESS-UI）の Phase 10 レビュー結果を参照する

**期待される成果物**:

- AC充足確認テーブル（全8項目チェック済み）

### タスク2: NFR全充足確認

**目的**: 非機能要件 NFR-1〜NFR-4 が全て充足されていることを確認する

**実行手順**:

1. 以下のテーブルを確認し、各NFRの充足状況を記録する:

| NFR   | 確認内容                         | 検証方法             | 充足 |
| ----- | -------------------------------- | -------------------- | ---- |
| NFR-1 | IPC経由で機密情報が漏洩しない    | セキュリティテスト   |      |
| NFR-2 | plan 30秒以内・execute 120秒以内 | パフォーマンステスト |      |
| NFR-3 | 既存APIが破壊されない            | シナリオE            |      |
| NFR-4 | LLMエラー後にクラッシュしない    | シナリオC            |      |

2. 全NFRにチェックが入っていることを確認する

**期待される成果物**:

- NFR充足確認テーブル（全4項目チェック済み）

### タスク3: 全体統合確認

**目的**: タスク01〜07の全成果物が統合されて正常に動作することを確認する

**実行手順**:

1. 以下のタスク成果物の統合動作を確認する:
   - タスク01（w1a: LLM Provider 抽象化）: LLMProvider インターフェースが正しく使用されていること
   - タスク02（w1b: Prompt Engineer）: プロンプトテンプレートが正しく適用されていること
   - タスク03（w2: Plan-Execute Facade）: RuntimeSkillCreatorFacade が正しく動作すること
   - タスク04（w3a: Output Persistence）: SkillFileWriter によるファイル永続化
   - タスク05（w3b: Improve LLM）: improve() 差分提案・適用
   - タスク06（w4: UI-Runtime Connection）: UI → Runtime パイプライン
   - タスク07（w5a: Streaming Progress UI）: ストリーミング進捗表示
2. w5a（ストリーミング進捗UI）との統合動作を確認する
3. IPCチャネル名が正本準拠であることを最終確認する:
   - `skill-creator:plan`（`skill-creator:plan` ではなく正確な名称）
   - `skill-creator:execute-plan`（`skill-creator:execute` ではない）
   - `skill-creator:verify`
   - `skill-creator:improve-skill`

**期待される成果物**:

- 全体統合確認結果

### タスク4: 総合判定

**目的**: リリース可否を判定する

**実行手順**:

1. タスク1〜3の結果を総合し、以下の判定基準に基づき判定する:
   - **PASS**: 全レビュー観点で問題なし → Phase 11 へ
   - **MINOR**: 軽微な指摘あり → 未タスク仕様書に変換後 Phase 11 へ
   - **MAJOR**: 重大な問題あり → Phase 5 へ戻る
   - **CRITICAL**: 致命的な問題あり → Phase 1 へ戻りユーザー確認
2. 判定結果と理由を記録する
3. MINOR 指摘が存在する場合、全て未タスク仕様書に変換する（省略不可）

**期待される成果物**:

- 総合判定結果（PASS / MINOR / MAJOR / CRITICAL）
- MINOR 指摘の未タスク仕様書（該当する場合）

## レビューゲート

| 判定     | 条件                     | 次のアクション                     |
| -------- | ------------------------ | ---------------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11 へ                        |
| MINOR    | 軽微な指摘あり           | 未タスク仕様書に変換後 Phase 11 へ |
| MAJOR    | 重大な問題あり           | Phase 5 へ戻る                     |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻りユーザー確認         |

**MINOR の定義**: 機能に影響しないが改善が望ましい事項（命名、コメント、ログレベル等）

**MAJOR の定義**: AC または NFR の一部が未充足、またはリグレッションが検出された

**CRITICAL の定義**: アーキテクチャレベルの問題、セキュリティ脆弱性、データ損失リスク
