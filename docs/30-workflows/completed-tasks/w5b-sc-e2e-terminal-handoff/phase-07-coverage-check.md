## 目的

E2Eテストの統合カバレッジを計測し、基準値を確認する。

## 背景

カバレッジゲートフェーズ。基準値（Line 80% / Branch 60% / Function 80%）未達の場合は Phase 6 に戻る。Phase 4〜6 で作成した全テスト（5シナリオ + 拡充テスト）の統合カバレッジを計測し、品質基準を満たしているかを判定する。v8 プロバイダのインライン関数カウントに注意（P41）。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: E2Eテスト統合カバレッジ計測

**目的**: カバレッジレポートを生成する

**実行手順**:

1. 以下のコマンドでカバレッジ計測を実行する（P40対策: `cd apps/desktop`）:

   ```bash
   cd apps/desktop && pnpm vitest run --coverage src/test/e2e/
   ```

2. カバレッジレポートの対象: `skill-creator` 関連の Main プロセスハンドラ
3. カバレッジレポートの出力形式（text / html / json）を確認する

**期待される成果物**:

- カバレッジレポート

### タスク2: シナリオカバレッジ確認

**目的**: 各シナリオが対応する経路をカバーしていることを確認する

**実行手順**:

1. シナリオA: 正常フロー（plan + execute-plan）のカバレッジを確認する
2. シナリオB: TerminalHandoff 経路のカバレッジを確認する
3. シナリオC: LLMエラーパスのカバレッジを確認する
4. シナリオD: improve 機能のカバレッジを確認する
5. シナリオE: 後方互換パス（`skill:create`）のカバレッジを確認する
6. 拡充テスト（同時実行・大量入力・タイムアウト・セキュリティ・ネットワーク切断）のカバレッジ貢献を確認する

**期待される成果物**:

- シナリオ別カバレッジサマリー

### タスク3: カバレッジ基準確認

**目的**: 各カバレッジ指標が基準値を満たしていることを確認する

**実行手順**:

1. **Line Coverage**: 80% 以上であることを確認する
2. **Branch Coverage**: 60% 以上であることを確認する（エラーパスのカバレッジに注意）
3. **Function Coverage**: 80% 以上であることを確認する（**P41**: v8プロバイダのインライン関数カウントに注意）
4. 各指標の実測値を記録する

**期待される成果物**:

- カバレッジ基準確認結果

### タスク4: ゲート判定

**目的**: Phase 8 に進めるかを判定する

**実行手順**:

1. 全指標（Line / Branch / Function）が基準値以上の場合: **Phase 8 へ進行**
2. いずれかの指標が基準値未達の場合: **Phase 6 に戻り追加テストを作成する**
3. 未達の場合、具体的にどの経路・関数がカバーされていないかを特定し、Phase 6 で追加すべきテストケースを列挙する

**期待される成果物**:

- ゲート判定結果

## カバレッジゲート

### ゲート判定基準

| 指標              | 基準値 | 判定             |
| ----------------- | ------ | ---------------- |
| Line Coverage     | 80%+   | 基準値以上: PASS |
| Branch Coverage   | 60%+   | 基準値以上: PASS |
| Function Coverage | 80%+   | 基準値以上: PASS |

### ゲート結果判定

| 判定 | 条件                       | 次のアクション                     |
| ---- | -------------------------- | ---------------------------------- |
| PASS | 全指標が基準値以上         | Phase 8（リファクタリング）へ進行  |
| FAIL | いずれかの指標が基準値未達 | Phase 6 に戻り追加テストを作成する |

### 戻り先決定基準

| 問題の種類           | 戻り先                                |
| -------------------- | ------------------------------------- |
| カバレッジ不足       | Phase 6（テスト拡充）で追加テスト作成 |
| テスト設計の根本問題 | Phase 4（テスト作成）で設計見直し     |
