## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 同時実行テスト

**目的**: 複数リクエストの同時実行時に競合状態が発生しないことを検証する

**実行手順**:

1. 複数の `skill-creator:plan` を同時に呼び出した場合に正しく処理されることをテストする
2. 競合状態（Race Condition）が発生しないことを確認する
3. 2回の同時呼び出しで、それぞれ独立したレスポンスが返ることをアサートする

**期待される成果物**:

- 同時実行テストコード

### タスク2: 大量入力テスト

**目的**: 大量・特殊文字入力時の正常処理を検証する

**実行手順**:

1. スキル名が最大長（255文字）の場合に正しく処理されることをテストする
2. スキルの説明文が非常に長い場合（10,000文字）のパフォーマンスを確認する
3. 特殊文字（日本語・記号・絵文字）を含む入力の正常処理を確認する

**期待される成果物**:

- 大量入力テストコード

### タスク3: タイムアウトテスト（P13対策）

**目的**: タイムアウト制御が正しく動作することを検証する

**実行手順**:

1. plan が 30秒を超えた場合にタイムアウトエラーが返ることをテストする
2. execute が 120秒を超えた場合にタイムアウトエラーが返ることをテストする
3. タイムアウト後にアプリがクラッシュしないこと（NFR-4）を確認する
4. **P13対策**: タイマーテストは `vi.useFakeTimers()` + `vi.advanceTimersByTime()` を使用する

**期待される成果物**:

- タイムアウトテストコード

### タスク4: セキュリティテスト（NFR-1）

**目的**: セキュリティ要件を検証する

**実行手順**:

1. エラーレスポンスにシステム内部情報（スタックトレース・ファイルパス）が含まれないことをアサートする
2. `suggestedCommand` にシェルインジェクション可能な文字列（`; rm -rf /` 等）が含まれないことをアサートする
3. APIキーがレスポンスに含まれないことをアサートする

**期待される成果物**:

- セキュリティテストコード

### タスク5: ネットワーク切断テスト

**目的**: ネットワーク障害時のエラーハンドリングを検証する

**実行手順**:

1. LLM API への接続が途中で切断された場合に `{ success: false, error: { code: "NETWORK_ERROR" } }` が返ることをテストする
2. 切断後に再接続試行が行われることをアサートする

**期待される成果物**:

- ネットワーク切断テストコード
