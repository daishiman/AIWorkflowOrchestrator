## 2. スコープ外（Out of Scope）

### 2.1 機能

| 項目                   | 理由                                          |
| ---------------------- | --------------------------------------------- |
| リアルタイム協調編集   | 複数ユーザー同時編集は別タスクで対応          |
| コンフリクト自動解決   | 競合状態の自動マージは複雑すぎるため除外      |
| 履歴管理（Undo/Redo）  | 変更履歴の管理は別機能として検討              |
| 差分の可視化UI         | 変更内容のプレビュー表示は別タスクで対応      |
| 複数ファイル同時監視   | structure.md/index.html以外のファイルは対象外 |
| カスタムプロンプト設定 | ユーザーによるプロンプトカスタマイズは除外    |
| オフラインモード       | Agent SDKが必須のため、オフライン動作は除外   |

### 2.2 変更対象外ファイル

| ファイル                               | 理由                            |
| -------------------------------------- | ------------------------------- |
| `renderer/`配下のUIコンポーネント      | 既存のSyncStatusIndicatorを使用 |
| Agent SDK基盤コード                    | 別タスク（Agent SDK統合）で実装 |
| 他のスキル（hearing, structure, html） | 既存スキルは変更しない          |

## 3. 境界条件

### 3.1 入力条件

| 条件                       | 許容範囲                           |
| -------------------------- | ---------------------------------- |
| index.htmlファイルサイズ   | 最大10MB                           |
| structure.mdファイルサイズ | 最大1MB                            |
| 同時変更回数               | 1件（後続の変更は待機）            |
| 差分サイズ                 | 制限なし（ただし30秒タイムアウト） |

### 3.2 動作条件

| 条件                     | 要件                         |
| ------------------------ | ---------------------------- |
| Agent SDK可用性          | 必須（オフライン時はエラー） |
| ファイル書き込み権限     | 必須                         |
| プロジェクトディレクトリ | 有効なパスであること         |

### 3.3 タイムアウト・リトライ

| パラメータ                    | 値                            |
| ----------------------------- | ----------------------------- |
| Agent SDK呼び出しタイムアウト | 30秒                          |
| リトライ回数                  | 最大3回                       |
| リトライ間隔                  | 1秒→2秒→4秒（指数バックオフ） |
| 変更検知debounce              | 500ms                         |
| 無限ループ防止TTL             | 1000ms                        |

## 4. 成功基準

### 4.1 機能的成功基準

- [ ] index.htmlの変更が1秒以内に検知される
- [ ] modifier skillが正しく実行され、structure.mdが更新される
- [ ] 無限ループが発生しない（双方向）
- [ ] エラー時に適切なフィードバックがUIに表示される
- [ ] キャンセル操作が正常に機能する

### 4.2 非機能的成功基準

- [ ] 通常の同期処理が5秒以内に完了する
- [ ] コードカバレッジが80%以上である
- [ ] ESLint/TypeScriptエラーがない
- [ ] 既存の順方向同期機能が正常に動作する

## 7. 除外事項の詳細理由

### 7.1 リアルタイム協調編集

**理由**: 複数ユーザーの同時編集をサポートするには、以下が必要:

- 操作変換（Operational Transformation）または CRDT の実装
- リアルタイム通信インフラ（WebSocket等）
- コンフリクト検出・解決ロジック

これらは本タスクの範囲を大幅に超えるため、別タスクとして切り出す。

### 7.2 コンフリクト自動解決

**理由**: 自動マージは以下の複雑さを伴う:

- マージアルゴリズムの設計
- セマンティックな競合検出
- ユーザー意図の推測

現フェーズでは競合時にエラー通知のみとし、自動解決は将来検討。

### 7.3 オフラインモード

**理由**: Agent SDK（Claude Code）はオンラインサービスであり、オフライン動作には:

- ローカルモデルの導入
- 同期キューイング
- オンライン復帰時の一括同期

が必要。本タスクではオンライン前提とする。
