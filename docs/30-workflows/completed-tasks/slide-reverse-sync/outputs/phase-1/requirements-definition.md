## 1. 概要

### 1.1 目的

slide-dependency-management機能において、`index.html`の変更を検知し、Claude Code（Agent SDK）を使用して変更内容を解析し、`structure.md`に適切に反映する逆同期機能を実装する。

### 1.2 背景

現在の実装では`structure.md → index.html`の片方向同期のみが実装されており、ユーザーが`index.html`を直接編集した場合に`structure.md`が更新されない問題がある。これにより設計図と実装の不整合が発生し、プロジェクト管理に支障をきたす。

### 1.3 ステークホルダー

| 役割             | 関心事                             |
| ---------------- | ---------------------------------- |
| スライド作成者   | 双方向の編集が反映されること       |
| プロジェクト管理 | 設計図と実装の整合性維持           |
| 開発者           | 保守しやすい実装、テスト可能な設計 |

## 2. 機能要件（FR）

### FR-1: ファイル監視拡張

**説明**: 既存のfile-watcherを拡張し、`index.html`の変更も監視対象に追加する。

**詳細**:

- chokidarを使用してindex.htmlを監視
- 変更検知時にコールバックを実行
- debounce設定（500ms）で重複イベントを抑制

**関連コンポーネント**: `file-watcher.ts`

---

### FR-2: 逆同期トリガー

**説明**: index.html変更検知時に逆同期処理を開始する。

**詳細**:

- onHtmlChangeコールバックの実装
- sync-managerのreverseSync()メソッド追加
- 同期状態の管理（syncing, synced, error）

**関連コンポーネント**: `file-watcher.ts`, `sync-manager.ts`

---

### FR-3: Claude Code差分解析

**説明**: Agent SDKを使用してindex.htmlの変更を意味的に解析する。

**詳細**:

- 変更前後のindex.htmlの差分を抽出
- structure.mdの現在の内容を取得
- Claude Codeに解析リクエストを送信
- 構造化された差分データを受信

**関連コンポーネント**: `skill-executor.ts`, `skills/modifier.ts`

---

### FR-4: structure.md更新

**説明**: 解析結果に基づいてstructure.mdを更新する。

**詳細**:

- 差分データをstructure.md形式に変換
- ファイル書き込み処理
- 更新完了イベントの発火

**関連コンポーネント**: `skills/modifier.ts`

---

### FR-5: 無限ループ防止（双方向）

**説明**: 同期による変更が連鎖的な同期を引き起こさないようにする。

**詳細**:

- changeContextMapの双方向対応
- structure.md変更時のマーキング（modifier skill起因）
- index.html変更時のマーキング（html skill起因）
- TTL管理（1秒）

**関連コンポーネント**: `file-watcher.ts`

---

### FR-6: 同期状態通知

**説明**: 同期処理の状態をUIに通知する。

**詳細**:

- IPCチャンネル経由での状態送信
- 状態種別: syncing, synced, error
- 進捗情報の送信（0-100%）

**関連コンポーネント**: `sync-manager.ts`, `ipc-handlers.ts`

---

### FR-7: エラーハンドリング

**説明**: 各種エラーを適切に処理し、ユーザーに通知する。

**詳細**:

- Agent SDK呼び出し失敗
- タイムアウト（30秒）
- 不正なHTML入力
- リトライ機構（最大3回）

**関連コンポーネント**: `skill-executor.ts`

---

### FR-8: キャンセル機能

**説明**: 実行中の逆同期処理をキャンセルできる。

**詳細**:

- AbortControllerを使用した中断
- 部分的変更のロールバック
- キャンセル完了通知

**関連コンポーネント**: `skill-executor.ts`, `sync-manager.ts`

## 4. 制約条件

### 4.1 技術的制約

- **Agent SDK依存**: Claude Agent SDKが利用可能であること
- **Electronアーキテクチャ**: Main/Renderer分離を維持
- **既存インターフェース**: 既存のSlideWatcher, SyncManager, SkillExecutorインターフェースとの互換性

### 4.2 ビジネス制約

- **後方互換性**: 既存の順方向同期機能を維持
- **ユーザー操作不要**: 自動同期が基本動作

## 7. 統合テスト連携要件

### 7.1 ファイル監視接続

```
file-watcher.ts
├── 監視対象: structure.md, index.html
├── イベント: change
├── 設定: debounce 500ms, awaitWriteFinish
└── 出力: ファイルパス、変更種別
```

### 7.2 Agent SDK接続

```
skill-executor.ts → Agent SDK
├── リクエスト: プロンプト（HTML差分 + structure.md）
├── レスポンス: 構造化差分データ
├── タイムアウト: 30秒
└── リトライ: 最大3回
```

### 7.3 IPC通信

```
sync-manager.ts → IPC → Renderer
├── チャンネル: slide:sync-status
├── ペイロード: { status, progress, error? }
└── 受信: SyncStatusIndicator
```

### 7.4 無限ループ防止

```
changeContextMap
├── キー: ファイルパス
├── 値: { source: 'skill' | 'user', timestamp, skillPhase }
├── TTL: 1000ms
└── チェック: handleChange()内で判定
```

## 8. リスク分析

| リスク                     | 影響度 | 発生確率 | 対策                                      |
| -------------------------- | ------ | -------- | ----------------------------------------- |
| Claude Codeの解析精度不足  | 高     | 中       | プロンプトのチューニング、サンプルの蓄積  |
| 無限ループの発生           | 高     | 低       | changeContextMapのTTL調整、テストでの検証 |
| 大きな差分での処理時間増大 | 中     | 中       | チャンク分割、進捗表示の実装              |
| 競合状態（同時編集）       | 中     | 低       | ロック機構の検討、警告表示                |

## 9. 用語定義

| 用語           | 定義                                                   |
| -------------- | ------------------------------------------------------ |
| 順方向同期     | structure.md → index.html の同期                       |
| 逆同期         | index.html → structure.md の同期                       |
| 差分解析       | 変更前後のファイルを比較し、意味的な差分を抽出する処理 |
| modifier skill | 逆同期を実行するClaude Codeスキル                      |
| html skill     | 順方向同期を実行するClaude Codeスキル                  |
