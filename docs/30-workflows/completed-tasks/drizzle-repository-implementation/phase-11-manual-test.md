## 目的

自動テストでは検証が難しいUX・実環境動作を手動テストで確認する。

## 背景

Drizzle Repositoryはインフラ層のコンポーネントであり、UIレベルの手動テストは限定的である。本Phaseでは、実際のSQLiteファイルを使用した動作確認と、Repository層の振る舞いを確認するテストを行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 自動テスト全実行確認

**目的**: 手動テスト前に全自動テストがパスすることを確認する

**実行手順**:

1. 全テスト実行:
   ```bash
   pnpm --filter @repo/shared test
   ```
2. 全テストがPASSすることを確認
3. 失敗がある場合は修正後再実行
4. カバレッジ確認:
   ```bash
   pnpm --filter @repo/shared test -- --coverage
   ```

**期待される成果物**:

- テスト実行結果の確認

---

### タスク2: 実ファイルDB動作確認

**目的**: インメモリではなく実ファイルDBでの動作を確認する

**実行手順**:

1. テスト用SQLiteファイルを作成:
   ```bash
   # テスト用DBファイル作成
   touch /tmp/test-drizzle-repo.db
   ```
2. マイグレーション実行（スキーマ作成）
3. 以下の操作を手動で確認:
   - セッション作成・取得
   - メッセージ作成・取得
   - 検索機能
   - 削除機能
4. DBファイルが永続化されていることを確認

**期待される成果物**:

- `outputs/phase-11/file-db-test-result.md`: 実ファイルDB動作確認結果

---

### タスク3: エラーシナリオ動作確認

**目的**: エラーケースの実際の動作を確認する

**実行手順**:

1. 存在しないIDでの検索:
   - `findById` で null が返ることを確認
2. 重複データの処理:
   - 同一IDでの `save` がupsert動作することを確認
3. 外部キー制約エラー:
   - 存在しないセッションIDへのメッセージ保存
4. DB接続エラーシミュレーション:
   - 不正なDB接続文字列での動作

**期待される成果物**:

- `outputs/phase-11/error-scenario-test-result.md`: エラーシナリオ確認結果

---

### タスク4: パフォーマンス動作確認

**目的**: 実環境でのパフォーマンスを確認する

**実行手順**:

1. 大量データでの動作確認:
   - 1000件のセッションを作成
   - 10000件のメッセージを作成
2. 検索パフォーマンス確認:
   - FTS5全文検索の応答時間測定
   - ページネーションの動作確認
3. 応答時間が許容範囲内であることを確認:
   - 一覧取得: < 100ms
   - 検索: < 200ms

**期待される成果物**:

- `outputs/phase-11/performance-manual-test.md`: パフォーマンス手動確認結果

---

### タスク5: 発見課題の記録

**目的**: 手動テストで発見された課題を記録する

**実行手順**:

1. 発見された課題・改善点を記録:
   - バグ（重要度: 高/中/低）
   - 改善提案
   - ドキュメント不足
2. 各課題の対応方針を決定:
   - 本タスク内で修正
   - 別タスクとして切り出し
   - 許容として記録
3. 重要度「高」の課題は本タスク内で対応

**期待される成果物**:

- `outputs/phase-11/discovered-issues.md`: 発見課題レポート

---

### タスク6: 手動テスト結果レポート作成

**目的**: 手動テスト結果を統合レポートとしてまとめる

**実行手順**:

1. テストカテゴリ別結果を集計:

   ```markdown
   ## テストカテゴリ別結果

   ### 機能テスト（正常系）

   | TC-ID  | 機能           | 期待結果       | 結果 | 備考 |
   | ------ | -------------- | -------------- | ---- | ---- |
   | TC-001 | セッション作成 | DBに保存される | PASS |      |
   | TC-002 | メッセージ作成 | DBに保存される | PASS |      |
   | ...    |                |                |      |      |

   ### エラーハンドリングテスト（異常系）

   | TC-ID  | 状況             | 期待結果 | 結果 | 備考 |
   | ------ | ---------------- | -------- | ---- | ---- |
   | TC-101 | 存在しないID検索 | null返却 | PASS |      |
   | ...    |                  |          |      |      |
   ```

2. 発見課題サマリーを記載
3. 次Phaseへの引き継ぎ事項を記載

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`: 手動テスト結果レポート
