## 技術リスク

### RISK-TECH-001: Drizzle API変更の可能性

| 項目         | 内容                                                       |
| ------------ | ---------------------------------------------------------- |
| リスク概要   | Drizzle ORMのAPI変更により、設計通りの実装ができない可能性 |
| 発生確率     | 低                                                         |
| 影響度       | 中                                                         |
| リスクレベル | 低                                                         |

**対策**:

- Drizzle ORM公式ドキュメントを参照して実装
- drizzle-orm パッケージバージョンをロック
- 既存プロジェクトでのDrizzle使用実績を確認

---

### RISK-TECH-002: 型変換エラーの可能性

| 項目         | 内容                                              |
| ------------ | ------------------------------------------------- |
| リスク概要   | DBレコード→Entity変換時に型不整合が発生する可能性 |
| 発生確率     | 低                                                |
| 影響度       | 中                                                |
| リスクレベル | 低                                                |

**対策**:

- 既存Mapperが型変換を処理済み（Phase 1で確認）
- ユニットテストで全フィールドの変換を検証
- TypeScript strictモードで型エラーを検出

---

### RISK-TECH-003: SQLiteとlibSQLの互換性

| 項目         | 内容                                                   |
| ------------ | ------------------------------------------------------ |
| リスク概要   | テスト環境（better-sqlite3）と本番環境（libSQL）の差異 |
| 発生確率     | 低                                                     |
| 影響度       | 低                                                     |
| リスクレベル | 低                                                     |

**対策**:

- SQLite標準SQL構文のみ使用
- libSQL固有機能は使用しない
- 統合テストで基本動作を確認

---

### RISK-TECH-004: トランザクション処理の複雑化

| 項目         | 内容                                                       |
| ------------ | ---------------------------------------------------------- |
| リスク概要   | saveManyでのトランザクション処理が想定通り動作しない可能性 |
| 発生確率     | 低                                                         |
| 影響度       | 中                                                         |
| リスクレベル | 低                                                         |

**対策**:

- Drizzle ORM `transaction()` APIを使用
- トランザクションテストで動作確認
- エラー時のロールバックを明示的にテスト

## 品質リスク

### RISK-QUAL-001: カバレッジ目標未達リスク

| 項目         | 内容                                                    |
| ------------ | ------------------------------------------------------- |
| リスク概要   | Line≥80%, Branch≥60%, Function≥80% を達成できない可能性 |
| 発生確率     | 低                                                      |
| 影響度       | 中                                                      |
| リスクレベル | 低                                                      |

**対策**:

- 全メソッドの正常系/異常系テストを作成
- Phase 6（テスト拡充）でカバレッジを追加
- Phase 7でカバレッジ確認、未達時はPhase 6に戻る

---

### RISK-QUAL-002: 既存テストとの干渉リスク

| 項目         | 内容                                       |
| ------------ | ------------------------------------------ |
| リスク概要   | 新規テストが既存テストに影響を与える可能性 |
| 発生確率     | 低                                         |
| 影響度       | 低                                         |
| リスクレベル | 低                                         |

**対策**:

- テストファイルを `__tests__/` ディレクトリに分離
- 各テストで独立したDBインスタンスを使用
- 全テスト実行で既存テストへの影響確認

---

### RISK-QUAL-003: Lintエラー/型エラー発生リスク

| 項目         | 内容                                         |
| ------------ | -------------------------------------------- |
| リスク概要   | 実装後にLintエラーや型エラーが発生する可能性 |
| 発生確率     | 中                                           |
| 影響度       | 低                                           |
| リスクレベル | 低                                           |

**対策**:

- 実装時にIDEのリアルタイム型チェック活用
- Phase 9（品質保証）で `pnpm lint` / `pnpm typecheck` 実行
- Hooksで自動フォーマット・Lint修正
