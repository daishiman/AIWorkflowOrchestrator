## 実行手順

### Task 1: カバレッジ測定の実行

以下のコマンドでカバレッジを測定する:

```bash
# カバレッジ付きテスト実行
pnpm --filter @repo/desktop test -- --run --coverage src/main/auth/__tests__/

# 対象ファイルを指定したカバレッジ測定
pnpm --filter @repo/desktop test -- --run --coverage \
  --coverage.include='src/main/auth/pkce.ts' \
  --coverage.include='src/main/auth/authCallbackServer.ts' \
  --coverage.include='src/main/auth/authFlowOrchestrator.ts' \
  --coverage.include='src/main/ipc/authHandlers.ts'
```

### Task 2: カバレッジ基準との照合

**カバレッジ基準**:

| 指標              | 最低基準 | 目標値 |
| ----------------- | -------- | ------ |
| Line Coverage     | 80%+     | 90%+   |
| Branch Coverage   | 60%+     | 75%+   |
| Function Coverage | 80%+     | 90%+   |

**対象ファイル別カバレッジ判定**:

| ファイル                      | Line | Branch | Function | 判定 |
| ----------------------------- | ---- | ------ | -------- | ---- |
| `pkce.ts`                     | -    | -      | -        | -    |
| `authCallbackServer.ts`       | -    | -      | -        | -    |
| `authFlowOrchestrator.ts`     | -    | -      | -        | -    |
| `authHandlers.ts`（変更部分） | -    | -      | -        | -    |

> 注: 上記の「-」は実行時に測定結果を記入する

**判定基準**:

| 判定 | 条件                                   | 次のアクション                                 |
| ---- | -------------------------------------- | ---------------------------------------------- |
| PASS | 全ファイルで全指標が最低基準を満たす   | Phase 8へ進行                                  |
| FAIL | いずれかのファイル・指標が最低基準未達 | Phase 6に戻りテストを追加後、再度Phase 7を実行 |

### Task 3: 未カバー領域の分析

カバレッジ未達の場合、以下を分析する:

1. **未カバー行の特定**: どの行・分岐がテストされていないか
2. **原因分析**: テスト不足か、到達不能コードか
3. **対応方針の決定**:
   - テスト追加で対応可能 → Phase 6に戻る
   - 到達不能コード → コード削除を検討（Phase 8で対応）
   - 外部依存による制約 → 理由を記録し例外とする

**よくある未カバー領域**:

| 領域                     | 想定される原因                   | 対応方針                                  |
| ------------------------ | -------------------------------- | ----------------------------------------- |
| エラーハンドリング分岐   | 異常系テスト不足                 | Phase 6でエッジケーステスト追加           |
| プラットフォーム固有分岐 | OS固有コードのモック不足         | Phase 6でプラットフォームテスト追加       |
| クリーンアップ処理       | 正常系のみテストで異常終了未検証 | Phase 6でエラー時クリーンアップテスト追加 |

### Task 4: カバレッジレポート作成

以下の内容を含むレポートを作成する:

1. 測定日時・測定環境
2. ファイル別カバレッジ数値
3. 基準との照合結果
4. 未カバー領域の分析結果（該当する場合）
5. 総合判定（PASS/FAIL）

---

## カバレッジ未達時のフロー

```
Phase 7: カバレッジ測定
  ├── PASS → Phase 8: リファクタリング
  └── FAIL → Phase 6: テスト拡充（追加テスト作成）
              └── Phase 7: カバレッジ再測定（ループ）
```

最大ループ回数: 3回
3回ループ後もFAILの場合、未カバー理由を記録しPhase 8へ進行する。
