## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

`useFeaturedSkills.ts` に `TODO(human)` が残っており、カテゴリ多様性ロジックは固定ルール中心でユーザーフィードバックを反映できていない。

### 1.2 問題点

- 推薦品質が静的で、利用状況に追従しない。
- 人気度以外の要素（直近利用、評価など）を扱えない。
- アルゴリズム改善の検証指標が仕様化されていない。

### 1.3 放置影響

- おすすめ体験がマンネリ化。
- 追加率改善の余地が未活用のまま残る。

---

## 2. 何を達成するか（What）

### 2.1 目的

おすすめ選定を「カテゴリ多様性 + 利用文脈」へ拡張し、ユーザーにとって有用なカード表示精度を高める。

### 2.2 完了イメージ

- 選定スコア式を明文化。
- popularity 以外の要因（例: 最終使用日、導入率）を評価可能にする。
- A/B比較可能なテストデータセットを定義する。

### 2.3 スコープ

- 含む: スコアリング改善、テスト追加、仕様化。
- 含まない: 外部分析基盤の構築。

---

## 3. どのように実行するか（How）

### 3.1 前提条件

- `useFeaturedSkills.ts` と関連テストを編集可能。
- 推薦指標に使うメタデータの取得可否を確認済み。

### 3.2 推奨アプローチ

1. 現行アルゴリズム（popularity + diversity）を基準実装として固定。
2. 新スコア関数を導入し、重みを定数化する。
3. 回帰防止として「カテゴリ偏り上限」制約を継続する。

### 3.3 実装課題と解決策（親タスクからの教訓）

| 課題                             | 解決策                              |
| -------------------------------- | ----------------------------------- |
| 仕様なき改善で恣意的変更が起きる | 指標と重みを仕様書に明記する        |
| 推薦ロジック変更でテストが壊れる | fixtureベースで比較テストを導入する |

---

## 4. 実行手順

1. 現行ロジックとTODO意図を整理する。
2. 新規スコアリング関数を実装し、重み定数を定義する。
3. 多様性制約（maxPerCategory）との整合を確認する。
4. 単体テストで旧/新アルゴリズムの差分を検証する。
5. 必要なら仕様書（`ui-ux-feature-components.md`）へ選定方針を追記する。
