## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

現状のローディング状態はスピナー中心であり、カードレイアウトの読み込み予告が不足している。

### 1.2 問題点

- FR-7-4 の「スケルトンカード表示」要件を満たしていない。
- 初期表示時にレイアウトの揺れをユーザーが感じやすい。
- 視覚的進捗が乏しく、体感速度が低下する。

### 1.3 放置影響

- UX評価の低下。
- モバイル/低速環境で読み込みストレス増加。

---

## 2. 何を達成するか（What）

### 2.1 目的

ロード中におすすめ領域とグリッド領域のスケルトンを表示し、実データ表示時の視覚ギャップを減らす。

### 2.2 完了イメージ

- おすすめ3枚 + カード6枚相当のプレースホルダーを表示。
- `isLoading` 解除で自然に実カードへ切り替え。
- 既存スピナーは補助情報として最小化または置換。

### 2.3 スコープ

- 含む: スケルトンUI追加、条件レンダリング、テスト追加。
- 含まない: API通信仕様変更。

---

## 3. どのように実行するか（How）

### 3.1 前提条件

- `SkillCenterView/index.tsx` を編集可能。
- 必要なら `SkeletonCard` atom を再利用可能。

### 3.2 推奨アプローチ

1. 既存 `isLoading` 分岐にスケルトン表示を追加する。
2. レスポンシブ列数と整合するスケルトン数を定義する。
3. `data-testid` を付与して表示切替をテストする。

### 3.3 実装課題と解決策（親タスクからの教訓）

| 課題                                 | 解決策                           |
| ------------------------------------ | -------------------------------- |
| ローディング分岐が単純すぎて要件漏れ | FRとテストケースを1対1で紐づける |
| レイアウト崩れの再発                 | 実カードと同じグリッド構造を使う |

---

## 4. 実行手順

1. `isLoading` の既存表示を確認する。
2. おすすめ/カードグリッドに対応するスケルトンコンポーネントを配置する。
3. レスポンシブクラスを実カードと一致させる。
4. ローディング解除時の表示切替をテストで固定する。
5. 必要に応じて仕様書のFR-7-4実装状況を更新する。
