#### P41 対策: インライン関数カバレッジ確認

Vitest の v8 カバレッジプロバイダはインライン arrow function を独立した関数としてカウントする。以下のパターンで Function Coverage が低下しやすい:

- コンポーネント Props 内のインラインコールバック
- `useMemo` / `useCallback` の引数関数
- イベントハンドラのインライン定義

**確認方法**: カバレッジレポートの Function Coverage が基準未達のファイルについて、インライン関数の呼び出し有無を確認する。

### ステップ 3: 未達の場合の対応

#### ループ条件

```
カバレッジ基準未達 → Phase 6 に戻る（テスト追加）→ Phase 7 で再測定
```

#### 未達時の具体的な対応手順

1. **カバレッジレポートを分析**: 未到達の行/分岐/関数を特定
2. **不足箇所リストを作成**: ファイルごとに未カバーの箇所をリスト化
3. **Phase 6 に戻る**: 不足箇所のテストを追加
4. **Phase 7 で再測定**: カバレッジが基準を満たすまで繰り返す

#### よくある未達パターンと対策

| パターン                       | 原因                             | 対策                                       |
| ------------------------------ | -------------------------------- | ------------------------------------------ |
| Branch Coverage 不足           | if/else の片方のパスが未テスト   | 条件分岐の両方をテストする                 |
| Function Coverage 不足         | P41: インライン関数が未呼び出し  | コールバックの戻り値を明示的に検証する     |
| Line Coverage 不足             | エラーハンドリングパスが未テスト | 各 IPC チャネルのエラーケースをテストする  |
| 特定コンポーネントの全指標不足 | テストが不十分                   | 対象コンポーネントのテストケースを追加する |
