# 要件定義書: TASK-UI-05-SKILL-CENTER-VIEW

## メタ情報

| 項目         | 値                                                  |
| ------------ | --------------------------------------------------- |
| タスクID     | TASK-UI-05-SKILL-CENTER-VIEW                        |
| Phase        | 1                                                   |
| 作成日       | 2026-03-01                                          |
| 対象ビュー   | SkillCenterView（新規作成）                         |
| 設計哲学     | 「タップ＆ディスカバー」-- アプリストア型の探索体験 |
| 関連スライス | `agentSlice`（既存利用）                            |
| 複雑度       | medium                                              |

## 目的

ユーザーが直感的にツールを探し、ワンタップで追加できるアプリストア型体験を提供する。AgentView はスキル「選択・実行」に専念させ、SkillCenterView はツールの「発見・管理」に特化する。

---

## 機能要件（FR）

### FR-1: おすすめセクション（FeaturedSection）

| 要件ID | 要件                                                                           | 優先度 |
| ------ | ------------------------------------------------------------------------------ | ------ |
| FR-1-1 | 画面最上部に「おすすめ」セクションを表示する                                   | 高     |
| FR-1-2 | 未追加のツールのみを最大3枚の大きめカード（h=160px）で表示する                 | 高     |
| FR-1-3 | アクセントカラー5%グラデーション（左下から右上）背景を適用する                 | 中     |
| FR-1-4 | アイコンを56px（通常カードより大きめ）で表示する                               | 中     |
| FR-1-5 | stagger出現アニメーション（`opacity 0->1` + `translateY(8px->0)`、200ms間隔）  | 中     |
| FR-1-6 | ツール追加後、追加済みカードをフェードアウトし次のおすすめが繰り上がる         | 中     |
| FR-1-7 | 未追加ツールが0件の場合、おすすめセクションを非表示にする                      | 高     |
| FR-1-8 | おすすめ選定ロジック: 人気度順ソート + カテゴリ多様性確保（同カテゴリ最大2件） | 中     |

**おすすめ選定基準（初期リリース）**:

| 優先度 | 条件                                | 理由                           |

| 2      | `skill.popularity` 降順             | 人気度の高いツールを優先表示   |
| 3      | カテゴリの多様性（同カテゴリ最大2） | 偏りのない推薦のため           |

### FR-3: 追加ボタン（AddButton）モーフィングアニメーション

| 要件ID | 要件                                                                        | 優先度 |
| ------ | --------------------------------------------------------------------------- | ------ |
| FR-3-1 | 「追加する」タップ -> スピナー（最大300ms）-> チェックマーク(✓)モーフィング | 高     |
| FR-3-2 | success-bounce: `scale(1.0 -> 1.15 -> 1.0)` + 色変化（300ms）               | 中     |
| FR-3-3 | ボタンテキストが「追加する」->「追加済み!」に変化する                       | 高     |
| FR-3-4 | ボタン色が primary -> success に変化する                                    | 中     |
| FR-3-5 | 失敗時にボタンが「追加する」に戻り、エラーToastを表示する                   | 高     |
| FR-3-6 | featured（おすすめカード用）とdefaultの2サイズをサポートする                | 中     |

**状態遷移**:

```
[追加する] --タップ--> (スピナー 300ms) --成功--> [追加済み! ✓]
                                          |
                                          +--失敗--> [追加する] + エラーToast
```

**アニメーションフェーズ**:

| フェーズ       | 内容                                        | 時間      |
| -------------- | ------------------------------------------- | --------- |
| タップ直後     | ボタン幅を維持しつつテキスト fadeOut        | 100ms     |
| 処理中         | 中央にスピナー表示                          | 最大300ms |
| 成功           | スピナー -> チェックマーク（✓）モーフィング | 200ms     |
| success-bounce | `scale(1.0 -> 1.15 -> 1.0)` + 色変化        | 300ms     |
| 最終状態       | 「追加済み!」テキスト fadeIn                | 150ms     |

**色変化**:

| 状態   | 背景色                         | 文字色                  |
| ------ | ------------------------------ | ----------------------- |
| 未追加 | `var(--status-primary)`        | `white`                 |
| 追加済 | `var(--status-success-subtle)` | `var(--status-success)` |

### FR-6: ツール操作フロー（追加/削除）

| 要件ID | 要件                                                                                   | 優先度 |
| ------ | -------------------------------------------------------------------------------------- | ------ |
| FR-6-1 | カード内「追加する」ボタンからの追加フロー（AddButton -> useImportSkill -> 成功/失敗） | 高     |
| FR-6-2 | ヘッダー右「+ 追加する」ボタンから既存SkillImportDialogを起動する追加フロー            | 高     |
| FR-6-3 | SkillDetailPanel「このツールを削除」から確認ダイアログ付きの削除フロー                 | 高     |
| FR-6-4 | 削除確認ダイアログ:「"{ToolName}" を削除しますか？この操作は取り消せません」           | 高     |
| FR-6-5 | 削除成功時: DetailPanel閉じる + カードボタンを「追加する」に戻す + Toast表示           | 高     |

**追加フロー（カード内ボタン）**:

```
SkillCard > [追加する] タップ
  -> AddButton: スピナー表示（最大300ms）
  -> useImportSkill(skillName) アクション実行
  -> 成功時:
     -> チェックマーク(✓)モーフィング
     -> success-bounce アニメーション
     -> ボタンテキスト「追加済み!」に変化
     -> おすすめセクション: 追加済みカードをフェードアウト
  -> 失敗時:
     -> ボタンを「追加する」に戻す
     -> エラー Toast 表示
```

**追加フロー（ヘッダーボタン）**:

```
[+ 追加する] ボタン（ヘッダー右）クリック
  -> 既存 SkillImportDialog を表示
  -> useImportSkill() アクション実行
  -> 成功時: カード一覧を更新 + 該当カードのボタンを「追加済み!」に + Toast 表示
  -> 失敗時: エラー Toast 表示
```

**削除フロー**:

```
SkillDetailPanel > [このツールを削除] タップ
  -> 確認ダイアログ:「"{ToolName}" を削除しますか？この操作は取り消せません」
  -> useRemoveSkill(skillName) アクション実行
  -> 成功時: DetailPanel 閉じる + カードのボタンを「追加する」に戻す + Toast 表示
  -> 失敗時: エラー Toast 表示
```

### FR-9: サブダイアログ

| 要件ID | 要件                                                                   | 優先度 | 移管元  |
| ------ | ---------------------------------------------------------------------- | ------ | ------- |
| FR-9-1 | ForkSkillDialog: 既存スキルを複製し新しい名前でカスタマイズ可能にする  | 中     | task-9e |
| FR-9-2 | ImportSkillDialog拡張: GitHub/Gist/URL/ローカルの4ソースタブを追加する | 中     | task-9f |
| FR-9-3 | ExportSkillDialog: Gist/ローカルへのエクスポート機能                   | 中     | task-9f |
| FR-9-4 | GenerateDocsDialog: LLMを使ったドキュメント自動生成 + DocPreview       | 低     | task-9i |

**FR-9-1: ForkSkillDialog（task-9e 移管）**

- SkillDetailPanel の「このツールをフォーク」アクションから起動
- フォームフィールド: 新しいツール名（必須、1-50文字、英数字+ハイフン）、説明文（任意）、コピー対象チェックボックス（agents/references/scripts/assets）
- バリデーション: 名前重複チェック、最低1つのコピー対象選択
- IPC: `skill:fork`（TASK-9E連携チャネル）

**FR-9-2: ImportSkillDialog拡張（task-9f 移管）**

- 4つのインポートソースタブ: GitHub（リポジトリURL+ブランチ+パス）、Gist（Gist ID）、URL（SKILL.md URL）、ローカル（ディレクトリパス）
- 共通フロー: ソース選択 -> 入力 -> 検証(`skill:validateSource`) -> プレビュー -> インポート(`skill:importFromSource`)

**FR-9-3: ExportSkillDialog（task-9f 移管）**

- エクスポート先: Gist（公開/非公開選択）、ローカル（ファイル選択UI）
- 成功後に共有URL表示（Gist の場合）、コピーボタン付き
- IPC: `skill:export`

**FR-9-4: GenerateDocsDialog（task-9i 移管）**

- 出力フォーマット選択（Markdown/HTML/PDF）、言語選択、セクション選択、テンプレート選択
- 生成中はプログレスバー表示
- DocPreview でプレビュー、エクスポート（docIdベース）
- IPC: `skill:docs:generate`, `skill:docs:export`

## IPC連携要件

既存のIPCチャネルを利用する。新規チャネル追加は本タスクのスコープ外（TASK-9F/9E/9Iが担当）。

### 基本IPCチャネル（既存）

| 操作           | IPCチャネル        | 引数                                              | 備考                                 |
| -------------- | ------------------ | ------------------------------------------------- | ------------------------------------ |
| ツール一覧取得 | `skill:list`       | なし                                              | 初期読み込み・リフレッシュ時         |
| ツール追加     | `skill:import`     | `skillName: string`                               | P44解決済み: stringを直接渡す        |
| ツール削除     | `skill:remove`     | `skillName: string`                               | P44/P45解決済み: skillNameに統一済み |
| ツール詳細取得 | `skill:get-detail` | `{ skillId: string }`                             | DetailPanel表示用                    |
| SKILL.md取得   | `skill:readFile`   | `{ skillName: string, relativePath: "SKILL.md" }` | SkillMarkdownCollapse表示用          |

### TASK-9F/9E/9I追加チャネル（サブダイアログ用）

| 操作                 | IPCチャネル              | 引数                                              | 提供元タスク |
| -------------------- | ------------------------ | ------------------------------------------------- | ------------ |
| 外部ソースインポート | `skill:importFromSource` | `ShareTarget`                                     | TASK-9F      |
| インポート元検証     | `skill:validateSource`   | `ShareTarget`                                     | TASK-9F      |
| スキルエクスポート   | `skill:export`           | `{ skillName: string, destination: ShareTarget }` | TASK-9F      |
| スキルフォーク       | `skill:fork`             | `ForkOptions`                                     | TASK-9E      |
| ドキュメント生成     | `skill:docs:generate`    | `{ skillName: string, options: SkillDocOptions }` | TASK-9I      |
| ドキュメント出力     | `skill:docs:export`      | `{ docId: string, format: "md" \| "html" }`       | TASK-9I      |

### IPC契約注意事項

- `skill:import` / `skill:remove`: P44/P45解決済み。引数は `string`（skillName）を直接渡す
- `skill:get-detail`: 引数は `{ skillId: string }` オブジェクト形式（実装契約に準拠）
- `skill:readFile`: TASK-9A契約準拠
- P42準拠の3段バリデーション（型チェック -> 空文字列 -> トリム空文字列）はMain側で実施済み

## UX言語マッピング（5D準拠）

| 旧表現（技術用語） | 新表現（ユーザー言語）   | 理由                               |
| ------------------ | ------------------------ | ---------------------------------- |
| 「スキルセンター」 | 「ツールを探す」         | 目的指向の表現で迷わない           |
| 「スキル」         | 「ツール」               | 日常的に馴染みのある語彙           |
| 「インポート」     | 「追加する」             | 操作が直感的に理解できる           |
| 「パーミッション」 | 「AIにできること」       | 技術的恐怖を和らげる平易な表現     |
| 「有効/無効」      | （廃止）                 | 追加/未追加の2状態のみで十分       |
| 「リムーブ」       | 「このツールを削除」     | 結果が明確な日本語表現             |
| 「フォーク」       | 「このツールをフォーク」 | 開発者向け機能のため技術用語を許容 |

**UX言語適用対象**:

- 画面タイトル: 「ツールを探す」
- ボタンテキスト: 「追加する」「追加済み!」「+ 追加する」
- 権限表示: 「AIにできること」セクション見出し + 各権限バッジの平易な表現
- ゼロステート: 「ツールを探してみよう」
- 削除確認: 「"{ToolName}" を削除しますか？この操作は取り消せません」
- 件数表示: 「XX件のツール」

## アーキテクチャ層別要件

### フロントエンド（Renderer）

- SkillCenterView コンポーネント群のUI表示
- 状態管理: agentSlice 既存利用（個別セレクタ経由、P31対策）
- 画面固有ローカル状態: DetailPanel開閉、削除確認ダイアログ、追加ボタン処理中状態
- TASK-UI-00 共通コンポーネント利用: SearchBar, CardGrid, TabSwitcher, SlideInPanel, Badge, Button, EmptyState
- Atomic Design 準拠: atoms(Badge, Button) -> molecules(SearchBar, TabSwitcher, SkillCard) -> organisms(FeaturedSection, SkillDetailPanel, SkillCenterView)

### バックエンド（Main）

- **変更なし**: 既存SkillServiceをそのまま利用
- IPC ハンドラの追加・修正は不要

### IPC通信

- 既存チャネルのみ利用（新規チャネル追加なし）
- TASK-9F/9E/9Iチャネルは各タスクが提供（本タスクでは利用のみ）
- P42準拠の3段バリデーションはMain側で実施済み

### セキュリティ

- 既存のIPC契約を遵守
- contextBridge経由API公開（既存APIのみ利用）
- Renderer から Node.js API を直接使用しない（01-architecture.md 準拠）
- 入力値はMain側でバリデーション済み（パストラバーサル攻撃対策含む）
