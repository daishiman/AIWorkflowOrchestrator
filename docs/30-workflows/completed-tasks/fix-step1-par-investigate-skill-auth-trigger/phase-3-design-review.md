## 目的

Phase 1（調査要件定義）と Phase 2（調査設計）の結果をレビューし、調査方法の妥当性を確認する。
**このゲートはユーザー承認が必須**。承認を得てから Phase 4（テスト仕様作成）へ進む。

## ゲート要件

このフェーズはゲートフェーズである。以下の判断が必要:

- **PASS**: 調査方法が妥当と判断され、Phase 4 以降の修正フェーズへ進む
- **MAJOR**: 調査方法に重大な問題があり、Phase 1 または Phase 2 へ戻る
- **PENDING**: ユーザー承認待ち（このタスクのデフォルト状態）

## レビュー観点

| 観点             | チェック内容                                         |
| ---------------- | ---------------------------------------------------- |
| 調査方法の妥当性 | `console.trace()` によるスタックトレース取得は有効か |
| スコープの適切さ | 調査対象が過大または過小でないか                     |
| 副作用リスク     | デバッグコード挿入が既存機能を壊さないか             |
| 修正方針の妥当性 | ステップ5で定義した修正パターンが網羅的か            |
| 破棄判断の妥当性 | patch か再構成かの判断基準が明確か                   |
| 完了基準の明確さ | 検証4条件で「調査完了」と判定できるか                |

## ユーザー承認事項

以下についてユーザーから承認を得ること:

1. `authSlice.ts` の `login()` に `console.trace()` を一時追加する方針
2. 調査完了後にデバッグコードを除去するコミットを作成する方針
3. 特定された呼び出し経路に基づいて修正を行う方針（修正内容は Phase 5 で確定）
4. Phase 5 開始前に再度修正内容の承認を得ること
5. 既存実装の破棄が最小複雑性になる場合は、別途ユーザー承認を取り直すこと

## 修正フェーズへの引き渡し条件

以下が全て確認された場合のみ Phase 4 へ進む:

- [ ] ユーザーから調査方法の承認を得た
- [ ] 全レビュー観点が PASS になった
- [ ] デバッグコード除去の責任者が明確になっている
- [ ] Phase 5 で修正前に再確認を行う合意が取れた
- [ ] 破棄判断が必要な場合の再承認フローが明記されている
