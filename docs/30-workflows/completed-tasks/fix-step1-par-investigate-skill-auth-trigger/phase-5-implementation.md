# Phase 5: 調査実行 + 不要呼び出しの修正

## メタ情報

| 項目   | 値                        |
| ------ | ------------------------- |
| Phase  | 5                         |
| 機能名 | TASK-TRACE-SKILL-AUTH-001 |
| 作成日 | 2026-04-01                |

## 目的

Phase 2 で設計した調査手順を実行し、`auth:login` の不要な呼び出し経路を特定・除去する。
このフェーズは「実装」ではなく「**調査実行 + 修正**」である。

## 前提条件

- Phase 3 ゲートでユーザー承認を得ていること
- Phase 4 でテスト仕様が確定していること
- TC-01 が RED（失敗）状態であることを確認していること
- patch か再構成かの破棄判断を Phase 2/3 の結果で仮固定していること

## 実行手順

### ステップ0: 修正方針の最終確定

Phase 2/3 の分析結果をもとに、patch で十分か、再構成が最小複雑性かを確定する。

- patch で十分な場合: 最小変更で trace → 修正 → cleanup を進める
- 再構成が最小複雑性の場合: 実装を止め、ユーザーに再承認を求める

### ステップ1: デバッグコードの挿入

対象ファイル: `apps/desktop/src/renderer/store/slices/authSlice.ts`

`login()` thunk の先頭に以下を追加する:

```typescript
// [TEMP DEBUG] TASK-TRACE-SKILL-AUTH-001 — 調査完了後に必ず削除すること
console.trace("[TRACE-SKILL-AUTH-001] auth/login が呼び出されました");
```

コミットはしない（調査専用の一時変更）。

### ステップ2: アプリ起動 + スキル生成ボタン押下

```bash
pnpm --filter @repo/desktop dev
```

Electron アプリを起動し、スキル生成画面でスキル生成ボタンを押下する。

### ステップ3: スタックトレースの記録

DevTools コンソールで `[TRACE-SKILL-AUTH-001]` のログを確認し、スタックトレースを記録する。

記録形式（`stacktrace-evidence.md` に保存）:

```
## 取得日時
2026-XX-XX HH:MM

## 操作
スキル生成ボタン押下

## スタックトレース
Error: [TRACE-SKILL-AUTH-001] auth/login が呼び出されました
    at authSlice.ts:XX (login)
    at <呼び出し元ファイル>:XX (<関数名>)
    at <さらに上位>:XX
    ...

## 特定された呼び出し元
- ファイル: <特定されたファイルパス>
- 関数: <特定された関数名>
- 行番号: <行番号>
- トリガー条件: <スキル生成のどのタイミングか>
```

### ステップ4: 原因分析

スタックトレースをもとに以下を分析する:

| 分析項目       | 内容                             |
| -------------- | -------------------------------- |
| 直接呼び出し元 | スタックの上部から特定           |
| 連鎖の起点     | スキル生成ボタン押下との関連     |
| 修正すべき箇所 | Phase 2 の修正パターンと照合     |
| 影響範囲       | 修正が他の機能に影響しないか確認 |

### ステップ5: 修正実施

**修正前に必ずユーザーに修正内容を確認すること（再確認ゲート）。**

特定されたパターンに応じて修正を行う:

| パターン                            | 修正箇所                 | 修正内容                               |
| ----------------------------------- | ------------------------ | -------------------------------------- |
| 条件なしでlogin()を呼んでいる       | 特定された呼び出し元     | `isLoggedIn` チェックを追加する        |
| useEffect の依存配列が不適切        | 特定されたコンポーネント | 依存配列を `[]` または適切な値に修正   |
| dispatch チェーンで意図せず呼ばれる | middleware / thunk       | 呼び出し条件を追加する                 |
| 意図的だが不要                      | 特定された呼び出し箇所   | 呼び出しを削除またはコメントアウト     |
| patch では責務境界が壊れる          | 特定された複数箇所       | 再構成案を提示し、ユーザー再承認を得る |

### ステップ6: デバッグコードの除去

修正完了後、`authSlice.ts` から `[TEMP DEBUG]` のコードを除去する。

確認コマンド:

```bash
# デバッグコードが残っていないことを確認
grep -r "TEMP DEBUG" apps/desktop/src/
grep -r "TRACE-SKILL-AUTH-001" apps/desktop/src/
```

### ステップ7: テストの実行（Green 確認）

```bash
# TC-01 が GREEN になることを確認
pnpm --filter @repo/desktop test -- --grep "auth:login"

# TC-02, TC-04 も継続して GREEN であることを確認
pnpm vitest run
```

## 修正サマリー記録

修正完了後に `fix-summary.md` を作成し、以下を記録する:

- 特定された呼び出し経路
- 修正したファイルと行番号
- 修正の理由と影響範囲
- patch / 再構成の破棄判断と、その根拠
- デバッグコード除去の確認
