## 目的

`auth:login` の不要な呼び出し経路を特定するための調査手順・デバッグ方法・検証4条件の確認方法を設計する。
Phase 3 のゲートでユーザー承認を得るための根拠となる設計書を作成する。

## 調査手順（5ステップ）

### ステップ1: authSlice.ts の login() にスタックトレース出力を追加

対象ファイル: `apps/desktop/src/renderer/store/slices/authSlice.ts`

`login()` thunk を最小侵襲な観測点として使う。もし trace がノイズ過多なら、同じ `auth:login` 境界を保ったまま観測位置を上げる。

`login()` thunk の先頭に以下のコードを一時的に追加する:

```typescript
// [TEMP DEBUG] スタックトレース取得用 — 調査完了後に必ず削除すること
console.trace("[TRACE-SKILL-AUTH-001] auth/login が呼び出されました");
```

注意事項:

- このデバッグコードは調査完了後に必ず除去する
- コメントに `[TEMP DEBUG]` プレフィックスをつけることで検索しやすくする

### ステップ2: スキル生成ボタン押下

Electron アプリを起動し、スキル生成ボタンを押下する。
この操作で `auth:login` IPC が発火するかを確認し、発火した場合のみスタックトレースをコンソールに記録する。
発火しない場合は、その事実自体を重要な調査結果として記録する。

### ステップ3: コンソールでスタックトレースを確認

Electron の DevTools（Renderer プロセス側）を開き、コンソールログを確認する。
`[TRACE-SKILL-AUTH-001]` のプレフィックスでフィルタリングする。

取得すべき情報:

- 呼び出し元ファイル名
- 呼び出し元関数名
- 呼び出し元行番号
- useEffect / dispatch 等の中間層の有無

### ステップ4: 呼び出し経路を特定

スタックトレースをもとに以下を特定する:

| 確認項目                | 確認方法                                 |
| ----------------------- | ---------------------------------------- |
| 直接呼び出し元          | スタックトレースの一番上                 |
| 連鎖の起点              | スタックトレースを下に辿る               |
| useEffect の有無        | スタックに `useEffect` が含まれるか      |
| Redux dispatch チェーン | スタックに dispatch / thunk が含まれるか |
| スキル生成との関連      | スキル生成ボタン押下との時系列相関       |

### ステップ5: 不要な呼び出しを除去

特定された呼び出し経路に基づき、以下のいずれかの修正を行う:

| パターン                            | 修正方針                                                 |
| ----------------------------------- | -------------------------------------------------------- |
| 条件なしでlogin()を呼んでいる       | auth 状態チェックを先に行い、未ログイン時のみ呼ぶ        |
| useEffect の依存配列が不適切        | 依存配列を修正してスキル生成時に再実行されないようにする |
| dispatch チェーンで意図せず呼ばれる | middleware またはthunk の呼び出し条件を修正する          |
| 意図的だが不要                      | 呼び出し箇所を削除または無効化する                       |

破棄判断:

- 1つの呼び出し箇所だけを直すと責務境界が崩れる場合は、patch ではなく再構成候補として Phase 3 に戻す
- 再構成が最小複雑性と判断される場合は、Phase 5 開始前にユーザー承認を取り直す

## 検証4条件の確認方法

| 条件                 | 確認方法                                                                    |
| -------------------- | --------------------------------------------------------------------------- |
| スタックトレース取得 | `console.trace()` の出力がコンソールに表示されること                        |
| 呼び出し元特定       | スタックトレースに具体的なファイル名・関数名・行番号が含まれること          |
| トリガー条件特定     | スキル生成ボタン押下と `auth:login` 呼び出しの時系列が一致すること          |
| 修正方針確定         | 特定されたパターンに対する修正アプローチが Phase 3 レビューで承認されること |

## デバッグ実行環境

| 項目             | 設定                                                      |
| ---------------- | --------------------------------------------------------- |
| 実行環境         | `pnpm --filter @repo/desktop dev`                         |
| DevTools 開き方  | Electron ウィンドウ右クリック → Inspect Element           |
| ログフィルター   | `[TRACE-SKILL-AUTH-001]` でフィルタリング                 |
| タイムアウト設定 | `auth:login` のタイムアウト値を一時的に延長することも検討 |

## リスクと対策

| リスク                           | 対策                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| スタックトレースが不明瞭         | `Error` オブジェクトを生成して `stack` プロパティを出力する |
| 開発環境と本番環境で挙動が異なる | 開発環境（`pnpm dev`）で再現確認を行う                      |
| タイムアウトで取得できない       | `safeInvoke` のタイムアウト値を一時的に延長する             |
| 呼び出しが非同期で追跡困難       | `AsyncLocalStorage` またはカスタムコンテキストを利用する    |
| patch で足りない変更を無理に押す | 再構成候補として Phase 3 / 5 へ戻し、ユーザー承認を取り直す |
