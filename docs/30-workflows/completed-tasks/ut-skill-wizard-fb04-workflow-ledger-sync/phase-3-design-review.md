- チェックリスト文言が明確・検証可能であること

- 既存テンプレート構造との整合性

## 実行タスク

> **Task / Step 分離ルール**: このセクションには plan のみを書く。実行結果は `outputs/phase-3/` へ記録する。

### タスク1: 設計レビュー実施

**目的**: Phase 2 の 4 設計書に対してレビューを実施し、判定を出す

**実行手順**:

1. `outputs/phase-2/skill-md-entry-design.md` をレビューする
2. `outputs/phase-2/compliance-template-design.md` をレビューする
3. `outputs/phase-2/guide-step1a-design.md` をレビューする
4. `outputs/phase-2/design-consistency-check.md` をレビューする
5. 各設計に対して PASS / MINOR / MAJOR / CRITICAL を判定する
6. レビュー結果を `outputs/phase-3/design-review-result.md` に記録する

**レビュー観点**:

| 観点         | 確認項目                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 文言の明確性 | チェックリスト項目が「誰でも同じ判断ができる」レベルで記述されているか |
| 網羅性       | 5 同期対象ファイルが全件含まれているか                                 |
| 重複・冗長   | 既存チェックリストと意味的に重複していないか                           |
| 配置の適切性 | 挿入位置が Phase 12 の実行フローに沿っているか                         |
| AC 充足      | AC-1〜AC-6 が設計で全て満たされているか                                |
| 命名の一貫性 | 既存テンプレートの命名パターン（`[FB-XX]` 形式等）に従っているか       |

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                                           | 次のアクション             |
| -------- | ---------------------------------------------- | -------------------------- |
| PASS     | 全レビュー観点で問題なし                       | Phase 4 へ進行             |
| MINOR    | 文言の調整・軽微な追記が必要                   | 指摘対応後、Phase 4 へ進行 |
| MAJOR    | 設計の見直しが必要（構造・配置・網羅性の問題） | Phase 2 へ戻り設計修正     |
| CRITICAL | AC 充足不可・根本的な要件の問題                | Phase 1 へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類               | 戻り先              |
| ------------------------ | ------------------- |
| 要件（AC）の問題         | Phase 1（要件定義） |
| 設計の構造・網羅性の問題 | Phase 2（設計）     |
