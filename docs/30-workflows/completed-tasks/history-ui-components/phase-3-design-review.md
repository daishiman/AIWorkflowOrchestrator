## 目的

実装開始前に要件・設計の妥当性を検証する。

## 判定基準

| 判定  | 条件             | 対応                         |
| ----- | ---------------- | ---------------------------- |
| PASS  | 全観点で問題なし | Phase 4へ進行                |
| MINOR | 軽微な指摘あり   | 指摘対応後Phase 4へ進行      |
| MAJOR | 重大な問題あり   | 影響範囲に応じて戻り先を決定 |

## レビュー観点

### 1. 要件整合性

| チェック項目                                   | 確認方法                         |
| ---------------------------------------------- | -------------------------------- |
| 全機能要件（FR-01〜FR-06）がカバーされている   | 設計書とFRの対応確認             |
| 全非機能要件（NFR-01〜NFR-04）が考慮されている | アクセシビリティ・性能設計の確認 |

### 2. コンポーネント設計

| チェック項目                               | 確認方法                  |
| ------------------------------------------ | ------------------------- |
| Atomic Designの原則に従っている            | 階層構造の確認            |
| Props設計がTypeScript的に正しい            | 型定義の確認              |
| 責務が適切に分離されている                 | Single Responsibility確認 |
| 再利用可能なコンポーネントが識別されている | 共通コンポーネントの確認  |

### 3. カスタムフック設計

| チェック項目                       | 確認方法                |
| ---------------------------------- | ----------------------- |
| Hooksの命名規則に従っている        | `use`プレフィックス確認 |
| 戻り値の型が明確に定義されている   | 型定義の確認            |
| エラーハンドリングが考慮されている | エラー状態の設計確認    |
| ローディング状態が考慮されている   | isLoading設計確認       |

### 4. データフロー

| チェック項目                     | 確認方法                      |
| -------------------------------- | ----------------------------- |
| IPC通信の設計が適切              | window API設計の確認          |
| 状態管理の戦略が明確             | ローカル/グローバル状態の確認 |
| エラー伝播が適切に設計されている | Result型の使用確認            |

### 5. アクセシビリティ

| チェック項目                             | 確認方法                       |
| ---------------------------------------- | ------------------------------ |
| キーボードナビゲーションが考慮されている | tabIndex、フォーカス管理の設計 |
| ARIA属性の使用が計画されている           | role、aria-\*属性の設計確認    |
| 色だけに頼らない情報伝達が設計されている | アイコン、テキストラベルの確認 |

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点       | 確認項目                               |
| ------------------ | -------------------------------------- |
| IPC設計            | IPC チャンネル定義の妥当性             |
| データフロー       | Renderer→IPC→Service→Repository の設計 |
| エラーハンドリング | IPC通信失敗時のUI表示設計              |
| 型整合性           | フロント/バックエンド間の型一致        |
