## Pitfall適合チェック

| Pitfall | タイトル                      | 設計の対応                                                                                                                           | 抵触 |
| ------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| P31     | Zustand Store Hooks無限ループ | 合成Hookを使用せず、`isExecuting` を個別セレクタまたはプリミティブ直接セレクタで参照。Store内部の `get()` 使用は安全（Hookではない） | No   |
| P48     | useShallow未適用無限ループ    | `isExecuting` はプリミティブ型（boolean）のため `Object.is` 比較で安定。`useShallow` は不要                                          | No   |
| P5      | リスナー二重登録              | リスナー登録は変更しないため影響なし。`setupSkillListeners.ts` の `onComplete` / `onError` は既存のまま                              | No   |
| P42     | .trim()バリデーション漏れ     | 文字列引数の追加はないため影響なし。`isExecuting` はboolean型                                                                        | No   |

### 補足: P31境界の詳細整理

- **Store内部（`get()`）:** `get().isExecuting` はZustandのStore内部APIであり、React Hookではない。P31の対象外
- **UIコンポーネント（セレクタ）:** `useAppStore((s) => s.isExecuting)` はプリミティブ型のセレクタであり、合成Hookではない。P31の対象外
- **合成Hookパターン:** 今回の設計では合成Hookの新規作成・使用は一切行わない。P31リスクゼロ

### 補足: P48境界の詳細整理

- `isExecuting` はboolean型であり、`Object.is(true, true)` は常に `true` を返す
- `.filter()` / `.map()` による新しい配列参照の生成は発生しない
- `useShallow` の適用は不要

## 設計リスク評価

| リスク項目                                 | 評価 | 対策                                                                                                                             |
| ------------------------------------------ | ---- | -------------------------------------------------------------------------------------------------------------------------------- |
| `get().isExecuting` のタイミングウィンドウ | 低   | Zustandの `get()` は同期的でありatomicに近い。JavaScriptのシングルスレッドモデルにより、同一マイクロタスク内での競合は発生しない |
| UI disabledとStore ガードの状態不整合      | 極低 | 同一の `isExecuting` stateを参照するため一致が保証される                                                                         |
| 既存テストへの影響                         | 極低 | 初回実行時は `isExecuting === false` であり、ガードを通過する。既存テストフローは影響を受けない                                  |
| listener復元経路の破損                     | 低   | `_handleComplete` / `_handleError` は変更しない。Phase 6で回帰確認を実施                                                         |
| ChatPanel の直接プリミティブ参照           | 低   | `useAppStore((s) => s.isExecuting)` はP31非該当。合成Hook化しないことだけを維持する                                              |
