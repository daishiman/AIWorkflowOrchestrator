## 目的

全体品質・整合性を検証し、手動テストに進む前の最終確認を行う。

## 背景

Phase 1-9で要件定義、設計、実装、テスト、品質保証が完了した。本Phaseでは、総合的なレビューを実施する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1で定義した要件が全て満たされているか確認する

**実行手順**:

1. Phase 1の要件定義（`outputs/phase-01/requirements.md`）を確認する
2. 各要件に対して充足状況を確認する
3. 未充足の要件がある場合は、原因を調査する
4. 確認結果を記録する

**期待される成果物**:

- 要件充足確認結果

---

### タスク2: 設計準拠確認

**目的**: Phase 2の設計に準拠して実装されているか確認する

**実行手順**:

1. Phase 2の設計書（`outputs/phase-02/design-document.md`）を確認する
2. 実装が設計に準拠しているか確認する
3. 逸脱がある場合は、正当な理由があるか確認する
4. 確認結果を記録する

**期待される成果物**:

- 設計準拠確認結果

---

### タスク3: 最終レビュー判定

**目的**: 総合的なレビューを実施し、判定を行う

**実行手順**:

1. 以下の観点でレビューする
   - 要件が全て充足されているか
   - 設計に準拠しているか
   - テストカバレッジが十分か
   - 品質基準を満たしているか
2. 判定結果を決定する
   - PASS: 問題なし → Phase 11へ
   - MINOR: 軽微な修正 → 修正後Phase 11へ
   - MAJOR: 重大な問題 → 該当Phaseへ戻る
3. レビュー結果を記録する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`

## レビューゲート判定

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11へ進行            |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 11へ    |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
