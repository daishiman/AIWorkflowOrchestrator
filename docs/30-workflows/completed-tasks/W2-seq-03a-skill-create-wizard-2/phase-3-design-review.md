## 目的

設計の矛盾・漏れ・依存関係を確認し、Phase 4 への進行可否を判断する。

## 背景

Phase 2 で設計した `SkillCreateWizard.tsx` の新設計（3 ステップ、useState 状態管理、inferSmartDefaults 統合、計装ポイント 5 つ）が、受け入れ基準 AC-01〜AC-07 を満たすか、矛盾・漏れがないかを確認する。

## 実行タスク

### タスク1: 多角的設計検証（30 種の思考法を全適用）

**目的**: 設計を多角的に検証する

**実行手順**:

1. **システム思考**: 責務境界の問題点はないか確認する
2. **依存関係分析**: Wave 1 コンポーネントとの依存が正しく設計されているか確認する
3. **価値とコストの見方**: 初回スコープで得る価値と導入コストを評価する
4. **仮説思考**: `useState` vs Zustand の判断が適切か再評価する
5. **問題解決思考**: `inferSmartDefaults` エラー時のフォールバックが設計されているか確認する
6. **全30種適用マトリクス**: 下表の 30 項目すべてについて、`outputs/phase-3/design-review-result.md` に観点メモを 1 行以上残す

| カテゴリ     | 思考法               | 確認ポイント                             |
| ------------ | -------------------- | ---------------------------------------- |
| 論理分析系   | 批判的思考           | 矛盾・飛躍・前提漏れがないか             |
| 論理分析系   | 演繹思考             | 大前提から結論までが一貫するか           |
| 論理分析系   | 帰納的思考           | 個別ケースから一般化しすぎていないか     |

| 構造分解系   | 要素分解             | 要件が最小単位まで分解されているか       |
| 構造分解系   | MECE2軸思考          | 漏れと重複がないか                       |
| 構造分解系   | プロセス思考         | 実行順序が自然で依存順に並ぶか           |
| メタ・抽象系 | メタ思考             | そもそも何を解くべきか再定義したか       |
| メタ・抽象系 | 抽象化思考           | 個別実装を抽象レベルへ持ち上げられるか   |
| メタ・抽象系 | ダブル・ループ思考   | 前提自体を見直す余地があるか             |
| 発想・拡張系 | ブレインストーミング | 代替案を十分に広げたか                   |

| 発想・拡張系 | 類推思考             | 類似ドメインの成功パターンを持ち込めるか |
| 発想・拡張系 | if思考               | 前提変更時の分岐を検討したか             |
| 発想・拡張系 | 素人思考             | 初見の人が詰まらないか確認したか         |
| システム系   | システム思考         | 全体の振る舞いに破綻がないか             |
| システム系   | 因果関係分析         | 何が何を引き起こすか明示できるか         |
| システム系   | 因果ループ           | 強化/抑制ループが破綻していないか        |
| 戦略・価値系 | トレードオン思考     | 競合する価値を両立できるか               |
| 戦略・価値系 | プラスサム思考       | ゼロサムではなく全体最適になっているか   |
| 戦略・価値系 | 価値提案思考         | 誰のどのコストを下げるか明確か           |

### タスク2: `inferSmartDefaults` エラー時フォールバック確認

**目的**: 呼び出しエラー時の挙動が設計されているか確認する

**実行手順**:

1. `inferSmartDefaults` が例外を投げた場合の処理を確認する
2. null を返す設計か、デフォルト値を使う設計か確認する
3. エラー時の UX への影響を評価する

**期待される成果物**:

- フォールバック設計確認記録

---

### タスク3: 旧設計との互換性破壊箇所の全列挙

**目的**: 破壊的変更が全て特定されていること確認する

**実行手順**:

1. Phase 1 の影響範囲マップと照合する
2. 削除される state・ハンドラ・Props を全て列挙する
3. 依存コンポーネント（ConversationRoundStep / CompleteStep / wizard/index.ts）への影響を確認する
4. 対処方針（削除・更新・新設）を決定する

**期待される成果物**:

- 破壊的変更一覧（`outputs/phase-3/breaking-changes.md`）

---

### タスク4: レビュー結果の判定と記録

**目的**: PASS / MINOR / MAJOR / CRITICAL を判定する

**実行手順**:

1. 全レビュー観点で問題がないか確認する
2. 指摘事項があれば記録する
3. レビュー結果を判定する
4. `outputs/phase-3/design-review-result.md` に記録する

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション             |
| -------- | ------------------------ | -------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4 へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4 へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る       |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻りユーザー確認 |

| ---------- | ------------------- |

| 設計の問題 | Phase 2（設計）     |
