## 採用方式: useState（ローカル状態管理）

### 判断理由

| 観点           | useState                           | Zustand slice                  | 判断                           |
| -------------- | ---------------------------------- | ------------------------------ | ------------------------------ |
| スコープ       | ウィザード内部のみ                 | アプリ全体で共有可能           | useState が適切                |
| テスタビリティ | render テストで直接確認可能        | store mock が必要              | useState が有利                |
| 永続化         | 不要（ウィザード閉じたらリセット） | 永続化も可能                   | 永続化不要なので useState      |
| パフォーマンス | re-render は最小限                 | 不要な再レンダリング防止が必要 | 差なし（小規模コンポーネント） |

### 結論

> **useState を採用する。** ウィザードのステップ状態・フォームデータは全てウィザードコンポーネント内部で完結するため、外部ストアへの依存は不要。ただし `createSkill` 等の副作用は既存 Zustand store hooks（`useCreateSkill` 等）を引き続き使用する。

### 将来移行方針

ウィザードの状態を別ページから参照する必要が生じた場合（例: ウィザードを閉じても途中保存したい）に Zustand slice への移行を検討する。その際は:

1. `useWizardFormStore` slice を新設
2. `useState` → `useWizardFormStore` への差し替え
3. テストは store mock を追加

### useWizardStep フック

ステップのインクリメント/デクリメント/ジャンプは `useWizardStep(STEPS.length)` カスタムフックに委譲。このフックは内部で `useState` を使用しており、ステップ境界チェック（0未満・最大超過防止）を提供する。
