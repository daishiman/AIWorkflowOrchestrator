## レビュー観点

### 要件との整合性

- [ ] 全ての機能要件が設計でカバーされているか
- [ ] 非機能要件（パフォーマンス、精度）が考慮されているか
- [ ] 受け入れ基準を満たす設計になっているか

### アーキテクチャの妥当性

- [ ] IRelationExtractorインターフェースが適切に設計されているか
- [ ] 依存関係逆転の原則に従っているか
- [ ] LLMプロバイダーとの疎結合が実現されているか

### 型設計の適切さ

- [ ] 関係タイプ（RelationType）が網羅的か
- [ ] ExtractedRelation型が必要な情報を含んでいるか
- [ ] Zodスキーマが適切にバリデーションを行えるか

### 統合ポイントの検証

- [ ] エンティティ抽出サービスとの連携が明確か
- [ ] ExtractionPipelineへの統合方法が設計されているか
- [ ] エラーハンドリングの方針が決まっているか

## レビューゲート判定

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |

### 判定チェックリスト

**PASS条件**:

- [ ] 要件との整合性: 全項目OK
- [ ] アーキテクチャの妥当性: 全項目OK
- [ ] 型設計の適切さ: 全項目OK
- [ ] 統合ポイントの検証: 全項目OK

**MINOR条件**:

- [ ] 軽微な命名改善の指摘
- [ ] ドキュメントの補足追記
- [ ] オプショナルな改善提案

**MAJOR条件**:

- [ ] インターフェース設計の変更が必要
- [ ] 型定義の大幅な変更が必要
- [ ] 要件の解釈に問題がある

**CRITICAL条件**:

- [ ] 要件自体に矛盾がある
- [ ] 技術的に実現不可能な設計
- [ ] スコープの大幅な変更が必要
