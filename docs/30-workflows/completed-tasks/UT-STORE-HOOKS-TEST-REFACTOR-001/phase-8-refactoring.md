## 目的

テストコードの品質を改善し、3つのSliceテスト間のパターンを統一する。重複の排除とテストユーティリティの整理を行う。

## 実行タスク

### タスク1: テストパターンの統一

**目的**: authModeSlice/llmSlice/agentSliceテスト間のパターンを統一

**実行手順**:

1. Store初期化パターンの統一確認
   - resetStore() の呼び出し方法
   - createMockElectronAPI() の使い方
2. テスト記述パターンの統一
   - describe構造の統一
   - テスト命名規則の統一
   - 参照安定性テストのパターン統一

### タスク2: 重複コードの排除

**目的**: テスト間の重複コードを最小化

**実行手順**:

1. 共通のmock設定の抽出（createMockElectronAPI等）
2. 共通のresetStore処理の統一
3. 重複するテストヘルパーの統合
4. `vi.restoreAllMocks()` と `vi.clearAllMocks()` の使い分けを統一
   - `restoreAllMocks()`: 元の実装に戻す（推奨 — afterEachで使用）
   - `clearAllMocks()`: 呼び出し履歴のみクリア（beforeEachで使用する場合）
   - 3ファイル間で統一パターンを適用

### タスク3: テストの可読性改善

**目的**: テストコードの可読性と保守性を向上

**実行手順**:

1. テスト名が検証内容を明確に表現していることを確認
2. テストグループ（describe）の構造が論理的であることを確認
3. 不要なコメントの削除、必要なコメントの追加
4. 内部アクション（`_handleStreamMessage` 等のプレフィックス `_` 付き）のテスト方針を確認
   - 内部アクションは直接テストせず、公開アクション経由で間接テストする方針を確認
