## 目的

Phase 5で移行したテストのカバレッジ不足箇所を特定し、参照安定性テスト・再レンダリングテスト・エッジケースを拡充する。

---

## 実行タスク

### タスク1: カバレッジ不足の特定

**実行手順**:

```bash
pnpm --filter @repo/desktop test -- --run --coverage agentSlice.selectors
```

1. Line/Branch/Function カバレッジを確認
2. 未カバー行・分岐を特定
3. 追加テストの優先度を決定

### タスク2: 参照安定性テストの拡充

**目的**: 全Sliceテストで参照安定性テストが十分に実施されていることを確認

**拡充対象**:

- agentSlice: CAT-05の4テストに加え、全アクションセレクタの参照安定性を追加
- authModeSlice/llmSlice: 不足があれば追加（既にrenderHook使用のため、確認のみの場合あり）

**設計原則**: 「1 selector = 1 field」に基づき、各セレクタHookが単一フィールドのみの変更で再レンダリングされることを検証する。関連しないフィールドの変更では再レンダリングが発生しないことを確認。

### タスク3: 再レンダリング・状態変更テストの拡充

**目的**: 状態変更時のHook動作を網羅的にテスト

**拡充内容**:

- 複数の状態が同時に変更された場合のテスト
- 関連しない状態が変更された場合に不要な再レンダリングが発生しないことのテスト

### タスク4: エッジケーステスト

**目的**: 境界値・異常系テストの追加

**テスト例**:

- 空配列/null/undefinedの状態セレクタ
- 大量データ時のセレクタ動作
- 高速連続状態変更時の動作

### タスク5: resetStore()フィールドスコープの検証

**目的**: resetStore()がagentSliceの全フィールド（13状態フィールド）を正しくリセットすることを検証

**確認項目**:

- [ ] resetStore()呼び出し後、全13状態セレクタが初期値を返す
- [ ] resetStore()がauthModeSlice/llmSliceのフィールドに影響しない（隔離性）
