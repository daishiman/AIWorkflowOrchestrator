## 目的

実際のユーザー環境で機能をテストし、UX・パフォーマンスを検証する。自動テストでは検証できないユーザー体験の品質を確認する。

## 背景

ストリーミング機能はユーザー体験に直結するため、実際の操作感・レスポンス・視覚的フィードバックを人間が確認する必要がある。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 環境セットアップ

**目的**: テスト環境の準備

**実行手順**:

1. 開発ビルドの起動（`pnpm --filter @repo/desktop dev`）
2. 各プロバイダーのAPIキー設定確認
3. テストシナリオの準備

**期待される成果物**:

- テスト環境確認チェックリスト

---

### タスク2: ストリーミングUXテスト

**目的**: ストリーミング体験の品質確認

**実行手順**:

1. 各プロバイダーでストリーミングを開始
2. レスポンスのリアルタイム表示を確認
3. カーソル・インジケーターの動作確認
4. 長文レスポンスのスクロール挙動確認

**テスト観点**:

| 項目               | 確認内容                          |
| ------------------ | --------------------------------- |
| 表示遅延           | チャンク受信から表示まで100ms未満 |
| スムーズな追記     | ちらつきなく文字が追加される      |
| 自動スクロール     | 新規テキストが表示領域に入る      |
| ストリーミング表示 | タイピングカーソルが表示される    |

---

### タスク3: キャンセル操作テスト

**目的**: キャンセル機能のUX確認

**実行手順**:

1. ストリーミング中にキャンセルボタンをクリック
2. 即座に停止することを確認
3. 途中までのテキストが保持されることを確認
4. 再度リクエストできることを確認

**テスト観点**:

| 項目               | 確認内容                       |
| ------------------ | ------------------------------ |
| キャンセル反応速度 | クリックから500ms以内に停止    |
| 部分テキスト保持   | 途中までの内容が表示されている |
| 状態リセット       | isStreaming=falseになっている  |
| 再リクエスト可能   | 次のリクエストが送信できる     |

---

### タスク4: エラーシナリオテスト

**目的**: エラー発生時のUX確認

**実行手順**:

1. 無効なAPIキーでリクエスト
2. ネットワーク切断をシミュレート
3. レート制限エラーをシミュレート
4. エラーメッセージの表示を確認

**テスト観点**:

| 項目             | 確認内容                   |
| ---------------- | -------------------------- |
| エラー表示       | 分かりやすいメッセージ表示 |
| 状態回復         | エラー後に再試行できる     |
| 部分テキスト扱い | エラー前のテキストが見れる |

---

### タスク5: パフォーマンステスト

**目的**: 実際の応答速度・メモリ使用量確認

**実行手順**:

1. 長時間のストリーミングを実行
2. メモリ使用量をモニタリング
3. 複数回連続でリクエストを送信
4. DevToolsでパフォーマンスを確認

**テスト観点**:

| 項目           | 確認内容                 |
| -------------- | ------------------------ |
| メモリリーク   | 連続使用でメモリ増加なし |
| 初回レスポンス | TTFB 3秒以内             |
| CPU使用率      | ストリーミング中も安定   |
