## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

390px幅の手動検証で、カード内の二次情報が詰まり気味に見え、読みやすさに改善余地が確認された。

### 1.2 問題点・課題

- モバイル幅で行間・余白が不足し、視認負荷が高い
- 情報優先度（主情報/副情報）の視覚差が弱い

### 1.3 放置した場合の影響

- モバイル利用時の可読性が低下する
- 同じ情報量でも「窮屈」に感じる印象が残る

## 2. 何を達成するか（What）

### 2.1 目的

390px幅を基準に、カードUIの読みやすさと情報優先度を改善する。

### 2.2 最終ゴール

- モバイル幅で主情報が先に読める
- 副情報が詰まらず、自然に折り返される

### 2.3 スコープ

#### 含むもの

- モバイル時のタイポグラフィ・行間・余白の微調整
- 必要最小限のレイアウト調整（CardGrid / MasterDetailLayout）
- モバイル証跡の再取得と比較

#### 含まないもの

- デスクトップ全面レイアウト変更
- 新規コンポーネント導入

### 2.4 成果物

- モバイル向けスタイル調整差分
- 再取得スクリーンショット（390px）
- 検証記録

## 3. どのように実行するか（How）

### 3.1 前提条件

- 既存のレスポンシブ設計（4ブレークポイント）を維持すること

### 3.2 依存タスク

- なし

### 3.3 必要な知識

- レスポンシブUI設計
- タイポグラフィと可読性設計

### 3.4 推奨アプローチ

主情報を崩さず、副情報の折り返しと余白を優先して調整する。構造変更よりスタイル調整を優先する。

## 4. 実行手順

### Phase構成

- Phase A: 可読性チューニング
- Phase B: 画面検証と回帰確認

### Phase A: 可読性チューニング

#### 目的

モバイル幅で詰まりを減らし、可読性を改善する。

#### 手順

1. 390px幅で詰まりが出る要素を特定する。
2. 行間・余白・文字サイズを最小差分で調整する。
3. 折り返しルールを確認し、主情報の視認性を優先する。

#### 成果物

- モバイル調整差分

#### 完了条件

- 390px幅で視覚的な窮屈さが緩和される。

### Phase B: 画面検証と回帰確認

#### 目的

調整が他サイズや操作性へ悪影響を与えていないことを確認する。

#### 手順

1. モバイル証跡を再取得する。
2. デスクトップ表示との整合を確認する。
3. テスト/型チェックを実施する。

#### 成果物

- 再撮影画像
- 検証ログ

#### 完了条件

- モバイル可読性改善を確認できる。
- 回帰がない。

## 6. 検証方法

### テストケース

- 390px mobile: カード密度・行間・折り返し
- desktop: 回帰なし確認

### 検証手順

1. `node apps/desktop/scripts/capture-ui-design-foundation-phase11.mjs` を実行する。
2. `pnpm --filter @repo/desktop typecheck` を実行する。
3. 関連テストを再実行し PASS を確認する。
