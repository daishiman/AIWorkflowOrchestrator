## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

手動テストで Light テーマ時のカード境界が弱く見え、情報ブロックの分離が瞬時に認識しづらいことを確認した。

### 1.2 問題点・課題

- `border-subtle` 系色が淡く、背景と境界の差が不足している
- Apple HIG 準拠の中で視認性を担保する閾値が定義されていない

### 1.3 放置した場合の影響

- Light テーマでの視線誘導が悪化し、情報探索コストが上がる
- コンポーネント間で境界の見え方がばらつく

## 2. 何を達成するか（What）

### 2.1 目的

Light テーマの境界コントラストを改善し、カード群の情報分離を安定化する。

### 2.2 最終ゴール

- CardGrid を含む主要カードUIで境界が一目で識別できる
- 既存ダークテーマとアクセント配色を崩さない

### 2.3 スコープ

#### 含むもの

- `tokens.css` の Light テーマ境界色（`--border-subtle` / 必要に応じて `--border-default`）調整
- 調整後の Phase 11 スクリーンショット再取得（Lightデスクトップ中心）
- 影響コンポーネントの回帰確認

#### 含まないもの

- ダークテーマの再設計
- コンポーネント構造変更（DOM/責務分割）

### 2.4 成果物

- 境界色調整コミット差分
- 再取得スクリーンショット
- 検証記録（手動 + 既存テスト再実行）

## 3. どのように実行するか（How）

### 3.1 前提条件

- `apps/desktop` のUIプレビューが起動できること
- TASK-UI-00 の現行成果物が参照可能であること

### 3.2 依存タスク

- なし（単独で着手可能）

### 3.3 必要な知識

- デザイントークン設計（CSS Variables）
- Apple HIG のコントラスト原則

### 3.4 推奨アプローチ

最小変更でトークン値を調整し、再撮影と比較で判定する。コンポーネント個別上書きは最後の手段とする。

## 4. 実行手順

### Phase構成

- Phase A: トークン調整
- Phase B: 視覚検証と回帰確認

### Phase A: トークン調整

#### 目的

境界コントラストの不足を最小差分で解消する。

#### 手順

1. `tokens.css` の Light テーマ境界関連変数を調整する。
2. CardGrid/Panel/Dialog で境界表示を確認する。
3. 影響が大きい場合は段階的に値を戻して最適点を決める。

#### 成果物

- トークン修正差分

#### 完了条件

- Light テーマで境界の視認性改善が確認できる。

### Phase B: 視覚検証と回帰確認

#### 目的

変更が仕様と既存体験を壊していないことを確認する。

#### 手順

1. Phase 11 用スクリーンショットを再取得する（Lightデスクトップ必須）。
2. 既存UIテストと typecheck を実行する。
3. 変更内容と判定を成果物に記録する。

#### 成果物

- 再撮影画像
- 検証ログ

#### 完了条件

- 主要ケースの視覚差分が改善方向である。
- 回帰（テスト/型エラー）がない。

## 6. 検証方法

### テストケース

- Light desktop: カード群の境界視認性確認
- Dark desktop: 変更影響なし確認

### 検証手順

1. `node apps/desktop/scripts/capture-ui-design-foundation-phase11.mjs` を実行する。
2. `pnpm --filter @repo/desktop typecheck` を実行する。
3. 必要なテストを実行して回帰がないことを確認する。
