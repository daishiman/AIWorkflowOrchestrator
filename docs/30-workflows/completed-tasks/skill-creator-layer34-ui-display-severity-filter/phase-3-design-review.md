### 2. タスク分離と依存関係

| チェック項目                                               | 結果 | 備考                                                                    |
| ---------------------------------------------------------- | ---- | ----------------------------------------------------------------------- |
| フィルタロジックが既存 Layer grouping から分離されているか | PASS | `filterChecksBySeverity` は pure function、`checksByLayer` の下流に配置 |
| 各サブタスク (T-01-1〜T-01-6) が単一責務であるか           | PASS | 型定義/state/UI/データ適用/ライフサイクル/テストと明確に分離            |
| 依存関係に循環がないか                                     | PASS | T-01-1 → T-01-2 → T-01-3/4 → T-01-5 → T-01-6 の一方向                   |
| 既存コンポーネント (VerifyLayerGroup) への影響が最小限か   | PASS | 入力データの差し替えのみ、コンポーネント内部は変更不要                  |

### 3. 技術設計の妥当性

| チェック項目                                           | 結果 | 備考                                                       |
| ------------------------------------------------------ | ---- | ---------------------------------------------------------- |
| useMemo チェーンの依存が正しいか                       | PASS | `checksByLayer` → `filteredChecksByLayer` の依存順が正しい |
| `filterChecksBySeverity` が pure function であるか     | PASS | 引数のみに依存し副作用なし、テスト容易性が高い             |
| `all` フィルタの早期リターンが妥当か                   | PASS | 新規配列生成を避けパフォーマンス上有利                     |
| `activeWorkflowId` 変更時の useEffect リセットが安全か | PASS | 既存の `expandedLayers` リセットと同パターン               |
| reverify 時のフィルタ維持が自然に実現されるか          | PASS | `activeWorkflowId` が変わらないため特別な処理不要          |
| フィルタ後の空 Layer 除外ロジックが正しいか            | PASS | `filtered.length > 0` のチェックで自然に除外               |

### 4. リスク軽減策

| チェック項目                                          | 結果 | 備考                                                        |
| ----------------------------------------------------- | ---- | ----------------------------------------------------------- |
| 後方互換性がデフォルト値 `"all"` で確保されているか   | PASS | `all` は全件表示であり、フィルタ導入前と同一の動作          |
| Layer grouping との干渉リスクが設計で回避されているか | PASS | フィルタは `checksByLayer` の下流に配置し、既存ロジック不変 |
| useMemo 依存配列の漏れ対策があるか                    | PASS | ESLint exhaustive-deps ルールで検出可能                     |
| 変更範囲が小規模で制御可能か                          | PASS | 変更ファイルは 2 ファイルのみ（本体 + テスト）              |
