## 背景

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1で定義した要件がすべて満たされていることを確認する

**実行手順**:

1. Phase 1の要件定義書を再読
2. 以下の観点でチェック:
   - 機能要件の充足
   - 非機能要件の充足
   - 制約条件の遵守
3. 未充足項目があれば記録

**期待される成果物**:

- `outputs/phase-10/requirements-check.md`

---

### タスク2: 設計準拠確認

**目的**: Phase 2で作成した設計に準拠していることを確認する

**実行手順**:

1. Phase 2の設計書を再読
2. 以下の観点でチェック:
   - アーキテクチャ設計との整合性
   - IPC設計との整合性
   - 型定義設計との整合性
3. 乖離があれば記録

**期待される成果物**:

- `outputs/phase-10/design-compliance.md`

---

### タスク3: 成果物完全性確認

**目的**: 全Phaseの成果物が揃っていることを確認する

**実行手順**:

1. Phase 1〜9の成果物リストを作成
2. 各成果物の存在を確認
3. 欠落があれば記録

**期待される成果物**:

- `outputs/phase-10/artifacts-completeness.md`

---

### タスク4: 最終レビュー判定

**目的**: 総合的なレビュー結果を判定する

**実行手順**:

1. タスク1〜3の結果を集約
2. レビュー判定基準に基づいて判定
3. 判定結果と理由を記録

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11へ進行            |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 11へ    |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
