## 目的

Phase 2で作成した設計の妥当性を検証し、実装に進む前に問題点を洗い出す。要件との整合性、アーキテクチャの適切性、セキュリティ観点を確認する。

## 背景

設計レビューゲートは、実装開始前に設計品質を担保するための重要なチェックポイント。ここで問題を発見することで、手戻りコストを最小化する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件整合性レビュー

**目的**: Phase 1の要件がPhase 2の設計に正しく反映されているか確認する

**実行手順**:

1. 機能要件チェックリストの作成・確認
2. 非機能要件チェックリストの作成・確認
3. 未対応要件がないか確認
4. 整合性レビュー結果を記録

**期待される成果物**:

- `outputs/phase-3/requirements-review.md`

---

### タスク2: アーキテクチャレビュー

**目的**: 設計されたアーキテクチャの適切性を検証する

**実行手順**:

1. 以下の観点でレビュー:
   - 責務分離が適切か
   - 既存アーキテクチャとの整合性
   - テスタビリティの確保
   - 拡張性・保守性
2. 懸念点の洗い出し
3. アーキテクチャレビュー結果を記録

**期待される成果物**:

- `outputs/phase-3/architecture-review.md`

---

### タスク3: セキュリティレビュー

**目的**: セキュリティ観点での設計検証を行う

**実行手順**:

1. 以下の観点でレビュー:
   - 永続化データに機密情報が含まれないか
   - ファイルアクセス権限の適切性
   - IPC通信のセキュリティ
2. セキュリティリスクの評価
3. セキュリティレビュー結果を記録

**期待される成果物**:

- `outputs/phase-3/security-review.md`

---

### タスク4: 統合テスト観点レビュー

**目的**: 統合テストの実行可能性を設計段階で確認する

**実行手順**:

1. 以下の統合テスト観点でレビュー:
   - IPC通信テストの実行可能性
   - アプリ再起動テストの実行可能性
   - モック/スタブの設計適切性
2. 統合テストレビュー結果を記録

**期待される成果物**:

- `outputs/phase-3/integration-test-review.md`

---

### タスク5: レビュー結果サマリー

**目的**: レビュー結果を総合し、ゲート判定を行う

**実行手順**:

1. 各レビュー結果を集約
2. 以下の判定を実施:

| 判定     | 条件                     | 次のアクション        |
| -------- | ------------------------ | --------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行         |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り設計修正 |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻り要件確認 |

3. レビューサマリーを作成

**期待される成果物**:

- `outputs/phase-3/review-summary.md`
