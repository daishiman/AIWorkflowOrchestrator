## 目的

自動テストでは検証できないユーザー体験・UI/UX・実環境動作を手動で確認する。特に、状態管理の集約によってrace conditionが解消され、複数コンポーネント間の状態整合性が保たれることを実環境で検証する。

## 背景

本タスクはスキル機能の状態管理を3つの経路（skillSlice、ローカルstate、useSkillExecution）から単一のagentSliceに集約するリファクタリングである。状態管理の変更は自動テストだけでは検出しにくい微妙な不整合を引き起こす可能性があるため、手動での検証が必須。

## 手動統合テスト（詳細）

### API接続: skill.execute IPC呼び出し

**確認手順**:

1. Electron DevTools を開く（`Cmd+Option+I`）
2. Console タブを開く
3. 以下のコードを実行してIPC呼び出しを確認:

```javascript
// 1. 利用可能なスキルを確認
const skills = await window.electronAPI.skill.list({ forceRefresh: false });
console.log("Available skills:", skills);

// 2. スキルが存在する場合、実行を試行
if (skills.data && skills.data.length > 0) {
  const result = await window.electronAPI.skill.execute({
    skillId: skills.data[0].id,
    prompt: "テストプロンプト",
  });
  console.log("Execute result:", result);
}
```

**期待結果**: エラーなく実行され、executionIdを含むレスポンスが返る

### データ永続化: インポート済みスキルの保存

**確認手順**:

1. 新しいスキルをインポート
2. インポート成功を確認
3. アプリを完全に終了（`Cmd+Q`）
4. アプリを再起動
5. スキル一覧を確認

**期待結果**: 再起動後もインポート済みスキルが表示される

### エラーハンドリング: 実行エラー時のUI表示

**確認手順**:

1. 無効なスキルIDでの実行を試行（DevToolsから）:

```javascript
const result = await window.electronAPI.skill.execute({
  skillId: "non-existent-skill-id",
  prompt: "test",
});
console.log("Error result:", result);
```

2. UIでのエラー表示を確認

**期待結果**:

- APIはエラーレスポンスを返す（success: false）
- UIにエラーメッセージが表示される
- アプリがクラッシュしない

### 状態同期: 複数コンポーネント間の状態整合性

**確認手順**:

1. React DevTools を開く
2. Components タブで AgentView と ChatPanel を確認
3. スキルを実行
4. 両コンポーネントの props/state を比較

**期待結果**:

- 両コンポーネントで `isExecuting` が同一
- 両コンポーネントで `selectedSkill` が同一
- ローカルstateが AgentView に存在しない

## 注意事項

### 状態管理変更に関する特記事項

> **重要**: 本タスクはリファクタリングであり、機能の追加・変更は含まない。
>
> テスト時に「動作が変わった」と感じた場合は、それがバグである可能性が高い。
>
> 以下の動作は変更されてはならない:
>
> - スキル実行の成功/失敗の判定
> - ストリーミングメッセージの表示順序
> - エラー時のUI表示
> - 中断機能の動作

### race condition 検証のポイント

| 検証項目                     | 確認方法                                            |
| ---------------------------- | --------------------------------------------------- |
| executionId の設定タイミング | 実行開始直後に executionId が null でないことを確認 |
| メッセージの損失             | 高速連続実行時にメッセージが欠落しないことを確認    |
| 状態の不整合                 | 実行中に別の実行を開始した場合の動作を確認          |
