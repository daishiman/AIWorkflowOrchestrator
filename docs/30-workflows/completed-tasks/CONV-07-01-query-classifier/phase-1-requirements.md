## 目的

クエリ分類器の要件を明確化し、受け入れ基準を定義する。HybridRAGパイプラインの第1段階として、クエリタイプに応じた最適な検索戦略選択を実現するための要件を整理する。

---

## 背景・課題

### 課題

1. VectorRAG単体ではグローバルクエリ（全体のテーマは？）の正解率が0%
2. クエリタイプに応じた検索戦略の最適化が未実装
3. ユーザーの検索意図を正確に把握する仕組みがない

### 解決策

クエリを3タイプ（local/global/relationship）+ フォールバック（hybrid）に分類し、タイプに応じた検索重み付けを行う。

---

## 機能要件

### FR-01: クエリ分類機能

| ID      | 要件                                                                | 優先度 |
| ------- | ------------------------------------------------------------------- | ------ |
| FR-01-1 | 検索クエリを4タイプ（local/global/relationship/hybrid）に分類できる | 必須   |
| FR-01-2 | 分類の信頼度スコア（0.0〜1.0）を算出できる                          | 必須   |
| FR-01-3 | クエリからエンティティを抽出できる                                  | 必須   |
| FR-01-4 | クエリからキーワードを抽出できる                                    | 必須   |
| FR-01-5 | 関係性クエリの場合、関係のヒントを抽出できる                        | 推奨   |

### FR-02: LLMベース分類器

| ID      | 要件                                                      | 優先度 |
| ------- | --------------------------------------------------------- | ------ |
| FR-02-1 | LLMを使用して高精度な分類を行える                         | 必須   |
| FR-02-2 | LLMレスポンスのパース失敗時にルールベースへフォールバック | 必須   |
| FR-02-3 | 信頼度が閾値未満の場合はhybridにフォールバック            | 必須   |
| FR-02-4 | 設定可能な最小信頼度閾値を提供する                        | 必須   |

### FR-03: ルールベース分類器

| ID      | 要件                                     | 優先度 |
| ------- | ---------------------------------------- | ------ |
| FR-03-1 | 正規表現パターンマッチングで分類を行える | 必須   |
| FR-03-2 | グローバルクエリのパターンを検出できる   | 必須   |
| FR-03-3 | 関係性クエリのパターンを検出できる       | 必須   |
| FR-03-4 | 日本語・英語の両方に対応する             | 必須   |

### FR-04: 検索重み付け

| ID      | 要件                                                         | 優先度 |
| ------- | ------------------------------------------------------------ | ------ |
| FR-04-1 | クエリタイプに応じた検索重み（keyword/semantic/graph）を返却 | 必須   |
| FR-04-2 | 重みの合計が1.0になることを保証                              | 必須   |

| -------- | ---------------------------------- | ------ |
| NFR-02-1 | LLMエラー時のフォールバック成功率  | 100%   |
| NFR-02-2 | 分類精度（テストセットでの正解率） | > 80%  |

### NFR-03: テスト品質

| ID       | 要件                            | 目標値 |
| -------- | ------------------------------- | ------ |
| NFR-03-1 | ユニットテストLine Coverage     | > 80%  |
| NFR-03-2 | ユニットテストBranch Coverage   | > 60%  |
| NFR-03-3 | ユニットテストFunction Coverage | > 80%  |

## 入出力仕様

### 入力

| 項目    | 型                         | 説明                             |
| ------- | -------------------------- | -------------------------------- |
| query   | string                     | 検索クエリテキスト（1-1000文字） |
| options | QueryClassificationOptions | 分類オプション（任意）           |

### 出力

| 項目              | 型        | 説明                                             |
| ----------------- | --------- | ------------------------------------------------ |
| type              | QueryType | クエリタイプ（local/global/relationship/hybrid） |
| confidence        | number    | 信頼度（0.0〜1.0）                               |
| extractedEntities | string[]  | 抽出されたエンティティ名                         |
| relationHint      | string?   | 関係性のヒント（該当時のみ）                     |
| keywords          | string[]  | 抽出されたキーワード                             |
| intent            | string    | クエリの意図を1文で説明                          |

## 受け入れ基準

### AC-01: 基本分類

- [ ] ローカルクエリ（「Reactとは？」等）がlocalに分類される
- [ ] グローバルクエリ（「全体のテーマは？」等）がglobalに分類される
- [ ] 関係性クエリ（「AとBの違いは？」等）がrelationshipに分類される
- [ ] 分類できない場合はhybridにフォールバックする

### AC-02: エンティティ抽出

- [ ] 関係性クエリから比較対象のエンティティが抽出される
- [ ] ローカルクエリから対象エンティティが抽出される

### AC-03: 検索重み

- [ ] localクエリ: keyword=0.35, semantic=0.35, graph=0.3
- [ ] globalクエリ: keyword=0.2, semantic=0.3, graph=0.5
- [ ] relationshipクエリ: keyword=0.2, semantic=0.2, graph=0.6
- [ ] hybridクエリ: keyword=0.33, semantic=0.33, graph=0.34

### AC-04: エラーハンドリング

- [ ] LLMエラー時にルールベース分類器にフォールバックする
- [ ] JSONパースエラー時にルールベース分類器にフォールバックする
- [ ] 信頼度が閾値未満の場合はhybridにフォールバックする
