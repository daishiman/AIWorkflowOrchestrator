## 目的

lint / 型チェック / カバレッジ / セキュリティスキャンを一括実行し、`scripts/verify-ipc-4layer.js` が品質ゲートを全て通過していることを最終確認する。Phase 1〜8 の成果物を横断的に検証し、Phase 10（最終レビューゲート）への進行可否を判定する。

## 背景

品質保証フェーズは、実装・テスト・リファクタリングを経た成果物が、プロジェクトの品質基準を満たしているかを一括判定する最終チェックポイントである。IPC 4層整合検証スクリプトは CI パイプラインに組み込まれるため、スクリプト自体の品質が CI の信頼性に直結する。型安全性、コーディング規約準拠、テスト網羅性、セキュリティ（パストラバーサル防止等）を総合的に検証する。

### タスク1: 静的解析一括実行

**目的**: TypeScript 型チェック・ESLint・ユニットテストを一括実行し、品質基準を確認する

**実行手順**:

1. TypeScript 型チェックを実行する
   - 対象: `scripts/verify-ipc-4layer.js` および関連モジュール
   - 期待結果: エラー 0件
2. ESLint を実行する
   - 対象: 実装ファイル + テストファイル
   - 期待結果: エラー 0件（警告は許容するが記録する）
3. ユニットテストを全件実行する
   - 対象: Phase 4-6 で作成した全テストファイル
   - 期待結果: 全テスト GREEN
4. カバレッジ計測を再実行する
   - 期待結果: Phase 7 で確認した基準値（Line 80%+、Branch 60%+、Function 80%+）を維持

**期待される成果物**:

- 品質レポート（`outputs/phase-9/quality-report.md`）に結果を記録

### タスク2: セキュリティスキャン

**目的**: 検証スクリプトにセキュリティ上の問題がないことを確認する

**実行手順**:

1. 以下のセキュリティ観点で検証スクリプトを精査する

| セキュリティ観点     | 確認内容                                                                 | 結果 |
| -------------------- | ------------------------------------------------------------------------ | ---- |
| パストラバーサル防止 | ファイルパスの入力値が検証されており、任意ファイル読み取りを防止している | TBD  |
| 正規表現 ReDoS 耐性  | パーサーの正規表現がReDoS攻撃に脆弱でないこと                            | TBD  |
| 外部依存の脆弱性     | Node.js 標準ライブラリのみ使用で外部依存がないこと（NFR-2準拠）          | TBD  |
| 機密情報の非露出     | エラーメッセージにファイルシステムの内部パスが過度に露出していないこと   | TBD  |
| exit code の適切性   | 検証失敗時に確実に exit 1 を返し、CI を失敗させること                    | TBD  |

2. 発見したリスクをリスクレジスタに記録する

**期待される成果物**:

- リスクレジスタ（`outputs/phase-9/risk-register.md`）

**実行手順**:

| チェック項目                      | 確認内容                                                                  | 結果 |

| CI統合→スクリプトの独立性         | GitHub Actions 設定がスクリプトの内部ロジックに依存していないか           | TBD  |
| 既存スクリプトとの相互依存        | `check-ipc-contracts.ts` と `verify-ipc-4layer.js` が相互依存していないか | TBD  |
| リファクタリング→テスト変更の波及 | Phase 8 のリファクタリングがテストの変更を不必要に誘発していないか        | TBD  |

3. Phase 3（設計レビューゲート）の MINOR 指摘が解決済みであることを確認する

### タスク4: 品質ゲート最終判定

**目的**: 全品質チェック結果を集約し、Phase 10 への進行可否を判定する

**実行手順**:

1. タスク1〜3 の結果を集約する
2. 品質ゲートチェックリスト（後述）の全項目を判定する
3. Phase 10 への進行可否を決定する

| 状態                       | 判定  | 次のアクション                    |
| -------------------------- | ----- | --------------------------------- |
| 全品質ゲート PASS          | GO    | Phase 10 へ進む                   |
| 軽微な警告のみ             | GO    | 警告を記録し Phase 10 へ進む      |
| セキュリティリスクあり     | NO-GO | リスク対応後、タスク2 を再実行    |
| テスト失敗 or 型エラーあり | NO-GO | 影響範囲に応じて Phase 5-8 に戻る |
| カバレッジ基準未達         | NO-GO | Phase 6-7 に戻りテスト補完        |

**期待される成果物**:

- 品質レポートにゲート判定結果を統合記録
