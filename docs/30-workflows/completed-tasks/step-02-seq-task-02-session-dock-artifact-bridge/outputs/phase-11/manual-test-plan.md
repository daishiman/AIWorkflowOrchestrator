# Manual Test Plan - Session Dock Artifact Bridge

## 概要

本タスクは設計タスク（type: design）であるため、実画面での手動テストは実施不可。代わりに、実装タスクで実施すべき手動テストの walkthrough シナリオと確認項目を定義する。

## Scenario 1: Session Open / Close / Reopen

### S1-1: 初回 dock open

| 手順 | 操作                                         | 期待結果                              |
| ---- | -------------------------------------------- | ------------------------------------- |
| 1    | AI からの handoff guidance を受信する        | dock が `collapsed` → `ready` に遷移  |
| 2    | dock の「開く」ボタンをクリック              | dock パネルが展開される               |
| 3    | guidance 内容が表示されていることを確認      | handoff guidance テキストが表示される |
| 4    | 「実行する」ボタンが表示されていることを確認 | primary CTA が「実行する」である      |

### S1-2: dock close

| 手順 | 操作                                 | 期待結果                     |
| ---- | ------------------------------------ | ---------------------------- |
| 1    | `ready` state で「閉じる」をクリック | dock が `collapsed` に遷移   |
| 2    | dock が折りたたまれていることを確認  | 最小限の status bar のみ表示 |

### S1-3: reopen restore

| 手順 | 操作                                          | 期待結果                                           |
| ---- | --------------------------------------------- | -------------------------------------------------- |
| 1    | `done` state で dock を折りたたむ             | dock が `collapsed` に遷移（session データは保持） |
| 2    | dock を再度開く                               | 前回の session データが restore される             |
| 3    | Artifact Summary が表示されていることを確認   | 前回の成果物一覧が表示される                       |
| 4    | transcript entries が保持されていることを確認 | 前回の実行ログが折りたたみ内に存在する             |

### S1-4: reopen restore failure

| 手順 | 操作                                                                 | 期待結果                                           |
| ---- | -------------------------------------------------------------------- | -------------------------------------------------- |
| 1    | 存在しない session ID で restore を試みる（DevTools から injection） | `ready` state にフォールバック                     |
| 2    | エラー通知が表示されていることを確認                                 | 「セッションを復元できませんでした」等のメッセージ |

## Scenario 2: 実行フロー全体

### S2-1: handoff → running → done

| 手順 | 操作                                        | 期待結果                              |
| ---- | ------------------------------------------- | ------------------------------------- |
| 1    | `ready` state で「実行する」をクリック      | dock が `handoff` に遷移              |
| 2    | CLI session が開始される                    | dock が `running` に遷移              |
| 3    | transcript が streaming 表示される          | リアルタイムでログが表示される        |
| 4    | CLI session が正常完了する                  | dock が `done` に遷移                 |
| 5    | Artifact Summary が primary に表示される    | 生成ファイル一覧が [1] 位置に表示     |
| 6    | Execution Summary が secondary に表示される | 実行時間・exit code が [2] 位置に表示 |
| 7    | Transcript が折りたたみで [3] に配置        | 「詳細ログを表示」リンクが表示される  |

### S2-2: running → aborted（ユーザー中止）

| 手順 | 操作                                     | 期待結果                                       |
| ---- | ---------------------------------------- | ---------------------------------------------- |
| 1    | `running` state で「中止する」をクリック | dock が `aborted` に遷移                       |
| 2    | Error Summary が表示される               | 中止理由: `user_abort`、exit code、stderr 抜粋 |
| 3    | 「やり直す」ボタンが表示される           | primary CTA が「やり直す」                     |
| 4    | 「ガイダンスに戻る」ボタンが表示される   | secondary CTA が「ガイダンスに戻る」           |

### S2-3: running → aborted（プロセスエラー）

| 手順 | 操作                                    | 期待結果                                    |
| ---- | --------------------------------------- | ------------------------------------------- |
| 1    | CLI session がエラーで終了する          | dock が `aborted` に遷移                    |
| 2    | Error Summary に exit code が表示される | 非ゼロ exit code が表示される               |
| 3    | stderr 抜粋が最大 10 行で表示される     | truncation + 「全文を見る」リンクが存在する |

### S2-4: running 中の dock 折りたたみ拒否

| 手順 | 操作                                     | 期待結果                                      |
| ---- | ---------------------------------------- | --------------------------------------------- |
| 1    | `running` state で dock を閉じようとする | dock は折りたたまれない（MN-01 設計意図準拠） |
| 2    | 「中止する」CTA のみが操作可能           | 実行中は中止のみ許可される                    |

## Scenario 3: Artifact-First 確認

### S3-1: done state の表示階層

| 手順 | 確認項目                                  | 期待結果                                             |
| ---- | ----------------------------------------- | ---------------------------------------------------- |
| 1    | [1] Artifact Summary が最上位に表示される | 生成ファイル一覧 + 変更差分プレビュー + 次アクション |
| 2    | [2] Execution Summary が次に表示される    | 実行時間 + exit code + warning/error 数              |
| 3    | [3] Transcript Detail が折りたたみで配置  | デフォルト閉じ、クリックで展開                       |
| 4    | [4] Share Rail が footer に配置           | done state でのみ表示される                          |

### S3-2: empty artifact

| 手順 | 確認項目                          | 期待結果                                         |
| ---- | --------------------------------- | ------------------------------------------------ |
| 1    | artifact が空の done state を表示 | 「成果物はありません」メッセージが表示される     |
| 2    | transcript リンクが表示される     | 「詳細ログを確認する」リンクで transcript に遷移 |

### S3-3: aborted state の表示

| 手順 | 確認項目                                    | 期待結果                                          |
| ---- | ------------------------------------------- | ------------------------------------------------- |
| 1    | Error Summary が primary に表示される       | 中止理由・exit code・stderr が最上位              |
| 2    | partial artifacts が secondary に表示される | 「部分的な成果物」として Artifact Summary が2番目 |

## Scenario 4: Manual Share + Provenance

### S4-1: 選択範囲を送る

| 手順 | 操作                                               | 期待結果                                                      |
| ---- | -------------------------------------------------- | ------------------------------------------------------------- |
| 1    | transcript 内のテキストを選択する                  | 選択範囲がハイライトされる                                    |
| 2    | Share Rail の「選択範囲を送る」をクリック          | 選択テキストが chat message として送信される                  |
| 3    | 送信された message に Provenance Chip が付与される | `source: session-{id}` + `sharedAt: {timestamp}` が表示される |
| 4    | Provenance Chip の「見る」リンクをクリック         | 元の transcript エントリにジャンプする                        |

### S4-2: 直近出力を添付

| 手順 | 操作                                      | 期待結果                                     |
| ---- | ----------------------------------------- | -------------------------------------------- |
| 1    | Share Rail の「直近出力を添付」をクリック | 最新の transcript entry が chat に添付される |
| 2    | Provenance Chip が付与されることを確認    | source に entryIndex が含まれる              |

### S4-3: セッションを貼る

| 手順 | 操作                                        | 期待結果                                               |
| ---- | ------------------------------------------- | ------------------------------------------------------ |
| 1    | Share Rail の「セッションを貼る」をクリック | session 全体のサマリーが chat message として送信される |
| 2    | サマリーに session ID が含まれることを確認  | `session-{UUID}` 形式の ID が表示される                |

### S4-4: credential サニタイズ確認

| 手順 | 操作                                                    | 期待結果                                       |
| ---- | ------------------------------------------------------- | ---------------------------------------------- |
| 1    | transcript に `api_key=sk-test123456789012345` を含める | share 前の transcript には credential が見える |
| 2    | 「選択範囲を送る」で share する                         | share された message では `[REDACTED]` に置換  |
| 3    | `Bearer eyJhbGc...` パターンを確認                      | share 時に `[REDACTED]` に置換される           |

### S4-5: Share Rail 表示タイミング

| 手順 | 確認項目                        | 期待結果                             |
| ---- | ------------------------------- | ------------------------------------ |
| 1    | `running` state で Share Rail   | 表示されない                         |
| 2    | `done` state で Share Rail      | footer に 1 ドロップダウンとして表示 |
| 3    | `aborted` state で Share Rail   | footer に 1 ドロップダウンとして表示 |
| 4    | `collapsed` state で Share Rail | 表示されない                         |

## Scenario 5: Edge Cases

### S5-1: unavailable state

| 手順 | 操作                                 | 期待結果                           |
| ---- | ------------------------------------ | ---------------------------------- |
| 1    | CLI 未インストール状態で dock を開く | `unavailable` state に遷移         |
| 2    | 「インストールする」CTA が表示される | primary CTA がインストールへの導線 |

### S5-2: guidance-only state

| 手順 | 操作                           | 期待結果                     |
| ---- | ------------------------------ | ---------------------------- |
| 1    | 実行不要の guidance を受信する | `guidance-only` state に遷移 |
| 2    | guidance テキストが表示される  | 実行 CTA は表示されない      |
| 3    | 「閉じる」のみが操作可能       | primary CTA が「閉じる」のみ |

### S5-3: session persistence 上限

| 手順 | 操作                                      | 期待結果                              |
| ---- | ----------------------------------------- | ------------------------------------- |
| 1    | 11 件目の session を作成する              | 最古の session が FIFO で削除される   |
| 2    | 削除された session を reopen しようとする | restore 失敗 → ready にフォールバック |

## アクセシビリティ確認項目

| 確認項目                                 | 期待結果                                         |
| ---------------------------------------- | ------------------------------------------------ |
| Tab キーで全 CTA にフォーカス可能        | collapsed/ready/done/aborted の全 CTA が操作可能 |
| aria-live で dock state 変更が通知される | screen reader に state 遷移が伝達される          |
| 色だけに依存しない情報表現               | error/warning にはアイコン + テキストを併用      |
| コントラスト比 4.5:1 以上                | 全テキスト要素が WCAG 2.1 AA 準拠                |
