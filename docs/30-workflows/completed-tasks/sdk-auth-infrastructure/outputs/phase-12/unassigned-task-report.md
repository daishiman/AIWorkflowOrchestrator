## 3. 未タスク詳細

### 3.1 UT-AUTH-001: withValidation ラッパーの使用

**背景**: 既存の `authHandlers.ts` では `withValidation` ラッパーを使用してIPC sender検証を行っている。`authKeyHandlers.ts` でも同じパターンを使用することで一貫性が保たれる。

**現状**: 直接 `validateIpcSender()` を呼び出している。

**対応方針**: リファクタリングタスクとして、`withValidation` ラッパーに置き換える。

**優先度**: 低（機能に影響なし、コード一貫性の問題）

---

### 3.2 UT-AUTH-002: SDK apiKey オプション対応確認

**背景**: Claude Agent SDK が `apiKey` オプションを受け付けることを確認する必要がある。SDK のデフォルト認証処理との競合がないかも確認が必要。

**現状**: 未確認。

**対応方針**: SDK ドキュメントを確認し、`query()` API への apiKey 渡し方法を検証する。

**優先度**: 中（SDK 統合時に必須）

---

### 3.3 UT-AUTH-005: validateKey() の検証方法軽量化

**背景**: 現在の `validateKey()` は `/v1/messages` エンドポイントにテストリクエストを送信する設計。これにより以下の懸念がある:

- 課金が発生する可能性
- ネットワークエラー時の挙動

**対応方針**: 以下のいずれかを検討:

1. `/v1/models` エンドポイント（GET）を使用（軽量）
2. 形式チェックのみ（ネットワーク不要）
3. 現状維持（機能的には問題なし）

**優先度**: 中（ユーザー体験に影響）

---

### 3.4 UT-AUTH-006: packages/shared への AUTH_KEY_CHANNELS 統合

**背景**: 設計書では `packages/shared/src/ipc/channels.ts` に `AUTH_KEY_CHANNELS` を追加する方針だが、実際は `preload/channels.ts` にのみ存在。

**現状**: preload に定義済み、shared には未追加。

**対応方針**: モノレポ構成の整合性を取るために、shared への統合を検討。

**優先度**: 低（現状動作に問題なし）

---

### 3.5 UT-AUTH-008: UI 設定画面統合

**背景**: 認証キー管理 API は実装完了しているが、ユーザーが UI から認証キーを設定する画面はまだ存在しない。

**対応方針**: 設定画面に API キー入力フィールドを追加し、`window.electronAPI.authKey` を使用して設定できるようにする。

**優先度**: 中（ユーザー向け機能）

---

### 3.6 UT-AUTH-009: Supabase 認証との統合

**背景**: 現在、Anthropic API Key と Supabase 認証は独立している。将来的に統合が必要になる可能性がある。

**対応方針**: 認証フロー全体の設計を見直し、必要に応じて統合を検討。

**優先度**: 中（アーキテクチャレベルの検討）
