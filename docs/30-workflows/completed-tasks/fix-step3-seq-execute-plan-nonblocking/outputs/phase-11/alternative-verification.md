## 代替検証の理由

本タスクは NON_VISUAL（IPC パターン変更のみ）であり、画面表示に変更がないため、アプリケーション起動による手動操作テストではなく、自動テストエビデンスによる代替検証を実施する。

## 各テストケースの代替検証詳細

### TC-T2-01: 即応性検証（手動テストステップ4の代替）

- **手動テスト**: 「実行する」クリック後、画面が即座に「実行中」に遷移する
- **自動テスト**: `executeAsync` に 10秒かかる処理を設定し、invoke が 100ms 以内に `{ accepted: true, planId }` を返すことを検証
- **判定**: PASS -- fire-and-forget パターンにより、バックグラウンド処理の完了を待たずに即座にレスポンスが返ることを確認

### TC-T2-02b: workflow-state-changed relay 検証

- **手動テスト**: 受付後に workflow state が renderer に届き、画面が状態変化を追跡できる
- **自動テスト**: `onWorkflowStateSnapshot` が `SKILL_CREATOR_WORKFLOW_STATE_CHANGED` を用いて snapshot を relay することを検証
- **判定**: PASS -- Main 側から Renderer 側へのイベント伝播が保証されていることを確認

### TC-T2-02c: destroyed window guard 検証

- **手動テスト**: ウィンドウ破棄後に stale なイベント送信が発生しない
- **自動テスト**: `mainWindow.isDestroyed()` が true の場合に `webContents.send` が呼ばれないことを検証
- **判定**: PASS -- 破棄済みウィンドウへの送信が抑止されることを確認

### TC-T2-03: エラー耐性検証（手動テストステップ5の代替）

- **手動テスト**: DevTools コンソールに IPC タイムアウトエラーが記録されていない
- **自動テスト**: `executeAsync` が `Error("Agent SDK error")` を throw しても、invoke は正常に `{ accepted: true, planId }` を返すことを検証
- **判定**: PASS -- バックグラウンドエラーがフロントエンドのレスポンスに影響しないことを確認

### TC-T2-03b: reject ログ化検証（fire-and-forget 側）

- **自動テスト**: `executeAsync` が reject した場合に、`creatorHandlers.ts` の fire-and-forget 側 catch が sanitized message を `console.error` に出力することを検証
- **判定**: PASS -- 非同期エラーが未処理のまま残らず、診断可能なログとして記録されることを確認

### AUX-01: ack レスポンス構造検証

- **自動テスト**: ack レスポンスに `{ accepted: true, planId }` が含まれることを検証
- **判定**: PASS -- Renderer 側の型ガードと受理後フローが正しく動くことを確認

### AUX-02: planId trim 検証

- **自動テスト**: `planId` の前後空白が trim され、`executeAsync` に正規化値が渡ることを検証
- **判定**: PASS -- 不要な空白による workflow id の揺れを防げることを確認

### TC-T2-07: 負荷時即応性検証（手動テストステップ4の強化版）

- **手動テスト**: 単一リクエストの即応性確認
- **自動テスト**: 10件の並列 invoke が全て 100ms 以内に完了することを検証（`executeAsync` は resolve しない無限 Promise）
- **判定**: PASS -- 手動テストでは確認困難な高負荷シナリオでも即応性を維持することを確認
