## 技術的教訓

| 教訓                                             | 詳細                                                                                                                                                                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-3 と AC-3 の分離設計                         | `validateUserInputSubmission` が verification_review に対して no-op fallback（NFR-3）を持ちつつ、null/undefined/空文字は拒否（AC-3）するという2層設計は意図が明確でよい。テストで両パスを明示的にカバーすることで契約が文書化される |
| private method テストの回避（Feedback P0-09-U1） | `createVerificationReviewRequest()` は private 関数のため、`recordExecutionFailure()` / `recordVerifyFailure()` の public API 経由でテストすることで、実装詳細に依存しないテストが書けた                                            |
| textValue の扱い                                 | `SkillCreatorUserInputSubmission.textValue` は型上 optional のまま残すことで後方互換性を維持しつつ、テストから除去することで single_select の意図を明確化できた                                                                     |
