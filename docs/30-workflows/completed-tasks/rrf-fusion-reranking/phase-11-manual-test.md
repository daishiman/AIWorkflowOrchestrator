## 目的

自動テストでカバーできない部分を手動で検証し、実際の動作を確認する。

## 背景

自動テストは多くのシナリオをカバーするが、UIとの統合や実際のAPIとの連携など、手動でしか確認できない部分がある。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 開発環境での動作確認

**目的**: 開発環境で実際に動作することを確認する

**実行手順**:

1. 開発サーバーを起動:

   ```bash
   pnpm --filter @repo/web dev
   ```

2. 以下のシナリオを手動で実行:

| #   | シナリオ           | 手順                                     | 期待結果                      | 結果 |
| --- | ------------------ | ---------------------------------------- | ----------------------------- | ---- |
| 1   | 基本的な検索実行   | 検索クエリを入力して実行                 | 結果が表示される              |      |
| 2   | RRF Fusion結果確認 | 複数戦略の結果が統合されていることを確認 | fusedScoreが表示される        |      |
| 3   | Reranking結果確認  | リランク後の順序が変わっていることを確認 | rerankedScoreが表示される     |      |
| 4   | ソース情報確認     | 各結果のソース情報を確認                 | sources配列に戦略名が含まれる |      |

**期待される成果物**:

- `outputs/phase-11/dev-environment-test.md` - 開発環境テスト結果

---

### タスク2: API統合テスト（実環境）

**目的**: 実際のReranker APIとの連携を確認する

**実行手順**:

1. 環境変数を設定（必要に応じて）:
   - `COHERE_API_KEY`: Cohere API キー
   - `VOYAGE_API_KEY`: Voyage AI API キー
   - `OPENAI_API_KEY`: OpenAI API キー（LLMReranker用）

2. 以下のAPI連携を確認:

| #   | テスト項目         | 確認方法                         | 期待結果                     | 結果 |
| --- | ------------------ | -------------------------------- | ---------------------------- | ---- |
| 1   | CohereReranker連携 | Cohere APIキーを設定して検索実行 | rerankスコアが付与される     |      |
| 2   | VoyageReranker連携 | Voyage APIキーを設定して検索実行 | rerankスコアが付与される     |      |
| 3   | LLMReranker連携    | OpenAI APIキーを設定して検索実行 | LLMスコアが付与される        |      |
| 4   | フォールバック確認 | 無効なAPIキーを設定して検索実行  | NoOpRerankerにフォールバック |      |

**期待される成果物**:

- `outputs/phase-11/api-integration-test.md` - API統合テスト結果

---

### タスク3: エラー状態の手動確認

**目的**: エラー発生時の挙動を手動で確認する

**実行手順**:

1. 以下のエラーシナリオを確認:

| #   | エラーシナリオ  | 再現方法                   | 期待される動作         | 結果 |
| --- | --------------- | -------------------------- | ---------------------- | ---- |
| 1   | 検索結果なし    | 存在しないキーワードで検索 | 空配列が返される       |      |
| 2   | APIタイムアウト | ネットワークを一時的に遮断 | フォールバックが動作   |      |
| 3   | レート制限      | 短時間に大量リクエスト     | 適切なエラーメッセージ |      |
| 4   | 不正なAPIキー   | 無効なAPIキーを設定        | フォールバックが動作   |      |

**期待される成果物**:

- `outputs/phase-11/error-handling-test.md` - エラーハンドリングテスト結果

---

### タスク4: パフォーマンス体感確認

**目的**: 実際の使用感としてパフォーマンスを確認する

**実行手順**:

1. 以下のシナリオでレスポンス時間を体感確認:

| #   | シナリオ        | 確認方法                     | 許容範囲       | 結果 |
| --- | --------------- | ---------------------------- | -------------- | ---- |
| 1   | 通常検索        | 一般的なクエリで検索         | 2秒以内        |      |
| 2   | 複雑なクエリ    | 長いクエリで検索             | 5秒以内        |      |
| 3   | Reranking有効時 | Reranker有効で検索           | +1秒以内の増加 |      |
| 4   | 大量結果時      | 多くの結果が返るクエリで検索 | 3秒以内        |      |

**期待される成果物**:

- `outputs/phase-11/performance-feel-test.md` - パフォーマンス体感テスト結果

---

### タスク5: 手動テスト結果サマリー

**目的**: 全手動テスト結果を集約し、判定する

**実行手順**:

1. 全テスト結果を集計
2. 以下の基準で判定:

| 判定     | 条件               | 次のアクション         |
| -------- | ------------------ | ---------------------- |
| PASS     | 全テストが期待通り | Phase 12へ進行         |
| MINOR    | 軽微な問題あり     | 問題記録後、Phase 12へ |
| MAJOR    | 重大な問題あり     | 影響範囲に応じて戻る   |
| CRITICAL | 致命的な問題あり   | Phase 1へ戻り再検討    |

**期待される成果物**:

- `outputs/phase-11/manual-test-summary.md` - 手動テスト結果サマリー
