## Minor指摘（対応推奨）

### M-001: ワーカースレッド対応未考慮

| 項目      | 内容                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------- |
| 検出箇所  | `outputs/phase-2/search-engine-design.md` - WorkspaceSearchEngine                                                   |
| 内容      | 大規模ファイル検索時のWeb Worker対応が設計に含まれていない                                                          |
| 影響度    | 低（現状のAsyncGeneratorで十分対応可能）                                                                            |
| 対応方針  | Phase 5実装時に必要に応じて追加。初期実装はメインスレッドで実施し、パフォーマンス問題が発生した場合にWorker化を検討 |
| 対応Phase | Phase 5（実装）または将来のパフォーマンス改善時                                                                     |

**詳細:**

- 現状設計では、ワークスペース検索はメインスレッドのAsyncGeneratorで実行
- 1000ファイル以上の大規模検索時にUIブロッキングの可能性あり
- ただし、NFR-001-3で3秒以内の要件があり、ストリーミング処理で対応可能と判断

### M-002: 検索履歴上限の根拠不明確

| 項目      | 内容                                                           |
| --------- | -------------------------------------------------------------- |
| 検出箇所  | `outputs/phase-2/state-design.md` - FileSearchStore            |
| 内容      | 検索履歴の上限50件の設定根拠がドキュメント化されていない       |
| 影響度    | 低（ユーザー体験に大きな影響なし）                             |
| 対応方針  | 設定可能なパラメータとして実装し、ユーザー設定で変更可能にする |
| 対応Phase | Phase 5（実装）                                                |

**詳細:**

- 現状: `state.searchHistory.slice(0, 49)` で50件固定
- 提案: `SearchSettings.maxHistoryItems` として設定可能に
- デフォルト値50は、VS Codeの挙動を参考にした妥当な値
