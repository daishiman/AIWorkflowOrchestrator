## OI-01 詳細: prompt バリデーション

### 現状（実コード確認済み）

- skill:execute ハンドラの skillName パスでは、`args.prompt` の型チェックや空文字チェックを行わない
- テスト SH-EXE-V00 にて `{ skillName: "Test Skill", prompt: "" }` で正常実行を確認済み
- `executeSkill(skill.id, { prompt: args.prompt })` でサービス層に prompt をそのまま渡す

### 判断

- **設計上の意図的判断**: prompt は任意の内容（空文字を含む）を許容する設計
- **根拠**: SkillExecutionRequest 型定義（`packages/shared/src/types/skill.ts` L311）で `prompt: string` は必須フィールドだが、空文字を禁止する制約はない
- **リスク**: 低。prompt の内容バリデーションはサービス層/実行エンジンの責務

### 対応方針

変更不要。現状の設計を維持。

## OI-02 詳細: workingDirectory バリデーション

### 現状（実コード確認済み）

- skill:execute ハンドラでは `workingDirectory` の存在チェック、型チェック、パストラバーサルチェックを行わない
- `SkillExecutionRequest` 型定義で `workingDirectory?: string` はオプショナルフィールド
- workingDirectory はサービス層/SkillExecutor に渡されるが、ハンドラ層での使用箇所は `{ prompt: args.prompt }` のみで workingDirectory は渡されていない

### 判断

- **設計上の意図的判断**: ハンドラ層では workingDirectory を使用しておらず、バリデーション追加は不要
- **注意点**: 将来 workingDirectory をサービス層に渡す場合は、ハンドラ層でのパストラバーサル対策が必要
- **リスク**: 低。現時点では使用されていないため影響なし

### 対応方針

変更不要。将来 workingDirectory 対応時に Phase 2 から再設計。
