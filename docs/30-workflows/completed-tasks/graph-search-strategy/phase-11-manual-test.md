## 目的

自動テストでカバーできない観点を手動で検証する。実際の使用シナリオでの動作確認と、エッジケースの確認を行う。

## 背景

自動テストは仕様に基づくテストだが、実際の使用感やUI/UX観点、想定外のシナリオでの動作は手動確認が必要。特にHybridRAGSearcherとの統合動作を確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 統合動作確認

**目的**: HybridRAGSearcherとの連携動作を確認

**実行手順**:

1. HybridRAGSearcherにGraphSearchStrategyを登録
2. 実際のクエリを投入して動作確認
3. 他の戦略（Keyword, Vector）との並列実行を確認
4. 結果のマージが正しく動作することを確認

**期待される成果物**:

- 統合動作確認結果

**確認シナリオ**:

```typescript
// HybridRAGSearcherでの使用確認
const searcher = new HybridRAGSearcher({
  strategies: [
    new KeywordSearchStrategy(fts5Engine),
    new VectorSearchStrategy(vectorStore, embeddingProvider),
    new GraphSearchStrategy(graphStore, embeddingProvider, communitySummarizer),
  ],
  mergeStrategy: new RRFMergeStrategy(),
});

// クエリ実行
const result = await searcher.search("プロジェクト管理について");
```

### タスク2: シナリオベーステスト

**目的**: 実際のユースケースでの動作確認

**実行手順**:

1. localSearchシナリオを実行
2. globalSearchシナリオを実行
3. relationshipSearchシナリオを実行
4. 混合クエリシナリオを実行

**期待される成果物**:

- シナリオテスト結果（`outputs/phase-11/scenario-test.md`）

**テストシナリオ**:

| シナリオ       | クエリ例                        | 期待動作                             |
| -------------- | ------------------------------- | ------------------------------------ |
| ローカル検索   | 「TypeScriptの型定義について」  | 関連エンティティ・チャンクを返す     |
| グローバル検索 | 「プロジェクト全体の設計思想」  | コミュニティサマリを返す             |
| 関係検索       | 「UserServiceとDatabaseの関連」 | エンティティ間のパスを返す           |
| フォールバック | 「存在しないエンティティ」      | 空配列またはフォールバック結果を返す |
| フィルタ適用   | fileIds指定でのフィルタ検索     | 指定ファイルの結果のみ返す           |

---

### タスク3: エッジケーステスト

**目的**: 境界条件・異常条件での動作確認

**実行手順**:

1. 空クエリでの動作確認
2. 非常に長いクエリでの動作確認
3. 特殊文字を含むクエリでの動作確認
4. 大量結果時の動作確認

**期待される成果物**:

- エッジケーステスト結果

**エッジケース一覧**:

| ケース               | 入力例                          | 期待動作                 |
| -------------------- | ------------------------------- | ------------------------ |
| 空クエリ             | ""                              | エラーまたは空配列       |
| 長いクエリ           | 10000文字のテキスト             | 正常処理またはトリミング |
| 特殊文字             | "<script>alert('xss')</script>" | エスケープして安全に処理 |
| Unicode              | "日本語🎉絵文字"                | 正常処理                 |
| limit=0              | limit: 0                        | 空配列                   |
| limit=1000           | limit: 1000                     | 最大値に制限して処理     |
| 存在しないentityType | entityTypes: ["NONEXISTENT"]    | 空配列                   |

---

### タスク4: パフォーマンス体感確認

**目的**: 実際の使用感でのレスポンス確認

**実行手順**:

1. 通常クエリのレスポンス時間を体感確認
2. 複雑なクエリのレスポンス時間を体感確認
3. 連続クエリ時の安定性を確認

**期待される成果物**:

- パフォーマンス体感レポート
