#### 2.2 typesVersions 逆方向チェック不在の妥当性

typesVersions → exports の逆方向チェック（チェック6）を設けていない理由:

- typesVersions は exports のサブセットとして管理される（exports に存在しないサブパスを typesVersions に追加する理由がない）
- チェック5（exports → typesVersions）で typesVersions の不足を検出でき、余剰エントリは実害がない（TypeScript の型解決に使用されない余分なエントリは無害）
- 将来、typesVersions に余剰エントリの検出が必要になった場合はチェック6として追加可能

**判断**: typesVersions 逆方向チェック不在は **妥当** と判断する。理由が上記3点で合理的であるため。

## ゲート判定基準

### 判定区分

| 判定              | 条件                                                                                   | 対応                                                    |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| PASS              | 全レビュー項目が確認済みで、設計に問題がない                                           | Phase 4 へ進む                                          |
| MINOR             | 軽微な改善点がある（命名変更、コメント追加、ドキュメント補足）                         | 指摘対応後 Phase 4 へ（指摘は未タスク仕様書に変換必須） |
| MAJOR（要件問題） | 5段階チェックの要件に漏れがある、受入基準が不十分、スコープ定義が曖昧                  | Phase 1 へ戻る                                          |
| MAJOR（設計問題） | チェッカー関数の設計が要件を満たさない、CIジョブ依存関係が不正、正規表現がマッチしない | Phase 2 へ戻る                                          |

### MINOR 判定時の具体例

以下は MINOR 判定となる指摘の例:

- 型定義の命名がプロジェクト規約と一致しない（例: `CheckIssue` → `SyncCheckIssue`）
- レポートフォーマットの文言修正（例: 「存在しません」→「見つかりません」）
- 追加のエッジケーステストの提案

### MAJOR 判定時の具体例

以下は MAJOR 判定となる指摘の例:

- **要件問題**: 5段階チェック以外に必要なチェック（例: exports の types/import パスの存在確認）が漏れている
- **設計問題**: 正規表現が現在の vitest.config.ts のフォーマットにマッチしない
- **設計問題**: CIジョブの `needs` 設定が不正で、check-module-sync が build-shared の後に実行される
