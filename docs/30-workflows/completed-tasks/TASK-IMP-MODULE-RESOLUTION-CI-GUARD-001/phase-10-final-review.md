### Task 1: 機能完全性レビュー

Phase 1 で定義した要件と受入基準に対する充足状況を検証する。

#### 1.1 5段階チェックの実装確認

| チェック# | 検証方向                | 実装状況 | 確認方法                                       |
| --------- | ----------------------- | -------- | ---------------------------------------------- |
| 1         | exports → paths         | 確認     | `checkExportsVsPaths` 関数の存在と動作         |
| 2         | paths → exports         | 確認     | `checkPathsVsExports` 関数の存在と動作         |
| 3         | exports → aliases       | 確認     | `checkExportsVsAliases` 関数の存在と動作       |
| 4         | aliases → exports       | 確認     | `checkAliasesVsExports` 関数の存在と動作       |
| 5         | exports → typesVersions | 確認     | `checkExportsVsTypesVersions` 関数の存在と動作 |

#### 1.2 受入基準チェック（Phase 1 Task 2 から転記）

- [ ] `.github/workflows/ci.yml` に `check-module-sync` ジョブが定義されている
- [ ] `check-module-sync` ジョブは `lint` と並列に実行される
- [ ] `check-module-sync` ジョブは `build` ジョブの `needs` に含まれている
- [ ] `exports` にあるが他層にないエントリを検出し、exit code 1 で終了する
- [ ] 他層にあるが `exports` にないエントリを検出し、exit code 1 で終了する
- [ ] 全層が整合している場合、exit code 0 で正常終了する
- [ ] 不整合検出時に差分レポートが出力される
- [ ] 差分レポートに修正方法ガイダンスが含まれる
- [ ] サマリーにエントリ数と不足数が表示される

## ゲート判定

### 判定基準

| 判定     | 条件                                                        | 対応                                               |
| -------- | ----------------------------------------------------------- | -------------------------------------------------- |
| PASS     | 全6観点で問題なし                                           | Phase 11 へ進む                                    |
| MINOR    | 機能に影響しない軽微な指摘（命名改善、コメント追加等）      | 未タスク仕様書に変換後 Phase 11 へ（**省略不可**） |
| MAJOR    | 機能要件の未充足、テスト不足、CI統合の問題                  | 影響範囲に応じて Phase 1-5 へ戻る                  |
| CRITICAL | 5段階チェックの設計自体に誤りがある、セキュリティ脆弱性あり | Phase 1 へ戻り要件再確認                           |

### MINOR 指摘の処理

MINOR 判定の指摘は**全て**未タスク仕様書に変換する。「機能影響なし」であっても省略不可。

変換先: `docs/30-workflows/unassigned-task/` 配下に指示書を作成する。

## 実行手順

1. 機能完全性レビューを実施する（Task 1）
   - 5段階チェックの実装確認
   - 受入基準チェック（Phase 1 から転記した全項目）
2. コード品質レビューを実施する（Task 2）
   - TypeScript strict モード準拠
   - コーディング規約準拠

3. テスト品質レビューを実施する（Task 3）
   - カバレッジ基準の充足
   - テストケースの網羅性
4. CI統合レビューを実施する（Task 4）
   - ジョブ定義の正確性
   - 依存関係の正確性
5. セキュリティレビューを実施する（Task 5）
   - 読み取り専用の確認
   - パストラバーサルの確認
6. ドキュメントレビューを実施する（Task 6）

7. ゲート判定を行い、結果を記録する
8. MINOR 指摘がある場合、未タスク仕様書に変換する
9. レビュー結果を `outputs/phase-10/` に記録する
