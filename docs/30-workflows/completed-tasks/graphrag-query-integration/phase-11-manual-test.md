## 目的

自動テストでは検証しきれない部分を手動で確認する。実際の使用シナリオに基づいた動作確認と、ユーザー視点での品質検証を行う。

## 背景

自動テストはロジックの正確性を検証するが、実際のユースケースでの使用感やエッジケースは手動テストで確認する必要がある。特にLLM統合やコミュニティ要約の品質は、人間の判断が必要となる。

### タスク2: ユースケースシナリオテスト

**目的**: 実際のユースケースに基づいたシナリオテストを実行する

**実行手順**:

```typescript

const service = new GraphRAGQueryService(dependencies);

  "このプロジェクト全体の概要を教えてください",
  { enableCommunitySummary: true },
);
console.log(result);
```

| 確認項目                   | 期待結果                      | 実際の結果 | 判定 |

| 処理時間が妥当             | < 5秒                         | ?          | ?    |


### タスク3: パフォーマンス体感テスト

**目的**: 実際の使用時のパフォーマンスを体感的に確認する

**実行手順**:

1. レスポンス時間を測定する

| クエリタイプ              | 期待時間 | 実測時間 | 判定 |
| ------------------------- | -------- | -------- | ---- |
| 短いクエリ（< 10文字）    | < 2秒    | ?ms      | ?    |
| 中程度クエリ（10-50文字） | < 3秒    | ?ms      | ?    |
| 長いクエリ（> 50文字）    | < 5秒    | ?ms      | ?    |

2. 連続クエリテスト

```typescript
// 5回連続クエリ
for (let i = 0; i < 5; i++) {
  const start = Date.now();
  await service.query(`テストクエリ ${i}`);
  console.log(`Query ${i}: ${Date.now() - start}ms`);
}
```

| 確認項目         | 期待結果                 | 実際の結果 | 判定 |
| ---------------- | ------------------------ | ---------- | ---- |
| 初回クエリ時間   | < 5秒                    | ?          | ?    |
| 2回目以降の時間  | 初回と同等またはそれ以下 | ?          | ?    |
| メモリリークなし | メモリ使用量安定         | ?          | ?    |

**期待される成果物**:
