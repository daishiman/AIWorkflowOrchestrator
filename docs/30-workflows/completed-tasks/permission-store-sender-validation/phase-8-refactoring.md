## 実行タスク

### Task 1: sender 検証パターンの確認

Phase 2 の設計段階で `withValidation` ラッパーパターンを採用済み。これにより sender 検証の重複コードは最小化されている。

**Phase 2 での判断**: `withValidation` ラッパーの採用により、4ハンドラ × 8行 = 32行の重複が、4ハンドラ × 4行 = 16行に削減されている。追加のリファクタリングは不要。

**確認事項**:

- [ ] `withValidation` パターンが全4ハンドラに一貫して適用されていること
- [ ] 不要な import（`validateIpcSender`, `toIPCValidationError` の直接 import）が残っていないこと

### Task 2: テストコードの重複削減

- `createMockEvent` ヘルパーが適切に活用されているか確認
- モックセットアップの共通化を検討

### Task 3: 命名の一貫性確認

- `event` vs `_event` の統一（全て `event` に変更済みか）
- コメントの一貫性
