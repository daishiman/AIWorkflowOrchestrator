## 目的

- リスク・懸念事項の洗い出し

- PASS / MINOR / MAJOR 判定と戻り先の確定
- ゲート判定

## 実行手順

### ステップ1: 4 条件評価を実施する

価値性、実現性、整合性、運用性の観点で設計を評価する。

### ステップ2: リスクと懸念事項を洗い出す

実装上のリスク、他タスクとの競合可能性、技術的不確実性を特定する。

### ステップ3: ゲート判定を行う

実装着手可否を判定し、条件付き承認の場合は条件を明記する。

## 判定ルール（戻り先）

| 判定  | 影響             | 戻り先                               |
| ----- | ---------------- | ------------------------------------ |
| PASS  | 実装へ進行       | Phase 4                              |
| MINOR | 仕様は維持       | Phase 5/8 で修正、Phase 10/12 で確認 |
| MAJOR | 仕様再設計が必要 | Phase 2 へ戻る                       |

## simpler alternative

- 既存 Facade/IPC の薄いラッパーで実現できる場合は新規 state を増やさない
- UI 追加が最小部品で成立するかを検討し、差分が大きい場合は差し戻す
