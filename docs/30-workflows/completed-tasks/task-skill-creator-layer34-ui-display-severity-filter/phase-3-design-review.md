# Phase 3: 設計レビュー - SkillCreator Layer3/4 severity フィルタ追加

## メタ情報

| 項目   | 値                                                    |
| ------ | ----------------------------------------------------- |
| Phase  | 3                                                     |
| 機能名 | task-skill-creator-layer34-ui-display-severity-filter |
| 作成日 | 2026-04-03                                            |

## 目的

Phase 2 の設計を多角的にレビューし、Phase 4（テスト作成）へ進めるかを判定する。

## 実行タスク

### タスク1: 設計整合性レビュー

**目的**: 設計が要件を満たしているか検証する。

**手順**:

1. AC-1〜AC-7 の全受け入れ基準が設計でカバーされていることを確認する
2. `SeverityFilterValue` 型が `RuntimeSkillCreatorVerifyCheckSeverity` と整合していることを確認する
3. `expandedLayers` state との独立性が設計で保証されていることを確認する
4. reverify 後の state 維持が設計で明示されていることを確認する

**期待される成果物**: 設計整合性チェック結果

### タスク2: UI/UX レビュー

**目的**: UI 設計が Apple HIG 準拠かつ既存 UI との一貫性を持つか検証する。

**手順**:

1. セグメントコントロールが既存 UI パターンと一貫しているか確認する
2. 8px グリッドに基づくスペーシングが設計されているか確認する
3. ダーク/ライトモード対応が CSS 変数で実現されているか確認する
4. フィルタ後の「表示中 X / 全 Y 件」表示が情報隠蔽を防ぐか確認する

**期待される成果物**: UI/UXレビュー結果

### タスク3: テスタビリティレビュー

**目的**: Phase 4 で効果的なテストを書けるか設計の観点から検証する。

**手順**:

1. filter state が外部から操作可能か（`fireEvent.click` で切り替え可能か）確認する
2. filter 後の DOM 状態が検証しやすい `data-testid` 属性を設計に含めるか確認する
3. mock データで severity の各パターンを網羅できるか確認する

**期待される成果物**: テスタビリティレビュー結果

### タスク4: 判定

**目的**: Phase 4 へ進行可能かを判定する。

| 判定  | 条件             | 戻り先                    |
| ----- | ---------------- | ------------------------- |
| PASS  | 設計に問題なし   | Phase 4                   |
| MINOR | 軽微な修正で解決 | Phase 4（修正事項を記録） |
| MAJOR | 設計問題あり     | Phase 2                   |

**期待される成果物**: 判定結果
