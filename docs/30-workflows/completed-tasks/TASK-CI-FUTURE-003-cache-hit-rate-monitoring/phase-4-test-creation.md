## 目的

Phase 5 の実装を検証するためのテストケースと CI 実行計画を定義する。
本タスクは GitHub Actions YAML の変更のみのため、「テスト」は実際の CI 実行による動作確認を指す。

## 背景

ユニットテストが書けない性質の変更（GitHub Actions YAML）であるため、テストケースは「どの状態で CI を実行し、何を確認するか」として定義する。
キャッシュを意図的にヒット・フォールバック・ミスさせる方法を事前に設計する。

## 実行タスク

### Task 4-A: テストケース定義

3 状態それぞれのテストケースを定義する。

| Case | ID     | 状況                                       | 事前操作                               | 期待する Summary 出力                   | 期待するアノテーション     |
| ---- | ------ | ------------------------------------------ | -------------------------------------- | --------------------------------------- | -------------------------- |
| 1    | TC-001 | 完全一致キーでキャッシュヒット             | なし（通常の CI 実行）                 | `✅ 完全ヒット (Exact Hit)`             | なし                       |
| 2    | TC-002 | `restore-keys` フォールバックでヒット      | `pnpm-lock.yaml` の軽微な変更          | `⚠️ フォールバックヒット (Partial Hit)` | `::notice::`               |
| 3    | TC-003 | キャッシュが存在せずミス                   | GitHub Actions Cache を手動削除        | `❌ キャッシュミス (Miss)`              | `::warning::`              |
| 4    | TC-004 | 前ステップが失敗した場合にも判定が動作する | キャッシュステップを意図的に失敗させる | Summary にキャッシュ状態が出力される    | 状態に応じたアノテーション |

### Task 4-B: キャッシュ状態操作方法の定義

各テストケースの事前操作手順を具体的に定義する。

#### TC-002（フォールバックヒット）の操作手順

```bash
# pnpm-lock.yaml に軽微なコメントを追加してキャッシュキーを変更する
# ただし依存関係は変わらない状態にする
echo "# test-cache-key-change" >> pnpm-lock.yaml
git add pnpm-lock.yaml
git commit -m "test: キャッシュキー変更テスト用"
```

#### TC-003（キャッシュミス）の操作手順

```bash
# GitHub CLI でキャッシュを削除する
gh cache delete --all --repo daishiman/AIWorkflowOrchestrator
# または GitHub UI: リポジトリ > Actions > Caches から手動削除
```

### Task 4-C: 確認手順の定義

各テストケースの確認手順を定義する。

1. GitHub Actions の実行ページを開く
2. 対象ジョブの「キャッシュヒット率確認」ステップを確認する
3. ページ上部の「Summary」タブを開く
4. 期待する Markdown テーブルが表示されているか確認する
5. 「Annotations」セクションで `::warning::` または `::notice::` が出力されているか確認する

### Task 4-D: 異常系テストケース定義

| Case | ID     | 状況                              | 期待する動作                                      |
| ---- | ------ | --------------------------------- | ------------------------------------------------- |
| 5    | TC-005 | `cache-hit` が空文字列の場合      | ミスとして判定される                              |
| 6    | TC-006 | `GITHUB_JOB` 環境変数が利用可能か | テーブルにジョブ名が表示される                    |
| 7    | TC-007 | 複数ジョブで同時実行した場合      | 各ジョブの Summary に独立したテーブルが出力される |
