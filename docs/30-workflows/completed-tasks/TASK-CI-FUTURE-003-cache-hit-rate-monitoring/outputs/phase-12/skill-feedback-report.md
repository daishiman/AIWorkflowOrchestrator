## `task-specification-creator` スキルへのフィードバック

### FB-001: GitHub Actions YAML 変更タスクのテスト計画テンプレート

**観察**: Phase 4 のテスト作成において、本タスクは GitHub Actions YAML の変更のみのためユニットテストが書けない。テストケースは「どの状態で CI を実行し何を確認するか」という CI 実行ベースの計画として定義する必要があった。

**提案**: `task-specification-creator` のテンプレートに「GitHub Actions / インフラ変更タスク用テスト計画」セクションを追加し、CI 実行ベースのテストケース定義形式（状態・事前操作・期待 Summary 出力・期待アノテーション）を標準化する。

---

### FB-002: Phase 11 手動テストの証跡収集方法の標準化

**観察**: Phase 11 の手動テストで「スクリーンショット」の取得が CI ツールの制約上難しい。GitHub Actions Summary は Web UI でのみ確認でき、ローカル環境では再現できない。

**提案**: スクリーンショットが取得できない場合の代替手段として「GitHub Actions 実行 URL + `gh run view` ログ出力」を標準の証跡形式として明記する。

---

### FB-003: カスタムアクション内配置パターンのドキュメント化

**観察**: キャッシュステップがカスタム複合アクション内にある場合、`ci.yml` 各ジョブから `steps.<id>.outputs.*` を直接参照できない。判定ステップをアクション内に配置することで解決したが、この設計判断は Phase 2 で初めて明らかになった。

**提案**: Phase 1 の現状確認チェックリストに「キャッシュステップがカスタムアクション内にある場合の outputs 参照方針」を追加する。

---

## 総評

`task-specification-creator` は全体的に機能しており、Phase 1-12 の実行を適切にガイドできた。上記 3 点はエッジケースの改善提案であり、致命的な問題はない。
