## Task 4-B: キャッシュ状態操作方法の定義

### TC-002（フォールバックヒット）の操作手順

```bash
# pnpm-lock.yaml に軽微なコメントを追加してキャッシュキーを変更する
# ただし依存関係は変わらない状態にする
echo "# test-cache-key-change" >> pnpm-lock.yaml
git add pnpm-lock.yaml
git commit -m "test: キャッシュキー変更テスト用"
```

この操作により:

- キャッシュキーが変わるため `cache-hit=false`
- `restore-keys` の部分マッチにより `node_modules` が復元される

### TC-003（キャッシュミス）の操作手順

```bash
# GitHub CLI でキャッシュを削除する
gh cache delete --all --repo daishiman/AIWorkflowOrchestrator
# または GitHub UI: リポジトリ > Actions > Caches から手動削除
```

## Task 4-C: 確認手順の定義

1. GitHub Actions の実行ページを開く（リポジトリ > Actions > 最新の CI 実行）
2. 対象ジョブ（lint, typecheck 等）の「キャッシュヒット率確認」ステップを確認する
3. ページ上部の「Summary」タブを開く
4. 「キャッシュヒット率レポート」テーブルが出力されているか確認する
5. 「Annotations」セクションで `::warning::` または `::notice::` が出力されているか確認する
