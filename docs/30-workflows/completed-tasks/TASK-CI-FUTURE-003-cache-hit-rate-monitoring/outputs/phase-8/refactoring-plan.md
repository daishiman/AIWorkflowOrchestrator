## Task 8-A: 重複コード排除の方針決定

| 方法                                   | メリット                                     | デメリット                       | 採用判断 |
| -------------------------------------- | -------------------------------------------- | -------------------------------- | -------- |
| 各ジョブにステップをコピー（現状）     | シンプル、独立性が高い                       | ジョブ増加時にメンテナンスが煩雑 | ❌       |
| **カスタムアクション内に配置（採用）** | DRY 原則・一箇所で管理可能・全ジョブ自動適用 | アクション内への変更が必要       | ✅       |
| `workflow_call` による共通ジョブ化     | ジョブ全体の共通化                           | CI 構造が複雑になる              | ❌       |

**採用理由**: カスタムアクション内配置により DRY 原則を実現。Phase 5 の実装で既に採用済み。対象ジョブが 9 件あるためコピー方式では保守性が低下する。

## Task 8-B: bash スクリプトの改善

Phase 5 実装時点で既に Phase 8 の改善事項を反映済み。

| 対象                        | Before（設計時）       | After（実装済み）                             | 理由                     |
| --------------------------- | ---------------------- | --------------------------------------------- | ------------------------ |
| 変数の引用符                | `"$CACHE_HIT"` のみ    | `"$CACHE_HIT"` + `"$CACHE_REASON"` 引用符付き | 特殊文字対策             |
| Summary 出力のジョブ名      | `$GITHUB_JOB`          | `${GITHUB_JOB:-unknown}`                      | 未定義時のフォールバック |
| `$GITHUB_STEP_SUMMARY` 参照 | `$GITHUB_STEP_SUMMARY` | `"$GITHUB_STEP_SUMMARY"`（引用符付き）        | スペース等の特殊文字対策 |
| アノテーションのメッセージ  | -                      | 日本語メッセージ                              | プロジェクトの言語方針   |
