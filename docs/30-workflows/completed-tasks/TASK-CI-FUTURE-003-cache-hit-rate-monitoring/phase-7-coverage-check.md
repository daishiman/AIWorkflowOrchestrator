# Phase 7: テストカバレッジ確認

## メタ情報

| 項目       | 内容                                 |

| Phase      | 7                                    |
| 機能名     | TASK-CI-FUTURE-003                   |
| タスク名   | キャッシュヒット率のモニタリング設定 |

| 後続Phase  | Phase 8                              |
| 作成日     | 2026-04-15                           |
| ステータス | pending                              |

## 目的

Phase 4〜6 のテストが、Phase 1 で定義した受け入れ基準と機能要件を網羅しているかを可視化する。
未到達パスを特定し、Phase 8 以降での対処方針を決定する。

## 実行タスク

### Task 7-A: 受け入れ基準の網羅率確認

Phase 1 の受け入れ基準 AC-001〜AC-006 それぞれについて、対応するテストケースが存在するかを確認する。

| 受け入れ基準 | 内容                                               | 対応テストケース | 網羅状態 |
| ------------ | -------------------------------------------------- | ---------------- | -------- |
| AC-001       | 完全ヒット時に `✅ 完全ヒット (Exact Hit)` が表示  | TC-001           | -        |
| AC-002       | フォールバックヒット時に `⚠️` が表示               | TC-002           | -        |
| AC-003       | キャッシュミス時に `❌` が表示                     | TC-003           | -        |
| AC-004       | キャッシュミス時に `::warning::` が出力される      | TC-003           | -        |
| AC-005       | 判定ステップが失敗しても CI 全体がブロックされない | TC-004, TC-011   | -        |
| AC-006       | CI 実行時間に実質的な影響がない                    | RG-004           | -        |

### Task 7-B: 機能要件の網羅率確認

Phase 1 の機能要件 FR-001〜FR-006 それぞれについて、実装とテストの網羅状態を確認する。

| 要件ID | 要件内容                                              | 対応テストケース       | 実装確認 | テスト確認 |
| ------ | ----------------------------------------------------- | ---------------------- | -------- | ---------- |
| FR-001 | 3 状態（完全ヒット・フォールバック・ミス）を判定する  | TC-001, TC-002, TC-003 | -        | -          |
| FR-002 | `$GITHUB_STEP_SUMMARY` に Markdown テーブルを出力する | TC-001〜TC-003         | -        | -          |
| FR-003 | キャッシュミス時に `::warning::` を出力する           | TC-003                 | -        | -          |
| FR-004 | フォールバックヒット時に `::notice::` を出力する      | TC-002                 | -        | -          |
| FR-005 | `if: always()` が設定されている                       | TC-004, TC-011         | -        | -          |
| FR-006 | `continue-on-error: true` が設定されている            | TC-010, TC-011         | -        | -          |

### Task 7-C: 未到達パスの分析

Phase 4〜6 のテストで未検証の条件を特定し、対処方針を記録する。

| 未到達パス                     | 理由                                                  | 対処方針                         |
| ------------------------------ | ----------------------------------------------------- | -------------------------------- |
| `cache-hit` が存在しないケース | `pnpm-install-retry` が `cache-hit` を出力しない場合  | Phase 8 で条件分岐の追加を検討   |
| 複数ジョブの同時実行           | 並列ジョブが同一 Summary ファイルに書き込む場合の競合 | Phase 8 でマルチジョブ対応を検討 |

### Task 7-D: トレーサビリティ網羅率の算出

```
受け入れ基準網羅率 = 対応テストケースが存在する AC の数 / AC 総数 × 100
機能要件網羅率    = 対応テストケースが存在する FR の数 / FR 総数 × 100

目標: 両指標ともに 100% を達成する
```

## 実行手順

1. Phase 1 の受け入れ基準一覧を確認する
2. Task 7-A のテーブルを埋める（各 AC に対応する TC を確認し ✅/❌ を記録する）
3. Task 7-B のテーブルを埋める（各 FR に対応するテストと実装の状態を確認する）
4. 未到達パスを Task 7-C に記録する
5. Task 7-D で網羅率を算出する
6. 100% 未達の場合は Phase 8 での対処方針を記録する
7. 成果物を `outputs/phase-7/` に保存する
