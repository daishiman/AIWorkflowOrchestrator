## 目的

Phase 5 の実装を Phase 7 の未到達パス分析を踏まえて改善し、重複排除・再利用性向上・保守性向上を図る。

## 実行タスク

### Task 8-A: 重複コードの排除検討

複数ジョブに同一の判定ステップが追加されている場合、重複を削減する方法を検討する。

| 方法                               | メリット                   | デメリット                             | 採用判断 |
| ---------------------------------- | -------------------------- | -------------------------------------- | -------- |
| 各ジョブにステップをコピー（現状） | シンプル、独立性が高い     | ジョブ増加時にメンテナンスが煩雑       | -        |
| 再利用可能なカスタムアクション化   | DRY 原則、一箇所で管理可能 | カスタムアクション作成のオーバーヘッド | -        |
| `workflow_call` による共通ジョブ化 | ジョブ全体の共通化         | CI 構造が複雑になる                    | -        |

**判断基準**: 対象ジョブが 3 件以下の場合は現状（コピー）を維持する。4 件以上になった場合はカスタムアクション化を検討する。

### Task 8-B: bash スクリプトの改善

Phase 5 で実装した bash スクリプトの品質を改善する。

変更対象・Before・After・理由テーブル:

| 対象                       | Before                                         | After                                             | 理由                                    |
| -------------------------- | ---------------------------------------------- | ------------------------------------------------- | --------------------------------------- |
| 条件分岐の順序             | `cache-hit=true` → `node_modules` 存在確認の順 | 変更なし（正しい優先順位）                        | `cache-hit=true` の優先判定が正しいため |
| 変数の引用符               | `"$CACHE_HIT"` のみ                            | `"$CACHE_HIT"` + `"$CACHE_REASON"` 一貫して引用符 | 特殊文字対策                            |
| Summary 出力のジョブ名     | `$GITHUB_JOB`                                  | `${GITHUB_JOB:-unknown}`                          | 未定義時のフォールバック                |
| アノテーションのメッセージ | 英語                                           | 日本語（TASK-CI-FUTURE-003 に合わせて）           | プロジェクトの言語方針                  |

### Task 8-C: Phase 7 未到達パスへの対応

Phase 7 で特定された未到達パスへの対処を実施する。

| 未到達パス               | 対処内容                                                                   |
| ------------------------ | -------------------------------------------------------------------------- |
| `cache-hit` が未定義     | bash の `-z` チェックで `cache-hit` が空の場合をミスとして扱う（変更なし） |
| 複数ジョブの同時書き込み | `>>` 追記形式のため競合しない（変更不要）                                  |

### Task 8-D: ナビゲーションドリフトの確認

`.github/workflows/ci.yml` 内の参照が正確かを確認する。

| 確認項目                                         | 期待値                  | 確認結果 |
| ------------------------------------------------ | ----------------------- | -------- |
| `steps.cache-node-modules.outputs.cache-hit`     | 正確な参照              | -        |
| `steps.cache-node-modules.outputs.cache-reason`  | 正確な参照              | -        |
| 全対象ジョブの `id` が一意で命名規則に従っている | `cache-node-modules` 等 | -        |
