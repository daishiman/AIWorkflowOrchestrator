## 目的

`.github/workflows/ci.yml` に対するキャッシュヒット率モニタリング機能の要件を確定し、受け入れ基準を固定する。

## 背景

TASK-CI-OPT-001 で node_modules キャッシュを導入し CI 実行時間を 15 分超から約 5〜7 分に短縮した。
しかしキャッシュが劣化してもモニタリング手段がなく、開発者が能動的にログを確認しなければ状態がわからない。
本タスクは `actions/cache@v4` の `cache-hit` output と cache restore 直後の `node_modules` 存在確認を活用し、3 状態（完全ヒット・フォールバックヒット・ミス）を自動で判定・通知する仕組みを整備する。

## タスク分類

| 分類       | 該当 | 理由                                      |
| ---------- | ---- | ----------------------------------------- |
| UI task    | ❌   | フロントエンドの変更なし                  |
| docs-only  | ❌   | GitHub Actions YAML の変更を伴う          |
| 設計タスク | ✅   | CI 設定変更のみ（コードロジック変更なし） |

## 実行タスク

### Task 1-A: 現状確認

現在の `.github/workflows/ci.yml` において以下を確認する。

1. `actions/cache@v4` または `pnpm-install-retry` カスタムアクションの設定箇所を列挙する
2. 各キャッシュステップに `id` が設定されているかを確認する（`id: cache-node-modules` 等）
3. `steps.<id>.outputs.cache-hit` と cache restore 直後の `node_modules` 存在を確認できるかを確認する
4. 対象ジョブ（lint、typecheck、test 等）の一覧を確定する

### Task 1-B: 機能要件の定義

以下の機能要件を確定する。

| 要件ID | 要件                                                                          | 優先度 |
| ------ | ----------------------------------------------------------------------------- | ------ |
| FR-001 | 各 CI ジョブでキャッシュの3状態（完全ヒット・フォールバック・ミス）を判定する | 必須   |
| FR-002 | 判定結果を `$GITHUB_STEP_SUMMARY` に Markdown テーブル形式で出力する          | 必須   |
| FR-003 | キャッシュミス時に `::warning::` アノテーションを出力する                     | 必須   |
| FR-004 | フォールバックヒット時に `::notice::` アノテーションを出力する                | 推奨   |
| FR-005 | 判定ステップに `if: always()` を設定し前ステップ失敗時も動作させる            | 必須   |
| FR-006 | 判定ステップに `continue-on-error: true` を設定し CI 全体への影響を防ぐ       | 必須   |

### Task 1-C: 非機能要件の定義

| 要件ID  | 要件                                                             | 優先度 |
| ------- | ---------------------------------------------------------------- | ------ |
| NFR-001 | 追加ステップの実行時間が数秒以内（既存 CI への影響を最小化）     | 必須   |
| NFR-002 | キャッシュ判定ロジックが誤判定しない（ヒット時ミス判定しない等） | 必須   |
| NFR-003 | 複数ジョブに同一ロジックを適用できる構造とする                   | 推奨   |

### Task 1-D: 受け入れ基準の固定

| 基準ID | 検証内容                                                                                 | 検証方法 |
| ------ | ---------------------------------------------------------------------------------------- | -------- |
| AC-001 | 完全ヒット時に `✅ 完全ヒット (Exact Hit)` が Summary に表示される                       | CI実行   |
| AC-002 | フォールバックヒット時に `⚠️ フォールバックヒット (Partial Hit)` が Summary に表示される | CI実行   |
| AC-003 | キャッシュミス時に `❌ キャッシュミス (Miss)` が Summary に表示される                    | CI実行   |
| AC-004 | キャッシュミス時に `::warning::` アノテーションが出力される                              | CI実行   |
| AC-005 | 判定ステップが失敗しても CI 全体がブロックされない                                       | CI実行   |
| AC-006 | 既存 CI ジョブの実行時間に実質的な影響（5秒超）がない                                    | CI実行   |

## 実行手順

1. `.github/workflows/ci.yml` を読み込み、キャッシュステップの一覧を抽出する
2. `.github/actions/pnpm-install-retry/action.yml` を読み込み、`cache-hit` outputs が利用可能か確認する
3. キャッシュステップに `id` が未設定の場合は「Phase 2 での追加が必要」と記録する
4. 機能要件 FR-001〜FR-006 と非機能要件 NFR-001〜NFR-003 を文書化する
5. 受け入れ基準 AC-001〜AC-006 を文書化する
6. 成果物を `outputs/phase-1/` に保存する
