## 目的

Phase 1〜9 の全成果物を俯瞰し、Phase 11（手動テスト）へ進める品質に達しているかをゲート判定する。
受け入れ基準 AC-001〜AC-006 を全て満たしているかを最終確認する。

## 実行タスク

### Task 10-A: 受け入れ基準の最終確認

Phase 1 で定義した受け入れ基準を全て確認する。

| 基準ID | 検証内容                                                                                 | 確認結果 | 証跡 |
| ------ | ---------------------------------------------------------------------------------------- | -------- | ---- |
| AC-001 | 完全ヒット時に `✅ 完全ヒット (Exact Hit)` が Summary に表示される                       | -        | -    |
| AC-002 | フォールバックヒット時に `⚠️ フォールバックヒット (Partial Hit)` が Summary に表示される | -        | -    |
| AC-003 | キャッシュミス時に `❌ キャッシュミス (Miss)` が Summary に表示される                    | -        | -    |
| AC-004 | キャッシュミス時に `::warning::` アノテーションが出力される                              | -        | -    |
| AC-005 | 判定ステップが失敗しても CI 全体がブロックされない                                       | -        | -    |
| AC-006 | 既存 CI ジョブの実行時間に実質的な影響（5秒超）がない                                    | -        | -    |

### Task 10-B: CI 変更範囲確認

本タスクは GitHub Actions CI の設定変更のみのため、アプリ本体コードへの影響はない。
以下の確認のみ実施する。

| 確認項目                                                       | 確認結果 |
| -------------------------------------------------------------- | -------- |
| アプリケーションコード（`apps/`、`packages/`）の変更がないこと | -        |
| `.github/workflows/ci.yml` のみが変更対象であること            | -        |
| 判定ステップが Summary / annotation 出力に限定されていること   | -        |

### Task 10-C: ブロッカー確認

Phase 11 への移行を妨げるブロッカーを確認する。

| カテゴリ     | チェック内容                                                | ブロッカー有無 |
| ------------ | ----------------------------------------------------------- | -------------- |
| 機能完全性   | FR-001〜FR-006 が全て実装されているか                       | -              |
| テスト完全性 | AC-001〜AC-006 に対応するテストが全て実行済みか             | -              |
| 品質         | Phase 9 の品質保証レポートで未解決問題がないか              | -              |
| セキュリティ | Phase 9 のセキュリティ確認が全項目クリアか                  | -              |
| 回帰         | 既存 CI ジョブへの影響がないか（RG-001〜RG-004 全 PASS か） | -              |

### Task 10-D: ゲート判定

| 判定基準             | 合格条件                                |
| -------------------- | --------------------------------------- |
| CRITICAL ブロッカー  | 0 件（1 件以上あれば Phase 5 差し戻し） |
| MAJOR ブロッカー     | 0 件（1 件以上あれば Phase 8 差し戻し） |
| MINOR 問題           | 記録のみ（Phase 11/12 で対処可）        |
| 受け入れ基準全充足   | AC-001〜AC-006 が全て ✅                |
| Phase 9 品質レポート | 全項目 PASS                             |

### Task 10-E: 是正計画

ブロッカーが存在する場合の是正計画を記録する。

| ブロッカー内容 | 差し戻し先 | 是正内容 | 期限 |
| -------------- | ---------- | -------- | ---- |
| （なし）       | -          | -        | -    |

## 実行手順

1. Phase 9 の全成果物（`outputs/phase-9/`）を確認する
2. Task 10-A の受け入れ基準を全て確認し、証跡（CI 実行ログ URL 等）を記録する
3. Task 10-B の CI 変更範囲を確認する
4. Task 10-C のブロッカー確認を実施する
5. Task 10-D のゲート判定を実施する
6. ブロッカーがある場合は Task 10-E に是正計画を記録し、該当 Phase へ差し戻す
7. PASS の場合は最終レビュー結果を `outputs/phase-10/` に保存する
