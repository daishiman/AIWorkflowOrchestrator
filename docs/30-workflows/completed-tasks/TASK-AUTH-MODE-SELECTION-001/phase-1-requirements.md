## 目的

認証方式選択機能の要件を明確化し、Claude Code CLI認証メカニズムを調査する。

## 背景

現在のAIWorkflowOrchestratorでは、スキル実行時に2つの認証方式が存在する:

1. **サブスクリプション認証**: Supabase OAuth経由でログインし、サブスクリプションに紐づくAPI使用権を利用
2. **APIキー認証**: ユーザーが自身のAnthropic APIキーを設定して直接利用

これらの認証方式をユーザーが明示的に選択・切り替えできる機能が必要。また、Claude Code CLIの認証トークン（`~/.claude/`ディレクトリ）を活用する可能性も調査する。

---

## 実行タスク

### タスク1: Claude Code CLI認証メカニズム調査

Claude Code CLIが使用する認証トークンの格納場所と形式を調査する。

**調査項目**:

| 項目                 | 調査内容                             |
| -------------------- | ------------------------------------ |
| ディレクトリ構造     | `~/.claude/` 配下のファイル構成      |
| トークン格納ファイル | 認証トークンが保存されるファイル名   |
| トークン形式         | JSON/テキスト/暗号化形式の確認       |
| 有効期限             | トークンのTTLと更新メカニズム        |
| 取得方法             | プログラムからトークンを取得する方法 |
| セキュリティ考慮     | ファイルパーミッション、暗号化の有無 |
| 既存実装との互換性   | AuthKeyServiceとの統合可能性         |

**成果物**: `outputs/phase-1/cli-auth-investigation.md`

### タスク2: ユーザーストーリー定義

ユーザー視点での認証方式選択の利用シナリオを定義する。

**ユーザーストーリー（最低3件）**:

| ID   | ユーザーストーリー                                                                                      | 優先度 |
| ---- | ------------------------------------------------------------------------------------------------------- | ------ |
| US-1 | サブスクリプションユーザーとして、ログイン状態でスキルを実行したい。追加のAPIキー設定なしで利用できる。 | 高     |
| US-2 | 自分のAPIキーを持つユーザーとして、サブスクリプションに依存せず自分のAPIキーでスキルを実行したい。      | 高     |
| US-3 | ユーザーとして、設定画面で認証方式を切り替えたい。UIで明確に現在の認証方式を確認できる。                | 高     |
| US-4 | サブスクリプション未契約ユーザーとして、無料トライアルが終了した場合にAPIキー認証に切り替えたい。       | 中     |
| US-5 | 開発者として、Claude Code CLIのトークンを流用してシームレスに認証したい。                               | 低     |

**成果物**: `outputs/phase-1/user-stories.md`

### タスク3: 機能要件・非機能要件の文書化

**機能要件（FR）**:

| ID   | 要件                                                                   | 優先度 |
| ---- | ---------------------------------------------------------------------- | ------ |
| FR-1 | ユーザーは設定画面で認証方式（サブスクリプション/APIキー）を選択できる | 必須   |
| FR-2 | 選択した認証方式はアプリ再起動後も永続化される                         | 必須   |
| FR-3 | 認証方式に応じて適切な認証プロバイダーがスキル実行時に使用される       | 必須   |
| FR-4 | サブスクリプション認証選択時、未ログインならエラーメッセージを表示する | 必須   |
| FR-5 | APIキー認証選択時、キー未設定ならエラーメッセージを表示する            | 必須   |
| FR-6 | 現在の認証方式と認証状態をUIに表示する                                 | 必須   |
| FR-7 | 認証方式変更時、確認ダイアログを表示する（破壊的操作保護）             | 推奨   |
| FR-8 | Claude Code CLIトークンの自動検出機能（`~/.claude/`ディレクトリ）      | 任意   |

**非機能要件（NFR）**:

| ID    | 要件                                                | 基準                  |
| ----- | --------------------------------------------------- | --------------------- |
| NFR-1 | 認証方式切り替えは1秒以内に完了する                 | レスポンスタイム < 1s |
| NFR-2 | トークン・APIキーは暗号化して保存する               | safeStorage使用       |
| NFR-3 | Renderer ProcessにAPIキー・トークンを直接公開しない | Main Process管理      |
| NFR-4 | 認証エラーはサニタイズしてRendererに送信する        | 機密情報漏洩防止      |
| NFR-5 | 認証状態変更のログは構造化ログとして記録する        | 監査対応              |

**成果物**: `outputs/phase-1/requirements-definition.md`

### タスク4: 受入基準の定義

**受入基準（Given-When-Then形式）**:

| ID   | Given（前提条件）                      | When（操作）                      | Then（期待結果）                                |
| ---- | -------------------------------------- | --------------------------------- | ----------------------------------------------- |
| AC-1 | サブスクリプション認証が選択されている | ログイン済みでスキルを実行する    | スキルが正常に実行される                        |
| AC-2 | サブスクリプション認証が選択されている | 未ログイン状態でスキルを実行する  | 「ログインが必要です」エラーが表示される        |
| AC-3 | APIキー認証が選択されている            | APIキー設定済みでスキルを実行する | スキルが正常に実行される                        |
| AC-4 | APIキー認証が選択されている            | APIキー未設定でスキルを実行する   | 「APIキーを設定してください」エラーが表示される |
| AC-5 | 設定画面を開いている                   | 認証方式を切り替える              | 選択が即座に反映され、永続化される              |
| AC-6 | 認証方式を切り替えた後                 | アプリを再起動する                | 切り替えた認証方式が維持されている              |
| AC-7 | トークンが期限切れの状態               | スキルを実行する                  | 適切なエラーメッセージが表示される              |

**成果物**: `outputs/phase-1/acceptance-criteria.md`
