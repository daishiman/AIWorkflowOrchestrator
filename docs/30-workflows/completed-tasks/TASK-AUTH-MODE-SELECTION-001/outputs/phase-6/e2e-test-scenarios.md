## 概要

認証方式選択機能の完全なユーザーフローをカバーするE2Eテストシナリオを設計する。

## E2Eテストシナリオ

### シナリオ1: サブスクリプション認証からAPIキー認証への切り替え

**前提条件**:

- ユーザーはサブスクリプション認証でログイン済み
- Claude Code CLIでトークンが設定されている

**テスト手順**:

1. 設定画面を開く
2. 認証方式セクションを表示
3. 現在の認証方式が「サブスクリプション」と表示されていることを確認
4. 「APIキー」を選択
5. 確認ダイアログが表示されることを確認
6. APIキー入力フィールドにキーを入力
7. 「切り替え」ボタンをクリック
8. 認証方式が「APIキー」に変更されたことを確認
9. スキル実行を行い、APIキーで認証されることを確認

**期待結果**:

- 認証方式が正しく切り替わる
- スキル実行時にAPIキーが使用される
- UIに現在の認証方式が正しく表示される

### シナリオ2: APIキー認証からサブスクリプション認証への切り替え

**前提条件**:

- ユーザーはAPIキー認証モード
- Claude Code CLIでトークンが設定されている

**テスト手順**:

1. 設定画面を開く
2. 認証方式セクションを表示
3. 現在の認証方式が「APIキー」と表示されていることを確認
4. 「サブスクリプション」を選択
5. 確認ダイアログが表示されることを確認
6. 「切り替え」ボタンをクリック
7. 認証方式が「サブスクリプション」に変更されたことを確認
8. スキル実行を行い、サブスクリプショントークンで認証されることを確認

**期待結果**:

- 認証方式が正しく切り替わる
- スキル実行時にサブスクリプショントークンが使用される

### シナリオ3: 認証エラーからの復旧

**前提条件**:

- ユーザーはサブスクリプション認証モード
- トークンが期限切れまたは無効

**テスト手順**:

1. スキル実行を試みる
2. 認証エラーが表示されることを確認
3. エラーメッセージに「再ログインが必要」と表示されることを確認
4. 設定画面を開く
5. 認証方式を「APIキー」に切り替え
6. 有効なAPIキーを入力
7. スキル実行を再試行
8. スキルが正常に実行されることを確認

**期待結果**:

- エラーメッセージが適切に表示される
- 認証方式を切り替えて復旧できる

### シナリオ4: アプリケーション再起動後の認証方式維持

**前提条件**:

- ユーザーがAPIキー認証モードに設定済み

**テスト手順**:

1. アプリケーションを終了
2. アプリケーションを再起動
3. 設定画面を開く
4. 認証方式が「APIキー」のままであることを確認
5. スキル実行を行い、APIキーで認証されることを確認

**期待結果**:

- 認証方式の設定が永続化されている
- 再起動後も同じ認証方式が使用される

### シナリオ5: オフライン時の認証方式操作

**前提条件**:

- ネットワーク接続が切断されている

**テスト手順**:

1. ネットワーク接続を切断
2. 設定画面を開く
3. 認証方式を切り替えようとする
4. オフラインエラーが表示されることを確認
5. ネットワーク接続を復旧
6. 認証方式の切り替えを再試行
7. 正常に切り替わることを確認

**期待結果**:

- オフライン時は適切なエラーメッセージが表示される
- オンライン復旧後は正常に動作する

### シナリオ6: 無効なAPIキーでの切り替え試行

**前提条件**:

- ユーザーはサブスクリプション認証モード

**テスト手順**:

1. 設定画面を開く
2. 「APIキー」を選択
3. 無効なAPIキー（短すぎる、フォーマット不正）を入力
4. 「切り替え」ボタンをクリック
5. バリデーションエラーが表示されることを確認
6. 認証方式が変更されていないことを確認

**期待結果**:

- 無効なAPIキーでは切り替えが拒否される
- 適切なエラーメッセージが表示される

## 技術的考慮事項

### Playwrightテスト実装時の注意点

1. **Electron環境**: Playwrightの`_electron`モジュールを使用
2. **IPC通信**: IPCチャンネルのモック化が必要
3. **Keychainアクセス**: テスト環境ではモックが必要
4. **ネットワーク状態**: Playwrightのネットワーク制御機能を使用

### テストデータ

```typescript
// テスト用APIキー（無効なキー）
const TEST_INVALID_API_KEYS = [

// テスト用有効なAPIキー形式
const TEST_VALID_API_KEY_FORMAT = "sk-ant-api03-valid-test-key-123456789";
```
