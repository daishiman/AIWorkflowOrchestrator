## US-1: サブスクリプション認証でのスキル実行

**As a** サブスクリプションユーザー
**I want to** ログイン状態でスキルを実行したい
**So that** 追加のAPIキー設定なしで利用できる

### 受入基準

- Claude Code CLIでログイン済みであること
- 設定画面でサブスクリプション認証が選択されていること
- スキル実行が成功し、結果が表示されること
- APIキーを別途設定する必要がないこと

### 優先度

高

---

## US-2: APIキー認証でのスキル実行

**As a** 自分のAPIキーを持つユーザー
**I want to** サブスクリプションに依存せず自分のAPIキーでスキルを実行したい
**So that** サブスクリプション契約なしでもサービスを利用できる

### 受入基準

- 設定画面でAPIキー認証が選択されていること
- 有効なAnthropic APIキーが設定されていること
- スキル実行が成功し、結果が表示されること
- サブスクリプションログイン状態に関係なく動作すること

### 優先度

高

---

## US-3: 認証方式の切り替え

**As a** ユーザー
**I want to** 設定画面で認証方式を切り替えたい
**So that** 状況に応じて最適な認証方式を選択できる

### 受入基準

- 設定画面に認証方式選択UI（セグメントコントロール）が表示されること
- 現在選択中の認証方式が明確に視覚化されていること
- 切り替え時に確認ダイアログが表示されること
- 切り替え後、選択が即座に反映されること
- アプリ再起動後も選択が維持されること

### 優先度

高

---

## US-4: 認証状態の確認

**As a** ユーザー
**I want to** 現在の認証状態をUIで確認したい
**So that** スキル実行前に認証が有効かどうかを把握できる

### 受入基準

- 設定画面で現在の認証方式が表示されること
- 認証の有効性（ログイン済み/未ログイン、APIキー設定済み/未設定）が表示されること
- トークン/キーの有効期限に関する情報が表示されること（該当する場合）
- 認証エラー時は明確なエラーメッセージが表示されること

### 優先度

高

---

## US-5: サブスクリプション未契約時のフォールバック

**As a** サブスクリプション未契約ユーザー
**I want to** 無料トライアルが終了した場合にAPIキー認証に切り替えたい
**So that** サービスを継続利用できる

### 受入基準

- サブスクリプション認証が無効になった場合、明確なエラーメッセージが表示されること
- エラーメッセージにAPIキー認証への切り替え案内が含まれること
- 設定画面への導線が提供されること
- APIキー認証への切り替えがスムーズに行えること

### 優先度

中

---

## US-6: 認証エラーからの復旧

**As a** ユーザー
**I want to** 認証エラーが発生した場合に適切なガイダンスを受けたい
**So that** 問題を迅速に解決してサービスを再開できる

### 受入基準

- サブスクリプション認証失敗時:「ログインが必要です」エラーと再ログイン導線
- APIキー認証失敗時:「APIキーを設定してください」エラーと設定画面導線
- トークン期限切れ時:「認証の更新が必要です」エラーと更新導線
- ネットワークエラー時:「接続を確認してください」エラーとリトライオプション

### 優先度

中

---

## US-7: Claude Code CLIトークンの自動検出

**As a** Claude Code CLIユーザー
**I want to** CLIで認証済みのトークンを自動検出してほしい
**So that** 追加の認証設定なしでシームレスに利用開始できる

### 受入基準

- アプリ初回起動時にClaude Code CLIの認証状態をチェックすること
- CLIでログイン済みの場合、サブスクリプション認証を自動選択すること
- CLI未認証の場合、認証方式選択を促すUIを表示すること
- 自動検出の結果をユーザーに通知すること

### 優先度

低
