## 機能要件 (FR)

| ID    | 要件                                                                   | 優先度 | 備考                                             |
| ----- | ---------------------------------------------------------------------- | ------ | ------------------------------------------------ |
| FR-1  | ユーザーは設定画面で認証方式（サブスクリプション/APIキー）を選択できる | 必須   | セグメントコントロールUI                         |
| FR-2  | 選択した認証方式はアプリ再起動後も永続化される                         | 必須   | electron-store使用                               |
| FR-3  | 認証方式に応じて適切な認証プロバイダーがスキル実行時に使用される       | 必須   | AuthModeServiceで切り替え                        |
| FR-4  | サブスクリプション認証選択時、未ログインならエラーメッセージを表示する | 必須   | 「ログインが必要です」                           |
| FR-5  | APIキー認証選択時、キー未設定ならエラーメッセージを表示する            | 必須   | 「APIキーを設定してください」                    |
| FR-6  | 現在の認証方式と認証状態をUIに表示する                                 | 必須   | 認証状態インジケーター                           |
| FR-7  | 認証方式変更時、確認ダイアログを表示する                               | 推奨   | 破壊的操作保護                                   |
| FR-8  | サブスクリプション認証時、macOS Keychainからトークンを取得する         | 必須   | keytarライブラリ使用                             |
| FR-9  | トークン取得時、ユーザーにKeychainアクセス許可を求める                 | 必須   | macOSセキュリティ要件                            |
| FR-10 | 認証エラー時、エラー種別に応じた復旧ガイダンスを表示する               | 推奨   | エラーハンドリングUX向上                         |
| FR-11 | Claude Code CLIトークンの自動検出機能                                  | 任意   | 初回起動時の自動設定                             |
| FR-12 | 認証方式ごとに独立したバリデーションロジックを実装する                 | 必須   | APIキー: `sk-ant-api03-`, OAuth: `sk-ant-oat01-` |

## 非機能要件 (NFR)

| ID     | 要件                                                    | 基準                     | カテゴリ       |
| ------ | ------------------------------------------------------- | ------------------------ | -------------- |
| NFR-1  | 認証方式切り替えは1秒以内に完了する                     | レスポンスタイム < 1s    | パフォーマンス |
| NFR-2  | トークン・APIキーは暗号化して保存する                   | safeStorage/Keychain使用 | セキュリティ   |
| NFR-3  | Renderer ProcessにAPIキー・トークンを直接公開しない     | Main Process管理         | セキュリティ   |
| NFR-4  | 認証エラーはサニタイズしてRendererに送信する            | 機密情報漏洩防止         | セキュリティ   |
| NFR-5  | 認証状態変更のログは構造化ログとして記録する            | 監査対応                 | 運用           |
| NFR-6  | Keychainアクセスは初回のみユーザー確認、以降は自動      | UX考慮                   | ユーザビリティ |
| NFR-7  | 認証UIは200-300msのアニメーションで状態遷移を表現する   | Apple HIG準拠            | デザイン       |
| NFR-8  | 認証関連のIPC通信はすべてMain Process経由で行う         | Electronセキュリティ原則 | アーキテクチャ |
| NFR-9  | 認証情報は環境変数からも取得可能（ANTHROPIC_API_KEY等） | 開発者UX                 | 互換性         |
| NFR-10 | テストカバレッジは80%以上を維持する                     | Line Coverage >= 80%     | 品質           |

## アーキテクチャ層別要件

### フロントエンド（Renderer Process）

| 要件                   | 詳細                                                 |
| ---------------------- | ---------------------------------------------------- |
| 認証方式セレクタUI     | セグメントコントロール（サブスクリプション/APIキー） |
| 認証状態インジケーター | アイコン+テキストで認証状態を表示                    |
| エラーメッセージ表示   | Toast/AlertでエラーとガイダンスをInline表示          |
| 設定画面への導線       | ナビゲーションで設定画面に遷移可能                   |

### バックエンド（Main Process）

| 要件                    | 詳細                                              |
| ----------------------- | ------------------------------------------------- |
| AuthModeService         | 認証方式の取得/設定/バリデーションを統括          |
| SubscriptionAuthService | macOS Keychain経由でClaude Code CLIトークンを取得 |
| APIKeyAuthService       | 既存AuthKeyServiceを拡張                          |
| 認証方式永続化          | electron-storeで認証方式設定を保存                |

### IPC通信

| チャンネル         | 方向            | 内容                         |
| ------------------ | --------------- | ---------------------------- |
| auth-mode:get      | Renderer → Main | 現在の認証方式を取得         |
| auth-mode:set      | Renderer → Main | 認証方式を設定               |
| auth-mode:status   | Renderer → Main | 認証状態（有効性）を取得     |
| auth-mode:validate | Renderer → Main | 指定認証方式のバリデーション |

### セキュリティ

| 要件             | 詳細                                               |
| ---------------- | -------------------------------------------------- |
| トークン暗号化   | APIキー: safeStorage, サブスクリプション: Keychain |
| Main Process管理 | 認証情報はMain Processでのみ保持                   |
| エラーサニタイズ | 内部エラーメッセージを除去してからRendererに送信   |
| ログ出力制限     | トークン/APIキーをログに出力しない                 |

### データ

| 要件               | 詳細                                      |
| ------------------ | ----------------------------------------- |
| 認証方式設定       | electron-store: `settings.authMode`       |
| APIキー            | electron-store + safeStorage: 暗号化保存  |
| サブスクリプション | macOS Keychain: `Claude Code-credentials` |

## 接続要件

| カテゴリ     | 内容                                                               |
| ------------ | ------------------------------------------------------------------ |
| API接続      | Anthropic API（APIキー認証時）、Claude API（サブスクリプション時） |
| 認証フロー   | サブスクリプション: OAuth PKCE (Keychain経由)、APIキー: 直接設定   |
| データフロー | 設定→Main Process→IPC→Renderer UI                                  |
| 外部依存     | keytar (Keychain), electron-store, safeStorage                     |

## 制約事項

| ID  | 制約                                                                  | 影響                   |
| --- | --------------------------------------------------------------------- | ---------------------- |
| C-1 | macOS Keychainアクセスには初回ユーザー確認が必要                      | 初回UXへの影響         |

| C-4 | 現バージョンはmacOSのみ対応（Windows/Linuxは別途対応）                | プラットフォーム制限   |
