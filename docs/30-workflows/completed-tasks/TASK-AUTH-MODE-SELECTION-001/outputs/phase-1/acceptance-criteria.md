## AC-1: サブスクリプション認証でのスキル実行成功

**Given（前提条件）**

- サブスクリプション認証が選択されている
- Claude Code CLIでログイン済みである
- macOS Keychainにトークンが保存されている

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- スキルが正常に実行される
- 実行結果がUIに表示される
- エラーメッセージは表示されない

**関連要件**: FR-3, US-1

---

## AC-2: サブスクリプション認証で未ログイン時のエラー

**Given（前提条件）**

- サブスクリプション認証が選択されている
- Claude Code CLIで未ログイン状態である
- macOS Keychainにトークンが保存されていない

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- 「ログインが必要です」エラーメッセージが表示される
- Claude Code CLIでのログイン方法に関するガイダンスが表示される
- スキルは実行されない

**関連要件**: FR-4, US-6

---

## AC-3: APIキー認証でのスキル実行成功

**Given（前提条件）**

- APIキー認証が選択されている
- 有効なAnthropic APIキー（`sk-ant-api03-`形式）が設定されている

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- スキルが正常に実行される
- 実行結果がUIに表示される
- エラーメッセージは表示されない

**関連要件**: FR-3, US-2

---

## AC-4: APIキー認証でキー未設定時のエラー

**Given（前提条件）**

- APIキー認証が選択されている
- APIキーが設定されていない

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- 「APIキーを設定してください」エラーメッセージが表示される
- 設定画面への導線（リンク/ボタン）が提供される
- スキルは実行されない

**関連要件**: FR-5, US-6

---

## AC-5: 認証方式の切り替えと即時反映

**Given（前提条件）**

- 設定画面を開いている
- 現在「サブスクリプション認証」が選択されている

**When（操作）**

- ユーザーが「APIキー認証」を選択する
- 確認ダイアログで「切り替え」を選択する

**Then（期待結果）**

- 認証方式が「APIキー認証」に切り替わる
- UIのセグメントコントロールが「APIキー認証」を選択状態で表示する
- 認証状態インジケーターがAPIキー認証の状態を反映する
- 切り替え完了の通知が表示される

**関連要件**: FR-1, FR-7, US-3

---

## AC-6: 認証方式の永続化

**Given（前提条件）**

- 認証方式を「APIキー認証」に切り替えた

**When（操作）**

- アプリを再起動する

**Then（期待結果）**

- 起動後、認証方式は「APIキー認証」のまま維持されている
- 設定画面のセグメントコントロールが「APIキー認証」を選択状態で表示する
- サブスクリプション認証に戻っていない

**関連要件**: FR-2, US-3

---

## AC-7: トークン期限切れ時のエラー

**Given（前提条件）**

- サブスクリプション認証が選択されている
- macOS Keychainに保存されているトークンの有効期限が切れている

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- 「認証の更新が必要です」エラーメッセージが表示される
- Claude Code CLIでの再ログイン方法に関するガイダンスが表示される
- スキルは実行されない

**関連要件**: US-6

---

## AC-8: 認証状態の表示

**Given（前提条件）**

- 設定画面を開いている

**When（操作）**

- 画面を表示する

**Then（期待結果）**

- 現在選択中の認証方式がセグメントコントロールで強調表示される
- 認証の有効性（有効/無効）がインジケーターで表示される
- サブスクリプション認証の場合:「ログイン済み」または「未ログイン」
- APIキー認証の場合:「キー設定済み」または「キー未設定」

**関連要件**: FR-6, US-4

---

## AC-9: Keychainアクセス許可

**Given（前提条件）**

- サブスクリプション認証を初めて使用する
- アプリにKeychainアクセス許可が付与されていない

**When（操作）**

- ユーザーがサブスクリプション認証を選択してスキルを実行する

**Then（期待結果）**

- macOSのKeychainアクセス許可ダイアログが表示される
- ユーザーが「許可」を選択すると、トークン取得が成功する
- ユーザーが「拒否」を選択すると、適切なエラーメッセージが表示される
- 「常に許可」を選択すると、以降は自動的にアクセスが許可される

**関連要件**: FR-9, NFR-6

---

## AC-10: 無効なAPIキーでのエラー

**Given（前提条件）**

- APIキー認証が選択されている
- 無効なAPIキー（形式不正または失効したキー）が設定されている

**When（操作）**

- ユーザーがスキルを実行する

**Then（期待結果）**

- 「APIキーが無効です」エラーメッセージが表示される
- 有効なAPIキーの形式に関するヒントが表示される
- 設定画面への導線が提供される
- スキルは実行されない

**関連要件**: FR-12, US-6

---

## AC-11: 確認ダイアログのキャンセル

**Given（前提条件）**

- 設定画面を開いている
- 現在「サブスクリプション認証」が選択されている

**When（操作）**

- ユーザーが「APIキー認証」を選択する
- 確認ダイアログで「キャンセル」を選択する

**Then（期待結果）**

- 認証方式は「サブスクリプション認証」のまま維持される
- UIの選択状態は変更されない
- 何も通知は表示されない

**関連要件**: FR-7
