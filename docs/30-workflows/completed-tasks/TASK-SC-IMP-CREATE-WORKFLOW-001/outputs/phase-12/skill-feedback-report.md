## 実装を通じて得られた知見

### 設計上の学び

1. **collaborative パターンとの一貫性**: `runCollaborativeWorkflow` が `loadAgent("hearing")` を呼ぶ構造を踏襲すると、`create` モードの意図も読み取りやすい。
2. **Null を型システムに組み込む**: `StructurePlanJson | null` は「失敗したら止める」ではなく「失敗しても後続処理を継続する」意図を型で示せる。
3. **local variable handoff の明示**: `void structurePlan` を残しても、`structurePlan` を local variable で受けることで、タスクA接続点が隠れにくくなる。

### プロセス上の学び

- UI 変更がないタスクでは、スクリーンショットの有無を `manual-test-result.md` で先に固定しておくと迷いにくい。
- `CreateSkillOptions.description` のように型上必須の値は、`undefined` を前提にしないほうが仕様と実装がぶれない。
- Phase 12 は「接続点を作った」と「最終生成まで終えた」を分けて書くと、依存関係の誤読を防ぎやすい。
