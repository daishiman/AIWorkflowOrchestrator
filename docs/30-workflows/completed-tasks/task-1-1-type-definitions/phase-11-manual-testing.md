## 3. 実行タスク

### Task 11-1: インポート体験テスト

**目的**: 開発者が型をインポートする際の体験を確認

**手順**:

1. VSCode で apps/desktop のファイルを開く
2. 型をインポートするコードを記述
3. 自動補完が正しく機能することを確認
4. インポート文が正しく生成されることを確認

**確認項目**:

- [ ] `import type { SkillMetadata } from "@repo/shared"` が自動補完される
- [ ] 全ての新規型が補完候補に表示される
- [ ] インポートパスが正しい

### Task 11-2: 型推論テスト

**目的**: IDE での型推論が正しく機能することを確認

**手順**:

1. VSCode で型を使用するコードを記述
2. 変数にホバーして型情報を確認
3. Discriminated Union の型絞り込みを確認

**確認項目**:

- [ ] 変数の型が正しく推論される
- [ ] プロパティアクセス時に適切な補完が表示される
- [ ] switch 文での型絞り込みが機能する

**テストコード例**:

```typescript
import type { SkillStreamMessage } from "@repo/shared";

function handleMessage(message: SkillStreamMessage) {
  switch (message.type) {
    case "assistant":
      // message.content が AssistantMessageContent に絞り込まれることを確認
      console.log(message.content.text);
      break;
    case "tool_use":
      // message.content が ToolUseMessageContent に絞り込まれることを確認
      console.log(message.content.toolName);
      break;
  }
}
```

### Task 11-3: JSDoc 表示テスト

**目的**: JSDoc コメントがホバー時に正しく表示されることを確認

**手順**:

1. VSCode で型名にホバー
2. JSDoc コメントが表示されることを確認
3. プロパティにホバーしてコメントを確認

**確認項目**:

- [ ] interface 名ホバーで説明が表示される
- [ ] プロパティホバーで説明が表示される
- [ ] @see タグが適切にリンクされる（可能な場合）

### Task 11-4: エラーメッセージテスト

**目的**: 型エラー時のメッセージが分かりやすいことを確認

**手順**:

1. 意図的に型エラーを発生させるコードを記述
2. エラーメッセージを確認
3. エラーの原因が特定しやすいことを確認

**確認項目**:

- [ ] 必須プロパティ欠落時のエラーが明確
- [ ] 型不一致時のエラーが明確
- [ ] Discriminated Union での型不一致エラーが明確
