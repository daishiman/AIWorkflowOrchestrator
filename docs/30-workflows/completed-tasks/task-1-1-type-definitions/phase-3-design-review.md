## 3. 実行タスク

### Task 3-1: 要件レビュー

**手順**:

1. phase-1-requirements.md を開く
2. 各チェック項目を確認
3. 判定結果を記録

**チェックリスト**:

- [ ] REQ-01: 全型が要件として定義されているか確認
- [ ] REQ-02: 受け入れ基準の具体性を確認
- [ ] REQ-03: 制約事項の明確さを確認
- [ ] REQ-04: 既存型との関係を確認

### Task 3-2: 設計レビュー

**手順**:

1. phase-2-design.md を開く
2. specification.md §5.1 と照合
3. 各チェック項目を確認
4. 判定結果を記録

**チェックリスト**:

- [ ] DES-01: 型定義の一致を確認
- [ ] DES-02: 既存型との共存方針を確認
- [ ] DES-03: Discriminated Union の判別子を確認
- [ ] DES-04: JSDoc 方針を確認
- [ ] DES-05: エクスポート方針を確認

### Task 3-3: 整合性レビュー

**手順**:

1. 既存の型定義ファイルを確認
2. aiworkflow-requirements の関連仕様を確認
3. 整合性を検証

**チェックリスト**:

- [ ] CON-01: 型名の命名規則確認
- [ ] CON-02: プロパティ名の一貫性確認
- [ ] CON-03: agent-execution.ts との整合性確認
- [ ] CON-04: aiworkflow-requirements との整合性確認

### Task 3-4: レビュー結果まとめ

**手順**:

1. 全チェック項目の判定結果を集計
2. 問題点があれば Phase 2 に差し戻し
3. 問題なければ Phase 4 に進む

## 4. ゲート判定基準

### 4.1 合格基準

| 条件                        | 必須 |
| --------------------------- | ---- |
| 要件レビュー: 全項目 PASS   | ○    |
| 設計レビュー: 全項目 PASS   | ○    |
| 整合性レビュー: 全項目 PASS | ○    |
| 重大な懸念事項がない        | ○    |

### 4.2 不合格時のアクション

| 問題の種類       | アクション                          |
| ---------------- | ----------------------------------- |
| 要件の不備       | Phase 1 へ差し戻し、要件を修正      |
| 設計の不備       | Phase 2 へ差し戻し、設計を修正      |
| 整合性の問題     | Phase 2 へ差し戻し、設計を調整      |
| 仕様書との不一致 | specification.md を確認、設計を修正 |
