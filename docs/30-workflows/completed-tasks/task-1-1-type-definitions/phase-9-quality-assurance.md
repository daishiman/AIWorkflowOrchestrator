## 1. 目的

型定義の品質を多角的に検証し、本番環境での使用に耐えうる品質を確保する。

---

## 2. 品質保証項目

### 2.1 型定義タスクの品質保証

型定義は実行時コードではないため、以下に焦点を当てる：

| カテゴリ         | 検証内容                         |
| ---------------- | -------------------------------- |
| 静的解析         | TypeScript strict モード、ESLint |
| 型安全性         | 型の厳密性、any 型の排除         |
| ドキュメント品質 | JSDoc カバレッジ、説明の正確性   |
| 互換性           | 他パッケージとの互換性           |

---

## 3. 実行タスク

### Task 9-1: 静的解析

**目的**: TypeScript と ESLint による静的解析を実行

**コマンド**:

```bash
# TypeScript strict モードチェック
pnpm --filter @repo/shared tsc --noEmit --strict

# ESLint チェック
pnpm --filter @repo/shared lint

# Prettier フォーマットチェック
pnpm --filter @repo/shared format:check
```

**確認項目**:

- [ ] TypeScript strict モードでエラーなし
- [ ] ESLint エラーなし
- [ ] Prettier フォーマットエラーなし

### Task 9-2: 型安全性検証

**目的**: 型定義が厳密で安全であることを確認

**確認項目**:

- [ ] `any` 型が使用されていない（`unknown` を使用）
- [ ] `as` キャスト が使用されていない
- [ ] `// @ts-ignore` がない
- [ ] 全プロパティに適切な型が指定されている

**検証コマンド**:

```bash
# any 型の検索
grep -n "any" packages/shared/src/types/skill.ts | grep -v "Record<string, unknown>"

# @ts-ignore の検索
grep -n "@ts-ignore" packages/shared/src/types/skill.ts
```

### Task 9-3: ドキュメント品質検証

**目的**: JSDoc コメントが適切に付与されていることを確認

**確認項目**:

- [ ] 全 interface に JSDoc がある
- [ ] 全 type に JSDoc がある
- [ ] 全プロパティにコメントがある
- [ ] コメントが仕様書と一致している

**検証方法**:

```bash
# JSDoc のない export を検索
grep -n "^export " packages/shared/src/types/skill.ts | grep -v "@"
```

### Task 9-4: 互換性検証

**目的**: 他パッケージとの互換性を確認

**コマンド**:

```bash
# shared パッケージのビルド
pnpm --filter @repo/shared build

# desktop パッケージの型チェック
pnpm --filter @repo/desktop typecheck

# web パッケージの型チェック
pnpm --filter @repo/web typecheck
```

**確認項目**:

- [ ] shared パッケージがビルド可能
- [ ] desktop パッケージで型エラーなし
- [ ] web パッケージで型エラーなし

### Task 9-5: セキュリティ考慮

**目的**: 型定義にセキュリティ上の問題がないことを確認

**確認項目**:

- [ ] 機密情報を示唆する型名がない
- [ ] パスワード・トークンなどの型が平文で定義されていない
- [ ] 型定義が攻撃ベクトルにならない

**注記**: 型定義自体はセキュリティリスクが低いが、設計上の考慮は必要
