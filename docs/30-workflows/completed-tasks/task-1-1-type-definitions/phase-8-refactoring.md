## 1. 目的

テストが通る状態を維持しながら、型定義の品質を改善する。コードの可読性、一貫性、保守性を向上させる。

---

## 2. リファクタリング方針

### 2.1 型定義タスクでのリファクタリング

型定義は実行時コードではないため、以下に焦点を当てる：

| 項目                 | 内容                         |
| -------------------- | ---------------------------- |
| JSDoc コメントの充実 | 全プロパティに説明を追加     |
| 型の整理             | 関連する型のグループ化       |
| 命名の一貫性         | 命名規則の統一               |
| 重複の排除           | 共通部分の抽出（必要な場合） |

### 2.2 リファクタリングしないこと

- 機能の追加・変更
- 既存型の削除
- 破壊的変更

---

## 3. 実行タスク

### Task 8-1: JSDoc コメントの見直し

**目的**: 全ての型・プロパティに適切な JSDoc コメントを付与

**確認項目**:

- [ ] 全 interface に JSDoc コメントがある
- [ ] 全 type に JSDoc コメントがある
- [ ] 全プロパティに `/** 説明 */` がある
- [ ] 説明が仕様書と一致している

**例**:

```typescript
/**
 * スキルメタデータ（SKILL.md frontmatter）
 * 配下の全情報を含む
 *
 * @see specification.md §5.1
 */
export interface SkillMetadata {
  /** スキル識別子（ディレクトリ名と一致） */
  name: string;
  // ...
}
```

### Task 8-2: 型のグループ化確認

**目的**: 関連する型が適切にグループ化されていることを確認

**確認項目**:

- [ ] セクションコメントで区切られている
- [ ] 依存関係の順序が適切（依存される型が先）
- [ ] 関連する型が近くに配置されている

**構成**:

```typescript
// ========================================
// Section 1: 既存型（維持）
// ========================================

// ========================================
// Section 2: スキルメタデータ（§5.1）
// ========================================

// ========================================
// Section 3: 実行関連（§5.1）
// ========================================

// ========================================
// Section 4: ストリーミングメッセージ（§5.1）
// ========================================

// ========================================
// Section 5: 権限確認（§5.1）
// ========================================
```

### Task 8-3: 命名の一貫性確認

**目的**: 型名・プロパティ名が一貫した命名規則に従っていることを確認

**命名規則**:
| 対象 | 規則 | 例 |
| -------------- | -------------------------------------- | -------------------------- |
| interface 名 | PascalCase | `SkillMetadata` |
| type 名 | PascalCase | `SkillExecutionStatus` |
| プロパティ名 | camelCase | `executionId` |
| リテラル型 | snake_case または kebab-case（文字列） | `"permission_pending"` |

**確認項目**:

- [ ] 全 interface 名が PascalCase
- [ ] 全 type 名が PascalCase
- [ ] 全プロパティ名が camelCase
- [ ] リテラル型の値が一貫している

### Task 8-4: 重複の確認と整理

**目的**: 重複した定義がないことを確認し、必要に応じて共通化

**確認項目**:

- [ ] 同じ構造の型が重複していない
- [ ] 共通のベース型が適切に使用されている
- [ ] 不必要なユニオン型がない

**注意**: 後方互換性を維持するため、既存型との統合は行わない

### Task 8-5: インポート・エクスポートの整理

**目的**: エクスポートが整理されていることを確認

**確認項目**:

- [ ] 不要なエクスポートがない
- [ ] エクスポート順序が論理的
- [ ] 循環参照がない

```bash

# フォーマット

```
