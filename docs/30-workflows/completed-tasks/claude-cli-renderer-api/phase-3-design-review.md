## 目的

Phase 1-2で定義した要件・設計の妥当性を検証し、実装フェーズに進む判断を行う。

## 背景

設計レビューゲートは品質パイプラインの重要なチェックポイント。問題があれば早期に発見し、手戻りを防ぐ。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件レビュー

**目的**: Phase 1で定義した要件の妥当性を検証する

**実行手順**:

1. `outputs/phase-1/requirements.md`を読み、以下を確認する:
   - 機能要件が明確か
   - 非機能要件が適切か
   - IPC接続要件が明記されているか
2. レビュー結果を記録する

**期待される成果物**:

- 要件レビュー結果

---

### タスク2: 設計レビュー

**目的**: Phase 2で作成した設計の妥当性を検証する

**実行手順**:

1. `outputs/phase-2/api-design.md`を読み、以下を確認する:
   - APIシグネチャが適切か
   - 戻り値の型が一貫しているか（`ClaudeCliResult<T>`パターン）
2. `outputs/phase-2/ipc-design.md`を読み、以下を確認する:
   - チャンネル名が一貫しているか
   - ホワイトリスト登録が完全か
3. `outputs/phase-2/security-design.md`を読み、以下を確認する:
   - `safeInvoke`/`safeOn`パターンが適用されているか
   - `contextBridge`による安全な公開が行われているか
4. レビュー結果を記録する

**期待される成果物**:

- 設計レビュー結果

---

### タスク3: 既存実装との整合性確認

**目的**: 既存実装が要件・設計と整合しているか確認する

**実行手順**:

1. `apps/desktop/src/preload/index.ts`の`claudeCliAPI`実装を確認する
2. Phase 2の設計と比較し、以下を確認する:
   - 全APIメソッドが実装されているか
   - 型定義が一致しているか
   - セキュリティパターンが適用されているか
3. 整合性確認結果を記録する

**期待される成果物**:

- 整合性確認結果

---

### タスク4: レビュー判定

**目的**: 設計レビューの最終判定を行う

**実行手順**:

1. タスク1-3の結果を総合し、以下の判定基準で評価する:
   - **PASS**: 全レビュー観点で問題なし → Phase 4へ進行
   - **MINOR**: 軽微な指摘あり → 指摘対応後、Phase 4へ進行
   - **MAJOR**: 重大な問題あり → 問題に応じて戻り先を決定
   - **CRITICAL**: 致命的な問題あり → Phase 1へ戻りユーザー確認
2. 判定結果を`outputs/phase-3/review-result.md`に出力する

**期待される成果物**:

- `outputs/phase-3/review-result.md`（レビュー結果報告書）

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
