## 目的

テストがパスしている状態を維持しながら、コードの品質を改善する。TDDのRefactor段階として、可読性・保守性を向上させる。

## 背景

既存実装の品質を確認し、必要に応じてリファクタリングを行う。テストが全パスする状態を維持することが必須。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード品質分析

**目的**: 既存コードの品質を分析する

**実行手順**:

1. `apps/desktop/src/preload/index.ts`の`claudeCliAPI`部分を分析する
2. 以下の観点で評価する:
   - 可読性: コードが理解しやすいか
   - 保守性: 変更が容易か
   - 一貫性: 他のAPI（`agentAPI`、`slideApi`等）と一貫しているか
   - DRY原則: 重複がないか
3. 改善点をリストアップする

**期待される成果物**:

- コード品質分析結果

---

### タスク2: 命名規則の確認

**目的**: 命名規則が一貫しているか確認する

**実行手順**:

1. 以下の命名を確認する:
   - API名: `claudeCliAPI`（他と一貫: `agentAPI`, `slideApi`）
   - メソッド名: `checkInstallation`, `listSkills`等
   - 型名: `ClaudeCliAPI`, `ClaudeCliListSkillsRequest`等
   - チャンネル名: `CLAUDE_CLI_CHECK_INSTALLATION`等
2. 不一貫な箇所があれば修正する

**期待される成果物**:

- 命名規則確認結果

---

### タスク3: 型定義の整理

**目的**: 型定義を整理し、重複を削除する

**実行手順**:

1. `apps/desktop/src/preload/types.ts`のClaude CLI関連型を確認する
2. `packages/shared/src/claude-cli/types.ts`との重複を確認する
3. 重複がある場合は、共通型を`@repo/shared`に統一する
4. 必要に応じてimportパスを整理する

**期待される成果物**:

- 整理済み型定義

---

### タスク4: エラーハンドリングの改善

**目的**: エラーハンドリングを一貫させる

**実行手順**:

1. `safeInvoke`と`safeOn`のエラーハンドリングを確認する
2. エラーメッセージが適切か確認する
3. エラー伝播パターンが一貫しているか確認する
4. 必要に応じて改善する

**期待される成果物**:

- エラーハンドリング改善結果

---

### タスク5: リファクタリング後のテスト確認

**目的**: リファクタリング後もテストがパスすることを確認する

**実行手順**:

1. テストを実行する: `pnpm --filter @repo/desktop test`
2. 全テストがパスすることを確認する
3. 型チェックを実行する: `pnpm --filter @repo/desktop typecheck`
4. 型チェックがパスすることを確認する

**期待される成果物**:

- テスト・型チェック通過確認
