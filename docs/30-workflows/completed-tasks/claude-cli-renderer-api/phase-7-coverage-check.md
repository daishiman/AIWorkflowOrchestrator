## 目的

テストカバレッジが目標値を達成しているか確認し、未達の場合はPhase 6に戻って追加テストを作成する。

## 背景

カバレッジ目標を達成することで、実装の品質を担保する。目標未達の場合は、追加テストが必要。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: カバレッジ計測

**目的**: 最終的なテストカバレッジを計測する

**実行手順**:

1. カバレッジ付きでテストを実行する:
   ```bash
   pnpm --filter @repo/desktop test --coverage
   ```
2. カバレッジレポートを確認する
3. `apps/desktop/src/preload/`ディレクトリのカバレッジを抽出する

**期待される成果物**:

- カバレッジレポート

---

### タスク2: カバレッジ目標との比較

**目的**: カバレッジが目標値を達成しているか判定する

**実行手順**:

1. 以下の目標値と比較する:

   **ユニットテストカバレッジ目標**:
   | 指標 | 最低基準 | 推奨基準 |
   | ----------------- | -------- | -------- |
   | Line Coverage | 80% | 90% |
   | Branch Coverage | 60% | 70% |
   | Function Coverage | 80% | 90% |

2. 目標達成状況を記録する

**期待される成果物**:

- 目標達成状況レポート

---

### タスク3: 未カバー箇所の特定

**目的**: カバレッジが不足している箇所を特定する

**実行手順**:

1. カバレッジレポートで未カバーの行/分岐を特定する
2. 以下のファイルの未カバー箇所をリストアップする:
   - `apps/desktop/src/preload/index.ts`（claudeCliAPI部分）
   - `apps/desktop/src/preload/channels.ts`
   - `apps/desktop/src/preload/types.ts`
3. 各未カバー箇所の理由を分析する:
   - テスト追加が必要か
   - テスト不可能な箇所か（例: エラーハンドリングのcatch句）

**期待される成果物**:

- 未カバー箇所リスト

---

### タスク4: カバレッジゲート判定

**目的**: カバレッジ目標の達成/未達を判定する

**実行手順**:

1. 以下の判定基準で評価する:
   - **PASS**: 全指標が最低基準以上 → Phase 8へ進行
   - **FAIL**: いずれかの指標が最低基準未満 → Phase 6に戻る
2. 判定結果を`outputs/phase-7/coverage-report.md`に出力する

**期待される成果物**:

- `outputs/phase-7/coverage-report.md`（カバレッジ判定レポート）
