## 概要

EP-3（利用前評価）と EP-4（利用後再評価）の呼び分けテストを定義する。既存の `skill:optimize:evaluate` チャネルを再利用し、新規 IPC チャネルを作成しない設計を検証する。P42（3段バリデーション）・P44（インターフェース不整合）・P45（引数命名セマンティクス）への準拠を確認する。

## TC-IPC-01: EP-3 呼び出し設計確認（Workspace スキル選択時）

| 項目               | 内容                                            |
| ------------------ | ----------------------------------------------- |
| テストケース ID    | TC-IPC-01                                       |
| テスト種別         | 設計検証テスト（IPC）                           |
| 対象 IPC           | `skill:optimize:evaluate`（既存チャネル再利用） |
| 呼び出しタイミング | Workspace でスキル選択後の EP-3 利用前評価      |

### 検証項目

| #   | チェック項目       | 期待設計                                                      | Pitfall 関連 |
| --- | ------------------ | ------------------------------------------------------------- | ------------ |
| 1   | チャネル名         | `skill:optimize:evaluate`（既存再利用、新規なし）             | -            |
| 2   | 引数型             | `SkillOptimizeEvaluateRequest { prompt: string }`             | P44 準拠     |
| 3   | 戻り値型           | `PromptEvaluation { score, breakdown?, feedback[] }`          | P44 準拠     |
| 4   | 引数バリデーション | 型チェック → 空文字列チェック → trim 空文字列チェック         | P42 準拠     |
| 5   | 引数名             | `prompt`（実際にプロンプト文字列を渡す — セマンティクス一致） | P45 準拠     |
| 6   | EP-3 コンテキスト  | 呼び出し元が Workspace であることを識別する設計               | -            |

### P42 3段バリデーション設計

```typescript
// 期待設計パターン
// Step 1: 型チェック
if (typeof args?.prompt !== "string") {
  throw VALIDATION_ERROR;
}
// Step 2: 空文字列チェック
if (args.prompt === "") {
  throw VALIDATION_ERROR;
}
// Step 3: trim 空文字列チェック
if (args.prompt.trim() === "") {
  throw VALIDATION_ERROR;
}
```

### 合否基準

EP-3 呼び出しの引数型・バリデーション設計が Phase 2 ipc-integration-design.md に定義されていれば PASS。

## TC-IPC-02: EP-4 呼び出し設計確認（Agent 実行結果後）

| 項目               | 内容                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| テストケース ID    | TC-IPC-02                                                                       |
| テスト種別         | 設計検証テスト（IPC）                                                           |
| 対象 IPC           | `skill:optimize:evaluate`（既存チャネル再利用）                                 |
| 呼び出しタイミング | Agent 実行完了後の PostExecutionActionBar「改善する」CTA クリック時（任意実行） |

### 検証項目

| #   | チェック項目    | 期待設計                                                             | Pitfall 関連 |
| --- | --------------- | -------------------------------------------------------------------- | ------------ |
| 1   | チャネル名      | `skill:optimize:evaluate`（EP-3 と同一チャネル）                     | -            |
| 2   | 引数型          | `SkillOptimizeEvaluateRequest { prompt: string }`                    | P44 準拠     |
| 3   | 戻り値型        | `PromptEvaluation { score, breakdown?, feedback[] }`                 | P44 準拠     |
| 4   | EP-3 との区別   | 呼び出しコンテキスト（利用前 vs 利用後）を設計書で区別               | -            |
| 5   | ScoreDelta 計算 | `postExecutionScore - preExecutionScore` を Renderer 側で計算        | -            |
| 6   | EP-4 は任意実行 | ユーザーが「改善する」CTA をクリックした場合のみ実行、自動実行しない | -            |

### EP-3/EP-4 呼び分け設計

| 評価ポイント | 呼び出し元 | トリガー        | 実行タイミング       | ブロック挙動                           |
| ------------ | ---------- | --------------- | -------------------- | -------------------------------------- |
| EP-3         | Workspace  | スキル選択      | 自動（スキル選択後） | 利用をブロックしない（バナー表示のみ） |
| EP-4         | Agent      | 「改善する」CTA | 任意（ユーザー操作） | 利用をブロックしない                   |

### 合否基準

EP-3 と EP-4 の呼び分けが設計書に明示されていれば PASS。

## TC-IPC-03: お気に入り管理の IPC 不要確認

| 項目            | 内容                                                                |
| --------------- | ------------------------------------------------------------------- |
| テストケース ID | TC-IPC-03                                                           |
| テスト種別      | 設計検証テスト（IPC）                                               |
| 検証対象        | お気に入り（favorite）管理に新規 IPC チャネルが不要であることの確認 |

### 検証項目

| #   | チェック項目 | 期待設計                                                              |
| --- | ------------ | --------------------------------------------------------------------- |
| 1   | 管理方式     | Zustand persist で Renderer 側のみで管理                              |
| 2   | 永続化       | customStorage 経由で localStorage に保存                              |
| 3   | データ型     | `Set<string>`（スキル名の集合）                                       |
| 4   | 新規 IPC     | なし（`skill:favorite:toggle` のような新規チャネルは作成しない）      |
| 5   | 理由         | お気に入りは UI 状態であり、Main Process のファイルシステム操作が不要 |

### 合否基準

IPC 不要の理由と代替手段（Zustand persist）が設計書に記載されていれば PASS。

## TC-IPC-04: P44/P45 引数命名セマンティクス確認

| 項目            | 内容                                                 |
| --------------- | ---------------------------------------------------- |
| テストケース ID | TC-IPC-04                                            |
| テスト種別      | 設計検証テスト（IPC）                                |
| 検証対象        | IPC 引数名が実際の値のセマンティクスと一致しているか |

### 検証項目

| #   | IPC チャネル              | 引数名           | 実際の値                 | セマンティクス一致 |
| --- | ------------------------- | ---------------- | ------------------------ | ------------------ |
| 1   | `skill:optimize:evaluate` | `prompt`         | スキルのプロンプト文字列 | 一致               |
| 2   | `skill:list`              | なし（引数不要） | -                        | 一致               |

### P44 チェックリスト（インターフェース不整合防止）

| #   | チェック項目                              | 状態     |
| --- | ----------------------------------------- | -------- |
| 1   | ハンドラ引数型と Preload 呼び出し型が一致 | 検証対象 |
| 2   | 引数名のセマンティクスが実際の値と一致    | 検証対象 |
| 3   | 新規 IPC チャネルが不要であることの確認   | 検証対象 |

### P45 チェックリスト（引数命名契約ドリフト防止）

| #   | チェック項目                                | 状態     |
| --- | ------------------------------------------- | -------- |
| 1   | `skillName` と `skillId` の混同がないこと   | 検証対象 |
| 2   | `prompt` が実際にプロンプト文字列であること | 検証対象 |

### 合否基準

全 IPC 引数名がセマンティクスに一致していれば PASS。

## IPC 設計原則コンプライアンス

| 原則                     | 内容                           | 本設計での適合                                |
| ------------------------ | ------------------------------ | --------------------------------------------- |
| 既存チャネル再利用       | 新規 IPC チャネルを作成しない  | `skill:optimize:evaluate` + `skill:list` のみ |
| P42 3段バリデーション    | 型 → 空文字列 → trim の3段検証 | EP-3/EP-4 両方に適用                          |
| P44 インターフェース整合 | ハンドラ ↔ Preload の型一致    | 既存チャネルのため整合済み                    |
| P45 命名セマンティクス   | 引数名と値の意味一致           | prompt → プロンプト文字列（一致）             |
