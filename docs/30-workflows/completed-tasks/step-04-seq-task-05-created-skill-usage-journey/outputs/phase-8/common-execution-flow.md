## 共通フロー定義

3シナリオ（A: 作成直後 / B: あとから / C: 履歴から）は、Agent 到達後の「実行 → 結果確認 → 次アクション選択」部分が完全に共通している。この共通部分を「共通: Agent 実行フロー」として抽出・定義する。

### 共通: Agent 実行フロー（ASCII図）

```
[共通: Agent 実行フロー]
    |
    v
Agent で実行開始
    |
    v
実行完了 → ExecutionResultSummary 表示
    |
    +--- ScoreDisplay (compact) + ScoreDelta 表示（EP-4 任意）
    |
    +--- PostExecutionActionBar
         |
         +--- もう一度使う
         |    → Agent 再実行（共通フロー先頭に戻る）
         |
         +--- 改善する
         |    → SkillAnalysisView (Task03 改善フロー)
         |    → コンテキスト: skillName + 最新 SkillAnalysis + 実行結果
         |
         +--- 完了
         |    → 履歴に記録（recentlyUsedSkills 更新）
         |    → 画面遷移なし
         |
         +--- terminal で続ける
              → Terminal Dock
              → コンテキスト: prompt bundle + context summary
```

### 共通フローの構成要素

| 構成要素         | コンポーネント           | 表示内容                                |
| ---------------- | ------------------------ | --------------------------------------- |
| 実行結果サマリー | `ExecutionResultSummary` | ステータス / 実行時間 / 結果プレビュー  |
| 品質スコア       | `ScoreDisplay` (compact) | 総合スコア数値                          |
| スコア変化       | `ScoreDelta`             | 前回スコアとの差分（`EP-4` 実行時のみ） |
| 品質バナー       | `ScoringGateBanner`      | ゲート判定に基づく改善推奨メッセージ    |
| アクションバー   | `PostExecutionActionBar` | 4つのアクションボタン                   |

## 各シナリオの固有部分テーブル

| シナリオ    | 開始地点            | 固有フロー（開始〜Agent 到達まで）                                                         | 合流点                      |
| ----------- | ------------------- | ------------------------------------------------------------------------------------------ | --------------------------- |
| A: 作成直後 | `EP-1` 採点完了画面 | `EP-1` 完了 → CTA（`ScoringGate` 別分岐） → Workspace（文脈準備 + スキル自動選択） → Agent | [共通: Agent 実行フロー] へ |
| B: あとから | Skill Center        | Skill Center → `SkillCard` クリック → `SkillDetailPanel` → 「使う」CTA → Workspace → Agent | [共通: Agent 実行フロー] へ |
| C: 履歴から | Agent 履歴タブ      | Agent 履歴タブ → 履歴エントリ選択 → パラメータ確認/変更 → Agent                            | [共通: Agent 実行フロー] へ |

### シナリオ別の固有条件

| シナリオ | 前提条件                                | 固有の品質表示                           | 固有の状態更新              |
| -------- | --------------------------------------- | ---------------------------------------- | --------------------------- |
| A        | `ScoringGate` が `USE_ALLOWED` 以上     | `EP-1` 採点結果を引き継ぎ                | なし（新規作成直後）        |
| B        | スキルが保存済み（`SAVE_ALLOWED` 以上） | `ScoreGateBadge` を `SkillCard` に表示   | `recentlyUsedSkills` を更新 |
| C        | 過去に1回以上実行した記録が存在         | 実行時スコア + 現在スコアの `ScoreDelta` | 前回パラメータの復元        |

## 簡素化効果

| 指標                                    | 簡素化前                                   | 簡素化後                                 | 削減          |
| --------------------------------------- | ------------------------------------------ | ---------------------------------------- | ------------- |
| フロー図記載行数（3シナリオ合計）       | 約45行（各シナリオに末尾フロー15行）       | 約27行（共通フロー15行 + 固有部分各4行） | 約40%削減     |
| メンテナンス箇所（末尾フロー変更時）    | 3箇所（各シナリオのフロー図）              | 1箇所（共通フロー定義のみ）              | 3箇所 → 1箇所 |
| `PostExecutionActionBar` の仕様記載箇所 | 3箇所（各シナリオ末尾）                    | 1箇所（共通フロー内）                    | 3箇所 → 1箇所 |
| テスト設計のフロー参照箇所              | 3箇所（TC-FLOW-A04〜A05 / B05 / C02〜C05） | 1箇所（共通フロー参照）                  | 参照の一元化  |

### 簡素化による品質向上

- **一貫性**: 3シナリオの末尾フローが同一定義を参照するため、仕様ドリフトが発生しない
- **保守性**: `PostExecutionActionBar` にアクション追加・変更があった場合、共通フロー定義1箇所の修正で全シナリオに反映される
- **テスト効率**: 共通フロー部分のテストケースを1セットで定義し、各シナリオのテストは固有部分のみに集中できる
- **レビュー効率**: Phase 10 最終レビューで末尾フローの整合性確認が1箇所で完了する
