### REQ-04: Workspace → Agent 二段構成

| 項目         | 内容                                                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phase 1 要件 | Workspace を「実行準備」、Agent を「実行本体」とする二段構成。推奨経路は Workspace 経由、省略経路は Agent 直接、履歴経路は Agent 直接                                                                                |
| Phase 2 設計 | screen-transition-design.md セクション1.2: 推奨経路/省略経路/履歴経路/改善経路の4経路を定義。セクション8: 推奨経路 vs 省略経路の選択基準、経路選択 UI（ドロップダウンメニュー）、Workspace 自動設定                  |
| 突合結果     | **適合**                                                                                                                                                                                                             |
| 根拠         | Task01 の画面責務（Workspace=文脈準備/Primary、Agent=実行本体/Primary）を厳守。Workspace は最終実行判断をせず「Agent で実行」ラベルで Agent に委譲する設計。ドロップダウン UI で推奨経路をデフォルトにする設計も明確 |

## 3. 指摘事項

### MINOR-01: 発見導線のソート/フィルタ UI 設計不足（REQ-05）

| 項目     | 内容                                                                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 重要度   | MINOR                                                                                                                                                                                                                   |
| 対象要件 | REQ-05（発見導線5種）                                                                                                                                                                                                   |
| 内容     | Phase 1 で定義されたソート基準6種（最終更新日/スコア順/関連度/スコアx利用頻度/最終使用日時/お気に入り登録日）とフィルタ条件4種（ScoringGate/カテゴリ/タグ/ステータス）のインタラクション UI 設計が Phase 2 に存在しない |
| 影響     | コンポーネント（RecommendedSkillSection/RecentlyUsedSection/SavedSkillList）は設計済みのため、ソート/フィルタ UI は実装時に既存 SkillCenterView のパターンを踏襲して追加可能。設計の根幹には影響しない                  |
| 対処方針 | Phase 4 以降で実装時に補完。または後続未タスクとして切り出し                                                                                                                                                            |
