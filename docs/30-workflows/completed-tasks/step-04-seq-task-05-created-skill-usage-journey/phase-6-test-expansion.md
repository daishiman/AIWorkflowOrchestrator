# Phase 6: テスト拡充

## メタ情報

| 項目  | 内容                                                                                         |
| ----- | -------------------------------------------------------------------------------------------- |
| Phase | 6                                                                                            |
| 名称  | テスト拡充                                                                                   |
| 目的  | Phase 4 で定義した設計テストを失敗系・境界値・回帰観点まで拡張し、運用時の取りこぼしをなくす |
| 入力  | Phase 4 テスト設計、Phase 5 outputs 一式、Phase 3/10 の指摘一覧                              |
| 出力  | 追加テスト設計、失敗系ハンドリング検証表、回帰ガード一覧                                     |
| 依存  | Phase 4, Phase 5                                                                             |

## 目的

作成済みスキル利用導線（作成直後 / あとから / 履歴）で起こりやすい失敗パターンを先回りして検証し、
Phase 7 で未カバー判定が出ない状態を作る。

## 実行タスク

- タスク1: 失敗系・境界値ケースを追加し、既存ケースでは見えない不具合を検出できる状態にする
- タスク2: 再利用導線（お気に入り/履歴/検索）の状態遷移ケースを追加し、導線の回帰を防止する
- タスク3: ScoringGate 境界値と CTA 制御の組み合わせを追加し、品質ゲート判定の揺れを防止する
- タスク4: IPC 失敗時のフォールバックと復旧手順を追加し、利用不能状態の長期化を防止する
- タスク5: 追加ケースを test plan と outputs に反映し、Phase 7 カバレッジ照合の入力を確定する

## 実行手順

### ステップ1: 失敗系ケースの拡張（タスク1）

1. Phase 4 の `TC-IPC-*` を起点に、`timeout / validation error / permission denied` を追加する
2. 失敗時に利用者が次に取る行動（再試行 / 改善に戻る / 別導線へ移動）を期待結果に明記する
3. 失敗ケースIDを `TC-FAIL-*` で採番する

### ステップ2: 再利用導線ケースの拡張（タスク2）

1. お気に入り・履歴・検索の各入口で `0件 / 1件 / 複数件` の3パターンを定義する
2. 各パターンで「利用開始までのクリック数」「戻り操作」「状態保持」を検証項目に含める
3. 追加ケースIDを `TC-REUSE-*` として管理する

### ステップ3: ScoringGate 境界値ケース追加（タスク3）

1. `NEEDS_IMPROVEMENT / SAVE_ALLOWED / USE_ALLOWED / RECOMMENDED` の境界点を洗い出す
2. 境界点ごとに CTA の可否・文言・補助説明の期待値を固定する
3. 追加ケースIDを `TC-GATE-BORDER-*` として記録する

### ステップ4: フォールバック復旧ケース追加（タスク4）

1. EP-3 / EP-4 呼び出し失敗時に表示すべき復旧導線を定義する
2. 「直前状態へ戻せるか」「再実行時に二重送信しないか」をチェック項目に追加する
3. 追加ケースIDを `TC-RECOVERY-*` として記録する

### ステップ5: テスト台帳同期（タスク5）

1. 追加ケースを `outputs/phase-6/test-expansion-plan.md` に転記する
2. Phase 7 用 coverage matrix の入力列（要件ID、ケースID、期待結果）を確定する
3. Phase 10/12 で未タスク化が必要な gap 候補をメモする
