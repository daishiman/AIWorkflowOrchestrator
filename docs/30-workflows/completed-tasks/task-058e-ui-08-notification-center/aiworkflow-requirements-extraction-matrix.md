## 目的

`aiworkflow-requirements` に従い、今回の 058e 仕様作成で何をどの検索語から抽出したかを固定する。`1概念1クエリ` の再調査結果と、0件だった概念の補完判断も含めて残す。

## 0件または弱ヒットだった概念の扱い

| 概念            | 検索結果                 | 判断                                                                                                                              |
| --------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `mark all read` | 直接ヒットが弱い         | `notification:mark-all-read` を `api-ipc-system.md` の channel 正本として採用し、UI 文言と操作位置は `task-058e` 原本を正本にした |
| `relative time` | 0件                      | system spec 側に直接規定がないため、表示契約は `task-058e` 原本を優先し、a11y と theme 要件のみ system spec 側から補強した        |
| `swipe`         | 通知 UI 直結の正本が弱い | gesture 自体は 058e task 原本を正本にし、Portal / a11y / quality だけ system spec から補強した                                    |

## 結論

| 観点           | 判定 | 理由                                                                                 |
| -------------- | ---- | ------------------------------------------------------------------------------------ |
| 必要仕様の抽出 | 適合 | Notification、Bell 導線、IPC、防御、Portal、a11y、品質、運用を分割クエリで再抽出した |
| 取りこぼし対策 | 適合 | 0件概念は task 原本を正本にし、どの system spec で補強したかを明示した               |
| 再利用性       | 適合 | 後続実装時に query 単位で再追跡できる形になっている                                  |
