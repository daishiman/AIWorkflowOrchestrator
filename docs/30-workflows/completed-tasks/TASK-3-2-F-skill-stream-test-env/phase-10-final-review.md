## 実行タスク

### タスク1: 受け入れ基準の達成確認

**目的**: Phase 1で定義した6つの受け入れ基準の全てが達成されていることを確認する。

**実行手順**:

1. Phase 1の受け入れ基準（`outputs/phase-1/acceptance-criteria.md`）を読み込む
2. 各受け入れ基準について検証コマンドを実行し、達成状況を記録する

| AC   | 基準                          | 検証コマンド                                                                                           | 結果      |
| ---- | ----------------------------- | ------------------------------------------------------------------------------------------------------ | --------- |
| AC-1 | 全テストがPASS                | `pnpm --filter @repo/desktop vitest run`                                                               | PASS/FAIL |
| AC-2 | `describe.skip`が0件          | `grep -r "describe.skip" apps/desktop/src/renderer/components/AgentView/__tests__/SkillStreamDisplay*` | 0件/N件   |
| AC-3 | Clipboard APIテストが正常PASS | 該当テスト実行                                                                                         | PASS/FAIL |
| AC-4 | `act()`警告がゼロ             | テスト実行ログ確認                                                                                     | 0件/N件   |
| AC-5 | カバレッジ100%維持            | `pnpm --filter @repo/desktop test:coverage`                                                            | 達成/未達 |
| AC-6 | テスト実行時間+20%以内        | 実行時間計測                                                                                           | 達成/未達 |

3. 全AC達成の場合、PASS判定
4. 未達成のACがある場合、原因と対策を記録する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`（最終レビュー結果）

---

### タスク2: コード変更の全体レビュー

**目的**: 全変更ファイルの品質を多角的にレビューする。

**実行手順**:

1. 変更ファイル一覧を確認する
   ```bash
   git diff --name-only main
   ```
2. 以下のレビュー観点でチェックする

| #   | 観点           | チェック項目                           | 結果 |
| --- | -------------- | -------------------------------------- | ---- |
| 1   | 機能完全性     | 全ACが達成されているか                 | -    |
| 2   | コード品質     | 命名が適切、重複なし、Clean Codeに準拠 | -    |
| 3   | テスト品質     | テストケースが適切、境界値テストあり   | -    |
| 4   | セキュリティ   | テストモックがセキュリティに影響しない | -    |
| 5   | パフォーマンス | テスト実行時間が許容範囲内             | -    |
| 6   | 保守性         | 設定変更が明確、ドキュメント化可能     | -    |
| 7   | 互換性         | 他テストへの影響がない                 | -    |

3. 各観点についてOK/MINOR/MAJORを判定する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`（タスク1の成果物に追記）

---

### タスク3: レビュー判定と次アクション決定

**目的**: 最終レビュー結果を総合判定し、次アクションを決定する。

**実行手順**:

1. タスク1とタスク2の結果を集計する
2. 以下の基準で総合判定する

| 総合判定 | 条件                                | 次アクション                      |
| -------- | ----------------------------------- | --------------------------------- |
| PASS     | 全ACが達成、全レビュー観点がOK      | Phase 11へ進行                    |
| MINOR    | 全ACが達成、一部レビュー観点でMINOR | MINOR指摘を記録し、Phase 11へ進行 |
| MAJOR    | ACが未達成 or レビュー観点でMAJOR   | 影響範囲に応じて戻り先を決定      |
| CRITICAL | 根本的な設計問題                    | Phase 1へ戻りユーザー確認         |

3. MINOR判定の場合、未完了タスク指示書の作成候補として記録する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`（最終判定を追記）
