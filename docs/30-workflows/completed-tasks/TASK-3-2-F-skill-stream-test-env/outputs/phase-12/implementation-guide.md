# TASK-3-2-F 実装ガイド

## Part 1: 概念説明（初心者向け）

### テスト環境とは何か？

テストとは、プログラムが正しく動くかを確認する作業です。例えるなら、料理のレシピを書いた後に「本当にこの手順で美味しい料理ができるか」を試してみることに似ています。

**テスト環境** = 料理を試作するためのキッチン

実際のお店で試作すると失敗した時に困りますよね。だから別の「試作用キッチン」を用意します。プログラミングでも同じで、本番のアプリを壊さないよう「テスト専用の環境」を作ります。

### なぜ環境を変えたのか？

元々使っていた「happy-dom」という環境は、軽くて速いのですが、一部の機能（コピー機能など）をうまく再現できませんでした。

**例え話**:

- happy-dom = 電子レンジだけのキッチン（簡単な調理はOK、でもオーブン料理は作れない）
- jsdom = フル装備のキッチン（何でも作れるが少し場所を取る）

今回「コピー機能」のテストが必要だったので、フル装備の「jsdom」に切り替えました。

### Clipboard API モックとは？

「コピー」ボタンを押すと、テキストがクリップボードに保存されます。でもテスト環境では本物のクリップボードは使えません。

**モック** = テスト用の「偽物」

例えるなら、演劇で使う「小道具のお金」です。本物のお金は使えないけど、お金を渡す演技の練習はできます。同じように「偽のクリップボード」を作って、コピー機能の動作確認をします。

### 「スキップされたテスト」とは？

テストの中には「今は動かない」と印をつけて飛ばしているものがありました（describe.skip）。これは「この料理は今のキッチンでは作れない」と書いてあるようなものです。

今回、キッチン（環境）をアップグレードしたので、これらの印を外して全てのテストを実行できるようにしました。

### act()警告について

Reactという技術を使うと、画面の更新（状態変更）のタイミングが重要になります。警告は「更新のタイミングがちょっとずれてるよ」というお知らせです。

**例え話**:
写真を撮る時に「はい、チーズ！」と言ってからシャッターを押しますよね。でも時々、言い終わる前にシャッターが切れてしまう。写真自体は撮れているけど、タイミングが完璧ではない。

警告は出ていますが、テスト結果自体は正しいので、今回は「許容」としました。

## Part 2: 技術詳細（開発者向け）

### Vitest環境設定

**vitest.config.ts**:

| 設定項目        | 値                      | 理由                                                    |
| --------------- | ----------------------- | ------------------------------------------------------- |
| environment     | "jsdom"                 | happy-domから変更。Clipboard API等のDOM機能完全サポート |
| setupFiles      | ["./src/test/setup.ts"] | グローバルモック設定を一元管理                          |
| pool            | "forks"                 | プロセス分離でテスト安定性向上                          |
| fileParallelism | false                   | テスト間の干渉防止                                      |

**テストファイルでの環境指定**:

各テストファイル先頭に以下のディレクティブを追加:

```
// @vitest-environment jsdom
```

### jsdomバージョン管理

**問題**: グローバルpnpmストアのjsdom@27.xがESM非互換でエラー発生

**解決策**: root package.jsonにpnpm.overrides追加

| 設定                 | 値       | 効果                         |
| -------------------- | -------- | ---------------------------- |
| pnpm.overrides.jsdom | "25.0.1" | 全パッケージでバージョン統一 |

### Clipboard API モック実装

**配置**: apps/desktop/src/test/setup.ts

**設計方針**:

- jsdom/happy-dom両環境で動作するよう二重対策
- Object.definePropertyで設定、失敗時はプロパティ直接上書き

| メソッド  | モック戻り値    | 用途                               |
| --------- | --------------- | ---------------------------------- |
| writeText | Promise<void>   | コピー操作のテスト                 |
| readText  | Promise<string> | ペースト操作のテスト（空文字返却） |

### window.skillAPI モック実装

**配置**: apps/desktop/src/test/setup.ts（beforeAll内）

**背景**: useSkillExecution/useSkillPermissionフックがwindow.skillAPIを参照

| メソッド               | 戻り値                 | 用途                   |
| ---------------------- | ---------------------- | ---------------------- |
| onStream               | () => void             | ストリームリスナー登録 |
| onPermissionRequest    | () => void             | 権限リクエストリスナー |
| sendPermissionResponse | Promise<void>          | 権限応答送信           |
| execute                | Promise<{executionId}> | スキル実行開始         |
| abort                  | Promise<void>          | 実行中断               |

### テスト固有モックの再設定パターン

**問題**: setup.tsのグローバルモックがテスト固有モックを上書きする

**解決策**: テストのbeforeEachでvi.stubGlobalを再実行

| 手順 | 内容                                                            |
| ---- | --------------------------------------------------------------- |
| 1    | テストファイルでmockSkillAPIを定義                              |
| 2    | vi.stubGlobal("skillAPI", mockSkillAPI)をモジュールレベルで実行 |
| 3    | beforeEach内で再度vi.stubGlobalを呼び出し                       |

### act()警告の対処パターン

**fakeTimersパターン**:

| 手順 | 内容                                                          |
| ---- | ------------------------------------------------------------- |
| 1    | vi.useFakeTimers()でタイマーをモック化                        |
| 2    | act(async () => { vi.advanceTimersByTime(ms) })で時間を進める |
| 3    | vi.useRealTimers()で元に戻す                                  |

**残存警告の原因と評価**:
