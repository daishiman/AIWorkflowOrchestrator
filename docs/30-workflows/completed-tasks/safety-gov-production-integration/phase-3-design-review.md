# Phase 3: 設計レビューゲート

## メタ情報

| 項目   | 値                                |
| ------ | --------------------------------- |
| Phase  | 3                                 |
| 機能名 | safety-gov-production-integration |
| 作成日 | 2026-03-31                        |

## 目的

Phase 2 の設計を評価し、Phase 4 テスト作成に進めるか判定する。
PASS / MINOR / MAJOR の判定を行い、MAJORの場合はPhase 2またはPhase 1に戻る。

## 実行タスク

- Phase 2 の IPC 4層整合性表をレビューし、登録漏れ・型漏れ・責務越境の有無を判定する
- ApprovalGate DI と session cleanup の owner を確認し、既存 handler への影響範囲を明文化する
- Push 通知 payload の最小化と preload 公開面の安全性を確認する
- ゲート判定を PASS / MINOR / MAJOR / CRITICAL で確定し、差し戻し先を明記する

### 1. 設計レビュー観点

#### 1.1 責務境界チェック

| 観点              | 確認内容                                                   | 判定 |
| ----------------- | ---------------------------------------------------------- | ---- |
| Main Process 境界 | ApprovalGate は Main Process にのみ存在するか              | -    |
| Preload 境界      | contextBridge 経由のみで Renderer が IPC 呼び出すか        | -    |
| Renderer 境界     | hooks が直接 ipcRenderer を呼ばず electronAPI を経由するか | -    |
| 状態所有権        | ApprovalGate の状態は Main Process が単独で保持するか      | -    |

#### 1.2 IPC 4層整合性レビュー

| 確認項目                                                            | 期待                           | 判定 |
| ------------------------------------------------------------------- | ------------------------------ | ---- |
| 全5チャンネルが ALLOWED_INVOKE または ALLOWED_ON に登録されているか | 全て登録済み                   | -    |
| Push 通知チャンネルが ALLOWED_ON_CHANNELS のみに属するか            | APPROVAL_REQUEST は ALLOWED_ON | -    |
| 既存 handler との命名衝突がないか                                   | なし                           | -    |

#### 1.3 型安全性レビュー

| 確認項目                                        | 期待                             | 判定 |
| ----------------------------------------------- | -------------------------------- | ---- |
| `ExecutionAPI` の全メソッドが型定義されているか | 5メソッド全て定義                | -    |
| `ElectronAPI` への追加が型安全か                | `execution: ExecutionAPI` の追加 | -    |
| Renderer から `any` キャストなしで呼び出せるか  | 型推論が通る                     | -    |

#### 1.4 セキュリティレビュー

| 確認項目                                                  | 期待                   | 判定 |
| --------------------------------------------------------- | ---------------------- | ---- |
| sender 検証が approvalHandlers に含まれているか           | 実装済み（既存コード） | -    |
| Push 通知に認証トークンが含まれないか（最小限データのみ） | payload に token 不含  | -    |

#### 1.5 simpler alternative の検討

| 代替案                                         | 採用/不採用 | 理由                                   |
| ---------------------------------------------- | ----------- | -------------------------------------- |
| ApprovalGate を global module singleton にする | 不採用      | テスタビリティが低下するため DI を維持 |
| revokeAll() を agentHandlers 内に直接実装      | 検討中      | セッション管理コードの場所次第         |
| execution namespace をフラットな API にする    | 不採用      | 名前空間による型安全性を維持           |
