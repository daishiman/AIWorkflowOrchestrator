## 目的

Phase 2 で作成した設計の妥当性を検証し、実装に進む前に設計品質を確保する。
要件との整合性、既存パターンとの一貫性、拡張性を確認する。

## 背景

設計レビューは、実装コスト増大を防ぐための重要なゲートである。
設計段階で問題を発見・修正することで、後工程での手戻りを最小化する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件整合性レビュー

**目的**: Phase 1 の要件と Phase 2 の設計が整合しているか確認する

**実行手順**:

1. `outputs/phase-1/requirements-specification.md` を読み込む
2. `outputs/phase-2/api-design.md` を読み込む
3. 要件の各項目が設計でカバーされているか確認する
4. 設計に過不足がないか確認する

**レビュー観点**:

| 観点             | 確認内容                                       |
| ---------------- | ---------------------------------------------- |
| 機能要件カバー   | 全機能が API として設計されているか            |
| 非機能要件カバー | パフォーマンス・セキュリティが考慮されているか |
| 型整合性         | TASK-1-1 の型定義と整合しているか              |
| IPC連携          | TASK-4-2 との連携が設計されているか            |

**期待される成果物**:

- `outputs/phase-3/requirements-alignment-review.md`

---

### タスク2: 既存パターン整合性レビュー

**目的**: slideSettingsStore.ts パターンとの一貫性を確認する

**実行手順**:

1. `apps/desktop/src/main/settings/slideSettingsStore.ts` を読み込む
2. `outputs/phase-2/schema-design.md` と比較する
3. 設計パターンの一貫性を確認する
4. 差異がある場合はその理由を確認する

**レビュー観点**:

| 観点             | 確認内容                         |
| ---------------- | -------------------------------- |
| Store構造        | electron-store の使用パターン    |
| スキーマ定義     | JSON Schema バリデーションの使用 |
| マイグレーション | バージョン管理パターン           |
| エクスポート形式 | シングルトン・オブジェクト形式   |

**期待される成果物**:

- `outputs/phase-3/pattern-consistency-review.md`

---

### タスク3: 拡張性レビュー

**目的**: 将来の機能追加に対する拡張性を確認する

**実行手順**:

1. `outputs/phase-2/schema-design.md` を読み込む
2. `outputs/phase-2/migration-design.md` を読み込む
3. 将来のスキーマ拡張が容易か確認する
4. 後方互換性維持の仕組みを確認する

**レビュー観点**:

| 観点             | 確認内容                                   |
| ---------------- | ------------------------------------------ |
| スキーマ拡張     | 新規フィールド追加が容易か                 |
| マイグレーション | 新バージョンへの移行パスが設計されているか |
| 後方互換性       | 古いデータの読み込みが保証されているか     |
| API拡張          | 新規メソッド追加が既存に影響しないか       |

**期待される成果物**:

- `outputs/phase-3/extensibility-review.md`

---

### タスク4: セキュリティレビュー

**目的**: セキュリティ上の問題がないか確認する

**実行手順**:

1. `outputs/phase-2/schema-design.md` を読み込む
2. 機密情報の取り扱いを確認する
3. 入力バリデーションを確認する
4. ファイルシステムアクセスの安全性を確認する

**レビュー観点**:

| 観点             | 確認内容                           |
| ---------------- | ---------------------------------- |
| データ保護       | 機密情報（権限設定等）の適切な管理 |
| 入力検証         | skillName 等の入力バリデーション   |
| ファイルアクセス | パストラバーサル対策               |
| エラー情報       | エラーメッセージからの情報漏洩防止 |

**期待される成果物**:

- `outputs/phase-3/security-review.md`

---

### タスク5: レビュー結果判定

**目的**: レビュー結果を統合し、次フェーズへの進行可否を判定する

**実行手順**:

1. タスク1〜4の成果物を読み込む
2. 発見された問題を重要度別に分類する
3. 判定結果（PASS/MINOR/MAJOR/CRITICAL）を決定する
4. 問題がある場合は修正アクションを定義する

**判定基準**:

| 判定     | 条件                     | 次のアクション           |
| -------- | ------------------------ | ------------------------ |
| PASS     | 全レビュー観点で問題なし | Phase 4 へ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4 へ   |
| MAJOR    | 重大な問題あり           | Phase 2 へ戻り設計修正   |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻り要件再確認 |

**期待される成果物**:

- `outputs/phase-3/review-summary.md`
