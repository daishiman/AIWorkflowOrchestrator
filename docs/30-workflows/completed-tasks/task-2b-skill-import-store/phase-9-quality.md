## 目的

静的解析、セキュリティ、パフォーマンスの観点からコード品質を検証する。
プロジェクト品質基準を満たしていることを確認する。

## 背景

品質保証フェーズでは、機能的な正しさだけでなく、非機能要件も検証する。
Lint、型チェック、セキュリティスキャンなど複数の観点からコードを検証する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: Lint 検証

**目的**: ESLint ルールへの準拠を確認する

**実行手順**:

1. ESLint を実行する
2. エラー・警告を確認する
3. 問題があれば修正する
4. 再度 Lint を実行して確認する

**コマンド**:

```bash
# Lint 実行
pnpm --filter @repo/desktop lint

# 自動修正
pnpm --filter @repo/desktop lint --fix
```

**期待される成果物**:

- `outputs/phase-9/lint-report.md`

---

### タスク2: 型チェック検証

**目的**: TypeScript の型エラーがないことを確認する

**実行手順**:

1. TypeScript コンパイラを実行する
2. 型エラーを確認する
3. 問題があれば修正する
4. 再度型チェックを実行して確認する

**コマンド**:

```bash
# 型チェック実行
pnpm --filter @repo/desktop typecheck
```

**期待される成果物**:

- `outputs/phase-9/typecheck-report.md`

---

### タスク3: セキュリティ検証

**目的**: セキュリティ上の問題がないことを確認する

**実行手順**:

1. コードレビューでセキュリティ観点を確認する
2. 入力バリデーションを確認する
3. ファイルシステムアクセスの安全性を確認する
4. 機密情報の取り扱いを確認する

**セキュリティチェックリスト**:

| 観点               | 確認内容                             | 結果 |
| ------------------ | ------------------------------------ | ---- |
| 入力バリデーション | skillName に不正な値が入らないか     | -    |
| パストラバーサル   | ファイルパスの安全性                 | -    |
| 機密情報           | 権限設定の適切な管理                 | -    |
| エラー情報漏洩     | エラーメッセージから情報が漏れないか | -    |
| インジェクション   | 動的なコード実行がないか             | -    |

**期待される成果物**:

- `outputs/phase-9/security-report.md`

---

### タスク4: ビルド検証

**目的**: プロダクションビルドが成功することを確認する

**実行手順**:

1. ビルドを実行する
2. エラー・警告を確認する
3. ビルド成果物を確認する
4. バンドルサイズを確認する

**コマンド**:

```bash
# ビルド実行
pnpm --filter @repo/desktop build
```

**期待される成果物**:

- `outputs/phase-9/build-report.md`

---

### タスク5: 品質ゲート総合判定

**目的**: 全ての品質基準を満たしているか総合判定する

**実行手順**:

1. タスク1〜4の結果を統合する
2. 品質基準との照合を行う
3. 判定結果を記録する

**品質ゲートチェックリスト**:

- [ ] 全ユニットテスト成功

#### コード品質

- [ ] コードフォーマット適用済み

#### テスト網羅性

- [ ] Line Coverage 80%+ 達成
- [ ] Branch Coverage 60%+ 達成
- [ ] Function Coverage 80%+ 達成

#### セキュリティ

- [ ] セキュリティレビュー完了
- [ ] 重大な脆弱性なし

#### ビルド

- [ ] ビルド成功
- [ ] 警告なし

**期待される成果物**:

- `outputs/phase-9/quality-gate-result.md`
