## 目的

テストカバレッジがプロジェクト基準を満たしているか確認する。
未達の場合は Phase 6 へ戻りテストを追加する。

## 背景

テストカバレッジはコード品質の重要な指標である。
カバレッジ目標を達成することで、十分なテストが行われていることを保証する。

---

## カバレッジ目標

### ユニットテスト

| 指標              | 最低基準 | 推奨基準 | 現在値 |
| ----------------- | -------- | -------- | ------ |
| Line Coverage     | 80%      | 90%      | -      |
| Branch Coverage   | 60%      | 70%      | -      |
| Function Coverage | 80%      | 90%      | -      |

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: カバレッジレポートの生成

**目的**: 現在のテストカバレッジを測定する

**実行手順**:

1. カバレッジ付きでテストを実行する
2. レポートを確認する
3. 未カバーの箇所を特定する

**コマンド**:

```bash
# カバレッジ付きテスト実行
pnpm --filter @repo/desktop test -- --coverage skillImportStore

# または vitest の場合
pnpm --filter @repo/desktop vitest run --coverage skillImportStore
```

**期待される成果物**:

- `outputs/phase-7/coverage-report.md`

---

### タスク2: カバレッジ分析

**目的**: カバレッジが目標を満たしているか分析する

**実行手順**:

1. 各カバレッジ指標を確認する
2. 目標値と比較する
3. 未達の場合は原因を特定する

**分析観点**:

| 観点              | 確認内容                     |
| ----------------- | ---------------------------- |
| Line Coverage     | 実行されていない行を特定     |
| Branch Coverage   | 通過していない分岐を特定     |
| Function Coverage | テストされていない関数を特定 |

**期待される成果物**:

- `outputs/phase-7/coverage-analysis.md`

---

### タスク3: 未カバー箇所の特定

**目的**: テストされていないコードパスを特定する

**実行手順**:

1. カバレッジレポートの詳細を確認する
2. 未カバー行・分岐を一覧化する
3. 優先度を付けて分類する

**分類基準**:

| 優先度 | 対象                             |
| ------ | -------------------------------- |
| 高     | メイン機能の未カバーパス         |
| 中     | エラーハンドリングの未カバーパス |
| 低     | ユーティリティの未カバーパス     |

**期待される成果物**:

- `outputs/phase-7/uncovered-paths.md`

---

### タスク4: カバレッジ改善計画

**目的**: カバレッジ目標達成のための計画を立てる

**実行手順**:

1. 未達の場合、追加すべきテストを特定する
2. 各テストの優先度を決定する
3. Phase 6 への戻りが必要か判定する

**判定基準**:

| 状況                   | アクション              |
| ---------------------- | ----------------------- |
| 全指標が目標達成       | Phase 8 へ進む          |
| 一部指標が未達（軽微） | テスト追加後 Phase 8 へ |
| 複数指標が大幅に未達   | Phase 6 へ戻る          |

**期待される成果物**:

- `outputs/phase-7/improvement-plan.md`

---

### タスク5: 統合テストカバレッジ確認

**目的**: 統合テストのカバレッジを確認する

**実行手順**:

1. IPC連携テストのカバレッジを確認する
2. ストア操作の全パターンがテストされているか確認する
3. 不足があれば追加テストを計画する

**確認観点**:

| テストカテゴリ     | 確認内容                             |
| ------------------ | ------------------------------------ |
| IPC連携            | 全チャンネルがテストされているか     |
| データフロー       | 正常系・異常系がテストされているか   |
| エラーハンドリング | 全エラーパターンがテストされているか |

**期待される成果物**:

- `outputs/phase-7/integration-coverage.md`
