## 目的

静的解析・セキュリティ・性能の観点から品質を保証する。

## 背景

本番リリース前に、コード品質・セキュリティ・パフォーマンスの基準を満たしていることを確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 静的解析

**目的**: Lint・型チェック・フォーマットの品質確認

**実行手順**:

1. ESLint実行:
   ```bash
   pnpm --filter @repo/shared lint
   ```
2. TypeScript型チェック:
   ```bash
   pnpm --filter @repo/shared typecheck
   ```
3. フォーマット確認:
   ```bash
   pnpm --filter @repo/shared format:check
   ```
4. 全てエラーなしであることを確認

**期待される成果物**:

- `outputs/phase-9/quality-report.md`（静的解析セクション）

---

### タスク2: テスト品質確認（統合テスト連携）

**目的**: 全テストが成功し、カバレッジ基準を満たすことを確認

**実行手順**:

1. 全ユニットテスト実行:
   ```bash
   pnpm --filter @repo/shared test -- community-summarizer
   ```
2. 全統合テスト実行:
   ```bash
   pnpm --filter @repo/shared test:integration
   ```
3. カバレッジ確認:
   ```bash
   pnpm --filter @repo/shared test:coverage -- community-summarizer
   ```
4. 結果を記録

**期待される成果物**:

- `outputs/phase-9/quality-report.md`（テスト品質セクション）

---

### タスク3: セキュリティ確認

**目的**: セキュリティリスクがないことを確認

**実行手順**:

1. 入力バリデーション確認:
   - プロンプトインジェクション対策
   - 不正入力のサニタイズ
2. 出力エスケープ確認:
   - LLMレスポンスのパース時の安全性
3. 依存関係の脆弱性チェック:
   ```bash
   pnpm audit
   ```
4. 結果を記録

**期待される成果物**:

- `outputs/phase-9/quality-report.md`（セキュリティセクション）

---

### タスク4: パフォーマンス確認

**目的**: パフォーマンス基準を満たすことを確認

**実行手順**:

1. 処理時間の確認:
   - 単一コミュニティ要約: 目標値以内
   - 一括処理: 並列処理が効いていること
2. メモリ使用量の確認:
   - 大量コミュニティ処理時のメモリリーク
3. 結果を記録

**期待される成果物**:

- `outputs/phase-9/quality-report.md`（パフォーマンスセクション）

---

### タスク5: 品質ゲート判定

**目的**: 品質基準を満たしていることを最終確認

**実行手順**:

1. チェックリストを確認:
   - [ ] Lintエラーなし
   - [ ] 型エラーなし
   - [ ] 全テスト成功
   - [ ] カバレッジ基準達成
   - [ ] セキュリティリスクなし
   - [ ] パフォーマンス基準達成
2. 判定結果を記録

**期待される成果物**:

- `outputs/phase-9/quality-report.md`（判定結果セクション）
