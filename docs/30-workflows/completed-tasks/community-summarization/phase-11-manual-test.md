## 目的

自動テストでは検証しにくいUX・実環境動作を手動で確認する。

## 背景

自動テストは機能の正確性を保証するが、実際のLLM呼び出しやユーザー体験は手動確認が必要。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 開発環境での動作確認

**目的**: 開発環境で基本機能が動作することを確認

**実行手順**:

1. 開発サーバーを起動:
   ```bash
   pnpm --filter @repo/desktop dev
   ```
2. テスト用コミュニティデータを準備:
   - 小規模コミュニティ（5エンティティ）
   - 中規模コミュニティ（20エンティティ）
   - 階層構造（親子コミュニティ）
3. 各機能を手動実行:
   - [ ] 単一コミュニティの要約生成
   - [ ] 子コミュニティを使用した要約生成
   - [ ] 全コミュニティの一括要約生成
4. 結果を確認

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（動作確認セクション）

---

### タスク2: LLM統合テスト（手動統合テスト連携）

**目的**: 実際のLLMプロバイダーとの統合を確認

**実行手順**:

1. 実LLMプロバイダーを設定:
   - OpenAI / Anthropic / その他
2. 実際の要約生成を実行:
   - [ ] 要約の品質確認（意味のある内容か）
   - [ ] キーワードの適切さ
   - [ ] mainEntities/mainRelationsの妥当性
   - [ ] sentiment判定の妥当性
   - [ ] confidence値の妥当性
3. 結果を記録

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（LLM統合テストセクション）

---

### タスク3: 埋め込み・検索テスト

**目的**: 埋め込み生成とセマンティック検索の動作確認

**実行手順**:

1. 実Embeddingプロバイダーを設定
2. 要約の埋め込み生成を確認:
   - [ ] 埋め込みベクトルが正しく生成される
   - [ ] DBに正しく保存される
3. セマンティック検索を確認:
   - [ ] クエリに関連する要約が返される
   - [ ] レベル指定検索が動作する
   - [ ] 類似度順にソートされる

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（検索テストセクション）

---

### タスク4: エラーケース確認

**目的**: エラー発生時の動作を確認

**実行手順**:

1. LLM接続エラー時の動作:
   - [ ] 適切なエラーメッセージが返される
   - [ ] 部分失敗時に処理が継続される
   - [ ] 失敗コミュニティIDが正しく返される
2. 埋め込み生成エラー時の動作:
   - [ ] 埋め込みなしで要約が保存される
3. 不正入力時の動作:
   - [ ] 空コミュニティ
   - [ ] 不正なコミュニティID

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（エラーケーステストセクション）

---

### タスク5: パフォーマンス確認

**目的**: 実環境でのパフォーマンスを確認

**実行手順**:

1. 処理時間を計測:
   - [ ] 単一コミュニティ要約: \_\_\_秒
   - [ ] 10コミュニティ一括: \_\_\_秒
   - [ ] 並列処理が効いているか確認
2. 結果を記録

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（パフォーマンステストセクション）

---

### タスク6: テスト結果サマリー

**目的**: 手動テスト結果を総括

**実行手順**:

1. 全テスト項目の結果を集約
2. 発見事項を記録:
   - スコープ外の発見事項
   - 改善提案
   - バグ（該当する場合）
3. Phase 12への引き継ぎ事項を記録

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`（サマリーセクション）
