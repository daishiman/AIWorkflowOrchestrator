### 2.2 階層順処理の重要性

```
Level 2:  [C1]─────[C2]
             ↘   ↙
Level 1:     [C3]
              ↓
Level 0:  [C4][C5][C6]

処理順序: C4, C5, C6 → C3 → C1, C2
         (level 0)   (level 1) (level 2)
```

**理由**:

- 親コミュニティ（C3）の要約生成時に、子コミュニティ（C4, C5, C6）の要約を使用可能
- 階層的に情報を集約することで、上位レベルの要約が下位レベルの内容を反映

### 2.3 並列処理の設計

```typescript
// チャンク分割
function chunkArray<T>(array: T[], size: number): T[][] {
  const chunks: T[][] = [];
  for (let i = 0; i < array.length; i += size) {
    chunks.push(array.slice(i, i + size));
  }
  return chunks;
}

// 同一レベル内での並列処理
const chunks = chunkArray(sortedCommunities, maxConcurrency);

for (const chunk of chunks) {
  const results = await Promise.all(
    chunk.map((community) => this.processCommunity(community)),
  );
  // 結果を集計
}
```

### 3.2 SQLクエリ構造

```sql
SELECT
  c.id,
  c.level,
  cs.summary,
  cs.keywords,
  cs.main_entities,
  cs.main_relations,
  cs.sentiment,
  cs.confidence,
  cs.token_count,
  cs.embedding,
  cs.created_at
FROM communities c
JOIN community_summaries cs ON c.id = cs.community_id
WHERE cs.embedding IS NOT NULL
  AND c.level = ?  -- オプション: level指定時のみ
ORDER BY vector_distance_cos(cs.embedding, ?) ASC
LIMIT ?
```
