## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、実装に進む前に設計の妥当性を検証する。

## 背景

設計レビューゲートは、実装前に問題を発見し、手戻りを最小化するための品質ゲートである。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件定義レビュー

**目的**: Phase 1の成果物が完全かつ適切かを検証

**実行手順**:

1. 要件定義書（`outputs/phase-1/requirements-definition.md`）をレビュー:
   - 機能要件が網羅されているか
   - 非機能要件が具体的か
   - 接続要件が明確か
2. スコープ定義（`outputs/phase-1/scope-definition.md`）をレビュー:
   - スコープ内/外が明確か
   - 既存機能との重複がないか
3. 受け入れ基準（`outputs/phase-1/acceptance-criteria.md`）をレビュー:
   - テスト可能な基準か
   - 漏れがないか

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`（要件レビューセクション）

---

### タスク2: 設計レビュー

**目的**: Phase 2の設計が要件を満たし、実装可能かを検証

**実行手順**:

1. アーキテクチャ設計をレビュー:
   - 既存アーキテクチャとの整合性
   - レイヤー構成の妥当性
   - 依存関係の適切さ
2. インターフェース設計をレビュー:
   - Result型パターンの適用
   - Branded Types（CommunityId等）の使用
   - メソッドシグネチャの一貫性
3. 型定義をレビュー:
   - タスク指示書との整合性
   - 既存型との互換性
4. プロンプト設計をレビュー:
   - 出力形式の妥当性
   - トークン効率

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`（設計レビューセクション）

---

### タスク3: 統合テスト観点レビュー（統合テスト連携）

**目的**: 統合ポイントの設計が適切かを検証

**実行手順**:

1. ILLMProvider統合をレビュー:
   - generate()呼び出しパラメータの妥当性
   - エラーハンドリングの網羅性
2. IEmbeddingProvider統合をレビュー:
   - embedSingle()呼び出しの妥当性
3. IKnowledgeGraphStore統合をレビュー:
   - findEntities(), getRelations()の使用方法
4. ICommunityRepository統合をレビュー:
   - 新規メソッドの設計妥当性
   - 既存メソッドとの整合性

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`（統合レビューセクション）

---

### タスク4: レビュー結果判定

**目的**: レビュー結果を総合判定し、次のアクションを決定

**実行手順**:

1. 各レビュー項目の指摘を集約
2. 指摘事項を分類:
   - **PASS**: 問題なし → Phase 4へ
   - **MINOR**: 軽微な指摘 → 指摘対応後、Phase 4へ
   - **MAJOR**: 重大な問題 → 影響範囲に応じて戻る
   - **CRITICAL**: 致命的な問題 → Phase 1へ戻りユーザー確認
3. 最終判定を記録

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`（判定結果セクション）

## レビューゲート判定基準

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
