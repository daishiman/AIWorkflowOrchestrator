## メタ情報

| 項目     | 値                                                                             |

| Phase    | 11                                                                             |

| 作成日   | 2026-04-14                                                                     |

## 目的

Electron デスクトップアプリを実際に操作し、ライトテーマ・ダークテーマ両方での目視確認を行う。自動テストでは検証できない視覚的・UX 的な品質を確認する。

---

## 実行タスク

- 開発環境の起動
- ライトテーマでの全目視確認
- ダークテーマでの全目視確認
- ウィザード全体フローの回帰確認
- 問題検出時の unassigned-task 生成

---

## 事前準備

```bash
# 開発環境起動
pnpm --filter @repo/desktop dev

# または
pnpm --filter @repo/web dev
```

## 手動テストシナリオ

### シナリオ1: CSS 変数監査（目視確認）

| 確認手順                                             | 期待結果                                       | ライト | ダーク |
| ---------------------------------------------------- | ---------------------------------------------- | ------ | ------ |
| スキルウィザードを開く（スキル作成ボタンをクリック） | ウィザードが開く                               | -      | -      |
| Step 0 の「次へ」ボタンを確認する                    | CSS 変数の色が正しく表示される（テーマと整合） | -      | -      |
| LLM モード・テンプレートモードの全ボタンを確認する   | 全ボタンの色がテーマと整合している             | -      | -      |
| テーマを切り替えてボタン色の変化を確認する           | テーマ切替後に全ボタンの色が正しく変わる       | -      | -      |

### シナリオ2: カテゴリ選択上限（目視確認）

| 確認手順                                                  | 期待結果                                                    | ライト | ダーク |
| --------------------------------------------------------- | ----------------------------------------------------------- | ------ | ------ |
| SkillInfoStep（カテゴリ選択ステップ）に進む               | カテゴリボタンが全て表示される                              | -      | -      |
| カテゴリを1件ずつ選択し、全7カテゴリのうち3件まで確認する | 選択済みカテゴリが視覚的に選択状態を示す                    | -      | -      |

| 上限到達後に未選択ボタンをクリックする                    | クリックしても選択されない（4件目が追加されない）           | -      | -      |
| 選択済みカテゴリを1件解除する                             | disabled が解除され、再度選択可能になる                     | -      | -      |

## 証跡ルール

- `manual-test-result.md` を Phase 11 の正本として扱う
- UI/UX 変更のあるタスクなので `screenshot-plan.json` と `phase11-capture-metadata.json` を必須にする
- `screenshot-plan.json` は `VISUAL` 前提で作成し、`phase11-capture-metadata.json` の `taskId` が `TASK-SW-UI-POLISH-001` と一致するか確認する
- Electron を起動できない場合は `CAPTURE_BLOCKED` として記録し、ダミー PNG は作成しない
- 問題が見つかった場合は `docs/30-workflows/unassigned-task/` に formalize する

## 問題検出時の対応

### 問題の重大度分類

| 重大度 | 条件                                           | 対応                           |
| ------ | ---------------------------------------------- | ------------------------------ |
| HIGH   | 機能が動作しない・クラッシュが発生する         | Phase 5 に差し戻し、即時修正   |
| MEDIUM | 視覚的に意図と異なる（アニメーション不動作等） | unassigned-task として記録     |
| LOW    | 微細な見た目の差異（許容範囲）                 | 備考欄に記録、次回タスクで対応 |

### 未タスク生成

HIGH 問題が発見された場合は `docs/30-workflows/unassigned-task/` に新規タスク指示書を生成する。
