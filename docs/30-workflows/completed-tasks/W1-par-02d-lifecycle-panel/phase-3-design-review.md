## 実行タスク

### Task 1: 変更最小化の検証

| チェック項目                                                 | 判定基準                                   |
| ------------------------------------------------------------ | ------------------------------------------ |
| 削除対象以外のコードが変更されていないか                     | 「2. スキルを確認する」以降が無変更        |
| `onClose` Props が削除されていないか                         | 既存Propsが保持されている                  |
| 既存のCSS定数（lifecycleButtonStyles等）が変更されていないか | スタイル定数は流用している                 |
| 不要なimport削除が漏れていないか                             | request/setState関連のimportが残っていない |

### Task 2: 影響範囲の確認

```bash
# 呼び出し元への影響を確認
rg -n "SkillLifecyclePanel" apps/desktop/src/ --glob "*.tsx" --glob "*.ts"

# 既存テストへの影響を確認
rg -n "skill-lifecycle-request-input|skill-lifecycle-create-button|skill-lifecycle-prepare-button" apps/desktop/src/ --glob "*.test.*"
```

影響が生じる可能性のある箇所:

| 箇所                                   | 影響の種類                                  | 対処方針                                     |
| -------------------------------------- | ------------------------------------------- | -------------------------------------------- |
| SkillLifecyclePanel の親コンポーネント | onOpenSkillWizard props を渡す必要あり      | 呼び出し元で props を追加する                |
| 既存テストスイート                     | 削除した data-testid を参照するテストがある | `SkillLifecyclePanel*.test.tsx` を再点検する |

### Task 3: 型安全性の確認

```typescript
// onOpenSkillWizard が必須 props になることの確認
// 既存の呼び出し元で TypeScript エラーが発生するか確認
interface SkillLifecyclePanelProps {
  onClose: () => void;
  onOpenSkillWizard: () => void; // 必須
}
```

呼び出し元で `onOpenSkillWizard` が渡されていない場合、TypeScript がコンパイルエラーを出すことで漏れを防止できる。

### Task 4: UX 観点のレビュー

| UX チェック項目                                    | 確認内容                                         |
| -------------------------------------------------- | ------------------------------------------------ |
| ウィザードボタンのテキストが意図を明示しているか   | 「スキル作成ウィザードを開く →」は分かりやすいか |
| セクションの見出し「1. スキルを作成する」が適切か  | 旧「1. 依頼をまとめる」との違いが明確か          |
| 説明テキストが十分か                               | ウィザードで何ができるかが伝わるか               |
| ボタンのスタイルが他のセクションと統一されているか | `lifecycleButtonStyles.primary` を使用しているか |

### Task 5: リスク評価

| リスク                                          | 影響度 | 対策                                                                |
| ----------------------------------------------- | ------ | ------------------------------------------------------------------- |
| 呼び出し元で onOpenSkillWizard 未追加           | 高     | TypeScript エラーで強制検出 / Phase 5 で対応                        |
| 既存テストが削除済み data-testid を参照         | 中     | Phase 4 でテストを更新する                                          |
| handleCreate/handlePrepare の削除による機能退行 | 低     | W2-seq-03a（SkillCreateWizard）へ機能を受け渡す前提であることを確認 |

### Task 6: 設計承認判定

上記チェックを全て完了し、問題がなければ設計を承認する。
30 思考法の適用結果を統合し、エレガントさを犠牲にしていないことを確認する。
GATE 判定は PASS / MINOR / MAJOR / CRITICAL の 4 段階で残す。
