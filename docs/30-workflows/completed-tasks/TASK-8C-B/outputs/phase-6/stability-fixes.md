## 1. フレーキーテスト対策

### 1.1 待機処理

| 対策               | 実装箇所         | コード                                            |
| ------------------ | ---------------- | ------------------------------------------------- |
| 明示的セレクタ待機 | `openDropdown()` | `waitForSelector(dropdown, { state: "visible" })` |
| UI安定化待ち       | `beforeEach`     | `waitForTimeout(100)`                             |
| DOMロード待ち      | `beforeAll`      | `waitForLoadState("domcontentloaded")`            |

### 1.2 オプショナルチェイニング

```typescript
// APIが存在しない場合でもエラーにならない
await page.evaluate(() => {
  window.electronAPI?.skill?.resetForTesting?.();
});
```

## 2. セレクタ安定性

### 2.1 ARIA属性ベースセレクタ

| セレクタ                                     | 安定性 | 理由                           |
| -------------------------------------------- | ------ | ------------------------------ |
| `[role="combobox"][aria-haspopup="listbox"]` | 高     | セマンティック、実装変更に強い |
| `[role="listbox"]`                           | 高     | 標準ARIA role                  |
| `[role="option"]:has-text()`                 | 高     | テキストベース、可読性高い     |

### 2.2 避けたセレクタ

| セレクタ例        | 避けた理由                     |
| ----------------- | ------------------------------ |
| `.class-name`     | スタイルクラスは変更されやすい |
| `div > div > btn` | 構造依存、リファクタで壊れる   |
| `:nth-child(n)`   | 順序依存、不安定               |

## 3. タイムアウト設定

| 設定項目               | 値         | 理由                         |
| ---------------------- | ---------- | ---------------------------- |
| beforeAll タイムアウト | 60000ms    | Electron起動に余裕を持たせる |
| waitForTimeout         | 100ms      | UI安定化の最小待機           |
| テスト全体             | デフォルト | 個別テストは短時間で完了予定 |

## 4. エラーハンドリング

### 4.1 Electron起動失敗対策

```typescript
beforeAll(async () => {
  electronApp = await electron.launch({
    args: [...],
    env: {...},
  });

  page = await electronApp.firstWindow();
  await page.waitForLoadState("domcontentloaded");
}, 60000); // タイムアウト設定
```

### 4.2 クリーンアップ

```typescript
afterAll(async () => {
  await electronApp?.close(); // オプショナルで安全にクローズ
});
```

## 5. テスト独立性

### 5.1 状態リセット

| リセット内容       | 実装方法                           |
| ------------------ | ---------------------------------- |
| スキル選択状態     | `resetForTesting?.()` API呼び出し  |
| ドロップダウン状態 | 各テスト開始時は閉じた状態から開始 |
| フォーカス状態     | 明示的なクリック/フォーカス設定    |

### 5.2 テスト順序非依存

各テストケースは以下を保証:

1. 前のテストの状態に依存しない
2. 自身で必要な状態を設定
3. 他のテストに影響する状態を残さない
