## 目的

実際のユーザー操作を模したシナリオで、実SDKとの統合が正しく機能することを手動で検証する。

## 背景

自動テストでは検証しきれないユーザー体験やUI/UXの問題を発見するため、手動テストを実施する。実際のClaude Code SDKを使用した実環境での動作確認を行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: テスト環境準備

**目的**: 手動テストを実施するための環境を準備する。

**実行手順**:

1. Claude Codeがインストールされていることを確認
   ```bash
   claude --version
   ```
2. 認証状態を確認
   ```bash
   claude auth status
   ```
3. デスクトップアプリをビルド
   ```bash
   pnpm --filter @repo/desktop build
   ```
4. アプリを起動
   ```bash
   pnpm --filter @repo/desktop start
   ```

**確認項目**:

| 項目         | 確認内容         | 結果  |
| ------------ | ---------------- | ----- |
| Claude Code  | インストール済み | OK/NG |
| 認証状態     | 認証済み         | OK/NG |
| アプリビルド | エラーなし       | OK/NG |
| アプリ起動   | 正常起動         | OK/NG |

**期待される成果物**:

- テスト環境準備完了確認

---

### タスク2: 基本機能テスト

**目的**: Agent実行の基本機能が正しく動作することを確認する。

**実行手順**:

1. Agent実行画面を開く
2. 新規セッションを作成
3. 簡単なプロンプトを入力して実行
4. ストリーミング応答を確認
5. 応答完了を確認
6. セッションを終了

**テストシナリオ**:

| シナリオ       | 操作                             | 期待結果                   |
| -------------- | -------------------------------- | -------------------------- |
| セッション作成 | 「新規セッション」ボタンクリック | セッションIDが表示される   |
| クエリ実行     | プロンプト入力→実行              | ストリーミング応答が開始   |
| 応答表示       | 応答を確認                       | テキストがリアルタイム表示 |
| 応答完了       | 完了を待機                       | 完了状態に遷移             |
| セッション終了 | 終了ボタンクリック               | セッションがクローズ       |

**期待される成果物**:

- 基本機能テスト結果

---

### タスク3: エラー処理テスト

**目的**: エラー発生時の動作が適切であることを確認する。

**実行手順**:

1. ネットワーク切断状態でクエリ実行を試行
2. エラーメッセージの表示を確認
3. ネットワーク復旧後の再試行を確認
4. 中断操作のテスト
5. タイムアウトのテスト（可能な範囲で）

**テストシナリオ**:

| シナリオ         | 操作                       | 期待結果                   |
| ---------------- | -------------------------- | -------------------------- |
| ネットワーク切断 | オフラインでクエリ実行     | エラーメッセージ表示       |
| 再試行           | ネットワーク復旧後に再試行 | 正常にクエリ実行可能       |
| 中断             | 実行中に中断ボタンクリック | 実行が停止、状態がリセット |
| 認証エラー       | 無効な認証状態でクエリ     | 認証エラーメッセージ表示   |

**期待される成果物**:

- エラー処理テスト結果

---

### タスク4: 権限確認テスト

**目的**: 権限確認ダイアログが正しく動作することを確認する。

**実行手順**:

1. ツール使用を要求するプロンプトを入力
2. 権限確認ダイアログの表示を確認
3. 許可ボタンの動作を確認
4. 拒否ボタンの動作を確認
5. 「今後も許可」オプションの動作を確認

**テストシナリオ**:

| シナリオ     | 操作                     | 期待結果               |
| ------------ | ------------------------ | ---------------------- |
| 権限確認表示 | ツール使用プロンプト実行 | 権限確認ダイアログ表示 |
| 許可         | 許可ボタンクリック       | ツール実行が継続       |
| 拒否         | 拒否ボタンクリック       | ツール実行がスキップ   |
| 永続許可     | 「今後も許可」選択→許可  | 次回から確認なしで実行 |

**期待される成果物**:

- 権限確認テスト結果

---

### タスク5: UI/UXテスト

**目的**: ユーザーインターフェースとユーザー体験が適切であることを確認する。

**実行手順**:

1. 画面レイアウトの確認
2. レスポンシブ動作の確認（ウィンドウリサイズ）
3. ローディング状態の表示確認
4. エラー状態の表示確認
5. 操作の直感性確認

**確認項目**:

| 項目         | 確認内容             | 結果  |
| ------------ | -------------------- | ----- |
| レイアウト   | 崩れがないか         | OK/NG |
| レスポンシブ | リサイズ時の表示     | OK/NG |
| ローディング | 進行状況がわかるか   | OK/NG |
| エラー表示   | エラーが明確か       | OK/NG |
| 操作性       | 直感的に操作できるか | OK/NG |

**期待される成果物**:

- UI/UXテスト結果

---

### タスク6: パフォーマンス体感テスト

**目的**: 実際の使用感としてパフォーマンスが許容範囲内であることを確認する。

**実行手順**:

1. 複数回のクエリ実行で応答速度を体感
2. 長時間使用後の動作を確認
3. 複数セッションの切り替えを確認
4. メモリ使用量を確認

**確認項目**:

| 項目               | 確認内容                         | 結果  |
| ------------------ | -------------------------------- | ----- |
| 初回応答           | ストレスなく応答が始まるか       | OK/NG |
| ストリーミング     | スムーズにテキストが表示されるか | OK/NG |
| 長時間使用         | 遅延や不安定さがないか           | OK/NG |
| セッション切り替え | 素早く切り替わるか               | OK/NG |

**期待される成果物**:

- パフォーマンス体感テスト結果
