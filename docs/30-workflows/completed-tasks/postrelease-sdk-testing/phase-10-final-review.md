## 目的

手動テストおよびドキュメント作成前に、実装とテストの完全性を最終確認する。

## 背景

Phase 9までで実装・テスト・品質検証が完了した。本Phaseでは、手動テストに進む前に、すべての成果物が要件を満たしているかを最終確認する。問題があればこのPhaseで指摘し、適切なPhaseへ戻って修正を行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1で定義した要件がすべて満たされているかを確認する。

**実行手順**:

1. 要件定義書を参照
2. 各要件に対応する実装・テストを確認
3. 要件充足マトリクスを作成
4. 未充足要件があれば特定

**確認項目**:

| 要件カテゴリ   | 確認内容                         | 結果      |
| -------------- | -------------------------------- | --------- |
| E2Eテスト      | SDK接続テストが実装されているか  | PASS/FAIL |
| パフォーマンス | 目標値を達成しているか           | PASS/FAIL |
| 安定性         | メモリリーク・クラッシュがないか | PASS/FAIL |
| ネットワーク   | 障害テストが実装されているか     | PASS/FAIL |

**期待される成果物**:

- 要件充足マトリクス

---

### タスク2: テストカバレッジ最終確認

**目的**: テストカバレッジが基準を満たしていることを最終確認する。

**実行手順**:

1. カバレッジレポートを確認
2. 基準値との比較
3. 未カバー箇所の妥当性確認
4. 必要に応じて追加テストを指示

**カバレッジ基準**:

| メトリクス | 目標    | 実績 | 判定      |
| ---------- | ------- | ---- | --------- |
| Line       | 80%以上 | XX%  | PASS/FAIL |
| Branch     | 60%以上 | XX%  | PASS/FAIL |
| Function   | 80%以上 | XX%  | PASS/FAIL |

**期待される成果物**:

- カバレッジ最終確認結果

---

### タスク3: SDK統合状態確認

**目的**: 実SDKとの統合が正しく行われていることを確認する。

**実行手順**:

1. SDKバージョンを確認
2. API呼び出しパターンを確認
3. ストリーミング処理を確認
4. エラーハンドリングを確認
5. セッション管理を確認

**確認項目**:

| 項目               | 確認内容                         | 結果      |
| ------------------ | -------------------------------- | --------- |
| SDKバージョン      | 最新版を使用しているか           | PASS/FAIL |
| query()            | 正しく呼び出されているか         | PASS/FAIL |
| createSession()    | セッション管理が適切か           | PASS/FAIL |
| abort()            | 中断処理が正しいか               | PASS/FAIL |
| onMessage          | ストリーミングが機能しているか   | PASS/FAIL |
| エラーハンドリング | AgentError階層が処理されているか | PASS/FAIL |

**期待される成果物**:

- SDK統合確認結果

---

### タスク4: 総合判定

**目的**: 全確認結果を総合し、次のPhaseに進めるかを判定する。

**実行手順**:

1. 全確認結果を集約
2. 問題点を重要度で分類
3. 判定結果を決定
4. 次のアクションを文書化

**判定マトリクス**:

| 確認項目         | 結果      | 重要度   |
| ---------------- | --------- | -------- |
| 要件充足         | PASS/FAIL | Critical |
| テストカバレッジ | PASS/FAIL | High     |
| SDK統合状態      | PASS/FAIL | Critical |
| 品質メトリクス   | PASS/FAIL | High     |

**期待される成果物**:

- 最終レビュー結果

## 判定基準

| 判定     | 条件             | 対応                         |
| -------- | ---------------- | ---------------------------- |
| PASS     | 全項目でPASS     | Phase 11へ進行               |
| MINOR    | 軽微な問題あり   | 問題を記録しPhase 11へ進行   |
| MAJOR    | 重大な問題あり   | 影響範囲に応じて戻り先を決定 |
| CRITICAL | 致命的な問題あり | Phase 1へ戻り要件再確認      |

### 戻り先決定基準

| 問題の種類           | 戻り先                |
| -------------------- | --------------------- |
| 要件不備             | Phase 1（要件定義）   |
| 設計不備             | Phase 2（設計）       |
| テスト不足           | Phase 4（テスト作成） |
| 実装不備             | Phase 5（実装）       |
| カバレッジ不足       | Phase 6（テスト拡充） |
| リファクタリング不足 | Phase 8（リファクタ） |
| 品質基準未達         | Phase 9（品質検証）   |
