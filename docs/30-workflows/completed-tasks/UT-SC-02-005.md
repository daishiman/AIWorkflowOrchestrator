## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

UT-SC-02-002 で `RuntimeSkillCreatorFacade.execute()` に `terminal_handoff` 分岐を追加し、IPC ハンドラ（`creatorHandlers.ts`）の戻り値型も `RuntimeSkillCreatorExecuteResponse`（Union 型）に更新された。しかし、Preload 層（`skill-creator-api.ts`）の `executePlan` 戻り値型が旧型 `RuntimeSkillCreatorExecuteResult` のまま追従していない。

これは P44（IPC インターフェース不整合）と P45（IPC 引数命名の契約ドリフト）の典型的な複合パターンである。

### 1.2 問題点・課題

| 問題                      | 詳細                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Preload 型定義の不整合    | `skill-creator-api.ts` の `executePlan` 戻り値型が `IpcResult<RuntimeSkillCreatorExecuteResult>` のまま          |
| Renderer 型ナロイング欠如 | `SkillLifecyclePanel.tsx` が `result.data.skillName` に直接アクセスし、`terminal_handoff` ケースを考慮していない |
| IPC 3層契約の型不一致     | Main Process（正） → Preload（誤） → Renderer（誤）で型が途切れている                                            |

### 1.3 放置した場合の影響

- `terminal_handoff` レスポンスが実際に返却された場合、Renderer 側で `result.data.skillName` が `undefined` になり、予期しない動作（サイレント失敗）が発生する
- TypeScript の型チェックが P44 パターンを検出できず、型安全性のガードが機能しない
- 今後の `terminal_handoff` UI 実装時に改めて型修正が必要になり、手戻りが発生する

## 2. 何を達成するか（What）

### 2.1 目的

Preload 層の `executePlan` 戻り値型を IPC ハンドラと一致させ、Renderer 側で `terminal_handoff` ケースの型ナロイングを実装することで、IPC 3層の型契約を完全に統一する。

### 2.2 最終ゴール

- Preload API、IPC ハンドラ、Renderer の3層で `RuntimeSkillCreatorExecuteResponse` Union 型が一貫して使用されている
- Renderer 側で `terminal_handoff` レスポンスが型安全にハンドリングされている

### 2.3 スコープ

#### 含むもの

- `skill-creator-api.ts` の `executePlan` 戻り値型を `RuntimeSkillCreatorExecuteResponse` に変更
- `SkillLifecyclePanel.tsx` の `handleExecutePlan` に `terminal_handoff` 型ナロイングを追加
- P42 準拠の3段バリデーション確認（既存 `creatorHandlers.ts` の `isBlank()` 確認のみ）
- 関連テストの型アサーション更新

#### 含まないもの

- `terminal_handoff` 時の Renderer UI 実装（別タスクスコープ）
- `RuntimeSkillCreatorFacade.execute()` のロジック変更（UT-SC-02-002 で完了済み）
- `creatorHandlers.ts` の IPC ハンドラ修正（既に正しい型を使用済み）
- 新規型定義の追加（`RuntimeSkillCreatorExecuteResponse` は既に定義済み）

### 2.4 成果物

| 成果物                                     | 説明                                    |
| ------------------------------------------ | --------------------------------------- |
| `skill-creator-api.ts` 型修正              | `executePlan` 戻り値型を Union 型に更新 |
| `SkillLifecyclePanel.tsx` 型ナロイング追加 | `terminal_handoff` ケースのハンドリング |
| テストファイル更新                         | 型変更に伴うアサーション修正            |

| タスク       | 状態   | 内容                                   |

IPC 3層の型を「下流（Main）から上流（Renderer）に向けて」統一する。

```
Step 1: Preload 層の型シグネチャ修正
Step 2: Renderer 層の型ナロイング追加
Step 3: テスト更新・型チェック確認
```
