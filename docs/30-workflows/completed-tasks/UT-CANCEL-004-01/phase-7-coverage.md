## 目的

`createSkill` の `signal` 引数追加に関わる変更行・分岐のカバレッジを可視化し、
テストが不足しているパスを特定する。

小規模タスク（2 ファイル・3 箇所の修正）の特性として、変更箇所が限定的であるため
**変更行の行カバレッジ 80% 以上** を必達目標とし、分岐カバレッジは 60% 以上を推奨とする。

Phase 8 のリファクタリングへ安全に移行できる状態を確立することが最終目標。

## 実行タスク

### タスク 1: カバレッジ計測

**目的**: `agentSlice.ts` の `createSkill` 変更行と `SkillCreateWizard.tsx` の修正箇所のカバレッジを算出する。

**実行手順**:

```bash
# agentSlice の createSkill signal テストのカバレッジ計測
pnpm --filter @repo/desktop test agentSlice.createSkill.signal --coverage

# SkillCreateWizard のカバレッジ計測
pnpm --filter @repo/desktop test SkillCreateWizard --coverage
```

**確認すべき変更行（agentSlice.ts）**:

| 変更行                                               | 内容                | 対応テスト                                           |
| ---------------------------------------------------- | ------------------- | ---------------------------------------------------- |
| `createSkill` シグネチャの `signal?: AbortSignal` 行 | 引数追加            | TC-01・TC-02（型定義行はカバレッジ対象外の場合あり） |
| `signal?.aborted` チェック行                         | early return ガード | TC-ABORT-01                                          |

**確認すべき変更行（SkillCreateWizard.tsx）**:

| 変更行                                    | 内容         | 対応テスト           |
| ----------------------------------------- | ------------ | -------------------- |
| `const signal = startGeneration()` 行     | 返値受け取り | TC-WIZ-01・TC-WIZ-03 |
| `createSkill(..., signal)` の signal 引数 | signal 渡し  | TC-WIZ-01・TC-WIZ-03 |

**期待される成果物**: `outputs/phase-7/coverage-report.md`

### タスク 2: ゲート判定

**目的**: カバレッジが目標値を満たすかを判定し、Phase 8 への進行可否を決定する。

**カバレッジ目標**:

| 指標                                         | 最低基準 | 推奨基準 | 備考                                       |
| -------------------------------------------- | -------- | -------- | ------------------------------------------ |
| `createSkill` 変更行 ライン カバレッジ       | 80%      | 90%      | 必達。未達の場合は Phase 6 へ戻る          |
| `createSkill` 分岐カバレッジ                 | 60%      | 70%      | signal あり・なし・aborted の 3 分岐が対象 |
| `SkillCreateWizard` 変更行 ライン カバレッジ | 80%      | 90%      | 必達                                       |

**確認すべき分岐一覧**（createSkill 内）:

| 分岐                                                       | 対応テスト ID                 | カバレッジ状況      |
| ---------------------------------------------------------- | ----------------------------- | ------------------- |
| `signal` が存在して store に渡り、IPC guard を通過する場合 | TC-01                         | Phase 4〜6 でカバー |
| `signal` が `undefined` で従来どおり IPC を呼ぶ場合        | TC-02・TC-COMPAT-01           | Phase 4〜6 でカバー |
| `signal.aborted` が `true` の場合（早期リターン）          | TC-ABORT-01                   | Phase 6 でカバー    |
| IPC がエラーを返した場合（catch ブロック）                 | TC-ABORT-02・既存エラーテスト | Phase 6 でカバー    |

**ゲート判定基準**:

| 判定             | 条件                                                            | 次のアクション                                                      |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| PASS             | 変更行ライン カバレッジが 80% 以上かつ分岐カバレッジが 60% 以上 | Phase 8（リファクタリング）へ進む                                   |
| CONDITIONAL PASS | ライン 80% 以上だが分岐 60% 未満                                | 不足分を `coverage-report.md` に記録して Phase 8 へ進む（推奨のみ） |
| FAIL             | ライン 80% 未満                                                 | Phase 6 へ戻り不足テストを追加する                                  |

### タスク 3: カバレッジ不足パスの特定と対処

**目的**: カバレッジレポートで検出された未カバーの行・分岐を特定し、対処方針を決定する。

**実行手順**:

1. カバレッジレポートの `createSkill` 関数行を確認し、`0x` 表示（未カバー）の行を列挙する
2. 未カバーの行・分岐がある場合、以下のいずれかで対処する

| 対処方針                                   | 適用条件                                            |
| ------------------------------------------ | --------------------------------------------------- |
| 本 Phase 内でテストを追加してカバーする    | 軽微な追加で対応可能（1〜2 テストケースで済む）場合 |
| Phase 6 へ差し戻して不足テストを追加する   | 複数のテストケース追加が必要な場合                  |
| 除外理由を `coverage-report.md` に明記する | 到達不可能なパス・意図的にテスト対象外とする箇所    |

---

### タスク 4: テスト実行時間の計測

**目的**: 追加されたテスト群が CI 実行時間に与える影響を計測し、許容範囲内であることを確認する。

**実行手順**:

```bash
# signal テストの実行時間計測
pnpm --filter @repo/desktop test agentSlice.createSkill.signal --reporter=verbose

# SkillCreateWizard テストの実行時間計測
pnpm --filter @repo/desktop test SkillCreateWizard --reporter=verbose
```

**評価基準**:

| 対象                                            | 許容基準  | 備考                                     |
| ----------------------------------------------- | --------- | ---------------------------------------- |
| `agentSlice.createSkill.signal.test.ts` 単体    | 15 秒以内 | 小規模タスクのため厳しめに設定           |
| `SkillCreateWizard.test.tsx` 単体（追加分込み） | 30 秒以内 | コンポーネントテストのため余裕を持たせる |
