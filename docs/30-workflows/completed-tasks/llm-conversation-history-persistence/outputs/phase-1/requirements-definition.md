## 機能要件（FR: Functional Requirements）

### FR-01: 会話自動保存

| 項目   | 内容                                                   |
| ------ | ------------------------------------------------------ |
| 優先度 | 高                                                     |
| 詳細   | 新規会話・メッセージ送信時に自動でDBに保存             |
| 根拠   | ユーザーの意識的な操作なしにデータが永続化される必要性 |
| 技術   | SQLite (better-sqlite3) を使用、Main ProcessでDB操作   |

**サブ要件:**

- FR-01-1: 新規メッセージ送信時に`chat_messages`テーブルにレコード作成
- FR-01-2: 会話が存在しない場合は`chat_sessions`テーブルに新規レコード作成
- FR-01-3: メッセージ追加時に`chat_sessions.message_count`を更新
- FR-01-4: メッセージ追加時に`chat_sessions.updated_at`を更新
- FR-01-5: メッセージ追加時に`chat_sessions.last_message_preview`を更新

### FR-02: 会話復元

| 項目   | 内容                                        |
| ------ | ------------------------------------------- |
| 優先度 | 高                                          |
| 詳細   | アプリ起動時に前回の会話一覧を復元          |
| 根拠   | アプリ再起動後もユーザーの作業継続性を保証  |
| 技術   | Redux Store初期化時にDBから会話一覧をロード |

**サブ要件:**

- FR-02-1: アプリ起動時に`chat_sessions`テーブルから会話一覧を取得
- FR-02-2: 会話選択時に`chat_messages`テーブルからメッセージ履歴を取得
- FR-02-3: 復元データをRedux Storeに反映

### FR-03: 会話一覧表示

| 項目   | 内容                                     |
| ------ | ---------------------------------------- |
| 優先度 | 高                                       |
| 詳細   | 保存された会話を一覧表示                 |
| 根拠   | ユーザーが過去の会話を把握・選択するため |
| 技術   | Rendererコンポーネントで一覧UI実装       |

**サブ要件:**

- FR-03-1: 会話タイトル表示
- FR-03-2: 最終更新日時表示
- FR-03-3: メッセージ数表示
- FR-03-4: 最新順ソート（updated_at DESC）
- FR-03-5: ピン留め会話の上部表示

### FR-04: 会話選択・継続

| 項目   | 内容                                       |
| ------ | ------------------------------------------ |
| 優先度 | 高                                         |
| 詳細   | 過去の会話を選択し、続きから対話できる     |
| 根拠   | 会話のコンテキストを維持した継続対話のため |
| 技術   | conversationIdを用いたメッセージ紐付け     |

**サブ要件:**

- FR-04-1: 会話選択時にメッセージ履歴をロード
- FR-04-2: 選択した会話のconversationIdを新規メッセージに付与
- FR-04-3: LLMへのリクエストにconversationIdを含める

### FR-05: 会話削除

| 項目   | 内容                                   |
| ------ | -------------------------------------- |
| 優先度 | 中                                     |
| 詳細   | 不要な会話を削除                       |
| 根拠   | ストレージ管理とプライバシー保護       |
| 技術   | ソフトデリート（deleted_atカラム設定） |

**サブ要件:**

- FR-05-1: 会話削除時に`deleted_at`を設定
- FR-05-2: 削除した会話は一覧から非表示
- FR-05-3: CASCADE DELETEでメッセージも論理削除

### FR-06: 会話タイトル自動生成

| 項目   | 内容                                            |
| ------ | ----------------------------------------------- |
| 優先度 | 中                                              |
| 詳細   | 最初のメッセージから会話タイトルを自動生成      |
| 根拠   | ユーザーの入力負担軽減                          |
| 技術   | 最初のメッセージの先頭N文字をタイトルとして使用 |

**サブ要件:**

- FR-06-1: 最初のユーザーメッセージから最大50文字を抽出
- FR-06-2: 新規会話作成時に自動設定

### FR-07: 会話タイトル編集

| 項目   | 内容                               |
| ------ | ---------------------------------- |
| 優先度 | 低                                 |
| 詳細   | ユーザーが会話タイトルを編集可能   |
| 根拠   | ユーザーによるカスタマイズ需要     |
| 技術   | IPCハンドラーでタイトル更新API提供 |

**サブ要件:**

- FR-07-1: タイトル編集UIを提供
- FR-07-2: タイトル更新API（conversation:update）

### FR-08: 会話検索

| 項目   | 内容                                   |
| ------ | -------------------------------------- |
| 優先度 | 低                                     |
| 詳細   | キーワードで会話を検索                 |
| 根拠   | 大量の会話から目的の会話を効率的に発見 |
| 技術   | SQLiteのLIKE検索（基本実装）           |

**サブ要件:**

- FR-08-1: タイトルでのキーワード検索
- FR-08-2: 検索結果を一覧表示

## 非機能要件（NFR: Non-Functional Requirements）

### NFR-01: パフォーマンス

| 項目   | 内容                                     |
| ------ | ---------------------------------------- |
| 優先度 | 高                                       |
| 基準   | 会話一覧の読み込み時間: 100会話で1秒以内 |
| 測定   | コンソールでの時間計測                   |

**サブ要件:**

- NFR-01-1: 会話一覧取得は軽量データのみ（メッセージ本文を含まない）
- NFR-01-2: インデックスを適切に設定
- NFR-01-3: メッセージ履歴は遅延読み込み（選択時のみ）

### NFR-02: データ整合性

| 項目   | 内容                               |
| ------ | ---------------------------------- |
| 優先度 | 高                                 |
| 基準   | メッセージの順序・内容の整合性保証 |
| 技術   | トランザクション必須               |

**サブ要件:**

- NFR-02-1: メッセージ挿入・更新はトランザクション内で実行
- NFR-02-2: message_indexによる順序保証
- NFR-02-3: 外部キー制約によるセッション-メッセージ関連の整合性

### NFR-03: ストレージ効率

| 項目   | 内容                     |
| ------ | ------------------------ |
| 優先度 | 中                       |
| 基準   | DBファイルサイズの適正化 |
| 技術   | WALモード使用            |

**サブ要件:**

- NFR-03-1: WALモード有効化
- NFR-03-2: 定期的なVACUUM検討（将来タスク）

### NFR-04: 型安全性

| 項目   | 内容                             |
| ------ | -------------------------------- |
| 優先度 | 高                               |
| 基準   | TypeScriptによる型安全なアクセス |
| 技術   | コンパイルエラーなし             |

**サブ要件:**

- NFR-04-1: Repository層でのDrizzle ORM使用
- NFR-04-2: IPC通信での型定義
- NFR-04-3: Redux Store型との整合性

### NFR-05: エラー耐性

| 項目   | 内容                                 |
| ------ | ------------------------------------ |
| 優先度 | 高                                   |
| 基準   | DB接続エラー時の適切なフォールバック |
| 技術   | ユーザーへの明示的通知               |

**サブ要件:**

- NFR-05-1: DB接続エラー時にエラーメッセージ表示
- NFR-05-2: トランザクション失敗時のロールバック
- NFR-05-3: エラー発生時もアプリがクラッシュしない

## IPC接続要件

### IPCチャンネル定義

| チャンネル               | 方向          | 入力                            | 出力                       |
| ------------------------ | ------------- | ------------------------------- | -------------------------- |
| conversation:list        | Renderer→Main | { userId, limit?, offset? }     | ConversationSummary[]      |
| conversation:get         | Renderer→Main | { conversationId }              | Conversation with Messages |
| conversation:create      | Renderer→Main | { userId, title, firstMessage } | Conversation               |
| conversation:update      | Renderer→Main | { conversationId, updates }     | Conversation               |
| conversation:delete      | Renderer→Main | { conversationId }              | { success: boolean }       |
| conversation:add-message | Renderer→Main | { conversationId, message }     | ChatMessage                |

### データフロー

```
Renderer(Redux) → IPC → Main(Repository) → SQLite → Main → IPC → Renderer(Redux)
```

### エラーハンドリング

| エラー種別     | 処理                             |
| -------------- | -------------------------------- |
| DB接続エラー   | Renderer側でエラートースト表示   |
| 制約違反エラー | Renderer側でエラーメッセージ表示 |
| 不明なエラー   | 汎用エラーメッセージ表示         |
