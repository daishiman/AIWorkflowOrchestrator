## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、実装に進む前に品質を確認する。
問題があれば適切なPhaseに戻り、修正を行う。

## 背景

TDDサイクルに入る前に設計の妥当性を検証することで、手戻りを最小化する。
特にIPC通信はセキュリティに関わるため、慎重なレビューが必要。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件レビュー

**目的**: Phase 1の成果物が適切かを検証する。

**実行手順**:

1. `outputs/phase-1/requirements-analysis.md` を確認する
2. `outputs/phase-1/ipc-channel-spec.md` を確認する
3. `outputs/phase-1/acceptance-criteria.md` を確認する
4. ui-ux-history-panel.md との整合性を検証する
5. レビュー結果を `outputs/phase-3/requirements-review.md` に記録する

**レビュー観点**:

- [ ] IPCチャンネル名が仕様と一致しているか
- [ ] パラメータ・戻り値型が仕様と一致しているか
- [ ] Result型パターンが正しく適用されているか
- [ ] 受け入れ基準が測定可能か

**期待される成果物**:

- `outputs/phase-3/requirements-review.md`（要件レビュー結果）

---

### タスク2: 設計レビュー

**目的**: Phase 2の成果物が適切かを検証する。

**実行手順**:

1. `outputs/phase-2/design-document.md` を確認する
2. Electronセキュリティベストプラクティスとの整合性を検証する
3. 既存のIPCハンドラー実装パターンとの一貫性を検証する
4. レビュー結果を `outputs/phase-3/design-review.md` に記録する

**レビュー観点**:

- [ ] contextIsolation: true が前提となっているか
- [ ] ipcMain.handle パターンを使用しているか
- [ ] DI（依存性注入）パターンが適用されているか
- [ ] エラーハンドリングが適切か

**期待される成果物**:

- `outputs/phase-3/design-review.md`（設計レビュー結果）

---

### タスク3: 統合テスト観点レビュー

**目的**: IPC統合テストの観点が十分かを検証する。

**実行手順**:

1. Phase 1で定義した統合テスト要件を確認する
2. IPC通信の境界テスト観点を検証する
3. エラー伝播のテスト観点を検証する
4. レビュー結果を `outputs/phase-3/integration-review.md` に記録する

**レビュー観点**:

- [ ] Renderer → Main 通信のテスト観点があるか
- [ ] Main → HistoryService 接続のテスト観点があるか
- [ ] エラー時のResult型返却テスト観点があるか
- [ ] 境界値・異常系のテスト観点があるか

**期待される成果物**:

- `outputs/phase-3/integration-review.md`（統合テスト観点レビュー結果）

---

### タスク4: レビュー結果判定

**目的**: レビュー結果を総合判定し、次のアクションを決定する。

**実行手順**:

1. タスク1〜3のレビュー結果を集約する
2. 判定基準に従って総合判定を行う
3. `outputs/phase-3/review-judgment.md` に判定結果を記録する

**期待される成果物**:

- `outputs/phase-3/review-judgment.md`（レビュー判定結果）

## レビューゲート判定基準

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
