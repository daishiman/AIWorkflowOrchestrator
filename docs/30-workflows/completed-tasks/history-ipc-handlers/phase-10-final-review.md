## 目的

全体の品質と整合性を最終確認し、手動テストに進む前の最終ゲートとする。
要件・設計・実装・テストの整合性を検証する。

## 背景

Phase 9までで機能実装と品質保証が完了している。本Phaseでは、全体を俯瞰して最終確認を行い、手動テストに進む準備が整っていることを確認する。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足レビュー

**目的**: Phase 1で定義した要件が全て満たされているか確認する。

**実行手順**:

1. `outputs/phase-1/acceptance-criteria.md` を確認する
2. 各受け入れ基準が満たされているか検証する
3. `outputs/phase-10/requirements-fulfillment-review.md` に結果を記録する

**レビュー観点**:

- [ ] 4つのIPCハンドラーが実装されている
- [ ] Result型で統一された形式で返却される
- [ ] エラーハンドリングが適切に実装されている
- [ ] 全てのテストが成功している

**期待される成果物**:

- `outputs/phase-10/requirements-fulfillment-review.md`（要件充足レビュー結果）

---

### タスク2: 設計整合性レビュー

**目的**: 実装がPhase 2の設計に従っているか確認する。

**実行手順**:

1. `outputs/phase-2/design-document.md` を確認する
2. 実装コードが設計に従っているか検証する
3. `outputs/phase-10/design-consistency-review.md` に結果を記録する

**レビュー観点**:

- [ ] ファイル構成が設計通りである
- [ ] 関数インターフェースが設計通りである
- [ ] エラーハンドリングが設計通りである
- [ ] 型定義が設計通りである

**期待される成果物**:

- `outputs/phase-10/design-consistency-review.md`（設計整合性レビュー結果）

---

### タスク3: 統合テスト結果確認

**目的**: IPC統合テストの結果を最終確認する。

**実行手順**:

1. 全統合テストを実行する
2. 全テストが成功することを確認する
3. カバレッジが基準を満たしていることを確認する
4. `outputs/phase-10/integration-test-final-review.md` に結果を記録する

**期待される成果物**:

- `outputs/phase-10/integration-test-final-review.md`（統合テスト最終確認結果）

---

### タスク4: 品質レポート確認

**目的**: Phase 9の品質レポートを確認し、問題がないことを確認する。

**実行手順**:

1. `outputs/phase-9/quality-report.md` を確認する
2. 全品質基準が満たされていることを確認する
3. `outputs/phase-10/quality-final-review.md` に結果を記録する

**期待される成果物**:

- `outputs/phase-10/quality-final-review.md`（品質最終確認結果）

---

### タスク5: 最終レビュー判定

**目的**: 全レビュー結果を統合し、最終判定を行う。

**実行手順**:

1. タスク1〜4のレビュー結果を集約する
2. 判定基準に従って総合判定を行う
3. `outputs/phase-10/final-review-judgment.md` に判定結果を記録する

**期待される成果物**:

- `outputs/phase-10/final-review-judgment.md`（最終レビュー判定結果）

## レビューゲート判定基準

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11へ進行            |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 11へ    |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
