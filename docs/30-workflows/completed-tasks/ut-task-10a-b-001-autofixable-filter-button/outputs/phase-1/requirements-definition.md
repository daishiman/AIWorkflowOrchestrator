## 機能要件（FR）

| ID   | 要件                                                                     | 検証観点                         |
| ---- | ------------------------------------------------------------------------ | -------------------------------- |
| FR-1 | `autoFixable === true` の提案だけを一括選択するUI操作を提供する          | ボタン押下後の選択Set            |
| FR-2 | 一括選択後、そのまま既存の「選択を適用」導線で適用できる                 | `applyImprovements` 呼び出し引数 |
| FR-3 | auto-fixable 提案が0件のときは操作不可（disabled）または無害なガード動作 | disabled/選択状態変化なし        |
| FR-4 | 既存の個別チェックボックス選択・解除を壊さない                           | 既存トグルテスト回帰             |

## 非機能要件（NFR）

| ID    | 要件                                        | 判定基準                |
| ----- | ------------------------------------------- | ----------------------- |
| NFR-1 | キーボード操作でボタンが操作可能            | `button` 要素であること |
| NFR-2 | ラベル/補助情報がスクリーンリーダー解釈可能 | `aria-label` を付与     |
| NFR-3 | 選択更新は O(n) で完了する                  | 提案配列1回走査         |
| NFR-4 | 既存API/IPC契約は変更しない                 | 型/チャネル差分なし     |

## 設計上の前提

- 一括選択は「現在の選択を上書き」して auto-fixable のみ選択状態にする。
- 選択状態は既存仕様どおり `Set<number>`（提案インデックス）を利用する。
- `Suggestion` の `autoFixable` は既存型（`@repo/shared/types/skill-improver`）を利用し、新規型追加は行わない。

## 引き継ぎ（Phase 2 へ）

1. `SuggestionList` に一括選択ボタンを追加する設計を確定する。
2. `useSkillAnalysis` に選択Set再構築ハンドラを追加する。
3. `SkillAnalysisView` で UI と Hook を結線する。
