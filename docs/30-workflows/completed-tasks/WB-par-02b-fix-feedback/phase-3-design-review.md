## レビューチェックリスト

### 構造検証

| チェック項目                                             | 判定     | 備考                                             |
| -------------------------------------------------------- | -------- | ------------------------------------------------ |
| 変更対象ファイルが全件特定されているか                   | REQUIRED | Phase 2で変更対象一覧を確認                      |
| `fetchSkills()`追加箇所が具体的に記述されているか        | REQUIRED | 追加行の前後コンテキストが明示されているか       |
| `skillPath` nullガードのロジックが完全に記述されているか | REQUIRED | null時・非null時の両ケースが設計されているか     |
| エラー表示UIの設計が完成しているか                       | REQUIRED | 文言・アクション・スタイルが全て設計されているか |
| AC-1〜AC-5との整合が確認されているか                     | REQUIRED | 各ACが設計で充足されているか                     |

### 4条件評価

| 条件   | 評価観点                                                 | 合否基準                                       |
| ------ | -------------------------------------------------------- | ---------------------------------------------- |
| 価値性 | 2ファイル・5行未満の変更で問題6/8/14/20を解消できるか    | 修正コスト対効果が明確に定義されている         |
| 実現性 | `fetchSkills`が既存のスコープ内で呼び出し可能か          | 関数の存在・スコープが確認されている           |
| 整合性 | templateモードの既存動作を破壊しないか                   | 変更範囲がLLMモード専用パスに限定されている    |
| 運用性 | `skillPath = null`のエラー状態がユーザーに明確に伝わるか | エラーメッセージとリトライ誘導が設計されている |

### 責務境界確認

| 境界                                                     | 問題なし | 備考                                     |
| -------------------------------------------------------- | -------- | ---------------------------------------- |
| `fetchSkills()`追加がLLMモード専用パスに限定されているか | -        | templateモードへの影響がないことを確認   |
| `skillPath`が`null`になる根本原因の修正を含まないか      | -        | 根本原因修正はWave Aタスク（スコープ外） |
| エラーUI変更が`CompleteStep`のprops契約を壊さないか      | -        | 既存のプロパティ型定義との整合を確認     |

## フェーズゲート判定基準

### PASS条件（全て満たすとPhase 4へ進む）

- [ ] 変更対象ファイルが全件特定されている
- [ ] `fetchSkills()`追加箇所の具体的な実装が確定している
- [ ] `skillPath` nullガードのロジック（null時・非null時）が明示されている
- [ ] エラー表示UIの文言・アクションが確定している
- [ ] 4条件（価値性・実現性・整合性・運用性）が全てPASS
- [ ] AC-1〜AC-5全てが設計で充足されている
- [ ] templateモードへの影響がゼロであることが確認されている

### FAIL条件（Phase 2へ差し戻し）

- 変更対象ファイルが未特定のものがある
- `fetchSkills()`の追加箇所が「成功パス末尾」程度の抽象記述にとどまっている
- nullガードの両ケース（null時/非null時）のどちらかが未設計
- エラー文言・リトライアクションが未定義
- 4条件のいずれかがFAIL
