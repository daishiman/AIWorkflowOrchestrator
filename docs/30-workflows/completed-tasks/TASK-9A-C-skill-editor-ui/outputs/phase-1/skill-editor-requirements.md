## 1. 機能要件

### 1.1 ファイルツリーサイドバー

| ID          | 要件                                                                                                                                            | 優先度 |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| FR-TREE-001 | `ImportedSkill` 型の `agents`, `references`, `scripts`, `assets`, `schemas`, `indexes`, `otherFiles` プロパティからツリー構造を構築する         | 必須   |
| FR-TREE-002 | 各 `SkillSubResource` の `relativePath` をツリーノードの一意キーとして使用する                                                                  | 必須   |
| FR-TREE-003 | `SkillOtherFile` は「その他」カテゴリとしてツリーに表示する。`SkillOtherFile` は `relativePath` を持たないため、`filename` をキーとして使用する | 必須   |
| FR-TREE-004 | 空のカテゴリ（ファイルが0件の配列）はツリーに表示しない                                                                                         | 必須   |
| FR-TREE-005 | カテゴリの表示順序は以下の固定順とする: agents, references, scripts, assets, schemas, indexes, その他                                           | 必須   |
| FR-TREE-006 | ファイルをクリック（選択）した際に `selectedFile` 状態を該当ファイルの `relativePath`（またはその他ファイルの場合は `filename`）に更新する      | 必須   |
| FR-TREE-007 | 選択中のファイルはハイライト表示する。ライトモード: `bg-blue-50`、ダークモード: `bg-blue-900/20`                                                | 必須   |
| FR-TREE-008 | カテゴリはデフォルトで展開状態とする（折りたたみ可能）                                                                                          | 推奨   |
| FR-TREE-009 | サイドバーの幅は `w-64`（256px）固定とし、縦方向にスクロール可能（`overflow-y-auto`）とする                                                     | 必須   |
| FR-TREE-010 | サイドバーのヘッダーにスキル名（`skill.name`）を表示する                                                                                        | 必須   |

### 1.3 ツールバー

| ID             | 要件                                                                                                                                          | 優先度 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| FR-TOOLBAR-001 | 保存ボタンを表示する。`hasChanges` が `false` または `isSaving` が `true` の場合、ボタンを無効化する（`disabled` 属性）                       | 必須   |
| FR-TOOLBAR-002 | `isSaving` が `true` の間、保存ボタンにスピナーアイコンを表示し、テキストを「保存中...」に変更する                                            | 必須   |
| FR-TOOLBAR-003 | 閉じるボタンを表示する。クリック時に `hasChanges` が `true` の場合、確認ダイアログを表示する                                                  | 必須   |
| FR-TOOLBAR-004 | 確認ダイアログのメッセージ: 「未保存の変更があります。破棄しますか?」。選択肢: 「破棄」「キャンセル」                                         | 必須   |
| FR-TOOLBAR-005 | 保存ショートカットキー: macOS では `Cmd+S`（`metaKey + s`）、Windows/Linux では `Ctrl+S`（`ctrlKey + s`）                                     | 必須   |
| FR-TOOLBAR-006 | ショートカットキー押下時にブラウザデフォルトの保存ダイアログを抑制（`preventDefault`）する                                                    | 必須   |
| FR-TOOLBAR-007 | ファイル名（`selectedFile` の値）をツールバー中央に表示する。フォント: `font-mono text-sm`                                                    | 必須   |
| FR-TOOLBAR-008 | 未保存変更がある場合（`hasChanges` が `true`）、ファイル名の後に「（未保存）」ラベルをバッジ形式（`bg-yellow-100 text-xs rounded`）で表示する | 必須   |
| FR-TOOLBAR-009 | ショートカット `Escape` キーでエディターを閉じる。`hasChanges` が `true` の場合は FR-TOOLBAR-003 と同様に確認ダイアログを表示する             | 必須   |

### 1.4 ローディング・エラーハンドリング

| ID           | 要件                                                                                                                                    | 優先度                                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ---- |
| FR-ERROR-001 | ファイル読み込み中（`isLoading` が `true`）はエディター領域にスピナーと「読み込み中...」テキストを中央寄せで表示する                    | 必須                                                                                               |
| FR-ERROR-002 | ファイル読み込みエラー時はエディター領域にインラインエラーメッセージを表示する。エラーメッセージは赤色テキスト（`text-red-500`）とする  | 必須                                                                                               |
| FR-ERROR-003 | ファイル保存エラー時はトースト通知でエラーメッセージを表示する。トーストは5秒後に自動的に消える                                         | 必須                                                                                               |
| FR-ERROR-004 | エラーメッセージは Main Process からサニタイズ済みの文字列を受け取る。Renderer 側で内部ファイルパスを含むメッセージを表示してはならない | 必須                                                                                               |
| FR-ERROR-005 | 読み込みエラー時にリトライボタンを表示し、クリックで再読み込みを実行できるようにする                                                    | 推奨                                                                                               |
| FR-ERROR-006 | `error` 状態は `string                                                                                                                  | null` 型とし、`null`の場合はエラー表示しない。新しいファイル選択時に`error`を`null` にリセットする | 必須 |

### 1.5 ファイル選択時のフロー

| ID          | 要件                                                                                                                                 | 優先度 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| FR-FLOW-001 | ファイルツリーでファイルをクリックした際、`hasChanges` が `true` の場合は確認ダイアログを表示する（FR-TOOLBAR-004 と同一ダイアログ） | 必須   |
| FR-FLOW-002 | 確認ダイアログで「破棄」を選択した場合、未保存の変更を破棄し、新しいファイルの読み込みを開始する                                     | 必須   |
| FR-FLOW-003 | 確認ダイアログで「キャンセル」を選択した場合、ファイル選択を中止し、現在のファイルの編集状態を維持する                               | 必須   |
| FR-FLOW-004 | ファイル読み込み開始時: `isLoading` を `true`、`error` を `null` に設定する                                                          | 必須   |
| FR-FLOW-005 | ファイル読み込み成功時: `content` にレスポンス内容を設定、`isLoading` を `false`、`hasChanges` を `false` に設定する                 | 必須   |
| FR-FLOW-006 | ファイル読み込み失敗時: `error` にサニタイズ済みエラーメッセージを設定、`isLoading` を `false` に設定する                            | 必須   |

### 1.6 保存フロー

| ID          | 要件                                                                                                      | 優先度 |
| ----------- | --------------------------------------------------------------------------------------------------------- | ------ |
| FR-SAVE-001 | 保存ボタンクリックまたは `Cmd+S` / `Ctrl+S` で保存処理を開始する                                          | 必須   |
| FR-SAVE-002 | 保存開始時: `isSaving` を `true` に設定する                                                               | 必須   |
| FR-SAVE-003 | IPC 経由で `window.electronAPI.skill.writeFile(skillName, selectedFile, content)` を呼び出す              | 必須   |
| FR-SAVE-004 | 保存成功時: `isSaving` を `false`、`hasChanges` を `false` に設定する                                     | 必須   |
| FR-SAVE-005 | 保存失敗時: `isSaving` を `false` に設定し、トースト通知でサニタイズ済みエラーメッセージを表示する        | 必須   |
| FR-SAVE-006 | `hasChanges` が `false` の場合、ショートカットキーによる保存は何もしない（無駄な IPC 呼び出しを防止する） | 必須   |

### 2.3 セキュリティ

| ID          | 要件                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| NFR-SEC-001 | Renderer Process からファイルシステムに直接アクセスしない。全てのファイル操作は IPC 経由で Main Process に委譲する              |
| NFR-SEC-002 | ファイルパスの検証（パストラバーサル防御）は Main Process 側（TASK-9A-B）の責務とする。Renderer 側では検証しない                |
| NFR-SEC-003 | エラーメッセージに内部ファイルパス、スタックトレース、システム情報を含めない。Main Process がサニタイズ済みメッセージを返却する |
| NFR-SEC-004 | `contextBridge` 経由でのみ IPC メソッドを呼び出す。`ipcRenderer` を直接使用しない                                               |
| NFR-SEC-005 | ユーザー入力（ファイル内容）を DOM に直接挿入しない。textarea の `value` プロパティ経由でのみ表示する                           |

## 3. IPC 連携要件 (TASK-9A-B)

### 3.1 readFile API

| 項目     | 値                                                                      |
| -------- | ----------------------------------------------------------------------- |
| API      | `window.electronAPI.skill.readFile(skillName, filePath)`                |
| 引数     | `skillName: string` - スキル名、`filePath: string` - ファイルの相対パス |
| 戻り値   | `Promise<string>` - ファイルの内容（テキスト）                          |
| エラー時 | Promise が reject され、サニタイズ済みエラーメッセージが返却される      |
| パス検証 | Main Process 側でパストラバーサル防御を実施（TASK-9A-B の責務）         |

**呼び出しシーケンス**:

```
Renderer (SkillEditor)
  → window.electronAPI.skill.readFile(skillName, relativePath)
  → Preload (contextBridge)
  → ipcRenderer.invoke("skill:readFile", skillName, relativePath)
  → Main Process (IPC Handler)
  → パストラバーサル検証 → ファイル読み込み → テキスト返却
```

### 3.2 writeFile API

| 項目     | 値                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------- |
| API      | `window.electronAPI.skill.writeFile(skillName, filePath, content)`                                |
| 引数     | `skillName: string` - スキル名、`filePath: string` - ファイルの相対パス、`content: string` - 内容 |
| 戻り値   | `Promise<void>` - 成功時は void で resolve                                                        |
| エラー時 | Promise が reject され、サニタイズ済みエラーメッセージが返却される                                |
| パス検証 | Main Process 側でパストラバーサル防御を実施（TASK-9A-B の責務）                                   |

**呼び出しシーケンス**:

```
Renderer (SkillEditor)
  → window.electronAPI.skill.writeFile(skillName, relativePath, content)
  → Preload (contextBridge)
  → ipcRenderer.invoke("skill:writeFile", skillName, relativePath, content)
  → Main Process (IPC Handler)
  → パストラバーサル検証 → ファイル書き込み → void 返却
```

### 3.3 エラーハンドリング

| エラー種別           | 発生条件                                         | Renderer 側の対応                                                          |
| -------------------- | ------------------------------------------------ | -------------------------------------------------------------------------- |
| ファイル未存在       | 指定パスにファイルが存在しない                   | インラインエラーメッセージを表示                                           |
| パストラバーサル拒否 | `filePath` に `../` 等のトラバーサル文字列を含む | インラインエラーメッセージを表示                                           |
| 権限エラー           | ファイルの読み取り/書き込み権限がない            | インラインエラーメッセージ（読み込み時）またはトースト通知（保存時）を表示 |
| ファイルサイズ超過   | 1MB を超えるファイルの読み込み                   | インラインエラーメッセージを表示                                           |
| スキル未存在         | 指定スキル名のスキルが見つからない               | インラインエラーメッセージを表示                                           |
| IPC 通信タイムアウト | Main Process からの応答が30秒以内にない          | インラインエラーメッセージ（読み込み時）またはトースト通知（保存時）を表示 |

**エラーメッセージのサニタイズ規則**（Main Process 側 - TASK-9A-B の責務）:

- 内部ファイルパスを含まないこと
- スタックトレースを含まないこと
- ユーザーが理解可能な日本語メッセージであること
- 例: 「ファイルの読み込みに失敗しました」「ファイルの保存に失敗しました」「指定されたファイルが見つかりません」

## 5. スコープ外

以下の機能は TASK-9A-C のスコープ外とし、後続タスクまたは別タスクで対応する:

| 項目                                     | 理由                                                               |
| ---------------------------------------- | ------------------------------------------------------------------ |
| シンタックスハイライト                   | テキストエリアベースでは実現が困難。将来 Monaco 等への移行時に対応 |
| 行番号表示                               | textarea では行番号の同期表示が困難。将来の拡張ポイント            |
| 検索・置換機能                           | ブラウザの `Ctrl+F` で代替可能。優先度低                           |
| ファイルの新規作成・削除                 | 編集機能のみが本タスクのスコープ                                   |
| ドラッグ&ドロップによるファイル並び替え  | ファイルツリーは読み取り専用の表示のみ                             |
| バイナリファイル（画像等）のプレビュー   | テキストファイルのみを対象とする                                   |
| 自動保存機能                             | 明示的な保存操作のみ。自動保存は将来タスクで検討                   |
| 差分表示（diff view）                    | 本タスクのスコープ外。将来の拡張ポイント                           |
| IPC ハンドラの実装                       | TASK-9A-B の責務。本タスクは Renderer 側 UI のみ                   |
| Main Process 側のパストラバーサル防御    | TASK-9A-B の責務                                                   |
| SkillEditor の呼び出し元（表示トリガー） | 呼び出し元コンポーネント（SkillDetailPanel 等）は別タスク          |

## 6. 型定義参照

### ImportedSkill 型（`@repo/shared`）

```typescript
interface ImportedSkill extends SkillMetadata {
  importedAt: Date;
  status: "active" | "disabled";
  content?: string;
}

interface SkillMetadata {
  name: string;
  description: string;
  allowedTools?: string[];
  path: string;
  updatedAt: Date;
  agents: SkillSubResource[];
  references: SkillSubResource[];
  scripts: SkillSubResource[];
  assets: SkillSubResource[];
  schemas: SkillSubResource[];
  indexes: SkillSubResource[];
  otherFiles: SkillOtherFile[];
}

interface SkillSubResource {
  filename: string;
  relativePath: string;
  description?: string;
  size: number;
}

interface SkillOtherFile {
  filename: string;
  type: "evals" | "logs" | "package" | "other";
  size: number;
}
```

### buildFileTree ユーティリティ

- **入力**: `ImportedSkill` オブジェクト
- **出力**: `Record<string, SkillSubResource[]>` 型（カテゴリ名をキー、ファイル配列を値）
- **制約**: 空カテゴリ（配列 length が 0）は出力に含めない
- **注意**: `SkillOtherFile` は `SkillSubResource` と型が異なるため、変換処理が必要（`filename` を `relativePath` として使用）

### getLanguage ユーティリティ

- **入力**: ファイル名（`string`）
- **出力**: 言語識別子（`string`）
- **動作**: 拡張子を抽出し、FR-EDITOR-003 のマッピング表に基づいて言語識別子を返却する
