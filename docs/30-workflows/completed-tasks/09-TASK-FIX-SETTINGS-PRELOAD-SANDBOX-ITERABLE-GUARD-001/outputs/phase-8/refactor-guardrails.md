# Phase 8: リファクタリングガード

## 振る舞い維持条件

1. **正常系**: `apiKey.list()` が正しいレスポンスを返す場合、4つのプロバイダー一覧が表示される → 変更なし
2. **異常系**: `apiKey.list()` が失敗した場合、エラーメッセージが表示される → 変更なし（既存の catch ブロック）
3. **追加**: `apiKey.list()` の shape 異常時、空配列 fallback + `console.warn` → 新規追加

## リファクタリング対象判定

| 項目                             | 判定   | 理由                                                    |
| -------------------------------- | ------ | ------------------------------------------------------- |
| loadProviders 関数の分割         | 不要   | 単一責務で十分小さい                                    |
| normalizeHelper の抽出           | 不要   | `Array.isArray` 1行で十分。抽象化は過剰                 |
| 共通オプショナルチェーンパターン | 不要   | AuthKeySection パターンに合わせただけで新規ヘルパー不要 |
| テスト fixture の共通化          | 検討可 | ただし本タスクでは ApiKeysSection のみなので不要        |

## 結論

- Phase 5 の修正は最小限で適切。追加のリファクタリングは不要。
- over-engineering を避け、必要十分な防御のみ残す。
