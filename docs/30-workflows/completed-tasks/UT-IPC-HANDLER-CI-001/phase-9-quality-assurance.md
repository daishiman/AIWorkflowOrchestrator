## 目的

全品質基準を満たしているか総合検証する。コード品質・テスト品質・CI 統合品質の 3 軸で評価し、リスク台帳と因果ループ監査によって将来の回帰リスクを最小化する。

## 実行タスク

### タスク 9-1: 品質レポートの作成

1. 以下の 3 軸で品質状態を評価し、`outputs/phase-9/quality-report.md` にまとめる。

   **コード品質**
   - `pnpm --filter @repo/desktop lint` がエラーなし
   - `pnpm --filter @repo/desktop typecheck` がエラーなし
   - `creatorHandlers.ts` の cyclomatic complexity が許容範囲内

   **テスト品質**
   - `pnpm --filter @repo/desktop test -- --run` が全パス
   - スナップショットファイルがリポジトリにコミット対象として存在する
   - テストケース名が要件 ID（REG-SNAP-01 / REG-DEDUP-01）と対応している

   **CI 統合品質**
   - CI ワークフロー（`.github/workflows/`）でスナップショットテストが実行されている
   - CI 失敗時のエラーメッセージから原因が特定できる

### タスク 9-2: リスク台帳の更新

1. 既知リスクと新規リスクを評価し、`outputs/phase-9/risk-register.md` を作成する。
2. 各リスクに対して影響度・発生確率・対策を記載する。

### タスク 9-3: 因果ループ監査

1. `registerRuntimeSkillCreatorHandlers()` の重複検出ロジックについて、以下の因果ループを検証する。
   - チャンネルが追加される → スナップショットが更新されない → CI が失敗する → 開発者が気づく
   - チャンネルが重複登録される → `ipcMain.handle()` が 2 回呼ばれる → スナップショット差分が出る → CI が失敗する
2. 各因果ループが正しく機能しているかをテストケースとの対応で確認する。
3. 監査結果を `outputs/phase-9/causal-loop-check.md` に記録する。

### タスク 9-4: PR テンプレートへのチェック項目追加の検討

1. `.github/PULL_REQUEST_TEMPLATE.md` を確認し、「スナップショット更新確認」チェック項目が存在するかを確認する。
2. 存在しない場合は追加を検討し、判断結果を `outputs/phase-9/quality-report.md` に記載する。
3. 追加する場合のチェック項目例:
   - `[ ] ipcMain チャンネルを追加・変更した場合、スナップショットを更新した`

## リスク評価

| リスク                                                                         | 影響度 | 発生確率 | 対策                                                               |
| ------------------------------------------------------------------------------ | ------ | -------- | ------------------------------------------------------------------ |
| `ipcMain` の mock が既存テストと競合する                                       | 中     | 低       | 独立したテストファイルに分離し `beforeEach` でリセット             |
| チャンネル追加時のスナップショット更新忘れ                                     | 低     | 中       | PR テンプレートに確認項目を追加                                    |
| スナップショットファイルがコミットされずに CI 失敗                             | 中     | 低       | CI で `--ci` 相当の検証を実行し、未コミット状態を検出              |
| `registerRuntimeSkillCreatorHandlers()` の実装変更で全スナップショットが陳腐化 | 中     | 低       | スナップショット更新は意図的な操作（`--updateSnapshot`）でのみ実施 |
