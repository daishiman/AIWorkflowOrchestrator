## REG-SNAP-01: スナップショット固定

| 項目     | 内容                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| ID       | REG-SNAP-01                                                                                    |
| 目的     | `registerRuntimeSkillCreatorHandlers()` が登録するチャンネル一覧をスナップショットで固定する   |
| 前提条件 | `ipcMain.handle` を spy/mock で置き換えている                                                  |
| 手順     | 1. spy/mock をセットアップする / 2. 関数を呼び出す / 3. 登録チャンネル名配列をソート・抽出する |
| 期待結果 | `expect(handles).toMatchSnapshot()` が既存スナップショット（19 チャンネル）と一致する          |
| 失敗条件 | チャンネルの追加・削除・名称変更があった場合、スナップショット差分が出力されテストが失敗する   |
| 完了基準 | CI でスナップショット差分が検出でき、`--updateSnapshot` なしでは CI が失敗すること             |

## REG-DEDUP-01: 重複チャンネル検出

| 項目     | 内容                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| ID       | REG-DEDUP-01                                                                             |
| 目的     | 同一チャンネル名が複数回 `ipcMain.handle()` で登録されていないことを検証する             |
| 前提条件 | REG-SNAP-01 と同じ spy/mock セットアップ                                                 |
| 手順     | 1. spy/mock をセットアップする / 2. 関数を呼び出す / 3. チャンネル名配列の重複を検査する |
| 期待結果 | `expect(new Set(handles).size).toBe(handles.length)` が成立する（重複なし）              |
| 失敗条件 | 重複チャンネルが存在する場合、Set のサイズ < 配列長になりテストが失敗する                |
| 完了基準 | `SKILL_CREATOR_GET_ADAPTER_STATUS` の二重登録のような問題を CI で検出できること          |

## REG-COUNT-01: チャンネル総数検証

| 項目     | 内容                                                   |
| -------- | ------------------------------------------------------ |
| ID       | REG-COUNT-01                                           |
| 目的     | 登録チャンネル総数が仕様通り 19 件であることを検証する |
| 期待結果 | `expect(handles).toHaveLength(19)` が成立する          |
| 完了基準 | チャンネルの意図しない追加・削除を件数で検出できること |
