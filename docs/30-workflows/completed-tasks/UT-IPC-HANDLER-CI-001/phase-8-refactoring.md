## 目的

テストコードの品質改善と保守性向上を行う。Phase 6 で実装したスナップショットテストを対象に、責務の整理・共通化・エラーメッセージの改善を実施し、レビュー時にテスト責務と失敗理由が即座に読み取れる状態にする。

## 実行タスク

### タスク 8-1: テストコードの責務整理

1. `creatorHandlers.registrationSnapshot.test.ts` の構造を見直し、以下を確認する。
   - `beforeEach` / `afterEach` が適切な位置に配置されているか
   - 各 `describe` ブロックが単一の責務に対応しているか
   - テストケース名がテスト目的を明確に表現しているか
2. 問題点を `outputs/phase-8/refactoring-plan.md` に列挙する。

### タスク 8-2: テストヘルパーの抽出検討

1. `ipcMain` の spy セットアップロジックが複数のテストで重複している場合、共通ヘルパー関数への抽出を検討する。
2. ヘルパーの抽出が保守性を高める場合は実施し、そうでない場合は理由を記録する。
3. 抽出の判断基準と結果を `outputs/phase-8/refactoring-plan.md` に記載する。

### タスク 8-3: エラーメッセージの改善

1. テスト失敗時に出力されるメッセージを確認し、以下の点を検証する。
   - 重複チャンネルが検出された場合のメッセージが重複チャンネル名を明示しているか
   - 欠損チャンネルが検出された場合のメッセージが期待値を明示しているか
   - `toMatchSnapshot()` 失敗時の差分が読み取りやすいか
2. 改善内容と判断根拠を `refactoring-plan.md` に記録する。

### タスク 8-4: リファクタ後の再テスト実施

1. リファクタリング後に以下を実行してグリーンであることを確認する。

   ```bash
   pnpm --filter @repo/desktop test -- --run
   ```

2. 実行結果を `outputs/phase-8/post-refactor-test-plan.md` に記録する。
