## 目的

ipcMain.handle() の重複・欠損を CI 自動検出するためのスナップショットテストの要件境界を固定する。

## 背景

`apps/desktop/src/main/ipc/creatorHandlers.ts` の `registerRuntimeSkillCreatorHandlers()` で `SKILL_CREATOR_GET_ADAPTER_STATUS` チャンネルが2回登録され、後続14ハンドラが全て未登録になる連鎖障害が発生した。コードレビューで見落とされ実行時まで検出できなかった。CI による自動検出が必要である。

## P50 チェック

Phase 1 着手前に、既存実装の有無と差分確認中心に寄せるべきかを判定する。

| 確認項目                                  | Yes の場合                                         | No の場合                          |
| ----------------------------------------- | -------------------------------------------------- | ---------------------------------- |
| current branch に関連実装が存在する       | 差分確認と回帰確認を Phase 5 の主作業にする        | 通常の新規実装フェーズとして扱う   |
| upstream に類似修正が既に取り込まれている | cherry-pick または再実装不要の判断を記録する       | 未取り込みとして通常進行する       |
| 前提タスクが完了済みである                | 依存解消タスクを簡略化し、入力成果物確認に集中する | Phase 1 で依存解消タスクを明記する |

本タスクでは、`fix-creator-handler-duplicate-skill-name-validation` の障害知見を参照しつつ、既存コードに対する回帰防止テスト追加タスクとして扱う。

## 実行手順

1. `creatorHandlers.ts` を読み込み、`ipcMain.handle()` の全呼び出し箇所を列挙する。
2. Bug Fix 後の正常状態（重複なし）でのチャンネル数を確定する。
3. 既存テストファイルを確認し、重複する検証がないことを確認する。
4. REG-SNAP-01（スナップショット固定）と REG-DEDUP-01（重複検出）の受け入れ基準を定義する。

## 統合テスト連携

- Phase 4 では、本 Phase で固定した `REG-SNAP-01` / `REG-DEDUP-01` と期待チャンネル一覧をそのままテスト仕様へ引き継ぐ。
- Phase 11 では `manual-test-result.md` が一次証跡になるため、ここで定義した識別子と受け入れ基準を再利用する。

## 多角的チェック観点

| 思考法         | 確認内容                                                         |
| -------------- | ---------------------------------------------------------------- |
| 水平思考       | 重複登録以外の障害パターン（欠損・順序不整合）も要件に含むか確認 |
| 逆説思考       | 「チャンネル数が正しくても順序違い」で問題が起きる可能性を確認   |
| システム思考   | CI→テスト→ハンドラ登録の全連鎖を要件に反映する                   |
| 垂直思考       | 障害の根本原因（二重 handle 呼び出し）から要件へ掘り下げる       |
| 類推思考       | 既存の ipc-double-registration.test.ts との構造比較              |
| if思考         | スナップショット更新忘れ・CI スキップ等の失敗パスを列挙          |
| 改善思考       | 再発防止としてスナップショット更新フロー要件を含む               |
| 抽象化思考     | 個別障害を「登録チャンネル契約の静的検証」問題へ抽象化           |
| 因果関係ループ | スナップショット更新頻度が高すぎるとテスト形骸化する循環を検査   |
| プロセス思考   | 要件→スナップショット設計→CI 統合の流れを固定する                |
