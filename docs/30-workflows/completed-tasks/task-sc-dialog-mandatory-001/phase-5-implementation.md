## 実行手順

### ステップ1: SKILL.md の修正

**変更箇所**: `# Skill Creator` 見出し直後（`## 設計原則` テーブルの前）

**挿入内容**（以下のブロックをそのまま挿入する）:

```markdown
## 必須：最初の実行ステップ

**このスキルを呼ばれたら、最初のアクションは必ず `AskUserQuestion` である。**

1. インタビュー深度を確認する（quick / standard / detailed）
2. 深度が確定したら `agents/discover-problem.md` を読み込み Phase 0-0 を開始する
3. `problem-definition.json` が存在しない場合は AskUserQuestion で問題定義を収集する

ユーザーの回答なしに生成を開始してはならない。
create / update / improve-prompt モードも、最初に深度確認の質問を行ってから着手する。
```

**挿入位置の確認方法**:

1. `.claude/skills/skill-creator/SKILL.md` を開く
2. `# Skill Creator` の行を特定する（ファイル先頭付近）
3. 「## 設計原則」または最初のテーブルの直前に上記ブロックを挿入する

**変更根拠**:

| 根拠             | 説明                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| LLM 指示設計原則 | 「説明文（宣言型）」ではなく「命令文（命令型）」でないと LLM は自律判断で飛ばす        |
| 配置場所         | フロントマター直後・設計原則より前に置くことで、コンテキスト長に関係なく最初に読まれる |
| 内容の簡潔さ     | 7行以内に収め、「何をすべきか」が即座にわかる                                          |
| 例外なし宣言     | 「〇〇の場合は不要」という抜け道を与えない                                             |

### ステップ2: discover-problem.md の修正

**変更箇所**: ファイル冒頭の `> **読み込み条件**...` ブロックの直後

**挿入内容**（以下のブロックをそのまま挿入する）:

````markdown
> **⚠ 実行ゲート: このファイルを読み込んだら、最初のアクションは必ず以下を実行すること。**
>
> ```
> AskUserQuestion で Phase 0-0-1 の質問（「何が困っているか」）を行う。
> ユーザーの回答なしに Phase 0-0-2 以降へ進んではならない。
> ```
````

**挿入位置の確認方法**:

1. `.claude/skills/skill-creator/agents/discover-problem.md` を開く
2. ファイル冒頭の `> **読み込み条件**` から始まるブロック引用の末尾を特定する
3. そのブロックの直後の空行の後に上記ブロックを挿入する

**変更根拠**:

| 根拠                                                          | 説明                                                                                            |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| discover-problem.md を読む = collaborative モードに入った証拠 | このタイミングで実行ゲートを設けることで、「読んでも実行しない」状態を排除する                  |
| `> **⚠**` 記法                                                | Markdown の引用ブロックはファイル読み込み時に視覚的に目立つ。LLM が重要な指示として処理しやすい |

### ステップ3: interview-user.md の修正

**変更箇所**: セクション 5.1（入力定義）の `problem-definition.json` 行

**変更前**:

```markdown
| problem-definition.json | discover-problem | JSON が存在 | Phase 0-0 未完了エラー |
```

**変更後**:

```markdown
| problem-definition.json | discover-problem | JSON が存在（任意） | **AskUserQuestion で問題定義を収集して作成する**（エラー停止しない） |
```

**変更内容の概要**:

- `必須条件` 列: `JSON が存在` → `JSON が存在（任意）`（必須から任意へ変更）
- `欠損時処理` 列: `Phase 0-0 未完了エラー` → `AskUserQuestion で問題定義を収集して作成する`（エラー停止しない）

**変更根拠**:

| 根拠                           | 説明                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| 初回呼び出し時は必ず存在しない | 「必須ファイルが存在しない → エラー」はフローの詰まりを引き起こす                    |
| フォールバックを明示することで | LLM が「前提条件が揃っていないから create モードに切り替えよう」と逃げる抜け道を塞ぐ |
