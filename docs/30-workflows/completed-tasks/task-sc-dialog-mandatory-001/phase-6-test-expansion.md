### ステップ1: エッジケース詳細

#### TC-007: 空入力（引数なし）での呼び出し

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- `problem-definition.json` が存在しないこと

**操作手順**:

1. Claude Code セッションを起動する
2. `/skill-creator` とのみ入力して送信する（スキル名・モード・説明など一切なし）

**期待結果**:

- エラーや例外が発生せず、Claude が正常に応答する
- 最初のレスポンスが `AskUserQuestion` であり、何を作りたいか・インタビュー深度を確認する質問が含まれる
- 「引数が足りないため実行できません」などのエラーメッセージが出力されない

**判定基準**:

| 判定 | 条件                                                                    |
| ---- | ----------------------------------------------------------------------- |
| PASS | 引数なしの呼び出しでも AskUserQuestion が最初のレスポンスとして返される |
| FAIL | エラーで停止する、または質問なしにスキル生成フローが開始される          |

---

#### TC-008: スキル名のみ指定（目的・ユーザー未指定）での呼び出し

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること

**操作手順**:

1. `/skill-creator file-organizer` のようにスキル名のみ指定して送信する（目的・想定ユーザーは未指定）

**期待結果**:

- スキル名は受け取りつつ、目的・想定ユーザーが未指定であることを認識する
- インタビュー深度の確認、または目的・想定ユーザーを補完する `AskUserQuestion` が返される
- スキル名だけで生成を開始せず、追加確認質問が必ず発生する

**判定基準**:

| 判定 | 条件                                                                            |
| ---- | ------------------------------------------------------------------------------- |
| PASS | スキル名のみの指定でも、目的・想定ユーザーを確認する AskUserQuestion が返される |
| FAIL | スキル名のみで目的・想定ユーザーを推定してスキル生成を開始する                  |

---

#### TC-009: コンテキスト長耐性確認（SKILL.md が長い場合）

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- SKILL.md のサイズが通常より大きい（将来の変更でコンテンツが増えた場合を想定）

**操作手順**:

1. SKILL.md のファイルサイズ・行数を確認しておく（記録用）
2. 通常の `/skill-creator` 呼び出しを実施する
3. `## 必須：最初の実行ステップ` ブロックが最初に参照・反映されているかを観察する

**期待結果**:

- SKILL.md のサイズに関係なく、`## 必須：最初の実行ステップ` ブロックが最初に読まれる
- ファイルの後半にある情報（collaborative フローの詳細など）を先に処理してブロックが無視されない
- 最初のレスポンスが AskUserQuestion である

**判定基準**:

| 判定 | 条件                                                                                  |
| ---- | ------------------------------------------------------------------------------------- |
| PASS | SKILL.md のコンテキスト長に関係なく、必須ブロックが先に参照されて最初の質問が返される |
| FAIL | SKILL.md の後半の情報が優先されて必須ブロックが無視され、質問なしに生成が始まる       |

---

#### TC-010: update/improve-prompt モードでの深度確認（境界条件）

**前提条件**:

- `/skill-creator` スキルが最新版（Phase 5 実装済み）であること
- 更新対象のスキルが既に存在すること（例: `my-existing-skill`）

**操作手順**:

1. `/skill-creator update my-existing-skill` のように既存スキル名を明示して送信する
2. 最初のレスポンスを観察する
3. 手順 1〜2 を `/skill-creator improve-prompt my-existing-skill` でも繰り返す

**期待結果**:

- `update` / `improve-prompt` モードで既存スキル名を明示した場合でも、インタビュー深度の確認質問（AskUserQuestion）が最初のレスポンスとして返される
- 既存スキルの内容を先読みしてそのまま更新作業を開始しない
- 深度確認後に対象スキルのコンテキストを読み込んで更新・改善フローに移行する

**判定基準**:

| 判定 | 条件                                                                                          |
| ---- | --------------------------------------------------------------------------------------------- |
| PASS | 既存スキル名を明示した `update` / `improve-prompt` モードでも、最初に深度確認の質問が返される |
| FAIL | 既存スキル名が指定されていることを理由に深度確認をスキップし、直接更新・改善フローを開始する  |
