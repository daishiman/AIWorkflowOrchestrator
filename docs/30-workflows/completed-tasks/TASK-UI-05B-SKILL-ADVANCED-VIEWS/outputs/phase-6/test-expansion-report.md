## 5. テスト設計方針

### 5.1 境界値テスト

- **大量データ**: 100件以上のリスト/データポイントによる描画安定性
- **長文字列**: 200文字超の名前/メッセージによるレイアウト耐性
- **ゼロ/空値**: 0件/空配列/空文字列による空状態ハンドリング
- **トリムロジック**: スペースのみ入力時のP42準拠バリデーション

### 5.2 エラー系テスト

- **IPC失敗**: `mockRejectedValue(new Error(...))` によるPromise拒否
- **タイムアウト**: ネットワークタイムアウト固有メッセージの表示確認
- **非Error例外**: `mockRejectedValue("文字列エラー")` による文字列例外のハンドリング
- **部分失敗**: トレンド取得失敗時にサマリーは表示される独立性確認

### 5.3 a11y テスト

- **ARIA role**: `role="status"` (ローディング), `role="alert"` (エラー)
- **aria-label**: スクリーンリーダーが読み取る操作説明
- **data-testid**: 全主要コンテナ・操作ボタンへのテストID付与

### 5.4 テスト修正履歴

Phase 6 テスト作成時に以下の修正が必要だった:

1. **SkillChainBuilder - 長いエラーメッセージ**: `ErrorDisplay` コンポーネントが「エラーが発生しました: 」プレフィックスを付与するため、`getByText(longError)` が失敗。`getByText(/x{500}/)` に変更
2. **SkillChainBuilder - タイムアウトエラー**: 同上の理由で完全一致が失敗。正規表現マッチ `/ネットワークタイムアウト/` に変更
3. **AnalyticsDashboard - ゼロ値**: `totalExecutions=0` と `totalSkills=0` の両方が「0」を描画するため `getByText("0")` で複数要素検出。`getAllByText("0")` に変更
