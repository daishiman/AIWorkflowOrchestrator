## 評価基準

各簡素化候補は以下の3軸で評価する:

| 軸             | 説明                                                  |
| -------------- | ----------------------------------------------------- |
| UX 影響        | ユーザー体験を損なわないか（LOW/MEDIUM/HIGH）         |
| Safety 影響    | 安全性が低下しないか（NONE/LOW/MEDIUM/HIGH）          |
| 実装コスト削減 | 実装時の工数がどの程度削減されるか（LOW/MEDIUM/HIGH） |

## 1. 採用候補（UX を壊さない簡素化）

### S-1: Disclosure Banner の短縮版導入

| 評価軸         | 判定   |
| -------------- | ------ |
| UX 影響        | LOW    |
| Safety 影響    | NONE   |
| 実装コスト削減 | MEDIUM |

**変更内容**: 3行の開示文を1行の短縮版 + [詳細] 展開に変更する。

**UX を壊さない根拠**:

- DSC-R1（必ず1回表示）は維持される
- FR-2b（AI モデル名含有）は短縮版でも維持される
- FR-3b（送信先種別含有）は [詳細] 展開で表示される
- 短縮版でも開示義務の核心（AI 利用 + 外部送信の可能性）は伝達される

**判定: 採用**

### S-2: Approval Sheet 内の AI 名再掲削除

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | LOW  |
| Safety 影響    | NONE |
| 実装コスト削減 | LOW  |

**変更内容**: Approval Sheet の操作説明から AI モデル名の記載を削除し、操作内容の説明に集中する。

**UX を壊さない根拠**:

- AI モデル名は直前の SessionDisclosureBanner で既に開示済み
- Approval Sheet の目的は「この操作を承認するか」の判断支援であり、AI 名は判断材料に直接寄与しない
- 情報量の削減によりユーザーの読解負荷が下がる

**判定: 採用**

### S-3: Approval Sheet 停止方法の1行化

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | LOW  |
| Safety 影響    | NONE |
| 実装コスト削減 | LOW  |

**変更内容**: 停止方法セクションを「中止はいつでも可能です」の1行に簡素化する。

**UX を壊さない根拠**:

- 中止ボタンは Session Dock の CTA として常に表示されており、Approval Sheet 内での詳細説明は冗長
- 1行でも「停止可能」という安心感は伝達される
- FR-1d（停止方法の明示）は満たされる

**判定: 採用**

### S-4: Advanced Console Panel の2区画統合

| 評価軸         | 判定   |
| -------------- | ------ |
| UX 影響        | LOW    |
| Safety 影響    | NONE   |
| 実装コスト削減 | MEDIUM |

**変更内容**: Raw Terminal Output と Operation Log を統合し、タイムスタンプ付き Terminal Log として1区画にする。

**UX を壊さない根拠**:

- Operation Log の情報は Raw Terminal Output に包含される
- タイムスタンプを追加することで時系列把握は維持される
- 区画数の削減により視覚的な認知負荷が下がる
- FR-4d（raw log 閲覧、低レベル操作ログ）の機能は維持される

**判定: 採用**

### S-5: Toggle 配置のメニュー内統一

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | LOW  |
| Safety 影響    | NONE |
| 実装コスト削減 | LOW  |

**変更内容**: 「高度な表示」toggle の配置候補を「Session Dock フッターまたはメニュー内」から「メニュー内」に限定する。

**UX を壊さない根拠**:

- CTA-R2（Primary CTA と並列しない）は維持される
- メニュー内配置は opt-in の意図を強化する（ユーザーが意図的にメニューを開く必要がある）
- フッター配置を排除することで Primary Surface のノイズが減る
- GATE-1（明示選択必須）の趣旨に合致する

**判定: 採用**

## 2. 棄却候補（Safety または UX を損なう簡素化）

### R-1: Approval Trigger の削減（APR-T4 システム設定変更の省略）

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | LOW  |
| Safety 影響    | HIGH |
| 実装コスト削減 | LOW  |

**棄却理由**: システム設定変更は不可逆操作を含む可能性がある。DENY-9（承認なし実行禁止）に抵触する。

**判定: 棄却**

### R-2: Disclosure Banner の完全省略（Approval Sheet のみで開示）

| 評価軸         | 判定   |
| -------------- | ------ |
| UX 影響        | MEDIUM |
| Safety 影響    | MEDIUM |
| 実装コスト削減 | MEDIUM |

**棄却理由**: Session open 時の開示（MUST-1）が満たされない。Approval Sheet は操作実行時にのみ表示されるため、操作が発生する前にユーザーが AI 利用を認知できない。DSC-R1 違反。

**判定: 棄却**

### R-3: Advanced Console の state 制限（running/done/aborted で非表示化）

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | HIGH |
| Safety 影響    | NONE |
| 実装コスト削減 | LOW  |

**棄却理由**: running state でログが見えないと、ユーザーが実行中の状況を把握できない。done/aborted でログが見えないと、結果の詳細確認ができない。上級者向け機能の利便性を大きく損なう。

**判定: 棄却**

### R-4: Approval Sheet の「詳細を見る」ボタン省略

| 評価軸         | 判定   |
| -------------- | ------ |
| UX 影響        | MEDIUM |
| Safety 影響    | LOW    |
| 実装コスト削減 | LOW    |

**棄却理由**: FR-1c で「詳細を見る」を含む3アクションの提供が要件として定義されている。技術的リテラシーの高いユーザーが判断材料を得るための導線として必要。省略すると受入基準 AC-1 の検証に影響する可能性がある。

**判定: 棄却**

### R-5: Consumer Auth Guard (CAG-1〜3) の設計ドキュメント省略

| 評価軸         | 判定 |
| -------------- | ---- |
| UX 影響        | NONE |
| Safety 影響    | HIGH |
| 実装コスト削減 | LOW  |

**棄却理由**: DENY-1 で明示的に禁止されている事項の enforcement 定義を省略すると、後続の実装タスクで設計根拠が不明確になる。AC-3 の検証にも影響する。

**判定: 棄却**

## 3. 簡素化サマリー

### 採用される簡素化（計5件）

| ID  | 内容                         | 削減効果                          |
| --- | ---------------------------- | --------------------------------- |
| S-1 | Disclosure Banner 短縮版     | Banner の初期表示面積を約60%削減  |
| S-2 | Approval Sheet AI 名再掲削除 | Approval Sheet の読解負荷を軽減   |
| S-3 | Approval Sheet 停止方法1行化 | 停止方法セクションを3行→1行に削減 |
| S-4 | Advanced Console 2区画統合   | Panel 内の区画数を3→2に削減       |
| S-5 | Toggle 配置のメニュー内統一  | Primary Surface のノイズを除去    |

### 棄却される簡素化（計5件）

| ID  | 内容                         | 棄却理由の核心            |
| --- | ---------------------------- | ------------------------- |
| R-1 | Approval Trigger 削減        | Safety 影響 HIGH (DENY-9) |
| R-2 | Disclosure Banner 省略       | DSC-R1/MUST-1 違反        |
| R-3 | Advanced Console state 制限  | UX 影響 HIGH              |
| R-4 | 「詳細を見る」ボタン省略     | FR-1c 違反                |
| R-5 | Consumer Auth Guard 設計省略 | Safety 影響 HIGH (DENY-1) |

### AC への影響評価

| AC   | 影響 | 理由                                             |
| ---- | ---- | ------------------------------------------------ |
| AC-1 | なし | Approval Trigger/Flow/Enforcement は全て維持     |
| AC-2 | なし | 短縮版でも開示義務の核心は維持。展開で詳細も提供 |
| AC-3 | なし | NAS/DENY/CAG は全て維持                          |
| AC-4 | 強化 | メニュー内統一により opt-in の意図がさらに明確化 |
