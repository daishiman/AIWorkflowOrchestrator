## 概要

## 改善提案

### SF-1: 設計タスク向けの Phase 4-10 スキップテンプレート

| 項目     | 内容                                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| カテゴリ | ワークフロー改善                                                                                                                                                                                                                     |
| 現状     | 設計タスクでも Phase 4-10（テスト作成〜最終レビュー）の仕様書が作成されるが、プロダクションコードがないため成果物は「設計レベルの計画」に留まる                                                                                      |
| 提案     | 設計タスク専用のフェーズテンプレートを用意し、Phase 4-10 を「設計検証」として統合する。具体的には: Phase 4-10 を「Phase 4: 設計検証サマリー」1フェーズに集約し、threat model + compliance check + AC 検証を1ドキュメントで完結させる |
| 効果     | 設計タスクの Phase 数が 13 -> 7 に削減され、空の outputs ディレクトリが発生しない                                                                                                                                                    |
| 優先度   | LOW                                                                                                                                                                                                                                  |

### SF-2: Compliance Baseline の DENY/MUST テンプレート化

| 項目     | 内容                                                                                                                                                                                                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| カテゴリ | テンプレート改善                                                                                                                                                                                                                                                                                                  |
| 現状     | DENY-1〜DENY-10、MUST-1〜MUST-10 を Phase 1 で毎回手動定義している。類似のsafetyタスクでは同じ禁止/遵守事項が繰り返される                                                                                                                                                                                         |
| 提案     | 共通の compliance baseline テンプレートを `task-specification-creator/templates/` に用意し、タスク固有の項目のみ追加する形にする。base template には DENY-5（API key Renderer渡し禁止）、DENY-6（terminal command API key含有禁止）、MUST-9（sanitizeErrorMessage）、MUST-10（P42 3段バリデーション）を常に含める |
| 効果     | 新規 safety タスクの Phase 1 作成時間が短縮され、禁止事項の記載漏れが防止される                                                                                                                                                                                                                                   |
| 優先度   | MEDIUM                                                                                                                                                                                                                                                                                                            |

### SF-3: Phase 11 スクリーンショット自動取得スキル

| 項目     | 内容                                                                                                                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| カテゴリ | 自動化改善                                                                                                                                                                                                                                      |
| 現状     | P53 により CLI 環境ではスクリーンショット取得が不可能。毎回 screenshot-plan.json を手動作成し、実装後に別途取得する運用になっている                                                                                                             |
| 提案     | Playwright または Electron `webContents.capturePage()` を使用したスクリーンショット自動取得スクリプトを作成する。screenshot-plan.json を入力として受け取り、各画面を自動キャプチャする skill を `task-specification-creator/skills/` に追加する |
| 効果     | Phase 11 の手動テストで実画面検証が CLI 環境でも実行可能になる                                                                                                                                                                                  |
| 優先度   | LOW                                                                                                                                                                                                                                             |
