## 目的

カバレッジ目標達成を検証し、統合テストを実行する。

## 背景

Phase 6でテストを拡充したため、カバレッジ目標を達成しているか確認する。未達の場合はPhase 6に戻り追加テストを作成する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ユニットテストカバレッジ測定

**目的**: ユニットテストのカバレッジを測定し、目標達成を確認する

**実行手順**:

1. カバレッジを測定する:

   ```bash
   pnpm --filter @repo/shared test:run --coverage
   ```

2. 以下の基準を確認する:

   | 指標              | 最低基準 | 推奨基準 | 達成状況 |
   | ----------------- | -------- | -------- | -------- |
   | Line Coverage     | 80%      | 90%      | [ ]      |
   | Branch Coverage   | 60%      | 70%      | [ ]      |
   | Function Coverage | 80%      | 90%      | [ ]      |

3. カバレッジが不足している場合:
   - カバレッジが低い箇所を特定
   - Phase 6に戻り追加テストを作成
   - 再度カバレッジを測定

**期待される成果物**:

- カバレッジレポート（コンソール出力）

---

### タスク2: 結合テストカバレッジ確認

**目的**: 結合テストのカバレッジ目標達成を確認する

**実行手順**:

1. 結合テストを実行する:

   ```bash
   pnpm --filter @repo/shared test:run --testPathPattern=integration
   ```

2. 以下の基準を確認する:

   | 指標                         | 目標 | 達成状況 |
   | ---------------------------- | ---- | -------- |
   | モジュール間インターフェース | 100% | [ ]      |
   | 正常系シナリオ               | 100% | [ ]      |
   | 異常系シナリオ               | 80%+ | [ ]      |

3. チェックリスト確認:
   - [ ] Domain-Repository統合テストがPASSする
   - [ ] UseCase-Repository統合テストがPASSする
   - [ ] E2E統合テストがPASSする

**期待される成果物**:

- 結合テスト実行結果

---

### タスク3: アーキテクチャ準拠テスト実行

**目的**: Clean Architecture準拠テストが全てPASSすることを確認する

**実行手順**:

1. アーキテクチャテストを実行する:

   ```bash
   pnpm --filter @repo/shared test:run --testPathPattern=architecture
   ```

2. 以下を確認する:
   - [ ] Domain層がInfrastructure層に依存していない
   - [ ] Domain層がApplication層に依存していない
   - [ ] Application層がInfrastructure層に依存していない
   - [ ] Domain層がDrizzle ORMに依存していない
   - [ ] リポジトリインターフェースがDomain層に配置されている
   - [ ] リポジトリ実装がInfrastructure層に配置されている

**期待される成果物**:

- アーキテクチャテスト実行結果

---

### タスク4: デスクトップアプリテスト実行

**目的**: デスクトップアプリ側のテストが全てPASSすることを確認する

**実行手順**:

1. デスクトップアプリのテストを実行する:

   ```bash
   pnpm --filter @repo/desktop test:run --coverage
   ```

2. 以下を確認する:
   - [ ] ChatHistoryProviderテストがPASSする
   - [ ] useChatHistoryフックテストがPASSする
   - [ ] 既存テストにリグレッションがない

**期待される成果物**:

- デスクトップアプリテスト実行結果

---

### タスク5: 依存関係ルール違反検証（dependency-cruiser）

**目的**: dependency-cruiserを使用して依存関係ルール違反がないことを確認する

**実行手順**:

1. dependency-cruiserを実行する:

   ```bash
   pnpm depcruise --validate -- packages/shared/src
   ```

2. 以下を確認する:
   - [ ] 違反が0件であること
   - [ ] 警告が許容範囲内であること

3. 違反がある場合:
   - 違反箇所を特定
   - Phase 5に戻り修正
   - 再度検証

**期待される成果物**:

- dependency-cruiser実行結果

---

### タスク6: カバレッジレポート作成

**目的**: カバレッジ達成状況を文書化する

**実行手順**:

1. カバレッジレポートを作成する:
   - 全体カバレッジサマリー
   - レイヤー別カバレッジ
   - 未カバー箇所の一覧（許容理由付き）

2. テスト実行結果サマリーを作成する:
   - ユニットテスト結果
   - 結合テスト結果
   - アーキテクチャテスト結果

**期待される成果物**:

- `outputs/phase-7/coverage-report.md` - カバレッジレポート
- `outputs/phase-7/test-execution-summary.md` - テスト実行サマリー

---

### タスク7: ゲート判定

**目的**: Phase 8へ進行可能か判定する

**実行手順**:

1. 以下の基準で判定する:

   | 基準                 | 条件    | 達成 |
   | -------------------- | ------- | ---- |
   | Line Coverage        | ≥80%    | [ ]  |
   | Branch Coverage      | ≥60%    | [ ]  |
   | Function Coverage    | ≥80%    | [ ]  |
   | アーキテクチャテスト | 全PASS  | [ ]  |
   | 結合テスト           | 全PASS  | [ ]  |
   | dependency-cruiser   | 違反0件 | [ ]  |

2. 判定結果:
   - **PASS**: 全基準を満たす → Phase 8へ進行
   - **FAIL**: 基準未達 → Phase 6に戻り追加対応

**期待される成果物**:

- `outputs/phase-7/gate-decision.md` - ゲート判定結果
