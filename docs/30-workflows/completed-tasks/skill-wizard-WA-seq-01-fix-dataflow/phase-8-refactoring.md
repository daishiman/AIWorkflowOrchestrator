## リファクタリング対象と方針

### buildSkillContext() の責務境界整理

| 対象                           | 確認観点                                      | 対処方法                                             |
| ------------------------------ | --------------------------------------------- | ---------------------------------------------------- |
| `buildSkillContext` の配置場所 | `SkillCreateWizard.tsx` 内か utils ファイルか | 再利用性が高い場合は `skillContextBuilder.ts` へ抽出 |
| 空文字正規化ロジック           | `\|\| undefined` パターンが重複していないか   | ヘルパー関数 `emptyToUndefined()` に抽出             |
| 型ガードの有無                 | 引数型が厳密に定義されているか                | 型定義の明確化                                       |

### buildSkillGenerationPrompt() の責務境界整理

| 対象                              | 確認観点                                                 | 対処方法                             |
| --------------------------------- | -------------------------------------------------------- | ------------------------------------ |
| フィールド数に応じた if ブロック  | 8 つの `if` ブロックが単純か・共通化できるか             | フィールドマップ配列への置き換え検討 |
| `q1Purpose ?? purpose` の優先順位 | フォールバックロジックが明示的に記述されているか         | コメントまたは定数化                 |
| プロンプトのラベル文字列          | ハードコードされた日本語ラベルを定数ファイルに切り出すか | 初回は inline でも可・TODO コメント  |

### テストコードの整理

| 対象                          | 確認観点                                                    | 対処方法           |
| ----------------------------- | ----------------------------------------------------------- | ------------------ |
| TC-01〜TC-18 の describe 構造 | 同一観点を重複検証するケースがないか                        | 統合・削除         |
| beforeEach の活用             | 複数ケースで同一セットアップを繰り返していないか            | beforeEach に集約  |
| テスト命名                    | 既存コードの命名規則（camelCase・日本語 it 文）と整合するか | 規則に合わせて修正 |
