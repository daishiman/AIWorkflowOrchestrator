## レビューチェックリスト

### 構造検証

| チェック項目                                                                | 判定     | 備考                                                       |
| --------------------------------------------------------------------------- | -------- | ---------------------------------------------------------- |
| `SkillCreationContext` の全フィールドが optional になっているか             | REQUIRED | 後方互換維持のため全フィールド optional が必須             |
| `buildSkillContext()` が pure function として設計されているか               | REQUIRED | 副作用なし・テスト容易性の確保                             |
| `createSkill` シグネチャ変更が既存呼び出し箇所に影響しないか                | REQUIRED | optional 追加による後方互換確認                            |
| IPC ハンドラのプロンプト組み込みが `context` の各フィールドを網羅しているか | REQUIRED | Q1〜Q6 + skillName + category が全てプロンプトに含まれるか |
| データフロー図が Renderer→Redux→IPC→Main の全経路をカバーしているか         | REQUIRED | フロー図の完全性確認                                       |

### 4条件評価

| 条件   | 評価観点                                                                     | 合否基準                                     |
| ------ | ---------------------------------------------------------------------------- | -------------------------------------------- |
| 価値性 | Q1〜Q6の回答がスキル生成プロンプトに組み込まれることでスキル品質が向上するか | 全Q1〜Q6が漏れなくプロンプトに反映される設計 |
| 実現性 | 変更範囲が4ファイルに収まり、初回スコープとして現実的か                      | 追加ファイルなし・変更は最小限               |
| 整合性 | 既存の IPC 契約・型システムと矛盾しないか                                    | 型エラーゼロ・既存テスト回帰なし             |
| 運用性 | `buildSkillContext` が独立関数として将来の変更に耐えられる設計か             | 単一責務・テスト容易・ドキュメント明確       |

### 後方互換性の確認

| 確認項目                                                      | 確認方法                           | 判定 |
| ------------------------------------------------------------- | ---------------------------------- | ---- |
| `context` なしで `createSkill` を呼ぶ既存コードが動作するか   | TypeScript 型チェック + 回帰テスト | -    |
| `SkillCreationContext` の全フィールドが optional であるか     | 型定義のコードレビュー             | -    |
| IPC ハンドラが `context` が未定義の場合にフォールバックするか | ハンドラ実装レビュー + 単体テスト  | -    |

### 型安全性の確認

| 確認項目                                                                  | 確認方法                 | 判定 |
| ------------------------------------------------------------------------- | ------------------------ | ---- |
| `buildSkillContext()` の引数型・戻り値型が正しく定義されているか          | 型定義レビュー           | -    |
| `SkillCreationContext` が `packages/shared` からインポートされているか    | import パス確認          | -    |
| `createSkill` Thunk の型引数が適切に設定されているか                      | Redux Toolkit 型チェック | -    |
| IPC チャンネル定義（preload）の型が `SkillCreationContext` を受け入れるか | preload 型定義確認       | -    |

### 責務境界確認

| 境界                                                          | 問題なし | 備考                                                      |
| ------------------------------------------------------------- | -------- | --------------------------------------------------------- |
| `buildSkillContext` がコンテキスト変換のみを行っているか      | -        | LLM プロンプト生成ロジックを含まないこと                  |
| `buildSkillGenerationPrompt` が Main Process のみに存在するか | -        | Renderer にプロンプト文字列生成ロジックが漏れていないこと |
| Redux Thunk が IPC 橋渡し以上の責務を持っていないか           | -        | ビジネスロジックを Thunk に含めない                       |

## フェーズゲート判定基準

### PASS 条件（全て満たすと Phase 4 へ進む）

- [ ] `SkillCreationContext` の全フィールドが optional として定義されている
- [ ] `buildSkillContext()` が pure function として設計されている
- [ ] 後方互換性が型レベルで担保されている

- `SkillCreationContext` に required フィールドが含まれている（後方互換が壊れる）
- `buildSkillContext()` に副作用が含まれる設計になっている
- IPC ハンドラの設計で Q1〜Q6 のいずれかがプロンプトに含まれていない
- 4条件のいずれかが FAIL
