# Phase 11: 手動テスト

## メタ情報

| 項目   | 値                 |

## 目的

実際の Anthropic API を使って improve() を呼び出し、LLM による改善提案が正しく生成・返却されることを確認する。

## 実行タスク

0. Phase 10 判定結果の前提条件確認
   - Phase 10 が MINOR 判定の場合、MINOR 指摘が全て未タスク仕様書に変換されていることを確認する
   - Phase 10 成果物（最終レビュー報告書）の判定結果を本ファイルに記録する
1. 手動テスト環境の準備
   - Anthropic API キーが設定されていることを確認
   - 既存のスキル（例: `test-skill`）が存在することを確認
2. 手動テストシナリオ MT-1: 基本的な改善提案生成
   - 操作: IPC 経由または直接 improve("test-skill", "このスキルの説明をより明確にしてください") を呼び出す
   - 期待結果: section, before, after, reason を含む改善提案が1件以上返される
   - 確認: JSON が正しいフォーマットであることを確認
3. 手動テストシナリオ MT-2: 改善提案の SKILL.md への適用
   - 前提: MT-1 で取得した改善提案（`RuntimeSkillCreatorImproveSuggestion[]` 型）を使用する
   - 操作: MT-1 で得た改善提案のうち1件を承認し、`applyImprovement(skillName, suggestion)` または同等の IPC ハンドラを呼び出す
   - 期待結果: SKILL.md の `section` に対応する箇所が `before` の内容から `after` の内容に更新される
   - 確認: 更新後の SKILL.md ファイルを直接開き、`after` の内容に一致するテキストが存在することを確認する
   - 確認: `before` の内容が SKILL.md から消えていること（部分置換でなく上書き）を確認する
4. 手動テストシナリオ MT-3: 存在しないスキルへの呼び出し
   - 操作: improve("non-existent-skill", "改善してください") を呼び出す
   - 期待結果: `{ success: false, error: { code: "SKILL_NOT_FOUND", message: "..." } }` が返される
   - 確認: エラーメッセージに内部パス情報（ホームディレクトリ等）が含まれていないことを確認する（P55対策）
5. 手動テストシナリオ MT-4: 実際の LLM レスポンス品質確認
   - 具体的なフィードバック（例: 「使用例をもっと追加してください」）を入力
   - 返された提案（`RuntimeSkillCreatorImproveSuggestion[]`）が以下を満たすか確認する:
     - `section` フィールドが SKILL.md の実在するセクション名である
     - `before` が現在の SKILL.md 内容と **完全一致** していることを厳密に確認する（部分一致や近似テキストではない）
     - `after` が意味のある改善内容になっている
     - `reason` が日本語または英語で改善理由を説明している
6. テスト結果を本ファイルに記録する
