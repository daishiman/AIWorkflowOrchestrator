## 1. アクセシビリティ要件（WCAG 2.1 AA準拠）

### NFR-D-001: フォーカストラップ

**要件**: モーダルダイアログ内でTabキーがループする

**詳細**:

- Tabキー押下時、最後のフォーカス可能要素からは最初の要素に移動
- Shift+Tabキー押下時、最初のフォーカス可能要素からは最後の要素に移動
- モーダル外の要素にはフォーカスが移動しない

**検証方法**: キーボード操作テスト

### NFR-D-002: スクリーンリーダー対応

**要件**: 支援技術がダイアログの存在と内容を認識できる

**実装詳細**:

| 属性              | 値             | 適用場所             |
| ----------------- | -------------- | -------------------- |
| `role`            | `alertdialog`  | ダイアログルート要素 |
| `aria-modal`      | `true`         | ダイアログルート要素 |
| `aria-labelledby` | タイトルのID   | ダイアログルート要素 |
| `aria-label`      | 各ボタンの説明 | 許可/拒否ボタン      |

**検証方法**: VoiceOver/NVDAでの動作確認

### NFR-D-003: キーボード操作

**要件**: すべての操作がキーボードのみで完了できる

**対応キー**:

| キー      | 動作                         |
| --------- | ---------------------------- |
| Tab       | フォーカス移動               |
| Shift+Tab | 逆方向フォーカス移動         |
| Enter     | フォーカス中のボタン実行     |
| Space     | フォーカス中のボタン実行     |
| Escape    | 拒否として処理（オプション） |

**検証方法**: キーボードのみでの操作テスト

### NFR-D-004: コントラスト比

**要件**: テキストと背景のコントラスト比が4.5:1以上

**対象**:

- ダイアログタイトル
- ツール名表示
- 引数表示
- ボタンラベル
- チェックボックスラベル

**検証方法**: Lighthouse アクセシビリティ監査

## 2. 性能要件

### NFR-D-005: ダイアログ表示レイテンシ

**要件**: 権限リクエスト受信からダイアログ表示まで100ms以内

**測定条件**:

- IPC受信完了からReactレンダリング完了まで
- 通常のCPU負荷状態

**検証方法**: Performance APIによる計測

### NFR-D-006: IPC応答時間

**要件**: ユーザー操作から権限応答送信完了まで50ms以内

**測定条件**:

- ボタンクリックイベント発火からIPC send完了まで
- 通常のCPU負荷状態

**検証方法**: Performance APIによる計測

### NFR-D-007: メモリ使用量

**要件**: ダイアログ表示中の追加メモリ使用量は5MB以下

**詳細**:

- リクエストデータのキャッシュ
- UIコンポーネントのレンダリング

**検証方法**: Chrome DevTools Memory タブ

## 3. セキュリティ要件

### NFR-D-008: 権限リクエストの改ざん防止

**要件**: Renderer側で受信した権限リクエストが改ざんされていないことを保証する

**対策**:

- Main Processからの送信時に`requestId`をUUID v4で生成
- 応答時に同一の`requestId`を返送することで紐付けを保証
- `requestId`はMain Process側のPermissionResolverで管理

### NFR-D-009: 正当なMain Processからのリクエストのみ処理

**要件**: 不正なIPCメッセージを拒否する

**対策**:

- `ALLOWED_ON_CHANNELS`にホワイトリスト登録されたチャネルのみリッスン
- 未登録チャネルからのメッセージは無視（safeOn関数で制御）

### NFR-D-010: 許可されたIPCチャネルのみ使用

**要件**: 権限応答は許可されたチャネルを通じてのみ送信する

**対策**:

- `ALLOWED_INVOKE_CHANNELS`にホワイトリスト登録されたチャネルのみinvoke可能
- `safeInvoke`関数でチャネル検証を実施

### NFR-D-011: 引数サニタイズ

**要件**: ユーザーに表示される引数データから機密情報が除去されている

**対策（Main Process側で実装済み）**:

- `sanitizeArgs()`で機密キー（password, token, key等）を`[REDACTED]`に置換
- 長文（500文字超）を省略表示

## 4. 保守性要件

### NFR-D-012: 既存PermissionDialogコンポーネントの再利用

**要件**: 新規コンポーネント作成を避け、既存実装を活用する

**対象コンポーネント**: `apps/desktop/src/renderer/components/organisms/PermissionDialog/`

**メリット**:

- 実装工数の削減
- 一貫したUI/UX
- アクセシビリティ対応の流用

### NFR-D-013: 既存agentSlice状態管理パターンの流用

**要件**: 同様の状態管理パターンを適用し、コードの一貫性を維持する

**流用パターン**:

- `pendingPermission`状態の管理
- `setPermissionRequest`/`respondToPermission`アクション
- `rememberedChoices`による選択記憶

### NFR-D-014: コード分離

**要件**: skillAPIとagentAPIの責務を明確に分離する

**詳細**:

- skillAPIは`skill:*`チャネルのみを使用
- agentAPIは`agent:*`チャネルのみを使用
- 共通の型定義は`@repo/shared`で管理

---

## 5. 信頼性要件

### NFR-D-015: エラーハンドリング

**要件**: IPCエラー時にユーザーに適切なフィードバックを提供する

**対応エラー**:

| エラー種別               | 対応                             |
| ------------------------ | -------------------------------- |
| IPC送信失敗              | コンソールログ出力、リトライなし |
| 無効なrequestId          | 警告ログ出力、無視               |
| ダイアログ表示中のエラー | エラー状態を表示、拒否として処理 |

### NFR-D-016: コンポーネントアンマウント時のクリーンアップ

**要件**: メモリリークを防止するためリスナーを確実に解除する

**詳細**:

- `useEffect`のクリーンアップ関数で`onPermission`の戻り値（解除関数）を呼び出す
- 保留中のリクエストがある場合は自動的に拒否として処理
