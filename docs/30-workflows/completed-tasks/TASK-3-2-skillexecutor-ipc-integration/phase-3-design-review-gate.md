## 目的

Phase 1〜2の成果物をレビューし、要件・設計の妥当性を検証する。問題があれば該当Phaseに戻って修正する。

## 背景

TDD開発を開始する前に、要件定義と設計の品質を確認するゲートフェーズ。このPhaseで問題を検出することで、後続Phaseでの手戻りを防ぐ。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件定義レビュー

**目的**: Phase 1の成果物が十分な品質であることを確認する

**実行手順**:

1. 要件の完全性を確認する

   | チェック項目   | 確認内容                             | 結果 |
   | -------------- | ------------------------------------ | ---- |
   | スコープ明確性 | 実装範囲が明確に定義されているか     |      |
   | 受け入れ基準   | 各要件に検証可能な基準があるか       |      |
   | 依存関係       | TASK-3-1-Aとの依存が明記されているか |      |
   | 除外項目       | スコープ外の項目が明記されているか   |      |

2. 要件の整合性を確認する
   - IPC統合要件とUI要件の整合性
   - 既存実装（SkillExecutor）との整合性

**期待される成果物**:

- `outputs/phase-3/requirements-review.md`

---

### タスク2: 設計レビュー

**目的**: Phase 2の設計が要件を満たし、実装可能であることを確認する

**実行手順**:

1. アーキテクチャ設計レビュー

   | チェック項目 | 確認内容                                      | 結果 |
   | ------------ | --------------------------------------------- | ---- |
   | データフロー | Main→Preload→Rendererのフローが明確か         |      |
   | 責務分離     | 各コンポーネントの責務が明確か                |      |
   | 既存パターン | 既存のagentAPI/llmAPIパターンと一貫性があるか |      |

2. Preload API設計レビュー

   | チェック項目       | 確認内容                       | 結果 |
   | ------------------ | ------------------------------ | ---- |
   | インターフェース   | 型定義が完全か                 |      |
   | エラーハンドリング | エラーケースが考慮されているか |      |
   | メモリ管理         | リスナー解除が設計されているか |      |

3. React Hook設計レビュー

   | チェック項目   | 確認内容                                    | 結果 |
   | -------------- | ------------------------------------------- | ---- |
   | State設計      | 必要な状態が網羅されているか                |      |
   | ライフサイクル | マウント/アンマウント処理が設計されているか |      |
   | 再レンダリング | 不要な再レンダリングを防ぐ設計か            |      |

4. UIコンポーネント設計レビュー

   | チェック項目       | 確認内容                      | 結果 |
   | ------------------ | ----------------------------- | ---- |
   | Props設計          | 必要なPropsが定義されているか |      |
   | コンポーネント構成 | 適切に分割されているか        |      |
   | 既存UIとの統合     | AgentViewとの統合方法が明確か |      |

**期待される成果物**:

- `outputs/phase-3/design-review.md`

---

### タスク3: システム仕様との整合性確認

**目的**: 設計がシステム仕様（aiworkflow-requirements）と整合しているか確認する

**実行手順**:

1. interfaces-agent-sdk.mdとの整合性確認
   - SkillExecutor型定義との整合性
   - IPCチャンネル仕様との整合性

2. security-skill-execution.mdとの整合性確認
   - セキュリティ要件の考慮

3. ui-ux-components.mdとの整合性確認
   - UI設計ガイドラインとの整合性

**期待される成果物**:

- `outputs/phase-3/system-spec-alignment.md`

---

### タスク4: レビュー結果判定

**目的**: レビュー結果に基づき、次のアクションを決定する

**実行手順**:

1. 発見された問題を分類する

   | 問題ID | 問題内容 | 重大度 | 影響範囲 |
   | ------ | -------- | ------ | -------- |
   |        |          |        |          |

2. 判定を行う

   | 判定     | 条件                     | 次のアクション            |
   | -------- | ------------------------ | ------------------------- |
   | PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
   | MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
   | MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
   | CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

3. 戻り先を決定する（MAJOR/CRITICALの場合）

   | 問題の種類 | 戻り先              |
   | ---------- | ------------------- |
   | 要件の問題 | Phase 1（要件定義） |
   | 設計の問題 | Phase 2（設計）     |

**期待される成果物**:

- `outputs/phase-3/review-result.md`
