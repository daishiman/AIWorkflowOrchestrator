### 2.3 問題分析

#### IT-1: オンライン復帰後の同期テストが困難

**背景**:

- Turso Embedded Replicasの自動同期機能に依存
- E2Eテストでネットワーク状態を完全に制御することは困難

**影響度**: 低

- 同期機能自体はTursoの責務であり、アプリケーション側でのテストは限定的で問題ない
- 基本的なオフラインCRUD動作はE2Eでテスト可能

**対処**:

- 統合テストで`syncStatus`状態変化を検証
- E2Eでは基本的なオフライン動作確認に留める

#### IT-2: 競合解決（LWW）のE2Eテストが困難

**背景**:

- 複数デバイスからの同時更新シナリオをE2Eで再現することは困難
- LWW（Last Write Wins）ロジックはサーバー側で実行

**影響度**: 低

- LWWは`updatedAt`タイムスタンプ比較であり、ロジックは単純
- 単体テストで十分に検証可能

**対処**:

- Repositoryの単体テストで`updatedAt`ベースの競合解決を検証
- 複数デバイスシナリオは手動テスト項目として記録
