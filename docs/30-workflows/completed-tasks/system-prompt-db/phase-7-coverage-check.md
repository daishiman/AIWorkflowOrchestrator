## 目的

テストカバレッジ目標を検証し、目標未達の場合はPhase 6に戻って追加テストを作成する。

## 背景

カバレッジ基準を満たすことで、コードの信頼性を確保する。目標未達の場合は追加テストが必要。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ユニットテストカバレッジ検証

**目的**: ユニットテストのカバレッジ目標を検証する

**実行手順**:

1. sharedパッケージのカバレッジを計測する
   ```bash
   pnpm --filter @repo/shared test:coverage
   ```
2. desktopパッケージのカバレッジを計測する
   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```
3. カバレッジ結果を確認する
   - Line Coverage: 80%以上（最低基準）
   - Branch Coverage: 60%以上（最低基準）
   - Function Coverage: 80%以上（最低基準）
4. 目標未達の場合、不足箇所を特定する
5. 成果物を `outputs/phase-7/unit-coverage-result.md` に出力する

**期待される成果物**:

- `outputs/phase-7/unit-coverage-result.md`

---

### タスク2: 結合テストカバレッジ検証

**目的**: 結合テストのカバレッジ目標を検証する

**実行手順**:

1. 結合テストを実行する
   ```bash
   pnpm --filter @repo/shared test src/repositories/__tests__/*.integration.test.ts
   ```
2. 結合テストカバレッジを確認する
   - Repository CRUD操作: 100%
   - モジュール間インターフェース: 100%
   - 正常系シナリオ: 100%
   - 異常系シナリオ: 80%+
   - マイグレーション処理: 100%
3. 目標未達の場合、不足箇所を特定する
4. 成果物を `outputs/phase-7/integration-coverage-result.md` に出力する

**期待される成果物**:

- `outputs/phase-7/integration-coverage-result.md`

---

### タスク3: カバレッジギャップ分析

**目的**: カバレッジ不足箇所を分析し、対策を立てる

**実行手順**:

1. ユニットテストのギャップを分析する
   - 未テストの関数/メソッド
   - 未テストのブランチ
   - 未テストの行
2. 結合テストのギャップを分析する
   - 未テストのシナリオ
   - 未テストのエラーケース
3. 優先度を付ける
   - 高: コア機能・セキュリティ関連
   - 中: エッジケース・エラーハンドリング
   - 低: ユーティリティ・ヘルパー
4. 成果物を `outputs/phase-7/coverage-gap-analysis.md` に出力する

**期待される成果物**:

- `outputs/phase-7/coverage-gap-analysis.md`

---

### タスク4: ゲート判定

**目的**: カバレッジ目標達成を判定する

**実行手順**:

1. カバレッジ目標達成を判定する
   - 全目標達成: PASS → Phase 8へ
   - 一部未達成: Phase 6へ戻り追加テスト
2. 判定結果を記録する
3. 成果物を `outputs/phase-7/coverage-judgment.md` に出力する

**期待される成果物**:

- `outputs/phase-7/coverage-judgment.md`
