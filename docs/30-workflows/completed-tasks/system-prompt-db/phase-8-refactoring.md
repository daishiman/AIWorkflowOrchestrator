## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード重複の排除

**目的**: 重複コードを共通化する

**実行手順**:

1. Repository層の重複を確認する
   - findAllByUserId / findById の共通クエリ部分
   - create / update のバリデーション部分
2. 共通処理を抽出する
   - ベースクエリビルダーの作成
   - 共通バリデーション関数の作成
3. IPC層の重複を確認する
   - sender検証の共通化
   - エラーハンドリングの共通化
4. テストを実行し、Greenを維持することを確認する
   ```bash
   pnpm --filter @repo/shared test
   pnpm --filter @repo/desktop test
   ```

**期待される成果物**:

- リファクタリング済みコード

---

### タスク2: 命名・構造の改善

**目的**: コードの可読性を向上させる

**実行手順**:

1. 変数名・関数名を確認する
   - 意図が明確な命名になっているか
   - プロジェクトの命名規則に従っているか
2. 関数の分割を検討する
   - 単一責任原則に従っているか
   - 長すぎる関数がないか
3. ファイル構造を確認する
   - 適切なディレクトリに配置されているか
   - 循環依存がないか
4. テストを実行し、Greenを維持することを確認する

**期待される成果物**:

- リファクタリング済みコード

---

### タスク3: 型定義の強化

**目的**: TypeScriptの型安全性を向上させる

**実行手順**:

1. 型定義を確認する
   - any型が使用されていないか
   - unknown型の適切な使用
   - ユニオン型・交差型の適切な使用
2. 型ガードを追加する
   - ランタイム型チェックの追加
   - エラーメッセージの型安全性
3. Genericsの活用を検討する
   - Repository共通インターフェース
   - IPC共通型
4. テストを実行し、Greenを維持することを確認する

**期待される成果物**:

- 型定義の強化

---

### タスク4: エラーハンドリングの統一

**目的**: エラーハンドリングパターンを統一する

**実行手順**:

1. エラー型を確認する
   - 既存のエラーパターンとの整合性
   - カスタムエラークラスの使用
2. エラーメッセージを統一する
   - ユーザー向けメッセージ
   - 開発者向けログ
3. エラー伝播パスを確認する
   - Repository → IPC → Renderer の流れ
   - 適切なエラー変換
4. テストを実行し、Greenを維持することを確認する

**期待される成果物**:

- エラーハンドリング統一

---

### タスク5: パフォーマンス最適化

**目的**: 必要に応じてパフォーマンスを最適化する

**実行手順**:

1. クエリ最適化を確認する
   - N+1問題がないか
   - 不要なクエリがないか
   - インデックスが有効活用されているか
2. メモリ使用を確認する
   - 大量データ処理時のメモリ使用
   - 不要なオブジェクト生成
3. 非同期処理を確認する
   - 並列化可能な処理
   - Promise.all の活用
4. テストを実行し、Greenを維持することを確認する

**期待される成果物**:

- パフォーマンス最適化
