### 後続実装タスクへの設計 NOTE

- **NOTE-1**: `retryable: true` エラーに対するリトライ回数上限（推奨: 最大3回）と `retryAfterMs` の UI 反映（カウントダウン表示）を実装時に設計すること
- **NOTE-2**: `cancelStreaming` の `streamingContent` リセット挙動（設計書「蓄積コンテンツ保持」vs 実装 `""` リセット）の方針を実装時に確定すること
- **NOTE-3**: chatSlice の旧 `callLLMAPI` パス（非ストリーミング）の廃止計画を実装時に策定すること
- **NOTE-4**: `blocked` → `ready` 状態遷移トリガーについて、state-machine.md では `auth-key:exists`（Claude Agent SDK キー）を使用しているが、LLM プロバイダー API キーの検証には `llm:check-health` が適切。実装時に遷移トリガーの IPC チャンネルを確定すること
- **NOTE-5**: ChatPanel.tsx が `useAppStore((s) => s.xxx)` のインラインセレクタを使用している。P31/P48 準拠で `store/index.ts` に定義済みの個別セレクタ（`useChatPanelStatus()` 等）に置換すること
- **NOTE-6**: `useStreamingChat` の戻り値 `{ state, actions }` が毎レンダーで新オブジェクトを生成している。`useMemo` 適用で不要な再レンダーを防止すること
