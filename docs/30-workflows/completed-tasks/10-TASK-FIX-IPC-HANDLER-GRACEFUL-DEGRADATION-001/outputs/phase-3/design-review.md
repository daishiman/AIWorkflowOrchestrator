## 4. 設計上の注目ポイント

### 4.1 依存関係の失敗伝播

`authKeyService` のように複数グループで共有される依存の初期化が失敗した場合、依存先は自然に失敗する設計となっている。明示的なスキップロジックを導入しないことで複雑性を抑えている。これは妥当な判断であり、ログに失敗原因が記録されるためデバッグにも支障はない。

### 4.2 themeWatcher の個別管理

`setupThemeWatcher` は戻り値（unsubscribe 関数）をモジュールスコープ変数にキャプチャする必要があるため、`safeRegister` ではなく個別の try-catch で処理する。これは `safeRegister` のシンプルなインターフェース（`() => void`）を維持するための合理的な例外である。

### 4.3 Supabase 条件分岐の例外隔離

`getSupabaseClient()` 自体の例外も隔離する設計としている。現行コードでは `getSupabaseClient()` が `null` を返す場合のみフォールバックハンドラが登録されるが、例外時にはフォールバックも登録されない。これは意図的な設計であり、Supabase の初期化が予期しない例外を投げた場合は認証機能全体を無効化するのが安全側の動作である。
