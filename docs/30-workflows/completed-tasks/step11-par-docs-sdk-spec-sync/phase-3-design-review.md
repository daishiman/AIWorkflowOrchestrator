- docs-only タスクとしての scope 逸脱（コード変更等）がないことを確認する
- 設計レビューゲートを通過する

## 設計レビュー観点

| 観点                   | 確認内容                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| current fact との整合  | 更新内容が completed ledger の事実と矛盾しない                                                                           |
| 対象ファイルの完全性   | SDK-02 の 3 ファイル、SDK-04 の 4 ファイルが全て対応表に含まれている                                                     |
| 更新順の妥当性         | ledger → index → system spec の順で競合が発生しない                                                                      |
| scope 逸脱なし         | `.ts`、`.tsx`、`.test.ts` 等のコードファイルが対象に含まれていない                                                       |
| 未完了表現の排除可能性 | 更新後に `更新予定`、`後でやる`、`後続判断待ち`、`仕様策定のみ`、`実行予定`、`保留として記録` が残らない設計になっている |
| no-op 根拠             | 更新が不要なファイルについて no-op 根拠が明記されている、または対象外であることが明記されている                          |
