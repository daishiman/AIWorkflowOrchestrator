## 目的

Phase 1（要件）とPhase 2（設計）の成果物をレビューし、実装に進む前に設計の妥当性を検証する。

## 背景

設計レビューは品質ゲートとして機能し、要件の漏れや設計の問題を早期に発見することで、後工程での手戻りを防ぐ。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件と設計の整合性確認

**目的**: 要件が設計に正しく反映されているかを確認する

**実行手順**:

1. Phase 1の機能要件とPhase 2の設計を照合
2. 機能要件の各項目が設計に反映されているか確認
3. 非機能要件が設計で考慮されているか確認
4. 受け入れ基準が達成可能な設計か確認
5. 不整合があれば指摘事項として記録

**期待される成果物**:

- `outputs/phase-3/requirements-design-mapping.md`

---

### タスク2: アーキテクチャレビュー

**目的**: 設計のアーキテクチャ品質を評価する

**実行手順**:

1. インターフェース設計の妥当性を評価
2. クラス設計の責務分離を評価
3. 依存関係の適切性を評価
4. テスト容易性を評価
5. 拡張性・保守性を評価

**期待される成果物**:

- `outputs/phase-3/architecture-review.md`

---

### タスク3: 統合テスト観点レビュー

**目的**: 統合テストの観点から設計を評価する

**実行手順**:

1. LLMプロバイダーとの統合ポイントを確認
2. データベース永続化の統合ポイントを確認
3. Knowledge Graphサービスとの連携を確認
4. エラーハンドリングの統合を確認
5. モック可能性を確認

**期待される成果物**:

- `outputs/phase-3/integration-review.md`

---

### タスク4: レビュー結果判定

**目的**: レビュー結果を総合判定し、次のアクションを決定する

**実行手順**:

1. 全レビュー観点の結果を集計
2. 判定（PASS/MINOR/MAJOR/CRITICAL）を決定
3. 指摘事項があれば対応方針を決定
4. 次のPhaseへの進行可否を判定

**期待される成果物**:

- `outputs/phase-3/review-decision.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
