## 目的

TDDのRefactor（リファクタリング）フェーズとして、コード品質を改善する。
テストをパスさせたまま、可読性・保守性を向上させる。

## 背景

バグ修正は完了しているが、以下の観点でコード品質を確認・改善する:

- コードの重複排除
- 命名の改善
- 型定義の整理
- コメントの追加

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード品質レビュー

**目的**: 修正したコードの品質を確認する

**実行手順**:

1. 修正箇所のコードを確認
2. コードスタイルの一貫性を確認
3. 不要なコードがないか確認
4. 改善点を洗い出す

**レビュー観点**:

| 観点           | 確認内容                         | 状態 |
| -------------- | -------------------------------- | ---- |
| 命名規則       | 変数・関数名が適切か             |      |
| コードスタイル | プロジェクト規約に準拠しているか |      |
| 重複           | 重複コードがないか               |      |
| 型定義         | 型が適切に定義されているか       |      |

**期待される成果物**:

- `outputs/phase-8/code-review.md`: コード品質レビュー結果

---

### タスク2: リファクタリング実施

**目的**: コード品質を改善するリファクタリングを実施する

**実行手順**:

1. 必要なリファクタリングを特定
2. テストが通ることを確認しながら修正
3. 各修正後にテストを実行

**リファクタリング候補**:

| 項目               | 現状                   | 改善案           |
| ------------------ | ---------------------- | ---------------- |
| 引数形式の統一     | 一部がオブジェクト形式 | 全メソッドで統一 |
| エラーハンドリング | 個別実装               | 共通化検討       |
| 型定義             | インライン定義         | 型ファイルに集約 |

**期待される成果物**:

- リファクタリングされたコード

---

### タスク3: テスト継続確認

**目的**: リファクタリング後もテストが全てパスすることを確認する

**実行手順**:

1. 全テストを実行
2. 全テストがパスすることを確認
3. カバレッジが維持されていることを確認

**実行コマンド**:

```bash
# テスト実行
pnpm --filter @repo/desktop test

# カバレッジ確認
pnpm --filter @repo/desktop test -- --coverage
```

**期待される成果物**:

- `outputs/phase-8/refactor-test-result.md`: リファクタリング後テスト結果

---

### タスク4: コードフォーマット適用

**目的**: コードフォーマッターを適用し、スタイルを統一する

**実行手順**:

1. ESLintを実行
2. Prettierを実行
3. フォーマット後の差分を確認

**実行コマンド**:

```bash
# Lint実行
pnpm lint

# フォーマット実行
pnpm format
```

**期待される成果物**:

- フォーマット適用されたコード
