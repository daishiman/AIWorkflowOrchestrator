## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1で定義した受け入れ基準が全て満たされているか確認する

**実行手順**:

1. `outputs/phase-1/acceptance-criteria.md` を確認
2. 各受け入れ基準の達成状況を確認
3. 未達の項目がないことを確認

**確認マトリクス**:

| 受け入れ基準                      | 達成状況 | 証跡                 |
| --------------------------------- | -------- | -------------------- |
| Agent画面でスキル一覧が表示される |          | 手動テストで確認予定 |
| スキルのインポートが動作する      |          | 手動テストで確認予定 |
| スキルの削除が動作する            |          | 手動テストで確認予定 |
| 全テストがパスする                |          | Phase 9結果参照      |
| 型チェックがパスする              |          | Phase 9結果参照      |

**期待される成果物**:

- `outputs/phase-10/requirements-verification.md`: 要件充足確認レポート

---

### タスク2: 設計整合性確認

**目的**: Phase 2の設計通りに実装されているか確認する

**実行手順**:

1. `outputs/phase-2/fix-design.md` を確認
2. 実装コードが設計通りか確認
3. 設計からの逸脱がないことを確認

**期待される成果物**:

- `outputs/phase-10/design-compliance.md`: 設計整合性確認レポート

---

### タスク3: 変更影響分析

**目的**: 修正による他機能への影響がないことを確認する

**実行手順**:

1. 修正したファイルの一覧を確認
2. 各ファイルの呼び出し元を確認
3. 影響を受ける可能性のある機能を特定
4. 影響がないことを確認

**変更ファイル一覧**:

| ファイル                                     | 変更内容           | 影響範囲  |
| -------------------------------------------- | ------------------ | --------- |
| `apps/desktop/src/renderer/preload/index.ts` | 引数形式修正       | AgentView |
| `apps/desktop/src/main/ipc/index.ts`         | ハンドラー登録確認 | 起動時    |

**期待される成果物**:

- `outputs/phase-10/impact-analysis.md`: 変更影響分析レポート

---

### タスク4: 最終レビュー判定

**目的**: 最終レビューの判定を行い、次フェーズへの移行可否を決定する

**実行手順**:

1. 全レビュー結果を集約
2. 判定基準に基づき判定
3. 指摘事項があれば記録
4. 次フェーズへの移行可否を決定

**判定基準**:

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11へ進行            |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 11へ    |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

**期待される成果物**:

- `outputs/phase-10/final-review-decision.md`: 最終レビュー判定結果
