## 目的

Phase 2で作成した設計の妥当性を検証し、実装フェーズに進む前に問題がないことを確認する。
設計レビューを通じて、修正内容の適切性とリスクを評価する。

## 背景

バグ修正においても、実装前に設計をレビューすることで、
修正漏れや新たなバグの混入を防止する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 設計整合性レビュー

**目的**: 設計がPhase 1の要件を満たしているか確認する

**実行手順**:

1. Phase 1の受け入れ基準と設計内容を照合
2. 修正対象の網羅性を確認
3. 設計漏れがないか確認
4. レビュー結果を記録

**レビューチェックリスト**:

| チェック項目 | 確認内容                   | 結果 |
| ------------ | -------------------------- | ---- |
| 要件充足     | 受け入れ基準を満たす設計か |      |
| 網羅性       | 全修正対象が含まれているか |      |
| 整合性       | 設計間に矛盾がないか       |      |
| 後方互換性   | 既存機能への影響はないか   |      |

**期待される成果物**:

- `outputs/phase-3/design-consistency-review.md`: 設計整合性レビュー結果

---

### タスク2: 技術的妥当性レビュー

**目的**: 設計の技術的な正確性を確認する

**実行手順**:

1. 型定義の整合性を確認
2. IPCチャネル設計の妥当性を確認
3. セキュリティ要件との整合性を確認
4. 既存アーキテクチャパターンとの整合性を確認

**技術レビュー項目**:

| 項目         | 確認内容                  | 参照仕様                   |
| ------------ | ------------------------- | -------------------------- |
| 型定義       | preload/handler間の型一致 | TypeScript定義             |
| IPC設計      | チャネル名・引数・戻り値  | architecture-patterns.md   |
| セキュリティ | validateIpcSender使用     | security-implementation.md |
| パターン     | Facadeパターン準拠        | architecture-patterns.md   |

**期待される成果物**:

- `outputs/phase-3/technical-review.md`: 技術レビュー結果

---

### タスク3: リスク評価

**目的**: 修正に伴うリスクを評価する

**実行手順**:

1. 既存機能への影響を評価
2. 新たなバグ混入リスクを評価
3. テスト不足リスクを評価
4. リスク軽減策を検討

**リスク評価マトリクス**:

| リスク項目                         | 発生確率 | 影響度 | 対策                 |
| ---------------------------------- | -------- | ------ | -------------------- |
| 引数形式変更による既存呼び出し影響 | 低       | 高     | 全呼び出し箇所の確認 |
| テスト不足による回帰               | 中       | 中     | テストカバレッジ確保 |
| ビルド問題の再発                   | 低       | 中     | ビルド後の動作確認   |

**期待される成果物**:

- `outputs/phase-3/risk-assessment.md`: リスク評価レポート

---

### タスク4: レビュー判定

**目的**: 設計レビューの最終判定を行う

**実行手順**:

1. 全レビュー結果を集約
2. 判定基準に基づき判定
3. 指摘事項があれば記録
4. 次フェーズへの移行可否を決定

**判定基準**:

| 判定     | 条件                     | 次のアクション          |
| -------- | ------------------------ | ----------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ   |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り再設計     |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻り要件再確認 |

**期待される成果物**:

- `outputs/phase-3/review-decision.md`: レビュー判定結果
