## 目的

静的解析、セキュリティチェック、品質メトリクスを確認し、
コードが品質基準を満たしていることを保証する。

## 背景

バグ修正とリファクタリングが完了した段階で、
最終的な品質チェックを行い、問題がないことを確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 静的解析

**目的**: ESLint、TypeScriptによる静的解析を実施する

**実行手順**:

1. ESLintを実行し、エラー・警告を確認
2. TypeScript型チェックを実行
3. 問題があれば修正

**実行コマンド**:

```bash
# ESLint実行
pnpm lint

# TypeScript型チェック
pnpm typecheck
```

**期待される成果物**:

- `outputs/phase-9/static-analysis.md`: 静的解析結果

---

### タスク2: セキュリティチェック

**目的**: セキュリティ観点での確認を行う

**実行手順**:

1. IPC sender検証が正しく実装されているか確認
2. 入力値のバリデーションが適切か確認
3. 機密情報の漏洩リスクがないか確認

**セキュリティチェックリスト**:

| チェック項目       | 確認内容                            | 状態 |
| ------------------ | ----------------------------------- | ---- |
| IPC sender検証     | validateIpcSenderが使用されているか |      |
| 入力バリデーション | skillId/skillIdsの検証があるか      |      |
| エラーメッセージ   | 機密情報が含まれていないか          |      |

**期待される成果物**:

- `outputs/phase-9/security-check.md`: セキュリティチェック結果

---

### タスク3: 品質ゲートチェック

**目的**: 品質基準を全て満たしていることを確認する

**実行手順**:

1. 機能検証（全テストパス）
2. コード品質（Lint/型エラーなし）
3. テスト網羅性（カバレッジ基準達成）
4. セキュリティ（重大な脆弱性なし）

**品質ゲートチェックリスト**:

#### 機能検証

- [ ] 全ユニットテスト成功
- [ ] 全統合テスト成功

#### コード品質

- [ ] Lintエラーなし
- [ ] 型エラーなし
- [ ] コードフォーマット適用済み

#### テスト網羅性

- [ ] Line Coverage 80%+
- [ ] Branch Coverage 60%+
- [ ] Function Coverage 80%+

#### セキュリティ

- [ ] 重大な脆弱性なし
- [ ] IPC sender検証実装済み

**期待される成果物**:

- `outputs/phase-9/quality-gate.md`: 品質ゲート結果

---

### タスク4: 品質レポート作成

**目的**: 品質保証の結果を総合的にまとめる

**実行手順**:

1. 全チェック結果を集約
2. 問題点と対応状況をまとめる
3. 品質レポートを作成

**期待される成果物**:

- `outputs/phase-9/quality-report.md`: 品質保証レポート
