## 目的

ローカルチェックを実行し、ユーザーの明示的な承認を得た後にのみコミット・PR を作成する。ユーザー承認がない限り、commit / push / PR 作成は一切実行しない。

## 背景

shared channels.ts への3チャネル集約と desktop preload channels.ts の import 元変更、および関連テストの追加・修正をまとめて PR として提出する。本 Phase はデフォルトで BLOCKED 状態であり、ユーザーの明示的な承認があった場合にのみ実行する。

---

## 実行タスク

### タスク1: ローカルチェック実行

**目的**: PR 作成前にローカル環境で品質ゲートを通過することを確認する

**実行手順**:

1. `git status` で変更ファイル一覧を確認する
2. `pnpm --filter @repo/shared build` で shared package のビルドを確認する
3. `pnpm --filter @repo/desktop build` で desktop のビルドを確認する
4. `pnpm --filter @repo/desktop test` で関連テストが全て green であることを確認する
5. `pnpm lint` で lint エラーがないことを確認する
6. `pnpm typecheck` で型エラーがないことを確認する
7. 結果を `outputs/phase-13/local-check-result.md` に記録する

**期待される成果物**:

- ローカルチェック結果

---

### タスク2: コミット作成（ユーザー承認後）

**目的**: 変更内容を適切なコミットメッセージでコミットする

**前提条件**: ユーザーからの明示的な承認

**実行手順**:

1. ユーザーからの承認を確認する（承認がない場合は実行しない）
2. 変更ファイルをステージングする
3. コミットメッセージを作成する（feat/fix/chore の適切な prefix を使用）
4. `--no-verify` は使用しない（禁止事項）

---

### タスク3: PR作成（ユーザー承認後）

**目的**: GitHub に PR を作成する

**前提条件**: ユーザーからの明示的な承認 + タスク2 完了

**実行手順**:

1. ユーザーからの承認を確認する（承認がない場合は実行しない）
2. リモートブランチに push する
3. `gh pr create` で PR を作成する
4. PR タイトルと本文に変更内容を記載する

---

### タスク4: CI確認

**目的**: CI パイプラインの実行結果を確認する

**前提条件**: タスク3 完了

**実行手順**:

1. PR 作成後、CI の実行状況を確認する
2. CI が全て green であることを確認する
3. CI 失敗がある場合は原因を調査・修正する
