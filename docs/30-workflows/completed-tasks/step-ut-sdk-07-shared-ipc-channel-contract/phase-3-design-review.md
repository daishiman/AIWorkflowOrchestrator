## 目的

Phase 2 設計の妥当性を判定し、Phase 4 以降に進行可能かゲート判定する。

## 背景

小規模タスクだが、preload → shared の import パス変更は Electron バンドル解決に影響するため、設計レビューを実施する。

---

## 実行タスク

### タスク1: 設計レビュー観点の評価

**目的**: Phase 2 設計を複数の観点から評価する

#### レビュー観点チェックリスト

| #   | 観点                       | 評価基準                                                     | 判定 |
| --- | -------------------------- | ------------------------------------------------------------ | ---- |
| 1   | 既存パターン準拠           | `*_CHANNELS` 命名・`as const` assertion が既存と一致するか   | [ ]  |
| 2   | single source of truth     | shared 定義 → desktop import で drift が構造的に防止されるか | [ ]  |
| 3   | Electron バンドル互換性    | preload からの `@repo/shared` import がビルド時に解決可能か  | [ ]  |
| 4   | テスト網羅性               | parity drift を検出するテストが設計されているか              | [ ]  |
| 5   | 後方互換性                 | 既存の利用箇所（hooks, handlers, views）に影響がないか       | [ ]  |
| 6   | よりシンプルな代替案の検討 | 過剰な抽象化がないか、必要十分な設計か                       | [ ]  |

---

### タスク2: よりシンプルな代替案の検討

**目的**: 過剰設計を避けるため、他の選択肢を検討する

#### 代替案比較

| 方式                                     | メリット                           | デメリット                      | 推奨 |
| ---------------------------------------- | ---------------------------------- | ------------------------------- | ---- |
| A: shared に追加、desktop から import    | drift 構造的防止、既存パターン準拠 | import パスのバンドル確認が必要 | ✅   |
| B: desktop 定義を維持、parity テストのみ | 変更最小、リスク低                 | drift 防止が人的テスト依存      | ❌   |
| C: 共通 enum を新設                      | 型安全性向上                       | 過剰設計、既存パターンと不一致  | ❌   |

**結論**: 方式 A を採用。既存の `CHAT_EXPORT_CHANNELS` / `SKILL_CHANNELS` と同じパターンを踏襲しており、最も自然な拡張。

### タスク3: ゲート判定

**目的**: Phase 4 への進行可否を判定する

#### レビュー結果判定基準

| 判定     | 条件                     | 次のアクション             |
| -------- | ------------------------ | -------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4 へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4 へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る       |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻りユーザー確認 |

#### 戻り先決定基準

| 問題の種類       | 戻り先              |
| ---------------- | ------------------- |
| 要件の問題       | Phase 1（要件定義） |
| 設計の問題       | Phase 2（設計）     |
| テスト設計の問題 | Phase 4（テスト）   |
| 実装の問題       | Phase 5（実装）     |
