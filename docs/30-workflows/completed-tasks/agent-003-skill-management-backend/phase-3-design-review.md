## 目的

Phase 2で作成した設計の妥当性を検証し、実装に進む前に設計上の問題を発見・解決する。既存のMain Processパターンとの整合性、セキュリティ、エラーハンドリングを重点的にレビューする。

## 背景

設計フェーズが完了し、型定義・クラス設計・IPC設計・セキュリティ設計が揃った。実装に進む前に設計の妥当性を検証し、手戻りを防止する。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 既存パターンとの整合性レビュー

**目的**: 既存のMain Process実装パターンとの整合性を確認する

**実行手順**:

1. 以下のファイルを確認する:
   - `apps/desktop/src/main/ipc/` - 既存IPCハンドラー
   - `apps/desktop/src/main/services/` - 既存サービス
   - `apps/desktop/src/preload/channels.ts` - 既存チャネル

2. 以下の観点でレビューする:

| レビュー観点               | チェック項目                                      |
| -------------------------- | ------------------------------------------------- |
| ファイル命名規則           | 既存のケバブケース/パスカルケースと一致しているか |
| IPCチャネル命名規則        | `{domain}:{action}` 形式を踏襲しているか          |
| クラス設計パターン         | 既存サービスと同様のパターンを使用しているか      |
| 依存性注入パターン         | constructorインジェクションを使用しているか       |
| エラーハンドリングパターン | 既存と同様のエラー形式を使用しているか            |

3. 不整合がある場合は設計を修正する

**期待される成果物**:

- `outputs/phase-3/pattern-review.md`

---

### タスク2: セキュリティレビュー

**目的**: セキュリティ設計の妥当性を検証する

**実行手順**:

1. システム仕様を確認する:
   - `.claude/skills/aiworkflow-requirements/references/security-api-electron.md`

2. 以下のセキュリティ観点でレビューする:

| セキュリティ観点     | チェック項目                               |
| -------------------- | ------------------------------------------ |
| パストラバーサル防止 | ベースパス外へのアクセスが防止されているか |
| IPC sender検証       | DevToolsからの呼び出しが拒否されるか       |
| 入力バリデーション   | 全IPC引数がバリデーションされているか      |
| エラーメッセージ     | 機密情報が漏洩しないか                     |
| ファイルアクセス制限 | シンボリックリンクをフォローしていないか   |

3. セキュリティリスクを特定・記録する:

```markdown
| リスク           | 影響度 | 発生確率 | 対策状況 | 判定 |
| ---------------- | ------ | -------- | -------- | ---- |
| パストラバーサル | 高     | 低       | 対策済み | PASS |
| IPC不正呼び出し  | 高     | 低       | 対策済み | PASS |
```

**期待される成果物**:

- `outputs/phase-3/security-review.md`

---

### タスク3: IPC設計レビュー

**目的**: IPC設計の妥当性を検証する

**実行手順**:

1. 以下のIPC設計観点でレビューする:

| IPC観点            | チェック項目                                   |
| ------------------ | ---------------------------------------------- |
| チャネル名の一意性 | 既存チャネルと衝突していないか                 |
| 引数の型安全性     | TypeScriptで型チェックが効くか                 |
| 戻り値の一貫性     | 成功/失敗時の形式が統一されているか            |
| エラーコード       | 一意で識別可能なエラーコードが定義されているか |
| preload APIの設計  | contextBridge経由で安全に公開されているか      |

2. IPC契約の完全性を確認する:

```typescript
// 全IPCチャネルの引数・戻り値が型定義されているか確認
agent:scan-available-skills  // { basePath?: string } → SkillScanResult
agent:get-imported-skills    // なし → Skill[]
agent:import-skills          // { skillIds: string[] } → ImportResult
agent:remove-skill           // { skillId: string } → RemoveResult
agent:get-skill-detail       // { skillId: string } → Skill | null
```

**期待される成果物**:

- `outputs/phase-3/ipc-review.md`

---

### タスク4: エラーハンドリングレビュー

**目的**: エラーハンドリング設計の妥当性を検証する

**実行手順**:

1. 以下のエラーシナリオがカバーされているか確認する:

| エラーシナリオ         | 対応 | エラーコード     |
| ---------------------- | ---- | ---------------- |
| SKILL.mdが存在しない   | ○    | -（スキップ）    |
| SKILL.md解析失敗       | ○    | PARSE_ERROR      |
| ファイル読み取りエラー | ○    | READ_ERROR       |
| 無効なスキルID         | ○    | NOT_FOUND        |
| パストラバーサル検知   | ○    | VALIDATION_ERROR |
| IPC不正呼び出し        | ○    | AUTH_ERROR       |
| 内部エラー             | ○    | INTERNAL_ERROR   |

2. エラー伝搬パスを確認する:

```
SkillScanner.scanDirectory()
    └→ エラー発生
        └→ SkillScanError に変換
            └→ SkillService.scanAvailableSkills()
                └→ result.errors に追加
                    └→ IPCハンドラー
                        └→ Renderer
```

**期待される成果物**:

- `outputs/phase-3/error-handling-review.md`

### タスク5: レビュー結果判定

**目的**: 全レビュー結果を集約し、次フェーズへの進行可否を判定する

**実行手順**:

1. 全レビュー結果を集約する
2. 以下の判定基準で判定する:

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り設計修正     |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

3. レビューサマリーを作成する:

```markdown
## レビューサマリー

### 判定: {{PASS/MINOR/MAJOR/CRITICAL}}

### レビュー結果

| カテゴリ           | 結果 | 指摘数 |
| ------------------ | ---- | ------ |
| 既存パターン整合性 | PASS | 0      |
| セキュリティ       | PASS | 0      |
| IPC設計            | PASS | 0      |
| エラーハンドリング | PASS | 0      |

### 指摘事項

（あれば記載）

### 次のアクション

Phase 4（テスト作成）へ進行
```

**期待される成果物**:

- `outputs/phase-3/review-summary.md`
