## 検出された未タスク一覧

### 未タスク 1: キャンセル後の半作成スキルディレクトリ残存クリーンアップ

| 項目         | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| タスクID候補 | `TASK-SC-CANCEL-CLEANUP-PARTIAL-DIR-001`                     |
| 検出フェーズ | Phase 12（CANCEL-003 ドキュメント作成中）                    |
| 優先度       | Low                                                          |
| 種別         | 機能追加（後処理・クリーンアップ）                           |
| 依存タスク   | TASK-SW-CANCEL-004（AbortSignal 伝播の完成後に対応が現実的） |
| 推定スケール | 小規模                                                       |

#### 問題の説明

スキル生成処理（`createSkill()` / `runCreateWorkflow()`）は、実行途中でキャンセルされると**部分的に作成されたスキルディレクトリ**がファイルシステム上に残存する可能性がある。

具体的には、以下のシナリオで残存が発生しうる:

1. スキルディレクトリ（例: `~/.claude/skills/my-skill/`）が作成された直後にキャンセルされる。
2. `SKILL.md` の生成途中でキャンセルされる（空ファイルや不完全なファイルが残る）。
3. 他のスキルアーティファクト（`agents/`, `workflows/` 等）が部分的に作成された状態でキャンセルされる。

#### 現在の状態

- CANCEL-003 では `cancelCurrentOperation()` が `AbortController.abort()` を呼び出すが、実際に非同期処理が中断されるかどうかは CANCEL-004 の実装次第。
- 仮に中断されたとしても、中断時点までに作成されたディレクトリ・ファイルは削除されない。
- ユーザーが次回同じスキル名で生成しようとした場合、既存ディレクトリとの衝突エラーが発生する可能性がある。

#### 推奨される対処方法

```typescript
// キャンセル処理後のクリーンアップ案
public async cancelCurrentOperation(): Promise<void> {
  this.currentAbortController?.abort();
  this.currentAbortController = null;

  // キャンセル後の部分ディレクトリをクリーンアップ
  if (this.partialSkillDir) {
    await fs.rm(this.partialSkillDir, { recursive: true, force: true });
    this.partialSkillDir = null;
  }
}
```

#### 対応方針

- **短期**: ユーザーに「キャンセル後は同名スキルが残存している場合がある」旨のエラーメッセージを表示する。
- **長期**: `cancelCurrentOperation()` でクリーンアップ処理を実行する。クリーンアップ対象ディレクトリのパスをサービス内で追跡する仕組みを追加する。

#### スコープ外とした理由（CANCEL-003）

CANCEL-003 のスコープは「メインプロセスのキャンセルハンドラー追加」に限定されており、クリーンアップは独立した問題として分離する方が責務が明確になるため。また、CANCEL-004 で `AbortSignal` の伝播が完成してから実際のキャンセル動作を確認した上で実装するのが適切と判断した。
