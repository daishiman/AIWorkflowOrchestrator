## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足性レビュー

**目的**: 実装がPhase 1の要件を全て満たしていることを確認する

**実行手順**:

1. Phase 1の機能要件と実装を突合
2. Phase 1の非機能要件と実装を突合
3. 不足している機能を特定
4. レビュー結果を記録

**レビュー観点**:

- [ ] FileContextBadge: ファイル名表示、削除機能
- [ ] ApplyControls: 適用/却下機能、ローディング状態
- [ ] FileContextDropZone: D&D、バリデーション
- [ ] DiffPreview: 差分表示、ApplyControls統合
- [ ] DiffEditor: Monaco Editor統合、シンタックスハイライト
- [ ] EditCommandInput: コマンド選択、カスタム指示

**期待される成果物**:

- `outputs/phase-10/requirements-review.md`

---

### タスク2: 設計整合性レビュー

**目的**: 実装がPhase 2の設計に従っていることを確認する

**実行手順**:

1. コンポーネント設計との整合確認
2. 状態管理設計との整合確認
3. アクセシビリティ設計との整合確認
4. レビュー結果を記録

**レビュー観点**:

- [ ] Props設計が設計通りか
- [ ] useFileContext/useDiffApply連携が設計通りか
- [ ] aria属性が設計通りに設定されているか
- [ ] キーボード操作が設計通りか

**期待される成果物**:

- `outputs/phase-10/design-review.md`

---

### タスク3: コード品質レビュー

**目的**: コード品質が基準を満たしていることを確認する

**実行手順**:

1. Phase 9の品質レポート確認
2. カバレッジレポート確認
3. コードレビュー観点での確認
4. レビュー結果を記録

**レビュー観点**:

- [ ] Lintエラー0件
- [ ] 型エラー0件
- [ ] Line Coverage ≥ 80%
- [ ] コードの可読性・保守性

**期待される成果物**:

- `outputs/phase-10/code-quality-review.md`

---

### タスク4: 統合テスト結果レビュー

**目的**: 統合テストの結果を確認する

**実行手順**:

1. 統合テスト実行
2. 全テスト成功を確認
3. テストカバレッジ確認
4. レビュー結果を記録

**期待される成果物**:

- `outputs/phase-10/integration-test-review.md`

---

### タスク5: レビュー結果判定

**目的**: 全レビュー結果を総合し、次フェーズへの進行可否を判定する

**実行手順**:

1. 全レビュー結果を集約
2. 判定基準に基づき判定
3. 指摘事項がある場合は対応計画を作成
4. 判定結果を記録

**判定基準**:
| 判定 | 条件 | 次のアクション |
| -------- | ------------------------ | ------------------------- |
| PASS | 全レビュー観点で問題なし | Phase 11へ進行 |
| MINOR | 軽微な指摘あり | 指摘対応後、Phase 11へ |
| MAJOR | 重大な問題あり | 影響範囲に応じて戻る |
| CRITICAL | 致命的な問題あり | Phase 1へ戻りユーザー確認 |

**期待される成果物**:

- `outputs/phase-10/review-result.md`
