## 低カバレッジ領域の分析

### hooks/ ディレクトリ（3.15%）

**低カバレッジの理由**:

- コンポーネントテストでは hooks をモック化している
- これは意図的な設計選択であり、コンポーネントを hooks から分離してテストするため
- hooks 自体は `hooks/__tests__/` に専用テストファイルがある

**useDiffApply.ts (2.74%)**:

- 14件の専用テストが存在 (`useDiffApply.test.ts`)
- コンポーネントテストではモック化されている
- 実装コードは IPC 通信を含むため、統合テストでカバー

**useFileContext.ts (2.98%)**:

- 9件の専用テストが存在 (`useFileContext.test.ts`)
- コンポーネントテストではモック化されている
- 実装コードは状態管理を含むため、単体テストで検証

### store/ ディレクトリ（66.96%）

**chatEditSlice.ts (68.8%)**:

- 21件の専用テストが存在 (`chatEditSlice.test.ts`)
- 未カバー行 (38-47, 121, 175-251):
  - 38-47: セレクター関数の一部
  - 121: エラーケースの分岐
  - 175-251: 非同期アクションの実装詳細

**低カバレッジの理由**:

- Zustand store のアクションは IPC 通信を伴う
- 統合テスト (`__tests__/integration/`) で実際の動作をテスト
- 単体テストでは主要なロジックをカバー

### index.ts ファイル（0%）

**低カバレッジの理由**:

- これらは re-export ファイル（バレルエクスポート）
- 実際のロジックは含まず、インポートパスを整理する目的
- テスト対象外として許容
