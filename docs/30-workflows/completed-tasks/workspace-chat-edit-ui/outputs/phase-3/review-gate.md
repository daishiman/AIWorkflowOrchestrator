## 1. 目的

Phase 2で作成した設計の妥当性を検証し、実装に進む前に品質を担保する。

---

## 2. レビュー項目

### 2.1 コンポーネント設計レビュー

| チェック項目                | 基準                                 | 判定 |
| --------------------------- | ------------------------------------ | ---- |
| Propsインターフェース完全性 | 全Propに型・説明・デフォルト値が定義 | [ ]  |
| コンポーネント階層の妥当性  | Atomic Design原則に準拠              | [ ]  |
| 既存コンポーネント再利用    | FileContextBadge等を適切に再利用     | [ ]  |
| 状態管理連携設計            | chatEditSliceとの連携フローが明確    | [ ]  |

### 2.2 IPC設計レビュー

| チェック項目                    | 基準                              | 判定 |
| ------------------------------- | --------------------------------- | ---- |
| チャンネル名の一貫性            | 既存 `chat-edit:*` パターンに準拠 | [ ]  |
| リクエスト/レスポンス型の整合性 | llm-workspace-chat-edit.md と一致 | [ ]  |
| エラーハンドリング設計          | 全エラーコードに対応策が定義      | [ ]  |

### 2.3 アクセシビリティ設計レビュー

| チェック項目                   | 基準                             | 判定 |
| ------------------------------ | -------------------------------- | ---- |
| キーボードナビゲーション網羅性 | 全操作がキーボードで可能         | [ ]  |
| ARIA属性の適切性               | WAI-ARIA 1.2仕様に準拠           | [ ]  |
| フォーカス管理設計             | フォーカストラップ・可視化が定義 | [ ]  |
| スクリーンリーダー対応         | 全要素にaria-labelまたはテキスト | [ ]  |

### 2.4 Storybook設計レビュー

| チェック項目               | 基準                                 | 判定 |
| -------------------------- | ------------------------------------ | ---- |
| 全コンポーネントカバレッジ | 8コンポーネント全てにStory定義       | [ ]  |
| 状態バリエーション網羅性   | 主要状態（default/disabled/error等） | [ ]  |
| インタラクション定義       | ユーザー操作シナリオが定義           | [ ]  |

---

## 3. ゲート判定基準

### 3.1 合格条件

- 全レビュー項目がPASS
- 重大な設計変更が不要
- 技術的負債が許容範囲内

### 3.2 判定結果

| 判定      | 条件                                  |
| --------- | ------------------------------------- |
| **PASS**  | 全項目クリア、Phase 4へ進行可能       |
| **MINOR** | 軽微な修正で対応可能、修正後Phase 4へ |
| **MAJOR** | 設計見直しが必要、Phase 2に差し戻し   |

## 4. タスク一覧

### Task 1: 設計ドキュメントレビュー

#### 手順

1. Phase 2の全設計ドキュメントを読み込み
2. チェックリストに基づいて各項目を検証
3. 不備・改善点を記録

#### 成果物

- `review-checklist.md`（判定結果入り）

---

### Task 2: システム仕様との整合性確認

#### 手順

1. aiworkflow-requirements仕様を確認
2. 設計がシステム仕様に準拠しているか検証
3. 不整合があれば記録

#### 参照仕様

| 仕様                     | パス                                                                           |
| ------------------------ | ------------------------------------------------------------------------------ |
| workspace-chat-edit仕様  | `.claude/skills/aiworkflow-requirements/references/llm-workspace-chat-edit.md` |
| UIコンポーネントパターン | `.claude/skills/aiworkflow-requirements/references/arch-ui-components.md`      |
| セキュリティAPI          | `.claude/skills/aiworkflow-requirements/references/security-api-electron.md`   |

#### 成果物

- `spec-conformance-check.md`

---

### Task 3: レビュー結果サマリー作成

#### 手順

1. 全レビュー結果を集約
2. ゲート判定（PASS/MINOR/MAJOR）を決定
3. 次フェーズへの申し送り事項を記録

#### 成果物

- `review-summary.md`
