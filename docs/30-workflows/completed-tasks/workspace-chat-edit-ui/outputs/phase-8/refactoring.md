## 1. 目的

TDD Refactor フェーズとして、テストを維持しながらコード品質を改善する。

---

## 2. リファクタリング方針

### 2.1 原則

- テストを壊さない
- 機能は変更しない
- コードの可読性・保守性を向上

### 2.2 対象外

- 新機能追加
- インターフェース変更
- パフォーマンス最適化（必要な場合は別タスク）

---

## 3. タスク一覧

### Task 1: コード重複の排除

#### 概要

FileAttachmentButtonとFileContextListで重複しているロジックを共通化する。

#### 確認ポイント

| 項目               | 確認内容                         | 対処 |
| ------------------ | -------------------------------- | ---- |
| イベントハンドラ   | 類似パターンがないか             | [ ]  |
| スタイリング       | 重複するTailwindクラスがないか   | [ ]  |
| ARIA属性           | 共通化可能なパターンがないか     | [ ]  |
| エラーハンドリング | 共通のエラー処理パターンがないか | [ ]  |

#### 成果物

- リファクタリング後のコンポーネント

---

### Task 2: 命名規則の統一

#### 概要

命名規則をプロジェクト標準に統一する。

#### 確認ポイント

| 項目           | 規則                                 | 確認 |
| -------------- | ------------------------------------ | ---- |
| コンポーネント | PascalCase                           | [ ]  |
| Props          | camelCase                            | [ ]  |
| ハンドラ       | handle + イベント名（handleClick等） | [ ]  |
| 定数           | UPPER_SNAKE_CASE                     | [ ]  |
| 型             | PascalCase + Props/State接尾辞       | [ ]  |

#### 成果物

- 命名規則統一後のコンポーネント

---

### Task 3: コメント・JSDoc整備

#### 概要

コンポーネントとPropsにJSDocコメントを追加する。

#### 確認ポイント

| 項目           | 要件                             | 確認 |
| -------------- | -------------------------------- | ---- |
| コンポーネント | 概要・使用例をJSDocで記述        | [ ]  |
| Props          | 各Propの説明・デフォルト値を記述 | [ ]  |
| 複雑なロジック | インラインコメントで説明         | [ ]  |

#### 成果物

- JSDoc追加後のコンポーネント

---

### Task 4: 型定義の厳密化

#### 概要

型定義をより厳密にし、型安全性を向上する。

#### 確認ポイント

| 項目     | 確認内容                          | 確認 |
| -------- | --------------------------------- | ---- |
| any型    | any型が使用されていないか         | [ ]  |
| Union型  | 適切なUnion型が使用されているか   | [ ]  |
| Generics | 必要に応じてGenericsを使用        | [ ]  |
| Readonly | 変更されないPropsにreadonly修飾子 | [ ]  |

#### 成果物

- 型定義強化後のコンポーネント

---

### Task 5: テスト再実行・確認

```bash
# Lint

```
