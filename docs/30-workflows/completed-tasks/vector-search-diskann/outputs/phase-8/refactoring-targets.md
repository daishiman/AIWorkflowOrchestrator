## 4. リファクタリング方針

### 4.1 共通基底クラス導入

```
[ISearchStrategy]
       ↑ implements
[BaseVectorSearchStrategy] ← 共通ロジック抽出
       ↑ extends
[VectorSearchStrategy]        [CachedVectorSearchStrategy]
       (直接実装)                    (キャッシュ追加)
```

抽出対象:

- `validateInput()`: 入力バリデーション
- `executeVectorSearch()`: ベクトル検索実行
- `toSearchResultItem()`: 結果変換
- `lastMetric` / `getMetrics()`: メトリクス管理

### 4.2 変更しない項目

以下は変更不要と判断:

- **命名**: 既に適切
- **関数分割**: search()メソッドは既に適切に分割済み
- **パフォーマンス**: 明らかなボトルネックなし

---

## 5. リファクタリング実行判断

**結論**: 共通基底クラス導入は影響範囲が大きく、テスト修正も必要になるため、現時点では**見送り**とする。

代わりに以下の軽微なリファクタリングを実施:

1. JSDocコメント追加（可読性向上）
2. 既存コードの命名確認（変更不要）
3. 型安全性確認（問題なし）
4. エラーハンドリング確認（現状で十分）
5. パフォーマンス確認（問題なし）

**理由**:

- 現在のテストカバレッジ（98.71%）を維持することを優先
- 2クラスの構造は明確で、将来の拡張時に統合を検討可能
- 過度なリファクタリングを避け、実用的な品質改善に集中
