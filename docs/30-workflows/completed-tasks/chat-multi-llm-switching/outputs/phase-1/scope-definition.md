# スコープ定義 - チャット内LLMモデル切り替え機能

## メタ情報

| 項目   | 内容                     |
| ------ | ------------------------ |
| 機能名 | chat-multi-llm-switching |
| Phase  | 1                        |
| 作成日 | 2026-01-07               |

---

## 機能概要

チャット画面内で複数のLLMプロバイダー/モデルを動的に切り替え、会話の途中でも異なるLLMからの回答を得られるようにする機能。

---

## スコープ内（In Scope）

### UI/UX

| ID      | 項目               | 詳細                                            |
| ------- | ------------------ | ----------------------------------------------- |
| SCOPE-1 | プロバイダー選択UI | ドロップダウンでOpenAI/Anthropic/Google/xAI選択 |
| SCOPE-2 | モデル選択UI       | プロバイダーに応じたモデル一覧表示              |
| SCOPE-3 | LLMラベル表示      | 各メッセージにLLMアイコン/ラベル表示            |
| SCOPE-4 | デフォルト設定     | 初期状態でのLLM自動選択                         |
| SCOPE-5 | 状態永続化         | 選択状態のローカル保存                          |

### 機能

| ID       | 項目                   | 詳細                             |
| -------- | ---------------------- | -------------------------------- |
| SCOPE-6  | リアルタイム切り替え   | 確認ダイアログなしの即時切り替え |
| SCOPE-7  | 会話履歴維持           | 切り替え後も全履歴をコンテキスト |
| SCOPE-8  | システムプロンプト維持 | 切り替え後も同一プロンプト適用   |
| SCOPE-9  | ストリーミング対応     | リアルタイムレスポンス表示       |
| SCOPE-10 | エラーハンドリング     | 各種エラー時の適切な表示         |

### 対応プロバイダー

| プロバイダー | 対応モデル（例）                 |
| ------------ | -------------------------------- |
| OpenAI       | GPT-4o, GPT-4o-mini, GPT-4 Turbo |
| Anthropic    | Claude 3.5 Sonnet, Claude 3 Opus |
| Google       | Gemini Pro, Gemini Pro Vision    |
| xAI          | Grok-2, Grok-2-mini              |

### エラーハンドリング

| ID       | エラー種別    | 対応                           |
| -------- | ------------- | ------------------------------ |
| SCOPE-11 | APIキー未設定 | 設定画面への誘導メッセージ     |
| SCOPE-12 | 接続エラー    | リトライボタン付きエラー表示   |
| SCOPE-13 | タイムアウト  | 30秒後にタイムアウトメッセージ |
| SCOPE-14 | レート制限    | 待機時間付きエラーメッセージ   |

---

## スコープ外（Out of Scope）

### Phase 1で実装しない項目

| ID     | 項目                   | 理由                       | 将来Phase |
| ------ | ---------------------- | -------------------------- | --------- |
| OUT-1  | 自動LLM選択機能        | タスク分析の複雑性         | 将来検討  |
| OUT-2  | カスタムモデル追加     | 管理画面の設計が必要       | 将来検討  |
| OUT-3  | 複数LLM同時実行        | UIの複雑性増大             | 将来検討  |
| OUT-4  | LLM比較ビュー          | 実装コスト高               | 将来検討  |
| OUT-5  | プロンプトテンプレート | 別機能として独立設計       | 別タスク  |
| OUT-6  | 利用料金トラッキング   | 課金システムとの連携が必要 | 将来検討  |
| OUT-7  | モデルパラメータ調整UI | temperature等の詳細設定    | 将来検討  |
| OUT-8  | APIキー設定画面        | 既存機能として実装済み     | 対象外    |
| OUT-9  | 新規プロバイダー追加   | Azure, AWS Bedrock等       | 将来検討  |
| OUT-10 | オフラインモード       | ローカルLLM対応            | 将来検討  |

## 前提条件

### 技術的前提

| ID    | 前提条件         | 詳細                                  |
| ----- | ---------------- | ------------------------------------- |
| PRE-1 | 既存チャット機能 | 基本的なチャットUIが実装済み          |
| PRE-2 | Zustand状態管理  | チャット状態管理の基盤が存在          |
| PRE-3 | Electron IPC     | Main/Renderer間通信の仕組みが存在     |
| PRE-4 | APIキー管理      | 設定画面でAPIキーを保存する機能が存在 |

### 運用的前提

| ID    | 前提条件           | 詳細                                    |
| ----- | ------------------ | --------------------------------------- |
| PRE-5 | 有効なAPIキー      | ユーザーが各プロバイダーのAPIキーを保有 |
| PRE-6 | インターネット接続 | LLM APIへのアクセスが可能               |

---

## 制約事項

### 技術的制約

| ID    | 制約                       | 影響                                |
| ----- | -------------------------- | ----------------------------------- |
| CON-1 | コンテキストウィンドウ制限 | 各LLMのトークン制限に依存           |
| CON-2 | APIレート制限              | プロバイダーごとのレート制限に依存  |
| CON-3 | レスポンス形式の違い       | 各LLMの出力形式の差異を吸収する必要 |

### ビジネス制約

| ID    | 制約        | 影響                               |
| ----- | ----------- | ---------------------------------- |
| CON-4 | API利用料金 | ユーザーの各プロバイダーの料金体系 |
| CON-5 | 利用規約    | 各プロバイダーの利用規約に準拠     |

## 成功基準

### 機能的成功基準

| ID   | 基準                                 | 測定方法       |
| ---- | ------------------------------------ | -------------- |
| SC-1 | 4プロバイダー全てで切り替え動作      | E2Eテスト      |
| SC-2 | 会話履歴が切り替え後も参照可能       | 統合テスト     |
| SC-3 | 全エラーケースで適切なメッセージ表示 | ユニットテスト |

### 非機能的成功基準

| ID   | 基準                        | 測定方法               |
| ---- | --------------------------- | ---------------------- |
| SC-4 | 切り替え応答時間 < 100ms    | パフォーマンステスト   |
| SC-5 | キーボードのみで全操作可能  | アクセシビリティテスト |
| SC-6 | APIキーがログに出力されない | セキュリティレビュー   |

## リスクと軽減策

| ID  | リスク                 | 影響度 | 軽減策                           |
| --- | ---------------------- | ------ | -------------------------------- |
| R-1 | API仕様変更            | 中     | アダプターパターンで抽象化       |
