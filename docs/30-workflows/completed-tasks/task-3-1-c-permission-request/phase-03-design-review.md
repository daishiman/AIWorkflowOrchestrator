## 目的

Phase 1（要件定義）と Phase 2（設計）の成果物をレビューし、実装に進む準備ができているか判定する。

### タスク2: 設計の妥当性確認

**目的**: 設計が技術的に妥当であるか確認する

**実行手順**:

1. 既存コードとの整合性を確認する
2. 依存タスク（TASK-3-1-B, TASK-3-2）との統合が適切か確認する
3. エラーハンドリングが適切か確認する

**レビューチェックリスト**:

| 観点               | 確認項目                                           | 判定 |
| ------------------ | -------------------------------------------------- | ---- |
| 既存コード整合性   | SkillExecutor の既存メソッドと矛盾がないか         | [ ]  |
| 依存タスク統合     | PermissionResolver の API が正しく使用されているか | [ ]  |
| 依存タスク統合     | createHooks への追加方法が適切か                   | [ ]  |
| エラーハンドリング | タイムアウト時の処理が適切か                       | [ ]  |
| エラーハンドリング | AbortSignal 処理が適切か                           | [ ]  |
| セキュリティ       | サニタイズルールが十分か                           | [ ]  |
| パフォーマンス     | 同期処理がブロッキングしないか                     | [ ]  |

**期待される成果物**:

- 設計妥当性確認結果

### タスク3: システム仕様との整合性確認

**目的**: aiworkflow-requirements の仕様と設計が整合しているか確認する

**実行手順**:

1. interfaces-agent-sdk.md の PermissionRequest 型と設計を照合する
2. security-skill-execution.md のセキュリティ基準と照合する
3. 不整合があれば記録する

**レビューチェックリスト**:

| 仕様書                   | 確認項目                                   | 判定 |
| ------------------------ | ------------------------------------------ | ---- |
| interfaces-agent-sdk     | PermissionRequest 型の構造が一致しているか | [ ]  |
| interfaces-agent-sdk     | IPC チャネル名が規約に従っているか         | [ ]  |
| security-skill-execution | サニタイズ対象が仕様を満たしているか       | [ ]  |
| security-skill-execution | 機密情報の定義が仕様と一致しているか       | [ ]  |

**期待される成果物**:

- システム仕様整合性確認結果

---

### タスク4: レビュー結果判定

**目的**: レビュー結果に基づき次のアクションを決定する

**実行手順**:

1. 全てのチェック項目の結果を集計する
2. 判定基準に基づき PASS/MINOR/MAJOR/CRITICAL を判定する
3. 次のアクションを決定する

**判定基準**:

| 判定     | 条件                    | 次のアクション             |
| -------- | ----------------------- | -------------------------- |
| PASS     | 全てのチェック項目が OK | Phase 4 へ進行             |
| MINOR    | 軽微な不整合が 1-2 件   | 指摘対応後、Phase 4 へ進行 |
| MAJOR    | 設計の大幅な修正が必要  | Phase 2 へ戻り設計を修正   |
| CRITICAL | 要件の問題が発見された  | Phase 1 へ戻りユーザー確認 |

**戻り先決定基準**:

| 問題の種類         | 戻り先                    |
| ------------------ | ------------------------- |
| 要件の不足・誤り   | Phase 1（要件定義）       |
| 設計の不備・矛盾   | Phase 2（設計）           |
| 軽微な修正のみ必要 | その場で修正後 Phase 4 へ |

**期待される成果物**:

- レビュー結果判定書
