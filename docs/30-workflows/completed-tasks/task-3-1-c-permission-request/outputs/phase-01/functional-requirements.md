## 機能要件一覧

### FR-001: 権限リクエスト送信

| 項目   | 内容                                               |
| ------ | -------------------------------------------------- |
| ID     | FR-001                                             |
| 要件名 | 権限リクエスト送信                                 |
| 優先度 | 必須                                               |
| 説明   | Renderer に権限確認リクエストを IPC 経由で送信する |

**詳細要件**:

- `skill:permission:request` チャネルで IPC メッセージを送信
- ペイロードには `executionId`, `requestId`, `toolName`, `args`, `reason` を含む
- `requestId` は各リクエストでユニークな UUID を生成
- 送信前に引数のサニタイズを実行

---

### FR-002: ユーザー応答待機

| 項目   | 内容                                                |
| ------ | --------------------------------------------------- |
| ID     | FR-002                                              |
| 要件名 | ユーザー応答待機                                    |
| 優先度 | 必須                                                |
| 説明   | PermissionResolver を使用してユーザー応答を待機する |

**詳細要件**:

- `PermissionResolver.waitForResponse(requestId)` を呼び出して待機
- Promise ベースの非同期待機を実装
- AbortSignal によるキャンセルをサポート

---

### FR-003: 承認時の実行継続

| 項目   | 内容                                         |
| ------ | -------------------------------------------- |
| ID     | FR-003                                       |
| 要件名 | 承認時の実行継続                             |
| 優先度 | 必須                                         |
| 説明   | ユーザーが承認した場合、ツール実行を続行する |

**詳細要件**:

- `PermissionResponse.approved === true` の場合に継続
- Hook から `{ behavior: 'allow' }` を返却
- ログに承認情報を記録

---

### FR-004: 拒否時の実行停止

| 項目   | 内容                                                     |
| ------ | -------------------------------------------------------- |
| ID     | FR-004                                                   |
| 要件名 | 拒否時の実行停止                                         |
| 優先度 | 必須                                                     |
| 説明   | ユーザーが拒否した場合、ツール実行を中止しメッセージ返却 |

**詳細要件**:

- `PermissionResponse.approved === false` の場合に停止
- Hook から `{ behavior: 'deny', message: string }` を返却
- 拒否理由がある場合はメッセージに含める
- ログに拒否情報を記録

---

### FR-005: タイムアウト処理

| 項目   | 内容                                               |
| ------ | -------------------------------------------------- |
| ID     | FR-005                                             |
| 要件名 | タイムアウト処理                                   |
| 優先度 | 必須                                               |
| 説明   | 一定時間応答がない場合、タイムアウトとして処理する |

**詳細要件**:

- デフォルトタイムアウト時間は 30 秒
- タイムアウト時間は設定可能
- タイムアウト時は自動的に拒否扱い
- タイムアウトメッセージを返却

---

### FR-006: 引数サニタイズ

| 項目   | 内容                                       |
| ------ | ------------------------------------------ |
| ID     | FR-006                                     |
| 要件名 | 引数サニタイズ                             |
| 優先度 | 必須                                       |
| 説明   | 機密情報を除去してから Renderer に送信する |

**詳細要件**:

- API キー、パスワード、トークン等の機密情報をマスク
- 500 文字を超える引数値は省略表示
- サニタイズ前の元データは保持し、実行時は元データを使用
- サニタイズ済みデータは表示専用

---

### FR-007: 権限リクエスト理由生成

| 項目   | 内容                                       |
| ------ | ------------------------------------------ |
| ID     | FR-007                                     |
| 要件名 | 権限リクエスト理由生成                     |
| 優先度 | 必須                                       |
| 説明   | ツール名と引数から人間可読な理由を生成する |

**詳細要件**:

- ツール別にカスタマイズされた理由文を生成
- Bash: 実行コマンドを含む（例: `Bashコマンドを実行: ls -la`）
- Write: ファイルパスを含む（例: `ファイルを作成: /path/to/file.ts`）
- Edit: ファイルパスを含む（例: `ファイルを編集: /path/to/file.ts`）
- その他: 汎用的な理由文（例: `{toolName}ツールを使用`）

---

### FR-008: ステータス通知

| 項目   | 内容                                       |
| ------ | ------------------------------------------ |
| ID     | FR-008                                     |
| 要件名 | ステータス通知                             |
| 優先度 | 推奨                                       |
| 説明   | 権限待機中であることをストリームで通知する |

**詳細要件**:

- 権限リクエスト送信時にステータスメッセージを出力
- `[権限確認待機中] {toolName}...` 形式でストリーム出力
- ユーザーが待機中であることを認識できるようにする
