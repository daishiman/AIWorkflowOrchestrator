## 受け入れ基準一覧

### AC-001: Hook 登録

| 項目     | 内容                                                            |
| -------- | --------------------------------------------------------------- |
| ID       | AC-001                                                          |
| 基準     | PermissionRequest Hook が SDK の hooks オブジェクトに追加される |
| 検証方法 | 単体テスト                                                      |

**Given-When-Then**:

```gherkin
Given SkillExecutor が初期化されている
When hooks オブジェクトを取得する
Then permissionRequest プロパティが関数である
```

---

### AC-002: IPC チャネル送信

| 項目     | 内容                                            |
| -------- | ----------------------------------------------- |
| ID       | AC-002                                          |
| 基準     | 権限リクエストが正しい IPC チャネルで送信される |
| 検証方法 | 単体テスト・モック検証                          |

**Given-When-Then**:

```gherkin
Given PermissionRequest Hook が呼び出される
When 権限リクエストを送信する
Then "skill:permission:request" チャネルで送信される
And ペイロードに executionId, requestId, toolName, args, reason が含まれる
```

---

### AC-003: 承認時の戻り値

| 項目     | 内容                                                      |
| -------- | --------------------------------------------------------- |
| ID       | AC-003                                                    |
| 基準     | ユーザーが承認すると `{ behavior: 'allow' }` が返却される |
| 検証方法 | 単体テスト                                                |

**Given-When-Then**:

```gherkin
Given 権限リクエストが送信されている
When ユーザーが承認する（approved: true）
Then Hook は { behavior: 'allow' } を返却する
```

---

### AC-004: 拒否時の戻り値

| 項目     | 内容                                                                      |
| -------- | ------------------------------------------------------------------------- |
| ID       | AC-004                                                                    |
| 基準     | ユーザーが拒否すると `{ behavior: 'deny', message: string }` が返却される |
| 検証方法 | 単体テスト                                                                |

**Given-When-Then**:

```gherkin
Given 権限リクエストが送信されている
When ユーザーが拒否する（approved: false）
Then Hook は { behavior: 'deny', message: '...' } を返却する
And message にはユーザーの拒否理由または定型文が含まれる
```

---

### AC-005: タイムアウト処理

| 項目     | 内容                                     |
| -------- | ---------------------------------------- |
| ID       | AC-005                                   |
| 基準     | 30秒のタイムアウト後、自動的に拒否される |
| 検証方法 | 単体テスト（タイマーモック使用）         |

**Given-When-Then**:

```gherkin
Given 権限リクエストが送信されている
When 30秒間ユーザー応答がない
Then Hook は { behavior: 'deny', message: 'タイムアウト...' } を返却する
```

---

### AC-006: 長大引数の省略

| 項目     | 内容                                      |
| -------- | ----------------------------------------- |
| ID       | AC-006                                    |
| 基準     | 500文字を超える引数が省略されて送信される |
| 検証方法 | 単体テスト                                |

**Given-When-Then**:

```gherkin
Given ツール引数に 500 文字を超える値がある
When 権限リクエストを送信する
Then 送信される args の該当値は省略形式になっている
And 省略形式は "{先頭200文字}...[省略: {N}文字]" である
```

---

### AC-007: Bash ツールの理由文

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| ID       | AC-007                                |
| 基準     | Bash ツールは実行コマンドを理由に含む |
| 検証方法 | 単体テスト                            |

**Given-When-Then**:

```gherkin
Given ツール名が "Bash" である
And 引数に command: "ls -la" がある
When 権限リクエスト理由を生成する
Then 理由文に "ls -la" が含まれる
And 理由文は日本語で記述される
```

---

### AC-008: Write/Edit ツールの理由文

| 項目     | 内容                                        |
| -------- | ------------------------------------------- |
| ID       | AC-008                                      |
| 基準     | Write/Edit ツールはファイルパスを理由に含む |
| 検証方法 | 単体テスト                                  |

**Given-When-Then**:

```gherkin
Given ツール名が "Write" または "Edit" である
And 引数に file_path: "/path/to/file.ts" がある
When 権限リクエスト理由を生成する
Then 理由文に "/path/to/file.ts" が含まれる
And 理由文は日本語で記述される
```
