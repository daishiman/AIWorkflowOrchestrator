## 目的

不要チャネルの除去、命名の最終統一、共通パターンの抽出を行い、IPC 統合の複雑性を最小化する。

## 実行タスク

### Task 1: 不要チャネルの除去

- Phase 1 の棚卸しで特定された重複チャネルのうち、統合により不要になったものを除去する
- 除去対象チャネルの使用箇所が全て更新されていることを確認する
- channels.ts のホワイトリストから除去済みチャネルを削除する
- 孤立したハンドラー（チャネルが存在しないハンドラー）がないことを確認する

### Task 2: 命名の最終統一

- 全チャネル名が Phase 2 で策定した命名規則に準拠していることを確認する
- ハンドラー関数名がチャネル名と一貫していることを確認する
- 型名がチャネル名と一貫していることを確認する
- コメントやドキュメント内の旧チャネル名が更新されていることを確認する

### Task 3: 共通パターンの抽出

- creatorHandlers.ts 内で重複しているエラーハンドリングロジックを共通関数に抽出する
- セキュリティチェック（sender 検証、パストラバーサル防止）が共通ミドルウェアとして抽出されていることを確認する
- preload 層の invoke パターンが共通ヘルパーとして統一されていることを確認する

### Task 4: デッドコードの除去

- 統合により不要になったヘルパー関数を除去する
- 未使用の型定義を除去する
- 未使用の import を除去する

### リファクタリング候補

以下を優先的に検討する:

1. **セキュリティミドルウェアの共通化**: Session/Runtime 両経路に散在する sender 検証・パストラバーサル防止を単一のミドルウェア関数に集約する
2. **エラーレスポンスの標準化**: 両経路のエラーレスポンス生成を共通のファクトリ関数に統一する
3. **チャネル定義の型安全な一元管理**: channels.ts のホワイトリストと creatorHandlers の登録を型レベルで紐づけ、不整合をコンパイル時に検出できるようにする
