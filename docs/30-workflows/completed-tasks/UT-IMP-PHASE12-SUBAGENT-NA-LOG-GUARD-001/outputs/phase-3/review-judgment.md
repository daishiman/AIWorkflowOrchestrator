## 10. 補足事項（任意改善点）

以下は機能・互換性に影響しない任意の改善点として記録する。PASS 判定に影響せず、未タスク化の必要もない。

### 10.1 verify-na-log コマンドの Markdown パース堅牢性向上（将来検討）

- **現状**: verify-na-log コマンドは `grep` と `IFS` によるパイプ区切り分割で Markdown テーブルをパースしている
- **懸念**: テーブルのカラム数変更やセル内にパイプ文字（`|`）が含まれる場合にパースが壊れる可能性がある
- **改善案**: 将来的に Node.js スクリプト（専用 Markdown パーサー使用）への移行を検討する
- **優先度**: 低（現時点では運用上問題なし）

### 10.2 baseline 取得の git worktree ベース方式への移行（将来検討）

- **現状**: `git stash` ベースで baseline を取得している
- **懸念**: 未コミット変更がある場合に `git stash` の操作がリスクを伴う（stash の衝突やpop 失敗）
- **改善案**: `git worktree add` を使用して一時的なワークツリーで baseline を取得し、取得後に `git worktree remove` で削除する方式への移行を検討する
- **優先度**: 低（現時点では運用上問題なし）
