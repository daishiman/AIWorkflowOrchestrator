## 目的

カバレッジ目標を検証し、品質基準を満たしていることを確認する。

## 背景

本タスクは定数定義（channels.ts）のみの変更であるため、
従来の「行カバレッジ80%以上」という基準は直接適用されない。
代わりに、定数定義に特化した検証を行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: カバレッジレポートの生成

**目的**: テストカバレッジを測定する

**実行手順**:

1. カバレッジ付きでテストを実行する
2. レポートを確認する

**検証コマンド**:

```bash
# カバレッジレポート生成
pnpm --filter @repo/desktop test -- --coverage --reporter=verbose

# HTMLレポート生成（オプション）
pnpm --filter @repo/desktop test -- --coverage --reporter=html
```

**期待される成果物**:

- カバレッジレポート

---

### タスク2: 定数定義カバレッジの確認

**目的**: 追加した定数が全てテストでカバーされているか確認する

**実行手順**:

1. 追加したチャネル定数がテストで参照されているか確認する
2. ホワイトリスト登録がテストで検証されているか確認する

**検証チェックリスト**:

| 定数                            | テストでの参照 | 確認 |
| ------------------------------- | -------------- | ---- |
| `SKILL_SCAN`                    | 存在確認テスト | [ ]  |
| `SKILL_UPDATE`                  | 存在確認テスト | [ ]  |
| `SKILL_COMPLETE`                | 存在確認テスト | [ ]  |
| `SKILL_ERROR`                   | 存在確認テスト | [ ]  |
| `SKILL_PERMISSION_REQUEST`      | 存在確認テスト | [ ]  |
| `SKILL_PERMISSION_RESPONSE`     | 存在確認テスト | [ ]  |
| ALLOWED_INVOKE_CHANNELSへの登録 | 登録確認テスト | [ ]  |
| ALLOWED_ON_CHANNELSへの登録     | 登録確認テスト | [ ]  |

**期待される成果物**:

- カバレッジチェックリスト
