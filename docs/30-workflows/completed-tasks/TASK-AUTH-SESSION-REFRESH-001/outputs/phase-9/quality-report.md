## 6. セキュリティチェック

### 6.1 トークン非露出確認

| チェック項目                                 | 結果 | 根拠                                                                                 |
| -------------------------------------------- | ---- | ------------------------------------------------------------------------------------ |
| Access Token が Renderer に送信されないこと  | PASS | Main Process完結型設計。Rendererに送信するのは `sessionExpiresAt` と `user` 情報のみ |
| Refresh Token が Renderer に送信されないこと | PASS | Refresh Token は Main Process 内の SecureStorage のみに保持                          |
| ログ出力にトークン文字列が含まれないこと     | PASS | ログには `expiresAt` タイムスタンプのみを出力                                        |
| IPC通信経由でトークンが漏洩しないこと        | PASS | `AUTH_STATE_CHANGED` イベントのペイロードにトークンを含めない設計                    |

### 6.2 暗号化保存確認

| チェック項目                                          | 結果 | 根拠                                                                  |
| ----------------------------------------------------- | ---- | --------------------------------------------------------------------- |
| Refresh Token が `safeStorage.encryptString()` で保存 | PASS | `storeRefreshToken()` 経由で暗号化保存。既存のSecureStorageフロー活用 |
| 平文でのトークン保存がないこと                        | PASS | `localStorage` や平文ファイルへのトークン保存コードなし               |

### 6.3 IPC保護確認

| チェック項目                           | 結果 | 根拠                                                             |
| -------------------------------------- | ---- | ---------------------------------------------------------------- |
| `withValidation()` ラッパーの適用      | PASS | 既存の `auth:refresh` ハンドラーは `withValidation()` で保護済み |
| チャンネルホワイトリストの整合性       | PASS | 新規IPCチャネルの追加なし。既存チャネルのみ使用                  |
| `validateIpcSender()` による送信元検証 | PASS | 既存の検証ロジックがそのまま適用                                 |

### 6.4 SDK競合防止確認

| チェック項目                                           | 結果 | 根拠                                                      |
| ------------------------------------------------------ | ---- | --------------------------------------------------------- |
| `autoRefreshToken: false` が設定されていること         | PASS | `supabaseClient.ts` にて `autoRefreshToken: false` を確認 |
| カスタムスケジューラーのみがリフレッシュを実行すること | PASS | TokenRefreshScheduler が唯一のリフレッシュ実行ポイント    |
