## 1. テスト設計方針

### 1.1 テスト対象

| 対象                     | テストファイルパス                                                       |
| ------------------------ | ------------------------------------------------------------------------ |
| TokenRefreshScheduler    | `apps/desktop/src/main/services/__tests__/tokenRefreshScheduler.test.ts` |
| 対象プロダクションコード | `apps/desktop/src/main/services/tokenRefreshScheduler.ts`                |

### 1.2 テスト環境・ツール

| 項目             | 値                                                                            |
| ---------------- | ----------------------------------------------------------------------------- |
| テストフレームワ | Vitest                                                                        |
| タイマー制御     | `vi.useFakeTimers()` + `vi.advanceTimersByTime()`                             |
| 非同期処理制御   | `flushPromises()` パターン（`new Promise(resolve => setImmediate(resolve))`） |
| モック手法       | モックファクトリ関数によるコールバック生成                                    |
| 環境             | `happy-dom`                                                                   |

### 1.3 テスト設計原則

1. **TDD Red-Green-Refactor**: 実装前にテストを作成し、全テストがRedであることを確認
2. **vi.useFakeTimers**: `setTimeout` ベースのスケジューラーをテスト制御するため、フェイクタイマーを使用
3. **flushPromises()**: 非同期コールバック（`onRefresh`、`onSuccess`、`onFailure`）の実行完了を待機
4. **モックファクトリ関数**: テストごとに独立したモックコールバックを生成し、テスト間の状態リークを防止

## 5. モックファクトリ関数の設計

```
createMockCallbacks() → TokenRefreshCallbacks
  ├── onRefresh: vi.fn()   // Supabase refreshSession() の代替
  ├── onSuccess: vi.fn()   // リフレッシュ成功時の後処理
  └── onFailure: vi.fn()   // 全リトライ失敗後の処理
```

| コールバック | モック動作（デフォルト）                             |
| ------------ | ---------------------------------------------------- |
| `onRefresh`  | 成功時: `{ expiresAt: Date.now() + 3600000 }` を返す |
| `onRefresh`  | 失敗時: `throw new Error('refresh failed')` をスロー |
| `onSuccess`  | 呼び出し記録のみ（`vi.fn()`）                        |
| `onFailure`  | 呼び出し記録のみ（`vi.fn()`）                        |
