### タスク1: 静的解析

**目的**: コードの品質を静的解析ツールで検証する

**実行手順**:

1. TypeScript型チェック：

   ```bash
   pnpm --filter @repo/desktop typecheck
   ```

2. ESLintチェック：

   ```bash
   pnpm --filter @repo/desktop lint
   ```

3. Prettierフォーマットチェック：

   ```bash
   pnpm --filter @repo/desktop format:check
   ```

4. 全テスト実行：

   ```bash
   pnpm --filter @repo/desktop test:run
   ```

5. 結果を記録する

**期待される成果物**:

- 静的解析結果

---

### タスク2: セキュリティ確認

**目的**: State parameter実装のセキュリティ要件を検証する

**実行手順**:

1. 以下のチェックリストを確認する：

| チェック項目                                                        | 判定 |
| ------------------------------------------------------------------- | ---- |
| crypto.randomBytes()で十分なエントロピーのstate生成（32バイト以上） |      |
| stateはメモリのみ保存（ディスクに永続化しない）                     |      |
| 有効期限が適切に設定されている（10分）                              |      |
| ワンタイムユース（検証後に即座に削除）                              |      |
| エラーメッセージに機密情報が含まれていない                          |      |
| state検証失敗時にトークンが拒否される                               |      |
| Map内の期限切れエントリが自動クリーンアップされる                   |      |
| state値がログに出力されない                                         |      |

2. `outputs/phase-09/quality-report.md` に結果を出力する

**期待される成果物**:

- セキュリティチェック結果

---

### タスク3: コード品質確認

**目的**: StateManagerの実装品質を最終確認する

**実行手順**:

1. 以下の観点で確認する：

| 観点               | 確認内容                                    |
| ------------------ | ------------------------------------------- |
| エラーハンドリング | 全異常系パスで適切にエラーが返されるか      |
| メモリリーク       | Mapエントリが際限なく増加しないか           |
| 並行性             | 同時に複数のOAuth認証が開始された場合の動作 |
| 型安全性           | any型が使用されていないか                   |

**期待される成果物**:

- `outputs/phase-09/quality-report.md`
