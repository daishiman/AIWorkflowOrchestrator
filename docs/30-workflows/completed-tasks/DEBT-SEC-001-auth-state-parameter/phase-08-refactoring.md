## 目的

テストが全て通過した状態を維持しながら、コードの品質を改善する（TDD Refactorフェーズ）。

## 実行タスク

- コード品質改善: 命名規則、関数分割、責務分離の見直し
- 重複排除: StateManager内の重複コードの排除
- 可読性向上: コメント、JSDoc追加
- パフォーマンス確認: Map操作の効率性確認

---

## リファクタリング観点

| 観点             | 確認内容                                                      |
| ---------------- | ------------------------------------------------------------- |
| 命名規則         | generate/validate/cleanupメソッド名が意図を適切に伝えているか |
| 責務分離         | StateManagerが単一責務原則に従っているか                      |
| エラーメッセージ | ユーザー向けエラーメッセージが分かりやすいか                  |
| 定数管理         | STATE_EXPIRY_MS等の定数が適切に外部化されているか             |
| 型安全性         | StateEntry型、メソッド戻り値型が厳密か                        |
| メモリ管理       | Map内の期限切れエントリが適切にクリーンアップされるか         |

---

## リファクタリング前の確認

```bash
# 全テスト通過を確認
pnpm --filter @repo/desktop test:run stateManager.test.ts
```

```bash
# テストが引き続き通過することを確認
pnpm --filter @repo/desktop test:run stateManager.test.ts

# 全体テスト
pnpm --filter @repo/desktop test:run

# 型チェック
pnpm --filter @repo/desktop typecheck
```
