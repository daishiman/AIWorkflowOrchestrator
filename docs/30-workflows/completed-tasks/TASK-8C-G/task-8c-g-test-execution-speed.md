## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-8C-Gで追加した skill-creator フィクスチャ検証テスト（96テストケース）の実行時間が約8秒で、テスト実行速度の品質基準（5秒以内）を超過している。

### 1.2 問題点・課題

- テスト実行時間が約8秒で、基準の5秒を超過
- `execSync` による外部プロセス起動（Node.jsの子プロセス）が主なボトルネック
- 各バリデーションスクリプト実行ごとに新しいNode.jsプロセスが起動される
- テストケース数が96件と多く、直列実行によるオーバーヘッドが蓄積

### 1.3 放置した場合の影響

- CI/CDパイプラインでのテスト全体の実行時間が増加
- 開発者のフィードバックループが遅延
- テスト追加時にさらに実行時間が増加する可能性

---

## 2. 何を達成するか（What）

### 2.1 目的

skill-creator フィクスチャ検証テストの実行時間を5秒以内に短縮する。

### 2.2 最終ゴール

- テスト実行時間を8秒→5秒以内に短縮
- 全96テストケースがPASSを維持
- テストの信頼性を維持（フレーキーテストを発生させない）

### 2.3 スコープ

#### 含むもの

- `skill-creator.fixture.test.ts` のパフォーマンス改善
- バリデーションスクリプト実行方法の最適化
- テスト並列化の検討

#### 含まないもの

- バリデーションスクリプト本体の機能変更
- テストケースの削減
- 新規テストケースの追加

### 2.4 成果物

- 最適化された `skill-creator.fixture.test.ts`
- パフォーマンス改善レポート（実行時間before/after）

## 3. どのように実行するか（How）

### 3.1 前提条件

- TASK-8C-G の全成果物が完了済み
- 96テストケースが全PASSの状態

### 3.2 依存タスク

- TASK-8C-G（完了済み）: テストファイルとフィクスチャの基盤

### 3.3 必要な知識・スキル

- Vitest の並列実行・concurrency設定
- Node.js child_process の最適化
- テストパフォーマンスプロファイリング

### 3.4 推奨アプローチ

| アプローチ                   | 説明                                         | 期待効果 |
| ---------------------------- | -------------------------------------------- | -------- |
| スクリプトモック化           | execSync をモック化し、直接JS関数として実行  | 大       |
| プロセスプール               | 事前にNode.jsプロセスを起動しておき再利用    | 中       |
| テスト並列化                 | Vitest の concurrent オプションで並列実行    | 中       |
| バリデーション結果キャッシュ | 同一フィクスチャの結果をキャッシュして再利用 | 小       |

## 7. リスクと対策

| リスク                           | 影響度 | 発生確率 | 対策                                 |
| -------------------------------- | ------ | -------- | ------------------------------------ |
| モック化による検証精度の低下     | 中     | 中       | 統合テストを別途用意して補完         |
| 並列実行でのリソース競合         | 中     | 低       | ファイルシステム操作を排他制御       |
| リファクタリングによるテスト破壊 | 高     | 低       | 段階的に変更し、各ステップでPASS確認 |

## 9. 備考

### ボトルネック分析（TASK-8C-G Phase 10 時点）

| 要因                      | 推定影響 | 詳細                                   |
| ------------------------- | -------- | -------------------------------------- |
| execSync 外部プロセス起動 | ~60%     | 各バリデーションスクリプトで新プロセス |
| ファイルシステムI/O       | ~20%     | フィクスチャファイルの読み込み         |
| Vitest オーバーヘッド     | ~20%     | テストセットアップ・ティアダウン       |

### 補足事項

- 現在のテスト実行時間（~8秒）は機能的には問題なく、CI/CDでも許容範囲内
- 優先度Lowのため、他の高優先度タスクの後に実施を推奨
- execSyncの代わりにバリデーションロジックを直接importする方式が最も効果的と推定
