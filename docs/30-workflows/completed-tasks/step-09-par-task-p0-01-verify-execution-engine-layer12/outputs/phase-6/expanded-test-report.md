## 3. 追加テスト詳細

### 3.1 Layer 3 テスト（10件追加）

Layer 3 は output-schema.json のセマンティック検証とエージェント/Trigger の品質検証を行う。Phase 4 ベースラインでは Layer 1/2 のみをカバーしていたため、全て新規追加。

#### 3.1.1 スキーマフィールド検証（T-L3-01 ~ T-L3-05）

- **L3-001**: `$schema` フィールドの存在チェック（info/warning）
- **L3-002**: `type` フィールドの有効性チェック
  - 有効な type 値: `object`, `array`, `string`, `number`, `integer`, `boolean`, `null`
  - 配列形式 `["object", "null"]` もサポート
  - `type` フィールドなしは warning、無効な値は error

#### 3.1.2 品質検証（T-L3-06 ~ T-L3-09）

- **L3-003**: エージェント責務記述の品質（20 文字以上で info、未満で warning）
- **L3-004**: SKILL.md Trigger セクションの品質（10 文字以上で info、未満で warning）

#### 3.1.3 条件付き emit（T-L3-10）

- output-schema.json が存在しない場合、L3-001/L3-002 は emit されないことを検証

### 3.2 Layer 3 エッジケーステスト（5件追加）

| テストID   | 検証観点                                                           |
| ---------- | ------------------------------------------------------------------ |
| T-L3-EC-01 | 非オブジェクトスキーマ（`{}`, `true`, `null`, `[]`）のハンドリング |
| T-L3-EC-02 | type 配列形式（`['object', 'null']`）と空配列の区別                |
| T-L3-EC-03 | 複数エージェントファイルで各 L3-003 が個別に emit                  |
| T-L3-EC-04 | 責務セクション直後に空行のみの場合の品質判定                       |
| T-L3-EC-05 | 複数行 Trigger の文字数合算による品質判定                          |

**特記事項**: T-L3-EC-01 は `isObjectLikeRecord()` 型ガードの動作を検証。boolean/null/array などの JSON プリミティブが `$schema` と `type` の検証をスキップし、両方 warning を返すことを確認。

### 3.3 Layer 4 テスト（8件追加）

Layer 4 は相互参照整合性の検証を行う。

#### 3.3.1 Anchors リスト項目検証（T-L4-01 ~ T-L4-03）

- **L4-001**: `## Anchors` セクション内にマークダウンリスト項目（`-` または `*`）が存在するか
- セクション自体の不在も error として検出

#### 3.3.2 references/ 参照整合性（T-L4-04 ~ T-L4-06）

- **L4-002**: SKILL.md 内で `references/` パスとして言及されたファイルが実在するか
- パストラバーサル（`references/../escape.md`）の検出・防止機能も検証
- references/ ディレクトリ不在時は emit しない

#### 3.3.3 agent ファイル言及確認（T-L4-07 ~ T-L4-08）

- **L4-003**: agents/ 配下の .md ファイル名が SKILL.md 本文で言及されているか
- `escapeRegex()` による正規表現安全性と、word boundary チェックによる偽陽性防止を検証
  - 例: `myplanner.md` が `planner.md` のチェックにマッチしないこと
