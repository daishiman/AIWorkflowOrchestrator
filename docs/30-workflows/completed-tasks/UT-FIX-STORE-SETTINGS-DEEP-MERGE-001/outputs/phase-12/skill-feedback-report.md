# スキルフィードバックレポート

## 知見 1: マージ戦略の設計明示

**内容**: IPCハンドラ実装時に「シャロー vs ディープ」マージ戦略を Phase 2 設計で明示的に決定すべきである。
本タスクでは Phase 12（スキルFBレポート）で後発的に発見されたが、本来は設計フェーズで議論・決定すべき事項。

**適用タイミング**: 新しい IPC ハンドラ実装時・設定オブジェクトを扱うハンドラの設計レビュー時

## 知見 2: Record<string, unknown> 型とマージ戦略の曖昧性

**内容**: `Record<string, unknown>` 型は値が何でもよいため、マージ戦略の設計を曖昧にしやすい。
設計書には `deepMerge` の型シグネチャとマージルール（配列/null/undefined の扱い）を明示することで、
実装者が判断を誤るリスクを減らせる。

**適用タイミング**: IPC ハンドラ設計書作成時

## 知見 3: 入力バリデーションと prototype pollution 防止

**内容**: IPC 経由の設定更新は、型だけでなく「plain object かどうか」まで検証する必要がある。
また、`__proto__` / `constructor` / `prototype` のような危険キーを無視しないと prototype pollution の経路になる。

**適用タイミング**: `settings:update` のようなオブジェクト更新型 IPC の設計・実装時
