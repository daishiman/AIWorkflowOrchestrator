### ステップ2: 実行タスクを上から順に実施する

Task 1（異常系）→ Task 2（境界値）→ Task 3（エッジケース）→ Task 4（回帰）の順で処理する。

#### Task 1: 異常系テスト追加

以下の異常系テストケースを追加する。

| #      | テストケース名                                         | 入力                      | 期待出力                       | 分類   |
| ------ | ------------------------------------------------------ | ------------------------- | ------------------------------ | ------ |
| T-6-1a | ハンドラファイルが空の場合は空の HandlerEntry[] を返す | 空文字列のソースファイル  | `[]`                           | 異常系 |
| T-6-1b | Preload ファイルが空の場合は空の PreloadEntry[] を返す | 空文字列のソースファイル  | `[]`                           | 異常系 |
| T-6-1c | ファイル読み取り失敗時にエラーハンドリングが機能する   | 存在しないファイルパス    | エラーメッセージと exit code 2 | 異常系 |
| T-6-1d | 不正な構文のソースファイルでもクラッシュしない         | 構文的に不正な TypeScript | 空配列または部分結果           | 異常系 |

#### Task 2: 境界値テスト追加

以下の境界値テストケースを追加する。

| #      | テストケース名                                         | 入力                         | 期待出力                   | 分類   |
| ------ | ------------------------------------------------------ | ---------------------------- | -------------------------- | ------ |
| T-6-2a | チャンネル名にスペースを含む場合に正しく抽出する       | `'skill: import'`            | 正しく抽出される           | 境界値 |
| T-6-2b | チャンネル名に特殊文字を含む場合に正しく抽出する       | `'skill:import-v2.0'`        | 正しく抽出される           | 境界値 |
| T-6-2c | ハンドラが0件のプロジェクトでもレポートが生成される    | Handler: `[]`, Preload: `[]` | `passed: true`, 空レポート | 境界値 |
| T-6-2d | 大量ハンドラ（100+）でもスクリプトがタイムアウトしない | 100+ ハンドラのソース        | 10秒以内に結果を返す       | 境界値 |

#### Task 3: エッジケーステスト追加

以下のエッジケーステストケースを追加する。

| #      | テストケース名                                        | 入力                                       | 期待出力                                     | 分類         |
| ------ | ----------------------------------------------------- | ------------------------------------------ | -------------------------------------------- | ------------ |
| T-6-3a | コメントアウトされた ipcMain.handle 行を無視する      | `// ipcMain.handle('disabled:ch', ...)`    | 抽出されない                                 | エッジケース |
| T-6-3b | ブロックコメント内の ipcMain.handle 行を無視する      | `/* ipcMain.handle('disabled:ch', ...) */` | 抽出されない                                 | エッジケース |
| T-6-3c | マルチライン定義の ipcMain.handle を正しく抽出する    | ハンドラ登録が複数行に渡るソース           | 正しく抽出される                             | エッジケース |
| T-6-3d | テンプレートリテラルのチャンネル名を検出する          | ``safeInvoke(`skill:${action}`, data)``    | ハードコード文字列として検出されない（動的） | エッジケース |
| T-6-3e | IPC_CHANNELS 定数を使わない直接文字列をR-03で検出する | `safeInvoke('skill:import', data)`         | R-03 warning として検出される                | エッジケース |

#### Task 4: 回帰テスト追加

以下の回帰テストケースを追加する。

| #      | テストケース名                                           | 入力                                                    | 期待出力                | 分類 |
| ------ | -------------------------------------------------------- | ------------------------------------------------------- | ----------------------- | ---- |
| T-6-4a | P44パターン具体例: skill:import の引数不一致が検出される | Handler: `{ skillIds: string[] }`, Preload: `skillName` | R-02 ドリフトとして検出 | 回帰 |
| T-6-4b | P44パターン具体例: skill:remove の引数不一致が検出される | Handler: `{ skillId: string }`, Preload: `skillName`    | R-02 ドリフトとして検出 | 回帰 |
