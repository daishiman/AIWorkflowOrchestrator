### Step 2: 30思考法レビュー要約

| 系統         | 適用した思考法                             | 結論                                                          |
| ------------ | ------------------------------------------ | ------------------------------------------------------------- |
| 論理分析系   | 批判的、演繹、帰納、アブダクション、垂直   | arm64 固定は誤った前提であり、不一致そのものを直すべき        |
| 構造分解系   | 要素分解、MECE、2軸、プロセス              | 診断・修正・再検証・close-out を分離すると漏れが減る          |
| メタ・抽象系 | メタ、抽象化、ダブルループ                 | 問題は個別テストではなく worktree 運用境界にある              |
| 発想・拡張系 | ブレスト、水平、逆説、類推、if、素人       | exact command と checklist を docs に残すのが最小コストで強い |
| システム系   | システム、因果関係、因果ループ             | install 経路と test 経路の不一致が再発ループを作る            |
| 戦略・価値系 | トレードオン、プラスサム、価値提案、戦略的 | まず対象テストを回復し、CI 全面改修は切り出すのが妥当         |
| 問題解決系   | why、改善、仮説、論点、KJ法                | backlog 重複防止と same-wave sync を早めに仕様化すべき        |

### Step 3: リスク評価

| リスク                             | 影響度 | 対策                                                              |
| ---------------------------------- | ------ | ----------------------------------------------------------------- |
| `pnpm install --force` で直らない  | 中     | `node_modules` 再生成と `pnpm rebuild esbuild` を fallback にする |
| arm64 / x64 どちらが正か議論になる | 中     | active runtime に合わせるという契約で固定する                     |
| Phase 12 で backlog が重複する     | 高     | 既存 UT エントリ再利用を明記する                                  |
| Phase 13 で禁止操作が紛れ込む      | 高     | blocked と明記し、公開は別指示待ちにする                          |
