#### Part 1: 概念的説明（中学生レベル）【必須】

**目的**: 技術的背景がない人でも無限ループの問題がなぜ発生し、どう解決されたのかを理解できるよう、日常の例えで説明する。

**記述ルール（必須）**:

- 日常生活での例え話を**必ず**含める
- 専門用語は使わない（使う場合は即座に括弧内で説明）
- 「なぜ必要か」を先に説明してから「何をするか」を説明

**必須項目**:

| セクション       | 内容                                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| 無限ループとは   | プログラムが同じ処理を永遠に繰り返してしまう状態                       |
| なぜ起きたか     | 「状態が変わった」と勘違いして何度も同じ処理を始めてしまう             |
| 何が改善されたか | 「最初の1回だけ実行する」というルールを明確にした                      |
| 日常例え         | 「扉を開けるたびに『開けなきゃ』と思い続けるロボット」の問題を解決した |

**例え話テンプレート（必須で使用）**:

```markdown
## 日常での例え

今までのコードでは、「設定を読み込む」という処理が何度も繰り返されていました。

例えると、ロボットが「扉が閉まっているか確認して、閉まっていたら開ける」という命令を受けているのですが、
扉を開けた後も「まだ確認しなきゃ」と思い続けて、ずっと確認と開ける動作を繰り返してしまう状態です。

問題点：

- ロボットは永遠に「確認→開ける→確認→開ける」を繰り返す
- 他の仕事ができなくなる
- 電池（CPU）がすぐになくなる

改善後：
このタスクでは、「最初の1回だけ扉を確認して開ける」というルールを明確にしました。

- 「もう確認したよ」というメモ（useRef）を残す
- 2回目以降は「メモがあるから確認しなくていい」と判断できる
- 他の仕事に取りかかれるようになった
```

**補足例え（依存配列の説明）**:

```markdown
### 依存配列（dependency array）とは

Reactには「この値が変わったら処理を実行して」というリストがあります。

例えると、「お母さんが帰ってきたら（依存）、おかえりを言う（処理）」という約束です。

問題：
毎回「新しいお母さん」が帰ってくると判断してしまう
（実際は同じお母さんなのに、毎回「別の人」と認識してしまう）

解決策：
「お母さんが帰ってきたかどうか」だけを見るようにする
（人そのものではなく、「帰ってきた」という事実だけを見る）
```

#### Part 2: 技術者向け実装詳細【必須】

**必須項目**:

| セクション                 | 内容                                               |
| -------------------------- | -------------------------------------------------- |
| 問題の根本原因             | 合成Hookが毎回新しいオブジェクトを返す仕組みの説明 |
| 短期解決策（useRef）       | useRefを使った初期化ガードパターンのコード例       |
| 長期解決策（個別セレクタ） | 個別セレクタベースへの再設計方針                   |
| 修正対象ファイル           | 修正が必要だったファイルの一覧                     |
| テスト追加ポイント         | 無限ループを検出するテストパターン                 |

**問題の根本原因（記載必須）**:

```typescript
// 問題のあるコード
const { initializeAuthMode } = useAuthModeStore();

useEffect(() => {
  initializeAuthMode(); // この関数は毎回新しい参照を持つ
}, [initializeAuthMode]); // 依存配列に関数を含めると無限ループ

// なぜ無限ループが発生するか：
// 1. useAuthModeStore()は毎回新しいオブジェクトを返す
// 2. そのオブジェクト内の関数（initializeAuthMode）も毎回新しい参照
// 3. useEffectは依存配列の値が変わると再実行
// 4. 関数が「変わった」と判断され、useEffectが再実行
// 5. 再実行によりコンポーネントが再レンダー
// 6. 再レンダーで再度useAuthModeStore()が呼ばれ、新しいオブジェクトが返る
// 7. 2に戻り、無限ループ
```

**短期解決策（記載必須）**:

```typescript
// 修正後のコード - useRefでガード
const { initializeAuthMode } = useAuthModeStore();
const initRef = useRef(false);

useEffect(() => {
  if (!initRef.current) {
    initRef.current = true;
    initializeAuthMode();
  }
}, []); // 依存配列は空にする
```

**長期解決策（記載必須）**:

```typescript
// 将来的な改善 - 個別セレクタベースに再設計
const authMode = useAuthMode(); // 値のみ取得
const setAuthMode = useSetAuthMode(); // 関数のみ取得

// これにより、値が変わらない限りre-renderしない
// 関数は安定した参照を持つように設計
```
