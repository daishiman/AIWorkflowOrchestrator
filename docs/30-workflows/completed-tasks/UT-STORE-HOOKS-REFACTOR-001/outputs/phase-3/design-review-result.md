## 4. 技術的リスク評価

| リスク項目                 | 評価 | 対策                             |
| -------------------------- | ---- | -------------------------------- |
| 既存コンポーネントへの影響 | 低   | 後方互換性を維持（非推奨化のみ） |
| パフォーマンス劣化         | 低   | 単一値セレクタで最適化           |
| テスト工数増加             | 中   | 個別セレクタごとのテスト必要     |
| 移行作業の複雑性           | 中   | 移行パターンを文書化済み         |

### 4.1 リスク詳細分析

#### 既存コンポーネントへの影響（低）

- 合成Store Hook（`useAuthModeStore()`等）は維持されるため、既存コードの変更は不要
- 新規コードのみ個別セレクタを使用する段階的移行が可能
- 破壊的変更なし

#### パフォーマンス劣化（低）

- 個別セレクタは単一の状態値のみを購読
- 無関係な状態変更で再レンダリングしない
- 再レンダリング回数は減少する見込み

#### テスト工数増加（中）

- 個別セレクタごとのテストが必要
- ただし、テストは単純で明確
- TDDアプローチで効率的に進行可能

#### 移行作業の複雑性（中）

- 修正パターン仕様で移行手順を文書化済み
- Before/Afterのコード例を提供
- チェックリストで移行漏れを防止
