## 受け入れ基準一覧

### AC-1: 無限ループ解消

#### 概要

個別セレクタを`useEffect`の依存配列に含めても無限ループが発生しないこと。

#### 検証コード

```typescript
// 以下のパターンで無限ループが発生しないこと
const fetchProviders = useFetchLLMProviders();
useEffect(() => {
  fetchProviders();
}, [fetchProviders]); // ESLint警告なし、無限ループなし
```

#### 検証方法

1. テストコード実行: アクションセレクタを依存配列に含めたテストケース
2. 開発環境での動作確認: SettingsView, LLMSettingsCardでの実際の動作
3. React DevTools: Profilerでの再レンダリング回数の確認

#### 合格基準

- テストが無限ループせずに完了すること
- 開発環境でUIが正常に動作すること
- 再レンダリング回数が有限であること

---

### AC-2: 後方互換性

#### 概要

既存の合成Store Hook（`useAuthModeStore()`, `useLLMStore()`等）が引き続き動作すること。

#### 検証コード

```typescript
// 既存コードが引き続き動作すること
const { mode, fetchMode } = useAuthModeStore(); // 非推奨だが動作する
```

#### 検証方法

1. TypeScriptコンパイル: 既存コードがコンパイルエラーなしでビルドされること
2. 単体テスト: 既存の合成Store Hookを使用したテストがパスすること
3. 手動テスト: 既存機能が正常に動作すること

#### 合格基準

- 既存コードの変更なしでビルドが成功すること
- 既存のテストが全てパスすること
- 非推奨警告（JSDoc `@deprecated`）が表示されること

---

### AC-3: 型安全性

#### 概要

個別セレクタHookが正しい型推論を提供すること。

#### 検証コード

```typescript
// 正しい型推論が効くこと
const mode = useAuthMode(); // AuthMode型として推論
const setMode = useSetAuthMode(); // (mode: AuthMode) => Promise<void>として推論
```

#### 検証方法

1. TypeScriptコンパイル: 型エラーなしでビルドされること
2. IDEでの型チェック: 補完候補が正しく表示されること
3. 型テスト: 意図しない型の代入がコンパイルエラーになること

#### 合格基準

- TypeScriptの`strict: true`モードでコンパイルエラーがないこと
- 各セレクタの戻り値型が仕様どおりであること
- 型アサーション（`as`）なしで使用できること

---

### AC-4: 再レンダリング最適化

#### 概要

無関係な状態変更で再レンダリングが発生しないこと。

#### 検証コード

```typescript
// 無関係な状態変更で再レンダリングしないこと
const mode = useAuthMode();
// status変更時に再レンダリングしない
```

#### 検証方法

1. 単体テスト: 特定の状態変更時に関連コンポーネントのみ再レンダリングされることを確認
2. React DevTools Profiler: 再レンダリング回数の計測
3. パフォーマンステスト: 大量の状態変更時のパフォーマンス測定

#### 合格基準

- 状態Aの変更時に、状態Aのみを参照するコンポーネントだけが再レンダリングされること
- React DevTools Profilerで不要な再レンダリングが確認されないこと
- 再レンダリング回数が最小限であること（状態変更1回につき関連コンポーネントのみ1回）
