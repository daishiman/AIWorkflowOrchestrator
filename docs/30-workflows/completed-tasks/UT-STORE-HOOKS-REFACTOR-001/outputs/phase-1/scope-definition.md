## 2. 影響範囲

### 2.1 直接影響

| 影響範囲               | 詳細                                          |
| ---------------------- | --------------------------------------------- |
| Zustand Store          | `index.ts`への個別セレクタ追加                |
| 設定画面コンポーネント | `useAuthModeStore()`, `useLLMStore()`使用箇所 |
| 型定義                 | 新規セレクタの戻り値型                        |

### 2.2 間接影響

| 影響範囲     | 詳細                                    |
| ------------ | --------------------------------------- |
| ESLint       | `react-hooks/exhaustive-deps`警告の解消 |
| テストコード | 新しいセレクタパターンへの対応          |
| ドキュメント | 使用方法の更新                          |

### 2.3 影響なし（スコープ外）

| 対象             | 理由                    |
| ---------------- | ----------------------- |
| Main Process     | Renderer層のみの変更    |
| Preload層        | Store操作には関与しない |
| IPC通信          | 変更なし                |
| データベース     | 変更なし                |
| 外部API（LLM等） | 変更なし                |

## 3. スコープIN/OUT

### 3.1 スコープIN（実装対象）

| 項目                               | 詳細                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| AuthModeSlice個別セレクタ          | 状態セレクタ7個、アクションセレクタ10個                 |
| LLMSlice個別セレクタ               | 状態セレクタ6個、アクションセレクタ8個、計算セレクタ3個 |
| AgentSlice個別セレクタ（主要部分） | 状態セレクタ約10個、アクションセレクタ約8個             |
| 合成Store Hookの非推奨化           | `@deprecated` JSDocの追加                               |
| 設定画面コンポーネントの移行       | 3コンポーネント                                         |
| 単体テスト                         | 無限ループ、再レンダリング、型安全性                    |
| ドキュメント                       | 移行ガイド、使用例                                      |

### 3.2 スコープOUT（実装対象外）

| 項目                           | 理由                                   |
| ------------------------------ | -------------------------------------- |
| 合成Store Hookの削除           | 後方互換性維持のため維持               |
| 全コンポーネントの移行         | 段階的移行のため、問題箇所のみ優先     |
| Slice内部のロジック変更        | セレクタ追加のみで内部構造は変更しない |
| 新規Sliceの追加                | 既存Sliceの改善のみ                    |
| パフォーマンス計測ツールの導入 | 別タスクとして検討                     |

## 5. リスク評価

### 5.1 技術的リスク

| リスク                     | 評価 | 対策                             |
| -------------------------- | ---- | -------------------------------- |
| 既存コンポーネントへの影響 | 低   | 後方互換性を維持（非推奨化のみ） |
| パフォーマンス劣化         | 低   | 単一値セレクタで最適化           |
| テスト工数増加             | 中   | 個別セレクタごとのテスト必要     |
| 移行作業の複雑性           | 中   | 移行パターンを文書化済み         |

| リスク           | 評価 | 対策                       |
| ---------------- | ---- | -------------------------- |
| セレクタ数が多い | 中   | 優先度に基づく段階的実装   |
| テスト作成工数   | 中   | TDDで効率的に進行          |
| レビュー工数     | 低   | 明確な設計基準による効率化 |
