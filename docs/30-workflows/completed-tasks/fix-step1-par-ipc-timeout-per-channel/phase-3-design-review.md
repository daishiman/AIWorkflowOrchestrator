## 設計レビュー観点

### 観点1: 後方互換性の維持

- `IPC_TIMEOUT_MS` の値と型が変わらないか
- `CHANNEL_TIMEOUTS` 未定義のチャンネルが `IPC_TIMEOUT_MS` へフォールバックするか
- `invokeWithTimeout` の引数・戻り値の型シグネチャが変わらないか
- 呼び出し元（`index.ts` / `skill-api.ts` / `skill-creator-api.ts`）の変更が不要か

### 観点2: 設計の単純さ

- `getChannelTimeout` が 1 行のフォールバック式で書けるか
- `CHANNEL_TIMEOUTS` が余分な層や抽象化なしに定義できるか
- 新しい型定義や shared type を増やしていないか

### 観点3: テスト可能性

- `getChannelTimeout` が `export` されていてユニットテスト可能か
- 各チャンネルの境界値（定義済み / 未定義）をテストできるか
- `invokeWithTimeout` のタイムアウト動作が既存テストと整合するか

### 観点4: 破棄判断

- チャンネル別クラスや factory パターンのような過剰な設計は破棄する
- `CHANNEL_TIMEOUTS` を外部から注入可能にする設計は不要として破棄する
- runtime でのチャンネル自動登録のような動的な仕組みは不要として破棄する
