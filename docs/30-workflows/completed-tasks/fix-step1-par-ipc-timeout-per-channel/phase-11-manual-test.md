自動テストでは確認しにくい実際の IPC 呼び出し動作を手動で検証する。

## 実行タスク

- MT-001〜MT-004 の手動シナリオを順番に実行する
- DevTools とログで `auth:login` / `auth:get-session` / `skill:execute` の IPC 呼び出しと応答を確認する
- 後方互換性の確認結果を記録する

## 前提条件

- アプリケーションがローカルで起動している
- DevTools が使用可能（console.log の確認用）
- タイムアウト値を確認できる環境（ログまたは trace）がある
- `getChannelTimeout` は internal helper なので、数値固定は Phase 4 / 5 の unit test で確認済みである
- Phase 11 では helper を直接呼ばず、実フローの timeout 挙動だけを確認する

---

## 実行手順

### シナリオ MT-001: auth:login 実フローの確認

1. アプリを起動する
2. ログイン操作を実行する
3. DevTools の Network または console で `auth:login` の IPC 呼び出しと完了を確認する
4. 500ms の個別タイムアウトで阻害されず完了することを確認する

### シナリオ MT-002: auth:get-session / auth:refresh 実フローの確認

1. セッション取得または更新が必要な操作を行う
2. DevTools の Network または console で `auth:get-session` または `auth:refresh` の IPC 呼び出しを確認する
3. 10 秒の個別タイムアウトで完了することを確認する

### シナリオ MT-003: skill:execute 実フローの確認

1. スキル実行フローを開始する
2. DevTools の Network または console で `skill:execute` の IPC 呼び出しを確認する
3. 60 秒の個別タイムアウトで正常に完了することを確認する
4. 既定の 5000ms で早期失敗しないことを確認する

### シナリオ MT-004: 後方互換性の確認

1. 既存の IPC 呼び出しフロー（auth 以外）が正常に動作することを確認する
2. タイムアウト変更によって既存機能に影響がないことを確認する
