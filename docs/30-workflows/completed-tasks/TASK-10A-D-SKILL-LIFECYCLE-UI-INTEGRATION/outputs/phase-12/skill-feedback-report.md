## ワークフロー改善点

### 1. プレースホルダー差替パターンの標準化

TASK-10A-D では「準備中」プレースホルダーを実コンポーネントに差し替えるアプローチを採用した。このパターンは以下の利点があった:

- 既存コンポーネント（SkillManagementPanel）の構造を維持しつつ段階的に機能を追加できる
- ビュー切替ロジックが既に存在するため、差替対象が明確
- テストも既存フレームワークの延長で書ける

**改善提案**: task-specification-creator の Phase 5 テンプレートに「プレースホルダー差替パターン」を公式パターンとして追加し、差替対象の特定手順を明文化する。

### 2. 複数セッションにまたがる大規模タスクの継続性

3セッションにわたるタスク実行で、コンテキスト圧縮後の引き継ぎが課題となった:

- Phase 1-5 の実装を1セッション目で完了
- Phase 6-9 の品質検証を2セッション目で完了
- Phase 10-12 のレビュー・ドキュメントを3セッション目で完了

**改善提案**: 各セッション終了時に `outputs/session-handoff.md` に次セッションへの引き継ぎ事項を記録するワークフローステップを追加する。

## 技術的教訓

### 1. Suggestion 型の正確なインポート

`applySkillImprovements` の引数を当初 `unknown[]` で定義したが、Preload API の型定義と不整合が発生した。`@repo/shared/types/skill-improver` から `Suggestion` 型を正しくインポートすることで解決。

**教訓**: IPC 境界を跨ぐ型定義は、必ず `@repo/shared` の共有型を使用し、`unknown[]` や `any` で仮定義しない。

### 2. P40（テスト実行ディレクトリ依存）の再確認

`cd apps/desktop` せずにテストを実行すると `@testing-library/jest-dom` の matcher が読み込まれず全テスト失敗する。このパターンは再発しやすい。

**教訓**: テストコマンドのドキュメントには常に `cd apps/desktop &&` プレフィックスを含める。
