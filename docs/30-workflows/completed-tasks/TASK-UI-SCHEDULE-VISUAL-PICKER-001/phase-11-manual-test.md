## 目的

Phase 10 までの自動テストでは検出できない UI ビジュアル品質・UX 快適性・AI 観点での操作性を、3層評価（Semantic / Visual / AI UX）で人間の目と操作感で確認する。

- **Semantic 層**: コンポーネントの意味・役割・状態が正しく伝わるか
- **Visual 層**: レイアウト・色・タイポグラフィ・アニメーションが仕様通りか
- **AI UX 層**: ユーザーが迷わず操作できるか、エラー時のガイダンスが適切か

## タスク分類: VISUAL

このタスクは UI コンポーネントを実装するため **VISUAL 分類** に該当する。
スクリーンショット計画（`screenshot-plan.json`）の作成と実施が必須要件である。

| 項目               | 内容                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 目的               | `FrequencySelector` で「毎日」を選択し、`TimePickerSection` で 9:00 を設定できることを確認                                                                                     |

| 操作手順           | 1. FrequencySelector で「毎日」を選択する<br>2. TimePickerSection で時刻「09:00」を入力する<br>3. CronPreview の出力が `0 9 * * *` であることを確認する<br>4. 保存ボタンを押す |

## 3層評価基準

### Semantic 層（意味・役割の正確さ）

| #   | 確認ポイント                                                         | 合否基準                                             |
| --- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| S-1 | FrequencySelector の各オプションラベルが日本語で正確か               | PASS: 「毎日」「毎週」「毎月」「毎時」等が正しく表示 |
| S-2 | WeekdaySelector のラベルが「月」〜「日」の順で正しいか               | PASS: 日本語曜日の並び順が仕様通り                   |
| S-3 | CronPreview が人間可読テキスト（cronHumanizer 出力）を表示しているか | PASS: 「毎日 9:00 に実行」等の自然言語が表示         |
| S-4 | エラーメッセージが具体的な対処方法を示しているか                     | PASS: ユーザーが次に何をすべきか明確                 |
| S-5 | AdvancedToggle のラベルが「上級者モード」の意図を伝えているか        | PASS: 切り替えで何が変わるかが分かる                 |

### Visual 層（見た目・デザインの品質）

| #   | 確認ポイント                                                           | 合否基準                                   |
| --- | ---------------------------------------------------------------------- | ------------------------------------------ |
| V-1 | Tailwind CSS のスタイルが設計仕様のカラーパレット通りか                | PASS: プライマリ/エラー/無効状態の色が統一 |
| V-2 | WeekdaySelector のチェック状態とデフォルト状態のコントラスト比 ≥ 4.5:1 | PASS: WCAG AA 準拠                         |
| V-3 | DayOfMonthSelector のボタングリッドが均等に並んでいるか                | PASS: ボタンサイズ統一・余白一定           |

| V-5 | アニメーション（モード切り替え等）がカクつかないか                     | PASS: 60fps を維持                         |

## HIGH 問題発見時の unassigned-task 自動生成フロー

手動テスト中に **HIGH** または **CRITICAL** 評価の問題を発見した場合、以下の手順で `unassigned-task` を自動生成する。

```
1. 問題を manual-test-result.md に記録する
   - 問題ID: BUG-{YYYYMMDD}-{連番}
   - 重篤度: HIGH / CRITICAL
   - 発見シナリオ番号
   - 再現手順
   - 期待動作 / 実際の動作
   - スクリーンショット ID

2. docs/30-workflows/unassigned-task/ 配下に unassigned-task ファイルを作成する
   - ファイル名: unassigned-TASK-UI-SCHEDULE-{BUG-ID}.md
   - 内容: タスク仕様書フォーマット（Phase 1-3 のみ記述）

3. artifacts.json の phase.11.artifacts に unassigned-task ファイルパスを追記する

4. Phase 12 の Task 12-4（未タスク検出）に HIGH 問題として引き継ぐ
```

## 統合テスト連携

Phase 10（統合テスト）で PASS した項目は手動テストのスコープ外とする。
ただし以下の場合は再確認を行う。

- 統合テストと実際の Electron 環境で挙動が異なる項目
- レンダラープロセスの IPC 通信タイミングに依存する項目
- 共通 validator が標準 API のみで動作すること

## 多角的チェック観点

- **回帰リスク**: 既存スケジュール（TASK-9G 実装分）を壊していないか
- **パフォーマンス**: DayOfMonthSelector（31 要素）のレンダリングが 16ms 以内か
- **国際化**: タイムゾーン表示が Electron の OS 設定に追従しているか
- **エラー境界**: VisualCronPicker 単体クラッシュが親コンポーネントに伝播しないか
- **メモリリーク**: スケジュール設定ダイアログを 10 回開閉してもメモリが増加しないか
