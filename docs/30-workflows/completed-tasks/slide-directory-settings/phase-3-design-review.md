## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物を検証し、実装に進む前に品質を確保する。要件と設計の整合性、セキュリティ要件の充足、システム仕様への準拠を確認する。

## 背景

設計レビューゲートは、実装前の最後の品質チェックポイント。ここで問題を発見することで、実装後の手戻りを防止する。特にElectronのセキュリティ要件（IPC通信、CSP）は実装後の修正コストが高いため、設計段階での確認が重要。

### タスク5: レビュー結果判定

**目的**: レビュー結果を総合判定し、次のアクションを決定する

**実行手順**:

1. 全レビュー結果を集約し、判定を行う

2. 判定基準:

| 判定     | 条件                             | 次のアクション        |
| -------- | -------------------------------- | --------------------- |
| PASS     | 全レビュー観点で問題なし         | Phase 4へ進行         |
| MINOR    | 軽微な指摘あり（1-2件）          | 指摘対応後、Phase 4へ |
| MAJOR    | 重大な問題あり（設計変更必要）   | Phase 2へ戻る         |
| CRITICAL | 致命的な問題あり（要件変更必要） | Phase 1へ戻る         |

3. 判定結果を `outputs/phase-3/review-verdict.md` に出力

- `outputs/phase-3/review-verdict.md`
