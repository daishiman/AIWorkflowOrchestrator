## 非機能要件一覧

### NFR-1: ホワイトリスト方式のIPC通信

**要件**: IPCチャンネルはホワイトリスト方式で管理する

**詳細**:

- 全てのIPCチャンネルを定数として定義（`SLIDE_SETTINGS_CHANNELS`）
- 定義外のチャンネルへのアクセスは拒否
- `contextBridge.exposeInMainWorld` で限定的なAPIのみ公開

**検証方法**:

- チャンネル定義ファイルの存在確認
- 未定義チャンネルへのアクセスがエラーになることを確認

**参照仕様**:

- `.claude/skills/aiworkflow-requirements/references/security-api-electron.md`

---

### NFR-2: パストラバーサル攻撃防止

**要件**: パストラバーサル攻撃を防止する

**詳細**:

- `../` を含むパスの拒否
- `..\\` を含むパス（Windows形式）の拒否
- `path.normalize()` + `path.resolve()` でパスを正規化
- ベースパスからの逸脱をチェック
- シンボリックリンクは `fs.realpath()` で解決後に検証
- URLエンコードされた `../`（`%2e%2e%2f`）の検出・拒否

**実装パターン**:

```typescript
private validatePath(targetPath: string): void {
  const normalized = path.normalize(targetPath);
  const resolved = path.resolve(this.basePath, normalized);

  if (!resolved.startsWith(this.basePath)) {
    throw new Error("PATH_TRAVERSAL_DETECTED");
  }
}
```

**検証方法**:

- `../` を含むパスでエラーが発生することを確認
- シンボリックリンクがベースパス外を指す場合に拒否されることを確認

### NFR-3: 読み込みパフォーマンス

**要件**: 設定読み込みは100ms以内に完了する

**詳細**:

- `electron-store` の同期的な `get()` メソッドを使用
- ファイルI/Oは初回のみ（メモリキャッシュ活用）
- 設定ファイルサイズは1KB未満を想定

**検証方法**:

- 設定読み込み時間を計測（100ms以内）
- パフォーマンステストで確認

---

### NFR-4: 破損時フォールバック

**要件**: 設定ファイル破損時はデフォルト値にフォールバックする

**詳細**:

- `electron-store` のスキーマバリデーション機能を活用
- JSON構文エラー時はデフォルト値を使用
- 必須フィールド欠損時はデフォルト値で補完
- フォールバック発生時はログに記録

**検証方法**:

- 破損したJSONファイルでアプリを起動し、デフォルト値が使用されることを確認
- 不正なスキーマバージョンでマイグレーションが試行されることを確認

---

### NFR-5: クロスプラットフォーム互換性

**要件**: Windows/macOS/Linuxで同一の動作を保証する

**詳細**:

- Electronのネイティブダイアログを使用（各OSのルックアンドフィール）
- パス区切り文字の自動処理（`path.join()` 使用）
- ホームディレクトリの展開（`os.homedir()` 使用）
- 各OSのデフォルトドキュメントフォルダに対応

**OS別の考慮事項**:

| OS      | パス区切り | ホームディレクトリ例  |
| ------- | ---------- | --------------------- |
| macOS   | `/`        | `/Users/{username}`   |
| Windows | `\`        | `C:\Users\{username}` |
| Linux   | `/`        | `/home/{username}`    |

**検証方法**:

- 各OSでダイアログが正常に表示されることを確認
- パスの正規化が各OSで正しく動作することを確認

---

### NFR-6: スキーママイグレーション

**要件**: 設定スキーマはバージョン管理し、マイグレーション対応する

**詳細**:

- `schemaVersion` フィールドでバージョン管理
- 古いバージョンからの自動マイグレーション
- マイグレーション失敗時はデフォルト値にリセット
- マイグレーションログの記録

**マイグレーション戦略**:

```typescript
// バージョン1からバージョン2へのマイグレーション例
const migrations = {
  "1→2": (oldSettings: SlideSettingsV1): SlideSettingsV2 => {
    return {
      ...oldSettings,
      newField: defaultValue,
      schemaVersion: 2,
    };
  },
};
```

**検証方法**:

- 古いバージョンの設定ファイルで新バージョンに正しくマイグレーションされることを確認
- マイグレーション失敗時にデフォルト値が使用されることを確認

## セキュリティ要件詳細

### IPC通信セキュリティ

| 要件             | 実装方法                       |
| ---------------- | ------------------------------ |
| ホワイトリスト   | `SLIDE_SETTINGS_CHANNELS` 定数 |
| sender検証       | `validateIpcSender()` 関数     |
| 型安全性         | `Result<T>` 型で統一           |
| contextIsolation | `true` 設定                    |
| nodeIntegration  | `false` 設定                   |
| sandbox          | `true` 設定                    |

### 入力バリデーション

| 項目             | バリデーション内容       |
| ---------------- | ------------------------ |
| 空文字列         | 拒否                     |
| 最大長           | 1000文字以下             |
| パストラバーサル | `../` パターン検出・拒否 |
| null文字         | 検出・拒否               |
| 特殊文字         | 日本語・スペースは許可   |

## パフォーマンス要件

| 操作           | 目標時間  | 測定方法             |
| -------------- | --------- | -------------------- |
| 設定読み込み   | 100ms以内 | アプリ起動時         |

| ダイアログ表示 | OSに依存  | ボタンクリック後     |
| バリデーション | 50ms以内  | パス入力後           |
