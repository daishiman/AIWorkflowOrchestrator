## 目的

テストカバレッジ目標の達成を検証し、統合テストを再実行してゲート判定を行う。カバレッジが目標に達していない場合は、Phase 6に戻って追加テストを作成する。

## 背景

Phase 6でテストを拡充した。このPhaseでは、カバレッジ目標を達成しているかを確認し、品質ゲートを通過する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ユニットテストカバレッジの確認

**目的**: ユニットテストのカバレッジ目標達成を確認する

**実行手順**:

1. カバレッジレポートを生成:

   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```

2. カバレッジ目標との比較:

| 指標              | 最低基準 | 推奨基準 | 実測値    | 判定 |
| ----------------- | -------- | -------- | --------- | ---- |
| Line Coverage     | 80%      | 90%      | \_\_\_\_% | [ ]  |
| Branch Coverage   | 60%      | 70%      | \_\_\_\_% | [ ]  |
| Function Coverage | 80%      | 90%      | \_\_\_\_% | [ ]  |

3. 未カバー部分の分析:
   - 未カバーの関数/ブランチをリストアップ
   - 追加テストが必要か判断

4. 結果を `outputs/phase-7/unit-coverage-report.md` に出力

**期待される成果物**:

- `outputs/phase-7/unit-coverage-report.md`

---

### タスク2: 統合テストの再実行

**目的**: 全ての統合テストが成功することを確認する

**実行手順**:

1. 統合テストを実行:

   ```bash
   pnpm --filter @repo/desktop test:integration
   ```

2. テスト結果の確認:
   - 全テストがパスしていること
   - 失敗したテストがある場合は原因を特定

3. 結果を `outputs/phase-7/integration-test-report.md` に出力

**期待される成果物**:

- `outputs/phase-7/integration-test-report.md`

---

### タスク3: 統合テストカバレッジの確認

**目的**: 結合テストのカバレッジ目標達成を確認する

**実行手順**:

1. 結合テストカバレッジの確認:

| 指標                         | 目標 | 実測値    | 判定 |
| ---------------------------- | ---- | --------- | ---- |
| IPCエンドポイント            | 100% | \_\_\_\_% | [ ]  |
| モジュール間インターフェース | 100% | \_\_\_\_% | [ ]  |
| 正常系シナリオ               | 100% | \_\_\_\_% | [ ]  |
| 異常系シナリオ               | 80%+ | \_\_\_\_% | [ ]  |
| 外部連携ポイント             | 100% | \_\_\_\_% | [ ]  |

2. IPCチャンネルカバレッジ:

| チャンネル                      | 正常系 | 異常系 | カバレッジ |
| ------------------------------- | ------ | ------ | ---------- |
| slideSettings:getDirectory      | [ ]    | [ ]    | \_\_\_\_%  |
| slideSettings:setDirectory      | [ ]    | [ ]    | \_\_\_\_%  |
| slideSettings:selectDirectory   | [ ]    | [ ]    | \_\_\_\_%  |
| slideSettings:validateDirectory | [ ]    | [ ]    | \_\_\_\_%  |
| slideSettings:getAllSettings    | [ ]    | [ ]    | \_\_\_\_%  |

3. 結果を `outputs/phase-7/integration-coverage-report.md` に出力

**期待される成果物**:

- `outputs/phase-7/integration-coverage-report.md`

---

### タスク4: ゲート判定

**目的**: カバレッジゲートを通過しているか判定する

**実行手順**:

1. ゲート判定基準:

| 判定  | 条件                         | 次のアクション              |
| ----- | ---------------------------- | --------------------------- |
| PASS  | 全カバレッジ目標達成         | Phase 8へ進行               |
| MINOR | 推奨基準未達だが最低基準達成 | Phase 8へ進行（改善点記録） |
| FAIL  | 最低基準未達                 | Phase 6へ戻り追加テスト     |

2. 判定結果:
   - ユニットテスト: [ ] PASS / [ ] MINOR / [ ] FAIL
   - 統合テスト: [ ] PASS / [ ] MINOR / [ ] FAIL
   - 総合判定: [ ] PASS / [ ] MINOR / [ ] FAIL

3. 判定結果を `outputs/phase-7/gate-verdict.md` に出力

**期待される成果物**:

- `outputs/phase-7/gate-verdict.md`

---

### タスク5: 改善点の記録（MINORの場合）

**目的**: 推奨基準未達の場合、改善点を記録する

**実行手順**:

1. 未達項目のリストアップ:
   - 未カバーの関数/ブランチ
   - 追加が望ましいテストケース

2. 改善の優先度設定:
   - 高: セキュリティ関連の未カバー部分
   - 中: エラーハンドリングの未カバー部分
   - 低: レアケースの未カバー部分

3. 改善点を `outputs/phase-7/improvement-notes.md` に出力

**期待される成果物**:

- `outputs/phase-7/improvement-notes.md`（MINOR判定の場合のみ）
