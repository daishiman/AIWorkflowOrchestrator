## 機能要件

### FR-1: 存在しない日付の検出

`validateCronExpression` 関数は、日フィールドと月フィールドが単純な数値で指定されており、weekday フィールドが `*` の場合に限り、その組み合わせが実在する日付かどうかを検証する。

- `0 9 31 2 *`（2月31日）→ エラーを返す
- `0 9 30 2 *`（2月30日）→ エラーを返す
- `0 9 29 2 *`（2月29日）→ 正常通過（cron として有効扱い）

### FR-2: 既存チェックとの連携

意味論的バリデーションは既存の「構文チェック → 値域チェック」に続く第3段階として追加する。既存の2段階チェックを変更しない。

### FR-3: エラーメッセージの日本語表示

意味論エラー時は日本語のエラーメッセージを返す。ScheduleDialog / ConversationRoundStep が既存の文字列表示ロジックをそのまま利用できる形にする。

### FR-4: 外部依存の追加禁止

新たな外部ライブラリを追加しない。純粋な TypeScript 実装のみで意味論チェックを実現する。

### FR-5: 公開 API の契約維持

`validateCronExpression(value: string): string | null` のシグネチャを変更しない。

---

## 非機能要件

### NFR-1: パフォーマンス

バリデーション処理時間は 100ms 未満であること（純粋な同期演算のため達成可能）。

### NFR-2: ブラウザ対応

Electron Renderer（ブラウザ環境）で動作すること。Node.js 専用 API を使用しないこと。

### NFR-3: バンドルサイズ

外部ライブラリを追加しないため、バンドルサイズへの影響はゼロ。

---

## スコープ外

- カンマ区切り・範囲指定・ステップ指定を含む複合フィールドの意味論チェック（実装コスト対比で除外）
- 閏年（2月29日）の実際の年の検証（cron は年未指定のため除外、2月29日は有効とする）
- UI コンポーネントの直接変更（既存の文字列表示ロジックで対応可能）
