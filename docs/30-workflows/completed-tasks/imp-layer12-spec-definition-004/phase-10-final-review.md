## 目的

Phase 1-9 の全成果物を総合的にレビューし、AC（受け入れ基準）の充足を確認して最終判定を行う。

## 実行タスク

### タスク1: AC（受け入れ基準）の充足確認

**目的**: AC-1 〜 AC-7 の全てが PASS であることを確認する

**手順**:

1. 各 AC を順に検証し、充足状況を記録する:

| AC   | 内容                                                                         | 判定 |
| ---- | ---------------------------------------------------------------------------- | ---- |
| AC-1 | Layer 1-2 の全 check ID（12 件）が仕様書に記載されている                     |      |
| AC-2 | Layer 3-4 の全 check ID（7 件）が仕様書に記載されている                      |      |
| AC-3 | 各 check ID に検証内容・severity・判定基準・エラーメッセージが記載されている |      |
| AC-4 | check ID の命名規則（`L{N}-{NNN}`）が統一されている                          |      |
| AC-5 | Layer 拡張ガイドラインが記載されている                                       |      |
| AC-6 | 実装（SkillCreatorVerificationEngine.ts）との整合性が確認されている          |      |
| AC-7 | Markdown 構文が正常で lint エラーがない                                      |      |

2. 全 AC が PASS でない場合、未達の AC を特定し対応方針を記録する

**成果物**: AC 充足状況テーブル

### タスク2: 設計との整合性確認

**目的**: Phase 2 設計書で決定した構成が実際の追記内容と一致するか確認する

**手順**:

1. Phase 2 設計書の以下の項目を追記済みファイルと突き合わせる:
   - 追記先ファイルが設計通りか
   - セクション構成が設計通りか
   - check ID テーブルのカラム定義が設計通りか
   - Layer 拡張ガイドラインの内容が設計通りか
2. 乖離がある場合、意図的な変更か意図しない差異かを判定する
3. 意図的な変更の場合は理由を記録する

**成果物**: 設計整合性確認結果

### タスク3: 判定と記録

**目的**: 最終レビュー結果を判定し記録する

**判定基準**:

| 判定     | 条件             | 対応                             |
| -------- | ---------------- | -------------------------------- |
| PASS     | 全観点で問題なし | Phase 11 へ進行                  |
| MINOR    | 軽微な指摘あり   | 未タスクとして記録後 Phase 11 へ |
| MAJOR    | 重大な問題あり   | 影響範囲に応じて戻り先を決定     |
| CRITICAL | 致命的な問題     | Phase 1 へ戻り                   |

**手順**:

1. タスク1・タスク2 の結果を総合的に評価する
2. 上記の判定基準に基づき判定を行う
3. MINOR 指摘がある場合は未タスクリストを作成する
4. MAJOR/CRITICAL の場合は具体的な問題点と戻り先を記録する
5. 最終判定結果を成果物に記録する

**成果物**: 最終判定結果
