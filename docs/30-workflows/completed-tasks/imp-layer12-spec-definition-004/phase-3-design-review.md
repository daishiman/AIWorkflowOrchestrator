## 目的

## 実行タスク

### タスク1: 追記先ファイルの妥当性検証

**目的**: 選択した追記先ファイルが適切かを検証する

**手順**:

1. 追記先ファイルの決定理由を再確認する
2. 以下の観点でレビューする:
   - Single Source of Truth 原則に違反していないか
   - 既存の参照構造（resource-map, topic-map）との整合性があるか
   - 追記後のファイルサイズが妥当か（500行以下を目安）
   - 他の仕様書からの参照が容易か
3. 問題があれば Phase 2 に差し戻す

**レビュー基準**:

| 観点           | 基準                                              |
| -------------- | ------------------------------------------------- |
| 配置の妥当性   | verify 契約の情報を探す際に自然に辿り着ける場所か |
| サイズの妥当性 | 追記後も可読性が維持されるか                      |
| 参照の容易性   | topic-map / resource-map から辿れるか             |
| 拡張性         | Layer 5 以降追加時にも構造が破綻しないか          |

### タスク2: ドキュメント構成のレビュー

**目的**: セクション構成と check ID テーブル設計の品質を確認する

**手順**:

1. セクション構成を以下の観点でレビューする:
   - 各セクションの責務が明確か
   - 情報の重複がないか
   - 読者が必要な情報に素早くアクセスできるか
2. check ID テーブルのカラム定義をレビューする:
   - 全カラムが必要か（過不足がないか）
   - カラムの順序が自然か
   - エラーメッセージの言語（英語）が実装と一致するか
3. Layer 拡張ガイドラインの実用性を確認する:
   - 将来の実装者が迷わず Layer を追加できるか
   - 採番ルールが明確か

### タスク3: 実装との整合性確認

**目的**: 設計内容が `SkillCreatorVerificationEngine.ts` の実装と矛盾しないか確認する

**手順**:

1. Phase 1 の check ID 棚卸し結果と設計のテーブル定義を突き合わせる
2. check ID の総数が一致するか確認する:
   - Layer 1: 5 checks（L1-001〜L1-005）
   - Layer 2: 7 checks（L2-001〜L2-007）
   - Layer 3: 4 checks（L3-001〜L3-004）
   - Layer 4: 3 checks（L4-001〜L4-003）
   - 合計: 19 checks
3. severity の割り当てが実装と一致するか確認する

### タスク4: 判定と記録

**目的**: レビュー結果を判定し記録する

**判定基準**:

| 判定  | 条件                   | 対応                  |
| ----- | ---------------------- | --------------------- |
| PASS  | 全観点で問題なし       | Phase 4 へ進行        |
| MINOR | 軽微な修正で解決可能   | 修正後 Phase 4 へ進行 |
| MAJOR | 設計の根本的な問題あり | Phase 2 へ差し戻し    |
