# Check ID 命名規則分析

## 命名パターン

### 基本形式

```
L{N}-{NNN}
```

| 要素    | 意味                                 | 例  |
| ------- | ------------------------------------ | --- |
| `L`     | Layer の頭文字（固定プレフィックス） | -   |
| `{N}`   | Layer 番号（1〜4）                   | 1   |
| `-`     | 区切り文字（固定）                   | -   |
| `{NNN}` | 3 桁連番（Layer 内で 001 から連番）  | 001 |

### Layer 番号の意味

| Layer | 名称                                       | 責務                                           |
| ----- | ------------------------------------------ | ---------------------------------------------- |
| 1     | 構造検証 (Structural)                      | ファイル・ディレクトリの存在確認               |
| 2     | コンテンツ検証 (Content)                   | ファイル内の必須セクション・構造の存在確認     |
| 3     | 詳細コンテンツ検証 (Detailed Content)      | フィールド値の妥当性・コンテンツ品質の検証     |
| 4     | 参照整合性・結合検証 (Reference Integrity) | ファイル間の参照整合性・クロスリファレンス検証 |

### 連番の採番ルール

- Layer 内で 001 から連番を割り当てる
- 欠番は許容しない（削除時は全体を振り直す）
- 各 Layer の連番は独立（Layer 1 の L1-005 の次は L1-006、Layer 2 は L2-001 から独立して採番）

## Severity 割り当て方針

| Severity  | 意味         | 用途                                                                | 件数 |
| --------- | ------------ | ------------------------------------------------------------------- | ---- |
| `error`   | 必須要件違反 | 品質ゲート（ハードゲート）。この check が fail するとスキルは不合格 | 10   |
| `warning` | 推奨要件違反 | 改善推奨。fail してもスキルは通過可能                               | 9    |

### Severity 割り当てパターン

- **error**: ファイル存在（SKILL.md, agents/）、必須セクション（H1, overview, Trigger）、JSON 妥当性、型妥当性、Anchors リスト項目
- **warning**: 推奨ディレクトリ（references/）、推奨ファイル（output-schema.json）、推奨セクション（Anchors, 責務）、コンテンツ品質（文字数閾値）、参照整合性

## Layer 間の依存関係

```
Layer 1（構造検証）
  ↓ ファイル・ディレクトリの存在が確認されて初めて
Layer 2（コンテンツ検証）
  ↓ セクションの存在が確認されて初めて
Layer 3（詳細コンテンツ検証）
  ↓ コンテンツの品質が確認されて初めて
Layer 4（参照整合性・結合検証）
```

- Layer 1 が fail するとそのファイルの Layer 2 以降は検証不能
- Layer 2 が fail するとそのセクションの Layer 3 以降は検証不能
- Layer 4 はファイル間の整合性検証のため、全ファイルの Layer 1-3 が前提

## 拡張時のルール

1. **新規 Layer 追加**: Layer 番号は連番（次は Layer 5）、`L5-001` から採番
2. **既存 Layer への check 追加**: 現在の最大連番 + 1（例: Layer 2 に追加なら L2-008）
3. **仕様書と実装の同期**: 仕様書追記 → 実装追加の順序を推奨（TDD アプローチ）
