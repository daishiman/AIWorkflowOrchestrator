## 目的

型安全性の問題・コードの重複を修正する（実装修正があった場合）。

## 実行タスク

### タスク1: リファクタ対象判定

**目的**: verify_existing タスクとして refactor 必要性を最小限に判定する。

**実行手順**:

1. Phase 5 の修正有無を確認する。
2. 型安全性・重複テスト・命名整合の観点で対象有無を判定する。

**期待される成果物**:

- refactor 判定ログ

### タスク2: 必要最小限の整理

**目的**: 変更があった場合のみ品質劣化を防ぐ整形を行う。

**実行手順**:

1. 型定義や重複テストの整理を実施する。
2. テスト再実行で回帰がないことを確認する。

**期待される成果物**:

- 整理結果
- 再実行結果

## 方針

本タスクは verify_existing モード。Phase 5 で実装修正がなかった場合、Phase 8 は「対象なし」として記録するだけでよい。

## リファクタリング対象（修正があった場合）

| 観点         | 確認内容                                                              |
| ------------ | --------------------------------------------------------------------- |
| 型安全性     | `skillCreatorAPI` の型が `any` や `unknown` になっていないか          |
| Optional連鎖 | `skillCreatorAPI?.cancelGeneration?.()` の optional chaining が適切か |
| 重複削除     | E2E テストと既存単体テストで同じロジックをテストしていないか          |
| 命名整合     | 新規追加した変数・関数名が既存コードの命名規則と一致しているか        |

## リファクタリング判断基準

| 判断                    | 対応                                           |
| ----------------------- | ---------------------------------------------- |
| 修正なし（verify のみ） | リファクタリング対象なし。Phase 9 へ進む       |
| 型安全性の問題あり      | 型定義を修正し Phase 9 で typecheck を確認する |
| 重複テストあり          | 重複を削除してテストを整理する                 |
