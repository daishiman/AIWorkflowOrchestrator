## 目的

4条件と CANCEL chain 整合で設計を監査し、Phase 4 進行可否を決定する。

## 実行タスク

### タスク1: 4条件レビュー

**目的**: 価値性・実現性・整合性・運用性を review gate として評価する。

**実行手順**:

1. 4条件ごとの評価基準を適用する。
2. verify_existing 前提が保たれているか確認する。
3. close-out 可能な成果物構成か判定する。

**期待される成果物**:

- 4条件レビュー結果
- review gate 判定

### タスク2: chain 整合と設計矛盾の監査

**目的**: CANCEL-001〜004 の責務境界とレーン競合を監査する。

**実行手順**:

1. CANCEL chain 整合チェックを行う。
2. CANCEL-003 の教訓適用を確認する。
3. 設計矛盾チェックを行い戻り先を判断する。

**期待される成果物**:

- chain 整合チェック結果
- 教訓適用確認
- 戻り先判断

## レビュー観点

### 4条件の評価

| 条件   | 評価基準                                                     | 確認項目                                                                         |
| ------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 価値性 | キャンセル chain 完結による UX・信頼性向上が定義されているか | AC-1〜AC-6 が CANCEL chain 完結を保証する内容になっているか                      |
| 実現性 | 初回スコープで実装可能な厚みに収まっているか                 | verify_existing モードで Main 側再実装がないこと。修正は最小限に限定されているか |
| 整合性 | 責務境界・依存関係・状態所有権が矛盾なく閉じているか         | Renderer/Preload/Main の責務分担が Phase 2 設計と一致しているか                  |
| 運用性 | 確認後の verify・spec sync・監査運用が破綻しないか           | Phase 12 mandatory 5 tasks で close-out 可能な成果物構成になっているか           |

### CANCEL chain 整合チェック

| チェック項目                                              | 期待値                                         |
| --------------------------------------------------------- | ---------------------------------------------- |
| CANCEL-001〜003 の完了前提が仕様書に明記されているか      | index.md および Phase 1 で明記                 |
| 本タスクの範囲が Main 側の再実装を含まないか              | Phase 2 修正パターンが Renderer/Preload に限定 |
| CANCEL-004 完了でチェーン完結であることが明記されているか | index.md 最終ゴールに記載                      |

### CANCEL-003 の教訓適用チェック

| 教訓（CANCEL-003 時点）                         | 本タスクでの対応                                     |
| ----------------------------------------------- | ---------------------------------------------------- |
| 新規実装テンプレートと既実装確認の混線          | 全フェーズを `verify_existing` として明記済み        |
| チェーン分割タスク管理で E2E 完了が不明確だった | `index.md` に「CANCEL-004 完了でチェーン完結」を明記 |

### 設計矛盾チェック

- [ ] Phase 2 の E2E テスト設計が既存 `useCancelGeneration.test.ts` と重複していないか
- [ ] SubAgent 分割で Lane A と Lane B が同一成果物を並行編集しないか
- [ ] 修正パターンが CANCEL-001〜003 の実装を破壊しないか

## レビュー判定基準

| 判定             | 条件                                                    |
| ---------------- | ------------------------------------------------------- |
| PASS             | 4条件すべて PASS、CANCEL chain 整合チェック全項目クリア |
| CONDITIONAL_PASS | 軽微な修正方針が確定すれば Phase 4 に進む               |
| FAIL             | 設計の根本的な矛盾があり Phase 2 に戻る必要がある       |
