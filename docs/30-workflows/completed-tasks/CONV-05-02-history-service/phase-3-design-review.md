## レビュー観点

### 1. 要件との整合性

- [ ] 全機能要件が設計でカバーされている
- [ ] 非機能要件（パフォーマンス、エラー処理）が設計に反映されている

### 2. 設計品質

- [ ] 単一責務原則（SRP）が守られている
- [ ] インターフェースが適切に分離されている
- [ ] 依存関係が適切（循環依存なし）

### 3. 型安全性

- [ ] TypeScript型が適切に定義されている
- [ ] Zodスキーマがランタイム検証をカバーしている
- [ ] Result型によるエラーハンドリングが一貫している

### 4. 統合観点

- [ ] ConversionRepository/FileRepositoryとの連携が明確
- [ ] エラーハンドリングの統合パターンが一貫している

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
