## 技術的教訓

### TL-1: P31派生パターン -- `.filter()`を使う派生セレクタには`useShallow`が必須

| 項目      | 内容                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発見Phase | Phase 8（リファクタリング）                                                                                                                                                      |
| 概要      | `.filter()`を使用する派生セレクタは毎回新しい配列参照を返すため、ZustandのデフォルトObject.is比較で毎回「変更あり」と判定される。`useShallow`でshallow比較に切り替えることで解決 |
| 適用範囲  | `useAvailableSkillsForImport`、`useFilteredAvailableSkills`                                                                                                                      |
| 重要度    | 高 -- P31の直接的な派生であり、同様のパターンが他のstore selectorにも存在しうる                                                                                                  |
| 提案      | `arch-state-management.md`にuseShallowパターンを追記し、派生セレクタ作成時の必須チェック項目とする                                                                               |

### TL-2: 仕様策定のみモードでもテスト作成・コード検証は有効

| 項目      | 内容                                                                                                                                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 発見Phase | Phase 4-7                                                                                                                                                                                                               |
| 概要      | 仕様策定タスクでありながら、テストコードを実際に作成・実行したことで、設計の不備（派生セレクタの参照不安定性）がPhase 6のエッジケーステストで検出された。仕様書だけでは気付けなかった問題が、テスト実行により顕在化した |
| 重要度    | 中 -- 仕様策定のみモードでも品質ゲートをスキップしない価値を実証                                                                                                                                                        |
| 提案      | 仕様策定のみモードのPhaseテンプレートに「テスト実行による設計検証」を推奨ステップとして追加                                                                                                                             |

### TL-3: 既存実装の設計適合確認は実装工数の大幅削減につながる

| 項目      | 内容                                                                                                                                                                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 発見Phase | Phase 1, Phase 5                                                                                                                                                                                                                                                               |
| 概要      | Phase 1で既存agentSliceの状態フィールド・アクション・セレクタを調査した結果、要件の大部分（FR-1の5状態フィールド、FR-3のimportSkill/removeSkillアクション）が既に実装済みであることが判明。Phase 5での新規実装はセレクタ2つの追加のみで完了し、当初想定の1/3以下の工数で済んだ |
| 重要度    | 高 -- モノレポの大規模コードベースでは、既存実装の活用可否が工数に大きく影響する                                                                                                                                                                                               |
| 提案      | Phase 1テンプレートに「既存実装との差分分析」セクションを追加し、新規作成 vs 既存拡張の判断を早期に行う                                                                                                                                                                        |
