## 判定基準

| 判定     | 条件                                         | 対応                                                            |
| -------- | -------------------------------------------- | --------------------------------------------------------------- |
| PASS     | 5 観点の全チェック項目で問題なし             | Phase 11 へ進行                                                 |
| MINOR    | 機能影響のない軽微な問題が 1-3 件            | 全指摘を未タスク仕様書に変換後、Phase 11 へ進行（**省略不可**） |
| MAJOR    | 機能影響のある問題（設計レベルの修正が必要） | 問題の影響範囲に応じて Phase 2-5 へ戻る                         |
| CRITICAL | 要件未充足またはセキュリティ上の重大な問題   | Phase 1 へ戻り要件を再確認                                      |

## 実行手順

### 観点 1: 要件充足

Phase 1 で定義した全受入基準が実装に反映されていることを確認する。

| #   | 受入基準                                                       | 確認方法                                                 | 結果 |
| --- | -------------------------------------------------------------- | -------------------------------------------------------- | ---- |
| 1   | selector設計: imported / available / filtered の算出責務が定義 | 各selectorの入力・出力・算出ロジックが明記されていること | ✓/✗  |
| 2   | action設計: import実行中フラグ・成功後再読込・失敗時エラー保持 | 状態遷移図が全パスを網羅していること                     | ✓/✗  |
| 3   | 競合回避: TASK-10A-Fのcreate/analyze経路と責務が重複していない | 境界定義表が明確で重複フィールドがないこと               | ✓/✗  |
| 4   | 再レンダー方針: 個別selector優先でP31無限ループ回避条件が定義  | useEffect依存配列の制約が明記されていること              | ✓/✗  |

### 観点 2: 設計準拠

Phase 2 の設計決定事項と実装の差分を検証する。

| #   | 設計決定事項                                                   | 確認方法                                                  | 結果 |
| --- | -------------------------------------------------------------- | --------------------------------------------------------- | ---- |
| 1   | Zustand Slice分割がドメイン単位で定義されている                | 1 Sliceに複数ドメインの状態が混在していないこと           | ✓/✗  |
| 2   | アクション関数がstore内で完結し、コンポーネントにIPCが漏れない | store action内でIPC呼び出しが完結する設計になっていること | ✓/✗  |
| 3   | `arch-state-management.md` の状態配置原則に準拠                | 各状態の配置先が原則テーブルと一致すること                | ✓/✗  |

### 観点 3: P31無限ループ対策

| #   | チェック項目                                                                 | 確認方法                                                | 結果 |
| --- | ---------------------------------------------------------------------------- | ------------------------------------------------------- | ---- |
| 1   | 合成Store Hook（useXxxStore()）の戻り値関数をuseEffect依存配列に含めていない | コード上で禁止パターンが存在しないこと                  | ✓/✗  |
| 2   | 個別セレクタ（useXxx()）が使用されている                                     | 全てのstoreアクセスが個別セレクタ経由であること         | ✓/✗  |
| 3   | Zustandアクション参照の安定性が保証されている                                | アクションセレクタの戻り値がZustandの安定参照であること | ✓/✗  |

### 観点 4: エラー遷移

| #   | チェック項目                                              | 確認方法                                              | 結果 |
| --- | --------------------------------------------------------- | ----------------------------------------------------- | ---- |
| 1   | import成功時: isImporting → false、一覧再同期が発生する   | 状態遷移定義に成功パスが明記されていること            | ✓/✗  |
| 2   | import失敗時: isImporting → false、エラー状態が保持される | 状態遷移定義に失敗パスが明記されていること            | ✓/✗  |
| 3   | エラーカテゴリがerror-handling.mdの分類に準拠             | エラーコード範囲が仕様と一致すること                  | ✓/✗  |
| 4   | 連打防止: import実行中に再度importが呼ばれない            | isImportingフラグによるガード条件が定義されていること | ✓/✗  |

### 観点 5: コード品質

| #   | チェック項目                            | 確認方法                          | 結果 |
| --- | --------------------------------------- | --------------------------------- | ---- |
| 1   | TypeScript strict: true 準拠            | any型・@ts-ignoreが存在しないこと | ✓/✗  |
| 2   | Result<T, E> パターンでエラーが返される | try/catchで握りつぶしていないこと | ✓/✗  |
| 3   | テストカバレッジが基準を満たす          | Line 80%+, Branch 60%+            | ✓/✗  |
