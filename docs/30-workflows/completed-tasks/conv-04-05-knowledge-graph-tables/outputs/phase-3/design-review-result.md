## 3. 改善提案

### 3.1 優先度: 低（実装時に対応）

| 提案                          | 理由               | 対応                     |
| ----------------------------- | ------------------ | ------------------------ |
| `embedding`カラムのサイズ制限 | ベクトル次元が可変 | metadataで記録推奨       |
| `importance`/`weight`の検証   | 0.0-1.0範囲の保証  | アプリケーション層で検証 |
| `positions`配列の最大長制限   | メモリ考慮         | アプリケーション層で制限 |

### 3.2 将来の拡張性

設計は以下の拡張に対応可能:

- ベクトル検索インデックス追加
- FTS5全文検索統合
- マルチテナント対応（metadataにtenant_id追加可能）

## 5. 結論

### 5.1 承認理由

1. **既存パターンとの整合性**: chunks.tsの実装パターンに完全準拠
2. **完全性**: 6テーブル全ての定義が完備
3. **拡張性**: metadataカラムによる将来拡張が可能
4. **パフォーマンス考慮**: 適切なインデックス戦略

### 5.2 次フェーズへの申し送り

- Phase 4（テスト作成）では受け入れ基準AC-01〜AC-22を全てカバーすること
- Phase 5（実装）では80%以上のテストカバレッジを達成すること
- `relations`テーブルの変数名は`graphRelations`を使用すること
