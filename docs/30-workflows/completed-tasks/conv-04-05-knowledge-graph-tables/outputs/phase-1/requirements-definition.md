# 要件定義書: Knowledge Graph テーブル群

## 1. 機能要件

### 1.1 entitiesテーブル

エンティティ（ノード）を格納するテーブル。

| 要件ID | 要件                                                           |
| ------ | -------------------------------------------------------------- |
| FR-01  | エンティティはUUID形式の一意な識別子を持つ                     |
| FR-02  | エンティティは名前（name）と正規化名（normalizedName）を持つ   |
| FR-03  | エンティティはタイプ（person, organization, location等）を持つ |
| FR-04  | 同一正規化名+タイプの組み合わせは一意である                    |
| FR-05  | エンティティはオプションで埋め込みベクトルを持てる             |
| FR-06  | エンティティは重要度スコア（0.0〜1.0）を持つ                   |
| FR-07  | エンティティは出現回数を追跡する                               |
| FR-08  | エンティティは別名（aliases）のリストを持てる                  |

### 1.2 relationsテーブル

エンティティ間の関係（エッジ）を格納するテーブル。

| 要件ID | 要件                                                       |
| ------ | ---------------------------------------------------------- |
| FR-09  | 関係はソースエンティティとターゲットエンティティを参照する |
| FR-10  | 関係はタイプ（related_to, part_of, uses等）を持つ          |
| FR-11  | 同一ソース+ターゲット+タイプの組み合わせは一意である       |
| FR-12  | 関係は重み（0.0〜1.0）を持つ                               |
| FR-13  | 関係は双方向フラグを持つ                                   |
| FR-14  | 関係は証拠数（この関係を支持するチャンク数）を追跡する     |
| FR-15  | エンティティ削除時、関連する関係もCASCADE削除される        |

### 1.3 relationEvidenceテーブル

関係の証拠（出典チャンク）を格納するテーブル。

| 要件ID | 要件                                              |
| ------ | ------------------------------------------------- |
| FR-16  | 証拠は関係とチャンクを参照する複合主キーを持つ    |
| FR-17  | 証拠は抜粋テキスト（excerpt）を持つ               |
| FR-18  | 証拠は信頼度スコア（0.0〜1.0）を持つ              |
| FR-19  | 関係またはチャンク削除時、証拠もCASCADE削除される |

### 1.4 communitiesテーブル

Leidenアルゴリズムで検出されたコミュニティを格納するテーブル。

| 要件ID | 要件                                                     |
| ------ | -------------------------------------------------------- |
| FR-20  | コミュニティはUUID形式の一意な識別子を持つ               |
| FR-21  | コミュニティは階層レベル（0, 1, 2...）を持つ             |
| FR-22  | コミュニティは親コミュニティへの参照を持てる（自己参照） |
| FR-23  | コミュニティは名前とLLM生成サマリーを持つ                |
| FR-24  | コミュニティはメンバー数を追跡する                       |
| FR-25  | コミュニティはオプションで埋め込みベクトルを持てる       |

### 1.5 entityCommunitiesテーブル

エンティティとコミュニティの多対多関係を格納する中間テーブル。

| 要件ID | 要件                                                              |
| ------ | ----------------------------------------------------------------- |
| FR-26  | エンティティIDとコミュニティIDの複合主キーを持つ                  |
| FR-27  | エンティティまたはコミュニティ削除時、レコードもCASCADE削除される |

### 1.6 chunkEntitiesテーブル

チャンクとエンティティの多対多関係を格納する中間テーブル。

| 要件ID | 要件                                                          |
| ------ | ------------------------------------------------------------- |
| FR-28  | チャンクIDとエンティティIDの複合主キーを持つ                  |
| FR-29  | 各チャンク内でのエンティティ出現回数を記録する                |
| FR-30  | 出現位置（開始・終了文字位置、表層形）のリストを持てる        |
| FR-31  | チャンクまたはエンティティ削除時、レコードもCASCADE削除される |

## 2. 非機能要件

### 2.1 パフォーマンス

| 要件ID | 要件                                               |
| ------ | -------------------------------------------------- |
| NFR-01 | エンティティの正規化名検索は O(log n) で実行可能   |
| NFR-02 | 関係のソース/ターゲット検索は O(log n) で実行可能  |
| NFR-03 | コミュニティのレベル別取得は O(log n) で実行可能   |
| NFR-04 | 100万エンティティ規模でのクエリ応答時間は100ms以内 |

### 2.2 データ整合性

| 要件ID | 要件                                     |
| ------ | ---------------------------------------- |
| NFR-05 | 外部キー制約によりデータ整合性を保証する |
| NFR-06 | 一意制約により重複データを防止する       |
| NFR-07 | CASCADE削除により孤児レコードを防止する  |

### 2.3 拡張性

| 要件ID | 要件                                         |
| ------ | -------------------------------------------- |
| NFR-08 | metadataカラムにより将来的な拡張を許容する   |
| NFR-09 | エンティティタイプ、関係タイプはEnum拡張可能 |

## 3. 正規化レベル

### 3.1 決定

**第3正規形（3NF）を採用**

### 3.2 根拠

1. エンティティ、関係、コミュニティは独立したドメイン概念
2. 中間テーブルにより多対多関係を適切にモデリング
3. JSONカラム（aliases, positions, metadata）は意図的な非正規化
   - 理由: 頻繁なアクセスパターン、スキーマの柔軟性
   - 欠点: 部分更新不可、検索非効率（許容範囲）

### 3.3 意図的な非正規化

| カラム        | テーブル      | 理由                               |
| ------------- | ------------- | ---------------------------------- |
| aliases       | entities      | 別名は単純なリスト、個別管理は過剰 |
| positions     | chunkEntities | 位置情報は頻繁に一括取得           |
| metadata      | 各テーブル    | 将来拡張のための柔軟性             |
| mentionCount  | entities      | 集計クエリ削減のための非正規化     |
| evidenceCount | relations     | 集計クエリ削減のための非正規化     |
| memberCount   | communities   | 集計クエリ削減のための非正規化     |

## 4. 外部キー制約

### 4.1 CASCADE動作定義

| テーブル          | 外部キー    | 参照先         | onDelete |
| ----------------- | ----------- | -------------- | -------- |
| relations         | sourceId    | entities.id    | CASCADE  |
| relations         | targetId    | entities.id    | CASCADE  |
| relationEvidence  | relationId  | relations.id   | CASCADE  |
| relationEvidence  | chunkId     | chunks.id      | CASCADE  |
| communities       | parentId    | communities.id | SET NULL |
| entityCommunities | entityId    | entities.id    | CASCADE  |
| entityCommunities | communityId | communities.id | CASCADE  |
| chunkEntities     | chunkId     | chunks.id      | CASCADE  |
| chunkEntities     | entityId    | entities.id    | CASCADE  |

### 4.2 理由

- **CASCADE**: 親削除時に子も削除が適切な場合
- **SET NULL**: 親削除時に子を保持すべき場合（コミュニティ階層）
