## 本Phaseにおける「リファクタリング」の定義（読み替え）

本タスクはコード実装を伴わない**文書作成タスク**である。したがって、従来の
「リファクタリング（コード可読性・保守性改善）」を以下のように**文書構成最適化**として
読み替え、文書品質工程として正当化する。

| 用語             | 通常の意味               | 本タスクでの読み替え                                 |
| ---------------- | ------------------------ | ---------------------------------------------------- |
| リファクタリング | 動作を変えないコード改善 | **記述内容を変えない文書構成の改善**                 |
| 可読性           | コード読解の容易さ       | **ポリシー文書を読む運用者の理解容易性**             |
| 保守性           | コード変更の容易さ       | **ポリシー見直し時の更新箇所特定の容易さ**           |
| 命名一貫性       | 変数・関数の命名規則     | **用語統一（archive/アーカイブ、LOGS.md/logs.md）**  |
| コード重複解消   | DRY 原則                 | **既存 `logs-archive-*.md` との記述重複の dedupe**   |
| テスト維持       | 動作確認テストが通る     | **Phase 6 検証・Phase 7 カバレッジ判定が維持される** |

**最小変更原則**: 意味（アーカイブ閾値・パス規則・手順）は一切変更しない。表現・構成のみ最適化する。

## 目的

Phase 5 で執筆され、Phase 6〜7 で検証・カバレッジ確認を通過したポリシー文書に対し、
**章立ての簡潔化**、**冗長表現の除去**、**用語統一**、**既存アーカイブ文書との重複の dedupe** を
実施し、ポリシー文書をプロダクション運用時の**長期保守に耐える品質**へ引き上げる。

Phase 7 のカバレッジ判定を下げない範囲で、読みやすさ・一貫性・ dedupe の 3 観点を改善する。

## 実行タスク

- (1) 章立ての簡潔化（セクション階層の整理・重複見出しの統合）
- (2) 冗長表現の除去（同一主張の繰り返し・不要な前置きの削除）
- (3) 用語統一（表記揺れの統一）
- (4) 既存 `logs-archive-*.md` との重複内容の dedupe（相互参照化）
- (5) リファクタリング前後の Phase 7 カバレッジ維持確認
- (6) mirror 側（`.agents/`）への再同期確認

## 実行手順

### 1. 章立ての簡潔化

Phase 2 設計で定義した 6 つの必須セクション（適用範囲 / 閾値 / パス規則 / 手順 / 運用ルール / 参照）を
**崩さずに**、以下の観点で整理する。

| 観点               | 整理方針                                                               |
| ------------------ | ---------------------------------------------------------------------- |
| 階層の深さ         | 最大 H3 まで。H4 以降が発生している場合は H2/H3 へ繰り上げまたは段落化 |
| 目次（TOC）の整合  | 冒頭の目次と本文見出しの表現が一致しているか                           |
| 見出しの対称性     | 「1.」「2.」等のナンバリングが欠番なく連続しているか                   |
| 見出し表現の冗長性 | 「〜について」「〜の詳細」等の冗長修飾語を削除                         |

### 2. 冗長表現の除去

以下のパターンを検出し、意味を変えない範囲で削除・統合する。

| 冗長パターン                                   | 対応                               |
| ---------------------------------------------- | ---------------------------------- |
| 同一閾値を複数セクションで繰り返し定義している | 定義は 1 箇所、他は相互参照に変更  |
| 「〜ことがあります」「〜する可能性があります」 | 必要な確定記述以外は断定表現に統一 |
| 「以下の通り」「前述の通り」の乱用             | リンク or 参照番号に置換           |
| 例示が多すぎて要点がぼける                     | 代表例 1 つに絞り残りは索引参照    |

### 3. 用語統一

検出対象の表記揺れと採用表記を事前に固定する。

| カテゴリ                 | 揺れている表記                     | 採用表記                                            |
| ------------------------ | ---------------------------------- | --------------------------------------------------- |
| archive の表記           | archive / アーカイブ               | **アーカイブ**（日本語優先）                        |
| LOGS.md のファイル名     | LOGS.md / logs.md / Logs.md        | **LOGS.md**（大文字固定）                           |
| スキルディレクトリ       | `.claude/skills` / `claude/skills` | **`.claude/skills/`**（先頭ドット・末尾スラッシュ） |
| mirror ディレクトリ      | `.agents/skills` / `agents/skills` | **`.agents/skills/`**（先頭ドット・末尾スラッシュ） |
| 月次表現                 | 月次 / 毎月 / マンスリー           | **月次**                                            |
| 閾値                     | 閾値 / しきい値 / 閾値             | **閾値**                                            |
| ファイル命名フォーマット | YYYY-MM / yyyy-MM / YYYYMM         | **YYYY-MM**                                         |
| mirror 同期              | mirror sync / ミラー同期 / 同期    | **mirror 同期**                                     |

### 4. 既存 `logs-archive-*.md` との重複内容の dedupe

| 重複パターン                                                        | dedupe 方針                                                  |
| ------------------------------------------------------------------- | ------------------------------------------------------------ |
| 既存 `logs-archive-index.md` がインデックス役を担っている内容の重複 | ポリシー文書からは削除し、`index.md` への相互参照に置換      |
| `logs-archive-legacy.md` の legacy 運用詳細                         | ポリシー文書では「legacy は遡及適用しない」の 1 文のみに集約 |
| 既存アーカイブが持つ具体事例                                        | ポリシー文書では代表リンクのみ、詳細は既存アーカイブ側へ誘導 |

**注意**: dedupe で削除した情報は、必ず**相互参照で到達可能**にする。情報が失われてはならない。

## スコープ

### 含むもの

- ポリシー文書の章立て簡潔化（最大 H3 までに整理）
- 冗長表現の除去（意味不変）
- 用語統一（表記揺れの解消）
- 既存 `logs-archive-*.md` との重複内容の dedupe（相互参照化）
- mirror 文書への同一リファクタリング反映
- topic-map.md の文言整合
- リファクタリング前後の差分記録

### 含まないもの

- 閾値・パス規則・手順の**意味的変更**（Phase 2 / Phase 5 の責務）
- 新規要件の追加（別タスク）
- 既存 `logs-archive-*.md` 自体のリファクタリング（別タスク）
- ポリシー文書のコード実装や自動化（別タスク）
- 新規セクションの追加（Phase 9 以降での必要性判断）

## リスクと対策

| リスク                                                | 影響度 | 対策                                                                          |
| ----------------------------------------------------- | ------ | ----------------------------------------------------------------------------- |
| 文書簡潔化により要件カバレッジが下がる                | 高     | Phase 7 カバレッジマトリクスの再評価を必須化、未達時は変更を巻き戻し          |
| dedupe により情報が参照先から到達不能になる           | 中     | 削除前後で「相互参照で到達可能か」を必ず検証する                              |
| 用語統一で既存 `logs-archive-*.md` との表記齟齬が発生 | 中     | 既存ファイルの表記を尊重し、ポリシー側では既存表記を「legacy 表記として注記」 |
| mirror 側への反映漏れ                                 | 中     | `diff` コマンドによる対称性確認をゲート判定に含める                           |
| 最小変更原則を超えた構造変更が混入                    | 高     | 変更記録に「意味変更なし」の明記を義務化し、Phase 9 レビュー時に再確認        |
