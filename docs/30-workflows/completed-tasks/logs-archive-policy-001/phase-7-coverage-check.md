## 本Phaseにおける「カバレッジ確認」の定義（読み替え）

本タスクはコード実装を伴わない**文書作成タスク**である。したがって、従来の
「カバレッジ確認（Line / Branch / Function）」を以下のように**文書要件カバレッジ**として
読み替え、文書品質工程として正当化する。

| 用語               | 通常の意味                         | 本タスクでの読み替え                                  |
| ------------------ | ---------------------------------- | ----------------------------------------------------- |
| Line Coverage      | 実行行のうちテストで通過した割合   | **Issue 要件項目のうちポリシー文書に明記された割合**  |
| Branch Coverage    | 条件分岐でテスト済みパスの割合     | **判定条件（閾値OR、境界）の記述漏れなし割合**        |
| Function Coverage  | 関数のうちテストで呼び出された割合 | **主要手順ステップが文書内で独立定義された割合**      |
| カバレッジレポート | 計測結果の集約レポート             | **要件 7 項目 × ポリシー文書 行番号引用マトリクス**   |
| ゲート判定         | 基準未達時の差し戻し               | **要件カバレッジ 100% 未達の場合 Phase 6 へ差し戻し** |

## 目的

Issue #2282 が要求する 7 項目の要件が、Phase 5 で執筆されたポリシー文書
（`.claude/skills/aiworkflow-requirements/references/logs-archive-policy.md`）に
**漏れなく・具体的に明記**されていることを確認する。
確認は**ポリシー文書の行番号による引用マトリクス**形式で残し、未達があれば
Phase 6（テスト拡充）へ差し戻す。

## 実行手順

### 1. 要件カバレッジマトリクスの作成

Phase 5 ポリシー文書を `cat -n` 相当で行番号付きで読み、以下のマトリクスを作成する。

| Req ID | 要件項目         | 明記箇所（行番号）                            | 明記品質 | 判定    | 備考 |
| ------ | ---------------- | --------------------------------------------- | -------- | ------- | ---- |
| R-01   | 閾値             | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |
| R-02   | archive 先       | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |
| R-03   | 手順             | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |
| R-04   | mirror 同期      | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |
| R-05   | topic-map 参照   | `indexes/topic-map.md:L??` + ポリシー側 `L??` | 明示的   | COVERED |      |
| R-06   | 見直しサイクル   | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |
| R-07   | エスカレーション | `logs-archive-policy.md:L?? - L??`            | 明示的   | COVERED |      |

**明記品質の定義**:

- **明示的**: セクション見出し or 段落で独立して記述
- **暗黙的**: 他項目の記述内に含まれるが単独の章見出しがない（要改善）
- **未記載**: 該当記述が見当たらない（未達）

### 2. カバレッジ率の算出

```
Line Coverage (要件項目カバー率) = COVERED 件数 / 7 × 100%
Branch Coverage (判定条件網羅率) = 判定分岐記述あり / 全判定分岐 × 100%
Function Coverage (手順独立定義率) = 6ステップ中 独立記述されているもの / 6 × 100%
```

### 3. カバレッジ目標との比較

| 指標                      | 最低基準 | 推奨基準 | 計測結果 | 判定   |
| ------------------------- | -------- | -------- | -------- | ------ |
| 要件項目カバー率          | 100%     | 100%     | TBD      | 確認要 |
| 判定条件網羅率            | 80%      | 100%     | TBD      | 確認要 |
| 手順独立定義率            | 100%     | 100%     | TBD      | 確認要 |
| mirror 対称性（差分ゼロ） | 100%     | 100%     | TBD      | 確認要 |

**注**: 要件項目カバー率は Issue #2282 の明示要件であるため、**100% 未満は即 Phase 6 差し戻し**。

### 4. 引用フォーマット（推奨）

行番号引用は以下のフォーマットを推奨する。

```markdown
- R-01: `.claude/skills/aiworkflow-requirements/references/logs-archive-policy.md:L12-L23`
  > 2. アーカイブ閾値
  >
  > - 行数: 300 行超
  > - サイズ: 30 KB 超
  > - 期間: 月次（毎月初に前月分評価）
  > - 判定: 上記いずれか1つ以上を満たした時点
```

実際の引用には Phase 5 で確定した行番号を使用する。

### 5. 未達時の対応

**要件項目カバー率 < 100% の場合**:

- 未達 Req ID を列挙
- 該当要件をポリシー文書に追記するための指示書を生成
- Phase 6 へ差し戻し（テスト拡充観点として再検証）

**判定条件網羅率 < 80% の場合**:

- 未網羅の判定分岐を列挙
- Phase 8（リファクタリング）での表現明確化候補として引き継ぎ

### 6. mirror 対称性確認

```bash
diff \
  .claude/skills/aiworkflow-requirements/references/logs-archive-policy.md \
  .agents/skills/aiworkflow-requirements/references/logs-archive-policy.md
# 期待: 差分ゼロ
```

### 7. topic-map.md 参照追加の確認

```bash
rg -n "logs-archive-policy" .claude/skills/aiworkflow-requirements/indexes/topic-map.md
# 期待: 1件以上マッチし、パスが正しい
```

### 8. ゲート判定

- **PASS**: 全指標が最低基準以上 → Phase 8 へ進む
- **未達**: いずれかの指標が最低基準未満 → Phase 6 へ戻す
