## 目的

Phase 2 の設計書を多角的に検証し、矛盾・漏れ・整合の問題がないことを確認してから実装フェーズへ進む。

## 背景

validator 修正は既存チェックへの副作用リスクを持つ。テンプレート修正は既存出力済みドキュメントとの互換性リスクを持つ。これらを設計段階でゲートする。

## 実行タスク

### タスク1: 設計レビュー実施

**目的**: Phase 2 設計書の品質を多角的に検証する

**実行手順**:

1. `outputs/phase-2/design-document.md` を読み込む
2. 以下の観点でレビューを実施する:
   - validator の修正が既存チェック項目に副作用を与えないか
   - テンプレート修正が既存出力済みドキュメントと非互換にならないか
   - changelog フィールド追加が既存ワークフロー出力と不整合にならないか
   - テスト設計が受け入れ基準を全て網羅しているか
3. レビュー結果を PASS / MINOR / MAJOR / CRITICAL で判定する
4. MINOR 以上の指摘がある場合は対処方針を記録する

**期待される成果物**:

- `outputs/phase-3/design-review.md`
