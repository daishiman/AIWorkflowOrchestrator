# 要件定義書: UT-TASK-SPEC-TEMPLATE-IMPROVEMENT-001

## 作成日

2026-04-06

## 問題の根本原因分析

### 問題1: extractSection() の切り出し範囲が不正確

**現状コード** (`validate-phase12-implementation-guide.js`):

```javascript
const TOP_LEVEL_NON_NUMBERED_HEADING = /\n##\s+(?!\d+\.)/;
```

**問題のシナリオ**:

- `## Part 2` 内に `## APIの概要` のような非番号付き `##` 見出しが含まれる場合、
  この正規表現にマッチして Part 2 の切り出しが誤って終了する
- 結果として `### 使用例` がその後ろにある場合、検査対象外となる

**影響を受けないケース** (現状で動作する):

- `## 1.`, `## 2.` など `\d+\.` で始まる番号付き小節は `(?!\d+\.)` で除外済み
- テンプレート標準の番号付きセクション(`## 1. アーキテクチャ概要`)は正常動作

**影響を受けるケース** (現状でバグ):

- `## APIシグネチャ`, `## 概要`, `## Overview` など非番号・非Partの `##` 見出しがPart 2内にある場合

**修正アプローチ採用: アプローチ B**

理由:

- アプローチ A (全文検索) はスコープが広すぎる。Part 2 以外に `### 使用例` が存在する場合に誤検知する可能性がある
- アプローチ B (Part-aware extraction) は境界を `^## Part \d+` に変更することで、Part 内の任意の `##` 見出しを保持しながら正確に Part 2 を切り出せる

### 問題2: documentation-changelog-template.md の必須フィールド

**現状確認**: ファイルを精査した結果、以下の5フィールドはすでにテンプレート本体に追加済み:

- `| 変更者 | {{AUTHOR}} |`
- `| 関連 Issue / PR | {{ISSUE_PR_LINK}} |`
- `| validator 実行結果 | {{VALIDATOR_RESULT}} |`
- `| current / baseline | {{CURRENT_BASELINE}} |`
- `| artifacts 同期結果 | {{ARTIFACTS_SYNC_RESULT}} |`

品質チェックリストの項目 `メタ情報テーブルの 5 必須フィールドが全て記録されているか` も存在する。
