## テストシナリオ

### シナリオ 1: isImported === true の場合のボタン表示確認

**前提条件:** インポート済みスキルが1件以上存在する

**手順:**

1. スキル一覧画面を開く
2. インポート済みスキルのカードをクリックし `SkillDetailPanel` を表示する
3. パネル内のボタン表示を確認する

**確認項目:**

- [ ] 「エディタで開く」ボタンが表示されている
- [ ] 「分析する」ボタンが表示されている
- [ ] ボタンのラベルテキストが正しい
- [ ] ボタンのスタイル（色・サイズ・余白）が Apple HIG に準拠している
- [ ] ライトモード・ダークモード双方で視認性が十分（コントラスト比 4.5:1 以上）

### シナリオ 2: isImported === false の場合のボタン非表示確認

**前提条件:** 未インポートスキルが1件以上存在する（またはモックデータを使用）

**手順:**

1. 未インポートスキルの詳細パネルを表示する

**確認項目:**

- [ ] 「エディタで開く」ボタンが表示されていない
- [ ] 「分析する」ボタンが表示されていない
- [ ] ボタン非表示によるレイアウト崩れがない

### シナリオ 3: 「エディタで開く」ボタンクリックの遷移確認

**手順:**

1. インポート済みスキルの詳細パネルを表示する
2. 「エディタで開く」ボタンをクリックする

**確認項目:**

- [ ] エディタ画面（または対応するビュー）に遷移する
- [ ] 遷移先でスキルが正しく読み込まれている
- [ ] 遷移アニメーションが自然である（200-300ms 程度）
- [ ] ブラウザの戻る操作（または専用の戻るボタン）で一覧に戻れる

### シナリオ 4: 「分析する」ボタンクリックの遷移確認

**手順:**

1. インポート済みスキルの詳細パネルを表示する
2. 「分析する」ボタンをクリックする

**確認項目:**

- [ ] 分析画面（または対応するビュー）に遷移する
- [ ] 遷移先でスキルが正しく認識されている
- [ ] エラーが発生しない

### シナリオ 5: モバイルサイズ（レスポンシブ）確認

**手順:**

1. DevTools でウィンドウ幅を 375px に設定する（iPhone SE 相当）
2. インポート済みスキルの詳細パネルを表示する

**確認項目:**

- [ ] ボタンがレイアウト内に収まっている（はみ出しなし）
- [ ] ボタンが縦並びになる場合、間隔が適切である（8px グリッド準拠）
- [ ] タップターゲットが最低 44x44px 以上である

### シナリオ 6: キーボード操作確認

**手順:**

1. Tab キーで「エディタで開く」ボタンにフォーカスを当てる
2. Enter キーを押す
3. Shift+Tab で「分析する」ボタンに戻り、Space キーを押す

**確認項目:**

- [ ] フォーカスリングが視覚的に確認できる
- [ ] Enter キーでボタンが起動する
- [ ] Space キーでボタンが起動する
- [ ] Tab 順序がコンテンツの論理順序に従っている
