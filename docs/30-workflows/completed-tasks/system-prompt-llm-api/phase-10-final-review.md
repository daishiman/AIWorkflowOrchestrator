## 目的

実装完了後、全体的な品質・整合性を検証する。重大な問題がある場合は該当Phaseに戻る。

## 背景

最終レビューは以下の観点で検証:

- 要件の充足確認
- コード品質の確認
- テスト結果の確認
- ドキュメントの整合性

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足レビュー

**目的**: 要件が全て満たされているか確認する

**実行手順**:

1. Phase 1の要件定義書を参照
2. 各機能要件の充足を確認
3. 各非機能要件の充足を確認
4. 受け入れ基準のクリアを確認

**チェックリスト**:

- [ ] システムプロンプト付きメッセージがLLM APIに送信される
- [ ] LLMからの応答がチャットUIに表示される
- [ ] 4つのプロバイダー全てで動作する
- [ ] エラー時に適切なメッセージが表示される
- [ ] 初回トークン応答時間 < 2秒（目標）

**期待される成果物**:

- 要件充足確認結果

---

### タスク2: コード品質レビュー

**目的**: コード品質基準を満たしているか確認する

**実行手順**:

1. 実装コードを確認
2. SOLID原則の遵守確認
3. エラーハンドリングの網羅性確認
4. 型安全性の確認

**チェックリスト**:

- [ ] 重複コードがない
- [ ] 関数が単一責任を持っている
- [ ] エラーハンドリングが適切
- [ ] TypeScript型が厳密に定義されている

**期待される成果物**:

- コード品質レビュー結果

---

### タスク3: テスト結果レビュー

**目的**: テストが網羅的に成功しているか確認する

**実行手順**:

1. ユニットテスト結果を確認
2. 統合テスト結果を確認
3. カバレッジ結果を確認

**チェックリスト**:

- [ ] 全ユニットテストが成功
- [ ] 全統合テストが成功
- [ ] カバレッジ基準を達成（Line 80%+, Branch 60%+, Function 80%+）

**期待される成果物**:

- テスト結果レビュー結果

---

### タスク4: 整合性レビュー

**目的**: システム全体の整合性を確認する

**実行手順**:

1. 既存LLMアダプターとの整合性確認
2. IPC通信仕様との整合性確認
3. システム仕様との整合性確認

**チェックリスト**:

- [ ] 既存実装パターンに従っている
- [ ] インターフェースが一貫している
- [ ] システム仕様書と実装が一致している

**期待される成果物**:

- 整合性レビュー結果

## 判定基準

| 判定     | 条件             | 次のアクション                      |
| -------- | ---------------- | ----------------------------------- |
| PASS     | 全観点で問題なし | Phase 11へ進行                      |
| MINOR    | 軽微な指摘あり   | 未完了タスクとして記録後Phase 11へ  |
| MAJOR    | 重大な問題あり   | 影響範囲に応じて戻り先を決定        |
| CRITICAL | 致命的な問題あり | Phase 1へ戻りユーザーと要件を再確認 |

## 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
