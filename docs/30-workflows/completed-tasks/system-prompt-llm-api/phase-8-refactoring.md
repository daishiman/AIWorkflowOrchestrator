## 目的

動作を変えずにコード品質を改善する。TDDのRefactorフェーズとして、テストが継続成功することを確認しながらリファクタリングを行う。

## 背景

リファクタリング対象:

- 重複コードの排除
- 命名の改善
- 構造の整理
- エラーハンドリングの統一

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コードスメル検出

**目的**: リファクタリング対象を特定する

**実行手順**:

1. 重複コードの検出
2. 長すぎる関数の検出
3. 複雑な条件分岐の検出
4. 命名の不適切さの検出

**チェックリスト**:

- [ ] DRY原則違反（重複コード）がないか
- [ ] 単一責任原則違反がないか
- [ ] 過度に複雑な関数がないか
- [ ] 命名規則に従っているか

**期待される成果物**:

- コードスメルレポート

---

### タスク2: リファクタリング実施

**目的**: 検出したコードスメルを修正する

**実行手順**:

1. 各コードスメルに対してリファクタリングを実施
2. リファクタリング後にテストを実行
3. テストが成功することを確認

**リファクタリングパターン例**:

```typescript
// Before: 重複したエラーハンドリング
function callOpenAI(...) {
  try { ... } catch (error) { handleError(error); }
}
function callAnthropic(...) {
  try { ... } catch (error) { handleError(error); }
}

// After: 共通のラッパー関数
function withErrorHandling<T>(fn: () => Promise<T>): Promise<T> {
  try {
    return await fn();
  } catch (error) {
    throw formatError(error);
  }
}
```

**期待される成果物**:

- リファクタリング済みコード

---

### タスク3: テスト継続成功確認

**目的**: リファクタリング後もテストが成功することを確認する

**実行手順**:

```bash
# 全テスト実行
pnpm --filter @repo/desktop test

# 型チェック
pnpm --filter @repo/desktop typecheck

# Lint
pnpm --filter @repo/desktop lint
```

**確認項目**:

- [ ] 全ユニットテストが成功
- [ ] 全統合テストが成功
- [ ] 型エラーがない
- [ ] Lintエラーがない

**期待される成果物**:

- テスト実行結果

---

### タスク4: コード品質確認

**目的**: リファクタリング後のコード品質を確認する

**チェックリスト**:

- [ ] SOLID原則に従っているか
- [ ] 関数が適切なサイズか（20行以内推奨）
- [ ] 循環的複雑度が低いか
- [ ] テストが書きやすい構造か

**期待される成果物**:

- コード品質レポート
