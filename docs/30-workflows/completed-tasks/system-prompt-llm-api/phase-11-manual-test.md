## 目的

自動テストでは検証できない実環境動作を手動で確認する。各LLMプロバイダーでシステムプロンプトが正しく機能することを検証する。

## 背景

手動テストで以下を検証:

- 実際のLLM API呼び出し
- システムプロンプトによるAI振る舞いの変化
- エラー時のUI表示
- 各プロバイダーでの動作確認

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 自動テストの事前実行

**目的**: 手動テスト前に全自動テストを実行する

**実行手順**:

```bash
# 全テスト実行
pnpm --filter @repo/desktop test
```

**確認項目**:

- [ ] 全自動テストが成功

---

### タスク2: 機能テスト（正常系）

**目的**: 各プロバイダーでシステムプロンプト機能が正しく動作することを確認する

**テストケース**:

| TC-ID  | プロバイダー | システムプロンプト             | ユーザーメッセージ | 期待結果           |
| ------ | ------------ | ------------------------------ | ------------------ | ------------------ |
| TC-001 | OpenAI       | 「翻訳アシスタント」           | 「Hello」          | 日本語で挨拶が返る |
| TC-002 | Anthropic    | 「関西弁で回答して」           | 「今日の天気は？」 | 関西弁で回答が返る |
| TC-003 | Google       | 「You are a coding assistant」 | 「Sort an array」  | コード例が返る     |
| TC-004 | xAI          | 「簡潔に回答して」             | 「宇宙とは」       | 短い回答が返る     |
| TC-005 | OpenAI       | （空欄）                       | 「Hello」          | 通常の挨拶が返る   |

**実行手順**:

1. デスクトップアプリを起動
2. 各プロバイダーのAPIキーを設定
3. テストケースを順番に実行
4. 結果を記録

**期待される成果物**:

- 機能テスト結果

---

### タスク3: エラーハンドリングテスト（異常系）

**目的**: エラー時に適切なメッセージが表示されることを確認する

**テストケース**:

| TC-ID  | 状況             | 期待結果                          |
| ------ | ---------------- | --------------------------------- |
| TC-101 | APIキー未設定    | 「APIキーを設定してください」表示 |
| TC-102 | APIキー無効      | 「APIキーが無効です」表示         |
| TC-103 | ネットワーク切断 | 「ネットワークエラー」表示        |

**実行手順**:

1. 各エラー状況を再現
2. エラーメッセージを確認
3. UIが適切に表示されることを確認

**期待される成果物**:

- エラーハンドリングテスト結果
