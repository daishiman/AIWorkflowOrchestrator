## 作成日: 2026-04-13

## 概要

`sendToAnalyticsProvider` 実装に関して識別したリスクとその対策を記録する。

---

## リスク一覧

### RISK-01: 外部エンドポイントの障害による IPC ブロック

| 項目       | 内容                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| リスク ID  | RISK-01                                                                                                               |
| リスク内容 | `ANALYTICS_ENDPOINT_URL` の外部サービスが応答しない場合、IPC ハンドラーが長時間ブロックする                           |
| 発生確率   | 中                                                                                                                    |
| 影響度     | 高（IPC 応答遅延によりアプリが固まる）                                                                                |
| 対策       | `AbortController` で 5000ms タイムアウトを設定した。タイムアウト後は `catch` でエラーを握り潰し、IPC レスポンスを返す |
| 対策状態   | 実装済み（TC-06 で検証済み）                                                                                          |

---

### RISK-02: 本番以外の環境での意図しない HTTP 送信

| 項目       | 内容                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ |
| リスク ID  | RISK-02                                                                                          |
| リスク内容 | 開発・テスト環境で `ANALYTICS_ENDPOINT_URL` が設定されていた場合、意図しない HTTP 送信が発生する |
| 発生確率   | 低                                                                                               |
| 影響度     | 中（不正なデータがアナリティクスサービスに送信される）                                           |
| 対策       | `NODE_ENV !== "production"` の場合に早期 return するガード節を設けた                             |
| 対策状態   | 実装済み（TC-02, TC-R03 で検証済み）                                                             |

---

### RISK-03: `ANALYTICS_ENDPOINT_URL` の環境変数漏洩

| 項目       | 内容                                                               |
| ---------- | ------------------------------------------------------------------ |
| リスク ID  | RISK-03                                                            |
| リスク内容 | `ANALYTICS_ENDPOINT_URL` がソースコードやログに含まれる            |
| 発生確率   | 低                                                                 |
| 影響度     | 低（URL 自体は機密情報ではないが、エンドポイントの存在が露出する） |
| 対策       | 環境変数として管理し、コードにハードコードしなかった               |
| 対策状態   | 実装済み（`process.env.ANALYTICS_ENDPOINT_URL` を使用）            |

---

### RISK-04: fetch のレスポンスボディの未処理によるメモリリーク

| 項目       | 内容                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| リスク ID  | RISK-04                                                                                      |
| リスク内容 | `fetch` のレスポンスボディを消費しない場合、Node.js の内部バッファが解放されない可能性がある |
| 発生確率   | 低                                                                                           |
| 影響度     | 低（イベント頻度が低い場合は実害なし）                                                       |
| 対策       | 現状は許容とした。アナリティクス送信は fire-and-forget であり、レスポンスボディの内容は不要  |
| 対策状態   | 許容（将来的に `response.body?.cancel()` を追加することを検討可能）                          |

---

### RISK-05: タイムアウト後の `clearTimeout` 漏れ

| 項目       | 内容                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| リスク ID  | RISK-05                                                                    |
| リスク内容 | `fetch` が正常完了した後も `setTimeout` が残存し、不要なリソースを消費する |
| 発生確率   | 低（`finally` ブロックで対処済み）                                         |
| 影響度     | 低                                                                         |
| 対策       | `finally { clearTimeout(timeoutId) }` で必ず `setTimeout` をキャンセルした |
| 対策状態   | 実装済み                                                                   |
