## 3. 既存機能との棲み分け

### 3.1 skill:import と skill:fork の違い

| 比較項目         | skill:import（スキルインポート） | skill:fork（スキルフォーク）                         |
| ---------------- | -------------------------------- | ---------------------------------------------------- |
| 用途             | 外部スキルの取り込み             | 既存スキルのローカルコピー + カスタマイズ            |
| 入力             | スキル名（文字列）               | SkillForkOptions（ソース、新名前、コピーフラグ4種）  |
| メタデータ       | なし                             | fork-metadata.json が自動生成される                  |
| SKILL.md 更新    | 更新しない（元のまま）           | name, description, forked-from, allowed-tools を更新 |
| 選択的コピー     | 非対応（全ファイルインポート）   | agents, references, scripts, assets を個別選択可能   |
| ロールバック     | なし                             | コピー途中のエラー時にディレクトリ全削除             |
| フォーク関係追跡 | なし                             | forked-from フィールドで親子関係を記録               |

### 3.2 チャネル一覧

| 機能               | チャネル名               | 用途                                  |
| ------------------ | ------------------------ | ------------------------------------- |
| スキルインポート   | `skill:import`           | 外部スキルのインポート（名前指定）    |
| スキル削除         | `skill:remove`           | 既存スキルの削除                      |
| スキル共有         | `skill:importFromSource` | 外部ソースからのインポート（TASK-9F） |
| **スキルフォーク** | **`skill:fork`**         | **既存スキルのコピー+メタデータ記録** |

## 5. 前提条件

### 5.1 技術的前提

| 前提条件                     | 説明                                                                      |
| ---------------------------- | ------------------------------------------------------------------------- |
| TASK-9B 完了済み             | SkillService / SkillFileManager が利用可能であること                      |
| ファイルシステムアクセス可能 | スキルディレクトリの読み取り・書き込み権限があること                      |
| Node.js fs API 利用可能      | Main Process で fs.cp, fs.mkdir, fs.rm, fs.writeFile が利用可能であること |

### 5.2 設計上の前提

| 前提条件                     | 説明                                                                |
| ---------------------------- | ------------------------------------------------------------------- |
| ローカルスキルのみ対象       | フォーク対象はローカルに存在するスキルに限定する                    |
| IPC経由のフォーク実行        | フォーク操作は IPC 経由で実行する（Renderer から直接操作しない）    |
| スキル名でのスキル特定       | フォーク元・フォーク先はスキル名（sourceSkill / newName）で特定する |
| SKILL.md の Frontmatter 形式 | SKILL.md が YAML Frontmatter を持つ Markdown 形式であること         |

## 6. 制約事項

### 6.1 技術的制約

| 制約                     | 説明                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| 同期的なコピー操作       | ファイルコピーは Node.js の fs API を使用する非同期操作                    |
| パフォーマンス上限       | 100ファイル以下のスキルを3秒以内にフォーク完了（NFR-1）                    |
| Frontmatter パーサー依存 | SKILL.md のパースは既存の Frontmatter パーサーに依存する                   |
| ロールバックの粒度       | ロールバックはフォーク先ディレクトリ全体の削除（個別ファイル単位ではない） |

### 6.2 セキュリティ制約

| 制約                         | 説明                                                      | 参照                       |
| ---------------------------- | --------------------------------------------------------- | -------------------------- |
| IPC送信元検証必須            | ハンドラで validateIpcSender() を実施する                 | `04-electron-security.md`  |
| P42準拠3段バリデーション     | 全文字列引数で型チェック→空文字列→トリム空文字列の3段検証 | `06-known-pitfalls.md#P42` |
| パストラバーサル防止         | sourceSkill, newName に `../` `..\\` を含む場合は拒否     | NFR-3                      |
| エラーメッセージのサニタイズ | IPC境界で内部エラー情報を漏洩しない                       | `04-electron-security.md`  |

### 6.3 互換性制約

| 制約                | 説明                                                 |
| ------------------- | ---------------------------------------------------- |
| 既存テスト全PASS    | 既存テスト（9000件以上）が全てPASSする状態を維持する |
| 既存IPC契約の非破壊 | 既存の skill:\* チャンネルの動作を変更しない         |
| 既存型定義の非破壊  | packages/shared の既存型定義を変更しない（追加のみ） |

## 7. リスク

| リスク                                   | 影響度 | 発生可能性 | 対策                                                                    |
| ---------------------------------------- | ------ | ---------- | ----------------------------------------------------------------------- |
| Frontmatter パース失敗                   | 中     | 中         | パース失敗時は warnings に記録し、SKILL.md 更新をスキップして続行する   |
| 大量ファイルのコピーでパフォーマンス劣化 | 中     | 低         | NFR-1 の基準（100ファイル以下/3秒）をテストで検証する                   |
| ロールバック中のエラー                   | 中     | 低         | ロールバック失敗時もエラーを記録し、ユーザーに手動削除を案内する        |
| シンボリックリンクの追跡                 | 中     | 低         | realpath() でシンボリックリンクを解決し、スキルディレクトリ外を検出する |
| 既存テストへの影響                       | 高     | 低         | IPC ハンドラ追加時に既存ハンドラのテストが影響を受けないことを検証する  |
