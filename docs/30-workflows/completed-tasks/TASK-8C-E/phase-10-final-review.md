### タスク4: PASS/FAIL 最終判定

**目的**: 最終レビューの判定を行う

**実行手順**:

1. タスク1〜3 の結果を総合する
2. 以下の10観点でレビューを実施する（タスクの性質に応じてAIが該当観点を選択）：

| #   | 観点               | 確認内容                                               |
| --- | ------------------ | ------------------------------------------------------ |
| 1   | 機能完全性         | 全ての受け入れ基準（AC-001〜AC-006）が満たされているか |
| 2   | コード品質         | テストコードがクリーンコード原則に従っているか         |
| 3   | テスト品質         | カバレッジが十分でテストケースが適切か                 |
| 4   | セキュリティ       | フィクスチャに脆弱性を誘発する内容がないか             |
| 5   | パフォーマンス     | テスト実行時の明らかなボトルネックがないか             |
| 6   | ドキュメント整合性 | フィクスチャ内容とテストの期待値が一致しているか       |
| 7   | エラーハンドリング | 無効スキルの処理が適切にテストされているか             |
| 8   | UI/UX              | （本タスクは該当なし）                                 |
| 9   | データ整合性       | YAML Frontmatter の値とパース結果が一致しているか      |
| 10  | 国際化（i18n）     | （本タスクは該当なし）                                 |

3. 判定基準：

| 判定     | 条件                     | 対応                                     |
| -------- | ------------------------ | ---------------------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11（手動テスト）へ進行             |
| MINOR    | 軽微な指摘あり           | 未完了タスクとして記録後 Phase 11 へ進行 |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻り先を決定             |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻りユーザーと要件を再確認     |

4. MAJOR 判定時の戻り先決定基準：

| 問題の種類       | 戻り先                      |
| ---------------- | --------------------------- |
| 要件の問題       | Phase 1（要件定義）         |
| 設計の問題       | Phase 2（設計）             |
| テスト設計の問題 | Phase 4（テスト作成）       |
| 実装の問題       | Phase 5（実装）             |
| テスト拡充の問題 | Phase 6（テスト拡充）       |
| カバレッジ未達   | Phase 7（カバレッジ確認）   |
| コード品質の問題 | Phase 8（リファクタリング） |

5. 最終レビュー結果を `outputs/phase-10/final-review-result.md` に出力する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`
