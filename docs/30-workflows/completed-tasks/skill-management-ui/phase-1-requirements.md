## 目的

スキル管理UI機能の機能要件・非機能要件を明確化し、受け入れ基準をGiven-When-Then形式で定義する。

## 背景

AGENT-001（エージェントダッシュボード基盤）が完了した状態を前提とし、AgentView内にスキル管理機能を追加する。本Phaseでは、ユーザーストーリーと受け入れ基準を確定させ、後続の設計・実装の基盤を構築する。

### タスク1: 機能要件の整理

**目的**: ユーザーが必要とする機能を明確化する

**実行手順**:

1. タスク指示書（`docs/30-workflows/unassigned-task/task-agent-02-skill-management-ui.md`）を確認
2. 既存のAgentView実装を確認（`apps/desktop/src/renderer/views/AgentView/`）
3. 以下の機能要件を文書化:
   - スキルインポート機能（ダイアログ）
   - スキル一覧表示機能（カード形式）
   - スキル検索機能（名前・Trigger）
   - スキルフィルタリング機能（カテゴリ）
   - スキル詳細表示機能（パネル）
   - スキル削除機能
   - 設定永続化機能

**期待される成果物**:

- 機能要件リスト（`outputs/phase-1/functional-requirements.md`）

### タスク2: 非機能要件の定義

**目的**: 品質・パフォーマンス・アクセシビリティ要件を明確化する

**実行手順**:

1. システム仕様書（`ui-ux-components.md`）からアクセシビリティ要件を抽出
2. 以下の非機能要件を定義:
   - パフォーマンス: スキル一覧表示 < 200ms
   - アクセシビリティ: WCAG 2.1 AA準拠
   - レスポンシブ: 最小幅800px対応
   - キーボード操作: Tab/Enter/Escapeで操作可能
3. 非機能要件を文書化

**期待される成果物**:

- 非機能要件リスト（`outputs/phase-1/non-functional-requirements.md`）

### タスク3: 受け入れ基準の作成（Given-When-Then形式）

**目的**: テスト可能な受け入れ基準を定義する

**実行手順**:

1. 以下のシナリオをGiven-When-Then形式で記述:

```gherkin
Feature: スキル管理UI

Scenario: スキルインポートダイアログを開く
  Given ユーザーがAgentViewを開いている
  When 「スキルをインポート」ボタンをクリックする
  Then スキルインポートダイアログが表示される
  And .claude/skills/配下の利用可能なスキル一覧が表示される

Scenario: スキルを選択してインポートする
  Given スキルインポートダイアログが表示されている
  And 3つのスキルにチェックを入れている
  When 「インポート」ボタンをクリックする
  Then 選択した3つのスキルがインポートされる
  And AgentViewのスキル一覧に追加される
  And インポート設定が永続化される

Scenario: インポート済みスキル一覧が表示される
  Given ユーザーがAgentViewを開いている
  And 5件のスキルがインポート済みである
  When 画面が読み込まれる
  Then インポート済みスキルがカード形式で一覧表示される
  And 各カードにスキル名と説明が表示される

Scenario: スキルを名前で検索できる
  Given ユーザーがスキル一覧を表示している
  When 検索バーに「tdd」と入力する
  Then 名前またはTriggerに「tdd」を含むスキルのみ表示される

Scenario: スキルをカテゴリでフィルタリングできる
  Given ユーザーがスキル一覧を表示している
  When カテゴリフィルターで「テスト」を選択する
  Then テストカテゴリのスキルのみ表示される

Scenario: スキル詳細を表示できる
  Given ユーザーがスキル一覧を表示している
  When スキルカードをクリックする
  Then 右側にスキル詳細パネルが表示される
  And スキル名、説明、Trigger、Anchorsが表示される

Scenario: スキル詳細から実行画面へ遷移できる
  Given ユーザーがスキル詳細パネルを表示している
  When 「実行」ボタンをクリックする
  Then エージェント実行画面に遷移する
  And 選択したスキルが実行対象として設定される

Scenario: インポート済みスキルを削除できる
  Given ユーザーがスキル詳細パネルを表示している
  When 「削除」ボタンをクリックする
  And 確認ダイアログで「はい」を選択する
  Then スキルがインポート一覧から削除される
  And 設定が永続化される

Scenario: 空のスキル一覧で適切なメッセージが表示される
  Given ユーザーがAgentViewを開いている
  And インポート済みスキルが0件である
  When 画面が読み込まれる
  Then 「スキルがインポートされていません」メッセージが表示される
  And 「スキルをインポート」ボタンが表示される

Scenario: キーボードでスキルを選択できる
  Given ユーザーがスキル一覧を表示している
  When Tabキーでスキルカードにフォーカスする
  And Enterキーを押す
  Then スキル詳細パネルが表示される

Scenario: Escapeキーで詳細パネルを閉じられる
  Given ユーザーがスキル詳細パネルを表示している
  When Escapeキーを押す
  Then スキル詳細パネルが閉じる
```

2. 受け入れ基準を文書化

**期待される成果物**:

- 受け入れ基準（`outputs/phase-1/acceptance-criteria.md`）
