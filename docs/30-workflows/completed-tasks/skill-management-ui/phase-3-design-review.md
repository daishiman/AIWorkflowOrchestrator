## 目的

Phase 1（要件）とPhase 2（設計）の成果物をレビューし、実装に進む前に品質を検証する。

## 背景

設計レビューゲートは、後工程での手戻りを防ぐための重要なチェックポイント。要件の完全性、設計の妥当性、アクセシビリティ、セキュリティの観点からレビューを行う。

**目的**: Phase 1の要件が完全かつ明確であることを確認する

**実行手順**:

1. 以下のチェックリストを確認:

| #   | チェック項目                                        | 確認結果 |
| --- | --------------------------------------------------- | -------- |
| 1   | 全機能要件が一覧化されている                        | [ ]      |
| 2   | 受け入れ基準がGiven-When-Then形式で記述             | [ ]      |

### タスク6: レビュー結果の判定

**目的**: 総合的なレビュー結果を判定し、次のアクションを決定する

**実行手順**:

1. 全チェック結果を集約
2. 以下の判定基準で結果を判定:

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

3. 戻り先決定基準:

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |

4. レビュー結果を文書化

**期待される成果物**:

- 設計レビュー結果報告書（`outputs/phase-3/review-result.md`）
