### Task 10-2: P62 対策確認

P62（DEFAULT_CONFIG への暗黙 fallback 禁止）の観点から確認した：

- 未選択プロバイダーでのリクエスト送信が不可能であることを確認
- `isAvailable: false` のプロバイダーが InlineModelSelector の選択肢から完全に除外されているため、ユーザーが意図しないプロバイダーを選択する経路が存在しない
- フィルタ後にプロバイダーが 0 件の場合は「モデルを選択」表示となり、リクエスト送信に進めない

### Task 10-3: UX 確認

| 確認項目                                                             | 結果                                                                      |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| チャット画面では未設定プロバイダーが見えない（混乱防止）             | PASS: `filter((p) => p.isAvailable)` により完全に非表示                   |
| 設定画面では全プロバイダーが見える（設定可能性の確保）               | PASS: ProviderSelector は変更なし、グレーアウト+バッジ表示を維持          |
| プロバイダー 0 件時に「モデルを選択」が表示される                    | PASS: `hasSelection` 判定により自動的に表示                               |
| 選択中プロバイダーの APIキーを削除した場合「モデルを選択」に遷移する | PASS: isAvailable が false になりフィルタで除外、hasSelection が false に |

### Task 10-4: アクセシビリティ確認

| 確認項目                                         | 結果                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------- |
| フィルタ後も aria-label 属性が正しい             | PASS: SelectorTrigger の aria-label は選択状態に応じて動的に更新される |
| フィルタ後も role 属性が正しい                   | PASS: ドロップダウンの role="listbox" 構造は維持される                 |
| フィルタ後もキーボード操作で全機能にアクセス可能 | PASS: 利用可能プロバイダーのみが Tab/Arrow キーで選択可能              |
| 0 件時のスクリーンリーダー対応                   | PASS: 「モデルを選択」がテキストとして読み上げ可能                     |

### Task 10-5: コンポーネント間の使い分け確認
