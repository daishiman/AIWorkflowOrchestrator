## 目的

Phase 1〜2で定義した要件・設計の妥当性を検証し、実装フェーズに進む前に品質を担保する。

## 背景

設計レビューゲートは、要件の漏れや設計の不整合を早期に発見し、手戻りを防止するための重要なチェックポイントである。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1で定義した全要件が設計で網羅されているか確認する

**実行手順**:

1. `outputs/phase-1/requirements-list.md`を読み込む
2. 各機能要件が設計で対応されているかチェック
3. 各非機能要件が設計で考慮されているかチェック
4. 未対応項目があれば記録

**期待される成果物**:

- 要件充足マトリックス

---

### タスク2: 設計整合性確認

**目的**: 各設計ドキュメント間の整合性を確認する

**実行手順**:

1. PermissionStoreのインターフェースとSkillExecutor連携設計の整合性を確認
2. IPCチャネル設計と設定UI設計の整合性を確認
3. データスキーマとシーケンス図の整合性を確認
4. 不整合があれば記録

**期待される成果物**:

- 設計整合性チェックリスト

---

### タスク3: 既存コードとの整合性確認

**目的**: 設計が既存のコードベースと整合しているか確認する

**実行手順**:

1. `SkillExecutor.ts`の現在の構造と連携設計の整合性を確認
2. `PermissionResolver.ts`との役割分担が明確か確認
3. 既存IPCパターンとの整合性を確認
4. 不整合があれば記録

**期待される成果物**:

- 既存コード整合性チェックリスト

---

### タスク4: セキュリティレビュー

**目的**: セキュリティ観点での設計レビューを行う

**実行手順**:

1. 機密データの保護方法が適切か確認
2. 危険なツールの自動許可に関する考慮があるか確認
3. 設定ファイルへの不正アクセス対策があるか確認
4. 問題があれば記録

**期待される成果物**:

- セキュリティレビュー結果

---

### タスク5: レビュー結果判定

**目的**: 総合的なレビュー結果を判定する

**実行手順**:

1. タスク1〜4の結果を集約
2. 以下の基準でレビュー結果を判定:
   - **PASS**: 全レビュー観点で問題なし
   - **MINOR**: 軽微な指摘あり（ドキュメント修正等）
   - **MAJOR**: 重大な問題あり（設計変更必要）
   - **CRITICAL**: 致命的な問題あり（要件再定義必要）
3. 判定結果と対応方針を記録

**期待される成果物**:

- `outputs/phase-3/design-review-report.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
