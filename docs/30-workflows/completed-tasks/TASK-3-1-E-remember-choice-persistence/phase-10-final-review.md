## 目的

全体品質・整合性を検証し、手動テストフェーズに進む前の最終確認を行う。

## 背景

Phase 1〜9で実施した要件定義、設計、実装、テスト、品質保証の成果を総合的にレビューし、最終的な品質を確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足最終確認

**目的**: 当初の要件が全て満たされているか最終確認する

**実行手順**:

1. Phase 1の要件一覧を参照
2. 各要件の充足状況を確認:
   - [ ] PermissionStoreが実装されている
   - [ ] 「次回から確認しない」で許可したツールが永続化される
   - [ ] アプリ再起動後も設定が維持される
   - [ ] 許可済みツールは権限ダイアログをスキップする
   - [ ] 設定画面から許可済みツールを削除できる
3. 未充足項目がある場合は記録

**期待される成果物**:

- 要件充足最終確認チェックリスト

---

### タスク2: コード整合性確認

**目的**: 実装コードの整合性を最終確認する

**実行手順**:

1. PermissionStoreとSkillExecutorの連携が正常か確認
2. IPCハンドラーが正しく登録されているか確認
3. 設定UIがIPCを通じて正しく動作するか確認
4. 問題がある場合は記録

**期待される成果物**:

- コード整合性チェックリスト

---

### タスク3: テスト結果最終確認

**目的**: 全テストの結果を最終確認する

**実行手順**:

1. 全テストを実行:
   ```bash
   pnpm --filter @repo/desktop test
   ```
2. テスト結果を確認:
   - [ ] ユニットテスト全件PASS
   - [ ] 統合テスト全件PASS
   - [ ] 連携テスト全件PASS
3. 失敗するテストがある場合は記録

**期待される成果物**:

- テスト結果最終確認

---

### タスク4: ドキュメント整合性確認

**目的**: ドキュメントと実装の整合性を確認する

**実行手順**:

1. Phase 2の設計ドキュメントと実装の整合性を確認
2. インターフェース定義と実際のAPIの整合性を確認
3. 不整合がある場合は記録

**期待される成果物**:

- ドキュメント整合性チェックリスト

---

### タスク5: 最終レビュー結果判定

**目的**: 総合的なレビュー結果を判定する

**実行手順**:

1. タスク1〜4の結果を集約
2. 以下の基準でレビュー結果を判定:
   - **PASS**: 全レビュー観点で問題なし
   - **MINOR**: 軽微な指摘あり（ドキュメント修正等）
   - **MAJOR**: 重大な問題あり（実装修正必要）
   - **CRITICAL**: 致命的な問題あり（要件再確認必要）
3. 判定結果と対応方針を記録

**期待される成果物**:

- `outputs/phase-10/final-review-report.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
