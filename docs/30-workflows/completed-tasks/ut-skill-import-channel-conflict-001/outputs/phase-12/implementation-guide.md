# Part 1: IPC チャネル名の競合ってなに？（やさしく解説）

## 1. なぜチャネル名が重要なの？

### 1.1 IPC チャネルって何？

コンピューターのアプリの中には、「表の部分」（画面に見えているところ）と「裏の部分」（画面には見えないけど、ファイルを読んだりインターネットに接続したりするところ）があります。

この「表」と「裏」は直接話ができないので、**伝言板**のようなしくみを使ってやり取りします。この伝言板のしくみを「IPC」（プロセス間通信）と呼びます。

伝言板にはたくさんのメッセージが飛び交うので、それぞれのメッセージには**名前（チャネル名）**をつけます。

これは、お店の商品棚についている**棚番号**と同じです。棚番号があるから、「3番の棚からお菓子を取ってきて」と頼めます。棚番号がなかったら、どこに何があるか分からなくなってしまいます。

### 1.2 チャネル名が被るとどうなる？

同じ住所に2軒の家が建っている状態を想像してみてください。郵便局の人が「東京都〇〇区△△町1-1」に手紙を届けようとしても、どちらの家に届ければいいか分かりません。手紙が間違った家に届いたり、届かなかったりします。

IPC チャネルでも同じことが起きます。もし同じ名前のチャネルが2つあると、アプリは**どちらにメッセージを届ければいいか分からなくなって、エラーが出たり、間違った処理が動いたり**します。

今回のケースでは、`skill:import` という名前が2つの場面で使われそうになっていました。

| 場面                      | やりたいこと                         | 例え               |
| ------------------------- | ------------------------------------ | ------------------ |
| 場面1（既にある機能）     | パソコンの中にあるスキルを読み込む   | 近所のお店で買い物 |
| 場面2（これから作る機能） | インターネットからスキルを持ってくる | ネット通販で買い物 |

どちらも「スキルを取り込む」という意味では同じですが、**やり方がまったく違います**。同じ名前をつけてしまうと、アプリが混乱します。

### 1.3 今回やったこと

「近所のお店で買う」と「ネット通販で買う」は、どちらも「買い物」ですが別の行動です。同じように、「パソコンの中から読み込む」と「インターネットから持ってくる」も別の操作です。

そこで、名前を分けました。

| 操作                 | 変更前の名前   | 変更後の名前               |
| -------------------- | -------------- | -------------------------- |
| パソコンから読み込む | `skill:import` | `skill:import`（変更なし） |
| ネットから持ってくる | `skill:import` | `skill:importFromSource`   |

「FromSource」は「外部の出どころから」という意味です。これで、2つの操作が明確に区別できるようになりました。

### 1.4 なぜ「建てる前」に直すの？

マンションを建てるとき、設計図に「301号室」が2つ書かれていたらどうなるでしょうか？建て始めてから気づいたら、壁を壊して作り直さないといけません。でも、設計図の段階で気づけば、紙の上で番号を直すだけで済みます。

今回のタスクも同じです。まだ「ネット通販で買う」機能（TASK-9F）は作り始めていません。設計図（仕様書）の段階で名前の被りに気づいたので、設計図を直すだけで済みました。

- 設計図（仕様書）の修正 = 簡単、安い、すぐ直せる
- 完成したアプリの修正 = 大変、時間がかかる、テストもやり直し

これが「予防的タスク」と呼ばれる理由です。問題が起きる前に、先手を打って直しておくということです。

## 2. IPC チャネル命名規則

本タスクで確立されたスキル関連 IPC チャネルの命名パターン:

```
skill:{動詞}           -- 既存ローカル操作（list, import, remove, get, update 等）
skill:{動詞}FromSource -- 外部ソース操作（importFromSource）
skill:{動詞}Source     -- ソース関連操作（validateSource）
skill:{動詞}           -- 新規単純操作（export）
```

### 既存チャネルと新規チャネルの対応表

| チャネル名               | 引数型                                            | 用途                 | 状態    |
| ------------------------ | ------------------------------------------------- | -------------------- | ------- |
| `skill:list`             | なし                                              | ローカルスキル一覧   | 既存    |
| `skill:import`           | `skillName: string`                               | ローカルスキル読込   | 既存    |
| `skill:remove`           | `skillName: string`                               | ローカルスキル削除   | 既存    |
| `skill:detail`           | `skillName: string`                               | スキル詳細取得       | 既存    |
| `skill:readMarkdown`     | `skillName: string`                               | Markdown読み取り     | 既存    |
| `skill:importFromSource` | `ShareTarget`                                     | 外部ソースインポート | TASK-9F |
| `skill:validateSource`   | `ShareTarget`                                     | ソース検証           | TASK-9F |
| `skill:export`           | `{ skillName: string, destination: ShareTarget }` | スキルエクスポート   | TASK-9F |

### 命名の判断基準

| 条件                                         | 命名パターン             | 例                       |
| -------------------------------------------- | ------------------------ | ------------------------ |
| 既存チャネルと用途が異なり、引数型も異なる   | `skill:{動詞}FromSource` | `skill:importFromSource` |
| 既存チャネルと名前衝突のリスクがない新規操作 | `skill:{動詞}`           | `skill:export`           |
| 操作対象がソース自体（検証、一覧等）         | `skill:{動詞}Source`     | `skill:validateSource`   |

## 4. TASK-9F 実装者向けの注意事項

TASK-9F を実装する際は、以下の手順でチャネルを追加する。

### 4.1 channels.ts への追加

```typescript
// apps/desktop/src/main/ipc/channels.ts

// 既存（変更不要）
SKILL_IMPORT = "skill:import",

// 新規追加
SKILL_IMPORT_FROM_SOURCE = "skill:importFromSource",
SKILL_VALIDATE_SOURCE = "skill:validateSource",
SKILL_EXPORT = "skill:export",
```

### 4.2 preload/types.ts への型定義追加

新チャネルの引数型（`ShareTarget`）と戻り値型を `preload/types.ts` に追加する。`ShareTarget` の定義は task-022 Step 1 を参照。

### 4.3 既存チャネルの取り扱い

| チャネル                   | 対応                                                         |
| -------------------------- | ------------------------------------------------------------ |
| `SKILL_IMPORT`（既存）     | **変更しない**。UT-FIX-SKILL-IMPORT-INTERFACE-001 で修正済み |
| `SKILL_IMPORT_FROM_SOURCE` | 新規追加。引数は `ShareTarget` 型                            |
