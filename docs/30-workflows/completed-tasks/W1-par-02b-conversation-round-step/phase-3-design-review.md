## 実行手順

### Step 0: 並列レーンの実行（Lane A/B/C/D）

- Lane A/B/C/D の表を埋め、判定（PASS/MINOR/FAIL）と必要アクションを確定する。
- どれかが MINOR/FAIL の場合は、必要箇所を Phase 1/2/3 に戻して修正し、解消できない論点は未タスク化して再レビューする（Phase 4 へ進まない）。

### Step 1: コンポーネント分割レビュー

確認ポイント:

- `ConversationRoundStep.tsx` が単一ファイルとして大きすぎないか
- サブコンポーネント（QuestionCard・ScheduleConfigInput・ApplySummaryCard・InterviewProgressBar）を別ファイルに分割すべきか

判断基準:

- 200行以下ならインライン可
- 200行超・再利用が見込まれる場合は別ファイル分割を検討

推奨: `ApplySummaryCard` と `InterviewProgressBar` は再利用可能性があるため、別ファイル分割を検討する。`QuestionCard` と `ScheduleConfigInput` は `ConversationRoundStep.tsx` 内にインライン実装とする。

### Step 2: ページング状態管理レビュー

確認ポイント:

- `currentPage` が内部状態（`useState`）で管理されることは適切か
- Page1 → Page2 の遷移時に未回答バリデーションが必要か（Page1は任意のため不要）
- Page2 → Page1 の「戻る」時に状態が保持されるか（`answers` は親管理のため保持される）

懸念点と対応:

- `currentPage` はコンポーネント内部状態で管理する（親に露出不要）
- Page1・Page2 ともに全問任意のため、ページ遷移時のバリデーションは不要

### Step 3: Q3スケジュールUI展開レビュー

確認ポイント:

- インライン展開による問数の変化がないことを確認（Q3の中に展開するため問数は常に6問）
- スケジュールUIの入力バリデーション（Touched-state方式）が適切か
- cron式のバリデーション範囲（書式チェックのみ、実行可否は問わない）

対応方針:

- cron式は簡易的なパターンマッチ（`/^(\*|[0-9,\-\/]+)\s+(\*|[0-9,\-\/]+)\s+...$/`）で検証
- タイムゾーンは `Intl.supportedValuesOf("timeZone")` から取得したリストで選択

### Step 4: Q5必須バリデーションタイミングレビュー

仕様確認:

- Q5必須チェックは「今すぐ生成する」ボタン押下時（Step 2 遷移時）のみ行う
- Page1→Page2 遷移時には Q5 チェックを行わない
- 適用サマリーカード表示時に Q5 未設定警告を表示する

問題なし。設計通りで適切。

### Step 5: 適用サマリーカード設計レビュー

確認ポイント:

- カードが表示されている間も背景のフォームを操作できるか（モーダルではなくインラインカード）
- dismissible（×ボタン）でカードを閉じた後、再度「今すぐ生成する」を押したときの挙動
- Q5未設定警告が表示されている状態で「生成する」を押せるか（警告は警告であり、ブロックしない）

対応方針:

- インラインカード（モーダルではない）として実装
- カードを閉じた後に再度「今すぐ生成する」を押すと再表示する
- Q5未設定警告は表示するが生成をブロックしない（`onGenerate("skip")` を呼べる）

### Step 6: スマートデフォルト初期化レビュー

確認ポイント:

- `useEffect` で `smartDefaults` が変更されたときに `answers` を更新するか
- ユーザーが一度回答した後に `smartDefaults` が変わった場合の挙動

対応方針:

- 初回マウント時のみ `smartDefaults` で初期化する（`useEffect(fn, [])` または Props 初期値）
- `smartDefaults` の変更で上書きしない（ユーザー回答を優先）

### Step 7: W1-par-02a 連携検証

確認ポイント:

- `formData.category` が `SkillInfoFormData` から正しく渡されるか
- `isQ5Required = formData.category === "external-integration"` の判定が確実か

検証結果: `formData` を Props として受け取るだけで連携が成立する。追加の Context/Store は不要。

### Step 8: 削除影響範囲の再確認

```bash
rg -n "ConfigureStep|WizardOptions" apps packages -g '*.ts' -g '*.tsx'
```

全参照箇所を `ConversationRoundStep` / `ConversationAnswers` に置き換えることを確認する。
