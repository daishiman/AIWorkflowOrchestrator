## プロンプトインジェクション対策

### 1. ユーザー入力の取り扱い

```typescript
// query パラメータはそのままプロンプトに埋め込まれる
const prompt = `Query: ${query}\n\nSearch Results:\n${resultsText}`;
```

**対策状況**:

- [x] クエリは検索システム経由で渡される（直接ユーザー入力ではない）
- [x] 検索結果コンテンツは500文字に制限
- [x] LLMレスポンスはJSON構造のみを期待し、パース時に検証

### 2. 出力の検証

```typescript
// JSON抽出で余分なテキストを除去
const jsonMatch = response.match(/\{[\s\S]*\}/);
if (!jsonMatch) {
  return this.createFallbackResponse(results.length);
}

// パース失敗時はフォールバック
try {
  const parsed = JSON.parse(jsonMatch[0]) as LLMEvaluationResponse;
  // ...
} catch {
  return this.createFallbackResponse(results.length);
}
```

**対策状況**:

- [x] JSON形式以外のレスポンスを安全に処理
- [x] パース例外をキャッチしてフォールバック
- [x] 評価数不足時は安全なデフォルト値で補完

### 3. スコア値の検証

```typescript
// スコアを0-1の範囲にクランプ
const normalizedScore = Math.min(Math.max(evaluation.score / 10, 0), 1);
```

**対策状況**:

- [x] 不正なスコア値（負数、10超）を安全な範囲に正規化
- [x] 境界値外の入力からの保護

## エラーメッセージの安全性

### Result型によるエラー伝播

```typescript
if (!llmResult.success) {
  return err(new Error(`LLM evaluation failed: ${llmResult.error.message}`));
}
```

**評価**:

- [x] 内部スタックトレースは露出しない
- [x] エラーメッセージは汎用的な表現を使用
- [x] LLM APIのエラー詳細は外部に伝播（API側でサニタイズ想定）
