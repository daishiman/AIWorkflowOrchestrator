## 1. 実装スコープ（In Scope）

### 1.1 必須実装（Must Have）

| カテゴリ   | 実装項目                         | 説明                              |
| ---------- | -------------------------------- | --------------------------------- |
| クラス     | RelevanceEvaluator               | LLMベースの関連性評価クラス       |
| クラス     | CorrectiveRAG                    | CRAGメインクラス                  |
| 型定義     | types.ts                         | CRAG関連の型・インターフェース    |
| 評価機能   | LLM呼び出しによる関連性評価      | ILLMClient.complete()を使用       |
| 評価機能   | 3段階アクション分類              | correct/incorrect/ambiguous       |
| 処理機能   | handleCorrect()                  | 結果をそのまま返却                |
| 処理機能   | handleAmbiguous()                | 低スコア結果のフィルタリング      |
| 処理機能   | 個別スコア算出                   | 各結果に0-1スコアを付与           |
| 処理機能   | 全体スコア計算（加重平均）       | 上位結果に重みを付けた加重平均    |
| エラー処理 | Result型によるエラーハンドリング | 例外をthrowせずResult.err()で返却 |
| テスト     | ユニットテスト                   | Line Coverage 80%以上             |
| テスト     | 統合テスト                       | LLM連携・パイプライン統合テスト   |

### 1.2 オプション実装（Should Have）

| カテゴリ         | 実装項目                        | 説明                            |
| ---------------- | ------------------------------- | ------------------------------- |
| 処理機能         | handleIncorrect() - Web検索補強 | IWebSearcher経由のWeb検索       |
| 処理機能         | Knowledge Refinement            | 不要情報の除去                  |
| オプション       | 評価プロンプトカスタマイズ      | maxEvaluate、閾値のカスタマイズ |
| インターフェース | IWebSearcher                    | Web検索プロバイダーの抽象化     |

## 2. 除外スコープ（Out of Scope）

### 2.1 本タスクでは実装しない項目

| カテゴリ | 除外項目                      | 理由                             |
| -------- | ----------------------------- | -------------------------------- |
| 機能     | 実際のWeb検索プロバイダー実装 | 別タスク（CONV-XX）で実装予定    |
| 機能     | 複数LLMプロバイダー対応       | ILLMClientの抽象化で対応済み     |
| 機能     | キャッシュ機構                | 別タスクで検討                   |
| 機能     | バッチ処理最適化              | 初期実装後の最適化フェーズで対応 |
| UI       | CRAG設定UI                    | フロントエンド別タスク           |
| API      | REST API公開                  | 内部サービスとして実装           |
| 永続化   | 評価結果の保存                | 初期実装では不要                 |

### 2.2 将来の拡張として検討

| カテゴリ | 拡張候補                  | 優先度 |
| -------- | ------------------------- | ------ |
| 機能     | 評価結果のキャッシュ      | 中     |
| 機能     | 非同期バッチ評価          | 低     |
| 機能     | 評価結果の履歴保存        | 低     |
| 機能     | A/Bテスト用の複数評価戦略 | 低     |
| 統合     | 外部RAGサービス連携       | 低     |

## 5. 技術的制約

### 5.1 パフォーマンス制約

| 制約項目       | 値                    | 理由                      |
| -------------- | --------------------- | ------------------------- |
| タイムアウト   | 10秒                  | UX要件                    |
| 評価対象結果数 | 最大5件（デフォルト） | LLMコスト・レスポンス時間 |

### 5.2 互換性制約

| 制約項目   | 値                                      | 理由                |
| ---------- | --------------------------------------- | ------------------- |
| TypeScript | strict mode                             | 型安全性            |
| Result型   | packages/shared/src/types/rag/result.ts | RAGパイプライン標準 |
