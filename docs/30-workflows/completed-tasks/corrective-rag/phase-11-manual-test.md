# Phase 11: 手動テスト

## メタ情報

| 項目   | 値             |
| ------ | -------------- |
| Phase  | 11             |
| 機能名 | corrective-rag |
| 作成日 | 2026-01-16     |

## 目的

自動テストでカバーできない観点（UX・実環境動作・エッジケース）を手動で検証する。

## 実行タスク

- 実環境テスト: 実際のLLM APIとの接続テスト
- シナリオテスト: ユーザーシナリオに基づく動作確認
- エッジケーステスト: 境界条件での動作確認

## テストシナリオ

### シナリオ1: 高品質検索結果の処理

| 手順 | 操作                   | 期待結果                    |
| ---- | ---------------------- | --------------------------- |
| 1    | 明確なクエリで検索実行 | 関連性の高い結果が返される  |
| 2    | CRAG評価を実行         | action: "correct"が返される |
| 3    | 結果を確認             | 元の結果がそのまま返される  |

### シナリオ2: 低品質検索結果の処理（Web検索有効）

| 手順 | 操作                          | 期待結果                      |
| ---- | ----------------------------- | ----------------------------- |
| 1    | 曖昧なクエリで検索実行        | 関連性の低い結果が返される    |
| 2    | CRAG評価を実行（Web検索有効） | action: "incorrect"が返される |
| 3    | Web検索が実行される           | augmentedContextに結果が設定  |

### シナリオ3: 中間品質検索結果の処理

| 手順 | 操作                         | 期待結果                      |
| ---- | ---------------------------- | ----------------------------- |
| 1    | 部分的に関連するクエリで検索 | 混在した結果が返される        |
| 2    | CRAG評価を実行               | action: "ambiguous"が返される |
| 3    | フィルタリングを確認         | 低スコア結果が除外されている  |

### シナリオ4: エラー処理の確認

| 手順 | 操作                          | 期待結果                   |
| ---- | ----------------------------- | -------------------------- |
| 1    | LLM APIがタイムアウトする状況 | Result.err()が返される     |
| 2    | エラーメッセージを確認        | 適切なエラー情報が含まれる |
| 3    | リトライ動作を確認            | 設定に従いリトライされる   |
