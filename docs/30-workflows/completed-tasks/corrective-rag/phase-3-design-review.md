## レビュー観点

### 1. 要件との整合性

| 確認項目                                                 | 結果 |
| -------------------------------------------------------- | ---- |
| 全機能要件（FR-001〜FR-009）が設計に反映されているか     | -    |
| 全非機能要件（NFR-001〜NFR-006）が設計に反映されているか | -    |
| 受け入れ基準が設計で実現可能か                           | -    |

### 2. アーキテクチャ妥当性

| 確認項目                               | 結果 |
| -------------------------------------- | ---- |
| クラス責務が単一責任原則に従っているか | -    |
| 依存関係が適切か（循環依存がないか）   | -    |
| 既存コードベースとの整合性があるか     | -    |
| 拡張性が確保されているか               | -    |

### 3. インターフェース設計

| 確認項目                                         | 結果 |
| ------------------------------------------------ | ---- |
| 型定義が明確か                                   | -    |
| Result型でエラーが適切に扱われているか           | -    |
| 既存インターフェース（ILLMClient等）と整合するか | -    |
| オプション設定が適切にデフォルト値を持つか       | -    |

### 4. セキュリティ・パフォーマンス

| 確認項目                                         | 結果 |
| ------------------------------------------------ | ---- |
| LLM API呼び出しのタイムアウトが設定されているか  | -    |
| エラーハンドリングが適切か                       | -    |
| プロンプトインジェクション対策が考慮されているか | -    |

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点       | 確認項目                                 |
| ------------------ | ---------------------------------------- |
| LLM連携設計        | ILLMClient.complete()の呼び出し設計      |
| 入力データフロー   | FusedSearchResult[] → RelevanceEvaluator |
| 出力データフロー   | CRAGResult → 呼び出し元への返却          |
| エラーハンドリング | LLM API失敗時のResult.err()返却          |
| Web検索連携        | IWebSearcher.search()のオプション設計    |
