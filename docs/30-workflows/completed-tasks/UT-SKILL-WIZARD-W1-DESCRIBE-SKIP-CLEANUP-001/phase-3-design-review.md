## 目的

Phase 2 の設計方針（削除方針・変更計画）に矛盾・漏れがないことを確認し、
Phase 4（テスト作成）へ進めるかのゲート判定を行う。

## ゲート判定基準

| 判定 | 条件                                                              |
| ---- | ----------------------------------------------------------------- |
| PASS | MAJOR 指摘なし（MINOR 指摘は Phase 4 以降で解消可）               |
| FAIL | MAJOR 指摘が1件以上あり、Phase 2 に戻って設計を修正する必要がある |

### MAJOR 判定基準（いずれかに該当すると FAIL）

- AC-1〜AC-5 のいずれかに対応する設計が欠落している
- 変更対象ファイルの特定が不完全（対象ファイル以外への影響が見落とされている）
- `describe.skip` ブロックを意図せず解除・削除する設計になっている
- 本体コード（SkillLifecyclePanel.tsx 等）への変更が含まれている

### MINOR 判定基準（指摘はするが PASS）

- 変更箇所の記述が不明確（後続 Phase で補足可能な範囲）
- 検証コマンドの記述が不十分（追記で対応可能）

## レビュー観点

| 観点                             | 確認内容                                                                                         | 判定 |
| -------------------------------- | ------------------------------------------------------------------------------------------------ | ---- |
| 削除方針の妥当性                 | 削除 vs 書き換えの選択が適切か（`describe.skip` 状態での最小変更として削除方針が妥当か）         | [ ]  |
| `describe.skip` 維持方針の妥当性 | スキップ状態を維持する方針が明示されており、意図せぬスキップ解除がないか                         | [ ]  |
| AC-1との整合性                   | 設計が `skill-lifecycle-request-input` 参照の全量削除を保証しているか                            | [ ]  |
| AC-2との整合性                   | `describe.skip` ブロック内の参照も含めて対応する設計になっているか                               | [ ]  |
| AC-3との整合性                   | 削除後のテストが現行 UI を反映した内容になることが設計に含まれているか（または削除のみで十分か） | [ ]  |
| AC-4との整合性                   | `pnpm --filter @repo/desktop test:run` PASS を検証コマンドとして定義しているか                   | [ ]  |
| AC-5との整合性                   | `pnpm --filter @repo/desktop typecheck` PASS を検証コマンドとして定義しているか                  | [ ]  |
| 影響範囲の確認                   | 変更が対象2ファイルのみに限定されており、他ファイルへの影響がないことを確認しているか            | [ ]  |
| 本体コードへの非影響             | SkillLifecyclePanel.tsx 等の本体コードへの変更が含まれていないか                                 | [ ]  |

## 設計の妥当性検証

### simpler alternative の検討

| 代替案                                               | 評価                                                             | 採用可否 |
| ---------------------------------------------------- | ---------------------------------------------------------------- | -------- |
| `describe.skip` ブロックごと削除する                 | スコープ拡大につながる。将来の復活可能性を排除するリスクがある   | 要検討   |
| 旧 testid 参照のみ削除し `it` ブロック構造を維持する | 最小変更で AC を満たせる。安全で影響範囲が最小                   | 推奨     |
