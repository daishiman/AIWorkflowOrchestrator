## 1. 削除対象と他コードの依存関係確認表

### 1-1. 削除対象3グループの相互依存

| 削除対象                                | 依存方向 | 依存先                                  | 依存の種類            | 備考                         |
| --------------------------------------- | -------- | --------------------------------------- | --------------------- | ---------------------------- |
| グループ1: State宣言 4件                | ← WRITE  | グループ2: useEffect                    | state setter 呼び出し | useEffectがsetterを呼ぶ      |
| グループ1: State宣言 4件                | ← READ   | グループ3: `_handleSubmitWorkflowInput` | state value 参照      | 関数内でのみ読み取られる     |

## 4. 4条件評価

### 評価サマリー

| 評価条件 | 評価結果 | 根拠                                                                                             |
| -------- | -------- | ------------------------------------------------------------------------------------------------ |
| 矛盾なし | **OK**   | 3グループの削除は相互に矛盾なく、外部参照も存在しない                                            |
| 漏れなし | **OK**   | State宣言・useEffect・関数の3グループを全て削除対象として特定済み。インポート行の扱いも明記済み  |
| 整合あり | **OK**   | 削除後の typecheck・lint・test が全てパスすることを検証手順で確認する設計になっている            |
| 依存整合 | **OK**   | 削除対象3グループ間の依存は閉じており、外部（JSX・他コンポーネント・他ファイル）からの参照はない |

### 評価詳細: 矛盾なし

- グループ1（State）を削除すると、グループ2（useEffect）の setter 呼び出しが参照不能になるが、グループ2も同時に削除するため矛盾は生じない
- グループ1を削除すると、グループ3（関数）の state 参照がコンパイルエラーになるが、グループ3も同時に削除するため矛盾は生じない
- `useState` インポートは他の state が使用するため、削除しない設計は矛盾しない

### 評価詳細: 漏れなし

- dead-code-list.md に記載の3グループ（70行）が全削除対象として網羅されている
- `useState` インポートの取り扱い方針（削除不要）を明記した
- `useEffect` インポートの取り扱い方針（他に使用箇所があれば削除不要）を明記した

### 評価詳細: 整合あり

- 削除後に `pnpm typecheck` でコンパイルエラーがないことを確認する手順を deletion-procedure.md に定義した
- 削除後に `pnpm lint` で ESLint エラー（未使用変数等）がないことを確認する手順を定義した
- 削除後に `pnpm test` で既存テストが全 PASS することを確認する手順を定義した

### 評価詳細: 依存整合

- `grep -rn "_handleSubmitWorkflowInput" apps/ packages/` で外部参照がないことを事前確認する
- `grep -rn "selectedOptionId\|textAnswer\|secretAnswer\|confirmAnswer" apps/ packages/` で JSX・他ファイルからの参照がないことを事前確認する
- カバレッジレポートにて `_handleSubmitWorkflowInput` の FNDA:0（未実行）を確認済み
