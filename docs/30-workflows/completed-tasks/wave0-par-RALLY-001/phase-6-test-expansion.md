## 目的

dead code 削除後の回帰テスト結果を確認し、追加テストが必要な場合は作成する。

## 実行タスク

- タスク1: 既存テストの回帰結果を整理する
- タスク2: uncovered 観点があるかを判断する
- タスク3: 必要な場合のみ targeted 追加を定義する

## テスト拡充方針

dead code 削除のためロジック変更はなく、基本的に追加テストは不要。ただし以下のケースを確認する。

### 回帰テスト確認

```bash
# 全テスト実行
pnpm --filter @repo/desktop test -- --reporter=verbose

# SkillLifecyclePanelに関連するテストのみ実行
pnpm --filter @repo/desktop test -- --reporter=verbose SkillLifecyclePanel
```

### 追加テスト検討

以下のシナリオで追加テストが必要か判断する:

| シナリオ                           | 追加テスト要否               | 理由             |
| ---------------------------------- | ---------------------------- | ---------------- |
| dead code 参照がないことの静的確認 | 不要（grep で確認済み）      | 静的解析で十分   |
| 削除後のビルド成功                 | 不要（typecheck で確認済み） | コンパイルで確認 |
| 既存機能の回帰                     | 既存テストで確認             | ロジック変更なし |

## 統合テスト連携

- Phase 7 は本Phaseの追加要否判断を前提に coverage を確認する
- targeted 追加が 0 件でも、その判断根拠を Phase 9 で再利用する
