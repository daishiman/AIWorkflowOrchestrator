## レビュー観点

### 1. 要件充足確認

- [ ] すべての受け入れ基準が満たされている
- [ ] スコープ外の機能が含まれていない
- [ ] 機能要件が正しく実装されている
- [ ] 非機能要件が満たされている

### 2. 設計整合性確認

- [ ] 設計書に従った実装になっている
- [ ] アーキテクチャパターンに準拠している
- [ ] 型定義が設計通りに実装されている
- [ ] IPCチャネルが設計通りに実装されている

### 3. テスト確認

- [ ] すべてのテストがパスしている
- [ ] カバレッジ目標を達成している
- [ ] 統合テストが実装されている
- [ ] エッジケースがカバーされている

### 4. 品質確認

- [ ] コード品質チェックがパス
- [ ] セキュリティチェックがパス
- [ ] アクセシビリティチェックがパス
- [ ] パフォーマンスが許容範囲内

## 判定基準

| 判定     | 条件             | 対応                     |
| -------- | ---------------- | ------------------------ |
| PASS     | 全観点で問題なし | Phase 11へ進行           |
| MINOR    | 軽微な指摘あり   | 指摘対応後Phase 11へ進行 |
| MAJOR    | 重大な問題あり   | 該当Phaseへ戻り修正      |
| CRITICAL | 致命的な問題あり | Phase 1へ戻り要件再確認  |

### 戻り先決定基準

| 問題の種類   | 戻り先                |
| ------------ | --------------------- |
| 要件の問題   | Phase 1（要件定義）   |
| 設計の問題   | Phase 2（設計）       |
| 実装の問題   | Phase 5（実装）       |
| テストの問題 | Phase 6（テスト拡充） |
| 品質の問題   | Phase 9（品質保証）   |
