## リファクタリング観点

### 1. 命名の改善

- [ ] 変数名が意図を明確に表現している
- [ ] 関数名が動作を適切に表現している
- [ ] 型名がドメイン概念を反映している

### 2. 関数の分割

- [ ] 1つの関数が1つの責務を持っている
- [ ] 関数の行数が適切（20行以下推奨）
- [ ] ネストが深すぎない（3レベル以下）

### 3. 重複の除去

- [ ] 同じロジックが複数箇所にない
- [ ] 共通処理がユーティリティ化されている

### 4. 型安全性の強化

- [ ] any型が使用されていない
- [ ] 適切な型ガードが実装されている
- [ ] nullableの取り扱いが明確

### 5. パフォーマンス改善

- [ ] 不要な再レンダリングがない
- [ ] メモ化が適切に使用されている
- [ ] 重い処理が最適化されている
