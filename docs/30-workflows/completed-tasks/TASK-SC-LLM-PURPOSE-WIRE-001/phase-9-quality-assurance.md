## 目的

リファクタリング（Phase 8）完了後の実装に対して、TypeScript 型チェック・ESLint・テストの3つの品質ゲートを
すべて通過させることで、PR 提出前の最終品質基準を満たすことを確認する。

## 背景

実装とリファクタリングを通じたコードの変更が、型安全性・コードスタイル・テスト結果のいずれかで
品質基準を下回っていないかを組織的に検証するフェーズである。
品質ゲートを段階的に実行することで、問題の原因を特定しやすくする。

---

## 実行タスク

### タスク1: TypeScript 型チェックの実行

**目的**: 実装コードに型エラーが存在しないことを確認する。

**実行コマンド**:

```bash
pnpm --filter @repo/desktop typecheck
```

**確認内容**:

- コマンドが exit code 0 で完了すること。
- `SkillCreatorService.ts` に型エラーが存在しないこと。
- purpose 抽出ロジックの追加により新たな型エラーが発生していないこと。
- `llmClient.generate` の引数型・戻り値型が正しく扱われていること。

**判定基準**:

| 状態              | 判定 | 対応                                           |
| ----------------- | ---- | ---------------------------------------------- |
| 型エラー 0 件     | PASS | 次のタスクへ進む                               |
| 型エラー 1 件以上 | FAIL | エラー内容を確認し、型定義を修正してから再実行 |

**期待される成果物**:

- 型チェック PASS の確認記録（エラー 0 件）

---

### タスク2: ESLint の実行

**目的**: 実装コードが ESLint ルールに準拠していることを確認する。

**実行コマンド**:

```bash
pnpm --filter @repo/desktop lint
```

**確認内容**:

- コマンドが exit code 0 で完了すること。
- `SkillCreatorService.ts` に ESLint エラー（error レベル）が存在しないこと。
- 警告（warning レベル）は許容されるが、新規追加した行で発生した警告はレビューして対処方針を記録する。

**判定基準**:

| 状態                   | 判定   | 対応                                            |
| ---------------------- | ------ | ----------------------------------------------- |
| ESLint エラー 0 件     | PASS   | 次のタスクへ進む                                |
| ESLint エラー 1 件以上 | FAIL   | エラー内容を確認し、コードを修正してから再実行  |
| 新規 warning あり      | 要記録 | 警告内容を outputs に記録し、対処方針を記載する |

**期待される成果物**:

- ESLint PASS の確認記録（エラー 0 件）
- 新規 warning がある場合はその内容と対処方針

---

### タスク3: 全テストの実行

**目的**: 実装・リファクタリングを経ても全テストが PASS していることを確認する。

**実行コマンド**:

```bash
pnpm --filter @repo/desktop test
```

**確認内容**:

- 全テストケースが PASS していること。
- purpose 抽出専用ユニットテスト（AC-7 で作成）が PASS していること。
- collaborative モード・orchestrate モードの既存テストが PASS していること（AC-6）。
- テスト実行時間が許容範囲内であること（LLM モックを使用しているため速度低下がないこと）。

**判定基準**:

| 状態          | 判定 | 対応                                             |
| ------------- | ---- | ------------------------------------------------ |
| 全テスト PASS | PASS | 次のタスクへ進む                                 |
| 1 件以上 FAIL | FAIL | 失敗テストの内容を確認し、実装またはテストを修正 |

**期待される成果物**:

- テスト全件 PASS の確認記録

---

### タスク4: 品質ゲートの総合判定

**目的**: 3つの品質ゲートの結果を統合して、Phase 10 への進行可否を判断する。

**総合判定テーブル**:

| 品質ゲート            | コマンド                                | 判定            |
| --------------------- | --------------------------------------- | --------------- |
| TypeScript 型チェック | `pnpm --filter @repo/desktop typecheck` | □ PASS / □ FAIL |
| ESLint                | `pnpm --filter @repo/desktop lint`      | □ PASS / □ FAIL |
| 全テスト              | `pnpm --filter @repo/desktop test`      | □ PASS / □ FAIL |

**総合判定基準**:

| 条件               | 判定     | 対応                                      |
| ------------------ | -------- | ----------------------------------------- |
| 3ゲートすべて PASS | **PASS** | Phase 10 へ進む                           |
| 型チェック FAIL    | **FAIL** | 型エラーを修正し Phase 9 再実行           |
| ESLint FAIL        | **FAIL** | Lint エラーを修正し Phase 9 再実行        |
| テスト FAIL        | **FAIL** | テスト修正または実装修正し Phase 9 再実行 |

**実行手順**:

1. タスク1〜3を順番に実行し、各判定結果を総合判定テーブルに記録する。
2. 3ゲートすべて PASS の場合のみ Phase 10 へ進む。
3. いずれか FAIL の場合は対応アクションを実施し、Phase 9 を再実行する。

**期待される成果物**:

- 総合判定テーブル（記入済み）

## 統合テスト連携

Phase 9 では以下の統合テスト連携アクションを実行する:

1. **統合テスト結果の確認**: `pnpm --filter @repo/desktop test` の実行結果には統合テストも含まれるため、統合テストの PASS も品質ゲートの一部として扱う。
2. **品質ゲート通過確認**: 統合テストが FAIL の場合、品質ゲートの「全テスト」判定は FAIL となり Phase 9 を通過できない。
3. **型安全性の統合確認**: `llmClient.generate` インターフェースへの型変更が統合テストで正しく検証されていることを確認する。
