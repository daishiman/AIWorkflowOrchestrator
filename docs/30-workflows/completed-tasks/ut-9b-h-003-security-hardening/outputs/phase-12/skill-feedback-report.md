## 技術的教訓（今回の苦戦箇所）

### 1. セキュリティ仕様の文言と実装の不整合

| 項目 | 内容                                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 課題 | 仕様書に英語デフォルトメッセージが残っていたが、実装は日本語メッセージを返却していた                                                                     |
| 原因 | 既存仕様の流用時に返却メッセージ仕様を実装差分で更新し切れていなかった                                                                                   |
| 解決 | `security-electron-ipc.md` と `api-ipc-agent.md` を実装準拠に統一し、`validatePath` / `sanitizeErrorMessage` / `ALLOWED_SCHEMA_NAMES` の返却仕様を明文化 |
| 教訓 | セキュリティ仕様は「関数名の記載」だけでなく「返却値・エラーメッセージ」まで一致確認が必須                                                               |

### 2. 完了済み未タスクの残置

| 項目 | 内容                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| 課題 | `UT-9B-H-003` 完了反映後も未タスク指示書が `unassigned-task/` に残っていた                           |
| 原因 | Step 1-C（関連タスクテーブル更新）は実施済みでも、物理ファイルの移管確認が抜けた                     |
| 解決 | `task-9b-h-security-hardening.md` を `completed-tasks/unassigned-task/` に移管し、仕様書参照先も更新 |
| 教訓 | テーブル更新と実ファイル配置確認は別ステップとして検証する                                           |

### 3. Phase 12の最終整合確認不足

| 項目 | 内容                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 課題 | 主要成果物は揃っていたが、`artifacts.json` のステータス更新が漏れていた      |
| 原因 | 文章成果物作成を完了条件の中心に置き、レジストリ更新を後回しにした           |
| 解決 | `phase-1`〜`phase-12` を `completed` に更新し、各Phase成果物を登録           |
| 教訓 | Phase 12完了判定は「ドキュメント生成」と「成果物レジストリ更新」の両輪で行う |
