## 目的

Phase 5 で実装した `createApplicationMenu()` / `buildMacTemplate()` / `buildDefaultTemplate()` が、実際のアプリ起動環境で以下を満たすことを手動で検証する。

1. キーボードショートカット（Cmd+= / Cmd+- / Cmd+0）がウィンドウコンテンツのズーム制御に正しく機能する
2. メニューバー「表示」メニューのズーム項目がクリック操作で機能する
3. 編集メニューの標準ショートカットが正常に動作する
4. 既存機能（DevTools 起動、IPC 通信）が引き続き動作する

### MT-1: ズームイン（Cmd+=）

**操作手順**:

1. 開発サーバーを起動する:
   ```bash
   pnpm --filter @repo/desktop dev
   ```
2. アプリウィンドウが表示されるまで待機する（起動完了の目安: ウィンドウにコンテンツが表示されること）。
3. アプリウィンドウにフォーカスを当てる（クリックでフォーカス確認）。
4. `Cmd+=`（等号キー）または `Cmd++`（Shift+等号）を押下する。
5. ウィンドウ内のテキストおよびコンテンツが拡大されることを目視で確認する。

**合格基準**:

- ウィンドウコンテンツが視覚的に拡大される（フォントサイズが大きくなる）。
- アプリがクラッシュしない。
- エラーダイアログが表示されない。

**対応受入基準**: AC-1

---

### MT-2: ズームアウト（Cmd+-）

**操作手順**:

1. MT-1 の後、引き続きアプリが起動している状態で実施する。
2. `Cmd+-`（マイナスキー）を押下する。
3. ウィンドウ内コンテンツが縮小されることを確認する。
4. 複数回（3〜5 回）押下して段階的に縮小されることを確認する。

**合格基準**:

- ウィンドウコンテンツが視覚的に縮小される（フォントサイズが小さくなる）。
- 複数回押下しても安定して動作する。
- アプリがクラッシュしない。

**対応受入基準**: AC-2

---

### MT-3: ズームリセット（Cmd+0）

**操作手順**:

1. MT-2 でズームアウトした状態から継続する（コンテンツが縮小されている状態）。
2. `Cmd+0`（ゼロキー）を押下する。
3. ウィンドウ内コンテンツが初期サイズ（100%）に戻ることを確認する。

**合格基準**:

- コンテンツのサイズが初期表示（ズーム操作前）と同じ大きさに戻る。
- MT-1 でズームインした後に Cmd+0 を押下しても同様に初期サイズに戻ること。
- アプリがクラッシュしない。

**対応受入基準**: AC-3

---

### MT-4: メニューバーからのズーム操作

**操作手順**:

1. アプリが起動している状態で、macOS メニューバーの「表示」をクリックする。
2. サブメニューに以下の 3 項目が表示されることを確認する:
   - 「拡大」（Cmd+=）
   - 「縮小」（Cmd+-）
   - 「実際のサイズ」（Cmd+0）
3. 「拡大」をクリックしてコンテンツが拡大されることを確認する。
4. 「縮小」をクリックしてコンテンツが縮小されることを確認する。
5. 「実際のサイズ」をクリックして初期サイズに戻ることを確認する。

**合格基準**:

- 「表示」メニューに「拡大」「縮小」「実際のサイズ」の 3 項目が存在する。
- 各項目の右側にキーボードショートカット（Cmd+=、Cmd+-、Cmd+0）が表示される。
- 各項目をクリックするとキーボード操作と同じズーム動作が発生する。

**対応受入基準**: AC-4

---

### MT-5: 編集メニューの標準ショートカット

**操作手順**:

1. アプリ内にテキスト入力フィールドがある画面に遷移する（設定画面など）。
2. テキストを入力してから以下の操作を順番に確認する:
   - `Cmd+Z`: 入力が取り消される（Undo）
   - `Cmd+Shift+Z`: 取り消しが戻る（Redo）
   - テキストを選択して `Cmd+X`: 選択テキストが切り取られる（Cut）
   - `Cmd+V`: クリップボードのテキストが貼り付けられる（Paste）
   - `Cmd+A`: 全テキストが選択される（Select All）
   - 選択テキストがある状態で `Cmd+C`: テキストがコピーされる（Copy）

**合格基準**:

- 各ショートカットが対応する編集操作を実行する。
- 操作後にアプリがクラッシュしない。
- テキストフィールドが存在しない画面では、これらのショートカットが押下されてもエラーが発生しない。

**対応受入基準**: AC-4（編集メニュー項目の存在確認）

---

### MT-6: 開発環境での起動確認

**操作手順**:

1. 以下のコマンドでアプリを起動する:
   ```bash
   pnpm --filter @repo/desktop dev
   ```
2. コンソール出力にエラーが含まれていないことを確認する（`ERROR` / `FATAL` / `TypeError` の文字列が出力されないこと）。
3. アプリウィンドウが表示されることを確認する。
4. Electron Main プロセスのコンソールに `Menu.setApplicationMenu` 関連のエラーが出力されていないことを確認する。

**合格基準**:

- `pnpm --filter @repo/desktop dev` コマンドが正常に完了し、アプリが起動する。
- コンソールに `Menu` 関連のエラーメッセージが出力されない。
- ウィンドウが表示された後、既存の認証フローや IPC 通信が正常に動作する。

**対応受入基準**: AC-6、AC-7、AC-8

---

### MT-7: DevTools の動作確認

**操作手順**:

1. アプリが起動している状態で、以下のいずれかの操作を実行する:
   - `F12` キーを押下する
   - `Cmd+Option+I` キーを押下する（macOS）
2. Chrome DevTools パネルがウィンドウ内または別ウィンドウで開くことを確認する。
3. DevTools を閉じる（同じキー操作または DevTools ウィンドウを閉じる）。

**合格基準**:

- DevTools が正常に開く（`optimizer.watchWindowShortcuts(window)` が引き続き機能している）。
- DevTools を開いた後もズームショートカット（MT-1〜MT-3）が引き続き動作する。
- アプリがクラッシュしない。

**対応受入基準**: AC-8（既存機能が変更されていないこと）

## CLI 環境での代替検証方法（P53 対応）

CLI 環境ではスクリーンショットの取得に制約がある。以下の代替手段を使用して視覚的な検証を補完する。

### 代替手段 A: Electron webContents.capturePage() による自動スクリーンショット

```typescript
// apps/desktop/src/main/__tests__/screenshot.ts（実行用スクリプト）
import { app, BrowserWindow } from "electron";
import * as path from "path";
import * as fs from "fs";

app.whenReady().then(async () => {
  const win = new BrowserWindow({ show: true });
  await win.loadURL("about:blank");

  // ズームインを実行
  win.webContents.setZoomLevel(1);
  const image = await win.webContents.capturePage();
  fs.writeFileSync(
    path.join(__dirname, "screenshot-zoom-in.png"),
    image.toPNG(),
  );

  app.quit();
});
```

### 代替手段 B: 自動テスト結果による間接検証

Phase 4〜7 で実装したユニットテストの実行結果が PASS していることをもって、メニュー構造の正確性を間接的に検証する。

```bash
# テスト実行コマンド
pnpm --filter @repo/desktop exec vitest run src/main/__tests__/menu.test.ts
```

テストが全件 PASS していれば:

- `createApplicationMenu()` が正しい Menu オブジェクトを返している
- `buildMacTemplate()` に `zoomIn`/`zoomOut`/`resetZoom` role が含まれている
- `buildDefaultTemplate()` に同 role が含まれている

を機械的に確認済みとみなす。

### 代替手段 C: 型チェック・Lint による静的検証

```bash
# 型チェック（TypeScript コンパイルエラーなし = 型安全な実装）
pnpm --filter @repo/desktop typecheck

# Lint（ESLint エラーなし = コーディング規約準拠）
pnpm --filter @repo/desktop lint
```
