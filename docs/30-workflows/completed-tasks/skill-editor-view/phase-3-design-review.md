## 目的

Phase 1（要件定義）と Phase 2（設計）の成果物を多角的に検証し、要件と設計の整合性・Apple HIG 準拠・セキュリティ・アクセシビリティ・パフォーマンスの観点でレビューを実施する。レビュー結果に基づき、Phase 4 への進行可否を判定する。

## 背景

SkillEditorView は IPC 通信を通じてファイルシステムを操作するため、セキュリティレビュー（パストラバーサル、引数バリデーション）が重要である。また、2 ペインレイアウトのレスポンシブ対応とアクセシビリティ（ツリーコンポーネントのキーボード操作）は実装難度が高く、設計段階での検証が効率的な開発に直結する。

## 実行手順

### タスク 1: 要件と設計の整合性確認

以下の観点で Phase 1 の要件と Phase 2 の設計を照合する：

| 確認項目             | 検証内容                                                                         |
| -------------------- | -------------------------------------------------------------------------------- |
| FR カバレッジ        | FR-1 〜 FR-8 の全機能要件がコンポーネント設計でカバーされている                  |
| NFR カバレッジ       | NFR-1 〜 NFR-15 の全非機能要件が設計に反映されている                             |
| AC カバレッジ        | AC-1 〜 AC-8 の受け入れ基準がテスト可能な設計になっている                        |
| Props 定義の整合性   | 8 コンポーネントの Props が Phase 1 の要件を満たす情報を伝達している             |
| 状態管理の網羅性     | 3 Hook の状態遷移が全ユーザーフロー（ツリー選択→編集→保存→警告）をカバーしている |
| IPC チャネルの整合性 | 6 IPC チャネルの引数・戻り値が Phase 1 の定義と一致している                      |
| スコープ逸脱         | 設計が Phase 1 で定義した除外範囲の機能を含んでいない                            |

### タスク 2: Apple HIG 準拠チェック

| 確認項目                     | 基準                                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| カラーパレット               | ライト/ダークモードで Apple HIG System Colors を使用している            |
| スペーシング                 | 8px グリッドでスペーシングが統一されている                              |
| 角丸                         | 8px 〜 12px の範囲でコンポーネント間が統一されている                    |
| 影                           | カード: `0 1px 3px rgba(0,0,0,0.04)` の繊細な影を使用している           |
| フォント                     | システムフォント（`-apple-system`, `BlinkMacSystemFont`）を優先している |
| エディターフォント           | 等幅フォント（monospace）14px を使用している                            |
| アニメーション               | 200-300ms の範囲で、目的を持ったアニメーションのみ使用している          |
| ホバー/アクティブ/フォーカス | すべてのインタラクティブ要素にフィードバック状態が定義されている        |
| 破壊的操作                   | ファイル削除・バックアップ復元に確認ダイアログが設計されている          |

### タスク 3: セキュリティレビュー

| 確認項目                      | 基準                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| IPC 引数バリデーション（P42） | 全 7 チャネルの引数に 3 段バリデーション（型チェック → 空文字列 → trim 空文字列）が設計されている           |
| パストラバーサル防止          | relativePath 引数にパストラバーサル攻撃（`../`）の検証が設計されている                                      |
| 読み取り専用制御              | isReadOnly=true の場合、書き込み系 IPC（writeFile, createFile, deleteFile）が呼び出されない設計になっている |
| エラーサニタイズ              | IPC エラーレスポンスが内部情報（パス、スタックトレース）を漏洩しない設計になっている                        |
| チャネル名管理                | IPC チャネル名が `IPC_CHANNELS` 定数で参照されている（ハードコード文字列禁止）                              |
| 送信元検証                    | IPC ハンドラが送信元ウィンドウを検証する設計になっている                                                    |

### タスク 4: アクセシビリティレビュー

| 確認項目                 | 基準                                                                            |
| ------------------------ | ------------------------------------------------------------------------------- |
| ARIA ツリー構造          | FileTreePanel に `role="tree"` + `role="treeitem"` が設計されている             |
| ARIA エディター          | EditorPanel に `role="textbox"` + `aria-multiline="true"` が設計されている      |
| キーボードナビゲーション | Tab 順序（ツリー → ツールバー → エディター）が定義されている                    |
| ツリー内キーボード操作   | ArrowUp/Down（移動）、ArrowRight/Left（展開/折りたたみ）が定義されている        |
| フォーカス管理           | 初期フォーカス、ダイアログフォーカストラップ、フォーカス復帰が定義されている    |
| コントラスト比           | すべてのテキスト・UI 要素で 4.5:1 以上のコントラスト比が確保されている          |
| スクリーンリーダー対応   | ファイルツリーの展開/折りたたみ状態が aria-expanded で通知される                |
| ダイアログ               | UnsavedChangesDialog に role="alertdialog" + aria-modal="true" が設計されている |

### タスク 5: パフォーマンスレビュー

| 確認項目               | 基準                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------- |
| ファイルツリー初期表示 | 500ms 以下で表示完了する設計になっている                                              |
| ファイル読み込み       | 300ms 以下で読み込み完了する設計になっている                                          |
| ファイル保存           | 1s 以下で保存完了する設計になっている                                                 |
| 大量ファイル対応       | ノード数 200 以上の場合の対策（遅延読み込み/仮想スクロール）が設計されている          |
| 再レンダリング最適化   | React.memo, useMemo, useCallback が適切なコンポーネントで使用予定として記述されている |
| IPC 呼び出し頻度       | 不要な IPC 呼び出し（重複読み込み、保存連打）を防止する設計になっている               |

## レビューゲート判定

### 判定基準

| 判定  | 条件                                                                                 | 対応                                     |
| ----- | ------------------------------------------------------------------------------------ | ---------------------------------------- |
| PASS  | タスク 1-5 の全確認項目が基準を満たしている                                          | Phase 4 へ進行                           |
| MINOR | 機能に影響しない軽微な指摘（命名改善、コメント追加、スペーシング微調整）のみ         | 指摘を記録し、Phase 4 で対応しながら進行 |
| MAJOR | 要件カバレッジ漏れ、セキュリティ脆弱性、アクセシビリティ未対応のいずれかが検出された | 戻り先を判定し、修正後に再レビュー       |

### 戻り先決定基準

| 問題の種類                           | 戻り先  | 理由                             |
| ------------------------------------ | ------- | -------------------------------- |
| FR/NFR の漏れ・矛盾                  | Phase 1 | 要件定義の修正が必要             |
| スコープ逸脱                         | Phase 1 | スコープ定義の再検討が必要       |
| コンポーネント設計の構造的問題       | Phase 2 | 設計の修正が必要                 |
| 状態管理設計の不備（状態遷移の漏れ） | Phase 2 | 状態管理の再設計が必要           |
| IPC 連携設計のセキュリティ問題       | Phase 2 | IPC 設計の修正が必要             |
| ARIA 属性の構造的な問題              | Phase 2 | アクセシビリティ設計の修正が必要 |
