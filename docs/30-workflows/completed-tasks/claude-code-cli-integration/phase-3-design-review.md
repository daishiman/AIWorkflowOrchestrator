# Phase 3: 設計レビューゲート

## メタ情報

| 項目   | 値                          |
| ------ | --------------------------- |
| Phase  | 3                           |
| 機能名 | claude-code-cli-integration |
| 作成日 | 2026-01-16                  |

## 目的

実装開始前に要件・設計の妥当性を検証し、問題点を洗い出す。

## 判定基準

| 判定  | 条件             | 対応                         |
| ----- | ---------------- | ---------------------------- |
| PASS  | 全観点で問題なし | Phase 4へ進行                |
| MINOR | 軽微な指摘あり   | 指摘対応後Phase 4へ進行      |
| MAJOR | 重大な問題あり   | 影響範囲に応じて戻り先を決定 |

### MAJORの戻り先判定

| 問題の種類         | 戻り先  |
| ------------------ | ------- |
| 要件の不備・矛盾   | Phase 1 |
| 設計の根本的問題   | Phase 2 |
| 要件と設計の不整合 | Phase 1 |

## レビュー観点

### 1. 要件整合性

| チェック項目             | 確認内容                                   |
| ------------------------ | ------------------------------------------ |
| 機能要件の網羅性         | 元タスク指示書の要件が全て反映されているか |
| 非機能要件の具体性       | パフォーマンス・セキュリティ要件が定量的か |
| 受け入れ基準の検証可能性 | 全ACがテスト可能な形式か                   |
| スコープの明確性         | 含む/含まないが明確か                      |

### 2. アーキテクチャ妥当性

| チェック項目       | 確認内容                                  |
| ------------------ | ----------------------------------------- |
| 既存設計との整合性 | Agent SDK統合との共存が可能か             |
| 責務分離           | Main/Renderer/共有の責務が明確か          |
| 拡張性             | 将来の機能追加に対応可能か                |
| セキュリティ設計   | IPC通信のセキュリティ要件を満たしているか |

### 3. IPC API設計

| チェック項目       | 確認内容                            |
| ------------------ | ----------------------------------- |
| チャンネル命名規則 | 既存パターンと一貫しているか        |
| 型安全性           | 全APIに型定義があるか               |
| エラーハンドリング | エラーケースが網羅されているか      |
| バリデーション     | Zodスキーマが適切に設計されているか |

### 4. プロセス管理設計

| チェック項目           | 確認内容                                 |
| ---------------------- | ---------------------------------------- |
| プロセスライフサイクル | spawn/monitor/kill の設計が明確か        |
| リソース管理           | メモリリーク・ゾンビプロセス対策があるか |
| タイムアウト処理       | タイムアウト時の挙動が定義されているか   |
| 並列実行               | 複数セッションの管理が設計されているか   |

### 5. セキュリティ設計

| チェック項目             | 確認内容                                 |
| ------------------------ | ---------------------------------------- |
| 入力バリデーション       | スキルパス・引数の検証が設計されているか |
| パストラバーサル対策     | 不正なパス指定への対策があるか           |
| サンドボックス           | CLI実行の権限制限が考慮されているか      |
| チャンネルホワイトリスト | 許可されたチャンネルのみ公開されているか |

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点       | 確認項目                             |
| ------------------ | ------------------------------------ |
| IPC API設計        | チャンネル定義の妥当性、型安全性     |
| プロセス管理設計   | spawn/kill/監視のエラーハンドリング  |
| ストリーミング設計 | stdout/stderrキャプチャの設計        |
| セッション管理設計 | 並列セッションの管理・クリーンアップ |
