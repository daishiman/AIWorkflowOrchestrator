### 2. アーキテクチャ妥当性レビュー

#### 2.1 既存設計との整合性

| 観点            | 既存Agent SDK              | CLI統合設計      | 整合性 |
| --------------- | -------------------------- | ---------------- | ------ |
| IPC通信パターン | invoke/handle, on/send     | 同一パターン採用 | ✅     |
| チャンネル命名  | `agent:xxx`                | `claude-cli:xxx` | ✅     |
| Result型        | `Result<T>`                | 同一パターン採用 | ✅     |
| セキュリティ    | sender検証、ホワイトリスト | 同一パターン採用 | ✅     |
| preload公開     | contextBridge              | 同一パターン採用 | ✅     |

**結果**: 既存Agent SDK設計と完全に整合している。

#### 2.2 責務分離

| レイヤー    | 責務                         | 設計上の分離                   |
| ----------- | ---------------------------- | ------------------------------ |
| React UI    | UI表示・ユーザー操作         | Zustand storeで状態管理        |
| preload     | API公開・IPC通信             | claudeCliAPI経由               |
| IPC Handler | リクエスト処理・セキュリティ | ClaudeCliIpcHandler            |
| Service     | ビジネスロジック             | ClaudeCliManager (Facade)      |
| Domain      | ドメインロジック             | SessionManager, ProcessManager |

**結果**: Main/Renderer/共有の責務が明確に分離されている。

#### 2.3 拡張性

- Skill実行方式: スクリプト種類（.mjs, .py, .sh, .ts）の追加が容易
- フィルタリング: FilterCriteriaの拡張が可能
- セッション管理: LRU以外のエビクションポリシーへの変更が可能
- IPC: 新チャンネル追加がホワイトリストへの追加のみで可能

**結果**: 将来の機能追加に対応可能な設計。

#### 2.4 セキュリティ設計

| 要件                         | 設計での対応                                |
| ---------------------------- | ------------------------------------------- |
| IPC通信セキュリティ          | CLAUDE_CLI_CHANNELS定数によるホワイトリスト |
| sender検証                   | validateIpcSender()でDevTools拒否           |
| パストラバーサル防止         | validatePath()で../検出                     |
| コマンドインジェクション防止 | shell: false でspawn                        |

**結果**: IPC通信のセキュリティ要件を満たしている。

### 3. IPC API設計レビュー

#### 3.1 チャンネル命名規則

| パターン             | 既存例           | CLI統合                     | 一貫性 |
| -------------------- | ---------------- | --------------------------- | ------ |
| 操作チャンネル       | `agent:execute`  | `claude-cli:execute-script` | ✅     |
| 取得チャンネル       | `agent:get-xxx`  | `claude-cli:get-xxx`        | ✅     |
| 一覧チャンネル       | `agent:list-xxx` | `claude-cli:list-xxx`       | ✅     |
| ストリームチャンネル | -                | `claude-cli:output-stream`  | ✅     |

**結果**: 既存パターンと一貫した命名規則。

#### 3.2 型安全性

- 全リクエスト型: ListSkillsRequest, ExecuteScriptRequest, etc.
- 全レスポンス型: ScanResult, ExecuteScriptResponse, etc.
- Result<T>型で統一されたエラーハンドリング
- Zodスキーマによるランタイムバリデーション

**結果**: 全APIに型定義がある。

#### 3.3 エラーハンドリング

| エラーケース      | エラーコード            | 設計での対応        |
| ----------------- | ----------------------- | ------------------- |
| CLI未インストール | CLI_NOT_INSTALLED       | CliDetector         |
| スキル未発見      | SKILL_NOT_FOUND         | SkillScanner        |
| セッション上限    | SESSION_LIMIT_EXCEEDED  | SessionManager      |
| パストラバーサル  | PATH_TRAVERSAL_DETECTED | validatePath()      |
| 不正sender        | IPC_SENDER_INVALID      | validateIpcSender() |

**結果**: エラーケースが網羅されている。

#### 3.4 バリデーション

- skillNameSchema: kebab-case、最大64文字
- sessionIdSchema: UUID形式
- timeoutMsSchema: 1秒〜30分の範囲
- safePathSchema: パストラバーサル防止

**結果**: Zodスキーマが適切に設計されている。

---

### 4. プロセス管理設計レビュー

#### 4.1 プロセスライフサイクル

| フェーズ | 実装                   | 設計上の対応                |
| -------- | ---------------------- | --------------------------- |
| spawn    | ProcessManager.spawn() | shell: false, stdio: pipe   |
| monitor  | runningProcesses Map   | プロセスID追跡              |
| kill     | ProcessManager.kill()  | SIGTERM → timeout → SIGKILL |

**結果**: spawn/monitor/killの設計が明確。

#### 4.2 リソース管理

| リスク         | 対策                                   |
| -------------- | -------------------------------------- |
| メモリリーク   | セッション完了時にプロセス参照をnullに |
| ゾンビプロセス | on("exit")でrunningProcessesから削除   |
| 孤児プロセス   | app.on("will-quit")で全プロセス終了    |

**結果**: メモリリーク・ゾンビプロセス対策がある。

#### 4.3 タイムアウト処理

- デフォルトタイムアウト: 30分
- タイムアウト時: setTimeout → kill()
- 設定可能: ExecuteScriptRequest.timeoutMs

**結果**: タイムアウト時の挙動が定義されている。

#### 4.4 並列実行

- 最大同時セッション: 10
- LRUエビクション: 古い完了セッションを削除
- セッション状態: pending, running, completed, failed, terminated

**結果**: 複数セッションの管理が設計されている。

### 5. セキュリティ設計レビュー

#### 5.1 入力バリデーション

| 入力       | バリデーション                       |
| ---------- | ------------------------------------ |
| skillName  | skillNameSchema (kebab-case, max 64) |
| scriptName | safePathSchema + 拡張子チェック      |
| args       | string[]型チェック                   |
| sessionId  | sessionIdSchema (UUID)               |

**結果**: スキルパス・引数の検証が設計されている。

#### 5.2 パストラバーサル対策

- `../`パターン検出
- URLエンコード攻撃検出 (`%2e%2e`)
- Nullバイト検出 (`\0`)
- path.normalize() + basePathチェック

**結果**: 不正なパス指定への対策がある。

#### 5.3 サンドボックス

- shell: false でスポーン（シェルインジェクション防止）
- 作業ディレクトリ制限（skillsBasePath内）
- スクリプト種類制限（.mjs, .js, .py, .sh, .ts のみ）

**結果**: CLI実行の権限制限が考慮されている。

#### 5.4 チャンネルホワイトリスト

- CLAUDE_CLI_CHANNELS定数で定義
- isValidChannel()で検証
- 定義外チャンネルは拒否

**結果**: 許可されたチャンネルのみ公開されている。
