## MINOR指摘

### m-01: stdin入力サポートの欠如

| 項目      | 内容                                                             |
| --------- | ---------------------------------------------------------------- |
| ID        | m-01                                                             |
| 観点      | プロセス管理設計                                                 |
| 重大度    | MINOR                                                            |
| 指摘内容  | 現在の設計ではstdin入力のサポートが含まれていない                |
| 影響範囲  | インタラクティブなスキルスクリプトが実行できない                 |
| 対応方針  | 将来の拡張として検討。現時点ではスコープ外（バッチ実行のみ対応） |
| 対応Phase | 将来課題                                                         |

**詳細**:

- ProcessManager.spawn()は`stdio: ['pipe', 'pipe', 'pipe']`で設定されているが、stdin経由の入力送信APIが設計されていない
- 現在のスコープでは、スクリプトはコマンドライン引数のみで動作する想定
- 将来的にインタラクティブ実行が必要な場合は、`writeToStdin(sessionId, data)`のようなAPIの追加を検討

**現時点での対応**:

- 対応不要（スコープ外）
- 将来の機能拡張として記録

### m-02: ネットワークエラー時のリトライ機構

| 項目      | 内容                                                     |
| --------- | -------------------------------------------------------- |
| ID        | m-02                                                     |
| 観点      | エラーハンドリング                                       |
| 重大度    | MINOR                                                    |
| 指摘内容  | ネットワークエラー発生時のリトライ機構が設計されていない |
| 影響範囲  | 一時的なネットワーク障害でCLI実行が失敗する可能性        |
| 対応方針  | CLI側の責務として扱う。Electron側でのリトライは行わない  |
| 対応Phase | 将来課題                                                 |

**詳細**:

- Claude Code CLIがAnthropic APIとの通信でエラーが発生した場合、Electron側でのリトライ機構がない
- CLIプロセスのstderrでエラーをキャプチャし、UI側で「再実行」ボタンを提供する設計
- CLI自体にリトライロジックが組み込まれている可能性があるため、二重リトライを避ける

**現時点での対応**:

- 対応不要（CLI側の責務）
- エラー発生時はUI側で「再実行」ボタンを表示する設計で対応可能
