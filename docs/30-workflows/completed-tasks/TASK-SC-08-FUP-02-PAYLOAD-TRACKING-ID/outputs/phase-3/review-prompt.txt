====================================================================
【task 概要】
====================================================================

- task id: TASK-SC-08-FUP-02-PAYLOAD-TRACKING-ID
- 目的: Electron IPC チャンネル skill-creator:progress の payload に
  planId / requestId を追加し、並行 executePlan 実行時の UI 混線を防ぐ
- 対象ファイル 4 件:
  1) apps/desktop/src/preload/skill-creator-api.ts
     （SkillCreatorProgress に planId? / requestId? を追加）
  2) apps/desktop/src/main/ipc/skillCreatorHandlers.ts
     （sendSkillCreatorProgress の progress 引数型に planId? / requestId? を追加）
  3) apps/desktop/src/main/services/runtime/RuntimeSkillCreatorFacade.ts
     （executeAsync の progress emit 経路に planId を貫通）
  4) apps/desktop/src/renderer/hooks/useStreamingProgress.ts
     （options?: { planId?: string } 引数を追加し callback 先頭で filter 分岐）

- task type: NON_VISUAL code task
- 後方互換ポリシー: planId / requestId / options.planId すべてオプショナル
- フィルタ条件: options.planId !== undefined
               && progress.planId !== undefined
               && progress.planId !== options.planId
               の 3 条件 AND のときのみスキップ
- 棄却案: skill-creator:progress:{planId} の動的 channel 多重化
  （Electron IPC ホワイトリスト機構と両立しないため棄却）

====================================================================
【AC（受入基準）】
====================================================================

AC-1: SkillCreatorProgress 型に planId?: string / requestId?: string 追加
AC-2: sendSkillCreatorProgress が planId / requestId を payload に含めて送信
AC-3: useStreamingProgress に options.planId フィルタリングロジック実装
AC-4: planId 一致時のみ Zustand ストアに書き込まれる
AC-5: planId 不一致の progress はスキップ
AC-6: progress.planId 未設定時は後方互換で受け入れ
AC-7: options.planId 未指定時は全通知受け入れ
AC-8: 既存 useStreamingProgress テストが全 PASS
AC-9: pnpm --filter @repo/desktop typecheck / lint / targeted test PASS
