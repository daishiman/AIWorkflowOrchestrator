## 目的

SettingsView 統合テストの実行結果を確認し、テストコード追加が既存テストや設定画面の動作に影響を与えていないことを検証する。

## 前提条件

- 本タスクはテストコード追加のみであり、UI 自体の変更は含まない
- 手動テストはテストコードの実行結果確認が中心となる
- 設定画面の表示確認は既存 UI が正常に動作していることの回帰確認として実施する

---

## テスト項目

### テスト 1: テストスイート実行確認

| 項目     | 内容                                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 目的     | 新規追加した統合テストが全件 GREEN であることを確認する                                                                                        |
| 実行手順 | 1. `cd apps/desktop` を実行する<br>2. `pnpm vitest run src/renderer/views/SettingsView/__tests__/SettingsView.integration.test.tsx` を実行する |
| 期待結果 | 全テストケース（INT-01 から INT-05 およびサブケース）が PASS する                                                                              |
| 判定基準 | テストスイート: 1 passed、テストケース: 9 passed                                                                                               |

### テスト 2: 既存テストとの共存確認

| 項目     | 内容                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 目的     | 統合テスト追加が既存の SettingsView 単体テストに影響を与えていないことを確認する                                                   |
| 実行手順 | 1. `cd apps/desktop` を実行する<br>2. `pnpm vitest run src/renderer/views/SettingsView/__tests__/SettingsView.test.tsx` を実行する |
| 期待結果 | 既存の 26 テストが全件 PASS する                                                                                                   |
| 判定基準 | テスト結果に FAIL が 0 件であること                                                                                                |

### テスト 3: 設定画面表示確認（AC-04）

| 項目     | 内容                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目的     | SettingsView を実際に表示し、全セクションが正常にレンダリングされることを確認する                                                                                                                       |
| 実行手順 | 1. 開発サーバーを起動する（`pnpm --filter @repo/desktop dev`）<br>2. SettingsView を開く<br>3. 以下の全セクションが表示されることを目視確認する                                                         |
| 確認対象 | - アカウントセクション（AccountSection）<br>- 認証方式セクション（AuthModeSelector）<br>- API キーセクション（ApiKeysSection）<br>- テーマセクション（ThemeSelector）<br>- RAG セクション（RAGSection） |
| 注意事項 | 本タスクはテストコード追加のみのため、UI 自体は既存のまま変更されていない。本テストは回帰確認として実施する                                                                                             |

### テスト 4: テストカバレッジ確認

| 項目     | 内容                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目的     | 統合テスト追加によるカバレッジ向上を定量的に確認する                                                                                              |
| 実行手順 | 1. `cd apps/desktop` を実行する<br>2. `pnpm vitest run --coverage src/renderer/views/SettingsView/` を実行する<br>3. カバレッジレポートを確認する |
| 期待結果 | 統合テスト追加前と比較してカバレッジが向上または維持されていること                                                                                |
| 判定基準 | Line Coverage、Branch Coverage、Function Coverage のいずれも低下していないこと                                                                    |

---

## AC-04 準拠要件

### 必須ステップ

- 手動テスト手順に「SettingsView を表示する」ステップが含まれていること（テスト 3 で対応）
- 証跡の必須項目に「設定画面全体の表示」が含まれていること

### 証跡の制約

- **設定画面を経由せず個別コンポーネントのみで検証した証跡は不可**
- SettingsView（設定画面シェル）を起点とした検証であることが証跡から判別できること
