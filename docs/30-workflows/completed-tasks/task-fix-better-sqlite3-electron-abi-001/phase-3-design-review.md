## 目的

## レビュー観点

### 正確性チェック

- [x] 修正箇所の特定は正確か
  - `apps/desktop/package.json` の `scripts` セクションへの `postinstall` 追加のみ。変更ファイルは1件、変更量は1行。正確。
- [x] 修正内容は問題を解決するか
  - `pnpm install` 後に `postinstall: pnpm rebuild:native` が自動実行され、native addon の再構築が「取り忘れ」にならない。これにより、`better-sqlite3` の ABI/arch ミスマッチ起因の `dlopen` エラーを再発しにくくする。
  - 既存の `rebuild:native` スクリプト（`pnpm rebuild better-sqlite3 && (pnpm rebuild esbuild || true)`）は再現可能な修復コマンドとして有効であり、`postinstall` から呼び出すことで自動化を実現する。
- [x] 副作用・回帰リスクはないか
  - `postinstall` の追加は `pnpm install` の実行時間を数十秒増加させるが、機能的な回帰リスクはない。
  - rebuild は冪等（何度実行しても同じ結果になる）であるため、意図しない副作用は発生しない。
  - リスク評価: LOW

### 整合性チェック

- [x] 既存コードとの整合性
  - `rebuild:native` スクリプトが既に定義済みであり、`postinstall` はそれを呼び出す形。既存の手動実行フローとの一貫性が保たれる。
  - `apps/desktop/package.json` の他のスクリプトと命名・書式が統一されている。
- [x] 型安全性の維持
  - `package.json` の変更は TypeScript の型に影響しない。
- [x] テスト戦略の妥当性
  - ABI バージョン確認テスト + 手動 E2E テストの組み合わせで充分な検証が可能。

### 実装容易性チェック

- [x] 変更量が最小か
  - `package.json` の `scripts` に1行追加するのみ。変更量は最小。
- [x] 実装手順が明確か
  - Phase 2 のコードスニペットがそのまま実装に使える。
  - `rebuild:native` の直後に `postinstall` を追加する配置も明確に指定されている。

### ビルドツールチェーン依存性の確認

- [x] macOS（Xcode Command Line Tools）環境での rebuild 動作
  - `pnpm rebuild better-sqlite3` は `node-gyp` を介して C++ をコンパイルするため、Xcode Command Line Tools が必要。CI 環境（macOS runner）では標準で利用可能。
- [x] 初回クローン時のビルドツールチェーン不在リスク
  - ビルドツールチェーンが未インストールの場合、`postinstall` は失敗する。この場合、明確なエラーメッセージ（`gyp` not found等）が表示され、開発者は必要なツールをインストールできる。サイレントな失敗ではないため許容範囲。

### リスク分析

| リスク                             | 発生条件                                | 確率 | 対策                                                                            |
| ---------------------------------- | --------------------------------------- | ---- | ------------------------------------------------------------------------------- |
| ビルドツールチェーン未インストール | 新規開発者環境、最小 CI イメージ        | 中   | エラーメッセージが明確なため対処可能、README に要件を記載                       |
| Electron 側のみでの不一致が残る    | Node 側は OK だが Electron 起動で失敗   | 中   | Phase 11 で検知し、必要なら Electron 向け rebuild を follow-up として未タスク化 |
| pnpm add 時の不要な rebuild        | `pnpm --filter @repo/desktop add <pkg>` | 低   | 冪等であるため問題なし（時間コストのみ）                                        |
| CI でのネットワーク制限            | ネイティブ rebuild が失敗               | 低   | キャッシュ/リトライ、または build toolchain を事前導入                          |

### 実装時の注意事項

1. `"postinstall": "pnpm rebuild:native"` を `rebuild:native` の直後の行に追加すること（関連スクリプトのグループ化）
2. JSON のカンマ区切りを忘れないこと（前の行末にカンマ追加が必要な場合がある）
3. 実装後は Phase 11 の手動テストで Electron 起動ログ/IPC 応答を確認し、AC-1/AC-2 を満たすことを証跡化すること
