実装に進める。後方互換性を維持しつつ dynamic resource pipeline をデフォルト有効化できる設計を確認。

## 後方互換性検証

| 確認項目                                         | 結果 | 根拠                                                                                                 |
| ------------------------------------------------ | ---- | ---------------------------------------------------------------------------------------------------- |
| 既存 static loader パスが破壊されないか          | PASS | fallback chain の優先度2: dynamic pipeline でリソース0件 + resourceLoader あり → static loader       |
| ipc/index.ts の既存 wiring が動作し続けるか      | PASS | ipc/index.ts は既に3コンポーネントを注入しているため、DI override により自動インスタンスは使われない |
| 外部注入コンポーネントが自動インスタンスより優先 | PASS | `deps.sourceResolver ?? new SkillCreatorSourceResolver()` パターンで外部注入が優先される             |

## degradation path レビュー

| manifest 未発見時の fallback が static loader に正しく遷移      | PASS | `resolveOperationResources()` でリソース0件 → static loader fallback の設計が確立                 |
