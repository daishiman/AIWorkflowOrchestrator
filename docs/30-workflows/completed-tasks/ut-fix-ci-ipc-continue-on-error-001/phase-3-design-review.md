## 目的

Phase 2で策定した設計（`continue-on-error: true` の1行削除）の妥当性を多角的にレビューし、Phase 4（テスト作成）および実装への進行可否を判定する。

## 背景

本タスクは `.github/workflows/ci.yml` への最小変更（1行削除）であるが、変更後にCI全体がブロッキング挙動に切り替わるため、設計の妥当性・安全性・リスクを事前に確認することが重要である。

---

**目的**: Phase 2の設計が要件を正しく満たしているかをレビューする。

**実行手順**:

1. 以下のレビュー観点ごとに確認し、各観点に問題がないかを評価する

**レビュー観点一覧**:

#### 観点A: 変更の最小性

| チェック項目   | 期待値                    | 確認方法                            |
| -------------- | ------------------------- | ----------------------------------- |
| 変更ファイル数 | 1ファイル（`ci.yml`）のみ | Phase 2 タスク1を参照               |
| 変更行数       | -1行（削除のみ）          | Phase 2 タスク4 Before/After を参照 |
| 追加ステップ   | なし                      | Phase 2 タスク2の結論を参照         |
| `needs` の変更 | なし                      | Phase 2 タスク3の結論を参照         |

#### 観点B: CI安定性

| チェック項目         | 期待値                             | 確認方法                                              |
| -------------------- | ---------------------------------- | ----------------------------------------------------- |
| スクリプトの外部依存 | 標準モジュールのみ（`fs`, `path`） | `scripts/verify-ipc-4layer.cjs` の `require` 文を確認 |

| タイムアウト設定     | 5分（適切）                        | スクリプトの処理量（ファイル走査のみ）を考慮          |

#### 観点C: IPC Guard の有効性

| チェック項目           | 期待値                                         | 確認方法                                           |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------- |
| 違反時のCIブロッキング | `verify-ipc-4layer` FAIL → `build` ジョブ SKIP | ci.yml の `build.needs` を確認（442〜453行）       |

| チェック項目                  | 期待値                                               | 確認方法                                                      |

| 削除対象の特定                | ジョブレベルの `continue-on-error: true`（297行目）  | `grep -n "continue-on-error" .github/workflows/ci.yml` で確認 |

## レビューゲート判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じてPhase 2へ |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 判定基準の詳細

#### PASS の条件

以下を全て満たす場合:

- 観点A（変更の最小性）: 変更が1行削除のみであること
- 観点B（CI安定性）: スクリプトが標準モジュールのみ使用し、ソースファイルへのアクセスに外部依存がないこと
- 観点C（IPC Guard有効性）: `build` ジョブが `verify-ipc-4layer` に依存しており、違反時にブロックが機能すること
- 観点D（誤削除リスク）: `security` ジョブへの影響がないことを設計上で明示済みであること
- リスク評価: R-01〜R-05 が「低」または「低〜中」であること

#### MINOR の条件

以下のいずれかに該当するが、Phase 4での対処が可能:

- 設計書の記述に不明瞭な箇所がある（内容は正しい）
- Before/After スニペットに軽微な書式上の問題がある

#### MAJOR の条件

以下のいずれかに該当する:

- `security` ジョブの `continue-on-error` との区別が設計上で不明確
- CI環境での動作検証方法が設計に含まれていない
- `build` ジョブとの依存関係の確認が不十分

#### CRITICAL の条件

以下のいずれかに該当する:

- ローカルで `node scripts/verify-ipc-4layer.cjs` が FAIL する（Phase 1タスク1）
- 変更後にCI全体に予期しない影響が及ぶ設計上の欠陥が発見された
- IPC違反が多数存在し、削除後に即座に全PRがブロックされる状況
