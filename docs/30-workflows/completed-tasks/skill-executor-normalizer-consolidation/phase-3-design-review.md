## 目的

Phase 2 の設計が要件を満たし、実装可能な品質であるかをレビューする。PASS/MINOR/MAJOR の判定を行い、Phase 4 への進行可否を決定する。

## 実行タスク

- タスク1: 設計整合性チェック
- タスク2: simpler alternative の検討
- タスク3: ゲート判定

- タスク1で AC・型互換・import パスの整合を確認する
- タスク2で simpler alternative を比較し、採否理由を固定する
- タスク3で PASS/MINOR/MAJOR を判定し、戻り先を確定する

### タスク1: 設計整合性チェック

**目的**: 設計が Phase 1 要件と整合しているかを検証する

**チェック項目**:

| チェック項目         | 確認内容                                                            | 判定  |
| -------------------- | ------------------------------------------------------------------- | ----- |
| AC-1 整合            | `unknown -> record` / `type` 抽出が1箇所に集約される設計か          | ✅/❌ |
| AC-2 整合            | sdkMessageNormalizer のテストが影響を受ける変更が最小か             | ✅/❌ |
| AC-3 整合            | SkillExecutor のテストが影響を受ける変更が最小か                    | ✅/❌ |
| 責務境界             | lane 固有の出力変換を shared helper に持ち込んでいないか            | ✅/❌ |
| import パス          | 新規 import パスが既存プロジェクト構造と整合するか                  | ✅/❌ |
| 4条件: 価値性        | 将来の SDK 変更点を1箇所へ寄せる価値が明確か                        | ✅/❌ |
| 4条件: 実現性        | 変更対象が 3 ファイル + 1 テストに収まり、過剰設計になっていないか  | ✅/❌ |
| 4条件: 整合性/運用性 | task spec / tests / Phase 12 close-out まで矛盾なく追跡できる設計か | ✅/❌ |

### タスク2: simpler alternative の検討

**目的**: より単純な代替案がないかを検討し、結果を記録する

**検討する代替案**:

| 代替案                                                | メリット                 | デメリット                                         | 採否    |
| ----------------------------------------------------- | ------------------------ | -------------------------------------------------- | ------- |
| A: 最小 helper を `sdkMessageUtils.ts` に切り出し     | 重複だけ解消、テスト容易 | 新規ファイル追加                                   | ✅ 採用 |
| B: normalizer 全体を共通抽象へ引き上げる              | 見た目上は統一される     | 出力契約差を隠蔽し、過剰抽象になる                 | ❌      |
| C: `sdkMessageNormalizer.ts` に helper を寄せて再利用 | ファイル増加なし         | skill-creator lane 依存が SkillExecutor に逆流する | ❌      |
| D: 統合見送り（現状維持 + コメント記録）              | 変更リスクゼロ           | 重複が残り、次回 SDK 変更点が分散する              | ❌      |

### タスク3: ゲート判定

**判定基準**:

| 判定              | 条件                                    | 戻り先                    |
| ----------------- | --------------------------------------- | ------------------------- |
| PASS              | 設計に問題なし                          | Phase 4                   |
| MINOR             | 軽微な修正で解決                        | Phase 4（修正事項を記録） |
| MAJOR（要件問題） | AC との不整合                           | Phase 1                   |
| MAJOR（設計問題） | topology やインターフェースに根本的問題 | Phase 2                   |

**MINOR 追跡テーブル**（MINOR 判定時のみ使用）:

| MINOR ID | 指摘内容 | 解決予定Phase | 解決確認Phase | 備考 |
| -------- | -------- | ------------- | ------------- | ---- |
| -        | -        | -             | -             | -    |
