## プロダクションコード修正の判断

### 判断結果: プロダクションコードの修正は不要

本タスクで発見された 252 件の失敗テストは、全て以下のいずれかに起因する:

1. **vitest.config.ts のエイリアス設定不足**（C-1, ~220 テスト）: テスト実行時のモジュール解決の問題であり、プロダクションコードに問題はない
2. **テストの非同期クリーンアップ不備**（C-2, ~30 テスト）: テストコード内の teardown 処理の不備であり、プロダクションコードに問題はない
3. **Vitest Worker の終了**（C-3, ~2 テスト）: テスト実行環境の既知問題であり、コード修正は不要

### 判断根拠

| 判断基準                                                         | 評価結果                                                         |
| ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| テスト内の設定・コード不備が原因か                               | はい: C-1 はエイリアス設定不足、C-2 はテスト teardown 不備       |
| プロダクションコードに fire-and-forget パターンがあるか          | 該当なし: 失敗の原因はプロダクションコードの非同期処理ではない   |
| プロダクションコードの `try/catch` 欠落があるか                  | 該当なし: 失敗はモジュール解決エラーとテストクリーンアップに起因 |
| プロダクションコードに明確なバグ（本番クラッシュリスク）があるか | 該当なし: 本番環境では vitest.config.ts の設定は使用されない     |

## 設定ファイル修正の影響分析

### vitest.config.ts の変更

#### 変更 1: resolve.alias へのサブパス追加

| 項目         | 内容                                                               |
| ------------ | ------------------------------------------------------------------ |
| 変更ファイル | `apps/desktop/vitest.config.ts`                                    |
| 変更内容     | `resolve.alias` に 5 つのサブパスエイリアスを追加                  |
| 影響範囲     | テスト実行時のモジュール解決のみ。プロダクションビルドには影響なし |
| リスク       | 低: 新規エイリアス追加であり、既存エイリアスの解決順序に影響しない |
| 検証方法     | 追加したエイリアスを参照するテストファイルの実行で PASS を確認     |

**既存エイリアスとの競合リスク評価**:

追加するサブパスは全て `@repo/shared` 配下のサブディレクトリを指す。`@repo/shared` 自体のエイリアスが既に登録されている場合、より具体的なサブパスエイリアスが優先される。Vitest の alias 解決は最長一致を使用するため、既存エイリアスへの影響はない。

#### 変更 2: dangerouslyIgnoreUnhandledErrors 設定行の削除

| 項目         | 内容                                                                         |
| ------------ | ---------------------------------------------------------------------------- |
| 変更ファイル | `apps/desktop/vitest.config.ts`                                              |
| 変更内容     | `dangerouslyIgnoreUnhandledErrors: true` の行を削除                          |
| 影響範囲     | テスト実行時の未処理 Promise 拒否検出が有効になる                            |
| リスク       | 中: 将来的に新規テストで未処理拒否が発生した場合、テスト失敗として検出される |
| 検証方法     | 全テスト実行で PASS を確認                                                   |
