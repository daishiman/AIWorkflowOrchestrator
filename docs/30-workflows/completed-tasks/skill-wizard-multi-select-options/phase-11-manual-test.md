### ステップ 2: 手動テストシナリオ

#### シナリオ 1: 単一選択から複数選択への動作確認

**目的**: 複数のボタンを独立してトグル選択できることを確認する。

| ステップ | 操作                                          | 期待結果                                                           |
| -------- | --------------------------------------------- | ------------------------------------------------------------------ |
| 1        | スキルウィザードを起動し Step 1 を表示する    | Q1〜Q6 が表示される                                                |
| 2        | Q1 の選択肢「自分のみ」をクリックする         | 「自分のみ」がアクティブスタイル（背景色が変化）になる             |
| 3        | Q1 の選択肢「チームメンバー」をクリックする   | 「チームメンバー」もアクティブスタイルになり、両方が選択状態になる |
| 4        | Q1 のすべての選択肢をクリックする             | 全選択肢がアクティブスタイルになる                                 |
| 5        | Q2〜Q6 でも同様に複数選択できることを確認する | 各設問で複数ボタンが同時にアクティブスタイルになる                 |

**確認ポイント**:

- [ ] 複数ボタンが同時にアクティブスタイルで表示される
- [ ] 「選択済み」バッジが 1 つ以上選択時に表示される
- [ ] 選択した個数・組み合わせに制限がない

---

#### シナリオ 2: 選択解除のトグル動作確認

**目的**: 選択済みボタンをクリックすると選択が解除されることを確認する。

| ステップ | 操作                                            | 期待結果                                                                 |
| -------- | ----------------------------------------------- | ------------------------------------------------------------------------ |
| 1        | Q1 で「自分のみ」と「チームメンバー」を選択する | 両方がアクティブスタイルになる                                           |
| 2        | 「自分のみ」を再クリックする                    | 「自分のみ」のアクティブスタイルが解除される（「チームメンバー」は維持） |
| 3        | 「チームメンバー」を再クリックする              | 「チームメンバー」のアクティブスタイルも解除される                       |
| 4        | 全選択が解除された状態を確認する                | 「選択済み」バッジが非表示になる                                         |

**確認ポイント**:

- [ ] 選択済みボタンを再クリックすると選択状態が解除される
- [ ] 他の選択済みボタンへの影響がない（独立したトグル）
- [ ] 全解除後に「選択済み」バッジが消える

---

#### シナリオ 3: Q3「定期実行」と他の選択肢の組み合わせ

**目的**: Q3 の「定期実行」が複数選択時も正しく ScheduleConfigInput を展開・収納することを確認する。

| ステップ | 操作                                                         | 期待結果                                           |
| -------- | ------------------------------------------------------------ | -------------------------------------------------- |
| 1        | Q3 を表示する                                                | ScheduleConfigInput が非表示であること             |
| 2        | 「定期実行」をクリックする                                   | ScheduleConfigInput が展開される                   |
| 3        | 「手動実行」をクリックする（定期実行は選択中のまま）         | ScheduleConfigInput が展開されたまま維持される     |
| 4        | 「イベントトリガー」をクリックする（定期実行は選択中のまま） | ScheduleConfigInput が展開されたまま維持される     |
| 5        | 「定期実行」を再クリックして選択を解除する                   | ScheduleConfigInput が閉じる（他の選択肢は維持）   |
| 6        | 「定期実行」を再クリックして再選択する                       | ScheduleConfigInput が再度展開される               |
| 7        | cron 式・タイムゾーンを入力後、「定期実行」を解除する        | ScheduleConfigInput が閉じ、入力値がリセットされる |

**確認ポイント**:

- [ ] 「定期実行」選択時のみ ScheduleConfigInput が展開される
- [ ] 「定期実行」以外の選択肢の組み合わせでは ScheduleConfigInput が表示されない
- [ ] 「定期実行」を他の選択肢と同時選択してもアコーディオンが維持される
- [ ] 「定期実行」解除時に ScheduleConfigInput が即座に閉じる

---

#### シナリオ 4: ApplySummaryCard での未回答時 SmartDefault 表示

**目的**: SmartDefaults 適用後の未回答問でサマリー表示が正しく機能することを確認する。

| ステップ | 操作                                                                      | 期待結果                                                                                  |
| -------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1        | Q1〜Q6 の一部を意図的に回答しない状態でウィザードを進める                 | ApplySummaryCard が表示される                                                             |
| 2        | 未回答の設問に SmartDefault 値が表示されていることを確認する              | SmartDefault の推論値が単一文字列で表示される                                             |
| 3        | Q1 で「自分のみ」と「チームメンバー」を選択してウィザードを進める         | ApplySummaryCard で Q1 が「回答済み」として扱われ、デフォルト値が上書きされないことを確認 |
| 4        | 「スマートデフォルトを適用」ボタンをクリックする                          | 未回答の設問に SmartDefault 値が `selectedOptions` として設定される                       |
| 5        | SmartDefault 適用後、各設問の選択ボタンに値が反映されていることを確認する | 推論値が選択肢に含まれる場合はボタンがアクティブスタイルになる                            |

**確認ポイント**:

- [ ] 未回答判定が `selectedOptions.length === 0 && freeText === ""` で正しく機能している
- [ ] SmartDefault 適用後、該当するボタンがアクティブスタイルになる
- [ ] SmartDefault 推論値が選択肢にない場合は freeText 欄に表示される

---

#### シナリオ 5: スマートデフォルト値の適用確認

**目的**: `applySmartDefaults()` の `string → [string]` 変換が UI に正しく反映されることを確認する。

| ステップ | 操作                                                                | 期待結果                                                                                            |
| -------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 1        | Q1〜Q6 を全て未回答のままウィザードを進める                         | ApplySummaryCard に全設問の SmartDefault 値が表示される                                             |
| 2        | 「スマートデフォルトを適用」をクリックする                          | 全設問に SmartDefault が適用される                                                                  |
| 3        | Step 1（ConversationRoundStep）に戻る                               | SmartDefault が選択肢に含まれる設問でボタンがアクティブになっている                                 |
| 4        | SmartDefault が選択肢に含まれない場合のテキスト入力欄を確認する     | freeText 欄に SmartDefault 値が表示されている                                                       |
| 5        | Q5（ツール選択）で「Slack」と「GitHub」を選択後にウィザードを進める | `resolveExternalIntegration` が先頭値（最初に選択した方）を参照していることを開発者ツールで確認する |

**確認ポイント**:

- [ ] SmartDefault 適用時にボタン選択状態が正しく更新される
- [ ] `freeText` に入るべき値が正しく入力欄に表示される
- [ ] Q5 複数選択時に先頭選択値が主ツールとして機能する
