## 教訓記録推奨

### L-MSO-001: SmartDefaultResult 不変設計パターン

**内容**: `SmartDefaultResult`（`string | null` × 6）を変更せず、UI 層の `createQuestionAnswer()` で `string → [string]` 変換を吸収する設計は、バックエンド・LLM プロンプト変更を不要にする有効なパターン。

**推奨**: `lessons-learned-current.md` への記録。類似の「外部インターフェースを保ちつつ UI 型を拡張する」タスクで参照価値がある。

### L-MSO-002: テスト環境の分離確認

**内容**: `pnpm --filter @repo/desktop test:run` の失敗原因はテストコードではなく、`esbuild` の host/binary バージョン不整合だった。`Host version "0.21.5" does not match binary version "0.25.12"` という依存関係ドリフトは、テスト失敗の見かけ上の症状を誤読しやすい。

**推奨**: Phase 4 テンプレートに「テスト失敗時はまず依存関係整合を確認する」チェックを追加し、`esbuild` / Vite 系のバイナリ不整合を先に除外する。

### L-MSO-003: フォールバック設計の早期明文化

**内容**: `handleCronChange` / `handleTimezoneChange` のフォールバック（SmartDefaults 経由で `selectedOptions` に「定期実行」がない場合の自動追加）は、設計段階（Phase 2）では明示されていなかったが、実装時に必要と判明した。

**推奨**: Q3 のような「特定選択肢が他の動作をトリガーする」パターンでは、SmartDefaults 経由の初期化パスを Phase 2 設計に含める。

### L-MSO-004: スクリーンショット取得ハーネスの後始末

**内容**: 画面証跡取得スクリプトは、ブラウザと開発サーバーの終了処理を明示的に扱わないと、ポート占有やハングが発生しやすい。今回も終了処理の調整とポート解放確認が必要だった。

**推奨**: 画面証跡系の自動化スクリプトには、終了待ちのタイムアウト、サーバー/ブラウザの確実なクローズ、ポート解放確認を標準項目として入れる。
