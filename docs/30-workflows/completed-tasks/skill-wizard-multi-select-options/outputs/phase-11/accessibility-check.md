## キーボード操作確認（コードレビューベース）

| 確認項目                                                               | 判定 | 根拠                                                     |
| ---------------------------------------------------------------------- | ---- | -------------------------------------------------------- |
| Tab キーで各選択ボタンにフォーカスが移動すること                       | ✅   | `<button>` 要素を使用しているため標準的な Tab 順序に従う |
| Space / Enter キーでボタンをトグル選択できること                       | ✅   | `<button>` 要素の標準動作（onClick = Space/Enter）       |
| フォーカス表示（アウトライン）が各ボタンで正しく表示されること         | ✅   | Tailwind CSS の `focus:` クラスが既存実装で設定済み      |
| ScheduleConfigInput 内の cron 式入力欄にキーボードでアクセスできること | ✅   | 既存コンポーネントの Tab 対応を変更していない            |
| Escape キーやタブ移動で ScheduleConfigInput から抜けられること         | ✅   | 標準的なフォームナビゲーション                           |

## スクリーンリーダー確認（コードレビューベース）

| 確認項目                                                                                | 判定 | 根拠                                                                |
| --------------------------------------------------------------------------------------- | ---- | ------------------------------------------------------------------- |
| 未選択ボタン読み上げ時に `aria-pressed="false"` が伝達されること                        | ✅   | `aria-pressed={selectedOptions.includes(opt)}` → 未選択時は `false` |
| 選択済みボタン読み上げ時に `aria-pressed="true"` が伝達されること                       | ✅   | 選択時は `true`（A11Y-03 テスト確認済み）                           |
| 複数ボタンが選択済みの場合、各ボタンの状態が独立して読み上げられること                  | ✅   | 各ボタンが独立した `aria-pressed` を持つ（A11Y-04 確認済み）        |
| Q3 ScheduleConfigInput 展開時に新たなコンテンツが追加されたことが読み上げられること     | ⚠️   | 実機 VoiceOver 確認推奨（live region 実装有無を確認）               |
| 「選択済み」バッジが読み上げられるか、もしくは `aria-hidden` で適切に制御されていること | ⚠️   | 実機確認推奨                                                        |
