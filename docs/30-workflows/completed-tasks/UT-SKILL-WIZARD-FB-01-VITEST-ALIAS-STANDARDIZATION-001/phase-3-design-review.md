## 設計の妥当性検証

### simpler alternative の検討

| 代替案                                     | 評価                                                | 採用可否 |
| ------------------------------------------ | --------------------------------------------------- | -------- |
| `tsconfig.json` の paths に alias を追加   | vitest は tsconfig paths を自動で読まないため不十分 | 不採用   |
| `@repo/shared` import をやめ相対パスに戻す | ESLint フックが再変換するため根本対応にならない     | 不採用   |
| `vite-tsconfig-paths` プラグイン導入       | 依存追加のオーバーヘッドあり。最小変更で対応可能    | 不採用   |

**結論**: Phase 2 の設計（resolve.alias の直接追加）が最もシンプルで実現可能。
