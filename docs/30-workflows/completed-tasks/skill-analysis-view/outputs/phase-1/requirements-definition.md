## 機能要件（FR）

### FR-1: スキル分析実行

| ID     | 要件                                                                              | 優先度 |
| ------ | --------------------------------------------------------------------------------- | ------ |
| FR-1-1 | 「分析」ボタンクリックで `window.electronAPI.skill.analyze(skillName)` を呼び出す | 必須   |
| FR-1-2 | 分析中はローディングスピナーまたはスケルトンを表示する                            | 必須   |
| FR-1-3 | 分析完了後、`SkillAnalysis` オブジェクトの結果を画面に表示する                    | 必須   |
| FR-1-4 | 分析実行中は「分析」ボタンをdisabledにする                                        | 必須   |

### FR-2: 分析結果表示

| ID     | 要件                                                                            | 優先度 |
| ------ | ------------------------------------------------------------------------------- | ------ |
| FR-2-1 | `overallScore`（0-100）を円形プログレスバーまたは数値＋カラーインジケータで表示 | 必須   |
| FR-2-2 | スコア値に応じて色を切り替え（80-100: 成功色、60-79: 警告色、0-59: エラー色）   | 必須   |
| FR-2-3 | `categories[]` 配列の各カテゴリを水平バーチャートで表示する                     | 必須   |
| FR-2-4 | 各カテゴリにカテゴリ名、スコア、詳細テキスト、課題リストを表示する              | 必須   |
| FR-2-5 | `suggestions[]` 配列を優先度別（high/medium/low）にグループ化して表示する       | 必須   |
| FR-2-6 | 各提案にタイプアイコン、優先度バッジ、説明文、自動修正可能フラグを表示する      | 必須   |
| FR-2-7 | `risks[]` 配列をレベル別に色分けして表示する                                    | 必須   |
| FR-2-8 | リスク情報にカテゴリ、レベル、説明、影響、緩和策を表示する                      | 必須   |

#### スコア色分けルール

| スコア範囲 | カラー                 | CSS変数            |
| ---------- | ---------------------- | ------------------ |
| 80-100     | 成功色（systemGreen）  | `--status-success` |
| 60-79      | 警告色（systemOrange） | `--status-warning` |
| 0-59       | エラー色（systemRed）  | `--status-error`   |

#### リスクレベル色分けルール

| リスクレベル | カラー                 | CSS変数            |
| ------------ | ---------------------- | ------------------ |
| critical     | エラー色（systemRed）  | `--status-error`   |
| high         | 警告色（systemOrange） | `--status-warning` |
| medium       | 情報色（systemBlue）   | `--status-info`    |
| low          | テキスト色             | `--text-secondary` |

### FR-3: 改善提案の選択・適用

| ID     | 要件                                                                                          | 優先度 |
| ------ | --------------------------------------------------------------------------------------------- | ------ |
| FR-3-1 | 各改善提案にチェックボックスを表示し、個別に選択できる                                        | 必須   |
| FR-3-2 | 「自動修正可能な提案のみ選択」フィルタボタンを提供する                                        | 必須   |
| FR-3-3 | 「選択した提案を適用」ボタンで `applyImprovements(skillName, selectedSuggestions)` を呼び出す | 必須   |
| FR-3-4 | 適用中はボタンをdisabledにし、ローディングインジケータを表示する                              | 必須   |
| FR-3-5 | 適用完了後、結果（適用数・スキップ数・エラー数）をトースト通知で表示する                      | 必須   |
| FR-3-6 | 適用完了後、分析結果を自動で再取得して画面を更新する                                          | 必須   |

### FR-4: 全自動改善

| ID     | 要件                                                           | 優先度 |
| ------ | -------------------------------------------------------------- | ------ |
| FR-4-1 | 「全自動改善」ボタンで `autoImprove(skillName)` を呼び出す     | 必須   |
| FR-4-2 | 実行前に確認ダイアログを表示する（破壊的操作の保護）           | 必須   |
| FR-4-3 | 実行中はボタンをdisabledにし、プログレスインジケータを表示する | 必須   |
| FR-4-4 | 完了後、結果サマリーを表示し、分析結果を再取得する             | 必須   |

### FR-5: エラーハンドリング

| ID     | 要件                                                             | 優先度 |
| ------ | ---------------------------------------------------------------- | ------ |
| FR-5-1 | 分析失敗時にエラーメッセージを表示し、「再試行」ボタンを提供する | 必須   |
| FR-5-2 | 改善適用失敗時に失敗した提案と成功した提案を区別して表示する     | 必須   |
| FR-5-3 | ネットワークエラー時にオフライン状態のメッセージを表示する       | 任意   |
| FR-5-4 | バリデーションエラー時に入力値の問題を明示する                   | 必須   |

## IPC連携要件

### 利用するIPCチャネル

| チャネル名       | 定数                          | 方向                     | 引数                                           | 戻り値              |
| ---------------- | ----------------------------- | ------------------------ | ---------------------------------------------- | ------------------- |
| `skill:analyze`  | `IPC_CHANNELS.SKILL_ANALYZE`  | Renderer → Main → Return | `skillName: string`                            | `SkillAnalysis`     |
| `skill:improve`  | `IPC_CHANNELS.SKILL_IMPROVE`  | Renderer → Main → Return | `skillName: string, suggestions: Suggestion[]` | `ImprovementResult` |
| `skill:optimize` | `IPC_CHANNELS.SKILL_OPTIMIZE` | Renderer → Main → Return | `skillName: string`                            | `ImprovementResult` |

### Preload API

`window.electronAPI.skill` に以下のメソッドを公開する:

- `analyze(skillName: string): Promise<SkillAnalysis>` -- スキル分析実行
- `applyImprovements(skillName: string, suggestions: Suggestion[]): Promise<ImprovementResult>` -- 選択した改善提案の適用
- `autoImprove(skillName: string): Promise<ImprovementResult>` -- 全自動改善実行

型定義の正本: `packages/shared/src/types/skill-improver.ts`

---

## データフロー

```
Renderer (SkillAnalysisView)
  → Preload (skill-api.ts: safeInvoke)
    → Main Process (IPC Handler)
      → SkillAnalyzer.analyze() / SkillImprover.applyImprovements()
    ← Main Process (結果返却)
  ← Preload (IpcResult<T> アンラップ)
← Renderer (state更新 → 再レンダリング)
```

## Renderer層の状態管理

| 状態名                | 型                      | 初期値  | 説明                                 |
| --------------------- | ----------------------- | ------- | ------------------------------------ |
| `analysis`            | `SkillAnalysis \| null` | `null`  | 分析結果                             |
| `isAnalyzing`         | `boolean`               | `false` | 分析中フラグ                         |
| `isImproving`         | `boolean`               | `false` | 改善適用中フラグ                     |
| `selectedSuggestions` | `Set<number>`           | 空Set   | 選択された改善提案のインデックス集合 |
| `error`               | `string \| null`        | `null`  | エラーメッセージ                     |

状態は `useState` でコンポーネントローカルに管理する。SkillAnalysisViewは単一画面で完結し、他コンポーネントとの状態共有が不要なため、Zustand Storeは使用しない。
