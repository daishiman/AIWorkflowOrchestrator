## Part 1: 中学生向け解説

### このアップデートで何が変わったの？

今回のアップデートでは、スキルを登録するときに使う「スキルウィザード」という画面を3つの点で改善しました。

---

### 1. カテゴリを何個でも選べるようになった

たとえば、ノートに「算数」「理科」「国語」とラベルシールを貼ることを考えてみてください。

以前のアプリは「**1枚しか貼れないラベルシール**」でした。「算数」を貼ったあとに「理科」を貼ろうとすると、「算数」がはがれてしまっていたのです。

今回の修正で「**何枚でも貼れるラベルシール**」になりました。「算数」と「理科」を同時に貼れますし、もう一度「算数」をタップするとその1枚だけをはがすこともできます。

---

### 2. 進行バーが「今どこまで答えたか」を正しく示すようになった

たとえば、テストの問題を解くとき、先生が「あなたは今2ページ目をやっている」と言うより、「あなたはもう3問答えた」と教えてくれるほうが自分の進み具合がわかりやすいですよね。

以前の進行バー（ProgressBar）は「ページ番号」をそのまま表示していました。だから画面を移動しても実際には何も答えていないのに、バーが進んでいるように見えることがありました。

今回の修正で、**実際に回答済みの問数だけをカウント**してバーに反映するようになりました。答えた分だけバーが伸びる、正直な表示になっています。

---

### 3. ボタンの色が統一されてわかりやすくなった

たとえば、道路の信号機を想像してください。赤・黄・青の意味が国によってバラバラだったら混乱しますよね。信号は世界中でルールが統一されているから安心して使えます。

今回の修正でアプリ内の「大事なボタン」の色をひとつのルール（CSS変数）で統一しました。これにより、どの画面でも「このボタンが一番重要」とひと目でわかるようになりました。色のルールを1か所で変えるだけで全ボタンに反映されるため、デザイン変更の手間も減ります。

## Part 2: 技術者向け解説

### 2-1. `SkillInfoFormData.category` の型変更

#### 変更概要

| 項目         | 変更前                  | 変更後            |
| ------------ | ----------------------- | ----------------- |
| 型定義       | `SkillCategory \| null` | `SkillCategory[]` |
| 未選択時の値 | `null`                  | `[]`（空配列）    |
| 複数選択     | 不可                    | 可                |

#### 影響範囲

- `SkillInfoFormData` インターフェースの `category` フィールド
- `category` を参照する全バリデーションロジック（`null` チェック → `length === 0` チェックへ）
- フォームの初期値（`null` → `[]`）
- subpath export（ルートbarrelへの変更は不要。型はコンポーネント内部で消費されるため外部APIに影響なし）

#### エッジケース

| ケース           | 挙動                                                 |
| ---------------- | ---------------------------------------------------- |
| 未選択のまま送信 | `category.length === 0` でバリデーションエラーを返す |
| 全カテゴリを解除 | 空配列 `[]` に戻り、未選択状態として扱われる         |

### 2-2. `handleCategoryClick` のトグルロジック

#### 実装仕様

```typescript
// 変更後
const handleCategoryClick = (value: SkillCategory) => {
  const next = formData.category.includes(value)
    ? formData.category.filter((c) => c !== value) // 解除
    : [...formData.category, value]; // 追加
  onFormDataChange({ ...formData, category: next });
};
```

#### 動作パターン

| 操作                       | `formData.category` の状態 | `next` の値         |
| -------------------------- | -------------------------- | ------------------- |
| 未選択カテゴリをクリック   | `[]`                       | `[value]`           |
| 選択済みカテゴリをクリック | `[value]`                  | `[]`                |
| 別カテゴリを追加クリック   | `[value]`                  | `[value, newValue]` |
| 選択済みを部分解除         | `[a, b]` → `b` をクリック  | `[a]`               |

#### エッジケース・エラーハンドリング

- `formData.category` が `undefined` になるパスは型定義上存在しないが、防御的に初期値を `[]` で保証する
- 同一カテゴリの連打（高速クリック）: `includes` が正しく機能するため重複追加は発生しない
- 設定可能なパラメータ: 選択上限数は現時点で無制限。上限を設ける場合は `next.length <= MAX_CATEGORY_COUNT` の条件を追加する

### 2-3. `currentQuestion` の動的計算

#### 実装仕様

```typescript
// 変更後
const answeredCount = QUESTION_KEYS.filter((key) =>
  isQuestionAnswered(answers[key]),
).length;
const currentQuestion = Math.max(1, answeredCount);
```

#### 変更前後の比較

| 項目               | 変更前                                     | 変更後                 |
| ------------------ | ------------------------------------------ | ---------------------- |
| 計算基準           | ページ番号（固定値または画面遷移カウント） | 回答済み問数（動的）   |
| 未回答時の最小値   | 設計依存                                   | 1（`Math.max` で保証） |
| 回答を飛ばした場合 | バーが過剰に進む可能性あり                 | 実際の回答数を反映     |

#### `isQuestionAnswered` の役割

- 各回答キーに対して「有効な回答が存在するか」を判定するユーティリティ関数
- `undefined` / `null` / 空文字 / 空配列をすべて「未回答」と判定する設計

#### エッジケース

| ケース     | `answeredCount`        | `currentQuestion`      |
| ---------- | ---------------------- | ---------------------- |
| 全未回答   | 0                      | 1（`Math.max` が保証） |
| 一部回答   | n（1以上）             | n                      |
| 全回答済み | `QUESTION_KEYS.length` | `QUESTION_KEYS.length` |

#### 設定可能な定数

| 定数                     | 説明                           | 変更時の影響                         |
| ------------------------ | ------------------------------ | ------------------------------------ |
| `QUESTION_KEYS`          | 進捗カウント対象の回答キー配列 | 追加/削除でProgressBar最大値が変わる |
| `Math.max` の第1引数 `1` | 最小表示値                     | 変更でProgressBarの初期表示が変わる  |

### 2-4. ボタンCSS変数統一

#### 変更概要

| 項目             | 変更前        | 変更後                       |
| ---------------- | ------------- | ---------------------------- |
| 背景色クラス     | `bg-blue-600` | `bg-[var(--status-primary)]` |
| テキスト色クラス | `text-white`  | `text-[var(--text-inverse)]` |

#### CSS変数の定義場所

- `--status-primary`: アプリ全体のプライマリアクションカラー（例: ブランドカラー）
- `--text-inverse`: プライマリ背景上のテキスト色（通常は白またはそれに準じる色）

#### 統一の意図

- `bg-blue-600` はTailwind固有の固定色であり、テーマ変更や将来のダークモード対応時に変更箇所が分散する
- CSS変数を使うことで、変数値を1か所変えるだけで全ボタンへ即時反映できる

#### 影響範囲

- 対象: SkillWizard内の主要アクションボタン群（次へ・保存・確定など）
- 非対象: セカンダリボタン・キャンセルボタン（別変数または別クラスを使用）
- subpath exportへの影響: なし（スタイル変更のみ。コンポーネントのAPIシグネチャは変わらない）

---

### 2-5. subpath exportへの影響方針

今回の変更はコンポーネント内部の実装変更（型・ロジック・スタイル）にとどまります。

- ルートbarrel（`index.ts`）への変更は不要
- `SkillInfoFormData` の型はコンポーネント内部で消費されるため、外部に公開するAPIシグネチャに変更はない
- 型変更が外部に公開されている場合は、呼び出し元の `category` 初期値を `null` から `[]` に変更する必要がある（別タスクで追跡）
