## 目的

正規化設計が dynamic skill-creator 主線を壊さず、UI と WorkflowEngine を SDK 生イベントから切り離せているかをレビューする。

## 背景

Phase 2 で設計した normalizer / Facade 統合 / IPC payload が、既存の dynamic skill-creator 読込パスを侵害しないことを検証する。レビューゲートを通過しなければ実装フェーズに進めない。

## 実行タスク

### Task 1: skill-creator 動的読込の確認

**目的**: skill-creator 動的読込を壊していないか確認する。

**実行手順**:

1. `.claude/skills/skill-creator/` の動的読込パスを追跡する
2. normalizer 導入による変更影響を評価する

**期待される成果物**:

- 動的読込影響レポート

### Task 2: 正規化契約の欠落確認

**目的**: `session_id` / provenance / result subtype の欠落がないか確認する。

**実行手順**:

1. Phase 1 の必須項目と Phase 2 の型定義を突合する
2. 欠落項目の有無をチェックする

**期待される成果物**:

- 契約欠落チェックリスト

### Task 3: 後続タスクへの入力契約確認

**目的**: 後続タスクへの入力契約が十分か確認する。

**実行手順**:

1. RT-03 / P0-05 / P0-08 / P0-09 が必要とする入力を列挙する
2. 正規化イベントがそれらを満たすか検証する

**期待される成果物**:

- 入力契約充足レポート
