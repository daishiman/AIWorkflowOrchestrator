# Phase 2 設計方針書

## 設計判断

1. `waitForCallback()` は「イベント待機API」として純化する。
2. サーバーライフサイクル管理（停止）は `stop()` に集約する。
3. `stop()` は idempotent にして呼び出し側が何度呼んでも安全にする。
4. `close` コールバックのエラーは握りつぶし、ワーカー終了フローの安定性を優先する。

## トレードオフ

- メリット: 責務が明確化され、timeout 経路の副作用が消える。
- デメリット: 呼び出し側で `stop()` を呼ぶ実装責任が明示的に必要。
- 判断: テストで `stop()` 明示実行を追加し、契約を固定する。
