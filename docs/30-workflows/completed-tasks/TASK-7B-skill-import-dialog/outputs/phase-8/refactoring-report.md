## 1. 主要リファクタリング（Phase 5で実施済み）

### RESOURCE_SECTIONS配列パターン

Phase 5の実装時に、6つの類似サブリソースセクションを`RESOURCE_SECTIONS`定数配列にリファクタリング済み。

| 項目       | 内容                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| 対象       | agents, references, scripts, assets, schemas, indexes の6セクション    |
| 実施内容   | `RESOURCE_SECTIONS`配列 + `.filter().map()`パターンで共通化            |
| 効果       | 約60行の重複コードを約15行に削減、新セクション追加時は配列要素追加のみ |
| テスト影響 | なし（外部動作は変更なし）                                             |

```typescript
const RESOURCE_SECTIONS = [
  { key: "agents", title: "サブエージェント (agents/)", data: skill.agents },
  {
    key: "references",
    title: "参照資料 (references/)",
    data: skill.references,
  },
  { key: "scripts", title: "スクリプト (scripts/)", data: skill.scripts },
  { key: "assets", title: "アセット (assets/)", data: skill.assets },
  { key: "schemas", title: "スキーマ (schemas/)", data: skill.schemas },
  { key: "indexes", title: "インデックス (indexes/)", data: skill.indexes },
];
```

## 2. コードスメル分析

### 2.1 分析結果サマリー

| #   | コードスメル候補                        | 判定   | 詳細                                             |
| --- | --------------------------------------- | ------ | ------------------------------------------------ |

### 2.2 各項目の詳細判断

#### コードスメル#1: サブリソースセクションの繰り返し（解決済）

- **状態**: Phase 5実装時にRESOURCE_SECTIONSパターンで解決済み
- **確認**: 現在のコードに重複パターンは残存していない

#### コードスメル#2: ESCキーハンドラー（見送り）

| 判断項目   | 内容                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 現状       | `useCallback` + `useEffect`でkeydownリスナーを登録                       |
| 検討内容   | `useEscapeKey(callback)`カスタムHookへの抽出                             |
| 判断       | 見送り                                                                   |
| 理由       | 単一コンポーネントでのみ使用。Hook抽出による複雑性増加がメリットを上回る |
| 再検討条件 | 同パターンが3箇所以上で使用される場合に再検討                            |

#### コードスメル#3: フォーカストラップ（見送り）

| 判断項目   | 内容                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 現状       | `useEffect`内でfocusable要素を検出しTab/Shift+Tab循環を実装                     |
| 検討内容   | `useFocusTrap(ref)`カスタムHookへの抽出                                         |
| 判断       | 見送り（将来検討）                                                              |
| 理由       | 現時点ではSkillImportDialogでのみ使用。RestoreDialog/PermissionDialogは独自実装 |
| 再検討条件 | ダイアログコンポーネント共通化タスク時にHook統一を検討                          |

#### コードスメル#4: Section/ResourceListのファイル分割（見送り）

| 判断項目   | 内容                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 現状       | SkillImportDialog.tsx内に3コンポーネントが同居                                             |
| 検討内容   | Section.tsx / ResourceList.tsx への分割                                                    |
| 判断       | 見送り                                                                                     |
| 理由       | 各サブコンポーネントは10行未満の小規模実装。分割によるファイル管理コストがメリットを上回る |
| 再検討条件 | サブコンポーネントが20行以上に成長した場合、または他コンポーネントから再利用する場合       |
