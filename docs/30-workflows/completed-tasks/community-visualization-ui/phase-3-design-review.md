## 目的

Phase 1（要件定義）およびPhase 2（設計）の成果物をレビューし、実装に進む前に設計の妥当性を検証する。

## 背景

実装開始前に設計の問題を発見・修正することで、後戻りコストを最小化する。要件と設計の整合性、技術的実現可能性、既存システムとの整合性を検証する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件レビュー

**目的**: Phase 1の要件定義が完全かつ明確であることを確認する

**実行手順**:

1. `outputs/phase-1/functional-requirements.md` をレビュー:
   - 全機能要件（FR-001〜FR-008）が明確に定義されているか
   - 受け入れ基準が測定可能か
   - 優先度設定が適切か
2. `outputs/phase-1/non-functional-requirements.md` をレビュー:
   - パフォーマンス要件が具体的か
   - アクセシビリティ要件がWCAG 2.1 AA準拠か
3. `outputs/phase-1/connection-requirements.md` をレビュー:
   - IPCチャンネル定義が完全か
   - エラーハンドリング方針が明確か

**レビュー観点**:

| 観点     | チェック項目             |
| -------- | ------------------------ |
| 完全性   | 全要件が網羅されているか |
| 明確性   | 曖昧な表現がないか       |
| 測定可能 | 達成判定が可能か         |
| 整合性   | 要件間に矛盾がないか     |

**期待される成果物**:

- 要件レビュー結果

---

### タスク2: 設計レビュー

**目的**: Phase 2の設計が要件を満たし、技術的に実現可能であることを確認する

**実行手順**:

1. `outputs/phase-2/library-selection.md` をレビュー:
   - 選定基準が適切か
   - 選定理由が論理的か
   - リスク評価が行われているか
2. `outputs/phase-2/component-design.md` をレビュー:
   - Atomic Design原則に従っているか
   - 責務分離が適切か
   - 再利用性が考慮されているか
3. `outputs/phase-2/hook-design.md` をレビュー:
   - Reactベストプラクティスに従っているか
   - エラー状態・ローディング状態が考慮されているか
4. `outputs/phase-2/wireframe.md` をレビュー:
   - 全ユースケースがカバーされているか
   - 空状態・エラー状態が設計されているか
5. `outputs/phase-2/ipc-design.md` をレビュー:
   - 既存IPCパターンと整合しているか
   - Result型パターンが採用されているか

**レビュー観点**:

| 観点         | チェック項目                     |
| ------------ | -------------------------------- |
| 要件充足     | 全要件を設計がカバーしているか   |
| 技術的妥当性 | 実現可能な設計か                 |
| 既存整合性   | 既存コードベースと整合しているか |
| 保守性       | 変更容易な設計か                 |

**期待される成果物**:

- 設計レビュー結果

---

### タスク3: 統合テスト観点レビュー

**目的**: 統合テストの観点が設計に反映されていることを確認する

**実行手順**:

1. IPC通信テストの観点:
   - 正常系・異常系のシナリオが定義されているか
   - モック戦略が明確か
2. コンポーネント統合テストの観点:
   - 親子コンポーネント間の連携がテスト可能か
   - 状態管理のテスト方針が明確か
3. データフローテストの観点:
   - Renderer → Main → DB → Main → Renderer のフローがテスト可能か

**期待される成果物**:

- 統合テスト観点レビュー結果

---

### タスク4: レビュー結果の判定

**目的**: レビュー結果に基づき、次フェーズへの進行可否を判定する

**実行手順**:

1. 全レビュー結果を集約
2. 指摘事項を分類:
   - CRITICAL: 致命的な問題（Phase 1へ戻る）
   - MAJOR: 重大な問題（該当Phaseへ戻る）
   - MINOR: 軽微な指摘（対応後進行）
   - INFO: 情報・提案（次Phase以降で対応可）
3. 判定を決定

**期待される成果物**:

- レビュー結果判定書
