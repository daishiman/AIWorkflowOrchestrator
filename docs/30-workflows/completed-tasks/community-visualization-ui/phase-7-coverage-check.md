## 目的

Phase 6で拡充したテストのカバレッジが基準を満たしていることを確認する。未達の場合はPhase 6へ戻りテストを追加する。

## 背景

リファクタリングフェーズ（Phase 8）に進む前に、十分なテストカバレッジを確保することで、安全なリファクタリングを可能にする。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ユニットテストカバレッジの検証

**目的**: ユニットテストのカバレッジが基準を満たしているか確認する

**実行手順**:

1. カバレッジレポートを生成:
   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```
2. 以下の基準を確認:
   | 指標 | 最低基準 | 推奨基準 | 現在値 | 判定 |
   | ----------------- | -------- | -------- | ------ | ---- |
   | Line Coverage | 80% | 90% | \_**\_% | ⬜ |
   | Branch Coverage | 60% | 70% | \_\_**% | ⬜ |
   | Function Coverage | 80% | 90% | \_\_\_\_% | ⬜ |
3. 未達項目がある場合:
   - 不足箇所を特定
   - Phase 6へ戻りテストを追加

**期待される成果物**:

- カバレッジ検証結果

---

### タスク2: 結合テストカバレッジの検証

**目的**: 結合テストのカバレッジが基準を満たしているか確認する

**実行手順**:

1. 以下の基準を確認:
   | 指標 | 目標 | 現在状態 | 判定 |
   | ---------------------------- | ---- | -------- | ---- |
   | API接続テスト | 100% | \_**\_ | ⬜ |
   | モジュール間インターフェース | 100% | \_\_** | ⬜ |
   | 正常系シナリオ | 100% | \_**\_ | ⬜ |
   | 異常系シナリオ | 80%+ | \_\_** | ⬜ |
   | 外部連携ポイント | 100% | \_\_\_\_ | ⬜ |
2. 統合テストを実行:
   ```bash
   pnpm --filter @repo/desktop test:integration
   ```
3. 未達項目がある場合:
   - 不足シナリオを特定
   - Phase 6へ戻りテストを追加

**期待される成果物**:

- 結合テスト検証結果

---

### タスク3: 統合テストの再実行

**目的**: 全ての統合テストが成功することを確認する

**実行手順**:

1. 統合テストスイートを実行:
   ```bash
   pnpm --filter @repo/desktop test
   ```
2. 全テストが成功することを確認
3. 失敗テストがある場合:
   - 原因を分析
   - Phase 5へ戻り修正

**期待される成果物**:

- テスト実行結果

---

### タスク4: ゲート判定

**目的**: カバレッジ基準達成を判定し、次フェーズへの進行可否を決定する

**実行手順**:

1. 全カバレッジ基準の達成状況を確認
2. 判定結果を記録:
   | 判定 | 条件 | 次のアクション |
   | -------- | ---------------------- | -------------- |
   | PASS | 全基準達成 | Phase 8へ進行 |
   | NOT_MET | いずれかの基準未達 | Phase 6へ戻る |

**期待される成果物**:

- ゲート判定結果書（`outputs/phase-7/gate-judgment.md`）
