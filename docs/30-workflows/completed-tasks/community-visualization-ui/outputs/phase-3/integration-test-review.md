## 3. データフローテストの観点

### 3.1 Renderer → Main → DB → Main → Renderer フロー

```
テストフロー:
1. Renderer: useCommunities Hook呼び出し
2. Renderer: window.electronAPI.community.getAll()
3. Preload: ipcRenderer.invoke('community:getAll')
4. Main: ipcMain.handle → CommunityRepository.findAll()
5. DB: SQLite Query実行
6. Main: Result<Community[], Error> 返却
7. Renderer: Hook状態更新
8. Renderer: CommunityGraph レンダリング
```

| ステップ        | テスト可能性 | モック/実装  |
| --------------- | ------------ | ------------ |
| 1. Hook呼び出し | 高           | 実装         |
| 2. API呼び出し  | 高           | モック       |
| 3. IPC invoke   | 中           | モック       |
| 4. Handler      | 高           | DIモック     |
| 5. DB Query     | 中           | インメモリDB |
| 6. 結果返却     | 高           | モック       |
| 7. 状態更新     | 高           | 実装         |
| 8. レンダリング | 高           | 実装         |

### 3.2 並列取得フローテスト

```
テストフロー（詳細パネル表示時）:
```
