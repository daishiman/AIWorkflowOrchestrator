# 実装ガイド: Phase 11 テスト証跡一本化テンプレート

## Part 1: 中学生レベル概念説明

### なぜテスト証跡を一本化するのか

あなたが学校でテストを受けたとき、答えを書いた後に「なぜその答えにしたのか」を先生に聞かれることはありませんか？

もしメモが何冊にも分かれていて、「件数はノート1に書いた」「特別なケースはルーズリーフに書いた」「判断の理由はメモ帳に書いた」となっていたら、先生はとても困ります。あなた自身も後から見返すときに「あれどこだっけ？」となってしまいます。

ソフトウェアのテストも同じです。「何件テストしたか」「どんな特別なケースを試したか」「なぜそのルールにしたのか」が別々のファイルに散らばっていると、後から確認するのにとても時間がかかります。

**テスト証跡の一本化**とは、このバラバラなメモを「1冊の記録ノート」にまとめることです。

このノートには次の3つが必ず書かれています:

1. **テスト件数サマリー**: 「合計9件。正常系3件、異常系2件、edge case 4件。全てOK（PASS）」のように一目でわかる
2. **edge case 一覧表**: 「空白だけを入力したらどうなるか」「すごく長い文字を入力したらどうなるか」など特別なケースの一覧
3. **仕様判断根拠**: 「空白は空文字として扱う」と決めた理由と、それを決めた会議の記録へのリンク

この3つが1ファイルにあれば、誰でも5分でテストの全体像を把握できます。

## Part 2: 技術者レベル（テンプレート構造・使い方）

### テンプレート構造

```markdown
# Phase 11 手動テスト証跡

## テスト件数サマリー

| 区分            | 件数 | PASS | FAIL | SKIP |
| --------------- | ---- | ---- | ---- | ---- |
| 正常系テスト    | -    | -    | -    | -    |
| 異常系テスト    | -    | -    | -    | -    |
| edge caseテスト | -    | -    | -    | -    |
| **合計**        | -    | -    | -    | -    |

### 実施情報

| 実施日 | 実施者 | 対象バージョン | 実施環境 | 関連Issue |
| ------ | ------ | -------------- | -------- | --------- |
| -      | -      | -              | -        | -         |

## edge case 一覧表

> EC-NNN: 3桁ゼロ埋め整数、001から連番、タスクをまたいでリセット可

| ID     | 観点 | 入力値（代表例） | 期待動作 | 仕様判断根拠ID | 結果 |
| ------ | ---- | ---------------- | -------- | -------------- | ---- |
| EC-001 | ...  | ...              | ...      | SD-001         | PASS |

## 仕様判断根拠

> SD-NNN: 3桁ゼロ埋め整数、001から連番、タスクをまたいでリセット可

| ID     | 判断内容 | 根拠 | 影響範囲 |
| ------ | -------- | ---- | -------- |
| SD-001 | ...      | ...  | ...      |
```

### 使い方

1. テスト実行前に「テスト件数サマリー」の区分列を埋める
2. edge case を実行しながら「結果」列を埋める
3. 仕様判断が必要になったタイミングで「仕様判断根拠」テーブルに追記し、EC-NNN から SD-NNN を参照する
4. 全件完了後に「合計」行の件数が各区分の合計と一致することを確認する

### EC-NNN / SD-NNN 採番ルール

| ルール                   | 内容                                               |
| ------------------------ | -------------------------------------------------- |
| フォーマット             | 3桁ゼロ埋め整数（EC-001, EC-002, ...）             |
| 開始番号                 | 001                                                |
| スコープ                 | タスク単位でリセット可（タスクをまたいだ再利用可） |
| 逆引き列（SD→EC）        | 設けない（正方向参照のみ）                         |
| 未参照の場合（根拠不要） | 仕様判断根拠ID 列に `-` を記入                     |

### このテンプレートが解決する問題

| 問題                                   | 解決方法                                     |
| -------------------------------------- | -------------------------------------------- |
| テスト件数が複数ファイルに分散している | サマリーテーブルを冒頭1箇所に集約            |
| edge case の網羅性が不明               | edge case 一覧表で全件を EC-NNN ID で可視化  |
| 仕様判断の根拠（空白→空文字等）が不明  | 仕様判断根拠テーブルで根拠ドキュメントを明示 |
| PASS/FAIL/SKIP の内訳が集計できない    | テスト件数サマリーに PASS/FAIL/SKIP 列を追加 |
