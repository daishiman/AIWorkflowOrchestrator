## 目的

docs-only task のため「リファクタリング」はコードではなく**テンプレート構造の簡潔化・重複排除**を指す。
Phase 7 までに作成した manual-test-result.md テンプレートおよび task-specification-creator スキルの Phase 11 テンプレートを対象とし、可読性・保守性を向上させる。

FB-RT-03 準拠の「対象 / Before / After / 理由」テーブル形式で変更を記録し、将来の改版時に変更意図を追跡可能にする。

## 背景

Phase 7 までの作業で以下の問題が判明している可能性がある:

- セクション名が類似しており役割が重複している
- 同一情報が複数箇所に記載されており保守コストが高い
- 表のカラム定義が不統一で、機械的な集計を妨げる
- 注記・脚注が散在し、一読では構造が把握しにくい

本 Phase ではこれらを整理し、テンプレートを最小・最明確な形に収める。

## 実行タスク

1. Phase 7 成果物（テンプレート群）を読み込み、重複箇所・冗長箇所を列挙する
2. 各変更を「対象 / Before / After / 理由」テーブルに記録する
3. edge case 一覧表セクションの行数・カラム定義が適切かを確認する
4. 仕様判断根拠セクションの記述が簡潔かつ明確かを確認する
5. task-specification-creator スキルの Phase 11 テンプレート箇所の重複を排除する
6. 変更後のテンプレートを上書き保存する

## 変更記録（FB-RT-03 準拠）

> **注記**: 実際の変更内容は Phase 8 実行時に記録する。以下はテーブル定義のテンプレートである。

| 対象ファイル / セクション | Before（変更前の状態）           | After（変更後の状態）              | 理由                               |
| ------------------------- | -------------------------------- | ---------------------------------- | ---------------------------------- |
| （Phase 8 実行時に記入）  | （冗長・重複していた箇所の説明） | （簡潔化・統合後の説明）           | （可読性向上・保守コスト削減など） |
| 例: edge case 表カラム    | 「補足」「備考」「注意」が混在   | 「判断根拠」1列に統合              | カラム意味の重複排除               |
| 例: テスト件数セクション  | Summary 上部と下部の2箇所に記載  | 冒頭の Summary テーブル1箇所に集約 | 編集時の二重メンテナンスを防ぐ     |
