## 目的

Phase 5で更新したテンプレートについて、既存のPhase 11実例との互換性を確認し、edge caseの追加テスト観点を洗い出す。また、既存テンプレート使用箇所への回帰確認を実施する。

## 既存Phase 11実例との互換性確認

### 互換性確認の方針

新テンプレートは既存実例に対して「追加のみ」の変更である。既存セクションの削除・改名は行っていないため、後方互換性は原則として保たれる。ただし以下の観点で確認が必要である。

### 互換性確認チェックリスト（AC-5対応）

| 確認項目                                                                         | 確認方法                                   | 期待結果                   |
| -------------------------------------------------------------------------------- | ------------------------------------------ | -------------------------- |
| 既存Phase 11実例の必須セクションが新テンプレートでも存在すること                 | 既存実例と新テンプレートの見出し一覧を比較 | 全必須セクションが存在する |
| 既存実例のテーブル構造が新テンプレートで変更されていないこと                     | 既存セクションのテーブルヘッダーを比較     | 変更なし                   |
| 新3セクション（edge case・サマリー・仕様判断根拠）が既存実例に「追加」できること | 既存実例への新セクション追加を手動で試行   | 構造的に追加可能           |
| 既存実例の`## テスト結果`等のセクション名と新セクション名が衝突しないこと        | セクション名の重複チェック                 | 衝突なし                   |

### 既存実例の調査対象

| 調査対象                            | パス（例）                                          | 調査観点                 |
| ----------------------------------- | --------------------------------------------------- | ------------------------ |
| 完了済みタスクのPhase 11実例        | `docs/30-workflows/*/phase-11-*.md`（パターン検索） | 既存セクション構造の把握 |
| skill-wizard-bugfix-wave 配下の実例 | `docs/30-workflows/skill-wizard-bugfix-wave/*/`     | 最近の実例として参照     |

### 互換性確認の判定基準

| 判定 | 条件                                                                 |
| ---- | -------------------------------------------------------------------- |
| PASS | 全確認項目で期待結果が得られ、既存実例に新セクションを追加できること |
| FAIL | いずれかの確認項目で衝突・破壊的変更が検出されること                 |
| WARN | 軽微な表記ゆれが検出されたが、実害なし（改善余地として記録）         |

## edge caseの追加テスト観点

### テンプレート構造に関するedge case

| EC-ID  | 観点                                   | 詳細                                                   | 対応方針                           |
| ------ | -------------------------------------- | ------------------------------------------------------ | ---------------------------------- |
| EC-T01 | edge case一覧表が空の場合              | 0件のedge caseしかないタスクでテンプレートが機能するか | プレースホルダー行を設ける         |
| EC-T02 | 仕様判断根拠IDが未紐付け（`-`）の場合  | edge case一覧表に `SD-NNN` を参照しない行がある場合    | `-` を許容値として明示             |
| EC-T03 | 同一SD-NNNを複数EC-NNNが参照する場合   | 多対1参照の表現が可能か                                | 許容する（設計済み）               |
| EC-T04 | テスト件数サマリーの数値が不整合の場合 | 内訳合計と合計行が一致しない場合の扱い                 | 記入ルールとして整合チェックを記載 |
| EC-T05 | 仕様判断根拠が未入力（空行）の場合     | SD-001 の根拠列が空の場合の扱い                        | 記入ルールとして「必須」と明示     |
| EC-T06 | EC-NNNが100件を超える場合              | EC-100, EC-101... の採番が3桁で表現できるか            | 3桁採番で0〜999まで対応可能        |

### テンプレート運用に関するedge case

| EC-ID  | 観点                                         | 詳細                                                       | 対応方針                                     |
| ------ | -------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------- |
| EC-O01 | 新テンプレートを既存タスクに遡及適用する場合 | 完了済みタスクのPhase 11実例に新セクションを後から追加する | 任意対応として許容する（必須でない）         |
| EC-O02 | 複数人がPhase 11を並行編集する場合           | EC-NNN / SD-NNN の採番が衝突する可能性                     | 採番は担当者が事前に予約する旨をガイドに記載 |
| EC-O03 | タスクをまたいでSS-NNNを再利用する場合       | 同一仕様判断が複数タスクに存在する場合の取り扱い           | タスクスコープで独立採番すると決定済み       |
