## 目的

Phase 2 の設計文書をレビューし、後方互換性、ナビゲーション契約、エッジケース、設計品質を検証する。さらに 30種の思考法をすべて使い、変更分が最小複雑性で最大要件充足になっているかを判定する。GATE 判定（PASS / MINOR / MAJOR / CRITICAL）を行い、Phase 4 への進行可否を決定する。

## 実行タスク

### Task 1: 後方互換性レビュー

- `SkillCreateWizard` への既存導線が維持されることを確認する
- `SkillManagementPanel` → `SkillLifecyclePanel` 導線が維持されることを確認する
- 既存の `ViewType` 定義への影響が最小であることを確認する
- 既存テストへの影響範囲を特定する

### Task 2: ナビゲーション契約との整合性レビュー

- `.claude/skills/aiworkflow-requirements/references/ui-ux-navigation.md` に定義されたナビゲーション契約との整合性を確認する
- メインナビゲーション構造の変更が契約に準拠することを確認する
- モバイル / デスクトップ両方のナビゲーションパターンが契約に準拠することを確認する

### Task 3: エッジケース分析

- 直接 URL アクセス時の挙動
- ブラウザ戻る / 進む操作時の挙動
- `SkillLifecyclePanel` が作成中状態でのナビゲーション離脱
- 両導線同時利用時の状態競合
- `ViewType` の未定義値が渡された場合の fallback

### Task 4: 設計品質チェック

- 単一責務原則の遵守確認
- 変更箇所の最小化確認
- テスト容易性の確認
- 将来の拡張性（TASK-UI-02/03 への影響）確認

### Task 5: 30種の思考法による多角的分析

- 論理、構造、メタ、発想、システム、戦略、問題解決の 7 群で設計を検証する
- 各群の観点を並列に検証し、最後に共通の改善候補へ束ねる
- 「結論」だけでなく「どの思考法で何を見たか」を記録する

### Task 6: GATE 判定

- PASS: 問題なし、Phase 4 へ進行
- MINOR: 軽微な修正で Phase 4 へ進行可能
- MAJOR: Phase 2 へ差し戻し、設計修正が必要
- CRITICAL: Phase 2 へ差し戻し、根本的な再設計が必要

## 30思考法の分析レーン

| カテゴリ     | 思考法                                                                    | 主な確認ポイント                         |
| ------------ | ------------------------------------------------------------------------- | ---------------------------------------- |
| 論理分析系   | 批判的思考 / 演繹思考 / 帰納的思考 / アブダクション / 垂直思考            | 論理の飛躍、前提漏れ、結論の妥当性       |
| 構造分解系   | 要素分解 / MECE / 2軸思考 / プロセス思考                                  | 漏れ、重複、責務境界、手順の順序         |
| メタ・抽象系 | メタ思考 / 抽象化思考 / ダブル・ループ思考                                | 前提そのものの妥当性、ルール修正の必要性 |
| 発想・拡張系 | ブレインストーミング / 水平思考 / 逆説思考 / 類推思考 / if思考 / 素人思考 | 代替設計、再構成案、初見でも分かるか     |
| システム系   | システム思考 / 因果関係分析 / 因果ループ                                  | 依存関係、波及効果、戻り先の整合         |
| 戦略・価値系 | トレードオン思考 / プラスサム思考 / 価値提案思考 / 戦略的思考             | 価値最大化、コスト最小化、波及価値       |
| 問題解決系   | why思考 / 改善思考 / 仮説思考 / 論点思考 / KJ法                           | 根因、改善仮説、論点の束ね上げ           |
