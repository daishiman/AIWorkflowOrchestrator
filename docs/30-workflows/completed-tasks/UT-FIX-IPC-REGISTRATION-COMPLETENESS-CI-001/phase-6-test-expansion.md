## 目的

fail path・回帰 guard を追加して、将来の変更への保護を強化する。

## 背景

Phase 5 の正常系テストに加え、異常系（fail path）テストを追加することで、CI が実際に問題を検出できることを確認する。ネガティブテストにより、テスト自体の有効性を担保する。

---

## 実行タスク

### タスク1: ネガティブテスト（fail path）の追加

**目的**: 重複登録・チャネル変更が発生した場合に CI が FAIL することを確認する

**実行手順**:

1. TC-04: 重複登録注入テストを実装する
   - `ipcMain.handle` を意図的に同一チャネルで 2 回呼び出すモックを作成
   - 重複検出アサーションが FAIL することを `expect.assertions()` や `toThrow` パターンで確認
2. TC-05: 想定外チャネル追加・削除・リネームテストを実装する
   - スナップショットに存在しない新しいチャネルが追加された場合にスナップショット差分が生じることを確認
3. 全テスト（TC-01〜TC-05）が PASS することを確認する

**追加テストケース**:

| テストID | 内容                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| TC-04    | 重複登録が注入された場合にアサーションが FAIL することを確認（ネガティブテスト）                 |
| TC-05    | チャネル名一覧に想定外の追加・削除・リネームがあった場合にスナップショット差分が生じることを確認 |

**実行コマンド**:

```bash
# 全テスト実行（TC-01〜TC-05）
pnpm --filter @repo/desktop vitest run src/main/ipc/__tests__/ipcHandlerRegistrationSnapshot
```

**期待される成果物**:

- テストファイルの更新（TC-04, TC-05 追加）
- `outputs/phase-6/expanded-test-cases.md`
- `outputs/phase-6/fail-path-result.md`
