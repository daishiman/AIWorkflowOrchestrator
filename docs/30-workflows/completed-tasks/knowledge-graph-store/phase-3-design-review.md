## 目的

実装開始前に要件・設計の妥当性を検証する。

## 背景

Phase 1-2の成果物をレビューし、実装に進む前に問題を検出・修正する。

---

## 判定基準

| 判定  | 条件             | 対応                         |
| ----- | ---------------- | ---------------------------- |
| PASS  | 全観点で問題なし | Phase 4へ進行                |
| MINOR | 軽微な指摘あり   | 指摘対応後Phase 4へ進行      |
| MAJOR | 重大な問題あり   | 影響範囲に応じて戻り先を決定 |

---

## レビュー観点

### 要件レビュー

| 観点       | 確認項目                     | 結果 |
| ---------- | ---------------------------- | ---- |
| 完全性     | 全機能要件が網羅されているか |      |
| 明確性     | 曖昧な表現がないか           |      |
| 一貫性     | 要件間に矛盾がないか         |      |
| 実現可能性 | 技術的に実装可能か           |      |

### 設計レビュー

| 観点             | 確認項目                               | 結果 |
| ---------------- | -------------------------------------- | ---- |
| アーキテクチャ   | クリーンアーキテクチャに準拠しているか |      |
| ドメインモデル   | エンティティ・VOの境界が適切か         |      |
| インターフェース | 使いやすいAPIか                        |      |
| 拡張性           | 将来の変更に対応しやすいか             |      |
