## 1. プロジェクトスコープ

### 1.1 目的

GraphRAGアーキテクチャの中核コンポーネントとして、抽出されたエンティティと関係を永続化し、グラフトラバーサル・検索機能を提供するKnowledge Graphストアを実装する。

### 1.2 主要成果物

| 成果物         | パス                                                                         | 説明                                   |
| -------------- | ---------------------------------------------------------------------------- | -------------------------------------- |
| 型定義         | `packages/shared/src/services/graph/types.ts`                                | StoredEntity, StoredRelation等の型定義 |
| ストア実装     | `packages/shared/src/services/graph/knowledge-graph-store.ts`                | IKnowledgeGraphStore実装               |
| ユニットテスト | `packages/shared/src/services/graph/__tests__/knowledge-graph-store.test.ts` | テストスイート                         |

## 2. スコープ内（In Scope）

### 2.1 エンティティ操作

| 機能                | 説明                                       |
| ------------------- | ------------------------------------------ |
| upsertEntity        | 新規エンティティの作成または既存とのマージ |
| getEntity           | IDによるエンティティ取得                   |
| getEntityByName     | 正規化名によるエンティティ取得             |
| findEntities        | 複合条件によるエンティティ検索             |
| findSimilarEntities | 埋め込みベクトルによる類似エンティティ検索 |
| deleteEntity        | エンティティの削除（CASCADE）              |

### 2.2 関係操作

| 機能           | 説明                                           |
| -------------- | ---------------------------------------------- |
| addRelation    | 新規関係の追加または既存とのマージ（重み累積） |
| getRelation    | IDによる関係取得                               |
| getRelations   | エンティティに関連する関係の取得               |
| findRelations  | ヒントによる関係検索                           |
| deleteRelation | 関係の削除                                     |

### 2.3 グラフトラバーサル

| 機能             | 説明                          |
| ---------------- | ----------------------------- |
| traverse         | BFSによるグラフ探索           |
| findShortestPath | 2エンティティ間の最短パス検索 |
| getNeighbors     | 隣接ノードの取得              |

### 2.4 グラフ統計

| 機能     | 説明                                     |
| -------- | ---------------------------------------- |
| getStats | エンティティ数、関係数、分布、密度の取得 |

### 2.5 バッチ操作

| 機能               | 説明                         |
| ------------------ | ---------------------------- |
| bulkUpsertEntities | 複数エンティティの一括Upsert |
| bulkAddRelations   | 複数関係の一括追加           |

### 2.6 技術要件

| 要件         | 内容                             |
| ------------ | -------------------------------- |
| データストア | SQLite/Turso (libSQL)            |
| ORM          | Drizzle ORM                      |
| ベクトル検索 | DiskANNインデックス              |
| 型定義       | TypeScript Branded Types         |
| エラー処理   | Result型によるエラーハンドリング |

## 3. スコープ外（Out of Scope）

### 3.1 後続タスクで対応

| 機能             | 対応タスク | 理由                               |
| ---------------- | ---------- | ---------------------------------- |
| コミュニティ検出 | CONV-08-02 | Leiden Algorithmは別コンポーネント |
| コミュニティ要約 | CONV-08-03 | LLMを使用した要約生成              |
| グラフ可視化UI   | 未定義     | フロントエンド実装が必要           |

### 3.2 対応しない機能

| 機能                            | 理由                              |
| ------------------------------- | --------------------------------- |
| 分散グラフストア                | 現時点では単一ノードで十分        |
| リアルタイム同期                | Turso Embedded Replicasで対応済み |
| グラフデータベース（Neo4j等）   | SQLiteベースで統一                |
| カスタムグラフアルゴリズム      | BFS/最短パスで要件を満たす        |
| グラフのエクスポート/インポート | 優先度が低い                      |

### 3.3 制限事項

| 制限               | 詳細                              |
| ------------------ | --------------------------------- |
| 最大エンティティ数 | 100万エンティティまでのテスト保証 |
| 最大関係数         | 1000万関係までのテスト保証        |
| トラバーサル深度   | maxDepth=10を推奨上限             |
| バッチサイズ       | 1000件/バッチを推奨上限           |

## 6. 除外事項の詳細

### 6.1 コミュニティ検出（CONV-08-02）

**理由**: Leiden Algorithmによるコミュニティ検出は独立したアルゴリズム実装が必要であり、ストア機能とは責務が異なる。

**依存関係**: コミュニティ検出はKnowledge Graphストアのトラバーサル機能を利用する。

### 6.2 グラフ可視化UI

**理由**: フロントエンド実装が必要であり、バックエンドのストア実装とは別レイヤーである。

**将来対応**: getStats()やtraverse()の結果を可視化に利用可能。

### 6.3 分散グラフストア

**理由**: 現時点のユースケースでは単一ノードで十分なパフォーマンスが得られる。Turso Embedded Replicasによるオフライン対応で要件を満たす。

## 8. リスクと軽減策

| リスク                             | 影響 | 軽減策                                   |
| ---------------------------------- | ---- | ---------------------------------------- |
| DiskANNの互換性問題                | 高   | libSQLバージョン固定、フォールバック検討 |
| 大規模グラフでのパフォーマンス低下 | 中   | インデックス最適化、バッチサイズ調整     |
| 依存タスクの遅延                   | 中   | モック実装で先行開発可能                 |
| エンティティマージの競合           | 低   | 楽観的ロック、Last-Write-Wins            |
