## 機能要件（FR: Functional Requirements）

### FR-001: スキル実行

**説明**: スキルのプロンプトを Claude Agent SDK に送信し、実行する

**詳細**:

- `execute()` メソッドが `SkillExecutionRequest` を受け取る
- Claude Agent SDK の `query()` API を呼び出してスキルを実行する
- 一意な `executionId` を生成して返却する
- 実行完了/エラー時に適切なレスポンスを返す

**受け入れ基準**:

- [ ] execute() メソッドが SkillExecutionRequest を受け取れる
- [ ] query() API を呼び出してスキルを実行できる
- [ ] executionId（UUID v4）を生成して返却する
- [ ] 実行完了時に SkillExecutionResult を返す
- [ ] エラー時に適切なエラーレスポンスを返す

**優先度**: 高

---

### FR-002: ストリーミング処理

**説明**: query() API のレスポンスをストリーミングで受信し、リアルタイムにRenderer Processへ配信する

**詳細**:

- `stream()` メソッドで AsyncIterable を返す
- IPC を通じて Main Process から Renderer Process へメッセージを配信
- SDKMessage 型（text, tool_use, error, complete）に対応

**受け入れ基準**:

- [ ] ストリーミングレスポンスを受信できる
- [ ] 受信したメッセージを IPC 経由で Renderer Process に配信できる
- [ ] SDKMessageType（text, tool_use, error, complete）を正しく処理できる
- [ ] isComplete フラグで完了を通知できる

**優先度**: 高

---

### FR-003: 実行中断（Abort）

**説明**: AbortController を使用して実行中のスキルをキャンセルする

**詳細**:

- `abort()` メソッドで実行中のクエリを中断
- executionId を指定して特定の実行をキャンセル
- 中断時に適切なクリーンアップを実行

**受け入れ基準**:

- [ ] abort() メソッドで実行中のクエリを中断できる
- [ ] AbortController の signal を query() に渡せる
- [ ] 中断時に AgentAbortedError を発生させる
- [ ] リソースのクリーンアップが実行される

**優先度**: 高

---

### FR-004: 複数実行管理

**説明**: 複数のスキル実行を同時に管理する

**詳細**:

- executionId で各実行を一意に識別
- 実行中の全てのクエリを追跡
- 特定の実行のみを中断可能

**受け入れ基準**:

- [ ] 複数のスキルを同時に実行できる
- [ ] executionId で各実行を識別できる
- [ ] getActiveExecutions() で実行中リストを取得できる
- [ ] 特定の executionId を指定して abort できる

**優先度**: 中

---

### FR-005: 実行状態管理

**説明**: スキル実行の状態を管理・追跡する

**詳細**:

- 実行状態（pending, running, completed, aborted, error）を管理
- 実行開始時刻、終了時刻を記録
- 状態変更時にイベントを発火

**受け入れ基準**:

- [ ] ExecutionState（pending, running, completed, aborted, error）を管理できる
- [ ] 実行開始・終了時刻を記録できる
- [ ] getExecutionStatus() で特定実行の状態を取得できる

**優先度**: 中

## 非機能要件（NFR: Non-Functional Requirements）

### NFR-001: パフォーマンス

**説明**: ストリーミング処理の遅延を最小限に抑える

**要件**:

- ストリーミングメッセージの配信遅延: 100ms 以下
- 同時実行数: 最大 5 クエリ
- メモリリーク: なし（長時間実行でも安定）

**計測方法**:

- ストリーミング遅延: SDK 受信からIPC送信までの時間計測
- 同時実行: 5つのクエリを同時実行し、全て正常完了を確認

---

### NFR-002: セキュリティ

**説明**: TASK-2C で定義されたセキュリティパターンを適用

**要件**:

- 許可ツールホワイトリスト（ALLOWED_TOOLS_WHITELIST）の検証
- 危険コマンド（isDangerousCommand）のブロック
- 保護パス（isProtectedPath）へのアクセス制限

**計測方法**:

- セキュリティテストで全パターンをカバー
- ペネトレーションテスト相当のシナリオ実行

---

### NFR-003: エラーハンドリング

**説明**: 適切なエラー処理とリカバリー

**要件**:

- SDK エラーの適切なラッピング
- ネットワークエラー時のリトライ（最大3回）
- タイムアウト処理（デフォルト30秒）
- エラー情報のログ記録

**計測方法**:

- 各エラータイプのテストケース
- ネットワーク切断シミュレーション

---

### NFR-004: 保守性

**説明**: コードの保守性・拡張性を確保

**要件**:

- TypeScript 厳密モード（strict: true）
- テストカバレッジ: Line 80%以上、Branch 60%以上
- 明確な責務分離（単一責任の原則）
- ドキュメントコメント

**計測方法**:

- TypeScript コンパイルエラーなし
- Vitest カバレッジレポート

---

### NFR-005: 信頼性

**説明**: 安定した動作と障害回復

**要件**:

- 異常終了時のリソース解放
- 中断後の状態一貫性
- セッション管理との連携

**計測方法**:

- 異常系テストの実行
- 長時間実行テスト
