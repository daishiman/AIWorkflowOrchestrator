## 目的

テストコードの品質向上を目的としたリファクタリングを行う（TDD Refactor フェーズ）。テストの可読性・保守性・構造を改善し、外部振る舞い（テスト結果）を変えずにコード品質を向上させる。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: テストコードの構造改善

**目的**: テストファイルの構造を最適化する

**実行手順**:

1. `skillIpc.integration.test.ts` を読み、以下の改善点を特定する：
   - 重複するMock設定の共通化
   - `describe` ブロックの入れ子が深すぎる箇所の平坦化
   - テストヘルパー関数の適切な配置（ファイル先頭 or 別ファイル）
   - テストデータ定数の整理

2. 以下のリファクタリングパターンを適用する：

| パターン            | 適用箇所                     | 改善内容                         |
| ------------------- | ---------------------------- | -------------------------------- |
| Extract Helper      | 重複するMock設定             | `createMockSkillService` に集約  |
| Extract Constant    | ハードコードされた文字列     | テストデータ定数に移動           |
| Rename for Clarity  | 不明瞭な変数名               | テスト意図が読み取れる命名に変更 |
| Group Related Tests | 関連テストの論理的グループ化 | `describe` ブロックの再構成      |

3. リファクタリング後にテストを実行し、全テストがパスすることを確認する

**期待される成果物**:

- リファクタリング済み `skillIpc.integration.test.ts`

---

### タスク2: コードスメル検出と修正

**目的**: テストコード内のコードスメルを検出・修正する

**実行手順**:

1. 以下のコードスメルを検出する：

| コードスメル     | 検出方法                       | 修正方法                   |
| ---------------- | ------------------------------ | -------------------------- |
| マジックナンバー | ハードコードされた数値         | 定数に置換                 |
| 長いテストケース | 1つの `it` ブロックが30行以上  | ステップ分割 or ヘルパー化 |
| 過度なMock設定   | `beforeEach` が20行以上        | ファクトリ関数に置換       |
| 重複アサーション | 同じ検証パターンの繰り返し     | カスタムマッチャーに置換   |
| 不要なコメント   | コードで明らかな内容のコメント | 削除                       |

2. 検出したコードスメルを修正する
3. 修正後にテストを実行し、全テストがパスすることを確認する

**期待される成果物**:

- コードスメル修正済み `skillIpc.integration.test.ts`

---

### タスク3: 実装コードのリファクタリング（必要に応じて）

**目的**: Phase 5 で追加した実装コードの品質を改善する

**実行手順**:

1. Phase 5 で `skillHandlers.ts` や `channels.ts` に追加したコードを確認する
2. 既存コードとのスタイル統一を確認する：
   - ハンドラーの記述パターンが既存と一致しているか
   - エラーハンドリングパターンが統一されているか
   - チャネル定数の命名規則が統一されているか
3. 必要に応じてリファクタリングする
4. テストが全てパスすることを確認する

**期待される成果物**:

- リファクタリング済み実装コード（変更がある場合のみ）

---

### タスク4: リファクタリングログの記録

**目的**: 実施したリファクタリングの内容を記録する

**実行手順**:

1. 実施したリファクタリングの一覧を記録する
2. 各リファクタリングの理由と効果を記録する
3. `outputs/phase-08/refactoring-log.md` に記録する

**期待される成果物**:

- `outputs/phase-08/refactoring-log.md`

## 多角的チェック観点

| 観点   | 確認内容                               |
| ------ | -------------------------------------- |
| 可読性 | テストコードの意図が明確に読み取れるか |
| 保守性 | テスト追加・修正が容易な構造か         |
| DRY    | 重複コードが適切に共通化されているか   |
| 命名   | テストケース名・変数名が適切か         |
