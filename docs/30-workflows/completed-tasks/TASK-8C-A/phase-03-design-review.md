## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件定義レビュー

**目的**: Phase 1 の要件定義書と受け入れ基準の品質を検証する

**実行手順**:

1. `outputs/phase-01/requirements-definition.md` を読み、以下を確認する：
   - 全チャネル（`skill:list-available`, `skill:list-imported`, `skill:import`, `skill:remove`, `skill:get-detail`, `skill:execute`, `skill:abort`, `skill:get-status`, 権限チャネル）が分析されているか
   - 各チャネルのパラメータ型・戻り値型が正確に記録されているか
   - SkillService メソッドマッピングが正確か
   - 22テストケースの前提条件・操作・期待結果が全て定義されているか
   - 既存テストとの差別化が明確か

2. `outputs/phase-01/acceptance-criteria.md` を読み、以下を確認する：
   - 全受け入れ基準（AC-001〜AC-010）が検証可能な形式で記述されているか
   - 各基準の検証方法が具体的か

3. レビュー結果を記録する

**期待される成果物**:

- 要件定義レビュー結果（`outputs/phase-03/design-review-result.md` に含む）

---

### タスク2: 設計レビュー

**目的**: Phase 2 の統合テスト設計の品質を検証する

**実行手順**:

1. `outputs/phase-02/integration-test-design.md` を読み、以下の観点でレビューする：

| レビュー観点       | 確認項目                                                   | 判定基準                      |
| ------------------ | ---------------------------------------------------------- | ----------------------------- |
| 構造の妥当性       | describe/it 構造が22テストケースを網羅しているか           | 22 `it()` ブロックの存在      |
| Mock の正確性      | SkillService Mock が実際のインターフェースと一致しているか | 型チェック可能                |
| セキュリティ設計   | validateIpcSender のMock方針が適切か                       | 正常/異常系の両方がテスト可能 |
| ヘルパー関数       | 5つのヘルパー関数のシグネチャが実装可能か                  | 型が定義可能                  |
| テストデータ       | テストデータ定数が適切な型と値を持つか                     | 型整合性                      |
| OperationResult    | 戻り値パターンが `OperationResult<T>` に準拠しているか     | 仕様一致                      |
| 既存テストとの共存 | 既存テストファイルと名前空間・Mock設定が衝突しないか       | 独立実行可能                  |

2. 各観点を PASS / MINOR / MAJOR で判定する
3. `outputs/phase-03/design-review-result.md` に結果を記録する

**期待される成果物**:

- `outputs/phase-03/design-review-result.md`

---

### タスク3: ゲート判定

**目的**: Phase 3 のレビュー結果に基づきゲート判定を行う

**実行手順**:

1. 全レビュー項目の判定結果を集計する
2. 以下の基準でゲート判定を行う：

| 判定  | 条件                       | 次のアクション              |
| ----- | -------------------------- | --------------------------- |
| PASS  | 全項目が PASS              | Phase 4 に進む              |
| MINOR | MINOR 項目あり、MAJOR なし | 指摘事項を記録し Phase 4 へ |
| MAJOR | MAJOR 項目あり             | 該当Phase に差し戻す        |

3. MAJOR の場合の差し戻し先：
   - 要件の問題: Phase 1 に差し戻し
   - 設計の問題: Phase 2 に差し戻し

4. 判定結果を `outputs/phase-03/design-review-result.md` に追記する

**期待される成果物**:

- ゲート判定結果（`outputs/phase-03/design-review-result.md` に含む）
