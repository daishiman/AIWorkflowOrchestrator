## 目的

自動テストでは検証しきれない観点（テストの実行体験・ログ出力・エラーメッセージの可読性・テスト実行パフォーマンス）を手動で確認する。本タスクはテスト自体が成果物であるため、テストコードの「使いやすさ」と「保守しやすさ」を重点的に検証する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: テスト実行体験の確認

**目的**: テスト実行時の出力が分かりやすいことを確認する

**実行手順**:

1. テストを個別実行し、出力を確認する：

   ```bash
   pnpm --filter @repo/desktop vitest run apps/desktop/src/main/ipc/__tests__/skillIpc.integration.test.ts --reporter=verbose
   ```

2. 以下を確認する：

| 確認項目                  | 合格基準                                     | 結果   |
| ------------------------- | -------------------------------------------- | ------ |
| テストケース名の可読性    | 各 `it` の説明から何をテストしているか分かる | \_\_\_ |
| describe グループの論理性 | チャネルごとにグループ化されている           | \_\_\_ |
| 失敗時のエラーメッセージ  | どのアサーションが失敗したか一目で分かる     | \_\_\_ |
| テスト実行時間            | 全22テストが5秒以内に完了する                | \_\_\_ |

3. 結果を記録する

**期待される成果物**:

- テスト実行体験結果（`outputs/phase-11/manual-test-result.md` に含む）

---

### タスク2: テスト失敗シナリオの確認

**目的**: テストが正しい理由で失敗することを確認する

**実行手順**:

1. 意図的にテストを失敗させ、エラーメッセージの品質を確認する：
   - `SkillService` のMock戻り値を変更してテストを失敗させる
   - 失敗メッセージから原因が特定できることを確認する
   - 変更を元に戻す

2. 以下のシナリオを確認する：

| シナリオ                    | 確認内容                                 | 結果   |
| --------------------------- | ---------------------------------------- | ------ |
| Mock戻り値の不一致          | 期待値と実際値の差分が明確に表示されるか | \_\_\_ |
| ハンドラー未登録            | `undefined` エラーが分かりやすいか       | \_\_\_ |
| OperationResult形式の不一致 | success/data/error の差分が表示されるか  | \_\_\_ |

3. 結果を記録する

**期待される成果物**:

- 失敗シナリオ確認結果（`outputs/phase-11/manual-test-result.md` に含む）

---

### タスク3: テストコードの保守性確認

**目的**: テストコードの保守性を人間の目で確認する

**実行手順**:

1. テストコードを読み、以下を確認する：

| 確認項目                 | 合格基準                                         | 結果   |
| ------------------------ | ------------------------------------------------ | ------ |
| 新規チャネル追加の容易さ | 新しいテストケース追加時の手順が明確             | \_\_\_ |
| Mock設定の理解しやすさ   | Mock設定を読んでテスト意図が理解できる           | \_\_\_ |
| ヘルパー関数の再利用性   | ヘルパー関数が他テストでも使えるか               | \_\_\_ |
| テストデータの管理       | テストデータが一箇所で管理されているか           | \_\_\_ |
| コメントの適切さ         | 必要十分なコメントがあるか（多すぎず少なすぎず） | \_\_\_ |

2. 改善提案がある場合は記録する（Phase 10 で MINOR 判定のものも含む）
3. `outputs/phase-11/manual-test-result.md` に記録する

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md`

---

### タスク4: 統合実行確認

**目的**: デスクトップアプリ全体のテストと統合して問題がないことを手動確認する

**実行手順**:

1. デスクトップアプリ全体のテストを実行する：

   ```bash
   pnpm --filter @repo/desktop vitest run
   ```

2. 以下を確認する：
   - 全テストがパスする
   - テスト実行順序による失敗がない
   - メモリリークやタイムアウトがない

3. 結果を `outputs/phase-11/manual-test-result.md` に追記する

**期待される成果物**:

- 統合実行結果（`outputs/phase-11/manual-test-result.md` に含む）
