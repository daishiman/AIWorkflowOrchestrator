### タスク2: 最終レビュー

**目的**: 全成果物の品質を10観点でレビューする

**実行手順**:

1. 以下の10観点でレビューする：

| #   | レビュー観点       | 確認内容                                                              | 判定   |
| --- | ------------------ | --------------------------------------------------------------------- | ------ |
| 1   | 機能完全性         | 22テストケースが全て実装・パスしているか                              | \_\_\_ |
| 2   | コード品質         | ESLint / Prettier / TypeScript strict がパスするか                    | \_\_\_ |
| 3   | テスト品質         | テストが実際のIPC通信パスを検証しているか（Mock過多でないか）         | \_\_\_ |
| 4   | カバレッジ         | `skillHandlers.ts` 行カバレッジ90%以上を達成しているか                | \_\_\_ |
| 5   | セキュリティ       | validateIpcSender テスト・チャネルホワイトリスト準拠                  | \_\_\_ |
| 6   | ドキュメント整合   | テストケースが要件定義・設計書と一致しているか                        | \_\_\_ |
| 7   | エラーハンドリング | OperationResult パターンの正常系/異常系が全チャネルで検証されているか | \_\_\_ |
| 8   | 既存互換性         | 既存テストに影響がないか                                              | \_\_\_ |
| 9   | 型安全             | テストコードの型定義が正確か                                          | \_\_\_ |
| 10  | 保守性             | テストコードの追加・修正が容易な構造か                                | \_\_\_ |

2. 各観点を PASS / MINOR / MAJOR / CRITICAL で判定する
3. `outputs/phase-10/final-review-result.md` に記録する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`

---

### タスク3: ゲート判定

**目的**: レビュー結果に基づき最終ゲート判定を行う

**実行手順**:

1. 判定基準：

| 判定     | 条件                            | 次のアクション                     |
| -------- | ------------------------------- | ---------------------------------- |
| PASS     | 全項目 PASS                     | Phase 11 に進む                    |
| MINOR    | MINOR あり、MAJOR/CRITICAL なし | 未タスク指示書を作成し Phase 11 へ |
| MAJOR    | MAJOR あり                      | 該当 Phase に差し戻し              |
| CRITICAL | CRITICAL あり                   | Phase 1 に差し戻し（要件再確認）   |

2. MAJOR の差し戻し先：
   - 要件の問題: Phase 1
   - 設計の問題: Phase 2
   - テスト設計の問題: Phase 4
   - 実装の問題: Phase 5
   - テスト拡充の問題: Phase 6
   - カバレッジの問題: Phase 7
   - コード品質の問題: Phase 8

3. MINOR の場合、`agents/generate-unassigned-task.md` を使用して未タスク指示書を作成する

4. `outputs/phase-10/final-review-result.md` に判定結果を追記する

**期待される成果物**:

- ゲート判定結果（`outputs/phase-10/final-review-result.md` に含む）
