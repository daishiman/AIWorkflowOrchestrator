## 目的

Phase 5 で全22テストをパスさせた後、テストカバレッジの向上とエッジケースの追加を行う。`skillHandlers.ts` の行カバレッジ90%以上を目標に、未カバーのブランチ・例外パスを特定しテストを追加する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: カバレッジ測定と分析

**目的**: 現時点のテストカバレッジを測定し、未カバー箇所を特定する

**実行手順**:

1. カバレッジ付きでテストを実行する：

   ```bash
   pnpm --filter @repo/desktop vitest run --coverage apps/desktop/src/main/ipc/__tests__/skillIpc.integration.test.ts
   ```

2. `skillHandlers.ts` のカバレッジを確認する：
   - 行カバレッジ（目標: 90%以上）
   - ブランチカバレッジ（目標: 60%以上）
   - 関数カバレッジ（目標: 80%以上）

3. 未カバーの行・ブランチを一覧化する
4. 各未カバー箇所に対して追加テストケースを計画する

**期待される成果物**:

- カバレッジ分析結果（ドキュメントには含めず、タスク2の入力とする）

---

### タスク2: エッジケーステストの追加

**目的**: カバレッジギャップを埋めるエッジケーステストを追加する

**実行手順**:

1. 以下のエッジケースカテゴリからテストを追加する：

| カテゴリ         | テストケース例                                       |
| ---------------- | ---------------------------------------------------- |
| 境界値           | 空配列の返却、空文字列のスキル名                     |
| null/undefined   | パラメータが null/undefined の場合のエラー処理       |
| 並行呼び出し     | 同一チャネルへの複数同時呼び出し                     |
| セキュリティ異常 | `validateIpcSender` が失敗した場合のエラーレスポンス |
| 型不正           | 期待と異なる型のパラメータが渡された場合             |
| ハンドラー未登録 | 登録前のチャネル呼び出し                             |

2. `skillIpc.integration.test.ts` にエッジケーステストを追加する
3. 追加テストが全てパスすることを確認する

**期待される成果物**:

- エッジケーステストが追加された `skillIpc.integration.test.ts`

---

### タスク3: 統合テスト連携の検証

**目的**: IPC統合テストと関連コンポーネントの統合動作を確認する

**実行手順**:

1. IPC テストディレクトリ全体のテストを実行する：

   ```bash
   pnpm --filter @repo/desktop vitest run apps/desktop/src/main/ipc/__tests__/
   ```

2. 全テストが衝突なく実行されることを確認する
3. `skill` 関連のサービステストも実行し、統合に問題がないことを確認する：
   ```bash
   pnpm --filter @repo/desktop vitest run apps/desktop/src/main/services/skill/
   ```

**期待される成果物**:

- 統合テスト実行結果（タスク4で記録）

---

### タスク4: カバレッジ再測定

**目的**: エッジケース追加後のカバレッジを再測定する

**実行手順**:

1. カバレッジ付きで全テストを再実行する
2. カバレッジが目標値を達成しているか確認する：
   - 行カバレッジ: 90%以上
   - ブランチカバレッジ: 60%以上
   - 関数カバレッジ: 80%以上
3. 目標未達の場合、追加テストケースを検討する（Phase 7 で再確認）

**期待される成果物**:

- カバレッジ測定結果（Phase 7 の入力とする）

## 統合テスト連携

Phase 6 で以下の統合テスト観点を検証する：

- **クロステスト影響**: 新規テストが既存 `skillHandlers.test.ts` / `skillHandlers.integration.test.ts` と衝突しない
- **サービス統合**: SkillService の各サブコンポーネント（Scanner, Parser, ImportManager, Executor）のテストと矛盾しない
- **カバレッジ統合**: 全テストファイルの合計カバレッジが目標を達成している
