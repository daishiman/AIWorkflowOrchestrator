# Phase 9 因果ループ監査

## ループ分析

### ループL1: DI欠落再発ループ

1. Handler追加時にDI引数未注入
2. 実行時にenv fallbackへ退避
3. preflightとMain判定が乖離
4. 障害修正で暫定対応が増える
5. 構造複雑化で再びDI漏れ

- 破断策:
  - `registerAllIpcHandlers` で単一生成・単一路配線を固定
  - `ipc-double-registration` に第3引数+同一インスタンス検証を固定
- 現在判定: 破断済み

### ループL2: カバレッジ閾値誤判定ループ

1. 部分実行でglobal threshold fail
2. failを品質低下と誤解
3. 無関係修正を追加
4. ノイズ増加で真因追跡困難

- 破断策:
  - Phase 7で対象ファイルカバレッジを別管理
  - 全体閾値判定は専用ジョブで分離
- 現在判定: 部分破断（運用ルールの定着が残課題）

## SubAgent-D統合結論

- 既知ループ2件は対応策を明文化済み。

- 整合性: あり
