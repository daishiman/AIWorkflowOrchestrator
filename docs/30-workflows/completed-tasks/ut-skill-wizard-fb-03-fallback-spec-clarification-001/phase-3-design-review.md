## レビューチェックリスト

### 構造検証

| チェック項目                                         | 判定     | 備考                                      |
| ---------------------------------------------------- | -------- | ----------------------------------------- |
| 変更対象ファイルが全件特定されているか               | REQUIRED | Phase 2で変更対象一覧を確認               |
| AC-4への追記内容が具体的に記述されているか           | REQUIRED | 追記テキストが明示されているか            |
| テストケース設計（TC-FB03-01〜03）が完成しているか   | REQUIRED | 3ケース全件の入力・期待が定義されているか |
| フィールド独立推論性の定義が矛盾なく記述されているか | REQUIRED | 誤解パターン vs 正解パターンの明示        |

### 4条件評価

| 条件   | 評価観点                                                       | 合否基準                             |
| ------ | -------------------------------------------------------------- | ------------------------------------ |
| 価値性 | 同様の仕様揺れを将来タスクで繰り返さないコスト削減効果があるか | 明確なコスト削減効果が定義されている |
| 実現性 | docs-onlyタスクとして初回スコープに収まっているか              | コード変更なしで完結するか           |
| 整合性 | 既存のAC定義・テンプレートと矛盾しないか                       | 矛盾箇所がゼロ                       |
| 運用性 | 追記後に他タスク実行者がAC-4を参照して正しく理解できるか       | レビュアーが明確に理解できる記述     |

### 責務境界確認

| 境界                                     | 問題なし | 備考                                 |
| ---------------------------------------- | -------- | ------------------------------------ |
| docs更新とコード変更が混在していないか   | -        | docs-onlyであることを確認            |
| AC-4の変更がAC-1〜3に波及していないか    | -        | 既存ACへの影響がないことを確認       |
| テストケース追加が既存テストを壊さないか | -        | 追加のみで削除・変更がないことを確認 |

## フェーズゲート判定基準

### PASS条件（全て満たすとPhase 4へ進む）

- [ ] 変更対象ファイルが全件特定されている
- [ ] AC-4追記内容の具体的なテキストが確定している
- [ ] TC-FB03-01〜03のテストケースが入力・期待値付きで定義されている
- [ ] 4条件（価値性・実現性・整合性・運用性）が全てPASS
- [ ] 既存仕様との矛盾がゼロ

### FAIL条件（Phase 2へ差し戻し）

- 変更対象ファイルが未特定のものがある
- AC-4追記内容が「〜する」程度の抽象記述にとどまっている
- テストケースの期待値が「適切な値」など曖昧な表現になっている
- 4条件のいずれかがFAIL
