## 目的

Phase 5で実装したPermissionDialogコンポーネントのコード品質を向上させる。全テストがパスし続けることを確認しながら、可読性・保守性・SOLID原則への準拠を改善する。

## 実行タスク

### Task 1: コード品質分析

**目的**: 現在の実装の改善点を洗い出す

**手順**:

1. `PermissionDialog.tsx` を読み、以下の観点で分析する:

| 分析観点          | チェック内容                              |
| ----------------- | ----------------------------------------- |
| 単一責任原則(SRP) | コンポーネントが1つの責務に集中しているか |
| 関数の長さ        | 各関数が適切な長さ（30行以内目安）か      |
| 重複コード        | DRY原則に反する重複がないか               |
| 命名規則          | 変数名・関数名が意図を明確に表しているか  |
| 型安全性          | any型の使用がないか、型が厳密か           |
| コメント          | 不要なコメントや自明なコメントがないか    |

### Task 2: formatArgs関数の改善検討

**目的**: ヘルパー関数の保守性を向上させる

**手順**:

1. `formatArgs` の現在の実装を確認する
2. 以下の改善を検討する:

| 改善案                     | 適用条件                              | 判断 |
| -------------------------- | ------------------------------------- | ---- |
| ツール別フォーマッタの分離 | フォーマットロジックが3種類以上の場合 | □    |
| 型ガードの導入             | typeof チェックが複数ある場合         | □    |
| テスタビリティの向上       | 関数がエクスポート可能な形に分離      | □    |

**注意**: 過度な分離は避ける。現時点で3種類（command/path/JSON）のみであれば現状維持が適切な場合もある。

### Task 3: アクセシビリティ実装の品質確認

**目的**: アクセシビリティ実装のベストプラクティス準拠を確認する

**手順**:

1. フォーカストラップの実装を確認する
2. 以下の改善を検討する:

| 改善案                           | 理由                                       | 判断 |
| -------------------------------- | ------------------------------------------ | ---- |
| カスタムフック化（useFocusTrap） | 再利用可能性向上                           | □    |
| useCallback の活用               | ハンドラのメモ化で不要な再レンダリング防止 | □    |
| ref管理の見直し                  | refの数が多い場合の整理                    | □    |

### Task 4: スタイリングの最適化

**目的**: Tailwind CSSクラスの整理と最適化

**手順**:

1. 長いクラス文字列がある場合の改善を検討する:

| 改善案                       | 適用条件                    | 判断 |
| ---------------------------- | --------------------------- | ---- |
| cn() ユーティリティの活用    | 条件付きクラスがある場合    | □    |
| クラスの論理的なグルーピング | クラスが5個以上連続する場合 | □    |

### Task 5: テスト継続確認

**目的**: リファクタリング後に全テストがパスすることを確認する

**手順**:

1. リファクタリング後にテストを実行する:
   ```bash
   pnpm --filter @repo/desktop vitest run src/renderer/components/skill/__tests__/PermissionDialog.test.tsx
   ```
2. 全テストが PASS であることを確認する
3. カバレッジが低下していないことを確認する:
   ```bash
   pnpm --filter @repo/desktop vitest run --coverage src/renderer/components/skill/__tests__/PermissionDialog.test.tsx
   ```
4. `pnpm --filter @repo/desktop typecheck` で型チェック通過を確認する
5. `pnpm --filter @repo/desktop lint` でリント通過を確認する
