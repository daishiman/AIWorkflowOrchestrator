3. Phase 1の非機能要件（NFR-001〜NFR-012）を読む
4. 実装が各NFRを充足しているか確認する

| 確認項目                         | 判定 |
| -------------------------------- | ---- |
| 全FR（14件）が実装済み           | □    |
| 全NFR（12件）が実装済み          | □    |
| スコープ外の機能が混入していない | □    |

### Task 2: 設計整合性レビュー

**目的**: Phase 2の設計と実装の整合性を確認する

**手順**:

1. Phase 2のコンポーネント階層設計と実装を比較する
2. 状態管理設計と実装を比較する
3. アクセシビリティ設計と実装を比較する

| 確認項目                     | 判定 |
| ---------------------------- | ---- |
| コンポーネント構造が設計通り | □    |
| 状態管理が設計通り           | □    |
| Store接続が設計通り          | □    |
| ARIA属性が設計通り           | □    |
| スタイリングが設計通り       | □    |

### Task 3: テスト品質レビュー

**目的**: テストの網羅性と品質を確認する

**手順**:

1. Phase 4/6のテストコードを読む
2. Phase 7/9のカバレッジレポートを確認する

| 確認項目                       | 判定 |
| ------------------------------ | ---- |
| 全テストがPASS                 | □    |
| カバレッジ基準を満たしている   | □    |
| エッジケースがテストされている | □    |
| アクセシビリティテストがある   | □    |

### Task 4: 既存コードとの整合性レビュー

**目的**: 既存のコードベースとの整合性を確認する

**手順**:

1. 既存の `components/Permission/PermissionDialog.tsx` との関係を確認する
2. `components/skill/index.ts` のエクスポートが正しいことを確認する
3. Store（`skillSlice.ts`）との接続が正しいことを確認する

| 確認項目                               | 判定 |
| -------------------------------------- | ---- |
| 既存コンポーネントとの名前衝突がない   | □    |
| エクスポートが正しく設定されている     | □    |
| Store APIの使用方法が正しい            | □    |
| 型定義（SkillPermissionRequest）と整合 | □    |

### Task 5: ゲート判定

**目的**: 最終レビュー結果に基づきゲート判定を行う

**判定基準**:

| 判定     | 条件                       | 次のアクション          |
| -------- | -------------------------- | ----------------------- |
| PASS     | 全検証項目がクリア         | Phase 11 に進む         |
| MINOR    | 軽微な指摘のみ             | 指摘を記録し Phase 11へ |
| MAJOR    | 設計・実装に問題がある     | Phase 5 or 4 に戻る     |
| CRITICAL | 要件定義レベルの問題がある | Phase 1 に戻る          |
