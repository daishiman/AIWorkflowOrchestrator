## 目的

自動テストでは検証しきれないUI/UX、アクセシビリティ、レスポンシブデザインの観点でPermissionDialogコンポーネントを手動で検証する。

## 実行タスク

### Task 1: ビジュアル検証

**目的**: コンポーネントの視覚的な表示を確認する

**手順**:

1. Storybook または開発環境でPermissionDialogを表示する
2. 以下を目視確認する:

| 検証項目                           | 期待結果                             | 判定 |
| ---------------------------------- | ------------------------------------ | ---- |
| オーバーレイが画面全体を覆う       | `bg-black/50` の半透明オーバーレイ   | □    |
| ダイアログが画面中央に表示される   | `flex items-center justify-center`   | □    |
| ヘッダーに警告アイコンがある       | 黄色背景に「⚠️」アイコンとタイトル   | □    |
| ツール名がバッジ表示される         | 灰色背景のバッジ内にツール名         | □    |
| 引数がコードブロック内に表示される | `<pre>` タグ内にフォーマット済み引数 | □    |
| ボタンの色が仕様通り               | 拒否:赤系、1回許可:グレー、許可:青   | □    |
| 閉じるボタン（✕）がヘッダー右端    | ヘッダー右上に配置                   | □    |

### Task 2: インタラクション検証

**目的**: ユーザー操作の応答性を確認する

**手順**:

1. 各ボタンのクリック動作を確認する:

| 操作                       | 期待動作                         | 判定 |
| -------------------------- | -------------------------------- | ---- |
| 「拒否」ボタンクリック     | ダイアログが閉じる               | □    |
| 「1回許可」ボタンクリック  | ダイアログが閉じる               | □    |
| 「許可」ボタンクリック     | ダイアログが閉じる               | □    |
| チェックボックスをクリック | チェック状態がトグルする         | □    |
| 閉じるボタン（✕）クリック  | ダイアログが閉じる（拒否と同等） | □    |
| オーバーレイ部分をクリック | ダイアログが閉じない             | □    |

### Task 3: アクセシビリティ手動検証

**目的**: スクリーンリーダー・キーボード操作での動作を確認する

**手順**:

1. キーボード操作を確認する:

| 操作              | 期待動作                             | 判定 |
| ----------------- | ------------------------------------ | ---- |
| Tab               | フォーカスが次の要素に移動する       | □    |
| Shift+Tab         | フォーカスが前の要素に移動する       | □    |
| Tab（最後の要素） | フォーカスが最初の要素に戻る（循環） | □    |
| Escape            | ダイアログが閉じる（拒否と同等）     | □    |
| Enter             | フォーカス中のボタンが実行される     | □    |
| Space             | チェックボックスがトグルされる       | □    |

2. スクリーンリーダー互換性を確認する（可能な場合）:

| 確認項目                   | 期待結果                            | 判定 |
| -------------------------- | ----------------------------------- | ---- |
| ダイアログとして認識される | role="dialog" が読み上げられる      | □    |
| タイトルが読み上げられる   | aria-labelledby の参照先が読み上げ  | □    |
| 説明が読み上げられる       | aria-describedby の参照先が読み上げ | □    |

### Task 4: 表示パターン検証

**目的**: 異なるデータパターンでの表示を確認する

**手順**:

1. 以下のデータパターンで表示を確認する:

| パターン         | 入力データ                                               | 期待表示                     | 判定 |
| ---------------- | -------------------------------------------------------- | ---------------------------- | ---- |
| Bashコマンド     | `{ command: "npm install" }`                             | `npm install`                | □    |
| 長いBashコマンド | `{ command: "find / -name '*.log' -mtime +30 -delete" }` | コマンド全文（横スクロール） | □    |
| ファイルパス     | `{ path: "/home/user/documents/file.txt" }`              | パス全文                     | □    |
| 複雑なJSON引数   | `{ query: "test", options: { limit: 10 } }`              | インデント付きJSON           | □    |
| 理由あり         | `reason: "ファイルを読み取るため"`                       | 理由セクション表示           | □    |
| 理由なし         | `reason: undefined`                                      | 理由セクション非表示         | □    |

### Task 5: 手動テスト結果レポートの作成

**目的**: 手動テスト結果を文書化する

**手順**:

1. `outputs/phase-11/manual-test-result.md` を作成する
2. 全検証項目の結果を記載する
3. 発見された問題点（あれば）を記録する
4. スコープ外の改善提案があれば記録する
