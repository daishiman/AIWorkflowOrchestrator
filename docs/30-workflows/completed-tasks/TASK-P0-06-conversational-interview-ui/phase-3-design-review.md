## 目的

Phase 2 の設計成果物に対して多角的なレビューを実施し、Phase 4（テスト作成）以降への進行可否を判定する。設計の整合性、実現性、責務境界の妥当性を検証し、実装段階で手戻りが発生するリスクを最小化する。

## 背景

本タスクは既存コンポーネントの拡張が中心であり、新規アーキテクチャの導入は含まない。レビューの焦点は以下に絞る：

1. P0-06/P0-08 の状態境界設計が実装可能か
2. 既存IPCチャンネルで全要件を満たせるか
3. 変更スコープが最小限に抑えられているか

---

### タスク3: IPC 4層整合性チェック

**目的**: 本タスクで使用するIPCチャンネルが4層すべてで整合しているかを検証する。

#### 既存チャンネルの4層整合性確認

| チャンネル                                   | 1. 定数定義              | 2. ホワイトリスト | 3. ハンドラ登録 | 4. Preload API                 |
| -------------------------------------------- | ------------------------ | ----------------- | --------------- | ------------------------------ |
| `skill-creator:question-received`            | `channels.ts` に定義済み | 確認必要          | 確認必要        | `skill-creator-session-api.ts` |
| `skill-creator:answer`                       | `channels.ts` に定義済み | 確認必要          | 確認必要        | `skill-creator-session-api.ts` |
| `skill-creator:external-api-config-required` | `channels.ts` に定義済み | 確認必要          | 確認必要        | `skill-creator-session-api.ts` |
| `skill-creator:configure-api`                | `channels.ts` に定義済み | 確認必要          | 確認必要        | `skill-creator-session-api.ts` |

**注意**: Phase 5（実装）開始前に、上記4チャンネルの2-3層（ホワイトリスト・ハンドラ登録）が実際に実装されているかを `grep` で確認すること。未実装の場合は本タスクのスコープ外であり、別タスクとして起票する。

```bash
# Phase 5 開始前に実行する確認コマンド
grep -rn "question-received\|external-api-config-required" \
  apps/desktop/src/preload/ --include="*.ts"
grep -rn "question-received\|external-api-config-required" \
  apps/desktop/src/main/ --include="*.ts"
```

### タスク4: P0-06/P0-08 境界設計レビュー

**目的**: 状態境界の設計が実装レベルで十分に明確であり、P0-08との責務衝突が発生しないことを検証する。

#### 境界チェックリスト

| #   | チェック項目                                                                            | 判定 | 根拠                                                                 |
| --- | --------------------------------------------------------------------------------------- | ---- | -------------------------------------------------------------------- |
| 1   | `useInterviewState` に `localStorage` への保存ロジックが含まれていないか                | PASS | 設計で明示的に禁止。境界コメントで保護                               |
| 2   | `useInterviewState` に SQLite への書き込みロジックが含まれていないか                    | PASS | 設計で明示的に禁止。永続化はP0-08の責務                              |
| 3   | `ConversationalInterview` から IPC経由の永続化が行われていないか                        | PASS | ConversationalInterviewはPresentation層。IPC呼び出しはブリッジ層のみ |
| 4   | `workflowSnapshot` の `planId`/`resumeTokenEnvelope` がlocalStorageに保存されていないか | PASS | 設計でこれらの値への書き込みを禁止                                   |
| 5   | undo操作がP0-08の永続状態に影響しないか                                                 | PASS | undo はメッセージ配列の操作のみ（揮発性）                            |

**判定**: 境界設計は十分に明確。P0-08との責務衝突リスクなし。
