## 目的

Phase 5〜7 で実装・検証された動作を一切変えずに、コード品質を改善する。TDD の Refactor フェーズとして、テストが全 PASS であることを常に維持しながらコードスメルを除去し、可読性・保守性を向上させる。

## 背景

本タスクは既存コンポーネントの拡張が中心であり、大規模な構造変更は不要である。リファクタリングの焦点は以下に絞る：

1. ブリッジ層（SkillCreatorConversationPanel）の型変換ロジックが局所化されているか再確認
2. useInterviewState 内の状態管理ロジックに不要な複雑性がないか
3. ConversationalInterview 内で Presentation 層の責務を超えた処理が混入していないか
4. 命名の一貫性とコードの重複が最小限であるか

### タスク2: ConversationalInterview.tsx のリファクタリング

**目的**: Presentation 層としての責務を明確に保ちつつ、コードスメルを除去する。

#### チェック項目

| #   | リファクタリング観点        | 確認内容                                                         | アクション                                                        |
| --- | --------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | 型変換ロジックの局所化      | コンポーネント内に Session Bridge 型への直接参照がないか         | 発見した場合はブリッジ層（SkillCreatorConversationPanel）へ移動   |
| 2   | renderInputWidget の責務    | switch 文が肥大化していないか、各 case が適切な長さか            | 肥大化している場合は個別の render 関数に分割                      |
| 3   | useState の数               | 不要な useState が存在しないか、関連する状態を統合できないか     | 関連する状態は useReducer またはオブジェクト state への統合を検討 |
| 4   | イベントハンドラの命名      | `handleSubmit`, `handleUndo` 等の命名が一貫しているか            | 不一貫がある場合は `handle{Action}` パターンに統一                |
| 5   | data-testid の付与漏れ      | Phase 2 で定義した 9 項目の data-testid がすべて付与されているか | 漏れがある場合は追加                                              |
| 6   | JSDoc コメント              | 公開 Props の説明が JSDoc で記述されているか                     | 不足している場合は追加                                            |
| 7   | APIキーガイダンスの条件分岐 | ガイダンスバナーの表示条件が明確で、ネストが深くないか           | 早期 return パターンまたは変数抽出で可読性を向上                  |

**リファクタリング後の検証**:

```bash
pnpm --filter @repo/desktop test -- --testPathPattern="skill/ConversationalInterview"
```

### タスク3: useInterviewState.ts のリファクタリング

**目的**: 状態管理ロジックの整理と P0-06/P0-08 境界コメントの適切性を再確認する。

#### チェック項目

| #   | リファクタリング観点         | 確認内容                                                                            | アクション                                                             |
| --- | ---------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | P0-06/P0-08 境界コメント     | ファイル先頭の `@scope` JSDoc が設計通りに記述されているか                          | 不足がある場合は Phase 2 の設計に従い追加                              |
| 2   | 状態初期化ロジックの重複     | `reset()` と `resetInputValues()` に重複した初期化処理がないか                      | 共通部分を内部ヘルパー関数に抽出                                       |
| 3   | submission 構築ロジック      | `buildSubmission()` の分岐が各 InputKind に対して一貫したパターンか                 | パターンが不一致の場合は統一                                           |
| 4   | undo 復元ロジック            | `restoreAnswerInputs()` の各 InputKind 復元処理が secret の空文字復元を含め正しいか | ロジックの正しさをテストで担保しつつ、可読性を改善                     |
| 5   | 戻り値のオブジェクト構造     | カスタムフックの戻り値が論理的にグループ化されているか                              | 必要に応じてネストオブジェクトに整理（ただし既存テストとの互換を維持） |
| 6   | 永続化ロジックの混入チェック | `localStorage`, `SQLite`, IPC 経由の保存呼び出しが含まれていないか                  | 発見した場合は即時削除（P0-06 の責務外）                               |

**リファクタリング後の検証**:

```bash
pnpm --filter @repo/desktop test -- --testPathPattern="skill/useInterviewState"
```

### タスク4: SkillCreatorConversationPanel.tsx のリファクタリング

**目的**: ブリッジ層の型変換ロジックが局所化されていることを確認し、可読性を改善する。

#### チェック項目

| #   | リファクタリング観点       | 確認内容                                                            | アクション                                                               |
| --- | -------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | mapToRequest / mapToAnswer | 型変換関数がコンポーネント外に切り出されているか                    | インライン定義の場合はファイル内トップレベルまたは別ユーティリティへ移動 |
| 2   | IPC イベントハンドラの整理 | `useEffect` 内の IPC リスナー登録が適切にクリーンアップされているか | クリーンアップ漏れがある場合は修正                                       |
| 3   | APIキー状態管理            | `apiKeyStatus` の状態管理がブリッジ層に閉じているか                 | ConversationalInterview 側に漏れている場合はブリッジ層に集約             |
| 4   | 進捗情報の接続             | `syncTotalSteps` の呼び出しが適切なタイミングで行われているか       | 不要な再レンダリングを引き起こしていないか確認                           |
| 5   | エラーハンドリング         | IPC エラー時のフォールバック処理が適切か                            | エラー境界またはフォールバック UI が不足していれば追加                   |

**リファクタリング後の検証**:

```bash
pnpm --filter @repo/desktop test -- --testPathPattern="skill/(ConversationalInterview|useInterviewState|interview-widgets)"
```

### タスク5: コードスメル検出と SOLID 原則適用確認

**目的**: 横断的にコードスメルを検出し、SOLID 原則への準拠を確認する。

#### コードスメル検出チェックリスト

| #   | コードスメル種別 | 検出方法                                                     | 対処方針                              |
| --- | ---------------- | ------------------------------------------------------------ | ------------------------------------- |
| 1   | 重複コード       | 3 ファイル間で類似したロジック（特に型変換・バリデーション） | 共通ユーティリティへの抽出            |
| 2   | 長すぎる関数     | 30 行を超える関数がないか                                    | 論理的な単位で分割                    |
| 3   | マジックナンバー | ハードコードされた数値（タイムアウト値、配列インデックス等） | 名前付き定数への抽出                  |
| 4   | 不必要な状態変数 | 他の状態から導出可能な値が useState で管理されていないか     | `useMemo` または算出プロパティへ変換  |
| 5   | 命名の不一貫性   | 同じ概念に対して異なる命名パターンが使われていないか         | 統一的な命名規則を適用                |
| 6   | 過度なネスト     | 3 段以上のネストがある条件分岐                               | 早期 return、ガード節パターンへの変換 |

#### SOLID 原則チェック

| 原則                             | 確認内容                                                         | 判定基準                                                             |
| -------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------- |
| **S** - 単一責任原則             | 各ファイルが 1 つの責務に専念しているか                          | ConversationalInterview=表示、useInterviewState=状態、Panel=ブリッジ |
| **O** - 開放閉鎖原則             | 新しい InputKind の追加が既存コードの変更最小限で可能か          | renderInputWidget の switch 文に case を追加するだけで対応可能か     |
| **L** - リスコフの置換原則       | Props の型が適切に定義され、型制約を満たしているか               | optional Props のデフォルト値が安全に動作するか                      |
| **I** - インターフェース分離原則 | ConversationalInterview の Props が過度に肥大化していないか      | 不要な Props が含まれていないか                                      |
| **D** - 依存性逆転原則           | ConversationalInterview がブリッジ層の具体実装に依存していないか | Props（コールバック）による依存性注入パターンが守られているか        |
