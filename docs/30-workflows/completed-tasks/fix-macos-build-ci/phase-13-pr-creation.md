## 目的

修正をPR作成してレビュー・マージ可能な状態にし、CIの通過を確認する。

## 背景

全Phaseが完了したら、PRを作成してコードレビューとマージを行う。

---

## ⚠️ PR作成に関する重要な注意【必須確認】

**PR作成は自動実行しない。必ずユーザーの明示的な許可を得てから実行すること。**

| 禁止事項                                     | 理由                                           |
| -------------------------------------------- | ---------------------------------------------- |
| 勝手にPRを作成する                           | レビュー前の変更がリモートに反映されてしまう   |
| ユーザー確認なしで`/ai:diff-to-pr`を実行する | 意図しないブランチやコミットが作成される可能性 |
| ローカル確認をスキップする                   | 動作確認されていないコードがPRに含まれる       |

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ローカル確認【PR作成前に必須】

**目的**: PR作成前にローカルでの最終確認を行う

**実行手順**:

1. `pnpm install` を実行
2. `pnpm --filter @repo/shared build` を実行
3. `pnpm --filter @repo/desktop build` を実行
4. `pnpm lint` を実行
5. `pnpm typecheck` を実行
6. 全てが成功することを確認

**期待される成果物**:

- ローカル確認完了の記録

---

### タスク2: ユーザーにPR作成の許可を確認【必須】

**目的**: ユーザーの明示的な許可を得る

**実行手順**:

1. 変更内容のサマリーをユーザーに提示
2. PR作成の許可を確認
3. ユーザーの承認を待つ
4. 承認が得られた場合のみ次のタスクへ

**期待される成果物**:

- ユーザー承認の記録

---

### タスク3: PR作成

**目的**: `/ai:diff-to-pr` スキルを使用してPRを作成する

**実行手順**:

1. ユーザー許可後、`/ai:diff-to-pr` を実行
2. ブランチのプッシュを確認
3. PRの作成を確認
4. PR URLを記録

**期待される成果物**:

- PR URL

---

### タスク4: CI通過確認

**目的**: PRのCIが通過することを確認する

**実行手順**:

1. PRのCI実行状況を監視
2. 全CIジョブの成功を確認
3. 失敗がある場合は原因を特定・修正
4. CI通過を確認

**期待される成果物**:

- CI通過確認の記録

---

### タスク5: タスク完了処理

**目的**: タスクディレクトリを完了タスクフォルダに移動する

**実行手順**:

1. PRがマージされた後（またはマージ準備完了後）
2. タスクディレクトリを `completed-tasks/` に移動
3. `artifacts.json` のステータスを `completed` に更新
4. 変更をコミット・プッシュ

```bash
# タスクディレクトリの移動
mv docs/30-workflows/fix-macos-build-ci/ docs/30-workflows/completed-tasks/

# artifacts.json の更新
# status: "completed" に変更

# コミット
git add docs/30-workflows/
git commit -m "docs(workflows): fix-macos-build-ciをcompleted-tasksに移動"
git push
```

**期待される成果物**:

- `completed-tasks/` に移動されたタスクディレクトリ
