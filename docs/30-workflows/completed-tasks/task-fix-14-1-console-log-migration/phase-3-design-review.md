## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物を多角的にレビューし、Phase 4以降に進むかどうかを判定する。

## 実行タスク

### Task 1: 要件レビュー

| チェック項目         | 確認内容                                     |
| -------------------- | -------------------------------------------- |
| 対象ファイル網羅性   | スキル関連サービス全ファイルを確認したか     |
| 箇所数の正確性       | grep実行で実測値を確認したか                 |
| 受入基準の検証可能性 | 各受入基準が自動化可能または手動で検証可能か |
| スコープ明確性       | 含む/含まないが明確に定義されているか        |

### Task 2: 設計レビュー

| チェック項目            | 確認内容                                                |
| ----------------------- | ------------------------------------------------------- |
| ログレベルの妥当性      | error/warn/info/debug の使い分けが適切か                |
| モックパターンの統一性  | テスト全体で同一のモックパターンを使用するか            |
| debugフラグ削除の妥当性 | `log.debug` への移行でdebugフラグが不要になることの確認 |
| プレフィックス形式      | `[ClassName]` 形式が既存パターンと一致するか            |
| セキュリティ確認        | ログメッセージに機密情報が含まれていないか              |

### Task 3: レビュー判定

#### 判定基準

| 判定          | 条件                                   |
| ------------- | -------------------------------------- |
| PASS          | 全チェック項目が問題なし → Phase 4 へ  |
| MINOR         | 軽微な指摘あり → 指摘対応後 Phase 4 へ |
| MAJOR（要件） | 要件に重大な問題 → Phase 1 へ          |
| MAJOR（設計） | 設計に重大な問題 → Phase 2 へ          |
