### 改善点 1: Phase 11 簡略化オプション

**対象スキル**: task-specification-creator

**現状の課題**:
console から electron-log への移行のようなリファクタリングタスクでは、UI変更が一切ないため、Phase 11（手動テスト）がほぼ不要になるケースがある。現在の Phase 仕様書テンプレートでは、手動テストの実施が必須となっており、「UI変更なし」の場合でも形式的にレポートを作成する必要がある。

**改善案**:
Phase 仕様書テンプレートに「UI変更なしの場合は Phase 11 を自動テスト確認のみに簡略化」するオプションを追加する。

**具体的な変更案**:

```markdown
## Phase 11: 手動テスト

### UI変更有無の判断

- [ ] 本タスクにUI変更が含まれるか確認

#### UI変更ありの場合

- [ ] 手動UIテスト実施（通常フロー）

#### UI変更なしの場合（リファクタリング、バックエンド変更等）

- [ ] 自動テスト全PASS確認
- [ ] 変更対象ファイルの grep 確認
- [ ] 「UI変更なしのため手動UIテスト不要」とレポートに記載
```

**期待効果**: リファクタリングタスクでの Phase 11 所要時間を短縮し、形式的な作業を削減する。

---

### 改善点 2: electron-log モックのテストテンプレート化

**対象スキル**: task-specification-creator

**現状の課題**:
本タスクでは、electron-log モックを9つのテストファイルに手動で追加する必要があった。Main Process のサービス層テストでは、electron-log のモックがほぼ必須であるにもかかわらず、テストテンプレートにデフォルトで含まれていない。

**改善案**:
テスト作成フェーズ（Phase 4）のテンプレートに、Main Process サービス層のテストで使用する electron-log モックをデフォルトで含める。

**具体的なテンプレート追加案**:

```typescript
// Main Process サービス層テストの標準モック
vi.mock("electron-log", () => ({
  default: {
    error: vi.fn(),
    warn: vi.fn(),
    info: vi.fn(),
    debug: vi.fn(),
  },
}));
```

**期待効果**: 新規テスト作成時の electron-log モック追加忘れを防止し、テスト実行時の stdout 汚染（P20 パターン）を予防する。
