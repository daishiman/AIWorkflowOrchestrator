# Phase 1 成果物: 要件定義書

> タスクID: TASK-IMP-CANONICAL-BRIDGE-LEDGER-GOVERNANCE-001
> 作成日: 2026-03-23
> Phase: 1 - 要件定義

## 1. 機能要件（Functional Requirements）

### FR-1: Canonical Source Table 定義

governance 対象となる全正本ファイルの一覧を table 形式で管理する。

| 要件ID | 要件                                                                                     | 検証方法                         |
| ------ | ---------------------------------------------------------------------------------------- | -------------------------------- |
| FR-1.1 | 台帳の三層構造（Entrypoint / Execution / Completion / Backlog）が table で定義されている | table 存在確認                   |
| FR-1.2 | 各正本ファイルの canonical path が絶対パスで記載されている                               | path 存在確認（`ls` で検証可能） |
| FR-1.3 | 各ファイルの責務・更新権限者・更新タイミングが記載されている                             | 3列すべてに値が入っている        |

### FR-2: Compatibility Bridge Rule 定義

旧パスと新パスの対応関係を bridge rule として定義する。

| 要件ID | 要件                                                                                      | 検証方法             |
| ------ | ----------------------------------------------------------------------------------------- | -------------------- |
| FR-2.1 | legacy-ordinal-family-register.md と canonical source table の cross-reference が存在する | 相互参照リンク確認   |
| FR-2.2 | 旧パスへのアクセスを canonical パスへリダイレクトするルールが明文化されている             | ルール文書の存在確認 |
| FR-2.3 | bridge rule の有効期限（deprecation timeline）が定義されている                            | 期限値の存在確認     |

### FR-3: State 遷移定義

spec_created / implementation_ready / completed の三状態遷移を厳密に定義する。

| 要件ID | 要件                                                                                     | 検証方法                |
| ------ | ---------------------------------------------------------------------------------------- | ----------------------- |
| FR-3.1 | 各状態の進入条件が Phase 番号ではなく成果物ベースで定義されている                        | 成果物条件の存在確認    |
| FR-3.2 | 設計タスク（type: design）と実装タスク（type: implementation）で遷移条件が区別されている | type 別条件の存在確認   |
| FR-3.3 | Phase 10 MINOR 判定後の遷移パスが明文化されている                                        | 遷移パス記載確認        |
| FR-3.4 | 逆遷移（rollback）の条件と手順が定義されている                                           | rollback 手順の存在確認 |

### FR-4: Same-Wave 更新ルール

task-workflow / backlog / lessons / legacy register の同期手順を定義する。

| 要件ID | 要件                                                                       | 検証方法               |
| ------ | -------------------------------------------------------------------------- | ---------------------- |
| FR-4.1 | Phase 12 完了時の同期チェックリストが定義されている                        | チェックリスト存在確認 |
| FR-4.2 | 同期対象ファイルの完全リスト（5カテゴリ以上）が存在する                    | リスト行数確認         |
| FR-4.3 | サブエージェント分割の上限（3ファイル以下/エージェント）が明記されている   | 数値制約の存在確認     |
| FR-4.4 | Mirror sync（.claude/ → .agents/）の実行手順と確認コマンドが記載されている | コマンド例の存在確認   |

### FR-5: Follow-up Formalization ルール

未タスクの formalization と current/baseline 切り分けを定義する。

| 要件ID | 要件                                                                       | 検証方法                   |
| ------ | -------------------------------------------------------------------------- | -------------------------- |
| FR-5.1 | 三ステップ管理（指示書作成 → テーブル登録 → リンク追加）が必須化されている | 3ステップ手順の存在確認    |
| FR-5.2 | 設計タスクでも三ステップが省略不可であることが明記されている               | 例外なし条件の記載確認     |
| FR-5.3 | current → baseline 移管の条件（wave 完了後）が定義されている               | 移管条件の存在確認         |
| FR-5.4 | GitHub Issue の同期（再評価クローズ時の同時 Close）が手順化されている      | Issue Close 手順の存在確認 |

## 2. 非機能要件（Non-Functional Requirements）

### NFR-1: 可読性

| 要件ID  | 要件                                                                   |
| ------- | ---------------------------------------------------------------------- |
| NFR-1.1 | governance 仕様書は Phase 12 Part 1 形式で中学生レベルの概念説明を含む |
| NFR-1.2 | table / checklist / command example で検証手順を具体化する             |

### NFR-2: 決定論性

| 要件ID  | 要件                                               |
| ------- | -------------------------------------------------- |
| NFR-2.1 | 曖昧表現（「適切に」「必要に応じて」）を使用しない |
| NFR-2.2 | 同期手順は bash コマンドレベルで再現可能にする     |

### NFR-3: 耐障害性

| 要件ID  | 要件                                                         |
| ------- | ------------------------------------------------------------ |
| NFR-3.1 | サブエージェント中断時の復旧手順を含む（P43 対策）           |
| NFR-3.2 | rate limit 発生時に changelog が不整合にならない仕組みを含む |
