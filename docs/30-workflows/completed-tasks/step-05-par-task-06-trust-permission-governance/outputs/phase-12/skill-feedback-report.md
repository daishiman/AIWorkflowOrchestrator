## 改善提案の詳細

### SF-01: 設計タスク Phase 11 テンプレート

**観察した事実**:

本タスクの Phase 11 仕様書（`phase-11-manual-test.md`）には「テスト方式: CLI 環境での設計文書ウォークスルー（P53対策）」と明記されており、
CLI 環境でのスクリーンショット取得不可問題（P53）への対応が仕様レベルで組み込まれていた。
この点は適切に機能した。

**残存する問題**:

一方で、テストケース（TC-01〜TC-07）のテーブルに「スクリーンショット取得」列や「画面確認」列が含まれていないことを
明示するフォーマット定義がテンプレートに存在しない。
将来の設計タスクで Phase 11 テンプレートをそのまま流用した場合、担当者が「スクリーンショットを撮るべきか」と迷うリスクがある。

**提案する改善**:

`task-specification-creator` スキルの Phase 11 テンプレートに「設計タスク専用セクション」を追加し、
以下を標準化する。

```markdown
## テスト方式（設計タスク）

| 項目       | 値                                                        |
| ---------- | --------------------------------------------------------- |
| テスト方式 | 設計文書ウォークスルー（P53対策: スクリーンショット不要） |
| 検証対象   | 設計文書の整合性・完全性・TASK-08との接続品質             |
| 合否判定   | 設計ウォークスルー結果の PASS/MINOR/MAJOR/CRITICAL        |
```

**対応推奨タイミング**: 次回の設計タスク（TASK-SKILL-LIFECYCLE-07 等）の Phase 11 作成前。

---

### SF-02: Phase 12 システム仕様書更新ワークフロー

**観察した事実**:

本タスクの Phase 12 仕様書（`phase-12-documentation.md`）Task 2 では
`.claude/skills/` 配下のシステム仕様書を直接更新する手順が定義されている。
しかし worktree 環境では `.claude/skills/` のファイルが main ブランチや他の worktree と共有されており、
設計タスクの途中段階でこれらを更新すると、他のタスクとのコンフリクトリスクが生じる。

P26（システム仕様書更新遅延）は「Phase 12 完了時点で更新する。PR マージを待たない」と指示しているが、
worktree 環境での並列開発においてこのルールが機能するかの検証が不足している。

**提案する改善**:

設計タスクの Phase 12 において、以下の2段階方式を標準化する。

- **Phase 12 で行うこと**: `system-spec-update-summary.md` に更新内容の全文（追加・変更・削除の差分）を記録する
- **Phase 13 で行うこと**: `system-spec-update-summary.md` の内容を `.claude/skills/` に実際に適用し、`git diff --stat -- .claude/skills/` で確認する

この方式により、P26（更新遅延防止）の意図を維持しながら worktree 環境での安全性を確保できる。

**対応推奨タイミング**: 次回の設計タスク開始前に `task-specification-creator` スキルの Phase 12 テンプレートを更新する。

### SF-03: 未タスク検出パターン（テンプレート）

**観察した事実**:

本タスクで検出した未タスク 8 件のうち 5 件（UT-06-001〜005）が「型定義→実装」パターンであった。
これは設計タスクでは予測可能なパターンであり、Phase 4（テスト作成）または Phase 12（未タスク検出）の開始時点で
テンプレートから自動的に候補として示されると検出効率が向上する。

**提案する改善**:

`task-specification-creator` スキルの設計タスク向け Phase 12 テンプレートの「未タスク検出チェックリスト」に
以下のパターンを追加する。

```markdown
### 設計タスク特有の未タスク検出パターン

- [ ] 「型定義→実装」パターン: 本タスクで定義した型/インターフェースに対して、
      具象クラス・定数実装・永続化ロジックが未実装の場合は未タスクとして登録する
- [ ] 「契約→テスト」パターン: 本タスクで定義した契約・仕様に対して、
      カバレッジギャップ（高リスク組合せ等）が存在する場合は未タスクとして登録する
- [ ] 「UI仕様→コンポーネント実装」パターン: 挿入点・表示条件が定義されているが
      React コンポーネントが未実装の場合は未タスクとして登録する
- [ ] 「仕様書間差異→設計決定」パターン: 2つ以上の仕様書で同一事項の記述が異なる場合は
      設計決定書の作成タスクとして登録する
```

**対応推奨タイミング**: 次回の設計タスク（TASK-SKILL-LIFECYCLE-07 等）の Phase 12 作成前。
