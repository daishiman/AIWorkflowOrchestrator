## 1. テンプレート改善

### 提案: blocked 分岐フローの Phase 仕様書テンプレート化

本タスクでは前提タスク（Task12 Phase 5）が未完了のため blocked 状態が発生した。
Phase 1 の要件定義で P50 チェックを実施し、blocked 分岐の方針を決定した。

このパターンは仕様書同期タスクで頻出するため、以下の標準化を提案する:

| 項目                     | 現状                 | 提案                                                                          |
| ------------------------ | -------------------- | ----------------------------------------------------------------------------- |
| P50 チェック位置         | Phase 1 で都度実施   | Phase 仕様書テンプレートに P50 チェックセクションを標準配置                   |
| blocked 分岐の判定基準   | タスクごとに都度判断 | 「設計確定値あり → 先行実施」「設計未確定 → 待機」の2パターンをテンプレート化 |
| P65 注記の付与タイミング | 実装時に都度判断     | blocked 先行実施時の必須ステップとしてチェックリストに追加                    |

## 2. ワークフロー改善

### 提案: blocked 分岐パターンの標準化

仕様書同期タスクにおける blocked 分岐の判定フロー:

```
前提タスクの Phase 5 完了?
  |
  +-- YES --> 通常フロー（実値参照で更新）
  |
  +-- NO --> 設計書に確定値あり?
              |
              +-- YES --> 先行実施 + P65注記付与
              |
              +-- NO --> 待機（前提タスク完了まで保留）
```

このフローを `phase-templates.md` の「仕様書同期タスク」セクションに追加することで、判断の一貫性を確保できる。

## 3. ドキュメント改善

### 提案: 仕様書同期タスク専用ガイドライン

通常の実装タスクと異なり、仕様書同期タスクでは:

- コード変更がない（仕様書のみの更新）
- Phase 4-9 が大幅に簡略化される（テスト=grep検証、実装=仕様書編集）
- カバレッジ基準が「参照箇所の網羅率」に置き換わる

これらの特性を反映した軽量版ワークフローガイドを作成することで、不要な Phase のスキップ判断が統一される。
