## 目的

実装開始前に要件・設計の妥当性を検証し、Phase 4（テスト作成）への進行可否を判定する。

## 判定基準

| 判定  | 条件             | 対応                         |
| ----- | ---------------- | ---------------------------- |
| PASS  | 全観点で問題なし | Phase 4へ進行                |
| MINOR | 軽微な指摘あり   | 指摘対応後Phase 4へ進行      |
| MAJOR | 重大な問題あり   | 影響範囲に応じて戻り先を決定 |

## レビュー観点

### 1. 要件の完全性

| チェック項目                                  | 結果 | 備考                                   |
| --------------------------------------------- | ---- | -------------------------------------- |
| 全ての重複型が特定されているか                | -    | 6型 + 追加型6型を特定                  |
| 各型の差異が明確に文書化されているか          | -    | Phase 2 で詳細設計済み                 |
| 受け入れ基準（AC-1〜4）が検証可能か           | -    | TypeScript型チェック、テスト通過で検証 |
| Single Source of Truth 原則が遵守されているか | -    | 正本への統一を設計                     |

### 2. 設計の妥当性

| チェック項目                           | 結果 | 備考                                            |
| -------------------------------------- | ---- | ----------------------------------------------- |
| 型統合設計が後方互換性を維持しているか | -    | SkillExecutionRequest: skillId→skillName 要確認 |
| Discriminated Union への移行が適切か   | -    | SkillStreamMessage の変換ロジック要確認         |
| 依存方向（apps → packages）が正しいか  | -    | 一方向依存を維持                                |
| 正本への追加型が適切に設計されているか | -    | RetryConfig 等の移行設計済み                    |

### 3. 影響範囲の網羅性

| チェック項目                           | 結果 | 備考                              |
| -------------------------------------- | ---- | --------------------------------- |
| 直接影響ファイルが全て特定されているか | -    | SkillExecutor.ts, skill.ts を特定 |
| 間接影響ファイルの調査が必要か         | -    | IPC、Renderer、テストの確認必要   |
| 破壊的変更のリスクが評価されているか   | -    | skillId→skillName の変更は注意    |

### 4. リスク評価

| リスク項目                                      | 影響度 | 対策                           |
| ----------------------------------------------- | ------ | ------------------------------ |
| skillId と skillName の不一致による実行時エラー | 高     | 全参照箇所の網羅的な検索と修正 |
| SkillStreamMessage 変換ロジックの不整合         | 中     | 段階的移行、型ガード導入       |
| 既存テストの失敗                                | 中     | 型変更と同時にテスト修正       |
| IPC チャンネルの型不整合                        | 中     | Preload 層の型定義も同時に確認 |

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点       | 確認項目                                 | 結果 |
