## 発見事項一覧

### F-001: P41影響によるFunc% 0%問題

- **カテゴリ**: 既知制約
- **重要度**: 情報（INFO）
- **対象ハンドラ**: skill:list, skill:scan, skill:getImported 他
- **詳細**: skill:list/scan は Line 92-100% なのに Func 0% となる。これは P41（v8 カバレッジプロバイダのインライン関数カウント）の影響であり、`validateIpcSender` のオプションオブジェクト内の `getAllowedWindows` arrow function がカバレッジプロバイダに独立した関数としてカウントされるが、テスト中に実行されないためである。
- **スクリプトの対応**: P41注記がレポートのサマリー末尾に正しく表示されていることを確認した。
- **対応**: 不要（既知の仕様であり、P41注記で利用者に周知済み）

### F-002: schedule/docs系ハンドラのカバレッジ0%

- **カテゴリ**: 未タスク候補
- **重要度**: 中（MEDIUM）
- **対象ハンドラ**: skill:schedule:list, skill:schedule:create, skill:schedule:update, skill:schedule:delete, skill:docs:list, skill:docs:get, skill:docs:templates
- **詳細**: schedule系4ハンドラおよびdocs系3ハンドラはテストが未作成であり、Line/Branch/Func全て0%である。これらのハンドラは TASK-9G（schedule）、TASK-9I（docs）で実装されたが、対応するユニットテストが未作成のまま残存している。
- **対応**: Phase 12で未タスク候補として記録し、後続タスクでテスト追加を検討する。

### F-003: JSON形式出力の有用性

- **カテゴリ**: 正常動作確認
- **重要度**: 情報（INFO）
- **詳細**: `--format json` オプションによるJSON形式出力が正常に動作することを確認した。出力されるJSONは以下の用途に活用可能である:
  - CI/CDパイプラインでのカバレッジゲート自動判定
  - カバレッジ推移のトラッキング（JSONをDBに保存）
  - 他のレポートツールとの連携
- **対応**: 不要（正常動作確認済み）

### F-004: --threshold オプションの未実装

- **カテゴリ**: 改善提案
- **重要度**: 低（LOW）
- **詳細**: 現在のスクリプトではカバレッジ判定閾値がハードコードされている（Line 80%, Branch 60%, Function 80%）。プロジェクトやチームによって異なる閾値を適用したいケースが考えられるため、`--threshold` オプションでカスタム閾値を設定できる機能は将来のタスク候補となる。
- **対応**: Phase 12で未タスク候補として記録する（優先度は低い）。

### F-005: ハンドラ単位測定の価値実証

- **カテゴリ**: 正常動作確認
- **重要度**: 情報（INFO）
- **詳細**: ファイル全体の平均Line Coverageは27.7%であり、プロジェクトの最低基準（80%）を大きく下回る。しかし、ハンドラ単位で見ると skill:import は100%、skill:remove は100%であり、テストが作成済みのハンドラは基準を充足している。この結果は、ファイル全体のカバレッジだけでは個別ハンドラのテスト状況を正確に把握できないことを示しており、ハンドラ単位の粒度で測定するスクリプトの価値を実証した。
- **対応**: 不要（設計意図どおりの動作確認）
