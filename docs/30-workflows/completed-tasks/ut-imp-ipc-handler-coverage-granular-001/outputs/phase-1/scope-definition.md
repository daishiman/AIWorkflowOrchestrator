## 1. スコープ「含むもの」

### 1.1 カバレッジ集計スクリプト

**ファイルパス**: `apps/desktop/scripts/coverage-by-handler.ts`

| 機能                           | 詳細                                                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| TypeScript AST 解析            | `ts-morph` を使用して `ipcMain.handle()` のコールバック関数の開始行・終了行・チャンネル名を検出する。                                |
| v8 カバレッジ JSON 解析        | Vitest が出力した `coverage-final.json` を読み込み、行・関数・分岐ごとのヒットカウントを解析する。                                   |
| ハンドラ単位カバレッジ算出     | ハンドラ行範囲と v8 カバレッジデータを突合し、Line/Branch/Function カバレッジを個別に算出する。                                      |
| JSON・Markdown レポート出力    | ハンドラごとの `{ channel, startLine, endLine, lines, branches, functions }` を JSON 出力し、Markdown テーブルを標準出力に出力する。 |
| 修正対象ハンドラ指定オプション | `--target {channel}` オプションで修正対象ハンドラを指定する（複数指定可）。                                                          |
| Phase 7 判定（PASS/FAIL）      | Rule-1〜Rule-4 に基づき、修正対象ハンドラのカバレッジが基準を満たすかを判定し、PASS/FAIL と終了コードを出力する。                    |
| 複数ファイル対応の汎用設計     | `--file {path}` オプションで任意の TypeScript ファイルを解析対象に指定できる設計とする。                                             |

### 1.2 集計スクリプトのテスト

**ファイルパス**: `apps/desktop/scripts/coverage-by-handler.test.ts`

| テスト種別               | 詳細                                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| AST 解析テスト           | フィクスチャ TypeScript ファイルを入力として、ハンドラ一覧（チャンネル名・行範囲）が正しく検出されることを検証する。 |
| カバレッジ算出テスト     | モックカバレッジデータを使用して、ハンドラ単位の Line/Branch/Function カバレッジが正しく算出されることを検証する。   |
| エラーハンドリングテスト | 存在しないファイル・不正 JSON・必須引数欠落に対して正しいエラーが発生することを検証する。                            |

| パフォーマンステスト     | `skillHandlers.ts` 相当のフィクスチャで実行時間が 5秒以内であることを検証する。                                      |

## 3. Phase 7 判定ルール（Rule-1〜Rule-4）

Phase 7（カバレッジ確認）において、集計スクリプトの出力を用いて以下の4ルールで PASS/FAIL を判定する。

### Rule-1: 修正対象ハンドラ基準充足

| 項目     | 内容                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| ルールID | Rule-1                                                                                                                              |
| ルール名 | 修正対象ハンドラ基準充足                                                                                                            |
| 条件     | `--target` で指定した全ての修正対象ハンドラの Line Coverage が 80% 以上、Function Coverage が 80% 以上、Branch Coverage が 60% 以上 |
| 判定     | PASS                                                                                                                                |
| 備考     | 修正対象ハンドラが複数の場合、全てのハンドラが基準を満たす場合のみ PASS。1つでも未達の場合は FAIL。                                 |

### Rule-2: ファイル全体基準未達の許容

| 項目     | 内容                                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ルールID | Rule-2                                                                                                                                                   |
| ルール名 | ファイル全体基準未達の許容                                                                                                                               |
| 条件     | ファイル全体のカバレッジが最低基準未達であっても、未達の原因が修正対象外ハンドラに限定される場合（修正対象ハンドラ自体は Rule-1 を満たす）               |
| 判定     | PASS                                                                                                                                                     |
| 備考     | Rule-2 を適用した場合、未カバーハンドラ名を出力に含める。Rule-4 との優先関係: Rule-4（Branch Coverage 全体）は Rule-2 で許容されない（別途確認が必要）。 |

### Rule-3: 未カバーハンドラの未タスク化

| 項目     | 内容                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| ルールID | Rule-3                                                                                                      |
| ルール名 | 未カバーハンドラの未タスク化                                                                                |
| 条件     | Rule-2 を適用した場合（ファイル全体が基準未達だが修正対象ハンドラは PASS）                                  |
| 必須対応 | Phase 12（ドキュメント）の未タスク検出工程で、未カバーハンドラのテスト追加タスクを以下3ステップで登録する。 |
|          | （1）`docs/30-workflows/unassigned-task/` に指示書を作成する                                                |
|          | （2）`task-workflow.md` の残課題テーブルに登録する                                                          |
|          | （3）関連仕様書に参照リンクを追加する                                                                       |
| 判定     | 必須対応（PASS/FAIL の判定自体には影響しないが、Phase 12 完了条件として必須）                               |

### Rule-4: Branch Coverage ファイル全体基準

| 項目     | 内容                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------- |
| ルールID | Rule-4                                                                                              |
| ルール名 | Branch Coverage ファイル全体基準                                                                    |
| 条件     | `skillHandlers.ts` ファイル全体の Branch Coverage が 60% 以上                                       |
| 判定     | PASS（条件を満たす場合）/ FAIL（60% 未満の場合）                                                    |
| 備考     | Rule-2 でファイル全体の Line/Function が許容された場合でも、Branch Coverage は別途 60% 以上が必要。 |

### ルール適用フロー

```
修正対象ハンドラが指定されているか？
  │
  ├── YES → Rule-1 チェック: 修正対象ハンドラが全て 80%/80%/60% を満たすか？
  │          │
  │          ├── YES → Rule-4 チェック: ファイル全体の Branch Coverage が 60% 以上か？
  │          │          │
  │          │          ├── YES → PASS
  │          │          └── NO  → FAIL（Rule-4 未達）
  │          │
  │          └── NO  → Rule-2 適用可否チェック: 未達の原因が修正対象外ハンドラのみか？
  │                     │
  │                     ├── YES → Rule-2 PASS（Rule-3 未タスク化必須）+ Rule-4 チェック
  │                     └── NO  → FAIL（修正対象ハンドラ自体が未達）
  │
  └── NO  → 全ハンドラのレポートを出力するが Phase 7 判定は行わない
```

## 4. 境界条件

| 境界                                                      | 扱い                                                                                   |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `--target` で指定したチャンネル名がファイルに存在しない   | エラーとして処理し、ハンドラが見つからない旨を stderr に出力する（スコープ外エラー）。 |
| 登録関数が1つのファイル（`registerSkillHandlers` のみ等） | 正常に動作する。登録関数が複数ある場合も正常に動作する。                               |
| カバレッジデータが全行 0（テストが1件もない場合）         | Line/Branch/Function Coverage 全て 0% として正しく算出する。                           |
| カバレッジデータの行番号がハンドラ境界と1行もマッチしない | Line Coverage 0% として算出し、エラーは発生させない。                                  |
