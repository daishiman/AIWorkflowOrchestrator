## 1. 背景と目的

`skillHandlers.ts`（約1,075行・23ハンドラ）のような複数の IPCハンドラを含むファイルでは、Vitest のファイル単位カバレッジ集計では **どのハンドラがテスト不足か**が特定できない。本タスクでは TypeScript AST 解析と v8 カバレッジ JSON を組み合わせた**ハンドラ単位カバレッジ測定基盤**を構築し、Phase 7 の合否判定を定量化する。

## 2. 機能要件（FR）

### FR-001: ハンドラ境界検出

| 項目   | 内容                                                                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件名 | ハンドラ境界検出                                                                                                                                       |
| 優先度 | 必須                                                                                                                                                   |
| 説明   | TypeScript AST（ts-morph）を使用して、対象ファイル内の `ipcMain.handle()` の各コールバック関数の **開始行番号・終了行番号・チャンネル名** を検出する。 |
| 制約   | ts-morph を使用する。ハードコードされたチャンネル名リストへの依存を持たない。                                                                          |
| 対象数 | `skillHandlers.ts` では 23ハンドラ（registerSkillHandlers: 14、registerSkillScheduleHandlers: 5、registerSkillDocsHandlers: 4）を検出する。            |

### FR-002: v8 カバレッジ JSON 解析

| 項目     | 内容                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名   | v8 カバレッジ JSON 解析                                                                                                                                                                |
| 優先度   | 必須                                                                                                                                                                                   |
| 説明     | Vitest が `--coverage --coverage.reporter=json` オプションで出力した v8 カバレッジ JSON ファイルを読み込み、行単位・関数単位・分岐単位のカバレッジデータ（ヒットカウント）を解析する。 |
| 入力形式 | `coverage/coverage-final.json`（Vitest v8 出力形式）                                                                                                                                   |
| 制約     | JSON ファイルパスを引数で受け取る。`coverage-final.json` というファイル名へのハードコード依存を持たない。                                                                              |

### FR-003: ハンドラ単位カバレッジ算出

| 項目     | 内容                                                                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名   | ハンドラ単位カバレッジ算出                                                                                                                                                                            |
| 優先度   | 必須                                                                                                                                                                                                  |
| 説明     | FR-001 で検出したハンドラの行範囲（startLine〜endLine）と、FR-002 で解析した v8 カバレッジデータを突合し、各ハンドラの **Line カバレッジ・Branch カバレッジ・Function カバレッジ** を個別に算出する。 |
| 算出単位 | ハンドラごとに `lines.total`、`lines.covered`、`lines.pct`、`branches.total`、`branches.covered`、`branches.pct`、`functions.total`、`functions.covered`、`functions.pct` を算出する。                |

### FR-004: レポート出力

| 項目              | 内容                                                                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名            | レポート出力                                                                                                                                                     |
| 優先度            | 必須                                                                                                                                                             |
| 説明              | ハンドラ単位のカバレッジ結果を **JSON 形式**および **Markdown テーブル形式** の2形式で出力する。                                                                 |
| JSON 出力スキーマ | ハンドラごとに `{ channel, startLine, endLine, lines: { total, covered, pct }, branches: { total, covered, pct }, functions: { total, covered, pct } }` を含む。 |
| Markdown 出力     | チャンネル名・Line%・Branch%・Function%・判定（PASS/FAIL）を含む Markdown テーブルを標準出力に出力する。                                                         |

### FR-005: 修正対象ハンドラの指定

| 項目               | 内容                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名             | 修正対象ハンドラの指定                                                                                                                                  |
| 優先度             | 必須                                                                                                                                                    |
| 説明               | コマンドライン引数で修正対象のハンドラ名（チャンネル名）を指定できる。指定したハンドラに対してのみ Phase 7 判定ルールを適用する。                       |
| インターフェース例 | `--target skill:remove` のようなオプション形式。複数ハンドラを指定する場合は `--target skill:remove --target skill:import` のように繰り返し指定できる。 |

### FR-006: 判定結果の自動出力

| 項目       | 内容                                                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 要件名     | 判定結果の自動出力                                                                                                              |
| 優先度     | 必須                                                                                                                            |
| 説明       | Phase 7 判定ルール（Rule-1〜Rule-4）に基づき、修正対象ハンドラのカバレッジが基準を満たすかの判定結果（PASS / FAIL）を出力する。 |
| 終了コード | `--target` 指定時、判定が PASS の場合は終了コード 0、FAIL を含む場合は終了コード 1 を返す。                                     |
| 出力内容   | 各ルールごとの判定理由とハンドラ名・カバレッジ数値を含む。                                                                      |

### FR-007: 複数ファイル対応

| 項目               | 内容                                                                                                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件名             | 複数ファイル対応                                                                                                                                                                                                   |
| 優先度             | 推奨                                                                                                                                                                                                               |
| 説明               | `skillHandlers.ts` 以外の IPC ハンドラファイルにも適用可能な汎用インターフェースで設計する。解析対象ファイルのパスをコマンドライン引数で受け取り、スクリプト内に `skillHandlers.ts` へのパスをハードコードしない。 |
| インターフェース例 | `--file apps/desktop/src/main/ipc/skillHandlers.ts` のようなオプション形式。                                                                                                                                       |

## 3. 非機能要件（NFR）

### NFR-001: 実行速度

| 項目     | 内容                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 要件名   | 実行速度                                                                                                  |
| 優先度   | 必須                                                                                                      |
| 説明     | `skillHandlers.ts`（約1,075行・23ハンドラ）の AST 解析およびカバレッジ算出処理が **5秒以内** に完了する。 |
| 測定条件 | CI 環境（GitHub Actions相当）での実行時間で測定する。                                                     |

### NFR-002: エラーハンドリング

| 項目       | 内容                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名     | エラーハンドリング                                                                                                                                                          |
| 優先度     | 必須                                                                                                                                                                        |
| 説明       | 以下の異常系に対して、処理を中断し明確なエラーメッセージを標準エラー出力（stderr）に出力する。                                                                              |
| 異常系一覧 | （1）指定ファイルが存在しない、（2）カバレッジ JSON が不正な形式、（3）AST 解析に失敗した（TypeScript 構文エラーを含むファイル）、（4）必須コマンドライン引数が欠落している |
| エラー形式 | エラーメッセージには原因ファイルパスまたは発生箇所の識別情報を含める。スタックトレースは含めない（ユーザー向けメッセージのみ）。                                            |

### NFR-003: テストカバレッジ

| 項目     | 内容                                                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件名   | テストカバレッジ                                                                                                                                                                                       |
| 優先度   | 必須                                                                                                                                                                                                   |
| 説明     | 集計スクリプト自体（`scripts/coverage-by-handler.ts`）のユニットテスト（`scripts/coverage-by-handler.test.ts`）が以下の基準を満たす。                                                                  |
| 閾値     | Line Coverage: 80%以上、Function Coverage: 80%以上、Branch Coverage: 60%以上                                                                                                                           |
| 測定方法 | `pnpm vitest run scripts/coverage-by-handler.test.ts --coverage --coverage.include='scripts/coverage-by-handler.ts'` で測定する（P40 対策のため `apps/desktop/` ディレクトリからの実行を基本とする）。 |

### NFR-004: P41 対策（v8 インライン関数カウント）

| 項目     | 内容                                                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 要件名   | P41 対策                                                                                                                                                                                               |
| 優先度   | 必須                                                                                                                                                                                                   |
| 説明     | Vitest の v8 カバレッジプロバイダが、インライン arrow function（例: `getAllowedWindows: () => [mainWindow]`）を独立した関数としてカウントするという既知の問題（P41）を考慮した集計ロジックを実装する。 |
| 具体対策 | ハンドラ境界内に存在するインライン arrow function を Function カバレッジの分母に含めるが、テストからコールバックの戻り値を明示的に検証するテストを追加し、Function Coverage の不当な低下を防ぐ。       |

### NFR-005: P40 対策（テスト実行ディレクトリ依存）

| 項目     | 内容                                                                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名   | P40 対策                                                                                                                                                               |
| 優先度   | 必須                                                                                                                                                                   |
| 説明     | モノレポ環境において、テスト実行ディレクトリが変わってもカバレッジ JSON のパス解決・ソースファイルのパス解決が正しく動作するよう、**相対パスベース**でパスを解決する。 |
| 具体対策 | ハードコードした絶対パスを使用しない。`process.cwd()` と入力引数を組み合わせて動的にパスを解決する。                                                                   |

### NFR-006: 型安全

| 項目   | 内容                                                                                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名 | 型安全                                                                                                                                                                                       |
| 優先度 | 必須                                                                                                                                                                                         |
| 説明   | `scripts/coverage-by-handler.ts` が TypeScript `strict: true` モードでコンパイルエラーなしで通過する。`any` 型を使用しない。型アサーション（`as`）を使用する場合はコメントで理由を明記する。 |

### NFR-007: 依存関係の最小化

| 項目   | 内容                                                                                                                                                                                                                                      |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要件名 | 依存関係の最小化                                                                                                                                                                                                                          |
| 優先度 | 推奨                                                                                                                                                                                                                                      |
| 説明   | `ts-morph` 以外の新規 npm パッケージ追加を最小限に抑える。ファイル読み込み・パス解決は Node.js 標準ライブラリ（`fs`、`path`）を使用する。コマンドライン引数解析は Node.js `process.argv` または既存利用中のライブラリを優先して使用する。 |

## 5. 用語定義

| 用語               | 定義                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------- |
| ハンドラ           | `ipcMain.handle(channel, callback)` の1呼び出し単位。チャンネル名とコールバック関数のペア。                     |
| ハンドラ境界       | ハンドラのコールバック関数の開始行番号から終了行番号までの範囲。                                                |
| v8 カバレッジ JSON | Vitest が `--coverage.reporter=json` で出力する `coverage-final.json`。行ごとのヒットカウントを含む。           |
| Line Coverage      | ハンドラ境界内の総行数に対する、1回以上実行された行の割合（%）。                                                |
| Branch Coverage    | ハンドラ境界内の総分岐数に対する、1回以上通過した分岐の割合（%）。                                              |
| Function Coverage  | ハンドラ境界内の総関数数に対する、1回以上呼び出された関数の割合（%）。インライン arrow function を含む（P41）。 |
| Phase 7 判定       | カバレッジ基準を満たしているかを Rule-1〜Rule-4 で判定し、PASS / FAIL を出力する処理。                          |
| 修正対象ハンドラ   | `--target` オプションで指定した、Phase 7 判定の主対象となるハンドラ。                                           |
| P41                | Vitest v8 カバレッジプロバイダがインライン arrow function を独立した関数としてカウントする既知の問題。          |
| P40                | モノレポ環境でテスト実行ディレクトリが変わると `vitest.config.ts` の読み込みが正しく行われない既知の問題。      |
