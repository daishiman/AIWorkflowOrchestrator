## 1. 機能要件の受け入れ基準

### FR-001: ハンドラ境界検出

| No. | 受け入れ基準                                                                                                                                                             | 検証方法                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------ |
| 1   | `skillHandlers.ts` を入力として実行した際、23個のハンドラ（registerSkillHandlers: 14、registerSkillScheduleHandlers: 5、registerSkillDocsHandlers: 4）が全て検出される。 | 自動テスト（ユニット）         |
| 2   | 各ハンドラのチャンネル名（例: `skill:remove`、`skill:import` 等）が正しく抽出される。                                                                                    | 自動テスト（ユニット）         |
| 3   | 各ハンドラの開始行番号と終了行番号が、実際のソースコード上の行番号と一致する。                                                                                           | 自動テスト（スナップショット） |
| 4   | `ipcMain.handle()` 以外の呼び出し（例: `ipcMain.on()`）はハンドラ一覧に含まれない。                                                                                      | 自動テスト（ユニット）         |
| 5   | 存在しないファイルパスを指定した場合、処理を中断し「ファイルが見つかりません: {パス}」というメッセージを stderr に出力する。                                             | 自動テスト（異常系）           |

### FR-002: v8 カバレッジ JSON 解析

| No. | 受け入れ基準                                                                                                                                                | 検証方法               |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | Vitest `--coverage --coverage.reporter=json` で出力された `coverage-final.json` を正常に読み込み、各行のヒットカウントが取得できる。                        | 自動テスト（ユニット） |
| 2   | 行ごとのヒットカウントが 0（未カバー）と 1以上（カバー済み）に正しく分類される。                                                                            | 自動テスト（ユニット） |
| 3   | 対象ファイルのエントリが `coverage-final.json` に存在しない場合、「カバレッジデータが見つかりません: {ファイルパス}」というメッセージを stderr に出力する。 | 自動テスト（異常系）   |
| 4   | JSON ファイルが不正な形式（JSON parse エラー）の場合、「不正なカバレッジ JSON: {ファイルパス}」というメッセージを stderr に出力する。                       | 自動テスト（異常系）   |
| 5   | 分岐カバレッジデータ（`branchMap`）が存在する場合は分岐単位のカバレッジを解析する。存在しない場合は Branch Coverage を `null` として記録する。              | 自動テスト（ユニット） |

### FR-003: ハンドラ単位カバレッジ算出

| No. | 受け入れ基準                                                                                                                    | 検証方法               |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | `skill:remove` ハンドラのカバレッジが、UT-FIX-SKILL-REMOVE-INTERFACE-001 のテスト実行結果と一致する（実質100%相当）。           | 自動テスト（統合）     |
| 2   | テストが存在しないハンドラ（例: `skill:debug:enable` 等）の Line Coverage が 0% として算出される。                              | 自動テスト（ユニット） |
| 3   | ハンドラ境界内の全行数（空行・コメント行を除く実行可能行）が `lines.total` に正しく計上される。                                 | 自動テスト（ユニット） |
| 4   | ハンドラ境界外の行（他ハンドラのカバレッジデータ）が、算出対象ハンドラの数値に混入しない。                                      | 自動テスト（ユニット） |
| 5   | ハンドラ境界内にネストされた関数（インライン arrow function を含む）が Function Coverage の算出対象に含まれる（P41 対策済み）。 | 自動テスト（ユニット） |

### FR-004: レポート出力

| No. | 受け入れ基準                                                                                                                                                                                                                       | 検証方法               |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | JSON 出力が `CoverageReport` 構造（`handlers[]` / `summary` / `p41Note`）を持ち、各ハンドラ要素に `handler.channelName`, `handler.startLine`, `handler.endLine`, `lineCoverage`, `branchCoverage`, `functionCoverage` が含まれる。 | 自動テスト（スキーマ） |
| 2   | Markdown テーブル出力が「チャンネル名・開始行・終了行・Line%・Branch%・Function%・判定」の列を持つ。                                                                                                                               | 自動テスト（ユニット） |
| 3   | `pct` の値が小数点第1位までの数値（例: `85.7`）として正しく出力される。                                                                                                                                                            | 自動テスト（ユニット） |
| 4   | 全ハンドラ数（23ハンドラ）のレポートが 1回の実行で出力される。                                                                                                                                                                     | 自動テスト（統合）     |

### FR-005: 修正対象ハンドラの指定

| No. | 受け入れ基準                                                                                                                                                    | 検証方法               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | `--target skill:remove` オプションを指定した場合、`skill:remove` ハンドラのみに Phase 7 判定ルールが適用される。                                                | 自動テスト（ユニット） |
| 2   | `--target` を複数回指定（例: `--target skill:remove --target skill:import`）した場合、指定した全ハンドラに判定が適用される。                                    | 自動テスト（ユニット） |
| 3   | 存在しないチャンネル名（例: `--target skill:nonexistent`）を指定した場合、「ハンドラが見つかりません: skill:nonexistent」というメッセージを stderr に出力する。 | 自動テスト（異常系）   |
| 4   | `--target` を指定しない場合、全ハンドラのレポートが出力されるが Phase 7 判定は行われない。                                                                      | 自動テスト（ユニット） |

### FR-006: 判定結果の自動出力

| No. | 受け入れ基準                                                                                          | 検証方法               |
| --- | ----------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | Rule-1〜Rule-4 の全条件を満たした場合、「PASS」が出力され、プロセスが終了コード 0 で終了する。        | 自動テスト（統合）     |
| 2   | いずれか1つでも条件を満たさない場合、「FAIL」が出力され、プロセスが終了コード 1 で終了する。          | 自動テスト（統合）     |
| 3   | 出力に「どのルールでなぜ PASS/FAIL したか」の理由（ルールID・ハンドラ名・カバレッジ数値）が含まれる。 | 自動テスト（ユニット） |
| 4   | Rule-2（ファイル全体基準未達の許容）が適用された場合、その旨と未カバーハンドラ名が出力に含まれる。    | 自動テスト（ユニット） |

### FR-007: 複数ファイル対応

| No. | 受け入れ基準                                                                                                                          | 検証方法               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |

| 2   | `skillHandlers.ts` 以外のファイル（例: テスト用フィクスチャの IPC ハンドラファイル）を入力として正しく解析できる。                    | 自動テスト（ユニット） |
