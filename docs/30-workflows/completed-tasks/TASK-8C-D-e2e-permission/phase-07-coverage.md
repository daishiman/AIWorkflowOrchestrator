## 目的

E2Eテストのカバレッジを確認し、クリティカルパスが網羅されていることを検証する。E2Eテストはコードカバレッジではなく、ユーザーシナリオカバレッジを重視する。

## 背景

E2Eテストでは、コードカバレッジ（行カバレッジ等）よりもユーザーシナリオの網羅性が重要。権限ダイアログの全ユーザーフローがテストされていることを確認する。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: シナリオカバレッジ確認

**目的**: 定義されたユーザーシナリオが全てテストされているか確認する

**実行手順**:

1. シナリオカバレッジマトリクスを作成

   | シナリオ           | テストケース | カバー状況 |
   | ------------------ | ------------ | ---------- |
   | 権限ダイアログ表示 | TC-1         | [ ]        |
   | ツール情報表示     | TC-2         | [ ]        |
   | 許可操作           | TC-3         | [ ]        |
   | 拒否操作           | TC-4         | [ ]        |
   | 選択記憶           | TC-5         | [ ]        |
   | 複数連続リクエスト | エッジケース | [ ]        |
   | タイムアウト処理   | 異常系       | [ ]        |
   | フォーカストラップ | A11y         | [ ]        |
   | Escapeキー閉じる   | A11y         | [ ]        |
   | ARIA属性           | A11y         | [ ]        |

2. 未カバーシナリオの洗い出し

3. 追加テストの必要性判断

**期待される成果物**:

- `outputs/phase-7/scenario-coverage.md`: シナリオカバレッジレポート

---

### タスク2: E2Eテスト品質メトリクス確認

**目的**: テスト品質の客観的指標を確認する

**実行手順**:

1. テスト実行メトリクスを収集

   | メトリクス             | 目標値   | 実測値 |
   | ---------------------- | -------- | ------ |
   | テストケース総数       | ≥5       | [ ]    |
   | 全テストPASS率         | 100%     | [ ]    |
   | 平均テスト実行時間     | ≤30秒/件 | [ ]    |
   | 全体実行時間           | ≤3分     | [ ]    |
   | フレーキーテスト発生率 | 0%       | [ ]    |

2. フレーキーテスト検出
   - 同じテストを5回連続実行
   - 不安定なテストがあれば修正

   ```bash
   for i in {1..5}; do
     pnpm --filter @repo/desktop test:e2e -- skillPermission
   done
   ```

3. 実行時間の最適化検討

**期待される成果物**:

- `outputs/phase-7/test-metrics.md`: テスト品質メトリクスレポート

---

### タスク3: 要件トレーサビリティ確認

**目的**: Phase 1 の要件が全てテストでカバーされているか確認する

**実行手順**:

1. 要件-テストマッピングを確認

   | 要件ID | 要件内容           | テストケース | カバー状況 |
   | ------ | ------------------ | ------------ | ---------- |
   | FR-1   | 権限ダイアログ表示 | TC-1         | [ ]        |
   | FR-2   | ツール情報表示     | TC-2         | [ ]        |
   | FR-3   | 許可操作で継続     | TC-3         | [ ]        |
   | FR-4   | 拒否操作で停止     | TC-4         | [ ]        |
   | FR-5   | 選択記憶機能       | TC-5         | [ ]        |
   | NFR-1  | 10秒以内表示       | TC-1         | [ ]        |
   | NFR-2  | WCAG 2.1 AA準拠    | A11yテスト   | [ ]        |

2. 未カバー要件の洗い出し

3. 受け入れ基準との照合

**期待される成果物**:

- `outputs/phase-7/requirements-traceability.md`: 要件トレーサビリティレポート

---

### タスク4: カバレッジ改善（必要に応じて）

**目的**: カバレッジ不足があれば追加テストを実装する

**実行手順**:

1. カバレッジギャップの分析
   - 未カバーシナリオの優先度付け
   - 追加テストのコスト/効果分析

2. 追加テストの実装（必要な場合）

3. 最終カバレッジ確認

**期待される成果物**:

- `outputs/phase-7/coverage-improvement.md`: カバレッジ改善レポート（または「改善不要」の判定）
