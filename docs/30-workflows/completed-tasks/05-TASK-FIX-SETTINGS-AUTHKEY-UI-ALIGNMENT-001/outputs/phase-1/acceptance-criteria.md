## 受け入れ条件一覧

### AC-1: authKey管理セクションの条件付き表示

- **条件**: SettingsView で AuthModeSelector の認証モードを「APIキー認証」に切り替える
- **期待結果**: authKey管理セクション（入力フィールド、保存ボタン、削除ボタン）が表示される
- **判定**: Yes / No
- **関連要件**: FR-1.1, FR-1.2

### AC-2: authKey管理セクションの非表示

- **条件**: SettingsView で AuthModeSelector の認証モードが「サブスクリプション認証」に設定されている
- **期待結果**: authKey管理セクションが表示されない
- **判定**: Yes / No
- **関連要件**: FR-1.1

### AC-3: APIキーの保存操作

- **条件**: authKey管理セクションの入力フィールドに有効なAPIキーを入力し、保存ボタンをクリックする
- **期待結果**: キーが保存され、ステータス表示が「保存済み」（S1）に更新され、入力フィールドがクリアされる
- **判定**: Yes / No
- **関連要件**: FR-1.2, FR-1.3, NFR-1.1

### AC-4: APIキーの削除操作

- **条件**: 保存済みキーが存在する状態で、削除ボタンをクリックする
- **期待結果**: キーが削除され、ステータス表示が「未設定」（S3）または「環境変数fallback」（S2）に更新される
- **判定**: Yes / No
- **関連要件**: FR-1.2

### AC-5: 4状態の正確な表示 - 保存済み（S1）

- **条件**: authKeyService にキーが保存されている
- **期待結果**: ステータス表示が「保存済み」を示し、成功を示すアイコンとテキストが表示される
- **判定**: Yes / No
- **関連要件**: FR-2, FR-2.1

### AC-6: 4状態の正確な表示 - 環境変数fallback（S2）

- **条件**: 保存済みキーが存在せず、環境変数 `ANTHROPIC_API_KEY` が設定されている
- **期待結果**: ステータス表示が「環境変数から検出」を示し、「保存済みキーは存在しない」旨の説明が表示される
- **判定**: Yes / No
- **関連要件**: FR-2, FR-2.2

### AC-7: 4状態の正確な表示 - 未設定（S3）

- **条件**: 保存済みキーも環境変数も存在しない
- **期待結果**: ステータス表示が「未設定」を示し、キー入力を促すガイダンスが表示される
- **判定**: Yes / No
- **関連要件**: FR-2, FR-2.3

### AC-8: `auth-key:exists` 応答にsourceフィールドが含まれる

- **条件**: Preload API の `authKeyAPI.exists()` を呼び出す
- **期待結果**: 応答に `source` フィールド（`"stored"` | `"env"` | `"none"`）が含まれ、`exists` フィールド（boolean）も引き続き返される
- **判定**: Yes / No
- **関連要件**: FR-3.1, FR-3.2

### AC-9: preflight との整合性

- **条件**: SettingsView の状態表示が S1（保存済み）または S2（環境変数fallback）である
- **期待結果**: `skillExecutionAuthPreflight` の `auth-key:exists` チェックがパスする
- **判定**: Yes / No
- **関連要件**: FR-4.1, FR-4.2

### AC-10: セキュリティ - キーの非永続化

- **条件**: APIキーを保存した後の状態
- **期待結果**: 入力フィールドがクリアされており、Renderer のDOMおよびReact stateにAPIキーの生値が残存していない
- **判定**: Yes / No
- **関連要件**: NFR-1.1, NFR-1.3

### AC-11: アクセシビリティ - キーボード操作

- **条件**: キーボードのみを使用してauthKey管理セクションを操作する
- **期待結果**: Tab キーで全要素に移動でき、Enter キーで保存/削除が実行でき、全要素に適切なARIAラベルが付与されている
- **判定**: Yes / No
- **関連要件**: NFR-2.1, NFR-2.2

### AC-12: テストカバレッジ基準の充足

- **条件**: 新規追加コンポーネントおよび変更ファイルに対してテストを実行する
- **期待結果**: Line Coverage 80%以上、Branch Coverage 60%以上を達成する
- **判定**: Yes / No
- **関連要件**: NFR-4.3
