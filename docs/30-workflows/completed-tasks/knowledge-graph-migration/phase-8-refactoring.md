## 目的

動作を変えずにコード品質を改善する。マイグレーション関連コードの可読性・保守性を向上させる。

## 背景

TDD（テスト駆動開発）のRefactorフェーズとして、テストを維持しながらコード品質を改善する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード品質分析

**目的**: 現在のコード品質を分析し、改善ポイントを特定する

**実行手順**:

1. マイグレーション関連コードを読み込む
2. コードスメル（重複、長いメソッド、複雑な条件分岐など）を特定
3. 改善ポイントをリストアップ

**期待される成果物**:

- コード品質分析結果

---

### タスク2: リファクタリング実施

**目的**: 特定した改善ポイントをリファクタリングする

**実行手順**:

1. 重複コードの抽出・共通化
2. 命名の改善（変数名、関数名、ファイル名）
3. コメントの追加・改善
4. 各変更後にテストを実行し成功を確認

**期待される成果物**:

- リファクタリング済みコード

---

### タスク3: テスト継続成功確認

**目的**: リファクタリング後もテストが成功することを確認する

**実行手順**:

1. `pnpm --filter @repo/shared test` を実行
2. 全テストがパスすることを確認
3. カバレッジが維持されていることを確認

**期待される成果物**:

- テスト成功確認レポート

## リファクタリング観点

| 観点     | 確認項目                             |
| -------- | ------------------------------------ |
| 重複排除 | 同じコードパターンが複数箇所にないか |
| 命名改善 | 変数名・関数名が意図を表しているか   |
| 構造整理 | 関数の責務が明確か                   |
| コメント | 複雑なロジックに説明があるか         |
