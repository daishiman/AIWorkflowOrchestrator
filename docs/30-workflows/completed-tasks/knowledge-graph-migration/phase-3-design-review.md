## 目的

実装開始前に要件・設計の妥当性を検証し、問題があれば前のPhaseへ戻る判断を行う。

## 背景

Phase 2で作成した設計が要件を満たしているか、実装可能かを検証する重要なゲートポイント。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件との整合性レビュー

**目的**: 設計が要件を満たしているか検証する

**実行手順**:

1. Phase 1の要件定義書を読み込む
2. Phase 2の設計書と突き合わせる
3. 各要件に対応する設計要素が存在するか確認
4. 漏れがあれば指摘事項として記録

**期待される成果物**:

- 整合性レビュー結果

---

### タスク2: 技術的妥当性レビュー

**目的**: 設計が技術的に実現可能か検証する

**実行手順**:

1. drizzle.config.ts設定の妥当性を確認
2. マイグレーション生成・適用手順の実現可能性を確認
3. 外部キー制約の設定順序が正しいか確認
4. 潜在的な問題があれば指摘事項として記録

**期待される成果物**:

- 技術的妥当性レビュー結果

---

### タスク3: 判定結果記録

**目的**: レビュー結果に基づき判定を行う

**実行手順**:

1. 全レビュー観点の結果を集約
2. 判定基準に基づき判定（PASS/MINOR/MAJOR/CRITICAL）
3. 指摘事項があれば対応方針を記録
4. 次のアクションを決定

**期待される成果物**:

- 設計レビュー結果

## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点     | 確認項目                                             |
| ---------------- | ---------------------------------------------------- |
| スキーマ設定     | graph/index.tsがdrizzle.config.tsに含まれているか    |
| マイグレーション | 生成・適用手順が明確か                               |
| 外部キー制約     | 依存関係の順序が正しいか                             |

## 判定基準

| 判定     | 条件                     | 対応                         |
| -------- | ------------------------ | ---------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行                |
| MINOR    | 軽微な指摘あり           | 指摘対応後Phase 4へ進行      |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻り先を決定 |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認    |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
