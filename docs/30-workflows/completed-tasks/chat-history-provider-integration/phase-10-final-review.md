## 目的

全体の品質と整合性を検証し、手動テストに進む前の最終チェックを行う。

## 背景

Phase 1〜9の成果物を総合的にレビューし、実装が要件を満たしているか、設計通りに実装されているかを最終確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件達成確認

**目的**: Phase 1で定義した要件が全て満たされているか確認する

**実行手順**:

1. Phase 1の要件定義を確認する
2. 各要件に対して実装状況を確認する:
   - [ ] ChatHistoryProviderがApp.tsxでラップされている
   - [ ] DrizzleリポジトリがProviderに注入されている
   - [ ] useChatHistoryが任意のコンポーネントで使用可能
   - [ ] isReadyフラグが正しく動作する
3. 確認結果を `outputs/phase-10/requirements-verification.md` に出力する

**期待される成果物**:

- `outputs/phase-10/requirements-verification.md`

---

### タスク2: 設計整合性確認

**目的**: 実装がPhase 2の設計に沿っているか確認する

**実行手順**:

1. Phase 2の設計書を確認する
2. 実装が設計通りであることを確認する:
   - リポジトリファクトリーの構造
   - Provider階層構造
   - 初期化フロー
3. 確認結果を `outputs/phase-10/design-conformance.md` に出力する

**期待される成果物**:

- `outputs/phase-10/design-conformance.md`

---

### タスク3: コード品質最終確認

**目的**: コード品質が基準を満たしているか最終確認する

**実行手順**:

1. Phase 9の品質チェック結果を確認する
2. 追加の品質確認を行う:
   - コメントの適切さ
   - エラーハンドリングの一貫性
   - 命名規則の遵守
3. 確認結果を `outputs/phase-10/code-quality-final.md` に出力する

**期待される成果物**:

- `outputs/phase-10/code-quality-final.md`

---

### タスク4: 統合テスト結果確認

**目的**: 統合テストが全てパスしていることを最終確認する

**実行手順**:

1. 全統合テストを実行する:
   ```bash
   pnpm --filter @repo/desktop test -- --run
   ```
2. テスト結果を確認する
3. 確認結果を `outputs/phase-10/integration-test-final.md` に出力する

**期待される成果物**:

- `outputs/phase-10/integration-test-final.md`

---

### タスク5: 最終レビューゲート判定

**目的**: 最終レビュー結果に基づきゲート判定を行う

**実行手順**:

1. タスク1〜4の結果を統合する
2. 以下の判定基準に基づき判定する:
   - **PASS**: 全項目で問題なし → Phase 11へ進行
   - **MINOR**: 軽微な指摘あり → 対応後、Phase 11へ
   - **MAJOR**: 重大な問題あり → 影響範囲に応じて戻る
   - **CRITICAL**: 致命的な問題あり → Phase 1へ戻りユーザー確認
3. 判定結果を `outputs/phase-10/final-gate-decision.md` に出力する

**期待される成果物**:

- `outputs/phase-10/final-gate-decision.md`
