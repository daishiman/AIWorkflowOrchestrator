## 目的

Phase 2 の設計が Phase 4 へ進められる品質かを判定する。責務境界・状態所有権・テスト戦略・アクセシビリティの4軸でレビューする。

## 実行タスク

### Task 1: 設計レビュー観点

以下の観点でレビューを実施する:

#### 1-A: 責務境界の確認

| チェック項目                                                            | 判定基準                                        |
| ----------------------------------------------------------------------- | ----------------------------------------------- |
| `description` の表示責務が `InlineModelSelector` に閉じているか         | ✅ 単一コンポーネントに責務を集約できている     |
| `LLMSelectorPanel` が直接修正不要な根拠が明確か                         | ✅ 内包するセレクターに委譲するため直接修正不要 |
| `ModelSelector` / `ProviderSelector` が baseline として明示されているか | ✅ 既存対応済み / 型前提不一致のため対象外      |
| `InlineModelSelector` への tooltip / helper text 設計が適切か           | ✅ スペース制約を考慮した代替案が提示されている |

#### 1-B: 状態所有権の確認

| チェック項目                                         | 判定基準                               |
| ---------------------------------------------------- | -------------------------------------- |
| `description` のデータ所有権が `LLMModel` 型にある   | ✅ `packages/shared` の schema が SSOT |
| renderer 側で description の独自変換・加工を行わない | ✅ 表示のみで状態変更なし              |

#### 1-C: テスト戦略の確認

| チェック項目                                                            | 判定基準                                        |
| ----------------------------------------------------------------------- | ----------------------------------------------- |
| description あり/なしの両パターンがテスト対象になっているか             | ✅ Phase 4 で両パターンのフィクスチャを定義する |
| 空文字（`""`）と `undefined` の両方が安全処理のテスト対象になっているか | ✅ 設計で明示されている                         |
| アクセシビリティ（`aria-label`）がテスト対象になっているか              | ✅ Phase 4 でアクセシビリティテストを定義する   |

#### 1-D: アクセシビリティの確認

| チェック項目                                            | 判定基準                                    |
| ------------------------------------------------------- | ------------------------------------------- |
| `aria-describedby` による補助テキストが設計されているか | ✅ Phase 2 の設計に含まれている             |
| tooltip の補助情報が screen reader に影響しないか       | ✅ sr-only で完全な文言を提供することで対応 |

### Task 2: レビュー判定

**判定基準**:

| レベル   | 内容                                        | アクション             |
| -------- | ------------------------------------------- | ---------------------- |
| PASS     | 全チェックが問題なし                        | Phase 4 へ進む         |
| MINOR    | 小さな修正が必要だが Phase 4 進行を妨げない | Phase 4 と並行して修正 |
| MAJOR    | 大きな設計変更が必要                        | Phase 2 に戻る         |
| CRITICAL | 根本的な見直しが必要                        | Phase 1 に戻る         |

**想定判定**: PASS（小規模 UI タスクであり、設計の複雑度が低い）

### Task 3: Phase 4 進行チェックリスト

Phase 3 完了後、以下が確認できた場合 Phase 4 へ進む:

- [ ] `InlineModelSelector` の修正箇所が確定している
- [ ] 安全処理（空文字・undefined）の実装方針が確定している
- [ ] テスト対象のフィクスチャ設計が完了している
- [ ] アクセシビリティ対応方針が確定している
- [ ] 既存機能への回帰リスクが評価されている
