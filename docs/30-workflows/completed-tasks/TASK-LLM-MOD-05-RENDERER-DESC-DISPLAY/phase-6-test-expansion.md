## 目的

Phase 4 の TDD テスト（T-1〜T-9）に加えて、`InlineModelSelector` の fail path・回帰 guard・境界値テストを追加し、テストカバレッジを強化する。

## 実行タスク

### Task 1: fail path テストの追加

| テストケース | 説明                                                        | 検証内容                                            |
| ------------ | ----------------------------------------------------------- | --------------------------------------------------- |
| T-10         | description が null の場合（型違反）に安全に処理される      | null チェックが description なし扱いになる          |
| T-11         | description が非常に長い文字列の場合でも tooltip が壊れない | 文字列全体が補助情報として保持される                |
| T-12         | description に HTML タグが含まれる場合に XSS が防がれる     | HTML タグがエスケープされてテキストとして表示される |

### Task 2: 回帰 guard テストの追加

既存テストが以下のシナリオで引き続き動作することを確認する:

| テストケース | 説明                                                                    | 検証内容                                            |
| ------------ | ----------------------------------------------------------------------- | --------------------------------------------------- |
| T-13         | モデル選択イベントが description 表示後も正常に発火する                 | onSelectionChange が正しいモデル ID を返す          |
| T-14         | provider 変更時に description が正しく更新される                        | provider 変更 → model リスト更新 → description 更新 |
| T-15         | キーボードナビゲーション（Tab/Enter/Escape）が description 追加後も動作 | フォーカス・選択が正常に動作する                    |

### Task 3: スナップショットテストの更新

description フィールドが追加されたことで既存のスナップショットが変更される可能性がある:

```bash
# スナップショット更新コマンド（実行前に変更内容を確認すること）
pnpm vitest run --update-snapshots
```

変更されるスナップショットを確認し、意図した変更であることを記録する。

### Task 4: テスト実行確認

```bash
pnpm --filter @repo/desktop test -- --reporter=verbose
```

全テストが PASS することを確認する。
