## 目的

Phase 5 で実装し Phase 6 でテストを拡充した IPCハンドラーのカバレッジが基準を満たしているか**最終確認**する。未達の場合は Phase 6 に戻る。

## カバレッジ基準

| 指標              | 最低基準 | 推奨基準 |
| ----------------- | -------- | -------- |
| Line Coverage     | 80%      | 90%      |
| Branch Coverage   | 60%      | 70%      |
| Function Coverage | 80%      | 90%      |

## 実行タスク

### Task 1: カバレッジ計測

以下のコマンドを実行し、カバレッジレポートを取得する:

```bash
cd apps/desktop && pnpm vitest run src/main/ipc/__tests__/skillFileHandlers --coverage --reporter=verbose
```

**計測対象ファイル**:

| ファイル                                         | 説明              |
| ------------------------------------------------ | ----------------- |
| `apps/desktop/src/main/ipc/skillFileHandlers.ts` | IPCハンドラー実装 |

**注意**: テストファイル自体はカバレッジ計測対象外。

### Task 2: ゲート判定

#### 2.1 判定テーブル

| 条件                         | 判定  | 対応                                       |
| ---------------------------- | ----- | ------------------------------------------ |
| 全3指標が最低基準を満たす    | PASS  | Phase 8 へ進む                             |
| 全3指標が推奨基準を満たす    | PASS+ | Phase 8 へ進む（高品質）                   |
| いずれかの指標が最低基準未満 | FAIL  | Phase 6 へ戻り、未カバー箇所のテストを追加 |

#### 2.2 FAIL 時の対応手順

1. カバレッジレポートの `Uncovered Lines` / `Uncovered Branches` を確認する
2. 未カバー箇所を特定し、以下の優先順位でテストを追加する:
   - **Branch Coverage 不足**: 条件分岐のうち未通過パスをテスト（if/else の片方のみカバーされていないケース）
   - **Line Coverage 不足**: 未実行行を特定し、その行を通過するテストを追加
   - **Function Coverage 不足**: 未呼出関数を確認し、呼び出すテストを追加
3. テスト追加後、Task 1 を再実行する
4. 基準を満たすまで Step 2-3 を繰り返す

#### 2.3 FAIL 時の典型的な未カバーパターン

| パターン                                       | テスト追加方法                                     |
| ---------------------------------------------- | -------------------------------------------------- |
| `isKnownSkillFileError` の特定のエラー分岐     | 該当エラークラスをモックで throw するテストを追加  |
| `validateIpcSender` 失敗時の throw 分岐        | `validateIpcSender` を `{ valid: false }` でモック |
| 引数バリデーションの特定分岐（型チェック）     | null, undefined, 数値, 配列の不正引数テストを追加  |
| `skillService?.scanAvailableSkills()` 呼び出し | `skillService` が undefined の場合のテストを追加   |
