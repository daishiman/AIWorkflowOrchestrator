## ワークフロー改善点

### 1. v8カバレッジ計測でのFunction Coverage注意点

**発見**: v8プロバイダーはインライン矢印関数(`() => [mainWindow]`)を個別の「関数」としてカウントする。モックされた関数に渡されるコールバックは呼び出されないため、Function Coverageが低くなる。

**提案**: Phase 4（テスト設計）または Phase 6（テスト拡充）の仕様書に、以下の注意書きを追加することを推奨:

> v8プロバイダー使用時、インラインコールバック関数は個別にカウントされます。モック関数に渡されるコールバックのテストも考慮してください。

### 2. ESM環境でのrequire("electron")非互換

**発見**: Vitest ESM環境で`require("electron")`がundefinedを返し、テストが失敗した。

**提案**: Phase 4の仕様書テンプレートに以下の注意書きを追加:

> Electronモジュールのモックは`vi.mock("electron")`＋`import`を使用してください。`require`は ESM環境で動作しません。

### 3. worktree環境での手動テスト代替

**発見**: worktree環境ではElectronアプリの起動が困難で、DevToolsでの手動テストが実行できない。

**提案**: Phase 11の仕様書テンプレートに、worktree環境でのフォールバック手順を標準化:

> worktree環境の場合、ユニットテスト・統合テスト結果をもって手動テストの代替とし、代替理由を成果物に記録する。

## 結論

task-specification-creator スキル自体への改善提案はないが、Phase 4/6/11 のテンプレートに技術的な注意点を追加することで、将来のタスク実行時の効率が向上する可能性がある。
