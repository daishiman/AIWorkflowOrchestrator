## 目的

Phase 1-2で作成した要件定義・設計の妥当性を検証し、実装フェーズへ進むかどうかを判定する。

## 背景

アニメーション実装において、パフォーマンスとアクセシビリティの両立は設計段階での決定が重要。設計レビューで問題を早期発見することで、手戻りを防ぐ。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件・設計整合性レビュー

**目的**: 要件と設計の整合性を確認する

**実行手順**:

1. Phase 1の要件定義書を再確認
2. Phase 2の設計書が全要件をカバーしているか確認:
   - 機能要件の実現方法
   - 非機能要件の達成方法
   - アクセシビリティ要件の対応
3. ギャップがあれば記録

**期待される成果物**:

- レビュー結果（タスク4で統合）

---

### タスク2: パフォーマンス設計レビュー

**目的**: パフォーマンス観点で設計を検証する

**実行手順**:

1. 以下の観点でレビュー:
   - GPU加速プロパティの適切な使用
   - will-changeの適切な使用（過剰使用の回避）
   - アニメーションのレイヤー分離
   - 60fps達成可能性
2. 問題点・改善点を記録

**期待される成果物**:

- レビュー結果（タスク4で統合）

---

### タスク3: アクセシビリティ設計レビュー

**目的**: アクセシビリティ観点で設計を検証する

**実行手順**:

1. 以下の観点でレビュー:
   - reduced-motion対応の完全性
   - WCAG 2.1準拠
   - フォーカス管理への影響
   - スクリーンリーダー互換性
2. 問題点・改善点を記録

**期待される成果物**:

- レビュー結果（タスク4で統合）

---

### タスク4: レビュー結果判定

**目的**: 設計レビューの合否を判定する

**実行手順**:

1. タスク1〜3の結果を集約
2. 判定基準に基づいて判定:
   - PASS: 全観点で問題なし
   - MINOR: 軽微な修正で対応可能
   - MAJOR: 設計の見直しが必要
   - CRITICAL: 要件から見直しが必要
3. レビュー結果を文書化

**期待される成果物**:

- `outputs/phase-3/design-review-result.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション          |
| -------- | ------------------------ | ----------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ   |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り設計修正   |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻り要件再検討 |

| 問題の種類       | 戻り先              |
| ---------------- | ------------------- |
| 要件の漏れ・誤り | Phase 1（要件定義） |
| 設計の問題       | Phase 2（設計）     |
