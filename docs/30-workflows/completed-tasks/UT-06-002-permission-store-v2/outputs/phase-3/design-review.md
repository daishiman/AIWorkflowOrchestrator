### 5. 設計書の `allowedAt` 型に関する懸念

| 懸念                                                                                                            | 詳細                     | 対策                                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Phase 5 設計書の `AllowedToolEntryV2.allowedAt` は `number`（Unix timestamp ms）だが、V1 は `string`（ISO8601） | 型変更は破壊的変更になる | V2 でも `allowedAt: string` を維持し、`calcExpiresAt` 呼び出し時に `new Date(allowedAt).getTime()` で変換。Phase 5 設計書の `allowedAt: number` は内部計算用の仕様であり、永続化形式は V1 互換の string を維持する |

### MINOR 指摘事項

#### MINOR-01: IPC ハンドラの sender 検証

- **内容**: `permission:clear-session` ハンドラに `event.sender` の検証が設計書に含まれていない
- **対策**: Phase 5 実装時に既存の `permission-store-handlers.ts` パターンに合わせて sender 検証を追加する。ただし、既存の3ハンドラ（getAllowedTools, revokeTool, clearAll）にも sender 検証が無いため、このタスクのスコープでは新規ハンドラのみに適用し、既存ハンドラへの適用は別途未タスク化する
- **未タスク化**: Phase 12 で検出・記録する
