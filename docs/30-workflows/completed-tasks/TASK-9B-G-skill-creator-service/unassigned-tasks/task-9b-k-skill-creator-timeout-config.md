## 1. なぜこのタスクが必要か（Why）

### 1.1 背景

TASK-9B-GでScriptExecutorにタイムアウト機能を実装した。
現在、デフォルトタイムアウト値（5分）はconstants.tsにハードコードされている。

### 1.2 問題点・課題

- タイムアウト値が環境変数で設定できない
- 12-Factor App原則に従っていない
- 本番環境と開発環境で異なる値を使いたい場合に再ビルドが必要

### 1.3 放置した場合の影響

- 運用上の柔軟性が低い
- 環境ごとの最適化が困難
- デバッグ時にタイムアウトを延長するのが面倒

---

## 2. 何を達成するか（What）

### 2.1 目的

タイムアウト設定を環境変数から読み取れるようにする。

### 2.2 最終ゴール

- 環境変数 `SKILL_EXECUTOR_TIMEOUT_MS` でタイムアウトを設定可能
- デフォルト値はフォールバックとして維持
- 設定値のバリデーション

### 2.3 スコープ

#### 含むもの

- 環境変数読み取り処理
- バリデーション（最小値、最大値）
- ユニットテスト

#### 含まないもの

- UIからの設定変更
- 設定ファイル（JSON/YAML）対応

## 4. 実行手順

### Phase 1-13: task-specification-creatorの標準フローに従って実行

### 参考: 実装例

```typescript
// config/timeout.ts
const MIN_TIMEOUT_MS = 10_000; // 10秒
const MAX_TIMEOUT_MS = 3_600_000; // 1時間
const DEFAULT_TIMEOUT_MS = 300_000; // 5分

export function getTimeoutMs(): number {
  const envValue = process.env.SKILL_EXECUTOR_TIMEOUT_MS;
  if (!envValue) return DEFAULT_TIMEOUT_MS;

  const parsed = parseInt(envValue, 10);
  if (isNaN(parsed)) return DEFAULT_TIMEOUT_MS;

  return Math.max(MIN_TIMEOUT_MS, Math.min(MAX_TIMEOUT_MS, parsed));
}
```
