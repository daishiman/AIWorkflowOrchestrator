## 実行手順

### Task 8-1: コードスメル検出と修正

| コードスメル         | 検出方法       | 修正方針       |
| -------------------- | -------------- | -------------- |
| 長すぎるメソッド     | 行数 > 30      | 責務分割       |
| 深いネスト           | インデント > 3 | 早期リターン   |
| マジックナンバー     | 数値リテラル   | 定数化         |
| 長いパラメータリスト | 引数 > 4       | オブジェクト化 |

### Task 8-2: 重複コードの排除

| 重複箇所           | 修正方針                   |
| ------------------ | -------------------------- |
| スクリプトパス構築 | ユーティリティメソッド抽出 |
| エラーハンドリング | 共通エラーハンドラ抽出     |
| ログ出力           | ログユーティリティ統一     |

### Task 8-3: 命名改善

| 対象       | 改善ポイント                                 |
| ---------- | -------------------------------------------- |
| 変数名     | 意図を明確に（例: result → executionResult） |
| メソッド名 | 動詞で開始、目的を明確に                     |
| クラス名   | 責務を反映                                   |
| 定数名     | SCREAMING_SNAKE_CASEで意味を明確に           |

### Task 8-4: SOLID原則の適用

| 原則                 | 適用ポイント                               |
| -------------------- | ------------------------------------------ |
| 単一責任             | 各クラスが1つの責務のみを持つことを確認    |
| 開放閉鎖             | 新規モード追加時の拡張ポイントを確認       |
| リスコフ置換         | インターフェース準拠を確認                 |
| インターフェース分離 | 必要なメソッドのみを公開                   |
| 依存性逆転           | 上位モジュールが下位に依存しないことを確認 |
