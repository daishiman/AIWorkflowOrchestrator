## 実行タスク

### タスク1: 要件・設計整合性レビュー

**目的**: Phase 1の要件がPhase 2の設計に正しく反映されているか確認する。

**手順**:

1. 機能要件FR-1〜FR-8が設計に反映されているか確認する
2. 非機能要件NFR-1〜NFR-5が設計で対応可能か確認する
3. 受け入れ基準AC-1〜AC-13が設計から検証可能か確認する

**レビュー観点**:

| 観点               | 確認項目                                                         |
| ------------------ | ---------------------------------------------------------------- |
| コンポーネント設計 | 統合対象の全コンポーネントが設計に含まれているか                 |
| 状態管理設計       | skillSlice/agentSliceの状態取得パターンが既存と一貫しているか    |
| データフロー       | Store → ChatPanel → 子コンポーネントのフローに矛盾がないか       |
| 既存機能との互換性 | 通常チャット機能（StreamingMessage等）への影響が最小限か         |
| アクセシビリティ   | WCAG 2.1 AA（aria-live, フォーカストラップ, キーボードナビ）対応 |
| パフォーマンス     | shallow比較セレクターで不要なリレンダリングを防止しているか      |

### タスク2: 既存テストとの互換性確認

**目的**: 統合によって既存テスト57件が破損しないことを事前確認する。

**手順**:

1. ChatPanel.test.tsx（311行）のテストケースが設計変更後も有効か確認する
2. StreamingMessage.test.tsx（513行）のテストケースが影響を受けないか確認する
3. SkillSelector.test.tsx、PermissionDialog.test.tsx等の既存テストへの影響を確認する

## 統合テスト連携【必須】

| レビュー観点       | 確認項目                                                |
| ------------------ | ------------------------------------------------------- |
| データフロー       | skillSlice → ChatPanel → SkillStreamingViewのフロー設計 |
| コンポーネント連携 | SkillSelector → ChatPanel → SkillImportDialogの連携設計 |
| エラーハンドリング | skillError発生時のUI表示設計                            |
