## 目的

Phase 6の拡充結果を検証し、カバレッジ基準を満たすまでゲートとして確認する。未達の場合はPhase 6へ戻りテスト拡充を行う。

## 背景

テストカバレッジはコードの品質指標として重要である。リファクタリング前にカバレッジ基準を達成することで、安全なリファクタリングを保証する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: ユニットテストカバレッジ確認

**目的**: ユニットテストカバレッジが基準を満たしていることを確認する

**実行手順**:

1. カバレッジレポートを生成:
   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```
2. 以下の基準を確認:

   | 指標              | 最低基準 | 推奨基準 | 実測値    | 判定 |
   | ----------------- | -------- | -------- | --------- | ---- |
   | Line Coverage     | 80%      | 90%      | \_\_\_\_% | □    |
   | Branch Coverage   | 60%      | 70%      | \_\_\_\_% | □    |
   | Function Coverage | 80%      | 90%      | \_\_\_\_% | □    |

3. 未達の場合: 具体的な未カバー箇所を特定

**期待される成果物**:

- ユニットテストカバレッジ判定結果

---

### タスク2: 結合テストカバレッジ確認

**目的**: 結合テストカバレッジが基準を満たしていることを確認する

**実行手順**:

1. 以下の基準を確認:

   | 指標                         | 目標 | 実測値    | 判定 |
   | ---------------------------- | ---- | --------- | ---- |
   | APIエンドポイント            | 100% | \_\_\_\_% | □    |
   | モジュール間インターフェース | 100% | \_\_\_\_% | □    |
   | 正常系シナリオ               | 100% | \_\_\_\_% | □    |
   | 異常系シナリオ               | 80%+ | \_\_\_\_% | □    |
   | 外部連携ポイント             | 100% | \_\_\_\_% | □    |

2. 未達の場合: 不足しているテストシナリオを特定

**期待される成果物**:

- 結合テストカバレッジ判定結果

---

### タスク3: 統合テスト実行確認

**目的**: 全ての統合テストが成功していることを確認する

**実行手順**:

1. 統合テストを実行:
   ```bash
   pnpm --filter @repo/desktop test apps/desktop/src/main/services/__tests__/HistoryService.integration.test.ts
   ```
2. 全テストがパスしていることを確認
3. 失敗テストがある場合: 原因を特定

**期待される成果物**:

- 統合テスト実行結果

---

### タスク4: ゲート判定

**目的**: カバレッジ基準達成を総合的に判定する

**実行手順**:

1. 全カバレッジ結果を集約
2. 判定を下す:
   - **PASS**: 全基準を達成 → Phase 8へ進行
   - **RETRY**: 一部未達 → Phase 6へ戻りテスト拡充
3. 検証レポートを作成

**期待される成果物**:

- カバレッジ検証レポート（`outputs/phase-7/coverage-report.md`）

## ゲート判定

### 判定基準

| 判定  | 条件                   | 次のアクション    |
| ----- | ---------------------- | ----------------- |
