## 目的

全体の品質と整合性を検証し、手動テストに進む前に問題がないことを確認する。

## 背景

最終レビューゲートは、実装の最終確認を行う重要なチェックポイントである。Phase 1（要件定義）からPhase 9（品質保証）までの成果物を総合的にレビューし、手動テストに進む準備が整っていることを確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: 全ての要件が実装されていることを確認する

**実行手順**:

1. Phase 1の受け入れ基準を再確認
2. 各受け入れ基準に対する実装状況を確認:

   | 基準                              | 実装状況 | 確認方法   |
   | --------------------------------- | -------- | ---------- |
   | getFileHistoryが実データを返す    | □        | テスト確認 |
   | getVersionDetailが実データを返す  | □        | テスト確認 |
   | getConversionLogsが実データを返す | □        | テスト確認 |
   | restoreVersionが復元を実行する    | □        | テスト確認 |
   | ページネーションが動作する        | □        | テスト確認 |
   | ログフィルタリングが動作する      | □        | テスト確認 |

3. 未充足の要件があれば特定

**期待される成果物**:

- 要件充足確認結果

---

### タスク2: 設計整合性確認

**目的**: 実装がPhase 2の設計に沿っていることを確認する

**実行手順**:

1. アーキテクチャ設計との整合性確認:
   - 統合パターンが設計通りか
   - 依存性注入が設計通りか
2. 型変換設計との整合性確認:
   - マッピングが設計通りか
3. エラーハンドリング設計との整合性確認:
   - Result型パターンが適用されているか

**期待される成果物**:

- 設計整合性確認結果

---

### タスク3: 品質基準確認

**目的**: Phase 9の品質基準が維持されていることを確認する

**実行手順**:

1. 全テストを実行:
   ```bash
   pnpm --filter @repo/desktop test
   ```
2. 静的解析を実行:
   ```bash
   pnpm --filter @repo/desktop lint
   pnpm --filter @repo/desktop typecheck
   ```
3. カバレッジを確認:
   - Line Coverage 80%以上
   - Branch Coverage 60%以上
   - Function Coverage 80%以上

**期待される成果物**:

- 品質基準確認結果

---

### タスク4: 統合テスト結果確認

**目的**: 統合テストが全て成功していることを確認する

**実行手順**:

1. 統合テストを実行:
   ```bash
   pnpm --filter @repo/desktop test apps/desktop/src/main/services/__tests__/HistoryService.integration.test.ts
   ```
2. IPCハンドラーテストを実行:
   ```bash
   pnpm --filter @repo/desktop test apps/desktop/src/main/ipc/__tests__/historyHandlers.test.ts
   ```
3. 全テストがパスしていることを確認

**期待される成果物**:

- 統合テスト結果

---

### タスク5: 最終判定

**目的**: 最終レビュー結果を判定する

**実行手順**:

1. 全確認結果を集約
2. 指摘事項を分類:
   - CRITICAL: 致命的な問題
   - MAJOR: 重大な問題
   - MINOR: 軽微な指摘
   - INFO: 情報共有
3. 最終判定を下す

**期待される成果物**:

- 最終レビュー結果（`outputs/phase-10/final-review-result.md`）

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
