## 目的

Phase 5（実装）完了後、リファクタリングに進む前にテストを拡充する。カバレッジ目標を達成し、統合テストを強化する。

## 背景

TDDのGreen段階では最小限の実装のみを行うため、エッジケースや異常系のカバレッジが不足している可能性がある。リファクタリング前にテストを拡充することで、安全なリファクタリングを可能にする。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 現在のカバレッジ確認

**目的**: 現在のテストカバレッジを測定し、不足箇所を特定する

**実行手順**:

1. カバレッジレポートを生成:
   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```
2. HistoryService.tsのカバレッジを確認:
   - Line Coverage
   - Branch Coverage
   - Function Coverage
3. カバレッジが不足している箇所を特定

**期待される成果物**:

- 現在のカバレッジレポート

---

### タスク2: エッジケーステストの追加

**目的**: エッジケースをカバーするテストを追加する

**実行手順**:

1. ページネーション境界テスト:

   ```typescript
   it("境界値: offset=0, limit=0の場合", async () => {});
   it("境界値: 最後のページを取得する場合", async () => {});
   it("境界値: 履歴が0件のファイル", async () => {});
   ```

2. 空データテスト:

   ```typescript
   it("変換ログが0件の場合", async () => {});
   it("メタデータがnullの場合", async () => {});
   ```

3. 大量データテスト:
   ```typescript
   it("履歴が1000件以上ある場合", async () => {});
   ```

**期待される成果物**:

- エッジケーステスト

---

### タスク3: 統合テストの拡充

**目的**: 統合テストのカバレッジを向上させる

**実行手順**:

1. API接続テストの拡充:
   - 複数同時リクエスト
   - 接続タイムアウト

2. データフローテストの拡充:
   - 型変換の網羅性確認
   - nullableフィールドの取り扱い

3. エラーハンドリングテストの拡充:
   - DB接続エラー
   - データ整合性エラー

4. 状態同期テストの拡充:
   - 復元後の一覧更新確認
   - 並行アクセス時の挙動

**期待される成果物**:

- 拡充された統合テスト

---

### タスク4: カバレッジ目標達成確認

**目的**: テストカバレッジが目標を達成していることを確認する

**実行手順**:

1. カバレッジレポートを再生成:
   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```
2. 以下の基準を確認:

   **ユニットテストカバレッジ**:
   | 指標 | 最低基準 | 推奨基準 |
   | ---- | -------- | -------- |
   | Line Coverage | 80% | 90% |
   | Branch Coverage | 60% | 70% |
   | Function Coverage | 80% | 90% |

   **結合テストカバレッジ**:
   | 指標 | 目標 |
   | ---- | ---- |
   | APIエンドポイント | 100% |
   | 正常系シナリオ | 100% |
   | 異常系シナリオ | 80%+ |

3. 未達の場合は追加テストを作成

**期待される成果物**:

- カバレッジレポート（`outputs/phase-6/coverage-report.md`）
