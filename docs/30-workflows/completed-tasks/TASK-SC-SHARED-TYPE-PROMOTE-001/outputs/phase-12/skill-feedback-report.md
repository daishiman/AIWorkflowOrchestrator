## task-specification-creator スキルへの改善提案

### 1. 条件付き成果物の扱い

**現状の課題**: Phase 2〜11 の成果物がすべて「昇格実施の場合のみ」という条件付きになっているにもかかわらず、
`artifacts.json` の初期値は全 Phase が `pending` で生成される。
「昇格不要・即クローズ」の場合、Phase 2〜11 の pending 項目が残り、
タスクが未完了に見える可能性がある。

**改善提案**: `artifacts.json` に `conditional: true` と `condition` フィールドが既に設定されているため、
Phase 完了スクリプト (`complete-phase.js`) が `conditional=true` の成果物を自動的に `skipped` にする機能を追加するとよい。

### 2. 型昇格判断タスクのテンプレート

**現状**: 「1箇所なら即クローズ、2箇所以上なら昇格」というフローが仕様書に記載されているが、
Phase 1 の結論に応じて後続 Phase が自動的に `skipped` にならない。

**改善提案**: 「条件分岐フロー型タスク」テンプレートを追加し、
Phase 1 の判断結果フラグ（`upgrade: true/false`）に基づいて後続 Phase のステータスを自動設定できるようにする。

### 3. 即クローズパターンの文書化

**現状**: 「1箇所のみ → 即クローズ」という判断を行った場合、
Phase 12 の完了条件に「Phase 11 手動テスト結果が存在すること」という記述があり、
昇格不要の場合も Phase 11 の成果物が求められているように読める。

**改善提案**: Phase 12 の完了条件に「昇格不要の場合は Phase 11 は N/A」という分岐を明記する。
