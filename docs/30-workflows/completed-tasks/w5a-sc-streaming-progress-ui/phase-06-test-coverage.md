## 目的

Phase 4 では網羅しきれなかった境界値・異常系・タイミング系テストを追加し、カバレッジ基準（TDD原則: テストファースト。カバレッジ基準: Line 80%/Branch 60%/Function 80%）を達成する。

## 背景

Phase 5 で実装が完了しテストがGreenになったが、Phase 4 で作成したテストだけでは境界値や異常系のカバレッジが不十分な可能性がある。本Phaseでは、カバレッジ基準を確実に達成するためにテストを拡充する。

## 実行タスク

### タスク1: 進捗100%未到達でのストリーム切断テスト

**目的**: ストリームが途中で切断された場合のUI挙動を検証する

**実行手順**:

1. `percent` が 80% の状態でストリームが切断された場合のUI確認テストを作成する
2. `NETWORK_ERROR` エラーが表示されることを確認するテストを作成する
3. プログレスバーが 80% で停止したまま表示されることを確認するテストを作成する

**期待される成果物**:

- `GenerateStep.test.tsx` 内にストリーム切断テストスイートが追加されている

### タスク2: 高速連続更新時のUI安定性テスト

**目的**: 短時間に大量の進捗イベントが届いた場合のUI安定性を検証する

**実行手順**:

1. 100ms 未満の間隔で進捗イベントが連続して届いた場合のUI安定性確認テストを作成する
2. P13（タイマーテスト）対策: レンダリングデバウンスのテストに `advanceTimersByTime` を使用する
3. 最終的な表示が最後のイベントと一致することを確認するテストを作成する

**期待される成果物**:

- `GenerateStep.test.tsx` または `useGenerationProgress.test.ts` 内に高速連続更新テストが追加されている

### タスク3: 境界値テスト

**目的**: 各プロパティの境界値における表示を検証する

**実行手順**:

1. `percent` = 0 / 50 / 100 の各境界でのプログレスバー表示テストを作成する
2. `previewContent` = `null` / 空文字列 / 長文（100行超）の各ケーステストを作成する
3. `message` が空文字列の場合のフォールバック表示テストを作成する

**期待される成果物**:

- テストファイル内に境界値テストスイートが追加されている

### タスク4: リスナー登録・解除テスト

**目的**: IPCリスナーのライフサイクル管理が正しいことを検証する

**実行手順**:

1. P5（リスナー二重登録防止）対策: コンポーネントのアンマウント時にリスナーが解除されることを確認するテストを作成する
2. 再マウント時に二重登録されないことを確認するテストを作成する

**期待される成果物**:

- `useGenerationProgress.test.ts` 内にリスナーライフサイクルテストが追加されている

### タスク5: エラー → リトライ → 成功フローテスト

**目的**: エラー発生後のリカバリフローが正しく動作することを検証する

**実行手順**:

1. `LLM_ERROR` 後にリトライボタンを押すと生成が再開されることを確認するテストを作成する
2. リトライ後に進捗が 0% からリスタートすることを確認するテストを作成する

**期待される成果物**:

- `GenerateStep.test.tsx` 内にエラーリカバリフローテストが追加されている

## 統合テスト連携

本Phaseで確認すべき統合テスト観点:

- ストリーム切断時にZustandストアのエラー状態が正しく更新されること
- リスナー解除後にイベントが到着してもストアが更新されないこと
- リトライフローでIPCが正しく再送信されること
