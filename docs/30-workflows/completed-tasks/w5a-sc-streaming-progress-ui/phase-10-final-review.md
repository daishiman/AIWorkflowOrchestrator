## 目的

AC-3（進捗ストリーミング）・AC-6（エラーメッセージ）の充足を多角的に検証し、PASS / MINOR / MAJOR / CRITICAL の判定を行う。MINOR 指摘は必ず未タスク仕様書に変換する。

## 背景

Phase 9 で品質ゲートを通過し、Lint・型チェック・テストの全てがクリーンな状態になっている。本Phaseでは、技術的な品質だけでなく、受入基準（AC-3: 進捗ストリーミング、AC-6: エラーメッセージ）への適合性、既知の落とし穴（P5/P31/P48）への対策状況、アクセシビリティの観点から多角的にレビューを行い、Phase 11 の手動テストに進められる状態であることを判定する。

## 実行タスク

### タスク1: AC-3（進捗ストリーミング）の検証

**目的**: 進捗ストリーミング表示が受入基準を満たしていることを検証する

**実行手順**:

1. SKILL_CREATOR_PROGRESS イベントを受け取り、UIがリアルタイムで更新されることを確認する
2. 4段階（構造計画中→SKILL.md生成中→agents生成中→バリデーション中）が正しい順序で表示されることを確認する
3. `percent` 値に応じてプログレスバーが正しく動作することを確認する

**期待される成果物**:

- AC-3 検証結果（充足 / 不充足の判定と根拠）

### タスク2: AC-6（エラーメッセージ）の検証

**目的**: エラーメッセージ表示が受入基準を満たしていることを検証する

**実行手順**:

1. API Key 未設定エラー時に設定画面への誘導が表示されることを確認する
2. LLMエラー時にリトライボタンが表示されることを確認する
3. ネットワークエラー時にオフライン表示が出ることを確認する
4. エラーメッセージにシステム内部情報（スタックトレース等）が漏洩していないことを確認する（セキュリティ）

**期待される成果物**:

- AC-6 検証結果（充足 / 不充足の判定と根拠）

### タスク3: P5（リスナー二重登録）対策の最終確認

**目的**: リスナー管理が正しく実装されていることを最終確認する

**実行手順**:

1. P5（リスナー二重登録防止）: useEffectクリーンアップでリスナー解除必須 -- コンポーネントのアンマウント・再マウント時にリスナーが正しく管理されていることを確認する

**期待される成果物**:

- P5 対策の最終確認結果

### タスク4: P31・P48 対策の最終確認

**目的**: Zustand の状態管理パターンが正しく適用されていることを最終確認する

**実行手順**:

1. P31（Zustand無限ループ）: 個別セレクタ使用、合成Hook依存回避 -- Zustand 個別セレクタが正しく使用されていることを確認する
2. P48（useShallow）: filter/mapの派生セレクタにuseShallow適用 -- `useShallow` が必要な箇所に適用されていることを確認する

**期待される成果物**:

- P31・P48 対策の最終確認結果

### タスク5: アクセシビリティ確認

**目的**: アクセシビリティ属性が正しく設定されていることを確認する

**実行手順**:

1. プログレスバーに `aria-valuenow` / `aria-valuemin` / `aria-valuemax` が設定されていることを確認する
2. エラーメッセージに `role="alert"` が設定されていることを確認する
3. キャンセルボタンに適切なラベルが設定されていることを確認する

**期待される成果物**:

- アクセシビリティ確認結果

### タスク6: 総合判定

**目的**: Phase実行ルール準拠に基づき最終判定を行う

**実行手順**:

1. タスク1-5 の結果を総合し、PASS / MINOR / MAJOR / CRITICAL の判定を行う
2. MINOR 指摘が存在する場合は全て未タスク仕様書に変換する（省略不可）

**期待される成果物**:

- 総合判定結果（PASS / MINOR / MAJOR / CRITICAL）
- MINOR 指摘の未タスク仕様書（指摘が存在する場合）

## 統合テスト連携

### 本Phaseが影響する統合テスト観点

- **AC-3 充足確認**: 進捗ストリーミング表示が受入基準を満たしていること
- **AC-6 充足確認**: エラーメッセージ表示が受入基準を満たしていること
- **リスナー管理**: アンマウント・再マウント時のリスナー登録・解除が正しいこと
- **アクセシビリティ**: aria属性・role属性が正しく設定されていること

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション                       |
| -------- | ------------------------ | ------------------------------------ |
| PASS     | 全レビュー観点で問題なし | Phase 11へ進行                       |
| MINOR    | 軽微な指摘あり           | 指摘を未タスク仕様書化後、Phase 11へ |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る                 |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認            |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |

### フィードバックループ脱出条件

- 最大イテレーション: 2回
- 3回目突入時: 未解決項目をMINOR指摘として未タスク仕様書に変換し、Phase 11へ進む
