## 目的

実装コードの品質を向上させる。進捗状態管理の共通ロジックをカスタムHookに抽出し、コンポーネントの責務を明確にする。

## 背景

Phase 5 で実装した GenerateStep コンポーネントには、リスナーロジック・エラー表示・プログレスバーなど複数の責務が混在している。Phase 7 でカバレッジ基準を達成した状態のテストスイートを安全網として、コードの構造改善を行う。リファクタリングにより保守性と再利用性を高め、後続の品質検証（Phase 9）・最終レビュー（Phase 10）をスムーズに進められる状態にする。

## 実行タスク

### タスク1: 進捗状態管理のカスタムHook抽出

**目的**: GenerateStep コンポーネントからリスナーロジックを分離し、単一責務の原則を適用する

**実行手順**:

1. `GenerateStep.tsx` 内にインライン実装されているリスナーロジックを `useStreamingProgress` Hook に完全移動する
2. コンポーネントが受け取るのは Hook の戻り値のみになるよう整理する
3. `useStreamingProgress` の返却型を明確に定義する

**期待される成果物**:

- リスナーロジックが完全にカプセル化された `useStreamingProgress` Hook

### タスク2: エラー表示コンポーネントの分離

**目的**: エラー種別ごとのUIを独立したコンポーネントに切り出し、責務を分割する

**実行手順**:

1. エラー種別（API Key / LLM / Network）ごとのサブコンポーネントを統合ファイルに切り出す
   - `generate-step/ErrorCards.tsx`
2. `GenerateStep.tsx` は条件分岐のみ担当するようリファクタリングする
3. Apple HIG準拠・Atomic Designパターンに従う

**期待される成果物**:

- `generate-step/ErrorCards.tsx`（ErrorCards統合ファイル）

### タスク3: プログレスバーの再利用可能コンポーネント化

**目的**: プログレスバーを汎用コンポーネントとして切り出し、再利用性を高める

**実行手順**:

1. プログレスバーを `packages/ui` の atoms として切り出す（再利用可能な場合）
2. ステップ表示コンポーネントを分離する
3. Apple HIG準拠・Atomic Designパターンに従う

**期待される成果物**:

- 再利用可能なプログレスバーコンポーネント
- ステップ表示コンポーネント

### タスク4: 型安全性の強化

**目的**: 型安全性を高め、ランタイムエラーを防止する

**実行手順**:

1. `any` 型の排除
2. エラーコードを union 型（`'API_KEY_NOT_SET' | 'LLM_ERROR' | 'NETWORK_ERROR'`）で定義する
3. P47（型安全マッピング）: `Record<ErrorCode, ReactNode>` パターンでエラーUIの対応表を管理する

**期待される成果物**:

- union 型で定義されたエラーコード型
- `Record<ErrorCode, ReactNode>` による型安全なエラーUIマッピング

### タスク5: リファクタリング後の動作確認

**目的**: リファクタリングによる回帰がないことを確認する

**実行手順**:

1. 全テストが引き続き Green であることを確認する
2. `pnpm typecheck` が通過することを確認する
3. Phase 7 で達成したカバレッジ基準を維持していることを確認する

**期待される成果物**:

- テスト実行結果（全 Green）
- 型チェック通過の確認
