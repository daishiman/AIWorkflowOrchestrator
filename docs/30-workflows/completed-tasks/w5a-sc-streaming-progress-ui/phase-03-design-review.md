## 目的

Phase 2 の設計内容を多角的にレビューし、既知の落とし穴（P5・P31・P48）への対策が十分かどうかを検証する。PASS / MINOR / MAJOR の判定を行い、次 Phase への移行可否を決定する。

## 背景

設計フェーズの成果物に対してレビューゲートを設け、実装前に設計上の問題を検出・修正することで、後続Phaseでの手戻りを防止する。特にZustandの状態管理パターンとIPCリスナーのライフサイクル管理は、実装後の修正コストが高いため、設計段階での検証が重要である。

## 実行タスク

### タスク1: P5（リスナー二重登録）対策レビュー

**目的**: IPCリスナーのライフサイクル管理が安全に設計されているか検証する

**実行手順**:

1. `useEffect` のクリーンアップ関数でリスナー解除が設計されているか確認
2. React StrictMode 下での二重実行を考慮しているか確認
3. モジュールレベルガードの要否を判断する

**期待される成果物**:

- P5対策レビュー結果（問題なし / 指摘事項あり）

### タスク2: P31（Zustand無限ループ）対策レビュー

**目的**: Zustandセレクタパターンが無限ループを引き起こさない設計か検証する

**実行手順**:

1. 合成Hook（`useGenerationProgress()`）の戻り値関数が `useEffect` の依存配列に含まれないよう設計されているか確認
2. 個別セレクタ（`useGenerationStage()` / `useGenerationPercent()` 等）が設計されているか確認

**期待される成果物**:

- P31対策レビュー結果（問題なし / 指摘事項あり）

### タスク3: P48（useShallow適用）レビュー

**目的**: 不要な再レンダリングを防止するuseShallow適用が適切か検証する

**実行手順**:

1. `.filter()` / `.map()` を使う派生セレクタに `useShallow` が適用されているか確認
2. `generationProgress` スライスで配列を返すセレクタの有無を確認

**期待される成果物**:

- P48対策レビュー結果（問題なし / 指摘事項あり）

### タスク4: エラーハンドリング設計レビュー

**目的**: エラー分岐の網羅性とセキュリティを検証する

**実行手順**:

1. 3種類のエラー（API Key未設定・LLMエラー・ネットワーク）の分岐が漏れなく設計されているか確認
2. エラーコードのサニタイズ（Renderer に内部情報を漏洩しない）が設計されているか確認

**期待される成果物**:

- エラーハンドリング設計レビュー結果

### タスク5: キャンセル設計レビュー

**目的**: キャンセルフローの安全性を検証する

**実行手順**:

1. AbortController の生成・破棄タイミングが正しいか確認
2. キャンセル後の状態リセット漏れがないか確認

**期待される成果物**:

- キャンセル設計レビュー結果

### タスク6: 総合判定

**目的**: レビュー結果を総合し、次Phaseへの移行可否を決定する

**実行手順**:

1. タスク1〜5の結果を総合する
2. PASS / MINOR / MAJOR / CRITICAL の判定を行う
3. 判定結果に基づく次のアクションを決定する

**期待される成果物**:

- 総合判定結果（PASS / MINOR / MAJOR / CRITICAL）と指摘事項一覧

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な設計問題あり       | Phase 2へ戻り設計修正     |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |

最大イテレーション: 2回。3回目突入時は未解決項目をMINOR指摘として未タスク仕様書に変換し、Phase 4へ進む。
