## 目的

スキル生成中の進捗をリアルタイムでUIに表示するための要件を定義する。現行の GenerateStep コンポーネント（スピナーのみ）の課題を明確にし、進捗表示・エラーハンドリング・キャンセル機能の受入基準を確立する。

## 背景

現行の GenerateStep コンポーネントはスピナーのみを表示しており、スキル生成がどの段階にあるか・エラーが発生したか・キャンセルが可能かといった情報をユーザーに提供できていない。本Phaseでは、ストリーミング進捗表示に必要な要件を網羅的に定義する。

## 実行タスク

### タスク1: SKILL_CREATOR_PROGRESS チャンネルの現行定義調査

**目的**: 進捗イベントの現行ペイロード型と送信箇所を把握する

**実行手順**:

1. `apps/desktop/src/preload/skill-creator-api.ts` のチャンネル定義を確認する
2. Main プロセス側の進捗イベント送信箇所を特定する

**期待される成果物**:

- `SKILL_CREATOR_PROGRESS` チャンネルの現行ペイロード型の記録

### タスク2: GenerateStep.tsx の現行UI実装確認

**目的**: 現行実装の問題点を具体的に把握する

**実行手順**:

1. スピナーのみの現行実装を把握する
2. 進捗データを受け取る口がないことを確認する

**期待される成果物**:

- GenerateStep.tsx の現行実装状態の記録

### タスク3: 進捗表示要件の定義

**目的**: 各段階のユーザー向けメッセージと表示仕様を定義する

**実行手順**:

1. 表示すべき段階の洗い出し（構造計画中 → SKILL.md 生成中 → agents 生成中 → バリデーション中）
2. 各段階のユーザー向けメッセージを定義する

**期待される成果物**:

- 進捗4段階の定義とユーザー向けメッセージ一覧

### タスク4: エラー表示要件の定義

**目的**: エラーパターンとその対応UIを定義する

**実行手順**:

1. API Key 未設定エラー → 設定画面への誘導
2. LLMエラー（レートリミット等）→ リトライ案内
3. ネットワークエラー → オフライン表示

**期待される成果物**:

- 3種類のエラーパターンと対応UIの定義

### タスク5: キャンセル機能要件の定義

**目的**: キャンセル操作の要件を明確にする

**実行手順**:

1. キャンセルトリガー（ボタン押下）の定義
2. AbortController による中断処理の要件定義
3. キャンセル後のUI状態の定義

**期待される成果物**:

- キャンセル機能の要件仕様

### タスク6: 受入基準（AC）の確定

**目的**: FR-2（リアルタイム進捗表示）・AC-3（進捗ストリーミング）・AC-6（エラーメッセージ）の充足基準を確立する

**実行手順**:

1. FR-2: リアルタイム進捗表示の受入基準を定義する
   - 進捗4段階（構造計画中→SKILL.md生成中→agents生成中→バリデーション中）がUIに反映されること
2. AC-3: 進捗ストリーミングの受入基準を定義する
   - Main プロセスからの進捗イベントがリアルタイムでUIに反映されること
3. AC-6: エラーメッセージの受入基準を定義する
   - 3種類のエラー（API Key未設定・LLMエラー・ネットワークエラー）が適切にUIに表示されること

**期待される成果物**:

- FR-2 / AC-3 / AC-6 の受入基準チェックリスト

## NFR（非機能要件）

### アクセシビリティ

- プログレスバーに `role="progressbar"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax` 属性を付与する
- 各ステップの状態変化を `aria-live="polite"` でスクリーンリーダーに通知する
- エラーメッセージに `role="alert"` を付与する

### パフォーマンス

- 高速連続更新に対するデバウンス処理（100ms）を適用し、UIのちらつきを防止する
- 進捗更新ごとの再レンダリングを最小限に抑える（個別セレクタパターン使用）

### i18n方針

- ユーザー向けメッセージは将来的な国際化を考慮し、メッセージキー方式で管理可能な構造にする（初期実装はハードコーディング可）

### セキュリティ

- エラー表示において内部実装の詳細（スタックトレース、内部API URL等）をユーザーに漏洩しないこと
- Renderer プロセスに送信するエラー情報はサニタイズ済みのエラーコードとユーザー向けメッセージのみとする
