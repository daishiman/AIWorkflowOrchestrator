### タスク3: blocker の有無判定

**目的**: Phase 11 進行を阻む blocker が存在しないことを確認する

**実行手順**:

1. 以下の観点で blocker を確認する
   - AC-001〜AC-005 のうち「未達」となっている項目があるか
   - 品質ゲート（typecheck / lint / test）で未解決のエラーが残っていないか
   - 実装に根本的な設計問題が発見されていないか
2. blocker がある場合は原因 Phase に戻る
3. blocker がない場合は Phase 11 への進行承認を記録する

**判定基準**:

| 判定     | 条件                                                    | 次のアクション                |
| -------- | ------------------------------------------------------- | ----------------------------- |
| PASS     | AC-001〜AC-005 が全て「達成」                           | Phase 11 へ進行               |
| MINOR    | 未達が 1 件以下かつ AC-001/002/003 を含まない           | 修正後に Phase 11 へ進行      |
| MAJOR    | 未達が 2 件以上、または AC-001/002/003 のいずれかが未達 | 未達 AC の原因 Phase へ戻る   |
| CRITICAL | 設計前提の崩壊、対象定義の破綻                          | Phase 1〜3 へ戻りユーザー確認 |

**戻り先決定基準**:

| 問題の種類                            | 戻り先           |
| ------------------------------------- | ---------------- |
| AC-001 未達（SKILL.md 更新されない）  | Phase 5          |
| AC-002 未達（purpose 再生成されない） | Phase 5          |
| AC-003 未達（AbortSignal 機能しない） | Phase 5 または 8 |
| AC-004 未達（TypeScript 型エラー）    | Phase 9          |
| AC-005 未達（テスト FAIL）            | Phase 5 または 9 |

4. 判定結果と根拠を `final-review-result.md` に記録する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md` の blocker 判定セクション（判定結果・根拠・次アクション）
