## 1. 目的

テストが全てパスしている状態を維持しながら、コードの品質を改善する（TDD: Refactor Phase）。

---

## 2. 実行タスク

### Task 1: コード品質評価

#### 手順

1. 修正したコードを以下の観点でレビューする：

   **可読性**
   - [ ] 変数名・関数名が明確である
   - [ ] コメントが適切に記述されている
   - [ ] 関数の長さが適切である

   **保守性**
   - [ ] 単一責任の原則を守っている
   - [ ] 重複コードがない
   - [ ] マジックナンバーがない

   **一貫性**
   - [ ] 既存コードスタイルと一致している
   - [ ] 命名規則が統一されている

2. 改善が必要な箇所を特定する

#### 成果物

- コード品質評価結果

#### 完了条件

- [ ] コード品質が評価されている
- [ ] 改善箇所が特定されている（ある場合）

---

### Task 2: デバッグログの整理

#### 手順

1. Phase 1で追加したデバッグログを確認する

2. 本番環境でも有用なログは維持する

3. 開発時のみ必要なログは以下のように条件付きにする：

   ```typescript
   if (process.env.NODE_ENV === "development") {
     console.log("[SkillImportManager] Store path:", (store as any).path);
   }
   ```

4. または、専用のロガーを使用する：

   ```typescript
   import { logger } from "@shared/utils/logger";

   logger.debug("[SkillImportManager] Store path:", (store as any).path);
   ```

#### 成果物

- 整理済みデバッグログ

#### 完了条件

- [ ] デバッグログが適切に整理されている
- [ ] 本番環境に不要なログが出力されないようになっている

---

### Task 3: 定数の整理（必要な場合）

#### 手順

1. `STORE_KEY`などの定数が適切な場所に定義されているか確認する

2. 複数ファイルで使用される定数は共通モジュールに移動する

3. 定数名が明確かどうか確認する

#### 成果物

- 整理済み定数定義

#### 完了条件

- [ ] 定数が適切な場所に定義されている
- [ ] 定数名が明確である

---

### Task 4: テスト実行・リファクタリング確認

#### 手順

1. リファクタリング後に全テストを実行する：

   ```bash
   pnpm --filter @repo/desktop test SkillImportManager
   ```

2. 全テストがパスすることを確認する

3. 型チェックを実行する：

   ```bash
   pnpm --filter @repo/desktop typecheck
   ```

4. Lintを実行する：

   ```bash
   pnpm --filter @repo/desktop lint
   ```

#### 成果物

- テスト・品質チェック結果

#### 完了条件

- [ ] 全テストがパス
- [ ] TypeScriptエラーなし
- [ ] Lintエラーなし
