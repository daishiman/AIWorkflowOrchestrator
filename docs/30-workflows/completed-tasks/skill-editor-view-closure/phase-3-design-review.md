## 目的

Phase 1（要件定義）と Phase 2（設計）の成果物を多角的に検証し、
実装前に問題を検出・修正する。PASS/MINOR/MAJOR の3段階で判定し、
次フェーズへの進行可否を決定する。

---

## 実行タスク

- 要件レビュー: Phase 1 の完全性と整合性を検証する
- 設計レビュー: Phase 2 の実現可能性と既存コード整合を検証する
- 横断レビュー: アクセシビリティ・セキュリティ・パフォーマンスをクロスレビューする
- 判定記録: PASS/MINOR/MAJOR の判定結果と指摘事項を記録する
- 未タスク化: MINOR 指摘事項を未タスク仕様書へ変換する（0件でも必須）

## 6. 指摘事項の処理

### 実装時に対応する指摘（Phase 5 での注意事項として管理）

| 指摘ID | 対応方針                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------- |
| M-001  | `MobileDrawer` に `useFocusTrap` hook を追加、または `focus-trap-react` ライブラリを検討              |
| M-002  | `useToast` で `MAX_TOASTS = 3` の上限を設け、超過時は古い Toast から削除する                          |
| M-003  | Phase 5 実装前に `grep -rn "ViewType" apps/desktop/src/` で既存実装を確認する                         |
| M-004  | Toast 実装時に `variantStyles: Record<ToastVariant, string>` を export する                           |
| M-005  | `useKeyboardNavigation` の `flatNodes` 計算を `useMemo(fn, [fileTree, expandedDirs])` でキャッシュ    |
| M-006  | `SkillEditorView` に `useEffect(() => { if (!isMobile) setIsDrawerOpen(false); }, [isMobile])` を追加 |
| M-007  | `useToast` の ID 生成に `crypto.randomUUID()` を使用                                                  |

### 未タスク登録対象

今回の MINOR 指摘は全て **Phase 5（実装）時の注意事項として管理**し、
個別の未タスク仕様書は作成しない（実装スコープ内で対応可能なため）。

`unassigned-task-detection.md` には **0件** として記録する。
