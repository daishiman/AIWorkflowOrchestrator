## 課題別要件定義

### UT-UI-05A-001: FileTree キーボードナビゲーション

#### 現状分析

- `FileTreeNode` は `role="treeitem"`, `aria-selected`, `aria-expanded` を実装済み
- **不足**: `tabIndex` がなく、`onKeyDown` ハンドラが存在しない
- WAI-ARIA Authoring Practices の Tree Pattern（1.2）が未準拠

#### 機能要件

| 要件ID  | 要件内容                                                                 |
| ------- | ------------------------------------------------------------------------ |
| F-001-1 | `ArrowDown` / `ArrowUp` で次/前のノードにフォーカスを移動できること      |
| F-001-2 | `ArrowRight` でディレクトリを展開、またはファイルを選択できること        |
| F-001-3 | `ArrowLeft` でディレクトリを閉じる、または親ディレクトリに移動できること |
| F-001-4 | `Enter` / `Space` でファイルを選択できること                             |
| F-001-5 | `Escape` でフォーカスをツリールートに戻すこと                            |
| F-001-6 | Home/End で最初/最後の表示ノードへ移動できること                         |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                 | 要件                                                                       |
| -------------------- | -------------------------------------------------------------------------- |
| 2.1.1 キーボード     | 全機能をキーボードのみで操作できること                                     |
| 4.1.2 名前・役割・値 | `role="tree"` / `role="treeitem"` の WAI-ARIA パターンを完全準拠させること |
| 2.4.7 フォーカス可視 | フォーカス時に `2px` 以上のリングで視覚的に識別できること                  |

#### UI/UX 要件（Apple HIG）

- フォーカスリング: `2px solid var(--status-primary)` + `outline-offset: -2px`
- フォーカス移動のアニメーション: なし（パフォーマンス重視）

#### 受け入れ基準

- [ ] Tab キーでツリーにフォーカスを入れられる（`tabIndex={0}`）
- [ ] Arrow キーでノード間を移動できる
- [ ] Enter で選択、ArrowRight で展開、ArrowLeft で折り畳みができる
- [ ] Escape でフォーカスが解放される
- [ ] キーボード操作中にフォーカスリングが表示される
- [ ] スクリーンリーダーが選択状態・展開状態を読み上げられる

### UT-UI-05A-002: モバイルドロワー

#### 現状分析

- `SkillEditorView` は `flex h-full w-full` の固定2ペインレイアウト
- `FileTreePanel` の幅が固定で、768px 未満でも常時表示される
- レスポンシブ対応なし

#### 機能要件

| 要件ID  | 要件内容                                                              |
| ------- | --------------------------------------------------------------------- |
| F-002-1 | 画面幅 768px 未満のとき、FileTreePanel をドロワーとして表示すること   |
| F-002-2 | ドロワーはハンバーガーボタン（≡）でトグルできること                   |
| F-002-3 | ドロワー外領域をクリックするとドロワーが閉じること（Overlay Dismiss） |
| F-002-4 | ドロワーは画面左からスライドインすること（transform: translateX）     |
| F-002-5 | 768px 以上では既存の2ペインレイアウトに戻ること                       |
| F-002-6 | ファイル選択後にドロワーが自動的に閉じること                          |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                       | 要件                                                |
| -------------------------- | --------------------------------------------------- |
| 2.1.1 キーボード           | Escape キーでドロワーを閉じられること               |
| 4.1.3 ステータスメッセージ | ドロワーの開閉状態を `aria-expanded` で公開すること |
| 1.4.13 ホバーコンテンツ    | オーバーレイはポインタ操作でも閉じられること        |

#### UI/UX 要件（Apple HIG）

- ドロワー幅: `280px`（固定）
- トランジション: `transform 250ms ease-in-out`
- オーバーレイ: `bg-black bg-opacity-30` + `backdrop-blur-sm`
- ハンバーガーボタン: `EditorToolBar` 内に配置（768px 未満のみ表示）

#### 受け入れ基準

- [ ] 画面幅 767px 以下でドロワーモードに切り替わる
- [ ] ハンバーガーボタンが `EditorToolBar` に表示される
- [ ] ドロワーが 250ms アニメーションで開閉する
- [ ] オーバーレイをクリックするとドロワーが閉じる
- [ ] Escape キーでドロワーが閉じる
- [ ] ファイル選択後にドロワーが自動的に閉じる
- [ ] 768px 以上では2ペインに戻る

### UT-UI-05A-003: Cmd/Ctrl+S 保存ショートカット

#### 現状分析

- `handleSave` は実装済みだが、キーボードショートカットのリスナーがない
- `EditorToolBar` に保存ボタンは存在する
- `isReadOnly` のとき保存が不要

#### 機能要件

| 要件ID  | 要件内容                                                                   |
| ------- | -------------------------------------------------------------------------- |
| F-003-1 | `Cmd+S`（macOS）/ `Ctrl+S`（Windows/Linux）でファイルを保存できること      |
| F-003-2 | `isReadOnly=true` のとき、ショートカットは無効であること                   |
| F-003-3 | ブラウザのデフォルト保存ダイアログをキャンセルすること（`preventDefault`） |
| F-003-4 | 保存中は重複実行を防ぐこと（二重送信防止）                                 |
| F-003-5 | ファイルが選択されていない状態では無効であること                           |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                         | 要件                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------ |
| 2.1.4 文字キーショートカット | 単一文字ショートカットではなく修飾キーとの組み合わせを使用すること（準拠済み） |

#### UI/UX 要件（Apple HIG）

- macOS: `Cmd+S`（`metaKey`）、Windows/Linux: `Ctrl+S`（`ctrlKey`）
- ショートカット実行後に Toast 通知を表示する（UT-UI-05A-004 と連携）

#### 受け入れ基準

- [ ] `Cmd+S`（macOS）で保存が実行される
- [ ] `Ctrl+S`（Windows/Linux）で保存が実行される
- [ ] ブラウザのデフォルト動作がキャンセルされる
- [ ] `isReadOnly=true` のとき無効
- [ ] 保存中（`isSaving=true`）のとき重複実行されない
- [ ] ファイル未選択時は無効

### UT-UI-05A-004: 保存成功 Toast 通知

#### 現状分析

- `handleSave` は `await saveFile()` 後にフィードバックなし
- エラーバナーは存在するが、成功通知はない
- Toast コンポーネントは未実装

#### 機能要件

| 要件ID  | 要件内容                                                                      |
| ------- | ----------------------------------------------------------------------------- |
| F-004-1 | 保存成功時に「保存しました」Toast を 2500ms 表示すること                      |
| F-004-2 | Toast は画面右下に表示されること                                              |
| F-004-3 | Toast 表示中に再保存した場合、既存 Toast をリセットしてカウントを再開すること |
| F-004-4 | Toast は手動で閉じられること（×ボタン）                                       |
| F-004-5 | 保存失敗時はエラー Toast を表示し、自動消去しないこと                         |
| F-004-6 | Toast 表示は `useToast` カスタムフックで管理すること                          |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                       | 要件                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| 4.1.3 ステータスメッセージ | Toast を `role="status"` または `role="alert"` で公開すること（成功: status, エラー: alert） |
| 1.4.2 音声の制御           | 音声フィードバックなし（視覚的 Toast のみ）                                                  |

#### UI/UX 要件（Apple HIG）

- 成功 Toast: `bg-[var(--status-success)]`、アイコン: `CheckCircle`
- エラー Toast: `bg-[var(--status-error)]`、アイコン: `XCircle`
- フォント: `text-sm font-medium`
- 角丸: `rounded-lg`
- 影: `shadow-md`
- 出現/消去アニメーション: `opacity 200ms ease-in-out` + `translateY 200ms`

#### 受け入れ基準

- [ ] 保存成功時に「保存しました」Toast が表示される
- [ ] Toast は 2500ms 後に自動消去される
- [ ] Toast は手動で閉じられる（×ボタン）
- [ ] 保存失敗時にエラー Toast が表示される（自動消去なし）
- [ ] Toast に `role="status"`（成功）または `role="alert"`（エラー）が設定される
- [ ] スクリーンリーダーが Toast を読み上げる

### UT-UI-05A-005: 読み取り専用表示強化

#### 現状分析

- `isReadOnly` props は存在するが、視覚的フィードバックが不十分
- ツールバーのボタングレーアウトのみ
- ロックアイコンやバナーによる明示的な「編集不可」表示がない

#### 機能要件

| 要件ID  | 要件内容                                                                     |
| ------- | ---------------------------------------------------------------------------- |
| F-005-1 | `isReadOnly=true` のとき、ファイル名の隣にロックアイコン（🔒）を表示すること |
| F-005-2 | エディターエリア上部に「読み取り専用」バナーを表示すること                   |
| F-005-3 | バナーには `Lock` アイコン + 「読み取り専用 — 編集できません」テキスト       |
| F-005-4 | ツールバーの保存・バックアップボタンを非表示にすること（グレーアウトでなく） |
| F-005-5 | テキスト選択（コピー）は許可すること                                         |
| F-005-6 | エディター入力フィールドに `readOnly` 属性を設定すること                     |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準             | 要件                                                      |
| ---------------- | --------------------------------------------------------- |
| 1.3.1 情報と関係 | 読み取り専用状態を `aria-readonly="true"` で公開すること  |
| 1.4.1 色の使用   | ロックアイコン + テキストで状態を伝え、色だけに依存しない |

#### UI/UX 要件（Apple HIG）

- バナー背景: `bg-[var(--bg-tertiary)]` + ボーダー下線
- バナーテキスト色: `text-[var(--text-secondary)]`
- ロックアイコン: `lucide-react` の `Lock` コンポーネント（16px）

#### 受け入れ基準

- [ ] `isReadOnly=true` のときロックアイコンがファイル名付近に表示される
- [ ] 「読み取り専用」バナーがエディター上部に表示される
- [ ] 保存・バックアップボタンが非表示になる
- [ ] エディターに `aria-readonly="true"` が設定される
- [ ] テキスト選択（コピー）はできる
- [ ] `isReadOnly=false` のときバナーとロックアイコンが非表示

### UT-UI-05A-006: ナビゲーション導線配線

#### 現状分析

- `SkillEditorView` は `onClose` callbacks を持つが、AppDock や SkillCenter からの遷移が未配線
- `ViewType` に `skill-editor` が定義されていない可能性がある
- AppDock → SkillCenter → SkillEditorView の遷移フローが未実装

#### 機能要件

| 要件ID  | 要件内容                                                                                |
| ------- | --------------------------------------------------------------------------------------- |
| F-006-1 | AppDock → SkillCenter でスキル管理画面に遷移できること                                  |
| F-006-2 | SkillCenter → SkillEditorView でスキル編集画面に遷移できること                          |
| F-006-3 | SkillEditorView の閉じるボタンで SkillCenter に戻れること                               |
| F-006-4 | `ViewType` 型に `'skill-editor'` を追加し、Zustand store で状態管理すること             |
| F-006-5 | 未保存変更がある場合、遷移前に `UnsavedChangesDialog` を表示すること                    |
| F-006-6 | SkillEditorView に遷移するとき、編集対象の `skillName` を store または props で渡すこと |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                 | 要件                                                         |
| -------------------- | ------------------------------------------------------------ |
| 2.4.2 ページタイトル | 遷移後にフォーカスが適切な要素（ページ見出し）に移動すること |

#### UI/UX 要件（Apple HIG）

- 遷移はアニメーションなし（View 切り替えの一貫性維持）
- 閉じるボタン: ツールバー右端に `×` アイコン

#### 受け入れ基準

- [ ] AppDock に「スキル」ナビゲーション項目が存在する
- [ ] SkillCenter のスキル一覧から「編集」で SkillEditorView に遷移できる
- [ ] SkillEditorView の閉じるボタンで SkillCenter に戻れる
- [ ] `ViewType` に `'skill-editor'` が追加されている
- [ ] Zustand store が `currentSkillName` を保持する
- [ ] 未保存変更時に `UnsavedChangesDialog` が表示される

### UT-UI-05A-007: マイクロアニメーション

#### 現状分析

- `FileTreeNode` に `transition-colors duration-150` のみ（色変化のみ）
- パネル切り替えやファイル選択時のトランジションなし
- エディターコンテンツの切り替え時にアニメーションなし

#### 機能要件

| 要件ID  | 要件内容                                                                 |
| ------- | ------------------------------------------------------------------------ |
| F-007-1 | ファイル選択時に選択背景色が `150ms` でフェードインすること              |
| F-007-2 | ディレクトリ展開/折り畳み時に `200ms` の高さアニメーションを適用すること |
| F-007-3 | エディターコンテンツ切り替え時に `150ms opacity` フェードを適用すること  |
| F-007-4 | ツールバーボタンのホバー時に `150ms` カラートランジションを適用すること  |
| F-007-5 | アニメーションは `prefers-reduced-motion` を尊重し、無効化できること     |

#### アクセシビリティ要件（WCAG 2.1 AA）

| 基準                                       | 要件                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| 2.3.3 インタラクションによるアニメーション | `prefers-reduced-motion: reduce` のとき全アニメーションを無効化すること |

#### UI/UX 要件（Apple HIG）

- アニメーション時間: 150ms〜250ms の範囲（目的を持ったもののみ）
- イージング: `ease-in-out`（自然な動き）
- Tailwind CSS の `transition-*` クラスを使用すること

#### 受け入れ基準

- [ ] ファイル選択時に 150ms の背景色フェードインがある
- [ ] ディレクトリ展開/折り畳みに高さアニメーションがある
- [ ] エディターコンテンツ切り替えに opacity アニメーションがある
- [ ] ツールバーボタンにホバーアニメーションがある
- [ ] `prefers-reduced-motion: reduce` でアニメーションが無効化される

## 多角的チェック観点

### アクセシビリティ

- [ ] WAI-ARIA Tree Pattern 1.2 を完全準拠しているか（F-001）
- [ ] 全インタラクティブ要素にキーボードアクセスができるか
- [ ] WCAG 2.1 AA のコントラスト比（4.5:1 以上）を満たしているか

### セキュリティ

- [ ] `isReadOnly` 状態でサーバーへの書き込みリクエストが発生しないか
- [ ] キーボードショートカットが XSS の起点にならないか（入力値サニタイズ確認）

### パフォーマンス

- [ ] アニメーションが `transform`/`opacity` の GPU 合成レイヤーを使用しているか
- [ ] ドロワーの `resize` イベントリスナーが `debounce` されているか
- [ ] Toast の複数表示でメモリリークが発生しないか
