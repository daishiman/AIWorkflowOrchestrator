## 目的

自動テストでは確認できない、実際のスキルディレクトリに対する Layer3/4 verify 動作と verify→improve→reverify ループの挙動を手動で確認する。

## 実行タスク

- 実際のスキル（例: `task-specification-creator`）で Layer3/4 verify を実行する
- 手動での verify→improve→reverify ループを実施する
- 発見した問題点を記録する
- 自動テストでの追加が必要な場合は記録する

## 手動テストシナリオ

### シナリオ MT-01: 実際のスキルでの Layer3 verify

**対象スキル**: `.claude/skills/task-specification-creator/`

**手順**:

1. 対象スキルの `output-schema.json` を確認する
2. `SkillCreatorVerificationEngine.verify()` を Electron アプリから呼び出す（またはテストコードで直接呼び出す）
3. L3-001（`$schema` フィールド）と L3-002（`type` フィールド）の結果を確認する
4. agent の責務記述（L3-003）の結果を確認する

**確認ポイント**:

- L3-001 が期待どおりの severity を返す
- L3-002 が実際の schema に対して正しく評価される
- L3-003 が各 agent の実際の記述量に対して正しく評価される

### シナリオ MT-02: 実際のスキルでの Layer4 verify

**対象スキル**: `.claude/skills/task-specification-creator/`

**手順**:

1. 対象スキルの `SKILL.md` を確認して Anchors セクションの内容を確認する
2. L4-001（Anchors リスト項目）の結果を確認する
3. `references/` ディレクトリが存在する場合、L4-002（参照整合性）の結果を確認する
4. L4-003（agent ファイル名参照）の結果を確認する

**確認ポイント**:

- L4-001 が実際の SKILL.md の Anchors 記述に対して正しく評価される
- L4-002 が `references/` の実在ファイルと正しく照合される

### シナリオ MT-03: 手動 verify→improve→reverify ループ

**手順**:

1. Layer3/4 チェックが fail する状態のスキルを用意する（テスト用フィクスチャを使用）
2. `engine.verify()` で fail を確認する
3. 問題箇所を手動で修正する
4. `engine.verify()` で info になることを確認する

**確認ポイント**:

- 修正後の re-verify が確実に改善された結果を返す
- verify 結果が deterministic（同じ入力で同じ出力）である

## 発見した問題の記録方法

| 項目         | 内容                                   |
| ------------ | -------------------------------------- |
| 問題ID       | MT-BUG-xxx（連番）                     |
| 発見シナリオ | MT-01 / MT-02 / MT-03                  |
| 再現手順     | 具体的な手順を記述                     |
| 期待結果     | 正しい動作の説明                       |
| 実際の結果   | 問題のある動作の説明                   |
| 対処方針     | fix / skip / accept / defer のいずれか |

## 統合テスト連携

- Phase 12 でドキュメント更新時に手動テスト結果を参照する
