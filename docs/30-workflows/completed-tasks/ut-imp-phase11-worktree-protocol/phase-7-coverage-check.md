## 目的

Phase 6 で拡充したテスト（ユニットテスト43ケース + E2Eテスト16ケース）のカバレッジ基準が以下の全項目を満たしていることを確認する。未達の場合は Phase 6 に戻り、追加テストを作成する。

| 指標              | 最低基準 | 推奨基準 |
| ----------------- | -------- | -------- |
| Line Coverage     | 80%      | 90%      |
| Branch Coverage   | 60%      | 70%      |
| Function Coverage | 80%      | 90%      |

## 実行手順

### Task 1: ユニットテストカバレッジの計測

**目的**: Phase 6 で拡充した全ユニットテストを実行し、対象ソースファイルのカバレッジを計測する。

**実行コマンド**:

```bash
cd apps/desktop && pnpm vitest run --coverage src/main/utils/__tests__/
```

**計測対象ファイル**:

| ファイル                   | テストファイル                   | テストケース数 |
| -------------------------- | -------------------------------- | -------------- |
| `worktree-detector.ts`     | `worktree-detector.test.ts`      | 11             |
| `deferred-tests-parser.ts` | `deferred-tests-parser.test.ts`  | 13             |
| `test-layer-classifier.ts` | `test-layer-classifier.test.ts`  | 13             |
| （統合テスト）             | `worktree-protocol-flow.test.ts` | 6              |
| **合計**                   |                                  | **43**         |

**期待するカバレッジ結果**:

| ファイル                   | Line Coverage | Branch Coverage | Function Coverage |
| -------------------------- | ------------- | --------------- | ----------------- |
| `worktree-detector.ts`     | 90%+          | 70%+            | 100%              |
| `deferred-tests-parser.ts` | 90%+          | 70%+            | 100%              |
| `test-layer-classifier.ts` | 90%+          | 70%+            | 100%              |
| **全体**                   | **80%+**      | **60%+**        | **80%+**          |

**注意事項**:

- P41 対策: v8 カバレッジプロバイダはインライン arrow function を独立した関数としてカウントする。Function Coverage が低下する場合は、インライン関数のコールバックを明示的にテストで呼び出す
- カバレッジレポートは `coverage/` ディレクトリに出力される

### Task 2: E2E テストカバレッジの確認

**目的**: E2E テスト（Playwright）の実行結果を確認し、テストケースの PASS/FAIL 状態を記録する。

**実行コマンド**（Electron ビルド済み環境）:

```bash
cd apps/desktop && npx playwright test e2e/ --reporter=list
```

**確認対象**:

| テストファイル             | テストケース数 | 期待結果    |
| -------------------------- | -------------- | ----------- |
| `ipc-skill-remove.spec.ts` | 8              | 全 PASS     |
| `ipc-skill-import.spec.ts` | 8              | 全 PASS     |
| **合計**                   | **16**         | **全 PASS** |

**注意事項**:

- E2E テストは Electron ビルド後にのみ実行可能
- Worktree 環境ではビルドが困難なため、CI 環境での実行結果を記録する
- Worktree 環境で実行不可の場合は、「CI 実行予定」として `outputs/phase-7/coverage-report.md` に記録する

### Task 4: カバレッジゲート判定

**目的**: カバレッジ計測結果を基準値と比較し、ゲート判定を行う。

**判定基準**:

| 判定結果 | 条件                                                         | 次のアクション |
| -------- | ------------------------------------------------------------ | -------------- |
| PASS     | Line 80%+ かつ Branch 60%+ かつ Function 80%+ の全基準を達成 | Phase 8 へ     |
| FAIL     | いずれかの基準を未達                                         | Phase 6 へ戻る |

**ゲート判定テンプレート**:

```markdown
## カバレッジゲート判定結果

| 指標              | 基準 | 実測値 | 判定          |
| ----------------- | ---- | ------ | ------------- |
| Line Coverage     | 80%+ | XX.X%  | PASS/FAIL     |
| Branch Coverage   | 60%+ | XX.X%  | PASS/FAIL     |
| Function Coverage | 80%+ | XX.X%  | PASS/FAIL     |
| **総合判定**      |      |        | **PASS/FAIL** |
```

### Task 5: 未達時の Phase 6 戻りフロー

**実行条件**: Task 4 のゲート判定が FAIL の場合のみ実行する。

**戻りフロー手順**:

1. 未達の指標（Line / Branch / Function）を特定する
2. 未カバーの具体的なコード行・ブランチ・関数を `coverage/` レポートから抽出する
3. 追加テストケースを設計する（テストケース ID は既存の連番に続ける）
4. Phase 6 の該当 Task に戻り、テストを追加する
5. Phase 7 を再実行する

**未達時の記録テンプレート**:

## 多角的チェック観点

### セキュリティ観点

- [ ] カバレッジレポートに機密情報（ファイルパス以外のシークレット）が含まれていない
- [ ] テスト結果の artifacts にテストデータの機密情報が含まれていない

### パフォーマンス観点

- [ ] カバレッジ計測を含むユニットテスト全体の実行時間が60秒以内に収まっている
- [ ] フレイキーテスト確認（3回実行）の合計時間が3分以内に収まっている
- [ ] E2E テスト全体の実行時間が60秒以内に収まっている（NFR-2）

### 既知の落とし穴（Pitfall）対策

- [ ] P41 対策: v8 カバレッジプロバイダのインライン関数カウントを確認し、Function Coverage が不当に低下していないことを確認
- [ ] P9 対策: テスト間の状態リークによるフレイキーテストが発生していないことを3回連続実行で確認
- [ ] P40 対策: カバレッジ計測コマンドが `apps/desktop/` ディレクトリから実行されている

### コード品質観点

- [ ] カバレッジレポートの数値が `outputs/phase-7/coverage-report.md` に正確に転記されている
- [ ] ゲート判定結果が根拠（カバレッジ数値）と共に記録されている
- [ ] 未達箇所がある場合、具体的なファイル名・行番号が記録されている
