## 実行手順

### ステップ 1: カバレッジ分析

`skill-api.ts` への追加は以下の2箇所のみ:

| 変更箇所                  | カバレッジ対象 | テストカバー状況            |
| ------------------------- | -------------- | --------------------------- |
| インターフェース定義      | 対象外         | 型のみのため実行コードなし  |
| `evaluateSafety` メソッド | 対象           | T-1〜T-3 で呼び出し確認済み |

`evaluateSafety` は分岐のない1行の arrow function（`safeInvoke` 呼び出し）であるため、T-1〜T-6 で Line/Branch/Function 全て 100% 達成可能。

### ステップ 2: 追加テスト判断

Phase 4 の T-1〜T-6 でカバー済みの観点:

| テスト | カバー観点                              |
| ------ | --------------------------------------- |
| T-1    | safeInvoke が正しいチャンネルで呼ばれる |
| T-2    | 引数が正しく渡される                    |
| T-3    | 戻り値が変換なしで返される              |
| T-4    | ホワイトリスト確認                      |
| T-5    | プロパティ存在確認                      |
| T-6    | エラー伝搬確認                          |

追加テスト候補の検討:

| 候補                                 | 必要性 | 判断                                               |
| ------------------------------------ | ------ | -------------------------------------------------- |
| 複数回呼び出しで引数が独立に渡される | 低     | safeInvoke 自体のテストで網羅済み                  |
| undefined 引数での呼び出し           | 低     | Main 側の3段バリデーションでカバー済み（P42 準拠） |

**結論**: T-1〜T-6 で十分。追加テスト不要。

cd apps/desktop && pnpm vitest run src/preload/__tests__/skill-api.evaluateSafety.test.ts --coverage
