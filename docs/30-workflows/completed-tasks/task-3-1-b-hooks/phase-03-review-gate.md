## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、実装に進む前に品質を確保する。

## 背景

設計レビューゲートは、要件と設計の整合性を検証し、実装フェーズで手戻りが発生しないようにするための重要なチェックポイントである。

> 以下のタスクを順番に実行してください。

### タスク1: 要件カバレッジ確認

**目的**: Phase 1で定義した全要件がPhase 2の設計でカバーされているか確認する

**実行手順**:

2. 非機能要件（NFR-001〜NFR-003）が設計で考慮されているかチェック
3. 未対応の要件があれば指摘

**期待される成果物**:

- 要件カバレッジマトリックス

**目的**: 設計ドキュメント内の整合性を確認する

**実行手順**:

3. 依存タスク（TASK-3-1-A、TASK-2C）との整合性を確認

**期待される成果物**:

- 整合性確認チェックリスト

### タスク3: 技術的リスク評価

**目的**: 実装時に発生しうる技術的リスクを評価する

**実行手順**:

1. 依存ライブラリ（Claude Agent SDK）のリスクを評価
2. パフォーマンスリスクを評価
3. セキュリティリスクを評価

**期待される成果物**:

- リスク評価表

#### リスク評価表

| リスク                     | 影響度 | 発生確率 | 対策                                  |
| -------------------------- | ------ | -------- | ------------------------------------- |
| SDK Hooks APIの変更        | 中     | 低       | SDKバージョンを固定、型定義で検出可能 |
| 危険パターンの漏れ         | 高     | 低       | TASK-2Cで網羅的に定義済み             |
| 保護パスの漏れ             | 高     | 低       | TASK-2Cで網羅的に定義済み             |
| Hook処理でのブロッキング   | 中     | 低       | 非同期処理、タイムアウト設定で対応    |
| ストリームメッセージの欠落 | 中     | 低       | エラーハンドリングでcatchして通知     |

### タスク4: レビュー判定

**目的**: 次のPhaseに進むかどうかを判定する

**実行手順**:

1. 全チェック項目の結果を集約
2. 判定基準に基づいて判定
3. 判定結果と理由を記録

**期待される成果物**:

- レビュー判定結果

#### レビュー判定基準

| 判定     | 条件                     | 次のアクション          |
| -------- | ------------------------ | ----------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ   |
| MAJOR    | 重大な問題あり           | Phase 2へ戻り設計修正   |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻り要件再定義 |

#### 判定結果記入欄

| 項目           | 内容                                |
| -------------- | ----------------------------------- |
| 判定           | （PASS / MINOR / MAJOR / CRITICAL） |
| 判定理由       | （判定の根拠を記載）                |
| 指摘事項       | （ある場合のみ記載）                |
| 次のアクション | （判定に基づくアクションを記載）    |
