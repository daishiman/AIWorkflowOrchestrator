## 実行手順

### Task 1: 要件 ↔ 設計の整合性検証

Phase 1 の受入基準を1つずつ Phase 2 の設計と照合する。

| 要件 ID | 要件内容                                             | 設計の対応箇所                  | 判定 |
| ------- | ---------------------------------------------------- | ------------------------------- | ---- |
| F-1     | SlideSyncCard が 4状態表示                           | Task 1.1 Props + 状態マッピング | -    |
| F-2     | SlideProgressRow が running 時に表示                 | Task 1.2 条件レンダリング       | -    |
| F-3     | SlideWatchStatus が 3状態表示                        | Task 1.3 WatcherState 型        | -    |
| F-4     | SlideGuidanceBlock が 2バリアント                    | Task 1.4 GuidanceVariant 型     | -    |
| F-5     | Persistent Terminal Launcher                         | Task 5 全状態共通固定表示       | -    |
| F-6     | degraded: failure reason + retry + terminal fallback | Task 1.4 degraded variant CTA   | -    |
| F-7     | guidance: 設定導線 + terminal launcher               | Task 1.4 guidance variant CTA   | -    |
| Q-1     | Apple HIG System Colors                              | Task 1 カラーパレット           | -    |
| Q-2     | キーボード操作                                       | Task 5 アクセシビリティ         | -    |
| Q-3     | ARIA ラベル                                          | 各コンポーネント設計            | -    |
| Q-4     | 個別セレクタ（P31/P48）                              | Task 3 selectors.ts             | -    |

### Task 2: 正本仕様との整合性検証

1. `ui-ux-feature-components-details.md` L177-L247 の各仕様項目と設計を照合
2. 以下の観点で差分がないか確認:
   - コンポーネント名・責務の一致
   - 状態 → UI マッピングの一致
   - CTA ラベル・挙動の一致
   - カラーパレットの一致

### Task 3: P31/P48/P62 対策の検証

| 落とし穴 | 対策設計                                   | 検証観点                                  |
| -------- | ------------------------------------------ | ----------------------------------------- |
| P31      | 個別セレクタ（useSyncStatus 等）           | store 全体参照が残っていないか            |
| P48      | useShallow で派生セレクタをラップ          | .filter/.map で新配列を返すセレクタの有無 |
| P62      | deriveSlideUIStatus で guidance 状態を導出 | DEFAULT_CONFIG fallback が存在しないか    |
| P46      | Omit で HTML 標準属性との衝突回避          | Props 名に content/color 等がないか       |
| P47      | variantStyles を Record で外部定義         | テスト側から参照可能な定数設計            |

### Task 4: アクセシビリティ検証

| 項目             | 基準                   | 検証方法                           |
| ---------------- | ---------------------- | ---------------------------------- |
| コントラスト比   | 4.5:1 以上             | systemColors の Light/Dark 値確認  |
| キーボード       | 全 CTA にフォーカス可  | Tab 順序設計の確認                 |
| ARIA ラベル      | 全インタラクティブ要素 | Props に aria-label を含めているか |
| 色以外の情報伝達 | テキスト併用           | Badge にラベルテキストがあるか     |

### Task 5: 依存タスク境界の検証

| 本タスク（UT-SLIDE-UI-001）の責務 | UT-SLIDE-IMPL-001 の責務 |
| --------------------------------- | ------------------------ |
| UI コンポーネント実装             | store フィールド追加     |
| 個別セレクタ定義                  | IPC ハンドラ接続         |
| SlideUIStatus 導出ロジック        | SyncStatus 型語彙変更    |
| 条件レンダリング                  | handoffGuidance DTO 実装 |
| モック状態でのテスト              | 実データでの結合テスト   |

**確認**: UI タスクが store 未実装フィールドに依存する箇所は、型定義のみ先行しモック値でテスト可能か。

## レビュー判定基準

| 判定  | 条件                                         | 対応               |
| ----- | -------------------------------------------- | ------------------ |
| PASS  | 全検証項目クリア                             | Phase 4 へ         |
| MINOR | 軽微な改善点あり（命名、コメント等）         | 指摘対応後 Phase 4 |
| MAJOR | 設計の根本的問題あり（状態管理、責務分離等） | Phase 2 へ戻る     |
