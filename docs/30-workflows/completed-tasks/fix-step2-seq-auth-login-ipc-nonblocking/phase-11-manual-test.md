# Phase 11: 手動テスト（NON_VISUAL）

## メタ情報

| 項目       | 値                                         |
| ---------- | ------------------------------------------ |
| Phase      | 11                                         |
| 機能名     | auth:login IPCハンドラーの非ブロッキング化 |
| 作成日     | 2026-04-01                                 |
| テスト種別 | NON_VISUAL（ログ/コンソール確認）          |

## 目的

`auth:login` が 500ms 制約内で即時応答し、成功・失敗の状態通知は `AuthFlowOrchestrator` が継続送信することを手動で確認する。

## 実行タスク

- MT-01〜MT-04 の手動シナリオを順番に実行する
- 各シナリオで応答時間、状態通知、失敗経路を確認する
- 結果を `outputs/phase-11/` に記録する

## 事前条件

- アプリケーションが起動している
- `auth:login` を呼び出せる状態である
- コンソールとログを確認できる

## テスト手順

### シナリオ MT-01: 500ms 以内の即時応答

```
1. アプリケーションを起動する
2. `auth:login` を呼び出す操作を実行する
3. 呼び出し直後に `{ success: true }` が返ることを確認する
4. 応答待ちが 500ms を超えないことを確認する
```

| 確認項目 | 期待結果            | 実際の結果 |
| -------- | ------------------- | ---------- |
| 応答時間 | 500ms 以内          | TBD        |
| 戻り値   | `{ success: true }` | TBD        |

### シナリオ MT-02: 無効 provider の即時拒否

```
1. 無効な provider を指定して `auth:login` を呼び出す
2. 例外またはエラーコードを確認する
3. 呼び出し側が待機し続けないことを確認する
```

| 確認項目   | 期待結果                | 実際の結果 |
| ---------- | ----------------------- | ---------- |
| エラー種別 | `auth/invalid-provider` | TBD        |
| 応答性     | 即時拒否                | TBD        |

### シナリオ MT-03: 成功時の状態通知分離

```
1. 有効な provider で `auth:login` を呼び出す
2. handler が待たずに戻ることを確認する
3. `AuthFlowOrchestrator` が `AUTH_STATE_CHANGED` を送信することを確認する
4. handler 側で同じ通知を重複送信していないことを確認する
```

| 確認項目 | 期待結果          | 実際の結果 |
| -------- | ----------------- | ---------- |
| 通知元   | orchestrator のみ | TBD        |
| 重複送信 | なし              | TBD        |

### シナリオ MT-04: 失敗・キャンセル時の非ブロッキング確認

```
1. 認証をキャンセルするか失敗経路を発生させる
2. handler が待機し続けないことを確認する
3. 失敗通知が orchestrator から届くことを確認する
```

| 確認項目 | 期待結果          | 実際の結果 |
| -------- | ----------------- | ---------- |
| 応答性   | 待機なし          | TBD        |
| 失敗通知 | orchestrator 由来 | TBD        |
