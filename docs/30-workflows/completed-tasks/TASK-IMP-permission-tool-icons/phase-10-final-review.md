### ステップ3: 最終レビュー判定

| 判定         | 条件                              | アクション           |
| ------------ | --------------------------------- | -------------------- |
| **PASS**     | 全AC達成、全成果物✅              | Phase 11へ進む       |
| **MINOR**    | 軽微な修正が必要（1-2項目が❌）   | 修正後Phase 11へ進む |
| **MAJOR**    | 重大な修正が必要（3項目以上が❌） | 該当Phaseへ差し戻し  |
| **CRITICAL** | 根本的な問題                      | Phase 1へ差し戻し    |

**差し戻し先基準（8カテゴリ）**:

| 問題の種類       | 差し戻し先                  |
| ---------------- | --------------------------- |
| 要件の問題       | Phase 1（要件定義）         |
| 設計の問題       | Phase 2（設計）             |
| テスト設計の問題 | Phase 4（テスト作成）       |
| 実装の問題       | Phase 5（実装）             |
| テスト拡充の問題 | Phase 6（テスト拡充）       |
| カバレッジ不足   | Phase 7（カバレッジ確認）   |
| コード品質の問題 | Phase 8（リファクタリング） |

**MINOR判定時のフロー**:

```
MINOR判定 → 課題を分析
    ↓
未タスク指示書を作成（generate-unassigned-task agent使用）
    ↓
docs/30-workflows/unassigned-task/ に配置
    ↓
Phase 11へ進む
```

**エスカレーション条件**: 差し戻し先判断が困難、複数Phaseにまたがる問題、要件自体の見直し、重大なセキュリティ懸念の場合はユーザーに判断を求める。
