### ステップ3: レビュー判定

| 判定         | 条件                              | アクション          |
| ------------ | --------------------------------- | ------------------- |
| **PASS**     | 全チェック項目が✅                | Phase 4へ進む       |
| **MINOR**    | 軽微な修正が必要（1-2項目が❌）   | 修正後Phase 4へ進む |
| **MAJOR**    | 重大な修正が必要（3項目以上が❌） | Phase 2へ差し戻し   |
| **CRITICAL** | 設計の根本的な問題                | Phase 1へ差し戻し   |

**差し戻し先基準**:

| 問題の種類           | 差し戻し先          |
| -------------------- | ------------------- |
| 要件の問題           | Phase 1（要件定義） |
| 設計の問題           | Phase 2（設計）     |
| 要件・設計両方の問題 | Phase 1（要件定義） |

### ステップ4: レビュー結果の記録

レビュー結果を `outputs/phase-3/design-review-result.md` に記録する。

記録内容:

- レビュー日時
- 各チェック項目の結果（✅/❌）
- 6観点レビュー結果
- 判定結果（PASS/MINOR/MAJOR/CRITICAL）
- 指摘事項（ある場合）
- 対応方針（ある場合）

**エスカレーション条件**: 差し戻し先判断が困難、複数Phaseにまたがる問題、要件自体の見直し、重大なセキュリティ懸念の場合はユーザーに判断を求める。
