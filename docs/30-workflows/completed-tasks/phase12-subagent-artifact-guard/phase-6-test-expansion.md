## 目的

Phase 5 で実装したテンプレート・監査ルール・三点突合チェックリストに対し、エッジケーステスト・回帰テスト・クロスバリデーションを追加してテスト網羅性を高める。Phase 4 の基本テストでカバーしきれなかった境界条件と既存ワークフローとの整合を検証する。

## 背景

Phase 4 の基本テストはテンプレートの必須構造と正常系を対象としたが、実運用では不完全な入力・重複データ・既存成果物との後方互換性が課題になる。本Phase ではこれらのエッジケースを網羅し、テンプレートと監査スクリプトの堅牢性を確認する。

## 実行タスク

- Task 6-1 エッジケーステスト: 異常入力と境界値でテンプレート検証の堅牢性を確認する
- Task 6-2 回帰テスト: 既存完了ワークフローとの後方互換性を確認する
- Task 6-3 クロスバリデーション: summary と subagent-report の内容整合を検証する

### Task 6-1: エッジケーステスト

異常・境界入力に対するテンプレートと監査スクリプトの動作を検証する。

**テストケース:**

1. **空テンプレートケース**
   - spec-update-summary.md が空ファイルの場合、構造検証テストが FAIL を返す
   - spec-sync-subagent-report.md が空ファイルの場合、責務テーブル検証が FAIL を返す

2. **不完全な SubAgent 責務表**
   - 「完了条件」列が欠落したテーブルで FAIL を返す
   - SubAgent ID が重複したテーブルで FAIL を返す
   - 「担当仕様書」が空文字列のケースで FAIL を返す

3. **重複メタ情報ケース**
   - `## メタ情報` が2回以上出現するファイルで、1セクション原則違反を検出する
   - メタ情報テーブル内の必須項目（タスクID）が欠落している場合に FAIL を返す

4. **境界値ケース**
   - SubAgent数=0（更新対象仕様書なし）の場合の正常動作
   - SubAgent数=1（最小ケース）の場合の正常動作
   - 更新対象仕様書に日本語パスが含まれる場合の正常動作

### Task 6-2: 回帰テスト

既存の完了済みワークフローの成果物が新テンプレートの構造基準に準拠しているかを検証する。

**テストケース:**

1. **既存 spec-update-summary 検証**
   - `docs/30-workflows/completed-tasks/` 配下の既存 spec-update-summary.md を新テンプレートの構造チェッカーで検証
   - 既存ファイルが新テンプレートの必須セクションを含んでいるか確認
   - 差分がある場合は「既存ファイル形式」と「新テンプレート形式」の対応表を作成

2. **既存 subagent-report 検証**
   - 既存の SubAgent 関連成果物（もしあれば）を新テンプレートの形式で検証
   - 既存ファイルが存在しない場合は「新規作成が必要」と判定

3. **三点突合の後方互換テスト**
   - 既存の phase-12-documentation.md / documentation-changelog.md のペアに対し、三点突合チェックリストを実行
   - 既存ファイル形式での突合可能性を確認（完全一致でなくてもキー項目の抽出が可能か）

### Task 6-3: クロスバリデーション

`spec-sync-subagent-report.md` と `spec-update-summary.md` の内容整合を検証する。

**テストケース:**

1. **SubAgent数の整合**
   - subagent-report のSubAgent行数と summary の更新対象仕様書数が一致すること
   - 不一致の場合に差分を明示するエラーメッセージが出力されること

2. **仕様書パスの整合**
   - subagent-report の「担当仕様書」列と summary の「更新対象仕様書一覧」のパスが完全一致すること
   - パスの正規化（末尾スラッシュ、相対/絶対パス）による偽の不一致を防ぐこと

3. **ステータスの整合**
   - subagent-report の全SubAgentが「完了」の場合、summary の全仕様書も「完了」であること
   - 1件でも「未完了」の場合、summary の該当仕様書も「未完了」であること

4. **テンプレート→監査フロー結合テスト**
   - Phase 5 で作成したテンプレートに正常値を入力
   - 監査スクリプトで検証し currentViolations=0 であることを確認
   - テンプレートに意図的にエラーを挿入し currentViolations>=1 であることを確認
