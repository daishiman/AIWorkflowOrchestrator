## 目的

全成果物の多角的品質検証と完了判定を行い、Phase 11（手動テスト検証）への進行可否を決定する。「コードの最終レビュー」ではなく「ドキュメント運用改善の全成果物に対する最終品質ゲート」として実施する。

## 背景

Phase 1-9で要件定義→設計→テスト→実装→カバレッジ→リファクタリング→品質保証の全工程が完了している。Phase 10では、全成果物を横断的にレビューし、4つの最終ゴール（テンプレート再利用性、SubAgent責務保持、三点突合説明可能性、未タスク監査運用）が達成可能であることを確認する。

## SubAgent分担

| SubAgent | 担当                                       |
| -------- | ------------------------------------------ |
| A        | 要件充足性・スコープ遵守の検証             |
| B        | テンプレート品質・三点突合実行可能性の検証 |
| C        | 監査基準明確性・親タスク教訓反映度の検証   |

## レビューゲート判定基準

| 判定     | 条件                     | 対応                                                   |
| -------- | ------------------------ | ------------------------------------------------------ |
| PASS     | 全レビュー観点で問題なし | Phase 11 へ進行                                        |
| MINOR    | 軽微な指摘あり           | 未タスク仕様書に変換後 Phase 11 へ進行（**省略不可**） |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて Phase 1-5 へ戻る                      |
| CRITICAL | 致命的な問題あり         | Phase 1 へ戻り要件再確認                               |

### MINOR指摘の未タスク化ルール

MINOR判定の指摘は**全て**未タスク仕様書に変換する（省略不可）。以下の3ステップを必ず完了する:

1. `docs/30-workflows/unassigned-task/` に指示書を作成する
2. `task-workflow.md` の残課題テーブルに登録する
3. 関連仕様書に参照リンクを追加する

## 実行タスク

- Task 10-1 要件充足性レビュー: 4つの最終ゴール達成可否を検証する
- Task 10-2 テンプレート品質レビュー: 誰が使っても解釈が一致する構造か検証する
- Task 10-3 三点突合実行可能性レビュー: 再現可能な判定手順か検証する
- Task 10-4 監査基準明確性レビュー: current/baseline の判定一意性を検証する
- Task 10-5 親タスク教訓反映度レビュー: 既知課題が対策済みか検証する
- Task 10-6 スコープ遵守レビュー: 対象外変更が混入していないか検証する
- Task 10-7 エレガンス再評価レビュー: 破棄案より採用案が妥当かを再判定する

### Task 10-1: 要件充足性レビュー

4つの最終ゴールが全て達成可能であることを検証する:

1. **テンプレート再利用性**: `spec-update-summary.md` がテンプレート準拠構造で再利用可能か
2. **SubAgent責務保持**: `spec-sync-subagent-report.md` が1仕様書=1SubAgentの責務/依存/完了条件を保持しているか
3. **三点突合説明可能性**: Step 2判定が三点突合で説明可能か
4. **未タスク監査運用**: `currentViolations=0` を合否基準として運用できるか

### Task 10-2: テンプレート品質レビュー

- 100人中100人が同じ理解で使用できるテンプレートであるかを検証する
- フィールドの定義が明確で、記入者の解釈による差異が発生しないことを確認する
- 記入例（Phase 5成果物）と照合し、テンプレートの使用方法が自明であることを確認する

### Task 10-3: 三点突合の実行可能性レビュー

- Phase 8で簡素化された三点突合手順が明確で再現可能であることを検証する
- 手順の各ステップに曖昧さがなく、判定基準が定量的であることを確認する
- 三点突合の入力（仕様書セクション、実ファイル、テスト）の取得方法が明示されていることを確認する

### Task 10-4: 監査基準の明確性レビュー

- `currentViolations` と `baseline` の分離が判定可能であることを検証する
- 監査スクリプトの実行結果からPASS/FAILの判定が一意に決定できることを確認する
- 監査基準の閾値が明示的に定義されていることを確認する

### Task 10-5: 親タスク教訓の反映度レビュー

親タスク（TASK-9A-B等）から抽出された4つの課題が全て対策されているかを検証する:

1. Phase 12成果物の責務固定ルール
2. Step 2三点突合ルール
3. 苦戦箇所の再利用手順
4. task-workflow.md / lessons-learned.md同期

### Task 10-6: スコープ遵守レビュー

以下が含まれていないことを確認する:

- Main/Preload/Renderer新規実装
- 既存baseline違反の全件解消
- Phase 1-11の定義変更

### Task 10-7: エレガンス再評価レビュー

Phase 2 の設計時に決めた「破棄案 vs 改善案」の判定が、Phase 9 までの実装・品質結果と矛盾しないかを再評価する。

1. `outputs/phase-2/elegance-decision-record.md` の採用理由が、Phase 5/8/9 の成果物で裏づけされているか確認
2. 破棄案を今採用した場合の移行コスト・互換性リスクを再計算する
3. 採用案が `currentViolations=0` / warning=0 達成と両立しているか確認する
4. 再評価結果を `outputs/phase-10/elegance-gate-review.md` に記録する
