## 3. SubAgent命名規則

| 規則               | 正しい形式                                        | 誤った形式                       |
| ------------------ | ------------------------------------------------- | -------------------------------- |
| SubAgent識別子     | `SubAgent-A`, `SubAgent-B`, ..., `SubAgent-F`     | `A`, `B`, ..., `F`（短縮形禁止） |
| Step 2チーム識別子 | `SubAgent-S2-A`, `SubAgent-S2-B`, `SubAgent-S2-C` | `S2-A`, `S2-B`（短縮形禁止）     |
| 依存関係記述       | `SubAgent-A完了後`, `SubAgent-A/B/C完了後`        | `A完了後`（短縮形禁止）          |

**理由**: CP-5（SubAgent数整合）の機械検証コマンド `rg -c '^\| SubAgent-'` がセクション横断で正確にカウントできるため。

## 4. 仕様書パス記述規則

| 規則           | 正しい形式                      | 誤った形式                       |
| -------------- | ------------------------------- | -------------------------------- |
| 可変仕様書パス | `references/interfaces-*.md`    | `references/<interface-spec>.md` |
| 可変仕様書パス | `references/api-ipc-*.md`       | `references/<api-ipc-spec>.md`   |
| 可変仕様書パス | `references/security-*.md`      | `references/<security-spec>.md`  |
| 固定仕様書パス | `references/task-workflow.md`   | 変更なし                         |
| 固定仕様書パス | `references/lessons-learned.md` | 変更なし                         |

**理由**: プレースホルダー形式（`<...>`）はMarkdownのHTML解釈で消失するリスクがある。ワイルドカード形式（`*`）は、実際のファイル検索コマンド（`rg --files | rg 'interfaces-'`）と整合する。
