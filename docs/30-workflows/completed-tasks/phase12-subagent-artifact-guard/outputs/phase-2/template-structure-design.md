## 2. 三点突合ルール設計（Task 2-3）

### 2.1 三点の定義

| 点  | 成果物                       | 表す内容                             | 情報の性質     |
| --- | ---------------------------- | ------------------------------------ | -------------- |
| 点1 | `phase-12-documentation.md`  | 更新対象テーブル（何を更新すべきか） | 「計画・目標」 |
| 点2 | `documentation-changelog.md` | Step 2判定（何を更新したか・判定）   | 「実績・証跡」 |
| 点3 | `spec-update-summary.md`     | 更新対象一覧（実際に何を更新したか） | 「実施内容」   |

### 2.2 突合アルゴリズム（3ルール）

**ルール(1): Step 2 要否の一貫性確認**

```
IF 点1の更新対象テーブルに「arch-*」または「api-*」または「interfaces-*」または「security-*」が含まれる
THEN 点2のStep 2判定行（| 2 |）は「完了」であること
ELSE 点2のStep 2判定行は「該当なし」または「N/A」であること

違反判定: 点1にarch/api/interfaces/securityが含まれるのに点2が「該当なし」→ DRIFT
```

**ルール(2): 更新対象の包含関係確認**

```
IF 点2のStep 2で更新した仕様書 = {A, B, C}
THEN 点3の更新対象一覧 ⊇ {A, B, C} であること
     （点3は点2の仕様書を全て含む。点3が点2を上回ることは許容）

違反判定: 点2に記載した仕様書が点3に存在しない→ DRIFT
```

**ルール(3): 反映内容の実質確認**

```
IF 点3の更新対象一覧に仕様書Xが含まれる
THEN 点3のその仕様書Xの「反映内容」セルに実質的な記述があること
     （「記録済み」「更新済み」だけではなく、何を記録したかが記載されている）

違反判定: 反映内容が空欄または「-」のみ→ DRIFT
```

### 2.3 判定パターン

| 判定      | 条件                                                  | 対応                                                         |
| --------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| **PASS**  | ルール(1)〜(3)が全て満足する                          | 三点整合。Phase 12完了可                                     |
| **DRIFT** | ルール(1)〜(3)のいずれかで不一致が発生している        | 不一致点を特定し、該当成果物を修正してから再確認             |
| **N/A**   | 点1にarch-_/api-_/interfaces-*/security-*が含まれない | Step 2対象なし（ドキュメントのみタスク）。N/A理由を点2に明記 |

### 2.4 機械検証コマンド

```bash
# === 点1確認: phase-12-documentation.md の更新対象確認 ===
# Step 2対象（arch/api/interfaces/security）が含まれるか
rg -n 'arch-|api-|interfaces-|security-' \
  docs/30-workflows/completed-tasks/phase12-subagent-artifact-guard/phase-12-documentation.md
# 期待: 該当行が存在→ルール(1)でStep 2「完了」を期待。存在しない→ N/A

# === 点2確認: documentation-changelog.md の Step 2 判定確認 ===
# Step 2行（| 2 |）の判定値を取得
rg -n '^\| 2\s+\|' \
  docs/30-workflows/completed-tasks/phase12-subagent-artifact-guard/outputs/phase-12/documentation-changelog.md
# 期待: Step 2の判定行が1件検出され、「完了」または「該当なし」と記載されている

# === 点3確認: spec-update-summary.md の更新対象一覧確認 ===
# references/ 配下の仕様書行を抽出
rg -n '^\|.*references/' \
  docs/30-workflows/completed-tasks/phase12-subagent-artifact-guard/outputs/phase-12/spec-update-summary.md
# 期待: Step 2で更新した仕様書が全て列挙されている

# === 整合性チェック（手動確認） ===
# 上記3コマンドの結果を並べて、ルール(1)〜(3)を逐次確認する
# - 点1の結果 → ルール(1)の前提条件を判定
# - 点2の結果 → ルール(1)(2)の充足を確認
# - 点3の結果 → ルール(2)(3)の充足を確認
```

### 2.5 三点突合の実行タイミング

| タイミング            | 実行者           | 目的                                  |
| --------------------- | ---------------- | ------------------------------------- |
| Phase 12 Task 2開始前 | SubAgent-S2-A    | 点1を確認し、Step 2要否を確定する     |
| Task 2実施中          | SubAgent-S2-B    | 点2を更新し、Step 2判定を記録する     |
| Task 2完了後          | SubAgent-S2-C    | 点3を確認し、三点突合の最終判定を行う |
| Phase 12完了直前      | 実行エージェント | 三点突合の最終確認（PASS/DRIFT/N/A）  |

## 3. テンプレート整合設計のバリデーション

### 3.1 整合ポイントの機械検証方法

| 整合ポイント                         | 検証方法                                                                    | 期待結果               |
| ------------------------------------ | --------------------------------------------------------------------------- | ---------------------- |
| summary ↔ report のSubAgent名一致    | `rg -n '^\| SubAgent-' summary.md report.md` で行数比較                     | 同一SubAgent名・同数   |
| summary ↔ changelog のStep 2判定一致 | `rg -n '^\| 2\s+\|' changelog.md` と `rg -n 'Step 2' summary.md` 比較       | 判定値が一致           |
| report完了条件 ↔ Phase仕様書完了条件 | report§6チェックリストとphase-12-documentation.md完了条件を下記対応表で照合 | 1対1の対応が明確       |
| 監査スクリプト ↔ 合否基準            | `audit --diff-from HEAD` 結果と `currentViolations=0` 基準の照合            | `currentViolations: 0` |

#### report§6 ↔ phase-12-documentation.md 完了条件 対応表

| spec-sync-subagent-report §6 チェック項目 | phase-12-documentation.md 完了条件                         |
| ----------------------------------------- | ---------------------------------------------------------- |
| currentViolations=0 確認                  | 監査スクリプト実行結果が全PASS                             |
| SubAgent分担テーブルが summary と一致     | summary §3 と report §2 の SubAgent名が完全一致            |
| 各仕様書の必須記載内容が記録済み          | Step 1-A〜Step 2 の全記録が documentation-changelog に存在 |
| 検証コマンド結果が summary §7 と一致      | 検証コマンド実行結果が summary/report 間で同一             |
| Step 2 判定が changelog と一致            | 三点突合の PASS/DRIFT/N/A 判定が確定                       |

#### summary↔report 不一致時の修正フロー

不一致発生時は **summary を正本** とし、report を修正する（summaryがデータフロー上で先に作成される位置づけのため）。

### 3.2 テンプレート更新時の影響範囲

本設計では、テンプレートのセクション構造変更が影響する成果物を以下の通り限定する。

| 変更対象テンプレート                                             | 影響成果物                     | 影響範囲の制限                   |
| ---------------------------------------------------------------- | ------------------------------ | -------------------------------- |
| `phase12-system-spec-retrospective-template.md` のセクション追加 | `spec-update-summary.md`       | 追加セクション分のみ             |
| `phase12-spec-sync-subagent-template.md` のSubAgent追加          | `spec-sync-subagent-report.md` | 追加SubAgent行のみ               |
| 三点突合ルール変更                                               | 全3成果物                      | ルール変更前後で三点突合を再実行 |
