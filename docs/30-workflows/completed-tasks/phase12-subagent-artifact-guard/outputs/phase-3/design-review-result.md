### 2.3 MINOR 指摘事項

#### 指摘 [3-1-M1]: 判定木の第3分岐が2段階確認構造になっている

**対象**: `architecture-design.md` §1.2 プロファイル選択基準

**問題**:

```
(3) IPC/API変更あり？
    YES → P-STD5 を適用
    NO  → P-STD5 または P-RECHECK をステータス確認後に判断
          判断基準: task-workflow.md に step 2 更新対象が存在するか
```

「確認後に判断」という2段構造が残っており、判定木の完全な一意性が確保されていない。

**対応方針**: 以下のように判定木の第3分岐を明確化する

```
(3) IPC/API変更あり？
    YES → P-STD5 を適用
    NO  → (4) task-workflow.md に Step 2 更新対象（arch/api/interfaces/security）の記載あり？
           YES → P-STD5 を適用
           NO  → P-RECHECK を適用
```

**優先度**: 中（Phase 4テスト設計前に対応推奨）
