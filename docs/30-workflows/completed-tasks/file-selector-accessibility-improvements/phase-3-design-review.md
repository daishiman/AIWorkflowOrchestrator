## 目的

Phase 1〜2で定義した要件と設計の妥当性を検証し、実装に進む前に品質ゲートを通過させる。

## 背景

設計レビューゲートでは以下を検証する:

1. 要件の完全性と妥当性
2. 設計のWCAG 2.1 AA準拠
3. 既存システム仕様との整合性
4. 実装可能性とリスク評価

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件の妥当性レビュー

**目的**: Phase 1で定義した要件が完全かつ妥当であることを検証する

**実行手順**:

1. 要件の完全性チェック:
   - [ ] 全てのWCAG違反項目が要件として定義されている
   - [ ] 受け入れ基準が具体的かつテスト可能である
   - [ ] スコープ内外が明確に定義されている

2. 要件の妥当性チェック:
   - [ ] WCAG 2.1 AA準拠に必要十分な要件が含まれている
   - [ ] 既存のUIデザインと矛盾しない
   - [ ] パフォーマンス要件が考慮されている

3. システム仕様との整合性確認:
   - ui-ux-file-selector.md のアクセシビリティ対応セクション
   - ui-ux-design-system.md のコントラスト比要件

**期待される成果物**:

- 要件レビュー結果（outputs/phase-3/requirements-review.md）

---

### タスク2: 設計の妥当性レビュー

**目的**: Phase 2で作成した設計がWCAG準拠かつ実装可能であることを検証する

**実行手順**:

1. useFocusTrap設計レビュー:
   - [ ] フォーカス可能要素の検出ロジックが正しい
   - [ ] Tab/Shift+Tab の循環処理が設計されている
   - [ ] 前回のアクティブ要素の保存・復元が設計されている
   - [ ] エッジケース（空のコンテナ、動的要素）が考慮されている

2. aria属性設計レビュー:
   - [ ] WAI-ARIA Practicesに準拠している
   - [ ] ID参照が正しく設計されている
   - [ ] 状態同期ロジックが設計されている

3. コンポーネント連携設計レビュー:
   - [ ] フォーカスフローが明確に設計されている
   - [ ] イベント伝播の優先順位が定義されている

**期待される成果物**:

- 設計レビュー結果（outputs/phase-3/design-review.md）

---

### タスク3: WAI-ARIA Practices準拠確認

**目的**: 設計がWAI-ARIA Practicesに準拠していることを確認する

**実行手順**:

1. Dialog (Modal) パターン確認:
   - [ ] role="dialog" が設定されている
   - [ ] aria-modal="true" が設定されている
   - [ ] aria-labelledby でタイトルを参照している
   - [ ] フォーカストラップが設計されている
   - [ ] Escapeキーでの閉じる動作が設計されている

2. Listbox パターン確認:
   - [ ] role="listbox" が設定されている
   - [ ] role="option" が各項目に設定されている
   - [ ] aria-selected が設定されている
   - [ ] キーボードナビゲーション（↑/↓/Home/End）が設計されている

3. Button パターン確認:
   - [ ] aria-expanded が設定されている
   - [ ] aria-haspopup="dialog" が設定されている
   - [ ] aria-controls でモーダルを参照している

**期待される成果物**:

- WAI-ARIA準拠確認結果（outputs/phase-3/wai-aria-compliance.md）

---

### タスク4: リスク評価とレビュー判定

**目的**: 実装リスクを評価し、次フェーズへの進行可否を判定する

**実行手順**:

1. リスク評価:
   | リスク | 影響度 | 発生確率 | 対策 |
   | -------------------------------------------- | ------ | -------- | ------------------------------ |
   | フォーカストラップが他コンポーネントに影響 | 中 | 低 | hook化して分離、十分なテスト |
   | 既存UIが崩れる | 中 | 低 | ビジュアルリグレッションテスト |
   | パフォーマンス低下 | 低 | 低 | useCallbackで最適化 |
   | スクリーンリーダー互換性問題 | 中 | 中 | 複数リーダーでテスト |

2. レビュー判定:
   | 判定 | 条件 | 次のアクション |
   | -------- | ------------------------ | ------------------------- |
   | PASS | 全レビュー観点で問題なし | Phase 4へ進行 |
   | MINOR | 軽微な指摘あり | 指摘対応後、Phase 4へ |
   | MAJOR | 重大な問題あり | Phase 1または2へ戻る |
   | CRITICAL | 致命的な問題あり | Phase 1へ戻りユーザー確認 |

**期待される成果物**:

- リスク評価レポート（outputs/phase-3/risk-assessment.md）
- レビュー判定結果（outputs/phase-3/review-decision.md）
