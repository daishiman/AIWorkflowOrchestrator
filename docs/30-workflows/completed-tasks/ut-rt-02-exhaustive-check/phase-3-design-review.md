## 実行手順

### ステップ1: 設計レビュー

以下のチェックリストでレビューを実施する：

#### 機能設計チェック

| チェック項目                                                     | 確認 | 判定 |
| ---------------------------------------------------------------- | ---- | ---- |
| assertNever の配置がプロジェクト慣習に従っている                 | -    | -    |
| switch 文のすべての case が現行 union 型バリアントを網羅している | -    | -    |
| default case に assertNever が配置されている                     | -    | -    |
| 判別子プロパティが literal 型であることが設計に明記されている    | -    | -    |
| 既存 T-01〜T-06 への影響が最小限（振る舞い変更なし）             | -    | -    |

#### 型安全性チェック

| チェック項目                                                           | 確認 | 判定 |
| ---------------------------------------------------------------------- | ---- | ---- |
| discriminated union の判別子が `boolean` でなく literal 型になっている | -    | -    |
| 新バリアント追加時にコンパイルエラーが発生する設計になっている         | -    | -    |
| `assertNever` の型シグネチャ `(x: never): never` が正しい              | -    | -    |

#### リスクチェック

| リスク                            | 影響度 | 設計上の対策                         |
| --------------------------------- | ------ | ------------------------------------ |
| 判別子が boolean 型のままの場合   | 中     | Phase 1 で literal 型確認済みか      |
| switch 化で既存テストが壊れる場合 | 中     | テストは振る舞いをアサートしているか |
| assertNever の重複実装            | 低     | 再利用を優先し重複禁止               |

### ステップ2: 判定

| 判定     | 条件                     | 対応                                     |
| -------- | ------------------------ | ---------------------------------------- |
| PASS     | 全チェック項目で問題なし | Phase 4 へ進行                           |
| MINOR    | 軽微な指摘あり           | 未タスク候補として記録後、Phase 4 へ進行 |
| MAJOR    | 設計に重大な問題あり     | Phase 2 へ戻り設計修正                   |
| CRITICAL | 要件レベルの問題あり     | Phase 1 へ戻りユーザーと確認             |

### ステップ3: 未タスク候補の記録

MINOR 判定事項があれば `outputs/phase-3/minor-issues.md` に記録し、Phase 12 で未タスク化する。
