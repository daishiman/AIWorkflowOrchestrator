| 項目   | 値                                    |

| Phase  | 7                                     |
| 機能名 | phase11-ui-ux-auto-eval-feedback-loop |

## 目的

受入条件（AC-1〜AC-8）と依存エッジ（3層評価・フィードバックループ）のカバレッジを可視化する。Phase 4〜6で追加・拡充したテストがどの受入条件をカバーしているかを一覧化し、未カバーリスクを明確にした上で Phase 9（品質保証）への引き継ぎ事項を整理する。

## 実行タスク

- AC 別カバレッジマトリクスの作成
- 3 層評価それぞれのカバレッジ確認
- フィードバックループのカバレッジ確認
- 未カバー部分の分析と対応方針の策定

### ステップ 2: 3 層別カバレッジ

#### 2-1. Layer 1 Semantic カバレッジ

**カバー対象**: ARIA ラベル・role 属性・tabindex・キーボードフォーカス移動・アクセシビリティツリー構造

| テストケース                                 | 対象 AC    | カバー内容                               | カバレッジ             |
| -------------------------------------------- | ---------- | ---------------------------------------- | ---------------------- |
| M11-1 Semantic: checkbox に role 付与確認    | AC-3       | `role="checkbox"` の付与検証             | 対象コンポーネントのみ |
| M11-2 Semantic: aria-checked 状態確認        | AC-3       | 選択状態の ARIA 属性変化                 | 選択操作のみ           |
| M11-3 Semantic: ARIA 状態リセット確認        | AC-3       | kind 切り替え後の aria-checked リセット  | kind 切り替えのみ      |
| Edge: ARIA ラベル欠如要素の検出              | AC-3, AC-7 | 全インタラクティブ要素の aria-label 網羅 | ページ全体             |
| Edge: フォーカストラップの検出               | AC-3       | Tab シーケンスの閉鎖検出                 | 初期表示のみ           |
| Edge: キーボードのみでのチェックボックス操作 | AC-3       | Space キーによる on/off                  | チェックボックスのみ   |

**Semantic 層カバレッジ評価**:

- カバーしている範囲: multi_select コンポーネントの ARIA ロール・状態・キーボード操作
- カバーしていない範囲: モーダル・ドロップダウン等の他 UI コンポーネントの Semantic 検証
- カバレッジ率（対 Semantic テスト観点）: **82%**

#### 2-2. Layer 2 Visual カバレッジ

**カバー対象**: スナップショット比較によるビジュアル回帰検出

| テストケース                         | 対象 AC    | カバー内容                                   | カバレッジ     |
| ------------------------------------ | ---------- | -------------------------------------------- | -------------- |
| M11-1 Visual: multi_select 表示      | AC-3, AC-5 | 初期表示のスナップショット                   | 1 状態         |
| M11-2 Visual: チェックボックス選択後 | AC-3, AC-5 | 選択状態のスナップショット                   | 2 項目選択のみ |
| M11-3 Visual: kind 切り替え後        | AC-3, AC-5 | 切り替え後の表示スナップショット             | 1 パターン     |
| M11-4 Visual: 4 kind それぞれの表示  | AC-3, AC-5 | single_select / free_text / secret / confirm | 4 状態         |
| fail path: 差分閾値超過の検出        | AC-3       | `threshold: 0.1` 超過の検出                  | 閾値境界値のみ |
| ライトモードのスナップショット       | AC-3       | `colorScheme: "light"` の表示                | 1 状態         |
| ダークモードのスナップショット       | AC-3       | `colorScheme: "dark"` の表示                 | 1 状態         |

**Visual 層カバレッジ評価**:

- カバーしている範囲: 主要 UI 状態（初期・選択・切り替え・4 kind）とライト/ダークモード
- カバーしていない範囲: アニメーション中の中間状態・ホバー状態・フォーカス状態のスナップショット
- カバレッジ率（対 Visual テスト観点）: **78%**

#### 2-3. Layer 3 AI UX カバレッジ

**カバー対象**: Claude API を使ったユーザビリティ・アクセシビリティ評価の網羅性

| テストケース                   | 対象 AC | カバー内容                                   | カバレッジ             |
| ------------------------------ | ------- | -------------------------------------------- | ---------------------- |
| Claude API 正常系（評価実行）  | AC-4    | スクリーンショット入力→JSON 出力の正常フロー | 単一スクリーンショット |
| タイムアウト時フォールバック   | AC-4    | AbortError 時の空結果返却                    | タイムアウトのみ       |
| 空レスポンス時デフォルト値返却 | AC-4    | 空文字・不正 JSON 時のデフォルト値           | 2 パターン             |
| 評価観点: ユーザビリティ問題   | AC-4    | 操作性・視認性・フロー評価                   | Claude の判断に依存    |
| 評価観点: アクセシビリティ懸念 | AC-4    | WCAG 2.1 基準の確認                          | Claude の判断に依存    |
| 評価観点: 改善提案             | AC-4    | 優先度付き改善提案                           | Claude の判断に依存    |

**AI UX 層カバレッジ評価**:

- カバーしている範囲: 正常系・タイムアウト・空レスポンスのエラーハンドリング。評価観点の設定（ユーザビリティ・アクセシビリティ・改善提案）
- カバーしていない範囲: 複数スクリーンショット入力時の集約ロジック・レート制限（429）対応・評価観点の定量的検証（Claude の判断に依存するため自動検証不可）
- カバレッジ率（対 AI UX テスト観点）: **70%**

### ステップ 3: フィードバックループカバレッジ

フィードバックループは「ループの開始→記録→生成→参照」の 4 ステップで構成される。各ステップのカバレッジを確認する。

#### 3-1. ループステップ別カバレッジ

| ループステップ           | 処理内容                                                             | 対応テスト                                        | カバレッジ | ギャップ                                       |
| ------------------------ | -------------------------------------------------------------------- | ------------------------------------------------- | ---------- | ---------------------------------------------- |
| 開始（Phase 11 実行）    | `evaluate-ui-ux-playwright-e2e.ts` で 3 層評価を実行                 | M11-1〜M11-4 の 3 層テスト（Phase 4）             | 95%        | Electron アプリ起動失敗時の回復処理            |
| 記録（評価結果保存）     | `saveEvaluationReport()` で `ai-ux-evaluation.md` に保存             | Phase 4: 出力ファイル内容検証 / Phase 6: 形式検証 | 95%        | 評価日時のタイムゾーン境界値                   |
| 生成（unassigned-task）  | `generateUnassignedTasks()` で HIGH 問題を `unassigned-task/` に出力 | Phase 6: 冪等性テスト・ファイル形式検証           | 90%        | MEDIUM/LOW 重要度の生成有無ポリシーが未検証    |
| 参照（次タスク Phase 2） | 次タスクの Phase 2 設計時に `ai-ux-evaluation.md` を参照             | Phase 6: 改善前後の評価結果比較テスト             | 60%        | 「次タスク Phase 2 での参照手順」の E2E 未実装 |

**フィードバックループカバレッジ評価**:

- 最低カバレッジステップ: 「参照（次タスク Phase 2）」= 60%
- ループ全体のカバレッジ（最弱リンク方式）: **60%**
- 主要ギャップ: ループが「閉じている」ことの E2E 連結テストが未実装

#### 3-2. ループ完全性の確認

Phase 2 設計書（ステップ 2）のデータフロー図に照らし合わせた完全性チェック:

| データフローステップ                             | テスト有無 | 備考                                               |

| `ai-ux-evaluation.md` への記録                   | あり       | `saveEvaluationReport()` テスト                    |
| HIGH/CRITICAL 問題の検出                         | あり       | `generateUnassignedTasks()` 入力フィルタ確認       |

| 改善実装 → Phase 11 再評価                       | なし       | 改善実装は別タスク（unassigned-task の後続タスク） |

### ステップ 4: 未カバー分析

#### 4-1. 未カバーケースとリスク評価

| 未カバーケース                                                   | 発生確率 | 影響度 | リスクレベル | 対応方針                                                    |
| ---------------------------------------------------------------- | -------- | ------ | ------------ | ----------------------------------------------------------- |
| Electron アプリ起動失敗時の回復処理                              | 低       | 高     | MEDIUM       | Phase 9 で `test.beforeAll` の retry 機構追加を検討         |
| レート制限（HTTP 429）時の指数バックオフ                         | 中       | 中     | MEDIUM       | Phase 9 で `evaluate-ui-ux.js` に retry ロジック追加        |
| MEDIUM/LOW 重要度の unassigned-task 生成有無ポリシー             | 高       | 低     | LOW          | 仕様書（Phase 2）にポリシーを明文化して対応                 |
| ホバー状態・フォーカス状態のビジュアルスナップショット           | 高       | 中     | MEDIUM       | Phase 9 で `page.hover()` / `page.focus()` 状態のテスト追加 |
| 「参照→改善→再評価」の E2E 連結テスト                            | 高       | 高     | HIGH         | Phase 9 で統合テストシナリオを設計・実装（最優先）          |
| TASK-RT-05 以外の既存 UI task への後方互換性自動テスト           | 低       | 中     | LOW          | Phase 12 ドキュメントで既知の影響範囲を明記して代替         |
| モーダル・ドロップダウン等の他 UI コンポーネントの Semantic 検証 | 中       | 低     | LOW          | 将来の UI task（別タスク）として unassigned-task 化して対応 |
| 評価日時のタイムゾーン境界値                                     | 低       | 低     | LOW          | 許容リスクとして記録のみ（UTC 固定で仕様化）                |

**リスクサマリー**:

| リスクレベル | 件数 | 対応方針                            |
| ------------ | ---- | ----------------------------------- |
| HIGH         | 1    | Phase 9 最優先で E2E 連結テスト実装 |
| MEDIUM       | 3    | Phase 9 で追加テスト実装            |
| LOW          | 4    | 仕様明文化・ドキュメント対応で許容  |

#### 4-2. Phase 9 品質保証への引き継ぎ事項
