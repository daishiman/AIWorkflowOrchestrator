## 目的

PermissionDialogのリスクバッジ表示を実環境（Electronアプリ or 開発サーバー）で目視確認し、UX・アクセシビリティ・レスポンシブ対応を検証する。自動テストではカバーできない視覚的・体験的な品質を確認する。

---

## 実行タスク

### Task 1: リスクバッジ目視確認

**目的**: 各リスクレベルのバッジが正しく表示されることを目視確認する。

**手順**:

1. 開発サーバーを起動する：

   ```bash
   pnpm --filter @repo/desktop dev
   ```

2. 以下の各リスクレベルのツールでPermissionDialogを表示し、目視確認する：

   | #   | ツール名 | リスクレベル | 確認項目                                             | 結果 |
   | --- | -------- | ------------ | ---------------------------------------------------- | ---- |
   | 1   | Bash     | High         | オレンジ色リスクバッジ「High」が表示される           |      |
   | 2   | Read     | Low          | 緑色リスクバッジ「Low」が表示される                  |      |
   | 3   | Write    | Medium       | 黄色リスクバッジ「Medium」が表示される               |      |
   | 4   | 未定義   | Medium       | 黄色リスクバッジ「Medium」が表示される（デフォルト） |      |

3. セキュリティ影響テキストが人間可読説明文の下に表示されていることを確認する

4. リスクバッジが既存のUI要素（ツールアイコン、ツール名バッジ）と視覚的に調和していることを確認する

**期待される成果物**: 目視確認チェック結果

### Task 2: アクセシビリティ手動テスト

**目的**: スクリーンリーダー対応とキーボード操作を手動で確認する。

**手順**:

1. キーボード操作テスト：
   - Tabキーでダイアログ内の各要素にフォーカスが移動することを確認する
   - リスクバッジの追加によりタブ順序が崩れていないことを確認する
   - Escapeキーでダイアログが閉じることを確認する

2. スクリーンリーダーテスト（macOS VoiceOverまたは同等機能）：
   - リスクバッジのaria-labelが正しく読み上げられることを確認する
   - 「リスクレベル: High」等の情報が伝わることを確認する

3. 色覚多様性テスト：
   - リスクバッジのテキスト（Low/Medium/High/Critical）のみで識別可能であることを確認する
   - 色のみに依存していないことを確認する

**期待される成果物**: アクセシビリティテスト結果

### Task 3: レイアウト・レスポンシブ確認

**目的**: さまざまなウィンドウサイズでレイアウトが崩れないことを確認する。

**手順**:

1. PermissionDialogのレイアウトを確認する：
   - 最小幅でのバッジ表示（テキストが切れていないか）
   - 長いツール名＋リスクバッジの横並び表示
   - セキュリティ影響テキストの折り返し

2. Electronウィンドウのリサイズ時にレイアウトが崩れないことを確認する

**期待される成果物**: レイアウト確認結果

### Task 4: 既存機能の回帰確認

**目的**: リスクバッジ追加により既存機能が損なわれていないことを確認する。

**手順**:

1. 以下の既存機能が正常に動作することを目視確認する：
   - 3ボタン（拒否/1回許可/許可）のクリック動作
   - 「次回から自動的に許可する」チェックボックス
   - 「詳細を表示/隠す」トグル
   - 人間可読説明文の表示
   - ツールアイコンの表示

**期待される成果物**: 回帰確認結果
