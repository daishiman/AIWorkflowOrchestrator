## 目的

PermissionDialogツールリスクレベル・セキュリティメタデータ表示の全実装について、機能完全性・コード品質・テスト品質・セキュリティ・UI/UXの観点から最終検証を行い、手動テスト・ドキュメント更新フェーズへ進行可能かを判定する。

---

## 実行タスク

### Task 1: 機能完全性レビュー

**目的**: 全ての受け入れ基準が満たされているかを検証する。

**手順**:

1. Phase 1で定義した機能要件を1つずつ検証する：

   | FR-ID | 要件                                       | 検証結果 |
   | ----- | ------------------------------------------ | -------- |
   | FR-1  | 12ツール全てにリスクレベルが定義されている |          |
   | FR-2  | リスクレベルバッジが表示される             |          |
   | FR-3  | 色分けが適用されている                     |          |
   | FR-4  | セキュリティ影響テキストが表示される       |          |
   | FR-5  | デフォルトリスクレベルが設定されている     |          |
   | FR-6  | Progressive Disclosureに従っている         |          |

2. 非機能要件を検証する：

   | NFR-ID | 要件                                         | 検証結果 |
   | ------ | -------------------------------------------- | -------- |
   | NFR-1  | テストカバレッジ Lines 95%以上               |          |
   | NFR-2  | WCAG 2.1 AAコントラスト比4.5:1以上           |          |
   | NFR-3  | TypeScript strict modeエラーなし             |          |
   | NFR-4  | スクリーンリーダーでリスクレベル読み上げ可能 |          |
   | NFR-5  | レンダリング性能劣化なし                     |          |
   | NFR-6  | 色覚多様性対応                               |          |

**期待される成果物**: 機能完全性チェック結果

### Task 2: コード品質レビュー

**目的**: コードがクリーンコードの原則に従っているかを検証する。

**手順**:

1. toolMetadata.tsの品質確認：
   - 命名が適切で一貫性があるか
   - 関数が単一責務か
   - 不要なコードがないか
   - コメントが必要十分か

2. PermissionDialog.tsx（リスクバッジ関連部分）の品質確認：
   - 既存コードのスタイルと一貫しているか
   - 重複コードがないか
   - 変更が最小限で既存機能に影響を与えていないか

**期待される成果物**: コード品質レビュー結果

### Task 3: テスト品質レビュー

**目的**: テストケースが適切で十分かを検証する。

**手順**:

1. テストケースの網羅性を確認する：
   - 正常系（12ツール全て）がカバーされているか
   - 異常系（未定義ツール、空文字列）がカバーされているか
   - 境界値がカバーされているか
   - アクセシビリティがカバーされているか

2. テストの品質を確認する：
   - テスト名が意図を正確に表現しているか
   - アサーションが適切か
   - テストが独立しているか（テスト間の依存がないか）

**期待される成果物**: テスト品質レビュー結果

### Task 4: セキュリティ最終確認

**目的**: セキュリティ上の懸念が残っていないことを最終確認する。

**手順**:

1. security-skill-execution.mdとtoolMetadata.tsのリスクレベルの整合性を最終確認する
2. XSS等のフロントエンドセキュリティ脆弱性がないことを確認する
3. ユーザーを誤解させる表現がないことを確認する

**期待される成果物**: セキュリティ最終確認結果

### Task 5: UI/UX最終確認

**目的**: Apple HIG準拠、WCAG準拠、デザイン原則準拠の最終確認。

**手順**:

1. Progressive Disclosureパターンが正しく適用されているか確認する
2. リスクバッジが視覚的ノイズになっていないか確認する
3. 色+テキストの多重表現が機能しているか確認する
4. キーボードナビゲーションに影響を与えていないか確認する

**期待される成果物**: UI/UX最終確認結果

## 判定基準

| 判定     | 条件                     | 対応                                   |
| -------- | ------------------------ | -------------------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 11（手動テスト）へ進行           |
| MINOR    | 軽微な指摘あり           | 未完了タスクとして記録後Phase 11へ進行 |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻り先を決定           |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザーと要件を再確認    |

### 戻り先決定基準

| 問題の種類       | 戻り先                      |
| ---------------- | --------------------------- |
| 要件の問題       | Phase 1（要件定義）         |
| 設計の問題       | Phase 2（設計）             |
| テスト設計の問題 | Phase 4（テスト作成）       |
| 実装の問題       | Phase 5（実装）             |
| テスト不足の問題 | Phase 6（テスト拡充）       |
| カバレッジ未達   | Phase 7（カバレッジ確認）   |
| コード品質の問題 | Phase 8（リファクタリング） |
