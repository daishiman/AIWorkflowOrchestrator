## 統合テスト連携【必須】

統合テスト観点のレビューゲートを実施:

| レビュー観点         | 確認項目                                        |
| -------------------- | ----------------------------------------------- |
| インターフェース設計 | ICommunityDetectorの責務が明確か                |
| データフロー         | GraphStore → Leiden → Repository の流れが適切か |
| エラーハンドリング   | Result型によるエラー伝播が設計されているか      |
| 型安全性             | Branded Typesが適切に使用されているか           |

---

## レビュー観点

### 1. 要件との整合性

- [ ] FR-1〜FR-3が設計でカバーされているか
- [ ] NFR-1〜NFR-3が考慮されているか

### 2. アーキテクチャの妥当性

- [ ] 単一責務の原則が守られているか
- [ ] 依存性逆転の原則が守られているか
- [ ] 既存のIKnowledgeGraphStoreとの連携が適切か

### 3. ドメインモデルの妥当性

- [ ] Community型が必要な情報を持っているか
- [ ] 階層構造（parent/child）が適切に設計されているか
- [ ] Branded Types（EntityId, CommunityId）が適切に使用されているか

### 4. アルゴリズムの妥当性

- [ ] Leidenアルゴリズムの3フェーズが設計に反映されているか
- [ ] モジュラリティ計算が正しく設計されているか
- [ ] 再現性（seed）が考慮されているか

## 判定基準

| 判定     | 条件                     | 次のアクション                      |
| -------- | ------------------------ | ----------------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行                       |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ進行           |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻り先を決定        |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザーと要件を再確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
