## 1. 概要

### 1.1 目的

Knowledge Graph内のエンティティをLeidenアルゴリズムでクラスタリングし、意味的に関連するコミュニティを検出する。GraphRAGのグローバルクエリ対応の基盤を構築する。

### 1.2 背景

GraphRAGにおいて、グローバルクエリ（「全体のテーマは？」「主要な概念は？」等）への回答には、エンティティを意味的なグループ（コミュニティ）に分割し、それぞれのコミュニティ単位で要約を生成する必要がある。

Leidenアルゴリズムは、Louvainアルゴリズムの改良版であり、以下の利点を持つ：

- より高品質なコミュニティを検出可能
- 階層的なコミュニティ構造を発見
- 大規模グラフでも効率的に動作

### 1.3 ステークホルダー

| ステークホルダー | 役割         | 関心事                    |
| ---------------- | ------------ | ------------------------- |
| 開発者           | 実装担当     | APIの使いやすさ、型安全性 |
| RAGパイプライン  | 利用サービス | 検出精度、処理速度        |
| エンドユーザー   | 最終利用者   | クエリ応答の質            |

## 2. 機能要件 (FR)

### FR-001: コミュニティ検出

**説明**: Leidenアルゴリズムによりグラフ内のコミュニティを検出する

| 項目     | 内容                                          |
| -------- | --------------------------------------------- |
| 優先度   | 必須                                          |
| 入力     | Knowledge Graph（エンティティとリレーション） |
| 出力     | CommunityDetectionResult                      |
| 処理内容 | モジュラリティ最適化によるクラスタリング      |

**詳細要件**:

- FR-001-1: ローカル移動フェーズによるモジュラリティ最適化
- FR-001-2: リファインメントフェーズ（Leiden特有の品質改善）
- FR-001-3: 集約フェーズによる階層構造構築
- FR-001-4: 収束判定と最大イテレーション制限

### FR-002: 階層的コミュニティ構造

**説明**: 複数レベルの階層的なコミュニティ構造を構築する

| 項目     | 内容                               |
| -------- | ---------------------------------- |
| 優先度   | 必須                               |
| 入力     | 検出されたコミュニティ群           |
| 出力     | CommunityStructure（階層情報含む） |
| 処理内容 | 親子関係の設定、レベル別分類       |

**詳細要件**:

- FR-002-1: maxLevels パラメータによる階層レベル制限
- FR-002-2: 親コミュニティIDの設定
- FR-002-3: 子コミュニティIDの配列管理
- FR-002-4: エンティティからコミュニティへのマッピング

### FR-003: パラメータによる検出制御

**説明**: 解像度やサイズ等のパラメータでコミュニティ検出を制御する

| 項目   | 内容                       |
| ------ | -------------------------- |
| 優先度 | 必須                       |
| 入力   | CommunityDetectionOptions  |
| 出力   | パラメータに応じた検出結果 |

**パラメータ一覧**:

| パラメータ       | 型      | デフォルト | 説明                               |
| ---------------- | ------- | ---------- | ---------------------------------- |
| resolution       | number  | 1.0        | 大きいほど小さいコミュニティを検出 |
| maxLevels        | number  | 3          | 最大階層レベル                     |
| minCommunitySize | number  | 2          | 最小コミュニティサイズ             |
| maxIterations    | number  | 100        | 収束までの最大イテレーション       |
| seed             | number? | undefined  | 乱数シード（再現性のため）         |

### FR-004: 検出結果の永続化

**説明**: 検出したコミュニティをデータベースに保存する

| 項目     | 内容                        |
| -------- | --------------------------- |
| 優先度   | 必須                        |
| 入力     | CommunityStructure          |
| 出力     | Result<void, Error>         |
| 処理内容 | communitiesテーブルへの保存 |

**詳細要件**:

- FR-004-1: 既存コミュニティの削除（再検出時）
- FR-004-2: コミュニティの一括挿入
- FR-004-3: エンティティ-コミュニティマッピングの保存

### FR-005: コミュニティ取得

**説明**: 保存されたコミュニティ情報を取得する

| 項目   | 内容 |
| ------ | ---- |
| 優先度 | 必須 |

**詳細要件**:

- FR-005-1: エンティティIDからコミュニティ取得（全レベル）
- FR-005-2: レベル指定でのコミュニティ一覧取得
- FR-005-3: コミュニティIDからメンバーエンティティ取得

### FR-006: ICommunityDetectorインターフェース

**説明**: コミュニティ検出機能の抽象インターフェースを定義する

| 項目   | 内容 |
| ------ | ---- |
| 優先度 | 必須 |

**メソッド一覧**:

| メソッド                  | 戻り値                                  | 説明                           |
| ------------------------- | --------------------------------------- | ------------------------------ |
| detect()                  | Result<CommunityDetectionResult, Error> | コミュニティ検出実行           |
| saveResults()             | Result<void, Error>                     | 結果をDBに保存                 |
| getCommunitiesForEntity() | Result<Community[], Error>              | エンティティのコミュニティ取得 |
| getCommunitiesByLevel()   | Result<Community[], Error>              | レベル別コミュニティ取得       |
| getCommunityMembers()     | Result<StoredEntity[], Error>           | メンバーエンティティ取得       |

## 3. 非機能要件 (NFR)

### NFR-001: パフォーマンス

| 項目           | 目標値                | 測定方法          |
| -------------- | --------------------- | ----------------- |
| 処理時間       | 1000ノードで10秒以内  | 単体テストで計測  |
| メモリ使用量   | グラフサイズの3倍以内 | Node.jsヒープ監視 |
| イテレーション | 100回以内で収束       | ログ出力          |

### NFR-002: 型安全性

| 項目          | 要件                                   |
| ------------- | -------------------------------------- |
| Branded Types | EntityId, CommunityId, RelationId使用  |
| Result型      | ok/errパターンによるエラーハンドリング |
| 厳密な型定義  | any型の使用禁止                        |

### NFR-003: テスト品質

| 項目            | 目標値                 |
| --------------- | ---------------------- |
| Line Coverage   | 80%以上                |
| Branch Coverage | 70%以上                |
| 正常系テスト    | 全メソッドに対して必須 |
| 異常系テスト    | 主要エラーケースを網羅 |

### NFR-004: 再現性

| 項目         | 要件                     |
| ------------ | ------------------------ |
| 乱数シード   | seed指定で同一結果を保証 |
| 決定論的動作 | 同一入力で同一出力       |

### NFR-005: 保守性

| 項目       | 要件                       |
| ---------- | -------------------------- |
| JSDoc      | 全パブリックメソッドに記述 |
| ESLint     | 警告0件                    |
| コード構造 | 単一責任原則の遵守         |

## 4. 接続要件

### 4.1 IKnowledgeGraphStoreとの連携

| 連携項目       | 内容                                               |
| -------------- | -------------------------------------------------- |
| 入力データ取得 | getEntity(), getAllRelations()等でグラフデータ取得 |
| 統計情報取得   | getStats()でノード数・エッジ数取得                 |
| エンティティ型 | StoredEntity型を使用                               |

### 4.2 データフロー

```
IKnowledgeGraphStore (入力)
        │
        ▼
LeidenAlgorithm.detect() (検出処理)
        │
        ▼
CommunityStructure (検出結果)
        │
        ▼
CommunityDetector.saveResults() (永続化)
        │
        ▼
Database: communities, entity_communities テーブル
```

### 4.3 依存サービス

| サービス             | 依存関係                   |
| -------------------- | -------------------------- |
| IKnowledgeGraphStore | 必須（グラフデータ取得）   |
| CommunityRepository  | 必須（コミュニティ永続化） |

## 5. 制約条件

### 5.1 技術的制約

- TypeScript 5.x以上
- SQLite/Turso (libSQL) データベース
- Drizzle ORMによるデータアクセス

### 5.2 運用制約

- 検出処理は非同期で実行
- 大規模グラフ（10000ノード超）では分割処理を検討
