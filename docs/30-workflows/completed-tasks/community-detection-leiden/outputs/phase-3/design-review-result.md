### 2.2 アーキテクチャの妥当性

#### 単一責務の原則（SRP）

| コンポーネント            | 責務                   | 評価 |
| ------------------------- | ---------------------- | ---- |
| LeidenAlgorithm           | 純粋なアルゴリズム実行 | ○    |
| CommunityDetector         | ユースケース調整       | ○    |
| ICommunityRepository      | 永続化抽象             | ○    |
| SQLiteCommunityRepository | SQLite永続化実装       | ○    |

**所見**: 各コンポーネントが明確に分離され、単一の責務を持つ。

#### 依存性逆転の原則（DIP）

```
CommunityDetector
    ├── LeidenAlgorithm (composition - 純粋関数)
    ├── IKnowledgeGraphStore (interface - port)
    └── ICommunityRepository (interface - port)
```

**所見**: 具象クラスではなくインターフェースに依存。依存性逆転が正しく適用されている。

#### IKnowledgeGraphStoreとの連携

| 連携ポイント     | 設計での対応                  | 評価 |
| ---------------- | ----------------------------- | ---- |
| エンティティ取得 | getEntity(), getAllEntities() | ○    |
| リレーション取得 | getRelationsByEntity()        | ○    |
| グラフ統計       | getStats()                    | ○    |

**所見**: 既存のIKnowledgeGraphStoreインターフェースを適切に利用する設計。
