## リファクタリング観点

### 1. 重複排除

- [ ] 同じロジックが複数箇所にないか
- [ ] ヘルパー関数に抽出できるパターンがないか

### 2. 関数の分割

- [ ] 関数が長すぎないか（30行以内目標）
- [ ] 複数の責務を持つ関数がないか

### 3. 命名改善

- [ ] 変数名・関数名が意図を表しているか
- [ ] 一貫した命名規則が使われているか

### 4. SOLID原則

- [ ] 単一責務の原則（SRP）: 各クラス・関数は1つの責務のみ
- [ ] 開放閉鎖の原則（OCP）: 拡張に開いて修正に閉じているか
- [ ] リスコフの置換原則（LSP）: インターフェースが正しく実装されているか
- [ ] インターフェース分離の原則（ISP）: インターフェースが適切に分割されているか
- [ ] 依存性逆転の原則（DIP）: 高レベルモジュールが低レベルモジュールに依存していないか

### 5. コードスメル

- [ ] 長いメソッド
- [ ] 長いパラメータリスト
- [ ] 重複コード
- [ ] 条件の複雑さ
- [ ] 不必要なコメント

## リファクタリング手順

1. **リファクタリング前のテスト実行**: 全テストがパスすることを確認
2. **小さな変更を1つ実施**: 1つのリファクタリングのみ
3. **テスト実行**: 変更後もテストがパスすることを確認
4. **コミット**: 変更をコミット
5. **繰り返し**: 次のリファクタリングへ
