## 目的

自動テストでカバーできない動作確認を手動で実施する。実際の使用シナリオに基づいた検証を行い、ユーザー視点での品質を確認する。

## 背景

自動テストは網羅的なチェックに優れているが、実際のユースケースにおける使い勝手や予期しない動作は手動での確認が必要。特にコミュニティ検出結果の妥当性は、人間の判断が重要となる。

## 手動テストシナリオ

### シナリオ1: 基本的なコミュニティ検出

**目的**: 正常系の動作確認

**手順**:

1. テストグラフデータを準備（10ノード、20エッジ程度）
2. CommunityDetector.detect()を実行
3. 結果のコミュニティ数を確認
4. 各コミュニティのメンバーを確認
5. モジュラリティ値が正の値であることを確認

**期待結果**:

- [ ] コミュニティが1つ以上検出される
- [ ] 全ノードがいずれかのコミュニティに属する
- [ ] モジュラリティ > 0

---

### シナリオ2: 階層的コミュニティ構造

**目的**: 階層検出の動作確認

**手順**:

1. 階層構造を持つテストグラフを準備
2. maxLevels: 3 でコミュニティ検出を実行
3. 各レベルのコミュニティ数を確認
4. 親子関係が正しく設定されていることを確認

**期待結果**:

- [ ] 複数レベルのコミュニティが検出される
- [ ] レベル0（最細粒度）のコミュニティ数 ≥ レベル1
- [ ] 親子関係が正しく設定されている

---

### シナリオ3: Resolutionパラメータの効果

**目的**: パラメータ調整の動作確認

**手順**:

1. 同一グラフでresolution: 0.5で検出
2. 同一グラフでresolution: 2.0で検出
3. 検出されたコミュニティ数を比較

**期待結果**:

- [ ] 高resolution（2.0）でより多くのコミュニティ
- [ ] 低resolution（0.5）でより少ないコミュニティ

---

### シナリオ4: 再現性テスト

**目的**: seed指定による再現性確認

**手順**:

1. seed: 12345 で2回コミュニティ検出を実行
2. 結果を比較

**期待結果**:

- [ ] 2回の実行で同一の結果が得られる

---

### シナリオ5: 境界値テスト

**目的**: エッジケースの動作確認

**手順**:

1. 空グラフ（ノード0件）で検出
2. 1ノードのみのグラフで検出
3. 孤立ノードを含むグラフで検出

**期待結果**:

- [ ] 空グラフ: エラーにならず空の結果を返す
- [ ] 1ノード: そのノードのみのコミュニティを返す
- [ ] 孤立ノード: 孤立ノードのみのコミュニティが作成される

---

### シナリオ6: エラーハンドリング

**目的**: 異常系の動作確認

**手順**:

1. 不正なパラメータ（resolution: -1）で検出
2. 存在しないEntityIdでgetCommunitiesForEntity()を呼び出し

**期待結果**:

- [ ] Result.err()が返される
- [ ] 適切なエラーメッセージが含まれる
