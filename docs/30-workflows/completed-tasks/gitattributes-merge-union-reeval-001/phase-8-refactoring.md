## 目的

Phase 5 で確定した `.gitattributes` の挙動を**変えずに**、可読性・保守性・将来の追加容易性を向上させる。コメント整理・順序整列・重複削除・スタイル統一にスコープを限定し、glob パターンや merge 戦略の修正は本Phaseでは扱わない。

## 背景

Phase 5 で `merge=union` の適用範囲が縮小され、`.gitattributes` のエントリ数が増加した結果、コメントの粒度・順序・命名スタイルが統一されていない箇所が散在している。本Phase では navigation drift（関連スクリプト参照の散在）と mirror divergence（`.claude/skills/*` と `.agents/skills/*` の対称性破綻）を整理し、新規ファイル追加時の判断コストを下げる。

**重要**: 本Phaseのリファクタリングは `.gitattributes` 内コメント・順序・重複に限定する。挙動変更を伴う修正は Phase 5 で完了済みであり、Phase 8 で再度行うことは禁止する。

## 実行タスク

### タスク0: 重複・冗長エントリの整理

**目的**: 同一 glob パターンの重複定義や、より広い glob で代替可能な狭い glob を整理し、エントリ数を最小化する。

**実行手順**:

1. `.gitattributes` の全エントリを抽出し、glob パターンの正規化（末尾スラッシュ統一・ワイルドカード位置統一）を実施
2. 完全重複エントリを検出し、後方のものを削除
3. `.claude/skills/*` と `.agents/skills/*` の対称性を確認し、片方にしか存在しないエントリを補完または削除（mirror parity 維持）
4. カテゴリ毎にグループ化:
   - グループA: append-only ファイル（`merge=union` 対象）
   - グループB: 構造化ドキュメント（デフォルト 3-way 対象）
   - グループC: auto-generated インデックス（`merge=ours` 対象）
   - グループD: バイナリ・特殊ファイル
5. 各グループ内をアルファベット順に並べ替え

**期待される成果物**: `outputs/phase-8/refactoring-log.md` 内のセクション「重複削除と並び順整理」

### タスク1: コメントスタイルの統一化

**目的**: 各エントリ直前のコメントを「適用意図 + 注意事項 + 関連スクリプトリンク」の3要素テンプレートに統一する。

**実行手順**:

1. 以下のテンプレートを定義し、全コメントブロックに適用:

   ```
   # [意図] このパターンに対して <merge戦略> を適用する理由
   # [注意] 適用条件・前提条件・既知の制約
   # [関連] setup-merge-drivers.sh / 該当 issue / 該当タスク
   ```

2. 既存コメントから3要素を抽出し、欠落要素を補完
3. 1行コメントの場合は意図のみ明記し、注意・関連は省略可とする
4. グループ見出しコメントは `## グループ名` 形式で統一

**期待される成果物**: `outputs/phase-8/refactoring-log.md` 内のセクション「コメントスタイル統一」

### タスク2: navigation drift の削減

**目的**: 関連スクリプト・関連ドキュメントへの参照を集約し、`.gitattributes` 内コメントから直接辿れる構造に整える。

**実行手順**:

1. `.gitattributes` 冒頭に「関連リソース集約セクション」を追加:
   ```
   # === 関連リソース ===
   # - merge ドライバー登録: .claude/scripts/setup-merge-drivers.sh
   # - 判断ガイドライン: docs/30-workflows/gitattributes-merge-union-reeval-001/
   # - 元タスク Issue: #2281
   ```
2. 各エントリのコメントから上記リンクの重複記載を削除し、冒頭セクションへの参照に置き換え
3. `setup-merge-drivers.sh` 側にも `.gitattributes` への逆方向リンク（コメント）を追記推奨として記録（実装は本タスク範囲外）

**期待される成果物**: `outputs/phase-8/refactoring-log.md` 内のセクション「navigation drift 削減」

### タスク3: [Feedback RT-03] 変更内容のテーブル化記録

**目的**: 全リファクタリング変更を「対象 / Before / After / 理由」の4列テーブルで記録し、レビュー容易性とロールバック容易性を確保する。

**実行手順**:

1. タスク0-2で実施した全変更を以下の形式で列挙:

   | 対象 (行 or glob)                          | Before         | After                 | 理由           |
   | ------------------------------------------ | -------------- | --------------------- | -------------- |
   | `.claude/skills/*/references/log.md`       | (重複定義あり) | (1件に集約)           | 重複削除       |
   | グループA見出し                            | (なし)         | `## append-only`      | カテゴリ可視化 |
   | `.agents/skills/*/indexes/*.json` コメント | 1行のみ        | 3要素テンプレート適用 | スタイル統一   |

2. 変更件数を集計（重複削除 N件 / コメント統一 M件 / 構造追加 K件）
3. 挙動変更を伴わないことを `git diff --stat` および Phase 4-6 テストの再実行結果で確認

**期待される成果物**: `outputs/phase-8/refactoring-log.md` 内のセクション「変更テーブル」
