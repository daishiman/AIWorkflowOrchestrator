## 目的

自動テストでは検証できないユーザー体験・UI/UX・実環境動作を手動で確認する。SDK統合が期待通りに動作することを実機で検証する。

## 背景

Phase 10で最終レビューが完了した。本Phaseでは、実際のアプリケーション上でSDK統合機能の動作確認を行う。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: テスト環境準備

**目的**: 手動テストに必要な環境を準備する

**実行手順**:

1. APIキーの準備:
   - Anthropic Console から有効なAPIキーを取得
   - テスト用のAPIキーを用意（レート制限に注意）

2. アプリケーションをビルド:

   ```bash
   pnpm --filter @repo/desktop build
   ```

3. アプリケーションを起動:

   ```bash
   pnpm --filter @repo/desktop start
   ```

4. APIキーを設定:
   - 設定画面からAPIキーを入力
   - 保存されることを確認

**期待される成果物**:

- テスト環境セットアップ完了

---

### タスク2: 基本機能テスト

**目的**: SDK統合の基本機能が動作することを確認する

**実行手順**:

1. 以下のテストシナリオを実行:

   | シナリオ                | 操作                               | 期待結果                     | 結果 |
   | ----------------------- | ---------------------------------- | ---------------------------- | ---- |
   | スキル実行（hearing）   | hearingフェーズを実行              | 正常に完了し結果が表示される | [ ]  |
   | スキル実行（structure） | structureフェーズを実行            | structure.mdが生成される     | [ ]  |
   | スキル実行（html）      | htmlフェーズを実行                 | index.htmlが生成される       | [ ]  |
   | ModifierSkill実行       | modifierフェーズを実行             | スライドが修正される         | [ ]  |
   | 進捗表示                | スキル実行中の進捗を観察           | 進捗が正しく更新される       | [ ]  |
   | キャンセル              | 実行中にキャンセルボタンをクリック | 処理が中断される             | [ ]  |
   | 再実行                  | キャンセル後に再度実行             | 正常に実行される             | [ ]  |

2. 各シナリオの結果を記録

**期待される成果物**:

- 基本機能テスト結果

---

### タスク3: エラーハンドリングテスト

**目的**: エラー発生時の動作が正しいことを確認する

**実行手順**:

1. 以下のエラーシナリオを実行:

   | シナリオ           | 操作                           | 期待結果                         | 結果 |
   | ------------------ | ------------------------------ | -------------------------------- | ---- |
   | 無効なAPIキー      | 無効なAPIキーを設定して実行    | 認証エラーが表示される           | [ ]  |
   | APIキー未設定      | APIキーを削除して実行          | 設定を促すメッセージが表示される | [ ]  |
   | タイムアウト       | 長時間応答のシナリオを実行     | 30秒後にタイムアウトエラーが表示 | [ ]  |
   | ネットワークエラー | ネットワークを切断して実行     | 接続エラーが表示される           | [ ]  |
   | レート制限         | 短時間に大量のリクエストを実行 | レート制限エラーが表示される     | [ ]  |

2. エラーメッセージがユーザーフレンドリーであることを確認
3. エラー後のリカバリが可能であることを確認

**期待される成果物**:

- エラーハンドリングテスト結果

---

### タスク4: アクセシビリティ検証

**目的**: WCAG基準に基づくアクセシビリティを確認する

**実行手順**:

1. キーボード操作でスキル実行が可能であることを確認
2. スクリーンリーダーで進捗状態が読み上げられることを確認
3. 色のコントラストが十分であることを確認

**期待される成果物**:

- アクセシビリティ検証結果

---

### タスク5: レスポンシブデザイン検証

**目的**: 各デバイスサイズでのレイアウトを確認する

**実行手順**:

1. デスクトップサイズでのレイアウト確認
2. ウィンドウリサイズ時のレイアウト崩れがないことを確認
3. 進捗表示がウィンドウサイズに関係なく正しく表示されることを確認

**期待される成果物**:

- レスポンシブデザイン検証結果

---

### タスク6: 統合動作テスト

**目的**: 全フェーズを通じた統合動作を確認する

**実行手順**:

1. E2Eシナリオを実行:

   | シナリオ             | 操作                                | 期待結果                     | 結果 |
   | -------------------- | ----------------------------------- | ---------------------------- | ---- |
   | 全フェーズ連続実行   | hearing→structure→html を連続実行   | 最終的にスライドが生成される | [ ]  |
   | Modifier繰り返し実行 | modifierを複数回実行                | スライドが正しく更新される   | [ ]  |
   | 長時間セッション     | 1時間以上のセッションでスキルを実行 | メモリリークなく動作継続     | [ ]  |
   | 大容量ファイル       | 大きなstructure.mdからHTML生成      | 正常に処理される             | [ ]  |

2. パフォーマンスを観察:
   - 応答時間が許容範囲内であること
   - UIが固まらないこと

**期待される成果物**:

- 統合動作テスト結果

---

### タスク7: テスト結果レポート作成

**目的**: 手動テストの結果を文書化する

**実行手順**:

1. 全テスト結果を集約
2. 発見された問題を分類:
   - 致命的: リリースブロッカー
   - 重大: 修正推奨
   - 軽微: 改善検討
3. レポートを作成

**期待される成果物**:

- `outputs/phase-11/manual-test-result.md` - 手動テスト結果レポート
