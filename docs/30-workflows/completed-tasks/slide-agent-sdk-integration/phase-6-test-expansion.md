Phase 5の実装に対してテストを拡充し、カバレッジ目標を達成する。SDK統合の信頼性を確保するため、エッジケース・異常系・境界値のテストを追加する。

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: カバレッジ測定と分析

**目的**: 現在のテストカバレッジを測定し、不足領域を特定する

**実行手順**:

1. カバレッジ測定を実行:

   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```

2. カバレッジレポートを確認し、以下の観点で分析:
   - Line Coverage: 目標80%以上
   - Branch Coverage: 目標60%以上
   - Function Coverage: 目標80%以上

3. 未カバー領域を特定:
   - 未到達の行
   - 未到達の分岐（if/else, try/catch）
   - 未テストの関数

4. 不足テストケースをリストアップ

**期待される成果物**:

- カバレッジ分析結果

---

### タスク2: エッジケーステスト追加

**目的**: 境界値・異常入力・エラー条件のテストを追加する

**実行手順**:

1. 以下のエッジケーステストを追加:

| カテゴリ   | テストケース                                                |
| ---------- | ----------------------------------------------------------- |
| 境界値     | 空のプロンプトでエラーになる                                |
| 境界値     | 非常に長いプロンプト（100KB以上）でエラーになる             |
| 境界値     | タイムアウト直前（29.9秒）で応答が返る                      |
| 境界値     | タイムアウト直後（30.1秒）でタイムアウトエラー              |
| 異常入力   | 無効なスキルフェーズでエラーになる                          |
| 異常入力   | projectPathがnullでエラーになる                             |
| 異常入力   | projectPathが存在しないパスでエラーになる                   |
| エラー条件 | APIキーが未設定でエラーになる                               |
| エラー条件 | APIキーが無効でエラーになる                                 |
| エラー条件 | ネットワーク障害でエラーになる                              |
| エラー条件 | SDK応答が不正なJSON形式でエラーになる                       |
| 同時実行   | 同時に2つのスキル実行を試みると最初の実行が完了するまで待つ |

2. テストファイルに追加:
   - `skill-executor.test.ts`
   - `agent-client.test.ts`

**期待される成果物**:

- 追加されたエッジケーステスト

---

### タスク3: 統合テスト拡充

**目的**: SDK統合の全カテゴリでカバレッジを向上させる

**実行手順**:

1. 以下の統合テストを追加:

| シナリオカテゴリ   | テストケース                                |
| ------------------ | ------------------------------------------- |
| API接続テスト      | SDK接続のリトライ動作（将来実装向けスタブ） |
| API接続テスト      | 認証エラー時のリカバリフロー                |
| データフローテスト | 複数ファイル同時変更時の処理順序            |
| データフローテスト | 大容量ファイル（1MB以上）の処理             |
| エラーハンドリング | 連続エラー発生時のUI表示                    |
| エラーハンドリング | エラー後のリカバリ（正常実行への復帰）      |
| 認証連携テスト     | APIキーの再設定フロー                       |
| 認証連携テスト     | APIキー期限切れ時の動作                     |
| 状態同期テスト     | 進捗コールバックの頻度（過剰呼び出し防止）  |
| 状態同期テスト     | キャンセル後の状態クリーンアップ            |

2. テストファイルに追加:
   - `sdk-integration.test.ts`

**期待される成果物**:

- 追加された統合テスト

---

### タスク4: カバレッジレポート作成

**目的**: テスト拡充後のカバレッジを測定・文書化する

**実行手順**:

1. カバレッジ再測定:

   ```bash
   pnpm --filter @repo/desktop test:coverage
   ```

2. レポートを作成:
   - カバレッジ数値（Line/Branch/Function）
   - 改善前後の比較
   - 未カバー領域の理由（テスト不要の場合はその説明）

**期待される成果物**:

- `outputs/phase-6/coverage-report.md` - カバレッジレポート
