## 目的

Phase 2 の設計が Phase 4（テスト作成）へ進める品質を満たしているかを判定する。設計の妥当性・実現性・既存との互換性を確認する。

## 実行タスク

### Task 3-1: 設計の妥当性確認

以下の観点で Phase 2 設計書をレビューする。

**機能要件の充足確認**:

| 要件                                          | 設計書での対応          | 判定 |
| --------------------------------------------- | ----------------------- | ---- |
| AC-1: Task/Step 分離ガイドライン              | Task 2-1 で設計済み     | -    |
| AC-2: docs-only evidence ルール               | Task 2-2 で設計済み     | -    |
| AC-3: Phase 12「実行タスク」/「検証ログ」分離 | Task 2-3 で設計済み     | -    |
| AC-4: Handlebars 条件分岐                     | Task 2-2 で設計済み     | -    |
| AC-5: 既存フォーマット互換性                  | Task 2-4 で対象特定済み | -    |

**設計の実現性確認**:

- [ ] Handlebars 構文が `phase-spec-template.md` の既存スタイルと一致している
- [ ] `IS_NON_VISUAL` の分岐が既存テンプレートエンジンで処理可能
- [ ] `unassigned-task-template.md` への変更が既存フォーマットを崩さない

**スコープの妥当性確認**:

- [ ] 含む / 含まないが Phase 1 の要件定義と一致している
- [ ] 既存の完了済み Phase 仕様書への影響がない（遡及修正しない方針）
- [ ] スクリプト変更が含まれていない（テンプレートのみ）

### Task 3-2: リスク評価

| リスク                                                  | 影響度 | 発生確率 | 対策                                                         |
| ------------------------------------------------------- | ------ | -------- | ------------------------------------------------------------ |
| テンプレート改修による既存仕様書との非互換              | 中     | 低       | 既存仕様書は遡及修正しない方針とし、影響調査で確認           |
| docs-only 判定が曖昧で `IS_NON_VISUAL` が未設定になる   | 中     | 中       | `IS_NON_VISUAL=true` を必須化し、未設定は Blocker 扱いにする |
| Handlebars 条件分岐の複雑化によるテンプレート保守性低下 | 低     | 中       | 条件分岐は最小限に留め、コメントで判断基準を明記する         |
| Plan と current fact の記述ルールが形骸化する           | 中     | 中       | 未来形/過去形の記述ルールをテンプレートに明記する            |

### Task 3-3: レビュー判定

以下の基準で Phase 4 への進行を判定する。

| 判定基準                                | 結果 |
| --------------------------------------- | ---- |
| CRITICAL ブロッカーがゼロ               | -    |
| 設計が全 AC をカバーしている            | -    |
| Handlebars 構文の実現可能性が確認できる | -    |
| スコープが Phase 1 の要件と一致している | -    |

**判定**:

- PASS → Phase 4: テスト作成 に進む
- FAIL → Phase 2 へ差し戻し（指摘事項付き）
