## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 実装完全性レビュー

**目的**: 要件・設計通りに実装が完了していることを確認する。

**実行手順**:

1. Phase 1要件定義との照合
   - 機能要件の全項目が実装されているか
   - UI要件の全項目が実装されているか
2. Phase 2設計との照合
   - コンポーネント構成が設計通りか
   - API設計が設計通りか
   - Hooks設計が設計通りか
3. 実装漏れをリスト化する

**期待される成果物**:

- 実装完全性チェックリスト

---

### タスク2: 品質基準達成レビュー

**目的**: 品質基準が達成されていることを確認する。

**実行手順**:

1. テストカバレッジ確認
   - Line Coverage 80%+
   - Branch Coverage 60%+
   - Function Coverage 80%+
2. 品質レポート確認
   - Phase 9の品質レポートを参照
3. 未達成項目をリスト化する

**期待される成果物**:

- 品質基準チェックリスト

---

### タスク3: システム仕様整合性レビュー

**目的**: 既存システム仕様との整合性を確認する。

**実行手順**:

1. architecture-patterns.md との整合性
   - Preload APIパターン準拠
   - Zustand Sliceパターン準拠
2. interfaces-llm.md との整合性
   - 型定義の一貫性
   - IPC契約の整合性
3. 不整合箇所をリスト化する

**期待される成果物**:

- 整合性チェックリスト

---

### タスク4: 統合テスト結果レビュー

**目的**: 統合テストが全て成功していることを確認する。

**実行手順**:

1. 全テスト実行
   ```bash
   pnpm --filter @repo/desktop test
   ```
2. テスト結果を確認する
3. 失敗テストがあれば原因を調査する

**期待される成果物**:

- テスト実行結果ログ

---

### タスク5: 総合レビュー判定

**目的**: レビュー結果を総合判定し、次のアクションを決定する。

**実行手順**:

1. 発見課題を重要度別に分類する
   - CRITICAL: 致命的な問題
   - MAJOR: 重大な問題
   - MINOR: 軽微な問題
2. 総合判定を行う
   - PASS: 問題なし → Phase 11へ
   - MINOR: 軽微な指摘あり → 指摘対応後、Phase 11へ
   - MAJOR: 重大な問題あり → 影響範囲に応じて戻る
   - CRITICAL: 致命的な問題あり → Phase 1へ戻りユーザー確認
3. 判定結果をドキュメント化する

**期待される成果物**:

- `outputs/phase-10/final-review-result.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
