## ワークフロー改善

| 観点                                 | 教訓                                                                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 依存タスク確認                       | Phase 1 で依存タスクの完了確認を先行することで、実装の無駄が防げた                                                                                             |
| TDD の適用                           | 既存実装が存在する場合の TDD は「Red→Green」より「Green 状態の確認と拡充」が実態に即している                                                                   |
| ring buffer 設計                     | `slice(-maxEvents)` はシンプルで十分。専用の CircularBuffer クラスは過剰設計だった                                                                             |
| try/finally によるライフサイクル保証 | governance hooks の onSessionEnd を try/finally に配置することで、早期リターン時の audit 漏れを防止できた。この設計パターンは他の lifecycle フックにも応用可能 |
| policy immutability                  | policy table は deep freeze して返却し、参照先の accidental mutation を防ぐのが安全境界として有効だった                                                        |
| lint 証跡の解釈                      | exit code と warning 数を分けて記録しないと、`PASS` の表現が過剰断定になりやすい                                                                               |

## ドキュメント改善

| 観点                            | 内容                                                                                       |
