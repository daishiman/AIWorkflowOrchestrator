## 目的

Phase 1（要件定義）とPhase 2（設計）の成果物をレビューし、実装フェーズに進む妥当性を検証する。

## 背景

TDD（テスト駆動開発）のサイクルに入る前に、設計の妥当性を確認し、手戻りリスクを最小化する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件の妥当性検証

**目的**: Phase 1で定義した要件が適切かを検証する

**実行手順**:

1. 型一覧リストが完全であることを確認
2. エクスポートすべき型に漏れがないか確認
3. スコープ境界（Part 1/2/3）が適切か確認

**レビュー観点**:

| 観点           | 確認項目                                    |
| -------------- | ------------------------------------------- |
| 完全性         | `types.ts` の全 public 型がカバーされている |
| 一貫性         | 型名・パターンが既存コードと一貫している    |
| スコープ明確性 | Part 1の範囲が明確に定義されている          |

**期待される成果物**:

- レビュー結果（出力: `outputs/phase-3/requirements-review.md`）

---

### タスク2: 設計の妥当性検証

**目的**: Phase 2で作成した設計が適切かを検証する

**実行手順**:

1. エクスポート構造設計をレビュー
2. `export type` と `export` の使い分けが正しいか確認
3. 既存パターンとの整合性を確認

**レビュー観点**:

| 観点           | 確認項目                                       |
| -------------- | ---------------------------------------------- |
| TypeScript規約 | `export type` が型に対して正しく使用されている |
| パターン一貫性 | 他のバレルファイルと同じパターンを使用している |
| 影響最小化     | 既存コードへの影響がない                       |

**期待される成果物**:

- レビュー結果（出力: `outputs/phase-3/design-review.md`）

---

### タスク3: レビュー判定

**目的**: 次のPhaseに進む可否を判定する

**実行手順**:

1. タスク1, 2のレビュー結果を集約
2. 問題の重大度を分類
3. 次のアクションを決定

**期待される成果物**:

- 判定結果（出力: `outputs/phase-3/review-verdict.md`）

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | Phase 4へ進行             |
| MINOR    | 軽微な指摘あり           | 指摘対応後、Phase 4へ     |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類 | 戻り先              |
| ---------- | ------------------- |
| 要件の問題 | Phase 1（要件定義） |
| 設計の問題 | Phase 2（設計）     |
