# Phase 2 アーキテクチャ設計

## 1. 目的

`sandbox iterable` 障害を、Main/Preload/Renderer責務に分解して再発防止する。

## 2. 責務分離設計

| 層       | 責務                                                   | 今回の設計判断                                   |
| -------- | ------------------------------------------------------ | ------------------------------------------------ |
| Main     | 外部依存（Supabase）からのデータをRenderer契約に正規化 | `toAuthUser` で `AUTH_STATE_CHANGED.user` を統一 |
| Preload  | チャネル公開境界の固定                                 | 変更なし（既存契約維持）                         |
| Renderer | 受信データの最終防御・状態更新                         | `normalizeLinkedProviders` を導入                |

## 3. 障害分離設計

- 主因ログ: 契約崩れ（非配列/不正要素）を `console.warn` で分類。
- 副作用ログ: ネットワーク・認証失敗ログは既存経路を維持。
- 判定原則: クラッシュさせず「正規化して継続」を優先。

## 4. 非機能設計

- 後方互換: IPCチャンネル名・引数・戻り値の公開契約は変更しない。
- 冪等性: `linkProvider` で同provider重複を置換する。
