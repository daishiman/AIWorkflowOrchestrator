## QA チェックリスト

### コード品質チェック

| チェック項目                                                                    | 判定基準                      | 合否 |
| ------------------------------------------------------------------------------- | ----------------------------- | ---- |
| `buildSkillContext()` が pure function として実装されているか                   | 副作用ゼロ・同一入力→同一出力 | -    |
| `buildSkillGenerationPrompt()` が undefined フィールドを安全にスキップするか    | 実行時エラーゼロ              | -    |
| `SkillCreationContext` の全フィールドが optional になっているか                 | 型定義確認                    | -    |
| `createSkill` Thunk の修正が既存の Redux ストア型と整合しているか               | 型チェック PASS               | -    |
| IPC チャンネル定義（preload）が `SkillCreationContext` を正しく受け渡しているか | 型チェック + IPC 契約確認     | -    |

### テスト品質チェック

| チェック項目                                   | 判定基準                           | 合否 |
| ---------------------------------------------- | ---------------------------------- | ---- |
| テスト全件 PASS（TC-01〜TC-18）                | 0 件 FAIL                          | -    |
| 後方互換テスト（TC-10・TC-17）が PASS であるか | 既存呼び出しパターンが壊れていない | -    |
| E2E 相当テスト（TC-18）が PASS であるか        | Q1〜Q6 全フィールドの反映確認      | -    |
| カバレッジ目標（Phase 7）が達成されているか    | 変更箇所 line 100%・branch 90%以上 | -    |

### 静的解析チェック

```bash
# TypeScript 型チェック（最重要）
pnpm typecheck

# ESLint（変更ファイルのみ）
pnpm lint

# テスト全件実行
pnpm vitest run --reporter=verbose

# shared パッケージビルド確認（型エクスポート確認）
pnpm --filter @repo/shared build
```

## リスク評価

| リスク                                          | 発生確率 | 対処方法                                               |
| ----------------------------------------------- | -------- | ------------------------------------------------------ |
| 既存の `createSkill` 呼び出し箇所が壊れる       | 中       | TC-10・TC-17 の後方互換テストで検出・Phase 3 確認済み  |
| IPC シリアライズでエラーが発生する              | 低       | `SkillCreationContext` は plain object のため低リスク  |
| プロンプトが長大になり LLM の入力制限を超える   | 中       | Phase 5 実装時にトークン数チェックを追加することを推奨 |
| `buildSkillGenerationPrompt` のラベルが文字化け | 低       | UTF-8 環境での動作確認済み                             |
