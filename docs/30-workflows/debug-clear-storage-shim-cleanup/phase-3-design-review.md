## 目的

Phase 1（要件定義）と Phase 2（設計）の妥当性を多角的に検証し、Phase 4 以降の実装開始を判定する。

## 実行タスク

- タスク1: 要件と設計の整合性を検証する
- タスク2: 変更計画の安全性とスコープ適切性を検証する
- タスク3: レビュー判定を行い、ゲート通過可否を決定する

### タスク1: 要件−設計整合性検証

**目的**: Phase 1 の受入基準が Phase 2 の設計で全て実現可能であることを検証する

**チェック項目**:

| #   | 検証項目                                                       | 判定基準                                        |
| --- | -------------------------------------------------------------- | ----------------------------------------------- |
| 1   | AC-1〜AC-7 の全受入基準に対応する設計項目が存在するか          | 全ACに対応する変更計画が存在すること            |
| 2   | 棚卸し結果の分類（runtime / test helper / historical）が妥当か | 分類理由が明文化されていること                  |
| 3   | 削除対象の判断に漏れがないか                                   | `rg` 検索パターンが十分か再確認                 |
| 4   | スコープ外の変更が混入していないか                             | App.tsx / AuthGuard / safeInvoke 変更がないこと |

### タスク2: 安全性・スコープ検証

**目的**: 設計変更が既存動作を破壊しないこと、スコープが適切であることを検証する

**チェック項目**:

| #   | 検証項目                                                 | 判定基準                                          |
| --- | -------------------------------------------------------- | ------------------------------------------------- |
| 1   | e2e global-setup の変更が既存テストを破壊しないか        | `VITE_E2E_MODE` / `skipAuth` で認証バイパスが維持 |
| 2   | screenshot script の変更が CI/CD に影響しないか          | harness の動作要件が維持されていること            |
| 3   | completed workflow docs の降格がリンク整合性を壊さないか | `verify-unassigned-links.js` が PASS する設計     |
| 4   | `.claude/skills/` 内の変更がスキル実行に影響しないか     | 記述変更がスキルの挙動に影響しないことを確認      |
| 5   | 追加の未タスクが必要な箇所がないか                       | スコープ超過分は未タスク再分割計画が存在すること  |

### タスク3: ゲート判定

**判定基準**:

| 判定              | 条件                                        | 対応                  |
| ----------------- | ------------------------------------------- | --------------------- |
| PASS              | 全チェック項目が OK                         | Phase 4 へ            |
| MINOR             | 軽微な指摘のみ（文言修正等）                | 指摘対応後 Phase 4 へ |
| MAJOR（要件問題） | 棚卸しの分類が不十分、受入基準に漏れ        | Phase 1 へ戻る        |
| MAJOR（設計問題） | 副作用分析に不備、e2e/screenshot 設計に問題 | Phase 2 へ戻る        |
