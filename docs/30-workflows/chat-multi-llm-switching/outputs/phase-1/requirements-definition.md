## 1. 機能要件（Functional Requirements）

### FR-001: LLMプロバイダー選択

| 項目   | 内容                                                |
| ------ | --------------------------------------------------- |
| ID     | FR-001                                              |
| 名称   | LLMプロバイダー選択                                 |
| 説明   | ユーザーはチャット画面でLLMプロバイダーを選択できる |
| 優先度 | Must                                                |
| 関連AC | AC-001                                              |

**詳細要件**:

- 選択可能なプロバイダー: OpenAI, Anthropic, Google, xAI
- ドロップダウン形式での選択UI
- プロバイダー変更時、そのプロバイダーの最初のモデルが自動選択される

---

### FR-004: 会話履歴の維持

| 項目   | 内容                                                     |
| ------ | -------------------------------------------------------- |
| ID     | FR-004                                                   |
| 名称   | 会話履歴の維持                                           |
| 説明   | LLM切り替え後も過去の会話履歴が維持され、新LLMに渡される |
| 優先度 | Must                                                     |
| 関連AC | AC-006                                                   |

**詳細要件**:

- 切り替え前のメッセージ履歴を切り替え後のLLMリクエストに含める
- 各メッセージにどのLLMで生成されたかのメタデータを保持
- 履歴の最大長はコンテキストウィンドウサイズに依存

### FR-005: システムプロンプトの維持

| 項目   | 内容                                                    |

- 全プロバイダー/モデルで同一のシステムプロンプトを使用

## 3. 接続要件（統合テスト連携）

### 3.1 API接続要件

| 項目           | 要件                    |
| -------------- | ----------------------- |
| プロトコル     | HTTPS                   |
| 認証方式       | Bearer Token（APIキー） |
| エンドポイント | 各プロバイダーの公式API |

### 3.2 認証フロー要件

```
1. ユーザーが設定画面でAPIキーを入力
2. APIキーをセキュアストレージに保存
3. メッセージ送信時にAPIキーをヘッダーに設定
4. 無効なAPIキーの場合、エラーを表示
```

### 3.3 データフロー要件

```
[フロントエンド]
    ↓ メッセージ + プロバイダーID + モデルID + システムプロンプト + 会話履歴
[APIレイヤー]
    ↓ プロバイダー別リクエスト変換
[LLM API]
    ↓ ストリーミングレスポンス
[APIレイヤー]
    ↓ 共通レスポンス形式に変換
[フロントエンド]
    → 表示 + 履歴更新
```

### 3.4 コンテキスト共有要件

| 項目               | 要件                                  |
| ------------------ | ------------------------------------- |
| 会話履歴           | LLM切り替え後も全履歴を次のLLMに送信  |
| システムプロンプト | 全LLMで共通のシステムプロンプトを使用 |
| メタデータ         | 各メッセージに使用LLM情報を付与       |

## 4. スコープ定義

### 4.1 含むもの（In Scope）

| カテゴリ     | 項目                                                   |
| ------------ | ------------------------------------------------------ |
| プロバイダー | OpenAI, Anthropic, Google, xAI                         |
| UI           | LLM選択ドロップダウン、メッセージLLMラベル             |
| 機能         | リアルタイム切り替え、履歴維持、システムプロンプト維持 |
| エラー処理   | APIキーエラー、接続エラー、タイムアウト、レート制限    |

### 4.2 含まないもの（Out of Scope）

| カテゴリ     | 項目                           | 理由                                    |
| ------------ | ------------------------------ | --------------------------------------- |
| 同時送信     | 複数LLMへの同時メッセージ送信  | 別タスク（TASK-CHAT-SPLIT-COMPARE-001） |
| 自動選択     | タスクに応じたLLM自動選択      | 将来対応                                |
| コスト最適化 | コストベースの自動ルーティング | 将来対応                                |
| ローカルLLM  | Ollama等のローカルLLM          | 将来対応                                |
