## 1. アクター定義

### 1.1 主要アクター

#### AC-01: エンドユーザー

| 項目       | 内容                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| アクターID | AC-01                                                                     |
| 名称       | エンドユーザー                                                            |
| 説明       | AIWorkflowOrchestratorアプリケーションを使用してLLMとチャットするユーザー |
| 主な目標   | タスクに最適なLLMを選択し、効率的に質問・作業を行う                       |
| 技術レベル | 基本的なPCスキルを持つ一般ユーザー                                        |

**特性**:

- 複数のLLMの特性を理解している
- タスクに応じてLLMを使い分けたい
- 会話の文脈を維持しながら切り替えたい

---

### 1.2 二次アクター

#### AC-02: LLM APIサービス

| 項目       | 内容                                         |
| ---------- | -------------------------------------------- |
| アクターID | AC-02                                        |
| 名称       | LLM APIサービス                              |
| 説明       | OpenAI、Anthropic、Google、xAIのAPIサービス  |
| 役割       | チャットリクエストを処理し、レスポンスを返す |

**特性**:

- 各プロバイダー固有のAPI仕様
- 認証（APIキー）が必要
- レート制限あり

## 3. ユースケース詳細

### UC-01: LLMプロバイダー/モデルを選択する

| 項目           | 内容                                      |
| -------------- | ----------------------------------------- |
| ユースケースID | UC-01                                     |
| 名称           | LLMプロバイダー/モデルを選択する          |
| アクター       | エンドユーザー (AC-01)                    |
| 目的           | 使用するLLMプロバイダーとモデルを選択する |
| 事前条件       | チャット画面が表示されている              |
| 事後条件       | 選択されたLLMが次回メッセージに使用される |
| 優先度         | 高                                        |
| 関連FR         | FR-001, FR-002, FR-003                    |

| ステップ | アクター                             | システム                                                 |
| -------- | ------------------------------------ | -------------------------------------------------------- |
| 1        | プロバイダードロップダウンをクリック | -                                                        |
| 2        | -                                    | プロバイダー一覧（OpenAI, Anthropic, Google, xAI）を表示 |
| 3        | プロバイダーを選択                   | -                                                        |
| 4        | -                                    | 選択されたプロバイダーのモデル一覧を表示                 |
| 5        | モデルを選択                         | -                                                        |
| 6        | -                                    | 選択を状態に反映、Currentバッジを更新                    |

#### 代替フロー

**AF-01: モデルのみ変更**

| ステップ | アクター                         | システム                             |
| -------- | -------------------------------- | ------------------------------------ |
| 3a       | モデルドロップダウンのみクリック | -                                    |
| 4a       | -                                | 現在のプロバイダーのモデル一覧を表示 |
| 5a       | モデルを選択                     | -                                    |
| 6a       | -                                | 選択を状態に反映                     |

#### 例外フロー

**EF-01: プロバイダー一覧が空**

| ステップ | アクター | システム                                      |
| -------- | -------- | --------------------------------------------- |
| 2a       | -        | 「利用可能なLLMがありません」メッセージを表示 |

### UC-02: 会話中にLLMを切り替える

| 項目           | 内容                                           |
| -------------- | ---------------------------------------------- |
| ユースケースID | UC-02                                          |
| 名称           | 会話中にLLMを切り替える                        |

| ステップ | アクター                      | システム                                              |

| 5        | -                             | Currentバッジを更新                                   |

## 5. シナリオサマリー

### 5.1 主要シナリオ

| シナリオID | 名称           | 関連UC       | 説明                                      |
| ---------- | -------------- | ------------ | ----------------------------------------- |
| SC-01      | 初回LLM選択    | UC-01        | 初めてLLMを選択するシナリオ               |
| SC-02      | 会話中切り替え | UC-02, UC-04 | 会話の途中でLLMを切り替えるシナリオ       |
| SC-03      | マルチLLM会話  | UC-01〜UC-06 | 複数のLLMを使い分けながら会話するシナリオ |

### 5.2 シナリオ詳細: SC-03 マルチLLM会話

**前提条件**:

- ユーザーはチャット画面を開いている
- OpenAI、AnthropicのAPIキーが設定済み

**シナリオフロー**:

1. ユーザーがOpenAI/GPT-4oを選択（UC-01）
2. 「Pythonでソートアルゴリズムを説明して」とメッセージ送信（UC-03）
3. GPT-4oがコード例と説明を返す
4. メッセージにGPT-4oラベルが表示される（UC-06）
5. ユーザーがAnthropic/Claude 3.5 Sonnetに切り替え（UC-02）
6. 履歴が維持されていることを確認（UC-04）
7. 「さっきのコードをもっと効率的にできる？」とメッセージ送信（UC-03）
8. Claude 3.5 Sonnetが前の会話を参照して改善案を返す
9. メッセージにClaude 3.5 Sonnetラベルが表示される（UC-06）

**期待結果**:

- 両方のLLMの応答が履歴に表示される
- 各メッセージに正しいLLMラベルが付いている
- Claudeは前のGPT-4oの応答を参照した回答ができている

## 6. 非機能シナリオ

### NF-01: 高速切り替えシナリオ

**目的**: LLM切り替えのUI応答速度を検証

**手順**:

1. プロバイダードロップダウンをクリック
2. 別のプロバイダーを選択
3. UI更新完了までの時間を計測

**成功基準**: 100ms以内

### NF-02: アクセシビリティシナリオ

**目的**: キーボードのみでLLM切り替えが可能か検証

**手順**:

1. Tabキーでプロバイダードロップダウンにフォーカス
2. Enterで展開
3. 矢印キーで選択
4. Enterで確定

**成功基準**: 全操作がキーボードで完了可能
