## 実行手順

### Step 1: 要件定義レビュー

Phase 1の成果物をレビューする。

**レビュー観点**:

1. 機能要件の網羅性
2. 非機能要件の妥当性
3. 受け入れ基準の明確性
4. API Key管理のセキュリティ考慮

### Step 2: 設計レビュー

Phase 2の成果物をレビューする。

**レビュー観点**:

1. アーキテクチャの妥当性
2. IPC通信設計の適切性
3. 型定義の完全性
4. エラーハンドリング設計

### Step 3: 統合テスト観点の確認

統合テスト観点を明確化する。

**統合テスト観点**:

| カテゴリ             | 検証内容                           |
| -------------------- | ---------------------------------- |
| IPC通信テスト        | Renderer ↔ Main プロセス間通信     |
| Agent SDK接続テスト  | SDK初期化・API呼び出し             |
| エラーハンドリング   | SDK障害時のフロントエンド表示      |
| セッション管理テスト | セッション作成・再開・タイムアウト |

---

## レビュー判定基準

| 判定     | 条件                 | 対応                    |
| -------- | -------------------- | ----------------------- |
| PASS     | 全項目が基準を満たす | Phase 4へ進む           |
| MINOR    | 軽微な指摘のみ       | 指摘対応後Phase 4へ進む |
| MAJOR    | 重大な設計上の問題   | Phase 2へ戻り設計修正   |
| CRITICAL | 要件レベルの問題     | Phase 1へ戻り要件再定義 |
