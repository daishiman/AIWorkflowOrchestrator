## 実行手順

### Step 1: カバレッジ測定

現在のカバレッジを測定し、不足箇所を特定する。

```bash
# ユニットテストカバレッジ確認
pnpm --filter @repo/shared test:coverage

# 統合テスト実行
pnpm --filter @repo/desktop test:integration
```

### Step 2: ユニットテスト拡充

**カバレッジ目標**:

| 指標              | 最低基準 | 推奨基準 |
| ----------------- | -------- | -------- |
| Line Coverage     | 80%      | 90%      |
| Branch Coverage   | 60%      | 70%      |
| Function Coverage | 80%      | 90%      |

**追加テスト項目**:

1. エラーケースのテスト
2. 境界値テスト
3. 異常系テスト（タイムアウト、ネットワークエラー）

### Step 3: 統合テスト拡充

**結合テストカバレッジ目標**:

| 指標                         | 目標 |
| ---------------------------- | ---- |
| APIエンドポイント            | 100% |
| モジュール間インターフェース | 100% |
| 正常系シナリオ               | 100% |
| 異常系シナリオ               | 80%+ |
| 外部連携ポイント             | 100% |

**統合テストカテゴリ**:

| テストカテゴリ       | 検証項目                                |
| -------------------- | --------------------------------------- |
| IPC通信テスト        | Renderer ↔ Main プロセス間通信の往復    |
| Agent SDK接続テスト  | SDK初期化・API呼び出し・レスポンス検証  |
| エラーハンドリング   | SDK障害時のフロントエンド表示・リトライ |
| セッション管理テスト | セッション作成・再開・タイムアウト処理  |

### Step 4: テストの安定性確保

flaky-test-preventionスキルを参照し、テストの安定性を確保する。

**確認項目**:

- [ ] 非同期テストの適切な待機処理
- [ ] テスト間の依存関係排除
- [ ] 外部依存のモック化
