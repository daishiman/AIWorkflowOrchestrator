## 目的

`fetchSkills()` 非ブロッキング化の修正設計が AC-1〜AC-5 を満たし、
回帰リスクがなく、最小変更量で問題を解消できるかを gate 判定する。

## 実行タスク

### Task 1: 責務境界チェック

- `fetchSkills()` の失敗と `selectSkillByName` の実行が独立した責務であることを確認する
- `.catch()` パターンへの変換が `handleExecutePlan` と `processWorkflowOutcome` の両関数の責務境界を変えないことを確認する
- `fetchSkills()` 失敗時に `generationError` を設定しないことが UI への影響範囲として適切であることを確認する

### Task 2: 状態所有権チェック

- `fetchSkills()` 失敗時に `console.warn` のみで記録する設計が、エラー状態の所有権を適切に管理していることを確認する
- `selectSkillByName` の実行後の状態遷移が修正前後で同一であることを確認する
- 既存テスト U-8/U-13 が修正後も PASS することを設計レベルで確認する

### Task 3: リスク評価

| リスク                                                                                    | 影響度 | 発生確率 | 対策                                                                                       |
| ----------------------------------------------------------------------------------------- | ------ | -------- | ------------------------------------------------------------------------------------------ |
| `.catch()` 内で `console.warn` の記録が失敗しても処理が継続する                           | 低     | 極低     | `console.warn` は throw しないため問題なし                                                 |
| `fetchSkills()` 失敗時に `generationError` が非設定になることでユーザーへの通知が失われる | 中     | 低       | `fetchSkills()` 失敗はスキル一覧更新失敗であり、スキル選択の成功でユーザー体験は維持される |
| 修正が `handleExecutePlan` の他の `return true` パスに影響する                            | 高     | 低       | 変更は `fetchSkills()` 呼び出し部分のみに局所化されており、他パスは変更なし                |
| 既存テスト U-8/U-13 が `.catch()` パターン変換で回帰する                                  | 高     | 低       | U-8/U-13 は `fetchSkills()` 成功パスのテストであり、変換後も同一の動作となる               |

### Task 4: gate 判定

**判定結果: PASS**

- 実装は局所修正（`SkillLifecyclePanel.tsx` の 2 箇所のみ）で足りる
- AC-1〜AC-5 のすべてに対応する設計が揃っている
- 回帰リスクは低く、既存テストへの影響がない
- Phase 4 へ進める
