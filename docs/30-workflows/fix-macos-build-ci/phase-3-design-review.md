## 目的

Phase 1-2 の成果物をレビューし、実装に進む前に設計の妥当性を検証する。

## 背景

CI修正は本番環境に直接影響するため、実装前に設計の妥当性を確認することが重要。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足度のレビュー

**目的**: 設計が要件を満たしているか確認する

**実行手順**:

1. Phase 1 の要件定義書を確認
2. Phase 2 の設計がすべての要件を満たしているか検証
3. 受け入れ基準との整合性を確認
4. 不足や矛盾がある場合は記録

**期待される成果物**:

- 要件充足度チェックリスト（レビュー結果に含める）

---

### タスク2: 技術的妥当性のレビュー

**目的**: 設計の技術的な妥当性を確認する

**実行手順**:

1. 選定した解決策が技術的に正しいか確認
2. 設定値の妥当性を確認
3. 既存システムとの整合性を確認
4. リスク評価を実施

**期待される成果物**:

- 技術レビュー結果（レビュー結果に含める）

---

### タスク3: 影響範囲のレビュー

**目的**: 影響範囲分析が適切か確認する

**実行手順**:

1. 見落としている影響範囲がないか確認
2. ロールバック手順が実行可能か確認
3. 他のワークフローへの影響を再確認

**期待される成果物**:

- 影響範囲レビュー結果（レビュー結果に含める）

---

### タスク4: レビュー結果の判定

**目的**: 総合的なレビュー判定を行う

**実行手順**:

1. 各レビュー項目の結果を集約
2. PASS/MINOR/MAJOR/CRITICAL の判定を行う
3. 指摘事項と対応方針を記録
4. 次のアクションを決定

**期待される成果物**:

- 設計レビュー結果（`outputs/phase-3/design-review-result.md`）

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |
