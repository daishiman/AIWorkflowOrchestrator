## 選定理由

### 1. 確実性

- DMG生成を完全にスキップするため、`hdiutil` エラーを確実に回避できる
- GitHub Actions の macos-14 runner の制限に影響されない

### 2. シンプルさ

- `electron-builder.yml` の1ファイルのみ変更
- 変更行数が最小限（ターゲットリストからDMGを削除するだけ）
- 理解しやすく、保守しやすい

### 3. 低リスク

- 既存の設定を大きく変更しない
- ローカルビルドも同様に動作する
- 他のプラットフォーム（Windows/Linux）に影響なし

### 4. 実用性

- macOS ユーザーは ZIP からアプリをインストール可能
- ZIP は DMG と同等の配布形式として使用可能
- App Store 以外の配布では ZIP が広く使われている

### 5. 拡張性

- 将来、リリースワークフローで DMG 生成を追加可能
- `dmg` セクションの設定を残しておくことで、再有効化が容易

---

## 不採用オプションの理由

### オプション2: 環境変数切り替え

- 設定が複雑になる
- 環境変数の管理が必要
- 今回の問題に対してはオーバーエンジニアリング

### オプション3: ワークフローでターゲット指定

- 設定が分散する（electron-builder.yml とワークフローの両方）
- 保守性が低下する可能性
- オプション1で十分な場合は不要

### オプション4: 別DMGツール

- 他ツールも同様の問題を抱える可能性が高い
- 追加のツール管理が必要
- 実装・検証コストが高い

### オプション5: リリースワークフロー分離

- 今回の問題解決には過剰
- 将来の機能拡張として検討
- セルフホストランナーが必要になる可能性

## 実装アプローチ

### 変更対象

- `apps/desktop/electron-builder.yml`

### 変更内容

`mac.target` セクションから `dmg` を削除し、`zip` のみにする。

```yaml
# Before
mac:
  target:
    - target: dmg
      arch:
        - x64
        - arm64
    - target: zip
      arch:
        - x64
        - arm64

# After
mac:
  target:
    - target: zip
      arch:
        - x64
        - arm64
```

### 注意事項

- `dmg` セクション（`dmg.contents` など）は削除せず残す
- 将来のリリースワークフローで DMG 生成を再有効化できるようにする
