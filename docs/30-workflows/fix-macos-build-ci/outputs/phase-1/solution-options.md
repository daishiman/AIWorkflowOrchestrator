# 解決策オプション一覧

## 概要

`hdiutil: create failed - Device not configured` エラーを解決するための選択肢を列挙し、各案のメリット・デメリットを整理する。

---

## 解決策一覧

### オプション1: CI環境ではDMG生成を無効化しZIPのみにする（推奨）

**概要**: CI環境でのビルド時のみDMG生成をスキップし、ZIPファイルのみを生成する。

**実装方法**:

1. `electron-builder.yml` の `mac.target` から `dmg` を削除
2. または、CI環境向けの別設定ファイルを用意

**メリット**:
| メリット | 説明 |
|----------|------|
| 確実性 | DMG生成を完全にスキップするため、確実にエラーを回避 |
| シンプル | 設定変更が最小限 |
| 互換性 | ZIPはmacOSで問題なく使用可能 |
| 高速化 | DMG生成をスキップするためビルドが高速化 |

**デメリット**:
| デメリット | 説明 |
|------------|------|
| DMG非提供 | CI環境ではDMGを生成できない |
| 配布形式の制限 | ユーザーにZIPのみ提供（DMGは別途生成が必要） |

**実現可能性**: ★★★★★ (高)
**実装コスト**: 低
**リスク**: 低

### オプション2: 環境変数でターゲットを切り替える

**概要**: 環境変数 `ELECTRON_BUILDER_TARGET` などを使用して、CI環境とローカル環境でビルドターゲットを切り替える。

**実装方法**:

1. GitHub Actions ワークフローに環境変数を追加
2. `electron-builder.yml` を環境変数を参照する形式に変更
3. または、`--mac --target zip` オプションを直接指定

**メリット**:
| メリット | 説明 |
|----------|------|
| 柔軟性 | 環境に応じてターゲットを変更可能 |
| 設定一元管理 | electron-builder.ymlは1つのまま |

**デメリット**:
| デメリット | 説明 |
|------------|------|
| 複雑性 | 設定が複雑になる |
| 保守性 | 環境変数の管理が必要 |

**実現可能性**: ★★★★☆ (中〜高)
**実装コスト**: 中
**リスク**: 低

### オプション3: GitHub Actionsワークフローでターゲットを直接指定

**メリット**:

| electron-builder.yml変更不要 | 設定ファイルはそのまま |

**デメリット**:

| 整合性 | 設定ファイルとワークフローの設定が分散 |

**実現可能性**: ★★★★☆ (中〜高)

## 推奨する解決策

**オプション1: CI環境ではDMG生成を無効化しZIPのみにする**

### 理由

1. **確実性**: DMG生成をスキップすることで、確実にエラーを回避できる
2. **シンプル**: 設定変更が最小限で、理解しやすい
3. **リスク低**: 既存機能への影響が最小限
4. **実用性**: macOSユーザーはZIPからアプリをインストール可能
5. **将来性**: リリースワークフローで別途DMG生成を追加可能

### 実装アプローチ

`electron-builder.yml` の `mac.target` を以下のように変更:

```yaml
mac:
  target:
    - target: zip
      arch:
        - x64
        - arm64
```

DMG設定は残しておき（将来のリリースワークフロー用）、targetリストから除外するだけで対応。
