## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 実装ガイドの作成

**目的**: 修正内容を詳細に文書化する

**実行手順**:

1. **Part 1: 概念的な説明**を作成

   - 中学生にもわかる比喩・例え話を使った説明
   - なぜこの修正が必要だったか（Why-first原則）
   - どのような問題を解決したか
   - 全体アーキテクチャ（ASCII図解付き）

2. **Part 2: 技術的な詳細**を記述

   - 変更したファイルと内容
   - 設定の意図と根拠（「何をしたか」より「なぜそうしたか」を重視）
   - コード例 + 設計意図の説明
   - 対比説明（「悪い例」と「良い例」を並べる）

3. **用語集セクション**を追加【必須】

   - 専門用語の読み方・意味・コンテキスト
   - 英語の専門用語にはカタカナ読みを付記

4. **図解を追加**（ASCII図でアーキテクチャ・データフロー・関係性を可視化）

**記述原則**:

| 原則       | 内容                                                  |
| ---------- | ----------------------------------------------------- |
| Why-first  | 「何をしたか」より「なぜそうしたか」を重視            |
| 対比説明   | 「悪い例」と「良い例」を並べて違いを明確化            |
| 図解活用   | ASCII図でアーキテクチャ・データフロー・関係性を可視化 |
| コード注釈 | コードスニペットには必ず日本語コメントで意図を補足    |
| 読み方併記 | 英語の専門用語にはカタカナ読みを付記                  |

**期待される成果物**:

- 実装ガイド（`outputs/phase-12/implementation-guide.md`）
