## 目的

Phase 1-9 の成果物を総合的にレビューし、リリース品質を満たしていることを確認する。

## 背景

手動テストとドキュメント更新に進む前に、全体の品質と整合性を最終確認する。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足の最終確認

**目的**: Phase 1 の要件が全て満たされていることを確認する

**実行手順**:

1. Phase 1 の受け入れ基準を確認
2. 各基準の達成状況を確認
3. 未達項目がないことを確認
4. 結果を記録

**期待される成果物**:

- 要件充足確認結果（最終レビュー結果に含める）

---

### タスク2: 成果物の整合性確認

**目的**: 全Phaseの成果物が整合性を持っていることを確認する

**実行手順**:

1. 各Phaseの成果物を確認
2. 成果物間の整合性を確認
3. 矛盾や不足がないことを確認
4. 結果を記録

**期待される成果物**:

- 成果物整合性確認結果（最終レビュー結果に含める）

---

### タスク3: 品質基準の最終確認

**目的**: 全ての品質基準を満たしていることを確認する

**実行手順**:

1. Phase 9 の品質レポートを確認
2. 品質基準の達成状況を確認
3. 全基準を満たしていることを確認
4. 結果を記録

**期待される成果物**:

- 品質基準確認結果（最終レビュー結果に含める）

---

### タスク4: 最終レビュー判定

**目的**: 最終的なレビュー判定を行う

**実行手順**:

1. 各確認結果を集約
2. PASS/MINOR/MAJOR/CRITICAL の判定を行う
3. 指摘事項と対応方針を記録
4. 次のアクションを決定

**期待される成果物**:

- 最終レビュー結果（`outputs/phase-10/final-review-result.md`）

## レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
