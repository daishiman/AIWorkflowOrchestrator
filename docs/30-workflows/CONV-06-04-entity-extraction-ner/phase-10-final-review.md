## 目的

全体品質・整合性を検証し、手動テスト・ドキュメント更新・PR作成に進むかを判定する。

## 背景

最終レビューゲートは、実装完了後の品質を総合的に評価し、リリース準備に進むための最終チェックポイントとなる。

---

## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: 要件充足確認

**目的**: Phase 1の要件が全て満たされているかを確認する

**実行手順**:

1. 機能要件との照合
2. 非機能要件との照合
3. 受け入れ基準との照合
4. 未充足項目の特定

**期待される成果物**:

- `outputs/phase-10/requirements-verification.md`

---

### タスク2: 設計整合性確認

**目的**: Phase 2の設計が正しく実装されているかを確認する

**実行手順**:

1. アーキテクチャ設計との照合
2. インターフェース設計との照合
3. データフロー設計との照合
4. 乖離があれば記録

**期待される成果物**:

- `outputs/phase-10/design-verification.md`

---

### タスク3: 品質基準確認

**目的**: Phase 9の品質基準が全て満たされているかを確認する

**実行手順**:

1. 静的解析結果の確認
2. テストカバレッジの確認
3. セキュリティチェック結果の確認
4. パフォーマンス検証結果の確認

**期待される成果物**:

- `outputs/phase-10/quality-verification.md`

---

### タスク4: 最終判定

**目的**: レビュー結果を総合判定し、次のアクションを決定する

**実行手順**:

1. 全レビュー観点の結果を集計
2. 判定（PASS/MINOR/MAJOR/CRITICAL）を決定
3. 指摘事項があれば対応方針を決定
4. 次のPhaseへの進行可否を判定

**期待される成果物**:

- `outputs/phase-10/final-review-decision.md`

## レビューゲート

### レビュー結果判定

| 判定     | 条件                     | 次のアクション            |
| -------- | ------------------------ | ------------------------- |
| PASS     | 全レビュー観点で問題なし | 次のPhaseへ進行           |
| MINOR    | 軽微な指摘あり           | 指摘対応後、次のPhaseへ   |
| MAJOR    | 重大な問題あり           | 影響範囲に応じて戻る      |
| CRITICAL | 致命的な問題あり         | Phase 1へ戻りユーザー確認 |

### 戻り先決定基準

| 問題の種類       | 戻り先                |
| ---------------- | --------------------- |
| 要件の問題       | Phase 1（要件定義）   |
| 設計の問題       | Phase 2（設計）       |
| テスト設計の問題 | Phase 4（テスト）     |
| 実装の問題       | Phase 5（実装）       |
| 品質の問題       | Phase 8（リファクタ） |
