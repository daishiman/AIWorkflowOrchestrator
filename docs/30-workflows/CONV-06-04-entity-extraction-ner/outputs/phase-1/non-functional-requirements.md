## 1. 性能要件

### 1.1 処理速度

| 項目                       | 要件                         |
| -------------------------- | ---------------------------- |
| 単一チャンク抽出（LLM）    | < 5秒（LLM API応答時間含む） |
| 単一チャンク抽出（ルール） | < 100ms                      |
| バッチ抽出（100チャンク）  | < 60秒（並列処理時）         |
| マージ処理                 | < 500ms（1000エンティティ）  |

### 1.2 スループット

| 項目             | 要件                     |
| ---------------- | ------------------------ |
| LLM抽出          | 20チャンク/分（並列数5） |
| ルール抽出       | 1000チャンク/分          |
| バッチサイズ上限 | 100チャンク/バッチ       |

### 1.3 メモリ使用量

| 項目                       | 要件    |
| -------------------------- | ------- |
| 単一チャンク処理           | < 50MB  |
| バッチ処理（100件）        | < 500MB |
| 正規表現パターンキャッシュ | < 10MB  |

## 2. 信頼性要件

### 2.1 エラーハンドリング

| エラー種別               | ハンドリング方針                                    |
| ------------------------ | --------------------------------------------------- |
| LLM API タイムアウト     | 3回リトライ（指数バックオフ）、失敗時フォールバック |
| LLM レート制限           | 待機後リトライ（Retry-After ヘッダー準拠）          |
| JSON パースエラー        | ログ記録、空結果を返却                              |
| 入力バリデーションエラー | 即座にエラー返却（リトライなし）                    |
| DB 接続エラー            | リトライ後、エラー伝播                              |

### 2.2 フォールバック戦略

```
LLMEntityExtractor 失敗
    │
    ▼
RuleBasedEntityExtractor で再試行
    │
    ▼
成功 → 結果返却（extractorType: 'rule-based' をマーク）
失敗 → エラー返却
```

### 2.3 リトライ設定

| 設定項目         | 値                    |
| ---------------- | --------------------- |
| 最大リトライ回数 | 3回                   |
| 初期待機時間     | 1秒                   |
| バックオフ係数   | 2.0（指数バックオフ） |
| 最大待機時間     | 30秒                  |

### 2.4 タイムアウト設定

| 操作             | タイムアウト         |
| ---------------- | -------------------- |
| LLM API 呼び出し | 30秒                 |
| 単一チャンク抽出 | 45秒（リトライ含む） |
| バッチ抽出全体   | 5分                  |
| DB 書き込み      | 10秒                 |

## 3. セキュリティ要件

### 3.1 入力検証

| 検証項目             | ルール                                        |
| -------------------- | --------------------------------------------- |
| チャンクコンテンツ長 | 1〜100,000文字                                |
| チャンクID形式       | UUID v4形式                                   |
| オプション値範囲     | 定義された範囲内（minConfidence: 0.0〜1.0等） |
| 配列サイズ           | バッチ: 1〜100件                              |

### 3.2 出力サニタイズ

| 出力項目       | サニタイズ処理                             |
| -------------- | ------------------------------------------ |
| エンティティ名 | HTMLエスケープ、制御文字除去               |
| 説明文         | HTMLエスケープ、最大1000文字でトランケート |
| エイリアス     | HTMLエスケープ、各255文字でトランケート    |

### 3.3 LLMプロンプトインジェクション対策

| 対策                   | 説明                               |
| ---------------------- | ---------------------------------- |
| 入力サニタイズ         | 特殊文字エスケープ                 |
| システムプロンプト固定 | ユーザー入力で上書き不可           |
| 出力バリデーション     | JSON スキーマによる構造検証        |
| ローカル実行           | デスクトップアプリのため影響限定的 |

### 3.4 機密情報保護

| 項目             | 対策                              |
| ---------------- | --------------------------------- |
| API キー         | Electron SafeStorage で暗号化保存 |
| ログ出力         | API キー、個人情報をマスク        |
| エラーメッセージ | 内部詳細を含めない                |

## 4. 可用性要件

### 4.1 オフライン対応

| 状態       | 動作                                      |
| ---------- | ----------------------------------------- |
| オンライン | LLMEntityExtractor を使用                 |
| オフライン | RuleBasedEntityExtractor にフォールバック |
| 接続復旧時 | 自動的に LLM 使用を再開                   |

### 4.2 LLM 障害時の挙動

| シナリオ         | 挙動                                     |
| ---------------- | ---------------------------------------- |
| API タイムアウト | リトライ後、ルールベースにフォールバック |
| レート制限超過   | 待機後リトライ、超過時フォールバック     |
| 認証エラー       | エラー返却（フォールバックなし）         |
| サービス停止     | ルールベースにフォールバック             |

### 4.3 グレースフルデグラデーション

```
通常モード (LLM)
  │
  │ LLM障害検出
  ▼
縮退モード (Rule-based)
  │
  │ - 抽出精度は低下するが継続可能
  │ - UI にフォールバック状態を表示
  │
  │ LLM復旧検出
  ▼
通常モードに復帰
```

## 5. テスト容易性要件

### 5.1 モック可能性

| 依存              | モック方針                                |
| ----------------- | ----------------------------------------- |
| ILLMProvider      | インターフェース経由で DI、テスト時モック |
| IEntityRepository | インターフェース経由で DI、テスト時モック |
| 外部 API          | MSW によるネットワークモック              |
| 日時              | Date のモック可能な設計                   |

### 5.2 依存性注入パターン

```typescript
// 本番環境
const extractor = new LLMEntityExtractor({
  llmProvider: new ClaudeProvider(apiKey),
  entityRepository: new DrizzleEntityRepository(db),
});

// テスト環境
const extractor = new LLMEntityExtractor({
  llmProvider: mockLLMProvider,
  entityRepository: mockEntityRepository,
});
```

### 5.3 テストカテゴリ

| カテゴリ       | テスト対象                                 |
| -------------- | ------------------------------------------ |
| ユニットテスト | 純粋関数、バリデーション、正規表現パターン |
| 統合テスト     | LLM呼び出し（モック）、DB永続化            |
| E2Eテスト      | 抽出→永続化→検索の一連フロー               |

### 5.4 決定論的テスト

| 項目     | 対策                             |
| -------- | -------------------------------- |
| LLM 応答 | 固定シードまたはモックレスポンス |
| 日時依存 | 固定日時を注入                   |
| 順序依存 | ソート後に比較                   |
