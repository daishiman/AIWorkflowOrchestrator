## 目的

Phase 5 で実装した `createSkill()` のコールバック追加コードを、
最小複雑性・可読性・TASK-SW-STREAM-002 との接続準備という観点で再調整する。
テストが全て Green であることを維持しながらコードを整理する。

## 実行タスク

### Task 1: コード品質チェック

実装コードを以下の観点で確認する。

| 観点                         | チェック内容                                                                |
| ---------------------------- | --------------------------------------------------------------------------- |
| 命名の明確性                 | `SkillCreatorProgress` 型名・引数名 `onProgress` が意図を正確に表しているか |
| オプショナルチェーンの一貫性 | 全5箇所で `onProgress?.()` を統一して使用しているか                         |
| コールバック呼び出し位置     | 各処理の「開始直前」に配置されているか（処理中や処理後になっていないか）    |
| コメントの適切性             | 各コールバック箇所に `// AC-N:` 形式のコメントがあるか                      |

### Task 2: 命名と構造の整理

`createSkill()` の実装後コードを確認し、以下を整理する。

- `SkillCreatorProgress` 型定義の位置が適切か（他の型定義と近い位置にあるか）
- コールバック呼び出しの前後コメントで「どの処理の開始を通知しているか」が明確か
- `create` モード以外（`collaborative` / `orchestrate`）のブランチに意図しないコールバックがないか

### Task 3: リファクタリング後のテスト全件確認

```bash
# 全テスト Green 確認
pnpm --filter @repo/desktop test -- --testPathPattern="SkillCreatorService"
```

リファクタリング後も全テストが Green であることを確認する。

### Task 4: 技術的負債の記録

| 負債ID | 内容                                                           | 対応タスク               |
| ------ | -------------------------------------------------------------- | ------------------------ |
| TD-001 | `collaborative` / `orchestrate` モードに進捗通知がない         | 別タスク（モード別対応） |
| TD-002 | コールバック内例外がそのまま `createSkill()` に伝播する        | TASK-SW-STREAM-002 以降  |
| TD-003 | `SkillCreatorProgress` 型がファイルローカルで Preload 側と重複 | 型共通化タスク（別）     |
