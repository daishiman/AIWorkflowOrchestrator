## 実行タスク

> 以下のタスクを順番に実行してください。

### タスク1: コード重複の排除

**目的**: 重複しているコードを共通化する

**実行手順**:

1. 重複パターンを特定
2. 共通関数・ヘルパーに抽出
3. テストが通ることを確認

**期待される成果物**:

- リファクタリング後のコード

#### リファクタリング候補

| 箇所                 | 問題点                   | 改善案             |
| -------------------- | ------------------------ | ------------------ | --------------------- | -------------- |
| sendStream呼び出し   | 各所で同じパターンが重複 | ヘルパーメソッド化 |
| エラーメッセージ生成 | 文字列リテラルが散在     | 定数化             |
| パス取得ロジック     | `args.path               |                    | args.file_path`が重複 | 共通抽出関数化 |

---

### タスク2: 命名の改善

**目的**: 変数名・メソッド名をより明確にする

**実行手順**:

1. 命名が不明確な箇所を特定
2. より意図が伝わる名前に変更
3. テストが通ることを確認

**期待される成果物**:

- 命名改善後のコード

#### 命名改善候補

| 現在の名前 | 改善案                           | 理由                     |
| ---------- | -------------------------------- | ------------------------ |
| `_context` | `context` (使用しない場合は削除) | 未使用パラメータの明確化 |
| `msg`      | `streamMessage`                  | 型と用途の明確化         |

---

### タスク3: 型の厳格化

**目的**: 型定義をより厳格にし、型安全性を高める

**実行手順**:

1. `unknown`型の使用箇所を確認
2. 可能な限り具体的な型に変更
3. 型ガードの追加

**期待される成果物**:

- 型厳格化後のコード

#### 型改善候補

```typescript
// Before
content: {
  toolName: string;
  args: Record<string, unknown>;
  toolUseId: string;
}

// After
content: ToolUseContent;

// 型定義を追加
interface ToolUseContent {
  toolName: string;
  args: Record<string, unknown>;
  toolUseId: string;
}
```

---

### タスク4: エラーハンドリングの改善

**目的**: エラーハンドリングをより堅牢にする

**実行手順**:

1. 例外が発生しうる箇所を確認
2. 適切なエラーハンドリングを追加
3. エラーログの追加

**期待される成果物**:

- エラーハンドリング改善後のコード

#### 改善ポイント

- Hook内でのエラーをcatchしてログ出力
- sendStream失敗時のフォールバック処理
- 型ガード追加による実行時エラー防止

---

### タスク5: パフォーマンス最適化

**目的**: 不要な処理を削減しパフォーマンスを向上させる

**実行手順**:

1. 不要な処理を特定
2. 最適化を実施
3. パフォーマンス改善を確認

**期待される成果物**:

- 最適化後のコード

#### 最適化ポイント

- 文字列連結の最適化
- 不要なオブジェクト生成の削減
- 早期リターンの活用

---

### タスク6: リファクタリング後のテスト確認

**実行手順**:

**期待される成果物**:
