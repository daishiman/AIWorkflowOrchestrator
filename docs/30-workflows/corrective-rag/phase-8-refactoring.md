| 項目   | 値             |

| 作成日 | 2026-01-16     |

## 目的

テストで保護された状態でコード品質を向上させる。TDD Refactor（リファクタ）フェーズ。

## 実行タスク

- コードレビュー: 重複・複雑性の特定
- リファクタリング: コード品質向上の実施
- テスト維持: リファクタリング後もテストがGreen状態を維持

## リファクタリング観点

| 観点               | 確認項目                                   |
| ------------------ | ------------------------------------------ |
| DRY原則            | 重複コードがないか                         |
| 単一責任原則       | 各クラス・関数が単一の責務を持つか         |
| 可読性             | 変数名・関数名が意図を表現しているか       |
| 複雑性             | 循環的複雑度が高すぎないか（目安: 10以下） |
| エラーハンドリング | Result型が一貫して使用されているか         |

## 実行手順

### 1. コードレビュー

```bash
# 静的解析実行
pnpm --filter @repo/shared lint
pnpm --filter @repo/shared typecheck
```

### 2. リファクタリング候補の特定

| ファイル               | 確認観点                     |
| ---------------------- | ---------------------------- |
| relevance-evaluator.ts | プロンプト構築の可読性       |
| corrective-rag.ts      | アクションハンドラの責務分離 |
| types.ts               | 型定義の整理・再利用性       |

### 3. リファクタリング実施

以下の順序で実施:

1. 変数名・関数名の改善
2. 重複コードの抽出・共通化
3. 複雑な関数の分割
4. 型定義の整理

### 4. テスト確認

```bash
# リファクタリング後のテスト実行
pnpm --filter @repo/shared test
```
