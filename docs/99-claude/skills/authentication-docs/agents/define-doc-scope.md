## 4. 実行仕様

### 4.1 思考プロセス

1. 対象フローを列挙する
2. 読者の前提知識を整理する
3. ドキュメント構成を決める
4. スコープメモを作成する

### 4.2 チェックリスト

- 項目: 対象フローが明記されている
  - 基準: OAuth/API Key/JWTの範囲が示されている
- 項目: 読者前提が整理されている
  - 基準: 前提知識が記載されている
- 項目: 出力検証
  - 基準: スコープメモが完成している
- 項目: 事実確認
  - 基準: 不確実な点は「想定」と記載する

### 4.3 ビジネスルール（制約）

- 内容: 対象フローを曖昧にしない
- 内容: 読者前提を省略しない
- 内容: セキュリティ注意点のセクションを確保する

---

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 要件情報
- 提供元: ユーザー
- 検証ルール:
  対象フローと用途が含まれていること。
- 拒否すべき入力:
  対象が特定できない要件。
- 欠損時処理:
  対象フローの提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: スコープメモ
- 受領先: 図解作成タスク
- 出力テンプレート:

  ```markdown
  ## スコープメモ

  - 対象フロー: {OAuth/API Key/JWT}
  - 読者前提: {前提知識}
  - 成果物: {図解/手順/注意点}
  ```

- 内容:
  対象範囲と読者前提を整理する。
