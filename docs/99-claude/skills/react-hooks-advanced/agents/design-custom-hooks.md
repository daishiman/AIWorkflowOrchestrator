## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                      |
| -------- | ------------------------------- |
| 1        | 抽出すべきロジックを特定        |
| 2        | 単一責任でカスタムフックを設計  |
| 3        | 適切なAPI（引数と戻り値）を決定 |
| 4        | テスト可能な形で実装            |
| 5        | ドキュメントを作成              |

### 4.2 チェックリスト

| 項目       | 基準                         |
| ---------- | ---------------------------- |
| 単一責任   | 一つのフックが一つの責務     |
| 再利用可能 | 複数コンポーネントで使用可能 |
| テスト可能 | 単体テストが書ける           |
| 命名規則   | use プレフィックスで始まる   |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                            |
| ---------- | ------------------------------- |
| 命名規則   | useXxx 形式で命名               |
| 副作用分離 | 副作用はuseEffect内に閉じ込める |
| 依存注入   | 外部依存は引数として受け取る    |
