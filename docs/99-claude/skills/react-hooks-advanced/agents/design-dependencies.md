## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                             |
| -------- | -------------------------------------- |
| 1        | 分析レポートから依存配列の問題を抽出   |
| 2        | 依存配列の完全性原則を適用             |
| 3        | 古いクロージャ問題の回避パターンを適用 |
| 4        | 無限ループ発生パターンを排除           |
| 5        | 依存配列設計書を作成                   |

### 4.2 チェックリスト

| 項目               | 基準                              |
| ------------------ | --------------------------------- |
| 完全性確保         | 全ての依存が配列に含まれている    |
| 古いクロージャ対策 | stale closure問題が解消されている |
| 無限ループ防止     | 無限再実行のリスクがない          |
| ESLint準拠         | exhaustive-deps警告がゼロ         |

### 4.3 ビジネスルール（制約）

| 制約             | 説明                                |
| ---------------- | ----------------------------------- |
| 依存配列省略禁止 | 意図的な省略は避ける                |
| useRef回避策禁止 | 警告回避目的のuseRef使用は不可      |
| 関数のメモ化     | 依存に含む関数はuseCallbackでラップ |

---

## 5. インターフェース

### 5.1 入力

| データ名     | 提供元        | 検証ルール           | 欠損時処理     |
| ------------ | ------------- | -------------------- | -------------- |
| 分析レポート | analyze-hooks | 問題が特定されている | 前Taskの再実行 |

### 5.2 出力

| 成果物名       | 受領先            | 内容                             |
| -------------- | ----------------- | -------------------------------- |
| 依存配列設計書 | apply-memoization | 修正パターン、ベストプラクティス |

#### 出力テンプレート

```markdown
## 依存配列設計書

### 修正対象

| Hook        | 現状 | 修正後    | 理由                      |
| ----------- | ---- | --------- | ------------------------- |
| useEffect   | [a]  | [a, b]    | bも参照しているため       |
| useCallback | []   | [handler] | handlerが変更される可能性 |

### 適用パターン

1. **完全性原則**: 参照する全ての値を依存配列に含める
2. **関数の安定化**: useCallbackで関数をメモ化
3. **オブジェクトの分解**: オブジェクト全体ではなくプリミティブを依存に

### 回避すべきアンチパターン

- `// eslint-disable-next-line` で警告を無視
- useRefで依存を隠す
- 空の依存配列で「一度だけ実行」を意図
```
