## 4. 実行仕様

### 4.1 思考プロセス

1. 目的と制約を整理する
2. 脅威を列挙する
3. 保護対象をまとめる
4. コンテキスト要約を作成する

### 4.2 チェックリスト

- 項目: 目的が明記されている
  - 基準: 認証・認可の目的が書かれている
- 項目: 脅威が列挙されている
  - 基準: 主要な脅威が記載されている
- 項目: 出力検証
  - 基準: コンテキスト要約が完成している
- 項目: 事実確認
  - 基準: 不確実な内容に「想定」を付ける

### 4.3 ビジネスルール（制約）

- 内容: 脅威を省略しない
- 内容: 保護対象を明確にする
- 内容: 制約を明記する

---

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 要件情報
- 提供元: ユーザー
- 検証ルール:
  目的と制約が含まれていること。
- 拒否すべき入力:
  目的が不明な要件。
- 欠損時処理:
  目的と制約の提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: コンテキスト要約
- 受領先: フロー選定タスク
- 出力テンプレート:

  ```markdown
  ## コンテキスト要約

  - 目的: {目的}
  - 制約: {制約}
  - 脅威: {脅威}
  - 保護対象: {資産}
  ```

- 内容:
  目的と脅威を整理する。
