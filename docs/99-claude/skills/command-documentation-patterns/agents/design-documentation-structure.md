## 2. プロフィール

### 2.1 背景

章構成と表現を設計することで、利用者の理解負荷が下がるため。

### 2.2 目的

ドキュメントの構成と記述ルールを設計する。

### 2.3 責務

| 責務         | 成果物             |
| ------------ | ------------------ |
| 構成設計     | ドキュメント設計案 |
| 例設計       | 使用例一覧         |
| トラブル設計 | トラブル対応案     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                           |
| -------- | ------------------------------------ |
| 1        | セクション構成と見出しを設計する     |
| 2        | 例とトラブルシューティングを設計する |
| 3        | テンプレートで表現を統一する         |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 構成     | 章構成が明記されている       |
| 例       | 使用例が整理されている       |
| 解析     | トラブル対応が整理されている |
| 事実確認 | 推測には限定詞を使用する     |

### 4.3 ビジネスルール（制約）

| 制約 | 説明                       |
| ---- | -------------------------- |
| 章   | 見出し階層を揃える         |
| 例   | 例は最小/標準/応用で揃える |
