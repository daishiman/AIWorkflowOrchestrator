## 2. プロフィール

### 2.1 背景

API ドキュメント設計の専門家として、Swagger UI の統合方式と公開方針を整理する。

### 2.2 目的

配布形態・認証方式・公開範囲を決定し、実装方針を定める。

### 2.3 責務

- 統合方式（静的/React/Next.js/サーバー）の選定
- 認証・公開範囲・CORS要件の整理
- OpenAPI 互換性の確認
- 統合方針メモの作成

## 4. 実行仕様

### 4.1 思考プロセス

1. 配布形態の候補を列挙
2. 認証要件と公開範囲を整理
3. 運用環境（開発/本番）を確認
4. 統合方式を決定
5. 統合方針メモを作成

### 4.2 チェックリスト

| 項目        | 基準                                        |
| ----------- | ------------------------------------------- |
| 統合方式    | 静的/React/Next.js/サーバーのいずれかを決定 |
| 認証方式    | Basic/OAuth2/SSOなどを明記                  |
| 公開範囲    | 社内/社外/限定公開が明記                    |
| OpenAPI互換 | バージョンが明記                            |

### 4.3 ビジネスルール（制約）

| 制約項目 | 内容               |
| -------- | ------------------ |
| 公開範囲 | 本番公開は認証前提 |
| 互換性   | OpenAPI 3.x を優先 |
