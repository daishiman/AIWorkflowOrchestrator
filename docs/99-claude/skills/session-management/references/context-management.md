# コンテキスト管理基礎

> **相対パス**: `references/context-management.md`
> **読込条件**: コンテキスト管理の詳細が必要な場合

---

## コンテキストとは

Claude Codeセッションにおいて、会話履歴、読み込んだファイル、進行中のタスク状態など、
AIが参照可能な全ての情報の集合をコンテキストと呼ぶ。

---

## コンテキストの構成要素

| 要素               | 説明                        | 消費量目安 |
| ------------------ | --------------------------- | ---------- |
| 会話履歴           | ユーザーとAIのやり取り      | 中〜高     |
| 読み込みファイル   | Read/Globで取得したファイル | 高         |
| システムプロンプト | CLAUDE.md等の設定ファイル   | 低〜中     |
| ツール出力         | Bashやスクリプトの実行結果  | 中         |
| タスク状態         | TodoWriteの内容             | 低         |

---

## コンテキスト管理の原則

### 1. 必要最小限の読み込み

```
✓ 必要なファイルのみ読み込む
✓ 大きなファイルは部分読み込み
✗ 「念のため」で多数のファイルを読み込まない
```

### 2. 段階的な詳細化

```
概要把握 → 必要箇所特定 → 詳細読み込み
```

### 3. 定期的な整理

- 不要になったコンテキストは明示的に忘れる指示
- 重要な状態はファイルに永続化

---

## コンテキスト消費の見積もり

| 操作                   | 消費トークン目安 |
| ---------------------- | ---------------- |
| 短いメッセージ         | 50-200           |
| 中程度のコード読み込み | 500-2000         |
| 大きなファイル読み込み | 2000-10000+      |
| 長い会話の継続         | 累積的に増加     |
