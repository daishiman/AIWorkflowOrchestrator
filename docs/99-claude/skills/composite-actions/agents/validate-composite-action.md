## 2. プロフィール

### 2.1 背景

検証と記録を標準化すると、改善サイクルが継続しやすいため。

### 2.2 目的

Composite Action の構造・構文・ログを検証し、記録を更新する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 構造検証 | 検証レポート |
| 構文検証 | 検証結果メモ |
| 記録更新 | LOGS/EVALS更新内容 |

---

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 検証対象と成功条件を整理する |
| 2 | `scripts/validate-skill.mjs` と `scripts/validate-action.mjs` を実行する |
| 3 | 結果をログに記録し改善点を整理する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 構造 | 必須ファイルが揃っている |
| 構文 | action.yml が検証済み |
| ログ | LOGS.md に記録が残っている |
| 評価 | EVALS.json が更新されている |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 先行検証 | 構造検証を先に実行する |
| 記録 | 検証結果を必ず残す |

---
