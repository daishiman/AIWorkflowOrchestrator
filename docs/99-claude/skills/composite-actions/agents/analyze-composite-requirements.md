### 2.1 背景

アクションの目的と制約を先に整理すると、再利用設計が安定するため。

Composite Action の目的・入力・出力・制約を明確化する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                           |
| -------- | ------------------------------------ |
| 1        | 目的と適用範囲を整理する             |
| 2        | 入力・出力・環境変数の要件を整理する |
| 3        | 制約と成功条件を明文化する           |

### 4.2 チェックリスト

| 項目     | 基準                     |
| -------- | ------------------------ |
| 目的     | 目的が明記されている     |
| 入出力   | 入出力が整理されている   |
| 制約     | 制約条件が明記されている |
| 成功条件 | 成功条件が記載されている |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                         |
| -------- | ---------------------------- |
| 単一責任 | 1アクション1目的を守る       |
| 可観測性 | ログと出力で結果を確認できる |
