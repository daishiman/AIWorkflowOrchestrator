## 可観測性とは

システムの内部状態を外部から推測できる度合い。3つの柱で構成される。

| 柱         | 説明                           | 例                             |
| ---------- | ------------------------------ | ------------------------------ |
| メトリクス | 数値データの時系列             | CPU使用率、リクエスト数        |
| ログ       | イベントの記録                 | エラーメッセージ、アクセスログ |
| トレース   | 分散システムでのリクエスト追跡 | 相関ID、スパン                 |

## ゴールデンシグナル

Google SREが提唱する4つの基本監視指標。

### 1. レイテンシー（Latency）

リクエスト処理にかかる時間。

| 測定方法       | 推奨                        |
| -------------- | --------------------------- |
| パーセンタイル | p50, p95, p99               |
| 分離           | 成功/失敗リクエストを分ける |

### 2. トラフィック（Traffic）

システムへの需要量。

| 指標         | 単位         |
| ------------ | ------------ |
| RPS          | requests/sec |
| 同時接続数   | connections  |
| データ転送量 | bytes/sec    |

### 3. エラー（Errors）

失敗したリクエストの割合。

| 分類       | 例                   |
| ---------- | -------------------- |
| HTTPエラー | 5xx, 4xx             |
| 例外       | アプリケーション例外 |
| 論理エラー | 不正なレスポンス     |

### 4. 飽和度（Saturation）

リソースの使用率。

| リソース | 警告閾値 | 重大閾値 |
| -------- | -------- | -------- |
| CPU      | > 70%    | > 90%    |
| メモリ   | > 75%    | > 90%    |
| ディスク | > 80%    | > 95%    |

## SLI/SLO/SLA

### 用語定義

| 用語 | 正式名称                | 説明                             |
| ---- | ----------------------- | -------------------------------- |
| SLI  | Service Level Indicator | 測定可能なサービス品質指標       |
| SLO  | Service Level Objective | SLIの目標値                      |
| SLA  | Service Level Agreement | 顧客との契約（違反時ペナルティ） |

### 関係性

```
SLI（測定） → SLO（目標） → SLA（契約）
  ↓
エラーバジェット = 100% - SLO目標
```

### エラーバジェット例

| SLO    | 月間許容ダウンタイム |
| ------ | -------------------- |
| 99.9%  | 43.8分               |
| 99.95% | 21.9分               |
| 99.99% | 4.4分                |

## ログレベル

| レベル | 用途                   | 本番環境 |
| ------ | ---------------------- | -------- |
| ERROR  | 即座の対応が必要       | ✓        |
| WARN   | 注意が必要だが動作継続 | ✓        |
| INFO   | 重要な業務イベント     | ✓        |
| DEBUG  | デバッグ用詳細情報     | ✗        |

## 構造化ログ

### 必須フィールド

```typescript
interface LogEntry {
  timestamp: string; // ISO 8601形式
  level: string; // error/warn/info/debug
  message: string; // 人間可読メッセージ
  correlationId?: string; // リクエスト追跡用
}
```

### 非構造化 vs 構造化

```
非構造化:
2025-01-02 10:30:45 - User 123 logged in

構造化:
{"timestamp":"2025-01-02T10:30:45Z","level":"info","message":"User logged in","userId":123}
```

## アラート設計原則

### アクション可能なアラート

| 原則         | 説明                     |
| ------------ | ------------------------ |
| 明確な原因   | 何が問題かわかる         |
| 対応手順     | 何をすべきかわかる       |
| 適切な重大度 | 緊急度に応じた分類       |
| 抑制ルール   | ノイズを防ぐグルーピング |

### 避けるべきアラート

- ❌ アクション不要のアラート
- ❌ 頻繁に発火する閾値設定
- ❌ 無視されるアラート
