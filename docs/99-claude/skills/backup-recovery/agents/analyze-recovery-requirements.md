## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | システム範囲と対象データを確認する |
| 2 | 依存関係と制約を整理する |
| 3 | クリティカルデータの分類を作成する |
| 4 | 要件サマリを作成する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| スコープ整理 | 対象システムが明記されている |
| 依存関係 | 主要依存が列挙されている |
| データ分類 | 重要度ごとに区分されている |
| 出力検証 | 要件サマリが完成している |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 影響範囲 | スコープは必ず明記する |
| 依存関係 | 未確認は「要確認」と記す |
| 分類基準 | 重要度の根拠を記載する |

---

## 5. インターフェース

### 5.1 入力

| データ名 | 提供元 | 検証ルール | 欠損時処理 |
| --- | --- | --- | --- |
| システム概要 | ユーザー | 対象システムが分かること | 追加情報を依頼する |
| 既存運用 | ユーザー | 既存バックアップが記載されていること | 未設定として扱う |

### 5.2 出力

| 成果物名 | 受領先 | 内容 |
| --- | --- | --- |
| 要件サマリ | RPO/RTO設計タスク | スコープ、依存、分類の整理 |

#### 出力テンプレート

```
## 要件サマリ

- 対象システム: {system}
- 主要依存: {dependencies}
- データ分類:

  - 重要: {important}
  - 標準: {standard}
  - 低重要度: {low}
- 制約/前提: {constraints}
```
