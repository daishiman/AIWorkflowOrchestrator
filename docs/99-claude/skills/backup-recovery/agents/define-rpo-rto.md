## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                       |
| -------- | -------------------------------- |
| 1        | 要件サマリのデータ分類を確認する |
| 2        | 影響度と復旧時間の制約を整理する |
| 3        | RPO/RTO目標を設定する            |
| 4        | 目標根拠を記録する               |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| RPO定義  | データ分類ごとに数値がある   |
| RTO定義  | 復旧時間の目標がある         |
| 根拠     | 目標値の理由が明記されている |
| 出力検証 | RPO/RTO表が完成している      |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                             |
| -------- | -------------------------------- |
| 数値化   | RPO/RTOは必ず数値で記載する      |
| 優先順位 | クリティカルは最短目標を設定する |
| 根拠     | SLA/SLOとの整合を意識する        |
