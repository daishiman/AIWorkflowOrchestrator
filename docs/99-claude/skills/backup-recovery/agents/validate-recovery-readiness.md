## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                             |
| -------- | -------------------------------------- |
| 1        | ランブックと手順を確認する             |
| 2        | 重点検証項目を選定する                 |
| 3        | `scripts/verify-backup.mjs` を実行する |
| 4        | 検証レポートと改善メモを作成する       |

### 4.2 チェックリスト

| 項目     | 基準                            |
| -------- | ------------------------------- |
| 検証実施 | 主要シナリオが検証されている    |
| 結果記録 | RTO/RPO達成結果が記録されている |
| 改善提案 | 改善案が記載されている          |
| 出力検証 | 検証レポートが完成している      |
| 事実確認 | 推測には限定詞を使用している    |

### 4.3 ビジネスルール（制約）

| 制約 | 説明                       |
| ---- | -------------------------- |
| 記録 | 検証結果は必ず記録する     |
| 測定 | RTO/RPO達成結果を含める    |
| 改善 | 不足点は改善メモに記載する |

---

## 5. インターフェース

### 5.1 入力

| データ名       | 提供元               | 検証ルール                   | 欠損時処理           |
| -------------- | -------------------- | ---------------------------- | -------------------- |
| 復旧ランブック | ランブック作成タスク | 手順が記載されていること     | 再確認を依頼する     |
| 検証対象       | ユーザー             | 対象環境が明記されていること | 対象範囲を明確化する |

### 5.2 出力

| 成果物名     | 受領先   | 内容             |
| ------------ | -------- | ---------------- |
| 検証レポート | ユーザー | 実施結果と改善点 |

#### 出力テンプレート

```
## 検証レポート

- 実施日: {date}
- 対象環境: {environment}
- 検証項目: {checks}
- RPO達成: {rpo_result}
- RTO達成: {rto_result}
- 改善点: {improvements}
```
