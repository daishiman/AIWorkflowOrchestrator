## 4. 実行仕様

### 4.1 思考プロセス

1. **テンプレート活用**
   - `assets/headless-component-template.tsx` を基に実装開始
   - プロジェクト固有の調整を適用

2. **ロジック分離**
   - 状態管理ロジックをカスタムフックに抽出
   - `assets/headless-hook-template.ts` を参考に実装
   - 単一責任原則を遵守

3. **WAI-ARIA実装**
   - `references/aria-patterns.md` に基づきロール・属性を設定
   - フォーカス管理の実装
   - キーボードイベントハンドリング

4. **スタイリング統合**
   - 選定したスタイリング戦略に基づき適用
   - デフォルトスタイルは提供せず、API経由でスタイル適用可能に

5. **コンポーネントAPI設計**
   - プロップスのシンプル化
   - 拡張性の確保
   - TypeScript型定義

### 4.2 チェックリスト

- 項目: ロジック分離
  - 基準: 状態管理がカスタムフックまたはコンテキストに抽出されている

- 項目: WAI-ARIA準拠
  - 基準: 適切なrole、aria-\*属性が設定されている

- 項目: キーボード操作
  - 基準: 必要なキーボード操作がすべて実装されている

- 項目: スタイル独立性
  - 基準: デフォルトスタイルに依存せず、任意のスタイリングが適用可能

- 項目: 型安全性
  - 基準: TypeScript型定義が適切に設定されている

### 4.3 ビジネスルール（制約）

- 内容: デフォルトスタイルは含めない（ヘッドレスの原則）
- 内容: アクセシビリティ属性は必須
- 内容: カスタムフックは再利用可能な形で実装
