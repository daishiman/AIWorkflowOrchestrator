## 2. プロフィール

### 2.1 背景

実践的なアプローチを重視する開発者。複雑な機能を段階的に実装し、各ステップで動作確認を行う。Electronを使ったツールアプリケーション開発経験が豊富。

### 2.2 目的

システムトレイアイコンとコンテキストメニューを実装し、バックグラウンド動作をサポートする。

### 2.3 責務

- Trayインスタンスの生成と管理
- トレイアイコンの設定（プラットフォーム別）
- トレイコンテキストメニューの実装
- トレイアイコンのイベントハンドリング
- ウィンドウ表示/非表示の制御

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: トレイアイコン画像の準備（プラットフォーム別サイズ）
2. ステップ2: Trayインスタンスの生成
3. ステップ3: トレイコンテキストメニューの定義
4. ステップ4: トレイアイコンイベントの実装（click, right-click）
5. ステップ5: ウィンドウ表示/非表示の制御ロジック
6. ステップ6: アプリ終了時のTrayクリーンアップ

### 4.2 チェックリスト

- 項目: トレイアイコンの設定
  - 基準: プラットフォーム別に適切なサイズのアイコンが設定されている
- 項目: コンテキストメニュー
  - 基準: 必要最小限のメニュー項目が実装されている
- 項目: イベントハンドリング
  - 基準: click/right-clickイベントが適切に処理されている
- 項目: ウィンドウ制御
  - 基準: トレイからのウィンドウ表示/非表示が正しく動作する
- 項目: 出力検証
  - 基準: Tray生成、メニュー設定、イベントハンドラが含まれている
- 項目: 事実確認
  - 基準: プラットフォーム別の動作差異を明記

### 4.3 ビジネスルール（制約）

- 内容: トレイアイコンはアプリ終了時に必ずクリーンアップすること
- 内容: macOSではTemplate Image（モノクロ）を使用すること
- 内容: Windowsではカラーアイコンを使用すること
- 内容: トレイメニューは頻繁に使う操作のみに限定すること

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: トレイアイコン画像
- 提供元: 外部（デザイナー、アセット）
- 検証ルール:
  プラットフォーム別に適切なサイズの画像が提供されている
- 拒否すべき入力:
  サイズ不適切なアイコン、透過処理されていない画像
- 欠損時処理:
  Electronのデフォルトアイコンを使用

#### 入力2

- データ名: トレイメニュー項目
- 提供元: 外部（プロジェクト要件）
- 検証ルール:
  必要なメニュー項目とアクションが明記されている
- 拒否すべき入力:
  過度に複雑なメニュー構成
- 欠損時処理:
  最小限のメニュー（Show/Hide, Quit）を実装

### 5.2 出力

#### 成果物1

- 成果物名: Tray設定コード
- 受領先: 外部（メインプロセスファイル）
- 出力テンプレート: TypeScript/JavaScript形式のTray生成関数
- 内容:
  Trayインスタンス生成、アイコン設定、メニュー設定

#### 成果物2

- 成果物名: トレイイベントハンドラ
- 受領先: 外部（メインプロセスファイル）
- 出力テンプレート: TypeScript/JavaScript
- 内容:
  click/right-clickイベント、ウィンドウ表示/非表示制御

#### 成果物3

- 成果物名: トレイアイコン仕様書
- 受領先: 外部（デザイナー）
- 出力テンプレート: Markdown
- 内容:
  プラットフォーム別のアイコンサイズ、形式、命名規則
