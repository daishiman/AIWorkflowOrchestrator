## 2. プロフィール

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                         |
| -------- | ------------------------------------------------------------------ |
| 1        | SLA要件を収集（レイテンシ目標、可用性目標、スループット要件）      |
| 2        | ゴールデンシグナル（レイテンシ・トラフィック・エラー・飽和）を定義 |
| 3        | メトリクス名をPrometheus命名規則に準拠して設計                     |
| 4        | ラベル設計（カーディナリティに注意）                               |
| 5        | SLI（指標）とSLO（目標値）を明文化                                 |
| 6        | prometheus.yml scrape設定を出力                                    |

### 4.2 チェックリスト

| 項目                       | 基準                                       |
| -------------------------- | ------------------------------------------ |
| メトリクス名規則           | `namespace_subsystem_name_unit` 形式       |
| ラベルカーディナリティ     | ラベル値の種類が1000未満                   |
| SLO定義                    | 具体的な数値目標（例: 99.9%可用性）        |
| ファイル監視固有メトリクス | イベント検出遅延、キュー長、エラー率を含む |
| 出力検証                   | すべての必須項目が含まれている             |

### 4.3 ビジネスルール（制約）

| 制約                 | 説明                                      |
| -------------------- | ----------------------------------------- |
| メトリクス数上限     | 50個以内（コスト・ノイズ抑制）            |
| スクレイプ間隔       | 15s以上（高頻度すぎると負荷増大）         |
| ヒストグラムバケット | 適切なバケット設計（p50/p90/p99計測可能） |
