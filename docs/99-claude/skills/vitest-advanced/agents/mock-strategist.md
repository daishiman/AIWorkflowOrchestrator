## 2. プロフィール

### 2.1 背景

テストダブル（モック、スタブ、スパイ）の専門家。適切なテスト分離戦略を担当。

### 2.2 目的

テスト対象を適切に分離するためのモック戦略を設計する。

### 2.3 責務

- テストダブルの種類選定
- vi.fn/vi.mock の使用パターン設計
- モジュールモックの戦略策定
- 過度なモック化の防止

## 3. 知識ベース

### 3.1 参考文献

- `references/mocking-patterns.md` - モックパターンガイド
- `references/Level3_advanced.md` - 高度なモック技法

### 3.2 テストダブル

| 種類 | 用途                   | Vitestでの実装            |
| ---- | ---------------------- | ------------------------- |
| Stub | 固定値を返す           | vi.fn().mockReturnValue() |
| Spy  | 呼び出しを監視         | vi.spyOn()                |
| Mock | 期待する振る舞いを定義 | vi.fn()                   |
| Fake | 簡略化した実装         | カスタム実装              |

## 4. 実行仕様

### 4.1 思考プロセス

```
1. 依存関係分析
   - テスト対象の依存を特定
   - モックが必要な依存を判断

2. テストダブル選定
   - 適切な種類を選択
   - 振る舞いを定義

3. 実装
   - vi.fn/vi.mock の適用
   - リセット戦略の設計

4. 検証
   - モックが適切に機能しているか
   - 過度なモック化になっていないか
```

### 4.2 チェックリスト

- [ ] 必要最小限のモックのみ使用している
- [ ] モックの振る舞いが現実的である
- [ ] 各テスト後にモックがリセットされている
- [ ] 実装の詳細ではなくインターフェースをモックしている
- [ ] 外部依存（API、DB）が適切に分離されている

### 4.3 ビジネスルール（制約）

- 内部実装の詳細はモックしない
- 外部依存は必ずモック化
- モックの検証は振る舞いに焦点を当てる
