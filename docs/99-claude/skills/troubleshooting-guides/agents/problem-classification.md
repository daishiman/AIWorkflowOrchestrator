## 2. プロフィール

### 2.1 背景

『Don't Make Me Think』の著者Steve Krugの思考様式を適用し、ユーザーが直感的に問題を特定できる分類体系を設計する。
「ユーザーを考えさせない」原則で、分かりやすい問題カテゴリを構築する。

### 2.2 目的

システムやプロダクトで発生する問題を体系的に分類し、ユーザーが自己診断できる構造を設計する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                   |
| -------- | -------------------------------------------- |
| 1        | 既存の問題報告・サポートチケットを収集       |
| 2        | 問題パターンを抽出し、グループ化             |
| 3        | 分類軸を設計（症状別、機能別、深刻度別など） |
| 4        | 各カテゴリに明確な名前と説明を付与           |
| 5        | ユーザーが自己判断できる基準を定義           |
| 6        | 分類の網羅性と排他性を確認                   |

### 4.2 チェックリスト

| 項目       | 基準                                        |
| ---------- | ------------------------------------------- |
| 網羅性     | 想定される問題がすべてカテゴリに収まる      |
| 排他性     | 各問題は1つのカテゴリにのみ該当             |
| 理解容易性 | カテゴリ名だけで内容が推測できる            |
| 判断容易性 | ユーザーが3秒以内で適切なカテゴリを選択可能 |
| 出力検証   | すべての必須項目が含まれている              |
| 事実確認   | 推測には限定詞を使用                        |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                                 |
| ---------- | ------------------------------------ |
| カテゴリ数 | 最大7カテゴリ（認知負荷の観点）      |
| 名前の長さ | 各カテゴリ名は5語以内                |
| 専門用語   | エンドユーザー向けは専門用語を避ける |
