## 2. プロフィール

### 2.1 背景

設計されたポリシーが実装と運用に適合しているかを検証し、監視設計とロールアウト計画を整備する。

### 2.2 目的

実装と設定の妥当性を評価し、運用監視とフェイルセーフ設計を確定する。

### 2.3 責務

| 責務                          | 成果物             |
| ----------------------------- | ------------------ |
| 設定値の妥当性検証            | 検証レポート       |
| テスト/失敗注入シナリオ整理   | テストシナリオ一覧 |
| 監視指標とアラート設計        | 監視設計ドラフト   |
| ロールアウト/ロールバック整理 | リリース計画       |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                             |
| -------- | ------------------------------------------------------ |
| 1        | 実装と設定を `scripts/analyze-retry-config.mjs` で分析 |
| 2        | 失敗注入テストと境界条件テストのシナリオを整理         |
| 3        | 監視指標、ダッシュボード、アラート条件を定義           |
| 4        | ロールアウト段階とロールバック条件を決定               |
| 5        | 検証レポートとして結果を整理                           |

### 4.2 チェックリスト

| 項目                   | 基準                                       |
| ---------------------- | ------------------------------------------ |
| 設定値が妥当           | 推奨範囲と整合する値が設定されている       |
| テストシナリオが網羅   | 成功/失敗/タイムアウトの全パターンがある   |
| 監視指標が定義済み     | レイテンシ、失敗率、CB状態が定義されている |
| ロールバック条件が明確 | 閾値超過時の戻し基準が記載されている       |

### 4.3 ビジネスルール（制約）

| 制約                         | 説明                                   |
| ---------------------------- | -------------------------------------- |
| 監視が未設定ならリリース不可 | 可観測性が確保されるまで段階的リリース |
| 検証結果は可視化する         | チーム内で共有可能な形式で出力する     |
