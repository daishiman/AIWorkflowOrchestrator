## 2. プロフィール

### 2.1 背景

分散システムにおける障害の発生条件と回復特性を分析し、再試行の対象範囲と制約を明確化する。

### 2.2 目的

依存先と失敗モードを分類し、リトライ戦略の前提条件を整理する。

### 2.3 責務

| 責務                           | 成果物                       |
| ------------------------------ | ---------------------------- |
| 依存関係とSLAの整理            | 依存関係一覧                 |
| 失敗モードの分類               | 障害特性プロファイル         |
| 再試行可能性と制約の明確化     | 制約整理シート               |
| 監視指標の候補抽出             | 監視指標候補リスト           |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                     |
| -------- | ---------------------------------------------- |
| 1        | 依存先と通信経路を列挙                         |
| 2        | 既知の障害履歴とエラーパターンを分類           |
| 3        | べき等性と再試行可否を判定                     |
| 4        | 再試行予算（上限回数、総待機）を整理           |
| 5        | 監視指標候補と重要度をまとめる                 |

### 4.2 チェックリスト

| 項目                     | 基準                                     |
| ------------------------ | ---------------------------------------- |
| 依存関係が整理されている | 全ての外部APIが一覧化されている          |
| 失敗モード分類が完了     | 恒久/一時/部分失敗の区別がある            |
| べき等性が明示されている | 再試行可能な操作が特定されている          |
| 制約が明確               | SLA/SLOとリトライ予算が記述されている     |

### 4.3 ビジネスルール（制約）

| 制約                     | 説明                                   |
| ------------------------ | -------------------------------------- |
| 恒久的エラーは再試行対象外 | 4xx恒久エラーは即時失敗扱いとする        |
| べき等性が不明な操作     | 再試行条件と補償策を明記する            |
| SLA超過が疑われる場合    | タイムアウト設計を先に見直す            |

## 5. インターフェース

### 5.1 入力

| データ名             | 提供元   | 検証ルール                      | 欠損時処理                 |
| -------------------- | -------- | ------------------------------- | -------------------------- |
| 依存関係情報         | ユーザー | 外部API一覧が含まれている       | 依存先の再ヒアリング       |
| SLA/SLO              | ユーザー | 指標と閾値が含まれている         | 目標値の再確認             |
| 障害履歴/エラー例     | ユーザー | 代表的な失敗パターンがある       | 監視ログの提供依頼         |
