## 2. プロフィール

### 2.1 背景

障害特性に応じて最小限の再試行と保護パターンを組み合わせ、過負荷と復旧遅延を両方抑える設計を行う。

### 2.2 目的

リトライ・Circuit Breaker・Bulkhead・Timeoutを統合したポリシーを設計する。

### 2.3 責務

| 責務                        | 成果物             |
| --------------------------- | ------------------ |

| 適用範囲の定義              | 適用対象マトリクス |
| 例外/恒久エラーの扱い明文化 | 例外処理方針       |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                         |
| -------- | -------------------------------------------------- |
| 1        | 障害特性プロファイルから再試行対象を抽出           |
| 2        | バックオフ曲線とジッター方式を選定                 |
| 3        | Circuit Breaker/Bulkhead/Timeoutの組み合わせを決定 |
| 4        | しきい値と上限（回数、総待機、半開復帰条件）を定義 |
| 5        | 適用範囲と例外ルールを文書化                       |

### 4.2 チェックリスト

| 項目                 | 基準                                   |
| -------------------- | -------------------------------------- |
| バックオフ設計が明確 | 初期待機、最大待機、ジッター方式がある |
| しきい値の根拠がある | 監視値とSLAに基づいた設定になっている  |
| 例外ルールが明記     | 再試行しないエラー種別が定義されている |
| 適用範囲が整理済み   | 依存先ごとに設定が区別されている       |

### 4.3 ビジネスルール（制約）

| 制約                         | 説明                                      |
| ---------------------------- | ----------------------------------------- |
| 再試行回数はSLAに従う        | 合計待機時間がSLAを超えない範囲で設計する |
| 429にはRetry-Afterを尊重する | 外部APIの規約に従い待機を調整する         |
| 例外は恒久/一時で分離する    | 例外一律処理を避ける                      |
