## 2. プロフィール

### 2.1 背景

ドキュメント品質保証のベストプラクティスに基づき、ランブックの実効性を検証。
机上演習（テーブルトップエクササイズ）とピアレビューを組み合わせた検証手法を確立。

### 2.2 目的

ランブックの実効性を確保する。
ドライラン、レビュー、自動検証を通じて品質を担保する。

### 2.3 責務

| 責務               | 成果物             |
| ------------------ | ------------------ |
| 構造検証           | 構造検証レポート   |
| 完全性確認         | 完全性レポート     |
| ドライラン実施     | ドライランレポート |
| フィードバック収集 | 改善提案リスト     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                           |
| -------- | ---------------------------------------------------- |
| 1        | ランブックドラフトを受領                             |
| 2        | `scripts/validate-runbook.mjs` で構造検証            |
| 3        | `scripts/check-completeness.mjs` で完全性確認        |
| 4        | 必須セクションの存在をチェック                       |
| 5        | リンクと参照の整合性を確認                           |
| 6        | ドライラン（机上演習）を実施                         |
| 7        | 関係者レビューとフィードバック収集                   |
| 8        | 品質基準との照合（`references/quality-criteria.md`） |
| 9        | 改善提案リストを作成                                 |

### 4.2 チェックリスト

| 項目           | 基準                               |
| -------------- | ---------------------------------- |
| 構造検証通過   | validate-runbook.mjsがエラーなし   |
| 完全性確認通過 | check-completeness.mjsがエラーなし |
| ドライラン成功 | 手順に従って実行可能               |
| レビュー完了   | 少なくとも1名のピアレビュー        |
| 改善点反映     | 指摘された問題が修正されている     |

### 4.3 ビジネスルール（制約）

| 制約             | 説明                           |
| ---------------- | ------------------------------ |
| 自動検証必須     | スクリプトによる検証を必ず実施 |
| ドライラン必須   | 机上演習を省略しない           |
| ピアレビュー必須 | 作成者以外による確認           |
| 修正後再検証     | 修正を行った場合は再度検証     |

## 5. インターフェース

### 5.1 入力

| データ名           | 提供元           | 検証ルール          | 欠損時処理       |
| ------------------ | ---------------- | ------------------- | ---------------- |
| ランブックドラフト | runbook-creation | 標準構造のMarkdown  | 前Taskに確認依頼 |
