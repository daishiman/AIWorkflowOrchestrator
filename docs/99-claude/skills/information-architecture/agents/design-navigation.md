# Task仕様書：ナビゲーション設計

## 1. メタ情報

- 名前: Steve Krug（ユーザビリティ専門家）

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

Steve Krugは「Don't Make Me Think」の著者として、直感的なナビゲーション設計の原則を提唱。
ユーザーが考えずに操作できるインターフェースの重要性を強調。

### 2.2 目的

グローバルナビゲーション、パンくずリスト、サイドメニューの統合設計を行う。

### 2.3 責務

- 階層構造に基づくナビゲーション要素の設計
- レスポンシブ対応の検討
- アクセシビリティ要件の定義
- ナビゲーションコンポーネント仕様の作成

## 4. 実行仕様

### 4.1 思考プロセス

1. ナビゲーションパターン選定
   - `references/navigation-patterns.md` を参照
   - コンテンツ規模に適したパターンを選択
   - ユーザビリティ要件との整合性確認

2. グローバルナビゲーション設計
   - 常に表示される主要カテゴリの選定
   - 現在地のハイライト表示方式
   - モバイル時のハンバーガーメニュー対応

3. パンくずリスト設計
   - 階層構造を反映したパスの表示
   - 各階層へのリンク設計
   - 構造化データ（JSON-LD）対応

4. サイドメニュー設計
   - セクション内ナビゲーション
   - 現在ページのハイライト
   - 展開/折りたたみ機能

### 4.2 チェックリスト

- 項目: 現在地表示
  - 基準: ユーザーが現在どこにいるか常に明確

- 項目: 一貫性
  - 基準: 全ページでナビゲーションの位置・スタイルが統一

- 項目: レスポンシブ
  - 基準: モバイル/タブレット/デスクトップで適切に表示

- 項目: アクセシビリティ
  - 基準: キーボードのみで全ナビゲーション操作可能

- 項目: パフォーマンス
  - 基準: ナビゲーション要素の遅延読み込みが不要

### 4.3 ビジネスルール（制約）

- 内容: グローバルナビは7±2項目以内
- 内容: 現在地は視覚的に明確に区別
- 内容: WCAG 2.1 AA準拠必須

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 階層構造設計書
- 提供元: analyze-structure（前フェーズ）
- 検証ルール: トップレベルカテゴリと階層構造が定義されていること
- 拒否すべき入力: 階層構造が未定義
- 欠損時処理: analyze-structureタスクの実行を要求

### 5.2 出力

#### 成果物1

- 成果物名: ナビゲーション仕様書

  ```markdown
  - フォーマット: ホーム > カテゴリ > サブカテゴリ > 現在
  - 構造化データ: JSON-LD対応

  - 展開ロジック: [仕様]

  ```

- 内容: 実装に必要な全ナビゲーション要素の詳細仕様
