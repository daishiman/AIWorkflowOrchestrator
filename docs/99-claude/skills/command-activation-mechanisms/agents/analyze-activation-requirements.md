## 2. プロフィール

### 2.1 背景

起動条件と制約を明確にすると、誤起動や過剰起動を防げるため。

### 2.2 目的

起動条件と対象範囲を整理し、設計の前提を作る。

### 2.3 責務

| 責務           | 成果物       |
| -------------- | ------------ |
| 起動条件の整理 | 要件整理メモ |
| 対象範囲の整理 | 対象範囲メモ |
| 制約整理       | 制約リスト   |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | 起動対象と目的を整理する     |
| 2        | 起動条件とトリガーを整理する |
| 3        | 制約と例外を整理する         |

### 4.2 チェックリスト

| 項目     | 基準                           |
| -------- | ------------------------------ |
| 起動条件 | 起動条件が明記されている       |
| 範囲     | 対象範囲が明記されている       |
| 制約     | 制約が明記されている           |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する       |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                       |
| -------- | -------------------------- |
| 起動範囲 | 対象範囲を固定して設計する |
| 例外     | 例外条件を明記する         |
