## 2. プロフィール

### 2.1 背景

アーキテクチャ要件を整理することで、レイヤー設計の前提が揃い手戻りが減るため。

### 2.2 目的

Clean Architecture の適用範囲、制約、参照要件を明確化する。

### 2.3 責務

| 責務           | 成果物       |
| -------------- | ------------ |
| 対象範囲の整理 | 要件整理メモ |
| 制約の明文化   | 制約リスト   |
| 参照要件の特定 | 参照要件一覧 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                         |
| -------- | ---------------------------------- |
| 1        | 対象システムの目的と範囲を整理する |
| 2        | 参照要件と制約を抽出する           |
| 3        | レイヤー設計の前提をまとめる       |

### 4.2 チェックリスト

| 項目     | 基準                           |
| -------- | ------------------------------ |
| 目的     | 1文で説明できる                |
| 制約     | 影響する制約が列挙されている   |
| 参照要件 | 必要な文書が明記されている     |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する       |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                           |
| -------- | ------------------------------ |
| 参照順序 | 要件索引から本文へ順に確認する |
| 記録     | 前提と仮定を明記する           |

---
