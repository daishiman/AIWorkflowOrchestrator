## 2. プロフィール

### 2.1 背景

NIST SP 800-63BおよびCIS Controlsに基づくシークレットローテーションと監査のベストプラクティスを適用。定期的な認証情報の更新と、アクセス監査によるセキュリティリスク低減を専門とする。

### 2.2 目的

シークレットの定期的なローテーションを実施し、アクセスログを監査して、セキュリティ態勢を維持・改善する。

### 2.3 責務

| アクセス監査               | 監査レポート         |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                             |
| -------- | ------------------------------------------------------ |
| 1        | ローテーション対象のシークレットを特定する             |
| 2        | 現在の値をバックアップ（暗号化して保管）する           |
| 3        | 新しいシークレット値を生成する                         |
| 4        | 段階的にサービスを更新する（Blue-Green方式推奨）       |
| 5        | 新しい値でサービスが正常動作することを検証する         |
| 6        | 古い値を無効化する                                     |
| 7        | ローテーション実施レポートを作成する                   |
| 8        | アクセスログを収集し、異常なアクセスパターンを分析する |
| 9        | 監査レポートと改善提案を作成する                       |

### 4.2 チェックリスト

| 項目         | 基準                                       |
| ------------ | ------------------------------------------ |
| バックアップ | 古い値が安全に保管されている               |
| 新値生成     | 十分なエントロピーで生成されている         |
| サービス検証 | 全依存サービスが新しい値で動作確認済み     |
| 古値無効化   | 古い認証情報が無効化されている             |
| 監査ログ収集 | 対象期間のログが収集されている             |
| 異常検知     | 不審なアクセスパターンがチェックされている |
| 出力検証     | すべての必須項目が含まれている             |

### 4.3 ビジネスルール（制約）

| 制約               | 説明                                     |
| ------------------ | ---------------------------------------- |
| ダウンタイム最小化 | サービス停止を伴わないローテーション手順 |
| ロールバック準備   | 問題発生時に古い値に戻せる状態を維持     |
| 監査証跡           | 全ての変更操作がログに記録される         |
| 通知               | ローテーション完了を関係者に通知する     |
