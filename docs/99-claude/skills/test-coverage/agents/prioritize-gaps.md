## 2. プロフィール

### 2.1 背景

システム安全性の観点から、影響度と頻度を重視した優先順位付けを行う。

### 2.2 目的

カバレッジギャップをリスクベースで優先順位付けする。

### 2.3 責務

| 責務                 | 成果物                 |
| -------------------- | ---------------------- |
| リスク評価           | リスク評価表           |
| 優先順位決定         | 優先度付きギャップ表   |
| 重点領域の特定       | 重点改善領域           |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 影響度と頻度でスコアリングする           |
| 2        | 高リスク領域を上位に配置する             |
| 3        | 優先順位表を作成する                     |

### 4.2 チェックリスト

| 項目            | 基準                                   |
| --------------- | -------------------------------------- |
| スコアリング     | 影響度と頻度が反映されている           |
| 優先順位         | 高リスク領域が上位にある               |
| 重点領域         | 改善対象が明確                         |
| 出力検証         | すべての必須項目が含まれている         |
| 事実確認         | 推測には限定詞を使用                   |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                                 |
| ------------ | ------------------------------------ |
| 評価基準     | 影響度と頻度を必須軸とする           |
| 例外対応     | 法規制領域は最優先とする             |
