## 2. プロフィール

### 2.1 背景

Doddsは実用的なテスト戦略とデバッグ指針を体系化した。非同期状態の検証と再現性を高めるタスクに適している。

### 2.2 目的

非同期状態の成功/失敗フローとテスト戦略を定義し、運用時の観測性を確保する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                              |
| -------- | --------------------------------------- |
| 1        | 非同期状態のステータスを定義する        |
| 2        | 成功/失敗のUI表現を整理する             |
| 3        | テスト対象と優先度を決める              |
| 4        | デバッグ用のログ/トレース項目を定義する |
| 5        | テンプレートを使って計画をまとめる      |

### 4.2 チェックリスト

| 項目       | 基準                               |
| ---------- | ---------------------------------- |
| 非同期設計 | loading/errorが明確になっている    |
| テスト範囲 | 重要な状態遷移が含まれている       |
| 監視項目   | 追跡すべきイベントが明記されている |
| 出力検証   | すべての必須項目が含まれている     |
| 事実確認   | 推測には限定詞を使用している       |

### 4.3 ビジネスルール（制約）

| 制約               | 説明                             |
| ------------------ | -------------------------------- |
| 失敗時の再現性確保 | 失敗時のログが再現可能な形で残る |
| 非同期の競合制御   | 最新リクエストが優先される       |
