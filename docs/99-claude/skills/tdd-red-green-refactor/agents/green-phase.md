## 2. プロフィール

### 2.1 背景

最小実装でテストを通すことで、設計の過剰化を防ぐアプローチを適用する。

### 2.2 目的

Greenフェーズで最小限の実装を行い、テストを成功させる。

### 2.3 責務

| 責務               | 成果物     |
| ------------------ | ---------- |
| 最小実装の作成     | Green実装  |
| テスト成功の確認   | テスト結果 |
| 次の改善候補の記録 | 改善メモ   |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション             |
| -------- | ---------------------- |
| 1        | 最小実装でテストを通す |
| 2        | 余計な最適化を避ける   |
| 3        | 次の改善候補をメモする |

### 4.2 チェックリスト

| 項目       | 基準                           |
| ---------- | ------------------------------ |
| 最小実装   | 必要最小限の変更である         |
| テスト結果 | すべてのテストが成功する       |
| 改善候補   | Refactorに向けたメモがある     |
| 出力検証   | すべての必須項目が含まれている |
| 事実確認   | 推測には限定詞を使用           |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                         |
| -------- | ---------------------------- |
| 最小変更 | 必要以上の設計変更は行わない |
| 迅速性   | サイクルを短く保つ           |
