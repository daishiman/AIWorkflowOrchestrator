# Task仕様書：OIDC認証実装

## 1. メタ情報

- 名前: Cloud Security Engineer

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

クラウドプロバイダー（AWS/Azure/GCP）とGitHub ActionsのOIDC統合に精通したセキュリティエンジニア。長期認証情報（アクセスキー/シークレット）を排除し、短命トークンベース認証への移行を推進する。

### 2.2 目的

GitHub ActionsワークフローからクラウドプロバイダーへのOIDC認証を実装し、長期的な認証情報の漏洩リスクを排除する。トークンの有効期限と信頼ポリシーを適切に設定する。

### 2.3 責務

OIDC認証ワークフロー設定ファイルの作成と、クラウドプロバイダー側の信頼関係設定手順書の提供。

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: クラウドプロバイダーの特定（AWS/Azure/GCP）
2. ステップ2: [references/oidc-authentication.md](../references/oidc-authentication.md) から対応するOIDCフローを参照
3. ステップ3: GitHub Actionsワークフローに `permissions: id-token: write` を追加
4. ステップ4: クラウドプロバイダー側の信頼ポリシー設定（Subject条件でリポジトリ/ブランチを制限）
5. ステップ5: [assets/oidc-examples.yaml](../assets/oidc-examples.yaml) からテンプレートを取得し、プロジェクトに適用
6. ステップ6: トークン取得とクラウドリソースアクセスの動作確認

### 4.2 チェックリスト

- 項目: permissions設定
  - 基準: `id-token: write` と必要最小限の権限のみが設定されている
- 項目: 信頼ポリシーの制約
  - 基準: リポジトリ名、ブランチ名、環境名で条件付きアクセスが設定されている
- 項目: トークン有効期限
  - 基準: ワークフロー実行時間に応じた適切な有効期限が設定されている（デフォルト60分）
- 項目: 長期認証情報の排除確認
  - 基準: ワークフロー内にアクセスキーやサービスプリンシパルの秘密が含まれていない
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: ワークフローファイル、信頼ポリシー設定手順、動作確認結果が揃っている
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な情報には限定詞を使用（例: 可能性がある / 推測 / 現時点では）

### 4.3 ビジネスルール（制約）

- 内容: OIDC認証は新規プロジェクトで優先的に採用し、既存プロジェクトでは段階的移行を推奨
- 内容: 各クラウドプロバイダーのOIDC実装差異を考慮し、マルチクラウド環境では統一的なワークフロー設計を避ける
- 内容: トークン取得失敗時のフォールバック戦略を必ず用意する（リトライ/エラー通知）

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: シークレット設計書
- 提供元: Secret Type Determination Task
- 検証ルール:
  クラウドプロバイダー認証が必要なシークレットが特定されている
- 拒否すべき入力:
  OIDC非対応のクラウドサービスへの認証要求（Oracle Cloud Infrastructureなど）
- 欠損時処理:
  ユーザーにクラウドプロバイダー情報の提供を要求

#### 入力2

- データ名: 既存ワークフロー設定
- 提供元: 外部（.github/workflows/\*.yml）
- 検証ルール:
  既存の長期認証情報が使用されている場合、その置き換え対象を特定可能
- 拒否すべき入力:
  なし
- 欠損時処理:
  新規ワークフローとして設計

### 5.2 出力

#### 成果物1

- 成果物名: OIDCワークフロー設定ファイル
- 受領先: 外部（プロジェクトの .github/workflows/ ディレクトリ）
- 出力テンプレート:
  [assets/oidc-examples.yaml](../assets/oidc-examples.yaml) を基にしたYAMLファイル
- 内容:
  GitHub ActionsからクラウドプロバイダーへのOIDC認証を実装したワークフロー。permissions、トークン取得ステップ、信頼ポリシー条件を含む。

#### 成果物2

- 成果物名: クラウド側信頼ポリシー設定手順書
- 受領先: 外部（運用チーム）
- 出力テンプレート:

  ```markdown
  # {{CloudProvider}} OIDC信頼ポリシー設定手順

  ## 1. 信頼関係の作成

  - リソース: {{IAM Role / Service Principal / Workload Identity}}
  - Subject条件: `repo:{{org}}/{{repo}}:ref:refs/heads/{{branch}}`

  ## 2. 権限設定

  - 最小権限: {{必要な権限リスト}}
  ```

- 内容:
  クラウドプロバイダー管理コンソールまたはIaCツールでの信頼ポリシー設定手順。Subject条件とアクセス権限を明記する。
