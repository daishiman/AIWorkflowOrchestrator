# 18.3.7 エージェント起動フローの記述形式

**出典**: `docs/00-requirements/18-commands.md` の 18.3.7

## フェーズテンプレート（各フェーズ共通）

```markdown
### Phase {{phase_number}}: {{phase_name}}

#### 目的

{{phase_purpose}}

#### 背景

{{phase_background}}

#### ゴール

{{phase_goal}}

#### 起動エージェント

- `.claude/agents/{{agent_name}}.md`

#### Taskツール起動

Task ツールで `.claude/agents/{{agent_name}}.md` を起動

#### コンテキスト

- {{context_item_1}}
  ...
- {{context_item_N}}

#### 完了条件

- [ ] {{completion_condition_1}}
      ...
- [ ] {{completion_condition_N}}
```

## テンプレート変数の説明

| 変数                         | 説明                                         |
| ---------------------------- | -------------------------------------------- |
| `{{phase_number}}`           | フェーズ番号（1, 2, 3, ...）                 |
| `{{phase_name}}`             | フェーズ名（例: 要件分析、設計、実装、検証） |
| `{{phase_purpose}}`          | このフェーズで何を達成するか                 |
| `{{phase_background}}`       | なぜこのフェーズが必要か                     |
| `{{phase_goal}}`             | このフェーズの具体的なゴール                 |
| `{{agent_name}}`             | 起動するエージェント名（ケバブケース）       |
| `{{context_item_N}}`         | エージェントに渡すコンテキスト情報           |
| `{{completion_condition_N}}` | フェーズ完了の判定条件                       |

## エージェント起動の記述ルール

| ルール                 | 説明                                          |
| ---------------------- | --------------------------------------------- |
| 相対パス必須           | `.claude/agents/{{agent_name}}.md` 形式で記述 |
| 1フェーズ1エージェント | 各フェーズで起動するエージェントは1つ         |
| 目的/背景/ゴール明示   | 各フェーズの目的・理由・達成状態を明記        |
| コンテキスト明示       | 前フェーズからの引き継ぎ情報を明記            |
| 完了条件明示           | 次フェーズに進む条件を明確化                  |

## 目的の記述ガイドライン

| ガイドライン       | 説明                                 |
| ------------------ | ------------------------------------ |
| 1文で簡潔に        | 「〜を達成する」「〜を決定する」形式 |
| 動詞で開始         | 「分析する」「設計する」「生成する」 |
| 具体的な対象を明記 | 何を対象にするかを明確に             |

### 例

- ✅ 良い例: 「ユーザー要件を分析し、エージェント設計方針を決定する」
- ✅ 良い例: 「エージェントファイルを生成し、検証する」
- ❌ 悪い例: 「準備をする」（抽象的すぎる）

## 背景の記述ガイドライン

| ガイドライン       | 説明                                   |
| ------------------ | -------------------------------------- |
| 理由を説明         | なぜこのフェーズが必要かを明確に       |
| リスクを明記       | このフェーズを飛ばした場合の問題を記述 |
| 前フェーズとの関係 | 前フェーズの成果を受けてこのフェーズへ |

### 例

- ✅ 良い例: 「曖昧な要件のままエージェント作成を開始すると、単一責任原則が守られず手戻りが発生します」
- ❌ 悪い例: 「必要だから」（理由が不明確）

## ゴールの記述ガイドライン

| ガイドライン   | 説明                                   |
| -------------- | -------------------------------------- |
| 完了状態を明記 | 「〜された状態」「〜が定義された状態」 |
| 検証可能       | 完了を確認できる状態を記述             |
| 具体的な成果物 | 何が生成/決定されるかを明記            |

### 例

- ✅ 良い例: 「エージェントの目的・専門分野が明確化され、設計方針が決定された状態」
- ✅ 良い例: 「エージェントファイルが生成され、検証が完了した状態」
- ❌ 悪い例: 「だいたい完了」（曖昧）

## コンテキストの記述ガイドライン

| ガイドライン         | 説明                               |
| -------------------- | ---------------------------------- |
| 前フェーズからの情報 | 前Phaseで決定/生成された情報を列挙 |
| 具体的に             | 抽象的な表現を避ける               |
| 3-7個が目安          | 少なすぎず多すぎない適切な粒度     |

### 例

- ✅ 良い例: 「ユーザーが指定したエージェント名」
- ✅ 良い例: 「Phase 1で決定した設計方針（専門家モデル or 役割ベース）」
- ✅ 良い例: 「特定されたモデル人物と参考文献リスト」
- ❌ 悪い例: 「色々な情報」（抽象的）

## 完了条件の記述ガイドライン

| ガイドライン       | 説明                           |
| ------------------ | ------------------------------ |
| チェックリスト形式 | `- [ ]` 形式で記述             |
| 検証可能           | 自動または手動で確認できる条件 |
| 3-7個が目安        | 少なすぎず多すぎない適切な粒度 |
| 具体的             | 抽象的な表現を避ける           |

### 例

- ✅ 良い例: `- [ ] エージェントの目的が明確`
- ✅ 良い例: `- [ ] YAML Frontmatter が完全に設計されている（name, description, tools, model）`
- ✅ 良い例: `- [ ] 行数が450-550行範囲内`
- ❌ 悪い例: `- [ ] ちゃんと完了している`（検証不可能）

## 完全な例: Phase 1

```markdown
### Phase 1: 要件理解と分析

#### 目的

ユーザー要件を分析し、エージェント設計方針を決定する

#### 背景

曖昧な要件のままエージェント作成を開始すると、単一責任原則が守られず手戻りが発生します。要件を明確化し、既存エージェントとの重複を避けることが重要です。

#### ゴール

エージェントの目的・専門分野・モデル人物が明確化され、設計方針が決定された状態

#### 起動エージェント

- `.claude/agents/meta-agent-designer.md`

#### Taskツール起動

Task ツールで `.claude/agents/meta-agent-designer.md` を起動

#### コンテキスト

- ユーザーが指定したエージェント名（引数から取得）
- エージェントの目的と専門分野（ユーザーから収集）
- 既存エージェント一覧（.claude/agents/\*.md）
- 既存エージェントとの重複チェック結果

#### 完了条件

- [ ] エージェントの目的が明確
- [ ] 設計方針が決定（専門家モデル or 役割ベース）
- [ ] モデル人物の候補が特定されている（専門家モデルの場合）
- [ ] 既存エージェントとの重複がない
- [ ] Phase 2で必要な情報がすべて揃っている
```

## Phase数の推奨

| Phase数 | 推奨度 | 用途                           |
| ------- | ------ | ------------------------------ |
| 2-4個   | 推奨   | 標準的なコマンド               |
| 4-6個   | 許容   | 複雑なコマンド                 |
| 1個     | 非推奨 | Phase分解が不十分              |
| 7個以上 | 非推奨 | 分解しすぎ、コマンド分割を検討 |

## 検証チェックリスト

- [ ] すべてのPhaseに「目的」「背景」「ゴール」「起動エージェント」「Taskツール起動」「コンテキスト」「完了条件」が含まれている
- [ ] 各Phaseの目的が1文で簡潔に記述されている
- [ ] 各Phaseの背景が「なぜ必要か」を説明している
- [ ] 各Phaseのゴールが検証可能な完了状態を示している
- [ ] 起動エージェントが相対パス形式で記述されている
- [ ] コンテキストが具体的に記述されている
- [ ] 完了条件がチェックリスト形式で記述されている
- [ ] 完了条件が検証可能である
- [ ] Phase数が2-6個の範囲内である
