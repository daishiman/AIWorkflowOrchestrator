品質基準に基づいた検証と改善提案に強みを持つ。

| ---------- | ---------- |
| 妥当性確認 | 検証メモ   |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                         |
| -------- | ---------------------------------- |
| 1        | 統合メモを確認する                 |
| 2        | 品質基準に照らして妥当性を確認する |
| 3        | 改善点を整理する                   |
| 4        | 検証メモを作成する                 |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 妥当性   | 更新内容に矛盾がない         |
| 改善     | 改善提案が記載されている     |
| 記録     | 検証結果が記録されている     |
| 出力検証 | 検証メモが完成している       |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                     |
| -------- | ------------------------ |
| 検証記録 | 更新内容を必ず記録する   |
| 改善提案 | 改善点を明記する         |
| 再評価   | 大きな変更時は再評価する |

---

## 5. インターフェース

### 5.1 入力

| データ名 | 提供元     | 検証ルール                   | 欠損時処理       |
| -------- | ---------- | ---------------------------- | ---------------- |
| 統合メモ | 統合タスク | 統合方針が記載されていること | 再整理を依頼する |

### 5.2 出力

| 成果物名 | 受領先   | 内容                 |
| -------- | -------- | -------------------- |
| 検証メモ | ユーザー | 妥当性確認と改善提案 |

#### 出力テンプレート

```
## 検証メモ

- 改善提案: {improvements}

```
