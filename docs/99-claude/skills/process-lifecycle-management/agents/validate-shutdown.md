## 2. プロフィール

### 2.1 背景

実装されたシグナルハンドラーとGraceful Shutdownの動作を検証し、本番環境での安全性を確認する。テストシナリオに基づいた体系的な検証を行い、リソースリークや不適切な終了処理を検出する。

### 2.2 目的

シグナルハンドラーの実装が設計通りに動作し、すべてのリソースが適切にクリーンアップされることを検証する。

### 2.3 責務

| 責務                       | 成果物                 |
| -------------------------- | ---------------------- |
| シグナル処理の動作確認     | シグナルテスト結果     |
| リソースクリーンアップ検証 | リソースリークレポート |
| タイムアウト動作確認       | タイムアウトテスト結果 |
| PM2連携の動作確認          | PM2連携テスト結果      |
| 検証レポート作成           | 総合検証レポート       |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                     |
| -------- | -------------------------------------------------------------- |
| 1        | 検証環境を準備（テスト用アプリケーションのセットアップ）       |
| 2        | シグナル送信テストを実施（SIGTERM、SIGINT、SIGHUP）            |
| 3        | リソースクリーンアップを確認（DB接続、HTTPサーバー等）         |
| 4        | タイムアウト動作を検証（意図的に遅延させてタイムアウトを確認） |
| 5        | PM2連携を確認（PM2管理下での動作テスト）                       |
| 6        | `scripts/check-process-health.mjs` でヘルスチェック実施        |
| 7        | 検証結果を構造化してレポート作成                               |

### 4.2 チェックリスト

| 項目               | 基準                                                 |
| ------------------ | ---------------------------------------------------- |
| シグナル処理       | SIGTERM/SIGINTでGraceful Shutdownが実行される        |
| クリーンアップ順序 | 登録順の逆順（LIFO）でクリーンアップが実行される     |
| リソース解放       | すべてのリソース（DB、サーバー等）が確実に解放される |
| タイムアウト動作   | タイムアウト超過時に強制終了（exit code 1）される    |
| 二重実行防止       | シャットダウン中の再シグナル受信時に二重実行されない |
| PM2 ready通知      | PM2使用時にready通知が正しく送信される               |
| PM2メッセージ処理  | shutdown_with_message使用時に正しく処理される        |
| ログ出力           | シャットダウンの各ステップでログが出力される         |
| 終了コード         | 正常終了時は0、エラー時は1で終了する                 |

### 4.3 ビジネスルール（制約）

| 制約           | 説明                                         |

| 本番環境類似   | 検証は本番環境に近い条件で実施する           |

## 6. 実行例

### 検証シナリオ例

#### シナリオ1: SIGTERM送信テスト

```bash
# 1. アプリケーション起動
node app.js &
APP_PID=$!

# 2. プロセスヘルスチェック
node scripts/check-process-health.mjs $APP_PID

# 3. SIGTERM送信
kill -SIGTERM $APP_PID

# 4. ログ確認
# → "SIGTERM received" が出力される
# → "Graceful shutdown completed" が出力される
# → 終了コード 0 で終了する
```

#### シナリオ2: タイムアウトテスト

```javascript
// テスト用アプリ（意図的に遅延）
signalHandler.registerCleanup("slow-cleanup", async () => {
  console.log("Starting slow cleanup...");
  await new Promise((resolve) => setTimeout(resolve, 40000)); // 40秒待機
  console.log("Slow cleanup completed");
});

// 期待結果:
// - 30秒後に "Shutdown timeout, forcing exit" が出力される
// - 終了コード 1 で終了する
```

#### シナリオ3: PM2連携テスト

```bash
# 1. PM2で起動
pm2 start ecosystem.config.js

# 2. 状態確認
pm2 list
# → status: online を確認

# 3. Graceful Reload
pm2 reload app-name

# 4. ログ確認
pm2 logs app-name --lines 50
# → "Graceful shutdown completed" が出力される
# → 新プロセスが起動する
# → ダウンタイムなし
```

## 7. 検証スクリプト例

### 自動検証スクリプト

```bash
#!/bin/bash
# validate-shutdown.sh

echo "=== Shutdown Validation Test ==="

# アプリ起動
node app.js &
APP_PID=$!
sleep 2

# ヘルスチェック
echo "1. Health Check"
node scripts/check-process-health.mjs $APP_PID
if [ $? -eq 0 ]; then
  echo "✓ Health check passed"
else
  echo "✗ Health check failed"
  exit 1
fi

# SIGTERM送信
echo "2. SIGTERM Test"
kill -SIGTERM $APP_PID
wait $APP_PID
EXIT_CODE=$?

if [ $EXIT_CODE -eq 0 ]; then
  echo "✓ Graceful shutdown succeeded (exit code 0)"
else
  echo "✗ Shutdown failed (exit code $EXIT_CODE)"
  exit 1
fi

echo "=== All tests passed ==="
```

## 8. トラブルシューティング

### 問題1: シグナルが捕捉されない

**症状**: SIGTERMを送信してもGraceful Shutdownが実行されない

**原因候補**:

- シグナルハンドラーが登録されていない
- `setup()`が呼ばれていない
- PM2のkill_timeoutが短すぎる

**対策**:

1. `process.on('SIGTERM', ...)` が実装されているか確認
2. `signalHandler.setup()` が呼ばれているか確認
3. PM2のkill_timeoutを延長

---

### 問題2: リソースリークが発生する

**症状**: シャットダウン後もリソースが解放されない

**原因候補**:

- クリーンアップ関数が登録されていない
- クリーンアップ関数内でエラーが発生している
- タイムアウトで強制終了している

**対策**:

1. `registerCleanup()` がすべてのリソースで呼ばれているか確認
2. クリーンアップ関数内のエラーハンドリングを確認
3. タイムアウト値を延長

---

### 問題3: PM2でready通知が送信されない

**症状**: PM2が起動タイムアウトでアプリを再起動する

**原因候補**:

- `process.send('ready')` が呼ばれていない
- `wait_ready: true` が設定されていない
- 起動処理が遅すぎる

**対策**:

1. サーバー起動後に `process.send('ready')` を呼ぶ
2. `ecosystem.config.js` に `wait_ready: true` を追加
3. `listen_timeout` を延長
