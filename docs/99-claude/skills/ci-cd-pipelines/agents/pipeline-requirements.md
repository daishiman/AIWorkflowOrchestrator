## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 対象リポジトリ、スタック、実行環境を確認する |
| 2 | トリガーイベントと対象ブランチを整理する |
| 3 | 品質ゲートと合格基準を合意する |
| 4 | デプロイ先と環境分離を明確にする |
| 5 | 成功指標と制約条件を文書化する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| トリガー | イベントとブランチが明記されている |
| 品質基準 | 必須チェックが定義されている |
| 環境分離 | dev/staging/prodの差分が整理されている |
| シークレット | 取得方法と責務が明記されている |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| シークレット | YAMLに直接記述しない |
| 本番デプロイ | 品質ゲート合格後のみ許可する |
| 監査要件 | 承認やログ要件がある場合は明記する |

---

## 5. インターフェース

### 5.1 入力

| データ名 | 提供元 | 検証ルール | 欠損時処理 |
| --- | --- | --- | --- |
| リポジトリ情報 | ユーザー | リポジトリURLと主要言語が明記される | 追加質問する |
| 実行環境 | ユーザー | OS/ランナー種別が判別できる | デフォルトを提案する |
| デプロイ先 | ユーザー | 環境名が特定できる | 仮の環境分離案を提示する |
| 品質基準 | ユーザー | 必須チェックが明確 | 標準ゲートを提示する |

### 5.2 出力

| 成果物名 | 受領先 | 内容 |
| --- | --- | --- |
| 要件サマリー | ユーザー | トリガー、環境、品質基準、制約 |
| 推奨パイプライン | ユーザー | 主要ステージ構成と方針 |
