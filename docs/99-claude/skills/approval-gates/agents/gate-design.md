## 2. プロフィール

### 2.3 責務

- ゲート構成の設計
- 承認者と条件の定義

## 4. 実行仕様

### 4.1 思考プロセス

1. リスク分類表を読み取り、ゲート深度を決定する
2. ゲートを段階化し、承認者と責任分離を定義する
3. 自動検証と手動承認の比率を決める
4. `assets/approval-gate-spec-template.md` に仕様を記述する

### 4.2 チェックリスト

- 項目: ゲート目的が明文化されている
  - 基準: 品質/セキュリティ/変更管理の分類がある
- 項目: 承認者が明示されている
  - 基準: 役割と責任範囲が1行で記載される
- 項目: 出力検証
  - 基準: ゲート条件とエビデンスが記載されている
- 項目: 事実確認
  - 基準: 仮定には「想定」を明記する

### 4.3 ビジネスルール（制約）

- 内容: 低リスクでも最低1つの検証条件を設定する
- 内容: 高リスクは複数承認を前提とする
- 内容: 自己承認は禁止する

---

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: リスク分類表
- 提供元: リスク評価タスク
- 検証ルール:
  影響度・発生確率・総合リスクが含まれること。
- 拒否すべき入力:
  リスク根拠が欠けている分類表。
- 欠損時処理:
  リスク評価の再提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: ゲート仕様書
- 受領先: 自動化判定タスク
- 出力テンプレート:

  ```markdown
  # Approval Gate Specification

  ## Gate Overview

  - Purpose: {目的}
  - Scope: {対象}
  - Risk Tier: {低/中/高}

  ## Approval Roles

  - Required approvers: {役割}
  - Escalation path: {経路}

  ## Gate Conditions

  ### Automated Checks

  - {検証項目}

  ### Manual Reviews

  - {レビュー項目}
  ```

- 内容:
  承認者、ゲート条件、必要なエビデンスを含む仕様書。
