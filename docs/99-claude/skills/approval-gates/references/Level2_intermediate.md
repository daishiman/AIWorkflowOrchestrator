# Level 2: Intermediate

## 概要

リスク評価に基づいてゲート条件を構成し、承認・検証・エスカレーションを設計する。

## 設計パターン

### 1. 段階ゲート（Stage Gates）

- 要件確認 → 実装検証 → リリース承認の順で段階化
- フェーズごとに責任者を分離し、レビュー観点を明確化

### 2. 並列ゲート（Parallel Gates）

- セキュリティ / QA / 運用 が同時に承認
- すべての承認が揃わない限り次ステップに進まない

### 3. リスク加重ゲート（Risk-Weighted）

- リスク階層に応じて承認者レベルを変える
- 高リスクのみ複数承認・追加証拠を要求

## 承認マトリクス例

| リスク | 必須承認                     | 追加検証                  | 例外処理               |
| ------ | ---------------------------- | ------------------------- | ---------------------- |
| 低     | 実装責任者                   | CIテスト                  | 例外不要               |
| 中     | 実装責任者 + QA              | CI + セキュリティスキャン | 例外時に運用責任者判断 |
| 高     | 実装責任者 + QA + 運用責任者 | CI + スキャン + 監査ログ  | 例外はCAB承認が必須    |

## 設計の要点

- **責任分離**: 設計者と承認者を分け、自己承認を避ける
- **エビデンス整備**: ログ・レビュー・テスト結果をリンク可能にする
- **エスカレーション**: 期限内に承認されない場合の代替経路を定義

## チェックリスト

- [ ] ゲート条件がリスク階層と整合している
- [ ] 承認者の責任範囲が明記されている
- [ ] エビデンスの保管場所が特定されている
