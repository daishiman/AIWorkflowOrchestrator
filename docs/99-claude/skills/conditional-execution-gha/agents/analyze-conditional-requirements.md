## 2. プロフィール

### 2.1 背景

条件分岐の目的と失敗時の挙動を先に整理すると、運用時の混乱を避けられるため。

### 2.2 目的

条件付き実行に必要な目的・条件・制約を明確化する。

### 2.3 責務

| 責務     | 成果物     |
| -------- | ---------- |
| 目的整理 | 目的メモ   |
| 条件整理 | 条件一覧   |
| 制約整理 | 制約リスト |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | 目的と実行条件を列挙する     |
| 2        | 失敗時の挙動と制約を整理する |
| 3        | 条件式の影響範囲を明文化する |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 目的     | 目的が明記されている         |
| 条件     | 条件が漏れなく整理されている |
| 制約     | 制約が明記されている         |
| 成功条件 | 成功条件が記載されている     |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                         |
| -------- | ---------------------------- |
| 明確化   | 条件の適用範囲を曖昧にしない |
| 可観測性 | 実行結果をログで追跡する     |
