# ステークホルダー合意形成ガイド

## 概要

要件トリアージにおいて、ステークホルダー間の合意を形成するための手法を解説する。
優先順位付けの結果を関係者に説明し、合意を得るプロセスを体系化する。

## ステークホルダー分析

### ステークホルダーの特定

| ステークホルダー種別 | 役割                   | 関心事               |
| -------------------- | ---------------------- | -------------------- |
| プロダクトオーナー   | ビジネス価値の判断     | ROI、市場競争力      |
| 開発リード           | 技術的実現可能性の判断 | 技術的リスク、工数   |
| ユーザー代表         | ユーザー価値の代弁     | 使いやすさ、機能性   |
| 経営層               | 予算・リソースの承認   | コスト、戦略整合性   |
| 運用担当             | 保守性・運用性の評価   | 安定性、サポート負荷 |

### 影響度マトリクス

```
高
 │  Keep Satisfied │ Manage Closely
 │  (情報提供)      │ (密に連携)
影├─────────────────┼─────────────────
響│  Monitor        │ Keep Informed
力│  (最小限の対応) │ (定期報告)
低
 └─────────────────┴─────────────────→
   低              関心度              高
```

## 合意形成プロセス

### Phase 1: 準備

| ステップ | アクション                             |
| -------- | -------------------------------------- |
| 1        | ステークホルダーを特定・分類する       |
| 2        | 各ステークホルダーの関心事を整理する   |
| 3        | 説明資料を準備する（評価マトリクス等） |
| 4        | 合意形成の場を設定する                 |

### Phase 2: 説明

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | 評価プロセスと基準を説明する |
| 2        | 各要件の評価結果を共有する   |
| 3        | MoSCoW分類の根拠を説明する   |
| 4        | 質問に対応する               |

### Phase 3: 調整

| ステップ | アクション                 |
| -------- | -------------------------- |
| 1        | フィードバックを収集する   |
| 2        | 異なる意見の調整を行う     |
| 3        | 必要に応じて評価を修正する |
| 4        | 変更の理由を記録する       |

### Phase 4: 確定

| ステップ | アクション                 |
| -------- | -------------------------- |
| 1        | 最終的な優先順位を確認する |
| 2        | 合意を文書化する           |
| 3        | 次のアクションを明確にする |
| 4        | フォローアップ計画を立てる |

## 意見の相違への対処

### 対立パターンと対処法

| パターン             | 対処法                               |
| -------------------- | ------------------------------------ |
| ビジネス vs 技術     | データに基づく議論、トレードオフ明示 |
| 短期 vs 長期         | ロードマップで両立案を提示           |
| 機能追加 vs 品質改善 | ユーザー影響度で比較                 |
| 個別最適 vs 全体最適 | プロジェクト目標への貢献度で判断     |

### エスカレーション基準

| 状況                     | 対応                       |
| ------------------------ | -------------------------- |
| 担当者間で合意できない   | リーダーレベルに相談       |
| リーダー間で合意できない | 経営層に判断を仰ぐ         |
| 期限内に合意できない     | 暫定決定で進め、後日再評価 |

## コミュニケーション手法

### 効果的な説明のポイント

- データと根拠に基づいて説明する
- 視覚的な資料（マトリクス、グラフ）を活用する
- 相手の関心事に合わせて説明を調整する
- 決定の影響を具体的に示す

### 避けるべき行動

| 行動             | 問題点             |
| ---------------- | ------------------ |
| 一方的な通達     | 反発を招く         |
| 感情的な議論     | 合理的判断を妨げる |
| 根拠なしの主張   | 信頼性を損なう     |
| 変更履歴の未記録 | 後から追跡できない |
