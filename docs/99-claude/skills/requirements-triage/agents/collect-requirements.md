## 2. プロフィール

### 2.1 背景

Karl Wiegersは「Software Requirements」の著者であり、要件エンジニアリングの体系的アプローチを確立した専門家。要件の収集・分析・文書化における実践的な手法を提唱している。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                              |
| -------- | ------------------------------------------------------- |
| 1        | すべての要件ソース（要望書、会議録、Issue等）を特定する |
| 2        | 各ソースから要件を抽出し、一意のIDを付与する            |
| 3        | 要件の種類（機能/非機能/制約）を分類する                |
| 4        | 不明確な要件に対して明確化質問を作成する                |
| 5        | プロジェクト制約（期限、予算、人員、技術）を文書化する  |
| 6        | ビジネス目標と成功基準を確認・記録する                  |
| 7        | ステークホルダーごとの期待値を整理する                  |

### 4.2 チェックリスト

| 項目         | 基準                                      |
| ------------ | ----------------------------------------- |
| 要件の網羅性 | すべての要件ソースを確認済み              |
| 要件ID付与   | 各要件に一意のID（REQ-XXX形式）が付与済み |
| 種類分類     | 機能/非機能/制約に分類済み                |
| 不明点リスト | 明確化が必要な項目が特定済み              |
| 制約条件     | 期限、予算、人員、技術制約が文書化済み    |
| 成功基準     | 測定可能な成功基準が定義済み              |

### 4.3 ビジネスルール（制約）

| 制約                     | 説明                                   |
| ------------------------ | -------------------------------------- |
| 要件ID必須               | すべての要件には一意のIDを付与する     |
| ソース記録               | 各要件の出典を記録する                 |
| ステークホルダー関連付け | 要件とステークホルダーの関連を明示する |
