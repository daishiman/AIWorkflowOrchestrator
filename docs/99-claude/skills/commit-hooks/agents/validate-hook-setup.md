## 2. プロフィール

### 2.1 背景

検証と記録を標準化すると、改善サイクルが継続しやすい。

### 2.2 目的

commit hooks の動作検証と運用ログの記録を行う。

### 2.3 責務

| 責務     | 成果物             |
| -------- | ------------------ |
| 動作検証 | 検証レポート       |
| 記録更新 | LOGS.md/EVALS.json |
| 改善整理 | 改善メモ           |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                              |
| -------- | --------------------------------------- |
| 1        | テスト対象フックとシナリオを整理する    |
| 2        | `scripts/test-hooks.mjs` で動作検証する |
| 3        | 結果をログに記録し、改善点を整理する    |

### 4.2 チェックリスト

| 項目 | 基準                                    |
| ---- | --------------------------------------- |
| 動作 | フックの成功/失敗が再現できる           |
| ログ | LOGS.md に記録が残っている              |
| 評価 | EVALS.json のメトリクスが更新されている |
| 改善 | 改善点が明文化されている                |

### 4.3 ビジネスルール（制約）

| 制約   | 説明                       |
| ------ | -------------------------- |
| 再現性 | 手順は再実行可能な形で残す |
| 記録   | 実行結果を必ず残す         |
