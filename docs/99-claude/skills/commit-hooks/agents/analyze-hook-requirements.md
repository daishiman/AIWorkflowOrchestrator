## 2. プロフィール

### 2.1 背景

フックの目的と影響範囲を整理すると、品質ゲートの設計が安定する。

### 2.2 目的

対象フック、実行条件、品質要件を明確化する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 対象整理 | フック一覧 |
| 目的整理 | 品質要件メモ |
| 前提整理 | 依存ツール・制約一覧 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 対象フックと目的を列挙する |
| 2 | 実行条件と依存ツールを整理する |
| 3 | 品質ゲートの測定観点を列挙する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 対象 | フック種別が漏れなく列挙されている |
| 目的 | フックごとの目的が説明できる |
| 依存 | ツールやスクリプトの前提が整理されている |
| 整合 | 要件索引と整合している |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 明確化 | フック名と目的を一対一で紐付ける |
| 最小化 | 目的に不要な処理を含めない |

---
