## Event Sourcing

### 概念

```
State = f(Events[])
```

| 項目 | 説明                         |
| ---- | ---------------------------- |
| 定義 | 状態変更をイベントとして保存 |
| 利点 | 完全な履歴、監査、再生可能   |
| 欠点 | 複雑性、スナップショット必要 |

### 構成要素

| 要素        | 役割                 |
| ----------- | -------------------- |
| Event Store | イベントの永続化     |
| Aggregate   | イベントの生成と適用 |
| Projection  | 読み取りモデルの構築 |
| Snapshot    | 状態復元の高速化     |

## CQRS

### 概念

```
Command → Write Model → Events → Read Model ← Query
```

| 項目 | 説明                       |
| ---- | -------------------------- |
| 定義 | コマンドとクエリの責務分離 |
| 利点 | 独立スケーリング、最適化   |
| 欠点 | 結果整合性、複雑性         |

### 適用判断

| 条件                               | CQRS適用 |
| ---------------------------------- | -------- |
| 読み書きパターンが大きく異なる     | ○        |
| 読み取りと書き込みを別々にスケール | ○        |
| 複雑なドメインロジック             | ○        |
| シンプルなCRUD                     | ×        |

## Saga パターン

### 種類

| 種類          | 特徴                     | 用途               |
| ------------- | ------------------------ | ------------------ |
| Choreography  | 分散協調、イベントベース | 疎結合             |
| Orchestration | 中央制御、明示的フロー   | 複雑なワークフロー |

### 補償トランザクション

| ステップ | 失敗時の補償   |
| -------- | -------------- |
| 注文作成 | 注文キャンセル |
| 在庫予約 | 在庫解放       |
| 決済処理 | 返金処理       |

## スナップショット戦略

| 戦略       | トリガー     | 用途       |
| ---------- | ------------ | ---------- |
| イベント数 | N件ごと      | 一般的     |
| 時間       | N分/時間ごと | 定期       |
| サイズ     | Nバイト超過  | 大量データ |
