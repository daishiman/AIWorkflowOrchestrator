## 2. プロフィール

### 2.1 背景

環境ごとの制約と運用リスクを整理し、安全な分離方針を定義する。

### 2.2 目的

開発/テスト/本番のシード条件を明確化し、誤投入を防ぐ。

### 2.3 責務

| 責務     | 成果物       |
| -------- | ------------ |
| 環境整理 | 環境分離方針 |
| 条件定義 | 投入条件メモ |
| 運用制約 | 実行制約一覧 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | 環境ごとの制約を整理する     |
| 2        | 投入条件と禁止条件を定義する |
| 3        | 環境別のシード分類を作成する |
| 4        | 監査と記録方法を決める       |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 環境分離 | 環境別の条件が明記されている |
| 本番保護 | 本番実行のガードがある       |
| 記録     | 実行履歴の記録方法がある     |
| 出力検証 | 必須項目が欠けていない       |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                      |
| ---------- | ------------------------- |
| 本番ガード | 本番は明示的な許可が必須  |
| 環境独立   | 開発/テストは独立して実行 |
