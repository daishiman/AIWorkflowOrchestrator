# ファイル監視セキュリティの基本概念

## 概要

ファイル監視システムは、ファイルシステムへのアクセス権を持つため、攻撃者にとって魅力的なターゲットとなる。適切なセキュリティ対策なしに運用すると、機密データの漏洩や改ざんにつながるリスクがある。

## 主な脅威

### 1. パストラバーサル攻撃

監視対象外のファイルやディレクトリにアクセスする攻撃。

```
攻撃例:
  入力: ../../etc/passwd
  意図: 監視対象外のシステムファイルへのアクセス
```

| 攻撃パターン     | 説明                         |
| ---------------- | ---------------------------- |
| `../` シーケンス | 親ディレクトリへの移動       |
| URL エンコード   | `%2e%2e%2f` として偽装       |
| Unicode 正規化   | 異なるエンコーディングで偽装 |
| Null バイト      | パス終端の操作               |

### 2. シンボリックリンク攻撃

シンボリックリンクを利用して監視対象外のファイルにアクセスする攻撃。

```
攻撃例:
  1. 攻撃者が /watched/link → /etc/passwd のリンクを作成
  2. 監視システムがリンクをフォローして機密ファイルを読み取り
```

### 3. 権限昇格攻撃

監視プロセスの権限を悪用して、本来アクセスできないリソースにアクセスする攻撃。

## セキュリティ原則

### 1. 最小権限の原則 (Principle of Least Privilege)

監視プロセスには、必要最小限の権限のみを付与する。

| 権限タイプ   | 推奨設定             |
| ------------ | -------------------- |
| ユーザー     | 専用の非特権ユーザー |
| ファイル権限 | 読み取りのみ         |
| ネットワーク | 必要な通信のみ許可   |

### 2. Defense in Depth（多層防御）

複数の防御層を設け、一層が突破されても他の層で防御する。

```
[入力検証] → [パス正規化] → [権限検証] → [監視実行]
```

### 3. Fail-Safe Defaults（安全なデフォルト）

エラーや不明な状況では、安全側（拒否）に倒す。

```typescript
// Good: 安全なデフォルト
function validatePath(path: string): boolean {
  if (!path || typeof path !== "string") {
    return false; // 拒否
  }
  // 検証ロジック
}
```
