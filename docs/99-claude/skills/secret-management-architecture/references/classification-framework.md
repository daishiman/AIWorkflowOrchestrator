# シークレット分類フレームワーク

> **責務**: シークレットの重要度分類基準と保護レベル定義
> **対象Task**: classify-secrets

---

## 1. 分類レベル

### 1.1 Critical（最重要）

| 項目           | 内容                                           |
| -------------- | ---------------------------------------------- |
| 定義           | 漏洩時に事業継続が困難になるシークレット       |
| 漏洩時影響     | 壊滅的（事業停止、重大な法的責任、信用喪失）   |
| 保護要件       | HSM暗号化、多要素認可、リアルタイム監視        |
| ローテーション | 30日以内（自動必須）                           |
| 例             | マスターキー、ルートCA秘密鍵、本番DB管理者認証 |

### 1.2 High（高）

| 項目           | 内容                                          |
| -------------- | --------------------------------------------- |
| 定義           | 漏洩時に重大な財務・法的影響があるもの        |
| 漏洩時影響     | 重大（財務損失、規制違反、顧客データ漏洩）    |
| 保護要件       | 強固な暗号化、アクセスログ、アラート          |
| ローテーション | 90日以内（自動推奨）                          |
| 例             | 本番DB接続情報、外部API認証キー、決済認証情報 |

### 1.3 Medium（中）

| 項目           | 内容                            |
| -------------- | ------------------------------- |
| 定義           | 漏洩時に限定的な影響があるもの  |
| 漏洩時影響     | 中程度（一時的なサービス影響）  |
| 保護要件       | 標準暗号化、定期監査            |
| ローテーション | 180日以内（自動任意）           |
| 例             | ステージング環境認証、内部API鍵 |

### 1.4 Low（低）

| 項目           | 内容                       |
| -------------- | -------------------------- |
| 定義           | 漏洩時の影響が軽微なもの   |
| 漏洩時影響     | 軽微（運用上の不便）       |
| 保護要件       | 基本的な保護               |
| ローテーション | 365日以内（手動可）        |
| 例             | 開発環境設定、テストデータ |

## 2. 分類判定フロー

```
シークレット特定
      ↓
漏洩時の影響評価
      ↓
  ┌───────────────────────────────────────┐
  │ 事業継続に影響？ → Yes → Critical     │
  │         ↓ No                          │
  │ 財務/法的責任？ → Yes → High          │
  │         ↓ No                          │
  │ サービス影響？ → Yes → Medium         │
  │         ↓ No                          │
  │ Low                                   │
  └───────────────────────────────────────┘
      ↓
保護要件の決定
```

## 3. 分類基準詳細

### 3.1 評価観点

| 観点       | 評価項目                         |
| ---------- | -------------------------------- |
| 機密性影響 | データ漏洩時の被害範囲           |
| 完全性影響 | データ改ざん時の被害範囲         |
| 可用性影響 | サービス停止時の被害範囲         |
| 規制要件   | PCI DSS、GDPR、SOC 2等の適用可否 |
| 復旧難易度 | 漏洩後の回復にかかる時間とコスト |

### 3.2 シークレット種別

| 種別       | 説明                         | 典型的分類    |
| ---------- | ---------------------------- | ------------- |
| 認証情報   | DB/サービス接続パスワード    | High-Critical |
| APIキー    | 外部サービス認証             | Medium-High   |
| 暗号化キー | データ暗号化用               | Critical      |
| 証明書     | TLS/mTLS証明書と秘密鍵       | High-Critical |
| トークン   | JWT署名鍵、OAuthシークレット | High          |
| 設定値     | 機密性のある環境変数         | Low-Medium    |

## 4. 保護要件マトリクス

| 要件                 | Critical | High | Medium | Low  |
| -------------------- | -------- | ---- | ------ | ---- |
| HSM/KMS暗号化        | 必須     | 推奨 | 任意   | -    |
| アクセスログ         | 必須     | 必須 | 必須   | 推奨 |
| リアルタイムアラート | 必須     | 推奨 | -      | -    |
| 多要素認可           | 必須     | 推奨 | -      | -    |
| 自動ローテーション   | 必須     | 必須 | 推奨   | 任意 |
| バックアップ暗号化   | 必須     | 必須 | 必須   | 推奨 |
| 監査レビュー（月次） | 必須     | 必須 | 推奨   | -    |
