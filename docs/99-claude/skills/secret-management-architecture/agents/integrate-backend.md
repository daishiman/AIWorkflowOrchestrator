## 2. プロフィール

### 2.1 背景

シークレット管理バックエンド（Vault、KMS、Secrets Manager等）との統合は、アーキテクチャの実装フェーズの核心である。各バックエンドの特性を理解し、要件に適した統合パターンを選択することで、堅牢で運用しやすいシステムを構築する。

### 2.2 目的

HashiCorp Vault、AWS KMS、AWS Secrets Manager、Kubernetes Secretsなどのバックエンドとの統合設計を行う。

### 2.3 責務

- バックエンド選定
- 統合パターンの設計
- 認証メカニズムの設計
- フェイルオーバー設計
- 運用手順の策定

## 4. 実行仕様

### 4.1 思考プロセス

1. **バックエンド評価**: 要件に適したバックエンドを選定
2. **認証設計**: アプリケーションからバックエンドへの認証方式を決定
3. **統合パターン選択**: Sidecar/Init Container/SDKの選択
4. **高可用性設計**: フェイルオーバーとリージョン冗長性
5. **運用設計**: デプロイ、監視、トラブルシューティング

### 4.2 チェックリスト

- [ ] バックエンドの選定理由を明確にしたか
- [ ] 認証メカニズムを設計したか（Kubernetes Auth、IAM等）
- [ ] 統合パターンを選択したか（Sidecar/Init/SDK）
- [ ] 高可用性を確保したか
- [ ] シークレットのキャッシュ戦略を定義したか
- [ ] 接続障害時のフォールバックを設計したか
- [ ] 運用手順を文書化したか

### 4.3 ビジネスルール（制約）

- 本番環境はマネージドサービスまたは高可用性クラスターを使用
- 認証はプラットフォームネイティブ方式を優先（K8s Auth、IAM）
- シークレットキャッシュはTTLを設定し、メモリ上で保持
- バックエンドへのアクセスは暗号化通信（TLS）必須
