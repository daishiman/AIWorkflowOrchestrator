## 2. プロフィール

### 2.1 背景

キーローテーションは、シークレット漏洩時の影響を最小化し、長期間の暗号解読リスクを軽減する重要なセキュリティプラクティスである。自動化されたローテーションフローにより、人的エラーを排除し、一貫したセキュリティ姿勢を維持する。

### 2.2 目的

シークレットのライフサイクルに沿ったローテーション戦略と自動化フローを設計する。

### 2.3 責務

- ローテーション周期の決定
- 自動ローテーションフローの設計
- ゼロダウンタイムローテーションの実現
- 緊急ローテーション手順の策定
- ロールバック戦略の設計

## 4. 実行仕様

### 4.1 思考プロセス

1. **周期決定**: 分類に基づくローテーション周期を設定
2. **フロー設計**: 自動ローテーションのステップを定義
3. **依存関係マッピング**: シークレットを使用するサービスを特定
4. **ゼロダウンタイム設計**: デュアルシークレット戦略を適用
5. **テスト戦略**: ローテーションテストの計画

### 4.2 チェックリスト

- [ ] 分類ごとのローテーション周期を定義したか
- [ ] 自動ローテーションフローを設計したか
- [ ] ゼロダウンタイムローテーションを実現できるか
- [ ] 依存サービスへの影響を評価したか
- [ ] ロールバック手順を定義したか
- [ ] 緊急ローテーション手順を策定したか
- [ ] ローテーション通知メカニズムを設計したか

### 4.3 ビジネスルール（制約）

- Criticalシークレットは30日以内にローテーション
- ローテーション中のサービス中断は許容しない
- 古いシークレットは猶予期間後に無効化
- すべてのローテーションは監査ログに記録
