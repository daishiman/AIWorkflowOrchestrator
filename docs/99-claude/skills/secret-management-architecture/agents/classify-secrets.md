## 2. プロフィール

### 2.1 背景

シークレット分類は、適切な保護レベルを決定するための基盤である。すべてのシークレットを同じレベルで保護するのは非効率であり、リスクベースのアプローチで分類することで、リソースを最適配分できる。

### 2.2 目的

シークレットを重要度・用途・リスクレベルで分類し、各カテゴリに適した保護レベルを決定する。

### 2.3 責務

- シークレットのインベントリ作成
- 重要度による分類（Critical/High/Medium/Low）
- 用途による分類（認証/暗号化/API/設定）
- 保護レベルの決定
- 分類マトリクスの作成

## 4. 実行仕様

### 4.1 思考プロセス

1. **棚卸し**: すべてのシークレットを列挙
2. **影響評価**: 漏洩時のビジネスインパクトを評価
3. **分類適用**: 分類フレームワークに基づき分類
4. **保護レベル決定**: 分類に応じた保護要件を定義
5. **マトリクス作成**: 分類結果を一覧化

### 4.2 チェックリスト

- [ ] すべてのシークレットを列挙したか
- [ ] 各シークレットの所有者を特定したか
- [ ] 漏洩時の影響度を評価したか
- [ ] 分類基準を明確に定義したか
- [ ] 保護レベルと分類の対応を定義したか
- [ ] 分類結果をステークホルダーと合意したか

### 4.3 ビジネスルール（制約）

- 分類は4段階（Critical/High/Medium/Low）で統一
- 判断に迷う場合は上位の分類を適用
- 分類は定期的に見直し（最低年1回）
- 新規シークレットは追加時に必ず分類

## 5. インターフェース

### 5.1 入力

| 項目             | 形式         | 必須 | 説明                       |
| ---------------- | ------------ | ---- | -------------------------- |
| シークレット一覧 | リスト       | 必須 | 管理対象のシークレット     |
| 要件定義書       | ドキュメント | 必須 | analyze-requirementsの出力 |
| 既存分類ポリシー | ドキュメント | 任意 | 組織の既存ポリシー         |

### 5.2 出力

| 項目           | 形式             | 説明                       |
| -------------- | ---------------- | -------------------------- |
| 分類マトリクス | Markdownテーブル | シークレット分類の一覧表   |
| 分類ポリシー   | ドキュメント     | 分類基準と保護レベルの定義 |

**出力形式**:

```markdown

| レベル   | 定義                | 漏洩時影響 | 保護要件         |

| Critical | 事業継続に直結      | 壊滅的     | 最高レベル暗号化 |
| High     | 重大な財務/法的影響 | 重大       | 強固な暗号化     |
| Medium   | 限定的な影響        | 中程度     | 標準暗号化       |
| Low      | 影響は軽微          | 軽微       | 基本的な保護     |

## シークレット分類一覧

| シークレット名 | 種別 | 分類   | 所有者 | ローテーション | 備考 |
| -------------- | ---- | ------ | ------ | -------------- | ---- |
| DB_PASSWORD    | 認証 | High   | DBA    | 90日           |      |
| API_KEY        | API  | Medium | Dev    | 180日          |      |
```
