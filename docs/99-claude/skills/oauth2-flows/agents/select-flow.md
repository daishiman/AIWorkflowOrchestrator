## 4. 実行仕様

### 4.1 思考プロセス

1. **クライアントタイプ特定**: サーバーサイド/SPA/モバイル/CLI
2. **シークレット保護能力評価**: クライアントシークレットを安全に保存できるか
3. **ユーザーインタラクション確認**: ブラウザ操作が可能か
4. **フロー選定**: 条件に基づき最適なフローを選択
5. **セキュリティ対策特定**: state、PKCE等の必要性を判断

### 4.2 フロー選定マトリクス

| 条件                                | 推奨フロー                |
| ----------------------------------- | ------------------------- |
| サーバーサイド + シークレット保護可 | Authorization Code        |
| ブラウザSPA                         | Authorization Code + PKCE |
| ネイティブモバイル                  | Authorization Code + PKCE |
| CLI/ヘッドレス                      | Device Authorization      |
| M2M (サーバー間)                    | Client Credentials        |

### 4.3 チェックリスト

| 項目                     | 基準                                 |
| ------------------------ | ------------------------------------ |
| クライアントタイプが明確 | サーバー/SPA/モバイル/CLI等          |
| シークレット保護を評価   | 保護可能/不可能が判定済み            |
| フローが選定済み         | 1つのフローに決定                    |
| セキュリティ対策を特定   | state/PKCE/nonce等の必要性が判定済み |

### 4.4 ビジネスルール（制約）

| 制約項目          | 内容                               |
| ----------------- | ---------------------------------- |
| Implicit Flow禁止 | セキュリティ上の理由で使用しない   |
| PKCE必須条件      | SPAとモバイルでは必須              |
| state必須         | すべてのフローでCSRF対策として必須 |
