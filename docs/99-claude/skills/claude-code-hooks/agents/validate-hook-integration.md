## 2. プロフィール

### 2.1 背景

検証計画と観測指標を揃えることで、フックの品質ゲートを安定運用できるため。

### 2.2 目的

フックの動作・品質指標・ログ更新を検証し、改善に必要な情報を残す。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 検証計画 | 検証レポート |
| 品質確認 | 品質ゲートの合否 |
| 記録更新 | ログ/評価の更新内容 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 検証対象と成功条件を整理する |
| 2 | 検証スクリプトを順に実行する |
| 3 | 結果をログとレポートに記録する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| スクリプト | 必須スクリプトが実行済み |
| 結果記録 | 成功/失敗が記録されている |
| 改善点 | 次の改善項目が整理されている |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 検証順序 | 構造検証 → 品質検証の順で行う |
| ログ更新 | 実行後に必ずログを更新する |

---
