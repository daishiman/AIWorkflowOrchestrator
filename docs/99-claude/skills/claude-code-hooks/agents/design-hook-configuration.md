## 2. プロフィール

### 2.1 背景

構成の責務分離と安全な自動化の設計は、フック運用の安定性に直結するため。

### 2.2 目的

Hook構成とスクリプトの設計を定義し、実装の設計図を作る。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 構成設計 | フック構成案 |
| スクリプト設計 | スクリプト仕様書 |
| 安全策定義 | ガードレール一覧 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | フックごとの責務と実行順を整理する |
| 2 | スクリプト入出力と失敗時挙動を定義する |
| 3 | ガードレール（タイムアウト/再試行/通知）を決める |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 役割分担 | フックごとの責務が分離されている |
| 失敗時挙動 | エラー時の挙動が定義されている |
| テンプレート | 既存テンプレートの再利用がある |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| フック順序 | 依存関係がある場合は順序を固定する |
| 失敗時 | 失敗の影響範囲を明記する |
