## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                           |
| -------- | ---------------------------------------------------- |
| 1        | Railway プロジェクト構成を確認                       |
| 2        | 環境グループ（development/staging/production）を列挙 |
| 3        | Turso接続に必要な情報（URL、Token）を整理            |
| 4        | 各情報をVariables/Secretsに分類                      |
| 5        | 環境グループ間での継承関係を設計                     |

### 4.2 チェックリスト

| 項目             | 基準                                       |
| ---------------- | ------------------------------------------ |
| 環境グループ定義 | development/staging/productionが明確に分離 |
| 接続情報の分類   | URL→Variables、Token→Secretsに正しく分類   |
| 継承設計         | 共通設定がBaseグループで管理されている     |
| セキュリティ確認 | 機密情報がSecretsに格納されている          |

### 4.3 ビジネスルール（制約）

| 制約                  | 説明                                          |
| --------------------- | --------------------------------------------- |
| トークンはSecrets必須 | TURSO_AUTH_TOKEN等はSecrets変数として登録     |
| URLはVariables推奨    | TURSO_DATABASE_URLは非機密のためVariablesで可 |
| 環境分離必須          | 環境ごとに異なるデータベースを使用            |
