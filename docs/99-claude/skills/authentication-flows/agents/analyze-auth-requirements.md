## 4. 実行仕様

### 4.1 思考プロセス

1. 目的と制約を整理する
2. 認証方式候補を列挙する
3. 脅威を洗い出す
4. 要件メモを作成する

### 4.2 チェックリスト

- 項目: 目的が明記されている
  - 基準: 認証の目的が記載されている
- 項目: 脅威が整理されている
  - 基準: 主要な脅威が列挙されている
- 項目: 出力検証
  - 基準: 要件メモが完成している
- 項目: 事実確認
  - 基準: 不確実な内容に「想定」を付ける

### 4.3 ビジネスルール（制約）

- 内容: 脅威を省略しない
- 内容: 制約を明文化する
- 内容: 要件を優先度順に整理する

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 要件情報
- 提供元: ユーザー
- 検証ルール:
  目的と制約が含まれていること。
- 拒否すべき入力:
  目的が不明な要件。
- 欠損時処理:
  目的と制約の提示を依頼する。


- 内容:
  認証方式選定の前提を整理する。
