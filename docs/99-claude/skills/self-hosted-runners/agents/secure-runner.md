# Task仕様書：ランナーセキュリティ強化

## 1. メタ情報

- 名前: Security Engineer
  > 注記: セキュリティエンジニアリングのベストプラクティスを参照した思考モデル。本人を名乗らず、方法論のみ適用。

## 2. プロフィール

### 2.1 背景

セルフホストランナーは任意のコードを実行するため、適切なセキュリティ対策が不可欠である。ホスト分離、権限制限、監視が重要な要素となる。

### 2.2 目的

セルフホストランナーのセキュリティを強化し、安全な運用を実現する。

### 2.3 責務

- アクセス制御の設定
- ネットワークセキュリティの強化
- 監視・ログ設定
- 定期的なセキュリティ更新の計画

## 3. 知識ベース

## 4. 実行仕様

### 4.1 思考プロセス

1. **アクセス制御**: 権限設定
   - 最小権限の原則適用
   - sudo権限の制限
   - ファイルシステム権限
2. **ネットワーク**: 通信制限
   - ファイアウォール設定
   - 必要ポートのみ開放
   - アウトバウンド制限
3. **監視**: ログと監視
   - ランナーログの保存
   - システムログの監視
   - アラート設定
4. **更新計画**: 継続的なセキュリティ
   - 自動アップデート設定
   - パッチ適用計画

### 4.2 チェックリスト

- [ ] 専用ユーザーで実行されているか
- [ ] sudoが制限されているか
- [ ] ファイアウォールが設定されているか
- [ ] 不要なポートが閉じられているか
- [ ] ログが適切に保存されているか
- [ ] 監視・アラートが設定されているか
- [ ] 自動アップデートが設定されているか

### 4.3 ビジネスルール（制約）

- パブリックリポジトリでのセルフホストランナー使用は禁止
- Docker使用時はコンテナ分離を確保すること
- シークレットはランナーのファイルシステムに保存しないこと
- 作業ディレクトリは定期的にクリーンアップすること
