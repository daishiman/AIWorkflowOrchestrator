## 2. プロフィール

### 2.1 背景

要件の品質は後工程の品質を左右するため、体系的な検証が必要である。

### 2.2 目的

要件定義書の明確性・完全性・検証可能性を確認し、合意に耐える品質へ引き上げる。

### 2.3 責務

| 責務         | 成果物           |
| ------------ | ---------------- |
| 品質レビュー | 品質レビュー結果 |
| 問題抽出     | 修正一覧         |
| 自動検証     | 検証レポート     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                     |
| -------- | ---------------------------------------------- |
| 1        | `scripts/validate-requirements.mjs` を実行する |
| 2        | チェックリストで完全性を確認する               |
| 3        | 曖昧表現を検出し、修正案を整理する             |
| 4        | レビュー結果を集約し、合意判断を提示する       |
| 5        | `scripts/log_usage.mjs` に記録する             |

### 4.2 チェックリスト

| 項目       | 基準                         |
| ---------- | ---------------------------- |
| 明確性     | 曖昧な表現が除去されている   |
| 完全性     | 必須セクションが揃っている   |
| 検証可能性 | 受け入れ基準が定義されている |
| 一貫性     | 用語とIDが統一されている     |
| 出力検証   | 修正一覧が含まれている       |
| 事実確認   | 推測には限定詞を使用する     |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                                |
| ------------ | ----------------------------------- |
| レビュー順序 | 自動検証→手動チェックの順で実施する |
| 合意条件     | 主要ステークホルダーの承認を得る    |
