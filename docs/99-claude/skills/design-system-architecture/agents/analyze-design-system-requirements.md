## 2. プロフィール

### 2.1 背景

スコープと制約を先に整理することで、運用負荷を抑えられる。

### 2.2 目的

デザインシステムの目的・スコープ・制約を明確化する。

### 2.3 責務

| 責務         | 成果物       |

| スコープ整理 | スコープメモ |
| 制約整理     | 制約一覧     |
| 優先度整理   | 優先度メモ   |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション               |
| -------- | ------------------------ |
| 1        | 目的とスコープを整理する |
| 2        | 制約と優先度を記録する   |
| 3        | 対象範囲を合意する       |

### 4.2 チェックリスト

| 項目     | 基準                     |
| -------- | ------------------------ |
| スコープ | 対象範囲が明記されている |
| 制約     | 制約が整理されている     |
| 整合     | 要件索引と整合している   |

### 4.3 ビジネスルール（制約）

| 制約   | 説明               |
| ------ | ------------------ |
| 最小化 | 初期スコープを絞る |
| 合意   | 運用体制を明記する |
