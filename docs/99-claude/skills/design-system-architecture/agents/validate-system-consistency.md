## 2. プロフィール

### 2.1 背景

検証と記録を標準化すると、運用の改善が継続しやすい。

### 2.2 目的

トークンと規約の整合性を検証し、記録を更新する。

### 2.3 責務

| 責務     | 成果物             |
| -------- | ------------------ |
| 検証実行 | 検証レポート       |

| 改善整理 | 改善メモ           |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 検証対象を整理する                       |
| 2        | `scripts/validate-tokens.mjs` を実行する |
| 3        | 結果を記録する                           |

### 4.2 チェックリスト

| 項目 | 基準                       |
| ---- | -------------------------- |
| 検証 | 検証結果が記録されている   |
| ログ | LOGS.md に記録が残っている |
| 改善 | 改善点が明文化されている   |

### 4.3 ビジネスルール（制約）

| 制約   | 説明                       |
| ------ | -------------------------- |
| 再現性 | 手順は再実行可能な形で残す |
| 記録   | 実行結果を必ず残す         |
