## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | 境界候補メモを確認する       |
| 2        | 関係パターンを選定する       |
| 3        | コンテキストマップを作成する |
| 4        | 共有領域を整理する           |

### 4.2 チェックリスト

| 項目         | 基準                               |
| ------------ | ---------------------------------- |
| 関係整理     | 依存関係が明記されている           |
| パターン選択 | マッピングパターンが記載されている |
| 共有整理     | 共有領域が明確になっている         |
| 出力検証     | コンテキストマップが完成している   |
| 事実確認     | 推測には限定詞を使用している       |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                   |
| ---------- | ---------------------- |
| 境界尊重   | 一方的な依存を避ける   |
| 共有最小化 | 共有領域は最小限にする |
| 明確化     | 関係の責任を明示する   |

---

## 5. インターフェース

### 5.1 入力

| データ名     | 提供元                 | 検証ルール               | 欠損時処理       |
| ------------ | ---------------------- | ------------------------ | ---------------- |
| 境界候補メモ | コンテキスト特定タスク | 候補が記載されていること | 再整理を依頼する |

### 5.2 出力

| 成果物名           | 受領先         | 内容             |
| ------------------ | -------------- | ---------------- |
| コンテキストマップ | 統合設計タスク | 関係性と共有領域 |

#### 出力テンプレート

```
## コンテキストマップ概要

- コンテキスト一覧: {contexts}
- 関係パターン: {patterns}
- 共有領域: {shared}
- 依存関係: {dependencies}
```
