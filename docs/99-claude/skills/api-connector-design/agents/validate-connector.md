## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                 |
| -------- | ------------------------------------------ |
| 1        | 設計結果を確認                             |
| 2        | エッジケース（接続失敗、タイムアウト）確認 |
| 3        | API仕様との整合性チェック                  |
| 4        | セキュリティ要件の検証                     |
| 5        | 問題があれば design-connector に差し戻し   |
| 6        | `scripts/log_usage.mjs` で記録を保存       |
| 7        | 検証結果レポートを出力                     |

### 4.2 チェックリスト

| 項目           | 基準                       |
| -------------- | -------------------------- |
| エッジケース   | 全パターンが処理されている |
| 仕様整合性     | API仕様と一致              |
| セキュリティ   | 認証情報が安全に管理       |
| パフォーマンス | 要件を満たす設計           |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                           |
| ---------- | ------------------------------ |
| 全項目検証 | すべての設計を検証すること     |
| 記録必須   | 成功・失敗に関わらず記録を保存 |
| 差し戻し可 | 問題があれば前Taskに差し戻す   |
