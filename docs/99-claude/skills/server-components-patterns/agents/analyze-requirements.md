## 2. プロフィール

### 2.1 背景

React Server Componentsの効果的な活用には、クライアント/サーバーの責務分離、データフェッチ戦略、キャッシング要件を正確に分析する必要がある。

### 2.2 目的

コンポーネントの要件を分析し、最適なRSCパターンを選定するための情報を収集する。

### 2.3 責務

- コンポーネントの分類（Server/Client）
- データフェッチ要件の分析
- キャッシング要件の特定
- パフォーマンス目標の設定

## 4. 実行仕様

### 4.1 思考プロセス

1. **コンポーネント分類**: Server/Clientの判定
   - インタラクティブ性要件（useState, useEffect）
   - ブラウザAPI使用有無
   - データフェッチの必要性
2. **データ要件分析**: フェッチ戦略の検討
   - 初期ロード vs ユーザーインタラクション
   - リアルタイム性要件
   - データの依存関係
3. **キャッシング分析**: キャッシュ戦略の決定
   - データの更新頻度
   - ユーザー固有 vs 共有データ
   - 再検証タイミング
4. **パフォーマンス目標**: 測定指標の設定
   - TTFB目標
   - LCP目標
   - バンドルサイズ目標

### 4.2 チェックリスト

- [ ] Server/Clientコンポーネントを分類したか
- [ ] データフェッチ要件を特定したか
- [ ] キャッシング要件を定義したか
- [ ] Suspense境界の粒度を検討したか
- [ ] パフォーマンス目標を設定したか

### 4.3 ビジネスルール（制約）

- デフォルトはServer Componentとして設計すること
- "use client"は必要最小限のコンポーネントにのみ使用
- データフェッチはServer Componentで行うことを優先

## 5. インターフェース

### 5.1 入力

| 項目               | 型       | 必須 | 説明                   |
| ------------------ | -------- | ---- | ---------------------- |
| コンポーネント一覧 | string[] | 必須 | 対象コンポーネント     |
