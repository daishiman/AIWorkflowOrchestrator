# Task仕様書：脆弱性評価（assess-vulnerabilities）

## 1. メタ情報

- 名前: OWASP Foundation
  > 注記: Webアプリケーションセキュリティの標準化団体。OWASP Top 10の評価手法を参照する。

## 2. プロフィール

### 2.1 背景

脅威分析で特定された脅威に対応する具体的な脆弱性を評価・分類する。業界標準の分類体系（OWASP Top 10、CWE）を用いることで、一貫性のある報告と対策立案が可能になる。

### 2.2 目的

- 検出された脆弱性をOWASP Top 10/CWEで分類する
- 各脆弱性の影響範囲と悪用可能性を評価する
- 再現可能な証跡と手順を文書化する
- 次フェーズのリスク採点に必要な情報を整理する

### 2.3 責務

- 脆弱性の技術的分類
- 影響範囲の特定
- 証跡（PoC、スクリーンショット等）の収集
- 再現手順の文書化

## 4. 実行仕様

### 4.1 思考プロセス

1. **脆弱性分類**: OWASP Top 10カテゴリに分類
   - A01: Broken Access Control
   - A02: Cryptographic Failures
   - A03: Injection
   - A04: Insecure Design
   - A05: Security Misconfiguration
   - A06: Vulnerable and Outdated Components
   - A07: Identification and Authentication Failures
   - A08: Software and Data Integrity Failures
   - A09: Security Logging and Monitoring Failures
   - A10: Server-Side Request Forgery

2. **CWEマッピング**: 具体的なCWE IDを付与
   - 例: SQL Injection → CWE-89
   - 例: XSS → CWE-79

3. **影響評価**: 脆弱性が悪用された場合の影響
   - 機密性への影響
   - 完全性への影響
   - 可用性への影響

4. **悪用可能性評価**: 攻撃の実現容易性
   - 既知のエクスプロイト存在有無
   - 必要な技術スキル
   - 前提条件の複雑さ

### 4.2 チェックリスト

- [ ] 全脆弱性にOWASPカテゴリが付与されている
- [ ] 全脆弱性にCWE IDが付与されている
- [ ] 影響を受けるファイル/行が特定されている
- [ ] 再現手順が文書化されている
- [ ] 証跡（PoC/スクリーンショット）が添付されている

### 4.3 ビジネスルール（制約）

| 制約     | 説明                                    |
| -------- | --------------------------------------- |
| 標準分類 | 必ずOWASP/CWEで分類する（独自分類不可） |
| 再現性   | 第三者が再現できる手順を記述する        |
| 証跡必須 | 主観的な報告は不可。必ず証跡を添付      |
| 環境情報 | 検証環境の詳細を明記する                |

## 5. インターフェース

### 5.1 入力

| 項目         | 形式       | 説明                       |
| ------------ | ---------- | -------------------------- |
| 脅威リスト   | Markdown表 | Phase 1の出力              |
| スキャン結果 | レポート   | 自動スキャンツールの出力   |
| ソースコード | ファイル   | 手動レビュー対象           |
| 設定ファイル | ファイル   | セキュリティ設定の確認対象 |

### 5.2 出力

| 項目         | 形式     | 説明                       |
| ------------ | -------- | -------------------------- |
| 脆弱性評価書 | Markdown | 分類・評価された脆弱性一覧 |
| 証跡ファイル | 各種     | PoC、スクリーンショット    |
| 再現手順書   | Markdown | 各脆弱性の再現方法         |

**出力形式例**:

```markdown
## 脆弱性評価書

### V-001: SQLインジェクション

**分類**:

- OWASP: A03 Injection
- CWE: CWE-89

**影響を受けるファイル**:

- `src/api/users.ts` (Line 45)

**影響評価**:

- 機密性: High（全ユーザーデータ漏洩の可能性）
- 完全性: High（データ改ざんの可能性）
- 可用性: Medium（DROP文による破壊の可能性）

**再現手順**:

1. POST /api/users/search にリクエスト
2. `query` パラメータに `' OR '1'='1` を入力
3. 全ユーザーデータが返却される

**証跡**: `evidence/V-001-sqli-poc.png`
```
