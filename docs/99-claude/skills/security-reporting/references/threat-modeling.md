## STRIDEモデル

MicrosoftのAdam Shostackが提唱した脅威分類フレームワーク。

### カテゴリ定義

| カテゴリ | 英語                   | 説明                                        | 対策の方向性         |
| -------- | ---------------------- | ------------------------------------------- | -------------------- |
| S        | Spoofing               | なりすまし。正当なユーザーや システムを偽装 | 認証強化             |
| T        | Tampering              | 改ざん。データや設定の不正な変更            | 完全性検証           |
| R        | Repudiation            | 否認。行為の証拠を否定                      | 監査ログ             |
| I        | Information Disclosure | 情報漏洩。機密データの不正取得              | 暗号化・アクセス制御 |
| D        | Denial of Service      | サービス拒否。可用性の妨害                  | 冗長化・レート制限   |
| E        | Elevation of Privilege | 権限昇格。不正な権限取得                    | 最小権限原則         |

## 脅威アクター分類

### 外部脅威アクター

| タイプ           | 動機               | 技術力 | リソース |
| ---------------- | ------------------ | ------ | -------- |
| スクリプトキディ | 好奇心、自己顕示   | 低〜中 | 低       |
| ハクティビスト   | 政治的・社会的主張 | 中     | 中       |
| サイバー犯罪者   | 金銭的利益         | 中〜高 | 中〜高   |
| 国家支援攻撃者   | 諜報、破壊         | 高     | 非常に高 |
| 競合他社         | 競争優位性         | 中〜高 | 中〜高   |

### 内部脅威アクター

| タイプ             | 動機         | 特徴                   |
| ------------------ | ------------ | ---------------------- |
| 悪意のある従業員   | 復讐、金銭   | 内部知識を悪用         |
| 過失による従業員   | なし（ミス） | 設定ミス、誤操作       |
| 委託先・パートナー | 金銭、競争   | 限定的アクセス権を悪用 |

## 攻撃ベクトル

### Webアプリケーション固有

| 攻撃ベクトル         | 説明                                           | STRIDE |
| -------------------- | ---------------------------------------------- | ------ |
| ユーザー入力フォーム | SQLi, XSS, コマンドインジェクション            | T, I   |
| 認証エンドポイント   | ブルートフォース、クレデンシャルスタッフィング | S      |
| セッション管理       | セッションハイジャック、固定                   | S      |
| API エンドポイント   | 不正なデータアクセス、レート制限回避           | I, D   |
| ファイルアップロード | マルウェア、Webシェル                          | T, E   |
| サードパーティ連携   | OAuth脆弱性、SSRF                              | S, I   |

### インフラストラクチャ

| 攻撃ベクトル        | 説明                                   | STRIDE |
| ------------------- | -------------------------------------- | ------ |
| 公開ポート/サービス | 脆弱なサービスへの直接攻撃             | E, I   |
| 設定ミス            | 不適切な権限、デフォルト認証情報       | S, E   |
| 依存関係            | 脆弱なライブラリ、サプライチェーン攻撃 | T, E   |
| ネットワーク境界    | ファイアウォール迂回、横方向移動       | I, E   |

## 信頼境界の特定

### 定義

信頼境界（Trust Boundary）は、異なるセキュリティレベルの領域間の境界。

### 一般的な信頼境界

```
[インターネット] ←── 境界1 ──→ [DMZ/Webサーバー]
                                      │
                                   境界2
                                      │
                              [アプリサーバー]
                                      │
                                   境界3
                                      │
                              [データベース]
```

| 境界  | 両側                   | 必要な保護                 |
| ----- | ---------------------- | -------------------------- |
| 境界1 | インターネット ↔ DMZ   | WAF, IDS/IPS, DDoS対策     |
| 境界2 | DMZ ↔ 内部ネットワーク | ファイアウォール, 認証     |
| 境界3 | アプリ ↔ データベース  | 認証, 暗号化, アクセス制御 |

### 3. リスク評価（DREAD）

| 要素                | 説明         | 1            | 2        | 3    |
| ------------------- | ------------ | ------------ | -------- | ---- |
| D (Damage)          | 被害の大きさ | 軽微         | 中程度   | 深刻 |
| R (Reproducibility) | 再現性       | 困難         | 条件付き | 容易 |
| E (Exploitability)  | 悪用可能性   | 高度なスキル | 中程度   | 容易 |
| A (Affected Users)  | 影響範囲     | 一部         | 多数     | 全員 |
| D (Discoverability) | 発見可能性   | 困難         | 中程度   | 容易 |

**DREADスコア**: 各要素の合計（5〜15）
