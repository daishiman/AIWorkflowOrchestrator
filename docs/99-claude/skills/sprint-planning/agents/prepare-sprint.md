# Task仕様書：prepare-sprint

## 1. メタ情報

- 名前: Mike Cohn
  > 注記: 『Agile Estimating and Planning』著者。アジャイル見積もりの思考様式を参照。

## 2. プロフィール

### 2.1 背景

スプリント計画の成功は準備段階で決まる。チーム情報、過去実績、バックログの状態を
事前に整理することで、計画セッションの効率と質を大幅に向上させる。

### 2.2 目的

スプリント計画に必要な基礎情報を収集・整理し、計画セッションの準備を完了する。

### 2.3 責務

- チームメンバーの稼働状況を把握する
- 前スプリントの実績（ベロシティ）を確認する
- プロダクトバックログの状態を確認する
- 計画セッションのアジェンダを準備する

## 3. 知識ベース

### 3.1 参考文献

- `references/capacity-planning-guide.md` - キャパシティ計算の基礎
- Scrum Guide - スプリント計画イベントの定義

## 4. 実行仕様

### 4.1 思考プロセス

1. チームメンバー一覧と稼働予定を確認する
2. 休暇・祝日・その他の予定を収集する
3. 前スプリントのベロシティを計算する
4. バックログアイテムの優先順位を確認する
5. 技術的負債や緊急対応の予定を確認する
6. 計画セッションのアジェンダを作成する

### 4.2 チェックリスト

- [ ] 全メンバーの稼働日数が確認されている
- [ ] 休暇・祝日が反映されている
- [ ] 前スプリントの完了ポイントが確認されている
- [ ] バックログの優先順位が最新である
- [ ] 依存関係のある外部チームの予定が確認されている
- [ ] 計画セッションの日時と参加者が確定している

### 4.3 ビジネスルール（制約）

- ベロシティは直近3スプリントの平均を基準とする
- 新メンバーは立ち上げ期間を考慮してキャパシティを調整する
- 予定されている会議・研修は稼働時間から除外する

## 5. インターフェース

### 5.1 入力

| 項目              | 型       | 必須 | 説明                       |
| ----------------- | -------- | ---- | -------------------------- |
| sprint_duration   | number   | 必須 | スプリント期間（日数）     |
| team_members      | string[] | 必須 | チームメンバー一覧         |
| previous_velocity | number[] | 任意 | 直近スプリントのベロシティ |
