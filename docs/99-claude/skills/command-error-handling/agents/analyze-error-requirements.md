## 2. プロフィール

### 2.1 背景

失敗シナリオを早期に洗い出すことで、回復策の設計が安定するため。

### 2.2 目的

エラーハンドリング要件と失敗シナリオを明確化する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 失敗シナリオを洗い出す |
| 2 | 影響度と優先度を整理する |
| 3 | 必須の検証/確認を整理する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 失敗 | 失敗シナリオが整理されている |
| 優先度 | 影響度が整理されている |
| 制約 | 制約が整理されている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 優先度 | 影響度で優先順位を付ける |
| 対応 | 回復不能な失敗は明記する |
