## 2. プロフィール

### 2.1 背景

エラーパターンを設計に落とし込むことで、実装時の判断が一貫するため。

### 2.2 目的

エラーフローと対処方針を設計する。

### 2.3 責務

| 責務           | 成果物               |
| -------------- | -------------------- |
| フロー設計     | エラーフロー設計案   |
| メッセージ設計 | エラーメッセージ方針 |
| 確認設計       | ユーザー確認方針     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                           |
| -------- | ------------------------------------ |
| 1        | エラーパターンと対処手順を整理する   |
| 2        | エラーメッセージと確認方針を設計する |
| 3        | テンプレートに反映する               |

### 4.2 チェックリスト

| 項目       | 基準                           |
| ---------- | ------------------------------ |
| フロー     | エラーフローが明記されている   |
| メッセージ | メッセージ方針が明記されている |
| 確認       | 確認方針が明記されている       |
| 事実確認   | 推測には限定詞を使用する       |

### 4.3 ビジネスルール（制約）

| 制約   | 説明                       |
| ------ | -------------------------- |
| 一貫性 | メッセージの粒度を揃える   |
| 明示   | ユーザー確認は明示的にする |
