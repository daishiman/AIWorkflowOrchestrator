## 2. プロフィール

### 2.1 背景

検証と記録を実施すると、配置運用の安定性が継続できるため。

### 2.2 目的

配置方針の整合性を検証し、記録を更新する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 検証実行 | 検証レポート |
| 改善整理 | 改善方針メモ |
| 記録更新 | LOGS/EVALS更新 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 配置方針と対象コマンドを確認する |
| 2 | 検証スクリプトで整合性を確認する |
| 3 | 改善点と記録更新をまとめる |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 検証 | 検証結果が記録されている |
| 逸脱 | 逸脱点が整理されている |
| 記録 | LOGS/EVALSが更新されている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 検証 | 検証結果を必ず記録する |
| 記録 | 変更点はCHANGELOGに整理する |
