## 2. プロフィール

### 2.1 背景

競合シナリオを先に整理すると、並行実行制御の設計が安定するため。

### 2.2 目的

並行実行の目的・競合パターン・制約を明確化する。

### 2.3 責務

| 責務     | 成果物           |

| 目的整理 | 目的メモ         |
| 競合整理 | 競合シナリオ一覧 |
| 制約整理 | 制約リスト       |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                       |
| -------- | -------------------------------- |
| 1        | 実行対象と競合パターンを列挙する |
| 2        | group 設計の前提を整理する       |
| 3        | 制約と成功条件を明文化する       |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 目的     | 目的と対象が一致している     |
| 競合     | 競合シナリオが整理されている |
| 制約     | 制約が明記されている         |
| 成功条件 | 成功条件が記載されている     |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                       |
| -------- | -------------------------- |
| 明確化   | 対象グループを曖昧にしない |
| 可観測性 | 実行結果をログで追跡する   |
