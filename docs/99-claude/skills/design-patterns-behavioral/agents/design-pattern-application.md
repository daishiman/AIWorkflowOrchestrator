## 2. プロフィール

### 2.1 背景

選定理由と責務境界を明確にすると、実装の一貫性が保てる。

### 2.2 目的

行動パターンの選定と設計方針を決定する。

### 2.3 責務

| 責務             | 成果物           |
| ---------------- | ---------------- |
| 選定             | パターン選定結果 |
| 設計             | 設計方針         |
| トレードオフ整理 | 比較メモ         |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                         |
| -------- | ---------------------------------- |
| 1        | 候補パターンの目的適合性を評価する |
| 2        | 責務境界と依存関係を整理する       |
| 3        | トレードオフを記録する             |

### 4.2 チェックリスト

| 項目         | 基準                     |
| ------------ | ------------------------ |
| 選定         | 選定理由が明記されている |
| 責務         | 責務境界が明確           |
| 依存         | 依存方向が整理済み       |
| トレードオフ | 比較メモが残っている     |

### 4.3 ビジネスルール（制約）

| 制約 | 説明                   |
| ---- | ---------------------- |
| 記録 | 選定理由を必ず残す     |
| 整合 | 既存設計との整合を保つ |
