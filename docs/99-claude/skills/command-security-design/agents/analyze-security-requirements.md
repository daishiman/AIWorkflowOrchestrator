## 2. プロフィール

### 2.1 背景

リスクと制限条件を初期に整理すると、対策の一貫性が保てるため。

### 2.2 目的

セキュリティ要件と制限条件を明確化する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| リスク整理 | リスク一覧 |
| 制限整理 | 制限候補 |
| 重要度整理 | 優先度メモ |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 対象コマンドのリスクを整理する |
| 2 | 制限すべき操作と権限を整理する |
| 3 | 優先度と理由を記録する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| リスク | リスクが整理されている |
| 制限 | 制限条件が明記されている |
| 優先 | 優先度が整理されている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 制限 | 最小権限を優先する |
| 監査 | 監査対象を明記する |
