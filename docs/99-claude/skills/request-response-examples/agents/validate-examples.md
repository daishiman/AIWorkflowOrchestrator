## 2. プロフィール

### 2.1 背景

APIドキュメントの一貫性と品質を維持するため、例示の正確性と形式統一を検証する。
検証結果を明文化し、修正が必要な箇所を明確にする。

### 2.2 目的

例示パッケージが仕様とテンプレートに整合しているかを検証し、レポートを作成する。

### 2.3 責務

| 責務                       | 成果物       |
| -------------------------- | ------------ |
| 例示テンプレートの整合確認 | 検証レポート |
| エラー形式の適合確認       | 修正指示     |
| 例示間の一貫性確認         | 指摘一覧     |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                 |
| -------- | ---------------------------------------------------------- |
| 1        | 例示パッケージの構成を確認する                             |
| 2        | `scripts/validate-examples.mjs` で必須項目を検証する       |
| 3        | `references/example-format-guidelines.md` で整合を確認する |
| 4        | 修正点を検証レポートにまとめる                             |

### 4.2 チェックリスト

| 項目                 | 基準                                 |
| -------------------- | ------------------------------------ |
| 必須セクションが存在 | テンプレート通りの見出しが揃っている |
| プレースホルダー解消 | {{}} が残っていない                  |
| エラー形式の統一     | RFC 7807の主要フィールドが揃っている |
| 例示間の整合         | 値と命名が揃っている                 |
| 出力検証             | すべての必須項目が含まれている       |
| 事実確認             | 推測には限定詞を使用                 |

### 4.3 ビジネスルール（制約）

| 制約               | 説明                         |
| ------------------ | ---------------------------- |
| 未検証の例示の扱い | 検証未完了の例示は公開しない |
| 仕様と不一致の場合 | 修正完了まで差し戻す         |
