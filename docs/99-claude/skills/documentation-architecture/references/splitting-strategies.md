# ファイル分割戦略

> **相対パス**: `references/splitting-strategies.md`
> **読込条件**: 分割設計時に参照

---

## 分割判断基準

### 定量的基準

| 指標         | 閾値   | アクション         |
| ------------ | ------ | ------------------ |
| ファイル行数 | >500行 | 分割必須           |
| トピック数   | >1     | トピックごとに分割 |
| セクション数 | >10    | 論理的に分割検討   |
| 参照頻度差   | 大     | 頻度別に分割       |

### 定性的基準

| 状態                     | アクション       |
| ------------------------ | ---------------- |
| 複数の独立した概念       | 概念ごとに分割   |
| 異なる読者層が存在       | 読者層別に分割   |
| 更新頻度が部分的に異なる | 更新頻度別に分割 |

## 分割パターン

### 水平分割（Horizontal Split）

**適用場面**: 同レベルの並列コンテンツ

```
before:
  large-file.md (800行)

after:
  topic-a.md (300行)
  topic-b.md (250行)
  topic-c.md (250行)
```

**メリット**: 各ファイルが独立、並列編集可能

### 垂直分割（Vertical Split）

**適用場面**: 抽象度が異なるコンテンツ

```
before:
  comprehensive-guide.md (600行)

after:
  overview.md (概要: 100行)
  details.md (詳細: 300行)
  reference.md (参照: 200行)
```

**メリット**: 必要な深度だけ読み込み可能

### 参照分離（Reference Extraction）

**適用場面**: データや定義を含むコンテンツ

```
before:
  guide.md (説明 + データテーブル: 700行)

after:
  guide.md (説明のみ: 300行)
  data-tables.md (データのみ: 400行)
```

**メリット**: 本文が軽量化、データの再利用が容易

## 分割実行手順

### ステップ1: 分析

1. 現在の行数を確認
2. トピック境界を特定
3. 分割パターンを選択

### ステップ2: 設計

1. 新ファイル名を決定（命名規則に従う）
2. 各ファイルの内容範囲を決定
3. 相互参照の必要性を確認

### ステップ3: 実行

1. 新ファイルを作成
2. コンテンツを移動
3. 元ファイルから参照を追加
4. 他ファイルからのリンクを更新

### ステップ4: 検証

1. 全ファイルが500行以下か確認
2. 相互リンクが有効か確認
3. 情報の欠落がないか確認

## 分割時の注意点

### すべきこと

| 項目             | 理由               |
| ---------------- | ------------------ |
| 目次を維持       | 発見可能性の確保   |
| 相互リンクを設置 | ナビゲーション支援 |
| 分割理由を記録   | 将来の保守のため   |

### 避けるべきこと

| 項目                 | 問題点         |
| -------------------- | -------------- |
| 過度な細分化         | 管理コスト増大 |
| 意味的に不完全な分割 | 理解困難       |
| リンク更新忘れ       | リンク切れ発生 |

---

## 分割後の構造検証

| 検証項目     | 確認方法                             |
| ------------ | ------------------------------------ |
| 行数制約     | `wc -l` または analyze-structure.mjs |
| リンク有効性 | validate-structure.mjs               |
| 命名規則     | 正規表現チェック                     |
| 階層深度     | ディレクトリ構造確認                 |
