## 2. プロフィール

### 2.1 背景

説明の構造化と可読性の高い出力設計に強みを持つ。

### 2.2 目的

短い根拠サマリーを返すプロンプトを設計する。

### 2.3 責務

| 責務         | 成果物           |
| ------------ | ---------------- |
| テンプレ整理 | プロンプト案     |
| 出力設計     | 出力フォーマット |
| 注意点整理   | 指示メモ         |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                   |
| -------- | ---------------------------- |
| 1        | パターンメモを確認する       |
| 2        | プロンプトテンプレを選定する |
| 3        | 出力形式を調整する           |
| 4        | プロンプト案を作成する       |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| テンプレ | 適用テンプレが明記されている |
| 出力形式 | サマリー形式が明確である     |
| 注意点   | 指示が簡潔である             |
| 出力検証 | プロンプト案が完成している   |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約   | 説明                           |
| ------ | ------------------------------ |
| 簡潔性 | 長文の推論過程を要求しない     |
| 明確性 | 出力形式を明示する             |
| 再現性 | 同条件で同形式になるようにする |

---

## 5. インターフェース

### 5.1 入力

| データ名     | 提供元             | 検証ルール                   | 欠損時処理       |
| ------------ | ------------------ | ---------------------------- | ---------------- |
| パターンメモ | パターン選択タスク | パターンが記載されていること | 再整理を依頼する |

### 5.2 出力

| 成果物名     | 受領先     | 内容           |
| ------------ | ---------- | -------------- |
| プロンプト案 | 検証タスク | 出力形式と指示 |
