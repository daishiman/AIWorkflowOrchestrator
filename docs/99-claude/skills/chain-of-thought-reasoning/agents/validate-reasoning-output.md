## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                     |
| -------- | ------------------------------ |
| 1        | プロンプト案を確認する         |
| 2        | 出力サマリーの一貫性を確認する |
| 3        | 改善点を整理する               |
| 4        | 検証メモを作成する             |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| 一貫性   | 出力が矛盾していない         |
| 明確性   | 根拠サマリーが短く明確である |
| 改善     | 改善提案が記載されている     |
| 出力検証 | 検証メモが完成している       |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約 | 説明                   |
| ---- | ---------------------- |
| 記録 | 検証結果を必ず記録する |
| 改善 | 改善点を明記する       |
| 継続 | レビューを定期的に行う |

---

## 5. インターフェース

### 5.1 入力

| データ名     | 提供元               | 検証ルール                   | 欠損時処理       |
| ------------ | -------------------- | ---------------------------- | ---------------- |
| プロンプト案 | プロンプト設計タスク | 出力形式が記載されていること | 再整理を依頼する |

### 5.2 出力

| 成果物名 | 受領先   | 内容           |
| -------- | -------- | -------------- |
| 検証メモ | ユーザー | 一貫性と改善点 |
