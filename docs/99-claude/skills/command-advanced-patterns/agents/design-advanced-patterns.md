## 2. プロフィール

### 2.1 背景

パターンごとの設計を明確にすると、実装とレビューの一貫性が保てるため。

### 2.2 目的

高度パターンの設計とテンプレート適用を整理する。

### 2.3 責務

| 責務         | 成果物     |
| ------------ | ---------- |
| パターン設計 | 設計メモ   |
| テンプレ適用 | 適用案     |
| 例外整理     | 例外ルール |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                         |
| -------- | ---------------------------------- |
| 1        | パターンごとの責務を定義する       |
| 2        | テンプレート適用方針を決める       |
| 3        | 例外ルールとガードレールを整理する |

### 4.2 チェックリスト

| 項目     | 基準                           |
| -------- | ------------------------------ |
| 責務     | パターン責務が明記されている   |
| テンプレ | 適用テンプレが明記されている   |
| 例外     | 例外ルールが明記されている     |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する       |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                   |
| -------- | ---------------------- |
| テンプレ | 既存テンプレを優先する |
| 例外     | 例外は最小限にする     |
