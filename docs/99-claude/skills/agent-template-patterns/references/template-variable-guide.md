## 概要

エージェントテンプレートで使用する変数の命名規則と使用方法。

## 変数の記法

### 基本形式

```
{{variable_name}}
```

**ルール**:

- 二重中括弧で囲む
- snake_caseを使用
- 説明的な名前を付ける

## 変数カテゴリ

### 1. 基本情報変数

| 変数名                  | 説明                           | 例                           |
| ----------------------- | ------------------------------ | ---------------------------- |
| `{{agent_name}}`        | エージェント名（kebab-case）   | `code-reviewer`              |
| `{{agent_title}}`       | エージェントタイトル（日本語） | `コードレビューエージェント` |
| `{{agent_description}}` | エージェントの説明             | `コード品質を検証`           |
| `{{version}}`           | セマンティックバージョン       | `1.0.0`                      |
| `{{date}}`              | 日付                           | `2025-11-24`                 |

### 2. 設定変数

| 変数名                    | 説明                         | 例                        |
| ------------------------- | ---------------------------- | ------------------------- |
| `{{model}}`               | 使用モデル                   | `sonnet`, `opus`, `haiku` |
| `{{tools_list}}`          | ツールリスト（カンマ区切り） | `Read, Grep, Write`       |
| `{{write_allowed_paths}}` | 書き込み許可パス             | `[".claude/**"]`          |
| `{{approval_required}}`   | 承認要求                     | `true`, `false`           |

### 3. ワークフロー変数

| 変数名               | 説明               | 例                   |
| -------------------- | ------------------ | -------------------- |
| `{{phase_1_name}}`   | Phase 1の名前      | `コード読み込み`     |
| `{{phase_1_step_1}}` | Phase 1のステップ1 | `対象ファイルの特定` |
| `{{phase_1_tool_1}}` | Phase 1のツール1   | `Read`               |
| `{{phase_count}}`    | Phase数            | `3`, `5`, `7`        |

### 4. スキル・依存関係変数

| 変数名                   | 説明               | 例                                              |
| ------------------------ | ------------------ | ----------------------------------------------- |
| `{{skill_1_name}}`       | スキル1の名前      | `code-analysis`                                 |
| `{{skill_1_path}}`       | スキル1のパス      | `code-analysis`                                 |
| `{{dependency_section}}` | 依存関係セクション | `🔴 このエージェント起動時の必須アクション:...` |

### 5. コンテンツ変数

| 変数名                 | 説明                | 例                           |
| ---------------------- | ------------------- | ---------------------------- |
| `{{role_description}}` | 役割の説明          | `コード品質を保証する専門家` |
| `{{specialty_1}}`      | 専門分野1           | `静的解析`                   |
| `{{best_practice_1}}`  | ベストプラクティス1 | `明確な命名を使用`           |
| `{{avoid_1}}`          | 避けるべきこと1     | `過度な複雑性`               |

## 変数の使用例

### テンプレート

```yaml
---
name: {{agent_name}}
description: |
  {{agent_description}}

tools:
  - {{tools_list}}
  - {{tools_list}}
  - {{tools_list}}
model: {{model}}
version: {{version}}
---

# {{agent_title}}

## 役割

{{role_description}}

## 専門分野

- **{{specialty_1}}**: {{specialty_1_description}}
- **{{specialty_2}}**: {{specialty_2_description}}

## ワークフロー

### Phase 1: {{phase_1_name}}

**実施内容**:
1. {{phase_1_step_1}}
2. {{phase_1_step_2}}

**ツール使用**:
- {{phase_1_tool_1}}
```

### インスタンス化

```yaml
---
name: code-reviewer
description: |
  コード品質を検証し、改善提案を提供するエージェント。

tools:
  - Read
  - Grep
  - Write
model: sonnet
version: 1.0.0
---

# コードレビューエージェント

## 役割

コード品質を保証し、ベストプラクティスへの準拠を検証する専門家。

## 専門分野

- **静的解析**: コード構造とパターンの分析
- **品質評価**: コード品質メトリクスの測定

## ワークフロー

### Phase 1: コード読み込み

**実施内容**:
1. 対象ファイルの特定
2. ファイル内容の読み込み

**ツール使用**:
- Read
```

## 変数置換スクリプト

### 基本的な置換

```bash
#!/bin/bash
# instantiate-template.sh

TEMPLATE="templates/agent-template.md"
OUTPUT="output/my-agent.md"

# 変数を置換
sed -e 's/{{agent_name}}/my-agent/g' \
    -e 's/{{agent_title}}/マイエージェント/g' \
    -e 's/{{model}}/sonnet/g' \
    "$TEMPLATE" > "$OUTPUT"
```

### 高度な置換（ファイルから読み込み）

```bash
#!/bin/bash
# instantiate-template.sh

TEMPLATE="$1"
VALUES="$2"
OUTPUT="$3"

# valuesファイルから変数を読み込み
while IFS='=' read -r key value; do
    sed -i "s/{{${key}}}/${value}/g" "$OUTPUT"
done < "$VALUES"
```

**valuesファイル例**:

```
agent_name=code-reviewer
agent_title=コードレビューエージェント
model=sonnet
version=1.0.0
```

## 命名規則

### ✅ 良い変数名

- `{{agent_name}}`: 明確で説明的
- `{{phase_1_step_1}}`: 構造が明確
- `{{write_allowed_paths}}`: 目的が明確

### ❌ 悪い変数名

- `{{x}}`: 意味不明
- `{{temp}}`: 曖昧
- `{{abc123}}`: 非説明的

## ベストプラクティス

### ✅ すべきこと

1. **説明的な命名**: 変数の目的が明確な名前を使用
2. **一貫性**: 同じ概念には同じ変数名を使用
3. **構造化**: カテゴリごとにプレフィックスを使用（`phase_`, `skill_`）
4. **デフォルト値**: 可能な限りデフォルト値を提供
5. **ドキュメント**: すべての変数を表にリスト化

### ❌ 避けるべきこと

1. **短すぎる名前**: `{{a}}`, `{{x}}`
2. **不一致**: 同じ概念に異なる名前
3. **ハードコード**: 変数を使わずに値を直接記述
4. **未定義変数**: 使用する変数を説明しない
