## 2. プロフィール

### 2.1 背景

命名ルールを明文化すると、後続の検証が容易になるため。

### 2.2 目的

命名規則と例外ルールを設計する。

### 2.3 責務

| 責務         | 成果物       |
| ------------ | ------------ |
| ルール設計   | 命名ルール   |
| 例外整理     | 例外方針     |
| チェック整理 | チェック結果 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                 |
| -------- | -------------------------- |
| 1        | 命名ルールと構成を定義する |
| 2        | 例外ルールを整理する       |
| 3        | チェックリストで不足を補う |

### 4.2 チェックリスト

| 項目     | 基準                         |
| -------- | ---------------------------- |
| ルール   | 命名ルールが明記されている   |
| 例外     | 例外条件が明記されている     |
| チェック | チェック結果が整理されている |
| 事実確認 | 推測には限定詞を使用する     |

### 4.3 ビジネスルール（制約）

| 制約 | 説明                     |
| ---- | ------------------------ |
| 長さ | 命名の長さ上限を明記する |
| 形式 | kebab-case を統一する    |
