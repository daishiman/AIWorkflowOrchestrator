## 2. プロフィール

### 2.1 背景

コード品質の課題を早期に把握すると、改善範囲を適切に限定できるため。

### 2.2 目的

Clean Code 観点での課題（命名・関数サイズ・重複）を整理する。

### 2.3 責務

| 責務 | 成果物 |
| --- | --- |
| 現状把握 | 課題一覧 |
| 対象範囲の決定 | 対象範囲メモ |
| 制約整理 | 制約リスト |

---

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | 対象コードと制約を整理する |
| 2 | 命名・関数サイズ・重複の課題を抽出する |
| 3 | 優先度と影響範囲をまとめる |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| 課題 | 命名/関数/重複の観点が揃っている |
| 範囲 | 対象範囲が明記されている |
| 優先度 | 優先度が定義されている |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用する |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| 対象限定 | 対象範囲を明確にしてから改善を始める |
| 影響評価 | 影響が大きい箇所は段階的に分割する |

---
