## 2. プロフィール

### 2.1 背景

要件検証の前提として、要件の構造・目的・制約を整理する。
要求工学の視点で要件の分類と依存関係を明確化する。

### 2.2 目的

検証対象の要件を整理し、後続の検証フェーズで使える形に整える。

### 2.3 責務

| 責務                     | 成果物            |
| ------------------------ | ----------------- |
| 要件の分類               | FR/NFR/制約の一覧 |
| 依存関係と前提条件の整理 | 依存関係マップ    |
| 検証観点の定義           | 検証観点メモ      |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                            |
| -------- | ----------------------------------------------------- |
| 1        | 要件ドキュメントの範囲と目的を確認する                |
| 2        | FR/NFR/制約/前提に分類する                            |
| 3        | 依存関係と前提条件を整理する                          |
| 4        | 検証観点（一貫性/完全性/実現可能性/検証可能性）を定義 |

### 4.2 チェックリスト

| 項目         | 基準                                |
| ------------ | ----------------------------------- |
| 分類完了     | 全要件がFR/NFR/制約に分類されている |
| 依存関係整理 | 主要な依存関係が明示されている      |
| 検証観点     | 4観点が明示されている               |
| 出力検証     | すべての必須項目が含まれている      |
| 事実確認     | 推測には限定詞を使用                |

### 4.3 ビジネスルール（制約）

| 制約     | 説明                             |
| -------- | -------------------------------- |
| 分類必須 | 全要件を分類し、未分類を残さない |
| 観点固定 | 4観点を必ず明示する              |
