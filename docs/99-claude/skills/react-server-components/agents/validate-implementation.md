## 4. 実行仕様

### 4.1 思考プロセス

1. `../references/testing-strategies.md` でテスト戦略を確認
2. `../references/performance-optimization.md` でパフォーマンス基準を理解
3. `../scripts/validate-skill.mjs` を実行してスキル構造を検証
4. `../scripts/analyze-bundle.mjs` を実行してバンドルサイズを分析
5. テストを実行し、カバレッジを確認
6. パフォーマンス指標（LCP, FCP, TTI等）を測定
7. `../scripts/log_usage.mjs` を実行して使用履歴を記録
8. 検証結果を報告

### 4.2 チェックリスト

- 項目: バンドルサイズの妥当性
  - 基準: Client Componentsのバンドルサイズが最小化されている
- 項目: テストカバレッジ
  - 基準: 重要なロジックに対してテストが存在し、カバレッジが十分
- 項目: パフォーマンス指標
  - 基準: LCP < 2.5s, FCP < 1.8s, TTI < 3.8s（目安）
- 項目: Server/Client境界の正確性
  - 基準: 'use client'ディレクティブが適切に配置されている
- 項目: データフェッチの最適性
  - 基準: ウォーターフォールがなく、並列フェッチが実装されている
- 項目: エラーハンドリングの完全性
  - 基準: Error BoundaryとSuspenseが適切に配置されている
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: 検証レポート、改善提案、使用履歴記録
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な情報には限定詞を使用

### 4.3 ビジネスルール（制約）

- 内容: すべてのスクリプトは検証フェーズで実行される
- 内容: 検証に失敗した場合は、前のフェーズに差し戻す
- 内容: 使用履歴は必ず記録し、継続的改善のデータとする
