# ビジョンボード作成ガイド

## 概要

ビジョンボードは、製品ビジョンを視覚的に表現し、チーム全体で共有するためのツール。ビジョンステートメントを中心に、ターゲット顧客、ニーズ、製品属性、ビジネスゴールを整理します。

## ビジョンボードの構成要素

### 1. ビジョンステートメント

製品の究極的な目的を1-2文で表現。

**良い例**:

- "リモートワークを自然で生産的な体験に変える"
- "すべての開発者がAIを活用できる世界を創る"

**悪い例**:

- "最高のプロダクトを作る"（抽象的すぎる）
- "機能A、B、Cを持つツールを提供する"（機能列挙）

### 2. ターゲット顧客

誰のためのプロダクトか？

```
セグメント: リモートワーカー
ペルソナ: 佐藤健太、32歳、フロントエンドエンジニア
特徴:
  - 週5日リモートワーク
  - 3つのプロジェクトを並行
  - Slackとビデオ会議に疲れている
```

### 3. 顧客ニーズと課題

ターゲット顧客が抱える主要な課題。

**フレームワーク: Jobs-to-be-Done**

```
状況: チーム全体の進捗を把握したい時
課題: 各メンバーに個別確認が必要で時間がかかる
期待する成果: リアルタイムで全員の状況を一覧できる
```

### 4. 製品属性

製品が持つべき主要な特徴と差別化要素。

- **必須属性**: なければ製品として成立しない
- **差別化属性**: 競合と差別化できる独自性
- **魅力的属性**: あると嬉しいが必須ではない

**例**:

- 必須: リアルタイム同期
- 差別化: AIによる自動要約
- 魅力的: カスタマイズ可能なテーマ

### 5. ビジネスゴール

プロダクトが会社にもたらす価値。

```
収益目標: 12ヶ月でMRR $100K達成
市場シェア: リモートツール市場で5%獲得
戦略的意義: エンタープライズ市場への参入足がかり
```

## ビジョンボード作成プロセス

### Step 1: 準備（1-2時間）

**必要な情報を収集**:

- ユーザーインタビューの洞察
- 市場調査データ
- 競合分析
- 既存プロダクトのメトリクス（既存製品の場合）

**参加者を招集**:

- プロダクトマネージャー
- デザインリード
- エンジニアリングリード
- ビジネスステークホルダー

### Step 2: ドラフト作成（2-3時間）

**ワークショップ形式で各要素を埋める**:

1. **ビジョンステートメント**（30分）
   - 各自がドラフトを作成
   - 投票で上位3つを選択
   - ディスカッションで最終版を決定

2. **ターゲット顧客**（30分）
   - ペルソナを2-3個作成
   - 最も重要な1つを選択

3. **顧客ニーズ**（40分）
   - ポストイットでニーズをブレインストーミング
   - グルーピングして優先順位付け
   - 上位3-5個を選択

4. **製品属性**（40分）
   - 必須/差別化/魅力的の3カテゴリに分類
   - 各カテゴリで最重要項目を特定

5. **ビジネスゴール**（20分）
   - 測定可能な目標を設定
   - 時間軸を明確化

### Step 3: レビューと調整（1週間）

**フィードバック収集**:

- エグゼクティブレビュー
- チームレビュー
- 顧客への検証（可能であれば）

**調整**:

- フィードバックを反映
- 矛盾や曖昧さを解消

### Step 4: 確定と共有

**文書化**:

- `assets/vision-board-template.md` を使用
- ビジュアル化（図や画像を追加）

**共有**:

- チーム全体に発表
- Wiki/Notionに掲載
- 定期的に参照（スプリント開始時など）

## ビジョンボードの活用方法

### 意思決定の指針

**判断基準として使用**:

```
機能Xを実装すべきか？
  → ビジョンと整合性があるか？
  → ターゲット顧客のニーズに応えるか？
  → 製品属性に合致するか？
```

### チームの整列

**新メンバーのオンボーディング**:

- ビジョンボードを最初に共有
- 製品の方向性を理解してもらう

**定期的な振り返り**:

- 四半期ごとにビジョンボードを見直し
- 製品の進化に応じて更新

### ステークホルダーコミュニケーション

**説明資料として活用**:

- 投資家へのピッチ
- パートナーとの提携交渉
- 採用時の会社説明

## ビジョンボードのテンプレート

```markdown
# [プロダクト名] ビジョンボード

## ビジョンステートメント

[1-2文で製品が目指す姿を表現]

## ターゲット顧客

- **セグメント**: [誰のためのプロダクトか]
- **ペルソナ**: [具体的な人物像]
- **特徴**: [主要な属性]

## 顧客ニーズと課題

1. [最重要ニーズ/課題]
2. [第2のニーズ/課題]
3. [第3のニーズ/課題]

## 製品属性

- **必須**: [なければ成立しない機能]
- **差別化**: [競合との差別化要素]
- **魅力的**: [あると嬉しい機能]

## ビジネスゴール

- **収益目標**: [数値目標]
- **市場シェア**: [目標シェア]
- **戦略的意義**: [会社戦略への貢献]
```

## よくある落とし穴

### 抽象的すぎるビジョン

❌ "世界中の人々に価値を提供する"
✅ "非エンジニアがノーコードでAPIを統合できるようにする"

### 機能リストになってしまう

❌ "チャット、ファイル共有、タスク管理を持つツール"
✅ "チームのコンテキストを自動で共有し、非同期コラボレーションを実現"

### ビジネスゴールが曖昧

❌ "市場リーダーになる"
✅ "24ヶ月でSMB市場の10%シェア獲得、MRR $500K達成"

### ターゲットが広すぎる

❌ "すべてのビジネスパーソン"
✅ "10-50人規模のスタートアップの営業チーム"

## チェックリスト

- [ ] ビジョンステートメントは1-2文で簡潔
- [ ] ターゲット顧客が具体的なペルソナで定義されている
- [ ] 顧客ニーズが3-5個に絞られている
- [ ] 製品属性が必須/差別化/魅力的に分類されている
- [ ] ビジネスゴールが測定可能
- [ ] 全要素が互いに整合性がある
- [ ] チームメンバー全員が理解・納得している
