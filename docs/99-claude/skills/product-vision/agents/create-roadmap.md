# Task: ロードマップ作成

## メタデータ

- **Task ID**: create-roadmap
- **Phase**: Phase 3
- **所要時間**: 4-6時間（優先順位付け含む）
- **前提条件**: OKR設定完了、ビジョンボード完成

## 目的

OKR達成のための主要イニシアチブを特定し、優先順位付けと時系列計画を策定する。

## 入力

### 必須

- プロダクトビジョンボード
- 四半期OKR
- ユーザーフィードバック
- プロダクトメトリクス

### 推奨

- 競合分析
- 技術的制約
- リソース計画（人員、予算）
- ステークホルダー要望

## 出力

### 成果物

1. **プロダクトロードマップ**
   - 6-12ヶ月の戦略ロードマップ
   - Now-Next-Later形式または四半期形式
2. **イニシアチブリスト**
   - 各イニシアチブの詳細（目的、成果指標、主要施策、工数、RICE スコア）
3. **ステークホルダー別ロードマップ**（必要に応じて）
   - 経営陣向け
   - エンジニアリング向け
   - 営業/マーケティング向け

### 形式

Markdown形式、テーブルやタイムラインを使用

## 実行手順

### Step 1: イニシアチブの特定（1-2時間）

**必要な情報を収集**:

```bash
# 参照すべきリソース
cat .claude/skills/product-vision/references/basics.md
cat .claude/skills/product-vision/references/roadmap-planning.md

# テンプレートの準備
cp .claude/skills/product-vision/assets/roadmap-template.md \
   docs/roadmaps/YYYY-H[1-2]-roadmap.md
```

**ブレインストーミング**:

OKR達成のための施策を列挙:

1. 各OKRについて「どうすれば達成できるか？」を問う
2. ユーザー価値の高い改善を抽出
3. 技術的負債の解消項目を特定

**イニシアチブの文書化**:

各イニシアチブを以下の形式で記述:

```markdown
## イニシアチブ名: [名前]

**目的**: [なぜこれをやるのか]
**成果指標**: [どう測定するか]
**主要施策**:

- [施策1]
- [施策2]
- [施策3]
  **期間**: [見積もり期間]
  **依存関係**: [前提条件や他イニシアチブとの関連]
```

### Step 2: 優先順位付け（2-3時間）

**RICE フレームワークを使用**:

```
RICE Score = (Reach × Impact × Confidence) / Effort
```

**各要素の評価**:

- **Reach（到達範囲）**: 何人のユーザーに影響するか（月間）
- **Impact（影響度）**: 各ユーザーへの影響
  - 3 = 大きい影響
  - 2 = 中程度の影響
  - 1 = 小さい影響
  - 0.5 = 最小限の影響
- **Confidence（確信度）**: 成功の確信
  - 100% = 高い確信
  - 80% = 中程度の確信
  - 50% = 低い確信
- **Effort（工数）**: 人月単位の工数

**計算例**:

```
イニシアチブA: リファラルプログラム
  Reach: 10,000ユーザー
  Impact: 2（中程度の影響）
  Confidence: 80%
  Effort: 2人月
  RICE: (10,000 × 2 × 0.8) / 2 = 8,000

イニシアチブB: エンタープライズSSO
  Reach: 500ユーザー（エンタープライズ）
  Impact: 3（大きな影響）
  Confidence: 100%
  Effort: 4人月
  RICE: (500 × 3 × 1.0) / 4 = 375
```

**優先順位リストの作成**:

RICEスコアが高い順にソート。

### Step 3: タイムライン設定（1時間）

**原則**:

- 日付ではなく「順序」を重視
- バッファを含める（予期せぬ問題用）
- 依存関係を考慮

**Now-Next-Later形式**:

```
Now（現在-6週間）:
  - [イニシアチブ1]
  - [イニシアチブ2]

Next（6週間-3ヶ月）:
  - [イニシアチブ3]
  - [イニシアチブ4]

Later（3ヶ月以降）:
  - [イニシアチブ5]
  - [イニシアチブ6]
```

または**四半期形式**:

```
Q1: [テーマ]
  成果: [OKR Key Result]
  施策:
    - [イニシアチブ1]
    - [イニシアチブ2]

Q2: [テーマ]
  成果: [OKR Key Result]
  施策:
    - [イニシアチブ3]
    - [イニシアチブ4]
```

### Step 4: ロードマップの可視化（1時間）

**メインロードマップ**:

`assets/roadmap-template.md` を使用して作成。

**OKR連動の確認**:

各イニシアチブがどのOKR Key Resultに貢献するか明記:

```
イニシアチブ: リファラルプログラム
貢献するKR: MAUを10,000から25,000に増加
```

**依存関係の図示**:

```
ダッシュボード刷新
  ↓ (前提)
API v2リリース
  ↓ (前提)
サードパーティ統合
```

### Step 5: ステークホルダー別バージョン作成（必要に応じて、1時間）

**経営陣向け**:

- 高レベル（テーマとマイルストーン）
- ビジネス影響、収益への貢献を強調

**エンジニアリング向け**:

- 詳細（機能レベル）
- 技術的依存関係、必要なスキルセットを明記

**営業/マーケティング向け**:

- 中レベル（主要機能）
- 顧客訴求力、競合差別化を強調

## 成功基準

- [ ] 全イニシアチブがOKRに紐付いている
- [ ] 優先順位付けの根拠が明確（RICEスコア等）
- [ ] 依存関係が明記されている
- [ ] 柔軟性を持たせている（日付固定を避ける）
- [ ] ステークホルダーごとに適切な粒度
- [ ] チーム全員が理解・納得している
- [ ] 定期的な更新プロセスが確立されている

## よくある落とし穴

### 機能リストになる

❌ **悪い例**:

```
Q1: ダークモード、絵文字サポート、エクスポート機能
```

✅ **良い例**:

```
Q1: ユーザーエクスペリエンスの向上
  目標: ユーザー満足度70%→90%
  施策: カスタマイゼーション強化、アクセシビリティ改善
```

### 詳細すぎる

ロードマップは「戦略的計画」であり、「実装計画」ではありません。

❌ 各機能のUIモックアップまで含める
✅ イニシアチブの目的と期待される成果を示す

### 日付へのコミットメント

❌ "機能Xは5月15日リリース"
✅ "機能Xは Q2にリリース予定"

### OKRとの乖離

すべてのイニシアチブは、OKR達成に貢献すべきです。

## トラブルシューティング

### 問題: イニシアチブが多すぎる

**対処**:

- RICEスコアで上位20%に絞る
- "Later"に多くを配置
- 一部は次の四半期に延期

### 問題: リソース不足

**対処**:

- イニシアチブのスコープを縮小
- MVPアプローチ（最小限の機能で始める）
- 外部リソースの活用（外注、パートナー）

### 問題: 依存関係が複雑

**対処**:

- 依存関係図を作成
- クリティカルパスを特定
- ブロッカーを優先的に解消
