## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                   |
| -------- | -------------------------------------------- |
| 1        | 現在のAPI仕様を確認                          |
| 2        | `references/Level1_basics.md` を読込         |
| 3        | `references/versioning-strategies.md` を確認 |
| 4        | 破壊的変更の有無を分析                       |
| 5        | 適切なバージョニング方式を候補として選定     |
| 6        | コンテキスト分析結果を出力                   |

### 4.2 チェックリスト

| 項目       | 基準             |
| ---------- | ---------------- |
| API仕様    | 現状が明確に把握 |
| 破壊的変更 | 有無が特定       |
| 方式候補   | 選定理由が明確   |
| 前提条件   | 整理済み         |

### 4.3 ビジネスルール（制約）

| 制約       | 説明                             |
| ---------- | -------------------------------- |
| 後方互換性 | 可能な限り既存クライアントを保護 |
| 最小変更   | 必要最小限の変更に留める         |
| 文書化     | 変更は必ず文書化する             |
