> 相対パス: `references/event-design-guide.md`
> 原典: Domain-Driven Design (Eric Evans), Implementing DDD (Vaughn Vernon)

---

## イベント設計原則

| 原則     | 説明                       | 例                               |
| -------- | -------------------------- | -------------------------------- |
| 不変性   | 一度記録したら変更しない   | イベントは追記のみ               |
| 自己完結 | 必要十分な情報を含める     | 参照IDだけでなく値も含める       |
| 業務意味 | ビジネス的に意味のある変更 | OrderUpdated ❌ → OrderPlaced ✅ |
| 過去形   | 起こった事実を表現         | PlaceOrder ❌ → OrderPlaced ✅   |

---

## イベント命名規則

```typescript
// ✅ 良い例: 過去形・業務イベント
OrderPlaced;
PaymentProcessed;
ShipmentDispatched;
CustomerRegistered;

// ❌ 悪い例: 命令形・技術的
PlaceOrder; // 命令形（コマンド名）
OrderUpdated; // 何が更新されたか不明
DataChanged; // 技術的すぎる
```

## イベントスキーマ

### 必須フィールド

| フィールド  | 型     | 説明               |
| ----------- | ------ | ------------------ |
| type        | string | イベント種別       |
| version     | number | スキーマバージョン |
| timestamp   | Date   | 発生日時           |
| aggregateId | string | 対象アグリゲートID |

### メタデータ

| フィールド    | 用途               |
| ------------- | ------------------ |
| correlationId | リクエストトレース |
| causationId   | 因果関係追跡       |
| userId        | 実行者識別         |

---

## イベント粒度

| レベル | 説明           | 例                          |
| ------ | -------------- | --------------------------- |
| 細かい | 個別属性変更   | AddressChanged, NameChanged |
| 粗い   | 集約された変更 | CustomerProfileUpdated      |

**推奨**: ビジネス境界で分割（細かすぎず粗すぎず）

---

## バージョニング戦略

| 戦略              | 説明                     | 用途           |
| ----------------- | ------------------------ | -------------- |
| versionフィールド | イベントにバージョン番号 | 一般的         |
| タイプ名変更      | OrderPlacedV2            | 大きな変更時   |
| アップキャスト    | 読取時に変換             | 後方互換性維持 |

---

## アンチパターン

| パターン       | 問題                 | 対策               |
| -------------- | -------------------- | ------------------ |
| 巨大ペイロード | ストレージ増加       | 参照IDを使用       |
| CRUD的イベント | 意味が不明確         | ビジネスイベント化 |
| 同期待機       | スケーラビリティ低下 | 非同期処理         |
| バージョン無視 | 進化困難             | 初日から設計       |
