## Entity

### 定義

ライフサイクルを通じて**同一性（Identity）**を持つオブジェクト。

### 判断基準

| 基準       | Entity   | Value Object |
| ---------- | -------- | ------------ |
| 識別子     | 必須     | 不要         |
| 同一性判定 | IDで判定 | 属性値で判定 |
| 可変性     | 変更可能 | 不変         |

---

## Value Object

### 定義

**属性値のみ**で識別されるオブジェクト。不変で、等価性は全属性の比較で判定。

### 設計原則

| 原則       | 説明                   |
| ---------- | ---------------------- |
| 不変性     | 生成後に変更不可       |
| 等価性     | 全属性で判定           |
| 自己検証   | 生成時にバリデーション |
| 副作用なし | 変更は新インスタンス   |

---

## Aggregate

### 定義

**トランザクション整合性**を保つ単位。集約ルートを通じてのみアクセス可能。

### 設計4ルール（Vernon）

| ルール             | 説明                   |
| ------------------ | ---------------------- |
| 真の不変条件を守る | 集約内で整合性を保証   |
| 小さな集約を設計   | 1-3エンティティ程度    |
| ID参照を使用       | 集約間は直接参照しない |
| 結果整合性を使用   | 集約間は非同期で整合   |

---

## Repository

### 定義

集約の永続化と取得を抽象化するインターフェース。

### 設計原則

| 原則           | 説明               |
| -------------- | ------------------ |
| 集約単位       | 集約ルートのみ扱う |
| ドメイン層配置 | IFはドメイン層     |
| 実装は外部     | インフラ層で実装   |

---

## Domain Service

### 定義

特定のEntityやVOに属さない**ドメインロジック**を表現。

### 使用条件

| 条件               | 説明                 |
| ------------------ | -------------------- |
| 複数集約にまたがる | 単一集約に収まらない |
| ステートレス       | 状態を持たない       |
| ドメイン言語       | 技術用語を使わない   |
