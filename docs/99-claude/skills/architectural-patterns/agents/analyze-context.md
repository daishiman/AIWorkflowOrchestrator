## 4. 実行仕様

### 4.1 思考プロセス

1. 目的と主要制約を列挙する
2. 現状の構造（レイヤー/境界）を要約する
3. 変更頻度と影響範囲を整理する
4. パターン選定に必要な前提を提示する

### 4.2 チェックリスト

- 項目: 目的と制約が整理されている
  - 基準: 目的と制約が箇条書きで明示されている
- 項目: 現状構造が要約されている
  - 基準: レイヤー構成が1段落で説明できる
- 項目: 出力検証
  - 基準: 次タスクが判断できる情報が含まれる
- 項目: 事実確認
  - 基準: 推測には「想定」を付ける

### 4.3 ビジネスルール（制約）

- 内容: 制約を省略しない
- 内容: 推測を結論として断定しない
- 内容: 現状の変更影響を明記する

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 現状構造
- 提供元: ユーザー
- 検証ルール:
  主要レイヤーと責務が説明されていること。
- 拒否すべき入力:
  具体的な構造が不明な記述のみ。
- 欠損時処理:
  レイヤー構成の提示を依頼する。

#### 入力2

- データ名: 制約条件
- 提供元: ユーザー
- 検証ルール:
  技術・運用・組織の制約が含まれること。
- 拒否すべき入力:
  制約が一切記載されていない内容。
- 欠損時処理:
  制約一覧の提示を依頼する。

### 5.2 出力

#### 成果物1

- 成果物名: コンテキスト要約
- 受領先: パターン選定タスク
- 出力テンプレート:

  ```markdown
  ## コンテキスト要約

  ### 目的

  - {目的1}

  ### 制約

  - {制約1}

  ### 現状構造

  - レイヤー構成: {説明}

  ### 変更影響

  - {影響範囲}
  ```

- 内容:
  目的・制約・現状構造を簡潔にまとめる。
