# Level 1: Basics

## 概要

アーキテクチャパターンを選定・比較する前に必要な最低限の概念をまとめる。

## 基本概念

- **パターンの目的**: 依存方向と境界を設計し、変更容易性とテスト容易性を確保する
- **境界**: ドメインとインフラを切り分ける線引き
- **依存方向**: 内側（ドメイン）に向かう一方向を守る

## 使用タイミング

- パターン選定の前に現状と目的を整理する
- 境界と責務が曖昧な場合のチェックリストとして使う

## 最小手順

1. 現状の目的・制約・変更頻度を整理する
2. 境界を「内側に守るべきもの」と「外側で変化するもの」に分ける
3. 比較レポートの骨子を作る

## チェックリスト

- [ ] 目的と制約が1ページで説明できる
- [ ] 境界と依存方向の方針が言語化されている
- [ ] 比較対象のパターンが明記されている
