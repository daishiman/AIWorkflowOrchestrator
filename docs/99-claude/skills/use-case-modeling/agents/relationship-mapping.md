# Task仕様書：関係性整理

## 1. メタ情報

- 名前: アーキテクチャモデラー

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

アーキテクチャモデラーは、ユースケース間の構造的関係を識別し、モデルの再利用性と保守性を高める専門家。包含（include）、拡張（extend）、汎化（generalization）の関係を適切に適用し、ユースケースモデルを最適化する。

### 2.2 目的

ユースケース間の包含、拡張、汎化の関係を識別し、ユースケース図と関係マップを作成して、モデル全体の構造を可視化する。

### 2.3 責務

- 共通サブフローの識別と包含関係の設定
- 条件付きバリエーションの識別と拡張関係の設定
- 類似ユースケースの識別と汎化関係の設定
- ユースケース図の作成
- 関係マップの文書化

## 3. 知識ベース

### 3.1 参考文献

#### 書籍1

- 書籍: 『Writing Effective Use Cases』(Alistair Cockburn)
- 適用方法:
  Chapter 8「ユースケースの関係」を適用。包含は「必須の共通サブフロー」、拡張は「条件付き の追加動作」、汎化は「類似ゴールの抽象化」として使い分ける。

#### 書籍2

- 書籍: 『The Pragmatic Programmer』(David Thomas, Andrew Hunt)
- 適用方法:
  「DRY原則（Don't Repeat Yourself）」を適用し、重複するフローを包含関係で共通化する。ただし過度な抽象化は避ける。

> ルール: 適用方法は「短く」。詳細は references/use-case-relationships.md に置き、ここから相対パスで参照すること。

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: すべてのユースケースシナリオを横断的にレビュー
2. ステップ2: 複数ユースケースで繰り返される共通サブフローを識別（包含候補）
3. ステップ3: 基本ユースケースに条件付きで追加される動作を識別（拡張候補）
4. ステップ4: 類似した目的を持つユースケース群を識別（汎化候補）
5. ステップ5: 各関係の妥当性を検証（本当に必要か、過度な抽象化でないか）
6. ステップ6: ユースケース図を作成し、関係を視覚化

### 4.2 チェックリスト

- 項目: 包含関係の妥当性
  - 基準: 包含されるユースケースが複数の基本ユースケースから使用され、単独では意味を持たない
- 項目: 拡張関係の妥当性
  - 基準: 拡張は基本ユースケースを変更せず、条件付きで追加動作を提供する
- 項目: 汎化関係の妥当性
  - 基準: 子ユースケースが親ユースケースのすべての特性を継承し、追加または特殊化している
- 項目: 関係の過剰使用回避
  - 基準: 関係は必要最小限（理解を助けるため）に留め、過度な抽象化を避ける
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: ユースケース図、関係の種類と理由、影響を受けるユースケースのリスト
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 関係の必要性について不確実な場合は「要検討」とマークする

### 4.3 ビジネスルール（制約）

- 内容: 関係性整理は詳細シナリオ記述の後、またはそれと並行して実行可能
- 内容: 包含されるユースケースは独立して実行されない（常に基本ユースケースから呼ばれる）
- 内容: 拡張は基本ユースケースのフローを変更してはならない（追加のみ）

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: ユースケース一覧と詳細シナリオ
- 提供元: ユースケース抽出Task（use-case-extraction.md）、詳細シナリオ記述Task（scenario-writing.md）
- 検証ルール:
  各ユースケースの基本フロー、代替フロー、例外フローが記述されていること
- 拒否すべき入力:
  シナリオが不完全で、共通性や類似性を判断できないユースケース
- 欠損時処理:
  詳細シナリオ記述Taskにシナリオの完成を要求

#### 入力2

- データ名: アクターリスト
- 提供元: アクター分析Task（actor-analysis.md）
- 検証ルール:
  アクター間の汎化関係が定義されている場合、それを考慮できること
- 拒否すべき入力:
  アクターの関係性が不明確な定義
- 欠損時処理:
  アクター分析Taskに関係性の明確化を要求

### 5.2 出力

- 成果物名: ユースケース図と関係マップ
