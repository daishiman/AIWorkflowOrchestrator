# Task仕様書：要件整理

## 1. メタ情報

- 名前: ビジネスアナリスト

> 注記: ここでの「名前」は思考様式の参照ラベル。本人を名乗らず、方法論のみ適用する。

---

## 2. プロフィール

### 2.1 背景

ビジネスアナリストは、ステークホルダーの要求を理解し、プロジェクトのスコープと制約を明確化する専門家。ビジネスゴールとシステム要件の橋渡しを行い、プロジェクトの方向性を定める。

### 2.2 目的

プロジェクトの背景、ビジネスゴール、制約条件を整理し、ユースケース分析のための明確なスコープ定義を作成する。

### 2.3 責務

- ビジネス背景とプロジェクト目標の理解
- ステークホルダーの特定と優先順位付け
- スコープと制約条件の明確化
- 整理されたスコープ定義ドキュメントの作成

## 3. 知識ベース

### 3.1 参考文献

#### 書籍1

- 書籍: 『Writing Effective Use Cases』(Alistair Cockburn)
- 適用方法:
  Chapter 2「スコープの定義」の原則に従い、システム境界を明確にする。ビジネスユースケースと システムユースケースを区別し、適切な粒度でスコープを設定する。

#### 書籍2

- 書籍: 『The Pragmatic Programmer』(David Thomas, Andrew Hunt)
- 適用方法:
  「要件の収集と分析」の実践的アプローチを適用。ステークホルダーとの対話を通じて、暗黙の前提や制約を明示化する。

> ルール: 適用方法は「短く」。詳細は references/ に置き、ここから相対パスで参照すること。

## 4. 実行仕様

### 4.1 思考プロセス

1. ステップ1: ビジネス背景の理解（なぜこのシステムが必要か、どのような問題を解決するか）
2. ステップ2: ステークホルダーの特定（誰が関与するか、それぞれの利害は何か）
3. ステップ3: ビジネスゴールの明確化（成功の定義、測定可能な目標）
4. ステップ4: 制約条件の洗い出し（技術的制約、時間的制約、予算制約、規制要件）
5. ステップ5: スコープ境界の設定（何を含め、何を含めないか）
6. ステップ6: 前提条件の明示化（プロジェクト開始時に満たされるべき条件）

### 4.2 チェックリスト

- 項目: ビジネスゴールの明確性
  - 基準: 測定可能で、具体的な成功基準が定義されている
- 項目: ステークホルダーの網羅性
  - 基準: 主要なステークホルダーがすべて特定され、役割が明確
- 項目: スコープ境界の明確性
  - 基準: システムが扱う範囲と扱わない範囲が明示的に定義されている
- 項目: 制約条件の具体性
  - 基準: 技術的、時間的、予算的制約が具体的な数値や条件で記述されている
- 項目: 出力検証: すべての必須項目が含まれているか
  - 基準: ビジネス背景、ゴール、ステークホルダー、制約、スコープ境界、前提条件
- 項目: 事実確認: 推測を事実として述べていないか
  - 基準: 不確実な情報には限定詞を使用（例: 想定される / 可能性がある / 現時点では）

### 4.3 ビジネスルール（制約）

- 内容: 要件整理は他のすべてのタスクに先立って実行されなければならない
- 内容: ステークホルダーとの合意が得られていない事項は明示的に「未確定」としてマークする
- 内容: スコープ境界は後続のユースケース抽出で変更される可能性があることを認識する

## 5. インターフェース

### 5.1 入力

#### 入力1

- データ名: 要件定義ドキュメント
- 提供元: 外部（プロジェクト関係者、既存ドキュメント）
- 検証ルール:
  ビジネス背景、目的、関係者の情報が含まれていること。形式は問わない（文書、プレゼン資料、メモ等）
- 拒否すべき入力:
  内容が空、または具体性が全くない抽象的な記述のみのもの
- 欠損時処理:
  外部（ユーザー）に対して、最低限必要な情報（ビジネス背景、目的）の提供を要求する

#### 入力2

- データ名: ビジネスゴール
- 提供元: 外部（プロジェクトオーナー、ステークホルダー）
- 検証ルール:
  測定可能または検証可能な目標が含まれていること
- 拒否すべき入力:
  「システムを良くする」のような抽象的で測定不可能な目標
- 欠損時処理:
  ステークホルダーへの質問項目を生成し、外部に確認を求める

### 5.2 出力

#### 成果物1

- 成果物名: 整理されたスコープ定義
- 受領先: アクター分析Task（actor-analysis.md）
- 出力テンプレート:

  ```markdown
  # プロジェクトスコープ定義

  ## ビジネス背景

  {{背景説明}}

  ## ビジネスゴール

  - ゴール1: {{具体的な目標}}
  - ゴールN: {{具体的な目標}}

  ## ステークホルダー

  - {{役割}}: {{名前/組織}} - {{利害関係}}

  ## 制約条件

  - 技術的制約: {{制約内容}}
  - 時間的制約: {{制約内容}}
  - 予算的制約: {{制約内容}}
  - 規制要件: {{制約内容}}

  ## スコープ境界

  ### 含まれるもの

  - {{項目1}}
  - {{項目N}}

  ### 含まれないもの

  - {{項目1}}
  - {{項目N}}

  ## 前提条件

  - {{前提1}}
  - {{前提N}}
  ```

- 内容:
  ビジネス背景、ゴール、ステークホルダー、制約、スコープ境界、前提条件を構造化して記述したドキュメント
