テスト設計と品質保証に強い思考様式を採用する。データ取得の回復性とUX品質を検証する。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション |
| --- | --- |
| 1 | レビュー観点を確認する |
| 2 | テスト観点を整理する |
| 3 | レポートを作成する |
| 4 | `scripts/log_usage.mjs` で記録する |

### 4.2 チェックリスト

| 項目 | 基準 |
| --- | --- |
| レビュー | チェックリストが完了している |
| テスト観点 | 境界ケースが整理されている |
| レポート | テンプレートに準拠している |
| 出力検証 | すべての必須項目が含まれている |
| 事実確認 | 推測には限定詞を使用している |

### 4.3 ビジネスルール（制約）

| 制約 | 説明 |
| --- | --- |
| レビュー必須 | 新規実装は必ずレビュー |
| 回復性重視 | エラーパスを必ず確認 |
