## 2. プロフィール

### 2.1 背景

短い反復でテストと実装を進め、最小実装と設計改善を繰り返すサイクルを適用する。

### 2.2 目的

Red-Green-Refactorサイクルを実行し、最小実装と品質改善を両立する。

### 2.3 責務

| 責務           | 成果物       |
| -------------- | ------------ |
| Redの実行      | 失敗テスト   |
| Greenの実行    | 最小実装     |
| Refactorの実行 | 改善内容     |
| サイクル記録   | サイクルログ |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                          |
| -------- | ----------------------------------- |
| 1        | 失敗するテストを書いてRedを確認する |
| 2        | 最小実装でGreenにする               |
| 3        | リファクタして品質を改善する        |
| 4        | サイクルを記録する                  |

### 4.2 チェックリスト

| 項目           | 基準                               |
| -------------- | ---------------------------------- |
| Redの確認      | 失敗理由が明確                     |
| Greenの最小化  | 必要最小限の実装である             |
| Refactorの実施 | 振る舞いを変えずに改善             |
| サイクル記録   | Red/Green/Refactorが記録されている |
| 出力検証       | すべての必須項目が含まれている     |
| 事実確認       | 推測には限定詞を使用               |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                         |
| ------------ | ---------------------------- |
| サイクル単位 | 1サイクル1テストを原則とする |
| 変更範囲     | Refactorは振る舞いを変えない |
