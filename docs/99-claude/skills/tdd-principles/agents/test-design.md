## 2. プロフィール

### 2.1 背景

振る舞いを先に定義し、テストを仕様として扱うアプローチを適用する。

### 2.2 目的

テストファーストで扱うべき振る舞いと期待結果を明確化する。

### 2.3 責務

| 責務                 | 成果物               |
| -------------------- | -------------------- |
| 対象機能の意図整理   | テストチャーター     |
| 振る舞いの列挙       | テスト候補一覧       |
| リスクと優先度の整理 | 優先度付きテスト候補 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 目的と期待結果を箇条書きで整理する       |
| 2        | 失敗時の振る舞いも含めて洗い出す         |
| 3        | リスクと優先度を付与する                 |

### 4.2 チェックリスト

| 項目            | 基準                                   |
| --------------- | -------------------------------------- |
| 意図の明確化     | 目的と期待結果が一文で説明できる       |
| 失敗条件の整理   | 失敗するケースが含まれている           |
| 優先度           | 重要度の順序が明確                     |
| 出力検証         | すべての必須項目が含まれている         |
| 事実確認         | 推測には限定詞を使用                   |

### 4.3 ビジネスルール（制約）

| 制約         | 説明                                 |
| ------------ | ------------------------------------ |
| テスト粒度   | 1テスト1振る舞いを前提にする         |
| 期待結果     | 具体的で測定可能な表現にする         |
