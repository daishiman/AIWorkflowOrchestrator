# エラー分類ガイド

## 概要

エラーを適切に分類することで、リトライ可否、ログレベル、ユーザーへの通知方法を一貫して決定できる。

## エラーカテゴリ

### 1. Validation Error (1000-1999)

**定義**: クライアントからの入力が不正

**特徴**:

- リトライ不可（同じ入力では同じエラー）
- HTTPステータス: 400/422
- ログレベル: INFO/WARN

**例**:

- 必須フィールドの欠落
- スキーマ違反
- 型不一致
- 範囲外の値

### 2. Business Error (2000-2999)

**定義**: ビジネスルール違反

**特徴**:

- リトライ不可（状態変更が必要）
- HTTPステータス: 403/404/409
- ログレベル: INFO

**例**:

- 権限不足
- リソース不存在
- 重複作成
- 状態遷移不可

### 3. External Service Error (3000-3999)

**定義**: 外部サービスの障害

**特徴**:

- リトライ可能
- HTTPステータス: 502/503/504
- ログレベル: WARN/ERROR

**例**:

- API タイムアウト
- レート制限
- サービス停止
- ネットワークエラー

### 4. Infrastructure Error (4000-4999)

**定義**: インフラストラクチャの障害

**特徴**:

- リトライ可能（一時的な場合）
- HTTPステータス: 500/503
- ログレベル: ERROR

**例**:

- DB接続失敗
- ファイルシステムエラー
- メモリ不足
- ディスクフル

### 5. Internal Error (5000-5999)

**定義**: 予期しないエラー（バグ）

**特徴**:

- リトライ不可
- HTTPステータス: 500
- ログレベル: ERROR/CRITICAL

**例**:

- NullPointerException
- 型アサーションエラー
- 実装バグ

## 判定フローチャート

```
エラー発生
    ↓
入力に問題があるか？ → Yes → Validation Error
    ↓ No
ビジネスルール違反か？ → Yes → Business Error
    ↓ No
外部サービス起因か？ → Yes → External Service Error
    ↓ No
インフラ起因か？ → Yes → Infrastructure Error
    ↓ No
Internal Error
```
