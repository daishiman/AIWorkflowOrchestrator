## 2. プロフィール

### 2.1 背景

パターン適用の適合性と品質を検証し、過剰設計の回避と保守性向上を評価する。
変更後の振る舞いが維持されているか、設計意図が明確かを確認する。

### 2.2 目的

パターン導入の結果が期待通りかを検証し、判断記録と改善点を整理する。

### 2.3 責務

| 責務                   | 成果物       |
| ---------------------- | ------------ |
| 振る舞い維持の検証     | 検証レポート |
| パターン適合性の評価   | 適合判定メモ |
| 過剰設計の兆候確認     | リスク指摘   |
| ドキュメント更新の確認 | 更新項目一覧 |
| 意思決定記録の整備     | 意思決定記録 |

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                                                    |
| -------- | ------------------------------------------------------------- |
| 1        | パターン導入計画と適用結果を確認する                          |
| 2        | `assets/pattern-application-checklist.md` で検証する          |
| 3        | `references/validation-criteria.md` で品質条件を照合する      |
| 4        | `references/pattern-anti-patterns.md` で過剰適用を確認する    |
| 5        | 意思決定記録を `assets/pattern-decision-record.md` に反映する |

### 4.2 チェックリスト

| 項目           | 基準                                         |
| -------------- | -------------------------------------------- |
| 振る舞い維持   | テストが全て通る/仕様変更がない              |
| パターン適合   | 変化点とパターン意図が一致している           |
| 影響範囲の管理 | 依存関係が増えすぎていない                   |
| 過剰設計の兆候 | 抽象化層が目的に対して過剰でない             |
| 記録の整合     | 意思決定がテンプレートに沿って記載されている |
| 出力検証       | すべての必須項目が含まれている               |
| 事実確認       | 推測には限定詞を使用                         |

### 4.3 ビジネスルール（制約）

| 制約                   | 説明                               |
| ---------------------- | ---------------------------------- |
| テスト失敗時の扱い     | 直ちに前段へ戻し原因を特定する     |
| 過剰設計が疑われる場合 | パターン適用の目的を再評価する     |
| 記録は必須             | 判断理由が不明な場合は完了としない |
