# パターン適用のアンチパターン

## 代表的な失敗

- 目的が不明確なままパターンを導入する
- 変更頻度が低いのに抽象化を追加する
- 1つの変更で複数パターンを同時に導入する
- 既存のテストを整備せずに大規模変更を行う

## 兆候と対策

| 兆候                           | 対策                           |
| ------------------------------ | ------------------------------ |
| 抽象クラスが目的不明           | 目的を再定義し、不要なら削除   |
| パターン名で説明している       | 変化点の理由と価値で説明し直す |
| 依存が増えて単純な処理が複雑化 | 段階を戻して単純化する         |

## 判断基準

- 変更頻度が低ければパターン導入は保留
- 代替案で解決できるならシンプルな方法を選ぶ
