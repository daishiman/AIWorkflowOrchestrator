# パターン選定マトリクス

## 選定軸

| 軸                 | 目安                                           |
| ------------------ | ---------------------------------------------- |
| 変化頻度           | 週次以上なら抽象化を検討                       |
| 呼び出し分岐の複雑さ | 条件が増えるほど Strategy/State を検討         |
| 生成責務の重さ     | 生成ステップが3段階以上なら Factory/Builder   |
| 既存互換要件       | 互換維持が必要なら Adapter/Facade を検討       |
| 通知の拡張性       | 複数購読者が増えるなら Observer を検討         |

## パターン別の判断ガイド

| パターン          | 使うべき状況                           | 避けるべき状況                 |
| ----------------- | -------------------------------------- | ------------------------------ |
| Strategy          | 振る舞い切替が増える                   | 変化点が単一で拡張予定がない   |
| Template Method   | 共通フローに可変ポイントがある         | 例外フローが大きすぎる         |
| Factory           | 生成責務が散らばっている               | 生成が単純な場合               |
| Adapter           | 既存APIの互換が必要                     | 依存関係を変えられる場合       |
| Observer          | 通知先が増える見込み                   | 依存先が固定で少数             |

## 決定ルール

- 目的が「拡張性」か「変更の安全性」かを明文化する
- 抽象化レイヤーの増加は1段階に留める
- 既存テストが弱い場合は先に保護テストを作る
